## [1.4.0] - 2026-09-07

### 新增

- 增加浙江高院 2026-08-25 废止文件目录的效力身份闸门 `scripts/authority_status.py`：七件浙江劳动文件（2009 试行意见、解答一至五、2014 加班工资仲裁时效解答）不得作为现行依据引用；解答参考（六）（七）、纪要及国家司法解释不连带废止。

- 法源研究增加 `historical_reference` 历史引用通道：仅核对历史文献身份与锚点并附警示，不证明当前效力。
- 增加 `scripts/xml_safe.py` 安全 XML 解析（expat 探针拒绝 DTD 与实体定义，防十亿笑声／XXE 实体扩展），docx_style／ingest_materials 的 XML 解析统一接入。
- 增加废止专项测试 `tests/test_repeal_query.py`、法源执行器废止反例与 XML 安全回归 6 项；全量测试 79 项。

### 调整

- 内嵌知识数据联动废止复核：96 张争点卡中 38 张修订（含旧卡与解答原文相悖处的纠正）；编译载荷与知识构建统计同步重建。
- 领域评测期望值改写：场景判定不再依赖已废止旧解答，评测元数据记录效力复核状态。
- README 与快速上手取消"地方资料均现行有效"表述；法源研究与文书起草 Skill 增加引用纪律注记。

### 修复

- 修复 docx_style／ingest_materials 以标准库 `ElementTree.fromstring` 解析外部材料 XML 的实体扩展高危模式（Mimosa 安全门禁拦截后修复）。

## [1.3.0] - 2026-08-26

### 新增

- 增加 GitHub Release 自动发布工作流：`main` 分支的 `VERSION` 变更通过回归测试和领域评测后，自动创建 `v<version>` tag 及 GitHub Release。
- 增加本地材料接入执行器，生成逐材料哈希记录、文字层／OCR 路由、派生文本及 JSON／Markdown 索引。
- 增加事实分层与时间轴执行器；显式区分已证事实、双方陈述、争议事实和待核实事项，并脱敏身份证号和手机号。
- 增加事实冲突结构：冲突事实双向关联处理状态、说明和待核实行动，未解决冲突不得标记为已证事实。
- 增加请求／抗辩矩阵执行器；内置知识发现结果仅作待复核候选，正式矩阵校验构成要件、双方路径、引用关系、备选路径和失败后果。
- 增加证据链与举证责任执行器；按争点构成要件生成待复核骨架，回写经复核的待证命题、证据项、举证责任、证据缺口和补证行动。
- 增加不绑定外部服务的法源核验结果适配器；保存完整条文及哈希、官方来源／法律数据库 URL、效力起止、地域、相关日期和适用理由。
- 增加专业金额执行器，覆盖 N、N＋1、2N、三类加班工资、工伤一次性伤残补助金／伤残津贴／地域待遇／三笔一次性待遇合计、竞业限制补偿及金额合计，并生成可复算的 JSON／Markdown 台账。
- 增加版本化金额参数包及 Schema；内置全国工资折算参数和浙江最低工资公开参数，允许按同一契约追加年度社平工资及其他地域参数。
- 增加实质性对抗验证器，逐争点输出对方最强论证及回应、失败边界、事实分层和引用快照，并将报告绑定当前业务状态摘要。
- 增加逐争点程序分析执行器，记录并校验时效、管辖、一裁终局、临时救济和后续救济路径。
- 增加虚构案件端到端回归，真实执行全部办案节点并解析生成的 DOCX 内容；增加经确认决定登记命令及文书内部工作目录、Pandoc 严格失败模式。
- 增加正式产物端到端追溯：业务来源与上游产物、生成器和 LaborPilot 版本、文件哈希、验证报告及律师审批均绑定到具体 `artifact_id`，并可通过 `trace-artifact` 重新计算。
- 增加最小化知识构建统计清单及复算脚本，核对 149 份来源哈希承诺、96 张知识卡、22 项细分案由与 1 个兜底运行路由；公开结果不包含来源标题、路径、正文或完整知识卡数据。
- 增加 JLS Word 版式修正与独立结构校验，覆盖字体、字号、固定行距、缩进、标题、页面、表格和落款；增加律师复核初稿／最终提交版独立目录、防覆盖、最终版来源和内容门禁。
- 建立版本化领域评测基线，增加复合争点、否定语境、非劳动争议和法律生效边界用例，并阻断内部卡号字段、法律版本重叠或空档。
- 增加锁定公众号文章 PRD 的声明—证据审计，区分可执行实现、Agent／Skill 驱动、外部能力、产品输出边界和 GitHub 发布状态。

### 调整

- 争点路由和领域评测增加“没签劳动合同”等口语化表述，使未显式写出“二倍工资”时仍能召回相关争点。
- 明确运行脚本和测试需要 Python 3.11 以上版本，并将快速上手及专业 Skill 的命令统一为仓库根目录执行口径。
- 材料节点进入下游前复算源文件 SHA-256，并核对大小、接入记录和派生文件；事实节点核对陈述、状态和材料来源关系。
- 材料索引增加逐页文字层、可提取字符数和 OCR 状态；缺失或篡改分页索引时不得进入下游。
- 对抗验证由四项检查升级为六项，新增事实冲突和程序完整性；程序分析纳入业务状态摘要，事实或程序变化后旧报告失效。
- 争点节点不再仅检查 `issue_id`；待复核候选、缺少对方最强观点或存在无效引用的矩阵均不得进入下游。
- 证据节点升级为逐要件证据链门禁；构成要件与对方路径的证据 ID 必须双向一致，完全缺证仍须建立缺口链，不允许豁免。
- 证据评估为充分时，至少须有一项已关联真实材料且真实性状态已明确的可用证据。
- 法源节点由“存在已验证条文 ID”升级为逐要件适用性门禁；待核验线索、地域错配、时间越界、未生效或效力未明规则不得正式采用，且不得豁免。
- 法源与构成要件、对方路径的 `rule_ids` 必须双向一致；旧占位法源可在保留历史快照后显式升级。
- 金额节点升级为可独立重算门禁；每个数值输入须有案件来源，动态参数须保存版本、效力期间、地域、官方来源和参数包哈希，金额、算式、步骤或内容摘要被篡改时会被拦截。
- 存在待确认输入时不生成占位金额；N、N＋1、2N 必须明确确认三倍社平工资封顶是否适用，金额完成条件不得豁免。
- 对抗验证不再接受任意 `status/findings` JSON 自报通过；登记和节点转换会重新计算报告并核对 SHA-256，拦截伪造、过期或事后修改的报告。
- 文书生成不再把内部 Markdown 与用户侧 DOCX 强制放在同一目录，也不再在严格模式下把 Pandoc 失败作为成功返回。
- 文书生成改为必须显式指定文书类型，不再顺带生成未请求文件；最终提交版必须由当前已批准初稿生成，并作为新产物重新验证、重新审批。
- 验证报告保存被验证文件的哈希快照；律师批准必须绑定具体正式产物和当前必需验证记录，来源、上游文件、正式文件或报告被修改后不得完成阶段结案。
- 金额台账不再把事实或决定 ID 混入上游产物字段，改为使用带记录摘要的业务来源引用。
- 领域评测数据的 `package_version` 纳入 `VERSION` 唯一版本源的同步与漂移检查。

## [1.2.0] - 2026-08-22

### 新增

- 将 8 个领域评测转为自动回归测试，直接断言案件核心争点是否召回。
- 增加材料、事实、争点、证据、法源、请求、初稿和验证的机器完成条件。
- 增加经用户明确确认的结构化节点豁免，并保留确认人、理由和时间审计记录。
- 增加长期优化任务清单，持续追踪公众号文章目标能力与公开实现之间的差距。

### 调整

- 争点路由增加常见案件意图扩展和按意图保留核心争点，改善违法解除、工伤、社保被迫解除和试用期等复合查询。
- 工作图路由结果显示当前节点的机器完成条件；下游节点会重新检查上游条件是否仍然成立。

### 修复

- 阻止空业务状态通过连续转换进入阶段结案。
- 阻止不存在的初稿产物通过起草节点。
- 阻止验证者仅以 `--status pass` 而不附 JSON 报告自报通过。
- 阻止验证节点以无报告的 `escalate` 绕过门禁，并修复有报告升级后无法进入律师审批的问题。
