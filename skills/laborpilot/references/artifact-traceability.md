# 正式产物端到端追溯契约

## 目标

律师复核初稿和最终提交版不能只证明“文件存在”。任一正式产物都必须能够反查本次起草使用的业务记录和上游产物、生成器及 LaborPilot 版本、文件当前哈希、针对该文件形成的验证报告，以及律师实际批准的产物与验证快照。

追溯链只记录 ID、摘要和本地路径，不把原始案卷正文复制进案件状态。

## 产物分层

- `internal_work_product`：内部 Markdown、起草输入、金额台账等运行产物，不直接作为对外交付文件。
- `lawyer_review_draft`：供律师复核的初稿；必须完成来源、版本和哈希登记，并在交付前完成独立验证与律师审批。
- `final_submission`：拟对外提交的最终文件；必须直接派生自当前文件哈希已获律师批准的初稿，作为新文件重新验证，并由律师针对该具体文件作出审批。

`lawyer_review_draft` 和 `final_submission` 统称正式产物。文件从初稿变为最终提交版时应登记新的 `artifact_id` 和版本，不能改写旧记录冒充同一产物。

## 五段追溯链

### 一、业务来源

产物通过 `source_refs[]` 引用本案状态中的稳定业务 ID。每个引用至少保存集合名、记录 ID 和登记时对该记录计算的规范化 SHA-256。允许引用的集合为：

`materials`、`facts`、`issues`、`evidence`、`rules`、`calculations`、`claims`、`decisions` 和 `deliverables`。

正式产物至少具有一项业务来源；引用的 ID 必须真实存在，摘要必须能按当前记录重新计算。来源记录被事后修改时，原追溯链失效，须重新生成或重新登记产物。

### 二、上游产物

`derived_from[]` 保存直接上游 `artifact_id`。每条边必须指向已登记产物，且不得形成自引用或循环。验证时同时核对上游文件当前哈希与登记哈希。

起草输入 JSON、内部 Markdown 等应先作为内部产物登记；正式 DOCX 再通过 `derived_from[]` 指向直接起草输入。业务来源可以登记在直接上游，也可以同时登记在正式产物；完整链必须最终到达至少一项业务来源。

最终提交版的 `derived_from[]` 必须直接包含一个 `lawyer_review_draft`，且该初稿的当前文件哈希与律师批准时的快照一致。不能跳过已批准初稿直接从内部 Markdown 生成最终提交版，也不能把初稿原地改名或覆盖后继续沿用原 `artifact_id`。

### 三、生成与文件身份

每项产物至少登记：

- `artifact_id`、`kind` 和 `delivery_status`；
- 本地产物绝对路径、不可变版本号和当前文件 SHA-256；
- `generator`、`producer_version`、`created_by` 和 `created_at`。

`producer_version` 由当前公开包的 `VERSION` 自动读取，不依赖操作人手填。登记后文件内容变化、路径失效、版本缺失或生成器不明，均使追溯校验失败。

### 四、验证绑定

验证记录必须明确列出本次实际检查的 `artifact_ids[]`，并保存各产物登记哈希快照；报告继续保存 `report_path` 和 `report_sha256`。正式产物的确定性和对抗性验证必须同时指向该产物，不能用验证其他文件的报告替代。

产物文件或验证报告在登记后变化时，原验证失效。

### 五、律师审批绑定

`lawyer_approval` 的批准记录必须明确列出：

- 本次批准的正式 `artifact_ids[]` 及其哈希快照；
- 作为审批依据的 `validation_ids[]` 及其报告哈希快照；
- 批准范围、批准人和时间。

批准时应重新核对产物、业务来源、上游产物和验证报告。`stage_close` 转换时再次复算整条链；缺少绑定、引用错误、摘要过期、报告不属于该产物或文件事后变化，均不得完成阶段回写。

## 机器验收

`workflow_graph.py trace-artifact --state <case_state.json> --artifact-id <id>` 输出该产物的完整追溯结果。只有下列条件全部成立时状态为 `pass`：

1. 文件、版本、生成器和公开包版本完整，文件哈希匹配；
2. 业务来源与上游产物真实存在，摘要匹配且无循环；
3. 当前阶段要求的验证报告均绑定该产物，报告文件与哈希匹配；
4. 正式产物已有绑定到同一产物和同一组验证记录的律师批准；
5. 阶段结案时，上述结果仍可重新计算。

内部产物可在尚未验证或审批时返回 `incomplete`，但不得被当作正式交付完成。正式产物缺少任一必需环节时返回 `blocked`。
