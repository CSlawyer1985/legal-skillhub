## 如何阅读本文件

每个纵栏报告其来源基准实际衡量的指标。它们**不是**同一指标，因此各纵栏之间的分数**不可比较**。legalbenchmarks.ai 上的「可靠性」（律师清单全过）是远比 Vals LegalBench 上「准确率」（多项选择法律推理）严苛的量表。

模型名称反映基准在快照日期发布的内容。供应商迭代很快；此处的名称可能已被取代。**原型**（模型*所擅长*的）老化速度慢于其精确排名。

## 1. 合同起草

**来源：** legalbenchmarks.ai——「合同起草」（34 个任务，第三期，每月刷新）。
**指标：** `Reliability`（可靠性）= 在律师撰写的清单上*完全*正确的任务占比（二元；一项失误即整任务失败）。`Usefulness`（有用性）= 1-3 均值（清晰度/长度/结构）。成本 = 美元/任务。

**真相/不足**
- **Opus 4.8**——最佳全能起草者；独特地愿意*标记矛盾指令*而非直接起草绕过。真相：可靠性最高。不足：不是最便宜的。
- **Fable 5**——质量上与 Opus 持平，但成本/任务约为其 2.2 倍且未超越。不足：起草定价过高。
- **Grok 4.5**——最佳非 Anthropic 起草者，前四中最便宜；独特地擅长*保留本已健全的措辞不动*（更少无谓重写）。强烈的高性价比选择。
- **GPT 5.6 Sol**——**最高有用性（2.75）是个陷阱：**「比准确更精美」。其草稿中超过 50% 遗漏了隐藏于干净文字之后的 ≥1 项指令。不要仅凭可读性将起草路由至此。
- **所有模型**——冲突检测薄弱；GPT 5.6 Sol 在静默起草绕过矛盾方面最差。

**真相/不足**
- **GPT 5.6 Sol**——最擅长*穷尽式条款检索*和*跨文档比较*。盲区：**扫描文档**，以及**把条件式答案压平成绝对表述**（「若 X 则 Y」→「Y」）。核验条件句。
- **Opus 4.8 / Fable 5**——最可靠的一对（并列第 2），但是被测答案中**最冗长**的；你在输出 token 和后处理上付出代价。
- **Grok 4.5**——**所有模型中扫描文档处理最佳**，但完整性上回报不足（「几乎全部」而非全部）。图像密集型/接近 OCR 的提取路由至此，然后复核覆盖范围。
- **廉价档（Qwen 3.7 Max、GPT-5.4-mini、DeepSeek V4 Pro）**——可靠性垫底（55-62%）。适合低风险分诊，不适合你将依赖的提取。

**相关学术锚点（Wei Chen / Atticus Project）：** **CUAD**（条款提取，510 份合同，41 类条款）、**MAUD**（并购阅读理解，92 类问题）、**ACORD**（条款检索，1-5 相关性）。这些是该领域在需要可复现的提取/检索评估时使用的开放数据集。

**真相/不足**
- **前 10 名彼此相差约 2.9 个百分点。**在此基准上，「哪个模型是第一」大多是噪音——按成本/速度/约束选择，而非按排行榜名次。
- **Gemini 3 Flash 是性价比之选：** 86.86%，仅 **$0.5/$3 且 4.67 秒**——顶尖精度，第一梯队中最便宜最快。
- **Fable 5** 准确率领先，但在此处最贵（$10/$50）。
- **Grok 4.5** 准确率有竞争力，但**慢得离谱（67.88 秒）**——不要把它放进交互式研究循环。
- Vals 自身的告诫：性能因任务而异，即使是顶级模型也会在 FRCP 式规则问答中错误引用规则。**法律模型仍有显著改进空间。**

**来源 B：** Harvey——**法律代理基准（LAB）**（1200 多个代理任务，24 个实务领域，75,000 多条专家评审标准，**全过评分**，基于真实客户事项构建；长周期代理工作）。**尚无公开分数**（基线「即将推出」）。将 LAB 用作代理式法律研究的*任务设计标准*（多步骤、达评审质量的输出），而非记分牌。其前身 **BigLaw Bench** 覆盖短周期推理（读一份合同，答一个问题）。

## 4. 合同审查

**没有单一公开基准孤立「合同审查」。** 它是*复合*技能 = 找出条款（**信息提取**，§2）+ 判断相对标准的风险/偏离（**法律推理**，§3）+ 提出红线修改（**合同起草**，§1）+ 发现内部矛盾（**冲突检测**）。通过组合这三张表并加权主导特定审查的子任务来进行路由。

**派生指引（复合，非实测排行榜）**
- **提取密集型审查**（找出 X 类所有条款，构建义务矩阵）：加权 §2 → **GPT 5.6 Sol** 领先，但**核验条件句**（它会压平它们）；需要更安全、更可靠的解读选 **Opus 4.8**。
- **风险/偏离分析**（此赔偿是否市场标准？敞口多大？）：加权 §3 → 顶尖集群准确率旗鼓相当；成本/速度选 **Gemini 3 Flash**，最稳妥推理选 **Fable 5 / Opus 4.8**。
- **红线修改起草**（重写以保护客户）：加权 §1 → **Opus 4.8**（最佳起草者*且*最擅长标记矛盾）或 **Grok 4.5**（保留健全措辞，更便宜）。
- **长协议中的冲突检测**：**Opus 4.8** 是记录在案的突出者；**避免 GPT 5.6 Sol**（静默起草绕过矛盾最差）。
- **长协议（100+ 页）：** 宣称的上下文 ≠ 有效上下文。只有 **Gemini 3 Deep Think** 在接近 100 万 token 时保持质量；大多数模型在约 20 万-40 万后退化。其余切块 + map-reduce。

## 5. 法律翻译

**五个纵栏中公开基准覆盖最薄弱——将本节视为方向性的，而非像 §1-§3 那样有基准支撑。** 前沿 LLM 没有干净的法律翻译排行榜。指引由 (a) 不触及法律文本的通用机器翻译基准、(b) 用作代理的多语言推理基准，以及 (c) 专门的法律机器翻译研究三角互证。**认证/宣誓翻译始终需要合格的人类译者——LLM 在此只是初稿引擎，永远不是签署人。**

**通用翻译质量**
- **WMT25**（领域严格性标准）：人工评估 → **Gemini** 家族获胜（16 个语言对中领先 14 个）；GPT 和 Cohere Command-A 接近；DeepSeek/Claude 第二梯队。排名**依指标而异**——另一套方法论将 GPT-5、Grok 4、Claude Opus、Gemini 排成不同顺序。没有定论的「领导者」。
- **按语言划分（方向性）：** Claude 在德语/日语/韩语/荷兰语/意大利语领先，且**专业译者偏好其语气/语域**；Gemini 在中文/巴西葡萄牙语/乌克兰语领先，并为长文档承载更大的上下文窗口。

**多语言推理（无法律机器翻译数字时的代理）**
- 大致：**Gemini 3.1 Pro** 原始多语言知识居首（约 94 MMLU），**GPT-5.x** 接近且在 MMLU-ProX 上最强，**Claude Opus** 为强劲第三，多语言数学（MGSM）尤其出色。
- 这是*在*某种语言中的推理，而非翻译*质量*——是代理，不是替代。

**法律翻译特定证据（薄弱但真实）**
- **SwiLTra-Bench**（arXiv 2503.01372）——找到的最严谨的专门法律机器翻译基准（瑞士成文法/判例法，德/法/意/罗曼什语）。发现：**通用 LLM 在术语等价性、成文法语域和保留先例的判例法翻译上仍落后于专门的法规翻译系统**。
- **欧盟 EUR-Lex** 明确告诉用户**不要**依赖其自身的机器翻译工具处理立法——只有经人工核验的官方语言文本才具有真实性。机构对法律机器翻译的不信任是明确、直接的陈述。
- 术语表解决*术语一致性*，但不解决**否定准确率**、**法域概念映射**（普通法「discovery」/「plea bargain」无大陆法系对应）、**交叉引用完整性**或**法律效力**。这些正是使法律机器翻译危险的失败模式。

**阿拉伯语 / 中东北非地区**
- **不存在阿拉伯语法律*翻译*基准**——一个真实的空白。阿拉伯语法律*推理*基准存在（**ArabLegalEval**、**ALARB**）；耐人寻味的是，ArabLegalEval 是通过将英语 LegalBench 机器翻译成阿拉伯语*然后*专家核验构建的——这隐晦地承认原始机器翻译需要人工检查。
- 通用阿拉伯语推理：**Gemini 3.1 Pro / 3 Pro** 领先（约 93），**Claude Opus** 接近（约 91-92）。据报（软性/定性）Claude 的阿拉伯语散文更自然。
- **Mistral 是有记录的阿拉伯语弱点。** **Qwen**（Qwen-MT 系列）和 **Cohere Aya** 是专为多语言而建，是最强的*可自托管*阿拉伯语选项。
- **从右到左（RTL）是 UI 问题，不是模型问题**——输出文本没问题；显示对齐是前端事项（仅在你基于 API 构建自己的阿拉伯语 UI 时相关）。

**路由指标：** 无公开的。基于上述代理路由；**人工法律语言学家审查是强制性的，而非可选的**——这是有记录的行业共识，不是搪塞。

## 通用语境（为什么不能按通用排行榜路由）

- **纵栏会重排领奖台。** Artificial Analysis 智能指数领先者（Fable 5 约 60、GPT-5.6 Sol 约 58-59、Opus 4.8 约 56）*并非*每个法律维度的领先者——例如 Opus 4.8 登顶合同起草，而 GPT 5.6 Sol 登顶信息提取。绝不可按通用排行榜路由法律任务。
- **饱和隐藏差距。** GPQA/AIME 对第一梯队处于 94-100%——零路由信号。**HLE**（Fable 5 约 53%、Grok 4 Heavy 约 50%、Opus 4.8 约 46%）是仍能区分模型的一个推理测试。
- **宣称上下文与有效上下文在约 20 万 token 之后分歧 30-60 点。** 只有 Gemini 3 Deep Think 保持接近其 100 万规格。
- **成本地板：** 中国开放权重模型（DeepSeek V4 Flash 约 $0.06/M、Qwen）比封闭前沿便宜 10-50 倍——适用于本地/隐私和高批量分诊，代价是法律任务上的可靠性。
- **在代理基准上，脚手架 ≠ 模型**（GAIA 分数随 harness 摆动约 30 点）。代理式法律研究评价的是*系统*，而非模型。

## 横切告诫（纳入每个路由决策）

1. **能力 ≠ 可控性**（Wei Chen，Atticus Project）。高分基准分不意味着模型会保持在范围内、如实引用，或可安全无监督部署。治理是与原始性能分离的独立轴。
2. **全过现实**（Harvey）。捕获 10 个风险中 8 个的审查不是 80% 有用——它是实质性不完整。高风险工作按可靠性路由，而非平均质量。
3. **评分不完美。** legalbenchmarks.ai 的可靠性由*单一* LLM 评委（Claude Sonnet 4.6）评分；有用性由双评委小组（约 82% 一致）评分。其自身的偏差检查：Sonnet 未登顶任一排行榜，Anthropic 模型在长度上排名最低——这是反对自我评分偏袒的证据，但 LLM 评分的分数仍然不是地面真相。
4. **覆盖面狭窄。** legalbenchmarks.ai 仅英语、偏美/英、单轮、每任务一次运行（无漂移/一致性测试），任务集为私有。Vals LegalBench 是多选推理，不是起草。**非美国、非英语、多轮和长周期工作被低估。**
5. **基准漂移与路由坍塌。** 此处的数字每月过时；且总是选一个主导模型的路由器已经停止路由。新前沿模型发布时重新验证。
6. **静默质量退化。** 成本节约立即体现在账单上；质量损失数日后才体现在工作成果中。任何成本驱动的降级都要以抽查把关。
