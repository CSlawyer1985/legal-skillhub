# /disclosure-list

1. 识别制度——PD 57AD（商事与财产法院：商事法院、大法官庭、TCC、巡回商事、知识产权、金融清单）或 CPR 第 31 部分（其他所有法院，包括大多数郡法院多轨案件）。
2. PD 57AD 下：按争点选择适当的扩展披露模式（A–E）。初始披露（Initial Disclosure）也是必需的。
3. CPR 31 下：适用“标准披露”（CPR 31.6）——一方依赖的文件，加上对自己案件有不利影响 / 支持另一方案件 / 相关实践指引要求的文件。
4. 构建文件清单（CPR 下为 N265 表格；PD 57AD 下为披露审查文件）。
5. 在披露前应用特权筛查。

# 披露清单

## 适用哪种制度？

| 法院 / 审判庭 | 制度 |
|---|---|
| 商事与财产法院（商事、大法官、TCC、巡回商事、知识产权、金融清单） | PD 57AD（披露试点方案——现为常设制度） |
| 高等法院其他审判庭、郡法院、快速轨和多轨 | CPR 第 31 部分 |
| 小额索赔轨 | CPR 27.4（按指示的有限披露） |
| 家事程序 | FPR——单独制度，此处不覆盖 |

## PD 57AD——扩展披露模式

在初始披露（有限——依赖的文件加上对方理解案件所需的文件）之后，双方同意或法院命令按争点进行**扩展披露**，使用以下一种或多种模式：

| 模式 | 要求 |
|---|---|
| **A** | 披露限于已知的不利文件（不进一步检索）。 |
| **B** | 有限披露——为使对方能够理解所提出的案件而必需的文件。不进行超出初始披露已做范围的主动检索。 |
| **C** | 基于请求的检索——按请求指定的具体文件或狭窄类别进行披露。最狭窄的“真实检索”模式。 |
| **D** | 狭窄检索式披露——检索可能相关的文件 + 发现的不利文件。相当于标准披露的 PD 57AD 版本。 |
| **E** | 广泛检索——如模式 D，但包括调查线索方法（Peruvian Guano 式）。仅在为公平解决争点所必需时可用，通常须有强理由。 |

选择通过**披露审查文件（DRD）**进行——一份双方填写并交换的结构化协商文件。

## CPR 第 31 部分——标准披露

披露：
- 一方依赖的文件（CPR 31.6(a)）。
- 对自己案件有不利影响、对另一方案件有不利影响或支持另一方案件的文件（CPR 31.6(b)）。
- 相关实践指引要求一方披露的文件（CPR 31.6(c)）。

该义务及于一方控制下的文件（实际占有、有权占有或有权检查：CPR 31.8）。

## 输入

- 法院 / 审判庭（决定制度）。
- 披露争点（PD 57AD）或诉辩争点（CPR 31）。
- 保管人（员工、代理人、顾问）。
- 数据来源（电子邮件、文件共享、文档管理、消息应用——包括 WhatsApp / Signal、数据室平台）。
- 日期范围。
- 特权范围（意见特权、诉讼特权、无偏见、共同利益）。
- 保密性（商业敏感、监管、第三方）。
- 外国数据保护（GDPR——传输的第 6/49 条法律依据）。

## 工作流

### 第 1 步——制度检查
商事与财产法院 → PD 57AD。否则 CPR 31。

### 第 2 步——初始披露（PD 57AD）
各方随案件陈述书送达：依赖的文件 + 其他方理解案件所需的文件。披露争点清单随后载于 DRD。

### 第 3 步——披露争点（仅 PD 57AD）
聚焦的清单——与诉辩争点不同。应选择披露确实能提供信息的争点。

### 第 4 步——按争点选择模式（PD 57AD）
每个争点分配一个模式。可行时默认模式 C（基于请求）；更宽泛的争点用模式 D；模式 E 仅在例外案件中使用。

### 第 5 步——保管人 / 数据来源映射
谁持有相关文件；数据位于何处；使用什么平台（Outlook / Gmail / Teams / Slack / WhatsApp / 数据室 / 纸质）。

### 第 6 步——检索方法论
- 日期范围。
- 保管人。
- 数据来源。
- 关键词（PD 57AD 要求商定关键词清单和去重方法）。
- 技术辅助审查（TAR / 预测性编码）的使用——在 DRD 中披露使用情况。

### 第 7 步——特权审查
- 意见特权：律师与委托人之间为提供法律意见目的的沟通。
- 诉讼特权：与第三方（证人、专家）的沟通，其主导目的为合理设想的诉讼。
- 无偏见（WP）：和解往来函件。
- 共同利益：与第三方（保险人、共同被告）共享的法律利益。

特权文件按描述列明，不提供副本。允许对特权部分进行遮盖。

### 第 8 步——文件清单

**CPR 31——N265 文件清单（或等效）：**

三部分：
- 第 1 部分：控制中且可供检查的文件。
- 第 2 部分：控制中，但有权或负有义务不予检查的文件（特权）。
- 第 3 部分：曾经但不再处于控制中的文件（何时及如何失去控制）。

外加**披露声明**（由当事方亲自签署——CPR 31.10），证明检索和义务已履行。

**PD 57AD——披露证书**

由当事方（而非律师）签署，证明检索符合命令及该实践指引下的披露义务。与 CPR 31.10 声明一样，本技能产出的任何披露证书草稿都是**脚手架，而非已签署的证书**——全程携带相同的 DRAFT（草稿）横幅，不得呈现为已完成认证，且当事方必须在检索实际执行后亲自签署。

## 输出

使用以下章节产出清单。将其呈现为完成的文件清单——不要回显本模板，也不要为填充某个章节而虚构文件、保管人或来源。如某部分无内容，如实说明。列出的每份文件必须可追溯至用户提供的真实输入；技能界定范围并起草清单，它不生成清单中的文件。

## 披露声明（CPR 31.10）

> **DRAFT——并非已签署声明。** 这是披露声明的脚手架，而非完成的声明。在可以提交前：声明必须经审查；其描述的检索必须实际执行；且必须由当事方依 CPR 31.10 **亲自签署**。不要按生成原样提交。不要将空白呈现为已填写，也不要断言检索已执行——只有签署方才能证明这一点。呈现时附横幅，并将认证文本展示为当事方须自行采用的措辞，而非模型作出的声明。

本人 [姓名] 声明：
1. 本人地址为 [...]. 本人担任 [职务]。
2. 本人获授权代表 [当事方] 作出本披露声明。
3. 本人熟悉 [诉辩文件] 所列本案争点。
4. 本人已按 [命令 / 标准披露 / 商定范围] 对本人须披露的文件进行了检索。
5. 检索覆盖 [保管人、数据来源、日期范围、关键词]。
6. 本人未检索 [排除的来源——如 7 年以上纸质档案、休眠服务器]——并说明理由。
7. 本人证明本人理解披露义务，且据本人所知已履行该义务。

签署：[当事方——亲自签署，CPR 31.10]
日期：[date]

## 本技能不做什么

- 运行检索。它界定范围和列清单；检索本身在模型之外进行，且在任何清单或声明被认证之前必须实际执行。
- 决定特权。它按描述标记候选；由律师审查每个被标记文件并作出特权判断。
- 认证任何内容。披露声明（CPR 31.10）和披露证书（PD 57AD）由当事方亲自签署——模型起草脚手架，不作认证。
- 覆盖苏格兰 / 北爱尔兰程序（Commission and Diligence；RCS 附表 1）。
- 提供法律意见。这是产出供律师审查的草稿的起草辅助工具。其生成的任何内容都不应按生成原样提交——在依赖或送达任何输出前，与律师核验范围、检索和特权判断。
