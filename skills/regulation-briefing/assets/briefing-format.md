# 法规快讯格式

本文件规定法规快讯的成稿格式:单条快讯字段、汇总表字段、风险提示口径,以及 Word(`write_docx`)与 HTML(`write_html`)两种交付的展示要求。所有字段值一律以 `web_fetch` 打开的原文为准;原文未明确的字段写「原文未明确」,不得臆造或推断。

## 一、单条快讯字段

每条快讯按以下顺序组织字段,顺序固定,不得调换。字段缺值时保留字段名并填「原文未明确」,不得整行删除。

| 序 | 字段 | 取值要求 |
| --- | --- | --- |
| 1 | 标题 | 用法规/文件的正式全称,不简写、不加书名号以外的修饰。多个名称以官方公布名为准。 |
| 2 | 发文机关 | 写完整机关名(如「国家市场监督管理总局」「中国人民银行」)。联合发文列全部机关,以原文署名顺序排列。 |
| 3 | 文号 | 抄录原文文号(如「国市监规〔2026〕X 号」「主席令第 X 号」)。无文号的规范性文件填「无文号」。 |
| 4 | 发布日期 | 公布/印发日期,格式 `YYYY-MM-DD`。以原文落款或官方发布页为准。 |
| 5 | 生效日期 | 施行日期,格式 `YYYY-MM-DD`。如「自公布之日起施行」则写该日期并括注「(自公布之日起施行)」;附条件生效的照抄条件。 |
| 6 | 效力级别 | 从下列择一并写明:法律 / 行政法规 / 监察法规 / 司法解释 / 部门规章 / 地方性法规 / 地方政府规章 / 规范性文件 / 国家标准·行业标准。拿不准时按发文机关与文号判断,仍不确定写「待核实(规范性文件)」。 |
| 7 | 核心要点(3-5 条) | 每条一句,落到具体义务、主体、数额、时限或禁止行为。引用数字、比例、罚则、过渡期时逐字核对原文。不足 3 条说明原文篇幅有限,不凑数;超过 5 条只保留与目标读者最相关者。 |
| 8 | 影响与合规提示 | 1-3 句,面向律所/客户视角:谁受影响、需要做什么动作(备案/整改/更新合同模板/调整流程)、关键时间节点。区分「确定影响」与「需进一步评估」,不得把分析写成原文规定。 |
| 9 | 原文链接 | 可打开的真实 URL,优先官方发布页(立法机关、部委官网、国家法律法规数据库)。一条快讯至少一个可追溯链接;有多个来源时官方源在前。 |

### 单条快讯模板片段

```markdown
### 〔标题:法规/文件正式全称〕

- 发文机关:〔完整机关名;联合发文列全部〕
- 文号:〔原文文号 / 无文号〕
- 发布日期:〔YYYY-MM-DD〕
- 生效日期:〔YYYY-MM-DD(如「自公布之日起施行」括注)〕
- 效力级别:〔法律 / 行政法规 / 部门规章 / 司法解释 / 地方性法规 / 规范性文件 / ……〕

核心要点:
1. 〔要点一:具体义务/主体/数额/时限〕
2. 〔要点二〕
3. 〔要点三〕

影响与合规提示:〔谁受影响 + 需采取的动作 + 关键时间节点;区分确定影响与待评估〕

原文链接:〔官方发布页 URL〕
```

## 二、汇总表字段

当快讯包含多条时,正文前置一张汇总表,便于读者扫读。表头字段顺序固定:序号 / 法规名 / 机构 / 发布日 / 生效日 / 主题 / 链接。

- 序号:阿拉伯数字,与下文单条快讯顺序一致。
- 法规名:可用便于阅读的简称,但须与正文标题指向同一文件;首次出现的简称在正文标题处给出全称。
- 机构:发文机关,可用通用简称(如「市监总局」),全称在正文给出。
- 发布日 / 生效日:`YYYY-MM-DD`,与单条快讯一致。
- 主题:一个词或短语归类(如「数据合规」「反垄断」「劳动用工」「金融监管」),便于按主题筛选。
- 链接:原文 URL;HTML 交付时做成超链接,Word 交付时插入超链接字段。

### 汇总表模板片段

```markdown
| 序号 | 法规名 | 机构 | 发布日 | 生效日 | 主题 | 链接 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 〔简称〕 | 〔机构〕 | 2026-MM-DD | 2026-MM-DD | 〔主题〕 | 〔URL〕 |
| 2 | … | … | … | … | … | … |
```

## 三、风险提示口径

风险提示统一口径,避免把检索结论说成法律意见,也避免遗漏免责边界。

- 区分「原文规定」与「快讯分析」:核心要点只写原文有的内容;影响与合规提示是分析,须可与原文区分,语气用「可能」「建议关注」「需评估」而非断言。
- 确定性分级:对每条「影响与合规提示」隐含三档——确定影响(原文明文规定的义务)、较可能影响(原文指向但需结合主体情况)、待评估(需进一步信息)。后两档须显式标注「需进一步评估」。
- 时效声明:快讯反映检索截止日的公开信息,法规可能后续修订、被解释或废止;以现行有效文本和官方发布为准。
- 来源边界:已核验条目、存疑条目、未覆盖范围分别列明。存疑条目(打不开原文、来源冲突、日期不一致)单列并说明原因,不混入正文当作已核实。
- 非法律意见声明:快讯为信息整理,不构成针对具体事项的法律意见;具体适用应结合个案咨询执业律师。

### 风险提示模板片段(置于交付件末尾)

```markdown
---
说明与风险提示
- 本快讯依据 〔检索截止日 YYYY-MM-DD〕 的公开信息整理,法规可能后续修订或废止,以现行有效文本和官方发布为准。
- 「影响与合规提示」为初步分析,非针对具体事项的法律意见;标注「需进一步评估」者应结合个案核实。
- 已核验条目:〔N〕条;存疑条目:〔列明及原因〕;未覆盖范围:〔说明〕。
- 具体适用请咨询执业律师。
```

## 四、Word 与 HTML 交付要求

两种交付的字段、顺序、风险口径完全一致,差异仅在版式与技术约束。无论哪种,正文结构均为:标题与日期 → 汇总表 → 各单条快讯 → 风险提示。

### 4.1 Word(write_docx)展示要求

- 文档标题:首行用一级标题,如「〔主题〕法规快讯(〔时间窗〕)」,下一行小字注明检索截止日。
- 汇总表:用原生 Word 表格,表头加粗、首行重复(跨页时表头重复显示)。
- 单条快讯:每条用二级标题作为快讯标题;字段用项目符号或紧凑的两列小表;核心要点用有序列表。
- 链接:用超链接字段,显示文字为法规名或「原文」,底层指向真实 URL,不要只贴裸链接。
- 排版:正文中文宋体、标题黑体;字号层级清晰;每条快讯之间留空行或分隔。供打印/转发,需有页码与生成日期(可置页脚)。
- 风险提示:文末单独成段,可用浅色底纹或分隔线区分于正文。

### 4.2 HTML(write_html)展示要求

- 必须自包含:所有 CSS 内联或写入 `<style>`,不引用任何 CDN、外部字体或外部脚本;图标用文字或内联 SVG。可离线、单文件打开。
- 结构:`<header>` 放标题与检索截止日;汇总表用 `<table>`,可加表头吸顶或斑马纹便于扫读;每条快讯用 `<section>`,标题用 `<h2>`。
- 链接:`<a href>` 指向真实 URL,加 `target="_blank" rel="noopener"`;汇总表与单条快讯的链接都可点。
- 交互(可选,须不依赖外部资源):按主题筛选、汇总表锚点跳转到对应单条快讯。逻辑用内联 `<script>` 实现,不得引外部库。
- 风险提示:置于页面底部 `<footer>`,样式上与正文区分(如浅灰底、小字)。
- 移动端:响应式,窄屏下表格可横向滚动或转为卡片式,保证可读。

### 4.3 两种交付的差异对照

| 维度 | Word(write_docx) | HTML(write_html) |
| --- | --- | --- |
| 用途 | 打印、邮件附件、内部归档、再编辑 | 在线/离线浏览、内网发布、快速转发 |
| 链接形式 | 超链接字段(显示名 + 隐藏 URL) | `<a>` 标签,可直接点击 |
| 样式 | Word 样式表,宋体/黑体,页码页脚 | 内联 CSS,响应式,可选轻交互 |
| 资源约束 | 图片等随文档嵌入 | 必须完全自包含,禁外部 CDN/字体/脚本 |
| 汇总表 | 原生表格,表头跨页重复 | `<table>`,可吸顶/斑马纹/锚点跳转 |
| 可编辑性 | 收件人可二次编辑 | 一般只读,如需修改回到源文件 |

> 通用约定:无论 Word 还是 HTML,字段顺序、风险提示口径、来源可追溯性都不得因版式让步;每条快讯都必须能追溯到 URL、日期与原文摘录。
