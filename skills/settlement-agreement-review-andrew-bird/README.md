# settlement-agreement-review

审查或起草向员工支付费用以了结其索赔的协议——并标记决定其是否实际约束员工的法定条件。

和解协议只有满足 1996 年《雇佣权利法》第 203 条的累积条件，才能阻止法定的雇佣索赔；漏掉一项，员工就可以拿了钱仍继续索赔。本技能检查六项条件并标记明显缺口供事务律师确认，对照当事人立场（雇主或雇员）审查实质性条款，并浮出税务和可执行性风险。它不就有效性作出裁定，也不构成法律意见。

适用于在签批前检查协议的雇佣事务律师、审查离职者条款的法务团队，以及压力测试要约的员工顾问。

## 安装

```bash
git clone https://github.com/b1rdmania/settlement-agreement-review ~/.claude/skills/settlement-agreement-review
```

或在 [Legalise](https://github.com/b1rdmania/legalise) 工作区中：从技能库添加——审查清单、授予能力、在事项上启用、从聊天运行。每次运行都留下带签名、可审计的记录。

## 用法

```
/settlement-agreement-review --mode=review --party=employee
/settlement-agreement-review --mode=draft --party=employer
```

对照协议文本和事实运行：谁在离职、什么条款、付款明细，以及您代理哪一方。审查模式下返回带风险标记的批注审查；起草模式下返回可供完善的干净草稿。

## 功能

- 对照第 203 条 ERA 的六项条件（书面形式、特定投诉、独立顾问、顾问已确认、顾问已投保、条件陈述）检查协议并报告表面状态——标记缺口供事务律师确认。
- 对照当事人立场审查实质性条款——付款明细、保密和不诋毁、推荐信、保证、限制性契约、索赔清单、税务赔偿。
- 浮出 ITEPA 2003 下的税务问题，包括 PILON 上的 PENP，每一项数字都标记为需会计师提示而非权威结论。
- 输出带优先级变更的批注审查或干净草稿。
- 内联标记每一个不确定点——`[CONDITION GAP]`、`[NOT TAX ADVICE]`、`[CITE NEEDED]`、`[SME VERIFY]`——使任何内容都不会被读作定论。

## 不做什么

- 不提供法律意见——它标记明显问题供合格顾问确认。
- 不就协议是否有效作出裁定——它仅报告表面的第 203 条状态；有效性由事务律师确认。
- 不提供员工所需的独立意见——那必须按第 203(3A) 条 ERA 来自合格顾问。
- 不权威计算税务——每个数字都需要会计师或税务顾问签批。
- 不对照实时来源验证判例或法规——依赖前检查其引用的任何权威。
- 不覆盖苏格兰或北爱尔兰（法定框架不同）。
