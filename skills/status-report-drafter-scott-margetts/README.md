# status-report-drafter

将电子邮件、通话记录和工作流更新转化为结构化的事项状态报告 — 含 RAG 评级、偏差评注和升级标记。内部与面向客户两种格式。

## 本技能的功能

法律事项的状态报告以两种可预测的方式失败：要么完全不报告，要么产出只描述活动而不传达状况的报告。"团队一直在推进披露工作流"对读者毫无有用信息。良好的状态报告运用例外管理逻辑 — 以需要关注的内容领起、压缩在轨的内容、标记需要决策的内容。

技能接收您拥有的任何材料 — 一封邮件链、通话记录、工作流负责人的粗略更新 — 并产出适合目标受众格式的结构化报告。

**输出遵循 BLUF 原则（结论先行，Bottom Line Up Front）：** 30 秒后停止阅读的读者已掌握关键事项。继续阅读的读者获得逐级增加的细节。没有人应该为了知道什么重要而滚动屏幕。

## 三种报告格式

**内部报告：** 对状况直接，将回应框定为建议。为需要知道采取什么行动的合伙人和高级利益相关者而写。

**面向客户报告：** 传达相同的事实信息，并带有管理的信心。对事实专业地直接；对回应有所斟酌。不使用内部表述框架。

**临时更新（Ad hoc update）：** 供 Slack、Teams 或快速邮件更新的更短格式 — 当前位置、一行式工作流状态、未决事项。

## 输入

- 工作流负责人或相对方的电子邮件
- 通话或会议记录
- 先前的状态报告（用于识别变化）
- WIP 或计费数据（用于财务状况）
- 描述事项进展的任何其他往来函件或更新

技能在提供任何材料的情况下都能工作，并在关键信息缺失时予以标记。

## 产出

所有产出默认以 .docx 生成，文档页眉含客户名称、客户编号、事项名称和事项编号。

- 内部状态报告（按工作流 RAG、偏差评注、升级标记、所需决定）
- 面向客户状态报告（相同结构，受众适当的表述）
- 临时更新（供消息或邮件的短格式）

## 跨技能交接

- **识别到范围问题** → scope-change-controller 评估工作是否超出商定范围
- **从往来函件中提取到风险或决定** → risk-and-issues-manager 记入 RAID 日志
- **暗示范围问题的财务偏差** → budget-and-fee-manager 进行财务分析；scope-change-controller 进行范围外评估
- **识别到时间线影响** → timeline-generator 重新计算依赖关系和项目影响
- **需要利益相关者通知** → stakeholder-comms-planner 制定沟通方式和时机
