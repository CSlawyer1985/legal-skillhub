# 数据保存期限

> 参考：GDPR 第 5.1.e 条（保存限制）
> **文档**：[CNIL_durees_conservation.pdf](assets/CNIL_durees_conservation.pdf)

## 基本原则

GDPR 要求个人数据仅保存**有限**且与处理目的**相称**的期限。超过该期限，数据必须删除或匿名化。

> **GDPR 第 5.1.e 条**：数据应"以允许识别数据主体的形式保存，保存期限不超过处理目的所需的期限"

---

## 保存的三个阶段

### 1. 活跃库

**定义**：为日常运营需要可实时访问的数据。

**示例**：活跃客户账户、正在处理中的订单。

### 2. 中间存档

**定义**：日常不使用但为行政、法律或证明需要而保存的数据。

**限制访问**：仅获授权人员可以访问。

**示例**：已注销账户客户的发票。

### 3. 永久存档（罕见）

**定义**：出于公共利益原因（历史档案、科学研究）长期保存。

**规制**：条件严格，通常不适用于商业场景。

## 按类别的保存期限表

### 客户/潜在客户数据

| 数据类型 | 保存期限 | 法律依据/理由 |
|-----------------|----------------------|----------------------------|
| **活跃客户账户** | 商业关系存续期间 | 合同履行 |
| **不活跃客户账户** | 最后活动后 3 年 | 开发客户（合法利益） |
| **潜在客户（非客户）** | 最后接触后 3 年 | CNIL 建议 |
| **通讯订阅联系数据** | 直至退订 + 3 年 | 同意证明 |
| **订单历史** | 5 年（民事时效） | 法律保护 |

### 支付/会计数据

| 数据类型 | 保存期限 | 法律依据/理由 |
|-----------------|----------------------|----------------------------|

| **会计凭证** | 10 年 | 法定义务（《税收总法典》） |
| **支付数据（银行卡）** | 交易期间 | 安全 / PCI-DSS |
| **交易证明** | 5 年 | 民事时效 |
| **SEPA 授权** | 授权结束后 5 年 | CNIL 建议 |

## 良好实践

### 1. 制定保存政策

为每个数据类别记录：
- 保存期限
- 理由（目的、法定义务）
- 存档/删除程序

### 2. 自动化清理

```
建立自动化流程：
- 删除前告警（如相关）
- 到期自动删除
- 以匿名化替代删除
- 记录删除日志
```

### 3. 区分阶段

```
活跃库（常规访问）
    │
    │ [关系结束]
    ▼
中间存档（限制访问）
    │
    │ [法定保存期限届满]
    ▼
删除或匿名化
```

### 4. 在政策中告知

始终在隐私政策中说明保存期限，并附可理解的说明。

## 常见错误

| 错误 | 后果 | 解决方案 |
|--------|-------------|----------|
| 未设定期限 | 不符合 GDPR | 系统性表格 |
| 无限期保存 | CNIL 处罚 | 自动清理 |
| 所有数据同一期限 | 不成比例 | 按目的调整 |
| 不区分活跃/存档 | 访问不受控 | 保存阶段 |
| 忘记法定义务 | 检查时出现问题 | 发票保存 10 年 |
| 删除无日志 | 无合规证明 | 删除日志 |

## 特殊情况

### 匿名化数据

真正匿名化的数据（即使通过交叉比对也无法识别）不再是个人数据，可以无限期保存。

**注意**：假名化不是匿名化。

### 请求行使删除权

如果某人请求删除：
- 从活跃库中删除数据
- 如存在法定义务（发票、日志）则保留
- 告知该人保留了哪些数据及原因

### 进行中的争议

发生争议时，相关数据可以保存至程序结束，包括超过正常期限。
