## 1. 儿童数据

**来源：** EDPB 指南 1/2024，第 91-97 段；GDPR 第 6(1)(f) 条；《宪章》第 24(2) 条；《联合国儿童权利公约》第 3(1) 条

### 关键原则

- 儿童值得**特别保护**——对风险、后果、保障措施的认识较少（GDPR 序言第 38 条）
- 第 6(1)(f) 条明确提及儿童：“尤其是当数据主体为儿童时”
- **儿童的最大利益必须作为首要考虑**（《宪章》第 24(2) 条）
- 利益衡量检验必须**重新校准**——儿童的利益“非常经常地”超过控制者的利益

### 实务规则

| 情形 | 评估 |
|----------|------------|
| 利益与儿童利益一致（如儿童安全功能） | 可使用第 6(1)(f) 条 |
| 商业利益与儿童利益冲突 | 儿童利益一般应优先 |
| 针对儿童的广泛画像/定向广告 | 一般**不允许**通过第 6(1)(f) 条 |
| 面向儿童的营销/用户画像创建 | 适用特别保护（C-252/21，第 111 段） |

**注：** DSA（条例 2022/2065）另外禁止基于儿童数据画像的定向广告。

**年龄分层：** 并非所有儿童都一样。评估应根据年龄组、发展水平以及特定脆弱性而变化（第 97 段）。

### 儿童数据评估检查清单

- [ ] 第 6(1)(f) 条是否用于服务于儿童最大利益的目的？
- [ ] 如为商业目的：能否证明对儿童无负面影响？
- [ ] 是否涉及画像或定向投放？（如是：一般不允许）
- [ ] 是否考虑了年龄组和发展水平？
- [ ] 是否已实施加强的保障措施？
- [ ] DPO 是否专门审查过儿童数据评估？

## 2. 直接营销

**来源：** EDPB 指南 1/2024，第 109-120 段；GDPR 序言第 47 条；ePrivacy 指令第 5(3) 条和第 13 条

### 序言第 47 条的澄清

序言第 47 条指出，为直接营销目的进行的处理**可能**被视为出于合法利益。这**不是**自动放行：
- 并不意味着直接营销始终是合法利益（第 110 段）
- 并不意味着直接营销始终可以依赖第 6(1)(f) 条
- 仍须进行完整的三步检验

### ePrivacy 优先检查（必须首先进行）

| 渠道 | ePrivacy 要求 | 第 6(1)(f) 条可用？ |
|---------|---------------------|------------------------|
| 电子邮件、短信、彩信、即时通讯应用 | **须事先同意**（ePrivacy 指令第 13(1) 条） | **否** —— 同意是所需依据 |
| 向现有客户推销类似产品的电子营销 | **软性选择加入**例外（ePrivacy 指令第 13(2) 条） | 可能可以 —— 如满足条件 |
| 基于 Cookie/追踪的定向投放 | **须同意**（ePrivacy 指令第 5(3) 条） | 追踪**否**；下游处理也可能需要同意 |
| 邮政营销 | 不在 ePrivacy 范围内 | 可以 —— 须通过完整三步检验 |
| 电话（因成员国而异） | 检查国内实施情况 | 因法域而异 |

### 营销的利益衡量因素

| 因素 | 有利于控制者 | 有利于数据主体 |
|--------|-------------------|---------------------|
| 既有客户关系 | ✓ | |
| 类似产品/服务 | ✓ | |
| 易于退出的机制 | ✓ | |
| 非客户/潜在客户 | | ✓ |
| 为定向投放进行广泛画像 | | ✓ |
| 儿童为目标 | | ✓✓ |
| 来自第三方来源的数据 | | ✓ |
| 无先前关系 | | ✓ |

### 第 21(2) 条：绝对反对权

对直接营销处理提出反对的权利依第 21(2) 条是**绝对的**——无须利益衡量，无“强制性合法理由”抗辩。控制者必须在收到反对后停止处理。

**实务要求：** 必须明确、清晰且与其他信息分开告知数据主体这一权利（第 21(4) 条）。

## 3. 欺诈预防

**来源：** EDPB 指南 1/2024，第 100-108 段；GDPR 序言第 47 条

### 认可与界限

序言第 47 条：为欺诈预防“严格必要”的处理可构成合法利益。

**“欺诈预防”包括：**
- 预防欺诈行为的措施
- 欺诈检测（重复风险；弱点分析）
- 但：须逐案评估检测措施是否适合预防目的（第 102 段）

### 要求

1. **指明欺诈类型** —— 笼统的“打击欺诈”不足（第 106 段）
2. **严格必要性** —— 仅处理预防该特定欺诈类型严格所需的内容
3. **数据最小化** —— 结合第 5(1)(c) 条最小化数据
4. **存储限制** —— 第 5(1)(e) 条适用于欺诈相关数据的保留
5. **准确性** —— 用于评估欺诈风险的数据必须准确且可证明相关（第 105 段）
6. **比例性** —— 欺诈必须具有“实质性重要性”；琐碎欺诈不太可能超过数据主体的利益（第 105 段）

### 法律依据选择

如欺诈检测/预防是**法律强制要求** → 第 6(1)(c) 条更合适，而非第 6(1)(f) 条（第 107 段）。

在其他处理过程中附带发现欺诈 → 适用第 6(4) 条的进一步处理规则（第 108 段）。

## 4. IT/网络安全

**来源：** 援引 GDPR 序言第 49 条的 EDPB 指南 1/2024

### 序言第 49 条的认可

“为确保网络和信息安全所严格必要且相称范围内”的处理可构成合法利益。包括：
- 防止对网络的未经授权访问
- 防止恶意代码传播
- 阻止拒绝服务攻击
- 防止对计算机和电子通信系统的损害

### 要求

- **严格必要** —— 仅为特定安全目的所需
- **相称** —— 安全处理必须与威胁相称
- **最小化** —— 仅记录所需内容；考虑保留期限
- **非一揽子授权** —— 每项安全措施都需要自己的评估

### 典型处理活动

| 活动 | 可能合法 | 条件 |
|----------|------------------|------------|
| 防火墙日志 | 是 | 最小化数据，适当保留 |
| 入侵检测 | 是 | 与威胁等级相称 |
| 漏洞扫描 | 是 | 仅限自有系统 |
| 员工设备监控 | 可能 | 权力不平衡考量；比例性 |
| 全内容检查 | 有风险 | 必须证明元数据为何不足 |

## 5. 雇佣情境

**来源：** EDPB 指南 1/2024，第 43、47 段；WP29 意见 06/2014

### 特别考量

**雇主-雇员权力不平衡**从根本上影响 LIA：
- 与提供服务者-客户关系的评估不同（第 43 段）
- 控制者不应假定所有雇员共享相同利益（第 47 段）
- “在雇主-雇员关系情境下尤其如此”（第 47 段）

### 德国特定：劳资协议会权利

**《企业宪法法》（BetrVG）第 87(1) 条第 6 项：** 可监控雇员行为或绩效的技术设施须经劳资协议会共同决定。

**BetrVG 第 87(1) 条第 1 项：** 工作场所秩序和行为事项的共同决定。

**《联邦数据保护法》（BDSG）第 26 条（雇员数据保护）：** 雇员数据处理条款——核查除 GDPR 外是否还适用特定的德国规则。

### 评估因素

| 因素 | 对利益衡量的影响 |
|--------|-------------------|
| 监控强度 | 强度越高 = 对雇员的影响越重 |
| 雇员知情度 | 秘密监控显著改变利益平衡 |
| 目的特定性 | 一般监视 vs. 有针对性的调查 |
| 范围限制 | 所有雇员 vs. 特定关切 |
| 替代措施 | 能否在不处理雇员数据的情况下实现同样结果？ |
| 比例性 | 轻微工作场所问题 ≠ 正当化广泛监控 |

## 6. 集团内部数据共享

**来源：** 援引 GDPR 序言第 48 条的 EDPB 指南 1/2024，第 33 段

### 序言第 48 条的认可

“属于企业集团或隶属于中央机构的机构集团的控制者，可能对在集团内部为内部行政目的传输个人数据（包括处理客户或雇员的个人数据）具有合法利益。”

### 关键限制

- **无集团整体豁免** —— 每个处理数据的集团实体都必须进行自己的 LIA
- **仍须按实体进行完整三步检验**
- 合理预期很重要：单一品牌集团与松散关联的企业集团不同
- 数据主体更可能预期在单一品牌实体内部共享，而非在同一公司伞下看似无关的公司之间共享

### 实务方法

1. 绘制集团实体之间的数据流
2. 对每个数据流：识别每个实体的合法利益
3. 按实体评估必要性
4. 考虑数据主体对集团结构的预期
5. 按实体文件化，而非仅在集团层面

## 7. 第三国当局请求

**来源：** EDPB 指南 1/2024，第 135-136 段

### EDPB 立场

为避免因不遵守而受到制裁，控制者遵从第三国执法当局请求的利益，**通常会**被数据主体的利益或基本权利和自由所超过（第 136 段）。

### 实务影响

- 不能默认依赖第 6(1)(f) 条向第三国当局披露数据
- 必须另行考虑第五章传输保障措施
- 检查是否存在司法互助条约（MLAT）或其他国际协定提供适当的法律框架
- 考虑 GDPR 第 48 条（未经国际协定授权的传输）

## 8. AI/ML 处理

**主要来源：**
- **EDPB 意见 28/2024**，关于 AI 模型与个人数据处理（2024 年 12 月 17 日）——权威的欧盟层面指引
- **CNIL 关于 AI 开发合法利益的建议**（2025 年 6 月 19 日）——操作性最强的国内指引
- **CNIL 关于网络抓取措施的专题说明**（2025 年 6 月 19 日）
- **汉堡数据保护机构关于 LLM 的讨论文件**（2024 年 7 月 15 日）——有争议，部分被意见 28/2024 取代
- **DSK 联合指引《AI 与数据保护》**（2024 年 5 月 6 日）

关于这些来源的完整详细分析（包括 AI 特定缓解措施目录和合理预期标准），阅读 [additional-regulatory-sources.md] 第 1-2 节。

### 关键原则

**AI 模型的开发和部署均可用合法利益。** EDPB 在意见 28/2024 中明确确认了这一点。CNIL 认为，鉴于大规模同意不切实际，合法利益是 AI 开发者最可能的法律依据。

**公认的 AI 合法利益（EDPB 意见 28/2024，第 69 段）：**
- 开发协助用户的对话代理
- 开发检测欺诈内容或行为的 AI
- 改进信息系统中的威胁检测

**三步检验以充分的严格性适用** —— AI 处理不会获得更宽松的标准。

### AI 特定的必要性考量

EDPB 设定了高标准（意见 28/2024，第 73 段）：如果目的可以通过完全不涉及个人数据的 AI 模型实现，则处理个人数据就不必要。控制者必须对照侵入性更小的替代方案（合成数据、匿名化、更小的数据集）评估个人数据量。假名化等技术保障有助于满足必要性检验。

### AI 特定的合理预期标准

EDPB 提供七个评估 AI 情境下合理预期的因素（意见 28/2024，第 93 段）：
1. 个人数据是否公开可用
2. 数据主体与控制者之间关系的性质
3. 服务的性质
4. 个人数据收集的情境
5. 数据收集的来源（以及所提供的隐私设置）
6. 模型的潜在进一步用途
7. 数据主体是否实际知道其数据在线

仅在隐私政策中纳入 AI 训练**并不**产生合理预期（第 92 段）。

### AI 的缓解措施

EDPB 和 CNIL 提供了广泛的缓解措施目录，涵盖技术措施（假名化、数据掩蔽、差分隐私）、权利便利（收集前选择退出、扩展删除、内容吐露（regurgitation）索赔机制）、透明度措施（模型卡、媒体活动、网站清单）以及网络抓取特定措施（尊重 robots.txt/ai.txt、排除敏感来源、限于自由可访问的数据）。完整目录见 [additional-regulatory-sources.md] 第 1 节。

### 非法开发 → 部署影响

如 AI 模型使用非法处理的个人数据开发，EDPB 认为存在三种后果不同的情形。合法性评估取决于部署的是同一/不同控制者、模型是否已匿名化，以及部署控制者是否进行了适当的尽职调查。详情见 [additional-regulatory-sources.md] 第 1 节。

### 国内数据保护机构的分歧

荷兰数据保护局（Autoriteit Persoonsgegevens）主张，为 AI 训练进行网络抓取需要同意——这是最严格的立场。CNIL 明确采取更务实的做法，确认合法利益可用。控制者应监测这一分歧，并适用数据主体所在地法域的标准。
