# 结构与导航——参考

在审计达到第 5 步时加载。评估文件如何在章节、标题和交叉引用层面组织信息——与文件内部所用的语言无关。

## 本支柱涵盖的内容

一份文件即使在句子层面有完美的平实语言散文，仍可能因正确信息放错位置，或读者无法导航到其所需内容而辜负读者。本支柱评估：

1. 标题层级与连贯性。
2. 章节长度分布。
3. 目录与可查找性。
4. 定义术语管理。
5. 交叉引用密度与链条深度。
6. 分层起草与路标提示。
7. 信息分组（相关义务聚在一起与散落各处）。

## 检查点

### 1. 标题层级

关注：

- **所用标题层级数。** 大多数起草良好的长文件使用 2-4 个层级（如部/章/节/款）。5 层以上通常难以管理。1 层（50 个条款的平铺列表，无分组）也是问题。
- **标题措辞。** 标题应**描述性**（“付款时间表与滞纳金”），而非**抽象**（“一般规定”）。统计抽象标题（“General”“Miscellaneous”“Other matters”“Sundry”“Diverses dispositions”“Sonstiges”“Allgemeine Bestimmungen”——每种适度出现均可；文件四分之一内容置于“Miscellaneous”之下是警示信号）。
- **编号一致性。** 混合编号（1、1.1、1.1.1 与 A、B、C 无规则交错）是导航失败。
- **跳级。** 第 3 节 → 第 3.1 节 → 3.1.1.1（跳过 3.1.1）令人迷失。

严重程度：

- 所有标题描述性、层级 2-4 层、编号一致 → 绿。
- 大体描述性，有 1-2 个长度合理的抽象总括 → 黄。
- 相当比例内容置于抽象总括标题下，或编号不一致 → 琥珀。
- 无可用的层级，“Miscellaneous”部分包含实质性义务，或标题措辞歪曲内容 → 红。

### 2. 章节长度分布

对每个顶层章节计算：

- 字数。
- 子章节数量。

识别异常值——比全文档均值长 3 个标准差以上的章节。一份 12,000 字的文件中有一个 4,000 字的章节，即使每句话都写得很好，也是导航失败。

将分布报告为简短表格：

| 章节 | 字数 | 子章节 | 备注 |
| --- | --- | --- | --- |
| 1. 定义 | 1,400 | 0 | 高——定义通常应使用词汇表块 |
| 2. 期限与终止 | 600 | 4 | 可 |
| 12. 其他事项 | 3,200 | 8 | 异常——实质性义务被埋藏 |

### 3. 目录

对超过约 3,000 字或有 10 个以上章节的文件：

- 是否有目录？如无，标记缺陷。
- 是否准确？（目录条目与实际章节标题或编号不符时。）
- 是否有页码/超链接（格式允许时）？
- 是否至少展示两个层级？

对较短文件，缺少目录本身不构成缺陷。

### 4. 定义术语

定义术语强大，但在规模化时会失效。评估：

- **总数。** 含 80 个以上定义术语的文件令读者的工作记忆负担过重。
- **定义位置。** 行内定义（首次使用时定义）与开头的合并词汇表。现代法律设计实践对约 5,000 字以上的文件偏好词汇表方法。
- **“包括但不限于”式定义。** 包含开放式类别的定义（“Affiliate 指……以及任何其他实体……”）在每次使用时将解释负担转移给读者。注意此类定义。
- **仅使用一次的定义。** 仅使用一次的定义术语是浪费的机制。计数并报告。
- **定义术语大写纪律。** 如文件对定义术语使用首字母大写（“the Party”“the Services”），则每次小写使用“party”/“services”要么是未定义的普通名词使用（可以），要么是起草不一致（问题）。标记不一致——它们会实质性地使读者困惑。

### 5. 交叉引用——链条深度

除交叉引用密度（在语言模式支柱中涵盖）外：

- **链条深度。** 对第 7.2 条的交叉引用，其本身又包含对附表 B 的交叉引用，而附表 B 又交叉引用主协议，这是 3 层链条。任何超过 2 层的链条为琥珀。超过 3 层为红。
- **未解决的引用。** “如附件 C 所定义”而附件 C 未提供，无论语境如何均为红。
- **前向引用。** 第 5 条中出现“如第 23 条规定”——迫使读者要么跳转，要么凭信任继续读。统计出现次数。

### 6. 分层起草与路标提示

法律设计实践偏好**分层**：长条款顶部一段摘要，细节在下方；或消费者条款与条件开头的“关键术语”框。评估：

- 是否存在执行摘要或“本合同平实英语版”部分。
- 最长的条款是否有条款级摘要。
- 路标语言（“本节说明……”“简言之：”“Diese Klausel regelt…”“L'objet de la présente clause est…”）。

具有有效分层的文件在本支柱中获得明确的绿注，即使其他指标参差不齐。

### 7. 信息分组

通读文件，寻找散落的关联义务：

- 付款义务分散在“价格”“付款”“滞纳金”和“终止”中而无交叉引用。
- 数据保护义务部分在隐私通知中、部分在合同正文中。
- 责任限制出现在三个独立条款中，上限重叠或冲突。

标记散落成族的义务。这对报告第 10 节的优先关注清单具有影响力。

## 结构与导航支柱评分

将七个检查点以等权重合并为 0-100 的支柱分数：

1. 标题层级。
2. 章节长度分布。
3. 目录（或因长度而合理地缺失）。
4. 定义术语管理。
5. 交叉引用链条。
6. 分层起草/路标提示。
7. 信息分组。

每个检查点映射到一个分值：

- 绿 → 90。
- 黄 → 70。
- 琥珀 → 45。
- 红 → 20。
- 灰/不适用 → 从平均值中排除。

支柱分数 = 适用分值的平均值，四舍五入。
