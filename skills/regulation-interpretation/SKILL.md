# 法规解读 HTML

本 skill 用于把中文法律法规、部门规章、行业标准或政策文件解读成一份可离线打开的自包含 HTML 页面。每次处理新文件都必须重新确认输入、受众和解读重点。

## 步骤 1 — 确认输入

先确认法规/标准文件路径，路径必须在当前工作区内，格式为 `.docx` 或 `.pdf`。

可选项：

- 解读重点：适用范围、核心义务、处罚责任、与旧版差异或用户指定主题。
- 受众：内部参考或客户简报。缺失时默认内部参考，并说明用户可改为客户简报。

## 步骤 2 — 读原文

- `.docx` 使用 `read_docx`。
- `.pdf` 使用 `read_pdf`。
- 如果 `read_pdf`/`read_docx` 返回的内容以 `⟦SCANNED_PDF⟧` 开头，说明是扫描件或图片型文件、无法读取正文。告知用户可选择使用 `ocr_document` 做视觉识别，且会把页面图片发送到所配置的视觉识别服务、涉及数据出境，必须由用户同意确认门后才能调用；用户拒绝或要求文字版时停下。
- `ocr_document` 返回的 `⟦视觉识别·非逐字引用级⟧` 正文只能按识别级材料使用。后续解读和 HTML 中必须提示金额/日期/当事人/否定词/条号等关键信息需人工核对原文，并声明“基于视觉识别，需核对原文”。

## 步骤 3 — 结构化提炼

Read `assets/interpretation-method.md` 获取方法论。提炼时仅从原文抽取，不自行补写事实。结构至少覆盖：

- 文件名称、发文机关、文号、生效日期。
- 适用范围、监管对象、核心义务、禁止性规定。
- 法律责任与处罚、重点条款。
- 如用户提供旧版或对比文件，再提炼变化点；未提供时不要虚构差异。

## 步骤 4 — 法律视角解读

Read `assets/audience-rules.md` 获取受众口径。

反幻觉硬约束：

- 每条结论、义务、处罚、期限、金额或合规建议都必须锚定原文条款号或原文摘录。
- 不得臆造原文没有的条款、数字、罚则。
- 拿不准或原文没有写清时，明确标注“原文未明确”。
- 不要用常识或其他法规替代本文件原文；如需引用外部法规，先说明本文件未明确，并把外部依据标成补充判断。

## 步骤 5 — 生成 HTML 可视化

Read `assets/html-style.md` 获取 HTML 风格。产出一份完整 HTML 文档，并通过 `write_html({ outPath, html })` 写成工作区内 `.html` 文件。

HTML 硬约束：

- 必须完全自包含、零外部网络资源。
- CSS 必须内联 CSS；不得使用 `<link rel="stylesheet">` 引外部样式。
- 图表如需使用，必须用内联 SVG；不引任何外部 CDN、图片、字体、脚本或图表库。
- 离线直接双击打开应正常展示，不向外部域名发请求、不外泄文件内容。

建议结构：

- 概览卡：名称、机关、文号、生效日、适用范围。
- 适用范围与对象：说明适用事项、主体、除外情形或“原文未明确”。
- 核心义务(义务矩阵表)：必须用原生表格呈现义务主体、触发条件、履行期限、条款依据和责任后果。
- 法律责任/处罚。
- 合规 checklist：必须使用静态方框 `☐`，不得用表单 checkbox。
- 关键日期时间线：必须用 CSS 或内联 SVG 呈现生效节点、过渡期、整改期限；原文未明确时如实标注。
- 重点条款：摘录关键原文并做法律视角说明；仅在用户提供旧版/对比文件时输出条款对比，不虚构差异。
- 来源与免责：标注解读基于的文件名，声明仅供参考。

受众为客户简报时，可以简化论证深度与术语密度，但上述结构、三类必含可视化组件与自包含要求不变。

写盘前先概述即将生成的文件路径。`write_html` 是敏感写盘工具，会触发确认门；审计只记录 `outPath` 等元数据，不记录 HTML 正文。

## 步骤 6 — 常驻规则

- 每次解读新文件都重走步骤 1。
- 遇到以 `⟦SCANNED_PDF⟧` 开头的扫描件或图片型文件提示，先说明可选 `ocr_document` 视觉识别及数据出境确认；未获同意不得 OCR，获同意后的识别正文按非逐字引用级处理。
- HTML 必须完全自包含、零外部网络资源。
- 所有结论必须锚定原文条款/摘录；不得臆造原文没有的条款、数字、罚则；拿不准标“原文未明确”。
- 方法论、风格和受众口径都从 `assets/` 读取；不要把真实业务标准写进本文件。
- 写入 HTML 前必须等待确认门结果。
