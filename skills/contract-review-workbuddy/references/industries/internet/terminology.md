# 互联网/软件行业术语表

## 一、软件开发与交付相关术语

### 1.1 开发模式与流程
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **软件开发生命周期** | SDLC (Software Development Life Cycle) | 软件从需求分析到退役的全过程 | 用于界定开发方各阶段交付物和责任边界 |
| **敏捷开发** | Agile Development | 迭代式、增量式的软件开发方法 | 影响验收标准和需求变更条款的设计 |
| **需求规格说明书** | SRS (Software Requirements Specification) | 详细描述软件功能和性能需求的文档 | 作为验收标准的基准附件 |
| **用户验收测试** | UAT (User Acceptance Testing) | 最终用户验证系统满足业务需求的测试 | 约定UAT流程和通过标准，避免验收扯皮 |
| **Beta版本** | Beta Version | 面向部分用户开放的测试版本 | 区分Beta版与正式版的质量保证差异 |
| **灰度发布** | Canary Release | 逐步向用户推送新版本的方式 | 约定发布失败时的回滚责任和用户通知义务 |
| **持续集成/持续部署** | CI/CD (Continuous Integration/Continuous Deployment) | 自动化构建、测试和部署流程 | 影响交付频率和验收方式 |

### 1.2 源代码与知识产权
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **源代码托管** | Source Code Escrow | 将源代码交由第三方机构保管 | 约定触发释放条件（破产、违约），保障委托方权益 |
| **开源组件清单** | SBOM (Software Bill of Materials) | 软件中使用的所有开源组件及其许可清单 | 用于开源合规审查和GPL传染性风险评估 |
| **软件成分分析** | SCA (Software Composition Analysis) | 识别和分析软件中使用的开源组件 | 确保开源许可合规，避免被迫开源自有代码 |
| **GPL传染性** | GPL Contamination | GPL许可要求衍生作品也必须以GPL开源 | 禁止开发方使用GPL组件，避免委托方自有代码被迫开源 |
| **Apache 2.0许可** | Apache License 2.0 | 允许商用、修改和分发的宽松开源许可 | 可安全使用的开源许可，需保留版权声明 |
| **MIT许可** | MIT License | 极为宽松的开源许可，仅需保留版权声明 | 可安全使用的开源许可，商用友好 |
| **AGPL许可** | AGPL (Affero GPL) | 比GPL更强的传染性许可，网络使用也触发开源义务 | 严格禁止在SaaS服务中使用AGPL组件 |
| **软件著作权登记** | Software Copyright Registration | 向中国版权保护中心申请软件著作权登记 | 作为维权时的权属证据，建议开发完成后及时办理 |
| **职务作品** | Work Made for Hire | 员工为完成工作任务所创作的作品 | 约定职务作品著作权归公司，避免离职后权属纠纷 |

### 1.3 验收与质量
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **缺陷等级** | Defect Severity Level | 软件缺陷的严重程度分类（致命/严重/一般/轻微） | 约定不同等级缺陷的修复时限和验收标准 |
| **平均故障间隔时间** | MTBF (Mean Time Between Failures) | 系统两次故障之间的平均时间 | 作为系统稳定性的量化指标 |
| **平均修复时间** | MTTR (Mean Time to Repair) | 故障发生到修复完成的平均时间 | 作为运维响应能力的量化指标 |
| **功能点** | Function Point | 软件功能规模的度量单位 | 用于需求变更时工作量和费用的估算 |

## 二、SaaS/云服务相关术语

### 2.1 服务模式与架构
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **软件即服务** | SaaS (Software as a Service) | 通过互联网交付软件服务的模式 | 约定服务可用性、数据所有权和退出机制 |
| **平台即服务** | PaaS (Platform as a Service) | 提供应用开发和部署平台的云服务 | 明确平台责任边界和数据安全义务 |
| **基础设施即服务** | IaaS (Infrastructure as a Service) | 提供计算、存储、网络等基础设施的云服务 | 约定基础设施安全和数据本地化要求 |
| **多租户架构** | Multi-tenancy Architecture | 多个用户共享同一套系统实例的架构 | 必须约定数据隔离措施和安全审计要求 |
| **API限流** | API Rate Limiting | 限制API调用频率的机制 | 约定限流阈值和超限处理方式 |
| **服务降级** | Service Degradation | 在系统负载高时降低非核心功能服务质量 | 约定降级条件、通知义务和费用减免 |

### 2.2 服务级别协议
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **服务级别协议** | SLA (Service Level Agreement) | 定义服务质量和测量标准的协议 | 约定可用性指标、计算方式和违约赔偿 |
| **可用性** | Availability | 系统可正常提供服务的时间占比 | 通常承诺99.9%（月度停机不超过43.2分钟） |
| **恢复点目标** | RPO (Recovery Point Objective) | 数据恢复时可容忍的最大数据丢失量 | 约定RPO不超过1小时，影响备份策略 |
| **恢复时间目标** | RTO (Recovery Time Objective) | 故障发生后系统恢复所需的最大时间 | 约定RTO不超过4小时，影响灾备方案 |
| **月度活跃用户** | MAU (Monthly Active Users) | 每月至少使用一次服务的用户数 | 用于按用量计费模式的计费依据 |
| **日活跃用户** | DAU (Daily Active Users) | 每日至少使用一次服务的用户数 | 用于衡量服务规模和计费依据 |

### 2.3 计费与续约
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **Token计费** | Token-based Pricing | 按AI模型处理的Token数量计费 | 约定Token单价、计量方式和账单透明度 |
| **阶梯定价** | Tiered Pricing | 按使用量分段设置不同单价 | 约定各阶梯的用量范围和单价 |
| **自动续约** | Auto-renewal | 合同到期后自动延续的条款 | 约定提前通知期和终止便捷性，避免被动续费 |

## 三、数据合规相关术语

### 3.1 数据处理基础
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **个人信息** | Personal Information | 以电子或其他方式记录的与已识别或可识别的自然人有关的各种信息 | 确定告知同意和保护义务的适用范围 |
| **敏感个人信息** | Sensitive Personal Information | 一旦泄露或非法使用容易导致人格尊严受损或人身财产安全受危害的信息 | 需取得单独同意，加强保护措施 |
| **去标识化** | De-identification | 使个人信息在不借助额外信息的情况下无法识别特定自然人 | 去标识化信息仍属个人信息，需继续保护 |
| **匿名化** | Anonymization | 使个人信息无法识别特定自然人且不能复原 | 匿名化信息不再属于个人信息，可自由使用 |
| **数据控制者** | Data Controller | 决定数据处理目的和方式的组织 | 承担数据保护总体责任 |
| **数据处理者** | Data Processor | 代表数据控制者处理数据的组织 | 按控制者指令处理数据，配合安全事件响应 |

### 3.2 数据合规机制
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **委托处理协议** | DPA (Data Processing Agreement) | 规范委托处理个人信息双方权利义务的协议 | 必须签订DPA，明确处理目的、期限、方式 |
| **个人信息保护影响评估** | PIA/PIPIA (Personal Information Protection Impact Assessment) | 处理活动前对个人信息保护影响的评估 | 处理敏感信息、数据出境等场景需事前评估 |
| **数据出境标准合同** | Standard Contract for Cross-border Data Transfer | 个人信息出境时与境外接收方签订的合同 | 未达到安全评估门槛时采用标准合同备案 |
| **数据出境安全评估** | Security Assessment for Cross-border Data Transfer | 数据出境时向网信部门申报的安全评估 | CIIO和处理100万人以上个人信息必须申报 |
| **隐私政策** | Privacy Policy | 告知用户个人信息收集使用规则的文件 | 需单独弹窗提示，采用opt-in方式获取同意 |
| **最小必要原则** | Data Minimization Principle | 仅收集实现目的所必需的最少个人信息 | 不得过度收集，不得因拒绝非必要信息而拒绝服务 |

### 3.3 特殊数据类型
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **生物识别信息** | Biometric Information | 人脸、指纹、虹膜、声纹等个人生物特征 | 不得作为唯一验证方式，需提供替代方案 |
| **未成年人信息** | Children's Personal Information | 不满14周岁未成年人的个人信息 | 需监护人明示同意，建立专门保护机制 |
| **重要数据** | Important Data | 一旦遭到篡改、破坏、泄露或非法获取、非法利用，可能危害国家安全、经济运行、社会稳定的数据 | CIIO须境内存储，出境需安全评估 |
| **关键信息基础设施** | CII (Critical Information Infrastructure) | 重要网络设施、信息系统等 | CIIO须履行更严格的网络安全和数据保护义务 |

## 四、平台运营相关术语

### 4.1 平台类型与资质
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **网络内容平台** | UGC Platform (User Generated Content) | 用户生成和发布内容的平台 | 需建立内容审核机制，配备审核人员 |
| **ICP许可证** | ICP License (Internet Content Provider) | 经营性网站需取得的增值电信业务许可 | 未取得ICP许可不得开展经营性互联网信息服务 |
| **EDI许可证** | EDI License (Electronic Data Interchange) | 在线数据处理与交易处理业务许可 | 电商平台、在线交易需办理EDI许可 |
| **CDN** | CDN (Content Delivery Network) | 内容分发网络，加速内容传输 | 约定CDN服务质量和数据安全责任 |

### 4.2 平台责任
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **避风港原则** | Safe Harbor Principle | 平台在及时删除侵权内容后可免责 | 建立通知-删除机制，及时响应侵权投诉 |
| **通知-删除** | Notice and Takedown | 平台收到侵权通知后删除侵权内容的机制 | 约定通知格式、处理时限和反通知程序 |
| **红旗原则** | Red Flag Principle | 侵权事实明显如红旗飘扬时，平台不得视而不见 | 对明显侵权内容需主动采取必要措施 |
| **网络安全等级保护** | MLPS (Multi-Level Protection Scheme) | 网络安全等级保护制度 | 三级系统每年测评，二级系统每两年测评 |
| **等保三级** | MLPS Level 3 | 网络安全等级保护第三级 | 重要信息系统须达到等保三级要求 |

### 4.3 用户与内容管理
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **用户生成内容** | UGC (User Generated Content) | 用户创作和发布的内容 | 约定内容审核责任和侵权处理机制 |
| **格式条款** | Standard Terms | 当事人为了重复使用而预先拟定并在订立合同时未与协商的条款 | 免责条款需显著提示，否则可能无效 |
| **大数据杀熟** | Algorithmic Price Discrimination | 利用算法对老用户展示更高价格 | 禁止基于用户画像的差异化定价 |
| **竞价排名** | Paid Search / Sponsored Search | 付费搜索结果展示 | 须显著标明广告字样，与自然搜索结果区分 |

## 五、AI与知识产权相关术语

### 5.1 AI技术与服务
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **生成式AI** | Generative AI | 能够生成文本、图像、音视频等内容的AI | 提供生成式AI服务需完成备案和安全评估 |
| **大模型微调** | LLM Fine-tuning | 在预训练大模型基础上进行特定领域训练 | 约定微调后模型的知识产权归属和数据安全 |
| **检索增强生成** | RAG (Retrieval-Augmented Generation) | 结合检索和生成的AI技术 | 约定知识库内容的合法来源和更新责任 |
| **深度合成** | Deep Synthesis / Deepfake | 利用AI生成虚拟音视频、图像 | 深度合成内容须添加显著标识 |
| **联邦学习** | Federated Learning | 分布式机器学习技术，数据不出本地 | 可作为数据合规的技术解决方案 |

### 5.2 AI合规要求
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **算法备案** | Algorithm Filing | 向网信部门备案算法推荐服务 | 算法推荐服务上线前须完成备案 |
| **算法透明度** | Algorithm Transparency | 向用户说明算法推荐服务的情况和基本原理 | 提供不针对个人特征的选项或拒绝方式 |
| **生成式AI服务备案** | Generative AI Service Filing | 提供生成式AI服务向网信部门备案 | 备案后方可对外提供服务，公示备案信息 |
| **训练数据合规** | Training Data Compliance | 确保AI训练数据来源合法、处理合规 | 约定训练数据须为合法取得，保留来源记录 |

### 5.3 知识产权
| 术语 | 英文/缩写 | 释义 | 在合同中的意义 |
|------|-----------|------|----------------|
| **软件著作权** | Software Copyright | 软件作品享有的著作权 | 开发完成后及时办理软著登记 |
| **竞业限制** | Non-compete Clause | 限制员工离职后从事竞争业务的条款 | 期限不超过2年，需支付竞业补偿金 |
| **SDK** | SDK (Software Development Kit) | 软件开发工具包 | 约定SDK的数据采集范围和合规责任 |
| **埋点** | Event Tracking | 在软件中植入代码收集用户行为数据 | 须告知用户并取得同意，遵循最小必要原则 |
| **Cookie** | Cookie | 网站存储在用户浏览器中的小型数据文件 | 使用Cookie须告知用户并取得同意 |
| **设备指纹** | Device Fingerprinting | 通过设备特征识别用户设备的技术 | 可能构成个人信息收集，需告知同意 |
