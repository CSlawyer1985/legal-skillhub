# 系统架构与诉讼路线

1. 决策引擎

5. 输出状态

## 1. 决策引擎

```text
案件材料
  -> 主体与请求识别
  -> 实体关系和案由候选
  -> 仲裁／前置程序／管辖检查
  -> 当前诉讼阶段与期限
  -> 必要文书集合
  -> 缺失信息分级
  -> 现行法和案例核验
  -> 智能模板生成
  -> 自动校验
  -> 律师意见与风险
```

每一步保存依据和不确定性。前一步存在阻断级问题时，不得把后一步包装成确定结论。

## 2. 诉讼知识图谱

```text
争议发生
  -> 谈判／调解／催告
  -> 仲裁或诉讼路径选择
  -> 诉前证据保全／财产保全／行为保全
  -> 立案与管辖
  -> 送达与答辩
  -> 举证／鉴定／调查取证
  -> 庭前会议／开庭／调解
  -> 一审裁判
  -> 上诉／二审调解或裁判
  -> 再审申请／检察监督
  -> 执行申请
  -> 执行异议／复议
  -> 执行异议之诉
  -> 恢复执行／执行监督／终本管理
```

替代或特别路径：确定到期金钱债权可评估支付令；可背书转让证券丧失可评估公示催告；外国裁判或外国仲裁裁决进入条约／互惠或纽约公约的承认执行路径。

并行节点：诉讼费用、司法救助、回避、追加当事人、送达异议、期限申请、和解、撤诉、财产线索和执行担保。

## 3. 文书选择规则

### 必要文书

没有该文书就无法启动、应诉、保留权利或完成当前程序。例如起诉状、上诉状、管辖权异议、证据保全申请、执行申请。

### 可选文书

只有在法定事实成立并有策略收益时使用。例如回避申请、鉴定申请、调查取证申请、行为保全、追加当事人申请。

### 对方可能文书

预测最可能改变程序或实体结果的对方动作，并准备答复框架。不得罗列全部理论可能。

### 法院可能审查事项

只用于预测承办法官会审查哪些程序要件、证据和风险，不生成或储存法院专用文书模板。

### 历史示范文本

命中`validation_status=superseded`的教材附录节点时，仅用于说明旧版来源和变化，不得生成当前文书。系统必须跳转至其现行替代来源；本库44个法〔2024〕46号附录节点统一跳转法〔2025〕82号。

### 要素式诉辩路由

```text
起诉／答辩任务
  -> 是否命中法〔2025〕82号67类
  -> 命中11类专项节点时加载ELM节点
  -> 识别原告／被告并逐项选择claim_id
  -> 询问普通诉状或官方要素式逐栏填充稿
  -> 要件—阻断事实—证据组—抗辩—法院审查矩阵
  -> 互斥诉请、答辩立场与计算校验
  -> 生成正文或逐栏内容
  -> 自愿选择、旧表禁用和地方要求校验
```

普通诉状与要素式文本不是法律论证强弱的区别。无论外部呈现形式如何，内部都要完成同一套要件、事实、证据和风险审查。

专项矩阵覆盖11类纠纷、63个诉请级模块。原告端只加载选定诉请的必要要件和举证任务；被告端除读取相同矩阵外，还必须逐项记录`admit`、`deny`、`partial`或`unknown`及理由。系统不得因识别到一个案由而自动拼接该案由下的所有请求。

## 4. 信息采集规则

### 阻断生成

- 当事人主体身份或诉讼地位不明。
- 请求内容、金额、标的物或履行方式不明。
- 法院、仲裁、前置程序或当前阶段无法判断。
- 关键期限起算日、送达日或裁判生效日不明。
- 用户要求写入但无材料支持的核心事实。

### 影响策略

- 对方财产线索、担保情况、管辖连接点、合同版本、履行顺序、证据原件状态。
- 是否存在关联案件、重复起诉、既判力、诉讼时效中断或仲裁协议。

### 仅影响格式

- 联系电话、邮编、代理人执业信息、附件精确页码、落款日期。

## 5. 输出状态

- `分析意见`：可包含多个待核实方案，不得直接提交。
- `待补正草稿`：结构完整但存在阻断项，以变量标注。
- `可提交候选`：事实、主体、请求、期限和法条已核对；仍需当事人／律师最终签字确认。

要素式专项审计使用更细的机器状态：

- `blocked`：存在阻断事实缺失、被告未表态或互斥诉请。
- `needs_evidence`：关键事实已回答，但一个或多个证据组未配置。
- `structure_ready`：请求级结构完整，允许进入起草；只有完成现行法、金额、格式、附件和签字前审查后，才可能升级为“可提交候选”。
