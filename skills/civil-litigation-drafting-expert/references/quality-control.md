# 质量控制门禁

## 1. Consistency Check

- 当事人名称、诉讼地位、地址、金额、日期和案号在正文、证据目录、附件和其他文书中一致。
- 每项事实只使用一种已定义状态：已证明、拟证明、对方主张、争议中、待核实。
- 诉讼请求、事实理由、证据和法律依据形成一一或多对一映射。

## 2. Completeness Check

- 文书要素、签章、日期、法院、附件、副本和授权材料齐全。
- 已列出程序期限、前置程序、管辖依据、送达状态和费用请求。
- 教材章节导入具有 10 项章节输出和每文书必备字段。

## 3. Legal Validation

- 法律适用时点与案件事实、程序行为发生时间匹配。
- 引用官方现行文本；废止规则标记 `superseded` 并给出替代规则。
- 区分法律、司法解释、规范性文件、指导性案例、入库案例和普通案例。
- 教材 OCR 条号未核验时，不进入可提交版。

## 4. Logic Validation

- 先确定请求权基础，再分解要件、抗辩、证明责任和事实。
- 管辖、期限、主体和程序选择有清楚前提。
- 结论能由已证明事实和有效规则推出；不得用经验判断填补关键证据。

## 5. Citation Validation

- 每条法条包含名称、条号、引用目的、适用条件、效力状态、官方来源和核验日期。
- 引文与原文含义一致；不拼接条文、不省略改变结论的例外。
- 类案包含来源类型、案例编号、裁判日期、关联争点和可比／不可比事实。

## 6. Court Practice Validation

- 请求明确、具体、可判、可执行。
- 程序文书在法定期限内向有权机关提出，申请事项可操作。
- 格式、层级、称谓、数字、标点、落款和附件符合当前法院习惯；地方特殊要求单独核实。
- 成品仅限当事人文书，不含法院印章、法院落款、审判人员署名或内部审理意见。
- 法〔2025〕82号示范文本按“积极引导、自愿选择”使用，不得泛化为全国统一强制立案条件。
- 选择官方要素式文本时不删除、改名或隐藏官方要素；案件特有事实通过自由填写区或附页充分陈述。
- 选择普通诉状时仍以请求—要件—事实—证据—抗辩矩阵完成内部审查。
- 对地方或在线平台的特殊要素式填报要求，必须在正式提交前另行核验。

## 7. 阻断级错误

出现下列任一项，不得标记“可提交候选”：主体错误、法院明显错误、诉讼请求不可识别、法定期限可能届满且未核实、核心事实无来源、法律已废止或未核验、金额无法复算、附件指向不存在、混入法院印章或法院制作要素、把2024年试行表格作为现行文本、把自愿使用表述为全国统一强制、要素式诉状删除关键不利字段。

## 8. 自动校验命令

```bash
python3 scripts/validate_skill_data.py references/party-document-catalog.json
python3 scripts/validate_element_pleading_knowledge.py references/element-pleading-knowledge.json
python3 scripts/validate_element_claim_matrix.py references/element-pleading-claim-matrix.json
python3 scripts/regression_test_element_pleading.py
```

自动校验通过只说明数据结构完整，不代替律师对事实、法律和法院实践的最终复核。

当前还必须通过范围校验：所有目录节点均为`party_filing`；第2分卷来源页不得早于文件页196，第3、4分卷按连续边界核验；任何被明确排除的法院制作文书不得重新进入数据库。法〔2024〕46号附录节点必须全部为`superseded`，当前生成只能调用法〔2025〕82号。

要素式专项还必须通过：11个纠纷节点、22个诉辩变体、44个历史映射无缺失无重复；“银行信用卡纠纷”只能作为教材历史名称，现行生成名称为“信用卡纠纷”；每个节点必须包含请求、要件、事实、证据、法院审查、计算、风险和自动校验字段。

逐诉请强化层还必须通过：63个诉请模块、至少190个阻断事实问题、至少150组证据要求；每项诉请都有要件、事实、证据、答辩路径、法院审查和计算／处理规则；冲突救济不得并列为无条件请求；被告不得遗漏对任一被诉请求的回应。
