# 图表路由

凡请求把诉讼材料转成图、矩阵或结构化视觉规格，或审查现有诉讼图是否遗漏、失真或误导，先触发本 Skill，再回答“给谁、为了什么、什么信息造成理解或判断障碍”。授权不明或要求违规公开，不属于“不触发”，而是进入安全门后设 `workflow_status=hold` 或拒绝。纯法律检索、纯文字校对和纯文字摘要不触发本 Skill。

通过授权安全门后再选图。图表不是默认产物；若一段短文字或一张表已经足够，可以选择不绘图。此时仍应保留已经完成的权限判断，不得借“不绘图”绕过隐私或外发限制。

## 1. 受众与任务门

| 受众 | 常见任务 | 默认详略 | 特别约束 |
|---|---|---|---|
| 内部律师团队 | 全面梳理、找矛盾、定策略 | 细，允许多层图与治理 sidecar | 必须显式列未知项、反证和来源；默认本地、不外发 |
| 已授权客户 | 解释案情、方案与风险 | 中等，术语需解释 | 不能把策略性判断说成确定结果 |
| 法院或仲裁庭 | 帮助理解争点相关事实与关系 | 精简，只保留可核对内容 | 现行法、程序期限和提交格式须另行核验；治理字段不得进入可见正文 |
| 对方或调解场景 | 聚焦共同事实、分歧与可协商变量 | 按谈判目的严格控制 | 不暴露内部策略、特权材料或不应披露信息 |

如果受众已熟悉某一流程，且该流程不是争点，不为“显得专业”重复画图。若受众的知识壁垒正是理解障碍，优先画流程或结构图。

## 2. 核心要素路由

| 核心问题 | 首选图形 | 适用信号 | 不适用信号 |
|---|---|---|---|
| 时间点、先后顺序、期间、阶段变化 | 时间线 / 分阶段时间图 | “什么时候发生”“先后顺序决定什么”“多份文件跨多年” | 日期只是背景且关系才是争点 |
| 主体、合同、控制、代理、担保或事实关系 | 关系图 | “谁与谁是什么关系”“多层公司/合同链”“名义与实际主体不同” | 只有两方且关系可用一句话说清 |
| 资金、货物、票据、股权或文件的移动 | 流向图 | “谁向谁交付什么”“路径是否闭合”“资金与合同主体不一致” | 只有一个简单支付或交付动作 |
| 大量数值、静态/动态数据、差额或比例 | 数据表 / 对比图 / 数据流 | “多笔款项难对应”“持股比例变化”“工程量与结算差异” | 数值无争议且不影响判断 |
| 条件、程序分支、救济路径或依赖关系 | 流程图 / 决策树 | “满足何条件进入哪一步”“有多条程序路径” | 未完成现行法核验，或路径具有重大裁量而被画成必然 |
| 争点、事实命题、证据和反证之间的覆盖 | 争点—事实—证据矩阵 | “哪些争点有证据”“哪里有缺口/冲突”“证明对象是什么” | 试图用矩阵替代证据能力或证明力判断 |
| 地理、项目分区、现场位置 | 空间示意图 | 位置或空间顺序直接影响事实理解 | 需要测绘精度、比例尺或工程鉴定却只有示意资料 |
| 现有诉讼图是否完整、忠实 | 视觉完整性审查清单 | “这张现图漏了什么”“箭头/颜色是否误导”“与案卷或 SSOT 是否一致” | 只有纯审美改色且不涉及内容审查 |

选择空间示意图时，必须继续加载 [02-visual-patterns.md](02-visual-patterns.md) 的空间图章节及该章节指定的空间模板；未核对比例、方位、时间和建模假设时，只能标为示意，不得冒充测绘、勘验或鉴定成果。

## 3. 组合规则

- 两种核心要素都重要时，优先拆成两张图或主图 + 明细表；不要把所有事实塞进一张“万能图”。
- 时间与关系交织：主时间线保持事件顺序，关系图负责主体结构；通过稳定 ID 互相引用。
- 数据与流向交织：用流向图表达方向，用附表表达精确数值和计算口径。
- 程序与现行法交织：`legal_review` sentinel 始终存在；出现法条、管辖、流程图、期限、时效、救济或上诉等触发内容时，`required=true`，图中只放经人工实质核验的节点、条件和日期，并使 `legal_review.legal_rule_refs` 逐条覆盖 `legal_rule support_refs`。未核验时设 `workflow_status=research_draft`，若会影响对外提交、行动路径或重大结论则设 `workflow_status=hold`。
- 任何图形都不能混淆“3 个记录主维度 + 独立裁判处理维度 + 1 个规格级工作流门”：`fact_status`、`record_type`、`lifecycle` 属于记录，`adjudication_status` 独立记录裁判处理，`workflow_status` 只在规格顶层控制推进。图中至少为事实状态建立稳定视觉语义；`HOLD` 只控制流程，不得画成事实真伪。
- 对外不把 `confirmed` 写成“已查明”或“无争议”，优先标为“当前材料支持”。来源陈述使用 `record_type=source_statement`，并另记 `asserted_by` 与 `verification_basis`；裁判确认必须另有裁判文书和效力说明。
