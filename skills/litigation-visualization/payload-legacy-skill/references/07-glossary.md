# 操作术语表

本表用于统一 Skill 内部语言。遇到术语时，按“操作定义”执行；“容易混淆/边界”是强制检查项，不是可选提示。

| 术语 | 操作定义 | 容易混淆/边界 |
|---|---|---|
| 诉讼可视化 | 将已授权的案件事实、证据、争点、程序或数据转化为服务明确任务、可核对且可编辑的图示与说明。 | 不等于排版美化、插图，亦不等于把文字机械搬进方框。 |
| SSOT | `Single Source of Truth`，指图表生成前建立的唯一来源化底稿；主体、事件、关系/流向和争点证据记录均使用稳定 ID，图表从此派生，错误先在此修正。 | 不是把所有原文复制到一张表，也不取代原件、`source_ledger` 或治理 sidecar。 |
| `source_ledger` | 每项以 11 个字段记录来源：`source_id`、`source_kind`、`source_hash_or_version`、`custody_or_processing_location`、`ingested_at`、`source_cutoff`、`authorized_use`、`locator_prefix`、`page_or_unit_locator_scheme`、`ocr_or_derivation_note`、`description`。 | 解决来源身份与追溯问题，不自动证明来源内容真实，也不得直接混入法院可见件。 |
| 3 个记录主维度 + 独立裁判处理维度 + 1 个规格级工作流门 | `fact_status`、`record_type`、`lifecycle` 是记录主维度；`adjudication_status` 独立记录当事人/裁判处理；`workflow_status` 仅在规格或版本顶层控制推进。 | 不得合并命名；`HOLD` 不是事实状态，`inference` 不是事实状态，工作流门不得下沉到节点或边。 |
| `fact_status` | 命题在当前允许材料中的支持状态，仅允许 `confirmed`、`disputed`、`unknown`。 | 只回答材料支持状况，不回答记录性质、当前适用性或流程能否推进。 |
| `confirmed` / 当前材料支持 | 当前允许使用的材料支持该命题，且当前输入未见实质冲突。对外优先显示“当前材料支持”。 | 不等于无争议、已由独立调查查证、裁判确认或终局认定；裁判确认必须另记文书、效力和定位。 |
| `disputed` | 当前材料中有实质对立口径、支持与冲突材料或竞争性推论；必须并列 `support_refs` 与 `conflict_refs`。 | 不是由模型选择较可信的一方，也不能用 `HOLD` 替代争议状态。 |
| `unknown` | 当前材料不足以支持命题；`support_refs=[]`，并记录 `gap_reason`。可保留 `context_refs` 与 `conflict_refs`。 | 不是“没有任何来源”；上下文和冲突来源可解释缺口，但不能冒充支持。 |
| `record_type` | 记录性质，仅允许 `fact`、`source_statement`、`inference`、`legal_rule`。 | 不等同于事实状态；推论和法律规则仍须单独记录材料支持与流程限制。 |
| `source_statement` | 可确认某人在某材料中作出的陈述；必须记录 `asserted_by` 与 `verification_basis`。 | 陈述存在不等于陈述内容真实，不能自动转成 `record_type=fact`。 |
| `lifecycle` | 记录在当前版本与任务范围的适用性，仅允许 `current`、`superseded`、`not_applicable`。 | `superseded` 与 `not_applicable` 只控制当前使用，不判断命题真伪，也不能用于隐藏反证。 |
| `workflow_status` | 产物能否进入下一步，仅允许 `ready`、`research_draft`、`hold`。 | 是流程门结果，不是事实、证据或法律结论的可信等级。 |
| `adjudication_status` | 记录程序或裁判处理，仅允许 `not_adjudicated`、`party_admission`、`procedurally_disputed`、`judicially_determined`；后三种必须有 `adjudication_refs`。 | 不由 `fact_status=confirmed` 推导；`judicially_determined` 的定位须回链到 `source_kind=decision`，裁判效力仍需人工复核。 |
| `ready` | 指定版本已对指定受众、渠道、字段和用途通过当前适用门，可以进入已授权的下一步。 | 不等于事实已查明、法律结论必然正确、裁判确认或获准向其他对象发布。 |
| `research_draft` | 授权范围内可继续内部研究，但现行法、程序、期限或其他研究问题尚未完成核验。 | 不能作为可行动、可提交、可外发或“已核法律结论”。 |
| `HOLD` / `hold` | 授权、隐私、法源、来源完整性、视觉误导或其他强制门失败时，对受影响下游动作的暂停状态。 | `HOLD` 不是 `fact_status`，不会把命题变成 `unknown` 或 `disputed`；必须记录暂停范围、原因和恢复条件。 |
| 治理 sidecar | 与交付正文分离的 `source_ledger`、`privacy_authorization`、始终存在的 `legal_review` sentinel，以及适用的 `hold_control`、`spatial_review` 和放行日志。 | 不是案件事实或法院可见内容；不能因“只是内部文件”而省略访问和保留控制。 |
| `privacy_authorization` | 以 `processing_location`、处理者、接收者、渠道、`field_allowlist`、脱敏、保留，以及 `human_release_approved`、`human_release_by`、`human_release_at`、`authorization_basis` 记录处理和交付边界。 | 默认本地、不外发；外部处理或接收未批准时必须 `workflow_status=hold`；旧版本放行不自动继承。 |
| `legal_review` sentinel | 每个规格始终存在；无触发内容时 `required=false`、`law_check_status=not_required`。出现法条、管辖、流程图、期限、时效、程序、救济、上诉或 `legal_rule` 时 `required=true`，记录法域、法源、适用时点、核验日期和人工复核者。 | 触发后必须人工实质核验，且 `legal_rule_refs` 逐条覆盖全部 `legal_rule support_refs`；历史书籍、模型记忆、未核网页或脚本通过都不能完成该门。 |
| `hold_control` | 当 `workflow_status=hold` 时，以 `scope`、`reason`、`owner`、`recovery_conditions` 记录暂停边界和恢复条件；其他状态为 `null`。 | 暂停工作流不改变事实支持、记录性质、生命周期或裁判处理状态。 |
| `spatial_review` | 空间、现场、路线、边界或坐标视觉的治理记录，包括图种、测量方法、坐标/比例、方向、采集日期、数据版本、遮挡、误差、投影、时间变化、视角和建模假设。 | 字段齐全不等于测绘、勘验或鉴定正确；非空间任务为 `null`。 |
| `released_fields` | render manifest 明示实际交付的语义字段类别，必须是 `privacy_authorization.field_allowlist` 的子集。 | 不能用渲染清单扩大授权；真实放行仍由人工授权记录决定。 |
| 输出 locator | `line`、`cell`、`node`、`shape`、`table`、`slide` 用来检查目标位置是否含对应规格元素 ID。 | `page` 当前不受支持；ID 存在不证明视觉语义忠实、没有未建模断言或内容实质正确。 |
| 视觉完整性审查 | 对现有诉讼图逐项核对节点、边、形状、表格/幻灯片元素、来源、反证、未知项及视觉暗示，识别遗漏、失真和误导。 | 不是审美打分；脚本只能做 ID/结构核对，实质完整性必须人工判断。 |
| 人工复核状态 | 独立记录复核人、日期、范围、发现、修改要求及针对特定版本、受众和渠道的放行结果。 | “复核通过”不自动扩大材料授权、接收人或渠道，也不等于裁判确认；新版本或新渠道须重新复核。 |
| 呈送对象 | 图表的实际使用者及其任务、已知信息和阅读场景，如内部团队、客户或裁判者。生成前必须明确。 | 不是泛泛的“读者画像”，也不是案件主体名单。 |
| 信息壁垒 | 受众因不熟悉专业领域、业务流程或案件结构而无法高效理解信息的具体障碍。 | 案情复杂或材料很多，不必然构成需要作图的信息壁垒。 |
| 图表必要性门 | 先判断图表能否降低信息壁垒并服务当前任务；结果可以是制作、改版或不制作。 | 不得以“材料多”或“用户提到图表”为唯一理由自动作图。 |
| 核心要素 | 真正影响争点判断或案情理解的时间、关系、数据、程序或空间要素。 | 案件中出现日期、主体或数字，不代表它就是核心要素。 |
| 时间图 | 当时点、先后顺序或期间本身构成争点或理解主线时，用事件节点和时间轴表达。 | 不是任何带日期的案件大事记；每个事件仍须绑定来源和事实状态。 |
| 时间轴纵横划分 | 纵向用泳道表达主体、类别或对比；横向用起止点表达阶段和期间。 | 不得为排版随意分层；法律期间必须另行核验，不能只靠颜色表示法律效果。 |
| 流程图 | 以入口、步骤、判断条件、分支和结果表达程序、业务或救济路径。 | 不等同于时间线；涉及法律程序时必须核验现行法及核验日期。 |
| 统一入口、区分情形 | 从受众当前面对的同一问题出发，再按互斥或明确可并行的条件分流，并保留未知路径。 | 不是把若干独立小流程并排摆放，也不能把证据不足强行分到确定分支。 |
| 关系图 | 用唯一主体节点、带方向和类型的边，以及关键事实呈现事实关系、交易结构或法律关系。 | 不能只在两主体之间写一个抽象定性；客观行为与法律主张应分层。 |
| 以事实体现关系 | 每项关系主张至少关联一个可核对的合同、行为、付款、交付、控制或证据节点。 | 图形不能替代论证；一方定性应标为争议主张，而非画成“当前材料支持”的中性事实。 |
| 点线一致 | 同类主体使用相同节点语义，同类关系使用相同线型、方向和含义，并由图例定义。 | 同一箭头不得既表示持股又表示转让；任何编码例外都要说明。 |
| 数据图 | 在数据庞杂、发生重要变动或需要比较、构成、趋势分析时，用适当图形呈现。 | 有数字不等于需要数据图；必须记录来源、口径、单位、期间和计算方法。 |
| 静态数据与动态数据 | `before` 和 `after` 表达时点状态，`event` 表达谁以何种方式造成何种变动。 | 不得只列最终数值，也不得用最终状态倒推缺失的变动过程。 |
| 表格 | 当任务主要是核查、对账、多字段比较或证据对应时，优先用带来源和状态列的表格。 | 不是数据图的低级替代；汇总值必须能够从明细回算。 |
| 空间图 | 当路线、点面关系、层高或空间结构影响争点时，选择路线图、平面图或立体示意图。 | 示意图不能冒充测绘、勘验或鉴定；必须注明来源、比例、时间和建模假设。 |
| 全面罗列 | 在私域分析阶段先记录所有可能有价值的事实、细节、关系和可作图点，并绑定来源与状态。 | 不是把全部材料原样塞入最终图，也不授权暴露无关敏感信息。 |
| 细节图 | 只解决一个可检验问题的局部图，以共同主体、时间或争点标识供后续组合。 | 是中间分析单元，不当然适合作为独立呈送的最终图。 |
| 逻辑整合 | 选择一个明确主线和连接键，把细节图组合成可理解结构；必要时拆分主图和辅助图。 | 不等于机械拼页，亦不应把所有细节缩小后强塞进一张画布。 |
| 法律关系主线 | 以与核心争点关联最高的主体、权利义务或交易关系作为细节图连接中心。 | 不能仅因某主体出现次数多、诉讼地位高就把它设为中心。 |
| 时间主线 | 当取得时间、履行次序或程序推进决定争点时，以已核对的时点或期间连接各细节图。 | 文件形成日期不必然等于事实发生日期；争议日期应并列主张和证据状态。 |
| 全景图 | 作为导航层概览，仅保留核心主体、主线、争点和通往细节图或附表的索引。 | “全景”不等于内容越多越好；详细事实仍应留在可追溯的子图中。 |
| 精简内容 | 在罗列和整合之后，按争点相关性、理解必要性、来源可靠性和合法策略筛选最终信息。 | 不能一开始就挑重点，也不能删除反证、未知项或改变结论的重要条件。 |
| 3S 原则 | `Simple`：去重复但留关键细节；`Straight`：事实到观点路径无断点；`Strategy`：表达服务合法目标且不牺牲真实完整。 | 不等于字越少越好，也不允许把策略性变成只画有利事实。 |
| 客观真实与立场 | 将事实状态与当事人立场分别记录；允许强调主张，但底层事实、比例和来源必须可核对。 | 中立不等于没有观点；有立场也不允许篡改、遗漏反证或制造确定性。 |
| 线条、颜色、框架的视觉语义 | 先定义图例，再用线条表示联系和流向、颜色区分类别或强调、框架表达阶段或集合。 | 颜色不能作为唯一信息通道，醒目程度也不代表证据证明力。 |
| 案件事实图与法律关系图 | 事实图表达有来源的事件和行为；法律关系图表达明确标注主张者与争议状态的分析。 | 事实图不天然无立场，关系图中的法律定性也不当然已获裁判确认。 |
| 票面记载—实际流转—资金流向三线核对 | 对名义记载、凭证或标的的实际流转、资金去向分别建边并绑定证据，再生成差异表。 | 票面连续不证明实际交易真实，资金到账也不证明票据或标的流转一致。 |

## 状态转换与恢复条件

- `fact_status` 只随允许材料变化：`unknown` 在获得有效 `support_refs` 后可转为 `confirmed` 或 `disputed`；`confirmed` 一旦出现实质冲突应转为 `disputed`；冲突经来源修正或范围澄清消除后，才可重新评估。流程放行本身不得改变事实状态。
- `lifecycle` 独立变化：后续版本取代当前记录时标 `superseded`；确认不适用于当前对象、期间、法域或问题时标 `not_applicable` 并记录排除理由。生命周期变化不得删除原记录或反证。
- `workflow_status=hold` 只有在对应授权、隐私、法源、来源或视觉风险已解决，并记录适用的人工放行后，才可转为 `research_draft` 或 `ready`。
- `workflow_status=research_draft` 只有在条件触发的研究与法律核验完成、未决问题得到处置并完成相应人工复核后，才可转为 `ready`。
- 新接收人、新处理器、新渠道、新字段、新材料、新法域或版本实质变化会重新触发相应门；旧版本的 `ready` 和人工放行不得自动继承。
- 为解除 `HOLD` 而把 `unknown` 改成 `confirmed`，或用 `lifecycle=not_applicable` 隐藏不利材料，均属违规状态转换。

## 历史与排除术语

- **2017 年旧法条、程序期限和历史规范**：只可作为原书方法案例和“需要检索”的信号，不能作为现行法律结论。凡涉及权利、期限、程序、责任或法定构成，必须重新查询权威现行法源并记录检索日期。
- **旧工具、旧界面与未来技术设想**：智能制图、三维动画、触摸界面、远程互联或虚拟诉讼等描述，不代表本 Skill 已验证的能力，也不构成强制技术栈。工具选择以当前环境中的可编辑、可访问、可验证和隐私要求为准。
- **案例结果和使用反馈**：历史案例中的胜诉、采纳或效率评价不能转化为结果承诺。图示不改变举证责任、证据能力、证明标准或裁判权限。
