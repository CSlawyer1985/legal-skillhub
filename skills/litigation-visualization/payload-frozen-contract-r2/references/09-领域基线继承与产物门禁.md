# 领域基线继承与产物门禁

本协议把案件型 Skill 的经验回灌改成可复算门禁。原则是：donor 门禁不能靠“已参考”概括，产物边界不能靠目录名称猜测，渲染和 E2E 不能靠起草席自述通过。

## 1. 领域基线继承

每个 donor inventory 必须固定：Skill 名称、版本、冻结 SHA-256 和全部 required gate id。新 Skill 的 Sublation 决策集合必须与 inventory 完全相等；每个 gate 只能出现一次，并保留证据、法律影响、理由和回归测试。

任何漏项、重复、未知版本或无防复发测试的舍弃决定均进入 `HOLD-BASELINE-INHERITANCE`。

## 2. 当前产物类别

本 RC 只允许两类：

| artifact_class | audience | 最低要求 |
|---|---|---|
| `court_submission` | 法院及诉讼参与人 | 中文优先、治理元数据不可见、固定版式、来源可回溯 |
| `professional_service` | 律师或获授权客户 | 风险与策略边界明确、内部字段按允许清单输出 |

每个契约必须声明 source SSOT、允许字段、脱敏规则、推广门、渲染门、失败状态，并固定 `write_back=false`。任何新增类别都需要独立 Sublation 与用户授权，不能修改 schema 后静默启用。

## 3. 物理分层

推荐结构：

```text
delivery/
  court_submission/
  professional_service/
governance/
```

法院提交目录不得包含 SSOT、P0/L1/L2、cutoff、HOLD、locator、绝对路径、构建日志、验收结论或其他治理 sidecar。专业服务件也不得携带超出授权的私域字段。

## 4. 法院可见文本门

扫描前仅排除被明确标记为客户填充区的占位符。正文、页眉、页脚、表格、批注、隐藏文本和 OOXML 可见内容均在范围内。

通过条件：治理词命中 0、未解析占位符 0、非中文异常 0、隐藏文本 0、外部关系 0。任一失败进入 `HOLD-COURT-TEXT` 或 `HOLD-OUTPUT-CONTRACT`。

## 5. DOCX 渲染门

只要候选输出 DOCX，就必须使用同一固定字体环境执行两次逐页渲染。页数、每页像素哈希必须一致；稀疏页、空白页异常、越界表格、不可编辑对象、意外外链均为 0。失败进入 `HOLD-RENDER`。

## 6. 真实 E2E 门

案件型 Skill 晋升前至少需要：

1. 一套完整九文书任务，核对事实、金额、请求、证据定位、文风、DOCX 和逐页渲染；
2. 一套应正确停止的 HOLD 个案，验证风险不会因追求完整产出被掩盖；
3. 构建席与验收席不同，起草席不能读取答案键或验收推理；
4. 两案均有固定输入哈希、输出清单、验收记录和复算结果。

缺少任一任务或席位不独立时进入 `HOLD-E2E`。静态模板 PASS 不替代真实 E2E。
