# 授权、来源与只读基线

## 1. 授权记录

每次蒸馏必须先生成授权表，不以“文件在本机”推定可以处理、训练或公开。

| 字段 | 要求 |
|---|---|
| material_owner | 材料权利人或合法控制人 |
| authorizer | 作出本次授权的人 |
| allowed_use | 内部分析、内部 Skill、客户交付、公开发布等逐项列明 |
| prohibited_use | 禁止训练、禁止公开、禁止跨客户复用等 |
| retention | 保存期限与销毁要求 |
| jurisdictions | 适用法域和跨境限制 |
| approval_evidence | 授权记录的定位与哈希，不把授权原件打进公开包 |

授权不完整时只做材料清点，不进入内容提取。

## 2. 目录分区

至少建立四个不重合的逻辑根：

1. `source_readonly`：原件与元数据，只读。
2. `answer_key_sealed`：裁判结果、既有成品、人工答案键，只对验收席可见。
3. `staging_private`：候选、OCR、SSOT 和测试中间物。
4. `public_projection`：通过公开允许清单的派生物。

任何从 `public_projection` 指向前三个根的符号链接、快捷方式或挂载均视为 P0 失败。

## 3. 基线清单

对每个输入记录相对标识、媒体类型、字节数、修改时间、SHA-256、可读性、隐私等级和权利状态。交付包只保留脱敏相对标识，不保留本机用户名、绝对路径或客户目录名。

原件、答案键和冻结成品：

- 不改名、不移动、不覆盖；
- 不做原地 OCR 或格式转换；
- 新产物写入 staging；
- 发现原件漂移时停止比较，重新冻结基线。

## 4. 截止点与盲测

案件型任务记录两个时间：

- `evidence_cutoff`：起草者可使用的事实材料截止点；
- `law_checked_at`：法律席核验现行法的日期。

答案键隔离必须可验证：仅写“我没有看”不足以通过。应由文件允许清单、独立工作区、输入清单和验收日志共同证明。

## 5. 权利分级

| rights_status | 含义 | 允许动作 |
|---|---|---|
| `private-authorized` | 获内部处理授权 | 私域蒸馏，不得公开 |
| `licensed-internal` | 许可仅覆盖内部使用 | 内部引用和 Skill，不得分发 |
| `public-source` | 来源公开但未必可再发布全文 | 可验证和摘要，仍需遵守版权 |
| `cleared` | 已明确允许进入公开投影 | 可进入 GEO 候选，仍需发布授权 |
| `unknown` | 权利不明 | `HOLD-RIGHTS` |

公开可访问不等于可以复制全文；允许引用也不等于允许用客户事实训练或公开。
