# 多席独立验收与冻结

## 席位与证据

| 席位 | 最小证据 | 可作出的结论 |
|---|---|---|
| 构建席 | inventory、SSOT、测试输出、构建日志 | 候选构建完成 |
| 隐私席 | 输入/输出允许清单、扫描结果、随机抽样 | 隐私 PASS/HOLD |
| 法律席 | 法源清单、时效检查、正反例、误用评估 | 法律 PASS/HOLD |
| 盲测席 | 隔离证明、测试输入、独立输出、答案键对照 | 盲测 PASS/HOLD |
| 用户 | 上述证据与候选产物 | 安装、晋升或发布授权 |

“看起来不错”“测试脚本返回 0”或房间内的 `APPROVE` 文本都不能替代对应授权范围。

## 冻结顺序

1. 停止内容编辑并记录候选版本；
2. 验证必需文件、JSON/schema、触发用例和 HOLD 标签；
3. 扫描个人信息、凭据、绝对路径、缓存、隐藏文件和符号链接；
4. 独立检查法源日期、引用定位和公开允许清单；
5. 生成 `checksums.sha256`；
6. 由独立席从磁盘重新计算并比对；
7. 生成压缩包及其外层哈希；
8. 将状态标为本地候选或本地冻结，外部发布仍为 false。

任何内容改动都会使原哈希失效，必须重新验证和冻结。

## 失败处理

- P0 泄漏、答案键污染或法源失效：立即 HOLD，废弃受影响派生物并从干净检查点重建。
- 结构或格式失败：修复后重跑全套静态验证。
- 触发误判：回到原子记录和 Skill 输出契约，不做只改关键词的表面修补。
- donor 门遗漏、法院件治理词泄漏、DOCX 双遍不一致或真实 E2E 未闭合：进入对应 HOLD，不得以静态包测试替代。
- GEO 引用失真：撤销对应公开投影，不影响私域 SSOT，但需要记录事故和防复发测试。

## 权限边界

本地冻结、正式安装、团队同步、知识库写入、生产晋升和外部发布是六个独立权限。上一步通过不会自动授予下一步。

物理安装观察与安装授权也必须分开记录。目录存在只能证明可见部署状态，不能补造授权收据或生产晋升结论。
