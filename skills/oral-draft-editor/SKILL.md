# 口述稿整理成文 Skill

## 目的

把口语化口述稿整理成结构清晰、逻辑自洽的成文。口述稿天然带着散点、跳跃、重复和编号混乱，直接交付或排版会带上逻辑硬伤；本 skill 用「六项逻辑审校」在成稿前把这些硬伤找出来并理顺。措辞可适度润色，但**金句与关键信息一字不动**；不做内容压缩。

## 润色与结构边界

- **措辞：可适度润色**——口语冗余、语病、明显不通顺的句子可以顺；重复啰嗦的表达可以精简字词。但两类东西一律不改：
  1. **金句**：原文的生动比喻、口语化妙语、有个人风格的表述，保留原样；
  2. **关键信息**：数字、日期、人名、产品名、金额、法条、事实与结论，一字不改。
  - 拿不准某句是不是金句时，保留原样（宁可保守）。
- **结构：以原文逻辑为默认，不强制**——默认跟着原文的论述顺序走；为阅读流畅可以重排段落、把后置的结论提前，但不删并内容、不丢任何论点。
- 润色幅度在「改动清单」中说明，方便用户复核。

## 触发场景

- 用户提供口述稿 / 录音转写 / 口语化草稿，要求「整理成文」「写成文章」「理顺逻辑」
- 成文后要发布到公众号、做成课程要点稿、讲座逐字稿等
- 用户问「哪些有矛盾」「前后不一致的地方」

## 核心：六项逻辑审校

对全文逐段检查以下六类问题，发现问题先列出清单（含原文引用），再动手整理：

### ① 编号断裂
- 文中出现「第一/第二/第三」「特点/作用/点」「首先/其次/另外/最后」等序号词时，逐一核对：
  - 每个序号是否都有对应项？
  - 「第二个 X」前面有没有「第一个 X」？
  - 同一层级的称呼是否统一（特点/作用/点不能混用）？
- 处理：统一编号层级；缺失的第一项从上下文补出，或删掉孤立序号。

### ② 结论重复
- 同一结论是否在不同位置重复出现（换了说法但实质相同）？
- 处理：合并到一处，删掉重复的那句；若重复处各有侧重，则明确分工后保留。

### ③ 概念混用
- 常见陷阱：把「操作繁琐」（原生有但难用）说成「功能欠缺」（原生根本没有）。
- 处理：区分两类并分别归类，必要时用一句话点明区别（如「补的是原生根本没有的能力，跟『只是麻烦、不是没有』是两回事」）。

### ④ 一体两面未点破
- 同一个动作同时被夸「方便」又被批「有缺点」时，检查是否点明了两者是同一动作的两面。
- 处理：补点破句，如「方便的是『转发』这个动作，缺的是全文留存」。

### ⑤ 分工说明补位
- 文中同时出现「能力强 / 效果流畅」与「效果不佳 / 会出错」时，通常缺一句「谁负责什么」的分工说明。
- 处理：补桥梁句，如「人定规则、Agent 执行，两者配合才不会乱」。

### ⑥ 术语与中文标点统一
- 品牌名大小写（Workbuddy / WorkBuddy）、别名（ima Agent = ima Copilot）、笔误（dema agent → ima agent）在成稿前统一。
- 若全文用别名（如「自带 Agent」），在开头第一次出现处点明与正式名（如「ima Copilot」）的关系。
- **中文引号铁律（2026-08-30 实测踩坑）**：成稿的 md 源里引号必须直接写中文弯引号""（或直角引号「」），**禁止打 ASCII 直引号 `"`**。实测踩坑：成文时图省事打了 22 个直引号，pandoc 转 docx 后按英文规则配西文字体渲染，中文语境下左引号也显示成下引号。
  - 修复方法：源文件按开闭交替替换为 ""（奇数个 `"`→"，偶数个→"），再转 docx；转完给全部样式补 `w:eastAsia=微软雅黑` 中文字体声明（python-docx 遍历 doc.styles 设 rFonts.eastAsia）双保险。
- **同音错字校验**：口述稿/录音转写几乎必带同音错字，必须跑 `references/homophone-corrections.md` 的对照库与四步校验流程：
  1. 先拿对照表把全文过滤一遍（附录、标题、图表标注不能漏）；
  2. 对照表没有且不确定的专有名词，**主动联网查证官方正确写法**（大小写、空格、中文名），不等用户开口；
  3. 全网叫法不统一的，按最主流/官方写法修正，并主动说明"存在多种叫法，已采用 XXX"；
  4. 修正后汇报口径："已联网查证 X 项，修正 Y 项，存疑 Z 项"；查不到的**保留原文**加 `[存疑：可能为XXX]` 标注。
  - 高频误识示例：华语原点→华宇元典、沃克八点→WorkBuddy、免费的CP→免费的MCP、购房数据库→法律数据库。完整对照库见 `references/homophone-corrections.md`。

## 工作流

1. **通读**：完整读原文，不做摘要。
2. **审校**：跑六项清单，输出问题清单（问题类型 + 原文引用 + 处理动作）；第⑥项先过同音错字对照库，不确定的专有名词联网查证。
3. **确认**：问题清单给用户过目，确认后再动手（用户明确授权直接改的除外）。
4. **整理**：按清单逐项整理——结构可重排、措辞可按「润色与结构边界」适度润色，金句与关键信息一字不改；「点破句」是唯一允许新增的内容，且必须用原文口吻。
5. **自检**：对照六项清单复核输出，确认无残留问题；关键信息（数字/日期/人名/产品名/结论）与原文逐项核对无改动；术语全局一致（同一产品不得出现两种写法）；**同音错字自检**：对照表命中项全部修正、存疑项已标注、已按口径汇报查证结果；发现的新对照项当次任务内沉淀入库；**引号自检（不过关不交付）**：grep 成稿源文件，ASCII 直引号 `"` 数量必须为 0，中文语境引号全部为弯引号 "" 或直角引号「」。

## 禁止项

- ❌ 不摘要、不压缩原文内容（论点和事实一条不丢）
- ❌ 润色不碰金句与关键信息（数字/日期/人名/产品名/金额/法条/结论一字不改）
- ❌ 不凭空添加原文没有的收益、数据、结论
- ❌ 不擅自删用户明确点名的内容

## 输出

- 结构化的整理稿（Markdown 或按用户要求的格式）
- 附「改动清单」：新增 / 删除 / 移动 / 改名的具体位置，方便用户复核
