# ISO 27001:2022 至 NIS2 第 21 条交叉引用

ISO/IEC 27001:2022 认证为许多第 21 条措施的 NIS2 合规提供有力证据。然而，ISO 27001 认证**不能替代** NIS2 义务——实体仍直接负责满足第 21、20 和 23 条要求。

NIS2 超出 ISO 27001 的关键差距：
- **第 21(2)(d) 条**：NIS2 明确强制与 ENISA 协调风险评估（第 22 条）挂钩的供应链安全义务
- **第 21(2)(j) 条**：NIS2 明确强制 MFA——ISO 27001 附件 A.8.5 涵盖身份验证，但 MFA 并非普遍要求
- **第 20 条**：管理层机构个人责任无 ISO 27001 对应
- **第 23 条**：事件报告时间表（24 小时/72 小时/1 个月）比 ISO 27001 的一般事件管理控制更具规定性

## 无直接 NIS2 措施对应物的 ISO 27001 控制

以下 ISO 27001:2022 附件 A 控制对整体安全态势重要，但不映射到特定第 21 条措施。它们仍可能与 NIS2 治理和合规证据相关：

- **A.5.2** 信息安全角色与职责
- **A.5.31** 法律、法定、监管、合同要求
- **A.5.32** 知识产权
- **A.5.33** 记录保护
- **A.5.34** 隐私和个人可识别信息保护（→ 另见 GDPR）
- **A.6.4** 纪律程序
- **A.8.1** 用户终端设备
- **A.8.9** 配置管理
- **A.8.10** 信息删除

## ISO 27001 覆盖有限的 NIS2 要求

| NIS2 要求 | 与 ISO 27001 的差距 | 建议行动 |
|---|---|---|
| 第 20 条——管理层机构批准和个人责任 | 无 ISO 27001 对应 | 董事会网络安全政策；培训记录；记录在案的批准会议纪要 |
| 第 23 条——24 小时早期预警 | ISO 27001 A.5.24-5.26 涵盖事件管理但不含具体时间表 | 预起草 CSIRT 通知模板；自动化警报工作流 |
| 第 23 条——72 小时通知 | 同上 | 带时间表检查点的事件分诊运行手册 |
| 第 23 条——1 个月最终报告 | 同上 | 含第 23(4) 条全部所需字段的事后审查模板 |
| 第 22 条——ENISA 供应链风险评估 | ISO 27001 A.5.19-5.23 一般性涵盖供应商安全 | 监测 ENISA 和国家机构供应链公告；纳入供应商风险登记册 |
| 第 21(2)(j) 条——MFA 强制 | ISO 27001 A.8.5 涵盖身份验证；MFA 非普遍 | 至少为远程访问、特权账户、云控制台部署 MFA |

## 对 ISO 27001 认证实体的实务指引

如您的组织持有 ISO 27001:2022 认证，您已为 NIS2 做好准备，但应：

1. **确认实体分类**——核验您依第 3 条属于 EE 还是 IE，以及您所在成员国的转化法律
2. **处理第 20 条治理**——记录董事会层面批准网络安全措施，并确保维护培训记录
3. **实施第 23 条报告工作流**——您的 IRP 可能需要带有预起草 CSIRT 模板和 24 小时/72 小时/1 个月检查点的明确 NIS2 通知轨道
4. **审查供应链覆盖**——将您的供应商安全控制映射到第 21(2)(d) 条，并整合 ENISA 协调风险评估输出
5. **强制 MFA**——如尚未普遍，为远程访问和特权账户部署 MFA
6. **向国家主管机关登记**——大多数成员国要求范围内实体自行登记
