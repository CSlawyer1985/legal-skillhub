# 客户背调报告 Skill（v2.5）

> 用途：输入一家公司名称和一条指令，自动生成一份完备的客户背景调查报告（Word）及配套附件（PDF）。
> **输出目的：律所接案决策与洽谈准备**（不是通用企业尽调）。
> v2.0 准入合规模块 / v2.1 竞品对标（执行摘要红黄绿、历史服务机构、洽谈问题清单、复查机制）/ v2.2 MCP 采集层＋证据账本＋校验器 / v2.3 企查查 MCP 实测接入 / v2.4 ledger_build 自动化＋页码页脚＋双案例 / v2.5 十条强制规则固化（见第零节）。
> 本 Skill 为青训营参赛作品，独立运行，不调用任何刑事辩护/民商事办案 Skill。

---

## 零、强制规则（v2.5，不可违背）

1. **目的限定**：本 Skill 服务于"律所接案决策与洽谈准备"，一切章节必须回答"能不能接、怎么接、怎么收钱、怎么谈"四问之一，不能服务于此的内容一律删除。
2. **准入审查第一层留空**：利益冲突检索、反洗钱判断、受益所有人识别为报告第一层审查；AI 只生成检索清单与判断框架，**结论一律留空由律师填写**；AI 可给"初判（仅供参考）"但不得代替结论。
3. **双源核验**：每个关键数据点至少两个来源，官方优先；口径冲突必须进入《数据口径冲突表》列表呈现，不得只取一个数字。
4. **必备输出七件套**：数据口径冲突表、人工核验清单、未能核实清单、首次洽谈问题清单、时间轴＋行动窗口、收费方案、退出机制——缺一不得交付。
5. **必识别三要素**：现任服务者/潜在竞争者、决策链地图、客户可能的替代方案。
6. **财务保留条件**：财务数据引用必须附审计意见类型，存在差错更正/非标意见的必须附保留条件；意见类型未核验的写明"未核验"。
7. **数据源分级标注**：企查查/天眼查/**北大法宝等 MCP 接口出具的数据无需标注待核验**（视为已核验来源）；社交媒体、通用搜索引擎结果、百度百科等通用渠道内容必须标注"待核验"。
8. **决策链可视化**：必须基于公司架构分析决策链条，生成可视化图并嵌入报告"董监高与核心人员"节（md2docx.py 已支持 `![图注](路径)` 图片语法）。
9. **法律文书排版**：页眉使用天驰君泰 logo（scripts/tctl_logo.jpeg）、页脚强制页码；标题/正文格式严格区分（md2docx.py 已内置）。
10. **禁止 AI 评级与签字**：报告中不得出现 AI 给出的风险评级和"审批签字"栏；准入结论、签字处全部留空由律师完成。

## 一、触发条件

用户出现以下任一请求时，进入"客户背调模式"：

- "帮我背调一下XX公司"
- "对XX公司做一份客户背调报告"
- "XX公司要委托我们所，帮我查查背景"
- "生成XX公司的背调报告"

## 二、输入确认（第 0 步，必须执行）

开始采集前，向用户确认以下信息（用户已提供的跳过）：

| 项目 | 说明 | 默认值 |
|------|------|--------|
| 公司全称 | 必须是工商登记全称，不确定时先检索确认 | 无（必填） |
| 背调目的 | 常年法律顾问/专项服务/诉讼委托/其他 | 全方位法律服务洽谈 |
| 拟承接事项 | 是否涉及不动产买卖、代管资金/证券/资产、代管账户、为设立运营企业筹措资金、代理买卖经营性实体（用于反洗钱义务触发判断） | 待洽谈确定 |
| 重点关注 | 用户指定的重点方向（如诉讼风险、财务状况） | 全维度 |
| 报告日期 | 报告落款日期 | 当日 |

## 三、信息采集（第 1 步）

**信息来源以 MCP 数据源为优先、公开网页检索为降级补位。每条信息必须记录来源名称与 URL/接口名，无法核验的标注【待核实】。**

### 3.0 采集通道优先级（v2.2 新增）

1. **首选 MCP 数据源**：复制 `mcp_config.example.json` 为 `mcp_config.json`，配置企查查/快查等商用数据源（token 一律走环境变量，禁止写入配置文件），运行：

```bash
python3 scripts/mcp_collect.py <公司全称> output/[公司简称]背调
```

成功维度直接以接口数据为准；脚本自动输出 `mcp采集结果.md` 标明各维度采集状态；随后运行 `python3 scripts/ledger_build.py output/[公司简称]背调` 把原始 JSON 自动汇总为**证据账本机器草稿**（每条标"待AI判断"），AI 逐条确认后并入正式证据账本。
2. **降级链**：MCP 未配置/调用失败的维度 → WebSearch/FetchURL 公开检索 → 仍无结果的标注【待核实】。降级是正常流程而非失败，但证据账本中来源类型必须如实标注（"MCP 接口"或"公开网页检索"）。
3. **证据账本先行**：采集过程中所有事实先落入 `output/[公司简称]背调/证据账本.md`（按 `templates/证据账本模板.md`，claim→evidence→source→status→gap），报告正文只允许引用账本中"已核验/单源（已标注）"的条目。

按以下八个维度采集（使用 WebSearch / FetchURL，建议并行派发子代理，每个维度一个）：

| # | 维度 | 主要公开渠道 |
|---|------|-------------|
| 1 | 工商基本信息 | 国家企业信用信息公示系统、爱企查/企查查公开页（统一社会信用代码、注册资本、成立日期、经营范围、登记状态、注册地址） |
| 2 | 股权结构与实控人 | 公示系统、上市公司年报、巨潮资讯网（穿透至受益所有人） |
| 3 | 董监高与核心人员 | 上市公司公告、年报、官网（识别决策链与洽谈对象） |
| 4 | 主营业务与财务概况 | 年报/半年报（巨潮资讯网 cninfo）、招股书、行业研报 |
| 5 | 诉讼与被执行 | 中国裁判文书网、中国执行信息公开网、人民法院公告网、第三方聚合页（失信、限高、股权冻结） |
| 6 | 行政处罚与监管措施 | 公示系统、信用中国、证监会/交易所/证监局公开信息 |
| 7 | 知识产权与资质 | 国家知识产权局、商标局公开查询、行业资质公示 |
| 8 | 舆情与近期动态 | 主流财经媒体、公司公告、负面舆情（adverse media）检索 |
| 9 | 历史服务机构识别 | 招股书/上市公告书/再融资公告（IPO 及历次专项的律师、保荐人、审计机构）、重大诉讼公告中的代理律所、常顾披露——识别"谁在服务这家客户"，辅助案源与竞争判断（市面产品均无此维度，差异化亮点） |

采集规则：

1. **禁止编造**：没有检索到的信息写"公开渠道未查询到"，不得虚构。
2. **来源标注**：每条关键信息以括注标明来源编号与查询日期，编号与 PDF 附件一一对应。
3. **交叉核验**：涉及注册资本、实控人、重大诉讼、财务数据等关键事实，至少两个独立来源相互印证；不一致时并列记录并提示。
4. **时效警觉**：优先采用最近一期年报/公告；旧数据须标注所属期间。
5. **第三方工具免责意识**：使用天眼查/企查查等聚合平台时注明"聚合摘要，未直接核验原始记录"。

## 四、客户准入合规审查（第 2 步，v2.0 新增，不可跳过）

对标国际律所 Business Acceptance 机制与中国监管硬规范，完成以下六项审查并写入报告：

### 4.1 利益冲突检索（签约前强制，书面留痕）

依据《律师法》第 39/47 条、《律师执业行为规范（试行）》第 49 条及各地律协利冲规则，检索本所在办及历史案件当事人名单是否与客户及其关联方、客户的主要诉讼对手方存在冲突。报告中设"利益冲突检索记录"栏，载明检索日期、检索范围、检索结论（AI 无法访问本所案件库，该栏由律师填写，报告生成时留填空位并高亮提示）。

### 4.2 反洗钱义务触发判断（前置判断题）

依据新《反洗钱法》（2025-01-01 施行）第 64 条及《律师行业反洗钱工作管理办法》（司法部、中国人民银行司规〔2025〕2 号，2025-08-01 施行）第 12 条，判断拟承接事项是否落入五类触发情形（不动产买卖／代管资金证券资产／代管账户／为设立运营企业筹措资金／代理买卖经营性实体），或存在"合理怀疑洗钱""对身份资料有疑义"情形：
- **触发** → 报告中列入法定当事人尽职调查清单（第 13 条：营业执照、受益所有人信息、代理关系核实、委托事项目的与性质），并按第 16-17 条评估是否需强化尽调（PEP、高风险地区、交易异常），高风险须负责人审批后方可建立委托关系；
- **不触发** → 报告中简要说明判断依据，仍按商业背调标准完成其余审查（避免过度合规，但保留底线核查）。

### 4.3 受益所有人（UBO）识别

将股权结构穿透至自然人（实控人），识别一致行动安排、代持线索、控制权稳定性；上市公司以前十大股东＋实控人公告为准。

### 4.4 名单筛查记录

对照涉恐名单、联合国安理会定向制裁名单、央行认定的重大洗钱风险名单的公开信息进行筛查并留痕；涉外客户加查 OFAC/EU 制裁名单与 PEP 身份。命中者：依《办法》第 23 条立即终止服务并报告。

### 4.5 付费能力与费用风险评估

结合资信状况（净资产、被执行、失信、重整状态）、历史欠费线索、行业付款惯例，评估顾问费回收风险，给出收费结构建议（预付/半风险/共益债务优先受偿等）。

### 4.6 风险评级与准入结论

综合第 1 步事实与第 2 步审查，给出**低/中/高**风险评级，并出具三选一明确结论：
- **接受委托**；
- **附条件接受**（列明条件：如强化尽调、预付费、负责人审批、限定服务范围）；
- **拒绝委托**（列明否决性理由）。
结论后设**审批签字栏**（承办律师／部门负责人／高风险时管委会）与**存档提示**（身份资料与尽调底稿至少保存十年，《办法》第 21 条）。

## 五、律师视角分析（第 3 步）

1. **客户画像**：行业地位、发展阶段、治理特征。
2. **法律需求图谱**：结合行业与近期动态推演最可能需要的服务，按紧迫度排序。
3. **风险提示**：分级标注（高/中/低）；上市公司客户必须包含**证券监管状态专项**（处罚/立案对再融资、并购重组、信披考核的连锁限制；退市风险警示状态；重整程序中对照最高法/证监会 2024 年纪要的"重整价值负面清单"逐项评估）。
4. **洽谈建议**：切入点、服务包设计、收费策略、接触路径（决策链）、沟通注意事项、团队配置。
5. **首次洽谈问题清单**：根据背调发现自动生成 8-12 条首次面谈必问问题（股权疑点、在诉案件进展、实缴与资金安排、决策授权等），每条标注"问谁、为什么问、期望答案"，把背调从"信息汇总"升级为"接待武器"。

**报告首页必须有"执行摘要＋风险信号清单"**：一段式客户速览＋红/黄/绿三级风险信号表（红色=否决性/高危事项，黄色=需关注，绿色=正面信号），洽谈前 30 秒可读完。

## 六、成果生成（第 4 步）

产出"1 份 Word 报告 + 1 套 PDF 附件"：

1. **撰写 Markdown 底稿**：按 `templates/报告模板.md` 结构撰写（序言四要素：委托目的、方法与范围、基准日与依据、免责声明；风险提示前置；正文；结论与审批栏），存 `output/[公司简称]背调/报告底稿.md`。
2. **生成 Word 报告**（标题黑体居中、一级标题黑体、正文仿宋_GB2312 四号、首行缩进 2 字符、1.5 倍行距）：

```bash
python3 scripts/md2docx.py output/[公司简称]背调/报告底稿.md output/[公司简称]背调/[公司全称]背景调查报告.docx   # Word（含目录页/页眉logo/页码）
python3 scripts/md2html.py output/[公司简称]背调/报告底稿.md output/[公司简称]背调/附件底稿.md output/[公司简称]背调/[公司全称]背景调查报告.html   # HTML 展示版（来源编号为脚注超链接，附件锚点呈现）
```

3. **编制 PDF 附件**（信息来源汇编：原始信息摘录、来源链接、查询日期，编号与报告引用一一对应）：

```bash
.venv/bin/python scripts/md2pdf.py output/[公司简称]背调/附件底稿.md output/[公司简称]背调/附件-信息来源汇编.pdf
```

> 注：md2pdf.py 依赖青训营目录下 `.venv` 的 reportlab（内置中文字体 STSong-Light）。新机器上先执行 `python3 -m venv .venv && .venv/bin/pip install reportlab`。

4. **生成后必读回验证**：docx 用 python-docx 读回检查段落数与纸张尺寸（A4）；PDF 用 pdftotext 抽检首页文字。
5. **确定性校验（v2.2 新增，强制）**：

```bash
python3 scripts/check_report.py output/[公司简称]背调/报告底稿.md output/[公司简称]背调/附件底稿.md
```

校验必备章节、正文与附件来源编号双向一致、内部字样、执行摘要清单；**FAIL 时必须修正后重新生成 docx/PDF，不得带错交付**。
6. **双语输出（可选，涉外客户）**：涉跨境主体或外文舆情占比高时，执行摘要与风险信号清单追加英文译文（中文在前、英文在后），README 已提供英文操作说明。

## 六之一、定期复查与增量更新机制（v2.1 新增，对标 Intapp Active Monitoring / 企查查风险云图）

背调不是一次性动作。对已进入洽谈或签约流程的客户：

1. **复查时点**：报告基准日后 3 个月／6 个月，或发生重大事件（处罚落地、重整裁定、控制权变更）时即时复查；可用 Kimi Code 定时任务（CronCreate）设置提醒。
2. **增量更新方式**：重跑第 1 步采集（重点维度：诉讼被执行、监管处罚、股权变动、舆情），**只输出变更差异**，生成 1-2 页《背调更新页》（命名 `YYYYMMDD_背调更新页_N.md`），追加到原报告附件后，不重写整份报告。
3. **触发升级**：复查发现风险信号升级（如新增失信、立案进展）时，重新执行第 2 步准入审查并更新风险评级与准入结论。

## 七、质控清单（交付前逐项自检）

商务背调部分：
- [ ] 公司全称、统一社会信用代码与公示系统一致
- [ ] 八个维度无遗漏，未查到的维度已写明"公开渠道未查询到"
- [ ] 关键事实均有来源标注且经双源核验
- [ ] 分析部分有事实支撑，无无依据的定性

客户准入合规部分（v2.0 新增）：
- [ ] 利益冲突检索记录栏已设置并提示律师填写
- [ ] 反洗钱义务触发判断已完成且写明依据（触发/不触发＋理由）
- [ ] 受益所有人已穿透至自然人
- [ ] 名单筛查已执行并留痕
- [ ] 风险评级明确（低/中/高），准入结论三选一且附条件/理由
- [ ] 审批签字栏与十年存档提示齐备

形式部分：
- [ ] 序言四要素（目的/方法范围/基准日/免责声明）齐备
- [ ] 首页执行摘要＋红黄绿风险信号清单齐备
- [ ] 首次洽谈问题清单已生成（8-12 条，标注问谁/为什么问）
- [ ] 历史服务机构（律师/保荐/审计/代理律所）已识别或写明未查到
- [ ] 证据账本已建立，正文事实均可回溯到账本条目
- [ ] `check_report.py` 校验 PASS（含来源编号双向一致）
- [ ] Word 排版：标题居中、正文仿宋四号、首行缩进、表格完整、A4 页面已读回验证

## 九、竞品定位与能力边界（v2.1 新增）

**相对市面产品的定位**：企查查/天眼查/犀牛卫有数据无律师分析；案牍 AutoDD 有核查底稿但无准入合规模块且机构定制价；Harvey/CoCounsel 有分析但不做中文公开数据采集；通用 AI 深度研究有分析但无来源附件留存、有幻觉风险；Intapp 有准入合规但是重型工作流系统、不产出报告。本 Skill 的独特组合 = **公开采集＋逐条来源附件＋律师视角分析＋准入合规审查＋公文级 Word 排版＋零边际成本**。

**能力边界（如实标注，禁止过度承诺）**：
1. 无工商/司法权威数据库 API，数据维度与权威性与企查查/天眼查专业版存在差距；
2. 利益冲突检索只能设计检索范围与比对清单，实查须律师使用本所案件库完成；
3. 无 7×24 持续监控能力，依赖第六之一节的定时复查机制近似实现；
4. 报告时效性以基准日为准，重大事项须触发即时复查。
