# 客户法律咨询答复

快速检索法规和案例，草拟专业但通俗的答复，结论先行，简短清晰，可直接复制发送。

## Phase 0上下文检测

搜索 outputs/*_case_profile.json → 按 type="NDR" 过滤 → ask_user 确认继承 → 未找到则创建新 Profile。继承确认后跳过已完成采集步骤。

***

如不确定当前场景应使用本技能还是其他分析类技能，参见 `ndr-standards.md` §10 分析类技能择技规则。

## 工作流

### Step 1理解问题

提取核心法律争议点。信息不足时请用户补充。

> **依据时效与程序前置（2026-08-31 补引）** 材料提取与依据时效遵循 `ndr-standards.md` §7.8：所涉法规、监管规则**必须**标注发布或最新修订日期与最后核验日；对拟议或历史行为**必须**说明适用行为时法还是评价时法；涉审批/备案/登记/前置许可/第三方同意/优先购买权/内部决议程序的，**必须**先行提示程序前置及未满足后果（未满足即交易不成立/不生效/存在瑕疵）；新旧或层级规则冲突**必须**明确取舍并说明理由，**禁止**并列罗列不作判断。⛔ **NDR 域不存在 §J 章节**（属法官文书公共标准）。

### Step 2检索法律依据

执行 `ndr-standards.md` §2.3.5（AI虚假案例防范）。**基座前置｜检索分级（B层试点·2026-09-04）：§0 订阅检测＋引用前核验（§2.1.1 三态/AI防幻觉）所有档位强制，不得降级。调研深度按案情风险分档：①高风险（涉新司法解释/新法施行初期/交易金额重大/对方可能援引新规）→ 双源强制（百宸库+互联网各≥2组+深度fetch≥2-3件）；②常规（无①情形）→ 单源主检≥2组＋另一源抽查1次交叉验证关键条号与规则时效。

> **法条核验**：引用前按 §2.1.1 标 ✅/⚠️/⛔，⚠️/⛔ 不入文书；规则全文在公共标准不重复。⛔ NDR 域不存在 §J，法条核验对位设施即 §2.1.1＋§7.8＋§15.4；答复细则/模板见 `references/consultation-guide.md`、`references/consultation-template.md`。

### Step 3草拟答复

| 原则 | 要求 |
|------|------|
| 结论先行 | 第一句直接回答，对话感，像面对面聊天 |
| 通俗 | 日常语言解释法律逻辑，“合同无效”不如“对你没有约束力” |
| 简短 | 200-500 字，每句不超过 40 字 |
| 有据 | 关键判断附法规或案例依据；不确定的说“建议进一步核实” |
| 实用 | 如需下一步操作，一两句话建议 |

不写免责声明——面向已有委托关系，不需每次附正式声明。

### Step 4交付

执行 `ndr-standards.md` §8.3 交付前强制自检。通过后方可生成为 Word。

> **法条状态与依据时效普检（2026-08-31 补引）** 交付前**必须**执行 `ndr-standards.md` §15.4 五项普检（法条状态／时效标注／时法选择／前置条件／冲突取舍）：法条锚点表中 ⚠️/⛔ 项**不得**出现在交付答复正文，⛔ 状态条文**禁止**作为依据引用；未获权威原文时按 §2.1.1 fallback 处理。

直接输出可复制文本块。如需输出到文件，写入 `/sandbox/workspace/outputs/`。

## 工作流示例

用户“客户问供应商延迟交货，合同没写违约金，怎么索赔？”

→ 检索民法典第577/584条、相关案例 → 答复

> 虽然没有约定违约金，但按照《民法典》规定，你可以要求赔偿实际损失。关键是把损失算清楚——比如因为延迟交货导致的生产停工费、向第三方支付的违约金这些，保留好相关凭证。建议先发个函正式催告并说明损失情况，给个合理期限。对方继续不理的话可以考虑起诉。

***

### 强制纪律（2026-08-31 B1 补强）

1. **必须**在 Step 2 完成基座检索（§0 订阅检测＋检索分级：高风险双源强制[库+网各≥2组+深度fetch]、常规单源主检≥2组+另一源抽查1次；引用前核验 §2.1.1 不分档强制），⛔ **不得**跳过检索。
2. 每条引用法条**必须**按 §2.1.1 三态核验并落入「法条锚点」表；⚠️ 状态条文**不得**写入答复正文；⛔ 状态条文**禁止**作为依据引用。
3. ⛔ **禁止**凭记忆给出条号；**禁止**引用未获官方原文印证的文件、条款、案例。
4. 结论**必须**有据：关键判断附法规或案例依据；不确定的**必须**说明「建议进一步核实」，⛔ **不得**含糊作答。
5. 金额、期限、比例等量化信息**必须**经两个独立来源（或源文件原件）交叉核对后方可写入；⛔ **严禁**杜撰金额或期限。
6. 涉刑、涉诉或重大交易敏感问题**必须**提示客户寻求正式法律意见，⛔ **不得**以口头答复替代正式意见书。
7. 交付前**必须**执行 §15.4 法条状态与依据时效普检＋§8.3 交付前强制自检；⛔ 未通过**不得**交付。

## 输出文件格式约束（统一底座）

本技能输出 `.docx` 须与三系（NDR/DR/Judge）统一格式底座一致，唯一事实来源见 `/sandbox/workspace/skills/baichen-ndr-standard/references/format_base.py`。跨系强制一致项：
- 页边距：上/下 2.54cm，左/右 3.18cm
- 行距：正文 1.5 倍
- 字体：正文仿宋_GB2312；标题字族按本系规范（DR 诉辩黑体 / 行政宋体等）
- 首行缩进：2 字符（约 0.85cm）
- 日期：落款日期强制中文大写（如「二〇二〇年八月三日」），调用 `format_base._to_chinese_date()`
- 文件名：`[文书类型]_[当事人]_[案由/事项].docx`（DR/NDR 同范式）

使用 ima-docx 生成时，须将上述默认样式对齐本底座，不得另行硬编码不一致格式。
