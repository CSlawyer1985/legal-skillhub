# 回归测试与验收

本文件只在修改或验证技能时读取。测试时使用真实 MCP 返回材料，不使用互联网补充，也不提前把预期法律答案泄露给执行者。

> 已有自动化回归套件：`mcp-hegui/regression/{cases.json,run.mjs}`（零依赖 node 跑批，内置『错误市场零混入 / 标题冒充命中 / mode 与 answerability 一致』不变量断言，退出码可用于 CI）。运行：`HEGUI_MCP_URL=… HEGUI_TOKEN=… node run.mjs`。改本技能或服务端后先跑它。**已知性能基线**：重 consult（2 子问题）约 47s、聚源负载下更慢；经阿里云 CDN 公网入口约 30s 回源超时会切断重查询（服务端已做附件跨请求缓存 + faguiDetail/标题轨并发，但聚源过载时并发受 fagui 连接池封顶）。

## 一、测试记录格式

每个测试记录：

```text
用户问题
用户已知事实
识别出的法律子问题
首次法规调用参数
通过和剔除的法规
每个子问题的内部路由状态
是否触发公告检索
公告查询词
采用和排除的公告
最终答复包含项
耗时和降级状态
```

## 二、必测场景

1. 法规明确要求公告且数据库存在同类案例；
2. 法规明确要求公告但数据库没有同类案例；
3. 披露取决于处罚机关、重大程度、金额或比例，用户事实不足；
4. 用户补齐条件后从 `conditional` 转为 `required`；
5. 法规明确不触发披露；
6. 法规正文不足，只能形成 `unknown`；
7. 同一问题同时涉及披露、任职资格和程序；
8. 法规候选混入错误板块或错误主体规则；
9. 法规只命中发布通知，需要解析数据库记录对应附件；
10. 公告标题相似但正文事项不同；
11. 公告原文件无法下载或为扫描件；
12. 公告检索超时但法规检索成功；
13. 没有公告需求的法规咨询不启动公告检索；
14. 用户要求外部联网补法规时，技能仍坚持数据库证据边界并说明限制。

## 三、关键案例

### 案例 A：处罚机关缺失

```text
创业板上市公司独立董事非因本公司事宜受到行政处罚，是否需要公告，是否影响任职资格？
```

预期行为：

- 拆分披露和任职资格两个子问题；
- 首次只查法规；
- 披露结论根据处罚机关、是否重大等正文条件形成 `conditional` 或有前提的分支，不硬判；
- 任职资格单独寻找直接条款；
- 条件未满足前不检索公告；
- 最终法规部分提供正式条款，不展示内部路由 JSON。

### 案例 B：用户补充为证监会行政处罚

预期行为：

- 对照已命中的直接披露条款判断条件是否满足；
- 条件满足时只为披露子问题检索“独立董事＋行政处罚/处罚决定”；
- 正文确认处罚是否属于其他单位或个人事项；
- 返回通过验证的公告及数据库原文件；
- 公告不得替代任职资格条款。

### 案例 C：错误案例

公告标题只含“独立董事述职报告”“董事会决议”或“公司受到行政处罚”。

预期行为：主体或事件不一致，全部排除，不得作为独立董事受罚案例。

### 案例 D：数据库无材料

预期行为：明确说明法规或公告数据库未命中，不调用互联网搜索，不用记忆补充条款和案例。

### 案例 E：其他披露事项

使用控股股东股份冻结、实际控制人留置、募集资金用途变更、对外担保或重大诉讼等问题验证通用性。

预期行为：根据实际法规触发事实动态生成“主体＋事件”公告查询，不使用独立董事专用逻辑。

## 四、验收标准

- 无直接法规依据时，确定性结论为零；
- 错板块和错误主体法规引用为零；
- 用公告反推法规结论为零；
- `required` 必须由直接披露条款和满足的用户事实支持；
- `conditional` 不得因存在相似公告而升级；
- 不应检索公告的子问题触发次数为零；
- 采用公告的板块、主体和事件匹配率为 100%；
- 需要正文确认的限定事实均有验证片段；
- 每个采用案例均附数据库记录对应的公告原文件；
- 最终法规部分均包含名称、文号、状态、条款原文和适用分析；
- 数据库无结果时不会转向独立互联网搜索；
- 公告失败或超时时法规部分仍能正常返回；
- 多问题分别作答，不互相替代。

性能测试另记录法规阶段、公告元数据阶段、正文验证阶段和总耗时。公告阶段应受服务端总时限约束，但性能不足不得降低证据标准。

## 五、完整法规原文回归（T01–T10）

针对"完整条文引用"的专项回归，配合 [full-text-verification.md](full-text-verification.md)、[citation-standard.md](citation-standard.md)：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T01 | excerpt 只返回多款条文的前两款 | 必须读取附件补齐最后一款，展示完整多款 |
| T02 | excerpt 从条文中间开始 | 不得直接引用，回查完整正文后再引 |
| T03 | excerpt 拼接了多个不连续条文 | 分别回查目标条款，不引用拼接文本 |
| T04 | 发布通知命中、正式附件可解析 | 用正式附件正文，不引用通知正文 |
| T05 | 扫描 PDF 无文字层 | OCR 后视觉核对；不可靠则降级、不作确定引用 |
| T06 | 附件下载或解析失败 | 说明技术性失败，不输出确定原文、不误判无规定 |
| T07 | 一个问题涉及两个法律子问题 | 每个子问题分别给直接条款的完整原文 |
| T08 | 条款极长 | 减少引用条数，但不得截断已引用条款 |
| T09 | 只列法规名称、条号和链接（无原文） | 测评判法规依据不通过 |
| T10 | JSON 标准答案与现行完整条文冲突 | 标记标准答案待复核，以现行原件为正确性闸门 |

### 必测案例（多款条文完整性）

**问题**：深主板上市公司控股子公司给上市公司提供担保，是否需要披露？

**法规**：《深圳证券交易所上市公司自律监管指引第1号——主板上市公司规范运作（2026年修订）》第 6.2.11 条。

**验收重点**：

- 自动摘录可能只返回前两款；正式 PDF 中第 6.2.11 条共有**三款**；
- 最终答复必须展示**三款完整原文**（可用 `scripts/validate_clause_completeness.py --article 6.2.11` 做确定性核验）；
- 适用分析须说明第二款仅排除第一款规定；
- 第三款（为第一款规定主体以外的其他主体提供担保）不得遗漏。

## 六、评分门槛与封顶规则

### 1. 法规依据正确性维度（25 分）拆分

| 子项 | 分值 | 判定 |
|---|---:|---|
| 法规适用性 | 4 | 板块、主体、事项、版本正确 |
| 名称/文号/状态 | 3 | 正式名称、文号、生效状态完整 |
| 条号定位 | 3 | 条号准确且直接覆盖问题 |
| 完整条文展示 | 10 | 从条号到下一条前，全部款项/但书/例外完整 |
| 原件与链接 | 3 | 来自 hegui 数据库记录或正式附件，链接可核验 |
| 原文/概括/分析分离 | 2 | 三部分明确区分 |

### 2. 单题硬性通过门槛

同时满足：总分 ≥ 85；法律结论准确性 ≥ 24/30；法规依据正确性 ≥ 20/25；**完整条文展示 ≥ 8/10**；无硬性错误。

### 3. 缺完整原文的封顶

出现任一项，法规依据正确性最高 **8/25** 且单题不通过：只列名称/条号/链接、只给规则概括无逐字原文、原文未从条号开始、在本条结束前截断、漏款项/但书/例外、用人工省略号删节、无法证明文字来自 hegui 数据库正文或正式附件。

### 4. 硬性错误（判不通过）

把不完整 excerpt 标为"完整原文"、因漏最后一款改变结论、把规则概括伪装成逐字原文、凭记忆补写条文、改动比例/期限/否定词/例外、使用错误板块/失效版本/征求意见稿。
