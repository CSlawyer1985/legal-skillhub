# 公告案例检索与验证

只有内部路由允许检索公告时使用本文件。公告只用于参考披露方式，不得反推法规结论。

## 目录

1. 数据来源
2. 查询输入
3. 分层召回
4. 通用查询模式
5. 正文验证
6. 采用与排除
7. 性能和失败处理

## 一、数据来源

1. 只使用公告数据库返回的记录。
2. 只使用数据库记录对应的公告 PDF、DOCX 或其他原文附件。
3. 不调用搜索引擎、浏览器、公司官网或其他公开网站寻找案例。
4. 数据库没有合格案例时直接说明，不能从互联网补充。

## 二、查询输入

从用户事实和已通过法规闸门的披露触发事实中提取：

```json
{
  "board": ["创业板"],
  "subject_terms": ["独立董事", "独董"],
  "event_terms": ["行政处罚", "处罚决定", "受到处罚"],
  "qualifiers": ["非因本公司事项", "在其他单位任职期间"],
  "required_groups": [
    ["独立董事", "独董"],
    ["行政处罚", "处罚决定", "受到处罚"]
  ]
}
```

不得加入用户未提供的处罚机关、违法类型、金额、比例或结论性事实。

## 三、分层召回

### 第一层：高精度复合词

优先使用“主体＋事件”：

```text
独立董事 行政处罚
实际控制人 留置
控股股东 股份冻结
募集资金 变更用途
```

第一层已经取得足够候选时停止，不再扩展。

### 第二层：规范同义词

第一层不足时，最多增加一至两个同义查询：

```text
独立董事 处罚决定
实际控制人 被采取留置措施
控股股东 所持股份被冻结
募投项目 变更
```

不得单独使用“董事会”“股东大会”“公司治理”“公司章程”“信息披露”“公告”等宽泛词。

## 四、通用查询模式

| 事项 | 主体词 | 事件词 |
|---|---|---|
| 人员受到处罚 | 董事、独立董事、高级管理人员 | 行政处罚、处罚决定 |
| 人员被采取措施 | 控股股东、实际控制人、董事 | 留置、立案调查、强制措施 |
| 股份权利受限 | 控股股东、实际控制人、股东 | 冻结、质押、司法拍卖 |
| 股份变动 | 股东、董监高 | 减持计划、减持进展、权益变动 |
| 资金和担保 | 上市公司、控股子公司 | 对外担保、资金占用、财务资助 |
| 交易事项 | 上市公司、关联方 | 关联交易、资产购买、资产出售 |
| 募集资金 | 上市公司、募投项目 | 变更用途、延期、结项、补充流动资金 |
| 经营风险 | 上市公司 | 重大诉讼、仲裁、停产、债务逾期 |

表中词组只作为召回模板。实际查询必须保留用户主体和事件，不得把一个事项替换成另一个法律事实。

## 五、标题与正文分工

- 标题负责召回主体和核心事件。
- 正文负责验证标题通常不包含的限定事实。

以下事实通常必须进入正文验证：

```text
非因本公司事项
在其他单位任职期间
是否影响履职
是否属于重大行政处罚
是否达到金额或比例标准
是否为关联方
是否经过审议或追认
```

正文片段至少覆盖所有 `required_groups`，并能确认公告描述的是同一类事件，而不是制度说明、会议意见或一般任免。

## 六、采用与排除

### 可以采用

- `title_verified`：标题已经明确同时包含主体和事件，且不存在需要正文确认的关键限定事实。
- `content_verified`：正文片段确认主体、事件和全部必要限定事实。

### 必须排除

- 板块不一致；
- 主体不同，例如公司受罚被误当作独立董事受罚；
- 事件不同，例如监管问询被误当作行政处罚；
- 只命中“独立董事”“董事会”等宽泛词；
- 公告只是述职报告、会议决议、制度说明或普通任免；
- 原文无法访问且标题不足以完成事实验证；
- 正文片段没有覆盖必要限定事实。

采用的公告至少保留：数据库 ID、公司、代码、板块、标题、日期、匹配事实、验证片段、验证状态、文件类型和原文件地址。

## 七、性能和失败处理

1. 每个披露事项最多执行二至三个复合查询。
2. 默认查询最近三年，返回不超过八条候选。
3. 最多下载并验证前两条正文；精确标题已足够时避免不必要下载。
4. 一个查询已取得足够案例时停止回退。
5. 公告阶段超时、数据库失败或附件解析失败时，保留法规答复并标记公告部分暂不可用。
6. 没有通过验证的案例时，输出“本次公告数据库未检索到经正文验证且事实同类的案例”。
7. 不因公告缺失、超时或解析失败修改已经形成的法规结论。
