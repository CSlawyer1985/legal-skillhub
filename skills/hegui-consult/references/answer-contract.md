# 最终答复契约

最终答复必须向用户提供正式法规证据和可核验的公告原文件。内部路由只控制流程，不进入答复正文。

## 目录

1. 固定顺序
2. 结论及适用前提
3. 正式法规依据
4. 适用的公告格式
5. 公告参考案例
6. 待核实事项与风险
7. 检索审计
8. 数据来源措辞

## 一、固定顺序

1. 结论及适用前提；
2. 正式法规依据；
3. 适用的公告格式（补取到时）；
4. 公告参考案例；
5. 待核实事项与风险；
6. 必要时给出检索不足说明。

## 二、结论及适用前提

逐个法律子问题回答，并明确区分：

- **确定结论**：存在适用且直接覆盖的法规原文，用户事实满足条款条件；
- **附条件判断**：法规条件明确，但用户事实尚未完全补齐；
- **无直接依据**：数据库正文不足、适用性不明或 coverage 未覆盖。

不要把内部 `required`、`conditional` 等英文状态直接展示为法规结论。

对广泛问题（“某类事项是否合法/是否需要公告/某类人员能否任职”）**默认输出通用规则 + 条件式结论**，不强行收敛为单一“是/否”：规则有统一口径直接答；按板块区分则分别列口径；按主体或条件区分则给“情形 A→结论及依据 / 情形 B→…… / 情形 C→暂无直接依据”，最后只列确定具体情形所需的**最少非识别性事实**。不得为收敛结论而索取公司名称、姓名、代码等识别性信息（见 [clarification-policy.md](clarification-policy.md)）。

## 三、正式法规依据

每项法规必须包含：

```text
法规完整名称
文号
生效状态
颁布日期
适用板块或主体
具体条款号
条款完整原文（逐字引用正式法规原件中的完整条文，非截断摘录）
数据库记录对应的法规原文件
规则概括
适用分析
```

只引用 `applicability.passed=true`、且当前子问题被 `coverage`/`excerpt` 命中**或**经法规原件全文核验定位的材料。法规标题命中但正文为空、仅有发布通知或附件未解析时，不得列为正式依据。

`excerpt` 是**检索线索、不是完整原文**。展示“条款完整原文”前，必须按 [citation-standard.md](citation-standard.md) 从正式原件确认条文边界（从条号起、到下一条条号前止，含全部款项目、但书、例外），**逐字引用、不加省略号、不缩写改写**；`excerpt` 从条文中间起、截断、拼接或缺款项时，须读原件全文定位后再引用。条款是在自动 `excerpt` 未命中、经 [retrieval-strategy.md](retrieval-strategy.md) 第五节从原件全文定位到的，须注明“**该条款由 hegui 返回的法规原件全文定位**”。不得把无关摘录列为依据，也不得隐瞒自动摘录发生过意图漂移。

**原文、规则概括、适用分析三者必须分开**，不得把概括或分析包装进原文引用框。固定格式（详见 citation-standard.md 第九节）：

```markdown
### 《法规完整名称》（正式文号，现行有效）

- 发布日期：　- 施行日期：　- 适用范围：　- 具体条款：　- 法规原文件：[链接]()

**条款完整原文：**

> 第×条　……
>
> （一）……
>
> （二）……

**规则概括：** 用非引用格式概括该条规则。

**适用分析：** 将用户事实与条款的主体、行为、条件、比例、时限、例外逐项对应。
```

必须明确标记分析性质：

- “条文直接规定”：法规原文明示；
- “根据条文推导”：主体或事实与条文对应后的推论；
- “无直接规定”：数据库未检索到可支持确定结论的正文。

发送前对每段法规原文过一遍 citation-standard.md 第十节自检清单（条号完整、款项无遗漏、但书例外无删、数字比例期限否定词与原件一致、无人工省略号），任一项不满足即不得贴出该段原文。每条须先过 [full-text-verification.md](full-text-verification.md) 的 `quote_ready` 闸门。

**控制引用数量，而不是截断条文**：怕篇幅过长时，**减少引用的法规条数**——只选直接支持结论的必要条款；但一旦选择引用某条，就必须展示该条**完整原文**，不得靠删减同一条内部的款/项/但书来压缩长度。

## 四、适用的公告格式

仅当按 [format-retrieval.md](format-retrieval.md) 补取到公告格式文件时列出；未触发补取或库中未命中时省略本节或一句话说明“未在库中检索到该板块对应的现行公告格式文件”。每项包括：

```text
公告格式文件全名
文号
生效状态
对应“第几号”模板（事项明确时）
可下载附件地址（DOCX/交易所官网实际格式文件）
```

建议格式：

```markdown
依据上述条款，本事项公告应按交易所规定格式编制：

- 《深圳证券交易所上市公司自律监管指南第2号——公告格式（2026年7月修订）》（深证上〔2026〕920号，现行有效）
  对应模板：第X号 ×××公告
  [下载公告格式模板（DOCX）](附件地址)
```

只列 `applicability.passed=true`、板块一致、`coverage` 含 `"format"`（或标题即“……公告格式……”）且带可下载附件的格式文件。公告格式是“按什么模板写这份公告”，仍以法规条款作为“要不要披露”的依据，不得用格式文件反推披露义务。

## 五、公告参考案例

只列 `title_verified` 或 `content_verified` 的公告。每项包括：

```text
公司名称
证券代码
所属板块
公告标题
发布日期
与本事项相同的事实
正文验证片段（如需）
数据库记录对应的公告原文件
```

建议格式：

```markdown
1. 某公司（300XXX），《公告标题》，2026年X月X日

   同类事实：……

   正文验证：……

   [查看公告原文（PDF）](数据库记录对应的公告文件地址)
```

公告部分统一注明：

> 公告案例仅用于参考市场披露方式和实践口径，不能替代法规判断。

没有合格案例时写明：

> 本次公告数据库未检索到经正文验证且事实同类的公告案例。

不得省略“数据库”，也不得通过外部网站补充案例。

## 六、待核实事项与风险

只列会改变结论的事实，例如：

- 处罚或监管机关；
- 违法事项及所属领域；
- 是否属于重大行政处罚；
- 是否伴随市场禁入或不适当人选认定；
- 金额、比例、发生时间和公司知悉时间；
- 是否影响履职；
- 是否确与本公司无关。

## 七、检索审计

材料不足时，用简短自然语言说明：

- 已按哪些法律焦点重试；
- 哪些候选因市场或主体不适用被剔除；
- 哪些候选只有标题而缺少正文；
- 公告是否因超时或原文不可解析而未采用。

不要展示内部 JSON、数据库连接、鉴权信息、完整调用日志或工具错误堆栈。

## 八、数据来源措辞

可以说明：

> 本答复的法规和公告材料均来自已配置 MCP 所连接的法规、公告数据库及数据库记录对应的原文附件；未使用独立互联网检索补充材料。

仅在有助于解释材料边界时加入该说明，无需在每一段重复。
