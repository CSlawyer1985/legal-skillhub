# 法规完整条文核验方法

本文件是 [citation-standard.md](citation-standard.md)（引用规范/禁止行为/定义）的**方法层**：规定如何从正式原件定位并截取完整条文、如何用 `quote_ready` 闸门控制输出、如何处理 PDF/DOCX/OCR 与 excerpt 冲突。核心前提:`regulations[].excerpt` 只是**定位线索**，不等于完整条文；凡用于确定结论或展示给用户的条款，都要过本文件的核验与闸门。

## 一、条文边界识别

支持的条号格式（起止定位都按这些形态匹配）：

```text
第六条        第六十三条        第六条之一
6.2.11        7.2.1            （交易所业务规则的层级编号）
```

**截取规则**：

1. 定位目标条号的起始位置；
2. 定位**下一条同级条号**（如 6.2.11 的下一条是 6.2.12；第六条的下一条是第七条）；
3. 截取两者之间的**全部文字**；
4. 不把上一条尾部、章节标题混入本条；
5. 条文跨页时**连续提取**，不因翻页丢段；
6. 页眉、页脚、页码可清理，但不得改动正文内容；
7. 只允许规范化排版换行与多余空格，**不得改写文字、标点、数字或其含义**；本条为法规末条时，截取至该法规正文结束。

## 二、完整正文证据闸门（quote_ready）

每个法律子问题、每条拟引用法规，内部先形成如下状态（**不展示给用户**，仅用于把关）：

```json
{
  "legal_issue": "disclosure",
  "regulation_id": "法规数据库ID",
  "article_number": "6.2.11",
  "source_type": "database_content | attachment_pdf | attachment_docx | attachment_html | ocr",
  "source_url": "数据库记录或正式附件地址",
  "full_text_verified": true,
  "starts_with_article_number": true,
  "ends_before_next_article": true,
  "all_paragraphs_included": true,
  "quote_ready": true
}
```

`quote_ready=true` 须**同时**满足：

- `applicability.passed=true`；
- `coverage` 直接覆盖当前法律子问题；
- `content_status` 为 `parsed` 或 `attachment_parsed`；
- 已定位本条条号，且已定位下一条同级条号（或确认本条为末条）；
- 本条全部文字已提取；
- 条号、关键数字、比例、期限、否定词（应当/可以/不得/不适用）已核对；
- 来源链接来自 hegui 数据库记录或其解析出的正式附件。

**任一不满足 → 该材料不得作为完整条文输出。** 只有 `quote_ready=true` 的条款才能进入答复的「条款完整原文」。

## 三、引用前完整性检查清单

```text
[ ] 以目标条号开头
[ ] 在下一条之前结束
[ ] 所有自然段完整
[ ] 所有"前款/本条/前项"指代的内容均已包含
[ ] 所有款、项、目完整
[ ] 但书、除外、豁免完整
[ ] 数字、比例、期限完整
[ ] "应当/可以/不得/不适用"等规范词准确
[ ] 未加入人工省略号
[ ] 原件地址可核验
```

## 四、PDF / DOCX / OCR 处理

- **可检索 PDF**：提取文本后，再渲染目标页做视觉核对，防止分栏/表格错序；
- **DOCX**：读取完整段落，按条号边界截取；
- **HTML / TXT**：保留正文顺序与层级；
- **扫描 PDF（无文字层）**：允许 OCR，但必须逐字核对条号、数字、比例、期限、否定词，并在引用框外标注"以下文字由法规原件扫描页 OCR 识别并经页面核对"；
- **OCR 不可靠**（错字/乱码/无法确认）：不得作确定引用，降级说明。

## 五、excerpt 与正式原件冲突

**正式附件优先于自动摘录。** 发现 excerpt 从句中开始、提前结束、缺款项、拼接不连续条文或错行时：

1. **不引用** excerpt；
2. 用正式附件定位的完整条文替代；
3. 内部记 `excerpt_incomplete=true`；
4. 答复中注明"该条款由 hegui 返回的法规原件全文定位"，无需展示内部日志。

触发附件全文核验的情形（任一即触发，与 [retrieval-strategy.md](retrieval-strategy.md) 第五节一致）：excerpt 从句中开始 / 无条号 / 命中本条却无下一条条号 / 本条含"前款""本条第一款"等指代而摘录未展示对应款 / 夹杂其他不连续条文 / 只命中发布通知而正式附件未展开 / 用户明确要求法规原文 / 同一条存在多款项目或但书。

## 六、无法取得完整正文时的降级

技术故障、附件损坏、扫描件无法识别或数据库只返回不完整摘录时：写明"本次未能取得足够完整的法规正文"，**不展示截断摘录、不把概括写成原文、不凭记忆补写、不仅凭名称+条号+链接作确定结论**。三类分开表述：

- **工具超时 / 附件下载失败 / OCR 失败** → 技术性失败（不得说"无规定"）；
- **完整正文可读但无直接条款** → "未在该现行法规原件中检索到直接表述"；
- **自动摘录未命中** → 召回/摘录问题，必须继续查原件，尚不能认定法规无规定。

## 七、可选确定性校验脚本

对"多款条文是否被完整引用"可用 `scripts/validate_clause_completeness.py` 做确定性检查（输入正式附件全文 + 目标条号 + 待发答复，输出 `complete_match`/`ellipsis_detected`/`missing_segments`）。脚本只查**格式与完整性**，不判适用性；适用性仍由证据闸门处理。能跑脚本的客户端（Claude Code / Codex / Trae 等）在引用长的多款条文前建议跑一次。
