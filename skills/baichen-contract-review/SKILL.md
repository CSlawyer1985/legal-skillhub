# 合同审查

站在指定方立场，按 12 步审查法对合同进行系统性审查。先做风险分级校准深度，再四象限分层逐条审查。输出审查意见书（法律备忘录格式），docx 格式默认同时输出三文档。

| 步骤 | 要点 |
|------|------|
| 0. 格式预检 | 非 docx 格式须询问用户能否提供 docx |
| 1. 立场与法域 | 审查立场 + 适用法律（必问，2项），补充信息合并征询 |
| 2. 通读全文 | fetch 读取合同，识别类型、主体、交易结构 |
| 2.5. 客户意见 | 主动询问修改意见，3-5条提示性提问 |
| 2.6. 风险分级 | 按合同类型/金额/期限/风险信号判定高/中/低风险，校准审查深度 |
| 3. 12步审查 | 四象限分层→逐条审查+Playbook比对+强制知识检索+替代条款生成+缺失条款检查 |
| 4. 输出文档 | 审查意见书（按象限分组）+（docx时）修改版合同+修正版干净合同 |

## Phase 0文件格式预检

**最先执行。** `.docx`→直接进入 Phase 1；非 docx 格式→ask_user 能否提供 docx（无法提供则仅出审查意见书）。`.doc` 不属于 docx 格式。

## Phase 1需求确认

审查立场和法域为两个必问项，未指定时须逐项询问，不得默认推断。

| 确认项 | 执行要求 |
|--------|---------|
| 审查立场 | 甲方还是乙方？须说明该方在合同中的具体角色 |
| 法域 | 依据哪个法域法律审查？须解释不同法域对审查结果的影响 |

**输出交付物**默认输出全部支持类型。docx→同时生成审查意见书+修改版合同+修正版干净合同；非docx→仅审查意见书。客户明确要求跳过某项时才省略。

**可选补充信息（合并征询）**交易地位（强势/平等/弱势）、对方已有的修改意见、最关注的条款、交易金额与期限。

**交易地位影响**低风险强势→全面优化，有利版；中风险平等→平衡审查，平衡版为主；高风险弱势→防守为主，象限四底线不可退，底线版。未提供时默认中风险平等。

### 上浮判断

合同涉及以下领域时，须分流至对应技能处理：

| 触发关键词 | 对应技能 | 说明 |
|-----------|---------|------|
| 离婚协议 / 婚前协议 / 婚内协议 / 遗嘱 / 遗赠扶养 / 意定监护 | **婚姻家庭与继承** | 婚姻家庭与继承领域由 婚姻家庭与继承 技能专有处理，不做通用 12 步审查 |

## Phase 2.5询问客户修改意见

**必须主动询问。** 每轮至少 3 个具体条款的修改意向征询，最多 5 个。问题须嵌入具体合同条款原文。客户有明确意见的以客户意见为准。

## Phase 2.6风险分级

依据以下维度快速判定合同风险等级，校准后续审查深度

> **风险分级统一标准（强制引用）**：本节及本技能全文的「高风险/中风险/低风险」判定，一律以 `ndr-standards.md` §9（风险评级统一标准）三级评级为准，⛔ 不得自行定义另一套评级。**术语对齐：P0 ＝高风险、P1 ＝中风险、P2 ＝低风险**（本技能既有「高/中/低风险」表述与 §9 一一对应，含义不变；P0/P1/P2 仅用于内部标识，对客户交付文本统一写「高风险/中风险/低风险」）。§9 触发条件：高风险（P0）＝可能影响交易可行性、导致重大损失或违反强制性法律规定；中风险（P1）＝可通过交易条款设计或整改措施控制在可接受范围；低风险（P2）＝符合法律规定或仅有轻微瑕疵。

| 维度 | 高风险 | 中风险 | 低风险 |
|------|----------|----------|----------|
| 合同类型 | 建设工程/技术开发/并购 | 服务/租赁/借款 | NDA/意向书 |
| 交易金额 | ≥1000万或未知 | 100-1000万 | <100万 |
| 期限 | ≥3年 | 1-3年 | <1年 |
| 风险信号 | 含连带担保/IP归属/竞业限制 | 含违约金/保密条款 | 无特殊风险条款 |

### 三维风险评分矩阵

每条审查发现的风险条款，按以下三维进行 1-5 级评分：

> **与 NDR §9 的挂钩关系（强制）**：本矩阵是 `ndr-standards.md` §9（风险评级统一标准）在合同审查场景的**量化细化**，不是另一套评级——综合评分 5 分 → §9 高风险（P0）；3-4 分 → §9 中风险（P1）；1-2 分 → §9 低风险（P2）。⛔ 评分结论与 §9 触发条件冲突时以 §9 为准（§9 明定「各技能引用本定义，不得自行定义另一套评级标准；如需细化必须以本定义为基础追加说明而非覆盖」）。

| 维度 | 1级（低） | 3级（中） | 5级（高） |
|------|---------|---------|---------|
| **条款缺失度** | 条款存在但可优化 | 条款部分缺失 | 核心条款完全缺失 |
| **权利义务失衡度** | 轻微倾斜可接受 | 明显不对等 | 严重失衡可能显失公平 |
| **商业目标偏离度** | 措辞可微调 | 实质偏离意图 | 完全违背交易目的 |

**综合风险评分 = max(缺失度, 失衡度, 偏离度)**
- 5分 → 🔴 高风险（必须修改，不可接受）
- 3-4分 → 🟡 中风险（建议修改，有优化空间）
- 1-2分 → 🟢 低风险（可接受，可优化）

评分结果在审查意见书中逐条标注。

以最高维度为准。高风险→12步全量+Playbook逐条比对+强制检索；中风险→12步全量，象限三仅查红旗；低风险→仅查象限一/四+缺失条款检查，Playbook仅比红旗项。分级结果须在审查意见书中注明。

## Phase 312步逐条审查

**先加载**`references/review-steps.md`（审查要点）+ `playbook.md`（统一 Playbook，低风险=理想/安全区，中风险=折中区，高风险=红线区）。 ⛔ **并须同时加载 `references/review-playbook.md`（本技能自有审查 Playbook）**——按甲方/乙方立场分别给出条款级「可接受标准 ＋ 红旗警示 🚩 ＋ 替代方案」，覆盖违约责任/赔偿范围/知识产权归属/保密/争议解决/合同解除/付款/不可抗力 8 类通用高频条款，及买卖/服务/技术开发/租赁/劳动 5 类特定合同类型审查要点，另含「比对流程—立场感知—红旗优先」三项使用规则；具体调用见下文「审查 Playbook 比对」。三份文件缺一不可，⛔ 不得只取其一。

> **Playbook 与 Clause Library 分离**：`playbook.md` 为决策规则库（什么情况下构成什么风险等级），../baichen-contract-drafting/references/clause-framework.md 为条款素材库（标准条款文本三档）。审查时先查 Playbook 确定审查基线，再对照 Clause Library 出替代方案。

### 强制知识检索（不可跳过）

**基座前置｜双源检索（强制，不可跳过）**：执行 `ndr-standards.md` §0（订阅检测）+ §1（双源检索：百宸库 + 互联网各 ≥2 组 + 深度fetch≥2-3件库+2件网）。NDR 补充检索合同类型+核心风险点+法域依据；无直接相关结果时须在审查意见书中注明。

### 强制性法规更新核对（2024-2025·审查红线）
执行 ../baichen-contract-drafting/SKILL.md 强制性法规更新核对块（法释〔2023〕13号+新公司法，条款以最新为准）；审查时额外核对格式条款**电子合同仅设勾选、弹窗不足以认定已履行提示或说明义务**（法释〔2023〕13号第10条第3款；提示义务见第10条第1款、说明义务见第10条第2款，二者均对应《民法典》第496条第2款）。

### 审查 Playbook 比对

**12步审查中每步条款必须与 `playbook.md` 逐项比对**通过符合→无需标注；中风险有优化空间→建议修改，出替代方案；🚩触发红旗→高风险，必须重点标注并出替代方案。比对以 Phase 1 确认的审查立场为准。

**同时须逐条比对本技能自有审查 Playbook `references/review-playbook.md`（强制加载，不可跳过）**：该文件按 Phase 1 确认的立场（甲方/乙方、委托方/受托方）分列每类条款的**可接受标准**、**红旗警示 🚩**与**替代方案**，用途为——①判定当前条款相对本方立场是「通过／中风险／🚩 红旗」；②对 🚩 与中风险条款直接取用其「替代方案」栏生成可嵌入合同的替代措辞；③按其「二、特定合同类型审查规则」补足买卖/服务/技术开发/租赁/劳动合同的类型专属审查点；④按其「三、Playbook 使用规则」执行「识别条款→读取 Playbook→比对判定→输出建议」四步流程与「红旗优先原则」（红旗项必须全部识别并以高风险标注）。

> **双 Playbook 分工（⛔ 两者并存，不得互相替代）**：`playbook.md` ＝ F-N-1 家族**统一 Playbook**（理想/安全区—折中区—红线区三档，决定审查基线与风险档位）；`references/review-playbook.md` ＝ 本技能**审查专用 Playbook**（按立场给可接受标准＋红旗＋替代方案，决定单条款判定结论与替代措辞）。执行顺序：先统一 Playbook 定基线 → 再 review-playbook 定立场化判定与红旗 → 最后对照 ../baichen-contract-drafting/references/clause-framework.md（条款素材库）落地替代条款文本。低风险合同亦须至少比对 review-playbook 的红旗项（见 Phase 2.6 分级要求）。

### 替代条款生成

发现 🚩 或 中风险 条款时，须提供可直接嵌入合同的替代条款措辞。读取 playbook 三档方案→按 Phase 1 立场匹配层级→输出替代条款标注方案层级（低风险有利/中风险平衡/高风险底线）。（三档方案取自 `playbook.md`；🚩 红旗项与中风险项的**立场化替代措辞**取自 `references/review-playbook.md` 各条款的「替代方案」栏，例如违约金过低→增加迟延履行按日违约金＋根本违约独立违约金，违约金过高→设上限并排除间接损失。）

### 条款四象限分层审查

| 象限 | 定位 | 审查策略 | 篇幅 | Playbook比对 | 替代方案 |
|------|------|---------|------|-------------|---------|
| **象限一核心条款** | 合同基石（主体/标的/价款/期限/质量） | 深度审查，逐字逐句 | 40% | 全部比对 | 有风险必出 |
| **象限二支持性条款** | 保障核心履行（知识产权/保密/不可抗力/变更解除/附件效力） | 重点审查权利义务边界 | 30% | 全部比对 | 仅高风险中风险出 |
| **象限三效率优化条款** | 降低沟通成本（通知送达/联系人/生效份数/争议前置） | 快速审查格式规范 | 10% | 仅比红旗项 | 仅高风险出 |
| **象限四保障与救济条款** | 最坏安全网（违约责任/争议解决/终止后义务/完整协议） | 防守审查保底线 | 20% | 全部比对 | 仅高风险中风险出 |

跨象限以主要功能归属为准；象限三地址完整+方式明确+生效清楚→通过。

### 12步逐一审查

| 步骤 | 审查重点 | 象限归属 |
|------|----------|---------|
| 1. 交易情况 | 合同结构完整性、格式条款识别 | 全局 |
| 2. 合同名称 | 名称与法律关系一致性 | 象限一 |
| 3. 合同效力 | 无效情形、格式条款效力、显失公平 | 象限一/四 |
| 4. 缔约程序 | 招投标、政府采购、分包同意 | 象限一 |
| 5. 合同主体 | 主体适格性、资质、信息完整性 | 象限一 |
| 6. 合同标的 | 合法性、处分权、明确性 | 象限一 |
| 7. 支付条款 | 价格明确性、支付条件、背靠背条款 | 象限一 |
| 8. 履行期限 | 期限合理性、调整权分配 | 象限一 |
| 9. 质量验收 | 质量标准、验收程序、救济途径 | 象限一/四 |
| 10. 权利义务 | 对等性、放弃权利条款效力 | 象限一/四 |
| 11. 违约责任 | 与义务对应、对等性、违约金合理性 | 象限四 |
| 12. 其他条款 | 不可抗力、通知送达、争议解决、保密、知识产权、签署 | 象限二/三/四 |

### 缺失条款完整性检查

| 检查维度 | 常见缺失 | 建议 |
|---------|---------|------|
| 验收标准 | 无验收节点/瑕疵处理机制 | 增加验收条款 |
| 知识产权 | 涉及创作/技术但无IP条款 | 增加归属+许可条款 |
| 保密 | 涉及敏感信息但无保密条款 | 增加保密条款 |
| 不可抗力 | 长期合同无不可抗力条款 | 增加不可抗力条款 |
| 通知送达 | 无通知送达地址条款 | 增加，影响后续程序性权利 |
| 合同生效与期限 | 无生效条件或期限约定 | 明确生效条件和有效期 |

缺失条款检查结果纳入审查意见书"合同结构完整性"，以表格呈现。

### 对方书面确认识别与条款转化

扫描谈判往来邮件/会议纪要/函件中的对方书面确认（交付标准、时限、金额、验收条件），与合同条款逐项比对——对方已书面确认但未写入合同的，即谈判成果流失风险（履行时对方否认），提示转化为合同条款或附件；对方书面确认与合同条款矛盾的，以合同为准并提示风险。

### 审查原则

| 原则 | 要求 |
|------|------|
| 客户意见/立场优先 | 客户修改意见优先体现在修改版；始终站在指定方识别不利益条款 |
| 法域适配 | 依据指定法域引用条文，注意不同法域术语差异 |
| 风险分级 | 高风险（无效/重大损失）> 中风险（不对等但可能有效）> 低风险（建议优化） |
| 建设性建议 | 不仅指问题，还给出可操作修改方案 |
| 行文要求 | 结论先行；告知改与不改的后果差异；区分理想版/底线版 |

> 本表「风险分级」行与 NDR §9（风险评级统一标准）一致，详见 `ndr-standards.md` §9；P0/P1/P2 与高/中/低风险的对应关系见 Phase 2.6。
> 本表「行文要求」「建设性建议」两行与 NDR §7.1（结论先行 CRAC）、§7.5（建议引出语）、§7.7（建设性建议）含义一致，**保留本表原文不变**，写作规则整体详见 `ndr-standards.md` §7（写作规范补充）；其中 §7.2（一句一意，单句≤60 字）、§7.3（读者分层）、§7.4（自指称规范：声明/行动用「本所」）在审查意见书正文同样适用。

## 交付前质量保障

### 自检 (§15)

执行 `ndr-standards.md` §15 全部自检项（格式4项+内容4项+去AI化3项），逐项通过。

先读取 `references/memo-template.md`（**法律备忘录模板**：页眉「保密文件」／标题区表格（日期·收件人·发件人·事由）／致辞／四部分正文（一、合同主体审查　二、风险条款与修改建议　三、审查结论　四、后续谈判策略）／结语／落款，另含 docx 格式规范表；⛔ **勿与 ../跨境投资/references/memo-template.md**（跨境合规路径分析备忘录，11 章＋决策树结构）**混淆**——两文件同名异构，引用时必须写全相对路径，并核对文件首行标题为「# 法律备忘录模板」）。结构

1. 页眉"保密文件"；标题区表格（日期/收件人/发件人/事由）；致辞（替换占位符）
2. 正文（顺序固定）一、合同主体审查 → 一之二、合同结构完整性 → 二、风险条款与修改建议（象限一→二→四→三，高风险→中风险→低风险降序，客户意见优先标"客户意见"）→ 三、审查结论+风险定位 → 四、后续谈判策略（必须争取/可以折中/可以放弃）
3. 结语；落款北京市百宸（上海）律师事务所 + 中文大写日期

格式正文仿宋_GB2312 12pt首行缩进 2 字符 1.5 倍行距；风险项标"高风险/中风险/低风险"不用 emoji。（字体常量由 format_base 锁定，禁止本地硬编码）调用 `scripts/generate_memo.py` 生成 Word。

> 本段「风险项标高风险/中风险/低风险、不用 emoji」与 NDR §7.6（风险标注）一致，**原文保留不变**，详见 `ndr-standards.md` §7.6；风险等级定义见 §9，排版与自指称要求见 §7.2／§7.4。
