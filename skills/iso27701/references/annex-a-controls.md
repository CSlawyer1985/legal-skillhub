# ISO 27701:2025 附录 A——完整控制项参考

ISO/IEC 27701:2025 包含三个表中的 **78 项控制**：
- **A.1**：针对个人信息控制者（PII Controllers）的 31 项控制
- **A.2**：针对个人信息处理者（PII Processors）的 18 项控制
- **A.3**：共享信息安全控制（两种角色均适用）29 项

**编号说明：** 在每个领域中，.1 是领域目标声明（不是编号控制项）。控制项从 .2 开始。例如，A.1.2.1 是 A.1.2 领域的目标；控制项从 A.1.2.2 起。

---

## 表 A.1——个人信息控制者控制项（31 项）

作为个人信息控制者行事的组织必须实施所有适用的 A.1 控制项以及所有 A.3 控制项（共 60 项）。

---

### A.1.2——收集与处理的条件（8 项控制）

**领域目标**：确保个人信息仅在建立明确、有记录的法律依据的条件下收集和处理，且处理对相关方透明。

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.1.2.2 | 识别并记录目的 | 记录收集个人信息的具体目的；目的必须在收集开始前说明 | 目的陈述模糊或兜底式；处理活动记录（RoPA）中未记录目的 |
| A.1.2.3 | 识别法律依据 | 识别并记录每项处理活动的法律依据（同意、合同、法律义务、重大利益、公共任务、合法利益） | 无逐活动法律依据映射；合法利益主张未完成合法利益评估（LIA） |
| A.1.2.4 | 确定同意 | 在同意为法律依据时，界定何时及如何取得同意；确保其达到所需标准（自由给予、具体、知情、明确） | 预勾选框；捆绑式同意；无取得同意的记录 |
| A.1.2.5 | 获取并记录同意 | 实施机制以捕获、记录和维护同意的证明 | 无同意审计追踪；无法检索特定个人的同意记录 |
| A.1.2.6 | 隐私影响评估 | 对新的或重大变更的处理活动开展隐私影响评估（PIA）/数据保护影响评估（DPIA）；记录结果和决定 | PIA 流程存在但未一致触发；高风险处理无 DPIA |
| A.1.2.7 | 与个人信息处理者的合同 | 确保所有个人信息处理者均依据载明义务的书面数据处理协议（DPA）聘用 | 处理者合同缺失；旧合同无符合 GDPR 的 DPA 条款 |
| A.1.2.8 | 共同个人信息控制者 | 在两个组织共同确定目的时，记录共同控制者安排及各方义务 | 共同控制者安排未记录；责任未界定 |
| A.1.2.9 | 个人信息处理记录 | 维护涵盖所有处理操作的完整处理活动记录（RoPA） | RoPA 不完整、过时或未维护；系统变更时无更新流程 |

### A.1.3——对个人信息主体的义务（10 项控制）

**领域目标**：确保个人信息主体能够行使其权利，并获得关于其个人信息如何被处理的充分信息。

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.1.3.2 | 对个人信息主体的义务 | 建立并记录组织对个人信息主体的义务以及履行这些义务的机制 | 无记录在案的义务登记册；权利未映射至流程 |
| A.1.3.3 | 向个人信息主体提供的信息 | 确定在收集之前或收集时须向个人信息主体提供哪些信息 | 隐私声明未涵盖所有必需信息要素 |
| A.1.3.4 | 提供信息 | 以清晰、可获取、及时的方式向个人信息主体提供所需信息（通常通过隐私声明） | 隐私声明难以找到；信息以复杂的法律语言呈现 |
| A.1.3.5 | 修改或撤回同意 | 为个人信息主体提供修改或撤回先前同意且不遭受不利的机制 | 无撤回机制；将撤回当作删除而非同意变更处理 |
| A.1.3.6 | 反对个人信息处理 | 为个人信息主体提供反对处理的机制（特别是针对合法利益或直接营销） | 无记录在案的反对流程；无响应时限承诺（SLA） |
| A.1.3.7 | 访问、更正或删除 | 为个人信息主体提供访问其数据、请求更正不准确之处或请求删除（删除权/被遗忘权）的机制 | 无数据主体请求（DSR）工作流；删除请求未传播至所有系统 |
| A.1.3.8 | 告知第三方 | 在个人信息被更正或删除时，告知曾向其披露该信息的相关第三方 | 更正/删除后无跟踪并通知第三方的流程 |
| A.1.3.9 | 提供个人信息副本 | 应请求向个人信息主体提供其个人信息副本（访问权/数据可携权） | 无自动化或简化的方式履行主体访问请求 |
| A.1.3.10 | 处理请求 | 建立接收、跟踪、认证和回应所有类型数据主体请求并符合规定时限的流程 | 请求临时处理；无 SLA 跟踪；身份验证流程缺失 |
| A.1.3.11 | 自动化决策 | 在使用具有重大影响的自动化决策时，披露该情况并提供人工复核机制 | 自动化决定未披露；无退出或申诉机制 |

### A.1.4——设计及默认隐私保护（9 项控制）

**领域目标**：将隐私原则嵌入系统和流程的设计与运行中，确保个人信息仅在必要范围内被收集和处理。

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.1.4.2 | 限制收集 | 仅收集为既定目的所必需的个人信息（数据最小化） | "以防万一"收集超出要求的字段；产品设计中无数据最小化审查 |
| A.1.4.3 | 限制处理 | 仅为既定目的处理个人信息；无额外法律依据不得二次使用 | 超出原始目的将个人信息用于分析或画像 |
| A.1.4.4 | 准确性和质量 | 实施控制以维护个人信息的准确性；提供更正机制 | 无数据质量验证；无用户自助更正机制 |
| A.1.4.5 | 个人信息最小化 | 应用系统性控制以最小化持有和处理的个人信息量 | 软件开发周期（SDLC）中无个人信息最小化检查清单；字段未按必要性审查 |
| A.1.4.6 | 去标识化与删除 | 实施去标识化和删除程序，在不再需要时移除个人信息 | 无自动删除；个人信息无限期保留在测试环境中 |
| A.1.4.7 | 临时文件 | 确保包含个人信息的临时文件得到安全管理，并在不再需要时删除 | 包含个人信息的临时文件、日志和缓存不受保留/删除政策覆盖 |
| A.1.4.8 | 保留 | 为每个个人信息类别定义并实施与法律义务一致的数据保留时间表 | 无保留时间表；所有数据无限期保留；保留时间表未在技术上强制执行 |
| A.1.4.9 | 处置 | 在保留期结束时安全处置个人信息；记录处置情况 | 无安全删除流程；个人信息随一般数据一起处置 |
| A.1.4.10 | 个人信息传输控制 | 应用控制以保护传输中的个人信息（加密、安全通道、访问控制） | 个人信息通过未加密渠道传输；对电子邮件传输个人信息无控制 |

### A.1.5——个人信息的共享、转移与披露（4 项控制）

**领域目标**：确保向第三国或国际组织转移个人信息符合适用法律，且所有转移和披露均有记录。

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.1.5.2 | 个人信息转移的依据 | 识别并记录每次向第三国或国际组织转移个人信息的法律依据（充分性决定、SCC、BCR、减损） | 向第三国转移无记录在案的法律依据；SCC 未签署 |
| A.1.5.3 | 个人信息转移的国家 | 记录个人信息被转移到的国家或国际组织 | 无转移映射；经云提供商的转移未记录 |
| A.1.5.4 | 个人信息转移记录 | 维护所有向第三方转移个人信息的记录 | 转移日志未维护；无法全面了解所有第三方转移 |
| A.1.5.5 | 个人信息披露记录 | 维护所有向第三方披露个人信息（包括执法请求）的记录 | 披露日志未维护；无临时披露记录 |

## 表 A.2——个人信息处理者控制项（18 项）

作为个人信息处理者行事的组织必须实施所有适用的 A.2 控制项以及所有 A.3 控制项（共 47 项）。

---

### A.2.2——收集与处理的条件（6 项控制）

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.2.2.2 | 客户协议 | 仅依据个人信息控制者的书面指示处理个人信息；确保订立书面 DPA | 超出合同范围处理个人信息；未与所有控制者订立 DPA |
| A.2.2.3 | 组织的自身目的 | 不得为处理者自身目的处理个人信息；处理仅限于控制者指定的事项 | 将控制者个人信息用于自身分析、产品训练或营销 |
| A.2.2.4 | 营销与广告 | 未经明确授权，不得将代表控制者处理的个人信息用于营销或广告 | 在控制者客户之间将客户数据用于交叉营销 |
| A.2.2.5 | 侵权的指示 | 如指示将违反适用的隐私法律，通知控制者；不得执行侵权指示 | 无审查和上报潜在侵权控制者指示的流程 |
| A.2.2.6 | 客户义务 | 协助控制者履行其对个人信息主体的义务（如数据主体请求、DPIA、违规通知） | 无在合同时限内支持控制者履行数据主体请求的既定流程 |
| A.2.2.7 | 个人信息处理记录 | 维护为每位控制者开展的所有处理活动的记录 | 无按控制者的处理记录；单一合并日志不充分 |

---

### A.2.3——对个人信息主体的义务（1 项控制）

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.2.3.2 | 对个人信息主体的义务 | 在处理者与个人信息主体互动时，履行控制者界定的义务；适当时将咨询转至控制者 | 处理者员工不知道如何处理直接收到的数据主体请求咨询 |

---

### A.2.4——设计及默认隐私保护（3 项控制）

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.2.4.2 | 临时文件 | 确保处理期间代表控制者创建的临时文件按商定时间表管理和删除 | 临时处理文件在任务完成后仍被保留 |
| A.2.4.3 | 个人信息的返还、转移或处置 | 在处理协议终止时，将所有个人信息返还控制者或按其指示安全处置 | 无退场（offboarding）程序；合同结束后仍保留个人信息 |
| A.2.4.4 | 个人信息传输控制 | 应用控制以保护处理操作期间传输中的个人信息 | 处理者子系统之间传输个人信息未加密 |

---

### A.2.5——个人信息的共享、转移与披露（8 项控制）

| 控制编号 | 控制名称 | 描述 | 常见差距 |
|-----------|--------------|-------------|-------------|
| A.2.5.2 | 个人信息转移的依据 | 识别并记录向第三国或国际组织转移个人信息的法律依据 | 子处理者转移未映射至法律转移机制 |
| A.2.5.3 | 个人信息转移的国家 | 记录处理期间个人信息被转移到的国家或国际组织 | 作出数据驻留承诺但未执行；子处理者所在地未记录 |
| A.2.5.4 | 个人信息披露记录 | 维护所有向第三方披露个人信息的记录 | 处理者层面未维护披露日志 |
| A.2.5.5 | 个人信息披露请求的通知 | 在第三方（如执法机关）请求披露个人信息时，在法律允许的情况下于披露前通知控制者 | 无将政府/执法访问请求通知控制者的流程 |
| A.2.5.6 | 具有法律约束力的个人信息披露 | 在依法强制披露个人信息时（如法院命令），在法律允许的情况下通知控制者并记录披露 | 披露时未通知控制者；无法律审查流程 |
| A.2.5.7 | 分包方披露 | 向控制者披露所使用的所有子处理者的身份和所在地 | 子处理者清单未维护或未与控制者共享 |
| A.2.5.8 | 分包方聘用 | 在聘用新的子处理者前取得控制者授权；向下传递同等的数据保护义务 | 未经控制者授权聘用子处理者；子处理者合同中无数据保护条款 |
| A.2.5.9 | 分包方变更 | 提前通知控制者子处理者的任何变更；为控制者提供异议机会 | 未将子处理者变更通知控制者；无事前通知机制 |

## 表 A.3——共享信息安全控制（29 项）

适用于**所有组织**（控制者和处理者）。这些信息安全管理控制选自 ISO 27001/27002:2022 框架，经调整为支持隐私保护。

| 控制编号 | 控制名称 | 隐私相关性 |
|-----------|--------------|------------------|
| A.3.3 | 信息安全政策 | 政策必须明确涉及隐私和个人信息保护 |
| A.3.4 | 安全角色 | 界定与隐私相关的安全角色；确保数据保护官（DPO）/隐私官的互动 |
| A.3.5 | 信息分类 | 个人信息必须得到适当分类，以驱动正确的处理控制 |
| A.3.6 | 信息标识 | 标注含个人信息的资产，使处理控制得到一致应用 |
| A.3.7 | 信息转移 | 对系统、人员和组织之间转移个人信息实施控制 |
| A.3.8 | 身份管理 | 管理所有可访问个人信息系统人员的身份 |
| A.3.9 | 访问权限 | 基于需要知悉/最小权限原则限制对个人信息的访问 |
| A.3.10 | 供应商协议 | 供应商/承包商合同必须包含适当的隐私和数据保护条款 |
| A.3.11 | 事件管理 | 隐私违规必须在规定时限内被识别、报告和管理 |
| A.3.12 | 安全事件响应 | 事件响应计划必须涵盖个人数据泄露；须内置 GDPR 72 小时通知要求 |
| A.3.13 | 法律和监管要求 | 识别并遵守所有适用的隐私法律和法规 |
| A.3.14 | 记录保护 | 含个人信息的记录必须受到保护，防止未经授权访问、丢失或毁坏 |
| A.3.15 | 独立审查 | 对隐私信息管理体系（PIMS）和隐私控制进行定期独立审查（内部或外部审计） |
| A.3.16 | 政策合规 | 监控并核实对隐私政策和程序的遵守情况 |
| A.3.17 | 安全意识与培训 | 安全意识培训必须包含隐私培训；对高风险角色进行基于角色的隐私培训 |
| A.3.18 | 保密协议 | 所有可访问个人信息的人员必须签署保密/保密协议（NDA） |
| A.3.19 | 清洁桌面与清洁屏幕 | 含个人信息的实体文件和屏幕显示在无人看管时必须受到保护 |
| A.3.20 | 存储介质 | 含个人信息的可移动介质必须受控；处置必须安全 |
| A.3.21 | 设备安全处置 | 曾存有个人信息的设备在处置或再利用前必须安全擦除 |
| A.3.22 | 用户终端设备 | 可访问个人信息的终端必须具有适当的安全控制（加密、MDM、屏幕锁定） |
| A.3.23 | 安全认证 | 对处理个人信息的系统实施强认证控制；建议采用多因素认证（MFA） |
| A.3.24 | 信息备份 | 含个人信息系统的备份必须受到与主系统同等的控制保护 |
| A.3.25 | 日志记录 | 必须记录对个人信息的访问和处理；日志必须受到防篡改保护 |
| A.3.26 | 密码学使用 | 个人信息的静态和传输加密；密钥管理程序 |
| A.3.27 | 安全开发生命周期 | 将隐私设计嵌入 SDLC；在开发开始前定义隐私要求 |
| A.3.28 | 应用安全 | 处理个人信息的应用必须经过安全漏洞测试（包括输入验证、认证） |
| A.3.29 | 安全系统架构 | 系统架构必须隔离个人信息并支持最小权限原则 |
| A.3.30 | 外包开发 | 隐私和安全要求必须下传至外包开发合同 |
| A.3.31 | 测试信息 | 未经授权和同等控制，不得在测试环境中使用真实个人信息 |

## 控制数量汇总

| 表 | 角色 | 控制数 | 与 A.3 合并后 |
|-------|------|----------|-------------------|
| A.1 | 仅个人信息控制者 | 31 | 31 + 29 = **60** |
| A.2 | 仅个人信息处理者 | 18 | 18 + 29 = **47** |
| A.1 + A.2 | 控制者和处理者兼备 | 49 | 49 + 29 = **78** |
| A.3 | 所有组织 | 29 | 始终包含 |
