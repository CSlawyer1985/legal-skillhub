# 绩效制度合规审查器 - 需求说明书

## 1. 产品定位

面向 HRBP、绩效 COE 和法务合规人员的绩效管理制度合规审查工具。输入绩效制度文本（PIP 条款、绩效改进流程、试用期评估规则、调岗调薪触发条件等），逐条对照现行法律法规进行合规扫描，标注风险等级，给出修改建议和替代方案。

绩效制度的合规性往往被忽视——管理者关注"怎么让制度落地"，但忘了"制度本身是否合法"。等到员工发起争议时才发现制度条款存在硬伤，此时已经付出了管理成本、员工关系和潜在的法律代价。本工具的作用是在制度发布前完成合规审查，将风险消灭在设计阶段。

## 2. 痛点

1. **制度由不懂法的人起草、懂法的人不参与**
   HR 写制度时关注操作性（"连续两个季度 C 就不发奖金"），法务看制度时只关注严重违法条款，两者的中间地带——那些"不违法但有争议空间"的灰色条款——无人审查。

2. **PIP 被写成"劝退通知"的变体**
   很多 PIP 的实际操作是：给一个不可能完成的目标 → 30 天后名正言顺地做不利决定。这种 PIP 在法律实务中已被认定为程序瑕疵，但管理者浑然不觉。

3. **末位淘汰照搬外部实践但不了解本地法律边界**
   很多企业直接套用外部末位淘汰模型，不了解在不同地区的法律适用差异。在部分地区，"考核末位"不能直接等同于"工作不胜任"，中间缺了培训或调岗的法定程序。

4. **试用期评估标准模糊导致无法举证**
   "不符合录用条件"是试用期解除的唯一法定事由，但大多数 JD 里的录用条件没有量化标准。等到要用了，发现根本无法举证——因为没有说清楚什么是"符合"。

5. **调岗降薪条款踩中单方变更合同的雷区**
   制度中写"绩效不达标公司有权调整岗位和薪酬"，但忽略了调岗的合理性要求（关联性、可胜任性、非侮辱性）和薪酬调整的限度。

## 3. 目标用户

- HRBP（审查自己所支持部门的绩效制度是否存在合规风险）
- 绩效 COE（在新制度发布前做合规自检）
- 法务/合规人员（快速定位制度中的高风险条款，减少逐条审查的时间）

## 4. 核心功能

### 4.1 输入

| 字段 | 必填 | 说明 |
|------|------|------|
| 制度文本 | 是 | 绩效管理制度的完整或部分条款文本 |
| 制度类型 | 是 | PIP / 试用期评估 / 绩效分布与淘汰 / 调岗调薪 / 综合绩效制度 |
| 适用地区范围 | 否 | 默认适用全国通用法律法规，可指定地区获取针对性审查 |
| 制度用途 | 否 | 初次发布 / 修订对比（如为修订，还需提供旧版文本做差异审查） |

### 4.2 审查维度

| 审查维度 | 说明 | 检查要点 |
|---------|------|---------|
| 程序合规 | 制度制定和执行的程序是否符合法律要求 | 是否经民主程序、是否公示告知、是否有员工确认 |
| 实体合规 | 制度条款本身是否与法律法规冲突 | 条款内容是否低于法定标准、是否单方加重员工义务 |
| 可操作性 | 制度是否具备可执行的量化标准 | 录用条件是否可举证、不胜任认定是否有客观依据 |
| 程序完整性 | 制度是否覆盖了法定的必要环节 | PIP 是否含培训或调岗环节、试用期解除是否有提前通知 |
| 措辞风险 | 制度文本语言是否存在法律风险 | 是否有歧视性表述、是否有绝对化承诺 |

### 4.3 四大高风险场景专项审查

| 场景 | 核心审查点 | 典型违规模式 |
|------|----------|------------|
| PIP | 目标是否可达、周期是否合理、是否含培训/调岗前置、是否告知后果 | 目标不可达 → PIP 被认定为程序瑕疵；缺少培训环节 → 直接解除不合法 |
| 末位淘汰 | 末位是否等同于不胜任、是否有培训/调岗程序、是否考虑特殊保护群体 | 末位直接解除 → 违反不胜任解除的法定程序 |
| 试用期转正 | 录用条件是否明确量化、评估是否有客观依据、评估周期是否符合法定期限 | 录用条件模糊 → 无法举证"不符合录用条件" |
| 调岗降薪 | 调岗是否有合理关联、降薪幅度是否在合理范围、是否获得员工同意 | 跨专业大幅调岗 + 降薪 → 被认定为单方变更合同 |

### 4.4 风险定级

| 等级 | 含义 | 示例 |
|------|------|------|
| 🔴 高风险 | 明确违反法律规定，一旦争议必败诉 | 末位直接解除劳动合同且无培训/调岗程序 |
| 🟡 中风险 | 不直接违法但在争议中有败诉风险，或处于灰色地带 | PIP 目标挑战性偏高但未达到"不可能完成" |
| 🟢 低风险 | 实践中可操作的合法条款，但措辞可优化 | 使用了"必须""绝对"等绝对化表述但无实质违规 |
| ⚪ 提示 | 不涉及合规，但操作建议 | 建议增加员工签字确认环节以增强举证能力 |

### 4.5 输出结构（五板块）

#### 第一板块：制度条款逐条审查

逐条对照法律法规扫描，输出：

- 原文条款
- 风险等级（🔴/🟡/🟢/⚪）
- 合规依据（引述相关法律规定的核心要旨，使用中性化表述）
- 风险说明
- 修改建议（给出具体修改方案或替代条款表述）
- 修改后示例文本

#### 第二板块：整体合规评分

按审查维度评分（各 0-100 分）+ 加权总分 + 合规等级：

- 程序合规
- 实体合规
- 可操作性
- 程序完整性
- 措辞规范性

合规等级：合规（85+）/ 基本合规待优化（70-85）/ 存在中风险（55-70）/ 存在高风险（<55）

#### 第三板块：高风险条款汇总与整改优先级

集中列出所有 🔴 和 🟡 条款，按风险严重度排序，每项标注：
- 风险条款摘要
- 可能的法律后果
- 整改紧急度（立即 / 本周期 / 下次修订）
- 整改工作量评估（简单措辞修改 / 流程重构 / 需外部法律意见）

#### 第四板块：专项场景合规检查清单

按制度类型输出场景化检查清单，逐项标注"已满足 / 缺失 / 部分满足"：

如 PIP 场景检查清单：
- [ ] PIP 目标是否可量化且可达？
- [ ] PIP 周期是否合理（不少于 30 天）？
- [ ] 是否包含培训或调岗的前置程序？
- [ ] 是否明确告知评估不达标的后果？
- [ ] 是否有员工确认和申诉机制？
- [ ] 是否对特殊保护群体（医疗期、三期等）做了例外排除？

#### 第五板块：制度优化路线图

三个阶段：
1. **紧急修复**（🔴 条款，一周内）：必须立即修改的高风险条款
2. **制度完善**（🟡 条款，下次修订周期）：建议在下次制度修订时优化的条款
3. **长期建设**（🟢+⚪ 建议，按需）：可提升制度可操作性和员工体验的优化

## 5. 异常处理

| 异常 | 处理方式 |
|------|------|
| 制度文本为空或只有标题 | 提示无法审查，请提供完整条款 |
| 制度类型不明确 | 根据文本内容自动判断，标注"推测类型为 XXX"请用户确认 |
| 涉及特殊行业（如医疗/教育/金融） | 提示特殊行业可能有额外合规要求，建议咨询行业法务 |
| 制度引用了已废止的法规 | 🟡 标注引用了已更新的法规表述，建议更新 |
| 制度为外文或中英混合 | 以中文条款为准审查，英文版标注"请以中文版为准" |

## 6. 重要提示

> 本工具输出的合规审查意见为基于通用法律法规的分析参考，不构成正式法律意见。对于 🔴 高风险条款或涉及重大利益的制度修订，建议在采纳修改建议后咨询专业法律顾问做最终确认。
