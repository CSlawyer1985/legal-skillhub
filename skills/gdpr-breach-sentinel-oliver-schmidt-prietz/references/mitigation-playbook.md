# 缓解剧本

风险评估之后，生成针对该事件**量身定制的缓解剧本**。**不要**使用僵化的模板结构。相反，分析具体的违约情形——其类型、攻击向量、所涉数据、组织背景和紧迫性——并生成本案真正重要的应对行动。

## 剧本设计原则

1. **案件驱动，而非类别驱动。** 不要机械地分为"技术性"vs"组织性"或"立即"vs"长期"，除非该结构确实契合。有些事件需要取证优先的方法；另一些需要沟通优先；还有一些需要法律优先。围绕最重要的事项构建剧本。

2. **按影响排序，而非按惯例排序。** 首要行动应是任何能为本特定违约止血的行动——而非泛泛的"隔离系统"检查清单。如攻击者已离开且数据已外泄，网络隔离不如了解被取走了什么、谁面临风险重要。

3. **要具体。** 与其"审查访问控制"，不如说"审计所有对 [特定系统] 具有读取权限的数据库账户，撤销 90 天以上未使用的服务账户，并对所有剩余账户强制执行 MFA"。将每项行动针对事实定制。

4. **包含为什么。** 对每项行动，简要说明其对本案件为何重要。这有助于事件响应团队在资源有限时确定优先级。

5. **考虑依赖关系。** 有些行动会阻碍其他行动。如取证镜像必须先于系统变更，明确说明。如通知起草可以与技术遏制并行进行，也说明。

6. **思考监管机构会问什么。** 以监管机构希望看到被记录的内容来框定补救措施。监管机构经常问："你们立即做了什么？为什么没有做 X？你们改变了什么以防止再次发生？"

## 剧本输出格式

以带优先级的、有序的行动计划呈现剧本，包含：
- **行动项**——具体、实际，并针对案件定制
- **理由**——为何对本特定违约重要
- **优先级**（关键 / 高 / 中）
- **负责人**（具体角色，而非仅"IT"）
- **期限**（相对 T0，对行动现实）
- **依赖关系**（必须先发生什么，或什么可以并行）
- **状态**字段（待办 / 进行中 / 已完成）

按最适合案件的任何结构分组行动——可以按工作流（取证 / 法律 / 沟通 / 加固）、按时间线、按系统或按利益相关方。选择使剧本对用户情形最具可操作性的结构。

## 参考：常见行动类别

酌情从中选取——但仅包含适用于具体案件的内容，且始终定制化：

**遏制与取证：** 系统隔离、凭证撤销、证据保全、IOC 扫描、访问日志审计、攻击向量分析、横向移动评估

**数据与影响范围界定：** 精确识别受损数据、映射受影响个人、评估下游风险（身份盗窃、歧视、勒索、金融欺诈）

**法律与监管：** 监管机构通知准备、主体通知起草、执法机构接触、法律特权考量、DPA 合同义务审查、保险通知

**沟通：** 内部利益相关方简报、员工/工会委员会沟通、客户沟通、媒体应对准备、受影响个人支持渠道建立

**加固与预防：** 漏洞修复、加密实施、访问控制收紧、监测增强、检测规则创建、安全架构审查

**治理与文档：** 根本原因分析、DPIA 审查/更新、第 30 条记录更新、事件响应程序修订、培训需求评估、经验教训记录
