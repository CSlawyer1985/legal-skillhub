# 第 34 条决策框架——向数据主体告知

第 34 条是独立的法律决策，不是第 33 条的脚注。凡事实或 ENISA 评分提示可能存在高风险，即运行本框架，并将结果记录于**第 34 条决策备忘录**（见 [templates.md](templates.md)）。

---

## 1. 触发——第 34 条第 1 款

当违约**"可能对自然人的权利和自由造成高风险"**时，向数据主体告知该违约。

- "高风险"是高于第 33 条第 1 款"风险"触发的门槛——每个第 34 条案件同时也是第 33 条案件，反之则不然。
- 将风险提升至"高"的因素：特殊类别或财务数据、身份盗窃或欺诈可能、弱势主体、规模、有滥用意图的恶意行为者、后果的不可逆性、身体或心理伤害的可能性。
- 这是规范性法律检验：将 ENISA 评分以书面形式桥接至结论（SKILL.md 中的法律桥接）。SE ≥ 3 构成高风险的推定——但不由其决定。

## 2. 时机——"无不当迟延"

- 无固定的 72 小时期限，但紧迫性随告知的保护价值而递增：在主体可以采取行动之处（更改密码、挂失卡片、警惕钓鱼），每一小时延迟都将风险转移给他们。
- 与执法部门协调可以证明短暂延迟正当；记录该请求。
- 可以先通知监管机构，随后再告知主体——但不要让主体告知受制于完整调查；分阶段告知可以接受。

## 3. 例外——第 34 条第 3 款（按顺序评估全部三项）

### (a) 已采取适当保护措施——在违约**之前**

已就位**并适用于受影响数据**的技术和组织措施，特别是使未经授权者无法理解数据的措施（如最先进的加密）。

- 运行 [enisa-methodology.md](enisa-methodology.md) §5 中的加密逻辑树——此处不重复。密钥泄露或与数据同存 → 例外不可用。
- EDPB 模板直接询问此点（"数据是否无法理解……"）；回答 (a) 完好、(b) 可能被破坏或 (c) 否——仅在 (a) 时主张例外。

### (b) 后续措施——在违约**之后**

控制者已采取后续措施，**确保高风险不再可能实现**。

- 示例：在任何滥用前强制重置凭据 + 会话失效；远程擦除已确认；误发消息的接收者在阅读/使用前经可核验且可信地删除数据；被盗设备完好追回并经取证确认无访问。
- 标准是"不再可能实现"——而非"已降低"。记录该措施、其奏效的证据，以及剩余风险为何不再高。
- 如措施的有效性未获确认（如设备未确认远程擦除），该例外**尚**不可用——保持决定开放并重新评估。

### (c) 不成比例的努力 → 改为公开告知

个人告知需要**不成比例的努力**时（如联系方式在违约本身中丢失、人群规模极大且无可用渠道），控制者必须改作**公开告知或类似措施**，以**同等有效的方式**告知主体。

- 此例外改变的是*形式*，而非义务：(c) 项下沉默不是选项。
- 同等有效意味着：醒目网站通知、新闻稿、主体实际使用的社交渠道，使用相关语言——需要时组合使用。
- 当渠道存在时，仅成本很少使努力"不成比例"；记录比较。

## 4. 内容——第 34 条第 2 款（引用第 33 条第 3 款第 b-d 项）

以清晰通俗的语言，至少包括：

1. **违约性质**——发生了什么，用非律师能理解的语言。
2. **DPO 的姓名和联系方式**或其他联系点。
3. **可能的后果**——诚实、针对所涉数据具体化（如"看似来自我们的钓鱼邮件"、"欺诈性付款尝试"）。
4. **已采取或拟采取的措施**——遏制、缓解、预防。
5. **具体的自我保护步骤**——可操作、有优先级：更改密码（以及所有重复使用之处）、卡片挂失、欺诈警报、对提及该违约的意外联系保持警惕。

避免：淡化语言（"出于极度谨慎"）、埋没行动步骤、法律术语、指责主体。

## 5. 告知策略

| 维度 | 指引 |
|-----------|----------|
| **渠道** | 直接（信函/电子邮件/应用内）为默认；仅在 (c) 项下或作为补充时公开。如被破坏的渠道可能受攻击者控制，不要单独使用 |
| **分阶段** | 先通知已确认受影响的主体；随调查范围扩大而扩展。记录分阶段理由 |
| **弱势主体** | 未成年人（适当时经监护人）、患者、老年人——优先处理并调整语言 |
| **语言** | 使用受影响成员国的语言 / 提供服务所用语言 |
| **支持渠道** | 规模大或数据敏感时：专用联系热线/邮箱/FAQ；对接听人员做简报 |
| **欺诈/钓鱼警告** | 警告罪犯可能利用违约本身（"我们永远不会打电话向您索要密码"）；给出唯一的合法联系途径 |
| **记录** | 保留实际发送的带日期内容——EDPB 模板（§5）和附件清单均要求 |

## 6. 兜底——第 34 条第 4 款

如控制者未告知，监管机构可在考虑高风险可能性后**要求**告知，或决定适用某例外。将此纳入考量：薄弱的例外主张会招致监管机构命令，并招致对延迟的审查。
