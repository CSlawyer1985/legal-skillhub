# 技术措施——第9、10、12、14、15条

## 概览

技术措施是必须内建于高风险 AI 系统的设计和实施要求。这些要求主要适用于**提供者**（必须设计和开发），但也影响**部署者**（必须理解并在其范围内运营）。

---

## 第9条——风险管理系统

### 要求

风险管理系统是整个生命周期内**持续迭代的过程**：

**第1步：风险识别和分析（第9(2)(a)条）**
- 识别对健康、安全或基本权利已知和合理可预见的风险
- 考虑系统按预期用途使用时的风险
- 考虑可预见滥用产生的风险

**第2步：风险估计和评估（第9(2)(b)条）**
- 估计已识别风险的可能性和严重性
- 在预期使用和可预见滥用期间评估风险
- 考虑与其他系统或环境的相互作用效应

**第3步：上市后风险评估（第9(2)(c)条）**
- 基于上市后监测（第72条）的数据评估风险
- 纳入事件报告、用户反馈、监测数据

**第4步：风险管理措施（第9(2)(d)条）**
- 采取适当且有针对性的措施处理风险
- 考虑最先进水平和相称性
- 记录残余风险并传达给部署者

### 测试要求（第9(6)-(8)条）

| 要求 | 说明 |
|-------------|-------------|
| 适当指标 | 定义适合预期目的的指标 |
| 概率阈值 | 设定初步性能阈值 |
| 上市前测试 | 在投放市场前测试 |
| 真实世界条件 | 在反映实际部署的条件下测试 |
| 偏见测试 | 测试潜在歧视性影响 |

### 实施检查清单

| # | 行动 | 频率 | 责任 |
|---|--------|-----------|----------------|
| 1 | 建立风险管理框架 | 一次性 | 提供者 |
| 2 | 识别风险（预期使用） | 上市前 + 持续 | 提供者 |
| 3 | 识别风险（可预见滥用） | 上市前 + 持续 | 提供者 |
| 4 | 估计风险严重性和可能性 | 上市前 + 定期 | 提供者 |
| 5 | 设计缓解措施 | 上市前 | 提供者 |
| 6 | 测试缓解有效性 | 上市前 + 定期 | 提供者 |
| 7 | 记录残余风险 | 上市前 + 更新 | 提供者 |
| 8 | 向部署者传达风险 | 上市前 + 更新 | 提供者 |
| 9 | 监测上市后数据 | 持续 | 提供者 + 部署者 |
| 10 | 更新风险评估 | 定期（建议每年） | 提供者 |

## 第10条——数据与数据治理

### 数据质量要求

**训练、验证和测试数据集必须：**
1. **相关**——适合预期目的
2. **充分具有代表性**——反映目标人群
3. **无错误**——尽最大可能
4. **完整**——考虑到预期目的

### 数据治理框架

| # | 要求 | 说明 | 条款 |
|---|------------|-------------|---------|
| 1 | 设计选择 | 记录数据选择和准备的决定 | 第10(2)(a)条 |
| 2 | 收集流程 | 记录数据收集方法和来源 | 第10(2)(b)条 |
| 3 | 准备操作 | 记录标注、标签、清洗、增强 | 第10(2)(c)条 |
| 4 | 假设 | 提出并记录关于数据的假设 | 第10(2)(d)条 |
| 5 | 可用性评估 | 评估数据可用性、数量、适宜性 | 第10(2)(e)条 |
| 6 | 偏见检查 | 检查数据可能的偏见 | 第10(2)(f)条 |
| 7 | 缺口识别 | 识别数据缺口并予以处理 | 第10(2)(g)条 |

### 特殊类别个人数据——第10(5)条

处理特殊类别（GDPR 第9条）**严格**限于：
- 偏见监测
- 偏见检测
- 偏见纠正

**条件：**
- 对基本权利的适当保障
- 对再利用的技术限制
- 安全措施
- 数据最小化

## 第12条——记录保存（日志记录）

### 设计要求

高风险 AI 系统必须在技术上允许在其整个存续期内自动记录事件。

**最低日志记录能力：**

| 日志要素 | 说明 |
|-------------|-------------|
| 使用期间 | 每次使用实例的开始和结束时间 |
| 参考数据库 | 输入数据据以核对的数据库 |
| 输入数据匹配 | 导致匹配的输入数据 |
| 人员识别 | 参与结果核实的自然人 |

### 保留

- 部署者必须保留日志**至少6个月**（第26(6)条）
- 提供者必须设计系统以支持日志保留
- 日志必须应主管机关请求可供其获取

## 第14条——人工监督

### 设计要求

系统必须使自然人能够：

| # | 能力 | 说明 |
|---|-----------|-------------|
| (a) | 理解 | 充分理解能力和限制 |
| (b) | 监测 | 适当监测系统运行 |
| (c) | 认知 | 保持对自动化偏见的认知 |
| (d) | 解释 | 正确解释系统输出 |
| (e) | 超越 | 决定不使用、超越或反转输出 |
| (f) | 干预 | 干预或中断系统运行 |

### 人工监督方式

**人在环内（HITL）：** 人工在行动前核实每项输出。
**人在环上（HOTL）：** 人工监测运行并可干预。
**人在指挥（HIC）：** 人工有权随时超越。

适当水平取决于 AI 系统的风险和情境。

## 第15条——准确性、稳健性与网络安全

### 准确性

| 要求 | 说明 |
|-------------|-------------|
| 适当水平 | 准确性适合预期目的 |
| 声明指标 | 在使用说明中声明准确性水平 |
| 相关指标 | 针对特定 AI 系统类型使用适当指标 |
| 一致性能 | 贯穿整个生命周期，而非仅部署时 |

### 稳健性

| 要求 | 说明 |
|-------------|-------------|
| 错误韧性 | 对错误、故障、不一致具有韧性 |
| 技术措施 | 技术冗余、故障安全机制 |
| 组织措施 | 备份程序、回退流程 |
| 对抗韧性 | 对对抗性条件的韧性（第15(5)条） |

### 网络安全

| 要求 | 说明 |
|-------------|-------------|
| 未授权访问 | 防止未授权第三方访问 |
| 数据投毒 | 防止训练数据操纵 |
| 模型操纵 | 防止模型参数篡改 |
| 对抗输入 | 防止对抗样本（第15(5)条） |
| 供应链 | AI 系统供应链的安全 |
