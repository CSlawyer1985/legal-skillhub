# 专利说明书写作检查清单

## A. 形式检查

| # | 检查项 | 要求 | 通过 |
|---|--------|------|------|
| A1 | 摘要字数 | ≤300字 | □ |
| A2 | 摘要附图 | 指定1张最能体现发明的图 | □ |
| A3 | 技术领域 | 1-2句话，含"属于...技术领域" | □ |
| A4 | 背景技术 | ≥3段，含应用场景+现有方案+文献引用 | □ |
| A5 | 文献引用 | ≥2篇专利文献，含专利号 | □ |
| A6 | 发明内容 | 含目的+技术方案+有益效果三部分 | □ |
| A7 | 附图说明 | ≥3张图 | □ |
| A8 | 具体实施方式 | ≥5个步骤（S101+），每步有具体参数 | □ |
| A9 | 标准段落 | 引入段+硬件实现段+结尾段齐全 | □ |
| A10 | 权利要求总数 | ≥10条（方法5+系统5） | □ |

## B. 权利要求检查

| # | 检查项 | 要求 | 通过 |
|---|--------|------|------|
| B1 | 独立权利要求 | 方法1条(权1)+系统1条(权6) | □ |
| B2 | 从属权利要求引用 | 只能引用在前的权利要求 | □ |
| B3 | "其特征在于" | 每条权利要求特征部分都有此引导语 | □ |
| B4 | 方法系统对应 | 系统模块与方法步骤一一对应 | □ |
| B5 | 编号连续 | 1,2,3...连续，无跳号 | □ |
| B6 | 优选地/优选实施方式 | 从属权利要求用"优选地"引导 | □ |

## C. 内容质量检查

| # | 检查项 | 要求 | 通过 |
|---|--------|------|------|
| C1 | 有益效果 | ≥3条，每条与发明内容对应 | □ |
| C2 | 具体参数 | 实施方式中有具体数值（帧率/分辨率/阈值等） | □ |
| C3 | 术语统一 | 全文同一概念用同一术语 | □ |
| C4 | 无绝对化用语 | 不含"最好""最优""一定"等 | □ |
| C5 | 问题-方案对应 | 背景技术的问题与发明内容解决的问题对应 | □ |
| C6 | 场景具体 | 具体实施方式以具体场景为例（如"以图2为例"） | □ |
| C7 | 优选实施方式 | 至少2处"在更多的优选例中" | □ |
| C8 | 数据安全 | 如涉及数据处理，强调本地处理/不上传云端 | □ |

## D. 格式检查

| # | 检查项 | 要求 | 通过 |
|---|--------|------|------|
| D1 | 标题格式 | 黑体小三号居中 | □ |
| D2 | 章节标题 | 黑体四号 | □ |
| D3 | 正文格式 | 宋体小四号，行距1.5 | □ |
| D4 | 步骤编号 | S101, S102... 格式 | □ |
| D5 | 文件命名 | {DK编号}--{公司}--{发明名称}--发明（软件）--{日期}.docx | □ |

## E. 常见缺陷预警

| 风险 | 说明 | 修复建议 |
|------|------|---------|
| 技术方案太空泛 | 只说"检测"不说怎么检测 | 补充具体算法/模型/参数 |
| 权利要求过窄 | 从属权利要求只重复独立权利要求 | 拆分出新的技术特征 |
| 背景技术过简 | 只有1段，没有文献引用 | 补充现有技术方案和专利文献 |
| 有益效果无量化 | 只说"提升效率"不说具体多少 | 补充对比数据或具体场景说明 |
| 具体实施方式缺少参数 | 步骤描述没有数值 | 补充帧率、分辨率、阈值、时长等 |
| 系统模块不对应方法步骤 | 模块名称和步骤对不上 | 先定方法再翻译成模块语言 |
