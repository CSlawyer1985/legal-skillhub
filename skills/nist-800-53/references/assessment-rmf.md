# NIST SP 800-53——评估、RMF、持续监控与框架映射参考

## SP 800-53A Rev 5——评估程序

### 目的

SP 800-53A Rev 5（2022 年 1 月）为 SP 800-53 Rev 5 中的每项控制提供**评估程序**。每项程序规定：

1. **目标**——评估必须确定什么
2. **方法**——检查、访谈或测试
3. **对象**——检查/访谈/测试什么

### 三种评估方法

| 方法 | 说明 | 示例 |
|--------|-------------|---------|
| **检查** | 审查工件和文件 | 政策文件、SSP、配置文件、系统日志、架构图、审计记录、培训记录 |
| **访谈** | 与人员讨论实施情况 | ISSO、系统所有者、服务台、IT 管理员、最终用户、高层领导 |
| **测试** | 直接运行机制 | 漏洞扫描、渗透测试、配置检查、防火墙规则审查、备份恢复测试 |

### 评估深度

| 深度 | 说明 | 使用时机 |
|-------|-------------|----------|
| **基础** | 检查控制是否存在 | 初始评估；低影响系统 |
| **聚焦** | 评估实施情况 | 最常见方法 |
| **全面** | 彻底、深入的评估 | 高影响系统；3PAO 评估 |

### 安全评估报告（SAR）结构

SAR 记录评估结果：

1. **执行摘要**——高层发现和授权建议
2. **评估范围**——所评估的系统、组件、控制
3. **评估方法**——使用的方法、深度、时间框架
4. **发现**——逐项控制结果
5. **弱点和缺陷**——OTS（未满足）发现
6. **风险敞口**——已识别弱点的风险评级
7. **建议**——补救行动

**发现格式：**
```
控制：AC-2(3)
目标：确定不活跃账户是否在规定期限内被禁用。
状态：未满足（Other Than Satisfied）
发现：对 Active Directory 账户的审计识别出 47 个不活跃超过 120 天的账户；
     组织定义值（ODV）为 90 天。自动化账户审查流程运行不正常。
风险：中——休眠账户代表基于凭据攻击的攻击面。
建议：修复自动化审查流程；立即禁用已识别的 47 个账户。
```

## 行动计划与里程碑（POA&M）

### POA&M 目的

POA&M（CA-5）是一份活文档，跟踪评估、持续监控和自我评估中发现的所有安全弱点。联邦所有系统均要求。

### POA&M 必填字段

| 字段 | 说明 |
|-------|-------------|
| POA&M ID | 唯一标识符 |
| 弱点/缺陷 | 发现的说明 |
| 来源 | 如何发现（扫描、审计、评估、渗透测试） |
| 控制 ID | 相关的 SP 800-53 控制 |
| 风险级别 | 严重 / 高 / 中 / 低 |
| 计划完成日期 | 补救何时完成 |
| 里程碑说明 | 带日期的补救步骤 |
| 所需资源 | 人员、工具、预算 |
| 状态 | 未结 / 已完成 / 延迟 / 风险已接受 |

### POA&M 时间表（FedRAMP 指引）

| 风险级别 | 补救期限 |
|-----------|---------------------|
| 严重 | 30 天 |
| 高 | 90 天 |
| 中 | 180 天 |
| 低 | 1 年 |
| 运营要求 | 风险已接受；需 ISSO/SO 签名 |

### 风险接受

当弱点无法在标准时间表内补救时：
- 记录**风险接受**并附业务理由
- ISSO 和系统所有者必须签署
- 高/严重事项授权官员（AO）可能需要批准
- 在每个持续监控周期审查
- 高/严重发现不能无限期风险接受

## 风险管理框架（RMF）——SP 800-37 Rev 2

### 第 1 步——准备

**目的：** 确立管理安全和隐私风险的组织和系统背景。

**关键任务：**
- 分配角色：授权官员（AO）、系统所有者（SO）、ISSO、机构高级信息安全官员（SAISO）
- 制定或更新组织风险管理策略（PM-9）
- 识别共同控制（PM-10）
- 开展任务/业务流程分析（PM-11）
- 执行组织级风险评估（RA-3）
- 建立系统的信息生命周期

**输出：** 风险管理角色已分配；组织级风险评估已完成；共同控制清单已建立。

### 第 2 步——分类

**目的：** 基于 FIPS 199 对系统及处理、存储和传输的信息进行分类。

**关键任务：**
- 描述系统（SSP 第 1 和 2 节）
- 使用 SP 800-60 识别信息类型
- 确定保密性、完整性、可用性的影响级别
- 确定系统整体影响级别（高水位线）
- 记录在安全分类文件中

**输出：** 系统安全分类文件（由 AO 和 SO 签署）。

### 第 3 步——选择

**目的：** 为系统选择、裁剪并记录控制。

**关键任务：**
- 从 SP 800-53B 选择起始基线（低/中/高）
- 应用裁剪（共同控制、范围界定、ODV、补偿控制）
- 在 SSP 中记录所有裁剪决定
- 制定持续监控策略（CA-7）
- 审查并批准控制选择（AO 同意）

**输出：** 含控制选择的 SSP；持续监控策略。

### 第 4 步——实施

**目的：** 实施控制并记录其在运营环境中的部署方式。

**关键任务：**
- 实施所选控制
- 在 SSP 中记录实施情况（每项控制一段叙述）
- 记录开发者控制的设计和实施信息（SA-4）
- 识别并处理供应链风险（SR 系列）

**输出：** 已实施的控制；完成的 SSP 实施叙述。

### 第 5 步——评估

**目的：** 确定控制是否正确实施、按预期运行，并在满足安全和隐私要求方面产生预期结果。

**关键任务：**
- 使用 SP 800-53A 制定安全评估计划（SAP）
- 选择合格评估员（中/高系统独立；FedRAMP 为 3PAO）
- 开展评估（检查、访谈、测试）
- 在 SAR 中记录发现
- 根据 SAR 发现制定初始 POA&M

**输出：** SAP、SAR、初始 POA&M。

**独立性要求：**
- **低影响系统：** 允许自我评估
- **中影响系统：** 独立评估员（与实施团队不同的团队）
- **高影响系统 / FedRAMP：** 要求 3PAO；须经 A2LA/FedRAMP PMO 认可

### 第 6 步——授权

**目的：** 通过要求高级官员确定组织运营/资产的安全和隐私风险是否可接受，提供组织问责制。

**授权包内容：**
1. 系统安全计划（SSP）
2. 安全评估报告（SAR）
3. 行动计划与里程碑（POA&M）
4. 执行摘要（供 AO 审查）

**授权决定：**
- **运营授权（ATO）**——风险可接受；通常授予 3 年
- **共同控制授权（CCA）**——适用于共同控制提供方
- **拒绝运营授权（DATO）**——风险不可接受；系统必须关闭或补救
- **使用授权（ATU）**——适用于外部系统/服务

**持续授权：** 持续授权（中/高系统首选）以实时风险管理取代定期再授权。

### 第 7 步——监控

**目的：** 保持对系统安全和隐私态势的持续态势感知。

**关键任务：**
- 实施持续监控策略（CA-7）
- 对所选控制进行持续评估
- 响应系统和威胁环境的变化
- 向 AO 报告安全状态
- 随变化更新 SSP、SAR、POA&M
- 进行持续风险确定和接受

**FedRAMP 持续监控要求：**
- 每月漏洞扫描（操作系统、数据库、Web 应用）
- 年度渗透测试（由 3PAO 执行）
- 每月 POA&M 更新
- 重大系统变更前的重大变更请求
- 年度安全审查

## 持续监控（ConMon）策略

### 持续监控频率（SP 800-137 / CA-7）

| 活动 | 建议频率 | FedRAMP 频率 |
|----------|----------------------|------------------|
| 漏洞扫描（操作系统） | 每月 | 每月 |
| 漏洞扫描（Web 应用） | 每月 | 每月 |
| 漏洞扫描（数据库） | 每月 | 每周 |
| 控制评估（所选） | 持续/每季度 | 每年 |
| 安全意识培训 | 每年 | 每年 |
| 应急计划测试 | 每年 | 每年 |
| 完整控制评估 | 每 3 年/再授权时 | 每年（3PAO） |
| 渗透测试 | 每年（中+） | 每年（3PAO） |

### 持续监控自动化

支持持续监控实施的工具：
- **SCAP（安全内容自动化协议）**——标准化漏洞扫描
- **CVE/CVSS**——通用漏洞评分
- **OVAL/XCCDF**——配置检查
- **NVD（国家漏洞数据库）**——NIST 漏洞库
- **CDM（持续诊断与缓解）**——DHS/CISA 面向联邦机构的计划
- **OSCAL**——机器可读的安全控制文档

## OSCAL——开放安全控制评估语言

OSCAL（由 NIST 开发）提供 SP 800-53 内容的机器可读表示：

### OSCAL 层级

| 层级 | 目的 | 格式 |
|-------|---------|---------|
| **目录** | 控制定义（SP 800-53 目录） | JSON、XML、YAML |
| **配置文件** | 基线选择和裁剪 | JSON、XML、YAML |
| **组件定义** | 可复用组件实施 | JSON、XML、YAML |
| **系统安全计划** | 机器可读格式的 SSP | JSON、XML、YAML |
| **评估计划** | 机器可读格式的 SAP | JSON、XML、YAML |
| **评估结果** | 机器可读格式的 SAR 发现 | JSON、XML、YAML |
| **POA&M** | 机器可读格式的行动计划 | JSON、XML、YAML |

**FedRAMP OSCAL 采用：** FedRAMP 一直在推进基于 OSCAL 的 SSP 提交。支持 OSCAL 的工具：Trestle（IBM）、Xacta 360、Atlasity、Empower。

### SP 800-53 Rev 5 → NIST CSF 2.0

CSF 2.0（2024 年 2 月）映射到 SP 800-53：

| CSF 职能 | 关键 SP 800-53 系列 |
|-------------|----------------------|
| **GV（治理）** | PM、PL、AT、RA |
| **ID（识别）** | RA、CA、CM、PM |
| **PR（保护）** | AC、AT、CM、IA、MA、MP、PE、SC、SI、SR |
| **DE（检测）** | AU、CA、IR、RA、SI |
| **RS（响应）** | IR、CA |
| **RC（恢复）** | CP、IR |

完整映射：SP 800-53B 附录 B 提供 CSF 子类别 → SP 800-53 控制映射。

### SP 800-53 Rev 5 → CMMC 2.0

CMMC 2.0 基于 **NIST SP 800-171 Rev 2**，后者源自 SP 800-53：

| CMMC 级别 | SP 800-53 依据 |
|-----------|----------------|
| 第 1 级（基础） | 800-171 实践子集（来自 FAR 条款的 17 项实践） |
| 第 2 级（高级） | 完整 SP 800-171 Rev 2（110 项实践 = 约 320 项 SP 800-53 控制） |
| 第 3 级（专家） | SP 800-171 + 所选 SP 800-172 控制 |

SP 800-171 附录 D 提供每项 800-171 要求到 SP 800-53 源控制的映射。

### SP 800-53 Rev 5 → FedRAMP

FedRAMP 使用 SP 800-53 中或高基线并带覆盖参数：

| FedRAMP 差异 | 详情 |
|-------------------|----------------|
| 特定 ODV 值 | 在 FedRAMP 基线文件中定义 |
| 附加要求 | 向 US-CERT 报告事件；3PAO 要求 |
| 密码学 | 明确要求经 FIPS 140-2/140-3 验证的模块 |
| 持续监控 | 要求特定的每月/每年频率 |
| SSP 格式 | 必须使用 FedRAMP SSP 模板 |
| 授权类型 | 机构 ATO 或 JAB P-ATO |
