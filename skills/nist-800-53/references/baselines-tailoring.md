# NIST SP 800-53 第5版——基线、定制与叠加参考

## SP 800-53B——控制基线

SP 800-53B（2020年10月）是将控制基线与主 SP 800-53 目录分离的配套出版物。

### 低影响基线

**适用对象：** 机密性、完整性或可用性的丧失仅会造成有限不利影响的系统。

**示例：** 面向公众的网站、含非敏感数据的内部协作工具、参考数据库。

**大致范围：** 覆盖20个族的约156项控制和增强项（不计 PM 族）。

**关键特征：**
- 每个族都要求政策与程序控制
- 基本访问控制（AC-2 账户管理、AC-3 强制执行、AC-7 登录限制）
- 基础审计日志（AU-2 至 AU-12）
- 特权账户要求 MFA（IA-2(1)）——第14028号行政命令后扩展
- 基本边界保护（SC-7），无详细增强要求
- 事件响应计划（IR-8）、事件报告（IR-6）
- 漏洞扫描（RA-5）——频率由 ODV 定义

### 中影响基线

**适用对象：** 安全漏洞可能对组织运营、资产或个人造成严重不利影响的系统。

**示例：** 含个人身份信息（PII）的人力资源系统、财务管理系统、含敏感数据的内部协作、大多数联邦机构系统。

**大致范围：** 覆盖20个族的约323项控制和增强项。

**相对于低基线的主要增加：**
- 自动化账户管理（AC-2(1)）、不活动控制（AC-2(3)(5)）
- 信息流强制（AC-4）、职责分离（AC-5）
- 最小权限要求（AC-6 至 AC-6(10)）
- 审计的 SIEM 集成（AU-6(1)）
- 独立评估人（CA-2(1)）
- 带定义频率的持续监测（CA-7）
- 配置变更控制（CM-3）、基线自动化（CM-2(2)）
- 备用存储和处理场所（CP-6、CP-7）
- 设备和非组织用户认证（IA-3、IA-8）
- PKI/PIV 支持（IA-2(12)、IA-5(2)）
- 事件响应测试（IR-3）
- 开发方安全测试（SA-11）、配置管理（SA-10）
- 传输保护（SC-8(1)——要求 TLS）
- 静态加密（SC-28(1)）
- 软件完整性验证（SI-7(1)）
- 供应链计划和控制（SR-2、SR-3、SR-5 至 SR-8、SR-11、SR-12）

### 高影响基线

**适用对象：** 漏洞可能对国家安全、人身安全造成严重或灾难性影响，或造成重大财务损失的系统。

**示例：** 国家安全系统、持有关键数据的金融系统、应急服务、选举系统。

**大致范围：** 覆盖20个族的约422项控制和增强项。

**相对于中基线的主要增加：**
- 异常使用的账户监测（AC-2(12)）
- 渗透测试（CA-8）
- 内部威胁计划整合（AT-2(2) 组织层面；PM-12）
- 威胁狩猎（RA-10）
- 不可否认性（AU-10）
- 会话审计（AU-14）
- 供应链团队、防篡改、防伪（SR-2(1)、SR-6(1)、SR-9 至 SR-11(1)）
- 开发方架构审查（SA-17）
- 所有 SI 族控制，包括功能验证（SI-6）
- 增强的密码保护

## 定制流程（SP 800-53B 第2节）

定制从起始基线产生一套针对系统特定的控制。在 SSP（系统安全计划）中记录所有定制决定。

### 定制第1步——识别公共控制

**公共控制**（也称"继承控制"）在组织或设施层面实施，由多个系统继承：

| 示例 | 控制 | 实施方 |
|---------|---------|---------------|
| 企业防火墙 | SC-7 | 网络运营 |
| 门禁系统 | PE-3 | 设施 |
| 企业防病毒解决方案 | SI-3 | IT 安全 |
| 安全意识培训 | AT-2 | ISSO / HR |
| 物理数据中心安全 | PE-2、PE-13 | 数据中心运营 |

**指定类型：**
- **公共：** 完全从另一系统/组织继承
- **系统特定：** 完全由系统实施
- **混合：** 部分继承、部分系统特定

在 SSP 部分记录：公共控制继承表。

### 定制第2步——应用范围界定考量

移除不适用的控制，依据：

| 范围界定考量 | 示例 |
|----------------------|---------|
| 技术不存在 | 系统无远程维护能力时 MA-4（远程维护）不适用 |
| 物理位置 | 云托管系统的 PE-3 不适用（从云服务商继承） |
| 任务/运营需要 | 气隙系统的 AC-18（无线）不适用 |
| 适用法律/法规 | 不处理 PII 时某些 PT 控制不适用 |

**在 SSP 中记录每个范围界定决定**并附理由。监管者和审计者会严格审查无正当理由的范围界定。

### 定制第3步——组织定义值（ODV）

每个带方括号 `[Assignment: ...]` 的控制都要求 ODV。未填写 ODV 是常见的 SSP 发现项。

**需定义的高优先级 ODV：**

| 控制 | 参数 | 联邦指南 | 示例值 |
|---------|-----------|-----------------|---------------|
| AC-2(3) | 禁用前的不活动期 | OMB M-22-09：90天 | 90天 |
| AC-7 | 锁定前的最大登录尝试次数 | NIST 指南：3–5 | 3次 |
| AC-11 | 锁定前的会话不活动期 | OMB M-22-09：15分钟 | 15分钟 |
| AU-11 | 审计日志保留 | NARA/OMB：至少3年 | 3年 |
| CA-7 | 持续监测（ConMon）评估频率 | FedRAMP：每月/每年 | 控制每月；渗透测试每年 |
| IA-5(1)(a) | 最小密码长度 | NIST SP 800-63B：8+；典型联邦：15+ | 15个字符 |
| IA-5(1)(h) | 密码复杂性 | NIST SP 800-63B：无复杂性要求（记忆秘密） | 无组成规则 |
| RA-5 | 漏洞扫描频率 | CISA BOD 19-02；FedRAMP：OS 每月、数据库每周 | OS 扫描每月 |
| SI-2 | 关键漏洞修补期限 | CISA BOD 19-02：关键15天 | 关键15天；高30天 |

### 定制第4步——补偿控制

当基线控制无法按书面方式实施时，**补偿控制**提供等效安全性：

**补偿控制的要求：**
1. 必须与原始控制同样有效
2. 必须附理由记录
3. 不得产生额外风险
4. 必须作为授权的一部分接受评估
5. 必须在每次授权续期时审查

**示例：** 如果遗留系统无法实施 IA-2(1)（特权账户 MFA），补偿控制可以是：增强的特权访问监测（AC-2(12)）+ 严格 IP 白名单 + 特权访问工作站 + 会话记录。

### 定制第5步——补充基线

在以下情形下增加基线之外的控制：
- 风险评估识别出升高的威胁
- 机构或系统特定的安全要求要求
- 法律、法规或政策要求额外保护
- 系统处理的影响级别未反映的高度敏感数据

## 叠加

### 什么是叠加？

叠加是针对特定利益群体、技术类型或运营环境的预定制基线。叠加节省时间并促进一致性——组织应用叠加而非从头进行基线定制。

### FedRAMP 叠加

**范围：** 向联邦机构提供的云服务。

FedRAMP 对 SP 800-53 中基线的主要增加：
- 特定 ODV 值（如 AU-11：1年；RA-5：所有漏洞类型每月）
- FedRAMP 特定控制（如 FedRAMP 特定的持续监测要求）
- 要求 3PAO（第三方评估组织）进行独立评估
- 持续监测报告：每月漏洞报告、年度渗透测试、POA&M 更新
- JAB（联合授权委员会）授权用于 P-ATO 路径，而非机构 ATO 路径

### DoD/CNSS 叠加（CNSS 指令 1253）

**范围：** 国家安全系统（NSS）——涉密或情报系统。

主要增加：
- NSS 系统的更高基线要求
- CNSS 特定控制参数
- 适用于处理涉密国家安全信息（CNSI）的系统
- 与情报界指令（ICD）503 协调

### 隐私叠加

**范围：** 大规模处理 PII 的系统。

- 要求全部8项 PT 族控制
- 增强的 PM 隐私控制（PM-18 至 PM-27）
- 要求隐私影响评估（PTA/PIA）
- 《隐私法》系统要求 SORN
- 数据最小化和保留要求

### ICS/SCADA 叠加

**范围：** 工业控制系统、SCADA、运营技术。

参考：**NIST SP 800-82 第3版**——《OT 安全指南》。
- 可用性优先于机密性
- 实时处理约束影响控制适用性
- 遗留系统的容纳
- 安全系统隔离要求
- 物理过程监测集成

## 隐私基线（PT 族）——详细

### 《隐私法》关联

**1974年《隐私法》（5 U.S.C. § 552a）** 适用于联邦机构的记录系统（SOR）。SP 800-53 PT 控制实施《隐私法》要求：

| PT 控制 | 《隐私法》要求 |
|-----------|------------------------|
| PT-5 | 收集时提供隐私法通知 |
| PT-6 | 在《联邦公报》发布记录系统通知（SORN） |
| PT-8 | 计算机匹配协议 |

### 隐私影响评估（PIA）

**2002年《电子政务法》** 要求对收集 PII 的新建或重大修改的 IT 系统进行 PIA：
- 记录收集哪些 PII 及原因
- PII 如何被使用、保护、共享
- 访问控制和保留
- 发布在机构网站上（涉密除外）

相关控制：PL-2（SSP 包含隐私要求）、RA-3（隐私风险评估）。

## 供应链风险管理（SR 族）——详细

### SCRM 计划（SR-2）

记录组织的 SCRM 方法：
- 组件关键性（SR-4 来源）
- 供应商风险标准和评估流程（SR-6）
- 采购要求（SR-5）
- 组件真实性验证（SR-11）
- 与供应商的通知协议（SR-8）

### SBOM（软件物料清单）

第14028号行政命令和 CISA 要求提高了 SBOM 预期。SBOM 支持：
- SR-4（来源）——了解软件组件的来源
- SR-11（组件真实性）——验证软件完整性
- SA-4（采购）——在合同中要求 SBOM

**SBOM 最低数据字段（NTIA）：**
- 供应商名称、组件名称、版本、唯一标识符、依赖项、作者、时间戳

### 供应商评估（SR-6）

对关键供应商：
- 通过问卷、审计或现场访问进行年度评估
- 审查认证（ISO 27001、SOC 2 Type 2、FedRAMP）
- 合同性安全要求（SA-4、SA-9）
- 事件通知协议（SR-8）
