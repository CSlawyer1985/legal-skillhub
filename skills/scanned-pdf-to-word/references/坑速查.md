# 坑速查（实战索引）

> 从 SKILL.md 正文挪出来的两张表——它们是**数据/索引**，不是决策，
> 放在这里避免正文过长淹没规则。**遇到具体症状时查这里。**

## 一、通用坑（段落式与表格式都会碰）

| 症状 | 根因 | 解法 |
|---|---|---|
| 字体判成仿宋，用户说像楷体 | 拿国标 5.2.2 / 7.3.3「正文一般用3号仿宋」套了**表单** | 条文里带"一般/推荐/如无特殊说明"的都是**可调整项**，必须实测；`identify_font.py` 给 IoU 排名 |
| 拿不准该找哪几款字体 | 没问发布机关 | 动手前先问一句"这是哪个机关发布的"，查 `references/发文机关先验.md` |
| 先验与实测不一致 | 先验是【待验】级的行业说法 | 一律信实测，并把这次实测回填进先验表；向用户说明与惯例不同 |
| 重建下划线比原件**高 2pt 多** | ASCII 字体用了中文楷体，`_` 下沉只有 0.05em | `w:ascii` 改 Times New Roman（下沉 0.195em） |
| 下划线断成"_ _ _" | 用了全角 `＿`，被 East Asian 字体渲染 | 改用 ASCII `_` + TNR（ink>advance 才连续） |
| 填空线整串跳到下一行 | 连续 `_` 被视为一个单词 | 按原件换行位手动 `<w:br/>`，每行留 8pt 余量 |
| 某行末尾少了几个下划线 | **行末空格被引擎当尾随空格修剪**（连带吃掉其下划线） | 行末改用 `U+00A0` 不换行空格；或直接用 `_` 字符而非"空格+下划线格式" |
| 中文与数字间多出空隙 | Word 自动调整中英文间距 | `autoSpaceDE/DN = 0` |
| 字号差 1.5% 怎么调都不对 | `w:sz` 只能 0.5pt 步进 | 用 `w:w` 字符缩放补精度——**但必须先过第 1 步末尾的三道闸门**（先取整档 / ≥3 样本一致 / 有原件照抄），否则就是"把测量误差写进文档"（我踩过：22pt 被测成 21.8 又去凑 21.5+102%） |
| 标题看着偏左 | 对纸张居中 ≠ 对版心居中 | 按版心中心算 |
| 某段莫名多一行 | 填空线多了 1–2 个 `_` | 重算可用宽度 |
| soffice 转换没反应 | 不在 PATH / 复用了被占用的配置目录 | 绝对路径 + `-env:UserInstallation=file:///tmp/...` |
| "带条数"总也对不上 | 下划线与文字并带，条数天然不等 | 别用条数当指标，用逐行墨迹投影相关 |
| "Δy 超限"十几条，看着像版面崩了 | 阈值/最小带高没调好，0.6pt 的下划线碎成多条假带 | Otsu 阈值 + 最小带高 ≈ 下划线厚度 + 分辨率 ≥600dpi |
| Word 里字体变了 | 目标机器没装该字体 | 用规范字体名，并在交付说明里提示 |
| **成品"验收数据完美"却仍然错一片** | 拿扫描件当基准自证（同源循环），且验收工具用了 LibreOffice | **先要原件**（第 0 步）；验收用 Word 渲染（第 4 步）；接受"像 ≠ 对" |
| 字体目视判错（把楷体看成宋体、黑体看成宋体） | 200dpi 小字肉眼不可靠，IoU 又无区分度 | 用**墨迹密度**同口径判别（见「判定能力的边界」），族级仍存疑就写通用族名 |
| 多加了版记/页码 | 把发文通知的版记当附件内容 | 查原件有没有 footer；附件标识是否顶格另起（铁律 7） |
| 表格比文本列宽，改页边距去迁就 | 表格本来就可以居中溢出文本列 | 保留原页边距，用 `tblW` + `jc=center` |
| 被 LibreOffice 的假失配骗着改文档 | 它的表格纵向位置与折行数都不可信 | 只用 Word 验收；LO 的失配先怀疑 LO |
| 把 22pt 测成 21.8 还去凑字符缩放 | 把测量误差当真相 | 优先取整数/标准档位；差 >0.5pt 且多样本一致才动缩放 |
| **表格整体上移/下移 30~40pt** | 删掉了原件的 `w:docGrid`（或没管它） | 照抄原件的 docGrid；或给每段都设 `lineRule=exact`（见第 3 步第 6 条） |
| 为方便校对而改了文档 | **工具倒逼内容** | 手段不好用要换手段（换引擎/换方法），不动目的 |
| 复刻出来的东西"多了几块" | 交付目标没定义（文档 vs 页面画像） | 动手前问一句，见开篇「先定交付目标」 |
| 把没验证的推断当经验传下去 | 经验条目没写来源等级 | 每条经验必须标【原件】/【实证】/【反推】，见先验表来源分级 |


## 二、表格特有的坑


| 症状 | 根因 | 解法 |
|---|---|---|
| 表格整体右移 4pt | **`w:tblPr` 子元素顺序在 ECMA-376 里是强制的**，用 `append` 乱序会被渲染器忽略 | 按 `tblW → jc → tblCellSpacing → tblInd → tblBorders → shd → tblLayout → tblCellMar → tblLook` 顺序插入，别 append 图省事 |
| 表头长文字多折一行、溢出到格外 | **不是单元格边距的问题**——原件用默认 5.4pt 边距在 Word 里是 3 行，是 LibreOffice 回退字体后才折成 4 行 | **别去压 `w:tblCellMar`**（我压到 1.4pt 属多余改动）；用 Word 渲染复核，见第 4 步 |
| 明明有线，脚本却报"版记线缺失" | 测量门槛 `minpx` 太大：**0.75pt 的线在 z=6 下只有 4.5px**，`minpx=6` 全滤掉 | 细线场景 `minpx` 取 4；或按「线厚×分辨率」反推门槛 |
| 小字号字体判不出来（各候选都 ~0.3） | 200dpi 下 12pt 字仅 33px、笔画亚像素，**IoU 区分度天然不足** | 见下「判定能力的边界」，改用墨迹密度作族级判别 |
| 表格比文本列宽，以为要塞进版心 | **表格本来就可以比文本列宽**，原件靠 `jc=center` 居中、两边对称溢出 | 设 `tblW` = 实测总宽 + `jc=center`，**页边距照原样（本案上72/右90/下72/左90）**；别把页边距改小去迁就表格（我改成了左边距 56.17pt，是错的） |
| 表格边框粗细 | `w:sz` 单位 1/8pt，原件是 **sz=4（0.5pt）** | 我用了 sz=6（0.75pt），偏粗；按线厚中位数反推，别默认取 6 |
| 复刻时"多加了内容" | 把**发文通知的版记/页码**当成了附件的内容 | 先看清原件 Word 有没有 footer；见铁律 7 |
| 字号"精确化"过头 | 把测量误差当真相：原件是干净的 **22.0pt**，我测成 21.8 又做「21.5pt + 缩放 102%」去凑 | 交付时优先取**整数/标准档位**（22 / 16 / 14 / 12 / 11）；只有多个独立样本一致且差 >0.5pt 才动字符缩放 |
