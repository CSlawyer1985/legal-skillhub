# 校对与验证

> SKILL.md 只留"验什么东西"，这里放"怎么验、阈值多少、为什么"。

## 一、渲染器：优先 Microsoft Word

```bash
# ✅ 首选：Word + AppleScript（另一技能，别自己拼 osascript）
python3 ~/.workbuddy/skills/word-to-pdf-macos/scripts/batch_word_to_pdf.py <out.docx>
```

对同一份文件（律协《附件3》）两引擎渲染的差距：

| 现象 | LibreOffice | Word 原生 | 谁对 |
|---|---|---|---|
| 表格顶线 y | 197.4pt | **166.3pt** | Word（扫描件 168.0pt） |
| 表头长格折行 | 4 行 | **3 行**（行高 exact 51.1pt） | Word（扫描件 3 行） |

### 根因（别再当"玄学偏差"）

| 差距 | 根因 | **什么时候会犯** |
|---|---|---|
| 折行 3 → 4 行 | **字体回退**：LO 找不到 `黑体`，换成 SIL-Hei-Med-Jian，字宽变了 | 目标字体缺失时 |
| 纵向 31.1pt | **文档网格的行高算法与 Word 不同** | 文档带 `w:docGrid` 时 |

实证：把原件的 `docGrid` 删掉再让 LO 渲染，表格横线 197.4pt → **160.9pt**（位移 36.5pt）
—— **LO 认这个网格，只是算得和 Word 不一样**。所以：

- **文档没有网格、字体齐全时**：LO 的纵向位置也大致可信；
- **带网格、或字体被回退时**：LO 的纵向位置与折行数**一律不可信**。

### Word 用不了时怎么办（TCC 自动化权限被拒等）

macOS 自动化权限会随时失效（本案 21:24 还正常，21:27 连 `get count of documents` 都返回 `-10004`）。

| 做法 | 允许？ |
|---|---|
| 换用「同引擎独立实现对照」验构建保真度 | ✅ 允许，且足够 |
| 用 LO 渲染后**据此修改文档** | ❌ **绝对禁止**——这正是把文档带偏的那条路 |
| 参数验证降级为"人工确认 + 交付说明里标注不确定" | ✅ 允许 |
| 提示用户到「系统设置 → 隐私与安全性 → 自动化」为终端/WorkBuddy 勾选 Microsoft Word | ✅ 顺带做（恢复权限的正路，不要 pkill Word） |

## 二、进阶：用「同引擎独立实现对照」验构建保真度（不依赖 Word）

要验证的其实是**两件不同的事**，别混在一起：

| 要验什么 | 能否自证 | 手段 |
|---|---|---|
| **构建保真度**（构建器写得对不对） | **能** | 两份文档用**同一个引擎**渲染，引擎偏差相互抵消 |
| **参数正确性**（读出来的参数对不对） | **不能** | 必须外部真源（原件 / 与扫描件同源的环境） |

本案做法：把原件参数导出成 spec → 跑 `scripts/build_table_docx.py` → 两份都过 LO 渲染 →
**8 条横线 + 9 条竖线逐条 Δ = 0.00pt** ⇒ 构建环节零缺陷。

**附带价值**：Word 自动化权限被拒（`-10004`）时，这条路径照常可用。

## 三、验收线

**先明确基准**，否则阈值没有意义：

| 基准 | 能验什么 | 阈值 |
|---|---|---|
| **有原件**：对照原件声明值 | 一切（唯一能验"参数对不对"的基准） | 逐项相等；除非有理由，否则不允许出现差异 |
| **无原件**：对照扫描件 | 只能验"我复现了我的读法"（**自证**） | 见下表，且必须声明这是自证 |

| 指标 | 阈值 | 律协案定稿 |
|---|---|---|
| 逐行墨迹投影相关 | 越高越好（作版本间对比） | 0.575 |
| 每行的 y 与扫描件最近行带之差 | ≤ 4pt（≈1.4mm） | 均 0.87 / 最大 2.50pt |
| 字宽（列投影 / 文本层） | 与扫描件差 ≤ 0.1pt | 正文 15.300 vs 15.318；标题 21.200 vs 21.181 |
| 下划线纵向残差 | ≤ 1.5pt | 0.62~1.25pt |
| 最长行右端 | 与扫描件差 ≤ 2pt | 短 0.33pt（修正前短 8.88pt） |
| 表格列宽（逐列） | 与**原件**差 ≤ 0.6pt | 对原件单列最大差 1.5pt（**未达标**，源自扫描件 ~0.5% 横向偏差） |

⚠️ **从扫描件反推的绝对尺寸带 ~0.5% 系统性偏差**：律协案扫描件表格竖线总跨距 478.9pt，
Word 渲染原件 481.3pt（差 2.5pt / 0.52%），且**纵向无缩放**（行高总和 221.4 vs 221.5）。
所以列宽/版心会**整体略窄于原件**。有原件时以原件为准；只有扫描件时把这个偏差写进交付说明，
**别声称"0.1pt 级吻合"**。

## 四、阈值与最小带高（否则会凭空多出十几条假失配）

同一对文件：硬阈值 `mean<150` + 最小 3 行 → 重建 **31 带、4 条超 4pt、最大 14.5pt**；
换 **Otsu + 最小 6 行（≥0.72pt）** → 重建 **18 带、0 条超限、最大 2.30pt**。
差别全在抗锯齿灰边被当成独立墨带。**下划线只有 0.6pt 粗**，分辨率不足时它会碎成好几条带。

调参方向：**分辨率 ≥600dpi、阈值用 Otsu、最小带高 ≈ 下划线厚度**（细线场景 `minpx` 取 4）。
别用"墨迹带条数"当指标（下划线与文字并带，条数天然不等）；也别用"带序索引对齐"或单向最近邻匹配。
**用逐行墨迹投影相关**——对纵向位置最敏感、对并带免疫（本案 v6→v8 该指标 0.204 → 0.575）。

## 五、三个工具的分工

| 脚本 | 什么时候用 | 关键行为 |
|---|---|---|
| `scripts/verify_layout.py` | 与扫描件/原件做几何比对 | 传 `--rendered=<Word导出的PDF>`；不传则退回 LO 并**打印警告** |
| `scripts/audit_docx.py` | 交付前参数审计 | 打印"原件属性清单"逐项 + 计数 + **双向条目比对** + 一致性 + 与 spec 逐项比对；**退出码 1 = 不许交付** |
| `scripts/self_check.py` | 改完技能本体后 | frontmatter / 引用完整性 / **摘要表 vs 先验表同值** / 编号不重复 / 计数口径 / 脚本冒烟 / 关键规则在位 |
