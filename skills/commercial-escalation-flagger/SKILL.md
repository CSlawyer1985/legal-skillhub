# /escalation-flagger

根据审查指引中的上报矩阵指明合同问题的审批人并起草说明——而不是在下班前发"你有空吗"消息。

## 指令

1. **加载审查指引** → 上报部分。如缺失，说明——业务领域配置需要编辑。

2. **定性问题：** 金额阈值 / 条款偏离 / 自动触发 / 商业决策。

3. **匹配矩阵，指明审批人。** 具体——是人或角色，不是"法务领导层"。

4. **按模板起草上报说明：** 合同内容、审查指引立场、附带建议的选项、决策截止日期。

5. **不要发送。** 起草、展示、让律师发送。

## 示例

```
commercial-escalation-flagger
Acme主协议有无上限的责任——谁批准，我说什么？
```

```
commercial-escalation-flagger
参考：acme-review-memo.md
问题：§8.2 赔偿例外排除
```

## 目的

每个合同团队都有上报矩阵，无论是否形成书面。本技能读取书面矩阵，将合同问题与之匹配，指明审批人，并起草上报说明——让律师不必在傍晚发"你有空吗"消息。

## 加载矩阵

**哪一方？** 在匹配矩阵之前，确定公司在此合同中处于哪一方。通常很明显：如果对方是提供产品或服务的供应商，你是采购方；如果对方是购买你产品或服务的客户，你是销售方。如不明显，询问。读取匹配的审查指引部分（`### 销售方合同手册`或`### 采购方合同手册`），评估该条款是否在让步范围内或触发自动上报——同一条款在销售方可以接受，在采购方可能是硬性拒绝。在起草的上报说明中注明适用的是哪一方立场，让审批人知道适用了哪份合同手册。

读取审查指引 → `## 审批与上报`。如果缺失或模糊，说明——冷启动访谈应当已捕获此项，如未捕获则业务领域配置需要编辑。

预期结构：

| 可审批 | 阈值 | 上报至 | 方式 |
|---|---|---|---|
| 法务助理 | 标准条款，<50万元 | 主办律师 | 飞书 |
| 主办律师 | 非标准但在让步范围内，<500万元 | 法务负责人 | 飞书或邮件 |
| 法务负责人 | 其他一切 | CFO/董事会 | 会议 |

加上**自动上报触发条件**——无论金额大小均需上报的事项。通常：无限责任、知识产权转让、"永不接受"列表上的任何事项。

## 工作流

### 步骤1：定性问题

上报什么？

- **金额阈值：** 合同价值超出某人的审批权限
- **条款偏离：** 某条款超出审查指引中的让步范围——需要更高级别的人决定是否接受
- **自动触发：** 存在任何情况下都须上报的事项
- **商业决策：** 这不是法律判断——需要业务负责人而非法务领导层

不要上报实际上没问题的事项。如果条款在审查指引的让步范围内，不需要上报。

### 步骤2：匹配矩阵

```
问题是自动触发条件吗？
  → 是：上报至 [该触发条件指定的人]
  → 否：继续

合同价值是否超过审查者的阈值？
  → 是：上报至在该金额级别有审批权的人
  → 否：继续

条款偏离是否超出所有已记录的让步范围？
  → 是：上报至可以批准非标准条款的人
  → 否：审查者可以批准——不需要上报
```

### 步骤3：指明审批人

具体。不是"上报至法务领导层"——指出审查指引中的人名或角色。如果矩阵未涵盖该情况，说明："上报矩阵未涵盖[情况]。建议询问[法务负责人姓名]该问题归谁负责。"

### 步骤4：起草上报说明

审批人应能从消息本身做决定——不需要"让我调出合同看看"。

```markdown
**上报至：** [姓名]
**方式：** [飞书频道 / 邮件 / 会议 — 按审查指引]
**紧急程度：** [截止日期（如有）]

---

[姓名]你好——

需要你关于 [对方当事人] [协议类型] 的决定。[一句交易背景。]

**问题：** [一段。他们想要什么，为何超出我方标准，实际风险是什么（参照《民法典》第584条可预见损失或相关合同法规则）。]

**合同原文：**
> "[精确引用]"

**审查指引说：** [引用审查指引立场]

**选项：**
1. **接受** — [一行说明为何这可能可以]
2. **驳回并附：** "[建议的对应语言]" — [一行说明对方可能的反应]
3. **终止** — [一行说明在商业背景下是否现实]

**我的建议：** [哪个选项及简要理由]

**需要决策日期：** [日期（如存在截止日期）]

[完整审查备忘录链接]
```

### 步骤5：记录上报

如果团队使用工单系统或合同管理系统审批工作流，记录。如果没有，在审查备忘录中注明上报已发送、发送对象和发送时间。下一个读到备忘录的人应能看到状态。

## 校准：有疑问时上报并附注

不必要的上报成本约等于审批人30秒——阅读、说"好的，继续"，并留下记录表明已知晓。遗漏上报的成本是签署未经批准的条款，这是单向门。成本不对称。**有疑问时，上报。**

校准标准在审查指引中，而非在本技能中。查看审查指引的既定立场、让步范围和"无论金额大小均自动上报"列表：

- **明确在让步范围内：** 无需上报。
- **明确超出范围，或在自动上报列表上：** 上报。
- **不确定——条款模糊、新颖，或勉强可以说在范围内但论据牵强：** 同样上报，并在说明中明确注明不确定性。起草标注审批人需要决定的具体问题，以及技能为何无法将其明确归入让步范围。审批人来缩减范围；技能不做主观判断。

不要因为担心过度上报会训练审批人略读消息而压制上报。那是律师通过调整审查指引阈值来解决的审批人体验问题，而不是技能就自己不确定的条款自行主观判断来解决的问题。

如果出现审查指引未涵盖的条款，不要猜测阈值——询问审查律师该类问题是否应上报，并主动提出将答案记录入审查指引，以便未来审查保持一致。

## 本技能不做的事

- 不批准任何事项。只路由。
- 不在选项间做决定。草案包含建议但审批人决定。
- 不发送上报消息——只起草。律师审阅后发送。
