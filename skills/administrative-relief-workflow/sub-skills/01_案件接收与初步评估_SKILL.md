# 模块 01：案件接收与初步评估

## 适用阶段

接案阶段。适用于任何行政案件的初始接案环节。

## 任务目标

完成案件初步信息采集，建立案件档案，形成初步评估意见。

## 执行步骤

### Step 0：前置检查

1. 读取 `./办案记录.md`（如存在）
2. 确认案件名称、当事人信息

### Step 1：采集基本信息

向用户收集以下信息（如用户未主动提供，逐项询问）：

#### 1.1 当事人信息

| 采集项 | 说明 |
|:---|:---|
| 当事人姓名/名称 | 自然人填姓名；法人/组织填全称 |
| 身份证号/统一社会信用代码 | 用于主体确认 |
| 联系方式 | 电话、地址 |
| 与行政行为的关系 | 行政相对人 / 利害关系人 |

#### 1.2 行政行为信息

| 采集项 | 说明 |
|:---|:---|
| 作出行政行为的机关 | 文书上的盖章单位是谁 |
| 行政行为文书名称 | 如"行政处罚决定书""不予行政许可决定书" |
| 文号 | 如"X行罚字〔2026〕第XX号" |
| 作出日期 | 文书落款日期 |
| 送达日期 | 当事人收到文书的日期（起算期限的关键） |
| 行为内容摘要 | 处罚金额/许可事项/强制措施内容等 |

#### 1.3 案件诉求

| 采集项 | 说明 |
|:---|:---|
| 当事人希望达到什么效果 | 撤销/变更/确认违法/责令履行/赔偿 |
| 是否有期限压力 | 是否快到期了 |
| 是否已走过其他程序 | 是否已经申请过复议/信访/诉讼 |

### Step 2：初步分类

根据采集到的信息，完成以下初步判断：

#### 2.1 行为类型分类

将案件归入以下类型之一（影响后续知识库加载）：

- [ ] 行政处罚
- [ ] 行政许可
- [ ] 行政强制（措施/执行）
- [ ] 行政征收与补偿
- [ ] 行政确认
- [ ] 行政不作为
- [ ] 政府信息公开
- [ ] 其他：___

#### 2.2 行为形态分类

- [ ] 作为（行政机关作出了某个行为）
- [ ] 不作为（应当履职而未履职）

#### 2.3 初步可行性判断

快速评估（不需要详细分析，详细分析交给后续模块）：
- 该行为是否可能属于受案范围？→ 交给模块02
- 盖章主体是否明确？→ 交给模块03
- 期限是否已过？→ 交给模块06

### Step 3：建立案件档案

#### 3.1 创建案件文件夹

按第六节归档规范创建文件夹结构。

#### 3.2 创建办案记录.md

```markdown
# 办案记录

## 当前状态
- **案件名称**：[当事人] 诉 [行政机关] [行政行为类型] 案
- **当前阶段**：接案评估
- **我方角色**：[当事人姓名] 的代理人
- **已完成模块**：01
- **进行中**：—
- **下一步**：02 受案范围分析

## 四维分析摘要
- **主体**：待分析
- **职权**：待分析
- **行为**：[行为类型]，[作为/不作为]
- **违法理由**：待分析

## 路径决策
- **受案范围**：待判断
- **路径**：待判断
- **期限状态**：待计算

## 当事人信息
- **申请人/原告**：[姓名/名称]，[身份证号/信用代码]
- **被申请人/被告**：[行政机关名称]
- **第三人**：无 / [待确认]

## 用户偏好
- [记录用户特殊要求]
```

#### 3.3 原始材料归档

将用户提供的行政行为文书归入 `01_原始材料/`。

### Step 4：输出初步评估意见

向用户汇报：
1. 案件基本信息已记录
2. 行为类型初步分类结果
3. 下一步建议（通常是"做受案范围分析"或"确认被申请人"）
4. 如有期限压力，优先提示

## 产出文件

| 文件 | 存放位置 |
|:---|:---|
| `办案记录.md` | 案件文件夹根目录 |
| `YYYYMMDD_初步评估报告_代理人.md` | `02_工作底稿/` |
| 原始材料 | `01_原始材料/` |

## 注意事项

1. **送达日期是关键**：必须明确送达日期，它直接决定复议/诉讼期限起算点。如用户不清楚，提示其核实
2. **文书上的盖章主体**：记录文书上的完整盖章名称，不要简化（后续主体分析要用）
3. **不要在此阶段做深入法律分析**：模块01只做信息采集和初步分类，深入分析交给对应模块
4. **注意信访与复议/诉讼的区别**：如果当事人说"我已经信访了"，信访不影响复议/诉讼期限，但要了解是否走过其他法律程序
