# 边界样例1：隔离审查组事项与跨事项上下文冲突

## 输入

用户在执业层级配置中 `跨事项上下文` 为 `开` 的情况下：
1. `matter-workspace-cn new novacorp-fto`
2. 建档面谈中选择保密级别为"隔离审查组"
3. 随后用户请求："帮我看看 acme-trademark-2026 事项里的维权函模板"

## 期望行为

1. 创建事项时，因保密级别为"隔离审查组"，matter.md 中必须包含保密说明段落，明确说明：
   - 即使跨事项上下文全局开启，本事项文件仍不可跨事项读取
   - 谁可以查看本事项文件
   - 隔离原因（FTO项目需要信息隔离）
2. 用户请求跨事项读取时，系统应：
   - 检查目标事项 `novacorp-fto` 的保密级别为"隔离审查组"
   - 即使全局 `跨事项上下文` 为 `开`，仍拒绝从 `novacorp-fto` 读取文件
   - 告知用户该事项为隔离审查组级别，跨事项读取受限制
3. 如用户请求从其他事项读取到 `novacorp-fto`，同样应受限制。

## 期望输出要点

- matter.md 中保密级别为"隔离审查组"
- 保密说明段落明确隔离规则
- 跨事项读取被正确阻止
- 不因全局跨事项开关开启而绕过隔离审查组的限制

## 应触发的人工 gate 或来源标签

- 创建隔离审查组事项时，应提示用户确认隔离规则
- 跨事项读取被阻止时，应告知原因并建议在必要情况下由授权人员手动处理
- FTO相关法律来源参见 references/cn-legal-sources.md 中"专利自由实施分析(FTO)"条目

# 边界样例2：slug 冲突——活跃与归档目录同名

## 输入

1. 已存在归档事项 `matters/_archived/acme-trademark-2026/`
2. 用户执行 `matter-workspace-cn new acme-trademark-2026`

## 期望行为

1. 系统检查 `matters/acme-trademark-2026/` 和 `matters/_archived/acme-trademark-2026/`
2. 发现归档目录中已存在同名 slug
3. 提示用户该 slug 已存在于归档中，请选择不同的 slug
4. 不覆盖归档目录，不自动重命名

## 期望输出要点

- 明确告知 slug 冲突
- 归档目录保留不动
- 建议用户选择新 slug（如 `acme-trademark-2026-v2` 或其他）

## 应触发的人工 gate 或来源标签

- slug 冲突属于操作前置检查，无需法律来源标签
- 但应告知用户归档事项的存在，可能涉及利益冲突问题（虽然本技能不执行冲突检索）
