# SCC 模块指南——委员会实施决定 (EU) 2021/914

本文件在**涉及国际传输时**（进口方位于欧洲经济区以外，或可从欧洲经济区以外访问）**加载**。2021年 SCC 取代了2010年 SCC 和2001年控制者间 SCC；新传输不得再订立旧版本（截止期限已于2022年12月27日届满）。

## 四个模块

2021年 SCC 是**模块化**的。当事人选择与特定传输中数据出口方和数据进口方关系相匹配的模块。模块错误属实体瑕疵——不得为控制者间传输使用模块2。

| 模块 | 出口方 | 进口方 | 典型用途 |
|---|---|---|---|
| **模块1** | 控制者 | 控制者 | 两个独立控制者交换数据（例如集团内部欧盟与非欧盟关联公司之间、目的各异的传输；并购数据室；双方均为控制者的联合营销合作） |
| **模块2** | 控制者 | 处理者 | 欧盟控制者委托非欧盟处理者；商业 DPA 中最常见的情形 |
| **模块3** | 处理者 | 次处理者 | 欧盟处理者代表（可能为欧盟或非欧盟）控制者委托非欧盟次处理者 |
| **模块4** | 处理者 | 控制者 | 反向流动：非欧盟处理者向欧盟控制者回传（罕见；通常涉及受监管的分析结果回传） |

### 快速决策规则

1. **出口方就该数据扮演什么角色？** 控制者 → 模块1或2。处理者 → 模块3或4。
2. **进口方扮演什么角色？** 控制者 → 模块1或4。处理者 → 模块2或3。
3. 交叉对照。交集即你的模块。

如双方对**不同处理操作**扮演不同角色，可能需要**多份 SCC**（或单一 SCC 中对相关数据流进行模块切换；这罕见且复杂——优先拆分）。

## 强制性附件（适用于所有模块）

SCC 是一份*协议*，但通过三个附件*落地运作*：

| 附件 | 内容 | 来源 |
|---|---|---|
| **附件 I.A** | 当事人名单（全称、地址、联系人、该传输中的角色） | 签署时起草 |
| **附件 I.B** | 传输描述（数据主体类别、个人数据类别、敏感数据+保障措施、频率、性质、目的、保留、模块2/3时的次处理者） | **与 DPA 附件1 对应**——保持对齐 |
| **附件 I.C** | 主管监管机关 | 依第13条——通常为控制者（模块1/2）或欧盟代表（模块3/4）设立地的监管机关 |
| **附件 II** | 技术和组织措施 | **与 DPA 附件2 对应**——保持对齐 |
| **附件 III** | 次处理者名单（仅模块2/3，适用一般授权时） | **与 DPA 附件3 对应** |

**关键起草原则**：当 SCC 与 DPA 并行存在时，**DPA 附件与 SCC 附件必须保持一致**。最干净的方式是通过交叉引用纳入：“本 DPA 附件2中的 TOM 构成《标准合同条款》的附件 II。”

## SCC 与 DPA 的对接

将 DPA 与 SCC 结合有两种架构选择：

### 选项A：独立 SCC + DPA
当事人签署两份独立文件。SCC 援引底层主合同；DPA 处理第28条实体内容。

- **优点**：法律卫生最干净；SCC 未经修改；国际传输与第28条实体的管辖范围清晰。
- **缺点**：两套签署流程；如未共同维护，附件存在不一致风险。

### 选项B：整合式 DPA，纳入 SCC
DPA 以援引方式纳入 SCC，通常作为附件或“传输附表”，完整复制或附带 SCC。

- **优点**：单文件签署；易于维护。
- **缺点**：SCC 中渗入“修改”的风险（禁止——见下）；谈判中 SCC 部分受关注较少的风险。

**建议**：选项A对谈判级业务更干净；选项B适合商业批量业务，前提是 DPA 明确声明“SCC 未经修改地纳入”，且当事人抵制任何修改其内容的诱惑。

### 第28条对接（模块2/3下）

2021年 SCC 旨在模块2和3下**同时满足 GDPR 第28条**的处理者关系要求（见 SCC 第8条 + 附件 II）。这意味着原则上**一套独立的模块2 SCC 可替代 DPA**。

实务中：
- 对纯粹欧洲经济区内部、附带非欧洲经济区尾部处理的处理关系，独立的模块2 SCC 可行。
- 对大多数商业关系，SCC 在商业问题上（审计后勤、责任、期限、争议解决）过于简略——实务人员仍会签署独立 DPA，并以 SCC 为附件。
- 注意：起草良好的模块2 SCC + 严格的附件 II 已满足第28条——如会造成冲突，不要在别处重复 (a)-(h) 项义务。

## SCC 中不得修改的内容

实施决定允许增加条款（第2(a)条——额外保障措施）及修改新当事人加入的可选条款（第7条），但**实体条款不得修改**。常见的不被允许的修改尝试：

- 将数据进口方的责任上限降至第12条规定以下。
- 通过“双方同意无需进一步评估”稀释第14条（第三国法律评估）。
- 删除第15条（公共机关访问请求的通知）。
- 缩减第16条（数据出口方的暂停/终止权）。
- 限制数据主体的第三方受益人权利（第3条）。

此类修改**使 SCC 作为传输机制失效**。如进口方坚持此类要求，则不存在 SCC 交易——必须考虑替代机制（BCR、第49条例外、不传输）。

## 传输影响评估（TIA）

依 Schrems II 判决（欧盟法院 C-311/18）和 SCC 第14条，当事人必须评估第三国法律 (a) 是否提供基本等效保护，或 (b) 不提供——如不提供，**补充措施**能否填补缺口。

TIA 对 SCC（或 BCR）下的**每次传输均为强制性**；这是当事人的义务，而非监管机关的监管职责。

TIA 最低内容：
1. 传输描述（对应附件 I.B）。
2. 识别进口方所在国及适用法律。
3. 评估该等法律与欧盟基本等效性的兼容性（有问题的制度：允许批量访问的监控法、缺乏救济机制、附外国政府访问的数据本地化要求）。
4. 评估实务风险（进口方是否收到过政府访问请求？进口方能否抵制？）。
5. 补充措施：技术（密钥由第三国境外持有的加密、假名化）、合同（保证条款、透明度义务）、组织（处理政府请求的政策）。
6. 结论：传输可进行 / 附带措施可进行 / 不可进行。

TIA 在本 DPA 技能中提及，但**如可用则通过单独技能起草**。在 DPA/SCC 包中纳入一条序言，确认已进行 TIA。

## 特殊地位第三国

| 状态 | 机制 | 注释 |
|---|---|---|
| **充分性决定**（英国、瑞士、日本、韩国、加拿大（商业）、新西兰、以色列、阿根廷、乌拉圭、法罗群岛、根西岛、马恩岛、泽西岛、安道尔） | 向这些国家接收方传输**无需 SCC**（以决定范围为限） | 核实范围：例如日本充分性限于私营部门商业活动 |
| **欧美数据隐私框架（DPF）** | 进口方经 DPF 自我认证：**无需 SCC**；传输时在 DPF 名单上核实认证状态 | DPF 取代了隐私护盾（2023年7月）。DPF 认证同样面临 Schrems 式审查；存在未来失效的某些风险。 |
| **欧盟-英国** | 英国充分性决定至2025年6月27日，此后可能续期；英国是最容易的目的地 | 关注续期状态 |
| **其他国家（美国非 DPF、印度、中国等）** | 需 SCC + TIA | 中国和俄罗斯尤其：TIA 门槛高；通常需要补充措施 |

对 DPF 传输，DPA 仍应处理进口方停止 DPF 认证的情形——应触发后备机制（SCC + TIA）。

## DPA 中 SCC 部分的常见缺陷

1. **附件空白**——SCC 签署时附件 I.A 已填写但 I.B / II / III 空白。使 SCC 在操作上失去意义。
2. **模块错误**——对实际为控制者间（模块1）的传输使用模块2。
3. **模块过时**——援引2010年 SCC（已不再有效）。
4. **无 TIA**——将 SCC 作为传输机制引用但未进行 TIA；违反第14条义务。
5. **DPF 作为唯一依据且无后备**——仅依赖进口方的 DPF 认证，认证失效时无后备。
6. **修改实体条款**——见上；使 SCC 失效。
7. **SCC 附件与 DPA 附件不一致**——次处理者名单不同、TOM 描述不同；两者之一或两者必然有误。
8. **遗漏次处理者 SCC**——如欧盟处理者使用非欧盟次处理者，该流动需要欧盟处理者与非欧盟次处理者之间的模块3 SCC；常被遗忘。
9. **后续传输无规定**——非欧盟进口方进一步向其非欧盟次处理者传输，无 SCC 链条。

## 输出整合

加载本指南时，DPA 输出（无论是草拟还是审查）必须：

- 识别范围内每次传输流动所需的模块。
- 确认附件 I.A / I.B / I.C / II / III 已填写（或标注缺口）。
- 确认 TIA 存在或标注该要求。
- 对草拟：提供 SCC 整合方案（选项A独立或选项B整合）。
- 对审查：标注上述九种常见缺陷中的任何一种。
