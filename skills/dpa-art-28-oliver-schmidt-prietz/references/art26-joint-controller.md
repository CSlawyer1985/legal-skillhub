# GDPR 第 26 条——共同控制者

本文件规范 `JOINT_CONTROLLER` 子模式。当下文筛查表明共同控制时，它**先于**第 28 条检查清单加载，因为将共同控制误分类为处理会产生实质上有缺陷的协议。

## 第 26 条何时适用？

> 第 26 条第 1 款："两个或两个以上控制者共同确定处理的目的和方式的，应为共同控制者。"

当两个或两个以上当事方**共同确定**同一处理操作的**目的和方式**时，即存在共同控制。决定性标准是对处理基本方面产生**趋同影响**——而非正式标签、市场力量或哪一方运营技术基础设施。

参考框架是 **EDPB 关于 GDPR 中控制者和处理者概念的指南 07/2020**（最终版于 2021 年 7 月 7 日通过）。

## 筛查检验——第 28 条（控制者-处理者）与第 26 条（共同控制者）

凡角色存在任何歧义，均在受理时运行此筛查。每个"是"都将结论拉向共同控制；多个"是"将使处理者框架站不住脚。

| # | 问题 | 拉向 |
|---|---|---|
| S1 | 双方是否对处理各有自身目的（如双方都想为自身利益使用数据，而不仅仅是为对方提供服务）？ | **共同控制** |
| S2 | 数据是否在双方之间共享，使各方均可将其用于自己确定的目的？ | **共同控制** |
| S3 | 是否一方设计处理安排而另一方仅按指令执行？ | 处理者 |
| S4 | 是否一方仅通过服务费从处理中获益，对数据无自主使用？ | 处理者 |
| S5 | 双方是否共同决定基本方面：收集哪些数据、保留多久、谁有权访问、用于什么？ | **共同控制** |
| S6 | 处理是否不可分割——任何一方都无法独自有意义地进行？ | **共同控制** |
| S7 | 双方是否拥有独立的法律依据（对同一操作基于不同的第 6 条理由）？ | **共同控制** |
| S8 | 双方关系是否可描述为"提供者使用客户数据为客户执行服务 X"？ | 处理者 |
| S9 | 双方是否以合作形象呈现给数据主体（联合品牌、联合隐私通知、共享注册表单）？ | **共同控制** |
| S10 | 一方是否在服务费之外从数据中商业获益（如分析洞察、模型训练、广告）？ | **共同控制**（且该获益可能构成单独的控制者关系） |

**决策规则**：
- 0 个"共同控制"答案 → 处理者关系；使用第 28 条 / DPA。
- 1-2 个"共同控制"答案 → 可能为处理者，附注意点；重新审视 S1、S2、S5 核验；如这些为"否"，继续使用 DPA，但纳入第 28 条第 10 款确认。
- 3 个及以上"共同控制"答案 → 共同控制；切换至 `JOINT_CONTROLLER` 模式并起草第 26 条安排。
- **特殊情况**：如 S10 为"是"且处理者获益涉及同一数据，处理者对该衍生处理可能作为**单独控制者**行事，即使其仍为原始处理的处理者。两种关系均须记录。

## 常见场景及其分类

| 场景 | 典型分类 | 原因 |
|---|---|---|
| 云托管（IaaS） | 处理者 | 提供者对客户数据无自身目的 |
| 单一客户使用的 SaaS 分析工具 | 处理者 | 同上 |
| 跨客户聚合数据用于基准比较的 SaaS 分析工具 | 基准比较为**共同控制** + 主要使用为处理者 | 提供者对聚合数据有自身目的 |
| 支付服务提供者 | **通常为共同控制或单独控制者关系** | PSP 自行确定欺诈筛查和反洗钱目的 |
| 集团内公司间的人力资源共享服务 | **共同控制**（除非有书面分配的集团内处理者结构） | 相同目的、相同数据、多个控制者 |
| 带共享线索表单的联合营销活动 | **共同控制** | 双方都获得线索 |
| 联合品牌网络研讨会，会后共享与会者数据 | **共同控制** | 双方都想自行使用线索 |
| 雇主 + 职业健康服务提供者 | 单独控制者（非共同） | 目的不同、法律依据不同 |
| 共址数据中心（仅空间和电力） | 两者都不是（不处理个人数据） | 如无法访问数据 |
| 代发送控制者名单的电子邮件营销服务 | 处理者 | 无自身目的 |
| 用自身数据库丰富名单的电子邮件营销服务 | 丰富处理为**共同控制** | 提供者贡献自身数据并具有自身目的 |
| 嵌入式社交插件（点赞按钮、跟踪像素） | 收集为**共同控制** | CJEU 的 Fashion ID / Wirtschaftsakademie 系列案件 |

## 第 26 条安排必须包含的内容

第 26 条第 1-2 款要求共同控制者**以透明方式确定其各自对 GDPR 合规的责任**，**特别是**关于：

1. **数据主体权利的行使**：哪个控制者是主要联系点、请求如何转达、由谁回应。
2. **第 13 条和第 14 条下的信息义务**：谁提供信息、提供什么内容、以什么形式。

实务中，一份 JCA 除上述两项最低要求外，还必须处理：

| # | 要素 | 注释 |
|---|---|---|
| J1 | 共同控制的范围 | 哪些处理操作属于共同控制；哪些仍属单独控制者关系或处理关系 |
| J2 | GDPR 合规责任的分配 | 分配矩阵——见下文 |
| J3 | 数据主体权利——主要联系点和转达 | 数据主体可向任一控制者行使权利（第 26 条第 3 款——无论分配如何） |
| J4 | 信息义务（第 13/14 条） | 谁起草、发布、更新隐私通知；谁处理变更 |
| J5 | 违约处理 | 谁通知监督机构（第 33 条）；谁通知数据主体（第 34 条）；合作义务 |
| J6 | 安全（第 32 条） | 各方技术和组织措施；协调机制 |
| J7 | DPIA（第 35 条） | 谁开展；相互协商 |
| J8 | 处理记录（第 30 条） | 各方维护自己的记录；交换数据以保持一致 |
| J9 | 国际传输 | 传输机制的共同方法 |
| J10 | 共同控制者之间的审计/检查权 | 相互合作，而非第 28 条第 3 款第 h 项典型的单方权利 |
| J11 | 共同控制者之间的责任 | 内部分配（第 26 条第 3 款不影响外部连带责任） |
| J12 | 安排的公开摘要 | 第 26 条第 2 款要求——须提供给数据主体，通常通过隐私通知 |
| J13 | 期限、终止及终止后数据处理 | 共同控制结束时共享数据如何处理 |

### 第 26 条第 2 款公开摘要

JCA 必须被概括并**提供给数据主体**。通常通过以下方式实现：

- 在隐私通知中加入题为"与 [对方] 的共同控制"或 "Gemeinsame Verantwortlichkeit" 的章节。
- 摘要必须以（通俗语言）解释安排的**实质**——至少包括责任分配和权利联系点。
- 注意：无论内部分配如何，数据主体可向**任一**控制者行使权利（第 26 条第 3 款）。

无配套公开摘要计划的 JCA 是不完整的。

## 不属于 JCA 的内容

- **第 28 条强制性条款**——这些适用于控制者→处理者；在控制者↔控制者关系中没有对应物，照抄会产生无意义的内容。
- **次处理者条款**——共同控制者可各自聘请自己的处理者，但这些由单独的第 28 条合同规范，而非 JCA。
- **仿照第 28 条第 3 款第 h 项的审计权**——共同控制者相互合作；他们不以相同意义上的方式相互审计。

## 混合关系

同一当事方对不同的处理操作拥有**多个并存角色**，这很常见：

- 对主要处理操作为共同控制者；且
- 对各方在其自身数据副本上分别进行的衍生处理操作为单独控制者；且
- 一方还为另一方执行纯运营服务时构成控制者-处理者关系。

在此情况下，以适当的文书记录每种关系——共同部分用 JCA，处理部分用 DPA，（需要时）单独控制者部分用数据共享协议。**不要将其合并为单一文件**——每一部分的法律定性不同，且各自要求不同的强制性内容。
