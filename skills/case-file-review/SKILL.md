# case-file-review — 案卷阅卷与证据分析

对案卷材料进行 OCR → 事实提取 → 证据分析 → 矛盾检测 → 时间轴生成 → 报告输出，一站式完成从原始案卷到阅卷报告的全流程。

## 核心原则（不可跳过）

1. **OCR 是前提**：任何图片、PDF、扫描件必须先完成 OCR 转为可编辑文本，再进行分析。不得对未 OCR 的材料直接下结论。
2. **每一条结论必须有源头**：必须标注来源文件名 + 页码/段落号。无源头的结论不得出现在报告中。
3. **矛盾点必须显式标注**：多份证据之间但凡有不一致，必须列出矛盾内容、涉及证据及编号、矛盾等级。
4. **不确定即标注"待补充"**：证据中未提及的信息不得自行补全，必须标注"材料未提及"或"待补充"。

---

## 输入模式

用户可能提供以下两种输入组合之一：

### 模式 A：仅证据材料

用户只提供证据文件（PDF/图片/Word/扫描件等），没有起诉状或判决书等程序文书。

处理目标：完成 OCR → 提取事实 → 检测矛盾 → 生成时间轴 → 输出阅卷报告。

### 模式 B：起诉状 + 证据材料

用户同时提供起诉状（或其他确定法律关系的文书）和证据材料。

处理目标：完成 OCR → 提取起诉状中的法律关系与诉讼请求 → 逐项对照证据充分性 → 检测矛盾 → 生成时间轴 → 输出阅卷报告。

---

## 完整工作流程

### Phase 1：材料接收与分类

1. 列出用户提供的所有文件清单，按类型分类：
   - **程序文书**：起诉状、答辩状、判决书、裁定书等
   - **证据材料**：合同、函件、付款凭证、聊天记录截图、录音转写等
   - **附属材料**：证据目录、质证意见等

2. 判断输入模式（A 还是 B），告知用户当前使用的分析路径。

3. 如果文件数量超过 10 个，先列出全部文件清单供用户确认范围。

### Phase 2：OCR 处理（强制执行，不可跳过）

**对每一份图片、PDF、扫描件，逐份执行 OCR。** 不得笼统说"已完成 OCR"，必须逐份列出 OCR 结果。

OCR 工具优先级：
1. 已安装的 `MinerU Document Extractor` — 首选，支持 PDF/图片/Word/PPT/扫描件转 Markdown，表格和公式识别能力强
2. `paddle-ocr` — 法律 PDF 与扫描件结构化解析备选
3. `legal-ocr` — 法律材料保守优化备选

OCR 完成后输出清单：

```
OCR 处理清单：
├── 证据1_借款合同.pdf → OCR完成，共 5 页，保存为 证据1_借款合同.md
├── 证据2_银行转账凭证.png → OCR完成，保存为 证据2_银行转账凭证.md
├── 证据3_微信聊天记录截图.pdf → OCR完成，共 12 页，保存为 证据3_微信聊天记录.md
└── ...
```

### Phase 3：事实提取与证据编号

从 OCR 文本中逐份提取关键事实，规则见 `references/fact-evidence-extraction.md`。

1. 为每份证据分配唯一编号（证1、证2、证3……）
2. 按以下维度提取事实：
   - 时间节点（具体日期、时间段）
   - 主体信息（自然人/法人名称、身份关系）
   - 金额/数量（具体数字、币种、计算方式）
   - 行为/事件（谁做了什么、结果如何）
   - 权利义务（约定的权利、承诺的义务）

3. **每条事实标注源头**，格式：
   ```
   [证1-第3页-第2段] 2024年3月15日，甲方张三向乙方李四转账人民币50万元。
   ```

### Phase 4：法律关系分析（仅模式 B）

当用户提供了起诉状：

1. 从起诉状中提取：
   - 诉讼请求（逐项列出）
   - 事实与理由（概括核心事实主张）
   - 法律关系定性（如"民间借贷关系""买卖合同关系"等）

2. 将法律关系拆解为构成要件，参见 `references/legal-element-framework.md`。
   - 示例（民间借贷）：(1) 借贷合意 (2) 款项交付 (3) 借款期限/利息约定 (4) 还款事实

3. **逐要件对照证据**：
   | 构成要件 | 对应证据 | 证据充分性 | 说明 |
   |---|---|---|---|
   | 借贷合意 | 证1（借款合同） | ✅ 充分 | 合同第2条明确借款意思表示 |
   | 款项交付 | 证2（银行转账凭证） | ✅ 充分 | 转账金额与合同一致 |
   | 利息约定 | 证1（借款合同）第4条 | ✅ 充分 | 约定年利率12% |
   | 还款事实 | — | ❌ 缺失 | 未提供还款记录 |

4. 对证据不足的构成要件，给出补证建议。

### Phase 5：矛盾点检测

逐份交叉比对证据，自动标注所有不一致之处。规则详见 `references/contradiction-rules.md`。

**矛盾等级**：
| 等级 | 标识 | 定义 | 示例 |
|---|---|---|---|
| 🔴 严重 | 致命矛盾 | 直接影响关键事实认定的冲突 | 借款金额：合同写50万，转账凭证显示30万 |
| 🟡 一般 | 普通矛盾 | 影响次要事实或细节的不一致 | 同一事件两个证人说的具体时间相差1小时 |
| 🟢 轻微 | 可解释差异 | 可能存在合理解释的差异 | 同一笔金额的表述方式不同（"伍拾万" vs "500,000"） |

**输出格式**：
```
矛盾点 #1 [🔴 严重]
- 涉及证据：证1（借款合同）vs 证2（转账凭证）
- 矛盾内容：合同约定借款金额50万元，但银行转账记录显示实际转账30万元
- 来源：[证1-第1页-第3条] vs [证2-全页]
- 可能影响：直接影响本金数额的认定
```

### Phase 6：时间轴生成

从全部证据中提取有时间标记的事件，生成可视化时间轴。

1. 提取所有时间节点，去除重复，按时间排序
2. 标注每个时间节点的事件描述和来源
3. **生成 HTML 时间轴** — 使用 `scripts/timeline-template.html` 模板，填入实际数据，生成美观的交互式时间轴页面
4. **HTML 截图转 PNG** — 使用 `agent-browser` skill 对 HTML 页面进行全页截图，输出 PNG 图片
5. **同时生成 Mermaid 代码** — 作为备选格式嵌入报告

详见 `references/timeline-extraction.md`。

**输出**：
- `timeline.html` — 可独立打开的交互式时间轴页面
- `timeline.png` — 时间轴截图，嵌入阅卷报告
- Mermaid 代码块 — 嵌入报告 Markdown

### Phase 7：阅卷报告生成

按用户输入模式选择对应模板：
- 模式 A（仅证据）→ `templates/review-report-evidence-only.md`
- 模式 B（起诉状+证据）→ `templates/review-report-complaint-evidence.md`

报告以 Markdown 格式输出，文件命名：`[案号/案件名称]_阅卷报告.md`

报告结构：
1. **基本信息**（案件名称、案号、材料清单、分析日期）
2. **OCR 处理清单**
3. **事实与证据梳理**（逐份证据的事实提取，每条标注源头）
4. **法律关系分析**（仅模式 B — 构成要件逐项对照表）
5. **证据矛盾点清单**（按等级排列）
6. **时间轴**（嵌入 Mermaid 代码 + 时间轴截图）
7. **综合分析结论**（证据链完整度评估、关键风险提示、补证建议）

## 依赖工具

| 工具 | 用途 | 是否必须 |
|---|---|---|
| MinerU Document Extractor | OCR 处理（首选） | 是 |
| agent-browser | HTML 时间轴截图 | 是（如需截图） |
| PaddleOCR / legal-ocr | OCR 备选 | 否 |

如 OCR 工具不可用，先引导用户安装：使用 `find-skills` 搜索并安装 MinerU Document Extractor。

---

## 质量检查清单

生成报告后，逐项自检：

- [ ] 所有图片/PDF/扫描件均已执行 OCR
- [ ] 每条结论都有来源标注（文件名 + 页码/段落）
- [ ] 所有证据间矛盾点已检测并标注
- [ ] 时间轴覆盖了所有可确定的时间节点
- [ ] 时间轴 HTML 已生成并可正常打开
- [ ] 证据材料未提及的信息已标注"待补充"
- [ ] 报告格式规范、层级清晰、可直接交付
