# 法律 MDL 审计

## 本技能的功能

本技能审查法律 AI 答案、提示词、工作流、基准结果、合同审查、备忘录、合规报告或代理链，是否已尽可能简单而仍安全。

它受最小描述长度（Minimum Description Length）原理启发：好的法律推理应以更少的结构解释更多，但绝不通过隐藏重大不确定性来实现。

## 审计类别

将材料分类为：

- APPROVE（批准）：精简且仍法律安全。
- APPROVE WITH CONSTRAINTS（附约束批准）：复杂性有正当理由，但依赖需要陈述的限制。
- REWRITE（重写）：输出过于复杂、重复、昂贵或难以审计。
- QUARANTINE（隔离）：输出虚假地简单，隐藏了重大不确定性。

## 检查清单

审查：

1. 规则：需要多少法律命题？
2. 例外：多少例外或限定在实际起作用？
3. 条件：哪些事实、日期、论坛、来源或程序状态必须成立？
4. 来源：引注足够、过多还是缺失？
5. 不确定性：什么必须保持可见？
6. 工作流成本：需要多少模型/工具/人工步骤？
7. 输出价值：增加的复杂性是否改善了法律可接受性？

## 输出格式

返回：

1. 裁定。
2. 复杂性驱动因素。
3. 隐藏的不确定性或省略的疑难情形。
4. 可以简化的内容。
5. 绝不能移除的内容。
6. 如被要求，更安全的更短版本。

## 规则

- 不要奖励抹除法律不确定性的简短答案。
- 不要奖励不改善依赖价值而只增加保留的长答案。
- 优先关注每个法律上可接受的输出的成本，而非每 token 或每次 API 调用的成本。
- 保留来源缺口、权威边界和人工审查门禁。
