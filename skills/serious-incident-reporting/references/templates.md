## 2. 内部升级检查清单

### 最初 4 小时
- [ ] 确认事件负责人
- [ ] 确认法律/合规负责人
- [ ] 保全日志和部署状态
- [ ] 冻结版本/构建标识符
- [ ] 确认系统是否属于高风险
- [ ] 检查是否涉及死亡 / 严重损害 / 权利影响 / 关键基础设施
- [ ] 确定事件发生的成员国
- [ ] 确定可能适用的报告期限档位

### 最初 24 小时
- [ ] 起草定性备忘录
- [ ] 联系部署者/客户获取缺失事实
- [ ] 决定暂停 / 回滚 / 警告措施
- [ ] 准备初始机关报告
- [ ] 检查 GDPR / NIS2 / MDR / 产品安全的交叉
- [ ] 准备管理层摘要

### 最初 7 天
- [ ] 完成根本原因工作流
- [ ] 决定领域级纠正行动
- [ ] 如需要，提交补充报告
- [ ] 更新使用说明 / 客户指引
- [ ] 在上市后监测中记录经验教训
