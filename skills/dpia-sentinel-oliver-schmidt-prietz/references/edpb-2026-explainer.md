# EDPB DPIA 模板说明 —— 方法论参考

> 来源：EDPB《数据保护影响评估（'DPIA'）模板——说明》，1.0 版，2026 年 3 月 10 日通过，供公众咨询。

本参考将 EDPB 关于填写 DPIA 模板的指引提炼为供 DPIA Sentinel 使用的实务方法论笔记。

---

## 1. 模板的目的与范围

EDPB 模板是一种**数据录入和报告工具**，而非 DPIA 方法论。关键设计原则：

- **方法论无关。** “控制者可按照其偏好开展风险分析和管理流程，使用其选择的 DPIA 方法论”（引言）。模板以“所有监管机构（SA）都易于接受”的格式记录“始终应予文件化的最低限度信息”。
- **预定义字段促使回答完整。** 设计目标为易用——减少错误、节省时间，并确保捕获所有必要信息。
- **有意的冗余。** “DPIA 模板各部分之间的某些冗余，可确保每项强制要素均以可追溯的方式得到明确处理，同时支持交叉引用。此外，同一事实在不同部分发挥不同功能”（引言）。控制者必须建立各部分之间的关联，并在各表格中提供一致的信息。
- **为公众咨询而通过。** 这是 1.0 版（2026 年 3 月 10 日）。在将指引视为定论前，请核查最终通过版本。

## 2. 两类风险

这是模板最重要的方法论贡献。EDPB 明确将风险分为两条独立轨道，分别在模板的不同部分评估。

### 轨道 A —— 设计固有风险（第 3.1 节）

即使“一切均完全按设计运行、所有主体均遵守规则”仍然存在的风险（第 32 段）。

**核心原则：** “即使不存在失败或攻击，设计选择本身也会给数据主体的权利和自由带来风险”（第 32 段）。

**风险来源：** 主要来自：

- 所处理的个人数据本身（第 1.1.1 节）
- 处理的直接目的（第 1.1.2 节）
- 处理的性质、范围与情境（第 1.1.4 节）

**关键定义（第 32 段）：**

| 概念 | 定义 |
|---|---|
| **威胁（Threat）** | “任何可能对数据主体权利和自由产生不利影响的情形或事件（例如关联、识别、不准确或数据披露）”——可能造成物质、非物质或非实质损害 |
| **风险源（Risk source）** | “威胁得以实现的起源或根本原因”——例如处理的目的、错误设计和弱点、暴露、使用唯一标识符、长保留期限 |
| **影响（Impact）** | 威胁实现的后果，“始终考虑数据主体的权利和自由（见 GDPR 序言第 75 条）” |

**设计固有威胁的示例：**

- 关联风险（数据集组合可实现重新识别）
- 识别风险（数据范围可锁定个体）
- 不准确（数据范围或收集方法固有）
- 画像偏差（嵌入处理设计）
- 数据披露（按设计与第三方共享）

### 轨道 B —— 运营风险（第 4.1.a 节）

源于“非默认、意外、非法或异常事件”的风险（第 35 段）。

**核心原则：** “在设计、实施、配置或运行中，或有恶意行为者时，某些环节未按预期进行”（第 35 段）。“根本原因是偏离预期、合规的状态”（第 35 段）。

**须识别的最少威胁向量：**

1. 对个人数据的**非法访问**
2. 对个人数据的**不当修改**
3. **数据消失**（可用性丧失）

**风险源示例（第 35 段）：**

| 类别 | 示例 |
|---|---|
| 技术缺陷 | 软件漏洞、配置错误、错误的访问权限 |
| 操作失误 | 将数据发送给错误接收方、使用错误数据集、忘记取消配置 |
| 维护失败 | 未修补的漏洞、过时的组件 |
| 内部威胁 | 员工超出其授权使用范围 |
| 外部攻击 | 钓鱼、勒索软件 |

## 3. 风险评估方法论

### 等级量表

“通常使用 2 至 5 个等级的量表”（第 36 段）。EDPB **不**强制规定特定量表。控制者必须自行定义：

- 可能性等级及其含义
- 严重性等级及其含义
- 风险指标以及风险优先级排序方式
- 风险接受水平

DPIA Sentinel 使用 5x5 矩阵（可能性 1-5，严重性 1-5）。这与 EDPB 完全兼容。

### 风险公式

“风险水平表达数据主体受相应威胁影响的程度，通常是以下两者的函数：(i) 威胁实现的可能性；以及 (ii) 威胁实现时将产生的负面影响的量级（严重性）”（第 37 段）。

**标准计算：** 风险 = 可能性 x 严重性，“通常使用定性量表得出一个水平（例如低/中/高）”（第 37 段）。

### 调节因素（第 37-38 段）

“提高或降低风险可能性或严重性（而非作为相应威胁的主要来源）的特征”（第 37 段）。

| 方向 | 因素类型 | 示例 |
|---|---|---|
| **加重**（上调） | 规模 | 数量非常大的数据主体 |
| | 敏感性 | 高度敏感的数据 |
| | 脆弱性 | 处于依赖或脆弱境况的数据主体（儿童、患者、工人、移民） |
| | 暴露 | 高度暴露于外部对手 |
| **减轻**（下调） | 控制措施 | 设计选择和措施（来自第 2.3 节） |

**应用：** “调节因素并非始终存在，可能有助于将基线风险（可能性 x 严重性）上调或下调，以反映该特定处理及其情境的现实细微差别”（第 37 段）。这些**不是**公式乘数——它们代表经文件化论证的情境调整。

### 固有风险（第 37 段）

“对于特定数据处理，固有风险是控制者假定基线或初始计划措施后分配给计划处理的风险水平”（第 37 段）。

- 合并**轨道 A**（第 3.1 节）和**轨道 B**（第 4.1.a 节）风险
- 在行动计划（第 4.2 节）的额外缓解措施**之前**评估

### 剩余风险（第 42 段）

“控制者反思不可接受或过高的风险、决定增加额外缓解措施、并评估这些新措施实际在多大程度上降低了固有（初始或基线）风险之后，仍然存在的风险”（第 42 段）。

- 在第 4.2.a 节的额外缓解措施**之后**评估

### 风险可接受性（脚注 9）

关于可接受性的两项关键原则：

- “数据保护中的风险，如其潜在影响的严重性非常高，即使其发生的可能性很低，也可被视为不可接受”（脚注 9）
- “如对数据主体的后果可能极为严重，无论事件预计多么罕见，风险都可能被视为不可接受”（脚注 9）

这意味着高风险严重性/低可能性**不能**仅基于概率而被排除。

## 4. 基于资产的风险分析

### 定义

“‘资产’通常指用于处理个人数据的任何资源，无论有形或无形”（第 20 段）。“在数据保护语境中，资产既代表价值向量，也代表风险向量”（第 20 段）。

### 资产类型

| 类别 | 示例 |
|---|---|
| 硬件、基础设施、网络 | 服务器、笔记本电脑、移动设备、存储介质、扫描仪、VPN 网关 |
| 软件 | 数据库引擎、业务应用程序 |
| API 与模型 | 接口、AI/ML 模型 |
| 人员 | 用户、管理员、开发人员、操作人员、支持人员、决策者 |
| 场所与场地 | 数据中心、档案库 |
| 组织性 | 政策、程序、与处理者和分处理者的合同 |

### 范围界定原则

- 仅纳入**与风险相关**的资产：“其受损会以非琐碎方式合理地影响权利和自由”的资产（第 20 段）
- 与风险相关的资产示例：直接存储或处理个人数据的资产、控制访问或保护数据的资产、暴露或高影响组件（面向公众的门户、API、与第三方的数据共享接口）
- “非常小、通用或易于替代的要素通常无须单独列示”（第 20 段）

### 分组

- 按以下方式分组：逻辑模块、技术层或功能
- “在完整性与可管理性之间取得平衡”（第 20 段）
- 逐设备/逐服务的详细清单放在单独的技术文档中
- DPIA 模板捕获与风险评估和管理密切相关的架构

## 5. 数据生命周期阶段

模板规定了五个明确的生命周期阶段（第 19 段）：

| 阶段 | 描述 |
|---|---|
| **1. 收集** | 收集哪些数据以及如何收集，包括来源和提供给数据主体的信息 |
| **2. 使用** | 对数据执行的操作、使用的技术、涉及的自动化决策或画像分析、数据是否与其他数据集合并 |
| **3. 存储** | 数据存储的地点和方式（物理、云端、第三方），以及谁可访问 |
| **4. 共享与转移** | 向第三方共享数据或向欧盟境外转移、使用的法律机制或工具（如 SCC、充分性决定） |
| **5. 删除与销毁** | 不再需要时安全删除数据（包括永久擦除方法）的标准和程序 |

## 6. 实施状态模型

每项合规措施都要求三个层级（第 27 段）：

| 状态 | 定义 |
|---|---|
| **计划中（Planned）** | “保障措施仅处于意向或设计阶段，已被认定为必要，但尚未部署至生产环境” |
| **部分实施（Partially implemented）** | “措施的某些要素已到位，但重要方面缺失或不完整” |
| **已实施（Implemented）** | “措施存在、已部署并在真实环境中有效运行，而非仅停留在纸面；有证据表明控制措施按预期发挥作用” |

## 7. 必要性与比例性作为上游闸门

第 3 节在风险缓解（第 4 节）**之前**评估。这是顺序性闸门。

### 必要性（第 33 段）

- 评估处理对数据主体权利和自由而言是否**有效**且**侵入性最小**
- 分析处理是否“以可证明的方式按预期运行，至少达到适当或要求的水平”
- 必须提供**证据**——具体而言是“关于所考虑的不同替代方案及其实现目的之有效性的证据”
- 参考文献：EDPS《评估限制个人数据保护基本权利之措施的必要性：工具包》

### 比例性（第 34 段）

- “必要性是比例性的前提条件”（第 34 段）
- 讨论处理的重要性及其对数据主体、组织以及集体的潜在利益
- 核心问题：“考虑到对数据保护和隐私权利的限制，为达成目的而拟进行的处理，是否是对你所具有需求的相称回应？”（第 34 段）
- 处理产生的利益不应被其对基本权利和自由的不利影响所超过
- 必须利用第 3.1 节（设计固有风险）的结果来反思利弊平衡
- 参考文献：EDPS《评估限制隐私和数据保护基本权利之措施的比例性指南》

## 8. 四种结果的决策模型

第 6 节规定四种结果（第 49 段）：

| 结果 | 代码 | 使用时机 |
|---|---|---|
| **拒绝（REJECTED）** | (a) | 必须放弃处理——风险不可接受、要求的检验无法通过、DPO、数据主体或监管机构建议放弃 |
| **咨询（CONSULTATION）** | (b) | 咨询监管机构——或 (i) 采取一切可行措施后剩余风险仍然较高，或 (ii) 国内法依 GDPR 第 36(5) 条要求咨询 |
| **批准（APPROVED）** | (c) | 处理可按计划进行——剩余风险可接受；无第 36(5) 条要求适用 |
| **有条件批准（CONDITIONALLY APPROVED）** | (d) | 仅在满足特定条件后处理方可进行——必须将条件与第 4.2 节的措施关联（如“通过修改数据处理设计以更好地应对已识别的风险”） |

## 9. 与 WP 248 rev.01 的关系

EDPB 明确援引 WP 248 rev.01（《数据保护影响评估指南》）作为基础性 DPIA 方法论指南（脚注 2 和 3）。

### 模板从 WP 248 中**保留**的内容

- 两阶段风险评估（先固有风险，后剩余风险）
- 用于确定 DPIA 义务的九项标准门槛分析
- 进行 DPIA 的第 35(3) 条强制性触发情形

### 模板在 WP 248 之外**新增**的内容

- 将**调节因素**作为风险评估中的明确概念
- 将**资产清单**作为 DPIA 的结构化要素
- **五阶段数据生命周期**（收集、使用、存储、共享/转移、删除/销毁）
- **实施状态层级**（计划中 / 部分实施 / 已实施）
- **四种结果的结论模型**（拒绝 / 咨询 / 批准 / 有条件批准）
- 关于 DPIA 团队角色和职责的 **RACI 建议**

### 模板对 WP 248 的**细化**

- 将必要性和比例性作为相互独立、先后排序的评估
- 将设计固有风险与运营风险作为两条独立轨道
- 模板各部分之间的交叉引用以实现可追溯性
