# EDPB DPIA 模板 v1.0（2026 年 3 月 10 日）——字段规范

> 来源：EDPB《数据保护影响评估（"DPIA"）模板》1.0 版，2026 年 3 月 10 日通过，供公开征求意见。

本参考文件逐字段记录了完整的 EDPB 模板结构，供 DPIA Sentinel 在生成 EDPB 格式输出时使用。

---

## 第 0 节——处理活动概览

### 0.1 控制者

**目的：** 识别 GDPR 控制者及所有必要的联系信息。对于共同控制者，须明确界定每一方的义务和任务（每个控制者一张表格）。（¶0）

**评估阶段：** 受理

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 控制者 | 控制者的名称/法人实体 |
| 组织内部负责该处理活动的管理部门 | 涉及的内部部门/单位 |
| 主要营业机构/联系点或代表 | 主要联系人或欧盟代表 |
| 数据保护官（DPO）或类似职能的信息（如适用） | DPO 姓名、联系信息、职责 |

**备注：**
- 共同控制者：每个控制者一张表格，增加一行以明确各自对应的义务和任务。
- 义务/任务的定义必须遵循 EDPB 07/2020 号指南（关于 GDPR 中控制者和处理者概念）。

---

### 0.2 处理者与再处理者

**目的：** 识别参与处理活动的所有处理者和再处理者，并按照 EDPB 07/2020 号指南明确界定其义务和任务。（¶1）

**评估阶段：** 受理

**规定结构：**

| 列 | 内容 |
|--------|---------|
| # | 序号（1、2、……N） |
| 处理者 | 处理者或再处理者的名称 |
| 其义务和任务的定义 | 对处理者所做工作的明确描述 |

**备注：**
- 每个处理者/再处理者一行。
- 任务定义必须按照 EDPB 07/2020 号指南做到明确无歧义。

---

### 0.3 处理活动名称

**目的：** 提供该处理活动的内部名称（取自处理活动记录，ROPA），如有可能，提供当前版本，说明该处理活动过去变更的历史。（¶2）

**评估阶段：** 受理

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 处理活动的内部名称 | 处理活动记录中显示的名称 |
| 当前版本 | 版本标识符 + 处理活动本身的变更历史 |

**备注：**
- 这是*处理活动*的版本，不是 DPIA 文件的版本（后者见 0.5）。

---

### 0.4 处理活动规划

**目的：** 提供处理活动的预计启动和结束日期。（¶3-4）

**评估阶段：** 受理

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 预计启动日期 | 处理活动预计开始的日期 |
| 预计结束日期或终止条件 | 处理活动结束的日期或条件（如适用，例如有限定存续期的项目） |

**备注：**
- 仅在处理活动为临时性时才需要填写结束日期。

### 0.5 DPIA 技术表

**目的：** 记录 DPIA 自身的版本历史、评估团队、参考材料、开展 DPIA 的理由、范围、完成/确认日期以及公开意图。（¶5-11）

**评估阶段：** 受理

**规定结构：**

| 字段 | 内容 |
|-------|---------|
| 当前版本和版本日志 | DPIA 模板的版本 + DPIA 文件本身的变更历史（¶5） |
| 参与开展本 DPIA 的团队 | 姓名、角色、任务、职责。建议采用 RACI 矩阵（¶6） |
| 指南、标准、行为准则及其他参考材料 | 用于开展本 DPIA 的材料清单（¶7） |
| 开展 DPIA 的理由 | 复选框组——见下文（¶8） |
| 本 DPIA 的范围 | 考虑了哪些内容、排除了哪些内容，并说明排除的理由（¶9） |
| 完成日期 | DPIA 完成的日期（¶10） |
| 正式确认日期 | 负责官员（总经理、首席执行官等）正式批准 DPIA 的日期（¶10） |
| 公开意图 | 复选框：否 / 已公开发布（方式？）/ 已在外部共享（方式？）（¶11） |

**触发理由复选框（可多选）：**

*第 1 组——新处理活动，因高风险可能须开展 DPIA（GDPR 第 35 条第 3 款强制性要求）：*

| 复选框 | 标准 |
|----------|-----------|
| ☐ | 基于自动化处理（包括用户画像）对个人方面进行系统而全面的评估，并据此作出产生法律效力或类似重大影响的决定 |
| ☐ | 大规模处理第 9 条第 1 款所述的特殊类别数据或第 10 条所述的刑事定罪/犯罪数据 |
| ☐ | 大规模系统性地监控公众可进入的区域 |

*第 2 组——新处理活动，依国内法可能须开展 DPIA：*

| 复选框 | 标准 |
|----------|-----------|
| ☐ | 国内法要求（请说明） |

*第 3 组——新处理活动，依据 EDPB 和国内指导可能须开展 DPIA：*

| 复选框 | 标准 |
|----------|-----------|
| ☐ | 评估或打分，包括用户画像和预测 |
| ☐ | 具有法律或类似重大影响的自动化决策 |
| ☐ | 系统性监控 |
| ☐ | 敏感数据或高度个人性质的数据 |
| ☐ | 大规模处理的数据 |
| ☐ | 数据集匹配或合并 |
| ☐ | 涉及弱势数据主体的数据 |
| ☐ | 创新性应用或采用新的技术或组织解决方案 |
| ☐ | 阻止数据主体行使权利或使用服务或合同的处理活动 |
| ☐ | 其他（例如国内清单）——请说明 |

*第 4 组——新处理活动，DPIA 必要或有裨益：*

| 复选框 | 标准 |
|----------|-----------|
| ☐ | DPO 的意见或建议 |
| ☐ | 数据主体（或其代表）的意见或建议 |
| ☐ | 行为准则、标准、最佳实践等的要求 |
| ☐ | 其他（例如风险管理、证明问责、建立信任）——请说明 |

*第 5 组——风险已变化的既有高风险处理活动：*

| 复选框 | 标准 |
|----------|-----------|
| ☐ | 数据处理活动已发生变化 |
| ☐ | 处理活动所在的组织或社会背景已发生变化 |

须附叙述性说明："如何变化？"并提供解释。

**备注：**
- 可跨组多选复选框。
- 已公开版本不应包含敏感信息（例如安全细节）（¶11）。

### 1.1.d 处理活动的性质、范围和背景

**目的：** 描述处理活动的性质（操作、技术）、范围（从数据主体视角看的数据量、规模、频率、持续时间）和背景（用例、业务流程、与数据主体的关系、弱势群体）。（¶15-17）

**评估阶段：** 描述

**规定结构：**

| 字段 | 内容 |
|-------|---------|
| 处理活动的性质 | 个人数据将被如何处理：涉及的操作、使用的技术（¶15） |
| 处理活动的范围 | 数量/规模（数据主体人数、数据项目数）、地理和组织覆盖范围、从数据主体视角看的频率或持续时间（每次使用/会话、定期、持续/近持续、事件驱动/偶尔）（¶16） |
| 处理活动的背景 | 用例、所支撑的业务流程、控制者地位、与数据主体的关系、数据主体类别、潜在的弱势群体（¶17） |
| 是否为跨境处理活动？ | 复选框：否 / 是（正当性说明和细节） |
| 个人数据是否将传输给第三国或国际组织中的接收者？ | 复选框：否 / 是（正当性说明和细节） |

**备注：**
- 跨境处理：在多个成员国设有机构背景下的处理活动，或对多个成员国的数据主体产生实质性影响的处理活动。
- 国际传输：向第三国或国际组织的传输。

### 1.2 功能描述

**目的：** 以结构化方式概述处理活动，将其分解为阶段或环节。描述包括控制者、处理者和再处理者在内的完整数据生命周期。（¶18-19）

**评估阶段：** 描述

**规定结构：**

| 列 | 内容 |
|--------|---------|
| # | 序号（1、2、……N） |
| 处理阶段或环节 | 该阶段的名称/描述 |
| 操作类型 | 复选框：☐ 收集 / ☐ 使用 / ☐ 存储 / ☐ 共享与传输 / ☐ 删除与销毁 |
| 说明 | 该阶段发生何事的具体细节，涵盖数据生命周期的各个方面 |

**按 ¶19 须涵盖的数据生命周期方面：**
- **收集：** 收集哪些数据、如何收集、来源、向数据主体提供的信息。
- **使用：** 执行的操作、技术、自动化决策/用户画像、与其他数据集的合并。
- **存储：** 存储地点和方式（物理、云端、第三方）、谁可以访问。
- **共享与传输：** 向第三方共享、向欧盟境外传输、法律机制（SCC、充分性认定）。
- **删除与销毁：** 安全删除的标准和程序、永久擦除的方法。

**备注：**
- 应辅以一个或多个数据流图或类似图形。
- 此处的处理阶段将被第 1.3 节交叉引用。

### 1.3 处理手段、支撑资产与底层架构

**目的：** 基于 1.2 的功能描述，说明处理手段并提供必要支撑资产的清单。资产是用于处理个人数据的资源，既是价值载体也是风险载体。（¶20）

**评估阶段：** 资产清单

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 处理阶段或环节（参照 1.2 的功能描述） | 对 1.2 各阶段的交叉引用 |
| 处理手段和支撑资产 | 按类型分组的资产清单 |
| 说明 | 每项资产与处理活动和风险的关系 |

**资产类型类别：**
- **硬件、基础设施和网络资产：** 服务器、笔记本电脑、移动设备、存储介质、扫描仪、VPN 网关
- **软件：** 数据库引擎、业务应用
- **API 与模型：** API 端点、机器学习/人工智能模型
- **人员：** 用户、管理员、开发人员、操作人员、支持人员、决策者
- **场地与场所：** 数据中心、档案库
- **组织资产：** 政策、程序、与处理者/再处理者的合同

**备注：**
- 仅列入对风险分析必要的资产，即其受损可能对权利和自由产生非轻微影响的资产（¶20）。
- 重点关注：直接存储/处理个人数据的资产、控制访问或保护数据的资产、暴露/高影响组件（面向公众的门户、API、数据共享接口）。
- 非常小、通用或易于替换的要素无需单独列示。
- 按逻辑模块、技术层或功能分组。按设备/按服务的详细清单保留在单独的技术文档中（¶20）。
- 在完整性与可管理性之间取得平衡。

## 第 2 节——处理活动分析

### 2.1.a 法律依据

**目的：** 针对每个目的（来自 1.1.b）和每个次要/兼容用途（来自 1.1.c）分析处理活动的法律依据。对于第 6 条第 1 款第(f)项，须进行平衡测试（合法利益评估）。（¶22-23）

**评估阶段：** 必要性

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 目的/用途（参照 1.1.b 处理目的及 1.1.c 次要或兼容目的） | 对特定目的或次要用途的交叉引用 |
| 法律依据（GDPR 第 6 条第 1 款） | 复选框选择——见下文 |
| 正当性说明 | 推理；如为第 6 条第 1 款第(f)项，须包含 LIA 平衡测试 |

**法律依据复选框（GDPR 第 6 条第 1 款）：**

| 复选框 | 依据 |
|----------|-------|
| ☐ (a) | 数据主体已同意为一个或多个特定目的处理其个人数据 |
| ☐ (b) | 处理活动为履行数据主体作为一方的合同所必需，或为应数据主体在订立合同前的要求采取措施所必需 |
| ☐ (c) | 处理活动为控制者遵守法律义务所必需 |
| ☐ (d) | 处理活动为保护数据主体或另一自然人的重大利益所必需 |
| ☐ (e) | 处理活动为执行公共利益任务或行使授予控制者的官方权力所必需 |
| ☐ (f) | 处理活动为控制者或第三方追求的合法利益所必需，但此类利益被要求保护个人数据的数据主体的利益或基本权利和自由（尤其是数据主体为儿童时）所压倒的除外 |

**备注：**
- 来自 1.1.b 和 1.1.c 的每个目的/用途一行。
- 对于第 6 条第 1 款第(f)项：必须按照 EDPB 1/2024 号指南进行带平衡测试的合法利益评估（LIA）。
- 如果分析依赖于对已实施措施或剩余风险的假设，这些假设必须交叉引用到模板的相应章节。

---

### 2.1.b 解除处理禁止的理由

**目的：** 针对 1.1.a 中识别的每个特殊类别数据项目，识别并论证解除 GDPR 第 9 条第 2 款下处理禁止的理由。（¶24）

**评估阶段：** 必要性

**规定结构：**

| 列 | 内容 |
|--------|---------|
| 个人数据特殊类别（项目或要素，参照 1.1.a） | 对 1.1.a 中被标记为特殊类别的项目的交叉引用 |
| 解除处理禁止的理由（GDPR 第 9 条第 2 款） | 复选框选择——见下文 |
| 正当性说明 | 所选例外为何适用的推理 |

**第 9 条第 2 款复选框：**

| 复选框 | 理由 |
|----------|--------|
| ☐ (a) | 为一个或多个特定目的获得明确同意（除非联盟法或成员国法规定该禁止不得由数据主体解除） |
| ☐ (b) | 为履行就业、社会保障和社会保护法领域中的义务和权利所必需（经联盟法或成员国法或具有适当保障措施的集体协议授权） |
| ☐ (c) | 在数据主体身体上或法律上无法表示同意时，为保护其重大利益所必需 |
| ☐ (d) | 由具有政治、哲学、宗教或工会目标的非营利机构开展，仅涉及成员/前成员/经常联系者，未经同意不得对外披露 |
| ☐ (e) | 数据主体本人已明显公开的数据 |
| ☐ (f) | 为提起、行使或抗辩法律主张，或为以司法身份行事的法院所需 |
| ☐ (g) | 出于重大公共利益的需要（联盟法或成员国法、成比例、尊重数据保护权的本质、具有适当保障措施） |
| ☐ (h) | 为预防性或职业医学、工作能力评估、医疗诊断、健康或社会关怀的提供或管理所必需（联盟法或成员国法或与健康专业人员的合同，受第 9 条第 3 款条件约束） |

## 第 3 节——必要性与相称性考量

### 3.1 处理活动对数据主体权利和自由的影响

**目的：** 识别固有设计风险：按设计和计划实施的处理活动（即使在一切按预期运行时）所构成的威胁、其实现方式、风险来源以及对数据主体权利和自由的影响。（¶32）

**评估阶段：** 固有风险（轨道 A）

**规定结构：**

| 列 | 内容 |
|--------|---------|
| # | 序号（1、2、……N） |
| 按设计和计划实施的处理活动所构成的威胁（包括降低风险的技术、法律/合同和组织措施） | 对固有设计威胁的描述 |
| 它如何得以实现？ | 实现场景 |
| 风险来源（目的、错误设计和弱点、暴露等） | 起源/根本原因：处理目的、设计选择、弱点（例如唯一标识符、过长保留期）、暴露 |
| 对数据主体权利和自由的影响 | 后果：身体、物质或非物质损害（参见 GDPR 序言第 75 段） |

**关键定义（¶32）：**
- **威胁：** 任何可能对数据主体权利和自由产生不利影响的情况或事件（例如关联、识别、不准确、数据泄露）。
- **风险来源：** 威胁得以实现的原点（例如目的、错误设计、弱点、暴露）。
- **影响：** 威胁实现的后果，始终考虑数据主体的权利和自由。

**备注：**
- 这些风险即使一切完全按设计运行且所有行为者遵守规则时仍然存在。
- 威胁主要来源于：处理的个人数据（1.1.a）、目的（1.1.b）、性质/范围/背景（1.1.d）。
- 本表的场景将在第 4.1.c 节与 4.1.a 的场景合并（固有风险评估）。

### 3.2 评估处理活动的必要性

**目的：** 评估拟议处理活动是否有效且对数据主体权利和自由的侵扰性最小。提供所考虑替代方案的证据。（¶33）

**评估阶段：** 必要性 + 相称性

**规定结构：** 叙述性字段。

**内容要求：**
- 证明处理活动按预期发挥作用（至少达到适当/要求的水平）。
- 评估最小侵扰性。
- 提供关于所考虑的不同替代方案及其实现目的有效性的证据。
- 提供正当性说明。

**备注：**
- 必要性是相称性的先决条件（必须在 3.3 之前确立）。

---

### 3.3 评估处理活动的相称性

**目的：** 讨论处理活动的重要性及其潜在裨益，对比其对数据主体权利和自由的影响。进行利与弊的权衡。（¶34）

**评估阶段：** 必要性 + 相称性

**规定结构：** 叙述性字段。

**内容要求：**
- 讨论处理活动的重要性及其对数据主体、组织和整个社会的潜在裨益。
- 将（来自 3.1 的）对权利/自由的影响与处理活动产生的优势进行比较。
- 权衡利与弊、裨益与成本。
- 回答："为实现该目的而拟议的处理活动，鉴于对数据保护和隐私权的限制，是否是对该需求的相称回应？"
- 以完整、最新的信息提供证据和正当性说明。

**备注：**
- 必要性（3.2）是相称性的先决条件。
- 引用 EDPS《关于评估限制隐私和个人数据保护基本权利的措施之相称性的指南》。

## 第 4 节——风险评估与管理

### 4.1.a 非默认、意外、非法或异常事件造成的影响

**目的：** 识别运营/网络安全威胁：非默认、意外、非法或异常事件如何对数据主体权利和自由构成威胁。这些威胁在事情未按预期进行时实现（不同于涵盖设计风险的 3.1）。（¶35）

**评估阶段：** 固有风险（轨道 B）

**规定结构：**

| 列 | 内容 |
|--------|---------|
| # | 序号（1、2、……N） |
| 故障和偏离设计及默认状态所造成的威胁、对数据保密性、完整性和可用性（与网络安全相关）的威胁等 | 对运营/安全威胁的描述 |
| 它如何得以实现？ | 实现场景 |
| 风险来源（暴露和错误、漏洞等） | 根本原因：软件缺陷、配置错误、错误的访问权限、运营错误、维护缺失、内部人员滥用、外部攻击 |
| 对数据主体权利和自由的影响 | 后果 |

**最低强制威胁识别：**
- 非法访问个人数据
- 个人数据被非预期修改
- 个人数据消失

**典型风险来源（¶35）：**
- 软件缺陷
- 配置错误
- 错误的访问权限
- 运营错误（将数据发送给错误接收者、使用错误数据集、忘记取消配置）
- 维护缺失（未修补的漏洞、过时组件）
- 内部人员滥用（员工超出授权使用范围）
- 外部攻击（网络钓鱼、勒索软件）

**备注：**
- 这些威胁不同于 3.1：它们发生在偏离预期/合规状态或存在恶意行为者时。
- 本表的场景将在第 4.1.c 节与 3.1 的场景合并（固有风险评估）。

### 4.1.b 方法

**目的：** 说明风险评估和管理方法。提供理解与解读风险评估输出所必需的信息。（¶36）

**评估阶段：** 固有风险（轨道 A+B）

**规定结构：** 叙述性字段。

**内容要求：**

- 严重性等级及其含义（通常为 2 至 5 级量表）

**备注：**

**规定结构：** 叙述性字段。

**内容要求：**
- DPO 的意见、结论和建议（例如关于风险和缓解措施的意见）（¶45）
- 在 DPIA 过程和规划中遵循 DPO 意见后采取的行动（¶46）
- 回答问题："控制者如何落实了 DPO 的意见？"

### 5.2 数据主体或其代表的意见

**目的：** 记录数据主体（或其代表）的意见、结论和建议，并说明其在 DPIA 过程中的参与情况。（¶47-48）

**评估阶段：** 第 36 条核查

**规定结构：** 叙述性字段。

**内容要求：**
- 数据主体（或其代表）的意见、结论和建议（¶47）
- 其在 DPIA 过程中参与情况的说明（¶48）
- 如数据主体未参与：说明为何认为不适当或为何不可能

## 第 6 节——结论与决定

**目的：** 基于完整评估，就数据处理活动的可行性作出结论性决定。（¶49-50）

**评估阶段：** 文件化

**规定结构：** 四种互斥的复选框结果：

| 复选框 | 决定 | 描述 |
|----------|----------|-------------|
| ☐ | 驳回（REJECTED） | 处理活动必须放弃（风险不可接受、无法通过所需测试、DPO/数据主体/监管机构建议放弃等） |
| ☐ | 征询（CONSULTATION） | 处理活动将征询监管机构意见——选择下列子理由 |
| ☐ | 批准（APPROVED） | 处理活动可立即进行。剩余风险可接受，且无国内法要求征询或事先授权（GDPR 第 36 条第 5 款） |
| ☐ | 附条件批准（CONDITIONALLY APPROVED） | 处理活动仅在满足特定条件后方可进行 |

**征询（CONSULTATION）子理由：**

| 复选框 | 理由 |
|----------|--------|
| ☐ (a) | 数据控制者无法找到足够措施将风险降至可接受水平（剩余风险仍然较高），且不希望放弃该处理活动 |
| ☐ (b) | 国内法要求控制者就为执行公共利益任务（包括社会保护和公共卫生）进行的处理活动征询监管机构意见和/或取得其事先授权（GDPR 第 36 条第 5 款） |

**附条件批准（CONDITIONALLY APPROVED）的条件：**

| 字段 | 内容 |
|-------|---------|
| 条件 1 | 须满足的条件的描述 |
| 条件 2 | 须满足的条件的描述 |
| …… | 按需增加其他条件 |

**可选正当性说明：** 用于解释/论证所做决定的叙述性字段（¶50）。

**备注：**
- 附条件批准的条件可链接到模板的先前章节（例如 4.2 中的措施）。
