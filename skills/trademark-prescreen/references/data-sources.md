## 一、数据源分层（多源交叉预检）

单源检索容易漏、容易旧。**每个标样必须跨 ≥3 个源交叉核对**，高冲突类补至 ≥4 源。

**第1层 · 官方金标准（最高权重，最终裁定基准，全部免费）**
- **商标网上查询系统** wcjs.sbj.cnipa.gov.cn — 注册登录即用，含「近似查询/综合查询/状态查询/公告查询/商品服务项目查询」5 大模块，数据覆盖 1980 年至今。本 skill 做官方复核的**主入口，免费、无需数字证书**。
- **商标数据开放系统** sbj.cnipa.gov.cn — 全量商标数据批量下载（8 张表 60 项），需先申请「商标数字证书」（约 1 个月发放），适合程序化/批量拉取。
- **知识产权数据资源公共服务系统** ggfw.cnipa.gov.cn（原数据资源管理系统）— 自然人/企事业单位免费注册，开放专利/商标/地标等全量数据包下载，是**最易上手的全量免费源**。
- 正式结论以官方源为准（详见 `references/cnipa-guide.md`）。

**第2层 · 主力商业库（免费检索，交叉验证）**
- 权大师 quandashi.com（1.9亿+ 数据、139+ 国、含审查流程/状态/申请人/图样；官方开放 MCP/API，但网页端动态反爬，纯 WebFetch 抓不到明细，靠 WebSearch 拼结果或走 API）
- 标库网 biaoju.com.cn（8000万+、与商标网同步、近似比对强）
- 社标网 sheBiao.com（图形/近似检索见长）
- 路标网 chatm.com（猪八戒系，公告/分类检索）

**第3层 · 申请人关联（核实"谁注册的"、防同名企业混淆）**
- 企查查 / 天眼查 / 爱企查 / 启信宝 — 商标申请人 → 工商主体关联，确认是否为同名不同主体。

**第4层 · 通用检索兜底**
- WebSearch（必应/百度）：按 `标样+第X类+注册号` 补查零散结果。

**交叉原则**：同一冲突标若被 ≥2 个独立源印证 → 标记为「高可信障碍」；仅 1 源且无官方印证 → 标记「待官方复核确认」。报告中列出各源命中情况，提升可信度。

> 权大师/标库网等网页端动态加载严重，WebFetch 常只拿到空壳；可靠做法是用 WebSearch 带 site/关键词检索具体商标，或走权大师官方 MCP/API 做结构化调用。

## 二、检索降级策略（源不可用时自动切换 · 保底不卡死）

公开数据库随时可能打不开 / 反爬 / 限流。必须按以下优先级自动降级，绝不卡在单一源或编造"查无冲突"：

**四级降级框架**
1. **第2层某库失败**（WebFetch 空壳 / 超时）→ 立即切换同层其他库（权大师→标库网→社标网→路标网）继续；报告中标记「该源本次不可用」，不影响其他源结论。
2. **第2层全部失败** → 退回第1层官方源（中国商标网 wcjs + ggfw.cnipa.gov.cn），输出「基础版报告」，并在报告顶部标注「商业库不可用，结论以官方源为限」。
3. **官方源 WebFetch 也失败** → 用 WebSearch 兜底检索（带 `site:sbj.cnipa.gov.cn` / `标样 第X类 注册号` 等），标注「数据待官方复核」。
4. **所有源均不可达** → **不输出空报告**，而是输出「预检暂不可用」提示卡 + 给出用户手动去中国商标网核验的具体步骤（登录→商标网上查询→近似查询→输入检索词表的词）+ 建议委托备案代理机构。

**具体错误场景 → 提示语 → 修正建议（必须照此向用户明示，禁止只写模糊"待确认"）**

| 错误场景 | 向用户显示的提示语 | 修正建议 / 用户下一步 |
|---|---|---|
| WebFetch 抓权大师返回空壳（动态加载） | 「⚠️ 权大师网页端动态加载，本次未能读取明细，已自动切换至标库网 / 企查查继续检索」 | 无需用户操作；同源重试已自动跳过 |
| 某一商业库超时 / 限流（429） | 「⚠️ 标库网暂时限流，已跳过该源，改用社标网 + 中国商标网交叉核对」 | 自动重试其他源，不影响结论 |
| 官方源 wcjs 登录态失效 / 打不开 | 「⚠️ 中国商标网本次不可达，已用 WebSearch 兜底检索，相关结论标注『待官方复核』」 | 建议用户稍后自行登录 wcjs 复核检索词表 |
| 检索无结果（查不到在先商标） | 「✅ 本次检索未发现在先近似商标，但受 1–4 个月审查盲期影响，此结果≠绝对安全」 | 申报后做 1 年期监测，不服盲期风险 |
| 同名企业多家并存 | 「⚠️ 发现 N 家同名『XX公司』，已按『申请人主体=您提供的公司全称』筛选，其余不计入冲突」 | 请用户确认自己公司准确全称 |
| 所有源全部失败 | 「⚠️ 预检暂不可用：当前所有商标数据库均不可达。请手动前往中国商标网（wcjs.sbj.cnipa.gov.cn → 商标网上查询 → 近似查询）输入检索词表核验，或委托备案代理机构」 | 给出手动步骤清单 + 建议代理 |

**原则**：宁可降级输出有限结论 + 明确标注「哪个源失败 / 为什么 / 用户该怎么做」，也绝不卡死流程、不写模糊"待确认"、绝不编造注册号/检索结果。

## 三、经营范围 → 尼斯类别映射

把经营范围逐条映射到尼斯分类，做成映射表。常见对照：

| 业务 | 类 |
|---|---|
| 软件开发/物联网研发/网络技术服务/信息技术咨询/网站建设/SaaS/云计算/平面设计/图文制作 | **42** |
| 广告设计/代理/制作、市场营销策划、企业管理咨询、替他人推销、互联网销售(电商运营) | **35** |
| 可下载 APP/小程序/软件、通讯设备、计算机软硬件及外设 | **9** |
| 网络通讯、数据传送、互联网接入/聊天室 | **38** |
| 会议及展览、文化艺术交流、培训、在线出版 | **41** |
| 计算机及办公设备维修、机械安装维修 | **37** |
| 安全系统监控服务 | **45** |
| 各类实体商品销售（服装25/文具16/日用21/厨具21/体育器材28/化妆品3/食品29-30-32/针纺24等） | 对应商品类 |

> 只有"自有经营/自营销售"才需要商品销售类；纯为客户交付的项目不映射。

**类目锚点（提高映射准确率）**：尼斯分类以「类似群」判断商品/服务是否类似。常用核心类似群：42 类 4220（计算机编程/软件设计）；35 类 3501（广告）/3503（替他人推销）；9 类 0901（软件/APP）/0907（通讯设备）；38 类 3802（通讯/数据传输）；41 类 4102（组织活动）/4105（文娱）。映射时优先锁定类似群，避免"大类对但类似群错"导致白注册。

## 四、近似度三维评估与五级风险评级（启发式参考）

对每个检索到的冲突标，可再从「音 / 形 / 义」三维度定性评估近似程度（源自《商标审查审理指南》近似判定规则）：
- **音似**：读音完全相同 / 声母韵母同而声调不同 / 首字同音 / 拼音缩写相同 / 明显不同。
- **形似**：文字完全相同 / 含相同主要文字（占比>50%）/ 字形高度相似易误认 / 增减非显著性文字 / 排序不同 / 明显不同。
- **义似**：含义完全相同（同义或翻译）/ 高度近似 / 明显关联 / 易联想 / 明显不同。

据此给出 **五级风险评级**：极高（80–100，商标法第57条：同/近似商标+同/类似商品，5万–500万赔偿）/ 高（60–79，第30条：驳回或赔偿）/ 中（40–59）/ 低（20–39）/ 极低（0–19）。

⚠️ 此评级为**启发式参考**，非官方近似查询结论；精确核定必须以中国商标网 + 备案代理机构的官方近似查询为准。本框架借鉴公开商标风险评估方法论（音形义三维体系），不连真实商标库，仅用于让"近似程度"更直观。
