# ISM——控制适用性框架

来源：澳大利亚《信息安全手册》（Information Security Manual），2026 年 3 月版
发布机构：澳大利亚信号局（ASD）

---

## 密级与适用性标记

每项 ISM 控制都带有适用性标记，指明哪些系统密级需要该控制。

| 标记 | 密级 | 描述 |
|---------|---------------------|-------------|
| **NC** | 非保密（Non-Classified） | 一般政府信息；无需正式保护标记 |
| **OS** | 官方：敏感（OFFICIAL: Sensitive） | 敏感但未定密；大多数联邦机构系统的默认基线 |
| **P** | 受保护（PROTECTED） | 已定密信息；泄露可能损害国家/组织利益 |
| **S** | 机密（SECRET） | 高度敏感；泄露将对国家安全造成严重损害 |
| **TS** | 绝密（TOP SECRET） | 特别敏感；泄露将对国家安全造成严重损害 |

### 叠加规则
更高密级系统必须实施**低层级全部控制加上自身层级的控制**：
- NC 系统 → 仅 NC 控制
- OS 系统 → NC + OS 控制
- PROTECTED 系统 → NC + OS + P 控制
- SECRET 系统 → NC + OS + P + S 控制
- TOP SECRET 系统 → NC + OS + P + S + TS 控制

## 基于风险的控制选择流程

ISM 不强制一刀切的方法。选择流程：

1. **确定系统密级**——基于系统存储、处理或通信的信息的最高敏感性
2. **定义安全目标**——识别 CIA（保密性、完整性、可用性）要求
3. **使用适用性标记选择基线控制**
4. **裁剪控制**——为特定威胁添加控制；以风险理由记录排除项
5. **在 SSP 中记录**——所有选定的控制、排除项和理由必须记入系统安全计划

## 系统安全计划（SSP）——必需内容

SSP 是主要的授权工件。必须包括：

| 部分 | 内容 |
|---------|---------|
| 系统概览 | 名称、所有者、用途、环境 |
| 系统边界 | 范围内内容（硬件、软件、接口） |
| 密级 | 处理的最高密级 |
| 安全目标 | 保密性、完整性、可用性评级（高/中/低） |
| 控制选择 | 所有适用的 ISM 控制及适用性理由 |
| 已实施控制 | 每项控制的实施证据 |
| 已排除控制 | 未实施的控制，附成文的风险接受 |
| 风险登记册 | 已识别的风险、可能性、影响、处理 |
| 授权 | 授权官员签名和日期 |
| 审查安排 | 下次审查日期（最低：每 24 个月或重大变更后） |

## IRAP 评估要求

### 谁需要 IRAP 评估？
- **强制**：处理 PROTECTED 及以上密级的系统
- **强烈建议**：处理 OFFICIAL: Sensitive 密级的系统
- **政府政策**：任何用于向公民提供政府服务的系统

### IRAP 评估员要求
- 必须列入 ASD IRAP 评估员登记册
- 必须独立于被评估的系统
- 必须持有当前 ASD 认可的资质
- 查找评估员：https://www.cyber.gov.au/resources-business-and-government/assessment-and-evaluation-programs/irap/irap-assessors

### 评估周期
- 系统授权前的初始评估
- 每 **24 个月**重新评估（最低）
- **重大变更**后需要重新评估（重大架构变更、新密级、重大新功能）

### IRAP 评估工件检查清单
- [ ] 当前的系统安全计划（SSP）
- [ ] 网络架构图
- [ ] 资产登记册（硬件和软件）
- [ ] 带当前风险评级的风险登记册
- [ ] 政策套件（SSP 中引用的所有安全政策）
- [ ] 已实施控制的证据（配置截图、日志、测试结果）
- [ ] 先前的 IRAP 评估报告（如为重新评估）
- [ ] 针对任何未决发现的行动计划与里程碑（POA&M）
- [ ] 事件登记册（最近 12 个月）
- [ ] 补丁管理报告

## 八项要点（Essential Eight）——与 ISM 的关系

八项要点是从更广泛的 ISM 控制集中提取的**八项优先缓解策略**。它们不是单独的标准，而是优先化的子集。

| 八项要点策略 | 主要 ISM 章节 | 备注 |
|-------------------------|----------------------|-------|
| 应用程序控制（白名单） | 第 13 章 系统加固 | 阻止未经批准的软件执行 |
| 应用程序补丁 | 第 14 章 系统管理 | 关键补丁 ≤14 天 |
| 配置 Microsoft Office 宏 | 第 13 章 系统加固 | 限制宏执行 |
| 用户应用程序加固 | 第 13 章 系统加固 | 浏览器、Office、PDF 加固 |
| 限制管理权限 | 第 13 章 系统加固、第 6 章 人员 | 最小权限、PAM |
| 操作系统补丁 | 第 14 章 系统管理 | 关键操作系统补丁 ≤14 天 |
| 多因素认证（MFA） | 第 6、9、19 章 | 所有远程访问、特权账户使用 MFA |
| 定期备份 | 第 14 章 系统管理 | 经测试、离线/异地、3-2-1 规则 |

### 八项要点成熟度等级

| 等级 | 描述 | 适用对象 |
|-------|-------------|------------------|
| **ML0** | 实施不完整或无效 | 不合规 |
| **ML1** | 部分对齐；应对定向攻击 | 小型/低风险组织的最低要求 |
| **ML2** | 基本对齐；应对复杂威胁 | ASD 推荐的所有政府实体基线（2026 年目标） |
| **ML3** | 完全对齐；应对高级持续性威胁 | 关键基础设施和高风险行业的要求 |

## 补丁管理 SLA（第 14 章）

| 补丁严重性 | 最长修复时限 |
|------------------|------------------------------|
| 严重（CVSS 9–10） | 互联网暴露系统 48 小时；内部系统 14 天 |
| 高（CVSS 7–8.9） | 14 天 |
| 中（CVSS 4–6.9） | 30 天 |
| 低（CVSS < 4） | 在下一次维护窗口内 |

## 批准的加密算法（第 20 章）

ISM 强制使用 ASD 批准的算法。2026 年 3 月的关键要求：

| 用例 | 批准的算法 | 备注 |
|----------|----------------------|-------|
| 对称加密 | 最低 AES-128（PROTECTED+ 用 AES-256） | |
| 非对称加密 | 最低 RSA-2048；EC P-256 或以上 | PROTECTED+ 用 RSA-4096 / P-384 |
| 哈希 | 最低 SHA-256（PROTECTED+ 用 SHA-384） | 禁止 MD5 和 SHA-1 |
| TLS | 最低 TLS 1.2；首选 TLS 1.3 | 禁止 SSL 和 TLS 1.0/1.1 |
| 密钥交换 | ECDH 或 DHE（最低 2048 位） | 禁止静态 DH |
| SSH | 仅 SSH2；ED25519 或 RSA-4096 | 禁止 SSH1 |

## 日志保留要求（第 15 章）

| 系统密级 | 最低日志保留期限 |
|----------------------|----------------------|
| NC | 12 个月 |
| OFFICIAL: Sensitive | 18 个月 |
| PROTECTED | 18 个月 |
| SECRET / TOP SECRET | 依机构安全政策指示（通常 7 年） |

日志必须以防篡改方式存储，并与被监测系统分离。

## 主要差异：ISM 与 ISO 27001

| 方面 | ISM（ASD） | ISO 27001 |
|--------|-----------|-----------|
| 管辖 | 澳大利亚（政府强制） | 国际（自愿认证） |
| 结构 | 22 个指南章节 + 单项控制 | 10 个条款 + 93 项附录 A 控制（2022 年） |
| 评估 | IRAP（ASD 认证评估员） | 第三方认证机构 |
| 密级 | NC / OS / P / S / TS 标记 | 不基于密级 |
| 更新周期 | 通常每年（3 月版） | 约每 7 年重大修订 |
| 受众 | 政府实体 + 供应链 | 任何组织 |
| 八项要点 | ISM 的子集；ASD 对政府的强制要求 | 无直接对应物 |
