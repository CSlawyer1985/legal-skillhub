# 首次配置脚本

当 `user-config/profile.md` 不存在或残缺时走这份脚本。**一组一组问**，不要一次甩 3 组。

总原则：**能靠规则推断的字段不要主动问**——直接按启发式给出初判，让用户 review/纠正即可。

---

## 第一组：工时模板

### 步骤 1-A：拿到表头

> 我们先把工时表的模板搞清楚。挑一种最方便的方式：
>
> - **方案 A（推荐，最快）**：把模板文件**路径**给我（`.csv` / `.xlsx` / `.xls` 都行）——我自己打开读第一行。也可以拖文件到对话框。
> - **方案 B**：把 Excel/CSV 第一行那串列名复制粘贴给我。
> - **方案 C**：直接告诉我每一列的列名，按顺序用逗号分隔列出来。

**如果用户给的是文件路径**：
- `.csv`：用 Read 工具直接读第一行
- `.xlsx` / `.xls`：写一段 Python（`openpyxl`）读 sheet 1 的第一行；如果当前环境没装包，提示用户 `pip install openpyxl` 后重试，不要默默失败
- 读到表头后，回显给用户："读到表头是 `[列1,列2,...]`，对吗？" 让用户确认无误再进入 1-B
- **如果是 `.xlsx`/`.xls` 文件**：读完表头后，把原文件复制到 `user-config/template.xlsx`（保留列宽、样式等格式信息，后续生成输出时复用）

### 步骤 1-B：启发式分类 + 用户 review

拿到列名后，按下表自动分类（不要逐列问用户）：

| 列名包含的关键词（不区分大小写） | 推断类别 |
|--------------------------------|----------|
| 日期 / date | **B** 任务衍生（任务完成日） |
| 描述 / 内容 / 任务 / description / task / title / content | **B** 任务衍生（任务标题） |
| 项目 / matter / project | **C** 项目映射衍生（项目名） |
| 案号 / case / matter code | **C** 项目映射衍生（案号） |
| 客户 / client | **C** 项目映射衍生（客户名） |
| 小时 / hours / time / 时长 / 自报 | **D** 留空待手填 |
| 其他匹配不到的 | **A** 固定值 |

把分类结果展示给用户，只追问 A 类的固定值：

> 我按列名给你做了分类，你 review 一下：
>
> | 列名 | 类别 | 取值/来源 |
> |------|------|----------|
> | [列1] | B 任务衍生 | 任务完成日 |
> | [列2] | A 固定值 | **？请告诉我填什么** |
> | [列3] | C 项目映射 | 案号（来自 projects.csv） |
> | ... | ... | ... |
>
> **A 类**的列需要你告诉我"具体填什么"（典型是律师姓名、日志类型等每条都一样的值）。
> 其他类别如果哪里判错了，告诉我我改；没问题就只回答 A 类的填值。

### 步骤 1-C：落盘

- 表头写入 `template.csv` 或 `template.xlsx`（用户给什么格式就存什么格式）
  - Excel 输入 → 复制原文件到 `user-config/template.xlsx`（保留列宽/样式供后续输出复用）
  - CSV 输入或粘文本 → 写入 `template.csv`（header 一行 + UTF-8 BOM）
- 分类表 + A 类填值写入 `profile.md` 的"列分类表"段（见末尾 profile.md 示例）

**关于表头**：不同律所工时系统差异极大。坚持让用户先粘他们律所的原始模板，不要给"参考表头"，否则用户会被锚定。

---

## 第二组·前置：选择数据源

在开始问"工作单元白名单"之前，先确认用户用哪个任务工具：

> 你的任务记在哪个工具里？我目前支持四个：
>
> 1. **滴答清单 / TickTick**（中国/海外通用，最常见）
> 2. **Notion**（database 里的任务）
> 3. **Microsoft To Do**（Outlook 任务也是走这个）
> 4. **飞书 / Lark**（飞书原生任务模块）
>
> 告诉我编号或名字。

收到回答后，把 `source: <dida365|notion|todo|feishu>` 写入 `profile.md` 的"数据源"段。

然后**加载对应的 `references/sources/<source>.md` 中的"首次配置脚本"小节**，按其问答脚本走"工作单元白名单"收集，结果按对应 adapter 描述的格式写回 `profile.md` 的"工作单元白名单"段。

## 第二组（DiDa365 分支默认实现）

> 注：本节是 dida365 用户的便利入口。其余 source 直接看对应 adapter；当 `source: dida365` 时执行本节，等价于 `references/sources/dida365.md` 中的"首次配置脚本"。

调用 `mcp__dida364__list_projects` 列出所有项目，然后问：

> 上面这些项目里，**哪几个是"工作"项目**？（这些里的已完成任务会被拉进工时；没被你标的项目自动不参与，不用单独列。）

收齐后写入 `profile.md` 的"工作单元白名单"段（DiDa365 格式为 projectId 表）。

---

## 第三组：项目案号注册表

> 最后一步：你目前手上活跃的项目都有哪些？每个项目我只需要：
>
> - **项目名**（你内部叫它什么）
> - **案号**（律所给的编号，格式按你们所的规则即可）
>
> 可以一次性贴一段表格，也可以一个一个项目说。
>
> **关于关键词**：默认我用项目名本身去匹配任务标题，多数情况够用。只有当项目英文代号/缩写在你任务工具的标题里出现得更多（比如英文项目名"Apollo"、缩写"LDS"），才需要你单独告诉我额外关键词。

把每个项目追加到 `projects.csv`，列固定为：

```
项目名,案号,客户,关键词
```

- 客户列：用户没主动给就留空
- 关键词列：默认 = 项目名本身；用户额外给的用分号拼到末尾

完成后回显："已记录 N 个项目。"

## 配置完成

输出：

> 配置已保存到：
> - 列分类 + 工作单元白名单：`~/.claude/skills/law-firm-worklog/user-config/profile.md`
> - 表头模板：`~/.claude/skills/law-firm-worklog/user-config/template.xlsx`（或 `.csv`）
> - 项目注册表：`~/.claude/skills/law-firm-worklog/user-config/projects.csv`
>
> 下次直接说"生成 5 月工时"就行（默认导出 Excel）。也可以说"导出 CSV"来要 CSV 格式。新签项目随时告诉我，我会追加到注册表。

## profile.md 写入示例

```markdown
# 工时生成配置

## 数据源
source: dida365   # 可选：dida365 | notion | todo | feishu

## 工作单元白名单
<!-- 字段格式取决于 source，详见 references/sources/<source>.md -->
<!-- dida365 示例： -->
| projectId | 用途 |
|-----------|------|
| `xxx` | 主工作项目 |

## 列分类表

| 列名 | 类别 | 取值 / 来源 |
|------|------|------------|
| [列名 1] | A | [固定值] |
| [列名 2] | A | [固定值] |
| [日期列名] | B | 任务完成日（北京时间） |
| [描述列名] | B | 任务标题 |
| [项目列名] | C | 来自 projects.csv |
| [案号列名] | C | 来自 projects.csv |
| [小时数列名] | D | 留空，用户 Excel 手填 |

## 输出规则
- 文件名：`YYYY-MM-工作日志.xlsx`（默认）或 `YYYY-MM-工作日志.csv`
- Excel 输出：openpyxl 写，表头加粗/灰底/冻结首行/自动筛选，保留模板列宽
- CSV 输出：UTF-8 BOM 编码
- 默认输出目录：当前工作目录
```
