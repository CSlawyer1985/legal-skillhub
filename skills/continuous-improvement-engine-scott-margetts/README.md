# continuous-improvement-engine（持续改进引擎）

**插件：** LPM Core Plugin（14 个技能中的第 12 个）
**所属：** [LPM Skills for Claude](https://github.com/legalopsconsulting/lpm-skills)

---

## 本技能做什么

捕获、结构化并循环利用法律事务中的运营经验教训——在事务进行中、阶段门禁时以及事务结束时。把已发生的事情转化为下一件事务可复用的东西。

标准的经验教训流程之所以失败，是因为经验捕获得太晚（在结束时而非触发事件时）、按存档而非复用格式组织，并且没有反馈回路回到能防止问题复发的模板和长期假设中。本技能旨在修复全部三点：在记忆最鲜活的时刻进行进行中捕获、按下一次范围界定会议的格式组织结构化输出，以及明确路由到应更新模板的技能。

## 使用说明（v1）

**模式 1——粘贴事件文件：** 直接粘贴 RAID 更新、范围变更通知、计费差异或本地法律顾问（LC）绩效问题时，在粘贴前加 `[LESSON TRIGGER]` 前缀。这告诉技能要提取经验教训，而不是生成其他技能处理的下游文件（RAID 更新、OOS 通知等）。

示例：`[LESSON TRIGGER] R-003 has escalated — Dutch notary requires physical presence at signing, €8k unbudgeted.`（R-003 已升级——荷兰公证人要求签署时亲自到场，8 千欧元未列入预算。）

不加标记时，用你自己的话描述情况：*"我们的荷兰 RAID 风险 R-003 已显现——公证人要求亲自到场，8 千欧元未列入预算。请捕获这一经验教训。"*

**模式 0 完全绕开这一点。** 在模式 0 中，技能自行对整批每周数据完成检测和分类——无需标记。模式 0 是对模糊输入分类问题的架构性答案。

---

| 模式 | 何时使用 |
|---|---|
| **模式 1——进行中捕获** | 触发事件已发生：范围变更、风险显现、问题解决、交付问题、正面信号。现在捕获，而不是在结束时。 |
| **模式 2——事务中期审查** | 一个阶段已完成或到达季度审查点。 |
| **模式 3——事务结束回顾** | 事务即将结束。完整回顾，并为下一件同类事务生成复用包。 |

**模式 1 是价值最高的模式。** 在范围变更发生的那一周捕获的经验教训，比同一观察在事务结束时做出的要有用十倍。

---

## 触发信号

技能自动对这些输入分类：

- 范围变更通知或 scope-change-controller 的输出 → 模式 1
- 风险显现或 RAID 更新 → 模式 1
- 含延迟或未达成里程碑信号的状态报告 → 模式 1
- 阶段门禁或季度审查 → 模式 2
- 事务结束或正在结束 → 模式 3

---

## 关键输出

| 模式 | 主要输出 |
|---|---|
| 模式 1 | 结构化经验条目，含根本原因、经验陈述和具名复用目标 |
| 模式 2 | 事务中期审查，含经验表、识别出的模式和下一阶段的调整 |
| 模式 3 | 完整结束回顾 + **复用包（Reuse Package）**——为接手此类事务的下一任法律项目经理（LPM）准备的面向未来的简报 |

**复用包**（模式 3）是本技能价值最高的输出。它是最常被使用的部分。完整回顾是记录。

## 本技能协作的技能

| 技能 | 关系 |
|---|---|
| scope-change-controller（范围变更控制器） | 每起 OOS 事件 → 模式 1 触发；回顾发现 → 模式 3 输入 |
| risk-and-issues-manager（风险与问题管理器） | 每项显现的风险/已解决的问题 → 模式 1 触发；"已关闭——经验生效中"条目 → 结构化捕获 |
| status-report-drafter（状态报告起草器） | 交付信号（延迟、RAG 恶化）→ 模式 1 触发 |
| local-counsel-manager（本地法律顾问管理器） | LC 绩效问题和范围争议 → 模式 1 触发 |
| matter-intake-scoping（事务受理与范围界定） | 复用包和更新的长期假设反馈到下一件事务的范围界定 |
| risk-and-issues-manager（风险与问题管理器） | 模式经验 → 标准风险登记册更新 |
| scope-change-controller（范围变更控制器） | 模式经验 → 范围基线模板更新 |

## 应用的设计原则

- **以进行中捕获为主要工作流**——在触发事件时捕获经验，而非在结束时重构
- **为复用而格式化，而非为存档**——经验条目按范围界定会议格式化；复用包按模板库格式化
- **明确的反馈回路**——每条经验都路由到一个具名技能，其模板应被更新
- **产出输出**——立即从现有信息产出经验条目；不因等待完整输入而扣留
- **模板骨架**——经验条目、事务中期审查和回顾是技能填充的结构化模板
