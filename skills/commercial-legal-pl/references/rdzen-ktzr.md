# KTZR 核心——运营规则

一个文件，**运营**规则的单一真相来源——如何引用、如何使用门禁、如何处理用户角色、如何格式化。Workflow 按编号（R1、R2……）引用这些规则，而非重复它们。

标记 [P] 的规则可被 **`practice-profile.md`** 覆盖。

> **优先级：** 黄金规则（`zlote-reguly.md`）› KTZR 核心 › 编辑风格 › workflow 指令。

---

## R1 · 法条引用

**每一条条文引用**（在草稿、分析、条款中）→ 使用前调用 `verify_article()`。

- 当 `legal-cite` MCP 激活时：`verify_article("art. N ust. M KOD")`——**强制**，非可选
- 当 MCP 不可用时：在每条条文引用旁标注 `[未核验]`
- 格式：`art. N [ust. M] [§ P] [lit. X] KOD`——如 `art. 28 ust. 3 RODO`、`art. 473 § 2 KC`
- 条文内容幻觉 = **法律错误**，而非风格错误
- 法案在会话中缓存——首次获取一次性；后续即时
- **法院判决：** 判决编号（如 `II CSK 123/24`）**不要凭记忆给出**——编号幻觉与条文内容幻觉同样危险。如不确定——不带编号描述论点或标注 `[判决编号未核验]`

## R2 · 最终文件前的门禁

在生成每份最终文件（合同、规章、待粘贴条款）之前——停下并显示**以下区块**，等待用户回应：

```
⛔ 最终版本前——请确认：
1. 当事人数据（KRS/NIP/地址）是否已按来源核验？
2. 所引法条是否已核验（verify_article 或手工）？
3. 主办律师是否看过此草稿？
→ 「是，生成」/ 或指出需改进之处
```

**仅在确认后**——生成。**未经确认**——在文件上方返回 `[草稿——待核验]` 并停止。

**快速例外：**「快速模式」/「不用问直接做」→ 立即生成，在开头和结尾标注 `[草稿——待核验]`。

Workflow 可以**扩展**问题清单，增加文件类型特定要点（如 B2C/B2B、SLA）。不得删除要点 1-3。

## R3 · 用户角色——律师 / 非律师

| 信号 | 模式 |
|--------|------|
| 「我是律师 / 法律顾问 / 律师」，律所语境、专业问题 | **律师**（默认） |
| 「我不是律师」、「我必须签署」、「我是学生」、「我是客户 / 老板」 | **非律师** |
| 无信号 | **律师**——不明确询问 |

**律师模式：** 操作工具，最少警告。

**非律师模式：**
- 每个输出末尾加 ⚠️ 区块：*「本文件在签署 / 实施前须经法律顾问或律师核验。」*
- 最终文件：开头**和**结尾标注 `[草稿——须经律师核验]`
- 未经律师明确确认，不生成可签署 / 可实施的文件

## R4 · 律所配置 [P]

会话开始时读取 `practice-profile.md`（如存在）并在整个会话期间应用：

| `practice-profile.md` 中的章节 | 覆盖什么 |
|---------------------------------|-------------|
| `## 风险阈值` | 何时 RED/YELLOW、风格（保守/温和/进取） |
| `## 默认谈判立场` | cap、保密、争议地、违约金 |
| `## 风格与格式` | 正式度、法律设计、工作语言 |
| `## 排除` | 案件/客户类型——拒绝或标记超出定位 |

**无 `practice-profile.md`：** 应用 KTZR 标准值。同时建议运行 `workflows/konfiguracja-kancelarii.md`（一次性访谈，15-20 分钟）。

## R5 · 输出格式 [P]

在每份生成或修改的文件前，在脑中运行：

```
✓ 波兰语弯引号 „"     ✓ 长破折号 —        ✓ 金额数字和文字
✓ §/款/项编号     ✓ 大写 = 定义   ✓ 内部引用有效
✓ 条款中无拉丁语  ✓ 无「立即」    ✓ 当事人名称一致
✓ 法条引用：verify_article() 或 [未核验]
```

完整清单附示例和红旗：`references/format-checklist.md`。

输出中的章节格式（markdown、状态 emoji、最终版本零元文本）：见 SKILL.md「输出格式」一节。

## R6 · 代理性——每个阶段后 STOP

在分析和生成 workflow 中，在每个阶段后停下并等待用户确认或更正。不要一次性做完全部——这是代理式 workflow，不是一次性完成。

**例外：**「不用问直接做全部」/「快速模式」→ 执行所有操作，但结尾突出显示通常需要等待决策的地方。

## R7 · 渐进披露——不预先加载

仅在 workflow 的具体阶段需要参考文件时才打开它们。不要在会话开始时加载整个条款库。Workflow 指示每个步骤打开哪些文件。

例外：`zlote-reguly.md`、`rdzen-ktzr.md` 和 `practice-profile.md` 在会话开始时加载一次，并全程激活。
