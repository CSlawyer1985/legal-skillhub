# KTZR 的法律设计

**来源：** 本律所基于文献（Hagan、Haapio、Passera）和 WorldCC 合同设计模式库制定的法律设计应用标准——按律所定位（B2B IT，非消费类/非初创）调整。

**目标：** 确定**我们在 KTZR 中采纳哪些法律设计要素**，哪些超出定位（B2B IT，非消费类/非初创）。这里不是「给合同涂色」——而是选定能提高可读性、同时保持法律文件专业语气的技术。

## TL;DR

1. **法律设计 ≠ 装饰。** 它是按真实使用者（商业客户）而非另一位律师来设计文档的方法。
2. **WorldCC 模式库**（https://contract-design.worldcc.foundation）——开源，10 个模式家族。主要操作来源。
3. **KTZR 全面采纳 5 个家族**（布局、导航、强调、组织、语气），**选择性采纳 3 个**（概括、分层、视觉——仅当确实有用时），**2 个放弃或内部处理**（审查、规范性内容中的解释框）。
4. **KTZR 默认排版：** 正文 Arial 11.5 pt，条款标题下轻边框，正文两端对齐。仅当客户明确要求「经典」外观时才用 Times New Roman。
5. **每份合同都要回答的 5 个问题**决定是否值得加关键条款表、目录、时间线或解释框。
6. **反模式一律放弃：** 漫画合同、规范性内容中的彩色示意图、替代文字的图标、表情符号。
7. **KTZR「轻量法律设计」标准** = 经典法律结构 + 选择性视觉元素提高可读性，不破坏专业语气。

## KTZR 默认排版

除非客户要求其他标准，否则我们在**律所出具的每份文件**中应用这些设置。

### 字体

| 要素 | 字体 | 字号 | 字重 |
|---|---|---|---|
| 正文 | Arial | 11.5 pt | 常规 |
| 文件标题（协议、合同等） | Arial | 16–18 pt | 加粗 |
| 副标题（法律定性） | Arial | 12 pt | 加粗 |
| 条款标题（第 X 条 名称） | Arial | 12 pt | 加粗 |
| 字母/数字列表编号 | Arial | 11.5 pt | 常规 |

**例外：** 如客户明确要求「经典」外观（Times New Roman），我们使用 Times New Roman 12 pt。应用相同的结构和边框。

### 边框

| 要素 | 边框 | 颜色 | 粗细 |
|---|---|---|---|
| 条款标题下（第 X 条 名称） | 下边框 | `808080`（中灰） | 0.75–1 pt |
| 文件标题下 | 下边框 | `808080` | 1 pt |
| 表格（「关键条款」、摘要） | 全部 | `CCCCCC`（浅灰） | 0.5 pt |

原则：**微妙、单色。** 合同正文中绝不使用灰度以外的颜色。颜色仅用于辅助表格（且仅在客户明确委托更完整的法律设计时）。

### 版面

- 页边距：各边 2.5 厘米（1 英寸也可接受）。
- 正文两端对齐：是，对大多数段落。仅标题和章节标题居中。
- 间距：每段后 6 pt。行距 1.25。
- 列表：(a)(b)(c)、数字 1./2./3. 使用悬挂缩进。

## WorldCC 10 个模式家族——按 KTZR 过滤

Passera / Haapio 库所有家族的图谱 + KTZR 对每个家族的决策。

| 家族 | 作用 | KTZR 决策 | 我们的具体做法 |
|---|---|---|---|
| **强调** | 突出关键信息 | ✅ 采纳 | 金额、日期、期限、账号加粗。条款标题下**下边框**。定义以排版引号「...」内的斜体 |
| **布局** | 排布内容使之可读 | ✅ 采纳 | 留白、短段落、悬挂缩进。Arial 11.5 pt，页边距 2.5 厘米 |
| **导航** | 帮助在文档中查找 | ✅ 采纳 | 超过 5 页的合同加目录（自动生成）。**活动交叉引用**而非手工输入 |
| **组织** | 逻辑结构 | ✅ 采纳 | 条款按关系时间顺序排列，而非字母顺序。定义在前，最后条款在后 |
| **语气** | 措辞、语气、观感 | ✅ 采纳 | Plain Polish（平实波兰语）、主动语态、短句（KTZR 风格的 W1/W2） |
| **概括** | 摘要 | ⚖️ 选择性 | 开头的「关键条款」表——仅对超过 3 页的合同或商业客户会阅读时 |
| **分层** | 分级，关键在上 | ⚖️ 选择性 | 技术/操作条款移至附件；正文保持可读 |
| **视觉** | 辅助理解的图像 | ⚖️ 选择性 | 带阶段的项目（IT 实施、里程碑）用时间线。责任划分用 RACI 表。多主体流程用泳道图。**仅当确实能说明结构时** |
| **解释器** | 解释条款含义 | ⚠️ 谨慎 | 「解释」框仅用于极不直观的条款（责任上限、故意过错、赔偿），且客户示意不理解时 |
| **审查** | 检查完整性 | 🏠 内部 | 供我们团队使用的检查清单（`workflows/`），不引入对外文件 |

## 每份合同都要回答的 5 个问题

在将合同发给客户/对方之前：

1. **合同是否超过 3 页？** 是 → 加目录（Word：`插入 → 目录`）。
2. **合同是否包含商业客户想一眼看到的关键参数？** 是 → 开头加「关键条款」表（当事人、标的、报酬、期限、最重要的义务）。
3. **合同是否描述多阶段流程？** 是 → 考虑时间线（阶段 1 → 2 → 3）或泳道图（谁、何时、做什么）。
4. **合同是否包含接收方可能无法理解的技术复杂条款？** 是 → 旁边加简短解释框（最多 2-3 句平实波兰语）。
5. **交叉引用在 Word 中是否为活动（可点击）？** 否 → 改为超链接，因为静态文本「第 5 条第 2 款」在后续重新编号时会成为错误。

如问题 1-4 的答案为「否」，合同保持**KTZR 经典风格**（Arial 11.5、条款下边框、无额外视觉元素）。

## 具体技术分步

### A. 「关键条款」表（概括）

**何时用：** 超过 3 页的合同、每份和解协议、IT 实施合同、含多个订单的框架合同。

**位置：** 紧接文件标题之下、首部之前或之后——取决于惯例。

**结构（最小化，2 列）：**

```
| 当事人                  | 受托方：[名称] / 委托方：[名称]   |
| 标的               | [简短，1 句]                          |
| 报酬           | [金额 / 结算机制]             |
| 期限            | [日期或期间]                            |
| 最重要的期限   | [如付款期限、到期日]   |
| 管辖法院            | [城市]                               |
```

**性质：** 信息性，非规范性。以条款内容为准。如有人问及——我们可在最后条款中加「本表仅具信息性」条款，但默认不写（多余、显然）。

### B. 目录（导航）

**何时用：** 超过 5 页的合同。

**做法：** Word → `插入 → 目录` → 选择自动样式，将字体调整为 Arial 11.5。要求条款标题标记为 *Heading 2*（或相应样式）。

### C. 流程时间线（视觉）

**何时用：** 描述多阶段项目（IT 实施、建筑项目、迁移）的合同。对分 3 期付款的和解协议——*不值得*，分期表足够。

**做法：**
- Word：`插入 → SmartArt → 流程` → 3-7 个阶段的横向样式。
- 每个阶段 = 简短名称（1-3 个词）+ 日期/里程碑。
- 无图标，单色（灰色或一个呼应客户品牌的主色）。

### D. 泳道图（视觉）

**何时用：** 涉及 2 个以上主体的多阶段流程（如 IT 人员租赁——委托方 / 服务方 / 专家）。

**做法：** SmartArt → 行为代表各方的行、列代表各阶段的图。行间有流程箭头。

### E. 解释框（解释器）

**何时用：** 很少，仅当条款技术复杂且客户明确示意不理解时。

**结构：**
```
┌─────────────────────────────────────────────┐
│ 解释（信息性）：       │
│ [2-3 句平实波兰语，说明该条款在实践中 │
│ 的含义]                         │
└─────────────────────────────────────────────┘
```

**性质：** 信息性，非规范性。框须在视觉上与条款分离（如 1×1 表格带轻边框、10.5 pt 斜体）。

### F. 条款标题下的下边框（强调 + 布局）

**目的：** 微妙地将标题与内容分离，便于扫描文档。

**实现（Word）：**
- 选中标题段落（第 X 条 名称）。
- `段落 → 边框 → 下边框` → 颜色 `808080`，粗细 0.75 pt。
- 或在样式定义中：`pBdr → bottom`。

**实现（docx-js）：**
```javascript
new Paragraph({
  border: { bottom: { style: BorderStyle.SINGLE, size: 6, color: "808080", space: 4 } },
  children: [new TextRun({ text: "§ X. Tytuł", bold: true })]
})
```

## 反模式——我们避免什么

- **漫画合同**（以漫画插图替代内容）。斯坦福曾为南非不识字工人做过——不是我们的定位。
- **规范性内容中的彩色示意图**。看起来像演示文稿，不像法律文件。
- **条款中以图标替代文字**。图标可作为关键条款表中的点缀（如客户要求）；绝不替代规范性内容。
- **表情符号**——律所出具的**任何**文件中都不用。
- **加粗过多**——如果所有内容都突出，就没有内容突出。加粗保留给金额、日期、关键义务。
- **一份文档中使用两种不同字体**（除 Arial 正文 + 技术附件中代码用 Courier 等例外）。坚持一种。
- **表格单元格边框比内容更暗**——看起来像笔记本格子。始终用浅灰（`CCCCCC` 或更浅）。

## 使用决策——何时采用「轻量法律设计」

KTZR 默认以**「经典-清爽」**模式工作——无关键条款表、无时间线，但有我们的默认排版（Arial 11.5 + 下边框 + 平实波兰语）。

当满足**至少一项**以下条件时启动**「轻量法律设计」**模式：

- 合同超过 5 页且收件人是商业人士（非对方律师）。
- 合同描述带里程碑的多阶段流程。
- 客户明确要求法律设计 / 「用户友好」文档。
- 合同将被团队运营性使用（而非仅签署后收进文件夹）。

**「完整法律设计」模式**（色彩、图标、信息图）——**KTZR 不做**。如客户需要，我们转介给专门的设计律所。
