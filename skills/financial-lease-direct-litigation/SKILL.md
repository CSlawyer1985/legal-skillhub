# 普通直租型融资租赁合同纠纷

本技能提供普通直租型融资租赁合同纠纷的实务工作流。方法论基于李时瑀律师的办案经验蒸馏，使用者应结合案件事实、现行法律和自身专业判断调整。

本技能分享工作方法，不构成针对具体案件的法律意见。

## 0. 先做案型路由

在审查合同、起草诉状或编制证据目录前，先建立主体链、合同链、租赁物权属流、资金流和交易时间线。

按下列顺序判断：

1. **普通直租**：承租人选择租赁物和出卖人，出租人向出卖人购买租赁物，再交付承租人使用。
2. **售后回租**：承租人原已拥有租赁物，将其出售或转让给出租人，再从出租人处租回。
3. **融资转分期**：原融资租赁关系履行困难后，第三方买断、回购或承接相关资产/债务，承租人改按新安排分期偿还。
4. **第三方融资**：银行或其他融资机构参与购买、受让、融资或支付，并形成多方合同、物权和资金安排。
5. **混合或冲突**：文件夹标签、合同正文、付款台账或后续协议不一致，或同一案件先后出现多种结构。

只有第 1 类进入本技能的完整工作流。第 2 至第 4 类应停止并路由到相应专业模块；第 5 类必须人工复核，不得自动定性。路由未完成时只输出 `HOLD-ROUTE`，不得继续生成普通直租起诉状。

详见 [普通直租案型](knowledge/types/ordinary-direct-lease.md) 和 [公私边界](knowledge/governance/public-private-boundary.md)。

## 1. 材料读取与完整性门禁

先建立源材料清单，再进行法律分析。对每个 PDF、图片、DOCX、表格或压缩包至少记录：文件类型、页数或工作表数、文本层状态、OCR 状态、关键页、重复关系和读取结论。

- 可检索 PDF 先提取文本，再抽查关键页；
- 扫描 PDF 或图片必须逐页渲染并 OCR，不能因无文本层而直接认定“材料缺失”；
- 混合 PDF 要同时检查文本层和图像页；
- 无法打开、缺页、密码保护、严重倾斜或 OCR 置信不足时标记 `HOLD-MATERIAL-READABILITY`；
- “未找到”和“未能读取”必须分开记录；
- 关键材料的主体、编号、金额、日期和签章页需要回看原页，不以 OCR 文本单独定稿。

详见 [材料接收与可读性](knowledge/playbooks/material-intake-and-readability.md)。

## 2. 输出三件套与补件清单

普通直租路由通过后，面向用户的最低交付为三份相互独立、可编辑的 DOCX：

1. 民事起诉状；
2. 证据目录；
3. 缺失材料清单。

缺失材料清单必须与源材料清单逐项核对，已存在但尚未读出的材料不能误列为缺失。每个缺口写明用途、可接受材料、补件优先级及缺失影响，不回显内部策略或无依据结论。

详见 [缺失材料清单](knowledge/playbooks/missing-material-checklist.md)。

在三件套之外，先按功能整理工作底稿：

先按功能而不是文件名整理材料：

- 主体与授权材料；
- 融资租赁合同及全部附件；
- 买卖、采购、交付、验收和租赁物识别材料；
- 租赁支付表、付款凭证、对账和欠款明细；
- 保证、抵押、配偶承诺和其他增信文件；
- 催收、送达、保全、诉讼和执行材料。

对每份材料标记：`已取得`、`缺失`、`内容冲突`、`需回查原件`、`OCR待复核`、`隐私敏感`。当前权利人、当前余额、时效证据、催告、管辖连接点、出租人价款支付和租赁物现状均应单列。

## 3. 合同审查

围绕以下问题输出合同审查表：

1. 各方主体、签署权限和合同关联关系是否清晰；
2. 租赁物能否唯一识别，购买、交付、验收链是否闭合；
3. 租金、首付款、保证金、留购价和费用如何计算；
4. 所有权、占有使用、保险、登记和风险承担如何安排；
5. 违约、加速到期、解除、取回租赁物和损失计算如何衔接；
6. 保证、抵押及其他责任主体的范围和期间是否可证；
7. 管辖、送达和争议解决条款是否可执行；
8. 合同条款与实际付款、交付、催收记录是否一致。

不得仅凭合同模板推定案件事实。详见 [直租合同审查](knowledge/playbooks/contract-review.md)。

## 4. 起诉状起草

起诉状按以下结构生成：

1. **当事人与权利基础**：先核验原告现行名称、合同主体、债权转让、回购、承接或重组文件，再分别说明承租人、保证人、抵押人和其他责任主体的请求基础；
2. **诉讼请求**：将到期租金、未到期租金、违约责任、租赁物救济、担保责任和费用请求逐项拆开；支付全部未付租金路径与解除、收回租赁物路径不得机械并列；
3. **事实时间线**：签约、购买、交付、起租、付款、违约、催收及后续处置；
4. **请求权基础**：每项诉请对应合同条款、证据和经核验的法律依据；
5. **当前事实**：现余额、催告、时效、送达地址、管辖连接点、租赁物位置和控制状态必须有当前证据；
6. **金额说明**：正文只写可复核的计算结果，另附计算表并说明截止日、公式和冲抵顺序；
7. **附件清单**：与证据目录编号保持一致。

对调解轨和判决轨分别保留可调整的诉请方案，不能把谈判底线写成普遍法律规则。

详见 [起诉材料格式化](knowledge/playbooks/litigation-materials-drafting.md)。

## 5. 证据目录

按要件事实分组，而不是按文件形成顺序堆放：

1. 主体资格与代理权限；
2. 融资租赁关系成立；
3. 租赁物购买、交付和验收；
4. 出租人履行融资和交付义务；
5. 承租人付款、欠付及违约；
6. 保证、抵押或其他责任基础；
7. 催收、送达和权利主张；
8. 损失、费用和计算过程；
9. 保全、裁判与执行结果。

每项证据必须写明：证据名称、证明目的、对应诉请、真实性来源、原文件与页码/附件位置、读取状态、可能质证意见和补证缺口。目录完成后与缺失材料清单反向核对，防止同一材料一处写“已取得”、另一处写“缺失”。

详见 [证据目录](knowledge/playbooks/evidence-catalog.md)。

## 6. 代理词结构

代理词只提供写作结构，不替代案件事实判断或现行法回读：

1. 先列争点，不从结论倒推事实；
2. 每个争点分别列明合同依据、事实命题、证据位置、对方可能异议和待核法源；
3. 金额、日期、责任主体和救济方式必须与诉请、计算表、证据目录一致；
4. 不能确认的法律命题标记 `pending_current_text_verification`，不得包装成确定结论；
5. 结尾分别给出主张、备选路径和仍需补证事项。

详见 [代理词结构](knowledge/playbooks/agency-statement.md)。

## 7. 法律意见书结构

法律意见书按“已知事实、材料缺口、问题清单、分项分析、风险等级、行动建议”展开。内部版可以保留策略比较；对外版应删除谈判底线和内部评估。两类版本都必须：

- 明确事实来源和假设；
- 把法律命题与实务建议分开；
- 对未完成现行文本核验的命题标记状态；
- 避免预测确定胜诉、确定执行或确定回收结果。

详见 [法律意见书结构](knowledge/playbooks/legal-opinion.md)。

## 8. DOCX 质量门禁

三件套必须保持可编辑 OOXML，不以 PDF、截图或图片版替代。生成后至少完成：

- A4 纸型、稳定页边距、中文字体和样式层级；
- 真实 Word 表格、连续编号、跨页表头和可展开行高；
- 无空白页、截断、重叠、异常大留白或跳号；
- 起诉状、证据目录、计算表和缺失材料清单交叉引用一致；
- 逐页渲染检查后再交付，渲染文件仅用于本地复核；
- 文档元数据和可见署名仅保留“李时瑀律师”。

详见 [DOCX 质量门禁](knowledge/playbooks/docx-quality-gate.md)。

## 9. 保全、调判分轨与回收

完成初步事实和证据矩阵后，立即输出分轨建议：

- 以快速回款为目标的调解轨；
- 以责任确权、担保覆盖或后续执行为目标的判决轨；
- 保留谈判空间的双轨方案。

同时检查保全标的、责任主体财产线索、租赁物控制状态和执行可行性。不得把“胜诉”作为流程终点。

本公开包只提供风险检查框架，不把“每案必保”、固定让步比例、固定期限或特定执行路径写成普遍规则。救济选择必须结合合同、证据、现行法和可执行财产重新判断。

## 10. 法律依据门禁

每个法律命题必须标记为以下一种：

- `legal_authority_verified`：已从权威来源核验现行法条或司法解释；
- `public_case_verified`：已核验可公开引用的裁判文书，仅说明裁判样本；
- `personal_practice`：李时瑀律师的实务方法或谈判经验；
- `pending_current_text_verification`：命题域已识别，但现行文本尚未逐条回读；
- `unsupported_hold`：没有可靠依据，不得写成结论。

已回读的通用锚点列于 [已核验法源锚点](knowledge/authorities/verified-financing-lease-anchors.md)。其余实质法律命题默认保持 `pending_current_text_verification`。历史材料的时间效力问题在定稿前核验，但不替代案型、权利基础、现余额、时效证据和诉请路径选择等更直接的前置检查。

详见 [法律依据边界](knowledge/authorities/legal-authority-boundary.md)。

## 11. 脱敏与发布门禁

任何公共或商业版本不得包含客户或关联方的姓名、企业名称、身份证号、手机号、地址、账号、案号、合同号、设备号、签名、印章、二维码，作者所在律所名称，或可反向识别的精确金额与日期组合。

仅允许保留作者署名“李时瑀律师”。匿名案件摘要、原始路径映射和身份映射只在本地保存，不得上传。

发布前必须重新完成脱敏、链接、结构和法律边界审查。任一席位发现泄漏、案型错误或未经核验的实质法律结论即 `HOLD`。

详见 [署名与发布](knowledge/governance/attribution-and-release.md)、[隐私规则](PRIVACY.md) 和 [发布检查清单](RELEASE-CHECKLIST.md)。

## 12. 验证清单

- [ ] 已完成逐文件材料清单，PDF/扫描件可读性和 OCR 结果有记录；
- [ ] 已确认为普通直租，不含售后回租、转分期或第三方融资方法正文；
- [ ] 原告权利基础、现余额、时效证据、催告、管辖和租赁物现状已核验或明确 HOLD；
- [ ] 已选择一致的诉讼请求路径，没有机械叠加全部未付租金与解除、收回租赁物；
- [ ] 起诉状、证据目录和缺失材料清单三份可编辑 DOCX 均已生成；
- [ ] 输出中的事实、诉请、金额计算和证据编号互相一致；
- [ ] 已取得材料未被误列为缺失，“未找到”与“无法读取”已区分；
- [ ] 三份 DOCX 均为 A4 并通过逐页渲染检查；
- [ ] 未把谈判经验、模板语言或历史样本写成普遍法律规则；
- [ ] 未核验现行文本的命题仍标记 `pending_current_text_verification`；
- [ ] 公开包中仅出现署名“李时瑀律师”；
- [ ] 隐私、链接和发布审计均通过；
- [ ] 最终许可证已由用户在发布前确认。
