# chronology

直接从披露文件包构建诉讼时间线——每条记录都归属其来源文件，并置于 CPR 31.22 默示承诺（implied-undertaking）检查之后。

在英国民事诉讼中披露的文件只能用于该诉讼；在其他场合使用构成藐视法庭。本技能在提取任何内容之前先承认这一点：它检查 CPR 31.22 的立场，筛查特权，然后构建时间线，每条记录都附披露引用、文件路径或证人陈述段落，并对照案件理论为每个事件标注重要性。不是时间线生成器——来源归属和承诺检查才是重点。默认输出工作时间线，也可按请求输出事实陈述（Statement-of-Facts）和特定证人的变体。

## 安装

```bash
git clone https://github.com/b1rdmania/chronology ~/.claude/skills/chronology
```

或在 [Legalise](https://github.com/b1rdmania/legalise) 工作区中：从技能库添加——审查清单、授予能力、在案件上启用、从聊天中运行。每次运行都会留下带签名的可审计记录。

## 用法

```
/chronology [slug] [--format=working|sof|witness-[name]]
```

对一个带有披露文件包、证人陈述、案件理论、关键事实和己方立场的事项运行。它返回每条事件都归属其来源的时间线。

```
/chronology khan-v-acme --format=sof
```

为 Khan v Acme 事项构建时间线，并过滤为事实陈述叙事——🔴 和选定的 🟡 事件、散文、披露引用，排除带特权标注的记录。

## 它做什么

- 在从任何披露文件中提取之前运行 CPR 31.22 默示承诺检查，如果使用看起来涉及不同案件、商业目的或对外发布，则拒绝或标注。
- 确定特权状态（已清除 / 混合 / 暂停并筛查），并在来源未筛查处为记录标注 `priv: ok` / `priv: flag` / `priv: review`。
- 跨文件包、证人陈述、专家报告、公共登记簿和往来信函提取带日期的事件；将同一事件在多份文件中出现的情况去重为一条带多来源归属的记录。
- 将每条记录归属其来源——Bates 编号 / 披露引用、文件路径或证人陈述段落。来自网络搜索、模型知识或会话内用户陈述的记录标注为待核实。
- 对照指定一方的案件理论为每个事件标注重要性（🔴 影响事实认定者，🟡 有支持但可弹劾，⚪ 背景）。
- 产出工作时间线、事实陈述叙事或特定证人的时间线，含关键事件章节、空白章节，以及用于增量重建的版本跟踪。

## 它不做什么

- 不解决来源之间的矛盾——两者都保留并加标注。
- 不静默地从网络搜索或模型知识填补空白——先询问用户。
- 不决定特权状态——状态由用户选择，逐条标注为初筛；分发由律师决定。
- 不替代律师对哪些内容进入诉状或提交法院的判断。时间线及其标注是供律师审查的草稿，而非法律意见。
- 不涵盖苏格兰或北爱尔兰的诉讼程序。

## 要求

- Claude Code 或 Claude Cowork。无需 MCP 连接器。
- 一个可运行的事项（披露文件包、证人陈述或案件文件夹）。
- CPR 31.22 / 特权硬性门禁由宿主工作区上游强制执行。技能自身的检查是对其的补充，而非替代。仅对你被允许使用的材料独立运行。
