# /chronology

1. 在从披露文件中提取之前，运行 CPR 31.22 默示承诺检查。
2. 识别来源：用户提供的路径、案件文件夹、已声明的来源。
3. 提取带日期的事件，对照来源去重，按案件理论标注重要性。
4. 默认输出工作时间线；按请求输出事实陈述或特定证人的变体。

# 时间线——英国民事诉讼

## CPR 31.22 默示承诺检查

宿主工作区强制执行硬性门禁（案件 slug 与诉讼程序引用匹配、特权状态）。如果本技能在运行，该门禁已通过——本检查不替代它。技能仍执行下方自身的检查，如显示误用则拒绝或标注；它不是执法者。

在依据通过英格兰/威尔士诉讼程序的标准或扩展披露获得的任何文件构建之前，确认该使用被允许：

> CPR 31.22(1)：已向其披露文件的当事人只能为披露该文件的诉讼之目的使用该文件，除非：
> (a) 该文件已在公开举行的听证中向法院宣读、由法院宣读，或被提及；
> (b) 法院给予许可；或
> (c) 披露该文件的当事人与文件所属之人同意。

滥用披露文件（用于不同案件、不同主张、商业目的或对外发布）构成藐视法庭。

在从任何可能经披露获得的来源提取之前确认：
- 文件是否来自当前诉讼中的披露（从来源路径或案件背景推断；如不明显则呈现供确认）。
- 时间线是否将为用于同一诉讼而构建（默认假设：是——同一案件 slug、同一诉讼程序）。

如果答案显示"不同诉讼程序"或"外部使用"，拒绝构建，直到获得许可、当事人同意或公开法庭引用——否则将违反默示承诺。在输出表头显著标注：`CPR 31.22——除非获许可、经同意或在公开法庭被宣读，使用仅限于当前诉讼程序。`

在披露试点 / PD 57AD 司法辖区（商事与财产法院）的等效叠加：默示承诺适用；PD 57AD 不取代它。

## 特权筛查

文件可能受法律职业特权（咨询和诉讼特权）、共同利益特权、共同抗辩特权、无损谈判（without-prejudice）保护的保护。将特权内容提取到日后可能被分享的时间线中，可能造成弃权风险。

在提取前确定特权状态。从来源类型推断（已清除的产出文件夹 → A；混合邮箱 / 数据室 → B；无审查历史的临时文件包 → 默认为 B；明确指示暂停 → C）。在输出表头呈现推断的状态，以便律师覆盖。

- **A. 所有来源已经律师筛查并清除。** 不加标注地提取。
- **B. 混合或未筛查（歧义来源的默认）。** 提取并为每条记录标注 `priv: ok` / `priv: flag` / `priv: review`。事实陈述变体默认过滤被标注的记录。
- **C. 先暂停并筛查**（在律师明确指示时使用）。

## 输入

- 案件 slug、案件理论（一句话——案件的脊梁）、关键事实（pivot fact，案件所系的核心事件）、关键事实要点。
- 来源：披露文件包路径 / 云文件夹、补充披露、证人陈述、专家报告、公共登记簿（Companies House、Land Registry）、往来信函（公开和无损谈判——区别处理）。
- 己方立场（原告 / 被告）——驱动重要性标注。

## 工作流

### 第 1 步——CPR 31.22 默示承诺检查（见上）

### 第 2 步——特权状态选择（见上）

### 第 3 步——来源识别

先用户提供的路径，然后案件文件夹，然后已声明的来源。在"空白"章节中点名技能无法读取的任何来源——不要静默跳过。

### 第 4 步——提取

对每个可读来源，识别带日期的事件。通常每份文件一个事件。格式：`[日期] [行为人] [动词] [对象/接收人] [内容摘要]`。

### 第 5 步——去重

同一事件出现在多份文件中（日历记录、摘要邮件、会议记录）。合并为一条带多来源归属的记录。

### 第 6 步——重要性标注（按己方立场）

- **原告（进攻性）：** 🔴 确立诉因要件（义务、违约、因果关系、损失、通知）、以有利于原告的方式启动时效的事件。🟡 有支持但可弹劾。⚪ 背景。
- **被告（防御性）：** 🔴 打破因果关系、确立时效、支持积极抗辩（弃权、禁止反言、免除、共同过失）的事件。🟡 削弱原告叙事。⚪ 背景。

纪律：🔴 应保留给能影响事实认定者的事件。如果一切都是 🔴，那就什么都不是。

### 第 7 步——每条记录的来源归属

每条记录引用其来源：Bates / 披露清单引用、文件路径或证人陈述段落。从网络搜索、模型知识或会话内用户陈述推导的记录必须标注 `[web search — verify]`（网络搜索——待核实）、`[model knowledge — verify]`（模型知识——待核实）、`[user provided]`（用户提供）。

### 第 8 步——输出

默认工作时间线。变体：

- **事实陈述（SoF）**：过滤为 🔴 和选定的 🟡，散文叙事，附披露引用。默认排除带特权标注的记录。
- **特定证人**：过滤为具名证人是发件人、收件人、出席人或主题的事件。

## 输出

按以下章节产出时间线。将其呈现为完成的时间线——不要回显此模板，不要在输出中留下 `[占位符]` 标记或表情符号计数脚手架，也不要臆造事件来填行。将每条记录归属其来源文件；如果某章节没有内容，如实说明。

这是供律师审查的草稿，而非法律意见。时间线及其重要性标注是初筛；律师决定什么进入诉状或提交法院。

章节：

- 一行审查者说明：*工作成果，为诉讼而准备，受诉讼特权保护。*
- 一份 CPR 31.22 通知，点名来源文件所披露的诉讼程序。
- 一个表头：案件 slug、构建日期、案件理论、关键事实、己方立场框架、特权状态、来源数量、按标注统计的记录数量。
- 时间线表格——每条去重事件一行，含日期、事件、重要性标注、特权标记和来源。
- 关键事件（🔴）——能影响事实认定者的事件，每件附发生了什么、与案件理论的关联和来源。
- 空白——无事件日期段、预期但缺失的事件、无法读取的来源。

章节的工作形态（不要复制占位文本——从真实来源填充）：

[审查者说明：工作成果，为诉讼而准备，受诉讼特权保护。]

> **CPR 31.22 通知。** 来源包括在[诉讼程序]中披露的文件。依据 CPR 31.22，除非获许可、经同意或已在公开法庭被宣读，使用仅限于该诉讼程序。

## 增量构建

## 本技能不做什么

- 不解决来源之间的矛盾。两者都保留并加标注。
- 不静默地从网络搜索或模型知识填补空白。先询问用户。
- 不决定特权状态。状态由用户选择；逐条标注为初筛；律师决定分发。
- 不涵盖苏格兰 / 北爱尔兰诉讼程序。
