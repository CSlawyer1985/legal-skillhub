# 人工智能（AI）、数据合规与个人信息保护法律分析Plus

> **整理人**：浙江金道律师事务所 龚家勇律师（微信号：13967182079）

## Overview（概述）

本技能提供我国数据安全、数据合规、个人信息保护领域的**三库**支持：一是**规范性依据速查框架**（"法律—行政法规—部门规章—司法解释/刑法"四级规范体系），二是**学术文献知识库**（中国民商法律网 2021-01-01 起「数据合规与个人信息保护」主题文章 210 篇，按 13 个专题分类，含原文链接、网站内容摘要与 AI 观点提炼），三是**典型案例库**（经华宇元典 MCP 核验的 2023 年至今典型案例）。三者互补：规范库回答"法是什么"，学术库回答"学理与实务怎么看"，案例库回答"裁判实践如何认定"。

此外，自 **2026-08-30** 起，技能将**人工智能（AI）**作为与"数据合规 + 个人信息保护"并列的**第三支柱**，新增 `references/法规体系速查_人工智能AI专库.md`（AI 专项法规体系速查明细），承载经华宇元典 MCP 核验的 AI 部门规章、司法政策、国家标准/TC260、政策伦理与浙江省地方立法逐项明细；本 SKILL.md「速查框架」亦新增「六、人工智能（AI）专项规范层」。知识底座口径相应扩展为「AI + 数据合规 + 个人信息保护」三支柱。

本技能的最终交付物是一份 **docx 格式的结构化分析报告**，而非碎片化速查答复。其产出方法、章节结构与文末免责声明见下文「使用方法（生成 docx 分析报告）」。**三库**（规范体系速查框架 + 学术文献知识库 + 典型案例库）与"知识库空缺补充机制"共同构成报告的素材底座。

> **术语口径（2026-08-29 统一）**：本文件知识底座为**三库**：**规范性依据速查框架、学术文献知识库、典型案例库**。凡出现"三库未覆盖"之处，一律按"**内置知识库（含三库）未覆盖**"理解，案例缺失同样适用「知识库空缺补充机制」。

此外，技能内置**【典型案例库（2023 至今）】**，将最高人民法院、最高人民检察院、国家网信办、公安部及地方网信办 2023 年 1 月至 2026 年 8 月发布的与数据合规/数据安全/个人信息保护直接相关的**典型案例、指导性案例、检察公益诉讼案例、典型行政处罚与刑事打击案例**纳入知识库，作为规范体系与学术文献之外的第三类素材底座（详见「案例库（典型案例/处罚/刑事）」及 `references/典型案例库_数据合规与个人信息保护_2023至今.md`）。案例检索时点 2026-08-27，重点指导性案例经华宇元典权威案例库交叉核验。

**2026-08-29 扩充**：案例库新增**第七板块「中国 AI 司法实践案例图谱（金杜 80 例）」**，将金杜律师事务所汇编的 80 例中国 AI 司法案例（含 80 篇原文全文）纳入，并按**与数据合规/个人信息保护的关联度**分为 A/B/C/D 四级（A 类直接相关 19 例）。该板块属**律所汇编案例集**，与板块一至六的权威机关发布案例在权威性层级上不同，且其中约 46.25%（37 例）的争议焦点涉及 AIGC 可版权性（集中于 C 类 33 例，其余散见 B/D 类），属著作权法范畴，**引用须区分来源、优先检索 A 类**。详见 `references/典型案例库_AI司法实践案例图谱_金杜81例.md`。

此外，本技能在**内置知识库（三库）未覆盖**用户所需内容时，会通过华宇元典法律数据 MCP（yuandian-mcp）及官方网站（国家网信办、中国政府网、国家数据局、TC260 等）主动检索补充（详见「知识库空缺补充机制（外部检索增强）」），以「外部补充·需复核」标注来源与检索时点，保障回答的时效性与完整性。

技能内置内容均经**华宇元典法律数据库**核验（检索时点：2026-08-26；**复核修订：2026-08-29**），效力级别、施行日期、现行有效性以数据库返回为准。引用与正式适用前，请以官方公布的政府令/法律文本及最新状态为准复核。

## 使用方法（生成 docx 分析报告）

本技能的交付物为一份 **docx 格式的结构化分析报告**，而非碎片化速查答复。当触发后，按以下流程执行：

### 一、报告章节结构（强制）

报告正文须严格按以下四部分组织，文末附免责声明：

**一、法律层面分析**
- 基于用户提问，梳理所涉法律关系、权利义务、合规义务与潜在法律风险；
- 结合「四级规范体系速查框架」及个案事实，给出中立、可复核的法律分析（事实与观点分离，观点须说明依据与推理过程）；
- 必要时提示不同法律观点与反向风险（遵循"风险提示常态化"要求，避免绝对化结论）。

**二、相关法律法规规章司法解释政策等依据**
- 系统列举并摘录支撑前述分析的**法律、行政法规、部门规章、司法解释、刑法条文**原文条款；
- 每条均标注名称、令号/发文字号、施行日期、效力层级与来源（含知识库文件或官方 URL）；
- 内置知识库未覆盖的，按「知识库空缺补充机制」通过华宇元典 MCP 与官方网站检索补充，并统一以【外部补充·需复核】标注来源与检索时点。
- **数据竞争类议题的强制核查项（2026-08-29 新增）**：凡涉及数据抓取、数据搬运、数据产品、平台数据权益等不正当竞争议题，**必须同时核查并援引 2025 修订版《中华人民共和国反不正当竞争法》第十三条第三款**（2025-10-15 施行），不得以修订前的第二条作为唯一依据。

**三、相关学术论文分析**
- 从「学术文献知识库」（中国民商法律网 210 篇）中检索与议题相关的学术论文 / 实务文章，提炼核心观点与争议焦点；
- 列明标题、作者、来源栏目、发布日期、原文链接；AI 观点提炼须标注"非原文·需复核"；
- 说明各文献对本议题的可援引价值与局限。

**四、其他**
- 归入前述三节未涵盖但有助于用户决策的内容：实务建议、合规整改要点、待核实事项、检索时点说明、行业性标准（如 GB/T 系列）等。
- **临近生效/新法提示（强制）**：凡分析所涉规范处于"尚未生效"或距生效不足 60 日（含）的，须在相关分析处显著标注「【即将施行·YYYY-MM-DD】」，并提示过渡期安排与新旧衔接义务。示例：《小型个人信息处理者个人信息保护简化措施规定》尚未生效，自 2026-09-01 起施行，当前合规方案应预留衔接。

**文末免责声明（必填）**：报告结尾须以显著方式注明——**"此为AI分析，不作为法律意见和建议。"**

### 二、产出与交付

- 报告须生成 **docx 格式文件**，并在文档中**插入页码**（页脚）；
- 引用与正式适用前，须以官方公布的政府令/法律文本及华宇元典核验结果交叉复核，不得仅凭本技能检索结论定论；
- 严格区分"官方原文事实"与"AI 归纳观点"，后者均标注需复核。

## 知识库空缺补充机制（外部检索增强）

内置知识库（**三库**：四级规范体系速查框架 + 学术文献库 + 典型案例库）为高频、稳定内容的速查底座，但**不穷尽**全部现行规范、行业规章、国家标准、最新政策、全部学术成果与全部案例。当用户所需内容超出内置知识库时，按本机制**主动通过华宇元典法律数据 MCP 与官方网站检索补充**，并将外部结果以「外部补充·需复核」标注来源与检索时点。

### 一、判定"不在知识库"的标准

满足任一即视为缺失，启动补充：

- 名称 / 令号 / 条文未出现在「速查框架」与 `references/法规体系速查明细.md`；
- 用户所问学术主题 / 具体文章在「学术文献」13 专题、T16 补充专题与全量时间索引中无对应条目；
- **用户所问案例 / 案号 / 裁判规则未在「典型案例库」四个文件（含 AI 司法案例图谱 80 例及 AI 权威典型案例）中出现，或案例库中该条目标注为占位（如"详见官方通稿"）而无实质内容**；
- 用户要求某规范的最新状态、具体条文或全文，而内置内容仅含元数据。

> **检索前必做（2026-08-29 新增）**：涉及数据权益、数据抓取、数据产品、平台竞争等议题时，须先确认内置「速查框架」已含《反不正当竞争法》（2025 修订）；因本库曾在 2026-08-29 前的版本中遗漏该法，若检索结果仅指向《数据安全法》《个人信息保护法》而无反不正当竞争法条款，应判定为**内置库缺项**，按本机制以华宇元典 MCP 补检并回填。

### 三、标准操作流程

1. **先查内置三库**：检索 SKILL.md 速查框架、学术文献 13 专题与全量索引、典型案例库**四个**文件（`典型案例库_数据合规与个人信息保护_2023至今.md`、`典型案例库_数据安全法主题民事案件_华宇元典检索补录.md`、`典型案例库_AI司法实践案例图谱_金杜81例.md`、`典型案例库_AI权威典型案例_最高法及地方法院.md`，后者可用 `scripts/ai_cases_search.py --level A` 先筛直接相关案例），确认确属缺失。
2. **选渠道检索**：
   - 规范性依据 → 调 `yuandian-mcp` 对应工具（见上表）；语义检索用 `yuandian_law_vector_search`，`fatiao_filter` 按 `effect1`（法律 / 行政法规 / 部门规章 / 司法解释）与 `sxx`（现行有效 / 尚未生效）过滤，`return_num` 6–10；精确检索用 `yuandian_rh_fg_search` / `yuandian_rh_fg_detail`。
   - 政策原文 / 答问 / 解读 / 标准 → WebFetch 对应官方网站栏目。
3. **标注来源**：对返回结果统一前缀「【外部补充·需复核】」，注明来源（数据库 / 网站 + URL）、检索时点（YYYY-MM-DD），并区分"官方原文事实"与"AI 归纳观点"。
4. **双重核验（正式引用前）**：凡用于正式合规判断、诉讼论证或出具意见的，须以官方原文与华宇元典核验结果交叉确认，不得仅凭外部检索结果定论。
5. **可选持久化**：对高频、权威且状态稳定的缺失规范，将核验结果写入 `references/法规体系速查明细.md`（对应层级）或新建 `references/外部补充_*.md`，标注补充日期与来源，避免重复检索。

### 四、质量与合规约束

- **不臆造**：MCP / 网站均无结果时，明确告知"未检索到相关信息"，并建议用户提供更精确名称或至官方渠道核实；不得编造名称、令号、条文或日期。
- **时效复核**：外部结果存在滞后可能，每次正式引用前复核最新状态（新法施行、修正、失效）。
- **性质区分**：国家标准、学术文献均非狭义"法律 / 法规 / 规章 / 司法解释"，引用时须区分效力层级与约束力。
- 本机制为速查辅助的增强手段，不构成法律意见。

## 效力层级判定口径（关键）

我国规范性文件的严格四分位阶：

- **法律**——全国人大及其常委会制定（如《个人信息保护法》《数据安全法》）；
- **行政法规**——国务院制定（如《网络数据安全管理条例》《关键信息基础设施安全保护条例》）；
- **部门规章**——国务院各部门制定（如本框架第三部分各规章）；
- **司法解释**——"两高"发布（如第四部分各解释）。

**口径提示**："法律法规司法解释"若作广义理解，泛指数据合规与个人信息保护领域全部规范性依据，部门规章（如《小型个人信息处理者个人信息保护简化措施规定》）当然属该体系，处"规章"层级；若作狭义法律术语，"法规"仅指行政法规与地方性法规、"司法解释"特指"两高"文件，则部门规章不归入"法规"或"司法解释"，而是独立层级。
