# 监管交易卡生成器

## 目的

生成单个自包含 HTML 文件，将法规呈现为用于谈判、咨询或培训场景的交互式“交易卡”。输出清晰分离法律强制的内容与留给当事人自由决定的内容。这很重要，因为大多数监管指南将两者混为一谈，在不可协商的义务上浪费谈判资本，又让真正的灵活性白白流失。

## 何时使用

- 准备合同谈判，且特定法规驱动实质性条款时
- 向商业相对方或客户简报某项法规实际要求他们做什么时
- 构建需要超越单次简报时段的内部培训材料时
- 产出经邮件转发后仍不失结构的面向客户交付物时
- 任何需要逐条回答“我们必须，还是我们可以？”的问题的场景

## 输出格式

单个 HTML 文件，内联 CSS 和 JS，除可选网络字体外无外部依赖。可离线使用。打印友好。设计为在浏览器中打开并用作工作工具，而非静态参考。

核心可见组件：

- 跨法规章节的粘性导航
- 逐要求行，显示：带条款引用的要求、要求的响应、可协商方面和示例
- 次级材料的可折叠详情块
- 定义术语的悬停提示
- 每项要求的风险徽章（高 / 中 / 低）
- 适用处的可选双语切换

## 核心结构规则

交易卡中的每一行按此顺序回答三个问题：

1. **法规强制要求什么？**（附条款引用）
2. **完成方式的哪些部分是固定的？**（不可协商的下限）
3. **哪些可开放协商？**（实施机制、时间安排、当事人间分配、文档格式等）

无法区分（2）与（3）的行是没有想清楚的行。即使令人不适，也要强制区分，并将真正的歧义明确标记出来，而非藏在中立叙述中。

## 工作流

1. **识别法规。** 确认官方引注、现行合并版本和最后修订日期。
2. **核验文本。** 对照一手来源交叉核对（欧盟文件用 EUR-Lex，国内法用官方公报或同等物）。不依赖二手摘要。若法规较新或经修订，检查勘误。
3. **按业务逻辑而非条款顺序组织。** 用户按主题（数据访问、事件报告、第三方风险）而非条款编号阅读交易卡。相应分组并在各主题内引用条款。
4. **分类每项要求。** 对每项条款，写下强制最低要求，再分别写下当事人可自行决定的内容。抵制将两者合并的诱惑。
5. **每项要求添加示例。** 一个展示合规在实践中形态的具体场景，以及相关处的展示不合规形态的反例。
6. **构建 HTML。** 使用 `references/html-template.md` 中的模式。保持文件自包含。
7. **测试交互性。** 每个折叠、提示和筛选都应在未打开开发工具的冷浏览器中工作。
8. **添加版本元数据。** 法规引注、核验日期，以及可见的提示——用户在依赖输出作出任何约束性决定前应重新核验。

## 设计原则

### 谈判导向框架

将法律语言转化为三种语域：

- 法律：数据持有人应无不当延迟地向用户提供数据。
- 商业：您必须及时提供用户访问权限；什么算及时、以什么格式提供，由您谈判。
- 风险：未能提供访问权限将使您面临行政罚款和用户的私人诉权。

### 条款级精确性

始终引用具体条款。对条款位于正文、附件还是实施性文件保持精确。条款依赖尚未采纳的授权性文件时，明确说明。

### 示例丰富的行

每个主要要求至少一个示例。法规曾成为执法行动或已发布指引的对象时，纳入其中。法规过新、尚无执法时，也如实说明，而非用虚构示例冒充成熟实践填充。

## 严重程度框架

每行携带可见的风险等级：

| 严重程度 | 含义 |
|---|---|
| 高 | 面临实质性行政罚款、刑事处罚或私人诉权 |
| 中 | 可能受到行政处罚，监管行动可能性大 |
| 低 | 最佳实践；不合规不太可能被直接制裁，但可能影响日后执法态势 |

风险等级关乎不合规的后果，而非合规的难易程度。

## HTML 模板

完整模板见 `references/html-template.md`，包括：

- 含设计令牌的基础 CSS
- 导航和面板结构
- 含强制/可协商分隔的问题行布局
- 可折叠章节和提示模式
- 风险徽章样式
- 打印和移动样式表
- 双语切换模式

模板是起点。将文案和结构适配到具体法规。保持视觉一致性。

## 双语输出

对以双语材料为标准的法域（DACH 商业工作使用德语和英语、双重备案场景使用法语和英语等），模板支持语言切换。两种模式：

- **平行双栏**：适合术语映射和定义术语表
- **语言切换**：适合两种版本均具权威性的完整平行文本

不要机器翻译法律文本。若无法用两种语言产出准确平行法律文本，产出一语并注明翻译缺口。

## 质量检查清单

定稿前：

- [ ] 所有条款引用已对照一手来源核验
- [ ] 每行的强制 vs 可协商区分已明确
- [ ] 每个主要要求至少一个示例
- [ ] 交易卡中的每个定义术语都有提示定义
- [ ] 导航在所有面板间工作
- [ ] 检索和筛选（如包含）在所有内容上工作
- [ ] 打印样式表产出可用的打印文档
- [ ] 移动布局无横向滚动即可读
- [ ] 法规版本和核验日期可见显示
- [ ] 法规中的局限和未决问题得到诚实标记

## 局限与免责声明

交易卡是谈判和培训辅助工具。它不是法律意见，也不替代就具体事项咨询合格律师。在输出中按以下思路包含可见免责声明：

> “本交易卡反映截至 [日期] 的法规状况。法规会演变；指引和执法实践演变更快。在依赖本文档作出任何约束性决定前，核验现行文本。具体事项需由适用法域的合格法律顾问处理。”

## 输出位置

以清晰命名惯例保存生成文件：

```
[regulation-short-name]-deal-card-[YYYY-MM-DD].html
```

示例：`data-act-deal-card-2026-04-23.html`
