# 网站 RGPD 审计检查清单——从业者基准

> Knowledge file 1/2——Skill `audit-rgpd-site-internet`
> 来源：GDPR 从业者/DPO 实践，整合自 CNIL 学理（2020-091、2022-100、受众测量豁免）、GDPR 第 12-14 条、LCEN、ePrivacy 指令及 EDPB 建议。

---

## 范围

审计覆盖**十个部分**，全部通过对网站的直接观察（导航 + 浏览器开发者工具）核验。每个项目由从业者（在 AI 辅助下）判定**是 / 否 / 不适用**，并在**观察**列补充文字引用、URL 或截图。

22 项附录再现 GDPR 第 13 条和第 14 条对隐私政策的要求。

| # | 部分 | 主要基准 |
|---|---|---|
| 1 | 法律声明 | LCEN 第 6 条第 III 款、2007-1010 号法令 |
| 2 | 托管服务商相关信息 | LCEN 第 6 条第 III 款 |
| 3 | 收集表单 | GDPR 第 13 条 |
| 4 | 新闻通讯 | GDPR 第 7 条 + ePrivacy 第 5(3) 条 |
| 5 | 隐私政策 | GDPR 第 12-14 条 |
| 6 | cookies 政策和横幅 | 《数据保护与自由法》第 82 条 + CNIL 2020-091 号审议 |
| 7 | 密码（如有身份认证） | CNIL 2022-100 号审议 |
| 8 | 跟踪器和受众测量 | CNIL 受众测量豁免建议 |
| 9 | 可检测的次级处理方和欧盟境外转移 | GDPR 第 28 条 + 第 44-49 条、CCT 2021、EDPB 01/2020 |
| 10 | 权利收集的可及性 | GDPR 第 12 条、第 15-22 条 |

| 注册资本 | 注册资本金额（如适用） | |
| 地址 | 注册地址 | |

## 第 3 部分——数据收集表单

目标：核验网站上的每个收集表单是否包含完整的 GDPR 告知声明（GDPR 第 13 条）。

对网站上识别出的**每个**表单（联系、报价、应聘、账户创建等），核验：

| 子项目 | 描述 | 是/否 |
|---|---|---|
| 处理负责人身份 | 在表单上识别或通过引用识别 | |
| 目的 | 处理目的已说明（"用于回复您的请求"、"用于向您发送商业信息"等） | |
| 法律依据 | 已注明或可推知的法律依据（同意 / 合同 / 合法利益） | |
| 必填 / 选填性质 | 必填字段与选填字段区分（星号或声明） | |
| 保存期限 | 已声明期限或确定标准 | |
| 隐私政策引用 | 明确且可点击的引用 | |
| 敏感数据同意 | 如收集敏感数据（健康、观点、工会等）：是否收集明确同意？ | |
| 未成年人收集 | 如涉及未成年人：是否有相应声明，且未满 15 周岁时是否收集家长同意？ | |

## 第 4 部分——新闻通讯

目标：核验新闻通讯订阅表单的合规性（自由、具体、知情、明确的同意）。

| 项目 | 描述 | 是/否 |
|---|---|---|
| 同意收集 | 表单是否收集同意（如需要）？ | |
| 复选框默认空白 | 复选框是否默认为空白（不预勾选）？ | |
| 声明合规 | 同意收集声明是否合规（目的、撤回权、负责人身份）？ | |
| 替代退出机制（B2B 和现有客户） | 如不需要同意（面向现有客户推销同类产品——CPCE 第 L34-5 条）：是否设有反对勾选项？ | |
| 退订链接 | 每封邮件中是否存在（如可能，后续核验）？ | |

## 第 5 部分——隐私政策

目标：核验隐私政策的存在和合规性（GDPR 第 13 条和第 14 条）。

| 项目 | 描述 | 是/否 |
|---|---|---|
| 存在 | 网站是否设有隐私政策？ | |
| 专用页面 | 是否位于专用页面（而非淹没在销售条款中）？ | |
| 完整 | 是否完整（见下文第 13/14 条 22 项附录）？ | |
| 目的全面 | 所列目的是否全面（如招聘、推销、受众测量等）？ | |
| 可及性 | 是否可从每个页面轻松访问（页脚，最多 2 次点击）？ | |
| 语言可懂 | 是否以数据主体能理解的语言撰写（面向法语受众为法语）？ | |
| 适合未成年人 | 如数据主体可能为未成年人：他们能否理解？ | |
| 用语清晰简单 | 是否以清晰简单的用语撰写（CNIL——透明度原则）？ | |
| 更新日期 | 最近更新日期是否可见？ | |
| 版本历史 | 能否查阅既往版本（CNIL 建议）？ | |

## 第 6 部分——cookies 政策和横幅

目标：核验 cookies 政策和同意横幅的存在及合规性（《数据保护与自由法》第 82 条 / ePrivacy 第 5(3) 条 + CNIL 2020-091 号审议）。

### 6.1 cookies 政策

| 项目 | 描述 | 是/否 |
|---|---|---|
| cookies 政策存在 | 网站是否设有 cookies 政策页面或部分？ | |
| cookies 政策完整 | 是否完整列出所有 cookies（名称、目的、期限、发出方——第一方/第三方）？ | |
| 按目的区分 | cookies 是否按目的分组（技术、受众测量、广告、社交网络）？ | |
| 次级处理方已识别 | 是否明确点名第三方发出方（如 Google Ireland Limited、Meta Platforms Ireland Ltd）？ | |
| 管理方式 | 是否说明同意管理方式（引用浏览器设置 + 撤销链接）？ | |

### 6.2 cookies 横幅

| 项目 | 描述 | 是/否 |
|---|---|---|
| 横幅存在 | 首次访问时网站是否显示 cookies 横幅？ | |
| 负责人身份 | 横幅是否表明处理负责人身份（或明确引用）？ | |
| cookies 目的 | 横幅是否说明所用每种 cookies 的目的？ | |
| 接受/拒绝方式 | 横幅是否说明接受或拒绝跟踪器的方式？ | |
| 后果 | 横幅是否说明拒绝或接受的后果？ | |
| 撤回权 | 横幅是否表明存在撤回同意的权利？ | |
| 横幅重现 | 是否有方便访问的永久图标可让横幅重新出现？ | |
| 按钮等效（CNIL 2020-091） | "接受"、"拒绝"和"设置"按钮是否同颜色、同大小、同布局？ | |
| 拒绝同样简单 | 拒绝是否与接受同样简单（无需额外点击）？ | |
| 默认不投放 cookies | 可选 cookies 是否**不**默认投放（同意之前）？ | |
| 选择保存期限 | 选择保存多长时间？（最长 6 个月——CNIL 建议） | |
| 同意粒度 | 能否按 cookie 或按目的逐项同意？ | |

### 6.3 目的的强制声明（CNIL 提醒）

- 技术 cookies："为便于您浏览网站"
- 广告 cookies："根据您的浏览画像和所在位置向您提供个性化广告"
- 社交网络 cookies："在社交网络及其他在线平台上分享内容"
- 受众测量 cookies："生成旨在改善您在我们网站上体验的统计数据"

## 第 7 部分——密码（如网站设有身份认证）

目标：核验密码要求是否符合 CNIL 建议（2022-100 号审议）。

| 项目 | 描述 | 是/否 |
|---|---|---|
| CNIL 合规 | 密码要求是否符合 CNIL 建议？ | |
| 多次失败后锁定 | 多次失败后是否临时锁定（防暴力破解）？ | |
| 安全重置 | 是否通过带限时链接的邮件重置？ | |
| 不明文发送 | 注册后是否不通过邮件发送密码？ | |
| 支持 MFA | 是否提供多因素认证（建议用于敏感账户）？ | |

**三个符合 CNIL 的示例（任选其一）：**
- **示例 1**：至少 12 个字符 + 大写字母 + 小写字母 + 数字 + 特殊字符（从 ≥37 个中选择）
- **示例 2**：至少 14 个字符 + 大写字母 + 小写字母 + 数字（不强制特殊字符）
- **示例 3**：至少 7 个词的密码短语

## 第 8 部分——跟踪器和受众测量

目标：核验受众测量工具和广告像素的合规性（CNIL 基准——受众测量免同意）。

### 8.1 跟踪器识别

列出所有检测到的跟踪器（通过浏览器开发者工具——Network 选项卡 + uBlock Origin / Privacy Badger 扩展快速识别）：

| 跟踪器 | 发出方 | 目的 | 第三方 cookie？ | 需要同意？ |
|---|---|---|---|---|
| 例：Google Analytics 4 | Google Ireland Ltd | 受众测量 | 是（第三方） | 是（当前状态下不可豁免） |
| 例：Meta Pixel | Meta Platforms Ireland Ltd | 定向广告 | 是 | 是 |
| 例：Matomo（自托管） | [网站托管方] | 受众测量 | 否（第一方） | 符合 CNIL 豁免配置时为否 |
| 例：Hotjar / Microsoft Clarity | Hotjar Ltd / Microsoft | 热力图、会话回放 | 是 | 是 |

### 8.2 CNIL 受众测量豁免标准

受众测量工具要获得同意豁免，须同时满足：

| 标准 | 描述 | 是/否 |
|---|---|---|
| 目的严格限定 | 仅用于测量网站受众及其表现 | |
| 不交叉 | 数据不与其它处理交叉，不转传给第三方 | |
| IP 匿名化 | 存储前截断 IP 地址（至少最后一个字节） | |
| 不跨站跟踪 | 不跟踪其他网站的浏览行为 | |
| 期限合理 | cookie 有效期 ≤ 13 个月，数据保存期限 ≤ 25 个月 | |
| 托管 | 数据托管在欧盟或充分性国家（Schrems II） | |

**注意点**：Google Analytics（GA4）在其标准配置下不满足全部标准。CNIL 已确认 GA4 不免除同意。可考虑带服务端代理的配置，但仍存争议。

### 8.3 与 cookies 政策的一致性

| 项目 | 描述 | 是/否 |
|---|---|---|
| 所有跟踪器均已列出 | 技术上观察到的每个跟踪器是否都列入 cookies 政策？ | |
| 目的一致 | 所声明的目的是否与实际用途相符？ | |
| 同意一致 | 需要同意的跟踪器是否在获接受前确实被阻止？ | |

## 第 9 部分——可检测的次级处理方和欧盟境外转移

目标：识别通过网站分析可见的次级处理方，并核验欧盟境外转移（GDPR 第 28 条 + 第 44-49 条）。

### 9.1 可检测次级处理方的测绘

对每类服务，识别所用的次级处理方：

| 类别 | 常见次级处理方示例 | 典型所在地 | 境外转移机制 |
|---|---|---|---|
| 网站托管 | OVH、Scaleway、AWS、Google Cloud、Azure | 欧盟或美国 | DPF / CCT 2021 / 区域画像 |
| CDN | Cloudflare、Akamai、Fastly | 美国（但欧盟有 POP） | DPF / CCT 2021 |
| 在线支付 | Stripe、PayPal、Adyen、Worldline | 美国或欧盟 | DPF / CCT 2021 |
| 新闻通讯 | Mailchimp、Brevo、Sendinblue、Mailjet | 美国或欧盟 | DPF / CCT 2021 |
| CRM / 营销 | HubSpot、Salesforce、Marketo、ActiveCampaign | 美国 | DPF / CCT 2021 |
| 受众测量 | Google Analytics、Matomo、Plausible、Fathom | 美国或欧盟 | 如在美国则 DPF / CCT 2021 |
| 聊天 / 支持 | Intercom、Crisp、Zendesk、Freshdesk | 美国或欧盟 | 如在美国则 DPF / CCT 2021 |
| 嵌入视频 | YouTube、Vimeo、Dailymotion | 美国或欧盟 | 如在美国则 DPF / CCT 2021 |
| 网络字体 | Google Fonts（CDN）、Adobe Fonts | 美国 | 如调用外部 API 则 DPF / CCT 2021 |
| 交互式地图 | Google Maps、OpenStreetMap、Mapbox | 美国或欧盟 | 如在美国则 DPF / CCT 2021 |
| reCAPTCHA / 反机器人 | Google reCAPTCHA、hCaptcha、Cloudflare Turnstile | 美国或欧盟 | 如在美国则 DPF / CCT 2021 |

### 9.2 对每个已识别次级处理方的核验

对网站上识别出的每个次级处理方：

| 项目 | 描述 | 是/否 |
|---|---|---|
| 政策中提及 | 次级处理方是否在隐私政策中点名？ | |
| 目的已记录 | 委托处理的目的是否已记录？ | |
| 所在地已注明 | 处理所在地（欧盟 / 境外）是否已注明？ | |
| 转移机制 | 如境外：是否注明机制（DPF、CCT 2021、BCR、第 49 条例外）？ | |
| 提及 TIA | 如向有风险的第三国转移：是否完成 TIA 及补充措施（EDPB 01/2020）？ | |

### 9.3 Google reCAPTCHA 和 Google Fonts 的情形

常见且常被遗漏的情形：
- **reCAPTCHA**：将 IP 和行为数据传输给 Google Inc.（美国）。通常未收集同意（在横幅接受/拒绝之前即加载）。
- **托管在 Google 的 Google Fonts**：将 IP 传输至 Google CDN。建议：本地托管字体或使用代理。

## 第 10 部分——权利收集的可及性

目标：核验数据主体能否方便地行使 GDPR 权利（第 12 条 + 第 15-22 条）。

| 项目 | 描述 | 是/否 |
|---|---|---|
| 专用地址 | 是否有专用邮箱（privacy@、dpo@、donneespersonnelles@），还是仅有 contact@？ | |
| 专用表单 | 是否有供权利行使请求的在线表单？ | |
| 权利清单 | 隐私政策中是否完整列出各项权利（访问、更正、删除、限制、反对、可携带、撤回同意）？ | |
| 已声明期限 | 是否声明回复期限（1 个月，可延长 2 个月——第 12 条第 3 款）？ | |
| 身份识别方式 | 身份识别方式是否与风险相称（不一律要求身份证件）？ | |
| CNIL 声明 | 是否声明可向 CNIL 提出投诉（第 77 条）？ | |
| CNIL 联系方式 | 是否提供 CNIL 联系方式（3 Place de Fontenoy, 75007 Paris——www.cnil.fr/plaintes）？ | |
| 免费 | 是否声明首次请求免费（第 12 条第 5 款）？ | |

## 审计时应遍历的页面

审计覆盖**网站的所有页面**，优先：

1. 首页（页脚中是否有指向法律声明、隐私政策、cookies 政策的链接）
2. "法律声明"页面
3. "隐私政策"页面
4. "cookies 政策"页面（如独立）
5. "销售条款 / 使用条款"页面（核验其**不与**隐私政策**合并**）
6. 所有含收集表单的页面（联系、报价、新闻通讯、账户创建、应聘等）
7. 支付页面（如为电子商务——核验银行卡数据声明和支付次级处理方）
8. 每个页面的页脚（核验永久链接的持久性）
9. cookies 横幅（首次访问时及重现图标）
10. 显示动态数据的页面（搜索、用户画像、客户空间如可访问）
11. 账户创建和密码重置页面（如有身份认证）
12. 网站地图 / sitemap（用于识别所有公开页面）

## 审计推荐的常用技术工具

| 工具 | 用途 |
|---|---|
| 浏览器开发者工具（F12） | Application 选项卡 → Cookies（已投放 cookies）、Network 选项卡（第三方请求、跟踪器） |
| uBlock Origin 或 Privacy Badger 扩展 | 快速识别第三方跟踪器 |
| Wappalyzer 或 BuiltWith 扩展 | 识别技术栈（CMS、框架、分析、托管商） |
| Whois / DNS 查询 | 识别托管商、CDN、域名注册商 |
| Lighthouse（Chrome 审计） | 性能 + 可访问性补充审计（对建议有用） |
| EDPS Website Evidence Collector（开源） | 欧洲官方工具，用于自动化收集审计证据 |

使用这些工具属于对网站的被动观察，**不构成**安全侵害（无漏洞扫描、无注入、无未授权访问尝试）。
