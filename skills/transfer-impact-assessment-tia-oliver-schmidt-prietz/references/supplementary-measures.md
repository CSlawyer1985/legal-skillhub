# 补充措施目录

来源：EDPB 建议 01/2020 附件 2——补充措施示例。

本目录将措施映射到它们所针对的基本保障缺口。每项措施均包含诚实的"何时有效"和"何时**不**有效"指引——目标不是掩盖缺口，而是在可能处封堵缺口，并在不可能处诚实标注。

慕尼黑高等地方法院判决（21 U 3882/25 e，2026）确认加密 + 最少必要数据 + 透明度报告是德国法院接受的真正补充措施。本目录反映了这一实际接受。

---

## 技术措施

### TM-1：传输中和静态加密，密钥由出口方持有

**针对：** 大规模监控、当局对静态数据的访问、进口方侧泄露。

**何时有效：**
- 进口方不需要访问明文（纯存储服务、备份、存档）
- 密钥管理完全在欧洲经济区内、出口方控制之下
- 无已知弱点的现代算法（AES-256、RSA-4096+）
- 第三国法律无法强制出口方交出密钥

**何时**不**有效：**
- 进口方必须解密以进行处理（云 SaaS、分析、内容审核、AI 推理）
- 密钥托管于进口方或接收国境内的第三方
- 进口方是同时托管数据和密钥的云提供者（即使有 HSM 隔离，如进口方可被强制）

### TM-2：假名化

**针对：** 当局的再识别、部分数据最小化。

**何时有效：**
- 映射表/再识别密钥保留在欧洲经济区内、出口方控制之下
- 假名化数据单独对识别个人效用有限
- 稳健的假名化（带秘密盐的哈希，而非仅可逆的令牌化）

**何时**不**有效：**
- 当局可强制交出映射表（例如通过国内程序对出口方）
- 假名化可轻易逆转（例如简单 ID 置换）
- 进口方可通过其已持有的辅助数据再识别

### TM-3：拆分/多方处理

**针对：** 单一节点政府访问；无任何单一当事方掌握全貌。

**何时有效：**
- 处理可真正分布于多个司法辖区
- 没有任何单一处理者持有完整数据集
- 输出仅在欧洲经济区内聚合（或通过安全多方计算）

**何时**不**有效：**
- 服务架构要求集中处理
- 一方实际进行编排并可被强制拼凑出全貌

### TM-4：传输层加密（TLS / VPN）

**针对：** 出口方与进口方之间传输中的拦截。

**何时有效：**
- 标准 TLS 1.3 或更高版本，配强密码套件
- 经核验的证书链
- 对任何传输而言，这是基线卫生，本身不是 Schrems II 意义上的补充措施

**何时**不**有效：**
- 对针对进口方的合法披露请求无济于事（数据在端点解密）
- 对进口方侧泄露无济于事

## 合同措施

### CM-1：透明度义务（访问请求通知）

**针对：** 缺乏监督；数据主体不知晓访问。

**何时有效：**
- 进口方承诺将影响所传输数据的任何政府访问请求通知出口方
- 进口方承诺通知数据主体（在法律允许的情况下）
- 结合定期透明度报告（所收请求的汇总统计）

**何时**不**有效：**
- 当地法律禁止通知（美国 FISA 702 下的封口令、NSL 保密令等）
- 进口方承诺但缺乏执行能力
- 仅通知出口方，无告知受影响数据主体的途径

### CM-2：质疑/抗辩条款

**针对：** 救济薄弱、对过度宽泛请求的自动服从。

**何时有效：**
- 进口方承诺评估每项请求的合法性、必要性和相称性
- 进口方承诺通过可用的法律渠道质疑过度宽泛或非法的请求
- 进口方具有诉讼资格和现实的法律途径进行质疑

**何时**不**有效：**
- 当地法律下无可用的现实法律质疑途径
- 进口方因不服从而面临超过合同义务的严厉处罚
- 诉讼资格受限（例如进口方不能代表数据主体质疑）

### CM-3：强化审计权

**针对：** 缺乏监督、进口方合规核验。

**何时有效：**
- 出口方或独立审计师可有意义地检查进口方的合规情况
- 审计涵盖技术措施（加密部署、访问控制）和程序措施（请求处理）
- 审计发现可采取行动（纠正措施、终止）

**何时**不**有效：**
- 审计在规模上不切实际（例如审计超大规模云提供者的全部运营）
- 审计访问因国家安全/涉密操作主张而受限
- 审计发现无执行机制

### CM-4：数据本地化承诺

**针对：** 管辖越权；数据物理上存在于第三国。

**何时有效：**
- 进口方承诺将数据保存在欧洲经济区内（或其他商定司法辖区）进行存储和处理
- 架构支持本地化（区域云区域、欧盟主权云变体）
- 再处理者管理确保本地化延伸至整条链条

**何时**不**有效：**
- 服务架构要求传输（这正是业务往来的全部意义）
- 本地化仅为承诺，无技术强制
- 进口方的母公司可无视合同承诺强制跨境访问（EDPB 指南 05/2021 中的示例 12 问题）

## 组织措施

### OM-1：严格目的限制政策

**针对：** 功能蔓延；数据用于传输目的之外。

**何时有效：**
- 进口方的内部政策将处理约束于传输目的
- 访问控制在技术上强制执行目的限制
- 定期政策合规评估

**何时**不**有效：**
- 政策无技术强制执行
- 违约无后果
- 当局通过法院命令绕过内部政策

### OM-2：访问控制政策（最少必要访问）

**针对：** 进口方人员的宽泛内部访问。

**何时有效：**
- 基于角色的访问控制将数据暴露限制于需要知晓的人员
- 特权访问审查和撤销流程
- 有日志且可审计的访问痕迹

**何时**不**有效：**
- 当局通过法律程序绕过内部控制
- 进口方的管理员实际上拥有无限制访问

### OM-3：政府请求处理政策

**针对：** 对政府访问请求的临时/不一致回应。

**何时有效：**
- 进口方有文档化流程：合法性审查 → 最少必要 → 通知（如允许）→ 质疑（如适用）
- 经培训的人员处理请求
- 对收到和处理请求的公开透明度报告

**何时**不**有效：**
- 政策对法院命令/NSL 无法律效力
- 当地法律要求服从且无内部审查
- 无质疑途径

### OM-4：认证与行为准则

**针对：** 经核验的合规态势；第三方保证。

**何时有效：**
- 认可认证（ISO 27001、ISO 27701、SOC 2 类型 II、ENS、欧盟云行为准则）
- 认证涵盖相关处理范围
- 审计师独立性和能力经核验

**何时**不**有效：**
- 认证范围限于其他处理
- 审计师受制于人/缺乏独立性
- 认证机构本身受可疑政府影响

## 自动建议逻辑

当第 3 步识别出特定基本保障的缺口时，本技能使用以下映射将措施匹配到缺口：

| 识别出的缺口（按基本保障） | 建议措施 |
|---|---|
| 保障 A（规则不明确） | OM-3（请求处理政策）、CM-1（透明度义务） |
| 保障 B（大规模监控 / 无相称性） | TM-1（出口方持有密钥的加密）、TM-2（假名化）、CM-4（数据本地化） |
| 保障 C（无独立监督） | CM-1（透明度）、CM-3（审计权）、OM-4（认证） |
| 保障 D（无有效救济） | CM-2（质疑条款）、CM-1（透明度）、OM-3（请求处理） |
| 进口方必须处理明文 | TM-2（假名化）、TM-3（拆分处理），如两者均不可行 → 标注缺口无法封堵 |

本技能呈现匹配的建议，让使用者接受/拒绝/定制，然后针对缺口评估总体有效性。如有效性不足，本技能诚实标注：该传输无法按现结构进行。
