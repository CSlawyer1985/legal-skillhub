# TIA 文件模板

本文件定义 skill 产出的正式 TIA 文件的结构。skill 以 Markdown（预览）和 `.docx`（正式）版本输出同一结构。

使用 CNIL TIA 指南表格作为评估部分的视觉模型。

---

## 封面页

| 字段 | 内容 |
|---|---|
| 文件标题 | 传输影响评估——[进口者名称] |
| TIA 文号 | `TIA-<DEST-CC>-<YYYY>-<seq>`（如 `TIA-US-2026-001`） |
| 版本 | 1.0（初始） |
| 评估日期 | YYYY-MM-DD |
| 下次审查日期 | YYYY-MM-DD |
| 出口者 | 姓名、职务、EEA 设立地 |
| 进口者 | 姓名、职务、国家 |
| 评估人 | 姓名、职务 |
| 批准人（DPO） | 姓名、日期 |

## 第 3 节：第三国评估（EDPB 第 3 步）

### 块 A——数据保护框架

（CNIL 风格表格）

| 问题 | 发现 |
|---|---|
| 一般数据保护法？ | 是 / 否——名称、范围 |
| 独立监督机构？ | 是 / 否——名称、独立性评估 |
| 数据主体权利？ | 访问、更正、删除、反对——注明缺口 |
| 有效救济和制裁？ | 是 / 部分 / 否——理由 |

### 块 B——监控 / 政府访问法律

对每项相关法律（来自国家概况）：

| 法律 | 范围 | 权力 | 保障 A | 保障 B | 保障 C | 保障 D |
|---|---|---|---|---|---|---|

（每项保障：充分 / 关切 / 不足）

### 块 C——实务风险评估

| 问题 | 发现 |
|---|---|
| 进口者的政府访问请求历史？ | （引用透明度报告） |
| 现实的定向依据？ | （行业、数据类型、规模） |
| 进口者对明文的技术访问？ | 是 / 否 |
| 机关对此数据的现实兴趣？ | （说明理由） |

### 第 3 步结论

选择其一：
- ☐ (1) 传输工具有效——无需补充措施继续
- ☐ (2) 传输工具无效——需要补充措施
- ☐ (3) 传输工具纸面上无效，但无现实依据相信有问题的法律会适用——附充分文件继续

**理由：**（对三者均为强制；选项 3 要求实质性——而非模板化——推理）
