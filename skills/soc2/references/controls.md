## 安全——通用标准

### CC1——控制环境

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC1.1 | 展示 COSO 原则；对诚信和道德价值观的承诺 | 无行为守则或道德政策；领导层未明显参与 |
| CC1.2 | 董事会或同等机构对安全计划的监督 | 无文件化的董事会/高管安全监督；无会议纪要 |
| CC1.3 | 组织结构、汇报线、职权已定义 | 组织架构图非最新；安全角色未定义 |
| CC1.4 | 合格人员；人力资源生命周期控制 | 无背景调查；无安全培训计划 |
| CC1.5 | 安全责任的问责 | 绩效目标不包含安全；无执行机制 |

**示例控制（CC1.4）：**
```
控制 ID：    CC1.4-001
标题：       安全意识培训
类型：       预防性
负责人：     人力资源 / 安全
频率：       年度（+ 入职时）
描述：       所有员工完成年度安全意识培训，涵盖网络钓鱼、数据处理和事件报告。
             完成情况被跟踪，未完成者上报至经理。
证据：       学习管理系统（LMS）的培训完成报告、入职检查清单签署记录
测试：       检查培训平台报告；确认期间内完成率 >95%；抽样 5 名员工核实
             完成日期在 12 个月内。
```

### CC2——沟通与信息

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC2.1 | 支持控制目标的优质信息可用 | 政策无法访问或未分发；无内网/知识库 |
| CC2.2 | 关于安全责任的内部沟通 | 安全更新未传达；无全员会议或通讯 |
| CC2.3 | 与客户、监管机构、供应商的外部沟通 | 无向客户通知安全事件的流程；SLA 条款含糊 |

---

### CC3——风险评估

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC3.1 | 已定义风险目标；已声明风险容忍度 | 无书面风险偏好或容忍度声明 |
| CC3.2 | 风险识别和分析流程 | 无正式风险评估；仅非正式或临时进行 |
| CC3.3 | 已考虑舞弊风险 | 无舞弊风险评估或控制 |
| CC3.4 | 已评估技术变更风险 | 变更不触发风险重新评估 |

**示例控制（CC3.2）：**
```
控制 ID：    CC3.2-001
标题：       年度风险评估
类型：       侦测性
负责人：     CISO / 安全经理
频率：       年度 + 事件驱动
描述：       每年进行一次正式风险评估，识别威胁、脆弱性以及可能性/影响评级。
             维护风险登记册，由安全委员会每季度审查。
证据：       风险登记册（注明日期）、附签署的风险评估报告、
             安全委员会会议纪要
测试：       检查风险登记册；确认日期在 12 个月内；核实管理层签署；
             确认高风险项有修复责任人。
```

### CC5——控制活动

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC5.1 | 选择控制以缓解风险 | 控制未映射到风险；无控制矩阵 |
| CC5.2 | 已部署技术控制 | 无 MFA、无端点保护、无 SIEM |
| CC5.3 | 已部署政策和程序 | 政策存在但未执行；关键流程无程序 |

### CC6——逻辑和物理访问控制

这通常是测试最密集的领域。

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC6.1 | 逻辑访问安全措施 | 关键系统无 MFA；无 SSO；共享账户 |
| CC6.2 | 新访问权限的授予经授权 | 无正式的访问申请/审批流程 |
| CC6.3 | 离职/岗位变更的访问权限移除 | 离职员工未及时取消配置（>24 小时是警示标志） |
| CC6.4 | 访问凭证受保护 | 密码明文存储；特权账户无 PAM |
| CC6.5 | 逻辑访问被审查 | 无定期用户访问审查（季度/年度） |
| CC6.6 | 逻辑访问免受威胁限制 | 无 IDS/IPS；无网络分段 |
| CC6.7 | 数据传输受保护 | 传输中数据未加密；无 TLS 强制 |
| CC6.8 | 阻止未授权软件 | 无应用白名单或 MDM；影子 IT 不受控 |

**示例控制（CC6.3）：**
```
控制 ID：    CC6.3-001
标题：       访问终止——员工离职流程
类型：       预防性
负责人：     IT / 人力资源
频率：       事件驱动（每次离职）
描述：       员工离职时，IT 在人力资源发起的离职工单后 24 小时内禁用所有
             系统访问。检查清单确认：AD 账户已禁用、SaaS 应用访问已撤销、
             VPN 证书已吊销、硬件已归还。人力资源在 HRIS 中确认完成。
证据：       离职工单、访问撤销日志、HRIS 离职记录
测试：       在审计期间选取 10-25 起离职样本；使用 AD 日志和工单时间戳
             核实访问在 24 小时内被撤销。
```

### CC7——系统运营

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC7.1 | 脆弱性和恶意软件检测 | 无漏洞扫描；端点无 EDR |
| CC7.2 | 安全事件监控 | 无 SIEM 或日志聚合；警报未被审查 |
| CC7.3 | 安全事件被评估和响应 | 无事件响应计划；事件未记录 |
| CC7.4 | 安全事件被遏制和解决 | 无 IR 手册；无事后审查流程 |
| CC7.5 | 已识别漏洞被修复 | 关键漏洞修补无 SLA；无修补节奏 |

---

### CC8——变更管理

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| CC8.1 | 变更经授权、测试和批准 | 无工单或批准即部署变更；未在预发布环境测试 |

**示例控制（CC8.1）：**
```
控制 ID：    CC8.1-001
标题：       生产变更审批
类型：       预防性
负责人：     工程 / DevOps
频率：       事件驱动
描述：       所有生产变更在部署前需经授权审查人（技术负责人或经理）批准的
             变更请求工单。紧急变更需在 24 小时内追溯批准。变更在提升至
             生产前须在预发布/质量保证环境测试。
证据：       带批准的变更工单、部署日志、版本控制（GitHub/GitLab）中的
             PR 批准、JIRA/Linear 工单历史
测试：       在审计期间抽取 20-30 项变更；核实每项均有事先批准、
             非开发人员的测试人员，以及附部署确认的工单关闭。
```

## 可用性（A1）

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| A1.1 | 容量被监控和管理 | 无容量监控；资源阈值无告警 |
| A1.2 | 环境威胁被管理；备份经测试 | 无备份验证；无恢复测试 |
| A1.3 | 恢复经测试；RTO/RPO 已定义 | RTO/RPO 未定义；无灾难恢复测试记录 |

---

## 保密性（C1）

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| C1.1 | 保密信息被识别和保护 | 无数据分类；无数据清单 |
| C1.2 | 保密信息被适当处置 | 无数据保留/处置政策；无销毁证明 |

---

## 处理完整性（PI1）

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| PI1.1 | 处理完整、有效、准确、及时、经授权 | 无输入/输出验证；无对账控制 |
| PI1.2 | 系统输入经授权 | 无授权检查；无职责分离 |
| PI1.3 | 系统输出完整准确 | 无输出验证或对账 |
| PI1.4 | 处理错误被检测和纠正 | 无错误处理或告警；错误被静默丢弃 |
| PI1.5 | 存储项受保护 | 无完整性监控；无校验和 |

---

## 隐私（P1–P8）

| 标准 | 审计师关注点 | 常见差距 |
|---|---|---|
| P1 | 向个人提供隐私通知 | 无隐私通知；通知与实际做法不符 |
| P2 | 获得选择和同意 | 无同意机制；退出选择未被尊重 |
| P3 | 仅按声明收集个人信息 | 收集的数据多于披露范围；无数据最小化 |
| P4 | 仅按声明使用个人信息 | 将 PII 用于未披露的目的 |
| P5 | 个人信息按政策保留和处置 | 无保留时间表；PII 无限期保留 |
| P6 | 个人信息仅按授权披露 | 无数据共享协议；第三方未授权访问 |
| P7 | 个人信息质量得到维护 | 无更新/纠正不准确数据的流程 |
| P8 | 隐私投诉和询问得到处理 | 无 DSR（数据主体请求）流程；无隐私联系人 |

## 控制声明模板

```
控制 ID：    [TSC 标准-序号，如 CC6.1-002]
TSC 标准：   [如 CC6.1——逻辑访问安全措施]
控制标题：   [简短描述性名称]
控制类型：   [预防性 | 侦测性 | 纠正性]
控制负责人： [角色/团队]
频率：       [持续 | 每日 | 每周 | 每月 | 每季度 | 每年 | 事件驱动]
描述：       [该控制做什么、由谁执行、如何运作以及覆盖哪些
             系统/流程。2-5 句。]
证据：       [该控制产生的证明其运作的工件：日志、报告、工单、
             签署记录、截图、导出文件。]
测试程序：   [审计师将如何测试：样本量、数据来源、通过/失败标准。
             匹配类型 1（设计）与类型 2（运行）。]
相关政策：   [哪项政策管辖此控制]
关联风险：   [此控制缓解风险登记册中的哪些风险]
```
