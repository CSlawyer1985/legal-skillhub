# SOC 2 合规技能

## 1. 本技能做什么？

本技能将 Claude 变成 SOC 2 合规专家顾问。它在 SOC 2 业务的完整生命周期提供深入、结构化的指引——从初始就绪评估，到政策撰写、控制文档、审计证据准备和第三方供应商风险管理。

技能以 **AICPA 2017 信托服务标准（TSC），含 2022 年修订的重点关注点**为根基——这是 SOC 2 审计的权威标准。它涵盖全部五项信托服务标准：

| 标准                   | 代码    | 状态          |
| -------------------------- | ------- | --------------- |
| 安全（共同标准） | CC1–CC9 | 始终要求 |
| 可用性               | A1      | 可选        |
| 保密性            | C1      | 可选        |
| 处理完整性       | PI1     | 可选        |
| 隐私                    | P1–P8   | 可选        |

技能不提供泛化合规建议，而是将每个请求路由至专门知识领域——产出标准特定的差距评估、审计员可直接使用的控制陈述、含强制条款的政策草稿、证据清单和供应商问卷——全部使用精确的 AICPA 语言和标准代码。

---

## 2. 目标受众

技能旨在服务任何参与 SOC 2 计划的人，并自动根据背景调整语气和深度：

**首次经历 SOC 2 的初创企业和中小企业**
无先前合规经验的团队，需要概念解释、模板提供和关于从哪里开始的通俗语言指引。

**成熟组织的安全和合规团队**
希望快速推进的从业者——直接跳转到差距矩阵、标准特定控制陈述、证据目录和审计就绪文档，无需手把手指导。

**审计师和顾问**
需要精确 AICPA 标准语言、控制测试程序、抽样指引和可直接用于客户工作的结构化输出的专业人士。

**工程和 DevOps 团队**
需要了解其系统需要哪些控制（访问管理、变更控制、日志、补丁）以及需要产出什么证据的开发人员和基础设施工程师。

**法务和采购团队**
处理供应商合同、数据处理协议和第三方风险的人员，需要问卷模板、CUEC 跟踪和合同要求指引。

## 3. 常见用例

### 差距分析与就绪评估

- 正式审计前对照所有范围内 TSC 标准进行自我评估
- 识别 🔴 差距、🟡 部分控制和 🟢 已达标标准，并附补救优先级
- 构建带责任人、时间线和证据要求的补救路线图
- 界定 SOC 2 报告范围（Type 1 vs Type 2、纳入哪些 TSC、系统边界）

### 政策与程序撰写

- 起草 12 项核心 SOC 2 政策中的任何一项（信息安全、访问控制、事件响应、变更管理、风险评估、供应商管理、BCP/DR、数据分类、可接受使用、隐私通知、加密、漏洞管理）
- 审查既有政策是否缺少强制条款、措辞薄弱（“should” vs “must”）或缺少 TSC 映射
- 撰写年度政策审查文档

### 控制文档

- 以标准格式记录控制：控制 ID、TSC 标准、类型、负责人、频率、描述、证据和测试程序
- 构建映射到范围内 TSC 标准的完整控制矩阵
- 将现有实践转化为审计员可测试的控制陈述
- 识别预防性、检测性和纠正性控制覆盖之间的差距

### 审计证据准备

- 为每个范围内标准生成完整证据清单
- 了解哪些产物在 Type 1 与 Type 2 审计中证明控制
- 了解按控制频率的审计员抽样预期
- 组织镜像 TSC 结构的证据文件夹
- 在常见证据陷阱成为审计发现之前捕捉它们

### 供应商风险问卷

- 对供应商清单分层（关键 / 高 / 中 / 低），附适当的审查节奏
- 发送并评分 32 题供应商安全问卷
- 审查供应商的 SOC 2 报告——评估意见、例外和系统描述
- 从供应商 SOC 2 报告识别并跟踪互补用户实体控制（CUEC）
- 起草合同性安全要求（DPA、安全附录、违约通知 SLA）

## 4. 如何使用本技能

### 安装

1. 下载 `soc2.skill` 文件
2. 在 Claude 中进入 **设置 → 技能**
3. 上传 `.skill` 文件
4. 技能将在相关对话中自动激活

### 触发技能

当您的消息涉及 SOC 2 或相邻合规话题时，技能自动激活。您无需使用特定关键词——它按自然语言触发，例如：

- *“我们需要在 Q3 前完成 SOC 2，从哪里开始？”*
- *“能为我们撰写事件响应政策吗？”*
- *“CC6 访问控制需要什么证据？”*
- *“有客户要求我们填写他们的供应商安全问卷”*
- *“我们刚拿到 AWS 的 SOC 2 报告——如何审查它？”*
- *“为我们的变更管理流程起草一份控制陈述”*

### 示例提示

```
"为一家 30 人 SaaS 初创企业运行 SOC 2 差距分析。我们大多数系统有 MFA、
基本的事件响应流程，但没有正式政策，也没有供应商风险计划。"

"为一家使用 AWS、Okta、GitHub 和 Salesforce 的公司撰写访问控制政策。"

"为涵盖安全和可用性的 SOC 2 Type 2 审计，我需要收集什么证据？
我们使用 AWS，审计期为 12 个月。"

"这是我们目前的供应商清单。帮我按风险分层，并告诉我每个层级需要
什么尽职调查。"

"为我们的季度访问审查流程撰写一份映射到 CC6.5 的控制陈述。"
```

### 调整输出

技能根据您的背景自动调整：

- 提到您是 SOC 2 新手 → 通俗语言、更多解释、分步指引
- 在问题中使用 TSC 标准代码 → 详细技术输出、审计师风格语言
- 提到具体工具（如 Drata、Vanta、Secureframe）→ 将指引定制到该平台的证据格式

## 5. 技能实施细节

### 文件结构

```
soc2/
├── SKILL.md                    # 主技能——任务路由、TSC 参考、核心工作流
└── references/
    ├── controls.md             # 控制矩阵，含逐标准示例和测试程序
    ├── policies.md             # 全部 12 项政策的模板和写作标准
    ├── evidence.md             # 按标准的证据目录、抽样指南、质量清单
    └── vendor.md               # 供应商问卷、SOC 2 报告审查指南、CUEC 跟踪
```

**总规模：** 5 个文件约 1,276 行

### 架构

技能使用**渐进式披露模式**：

- 技能触发时始终加载 `SKILL.md`。它包含 TSC 速查、任务路由器表和五大用例的简明工作流说明。
- 四个 `references/` 文件在 Claude 需要深入时按需加载——例如，起草控制陈述时读取 `references/controls.md`，处理供应商风险问题时读取 `references/vendor.md`。

这使常驻上下文内容保持精简，同时在需要时可获取全面参考材料。

### 用于构建技能的资料

技能使用以下资料构建：

| 资料                                     | 描述                                                                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **AICPA 2017 TSC（2022 年重点关注点）** | 所有标准代码、定义和重点关注点的权威来源（CC1–CC9、A1、C1、PI1、P1–P8）                            |
| **SOC 2 审计方法论**               | 控制设计原则、Type 1 vs Type 2 区分、审计员测试程序和抽样预期                           |
| **真实世界差距模式**               | 源自公开就绪评估和审计公司指引的 CC1–CC9 最常被标记的差距                         |
| **政策写作标准**              | 安全政策最佳实践，含强制条款、语言标准（“must” vs “should”）和范围要求            |
| **证据最佳实践**               | 证据质量标准（同时性、可归因性、完整性）、常见陷阱和产物命名惯例                  |
| **供应商风险框架**                | CC9.2 供应商风险分层、CUEC 管理、SOC 2 报告审查方法论和合同性安全要求                     |
| **技能创建者框架**               | 使用带 YAML frontmatter、渐进式披露架构和参考文件分离的 Claude 技能创建者模式构建 |

### 设计决策

**贯穿始终的 TSC 标准代码** ——每项控制、政策、证据项和差距都标记其 AICPA 标准代码（如 CC6.3），使输出可直接用于审计文档而无需翻译。

**受众自适应输出** ——技能不采用单一响应风格，而是明确指示 Claude 检测用户的成熟度（初创 vs 从业者 vs 审计师）并相应调整语言、深度和格式。

**无规定性控制清单** ——与 AICPA 指引一致，技能不强求特定控制。它提供示例和模板，同时提醒用户控制必须根据其组织环境定制。

**参考文件间关注点分离** ——每个参考文件处理一个主要工作流，保持文件聚焦，每份约 280 行以内，便于清晰和快速加载。
