# NIST AI RMF——AI 风险概要、指标与跨框架映射

---

## AI 风险概要概念

**AI 风险概要**是组织对 AI RMF 的定制化应用，以反映：
- 其具体的 AI 用例和部署情境
- 适用的法律法规
- 其界定的风险容忍度
- 与其 AI 系统最相关的可信特性

AI RMF 界定了两种概要类型：

| 概要类型 | 说明 | 用途 |
|-------------|-------------|-----|
| **当前概要** | 组织目前所处状态——哪些类别已实施及实施程度 | 基线评估 |
| **目标概要** | 组织期望达到的状态——每个类别的期望水平 | 差距分析和路线图 |

当前概要和目标概要之间的差距驱动风险管理路线图。

### 如何构建 AI 风险概要

1. **范围**——界定哪些 AI 系统在范围内（所有 AI、特定高风险系统或单一系统）
2. **评估当前状态**——对19个类别逐一评级：未开始 (0) / 部分 (1) / 已实施 (2) / 已优化 (3)
3. **设定目标状态**——基于风险容忍度和监管要求界定每个类别的期望成熟度水平
4. **差距分析**——目标 > 当前的类别即为需要行动的差距
5. **排序**——按差距所代表的风险加权；先处理风险最高的差距
6. **路线图**——为缩小每项差距分配负责人、时间线和资源

## 可信 AI 特性——指标与指示器

### 1. 准确性与有效性
| 指标 | 说明 |
|--------|-------------|
| Precision / Recall / F1 | 分类准确性指标 |
| AUC-ROC | 判别性能 |
| Mean Absolute Error (MAE) | 回归性能 |
| Calibration Error | 预测概率与实际频率之间的一致性 |
| Out-of-distribution (OOD) performance | 在训练分布之外输入上的性能 |

### 2. 公平性与偏见管理
| 指标 | 说明 |
|--------|-------------|
| Demographic Parity | 各群体间正向预测率相等 |
| Equalized Odds | 各群体间真阳性率和假阳性率相等 |
| Counterfactual Fairness | 如敏感属性改变，结果是否会变化？ |
| Disparate Impact Ratio | 群体间正向结果率之比（≥0.8 为 EEOC“4/5规则”） |
| Disaggregated performance reporting | 按人口统计子群体细分的性能报告 |

### 3. 可解释性与可解释性
| 方法 | 说明 |
|--------|-------------|
| SHAP (SHapley Additive exPlanations) | 全局和局部特征归因 |
| LIME (Local Interpretable Model-agnostic Explanations) | 复杂模型的局部近似 |
| Counterfactual explanations | “需要改变什么才能产生不同结果？” |
| Model cards | 模型性能、预期用途和限制的标准摘要 |
| Saliency maps | 突出显示驱动图像模型决策的输入特征的视觉图 |

### 4. 稳健性与可靠性
| 指标 | 说明 |
|--------|-------------|
| Adversarial accuracy | 规避攻击下的性能（FGSM、PGD） |
| Poisoning resilience | 对训练数据操纵的抵抗能力 |
| Input perturbation sensitivity | 小幅输入变化下的性能稳定性 |
| Availability under load | 峰值条件下的系统正常运行时间和延迟 |
| Model drift detection | 对输入数据分布随时间的统计检验（PSI、KS 检验） |

### 5. 隐私
| 方法 | 说明 |
|----------|-------------|
| Differential Privacy (ε) | 数学隐私保证；ε 越低 = 隐私越强 |
| k-Anonymity | 训练数据中防止重新识别的最小群体规模 |
| Federated learning | 在不集中原始数据的去中心化数据上进行训练 |
| Membership inference attack resistance | 对推断某条记录是否在训练数据中的抵抗能力 |

### 6. 安全
| 威胁 | 说明 |
|--------|-------------|
| Evasion attacks | 为欺骗已部署模型而精心构造的对抗性输入 |
| Poisoning attacks | 注入以破坏模型行为的恶意训练数据 |
| Model extraction / inversion | 逆向工程模型或从输出中重建训练数据 |
| Prompt injection (LLMs) | 通过指令劫持模型行为的恶意输入 |

## 部门特定 AI 风险考量

| 部门 | 关键 AI 风险优先事项 | 相关法规 |
|--------|----------------------|---------------------|
| **医疗保健** | 安全（诊断错误）、跨患者群体的偏见、临床决策的可解释性 | HIPAA、FDA AI/ML 型 SaMD 指南、欧盟《AI 法案》（高风险：医疗器械） |
| **金融服务** | 信贷决策公平性、模型可解释性（不利行动通知）、欺诈检测准确性 | ECOA、《公平住房法》、CFPB 指南、欧盟《AI 法案》（高风险：信用评分） |
| **人力资源/招聘** | 招聘偏见、EEOC 差异性影响、筛选决定的可解释性 | EEOC、纽约市地方法144、欧盟《AI 法案》（高风险：雇佣） |
| **刑事司法** | 再犯预测偏见、正当程序、透明度 | 欧盟《AI 法案》（禁止：实时生物识别、社会评分） |
| **政府/公共部门** | 透明度、平等获取、公民权利合规 | 行政命令 13960、行政命令 14110、《AI 法案》（公共机构部署） |
| **教育** | 招生/评分中的偏见、学生隐私 | FERPA、COPPA、各州 AI 教育法律 |
| **自主系统** | 物理安全、容错、人工超越 | ISO 26262（汽车）、DO-178C（航空）、欧盟《AI 法案》（高风险） |

## 跨框架映射

### NIST AI RMF ↔ ISO/IEC 42001:2023

| AI RMF 功能/类别 | ISO 42001 对应 |
|--------------------------|---------------------|
| GOVERN 1（政策已建立） | 第5条（领导力）、第6条（规划）、A.2（AI 政策） |
| GOVERN 2（问责） | 第5.3条（角色和职责）、A.2.3 |
| GOVERN 3（角色） | 第5.3条、A.2.5（AI 系统影响的职责） |
| GOVERN 4（跨职能团队） | 第7.1条（资源）、A.2.5 |
| GOVERN 5（风险容忍度） | 第6.1条（风险和机遇）、A.5.2（AI 风险评估） |
| MAP 1（情境） | 第4条（组织情境）、A.3（内部/外部情境） |
| MAP 2（科学理解） | A.6（AI 系统生命周期） |
| MAP 3（利益相关者风险/收益） | 第4.2条（相关方）、A.8.4（影响评估） |
| MAP 5（可能性/影响） | A.5.2（AI 风险评估方法） |
| MEASURE 2（系统评估） | A.6.2（AI 系统设计）、A.10（AI 系统的使用） |
| MEASURE 3（持续监测） | 第9.1条（监测和测量）、A.6.2.5 |
| MANAGE 2（处理策略） | 第6.1.3条（AI 风险处理）、A.5.3 |
| MANAGE 3（事件响应） | A.9（绩效评估）、第10条（改进） |
| MANAGE 4（审查和改进） | 第10.2条（不符合）、第9.3条（管理评审） |

### NIST AI RMF ↔ 欧盟《AI 法案》（条例 (EU) 2024/1689）

| AI RMF 功能 | 欧盟《AI 法案》要求 |
|----------------|----------------------|
| GOVERN 1（AI 风险政策） | 高风险 AI 的第9条（风险管理系统） |
| GOVERN 2/3（问责） | 第16条（高风险 AI 提供者的义务）、第26条（部署者义务） |
| MAP 1（预期用途） | 第9(2)条——风险管理必须涵盖预期用途和合理可预见的滥用 |
| MAP 3（利益相关者映射） | 第9(2)(b)条——识别和分析已知及可预见风险 |
| MEASURE 2（系统评估） | 第10条（数据治理）、第15条（准确性、稳健性、网络安全） |
| MEASURE 3（持续监测） | 第72条（上市后监测）、第26(5)条——部署者监测义务 |
| MANAGE 3（事件响应） | 第73条（向市场监督机关报告严重事件） |
| 所有功能 | 附件 IX（高风险 AI 系统的技术文档要求） |

**关键差异：** 欧盟《AI 法案》对范围内的提供者和部署者具有强制性；NIST AI RMF 是自愿性的。受欧盟《AI 法案》约束的组织应使用 NIST AI RMF 作为满足第9条“适当的风险管理系统”要求的风险管理方法。

### NIST AI RMF ↔ NIST CSF 2.0

| AI RMF 功能 | NIST CSF 2.0 功能 |
|----------------|----------------------|
| GOVERN | GV（治理）——直接类似 |
| MAP | ID（识别）——风险识别 |
| MEASURE | DE（检测）+ ID（识别） |
| MANAGE | RS（响应）+ RC（恢复）+ PR（保护） |

**关系：** NIST CSF 2.0 广泛涵盖网络安全风险；NIST AI RMF 将此扩展至 AI 特定风险，包括偏见、公平性、可解释性和社会危害——这些超出 CSF 的范围。组织应同时实施两者：CSF 用于网络安全风险，AI RMF 用于 AI 特定风险。

## AI RMF 实施层级

与 NIST CSF 实施层级类似，AI RMF 描述四种组织成熟度水平：

| 层级 | 名称 | 说明 |
|------|------|-------------|
| 1 | **部分** | 临时性 AI 风险实践；认知有限；对 AI 事件被动反应 |
| 2 | **风险知情** | 已批准 AI 风险政策存在；实践未全组织推广；管理层有认知 |
| 3 | **可重复** | AI 风险管理正式成文、一致适用、定期审查 |
| 4 | **自适应** | 组织从 AI 风险经验中学习；主动更新实践；为部门知识作贡献 |

大多数组织从第1-2级起步。受监管情境以第3级为目标；AI 密集型行业以第4级为目标。

## 常见差距模式与整改优先级

| 差距模式 | 可能原因 | 建议行动 |
|-------------|-------------|-------------------|
| GOVERN 完整但 MAP/MEASURE 薄弱 | 政策已制定但未落地实施 | 使用 MAP 对每套已部署 AI 系统开展系统级 AI 风险评估 |
| MAP 已做但 MEASURE 缺失 | 风险已识别但未计量 | 为已部署模型配备监测；为每项已识别风险定义指标 |
| MEASURE 存在但无 MANAGE 行动 | 计量未连接至处理 | 建立计量到行动的规程；为登记簿条目分配风险负责人 |
| 各业务单元不一致 | 无集中式 AI 风险计划 | 建立带跨业务单元工作组的中央 AI 治理职能 |
| 技术控制强、社会风险视角弱 | 工程主导的计划 | 在 MAP 3 和 MEASURE 2 中增加法律、伦理和受影响社区视角 |
| 无生命周期覆盖 | 仅关注部署阶段 | 将 AI RMF 覆盖扩展至设计、开发和退役阶段 |
