# 法律数据库四引擎检索与分析 Skill v3.5

## 一、功能定位

**两大核心能力**：🔍 **法律检索** + 📊 **分析报告**

**v3.5 核心升级**：案号强制准入（无案号=虚假，禁止使用）+ 全渠道28渠道可靠性统一排序

### 0.0 案号强制准入规则（v3.5 新增 🚨 最高优先级）

> ⚠️ **铁律**：凡检索到的案例**无法提取完整案号**（格式：`(YYYY)XX…字第…号` 或 `入库编号202X-XX-X-XXX-XXX`），**一律视为虚假案例**，按以下规则处理：

| 情形 | 案号状态 | 处置 | 说明 |
|------|:---:|------|------|
| **完整案号** | ✅ 可提取 | ✅ 允许进入报告 | 例：`(2024)皖1702刑初229号`、`入库编号2023-05-1-300-010` |
| **仅部分案号** | ⚠️ 不完整 | ❌ 禁止使用 | 仅有"皖1702刑初"而无年份和完整编号 |
| **完全无案号** | ❌ 缺失 | ❌ 废弃 | 新闻转载、个人博客中无案号的案例描述 |
| **疑似虚构案号** | ❓ 无法验证 | ❌ 废弃 | 案号格式不符规范、无法通过搜索引擎交叉验证 |

**执行规则**：

1. **检索阶段**：每个检索到的案例，必须优先提取案号；若无法提取，直接丢弃，**不计入结果数**。
2. **报告阶段**：类案信息总表中，"案号"列为**必填列**（不可为"未披露""不详"等占位符）。案号缺失的案例不得出现在任何表格、分析、论点中。
3. **论证阶段**：对被告有利/不利的论点，**必须以完整案号为支撑**。无案号支撑的论点视为无效，不得列入报告第五部分。
4. **交叉验证**：提取到的案号须通过搜索引擎以引号精确搜索（`"{案号}"`）快速验证，确认至少 1 个独立来源可匹配同一案件。
5. **两高典型案例例外**：最高法/最高检官方发布的典型案例（通过 court.gov.cn / spp.gov.cn WebFetch 直接抓取），即使官方未公布完整案号，也可使用。但须标注"两高典型案例·案号待核实"并在数据来源中注明官方发布页 URL。

> **法理依据**：《最高人民法院关于统一法律适用加强类案检索的指导意见（试行）》第8条明确规定，类案检索报告应载明"案号"。案号是裁判文书的唯一法定标识，无案号的案例无法在裁判文书网验证，不具有类案参照价值。

### 0.2 多渠道并行 + 双源交叉验证规则

> ⚠️ **强制规则**：每项关键信息的检索，必须从至少 **2个不同可靠性等级的数据源** 获取并交叉验证。

| 关键信息 | 渠道一（主） | 渠道二（验证） | 不一致时 |
|---------|------------|------------|---------|
| **案号** | WebSearch 通用检索 | stealth-browser wenshu.gov.cn | 以官方原文为准 |
| **法条编号** | site:court.gov.cn | site:npc.gov.cn | 以npc.gov.cn(人大网)为准 |
| **法院名称** | WebSearch | WebFetch 案例详情页 | 以WebFetch详情页为准 |
| **裁判日期** | WebSearch | WebFetch 案例详情页 | 以WebFetch详情页为准 |
| **法规全称+文号** | site:court.gov.cn | site:npc.gov.cn / stealth flk.npc.gov.cn | 以官方数据库为准 |

> **关键发现**：URL模式精确匹配比 `site:` 搜索命中率高 **10倍以上**。

### A.1.1 为什么 URL模式精确匹配 更有效？

搜索引擎对 `.gov.cn` 站点的索引策略不同：
- `site:flk.npc.gov.cn` — JS渲染页面，搜索引擎**几乎不收录** → 0-1条结果
- `"spp.gov.cn/xwfbh"` — 搜索引擎收录了大量**引用该URL的页面**（如新闻转载），通过这些页面可间接定位到原文

**执行原则**：优先使用 🥇 级语法，失败后降级到 🥈，再失败降级到 🥉。

## D.2 限制与免责

1. **案号强制准入（v3.5新增）**：无完整案号的案例不得用于报告和展示。本规则可能导致检索结果数量减少，但提高了数据可靠性。
2. **裁判文书网访问限制**：对自动化访问严格限制，L2 WebSearch 命中率 <5%
3. **flk.npc.gov.cn JS 渲染**：通过 npc.gov.cn 和 court.gov.cn 替代检索
4. **数据完整性**：裁判文书网近期存在文书下架，部分历史文书不可检索
5. **非法律意见**：本 Skill 提供法律信息检索服务，不构成法律意见
6. **核实义务**：第三方平台的裁判文书和法规，建议通过官方渠道核实
7. **隐私保护**：检索时避免输入当事人真实姓名、身份证号等敏感信息
8. **最高法网站分页**：典型案例列表共21页407篇，单次 WebFetch 仅返回当前页20条

### D.3.2 案号验证流程

```
检索到案例 → 尝试提取案号
  ├── ✅ 完整案号 → 交叉验证（搜索引擎 "{案号}"）→ 通过 → 进入报告
  │                                         └── 失败 → 标注"⚠️案号待核实"→ 律师二次审查后决定
  ├── ⚠️ 部分案号 → 尝试通过其他渠道补全 → 补全成功 → 按完整案号流程
  │                                       └── 补全失败 → ❌ 废弃
  └── ❌ 无案号 → 直接废弃
```

### D.3.3 两高典型案例豁免说明

最高法/最高检官方发布的典型案例，有时官方页面未公布完整案号。对此类案例适用以下特殊规则：
- ✅ **允许使用**：但仍需在案号列标注"两高典型案例·官方页未公布案号"
- ✅ **可作为论据**：因具有最高级别的参照效力
- ⚠️ **不能替代裁判文书检索**：仍需检索有完整案号的普通裁判文书类案
- ⚠️ **数量限制**：报告中两高典型案例占比不得超过类案总数的 30%
