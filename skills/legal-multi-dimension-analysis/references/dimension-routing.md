# 维度路由表（Dimension Routing）

本文件供 Step 1 使用。目标是**精准识别本案应覆盖的法律维度**，避免无差别全开维度导致分析冗杂。

## 一、六维定义与典型触发词

| 维度 | 定义 | 典型触发关键词 |
|------|------|----------------|
| 民事维度 | 平等主体间的财产/人身关系纠纷 | 合同、违约、侵权、物权、公司决议、婚姻、继承、借贷、买卖 |
| 刑事维度 | 触犯刑法、应受刑罚的行为 | 犯罪、诈骗、侵占、职务侵占、挪用、贪污、故意伤害、盗窃、非法经营 |
| 行政维度 | 行政主体与相对人间的管理关系 | 行政处罚、行政许可、行政强制、行政复议、行政诉讼、违法建设、税务处罚 |
| 程序维度 | 纠纷解决的流程与救济路径 | 管辖、保全、执行、先予执行、民刑交叉、行刑衔接、附带民事诉讼、时效 |
| 经侦维度 | 经济犯罪侦查管辖的刑事线索 | 虚开、骗税、非法集资、集资诈骗、贷款诈骗、骗取贷款、违法发放贷款、洗钱、合同诈骗、传销、内幕交易、侵犯商业秘密 |
| 律师实务维度 | 代理策略与文书作业 | 诉略、举证、质证、抗辩、管辖异议、上诉状、代理词、法律意见书 |

## 二、路由规则（命中即启用对应维度）

1. **刑民交叉自动路由**：案由为民事（如合同违约、借贷纠纷），但事实出现"虚构事实/隐瞒真相""非法占有目的""明显不对价交易"等线索 → 同时启用【民事维度 + 刑事维度 + 程序维度（民刑交叉）】。
2. **行刑衔接自动路由**：案由为行政违法，但行为性质可能达到刑事立案标准（如偷税数额、环境污染后果、食品有毒有害）→ 同时启用【行政维度 + 刑事维度 + 程序维度（行刑衔接）】。
3. **经侦强制路由**：关键词命中经济犯罪管辖罪名清单 → 启用【经侦维度】，并在综合结论中体现"立案标尺 + 侦查方向 + 证据指引"，不得仅以民事/行政路径作答。
4. **综合题联动路由**：题干出现≥2 个法律部门交叉（如"合同×公司×担保""行政处罚×刑事追责"）→ 启用全部相关维度，并在 Step 4 做法律关系图谱。
5. **律师实务伴生路由**：用户身份为当事人/代理人、要求"怎么办/怎么诉/怎么辩" → 伴生启用【律师实务维度】。

## 三、维度路由表输出格式

```
维度路由表
| 启用维度 | 启用理由 | 关键触发词 |
|---------|---------|-----------|
| 民事维度 | 存在买卖合同关系与违约事实 | 合同、迟延交货 |
| 刑事维度 | 卖方可能虚构履约能力 | 虚构、非法占有目的 |
| 程序维度（民刑交叉） | 刑事事实影响民事违约认定 | 先刑后民 |
```

## 四、防错要点

- 禁止默认全开六维——只启用与案情要素相关的维度，降低噪声。
- 经侦维度一旦命中，必须在最终结论中落地"立案标尺/侦查方向"，不得悬空。
- 路由结果须回显给用户确认；用户可手动增删维度。
