# W3 并行写作

> 本文件定义工作流第三阶段：大纲冻结后的正文写作执行。
> W3 是"写作蓝图 → 正文"的执行阶段。大纲冻结后不可再调整结构。
>
> **核心纪律：结论从涵摄中自然产生。** Gate2 冻结的大纲仅提供审查路线图（结构+争议标记+待审问题），不包含任何实体结论。W3 的每一个涵摄单元必须从 **[总起]** 假设句出发，经过 **[定义]** → **[归入]** 后，在 **[结论]** 中**首次**得出审查结果。禁止将 Gate2 大纲中的审查方向当作预设结论进行反向论证。W4 核验阶段会比对 Gate2 大纲是否包含结论——若包含，标记 `[W4-大纲含结论]` 并回退 W2 修正。
>
> **法条锚定单点源铁律**：W3 写作过程中所有法条引用一律通过 `SKILL.md §6.5 法条锚定表` 的语义名称映射后再展示具体条文；本文件正文使用语义名称，禁止出现具体条号。报告 blockquote 中的法条全文展示规则参见 `methodology/gutachten-writing-rules.md §三` 与 `format/format-and-template.md §五`。

## 一、子 agent 切分策略

拆分维度优先级：诉讼请求项 > 行政行为单元 > 要件类别。每子 agent 覆盖不超过 5 个文件 / 1000 行。主线程保留：可受理性 8 闸门 + 全案结论 + 一致性校验。

**典型拆分**：

- 单诉讼类型：主线程（可受理性+结论）+ 子 agent 1-3（主体+程序 / 事实+法律适用 / 裁量+结果）
- 多诉讼类型：主线程 + 按诉讼类型各分配一个子 agent

**子 agent 切分映射**：W2 大纲中的诉讼请求项（R1/R2/R3…）按"一诉一 agent"原则分配；同一诉请下的行政行为单元次序内嵌于该 agent；备位请求（subsidiary）与主请求绑定同一 agent，避免跨 agent 引用造成的结论链断裂。

**轻量模式分支**（W1 §五触发条件全部满足时）：跳过子 agent 切分，主线程单 agent 走完 W3 全流程；字数上限 5000 字（与 W1 §五一致）；争议级别仅保留 ⭐ 与无标记两级（取消 🔍 中间档）；下文 §四字数弹性预算表与 §六门禁清单中的相应项按本分支裁剪。

## 二、校验尾标四选一

> **唯一真相源**：以 `format/format-and-template.md` §五 为准。

每条法条引用须附校验尾标（四选一）：

| 尾标 | 含义 |
|------|------|
| `[已校验]` | MCP 形式 + 实质关联性双层通过且时间锚定正确 |
| `[⚠️ 降级校验]` | MCP 不可达或部分降级，改用本地知识库/经验校验（含历史版本时附 `refer_date=YYYY-MM-DD`） |
| `[⚠️ 未经校验]` | 校验路径全部失败，引用仅供参考 |
| `[⚠️ 拟引未校]` | 起草阶段占位，最终交付前必须替换为前三档之一 |

W4 核验阶段须扫描全文，确保不残留 `[⚠️ 拟引未校]`；对 `[⚠️ 降级校验]` 与 `[⚠️ 未经校验]` 的引用须在核验报告中显式列出。

## 三、法条引用 MCP 核验流程

首次引用某法条时触发 MCP 校验（`${LEGAL_SEARCH.get_article}` 或 `${LEGAL_SEARCH.search_article}`），校验三要素：法条名称 + 条号 + 现行有效性（refer_date = 行政行为作出日期）。校验通过写入 verification-log.md 并缓存；后续同一法条复用缓存。MCP 不可用时按降级链调用备用源。

## 四、字数弹性预算

| 诉讼类型数 | 预算模式 | 调整规则 |
|-----------|---------|---------|
| 1 类型 | 标准预算 | 各要件按争议级别分配 |
| 2 类型 | 标准预算 | 各类型独立预算 |
| 3+ 类型 | 压缩模式 | 每新增类型减 15%，优先压缩"明显"项 |

压缩顺序：明显项（50-100 → 30-60）→ 🔍合理争议项（200-400 → 150-300）→ ⭐核心争议项不压缩。

## 五、写作纪律引用

W3 写作过程中须严格遵循以下方法论文件：

- **涵摄四步法**：总起句 → 定义 → 归入 → 结论，参见 `methodology/gutachten-writing-rules.md`
- **论证深度**：按三层分级控制，参见 `methodology/proportionality-and-discretion.md`
- **法律解释**：适用法律解释方法论工具箱，参见 `methodology/interpretation-toolkit.md`
- **比例原则与裁量审查**：四阶段展开 + 三类裁量瑕疵，参见 `methodology/proportionality-and-discretion.md`
- **概念纪律**：不确定法律概念全文一致，参见 `methodology/legality-examination-engine/framework.md` § 四
- **场景套色（写作语气）**：按 `.user-config.md` 的 `scenario` 字段执行写作语气分支（依据 [`../methodology/case-router.md`](../methodology/case-router.md) §3.1 矩阵）：
  - `academic`：纯第三人称评议，价值中立；称谓使用"原告/被告/第三人"等程序称谓；不附加策略性后缀。
  - `litigation`：攻防式语气（站位由 W1 当事人身份决定）；攻击面动词"质疑/抗辩/可主张"，防守面动词"可释明/可补强/可申请举证"；**不预设胜诉**；每个 ⭐ 要素结论段末尾追加一句 `**[诉讼策略提示]** ……`，用作 W4 风险清单素材。
  - `pre-enforcement`：克制中性语气，称谓改为"本机关/拟作出行为/相对人"；以"是否充分""是否留痕""是否可耐受司法审查"自问；每个 ⭐ 要素结论段末尾追加一句 `**[自查整改提示]** ……`，用作 W4 合法性体检清单素材。

## 六、W3 门禁（一致性校验 + 字数控制）

- [ ] 所有子 agent 任务完成
- [ ] 一致性校验通过（结论链无断裂、学说未漂移、法条版本统一）
- [ ] 字数总和与预算偏差 ≤10%
- [ ] 缺陷分级与判决类型对应
- [ ] 来源标识符无遗漏（[评注] [案例] [联网] [KB:]）
- [ ] 场景套色已落地：`litigation` 场景每个 ⭐ 要素含 `**[诉讼策略提示]**`；`pre-enforcement` 场景每个 ⭐ 要素含 `**[自查整改提示]**`；`academic` 场景无此后缀

通过后方可进入 W4。
