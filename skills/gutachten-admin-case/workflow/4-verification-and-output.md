# W4 三维核验与输出

> 本文件定义工作流第四阶段：对 W3 产出的鉴定论证文本进行三维核验，执行一次性修订，经用户预审后生成终稿并保存全部副产物。

---

## 一、触发条件

- W3 全部写作单元状态为 `✓ 完成`
- 若存在 `✗ 阻断` 单元 → 不得进入 W4，需先解决

---

## 二、核验维度（D1–D3 必做，D4 场景专属）

**轻量模式分支**（W1 §五触发条件全部满足时）：W4 简化为"D1 法条校验（必做）+ D2/D3 简版扫描（合并执行） + D4 仅 litigation/pre-enforcement 场景启用"。D2 仅检查⭐核心争议要素是否展开（无标记项免检），D3 仅扫描格式清单 1-5 项（6-10 项免检）。其余流程不变。

### D1：增量法条核验

**目的**：确保所有法条引用均已通过法律检索 MCP 校验、时效为现行有效。

**执行步骤**：

1. 扫描 W3 产出全文，提取所有法条引用（含具体条号 + 司法解释 doc_no）
2. 对每一条法条引用执行法律检索 MCP 终末复核（`${LEGAL_SEARCH.get_article}`），判定规则：
   - 返回 `${timeliness_field}` 等于 `${timeliness_active_value}` 且条文一致 → `[D1-✓]`
   - 返回条文差异 → `[D1-修订]`，用服务商返回原文替换
   - 返回时效不合或条号不存在 → `[D1-硬错]`，整条引用必须删除或替换
3. 比对 `verification-log.md`：已有记录且通过 → 标记 `[D1-✓]`（可省略复核）；无记录 → 新增校验，写入日志
4. **反向覆盖率核查（仅限通用流程支撑条款）**：读取 SKILL.md §6.5 法条锚定表（A 行诉法 / B 行诉解释 / C 行政处罚法 / D 行政复议法 / E 立法法 / F 行政强制法 / G 行政许可法 / H 政府信息公开条例 / I 房屋征收补偿条例 / J 工伤+国赔+保护规范），筛选与本案诉讼类型及行政行为实质类型相关的语义名称行，逐行检查报告正文是否至少引用一次对应条款。扫描器识别方括号风格占位符 `\[[^\[\]]+条款\]`。未命中的条款标记 `[D1-反向缺失]`，附注"报告未引用此条款，请确认是否属于本案不涉及情形"。**说明**：§6.5 A–J 十组已覆盖 9 类高频行政行为的核心法源，反向覆盖率核查即以本表为唯一权威源。

**L2 降级模式**：D1 维度自动跳过，报告标注 `[D1 因 L2 降级跳过]`。

### D2：大纲覆盖与事实保真

**目的**：确保大纲每一要素均已展开，且论证中的事实引用忠实于 W1 原始提取。

1. **大纲覆盖检查**：逐项比对 W2b 确认大纲与 W3 正文，核心争议要素 ≥500 字，非争议要素 100-200 字
2. **事实保真检查**：提取 W3 正文中所有事实陈述，逐条比对 W1 事实笔记，标记 `[忠实]` / `[偏离]` / `[新增]`

### D3：格式扫描

**目的**：确保终稿符合 `../format/format-and-template.md` 的全部格式要求，并遵循 `../methodology/gutachten-writing-rules.md` 的鉴定式写作风格规范。

逐项检查格式清单：

| # | 检查项 | 标准 |
|---|--------|------|
| 1 | 标题层级对应 | 九级标题与大纲一致 |
| 2 | 双层结构外壳完整 | 可受理性 H2 + 可证立性 H2 + 全案结论 H2 |
| 3 | 涵摄段落格式 | 每个涵摄单元含 `**[总起]**` `**[定义]**` `**[归入]**` `**[结论]**` 四标记（正则 `^\*\*\[(总起\|定义\|归入\|结论)\]\*\*`），缺失即标 `[D3-涵摄不完整]` |
| 4 | 法条引用格式 | Blockquote + 校验尾标 |
| 5 | 脚注格式 | 分类标注 |
| 6 | 术语一致性 | 全文统一 |
| 7 | 交叉引用格式 | 规范引用 |
| 8 | 缺陷分级位置 | 可证立性末尾 |
| 9 | 来源标注一致 | [评注] [案例] [联网] [KB:] 四标识符统一 |
| 10 | 字数 | 全文 ≤ 30000 字（含目录） |
| 11 | 法条全文展示（SKILL §5.2-6） | 首次引用法条 blockquote 全文，后续可简写 |
| 12 | 客观第三人称（SKILL §5.2-7） | 全文使用"原告/被告/第三人"等程序称谓，无"我方/对方/本方" |

### D4：反向错误清单扫描

**适用范围**：仅 `scenario=litigation` 与 `scenario=pre-enforcement` 启用；`scenario=academic` 默认跳过（学术研习不以避错为目标）。

**目的**：以"已知错误清单"反向比对报告各要素的分析结论，避免常见违法形态被遗漏，并向用户呈现独立的复核视角。

**执行步骤**：扫描可证立性层各要素的分析段落，按下表逐条比对，命中即生成相应警示标签写入 `report-D4-reverse-scan.md`，**不阻断 W4 输出**——D4 是复核辅助工具，最终是否修订由 §三 P4 决定。

| 要素 | 反面清单 | 警示标签 |
|------|---------|---------|
| 主体职权 | 部门越权 / 层级越权 / 地域越权 / 事项越权；5 种授权形式（法定职权/法律授权/法规授权/委托/相对集中行政处罚权）校验 | `[D4-越权]` |
| 程序 | 颠倒顺序 3 典型（先处罚后调查 / 先决定后告知 / 先执行后听证）；方式 / 步骤 / 顺序 / 时限 / 回避 / 监督 6 维 | `[D4-程序]` |
| 事实证据 | 主要证据不足 4 类（无证据 / 证据不充分 / 证据不合法 / 证据矛盾未排除）；证明标准三档（一般行政 / 限人身自由 / 行政赔偿）错配 | `[D4-证据]` |
| 法律适用 | 适用错误 5 类（应适用未适用 / 不应适用而适用 / 错误适用 / 援引规范性文件抵触上位法 / 法律版本错误） | `[D4-法适用]` |
| 裁量 | 滥用职权 4 表现（考虑不相关因素 / 遗漏相关因素 / 同案异罚无正当理由 / 报复性执法）；明显不当 4 维度（畸轻畸重 / 显失公平 / 违反比例原则 / 与立法目的相悖） | `[D4-裁量]` |
| 判决匹配 | [驳回诉讼请求条款] / [撤销判决要件条款] / [撤销并重作判决条款] / [履行判决条款] / [给付判决条款] / [确认违法判决条款] / [确认无效判决条款] / [行政赔偿/补偿判决条款] / [变更判决条款] 9 类边界混淆；典型错配（撤销 vs 确认违法 / 直接履行 vs 责令履职 + 重作 / 撤销 vs 变更 / 确认违法 vs 确认无效 / 驳回 vs 部分支持 / 给付 vs 行政赔偿补偿 / 撤销 vs 撤销并重作） | `[D4-判决错配]` |

**输出文件**：`reports/report-D4-reverse-scan.md`，结构为"要素 → 命中清单项 → 报告所在段落锚点 → 原文摘录 → 复核建议"。无命中亦应输出，写明"已扫描，全部要素未命中反向清单"。

**与 §三 修订的关系**：D4 命中项纳入 §三 P4 处理；不命中亦在终稿摘要中标注"D4 已完成"。

## 三、一次性修订

**修订原则**：单次通过，不循环。优先级排序：P1 → P2 → P3 → P4。

- **P1 法条准确性修订**：基于 D1 报告中的修订项，校验失败的法条删除或替换
- **P2 覆盖与保真修订**：基于 D2 报告，未覆盖节点补充展开，事实偏离修正为 W1 原始事实
- **P3 格式修订**：基于 D3 报告，逐项修正
- **P4 反向清单修订**（仅 litigation/pre-enforcement 场景）：基于 D4 报告命中项，逐项判断是否补充论证或调整结论——对论证遗漏作补充，对结论错配按 [D4-判决错配] 提示重新比对判决要件条款

**修订约束**：每个修订项仅处理一次。修订完成后不再返回核验（防止无限循环）。若某修订项无法完成，保留并标注，交由用户预审决定。

## 四、用户预审

向用户呈现：修订后草稿 + 四份核验报告（D1/D2/D3/D4，D4 仅 litigation/pre-enforcement 场景）+ 修订摘要。

用 AskUserQuestion 确认：

- "确认生成终稿" → 进入终稿输出
- "需要进一步修改" → 接收用户指示，执行定点修订（仅一轮）
- "退回重写" → 标记退回单元，返回 W3 对应写作单元重新执行

### 5.1 MD 优先输出流程

默认流程：**先落盘 Markdown 终稿 → 按格式偏好决定是否转 Word**。

1. **落盘 Markdown 终稿**：将修订后正文写入 `{工作目录}/report-final.md`（UTF-8，含 YAML frontmatter 记录 scenario/stance/降级级别/校验通过条数）。
2. **读取格式偏好**（优先级从高到低）：
   - 本案覆盖：`{工作目录}/_case_meta.md` 中 `report_format_override` 字段（由 W1 §零识别 `/format` 指令生成）
   - 全局默认：`.user-config.md` 中 `report_format_preference` 字段
3. **按偏好分支**：

   | 偏好取值 | W4 行为 |
   |----------|---------|
   | `md_only` | 仅落盘 MD，不询问、不转换。终稿摘要标注"仅 Markdown 输出" |
   | `md_and_docx` | 落盘 MD 后自动调用 cx-md2word 生成 `report-final.docx`，无需询问 |
   | `md_then_ask`（默认） | 落盘 MD 后向用户提问："Markdown 终稿已生成，是否转换为 Word (.docx)？"AskUserQuestion 两选项：`是，转换为 Word` / `否，仅保留 Markdown` |

4. **Word 转换命令**（触发时执行）：

```bash
cx-md2word --input report-final.md --output report-final.docx --preset legal
```

legal 预设：宋体、标题二号 22pt 居中、正文小四 12pt 首行缩进 2 字符、1.25 倍行距、页边距上下 2.54cm 左右 3.17cm、自动目录、H1-H9 映射 Heading 1-9。**verify_docx.py 后验**：检查字号、字体、段首缩进、行距、标题映射、目录跳转。不通过则 python-docx 后处理。

### 5.2 文件命名

```
[日期]-[案件简称]-鉴定式分析报告.[md|docx]
```

### 5.3 L2 降级模式终稿特殊处理

L2 模式下，终稿首页必须包含免责声明：

```
本报告在法律检索工具不可用的降级模式下生成。

使用前请自行通过权威渠道核实全部法条引用。
```

## 七、流程终结

终稿输出后：

1. 使用 `present_files` 工具向用户呈现终稿文件
2. 输出最终摘要（诉讼请求数 / 闸门通过数 / 六要素覆盖数 / 核心争议数 / 终稿格式 / 降级模式级别）
3. 提示后续可用操作：`/config` 修改配置 / `/format md|docx|ask` 单案覆盖 / 提交新案情 / 要求对特定部分深入展开
