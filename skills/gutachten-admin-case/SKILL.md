# 行政法鉴定式案例研习工作流

本 skill 将"双层结构（可受理性 + 可证立性）+ 诉讼请求类型识别 + 行政行为实质类型路由 + 鉴定式写作"四套方法论编排为统一的 W0→W4 工作流，以**六要素合法性审查骨架**作为可证立性层的内嵌子骨架。

裁判依据为中华人民共和国《行政诉讼法》（2017 修正）、《行政复议法》（2023 修订，2024-01-01 施行）、《最高人民法院关于适用〈中华人民共和国行政诉讼法〉的解释》（法释〔2018〕1 号，下简称"《行诉解释》"）及其他现行有效的部门行政法。方法论文本一律使用语义名称（如"撤销判决要件"），具体条文编号仅集中在 §6.5 "法条锚定表"与法条引用 blockquote 内。

## 一、技能定位

### 1.1 适用范围

**目标用户**：
- 法学院学生、行政法教师、行政法研究者、判例研读沙龙成员（学术研习场景）
- 律师、企业法务、复议机构办案人员、监察/审计人员（诉讼/复议实务参考场景）
- 行政执法机关办案人员、法制审核岗、合法性审查参谋人员（事前合法性自审场景）

**目标任务**：
- 学术研习：行政法课程作业、判例研读沙龙报告、行政法教学研究论文的个案分析底稿
- 诉讼实务参考：律师承接行政诉讼前的案件评估、企业法务的合规研判、复议机构办案的合法性逐项审查、监察/审计场景的依法行政检视
- 行政执法事前自审：行政机关在作出具体行政行为（处罚/强制/许可/征收/确认/给付/协议等）之前的合法性沙盘推演——预判可受理性出口、自查六要素、识别裁量空间与比例原则风险、检视所依据的规范性文件是否抵触上位法

**产出物**：双层结构完整报告（大纲 + 正文），覆盖"可受理性 8 闸门 + 可证立性（按诉讼类型展开）+ 全案结论"，严格遵循涵摄四步法。可证立性层在合法性审查环节调用六要素合法性审查骨架进行深度展开。规范性文件附带审查作为特殊之诉子类（详见 `suit-types/special-scenarios.md` §三 与 `methodology/interpretation-toolkit.md` 下位法抵触清单）自动纳入；在事前自审场景下，可独立作为"拟援引依据合法性体检"模块输出。

### 1.2 六要素合法性审查骨架的位置

六要素合法性审查骨架（语义对应《行政诉讼法》撤销判决要件条款，详见 §6.5）仅作为可证立性层的内嵌子骨架使用：

- **嵌入触发**：撤销之诉、确认违法之诉、确认无效之诉（重大且明显违法判定）、行政赔偿之诉（违法性前置审查）、多行政行为单元的并行审查
- **嵌入阶段**：W2b 大纲与 W3 写作阶段
- **使用文件**：`methodology/legality-examination-engine/framework.md`（六要素通用骨架 + 缺陷分级 + 判决类型决策树 + 概念纪律）
- **铁律**：使用本子骨架前必须完成可受理性 8 闸门筛查与诉讼请求类型识别，不得绕过

### 1.3 不适用场景

- 起诉状/答辩状等具体诉讼文书（请使用专门的行政诉讼文书 skill）
- 纯民商事或刑事案件（请使用 gutachten-civil-case / gutachten-criminal-case）
- 法官行政判决书的正式撰写、复议决定书的最终签发（本 skill 仅提供合法性逐项研判底稿，正式文书须人工把关）

## 二、工作流概览

```
用户案例输入
    │
    └── workflow/0-cold-start-interview.md（首次）
        → workflow/1-case-intake.md
```

### 3.4 双维度路由原则 + 场景/站位偏置层

| 维度 | 决定什么 | 典型分类 |
|------|---------|---------|
| **诉讼请求类型** | 可证立性审查的**程序骨架** | 撤销/履职/给付/确认/特殊（5 类） |
| **行政行为实质类型** | 合法性审查的**实体专属要点** | 处罚/强制/信息公开/征收/投诉举报/工伤/许可/协议/赔偿（9 类高频行政行为路由） |

两个维度正交：同一"撤销之诉"可能是"撤销行政处罚"也可能是"撤销强拆决定"，实体审查要点完全不同。详见 `methodology/case-router.md`。

**场景偏置层（W0 `scenario` 字段）**：在双维度之上叠加场景套色——`academic`（学术研习，无偏置）/ `litigation`（诉讼实务参考，⭐ 默认前推程序/证据/裁量/主体要素）/ `pre-enforcement`（事前合法性自审，⭐ 默认前推主体/程序前置/裁量基准内部一致性 + 规范性文件合法性体检独立 H3 节点）。偏置规则详见 `methodology/case-router.md §三`。

**站位偏置层（W2 `stance` 字段，仅 litigation 场景生效）**：代理人站位 `plaintiff` / `defendant` / `neutral`，影响 W3 写作语态、风险清单方向、W4 §五最终模板。识别问与正交叠加规则详见 `workflow/2-preselection-and-outline.md §1.4-bis`。

### 3.5 法律解释方法的运用

法律解释方法分三组：**六种通用解释方法**（文义/体系/历史/目的/合宪/判例）+ **比较法解释**（方法论参照，不构成实证法依据）+ **保护规范解释**（行政法专属，专用于闸门 4 原告资格判断）。三级素材优先级：注册知识库 > 法律检索 MCP + 联网搜索 > 自主解释路径（详见 `methodology/interpretation-toolkit.md` §一 与 §三）。

**素材可获取性约束**：W0 未注册外国法 / 区域法专项 KB 时比较法解释默认跳过；历史解释仅采信经 MCP 或联网检索取得的官方公开发布材料（立法说明 / 起草说明 / 官方释义 / 答记者问 / 新闻通稿），检索未命中时降级到其他解释方法。完整白名单与降级规则详见 `methodology/interpretation-toolkit.md` §1.7。

## 四、工作流阶段

```
W0 冷启动访谈 → MCP 能力槽 + 工具配置 + 知识库注册 + 报告格式 + 保存配置
       ↓ （首次运行，后续跳过）
W1 案件解析  → 中性事实笔记 + 设问逐字 + 行政行为单元划分 + 当事人识别
       ↓
   [路由器] 调用 methodology/case-router.md 做"行政行为实质类型"预识别
       ↓
W2 预选+大纲 → 双维度识别（诉讼请求类型 × 行政行为类型）+ 要件拆解 + 大纲成型
       ↓    （默认 Gate1 独立确认 → Gate2 独立确认；简单案件可合并为一次确认）
W3 并行写作  → ≥2 行政行为单元时多 subagent 并行；即时 MCP 校验；法律解释贯穿
       ↓
W4 三维核验  → 增量法条校验 + 大纲覆盖+事实忠实 + 格式扫描 → 一次性修订 → 输出
```

详见 `workflow/` 目录下各文件：`0-cold-start-interview.md` → `1-case-intake.md` → `2-preselection-and-outline.md` → `3-drafting.md` → `4-verification-and-output.md`。

### 4.1 阀门约束

W1 阶段只允许事实层——禁止条文号、合法性定性、争点预判、诉讼类型预设；W2 阶段是法律层的真正起点，条文号首次出现且须经 MCP 双层校验（法条级 + 现行有效性）。

### 4.2 阶段聚焦规则

| 阶段 | 焦点 | 暂时忽略 |
|------|------|---------|
| W1 | 事实抽取 + 设问逐字 + 行政行为单元划分 | 法条、定性、争点 |
| W2（Gate1） | 双维度路由 + 候选清单 | 涵摄展开、反对说 |
| W2（Gate2） | 要件拆解 + 大纲骨架 | 具体论证 |
| W3 | 涵摄四步法逐要件写作 | 格式、Word 输出 |
| W4 | 法条校验 + 覆盖率 + 事实忠实 + 格式 | 新增内容（仅修订） |

### 4.3 本案格式覆盖

用户在案情输入中夹带以下指令即触发本案一次性格式覆盖，不修改 `.user-config.md`：

| 指令 | 效果 |
|------|------|
| `/format md` | 本案仅输出 Markdown；W4 跳过 Word 询问 |
| `/format docx` | 本案强制双出（Markdown + Word），W4 直接调用 cx-md2word |
| `/format ask` | 本案 W4 结束后询问是否转 Word（默认行为） |

覆盖指令由 W1 首步识别并写入本案工作目录的 `_case_meta.md`，W4 输出阶段优先读取；未识别到指令时按 `.user-config.md` 缺省行为处理（详见 §七 §7.2）。

## 五、关键约束（三层）

### 5.1 铁律层（违反 = 报告失败）

1. **MCP 法条校验铁律**：报告中出现的每一条法规必须经 MCP 校验后方可写入正文。首次引用须完成双层校验（法条级 + 现行有效性），同一报告内重复引用同一条文免二次校验但须保留首次校验记录。MCP 不可用时降级为联网搜索 + 标注 `[⚠️ 降级校验]`。
2. **双闸确认规则（条件性）**：W2 阶段 Gate1（候选清单）与 Gate2（三层要件大纲）默认各自独立获得用户确认后方可进入下一阶段。**例外——简单案件快速通道**：当案件同时满足以下全部条件时，Gate1 与 Gate2 可合并为一次确认：① 单一诉讼请求（无备位请求）；② 单一行政行为单元；③ 无复议维持/共同被告情形；④ 8 闸门预判中无"不通过"项。
3. **事实-规范阀门约束**：W1 输出严格限于事实层（不含条文号、法律定性、争点预判）；W2 是法律层的真正起点。
4. **法条锚定单点源铁律**：方法论文件（methodology/、suit-types/、workflow/、format/）一律使用语义名称，具体条文编号仅出现在 §6.5 "法条锚定表"或法条引用 blockquote 内，且引用块须由 MCP 实时校验。

### 5.2 规范性规则层（标准合规，偏离须注释理由）

1. **涵摄四步法**：每个最小涵摄单元均按"总起句→定义→归入→结论"四步展开，不得跳步或合并。
2. **脚注自包含**：脚注必须完整可溯源（法律来源、裁判依据、学说出处），遵循"真实来源原则"。
3. **法律解释贯穿**：W2→W3 全程使用法律解释方法增强论证，不得仅在争点处才启用。
4. **格式真实来源**：`format/format-and-template.md` 为格式与模板的唯一真实来源。
5. **论证深度比例**：按 `methodology/proportionality-and-discretion.md §一` 三层分类（明显/争议/核心争点）分配论证篇幅。
6. **法条全文展示**：首次引用法条须展示完整条文，后续可简写。
7. **客观第三人称**：报告使用客观第三人称视角，不使用"我方""对方"。
8. **三维核验闭环**：W4 须完成法条增量校验 + 大纲覆盖率 + 事实忠实度三维核验。

### 5.3 弹性层（可通过注释调整）

1. **报告字数区间**：默认 ≤30,000 字，弹性预算可配置突破至 40,000 字；轻量模式可降至 5,000 字以下。
2. **反对说展开深度**：默认在核心争点处展开反对说，可配置为全面展开或最小化。
3. **排除请求权/审查要素表述**：未满足的要件可选择显性排除或省略。
4. **场景适配**：完整模式按全骨架展开；实务参考场景可在 W2 选择"轻量模式"，聚焦关键争点 + 结论先行。

### 6.2 降级策略

降级级别采用 **L0 / L1 / L2** 三档（与 W0 §三、W4 §二 D1 保持一致）：

| 资源 | L0 正常 | L1 部分降级 | L2 严重降级 |
|------|---------|------------|------------|
| 法律检索 MCP | 全绑定 `${LEGAL_SEARCH.*}` | 联网搜索 + `[⚠️ 降级校验]` | 自主解释 + `[⚠️ 未经校验]`；W4 D1 整维度跳过 |
| 用户知识库 | qmind retrieve | 本地 Read/Grep | 跳过（标注缺失） |
| 联网搜索 | Tavily/GoogleWebSearch | 内置 WebSearch | WebFetch |

降级级别由 W0 §三规则计算：法律检索 MCP 不可用 → L2；MCP 可用但无知识库 → L1；MCP + ≥1 知识库 → L0。L2 模式下报告首页必须添加免责声明。

### 6.3
