# 鉴定式写作纪律

> 本文件规定鉴定式行政法案例分析报告的写作风格细节，确保报告在句式、来源标注、法条引用等方面保持鉴定式严谨性。报告可用于学术研习或实务参考（律师案件分析底稿、法务合规研判、复议机构办案备忘），写作纪律对两种用途一并适用。

> **法条锚定单点源铁律**：本文档所有法条引用一律使用 `[语义名称]` 占位符，禁止出现具体条号。语义名称→现行编号的映射由 `SKILL.md §6.5 法条锚定表` 唯一维护。最终报告中的条文展示规则详见本文件 §三"法条引用规则"，但语义名称与现行编号的对应表始终是单点源。

---

## 一、涵摄四步纪律

每个最小涵摄单元必须让读者一眼识别"总起—定义—归入—结论"四步。总起句必须是假设句（"可能构成/可能不符合"），禁止直接断言。中间结论必须独立成段，使用确定性语言，与总起句形成"镜像"对应。

**结构化段落标记（W4 机械扫描锚点）**：

每个涵摄单元的四步须以下列粗体前缀开头，W4 D3 按正则 `^\*\*\[(总起|定义|归入|结论)\]\*\*` 逐段匹配，缺失任一步即标记 `[D3-涵摄不完整]`：

```
**[总起]** 〈假设句〉
**[定义]** 〈构成要件定义 + 来源〉
**[归入]** 〈案件事实涵摄至定义〉
**[结论]** 〈中间结论〉
```

> 注：标记为写作时内嵌标签，终稿输出时保留（可由 Word 模板映射为样式名/隐藏标记，不影响阅读排版）。

## 二、四种校验尾标

> **唯一真相源**：本节规则与 `format/format-and-template.md` §五 保持一致；如遇歧义，以 format-and-template.md §五为准。

每条法条引用块末尾必须标注且仅可标注以下四种之一：

| 尾标 | 含义 | 触发条件 |
|------|------|---------|
| `[已校验]` | MCP 形式 + 实质关联性双层通过且时间锚定正确 | 法条现行有效，行政行为发生时该法已生效未修订 |
| `[⚠️ 降级校验]` | MCP 不可达或部分功能降级，改用本地知识库/经验校验 | 检索后端故障、降级路径生效，已用 `refer_date` 取历史版本或本地比对 |
| `[⚠️ 未经校验]` | MCP 形式有效性失败/不可达且无降级路径 | 校验路径全部失败，引用仅供参考 |
| `[⚠️ 拟引未校]` | 写作时计划引用但尚未启动校验流程 | 起草阶段占位，最终交付前必须替换为前三档之一 |

**时间锚定**：行政行为发生在法律修订前 → 引用块必须用 `[⚠️ 降级校验]` 并注明 `refer_date=YYYY-MM-DD`，取行政行为作出时的历史版本。

**降级场景**（未配置 MCP）：全部法条引用统一标注 `[⚠️ 未经校验]`，并在 W4 核验阶段提示人工复核。

## 三、脚注引用四标识

| 标识符 | 来源类型 | 示例 |
|--------|---------|------|
| `[评注]` | 法律评注/教科书/释义 | `[评注] 行政诉讼法学释义类著作（年份/页码）：…` |
| `[案例]` | 指导性案例/公报案例 | `[案例] 最高法（年份）行申XXX号裁判要旨：…` |
| `[联网]` | 联网搜索 | `[联网] 法律法规官方文本/实务文章` |
| `[KB:]` | 用户注册的知识库 | `[KB:用户私有库] 知识库条目标题/章节定位：…` |

**铁律**：每个法律观点必须有出处；来源标识必须真实（禁止编造）；自助式解释不加脚注，在正文展开方法步骤；禁止 `[模型推理]` / `[此观点尚需查证]` 等占位脚注。

---

## 四、禁用语与推荐句式

| 禁用 | 替换 |
|------|------|
| "显然……" | "依……，可知……" |
| "我认为……" | "依[来源]……" |
| "毫无疑问……" | "依据现有事实……" |
| "笔者以为……" | "本报告认为……" |

## 五、学说争议显性化格式

涉及学派分歧时：

```
本议题在学说上存在分歧：
- 立场 A（[名称]）：[结论]，理由是 [核心论证]。
- 立场 B（[名称]）：[结论]，理由是 [核心论证]。
本报告采立场 [A/B]（依用户配置/默认立场），理由是：[选边理由]。
依此立场，本案应认定 [结论]。
```

"结论一致则不问理由"原则：当所有有代表性的学说立场对同一问题均得出相同结论时，无需展开学说争议，但应在脚注点明争议存在。

## 六、报告结构纪律

报告正文须严格遵循以下章节顺序：

```
封面 + 元数据
  ↓
目录
  ↓
（一）大纲（独立 H2，含全部计划检视的诉讼请求 + 闸门 + 要件树状图）
  ↓
（二）正文
  第一部分（多对当事人时启用）
    一、可受理性审查（必含 8 闸门）
    二、可证立性审查（依诉讼类型装配骨架）
    三、全案结论
```

**大纲 vs 正文的区别**：大纲为树状结构，列出所有计划检视的要件 + 争议标记，不展开论证；正文为完整鉴定式四步涵摄，按大纲展开。

## 七、篇幅分配指引

| 报告部分 | 建议占比 | 说明 |
|---------|---------|------|
| 行政行为单元划分 + 当事人列举 + 诉讼请求识别 | 5-10% | 前置铺垫 |
| 可受理性审查 | 15-25% | 核心争议闸门占 60-80% |
| 可证立性审查 | 55-70% | 核心争议要件占 50-70% |
| 判决类型预判与判决主文建议 | 5-10% | 结论导向 |
| 全案结论 | 3-5% | 汇总 |

总字数上限默认 30000 字（用户可在 `.user-config.md` 配置，可突破至 40000）。案情简单时可压缩至 8000-15000 字；可受理性单纯不通过案件压缩至 3000-6000 字。

## 八、报告纯净输出规则

### 8.1 内部工作流编号禁止出现在终稿

以下内部编号仅在工作流阶段（W1-W4）内部使用，**禁止出现在最终交付给用户的报告中**：

| 内部编号 | 含义 | 终稿中的替换 |
|---------|------|------------|
| `ACT-1`, `ACT-2`, … | 行政行为单元编号 | 使用"被告一""被告二"或自然表述 |
| `G1`, `G2`, … `G8` | 可受理性 8 闸门编号 | 使用中文标题（如"受案范围""原告适格"） |
| `R1`, `R2`, … | 诉讼请求编号 | 自然语言表述各项请求 |
| A 轨 / B 轨 / C 轨 | 审查程式轨道 | 删除或替换为范式名称（如"请求权审查四要件"），不展示轨道代号 |
| `act_id`, `R1_main`, `R2_subsidiary` | YAML 字段名 | 仅存在于中间文件，不进入终稿 |

### 8.2 自检清单

W4 核验阶段须扫描终稿，确认不包含以下模式：
- `ACT-\d`
- `/ G\d`（标题或正文中）
- `[AB]轨`
- `R\d`
- `act_id`

若检出，标记 `[W4-内部编号泄漏]` 并回退修正。
