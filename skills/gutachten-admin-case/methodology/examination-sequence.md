# 鉴定式行政法案例分析的外在结构（五级审查排序）

> "外在结构"指：当案件涉及多个诉讼请求、多方当事人或多个被诉行政行为时，整份报告的章节组织顺序——按何种逻辑把各项请求的审查依次展开，并在展开内部安排具体检视层级。
>
> 本文件与 `inner-structure.md`（内在结构：双层架构）、`legality-examination-engine/pipeline.md`（SOP 流水线）构成三维骨架：外在结构决定"报告写哪些章节、以什么顺序排列"；内在结构决定"每一章怎么写"；SOP 流水线决定"大纲怎么生成"。

> **法条锚定单点源铁律**：本文档所有法条引用一律使用 `[语义名称]` 占位符，禁止出现具体条号。语义名称→现行编号的映射由 `SKILL.md §6.5 法条锚定表` 唯一维护。本文件中出现的"§N"形式仅指本目录内部章节交叉引用（如 §6.5、§2.1），非法条编号。

## 一、五级审查排序

按以下五个维度递进，逐一锁定本案需审查的全部对象与展开方式：

### 第一级：诉讼请求拆分（"原告主张什么"）

行政诉讼的外在结构以**诉讼请求**——而非"双方关系"——为最高维度组织单元。这是行政诉讼与民事诉讼外在结构的根本差异：民事诉讼以当事人之间的法律关系为起点，行政诉讼以"公民 → 行政机关"的单向结构为起点，核心争议始终围绕被诉行政行为展开。

**操作步骤**：

1. **逐字摘录**：逐字摘录原告全部诉讼请求原话，严禁归纳改写；
2. **拆解复合请求**：不同被诉行为必拆、不同请求类型必拆（"撤销+赔偿"必拆为两项请求）；
3. **识别主位/备位关系**：

```
诉讼请求清单
   ├─ R1（主位请求）："请求撤销 XX 处罚决定"
   ├─ R2（备位请求）："若撤销不能，请求确认该处罚决定违法"
   │     → 条件：R1 结论 = "行政行为已不具有可撤销性"时激活
   └─ R3（独立请求）："请求行政赔偿"
         → 独立于 R1/R2 结果
```

4. **排列章节**：每项请求独立列章，按以下优先级排序：
   - 主位请求先于备位请求；
   - 形成性请求（撤销）先于确认性请求（确认违法/无效）；
   - 确认性请求先于给付性请求（赔偿/补偿）；
   - 附带审查（规范性文件审查）附于其所依附的主诉之后；
   - 独立的程序性请求（如管辖异议）前置于实体请求。

**备位请求的章节安排**：备位请求在其主位请求分析完毕后紧接展开，以"主位请求不成立→备位请求激活"为过渡句衔接，避免重复论述。若主位请求成立，则标注"备位请求因主位请求成立而不予展开"。

> 详细识别流程与 YAML 清单模板参见 `legality-examination-engine/pipeline.md` § 一。

### 第二级：可受理性 → 可证立性分层（"法院能否实体审理"）

对第一级拆分得到的**每一项诉讼请求**，按照"先程序后实体"的双层结构独立展开：

```
诉讼请求 Rn
   │
   ▼
┌───────────────────────────────┐
│  A. 可受理性（8 闸门逐项筛查）  │
│     G1 生效裁判约束（一事不再理）│
│     G2 受案范围               │
│     G3 行政复议前置            │
│     G4 原告资格               │
│     G5 被告适格               │
│     G6 管辖                   │
│     G7 起诉期限与形式要件      │
│     G8 诉的利益               │
│     G9 中间结论（强制收口节）  │
└───────────────────────────────┘
   │
   ├── 任一闸门不通过 → 该请求终止于可受理性层（裁定驳回起诉）
   │
   ▼ 8 闸门全部通过
┌───────────────────────────────┐
│  B. 可证立性（实体审查）        │
│     由第三级确定的诉讼类型骨架  │
│     叠加第四级确定的专属要点    │
│     按第五级展开具体检视        │
└───────────────────────────────┘
```

**逐项筛查规则**：可受理性闸门对**每个诉讼请求逐项筛查**，而非全案统一判定。例如：R1（撤销请求）通过闸门 / R2（赔偿请求）因闸门 G7 起诉期限不通过 → R1 进入可证立性、R2 终止，而非连带终止。

**双层展示纪律**：

- 可受理性否定即终止于该层，禁止"虽然不可受理但如果可受理则……"式的附带讨论；
- 可受理性通过后进入可证立性，通过即判决支持、不通过则判决驳回诉讼请求——二者法律效果截然不同（裁定 vs 判决）；
- 可受理性中争议性闸门以鉴定式展开，明显通过的闸门以裁判式一句话确认即可。

> 8 闸门完整展开参见 `legality-examination-engine/admissibility-screening.md`；双层架构总纲参见 `inner-structure.md`。

### 第三级：诉讼类型决定骨架（"用什么程式检验"）

通过可受理性进入可证立性的每项请求，由其**诉讼类型标签**决定实体审查骨架。行政诉讼的五种类型对应五套不同的审查程式：

| 诉讼类型 | 审查骨架 | 详细文件 | 核心逻辑 |
|---------|---------|---------|---------|
| 撤销之诉 | 六要素合法性审查 | `suit-types/revocation-suit.md` | 行政行为违法 → 撤销 |
| 履职之诉 | 请求权基础 + 行政裁量收缩 | `suit-types/performance-suit.md` | 法定职责 + 不作为/拒绝 → 责令履行 |
| 给付之诉 | 给付请求权 + 法定给付条件 | `suit-types/payment-suit.md` | 赔偿/补偿/一般给付 |
| 确认之诉 | 违法性或无效性审查 | `suit-types/declaratory-suit.md` | 行政行为已无可撤销性/确认无效 |
| 特殊之诉 | 专属程式 | `suit-types/special-scenarios.md` | 协议双轨/附带审查/复议共同被告/公益诉讼 |

**诉讼类型决定骨架，不可互换**。典型的骨架错配错误：

- 把"已执行完毕的强拆"仍以撤销之诉骨架展开 → 应以确认违法之诉骨架；
- 把"请求继续履行 PPP 协议"以给付之诉骨架展开 → 应以协议之诉（特殊之诉）骨架；
- 把"附带审查规范性文件"独立为一个诉讼类型 → 附带审查必须依附主诉。

**复合请求的骨架组装**：当案件同时包含多种诉讼类型时，各类型独立展开、互不混淆。在程式组装阶段（`legality-examination-engine/pipeline.md` § 四）完成骨架合成。

> 5 类型决策树与 7 步识别流程参见 `legality-examination-engine/pipeline.md` § 一。

---

### 第四级：行政行为类型决定实体要点（"叠加什么专属要点"）

诉讼类型决定骨架后，再由**被诉行政行为的实质类型**决定叠加哪些专属审查要点。这两个维度正交、缺一不可：

```
完整审查程式 = 诉讼类型骨架（第三级） × 行政行为类型专属要点（第四级）
```

9 类高频行政行为路由：

| # | 行为类型 | 叠加的核心专属审查要点 |
|---|---------|---------------------|
| 1 | 行政处罚 | 一事不再罚 / 听证程序 / 主观过错 / 裁量基准 / 告知义务 / 时效 |
| 2 | 行政强制 | 措施 vs 执行区分 / [强制措施程序要件条款] / 夜间禁止 / 公告期 |
| 3 | 信息公开 | 豁免三要件 / 重复申请 / 咨询信访区分 |
| 4 | 征收补偿 | 征收 vs 补偿双轨 / 公共利益 / 评估时点 / 强拆前置 |
| 5 | 投诉举报 | 原告资格（保护规范理论）/ 实质 vs 形式处理 |
| 6 | 工伤认定 | 三工要素 / 举证责任倒置 / 视同工伤边界 |
| 7 | 行政许可 | 撤回 vs 撤销 vs 注销三分 / 信赖保护 / 延续默示批准 |
| 8 | 行政协议 | 协议四阶（成立/效力/履行/救济）/ 单方变更合法性 / 违约 vs 违法区分 |
| 9 | 行政赔偿 | 赔偿 vs 补偿区分 / 先行处理程序 / 举证特殊规则 |

**叠加操作**：在 W2 Gate2 阶段通过 `case-router.md` §二 行政行为实质类型路由识别行为类型，再将对应专属要点叠加在诉讼类型骨架之上。示例：

```
"撤销行政处罚决定"案件：
  第三级 → 撤销之诉 → 六要素合法性审查骨架
  第四级 → 行政处罚 → 叠加 6 项专属要点
  合成 → 六要素合法性审查中"法律适用"要素下增设"一事不再罚""裁量基准"子节，
         "程序"要素下增设"听证程序""告知义务"子节
```

**兜底规则**：行为类型无法识别或不在 9 类之中时，仅走六要素合法性审查通用骨架，在报告中标注"行政行为类型未识别"并提示用户补充。多行为类型并存时分节展开各自专属要点。

> 9 类行为类型完整详表与双维度叠加规则参见 `case-router.md` §二。

### 第五级：六要素合法性审查展开序列（"每个要素怎么检验"）

进入实体审查后的最内层，以**六要素合法性审查骨架**为通用程式，按固定顺序逐项展开：

```
被诉行政行为的合法性审查
   │
   ├── 1. 主体要素（职权依据）
   │      ├── 法定职权有无
   │      ├── 管辖权限
   │      └── 委托/授权合法性
   │
   ├── 2. 程序要素
   │      ├── 法定程序遵守（通用：告知 / 听取意见 / 说明理由）
   │      ├── 专属程序要求（第四级叠加：如处罚类的听证程序/告知义务）
   │      └── 程序瑕疵分级：轻微违法不影响实体权利 vs 重大违法应予撤销
   │
   ├── 3. 事实证据要件
   │      ├── 证据充分性
   │      ├── 举证责任分配
   │      └── 证据标准（明显优势还是高度盖然性）
   │
   ├── 4. 法律适用要素
   │      ├── 援引法条是否正确且现行有效
   │      ├── 法律解释是否合理（参见 interpretation-toolkit.md）
   │      ├── 专属法律适用要点（第四级叠加：如处罚类的一事不再罚/时效）
   │      └── 五种法律适用错误精细形态（参见 revocation-suit.md §3.1）
   │
   ├── 5. 裁量要素
   │      ├── 裁量逾越（超出法定幅度）
   │      ├── 裁量滥用（违反比例原则/目的不当/考虑不相关因素）
   │      ├── 裁量怠惰（未行使裁量权）
   │      ├── 裁量收缩至零（参见 proportionality-and-discretion.md）
   │      └── D6 法定幅度自动校验（SOP-5 输出叠加）
   │
   └── 6. 处理结果适当性要件
          ├── 行政行为内容是否合法/适当
          └── 与前五要素发现的瑕疵之间的因果关系
```

**展开序列固定规则**：

1. 主体 → 程序 → 事实 → 法律 → 裁量 → 结果，六要素的检验顺序不可变动；
2. 前一要素否定不阻止后续要素检验——鉴定式要求穷尽检验全部要素（区别于实务中的"发现一项违法即撤销"）；
3. 每个要素内部以涵摄四步法（总起句→定义→归入→结论）展开，参见 `gutachten-writing-rules.md`；
4. 论证深度按三层分级控制——核心争点以鉴定式展开、无争议要素以裁判式一句话确认、中间地带用"简要鉴定式"，参见 `proportionality-and-discretion.md`。

**缺陷分级三档**（终局判断）：

| 档次 | 缺陷程度 | 法律效果 |
|------|---------|---------|
| 第一档 | 重大且明显违法 | 行政行为无效（自始不生效力） |
| 第二档 | 违法但未达重大明显 | 行政行为可撤销 |
| 第三档 | 程序轻微违法且未影响实体权利 | 确认违法但不撤销（"确认违法判决"条款 第 1 款第 2 项） |

> 六要素通用骨架、缺陷分级三档与要件拆解详见 `legality-examination-engine/framework.md`；具体条号统一参见 SKILL.md §6.5。

## 二、五级排序的优先级规则

当一个案件涉及多项诉讼请求时，按以下规则组织章节：

### 2.1 请求间优先级

1. **主位请求先于备位请求**：备位请求紧跟其主位请求之后，以条件句衔接。
2. **形成性请求先于确认性/给付性请求**：撤销之诉 → 确认之诉 → 给付之诉（赔偿）。这一排序的依据是"撤销是确认和赔偿的前提"——撤销成立则确认违法无展开必要，撤销不成立方转入确认违法，赔偿需以违法确认为前提。
3. **从诉依附主诉**：附带审查规范性文件的请求紧跟其依附的主诉之后。
4. **程序性请求前置**：管辖异议等程序性请求置于全部实体请求之前。

### 2.2 聚合与竞合

行政诉讼中的多项请求更多呈现**聚合**关系（而非竞合）：

- **聚合请求**（撤销+赔偿）：分别独立展开审查，但赔偿请求以违法确认为前提，故排列于撤销/确认之后；
- **择一请求**（主位撤销/备位确认违法）：主位先展开，结论决定备位是否激活；
- **附随请求**（附带审查规范性文件）：附于主诉可证立性审查中，不独立列章。

### 2.3 共同被告的章节安排

复议机关共同被告情形下，先审查原行政机关作出的行政行为，再审查复议决定。复议维持的以原行为审查为主体，复议改变的以复议决定审查为主体。

## 四、与民法/刑法外在结构的差异

| 维度 | 民法外在结构 | 刑法外在结构 | 行政法外在结构（本文件） |
|------|------------|------------|---------------------|
| 最高组织单元 | 双方关系（"谁向谁"） | 事实单元（独立行为-结果） | 诉讼请求（"请求什么"） |
| 排序核心逻辑 | 请求权基础竞争（合同→物权→侵权→不当得利） | 罪名严重性（重罪→轻罪） | 请求功能性（形成→确认→给付） |
| 检视程式来源 | 请求权基础三层四步 | 犯罪论三阶层 | 双层结构（可受理性闸门 + 可证立性六要素） |
| 内在结构层数 | 三层（成立→变动→可行使） | 三层（构成要件→违法性→有责性） | 两层（可受理性→可证立性） |
| 实体审查骨架 | 由请求权基础类型决定（18 类） | 由罪名决定（分则各罪） | 由诉讼类型×行政行为类型双维度决定 |
| 穷尽原则 | 穷尽全部可能的请求权基础 | 穷尽全部可能的罪名 | 穷尽全部诉讼请求 + 穷尽六要素 |

**核心差异总结**：行政法的外在结构具有独特的"双维度叠加"特征——诉讼类型决定骨架、行政行为类型决定实体要点，二者正交组合。民法和刑法均为单维度（请求权基础类型 / 罪名）直接决定全部检视程式。

## 五、穷尽原则在行政法中的适用

### 5.1 穷尽请求

对案件事实中所有**具有合理适用可能性的诉讼请求**，均须展开审查，不得遗漏。即使原告未明示某项请求，但案件事实显然支持的，应在报告中主动补充检视（尤其是备位请求和附带审查请求）。

### 5.2 穷尽六要素

对每一项通过可受理性的诉讼请求，在可证立性阶段须穷尽六要素全部检验。前一要素否定不阻止后续要素检验——鉴定式要求展示完整的法律分析，而非在发现第一个违法点后即止步。

### 5.3 穷尽闸门

在可受理性阶段，8 闸门须逐项过关。即使前一闸门明显通过，仍须明确确认（裁判式一句话即可）。对有争议的闸门须以鉴定式完整展开。

### 5.4 常见遗漏提示

| 容易遗漏的内容 | 典型遗漏场景 |
|--------------|------------|
| 备位请求（确认违法之诉） | 撤销之诉分析完毕后遗漏"若行政行为已不具有可撤销性"的转化分析 |
| 附带审查规范性文件 | 原告附带请求审查处罚依据的规范性文件合法性 |
| 复议机关共同被告 | 复议维持情形下遗漏对复议机关被告适格的分析 |
| 第三人诉讼地位 | 行政行为对利害关系人的权益影响分析 |
| 赔偿请求前提 | 先审查违法性（撤销/确认违法）再进入赔偿，二者不可跳步 |
| 起诉期限多标准 | [起诉期限条款]之六个月一般期限 / [复议后起诉期限条款]之 15 日 / [最长保护期条款] |

## 六、"结论一致则不问理由"原则

> **当不同学说、理论或解释路径对同一问题得出相同结论时，无需展开学说争议，直接得出结论即可。**

适用条件：（1）存在两个以上理论路径；（2）所有路径均指向相同结论；（3）结论本身可直接服务于涵摄。

行政法中的典型适用场景：

- 保护规范理论的不同公式（主观公权利三要件公式 vs 新保护规范理论）对个案原告资格得出相同结论时；
- 比例原则的三阶段（适当性/必要性/均衡性）中某一阶段已否定、后续阶段结论一致时；
- 行政行为成立标准的不同学说对个案得出相同结论时。

注意：本原则仅适用于**最终结论相同**的情形；中间结论相同但可能影响后续路径的，仍需展开。应在脚注点明争议存在与各说结论一致的事实。

> 完整规则与展开深度分级参见 `proportionality-and-discretion.md`。

## 七、审查排序操作指引

### 7.1 完整操作流程图

```
案件事实
  │
  ├─[第一级] 诉讼请求拆分
  │   ├─ R1（主位）："请求撤销 XX 处罚决定"    ← 撤销之诉
  │   ├─ R2（备位）："若撤销不能，确认违法"    ← 确认之诉（R1 失败时激活）
  │   └─ R3（独立）："请求赔偿损失 10 万元"   ← 给付之诉（需违法确认为前提）
  │
  ├─[第二级] 逐请求双层审查
  │   ├─ R1：可受理性 8 闸门 → 全部通过 → 可证立性
  │   ├─ R2：可受理性 8 闸门 → 全部通过 → 备用（视 R1 结论决定是否展开）
  │   └─ R3：可受理性 8 闸门 → G7 起诉期限不通过 → 终止
  │
  ├─[第三级] 诉讼类型 → 骨架
  │   ├─ R1 撤销之诉 → 六要素合法性审查骨架
  │   └─ R2 确认之诉 → 违法性审查骨架
  │
  ├─[第四级] 行政行为类型 → 专属要点
  │   └─ 行政处罚 → 叠加一事不再罚/听证/主观过错/裁量基准/告知/时效
  │
  └─[第五级] 六要素合法性审查展开
      R1：主体→程序→事实→法律→裁量→结果
      R2：（R1 结论为"不具有可撤销性"→ R2 激活）违法性审查
      R3：（G7 起诉期限不通过 → 本章不展开 → 终止于可受理性层）
```

### 7.2 章节排序速查表

| 情境 | 排序规则 |
|------|---------|
| 撤销+赔偿 | 撤销在先 → 赔偿在后（赔偿以违法确认为前提） |
| 撤销（主位）+确认违法（备位） | 撤销在先 → 确认违法紧随（条件激活） |
| 多个被诉行为 | 按行为时间顺序排列，先发生的先审查 |
| 复议共同被告 | 原行为在先 → 复议决定在后 |
| 附带审查规范性文件 | 嵌入所依附主诉的"法律适用"要素之中 |
| 程序性请求+实体请求 | 程序性请求前置 |
| 多原告合并审理 | 按原告编号顺序依次展开 |

### 7.3 注意事项

1. 审查排序是**报告展示顺序**，不是思维发现顺序。分析过程中可先浏览全部请求，再按排序规则组织正文。
2. 某项请求在可受理性层终止后，仍应完整标注"不通过"的闸门编号和理由，不可省略。
3. 备位请求的可受理性应独立审查——不因主位请求通过而自动通过。
4. 排序规则的调整应在报告导言中简要说明理由。
