# 合法性审查引擎 · 主流水线（SOP-1 / SOP-3 / SOP-4 / SOP-5）

> 本文件是 `legality-examination-engine` 的核心管线：从原告诉讼请求原话出发，依次完成"诉讼类型识别 → 行政行为定性 → 规范属性分类 → 程式组装与要件拆解"，最终产出可证立性大纲。
>
> 可受理性闸门审查（8 闸门）作为前置步骤独立成文，见 [`./admissibility-screening.md`](./admissibility-screening.md)；本文件假设可受理性已通过或已并行处理，专注于"合法性 / 可证立性"骨架。

> **法条锚定单点源铁律**：本文档所有法条引用一律使用 `[语义名称]` 占位符，禁止出现具体条号。语义名称→现行编号的映射由 `SKILL.md §6.5 法条锚定表` 唯一维护。如发现本文档残留具体条号（如《行政处罚法》§57），视为格式违规，应统一回退到语义名称。

## § 一 诉讼类型识别（5 类 × 决策树）

> 诉讼类型是引擎的"路由器"——骨架错配则整篇报告失效。本节规定从诉讼请求原话到结构化诉讼类型清单的完整识别流程。

### 1. 5 类型决策树

```
原告诉讼请求 = ?
    │
    ├─ 「请求撤销/部分撤销 [行政行为]」
    │   → 撤销之诉（revocation-suit）
    │   ⚠ 行政行为已不存在/不再具有可撤销性 → 转为确认违法之诉
    │
    ├─ 「请求 [行政机关] 履行 [法定职责]」
    │   → 履职之诉（performance-mandate-suit）
    │   └─ 子类型：针对不作为 → 嵌入履职骨架
    │
    ├─ 「请求 [行政机关] 给付 [金钱/财产/许可证…]」
    │   → 给付之诉（general-performance-suit）
    │   └─ 行政赔偿/补偿/法定给付
    │
    ├─ 「请求确认 [行政行为] 违法/无效」
    │   → 确认之诉（declaratory-suits）
    │   ├─ 确认违法：行政行为已不具有可撤销性 / 程序轻微违法
    │   └─ 确认无效：重大且明显违法（确认无效判决条款 + 行诉解释中确认无效情形条款）
    │
    └─ 「特殊类型」
        → 特殊之诉（special-scenarios）
        ├─ 行政协议之诉（公私双轨）
        ├─ 规范性文件附带审查（必伴随主诉）
        ├─ 复议机关共同被告（修饰主诉）
        └─ 行政公益诉讼（检察机关起诉，叠加诉前程序要件）
```

### 2. 5 类 → A/B/C 三轨映射

5 类诉讼类型按"审查范式"归入三轨，骨架不可互用。

| 诉讼类型 | 归属轨道 | 检视程式骨架 |
|---------|---------|-------------|
| 撤销之诉 | A 轨 · 违法性审查 | 六要素合法性审查（见 `framework.md`） |
| 确认违法之诉 | A 轨 · 违法性审查 | 六要素 + 违法性 + 不再具有可撤销性 |
| 确认无效之诉 | A 轨 · 违法性审查 | 六要素 + 重大且明显违法判定 |
| 履职之诉 | B 轨 · 请求权审查 | 请求权基础 / 要件 / 履行可能 / 抗辩 |
| 给付之诉（含一般给付） | B 轨 · 请求权审查 | 请求权基础 / 要件 / 履行可能 / 抗辩 |
| 特殊 · 行政协议之诉 | C 轨 · 协议四阶审查 | 协议成立 → 效力 → 履行与变更 → 救济 |
| 特殊 · 附带审查 | 依主诉所在轨叠加 | 主诉骨架 + 规范性文件合法性体检 |
| 特殊 · 复议共同被告 | 依主诉所在轨叠加 | 主诉骨架 + 复议程序与决定合法性 |
| 特殊 · 行政公益诉讼 | 依实质类型归入对应轨 | 对应骨架 + 诉前程序要件 |

权威三轨表见 `../case-router.md` §零 0.2 三轨范式对照表。

### 3. 典型识别错误（红线提示）

| 错误情形 | 后果 | 纠正 |
|---------|------|------|
| 把"请求撤销已执行完毕的强拆决定"识别为撤销之诉 | 撤销已无意义 | 应转为确认违法之诉 |
| 把"请求继续履行 PPP 协议"识别为给付之诉 | 协议之诉骨架错配 | 应识别为协议之诉（特殊之诉） |
| 把"附带审查规范性文件"独立列为诉讼类型 | 附带审查必须依附主诉 | 主诉 + 附带请求 |
| 把"撤销"和"确认违法"混为一谈 | 骨架不同 | 必拆为两种类型分别分析 |
| 把"复议维持"诉讼仅以原机关为被告 | 共同被告漏列 | 必须列复议机关为共同被告 |

### 4. 识别 7 步流程

1. **逐字摘录**：逐字摘录诉讼请求原话（禁止归纳/改写）；
2. **拆解复合请求**："撤销+赔偿"必拆、不同被诉对象必拆；
3. **判定主诉与从诉**：决定核心法律关系的为主诉，后续依赖前诉结果的为从诉；
4. **贴类型标签**：每项请求贴诉讼类型标签（5 类之一）；
5. **检测复议关系**：维持→共同被告 / 改变→仅复议机关 / 未作出→双轨选择；
6. **检测原告与第三人**：相对人/利害关系人/共同诉讼；
7. **输出结构化 YAML 清单**。

### 5. 备位请求建模

复合诉讼请求中常见"主请求不成立时备位请求自动激活"的条件逻辑：

```yaml
诉讼请求清单:
  R1_main:
    类型: 撤销之诉
    原话: "请求撤销 XX 处罚决定"
    状态: 主请求
  R2_subsidiary:
    类型: 确认违法之诉
    原话: "若撤销不能，请求确认该处罚决定违法"
    条件: R1_main 结论 = "行政行为已不具有可撤销性"
    激活规则: R1_main 失败时自动激活
```

该建模确保备位请求不被遗漏，也不在主请求成立时被冗余展开。

## § 二 行政行为定性

> 行政行为定性决定适用哪部具体行政法与对应的合法性审查标准。定性错误 → 适用法律错误 → 整篇报告失效。
>
> **范围说明**：本节列出 12 类行政行为定性维度（含完整理论谱系）；其中 9 类为路由表常用高频类型（见 [`../case-router.md`](../case-router.md)），其余 3 类为低频但需识别的形态（如行政规划、事实行为、内部行为等）。9 类高频路由是 12 类理论谱系在实务中的应用切片，二者不冲突：路由按"高频场景 + 专属审查清单"组织，本节按"行政法学理论类型 + 适用法律体系"组织。

### 1. 四要件前置审查（行政行为成立要件）

| 要件 | 内容 |
|------|------|
| 主体要件 | 行政主体作出（行政机关或被授权组织） |
| 内容要件 | 意思表示明确（有具体内容） |
| 形式要件 | 法定形式（书面/口头/默示） |
| 程序要件 | 完成法定程序步骤 |

行政行为成立 ≠ 行政行为合法。前者是"客体存在"，后者是"内容合法"。

### 2. 12 类典型标签及适用法律体系

| 编号 | 标签 | 适用法律 | 核心审查要点 |
|------|------|---------|------------|
| 1 | 行政许可 | 《行政许可法》 | 申请条件/审查程序/期限/听证 |
| 2 | 行政处罚 | 《行政处罚法》 | 处罚法定/一事不再罚/程序权利 |
| 3 | 行政强制 | 《行政强制法》 | 强制法定/比例原则/程序保障 |
| 4 | 行政征收/征用 | 《土地管理法》/《征收补偿条例》 | 公共利益/法定程序/补偿标准 |
| 5 | 行政确认/登记 | 单行法 | 申请要件/审查标准/程序 |
| 6 | 行政给付/赔偿/补偿 | 《国家赔偿法》/单行法 | 给付条件/标准/程序 |
| 7 | 行政规划 | 《城乡规划法》/单行法 | 编制程序/公众参与 |
| 8 | 行政协议 | 《民法典》合同编+行政法 | 性质识别/效力/履行/信赖保护 |
| 9 | 规范性文件 | 不可单独起诉 | 仅可附带审查（"附带审查"条款） |
| 10 | 事实行为 | 一般无救济 | 特殊情形（损害赔偿/信息公开） |
| 11 | 内部行为 | "受案范围负面清单"排除 | 外溢例外（影响外部利益时） |
| 12 | 不作为 | 单行法（法定职责依据） | 职责依据/申请要件/履行期限 |

### 3. 理论类型 vs 路由高频类型对照

| 路由高频类型（9 类） | 对应理论标签（本节 12 类） |
|----------------------|--------------------------|
| 行政处罚 | #2 行政处罚 |
| 行政强制 | #3 行政强制 |
| 政府信息公开 | #5 行政确认/登记（信息公开决定为确认性具体行政行为）；拒绝答复时 = #12 不作为 |
| 房屋征收补偿 | #4 行政征收/征用 + #6 行政给付/补偿（双轨） |
| 投诉举报处理 | #12 不作为（不予处理）/ #2 行政处罚（实质处理） |
| 工伤认定 | #5 行政确认/登记 |
| 行政许可 | #1 行政许可 |
| 行政协议 | #8 行政协议 |
| 行政赔偿诉讼 | #6 行政给付/赔偿/补偿 |
| —（低频，无高频路由） | #7 行政规划 |
| —（低频，附带审查） | #9 规范性文件 |
| —（一般无救济，特例处理） | #10 事实行为 / #11 内部行为 |

### 4. 特殊定性问题

#### 4.1 行政行为 vs 民事合同

关键区分点为行政机关身份（公权力 vs 私法主体）、协议目的（行政管理 vs 民事交易）、协议内容（行政权利义务 vs 民事权利义务）。实务高发争议：政府投资项目合同（行政协议）vs 政府租赁办公房屋合同（通常民事合同）vs 国有土地出让合同（行政协议）。

#### 4.2 复合行政行为拆分

一个行政决定包含多个行政行为时（如处罚决定+强制措施+责令改正），拆为多个独立行政行为各自审查。

#### 4.3 阶段性行政行为

征收决定+补偿决定+强制执行决定分阶段作出，各阶段为独立行政行为，可分别起诉。

#### 4.4 群体行政行为

一个行政行为涉及多个相对人（如拆迁决定影响多户），行政行为本身仍是一个，多个相对人均有原告资格。

### 5. 行政行为定性四要件

① 单方性（行使公权力） → ② 外部效力（产生外部法律效果） → ③ 具体性（针对特定对象/事件） → ④ 法律效果性（设立/变更/消灭法律关系）。四要件全数满足 → 具体行政行为成立。

## § 三 规范属性 10 类分类

> 不同属性的规范在检视程式中处于不同位置。本节规定如何将涉案条文快速分类为 10 种规范属性，以便在 § 四 程式组装时准确填充到对应的检视位置。

### 1. 10 类规范属性速查表

| 编号 | 规范属性 | 检视位置 | 典型条文特征 |
|------|---------|---------|------------|
| 1 | 职权规范 | 主体/职权审查 | "XX 机关负责/有权…" |
| 2 | 程序规范 | 程序审查 | "应当先 XX/应当告知" |
| 3 | 实体构成要件规范 | 事实+法律适用审查 | "下列情形/违反 XX 行为" |
| 4 | 裁量授权规范 | 裁量审查 | "可以处 X 元以上 Y 元以下" |
| 5 | 法律效果规范 | 处理结果审查 | "由 XX 机关给予处罚/责令" |
| 6 | 复议关联规范 | 复议程序审查 | 《行政复议法》条文 |
| 7 | 行政协议规范 | 协议审查 | 《民法典》合同编+协议特殊条款 |
| 8 | 信赖保护与诚信规范 | 信赖保护审查 | "信赖保护""不得撤销""依法保护" |
| 9 | 程序性救济规范 | 程序救济审查 | "复议/听证/起诉/申诉" |
| 10 | 规范性文件审查规范 | 附带审查 | 红头文件/行业规章 |

### 2. 复合属性条文

复合属性条文（如 [行政处罚决定作出条款] 同时包含程序/实体/裁量/法律效果属性）在不同检视位置分别审查。

**处理规则**：一条条文可能同时属于多个规范属性类别，此时在每个对应的检视位置各引用一次，分别就该位置所关注的维度进行涵摄。

## § 四 程式组装与要件拆解

> 本节是引擎的"出口"，将前三节产出组装为完整的可证立性大纲。三个子环节（程式组装 → 要件拆解 → 大纲成型）构成紧密衔接的尾部流水线。

### 1. 程式组装

```
§ 一 输出（诉讼类型）→ 调取基础骨架（suit-type-library）
§ 二 输出（行政行为定性）→ 骨架内"合法性审查"展开方式
§ 三 输出（规范属性）→ 每个检视位置填充条文
→ 候选审查程式骨架成型
```

复合诉讼骨架组装规则：主诉调取主骨架，从诉调取从骨架，主从骨架并列，注意主从依赖（从诉以主诉结论为前提）。复议机关共同被告在主骨架主体要件中专列子环节。

### 2. 要件拆解

把骨架展开为最小涵摄单元。每个最小单元 = 一个不可再分的法律构成要件 = 一个 H4 标题，由涵摄四步法占用整段文字。

**法定幅度自动校验步骤**：在要件拆解环节，凡涉及裁量授权规范的要件，自动执行以下比对：

```
步骤 1：提取法律规定的裁量幅度（如"处 5000 元以上 5 万元以下罚款"）
步骤 2：提取实际行政行为的处理结果（如"罚款 8 万元"）
步骤 3：自动比对 → 是否在法定幅度内
步骤 4：若超出 → 标记为"裁量逾越"争点，进入裁量审查环节深度展开
步骤 5：若在幅度内 → 仍需审查比例原则（适当性/必要性/均衡性）
```

### 3. 大纲成型——涵摄四步

大纲成型后，每个最小涵摄单元按以下四步展开：

| 步骤 | 功能 | 句式模板 |
|------|------|---------|
| **总起句** | 提出假设性问题 | "被诉行为 X 可能符合/不符合 [要件]。" |
| **定义** | 给出要件的工作定义 | "依 [法条/释义/通说]，[要件] 是指……" |
| **归入** | 事实与定义比对 | "本案中，[事实层映射]……，符合/不符合上述定义。" |
| **结论** | 确定性判断 | "因此，被诉行为 [符合/不符合] [要件]。" |

**行政法专属归入纪律**：
- **被告举证倒置**：合法性争点须以"被告应当证明……，否则……"句式展开（依"举证责任倒置"条款）；
- **裁量审查**：发现裁量空间时，须依"裁量逾越/裁量滥用/裁量怠惰 + 比例原则"四线索全面审查；
- **保护规范理论**：原告资格审查须明确指出"行政法律规范是否赋予原告主观公权利"。
