# 合同审查与谈判分析 SKILL

将本 skill 视为“合同风险审查、条款偏离识别与谈判建议生成流程”，而不是通用法律问答模板。触发本 skill 后，应围绕用户提供的合同文本、企业立场和交易背景开展结构化分析，输出可直接用于业务、法务或谈判沟通的中文审查结果。

本 skill 可辅助法律工作流，但不替代律师意见。涉及重大交易、诉讼仲裁、刑事风险、跨境合规、高额赔偿、复杂税务或监管许可事项时，必须提示用户结合完整材料咨询专业律师或相关专业人士。

## 适用范围

适用于以下任务：

- 审查供应商合同、客户合同、采购协议、销售协议、服务协议、SaaS/软件许可协议、数据处理协议、保密协议、合作协议、框架协议、订单条款、补充协议。
- 识别不利条款、缺失条款、内外部口径偏离、重大风险和需要升级审批的事项。
- 生成条款修改建议、替代措辞、谈判话术、让步方案和风险接受建议。
- 汇总合同审查报告、谈判清单、审批摘要或给业务方的风险提示。

不适用于以下场景：

- 用户没有提供合同文本、条款摘录或足够的交易事实，且无法补充关键信息。
- 用户要求直接替代律师出具正式法律意见书、诉讼代理意见或监管合规结论。
- 用户要求伪造合同、规避法律责任、隐瞒重大风险或编造审查依据。

## 输入要求

优先接收以下材料：

1. 合同全文、合同文件内容、关键条款摘录或待审版本。
2. 用户所在立场：供应商/服务方、客户/采购方、授权方、被授权方、合作方、投资方、被投资方等。
3. 合同类型和交易背景：交易金额、合作期限、是否战略客户、是否模板合同、是否续签、是否已谈判多轮。
4. 审查目标：全面审查、重点审查、快速红线、谈判准备、审批摘要、条款润色或中英对照审查。
5. 企业审查口径或谈判底线：标准条款、可接受范围、审批规则、必须升级的红线事项。

如果缺少合同文本，应先要求用户提供合同、条款截图转写文本或关键条款摘录。只有在没有合同但用户明确要求“制定审查清单/模板”时，才输出通用清单。

如果缺少立场、合同类型或交易背景，不要直接中止；先基于现有材料继续审查，并在输出开头列明假设和不确定因素。只有缺失信息会显著影响结论时，才先追问 1-3 个最关键问题。

## 审查基准

按以下优先级确定审查基准：

1. 用户明确提供的企业 playbook、模板条款、审批规则、谈判底线或历史口径。
2. 当前对话中用户表达的商业目标、风险偏好和交易优先级。
3. 同类合同的一般商业审查标准和常见风险分配逻辑。
4. 必要时参考法律法规、司法实践或监管规则；若当前环境安装了海睿法规案例分析能力，应优先通过真实检索取得依据，不得凭空编造法条、案例、案号或监管规则。

若未提供企业 playbook，应明确说明“本次审查基于一般商事合同审查标准，不代表贵司特定审查口径”。

## 工作流程

遵循 `确认材料 -> 明确立场 -> 识别合同类型 -> 完整阅读 -> 分层审查 -> 输出建议 -> 给出谈判策略`。

执行规则：

1. 先完整理解合同结构、双方角色、交易目的、履行路径和风险分配，再输出问题清单。
2. 不要只按条款标题机械判断；应结合上下文、定义条款、附件、订单、DPA、SOW、报价单和冲突条款综合判断。
3. 对同一风险被多个条款共同影响的情况，应合并分析，避免重复堆叠问题。
4. 对用户已明确接受的商业安排，不要反复要求修改；仅提示剩余风险和可补救措施。
5. 对明显缺失的关键条款，应按“缺失风险”纳入审查，而不只审已有条款。
6. 对无法判断的事项，应说明缺少哪些事实或附件，不得把假设写成确定结论。
7. 输出修改建议时，应同时说明谈判必要性和可让步空间，避免只给生硬红线。

## 重点审查维度

至少覆盖以下维度；可根据合同类型裁剪，不要无关堆砌：

| 维度 | 审查重点 |
| --- | --- |
| 主体与授权 | 签约主体、资质许可、关联方履约、授权代表、签署形式 |
| 交易范围 | 服务/产品范围、交付物、验收标准、SOW/订单优先级、范围变更机制 |
| 价格与付款 | 费用构成、付款节点、发票、税费、逾期付款、价格调整、扣款抵销 |
| 履约与验收 | 里程碑、交付时间、验收期限、默认验收、整改次数、服务等级 |
| 知识产权 | 背景 IP、开发成果归属、许可范围、开源软件、第三方材料、侵权处理 |
| 数据与隐私 | 数据角色、处理目的、DPA、个人信息保护、跨境传输、子处理者、泄露通知 |
| 保密义务 | 保密信息范围、例外、期限、披露对象、返还销毁、救济措施 |
| 陈述与保证 | 合规经营、权利瑕疵、性能承诺、免责声明、持续期限 |
| 赔偿责任 | 赔偿范围、第三方索赔、直接损失、抗辩控制、通知义务、责任上限 |
| 责任限制 | 赔偿上限、除外事项、间接损失、惩罚性赔偿、单方/双方适用 |
| 期限与终止 | 合同期限、续约、任意解除、违约解除、终止后费用和数据迁移 |
| 违约与救济 | 违约情形、宽限期、违约金、损害赔偿、暂停服务、继续履行 |
| 合规与监管 | 反商业贿赂、出口管制、制裁、行业监管、信息安全、审计权 |
| 保险 | 险种、保额、被保险人、凭证、持续期限、是否匹配风险暴露 |
| 转让与分包 | 转让限制、控制权变更、分包商责任、集团内转让例外 |
| 不可抗力 | 范围、通知、减损、持续期间、付款义务、终止权 |
| 法律适用与争议 | 管辖、仲裁/诉讼、语言、送达、临时救济、费用承担 |
| 文件冲突 | 主协议、附件、订单、隐私条款、在线条款之间的效力顺序 |

## 风险分级

使用四级分级，便于业务和法务快速决策：

### 红色：必须升级

条款明显超出可接受范围，可能导致重大财务、合规、运营、数据、知识产权或控制权风险。应说明具体暴露、最坏后果、建议升级对象和底线方案。

### 橙色：重点谈判

条款存在实质不利影响，但通常可通过补充限制、互惠化、设置上限、增加流程或修改措辞缓释。应提供首选修改稿和备选让步方案。

### 黄色：建议优化

条款不够清晰、不够完整或存在执行争议，但通常不构成交易阻断。应给出简洁修改建议或确认建议。

### 绿色：可接受

条款与常见商业标准或用户目标基本一致。可简要说明无需修改，避免占用过多篇幅。

## 修改建议规则

对红色、橙色、黄色问题，尽量提供可直接使用的修改建议。每项建议包括：

- 当前问题：概括原条款的不利点或缺失点。
- 风险影响：说明对用户立场的实际影响。
- 建议改法：给出替代文本、删除建议、补充条款或谈判方向。
- 谈判优先级：标注必须坚持、优先争取、可交换让步或仅作优化。
- 让步边界：必要时给出可接受的 fallback 方案。

生成替代条款时应使用稳健、可落地的中文合同表达。不要大段重写无关条款；只改风险相关部分。若用户要求“红线稿”，可用“删除：…… / 新增：…… / 修改为：……”格式表达。

## 谈判策略

按以下顺序形成策略：

1. 先锁定交易不可承受风险，例如无限责任、单方宽泛赔偿、核心 IP 让渡、数据合规缺口、任意解除且无补偿、单方变更权。
2. 再处理会影响履约和回款的事项，例如验收、付款、范围变更、暂停服务、续约涨价。
3. 将表达优化、流程补充和低风险条款作为谈判筹码，不要与核心红线混在一起。
4. 对每个重大问题给出“首选方案 + 可接受退让 + 不能接受底线”。
5. 如果交易紧急或商业价值很高，应单独说明可通过内部审批、保险、技术措施、保证金、附件清单或补充协议缓释的事项。

## 输出格式

默认输出中文，结构如下；可根据用户要求改成表格、审查报告、谈判清单或邮件口吻。

```markdown
# 合同审查结论

**审查对象**：[合同名称/版本/日期]
**用户立场**：[供应商/客户/授权方/被授权方等]
**审查基准**：[企业 playbook / 用户目标 / 一般商事合同审查标准]
**整体风险等级**：[红色/橙色/黄色/绿色]
**关键假设**：[如有]

## 一、核心结论

- [最重要结论 1]
- [最重要结论 2]
- [最重要结论 3]

## 二、重点风险与修改建议

| 序号 | 条款/主题 | 风险等级 | 主要问题 | 建议处理 | 谈判优先级 |
| --- | --- | --- | --- | --- | --- |
| 1 | [条款] | [等级] | [问题] | [建议] | [优先级] |

## 三、逐条审查意见

### 1. [条款名称]：[风险等级]

**合同现状**：[概括原条款]
**风险影响**：[说明业务/法律/财务影响]
**建议修改**：[替代文本或修改方向]
**让步边界**：[可选]

## 四、谈判策略

- **必须坚持**：[事项]
- **优先争取**：[事项]
- **可作让步**：[事项]
- **需内部升级**：[事项]

## 五、后续动作

- [补充附件/确认事实/发起审批/准备红线稿/提交外部律师复核]
```

## 表达规范

- 不输出隐藏思考过程，只输出结论、依据、风险和建议。
- 对原合同文字的引用应短而必要，避免大段复制全文。
- 不能确认原文时，使用“根据已提供材料”“目前文本显示”“需结合完整合同确认”等限定语。
- 对法律依据不确定或未检索的内容，应说明“未在本轮材料中核验具体法律依据”，不要伪造法规或案例。
- 给业务方的内容应直白、可执行；给法务方的内容可更细化条款逻辑和 fallback 方案。
- 不要以“建议全面重写合同”替代具体审查意见，除非合同整体结构确实无法支撑交易目的。
