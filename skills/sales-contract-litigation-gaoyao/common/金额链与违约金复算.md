# 金额链与违约金复算

## 基本原则

金额结论必须可从冻结输入复现，并与合同、交付、验收、对账和付款归属相互印证。显示值、手填合计或单一对账单均不能成为唯一金额源。

## 复算顺序

1. 锁定合同总价、含税口径、设备或批次范围及变更协议。
2. 建立应付款分期表：到期日、应付额、付款条件和证据 locator。
3. 建立实付款明细：日期、金额、付款人、收款人、流水号和归属状态。
4. 核对第三方代付、退款、折让、抵销和以物抵债，不明归属保持 `single-source` 或 `conflict`。
5. 使用 Decimal 逐笔计算本金余额，禁止二进制浮点直接用于最终金额。
6. 对工作簿同时读取公式态和缓存值，并逐行重算；记录舍入规则和异常单元格。
7. 违约金或利息逐期计算：基数、费率、起算日、截止日、天数规则、付款冲抵顺序和阶段合计。
8. 冻结基准日金额，并单列基准日后的继续计算公式及停止条件。

## 冲突处置

- 局部尾差：定位到具体单元格或行，比较公式、手填值和独立来源；未查明前不得静默抹平。
- 同源两种复算：标明“基于同一付款数据的不同复算路径”，不得包装为两份独立证据。
- 对账未签章或确认区空白：可作为单方计算或线索，证明力需合同、交付和银行流水补强。
- 付款归属不明：不得直接冲减或排除，应列专项补证和诉讼策略。
- 违约金过高、时效、管辖或送达风险：进入风险四元组，不因存在风险机械删除起诉状和证据目录。

## 冻结字段

至少冻结：`currency + contract_total + payments_total + principal_balance + penalty_as_of + calculation_date + daily_or_annual_rate + due_dates + allocation_rule + continuation_formula + source_ids + conflicts + reviewer`。

诉请、起诉状、证据目录、代理词、法律意见书和办案方案必须引用同一金额冻结；任何跨文书差异触发 `HOLD-CONSISTENCY`。
