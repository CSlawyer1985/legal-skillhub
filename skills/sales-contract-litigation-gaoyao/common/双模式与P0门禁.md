# 双模式与 P0 门禁

## production-intake

现实客户来件必须核验：

1. 关键材料可读性、完整性和来源。
2. 当事人、合同关系、诉请与在先裁判/调解/撤诉/仲裁的双维检索。
3. 是否存在重复起诉、管辖冲突、时效或主体资格问题。
4. 本次诉请是否与执行阶段或其他案由混同。

在先程序状态未知时使用 `HOLD-PRIOR-PROCEEDING`，不得因“材料看起来像已办案件”直接生成新起诉文书。

## retrospective-benchmark

历史样本必须记录：

- `cutoff` 及一手依据；
- 首次起诉前输入清单和完整 sha256；
- 答案集、后见集、历史工作成果集的物理隔离；
- 内容重叠、镜像传播和后见污染检查；
- 独立起草冻结 sha256；
- 答案键解封授权、解封时间和验收席。

无法用非答案键一手材料确定 cutoff 时使用 `HOLD-CUTOFF`。可以冻结隔离清单，但不得读取输入正文、建立 SSOT 或生成 L1/L2。

## 四级 P0

| 门 | PASS 要件 | FAIL/HOLD 后果 |
|---|---|---|
| P0-1 | 原件、镜像、locator、页码、哈希和可读性闭合 | 只输出可读性缺口 |
| P0-2 | production 在先程序闭合；或 retrospective cutoff/答案隔离闭合 | 不生成提交候选 |
| P0-3 | SSOT、金额、证据编号、法源与跨文书一致 | 输出差异表 |
| P0-4 | court profile、中文体例、表格、分页与渲染通过 | L1 保持 HOLD |

任一 P0 FAIL，整体状态为 HOLD。P0-2 PASS 不解除实体证据、时效、保证、管辖或金额 HOLD。
