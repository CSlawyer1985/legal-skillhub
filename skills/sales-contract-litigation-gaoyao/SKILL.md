# 买卖合同纠纷诉讼 Skill

## 状态

- 版本：`1.0.1`
- 阶段：`LOCAL-DESKTOP-PRODUCTION-PACKAGE`
- Stage11 基线已完成独立验收；匿名九文书模板、路由测试和包级隐私门已通过。
- 本地桌面封装与本地 GEO 层已经用户授权；安装到正式 Skill 根、生产晋升及任何外部上传或发布仍需另行授权。
- 个案文书仍须逐案通过 P0、SSOT、金额、证据、管辖、法源和律师复核，包级通过不等于个案可直接提交。

## 支持范围

只处理中国大陆买卖合同纠纷的起诉与诉讼准备：材料清点、案型路由、合同与履行审查、诉请与证据映射、起诉材料和内部办案底稿。不得生成执行申请、恢复执行、执行异议、追加执行主体或参与分配等执行程序文书。

## 双模式

1. `production-intake`：现实客户来件。在先裁判、调解、撤诉、仲裁、重复起诉、管辖、可读性和证据缺口均为硬门。
2. `retrospective-benchmark`：历史已办案件验证。必须先冻结首次起诉前 cutoff、输入集和答案集；裁判、调解、撤诉、执行及历史成果在独立起草冻结前不得读取正文。

模式不明时进入 `HOLD-MODE`，不得默认按历史案件继续起诉。

## 路由

主路由只有四类：

- `ordinary-goods-sale`
- `installment-title-retention`
- `mixed-cause-boundary`
- `HOLD-ROUTE`

次标签可以叠加：

- `reconciliation-confirmation`
- `quality-quantity-defense`
- `guarantee-security`
- `party-name-misroute-warning`

对账单只补强买卖链，不替代合同、交付、验收和付款归属；主体名称或文件夹名称不得决定案由。详见 [案型路由](common/案型路由.md)。

## 强制顺序

### P0-1 材料可读性与来源

逐文件记录格式、页数、完整 sha256、页码或段落 locator、可读性和重复项。扫描件、旧 Office 文件及 OCR 镜像须回看原页；关键金额、日期、主体、条款和签章不得只靠 OCR。

在读取正文前先按程序阶段和证明目的分类。诉前合同、订单、交付、调试、验收、对账、付款及银行流水可以进入诉讼输入候选；起诉后诉讼材料、裁判、执行材料、历史律师成果和答案键必须独立隔离。文件名、文件夹名或同名表格不能代替主体、内容、日期、公式和金额链核验。详见 [材料相关性与程序阶段甄别](common/材料相关性与程序阶段甄别.md)。

### P0-2 模式门

- `production-intake`：核验在先程序、重复起诉、管辖和本次诉请隔离。
- `retrospective-benchmark`：核验 cutoff、输入/答案物理隔离、后见污染和解封时间。

任一失败只允许输出缺口表，不得进入可提交 L1。

### P0-3 SSOT 与一致性

先建立 SSOT，再生成文书。主体、合同、标的、交付、验收、付款、余额、通知、时效、担保、管辖、诉请、证据编号和法源状态只能从 SSOT 派生，禁止各文书独立重算。

金额表须同时检查公式态、缓存值和逐行 Decimal 复算，记录分期到期日、约定费率、付款冲抵顺序、计算截止日及继续计算公式。局部尾差先标记为局部冲突并查明来源，不得在其他独立来源能够互证时机械否定整份材料。详见 [金额链与违约金复算](common/金额链与违约金复算.md)。

### P0-4 法院体例

L1 必须绑定 `court_profile_id`，采用法院提交体例并通过中文、表格、分页和逐页渲染检查。未冻结 court profile 时 L1 为 HOLD。

## 输出分层

- **L1 法院提交层**：民事起诉状、证据目录。仅在四级 P0 门均通过时可标注为提交候选。
- **L2 专业服务层**：合同审查方案、材料缺失清单、代理词、法律意见书、诉讼案件办案方案工作底稿、质证预案。
- **条件性文书**：仅在收到、编号并清点对方具体证据后，才可生成正式质证意见。

每项 L2 结论必须绑定证据编号、匿名原件 locator、条款/页码、计算和法源状态。风险必须包含 `severity + likelihood + impact_on_claim + evidence_basis`，不得虚构概率。

## 事实与证据状态

- `verified`
- `single-source`
- `ocr-only`
- `conflict`
- `missing`
- `not-applicable`

未知事实使用“待核实”“待补充”“以原件为准”等可见占位。占位不得静默保留在提交候选中。

## 硬停止

| HOLD | 触发条件 | 允许输出 |
|---|---|---|
| `HOLD-PRIVACY` | 身份、账户、联系方式、凭证或绝对路径进入非授权包 | 隐私处置记录 |
| `HOLD-READABILITY` | 关键原件不可读、缺页或镜像未核 | 可读性缺口 |
| `HOLD-CUTOFF` | 历史样本首次起诉 cutoff 无一手依据 | 隔离清单与补证要求 |
| `HOLD-ANSWER-KEY` | 答案键隔离无法证明 | 污染审计 |
| `HOLD-ROUTE` | 买卖与借贷、融资租赁、承揽、追偿等关系冲突 | 路由差异表 |
| `HOLD-PRIOR-PROCEEDING` | 在先程序或重复起诉风险未闭合 | 在先程序核验表 |
| `HOLD-EVIDENCE` | 权利基础、交付、价款、时效、保证或管辖缺证 | 材料缺失清单 |
| `HOLD-LEGAL` | 决定性法源未按当前日期核验 | 法源检索任务 |
| `HOLD-CONSISTENCY` | SSOT、金额、证据编号或跨文书冲突 | 差异表 |

任何 HOLD 均不得被“低置信度”掩盖，也不得输出“可直接提交”“必赢”或“无风险”。

## 隐私与发布

本包不得包含原始案卷、真实身份映射、答案键、历史结局、账户、联系方式、运行缓存、凭证、令牌、本机绝对路径或外部关系。所有逐案输出只能进入获授权的本地案件工作区。未经用户另行明确授权，不上传 GitHub、微信公众号、GBrain、Wiki、扣子、商店或其他平台。

## 包组成

- `legal/`：现行法官方来源矩阵、双时态适用路由、法院体例来源及来源快照清单。
- `templates/`：九份匿名 Markdown 与可编辑 DOCX 模板；正式质证意见生成门默认关闭。
- `testing/`：正向、反向、边界、隐私、过期法源、误用、retrospective 盲测和事实变体回归。

- `GEO.md`、`llms.txt`、`llms-full.txt`：仅投影通用方法、边界和作者署名，不含客户案情或结果保证。

## 验收与使用门

本包基于已独立验收的 Stage11 匿名模板冻结，并在桌面封装时再次执行结构、路由、隐私、DOCX、ZIP 和哈希复核。验收席不得读取隔离答案键或修改冻结产物。真实个案只有在 SSOT、事实日期、证据 locator、金额计算、管辖和全部 P0 门逐案闭合后，才能生成提交候选。

## VIS 机器边界（正典声明）

- VIS 唯一输入 = 同案独立 `frozen-07`（独立冻结的 07 工作底稿四件套）＋ `A01-A09` 九锚精确集；除此之外任何文本、SSOT、其他文书或跨案数据均不得作为 VIS 输入。
- VIS 默认关闭（default_enabled=false）；关闭态不得存在任何视图产物。
- fail-closed 条件（任一命中即 HOLD、零产物）：TEXT 未过、`frozen-07` 缺失、`frozen-07` 哈希不符、跨案路径或 case_id、`A01-A09` 锚集不全或失配、VIS 关闭却存在产物。
- VIS 不回写文本链与全局案件状态；九 DOCX/九 PDF 在 VIS 前后逐字节不变。
