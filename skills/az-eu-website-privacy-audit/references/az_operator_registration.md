# 阿塞拜疆运营者登记——审计参考

当审计到达报告中的“运营者登记评估（阿塞拜疆）”部分（SKILL.md 工作流第 8 步）时加载。

## 这是什么

依第 998-IIIQ 号法律，某些类别的个人数据信息系统的运营者必须在阿塞拜疆主管机关维护的**个人数据信息系统国家登记册**中登记该系统。信息系统类别由下位法规（内阁部长令）界定。

由于监管架构经历过重组（登记职能在不同机构间迁移过），审计报告中应称“阿塞拜疆主管机关”，并注明“与用户 / 数字发展和交通部核实当前名称”。除非用户提供，不要捏造或断言具体当前机构名称。

## 为何对网站审计重要

大多数通过表单、账户、KYC 流程或关联可识别用户的分析收集个人数据的商业网站，都在监管意义上运营信息系统。因此审计至少需要确定：

1. 用户的处理是否可能属于登记要求覆盖范围。
2. 隐私通知是否提及运营者的登记状态（系统类别、登记编号或类似标识符）。
3. 控制者是否具备登记所预设的基本记录保存。

仅凭网站无法确证登记——确认需要对国家登记册进行核查。在报告中明确说明该限制。

## 审计检查点

### 可能需登记的指标

满足以下**任一**条件时，增加用户必须登记的可能性：

- 网站有用户账户（登录/密码）。
- 受监管活动的 KYC、身份核验或入驻流程（金融服务、电信、网约车、带付款的市场平台）。
- 收集健康、生物特征或其他特殊类别数据。
- 18 岁以下儿童是可预见的用户群体。
- 处理规模可观（大众市场消费者网站、跨境流量、营销数据库）。
- 跨境数据转移是正常运营的一部分。

如满足三项或以上，将登记问题评为**可能需要——与国家登记册核实**。

### 较低风险指标

满足**全部**以下条件时降低可能性：

- 网站是静态信息页，无表单、无账户、无关联可识别用户的分析。
- 联系通过非识别渠道（通用电话号码、邮寄地址）。
- 无跨境处理。

即便如此，也不要断言“无需登记”——将评估记为**可能不需要——与律师核实**。

### 应查找的网站信号

- 隐私通知中关于控制者已在国家登记册登记并附系统标识符的声明。
- 单独的“个人数据处理信息”页面，反映登记通常包含的披露内容。
- 该披露的阿塞拜疆语版本政策通常比英语版本更完整。比较两者。

## 审计中要生成的发现表条目

在报告第 8 步，生成一个小表格：

| 问题 | 发现 | 状态 |
| --- | --- | --- |
| 网站的处理是否属于需要登记的信息系统类别？ | 可能 / 或许 / 不太可能 / 未核验 | — |
| 隐私通知是否提及登记？ | 是 / 否 | 绿色 / 黄色 / 红色 |
| 控制者的法律身份是否充分披露以允许登记核验？ | 是 / 否 | 绿色 / 红色 |

最后用一句话建议用户是否应在进一步推进前向主管机关核实登记状态。

## 此处不做的事

- 不就登记的实际申请程序、费用或时限提供建议——这些超出评估范围。
- 不断言用户目前是否已登记。
- 不确切点名当前监管机构（架构已变化）。
