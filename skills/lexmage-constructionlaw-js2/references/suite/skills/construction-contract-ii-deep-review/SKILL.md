# 《建工解释二》深度审查

共享知识库根目录：`../construction-contract-ii-router/references/knowledge-base`

## 必须读取

1. `../construction-contract-ii-router/references/common-protocol.md`
2. 知识库 `00-知识库导航与使用边界.md`
3. 知识库 `07-AI审查规则与触发词典.md`
4. 知识库 `09-争议问题与禁止过度推论.md`
5. [深度审查矩阵](references/deep-review-matrix.md)

收到文件、长材料或多份材料时，读取总控 `references/intake-and-delivery.md`。缺少关键事实时，从总控 `references/issue-question-cards.md` 选择问题。交付前读取并执行总控 `references/final-quality-gate.md`。

先用知识库 `07-AI审查规则与触发词典.md` 覆盖23条，再从 `02-二十三条逐条精解.md` 精读命中条文，不必把所有条文无差别加载。根据争议再读取知识库 `04`、`05`、`06`、`08`；需要引用原文时读取 `official/01-法释2026-12号全文.md`。

## 工作流

### 1. 建立四条事实链

- 主体与资质链；
- 合同与请求权链；
- 施工、质量与结算链；
- 资金、到期与已付款链。

分别标注已证明、当事人陈述、推断和未知。

存在多份材料时，先建立材料编号、统一时间轴、主体名称表和金额表；任何矛盾单独列示。

### 2. 先做前置判断

依次判断：

1. 第23条时间适用；
2. 招投标与合同效力；
3. 具体违法施工身份；
4. 工程范围和质量；
5. 债权性质、数额和到期；
6. 被告与请求权基础；
7. 优先受偿、时效和程序风险。

### 3. 对每个争点建立闭环

必须写明：

- 已知事实；
- 隐藏变量；
- 现行规则；
- 构成要件匹配；
- 支持证据与缺口；
- 对方最强抗辩；
- 分情形结论；
- 下一步行动。

### 4. 进行金额和请求权拆分

分别处理工程价款、折价补偿、工资、利息、违约金、停窝工损失、修复费、质保金和优先受偿范围。不要用一个“工程款”概念混合全部项目。

### 5. 给出诉讼结构

需要诉讼建议时，列明：

- 适格原告、被告和第三人；
- 每一项诉讼请求及请求权基础；
- 管辖、鉴定、保全和举证安排；
- 对方可能反诉或抵扣；
- 不能同时成立或需要备位表达的路径。

## 输出要求

先给当前可执行结论，不要把“还需材料”当作拒绝分析的理由。事实不足时按不同情形给结论，并只追问3—5个会改变判断的问题。

使用 [深度审查矩阵](references/deep-review-matrix.md) 的结构；对重大结论注明法源层级和审查基准日。
