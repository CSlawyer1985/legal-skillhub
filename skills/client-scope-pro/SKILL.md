# ClientScope Pro — 企业客户法律背调与服务机会识别（V2）

## 1. Skill 目标

当用户输入一个中国境内企业名称时，基于公开渠道完成企业背景调查，生成律师首次拜访前可直接使用的成套交付物：

1. **主报告**：《企业客户背景调查及法律服务机会分析报告》（Word，五部分结构，可点击目录，含释义节）；
2. **附件 PDF**：《风险模块与证据材料汇编》（按服务优先级重排、与主报告互相索引的 Evidence Pack 汇编）；
3. **证据包**：官方原始文件 PDF（按 A01、A11、A12… 编号存放于 evidence/ 子目录）。

核心目标不是生成企业百科，而是回答：作为准备第一次拜访该企业的律师——哪些事实已可靠核验？哪些存在不确定性？意味着什么潜在法律问题？应向客户核实什么？哪些事项可能转化为法律服务需求？

## 2. 核心原则（不可让步）

- 准确性 > 信息数量；一级信源 > 二手报道；事实核验 > 模型推断；可回溯性 > 表面完整性。
- 不得为报告完整而虚构、推测或补齐不存在的信息；不得伪造附件。
- 全部内容严格区分四类标注：**【已核验事实】【主体观点】【分析判断】【待核实】**，不得互相改写。
- 无法回溯官方原始信源的重大不利事项一律标注【待核实】。

## 3. 执行流程

### STEP 1 主体确认
确认企业完整名称、统一社会信用代码、曾用名、注册地址、法定代表人、成立时间、上市状态及代码、控股股东、实际控制人、关键子公司。存在同名/集团/母子公司/曾用名时先做主体消歧。主体未确认不得进入深度调查。注意新旧公告中持股数、称谓的矛盾（实践案例：协议转让公告与后续定期报告持股数不一致——必须标【待核实】并双向列明）。

### STEP 2 企业分类
判断企业类型（上市/非上市/国有/民营/外资/初创）、行业、业务、商业模式、经营区域、发展阶段，动态确定调查重点。上市公司必须启用专项模块：年报、审计意见、问询函、监管措施、股份质押冻结、风险警示、立案调查、纪律处分。

### STEP 3 检索矩阵
覆盖 23 个基础模块：工商股权／实控人／董监高／重大历史变更／主营业务／主要资产／投融资／对外担保／诉讼仲裁／执行／破产重整／行政监管／行政处罚／环保／安全生产／劳动用工／知识产权／数据网络安全／税务／重大合同项目／重大债务／控制权稳定性／重大舆情。按行业增加专项模块（制造：环保、安全、产品责任、供应链；房地产：土地、项目公司、融资、工程、预售）。

### STEP 4 信源管理与证据保存
开始检索前读取并执行 [`references/source-ranking.md`](references/source-ranking.md)。重大不利事项必须回溯至官方原始披露或监管决定原文；无法回源标【待核实】。**证据保存实操要点**（本 skill 相对 V1 的新增内容）：
- 巨潮资讯网托管 PDF 直接下载常被 403 拦截；先试直链，失败后带浏览器 UA＋Referer 重试，仍失败则：①寻找深交所官网（disc.static.szse.cn / reportdocs.static.szse.cn）托管的同名公告作**替代存证**（往往存在早前版本的同类公告）；②以权威媒体全文转述核验内容；③在附件索引中如实记录 URL 与"未保存（403）"，**不得伪造附件**。替代存证文件命名为 A11、A12 等延续编号并在索引中注明对应关系。
- 下载后用 `file` 命令校验是 PDF 而非 403 HTML 页面。

### STEP 5 重大事项核验
读取并执行 [`references/verification-rules.md`](references/verification-rules.md)，对重大诉讼、执行、失信、行政处罚、刑事风险、股权冻结、债务逾期、担保风险、破产重整、审计异常、证券监管、控制权变化等完成核验，建立 Fact Card（字段见该文件）。

### STEP 6 分析与综合
- 每一重要事项按"事实→影响→法律问题→服务机会→建议核实"五层模型分析；
- 近 3—5 年重大事件生成时间轴并做连续性分析（区分事实/相关性/推断，不得因时间接近认定因果）；
- 服务机会分高/中/储备三级，每项写明触发事实、判断依据、潜在服务、建议询问问题，不得只给评级。

## 4. 交付物结构（V2 关键变化）

生成成果前必须读取并执行 [`references/report-template.md`](references/report-template.md)（内容结构）与 [`references/format-spec.md`](references/format-spec.md)（排版规范与生成管线）。

**主报告采用五部分结构**（实战验证的逻辑合并方案，避免章节割裂）：
- 第一部分：引言（目的和使用／**释义**／信源原则与核验规则／相关基准日／执行摘要）
- 第二部分：主体确认与企业分类（保留企业基础信息表）
- 第三部分：风险与服务机会——将"重大事项核验＋检索矩阵概览＋服务机会识别"按具体事项合并，每事项五层结构呈现，服务机会嵌入各事项并汇总
- 第四部分：重大事件时间轴与连续性分析
- 第五部分：访谈与材料清单——合并"会谈作战卡＋待核实清单＋附件索引＋质量审核记录"

**弱化表格原则**：仅保留必要表格（企业基础信息表、释义表、时间轴表、附件索引表）；其余内容一律用多级层级文字呈现，基础事实完整保留在正文并通过 Fact ID 标注溯源（不设独立 Fact Card 汇总表）。

**附件 PDF 汇编**（Evidence Pack 的重组呈现，与主报告配套交付）：
- 按主报告"服务机会优先级汇总"重排为 7 个模块（高优先级→中优先级→储备→附录），每个模块统一体例：对应关系与衔接逻辑→核心事实要点→证据材料清单→访谈建议→待核实事项；
- 编制说明内置"附件模块↔主报告位置↔Fact ID"三向对应表，实现主报告与附件内容一一对应；
- 附录：A 证据材料总索引／B 已存证原始文件清单／C 待核实事项汇总清单；
- 格式要求：可点击跳转的目录（带页码）、PDF 书签、页脚页码、每部分前分页、统一黑白灰表格且表格行不跨页。

**用户默认指令**："背调：XXX"＝完整流程（主报告＋附件 PDF＋证据包）；"快速背调"＝仅执行摘要、重大风险、服务机会、会谈问题（此时不生成 Word/PDF，先文字交付）；"深度背调"＝完整检索＋核验＋附件整理。分阶段执行时只交付当前阶段内容。

## 5. 最终质量审核（输出前逐项检查）

主体错配／无来源金额／无来源案件／以搜索摘要代替原始信息／把媒体报道当确定事实／把企业自述写成客观事实／把 AI 分析写成事实／遗漏重要日期／过期信息／新旧信息冲突（含公告间持股数矛盾、业绩口径差异，须按"更正或待核实"处理）／重大不利信息依据／核心判断可回溯／URL、日期、文件名、附件编号齐备／Fact ID 三向追溯（正文↔Fact Card↔附件索引）／四个 references 文件均已读取执行。发现问题时先修正再输出。

交付时向用户说明：references 文件缺失时的降级原则（按 SKILL 正文原则执行并注明），以及证据包中未存证文件的复核建议。
