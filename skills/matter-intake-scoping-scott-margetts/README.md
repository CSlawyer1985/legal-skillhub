# matter-intake-scoping

覆盖完整执行前弧线的事项范围界定——从非结构化客户数据到结构化简报，再到其他所有 LPM 学科都引用的约定基线，并含一个事项中途恢复模式，用于 LPM 接手时没有书面基线的情形。

## 本技能的用途

四种运行模式：

**模式 1——委托前：** 接收客户发来的任何内容——邮件、组织结构图、资料室索引、通话记录——并将其整理为合伙人可以据此撰写报价方案的结构化简报。检测来源间的冲突、为每个数据点应用置信度标签、标记外部知识考量，并生成优先级排序的待解决问题清单。不撰写报价方案；但让它变快。

**模式 2——快速接案：** 委托确认后立即运行。以结构化格式捕获约定范围基线——包含项、排除项、假设、约束、里程碑、费用基础——由 scope-change-controller 在事项整个生命周期内管理。生成 LPM 参与定义，供与合伙人确认。

**模式 3——全面接案：** 模式 2 加完整利益相关方矩阵、全面假设日志、成功标准、初步风险登记册和启动会议议程。适用于大型或复杂事项。

**模式 4——事项中途恢复：** 从计费数据和往来函件反向工作，重建原始范围基线，识别什么发生了变化以及如何变化，并生成结构化的差异表和向 scope-change-controller 的交接。这是最常见的实际入口点。

## 文件夹结构

```
matter-intake-scoping/

├── README.md                                 # 本文件
└── references/
    ├── standing-assumptions.md               # 假设表现登记册——填充本文件
    └── matter-type-profiles/

```

## 提供什么与不提供什么

**提供：** 方法论——模式、工作流、置信度标注系统、冲突检测逻辑、输出格式、跨技能交接点、M365 连接模式指引。

**不提供：** 法律和运营内容。`references/` 文件是刻意留空脚手架。其结构已定义；其内容属于部署该技能的律所。

这一区分是刻意为之。组织客户数据和捕获范围基线的方法论是通用的、可迁移的。关于德国解散项目通常哪些假设成立、哪些司法管辖区要求哪些监管申报、以及奥地利合规实体结构长什么样的具体知识——那是律所积累的实务专长。它应留在律所，而非由第三方编码。

## 您的律所需要填充的内容

**`references/standing-assumptions.md`**

按事项类型划分的假设表现登记册——哪些假设一贯成立、哪些被打破、后果如何。随时间从事项复盘积累。技能的模式 1 和模式 2 消费此文件，生成经校准的假设候选清单，而非不加批判地沿用上一个事项的清单。

先从您最高频事项类型上最常见的三种失败模式入手。由此扩展。

**`references/matter-type-profiles/[type].md`**

每种事项类型一个文件（例如 `corporate-dissolution.md`、`cross-border-merger.md`）。每个画像识别该事项类型通常相关的知识领域——适用哪些监管阈值、产生哪些执行要求、常见哪些假设。复制 `template.md` 并填充。

技能在模式 1 的第 1 步路由到这些画像。没有已填充的画像，技能仍可工作——它回退到一般知识并标记差距。有了已填充的画像，它会自动浮出事项类型特定的标记。

## v2 架构说明

本技能设计为引用插件根目录层级的 `shared-knowledge/` 层——由部署律所填充并被 LPM 和律师技能共同消费的法律和法域知识文件（执行要求、实体类型、监管阈值）。该层尚未构建。构建后，本技能的路由机制已设计为使用它。`references/` 中的 `matter-type-profiles/` 文件是桥梁——它们指向 shared-knowledge 领域而非直接包含法律内容。

## 跨技能交接

- **到 scope-change-controller：** 模式 2/3 的范围摘要是 SCC 管理的基线。随“使用此范围摘要设置范围基线”一并传递。
- **到 risk-and-issues-manager：** 初始假设日志成为 RAID 日志中的 A 条目。
- **到 budget-and-fee-manager：** 范围参数是自下而上预算构建的输入。
- **来自 continuous-improvement-engine：** 事项结束时的假设表现数据回填 `references/standing-assumptions.md`。没有它，学习循环就没有再入口点。
