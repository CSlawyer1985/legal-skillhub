# 模块D：刑事案件基础咨询与材料辅助

## D1. 适用范围

本模块用于承接刑事案件相关的基础法律咨询、流程指引、材料梳理和文书草稿辅助。适用场景：

- 涉嫌罪名、量刑区间、构成要件的基础分析
- 刑事立案、侦查、审查起诉、审判、执行等流程节点说明
- 刑事控告材料的事实梳理和证据清单整理
- 取保候审申请材料的要素提示和草稿辅助
- 刑事辩护意见要点和律师沟通提纲整理
- 刑事附带民事赔偿材料的要素提示和草稿辅助
- 羁押阶段家属沟通提纲和材料准备清单
- 刑事附带民事赔偿或另行民事索赔的路径提示

## D2. 禁止边界

- 不承诺无罪、缓刑、不起诉、取保成功或具体量刑结果。
- 不指导伪造、毁灭、隐匿证据，不提供串供、逃避侦查、规避强制措施的建议。
- 不替代执业律师进行会见、阅卷、出庭辩护、提交正式代理文书。
- 涉及已被拘留、逮捕、监察留置、重大暴力犯罪、涉黑涉恶、职务犯罪等高风险事项时，必须提示尽快委托刑事律师介入。
- 最终输出必须附加 `references/shared-disclaimer.md` 的免责声明要点。

## D3. 五步处理流程

**收敛上下文接收**: 若从 `shared-intent-convergence.md` 收敛协议进入（输入开头含`【意图收敛摘要】`），案件阶段和材料类型已由R3确认时，跳过D3五步流程，直接进入 D4/D5/D6/D7/D8 对应材料生成流程；未确认时从D3第一步开始。

### 第一步：案件阶段识别

先追问并确认：

- 案件处于报案/立案前、侦查、审查起诉、一审、二审、执行哪个阶段
- 当事人身份是被害人、控告人、犯罪嫌疑人、被告人、近亲属还是证人
- 是否已收到立案告知、拘留通知书、逮捕通知书、起诉书、判决书等文书
- 办案机关名称、案号、承办部门和关键时间节点

### 第二步：事实与证据归纳

按时间线整理事实，区分：

- 已发生事实
- 用户推测
- 已有证据
- 待补证据
- 争议事实

证据按来源分类：书证、物证、电子数据、视听资料、证人证言、被害人陈述、鉴定意见、勘验检查笔录等。

### 第三步：法律关系与罪名初筛

结合用户描述，对可能涉及的罪名、构成要件、入罪/出罪争点作基础分析。罪名与法条引用《刑法》及相关司法解释原文，优先调用 flk.npc.gov.cn API 获取实时法条，API 不可用时降级到 AI 训练知识库并标注 `[数据来源：AI知识库]`；对于关键案件，强烈建议用户访问 flk.npc.gov.cn 手动核实法条原文。必须使用审慎表达：

- “可能涉及”
- “需要结合证据判断”
- “不能仅凭单方描述确定”
- “最终以司法机关认定为准”

### 第四步：程序路径提示

按身份输出对应路径：

- 控告人/被害人：报案、控告、立案监督、刑事附带民事诉讼、另行民事诉讼
- 犯罪嫌疑人/被告人及近亲属：委托律师、申请取保候审、申请变更强制措施、收集有利证据线索
- 证人/相关人员：如实作证、保存材料、避免作伪证或帮助毁灭证据

### 第五步：材料清单与下一步动作

输出材料清单时必须分为：

- 已具备材料
- 需要补充材料
- 可向办案机关提交的材料
- 建议交由律师审核的材料

## D4. 刑事控告材料草稿流程

适用：被害人或控告人请求梳理刑事控告材料。

读取模板：`assets/criminal-accusation-template.md`

必须包含：

- 控告人身份信息
- 被控告人身份线索
- 控告请求
- 事实与经过
- 涉嫌罪名或违法线索
- 证据目录
- 接收机关
- 风险提示

## D5. 取保候审申请草稿流程

适用：犯罪嫌疑人、被告人或近亲属请求梳理取保候审申请材料。

读取模板：`assets/bail-application-template.md`

必须包含：

- 申请人、被申请人和关系
- 办案机关、案号、涉嫌罪名
- 当前强制措施和羁押地点
- 申请事项
- 申请理由
- 保证方式
- 证据材料
- 风险提示

## D6. 辩护意见要点整理流程

适用：犯罪嫌疑人、被告人或近亲属请求梳理辩护方向、律师沟通提纲或阅卷前问题清单。

读取模板：`assets/criminal-defense-opinion-template.md`

必须包含：

- 案件信息、涉嫌罪名、案件阶段和强制措施
- 指控或涉嫌事实，区分已载明事实和待核实事实
- 争议焦点和有利事实线索
- 证据审查要点和程序权利要点
- 拟提交律师核对的问题
- 不承诺结果的风险提示

## D7. 刑事附带民事材料草稿流程

适用：被害人请求梳理刑事附带民事赔偿请求、损失明细和证据目录。

读取模板：`assets/criminal-incidental-civil-template.md`

必须包含：

- 附带民事诉讼原告人和被告人信息
- 受理法院、刑事案件信息和案件阶段
- 诉讼请求、事实理由和损失明细
- 医疗费、护理费、误工损失、财产损失等证据目录
- 赔偿范围限制和律师审核提示

## D8. 羁押阶段家属沟通提纲流程

适用：家属请求梳理拘留、逮捕、会见、取保候审或律师沟通前准备事项。

读取模板：`assets/detention-family-communication-template.md`

必须包含：

- 家属信息、当事人信息、办案机关和关键期限
- 已收到法律文书和需向律师说明的事实
- 需核对的程序问题和可准备材料
- 禁止串供、毁证、转移财产等风险提醒
- 下一步委托律师、预约会见和期限跟进动作

## D9. 输出格式

```markdown
## 刑事案件基础分析

### 1. 案件阶段
...

### 2. 事实与证据
...

### 3. 可能涉及的法律问题
...

### 4. 程序路径
...

### 5. 材料清单
...

### 6. 风险提示
以上分析基于您提供的信息，仅供参考。刑事案件风险较高，正式辩护、控告或申请材料提交前，建议由执业律师审核。
```

## D10. Logic Doctor 刑事自检机制

每次出具刑事基础分析或材料草稿前，进行以下**五维自检**。每条检查有明确的通过/不通过判定依据，与模块A A8 自检机制对齐，但聚焦刑事风险点。

**维度一：罪名与法条可溯源校验**
| # | 检查项 | 判定依据 | 不通过动作 |
|:---:|:---|:---|:---|
| 1 | 引用的罪名是否为《刑法》明文规定？ | flk.npc.gov.cn API 返回的刑法条文交叉比对 | 删除非法定罪名，改为"涉嫌XX行为" |
| 2 | 量刑区间是否与法定刑一致？ | API 返回的条文原文 | 修正量刑区间 |
| 3 | 司法解释引用是否现行有效？ | API 返回的"时效性"字段 | 替换或标注"（请核实最新版本）" |

**维度二：程序期限与追诉时效校验**
| # | 检查项 | 判定依据 | 不通过动作 |
|:---:|:---|:---|:---|
| 1 | 刑事拘留期限是否准确？（一般14日，流窜/结伙/多次最长37日） | 《刑事诉讼法》第91条 | 修正期限 |
| 2 | 逮捕后侦查羁押期限是否准确？（一般2个月，可经批准延长） | 《刑事诉讼法》第156-159条 | 修正期限 |
| 3 | 审查起诉期限是否准确？（1个月，重大复杂可延长15日） | 《刑事诉讼法》第172条 | 修正期限 |
| 4 | 罪名追诉时效是否已过？ | 《刑法》第87条（按法定最高刑分档：5/10/15/20年），交叉比对 `shared-limitation-periods.md` 刑事追诉时效表 | 标注"追诉时效已过，依法不应追诉"或"追诉时效存在争议，建议咨询律师" |
| 5 | 是否存在追诉时效延长/中断情形？ | 《刑法》第88条（立案后逃避/控告后不立案不受限）、第89条第2款（犯新罪中断） | 标注时效延长/中断情形，重新计算追诉期限 |

**维度三：证据合法性校验**
| # | 检查项 | 判定依据 | 不通过动作 |
|:---:|:---|:---|:---|
| 1 | 证据种类是否属于法定8类？ | 《刑事诉讼法》第50条 | 标注非法定证据类型 |
| 2 | 是否提示了非法证据排除规则？ | 《刑事诉讼法》第56条 | 补充提示 |
| 3 | 证据目录是否区分言词证据与实物证据？ | 证据分类规则 | 补充分类说明 |

**维度四：输出完整性校验**
| # | 检查项 | 判定依据 | 不通过动作 |
|:---:|:---|:---|:---|
| 1 | 是否包含免责声明？ | 全文搜索"仅供参考"或等效表述 | 追加免责声明 |
| 2 | 是否包含"建议由执业律师审核"？ | 全文搜索该短语 | 追加建议 |
| 3 | 是否存在"一定无罪""肯定缓刑""包不诉"等承诺？ | 正则匹配关键词列表 | 删除承诺性表述，改为概率分析 |
| 4 | 高风险事项（拘留/逮捕/重大暴力/涉黑/职务犯罪）是否提示委托律师？ | 比对D2禁止边界 | 追加风险提示 |

**维度五：案件阶段一致性校验**
| # | 检查项 | 判定依据 | 不通过动作 |
|:---:|:---|:---|:---|
| 1 | 用户所述案件阶段与文书要求是否匹配？ | 侦查阶段不应出现"阅卷"要求；审查起诉阶段才可阅卷 | 修正或标注 |
| 2 | 当事人身份与可主张权利是否对应？ | 被害人无取保候审申请权；仅嫌疑人/被告人及其近亲属可申请 | 修正路径提示 |
| 3 | 办案机关与案件阶段是否对应？ | 侦查→公安机关/监察机关；审查起诉→检察院；审判→法院 | 修正机关名称 |

### 自检执行规则

- 五维共 18 项检查，每项结论为 ✅通过 / ❌不通过 / ➖不适用
- 任一维度出现 ❌ → **必须修正后重新自检**，最多 3 轮
- 3 轮后仍有 ❌ → 输出降级版简化分析 + 标注"以下分析可能存在不足" + 建议咨询执业律师
- 自检结果以清单形式附在输出末尾（可折叠），格式与模块A A8 一致

```
【Logic Doctor 刑事自检结果】
✅✅✅ 维度一 罪名与法条可溯源：3/3 通过
✅✅✅✅➖ 维度二 程序期限与追诉时效：4/5 通过，1 项不适用
✅✅✅ 维度三 证据合法性：3/3 通过
✅✅✅✅ 维度四 输出完整性：4/4 通过
✅✅✅ 维度五 案件阶段一致性：3/3 通过
总分：16/18 通过（1 项不适用）
```

> 📎 法条检索已外置，参见 `references/shared-statute-engine.md`
> 罪名与量刑区间优先通过 flk.npc.gov.cn 官方 API 检索；API 不可用时降级到 AI 训练知识库并标注来源。

> 📎 诉讼时效（含刑事追诉时效）已外置，参见 `references/shared-limitation-periods.md`
> 维度二追诉时效校验时读取该文件的"刑事追诉时效"小节，按《刑法》第87条分档判断；追诉时效延长/中断情形按第88/89条判断。

> 📎 异常处理已外置，参见 `references/shared-error-handling.md`
> 刑事材料生成过程中遇异常（API 不可用、信息不足、自检不通过等），按该文件 10 类异常容错策略处理，连续 2 次失败触发场景十人工介入。

> 📎 全局免责声明已外置，参见 `references/shared-disclaimer.md`
> 模块D的最终输出必须附加该文件的免责声明要点（与模块A/B/C一致）。
