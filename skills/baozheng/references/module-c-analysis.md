# 模块C：深度法条分析与法规检索增强

本模块全部法规检索统一使用 `scripts/flk_npc_client.py`（封装 flk.npc.gov.cn `/law-search/` API），确保数据的真实性和时效性。API 不可用时降级到 AI 训练知识库并标注来源。两大流水线：

**输出边界：** 模块 C 的法条分析、法规检索、类案验证和概念深挖均为 AI 辅助参考信息；最终输出必须附加 `references/shared-disclaimer.md` 的免责声明要点，不得承诺案件结果或替代执业律师意见。

| 流水线 | 来源 | 定位 | 数据源 |
|:---|:---|:---|:---|
| **四步深度分析流水线** | `README.md` 四步法 | 以已知法条为中心，结构化分析 → 概念深挖 / 体系定位 / 案例验证（三步并行输出） | 法条原文以 flk.npc.gov.cn 为准 |
| **六步法规检索增强工作流** | 本文件 C2 节 | 端到端法规检索，从检索主题出发，经获取层→分析层→输出层，产出6份交付物 | 全部走 flk.npc.gov.cn 官方 API |

## C0. 工作流选择指南

**收敛上下文接收**: 若从 `shared-intent-convergence.md` 收敛协议进入（输入开头含`【意图收敛摘要】`），直接按摘要中的意图类型选择C1/C2/C3工作流，无需重新判断。

```
用户输入
  ├─ 给了具体法条？ → 四步深度分析流水线（C1）
  │   例："分析民法典第577条"、"拆解劳动合同法第47条"
  │
  ├─ 给了法律问题/场景但没给法条？ → 六步法规检索工作流（C2）
  │   例："帮我做民间借贷的全面法规检索"、"劳动合同纠纷涉及哪些法条"
  │
  └─ 只问某个单一能力？
       ├─ "这个法条上下游是什么" → 体系定位（C1步骤2，单节点）
       ├─ "实践中怎么判" → 案例验证（C1步骤4，单节点）
       ├─ "XX概念什么意思" → 概念深挖（C1步骤3，单节点）
       └─ 税务关键词 → 先确认：仅财税检索（C3 standalone）还是六步全流程（C2）？
```

| 对比维度 | 四步深度分析 | 六步工作流 |
|:---|:---|:---|
| 入口 | 已知法条 | 检索主题/法律问题 |
| 核心动作 | 分析 | 检索 + 分析 |
| 产出数量 | 1-4 份报告 | 6 份交付物 |
| 耗时 | 较短 | 较长 |
| 数据依赖 | 法条原文来自 flk.npc.gov.cn | 全部来自 flk.npc.gov.cn + 公开案例检索 |

## C1. 四步深度分析流水线

### 流水线总览

```
步骤1（入口）: 法条结构化分析
  └─ 从 flk.npc.gov.cn 获取法条原文，6维度拆解
       │
       ├── 步骤2（并行）: 法条体系定位
       │     └─ 上下游关联网络 + 竞合分析
       │
       ├── 步骤3（并行）: 法律概念深挖
       │     └─ 模糊概念6维度深挖
       │
       └── 步骤4（并行）: 类案检索验证
             └─ 司法实践验证
```

**关键规则：**
- 步骤1 是**必选入口**，步骤2/3/4 是**并行可选输出**
- 步骤1 必须先从 flk.npc.gov.cn 拉取法条原文，确保条文准确
- 步骤2/3/4 无先后依赖，可同时产出

---

### 步骤1：法条结构化分析

**触发**：用户要求分析某法条。关键词："分析这条法律"、"拆解法条"、"构成要件"等。

**执行流程：**
1. 优先通过 `scripts/flk_npc_client.py` 从 flk.npc.gov.cn 获取法条原文；API 不可用时使用 AI 训练知识库兜底（详见 references/shared-statute-engine.md）
2. 以条文原文为基础，进行6维度拆解
3. 标注数据来源：`[数据来源：flk.npc.gov.cn]` 或 `[数据来源：AI知识库]`

**6维度分析规范：**

| 维度 | 分析内容 |
|:---|:---|
| **① 立法意旨** | 规范目的？解决什么社会问题？保护何种法益？ |
| **② 适用前提** | 激活条件：主体资格 / 行为要件 / 时间节点 |
| **③ 构成要件** | 拆解为若干要件，标注积极要件/消极要件，明确并列/递进关系 |
| **④ 法律效果** | 满足要件后的法律后果（权利产生 / 义务设定 / 责任承担） |
| **⑤ 但书与例外** | 是否存在例外情形？但书条款的适用范围？ |
| **⑥ 关联法条** | 上位规范 / 并列条款 / 下位细化（为步骤2/3/4提供线索） |

**输出格式：**

```
【法条结构化分析 — 四步流水线 步骤1】

**分析对象**：《法律名称》第X条
**条文原文**："……"（来源：flk.npc.gov.cn）

① 立法意旨
   · 规范目的 / 保护法益：……

② 适用前提
   · 主体条件 / 行为条件 / 时间条件：……

③ 构成要件拆解
   | # | 要件内容 | 性质 | 关系 |
   |:---:|:---|:---:|:---:|
   | 1 | …… | 积极 | 与2并列 |

④ 法律效果
   · 主要效果 / 附带效果：……

⑤ 但书与例外
   · 例外一 / 例外二：……

⑥ 关联法条（后续步骤线索）
   · 上位 → …… | 并列 → …… | 下位 → ……

▶ 下一步可选：体系定位(步骤2) / 概念深挖(步骤3) / 案例验证(步骤4)

⚠️ 法条原文以 flk.npc.gov.cn 官方数据为准，分析仅供参考。
```

### 步骤2：法条体系定位

**触发**："这个法条的上下游是什么"、"构建法条网络"、"竞合分析"。

**6维度分析规范：**

| 维度 | 内容 |
|:---|:---|
| **① 上位规范** | 宪法/基本法层面的上位依据 |
| **② 并列条款** | 同法/相关法中并列规范同一事项的条款（附对比表） |
| **③ 下位细化** | 司法解释 / 行政法规 / 部门规章对该条的操作细则 |
| **④ 程序衔接** | 管辖 / 举证责任 / 诉讼时效 |
| **⑤ 竞合分析** | 请求权竞合路径对比（违约责任 vs 侵权责任 vs 其他），各路径举证难度、赔偿范围、利弊 |
| **⑥ 体系思维导图** | 以该法条为中心，树形展示关联网络 |

**输出格式：**

```
【法条体系定位报告 — 四步流水线 步骤2】

**中心法条**：《法律名称》第X条

① 上位规范：……
② 并列条款对比表：
   | 法条 | 规范内容 | 适用差异 | 关系类型 |
   |:---|:---|:---|:---|
③ 下位细化：……
④ 程序衔接：管辖 / 举证 / 时效
⑤ 竞合分析
   | 路径 | 举证难度 | 赔偿范围 | 利弊 |
   |:---|:---:|:---|:---|
   ▶ 建议：……
⑥ 体系思维导图

⚠️ 关联法条索引以 flk.npc.gov.cn 官方文本为准。
```

### 步骤3：法律概念深挖

**触发**：法条中的模糊概念。关键词："合理期限"、"重大误解"、"明显不当"、"如何界定"。

**6维度分析规范：**

| 维度 | 内容 |
|:---|:---|
| **① 立法原意** | 立法者引入该概念的价值考量和利益衡量 |
| **② 学理通说** | 主流法学理论的定义和解释框架 |
| **③ 司法解释** | 最高法是否对该概念有明确司法解释或指导意见（以 flk.npc.gov.cn 获取的司法解释原文为准） |
| **④ 裁判标准** | 法官认定的判断要素清单（含权重和判断方法） |
| **⑤ 边界案例** | 正例×2（构成该概念的典型情形）+ 反例×2（接近但不构成） |
| **⑥ 常见误区** | 实务中容易混淆或错误适用的情形 |

**输出格式：**

```
【法律概念深挖报告 — 四步流水线 步骤3】

**分析对象**：「XXX」概念
**出处**：《法律名称》第X条

① 立法原意：……
② 学理通说：……
③ 司法解释（来源：flk.npc.gov.cn）：
   · 《XXX司法解释》第X条：……
④ 裁判标准（判断要素清单）：
   | 要素 | 权重 | 判断方法 |
   |:---|:---:|:---|
⑤ 边界案例：正例×2 / 反例×2
⑥ 常见误区：……
```

### 步骤4：类案检索验证

**触发**："实践中怎么判"、"有没有类似案例"、"法院怎么看"。

**核心铁律：** AI 生成的案例信息必须标注"请通过中国裁判文书网/北大法宝/法信交叉验证"。无法确认案号的标注为"典型情形"。

**6维度分析规范：**

| 维度 | 内容 |
|:---|:---|
| **① 典型适用场景** | 该法条在司法实践中最常见的3类案件类型 |
| **② 裁判分歧点** | 不同法院/地区的理解差异（附倾向性判断） |
| **③ 指导性案例** | 最高法指导性案例/公报案例的核心裁判要旨 |
| **④ 高频败诉原因** | 当事人援引该法条却败诉的最常见原因（≥3个） |
| **⑤ 法官审查重点** | 法官适用该法条时的核心审查要素 |
| **⑥ 实务建议清单** | 基于裁判实践的可操作建议 |

**输出格式：**

```
【类案检索验证报告 — 四步流水线 步骤4】

**验证对象**：《法律名称》第X条
**法院层级覆盖**：最高法 / 高院 / 中院

① 典型适用场景（3类） / ② 裁判分歧表 / ③ 指导性案例
④ 高频败诉原因（≥3） / ⑤ 法官审查重点 / ⑥ 实务建议清单

⚠️ 案例信息请通过中国裁判文书网/北大法宝/法信交叉验证
```

## C2. 六步法规检索增强工作流

### 流水线总览

```
【获取层 — 并行启动】
  步骤1：官方 API 法规检索 (flk.npc.gov.cn)
          按层级输出法规清单 + 核心法条原文
  步骤2：公开案例检索
          搜索引擎 + 裁判文书网 + 财税专项（如适用）
                    ↓（合并，流入分析层）
【分析层 — 串行】
  步骤3：法条结构化分析
          对步骤1输出的核心法条做6维度拆解
                    ↓
  步骤4：法条体系定位
          关联网络 + 竞合分析（复用C1步骤2规范）
                    ↓
【输出层 — 串行】
  步骤5：类案检索验证
          基于步骤2案例 + 步骤3/4分析结果，复用C1步骤4规范
                    ↓
  步骤6：法律概念深挖
          优先深挖步骤5暴露的争议概念，复用C1步骤3规范
```

**关键规则：**
- 步骤1 和 步骤2 **并行启动**检索（各自独立获取数据，无依赖）
- 步骤2 的最终发布需等待步骤1完成后，以官方法条结果交叉验证案例中引用的法条
- 步骤3 依赖步骤1 的法规清单和法条原文
- 步骤4 依赖步骤3 的核心法条 + 步骤1 返回的关联法条原文
- 步骤5-6 依次依赖前序步骤产出
- 每步产出可作为独立报告输出
- **所有法条检索必须通过 flk.npc.gov.cn 官方 API，不得使用第三方非官方数据源**

### 各步骤详解

| 步骤 | 层级 | 数据源 | 输入 | 产出 |
|:---:|:---:|:---|:---|:---|
| 1 | 获取层 | **flk.npc.gov.cn 官方 API** | 检索主题 | 法规清单（按层级排列）+ 核心法条原文 |
| 2 | 获取层 | 搜索引擎 + wenshu.court.gov.cn + 财税专项 | 检索主题 | 案例检索报告 + 法规政策汇编 |
| 3 | 分析层 | —（基于步骤1产出） | 步骤1的法规清单+法条原文 | 核心法条结构化分析报告 |
| 4 | 分析层 | —（基于步骤1+3产出） | 步骤1返回的关联法条原文 + 步骤3的核心法条 | 法条关联网络图 + 竞合分析 |
| 5 | 输出层 | —（基于步骤2+3+4产出） | 步骤2案例 + 步骤3/4分析 | 类案验证报告（裁判分歧+败诉原因+实务建议） |
| 6 | 输出层 | —（基于步骤3+5产出） | 步骤3法条 + 步骤5争议概念 | 关键概念深挖报告（裁判标准+边界案例） |

### 步骤1：官方 API 法规检索（flk.npc.gov.cn）

**架构：** 复用 references/shared-statute-engine.md（flk.npc.gov.cn API 优先；不可用时降级到 AI 训练知识库并标注来源）。

```
检索主题关键词
  → flk.npc.gov.cn /law-search/ 官方 API（超时8秒，默认返回相关法条及原文）
  → API 失败/超时 → 降级到 AI 训练知识库 + 标注 [数据来源：AI知识库] + 建议访问 flk.npc.gov.cn 核验
  → 格式化输出：按法律层级排列
```

**检索策略：**
1. 按检索主题提取关键词，调用官方 API 查询
2. 按法律层级排列结果：宪法 > 法律 > 行政法规 > 司法解释
3. 输出格式：法规名称 + 条文号 + 条文原文（直接引用 API 返回内容，不做改写）

**输出格式：**

```
【法规检索结果 — 六步工作流 步骤1】

**检索主题**：[用户问题]
**数据来源**：国家法律法规数据库（flk.npc.gov.cn）

📜 法规层级汇编

| 层级 | 法规名称 | 相关条文 | 条文原文 |
|:---|:---|:---|:---|
| 法律 | 《民法典》 | 第X条 | "……" |
| 司法解释 | 《XXX解释》 | 第X条 | "……" |

> 以上条文原文均来自 flk.npc.gov.cn 官方 API 实时返回。
```

### 步骤2：公开案例检索

**数据源：**
- 中国裁判文书网（wenshu.court.gov.cn）—— 公开裁判文书
- 搜索引擎 —— 补充检索
- 财税专项：国家税务总局（chinatax.gov.cn）/ 财政部（mof.gov.cn）

**检索策略：**
1. 按争议类型构建检索关键词
2. 优先检索裁判文书网公开案例
3. 财税场景追加国家税务总局/财政部公告

**检索不可用降级策略：**
> 中国裁判文书网（wenshu.court.gov.cn）需要登录/验证码，API 检索经常不可用。按以下策略处理：
>
> | 场景 | 处理方式 |
> |:---|:---|
> | 裁判文书网不可用 | 使用搜索引擎检索公开裁判文书摘要（如"XX案 裁判要旨"），在输出中标注"案例信息来源于搜索引擎聚合，非裁判文书网直接查询" |
> | 搜索引擎也无相关案例 | 跳过步骤2案例检索，步骤5-6改为**纯法条分析模式**（仅基于步骤1+3+4的法规分析产出），在步骤5输出中注明"因案例检索数据不足，本报告仅含法条分析，缺少类案验证" |
> | 财税专项站点不可用 | 跳过财税政策汇编，在输出中注明"财税法规政策部分暂缺，建议手动访问 chinatax.gov.cn / mof.gov.cn 补充" |
>
> **核心原则**：步骤2检索失败**不阻断后续步骤**，步骤5-6可降级为纯法条分析模式继续执行。

**财税关键词策略：**
- 按税种：增值税 / 企业所得税 / 个人所得税 / 土地增值税 / 印花税
- 按争议类型：计税依据争议 / 税收优惠争议 / 程序合规争议 / 反避税争议

**案例分析框架：**

| 维度 | 内容 |
|:---|:---|
| 案件基本信息 | 案号/法院/当事人/争议类型 |
| 争议焦点 | 核心法律争议点（1-2个） |
| 法院观点 | 裁判核心理由 |
| 法律依据 | 引用法条（以步骤1官方API结果交叉验证） |
| 裁判结果 | 胜诉方/部分支持 |
| 参考价值 | 对类似案件的指导意义 |

**输出格式：**

```
【案例检索报告 — 六步工作流 步骤2】

**检索主题**：[法律问题/场景]

⚖️ 典型案例

| 案号 | 争议焦点 | 裁判要旨 | 参考价值 |
|:---|:---|:---|:---|
| …… | …… | …… | 高/中/低 |

📜 法规政策汇编（财税专项）
（如适用，按层级排列：法律 > 行政法规 > 部门规章 > 公告）

⚠️ 案例信息请通过中国裁判文书网（wenshu.court.gov.cn）交叉验证。
   法条引用以步骤1（flk.npc.gov.cn 官方 API）结果为准。
```

### 步骤3：法条结构化分析

复用 C1 步骤1 的6维度分析规范（立法意旨/适用前提/构成要件/法律效果/但书例外/关联法条）。

**输入差异：** C1步骤1 以用户指定的单一法条为对象；本步骤以步骤1输出的**核心法条集合**为对象，优先分析判决中最常引用的法条。

### 步骤4：法条体系定位

复用 C1 步骤2 的6维度分析规范（上位规范/并列条款/下位细化/程序衔接/竞合分析/体系思维导图）。

**输入差异：** C1步骤2 以单一法条为中心；本步骤以步骤3输出的核心法条集合为中心，构建跨法条关联网络。

### 步骤5：类案检索验证

复用 C1 步骤4 的6维度分析规范（典型场景/裁判分歧/指导案例/败诉原因/审查重点/实务建议）。

**输入差异：** 以步骤2案例 + 步骤3/4法条分析为双重输入，对法条集合+关联网络进行系统性案例验证，发现竞合场景下的裁判分歧。

### 步骤6：法律概念深挖

复用 C1 步骤3 的6维度分析规范（立法原意/学理通说/司法解释/裁判标准/边界案例/常见误区）。

**输入差异：** 以步骤3法条集合 + 步骤5案例验证中暴露的**争议概念集合**为对象，优先深挖裁判分歧较大的概念。

### 六步工作流 Init-Step-Poll 执行协议

> 注：本协议借自 Web 服务的 Init-Step-Poll 模式。在 AI Skill 对话场景下重新定义：Init=启动确认，Step=串行推进，Poll=每步完成后向用户输出进度摘要（非前端轮询）。

SKILL.md 要求本工作流按 Init-Step-Poll 协议执行，每步向用户报告进度。

#### Init 阶段（启动确认）

Agent 在启动六步工作流前，向用户发送确认话术（参见上文"六步工作流启动话术"），等待用户选择「全部执行」或「挑其中几步」后再启动。

确认后立即并行启动步骤1+2：
```
【Init】已确认检索主题：「{主题}」，启动获取层并行检索...
```

#### Step 阶段（串行推进）

步骤1+2 并行完成后，串行执行步骤3→4→5→6，每步开始前输出进度：

```
【Step 3/6】开始法条结构化分析（基于步骤1返回的 {N} 条核心法条）...
【Step 4/6】开始法条体系定位（关联网络 + 竞合分析）...
【Step 5/6】开始类案检索验证（基于步骤2案例 + 步骤3/4分析）...
【Step 6/6】开始法律概念深挖（聚焦步骤5暴露的争议概念）...
```

#### Poll 阶段（进度报告）

每步完成后输出该步的产出摘要（≤3句话），让用户了解进度，无需等待全部完成：

| 步骤 | Poll 报告模板 |
|:---|:---|
| 步骤1 | `已检索到 {N} 条法规，覆盖 {层级列表}，核心法条已提取。` |
| 步骤2 | `已检索到 {N} 个案例 + {M} 条财税政策，争议焦点已梳理。` |
| 步骤3 | `已完成核心法条结构化分析，{法条名} 第X条为主要适用依据。` |
| 步骤4 | `已输出法条关联网络，发现 {N} 处竞合关系。` |
| 步骤5 | `已完成类案验证，高频败诉原因已标注，实务建议已整理。` |
| 步骤6 | `已完成概念深挖，争议概念边界已厘清，全部交付物已产出。` |

**示例执行流程（民间借贷全面检索）：**

```
用户：帮我做民间借贷的全面法规检索
Agent：【Init】已确认检索主题：「民间借贷」，启动获取层并行检索...

Agent：✅ Step 2 完成：已检索到 12 个案例，争议焦点集中在利息计算和诉讼时效。

      ✅ Step 3 完成：已完成《民法典》第667条（借款合同定义）、第680条（禁止高利贷）等核心法条的结构化分析。

      ✅ Step 4 完成：已输出法条关联网络，发现民间借贷司法解释与民法典的 3 处竞合关系。
```

## C3. 财税案例法规检索独立使用

### 触发条件

关键词："税务"、"税"、"增值税"、"企业所得税"、"个人所得税"、"土增"、"印花税"、"发票"、"税务争议"、"滞纳金"等。

### 执行规范

1. **法规检索**：优先调用 flk.npc.gov.cn API 获取税收相关法律法规；API 不可用时降级到 AI 训练知识库并标注 `[数据来源：AI知识库]`；建议用户访问 flk.npc.gov.cn、chinatax.gov.cn、mof.gov.cn 核验最新政策
2. **政策检索**：建议用户访问国家税务总局（chinatax.gov.cn）、财政部（mof.gov.cn）公告
3. **案例检索**：建议用户访问中国裁判文书网（wenshu.court.gov.cn）查询税务行政案件
