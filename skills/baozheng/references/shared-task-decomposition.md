# 自动任务拆解协议

> 公共复用模块，被 `shared-intent-convergence.md` 第7节引用。
> 当收敛协议检测到混合意图或多领域问题时，自动拆解为有序任务队列，无需用户手动选择。

## 1. 触发条件

收敛协议完成 R1（领域）和 R2（意图）确认后，满足以下任一条件时触发：

| 条件 | 示例 |
|:---|:-----|
| 同一领域内咨询+起诉 | "我被欠薪了，想知道能赔多少，也想写劳动仲裁" |
| 查法条+起诉 | "帮我查劳动合同法，然后写起诉状" |
| 多领域混合 | "我被车撞了，对方还骗了我钱" |
| 刑事+民事并行 | "对方诈骗我，我要刑事控告也要民事起诉追回损失" |
| 同领域多个子问题 | "离婚要分财产，还有孩子抚养权，还有一套房子" |

**不触发的情况**（用户已明确单一意图，直跳）：

| 示例 | 原因 |
|:---|:-----|
| "帮我写离婚起诉状" | 单一意图，直跳 module-b |
| "我被骗了怎么办" | 单一意图（咨询），直跳 module-a |
| "我只想查一下劳动法" | 用户明确"只"做一件事 |

## 2. 拆解规则

### 2.1 意图→任务映射

| 意图类型 | 任务名称 | 目标模块 |
|:--------|:--------|:--------|
| 查法条/法规检索 | 法条检索 | module-c (C2) |
| 法条分析 | 法条深度分析 | module-c (C1) |
| 咨询分析 | 法律分析 | module-a (A2) |
| 起草起诉状 | 文书起草 | module-b |
| 刑事控告 | 控告材料 | module-d (D4) |
| 取保候审 | 取保申请 | module-d (D5) |
| 辩护意见 | 辩护要点 | module-d (D6) |
| 附带民事 | 附带民事材料 | module-d (D7) |
| 家属沟通 | 羁押沟通提纲 | module-d (D8) |

### 2.2 依赖排序规则

任务按以下优先级自动排序（数字越小越先执行）：

| 优先级 | 任务类型 | 理由 |
|:------|:--------|:-----|
| 1 | 法条检索(C2) | 下游任务需要法律依据 |
| 2 | 法条分析(C1) | 深度分析需要检索结果 |
| 3 | 法律分析(A) | 用户需要先了解权利再决定是否起诉 |
| 4 | 文书起草(B) | 起诉状建立在分析基础上 |
| 5 | 刑事材料(D) | 刑事材料通常独立于民事流程 |

**例外**：若用户明确表达顺序（如"先写起诉状再查法条"），以用户指定顺序为准。

### 2.3 同领域子问题合并

同一领域内的多个子问题**合并为一个任务**，不拆分：

| 用户输入 | 拆解结果 |
|:--------|:--------|
| "离婚，要分财产，还有孩子抚养权" | 1个任务：离婚纠纷（case-02），模块B追问时覆盖财产分割+抚养权 |
| "被车撞了，对方还打了我" | 2个任务：交通事故(case-07) + 人身损害(case-28)，不同案由 |
| "公司欠薪还违法开除" | 1个任务：劳动争议(case-08)，涵盖欠薪+违法解除 |

**合并判断**：是否属于同一个案由模板。属于→合并；不属于→拆分。

### 2.4 跨领域拆分

不同法律领域的问题**拆分为独立任务**：

| 用户输入 | 拆解结果 |
|:--------|:--------|
| "被车撞了，对方还骗了我钱" | 任务1：交通事故(case-07) → 任务2：民间借贷/诈骗(case-01) |
| "离婚，公司股权也要处理" | 任务1：离婚(case-02) → 任务2：公司股权(case-16) |

## 3. 任务队列格式

拆解完成后，向用户输出任务计划：

```
📋 任务拆解
根据您的需求，自动拆分为以下 N 个任务（按依赖顺序执行）：

1. [任务类型] 任务描述 → 目标模块
2. [任务类型] 任务描述 → 目标模块
...

─────────────────────────────────
开始执行任务 1/N ...
```

**示例**：

```
📋 任务拆解
根据您的需求，自动拆分为以下 3 个任务（按依赖顺序执行）：

1. 法条检索 检索《劳动合同法》关于欠薪和违法解除的条款 → 模块C
2. 法律分析 评估欠薪金额、赔偿金计算 → 模块A
3. 文书起草 劳动争议仲裁申请书 → 模块B（case-08）
─────────────────────────────────
开始执行任务 1/3 ...
```

## 4. 执行协议

### 4.1 顺序执行

任务按队列顺序逐个执行，每个任务完成后输出进度：

```
✅ 任务 1/3 完成：法条检索 — 已获取《劳动合同法》第38/46/47/85条
─────────────────────────────────
开始执行任务 2/3 ...
```

### 4.2 上下文传递

前置任务的输出作为后续任务的输入：

| 前置任务 | 传递内容 | 后续任务使用方式 |
|:--------|:--------|:--------------|
| 法条检索(C2) | 相关法条原文 | 法律分析(A)中引用；文书起草(B)中作为法律依据 |
| 法条分析(C1) | 构成要件分析 | 法律分析(A)中作为论证基础 |
| 法律分析(A) | 赔偿金额、法律结论 | 文书起草(B)中填写诉讼请求和事实理由 |

传递方式：在后续任务的【意图收敛摘要】中追加"前置任务输出"段。

### 4.3 失败处理

若某个任务执行失败（如 API 不可用）：

- 标注 `⚠️ 任务 X/N 部分完成：` + 原因
- 后续任务**不跳过**，继续执行（有前置输出的用前置输出，没有的用通用知识）
- 最终汇总时标注哪些任务未完成

### 4.4 最终汇总

全部任务执行完毕后，输出汇总：

```
📊 任务执行汇总
✅ 1/3 法条检索 — 已获取相关法条
✅ 2/3 法律分析 — 欠薪3个月，赔偿金约XX元
✅ 3/3 文书起草 — 已生成劳动争议仲裁申请书
─────────────────────────────────
以上为本次全部任务的执行结果。如有遗漏，请告诉我。
```

## 5. 用户中断

执行过程中，若用户中途打断（如"等一下，我只想要起诉状"）：

- 立即停止当前任务
- 确认用户意图
- 按用户新指令调整任务队列

## 6. 与收敛协议的衔接

收敛协议第7节（混合意图处理）的完整流程：

```
检测到混合意图或多领域
  ↓
启动本协议：拆解 → 排序 → 合并 → 输出计划
  ↓
按计划顺序执行任务
  ↓
最终汇总
```

**不再询问用户"先做哪个"**——仅在以下情况询问：
- 两个任务依赖关系不明确（如"刑事控告和民事起诉，哪个先？"各有利弊）
- 用户需求本身矛盾（如"我要起诉他但不想去法院"）
