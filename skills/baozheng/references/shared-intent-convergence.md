# 渐进式意图收敛协议

> 公共复用模块，被 SKILL.md、module-a 引用。
> 当用户输入意图不清晰时，按本协议逐步收敛，直至可派发到目标模块。

## 1. 协议总览

### 1.1 适用时机

- 用户输入**无法直接路由**到 A/B/C/D 任一模块时，启动本协议
- 用户输入**可直接路由**时（见第2节直跳规则），**不启动本协议**，直接派发

### 1.2 核心原则

1. **直跳优先**: 意图清晰时零轮次收敛，不浪费用户时间
2. **普通人语言**: 提问用日常用语，不暴露A/B/C/D模块名
3. **每轮必推进**: 每个收敛轮次必须获取至少一个确定性信息
4. **上下文传递**: 收敛中提取的事实传递到目标模块，不重复问
5. **用户选择优先**: 混合意图时询问用户偏好，不硬性路由
6. **最多3轮**: R1→R2→R3，超过3轮仍未收敛则走兜底路由（module-a A2流程）

### 1.3 状态机

```
用户输入
  │
  ├─ domain=HIGH ∧ intent=HIGH → S_SKIP（直跳目标模块）
  │
  ├─ domain=HIGH ∧ intent<MEDIUM → S_R2（第二轮）
  │
  ├─ domain<MEDIUM → S_R1（第一轮）
  │
  └─ domain=MEDIUM ∧ intent=MEDIUM → S_R1（保守策略）

S_R1 → domain确认 → S_R2 → intent确认 → detail不足? → S_R3 → S_DISPATCHED
                                                      ↓
                                                 detail充足 → S_DISPATCHED

S_R1连续2次未收敛 → 兜底路由 module-a A2

任意状态检测到用户转向 → S_RESTART → S_R1
```

## 2. 直跳规则（零轮次收敛）

以下输入模式**直接派发**，不启动收敛协议：

| 输入模式                                 | domain     | intent | 直跳目标            |
| :--------------------------------------- | :--------- | :----- | :------------------ |
| "帮我写XX起诉状"                         | 依XX定     | B      | module-b + 对应case |
| "起草离婚/劳动/借贷……诉状"               | 依关键词定 | B      | module-b + 对应case |
| "刑事控告/取保候审/辩护意见/羁押沟通"    | 刑事       | D      | module-d + 对应流程 |
| "分析民法典第577条/拆解法条"             | 法条       | C1     | module-c C1         |
| "检索XX法规/涉及哪些法条"                | 法规       | C2     | module-c C2         |
| "XX合法吗/怎么办/赔多少"（无其他行为词） | 依上下文   | A      | module-a A2         |

**判定方法**: 用户输入同时包含**领域专有词**(HIGH)和**行为词**(HIGH)时直跳。

- 领域专有词(HIGH): 离婚、工资、辞退、借贷、交通事故、取保候审、行政处罚、消费欺诈、退一赔三、食品安全、网暴、名誉权、隐私权、建设工程款、股权转让、征地拆迁、商业秘密……
- 行为词(HIGH): 写起诉状、查法条、控告、分析法条、检索法规、取保候审申请、刑事附带民事、辩护意见、羁押沟通……

## 3. 置信度评估

### 3.1 domain 置信度

| 等级   | 判定                         | 示例                             |
| :----- | :--------------------------- | :------------------------------- |
| HIGH   | 输入含领域专有词且无歧义     | "离婚"→婚姻家事；"工资拖欠"→劳动 |
| MEDIUM | 含跨领域歧义词但有上下文倾向 | "赔偿"单独出现→MEDIUM            |
| LOW    | 只有通用词                   | "怎么办""合法吗""被骗了"         |

### 3.2 intent 置信度

| 等级   | 判定                 | 示例                     |
| :----- | :------------------- | :----------------------- |
| HIGH   | 用户明确说出了行为词 | "写起诉状"→B；"查法条"→C |
| MEDIUM | 表达倾向但未明确     | "能帮我写"→B倾向         |
| LOW    | 仅描述问题未表达行为 | "我被骗了"→不确定        |

### 3.3 歧义关键词消歧

参见 `shared-activation-rules.md` 第"跨领域关键词消歧规则"节（17条规则）。

## 7. 混合意图处理

### 7.1 检测

用户输入同时触发2个及以上intent的关键词时判定为混合意图。

### 7.2 自动拆解

检测到混合意图或多领域问题时，**不询问用户选择**，直接启动自动任务拆解：

→ 读取 `references/shared-task-decomposition.md` 并按该协议执行

拆解协议自动完成：意图→任务映射 → 依赖排序 → 同领域合并 → 跨领域拆分 → 输出任务计划 → 顺序执行 → 最终汇总。

### 7.3 仅以下情况询问用户

| 情况                                                       | 处理                               |
| :--------------------------------------------------------- | :--------------------------------- |
| 两个任务依赖关系不明确（如刑事控告 vs 民事起诉，各有利弊） | 简要说明利弊，让用户选择执行顺序   |
| 用户需求本身矛盾（如"我要起诉他但不想去法院"）             | 澄清矛盾点，确认真实意图           |
| 用户明确说"我只想..."                                      | 不拆解，直接执行用户指定的单一任务 |

## 8. 意图切换检测

### 8.1 检测规则

| 已确定状态 | 用户新输入        | 判定     | 处理               |
| :--------- | :---------------- | :------- | :----------------- |
| domain=X   | 明确转向不同领域Y | 完全切换 | 重置到S_R1         |
| intent=X   | 同领域内调整意图  | 意图微调 | 更新intent，不重启 |
| 正在处理   | 新增不同领域问题  | 新增意图 | 保留当前+排队      |

### 8.2 处理话术

完全切换:

> 好的，我们来处理您新提到的[新问题]。

意图微调:

> 明白了，那我按[新意图]来帮您处理。

新增意图:

> 好的，我先完成当前的[原任务]，然后帮您处理[新问题]。

## 9. 上下文传递

### 9.1 收敛事实提取

收敛过程中从用户输入提取的事实，以"上下文信封"形式传递到目标模块：

```
【意图收敛摘要】
领域：{domain} | 意图：{intent} | 目标：{target_module}
已提取事实：{从用户输入中提取的当事人、金额、时间、证据等}
已提及证据：{用户提到的证据类型}
─────────────────────────────────
```

### 9.2 目标模块衔接

| 目标模块 | 衔接方式                                                                     |
| :------- | :--------------------------------------------------------------------------- |
| module-a | 从A2步骤二（法律定性）开始，跳过部分事实梳理                                 |
| module-b | 直接进入B2第一步（案由已确定），用已提取事实预填追问项                       |
| module-c | 直接按C0工作流选择指南确定C1/C2/C3                                           |
| module-d | 直接进入D4/D5/D6/D7/D8对应流程（案件阶段和材料类型已在R3确认时），或D3第一步 |

## 10. 兜底规则

1. 收敛3轮仍未明确 → 走 module-a A2 通用咨询流程
2. R1追问2次用户仍无法明确 → 走 module-a A2
3. 用户拒绝回答收敛问题 → 直接走 module-a A2，以用户原始输入作为咨询起点
4. 任何异常 → 参见 `shared-error-handling.md` 场景一/三
