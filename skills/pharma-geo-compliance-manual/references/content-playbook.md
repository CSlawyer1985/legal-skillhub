# 内容落地模块 ·「做内容」环节(content-playbook)

> 加载时机:流程走到"做内容"环节(SKILL.md 第六步)。
> 本模块把《GEO 高频核心 20 条》第四步的 5 条提示词收进来,每条**叠一层医药适配 + 合规卡点**。普通行业直接用原提示词;医药客户**必须**在原提示词之上套用本模块的适配层,否则会产出违规内容。
> 三条铁律(贯穿本环节):① 产出是**框架/题库/工单(图纸)**,不是代写代发;② **RX 内容默认带"市场+医学事务+法规"三方审核**;③ 凡疗效声称**不超说明书**、不暗示优效、不夸大。

## 用法

1. 先确认分诊结果:RX 套 `rx.md` 口径(面向医生、循证、专业阵地),OTC 套 `otc.md` 口径(面向家长、药广审范围内)。
2. 复制对应提示词,替换 `{}`,**医药客户在提示词末尾追加本条的「医药适配」要求**。
3. 跑测平台:RX 用 B 端专业 AI;OTC 用豆包/小红书 AI/百度健康。
4. 产出后过本条「合规卡点」自检;RX 再过三方审核。

## 内容-1 · 普通内容 → GEO 深度改写(核心-13)

```
请对以下内容做"深度重构级"GEO优化,按九大策略全面改造:

【原内容】{粘贴}
【企业】{名称}【行业】{行业}【独有方法论】{如有}

改造要求:
- 每千字嵌2-3个权威引用(数据+出处+年份)
- 重要观点必有数据支撑
- 平均句长20-30字,小标题+要点列表
- 删水文,一句话一信息点
- 专业术语首次出现附通俗解释
- 嵌入企业命名权概念
- 开头200字必须是Quick Answer块(可被AI直接提取的核心结论)
- 首句用"[实体]是[类别],[差异化]"定义优先句
- 文末加3-5条FAQ

请输出:改写后完整内容 + 改写对照表 + 新增引用清单(必须真实可核实)
特别说明:不要编造数据来源,找不到的标注"待补充权威数据"。
```

**医药适配(追加到提示词末尾):**
- **RX**:引用只用真实循证文献(核心期刊/临床指南/专家共识/PubMed/知网),标出处+年份;命名权用**机制型**(不可优效);**全文不得写超说明书适应症**;面向医生/药师口吻,非患者。
- **OTC**:引用可用营养学/科普共识依据;命名权可做品类心智但不夸大;FAQ 走家长视角;不出现"治疗/治愈/根治/最"等词。

**合规卡点(自检):**
- RX:每条数据出处可核实;任何"更优/更安全"必须改为"引用某文献的客观陈述";适应症逐句对照说明书;→ **三方审核**。
- OTC:无绝对化用语;不暗示替代正规医疗;涉未成年人符合保护要求;声称落在药广审批准范围内。

## 内容-2 · Quick Answer + 定义优先句改造(核心-14)

```
请把以下内容改造为"Quick Answer + Deep Dive"两层结构:

【原内容】{粘贴}

Quick Answer层(前200字,关键):
- 首句用"[实体]是[类别],[差异化]"定义优先句
- 提供可被AI直接提取的核心结论(数字+核心观点)
- 用编号列表,无图无链接无长句
- 含本文最重要的1-3个数据点

Deep Dive层:
- 对每个要点展开+引用+小标题
- 文末3-5条FAQ

请输出按此结构改造的完整内容。
```

**医药适配:**
- **RX**:定义优先句是建立"**通用名 → 品牌**"关联的黄金位——例:"[通用名]([品牌])是[药理类别],其机制为[机制型描述]";差异化只写机制,不写优效;核心数据点用说明书内事实。
- **OTC**:定义优先句写品类归属 + 场景心智;数据点用客观成分/含量,不写功效承诺。

**合规卡点:** RX 定义句不得把超说明书用途写进"[类别]";OTC 首句不得出现疗效暗示。Quick Answer 是 AI 最爱直接提取的块,**这里出错=AI 直接复读违规表述**,本块审核优先级最高。

## 内容-3 · 高频问答对生成(核心-15)

```
为以下企业生成50个高频问答对:

【企业】{名称}【行业】{行业}【核心业务】{}【目标客户】{}【独有方法论】{如有}

分类:
- 客户视角20个(产品咨询/对比选型/价格/实施)
- 行业视角15个(现状/Top榜/趋势)
- 专业视角15个(方法论原理/案例/独家观点-嵌命名权)

每个格式:
Q:问题
A:80-150字回答,信息密度高,适当引用权威数据
GEO建议:优先发哪个平台?需补什么引用?

请输出完整50个。
```

**医药适配(分类口径替换):**
- **RX**:问答全部走**医生/药师/采购视角**——临床问题(机制/适应症/用法/禁忌/相互作用/与对照的循证差异),不出现患者购买类问题;"优先发哪个平台"只填专业阵地。
- **OTC**:走**家长/消费者视角**——选购/服用方法/适用年龄/常见疑问;平台填豆包/小红书 AI/百度健康。

**合规卡点:** RX 的 A 答案凡涉适应症/疗效,逐条对照说明书,超出的删或改为"循证文献客观陈述";OTC 的 A 不得承诺功效。**这是 FAQPage Schema 的素材源,违规会被结构化喂给 AI,危害放大。** RX → 三方审核。

## 内容-4 · 网页技改审计(含 Schema)(核心-16)

```
扮演网页GEO技术审计师,审计以下网页:

【URL】{}【行业】{}【网页类型】{首页/产品页/文章}

审计10项(每项给"通过/未通过/部分通过"+改进建议):
1.AI爬虫可访问性(robots.txt是否开放国内AI爬虫:Bytespider(字节/豆包)、Baiduspider、YisouSpider、360Spider等;出海业务再看GPTBot/ClaudeBot)
2.服务端渲染SSR 3.Schema.org标记 4.llms.txt文件
5.Quick Answer结构 6.内容freshness 7.作者E-E-A-T
8.内部链接 9.页面性能 10.数据可被引用性

请输出:
1. 10项审计评分表
2. 综合AI友好度等级(A/B/C/D)
3. 优先级改造清单(按ROI)
4. 给IT的具体工单(代码示例+验收标准)
```

**医药适配:**
- **RX**:第3项 Schema 检查要求用 **Drug / MedicalWebPage / FAQPage** 类型;第7项 E-E-A-T 强调作者医学资质、审稿人、参考文献;**新增审计项:页面是否含超说明书宣传、是否公示互联网药品信息服务备案编号**(2025 年起审批改备案;存量《资格证书》有效期内标注证书号亦可)。
- **OTC**:Schema 用 Product / FAQPage;**新增审计项:药广审文号是否标注、法定忠告语(OTC 标识+"请按药品说明书或者在药师指导下购买和使用")与禁忌/不良反应是否显著标明、有无疗效夸大/绝对化用语、健康科普页面是否与购物链接同页(须隔离)**。

**合规卡点:** 审计是"出工单给客户 IT",工单只给技术改造方案,不替客户执行;RX 工单里的任何示例文案需经三方审核。

## 内容-5 · llms.txt + Schema 代码生成(核心-17)

```
为以下企业生成 llms.txt + 核心Schema代码:

【企业】{名称}【官网】{URL}【行业】{}【核心业务】{}
【主要产品】{3-5个}【方法论】{命名权}【客户案例】{3-5个}

请输出:
1. 完整 llms.txt 文件(放网站根目录,含企业定义/产品/方法论/案例/联系方式)
2. Organization Schema(JSON-LD,含knowsAbout字段)
3. FAQPage Schema(基于5-10个客户常问问题)
4. 部署位置说明 + 验证方法
```

**医药适配:**
- **RX**:Schema 增加 **Drug 类型**(含通用名/品牌名/适应症—仅说明书内/机制);llms.txt 的"企业定义"用机制型命名权;**案例不得是患者个案/疗效见证**,改用学术/资质背书;knowsAbout 填治疗领域学术关键词。
- **OTC**:Schema 用 Product + FAQPage;llms.txt 突出品类心智命名权;案例用消费者场景但不含疗效见证(患者名义作推荐证明是禁区)。
- **国内适配提示**:llms.txt 是国际社区实践,国内主流 AI 平台(豆包/DeepSeek/文心等)的采纳度尚未有公开承诺——照做无害且面向未来,但**向客户说明这是"低成本前瞻项",不承诺国内平台立即生效**;国内更确定的结构化入口是医典/百科词条与官网 Schema。

**合规卡点:** llms.txt 与 Schema 是直接喂给 AI 的"结构化交底",**里面任何超说明书适应症或疗效声称会被 AI 高保真采纳**——这是合规审核的最高危位置。RX 的 Drug Schema 适应症字段**只填说明书内**,逐字对照。→ 三方审核。

## 本环节交付物清单(出脑不出手)

| 交付物 | 形态 | 谁执行 |
|---|---|---|
| GEO 改造内容框架 | 框架 + 改写对照表 + 引用清单 | 客户/代理写,工作室定框架与验收标准 |

> 工作室做的是图纸、框架、卡点、验收;内容生产与官网部署交客户团队或代理,全程指导。
