# 政府采购合规检查

输出可追溯的事实、规则、证据和整改动作。发现问题不等于直接定性违法；区分已证实、存在风险和资料不足。

## 首次响应与法源

确认委托视角、项目属地、采购方式、行为期间、检查目的、范围和材料。回显已收到/缺失文件、适用规则层级和可形成的结论范围。仅有片段时输出“初步风险清单”，不称完整报告。

按国家规则、地方规则、项目文件/平台规则三层建立法源快照，记录标题、文号、效力、适用期间、原文链接和检索日期。历史项目按行为发生时规则判断。

## 工作流

1. 建立计划/意向、文件及更正、开评标、结果、合同、履约、付款和救济时间轴。
2. 按视角检查采购需求与文件、采购程序、代理机构执业、供应商材料与竞争行为。
3. 每项记录依据、方法、事实、证据文件/页码、结论、等级和整改动作。
4. 使用符合规定、存在问题、不涉及、无法判断四态，不能在证据不足时强行判断。
5. 红色为可能影响效力或导致处罚；黄色为程序/管理问题；蓝色为规范瑕疵。说明后果和证据充分度。
6. 对歧视、虚假材料或串通线索列替代解释和需调取证据，不凭单一异常直接定性。
7. 形成责任人、材料、动作、期限和复核方式明确的整改计划。

## 固定输出

- 项目快照、检查范围、规则版本和时间轴。
- 工作底稿：`事项｜依据｜方法｜事实｜证据位置｜结论｜等级｜整改`。
- 已证实、待核验、资料不足三栏问题清单。
- 整改计划和证据调取清单。

正式检查表需要统一版式时读取 `references/inspection-worksheet.md`。

## 边界

- 不为迎检隐去问题或一律写合规。
- 不把程序瑕疵自动等同于影响中标结果。
- 不把年度专项整治通知当所有历史项目的直接处罚依据。
- 涉及处罚、犯罪移送或诉讼策略时，由经办律师结合完整证据和属地规则复核。
