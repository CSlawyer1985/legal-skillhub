# /closing-checklist

1. 读取 `$LEGAL_AGENT_PROFILE_HOME/corporate-legal/deals/[代码]/closing-checklist.yaml` 并使用以下模式。
2. 如有状态更新：使用模式3（更新项目）。
3. 否则使用模式4：阻碍事项、关键路径、距交割天数。

## 事项上下文

**事项上下文。** 检查实务级 CLAUDE.md 中的 `## 事项工作区`。如果 `Enabled` 为 `✗`（企业法务用户的默认设置），则跳过本段其余内容——技能使用实务级上下文，事项机制不可见。如果已启用且无活跃事项，请询问："这是哪个事项？运行 `corporate-matter-workspace switch <事项简称>` 或说 `实务级`。"加载活跃事项的 `matter.md` 获取事项特定上下文和覆盖规则。将输出写入事项文件夹 `$LEGAL_AGENT_PROFILE_HOME/corporate-legal/matters/<事项简称>/`。除非 `跨事项上下文` 为 `开`，否则绝不读取其他事项的文件。

## 目的

当检查表完成时，交易即交割。表上每一项，均已完成。无所遗漏。本技能维护清单，从尽职调查过程中发现新项目时将其纳入，并告诉团队阻碍因素。

## 模式

### 模式1：根据购买协议初始化

阅读已签署（或接近定稿）的购买协议。提取：

- 每项交割的先决条件（位置因协议而异——阅读实际的条款标题）
- 每项交割的交付物（交割交付物附表或相应条款）
- 每项含交割前截止日期的承诺

每项均成为检查表项目，并附有协议条款的来源引用。

**填充监管/审批项前的研究义务。** 反垄断、外商投资和特定行业审批（例如经营者集中申报、外商投资安全审查、行业监管部门审批）具有因法域而异的操作机制、阈值和时间窗口，且这些内容会发生变化。从购买协议中提取每项监管条件的名称，然后研究当前有效的操作机制（谁来申报、何时申报、什么会触发二次审查、等待期多长）。引用原始来源并核实其时效性。不要凭记忆填充时间假设。

**重大不利影响/重大不利变化交割条件。** 从收购协议中提取定义术语——重大不利影响/重大不利变化的措辞是谈判形成的结果，并非标准条款。在将某一事件标记为潜在的重大不利影响/重大不利变化触发条件前，需研究所用特定语言在适用法律下的解释（不同法域对待例外条款和量化检验的处理方式不同）。

**从重大合同中提取同意要求** 取决于适用法律的默认规则和各合同中具体的禁止转让条款表述。应逐份合同研究适用规则而非假设一个默认规则。

### 模式2：从尽职调查中提取（"自我更新"部分）

模式2在上游技能产出带有交割前行动的发现时触发。本模式接收的上游技能和输出类型包括：

- **`diligence-issue-extraction` 发现**——任何标记为交割行动的发现（如获取同意、股东表决、董事会决议、监管申报、解除函、托管机制、清偿函）。不仅限于"同意"——见提取技能的交接部分以获取完整列表。
- **`material-contract-schedule` 控制权变更/转让条款**——清单构建过程中出现的控制权变更条款、禁止转让条款、最惠国待遇触发条款。
- **`deal-team-summary` 输出**——执行层简报汇总了各项提取发现，有时会呈现某项仅单项提取备忘录的机械阅读会遗漏的交割行动项（例如横跨多份劳动合同的决议表决、或合成同意包）。模式2读取交易文件夹中最新的 deal-team-summary 并将其中的交割行动项与检查表核对。任何由 deal-team-summary 标记为需要交割前行动且尚未列入检查表的项目均予追加。

交接模式涵盖全部范围的交割前行动，不仅限于同意：

```yaml
handoff:
  # 必填字段
  item: "[对方当事人或行动，一行]"
  category: "[第三方同意 | 股东/董事会行动 | 监管申报 | 解除/终止 | 托管/扣留 | 交割交付物]"
  source: "[合同名称 / 法条章节 / 数据室路径 + 页码]"
  blocking: true  # 除非协议中含重大性限定条件
  severity: "[🔴 / 🟠 / 🟡 / 🟢 — 继承自上游，见 CLAUDE.md 中的严重程度下限规则]"

  # 同意/第三方行动字段
  counterparty: "[例如：某某有限公司]"
  guarantor: "[例如：需要买方母公司提供担保，或不适用]"
  conditions: "[对方当事人附加的任何实质性条件——例如'需买方母公司提供替代担保后同意始生效']"
  notice_deadline: "[例如：交割前30天，或具体日期]"

  # 公司行动字段
  approval_body: "[股东会 | 董事会 | 专门委员会 | 监管机构]"
  approval_threshold: "[例如：需经出席会议的股东所持表决权的三分之二以上通过]"
  statutory_or_charter_source: "[例如：《公司法》第120条；公司章程第四条第2节]"

  # 时间安排
  estimated_time_to_complete: "[例如：30天]"
  must_occur_before: "[例如：交割 | 签署 | 中断期结束]"
```

保留上游技能填充的每个字段。一项"需要或者某某同意，附带替代担保条件及30天通知期限"的要求，应在检查表上显示全部三个要素（同意、担保人、通知），而非压缩为"某某对控制权变更的同意"。当上游技能提供了严重性等级时，承继——见 CLAUDE.md 中的跨技能严重性等级最低标准规则。

将事项追加至检查表。按（对方当事人 + 行动类型）去重，而非自由填写的项目名——例如，一项某某同意和一项某某解除是不同的事项，尽管都提及某某。去重时，应合并字段而非覆盖：如果一个交接事项填充了 `guarantor`自动，另一个交接事项填充了 `notice_deadline`字段，则核对清单中的该行应同时包含两者。


## 关键路径分析

不是所有阻碍项都同等重要。一项需要30天取得的同意是关键路径。而一份需要2天即可取得的良好存续证明不属于关键路径，尽管两者都构成阻碍。

对每项阻碍项，预估其完成所需要的时间。如果 `(截止日 - 今天) < 估计时间` ，则该事项有风险。这些排在每份状态报告的顶部。

如果检查表有超过约10项，或用户任何时候提问：提供仪表盘试图（见 CLAUDE.md `## 输出规范 → 数据密集产出的仪表盘选项`）。根据本输出内容设计提供方式：按状态计数（已完成/进行中/未开始/有风险）、按工作流分组的关键路径视图，以及带项目、负责人、截止日和距截止天数的可排序网格。

## 集成：数据室监控代理

代理每日检查检查表，如已连接则从邮件/飞书拉取任何状态更新，并将"当前阻碍事项"报告推送到交易团队频道。模式4是该代理的输出。

## 后果性行动准入（证明交割）

**在产出"已可交割/全部交割先决条件已满足"确认书或交割备忘录前：** 读取 `$LEGAL_AGENT_PROFILE_HOME/corporate-legal/profile.md` 中的 `## 使用者`。如果角色为**非法务人员**：

> 证明交割先决条件已满足（或出具如此主张的交割备忘录）具有法律后果——这是驱动资金流转和交割后义务履行的信号。你是否已与律师审查？如已审查，继续。如未审查，以下是带给律师的简要说明：
>
> - 完整的交割先决条件清单及状态（哪些已完成、哪些进行中、哪些未开始）
> - 已完成证据薄弱或缺失的任何事项
> - 对无法按时交割的项目所需的任何豁免或补充函
> - 待决问题（对方同意仍在待定、任何重大不利影响/重大不利变化/陈述更新风险）
> - 需向律师咨询的事项（这是否已可召集交割；是否有正在被跳过的交割条件不应被跳过；哪些事项需要列入例外清单）
>
> 如需寻找律师：联系中华全国律师协会或所在地地方律师协会以获取推荐服务。

在获得明确同意前，不越过此准入产出最终的"已可交割"认证。状态追踪和"当前阻碍事项"报告不需要此准入。

## 本技能不做什么

- 不负责取得同意、提交表格或起草文件。仅追踪这些事项需要发生。
- 不决定什么构成阻碍——此由购买协议决定。本技能读取协议。
- 不负责完成交易。其告知您何时可以完成交易。
