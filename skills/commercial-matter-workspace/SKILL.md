# /matter-workspace

多客户执业者跨多个客户和事项工作。事项工作区将一个客户或委托的上下文与其他客户或委托隔离开来。本命令管理这些工作区。

## 子命令

- `commercial-matter-workspace new <slug>` — 创建新事项工作区，运行简短收案访谈，写入 `matter.md`
- `commercial-matter-workspace list` — 列出事项及其状态和当前标记
- `commercial-matter-workspace switch <slug>` — 设置当前事项
- `commercial-matter-workspace close <slug>` — 归档事项（移至 `_archived/`，绝不删除）
- `commercial-matter-workspace none` — 脱离任何当前事项，纯业务领域级工作

## 指令

1. 读取 `$LEGAL_AGENT_PROFILE_HOME/commercial-legal/profile.md`——确认 `## 事项工作区` 部分已填充。如果 `Enabled` 为 `✗`，告知用户：

   > "事项工作区已关闭——你被配置为仅服务一家公司的企业法务，插件自动使用业务领域级上下文。如果你实际上跨多个客户工作，重新运行 `commercial-cold-start-interview --redo` 并选择私人执业设置。否则，你根本不需要 `/matter-workspace`。"

   不要报错——关闭状态是企业法务用户的预期状态。

2. 按第一个参数标识子命令（`new` / `list` / `switch` / `close` / `none`），使用以下子命令逻辑分发。
3. 向用户展示变更内容并在写入前确认。

## 说明

- 除非业务领域级 CLAUDE.md 中 `跨事项上下文` 为 `on`，技能绝不跨事项读取文件。
- 归档不是删除——已关闭的事项保持可读状态以供保留/利益冲突目的。
- 简称使用小写加连字符。示例：`acme-msa-2026`、`zenith-renewal`、`vendor-xyz-nda`。如简称在已归档和当前事项中被重用，已归档的保留在 `_archived/<slug>/` 下。

---

多客户执业者（私人执业——个人执业、小型律所、大型律所）跨多个事项工作。一个事项的上下文不得泄露至另一个事项。这是本技能存在的保密承诺。

**默认状态为关闭。** 企业法务用户永远不会看到——他们仅以业务领域级别运行。事项工作区在冷启动时为私人执业用户开启，或通过编辑审查指引中的 `## 事项工作区` 部分开启。

## 存储布局

所有事项数据位于：

```
$LEGAL_AGENT_PROFILE_HOME/commercial-legal/
├── CLAUDE.md                       # 业务领域级审查指引
└── matters/
    ├── <slug>/
    │   ├── matter.md               # 客户、对方当事人、事项类型、关键事实、覆盖规则
    │   ├── history.md              # 日期化的事件日志（仅追加）
    │   ├── notes.md                # 自由形式的工作笔记
    │   └── outputs/                # 事项的技能输出（可选子文件夹）
    └── _archived/
        └── <slug>/                 # 已关闭的事项——可读但非当前
```

## 当前事项存于业务领域 CLAUDE.md

业务领域级 CLAUDE.md 中 `## 事项工作区` 下的 `Active matter:` 行是唯一真实来源。切换事项编辑该行。无独立状态文件。

## 子命令逻辑

### `new <slug>`

1. 确认简称在 `matters/<slug>/` 和 `matters/_archived/<slug>/` 中均未被占用。如被占用，要求用户选择其他简称。
2. 运行收案访谈：
   - **委托人**（我方代理的一方，或企业法务中的内部业务单元）
   - **对方当事人**（另一方——可能有多个）
   - **事项类型**（参照插件实务画像中的典型类别；商事合同领域：供应商主协议 | 客户协议 | 保密协议 | SaaS订阅 | 修订协议 | 续约 | 其他）
   - **保密级别**（标准 | 加强 | 清洁小组——加强级别在跨事项设置中提示额外注意）
   - **关键事实**（2-5句话：事项内容、利益方、风险所在、与默认审查指引的不同之处）
   - **事项特定覆盖规则**（如"客户要求责任上限24个月而非12个月""对方为战略合作伙伴——维护关系的语气"）
   - **关联事项**（任何关联事项的简称）
3. 使用以下模板写入 `matters/<slug>/matter.md`。
4. 种子 `matters/<slug>/history.md`，写入单条"已开立"条目。
5. 创建空 `matters/<slug>/notes.md`。
6. **不要**自动切换。询问："要现在切换至 `<slug>` 吗？（`commercial-matter-workspace switch <slug>`）"

### `list`

列举 `matters/*/matter.md`。读取每个文件的前几行提取状态。打印表格：

| 简称 | 委托人 | 事项类型 | 状态 | 开立时间 | 当前 |
|---|---|---|---|---|---|

当前事项标记 `*`。已归档事项在单独的"已归档"标题下列出（如有）。

### `switch <slug>`

1. 确认 `matters/<slug>/matter.md` 存在。如不存在，提示 `commercial-matter-workspace new <slug>`。
2. 将业务领域级 CLAUDE.md 中的 `Active matter:` 行更新为 `Active matter: <slug>`。
3. 向用户展示 matter.md 摘要，供其确认切换至正确的事项。

### `close <slug>`

1. 确认 `matters/<slug>/` 存在。
2. 向 `matters/<slug>/history.md` 追加含今日日期的"已关闭"条目。
3. 将 `matters/<slug>/` 移动至 `matters/_archived/<slug>/`。
4. 如果关闭的是当前事项，将 `Active matter:` 设为 `none — 仅业务领域级上下文`。

### `none`

将业务领域级 CLAUDE.md 中的 `Active matter:` 设为 `none — 仅业务领域级上下文`。与用户确认。

## matter.md 模板

```markdown
[工作成果文件头 — 按插件配置 ## 输出规范 — 因使用者角色而异]

# 事项：[委托人] — [简短描述]

**简称：** [slug]
**开立时间：** [YYYY-MM-DD]
**状态：** 进行中
**保密级别：** [标准 / 加强 / 清洁小组]

---

## 当事方

**委托人：** [名称]
**对方当事人：** [名称]

## 事项类型

[供应商主协议 | 客户协议 | 保密协议 | SaaS订阅 | 修订协议 | 续约 | 其他 — 附一行说明]

## 关键事实

[2-5句话。事项内容。利益方是谁。风险所在。与默认审查指引的不同之处。]

## 事项特定覆盖规则

*适用于本事项且仅限本事项、对业务领域级审查指引的偏离。*

- [如："责任上限：委托人要求24个月，而非审查指引标准12个月。"]
- [如："语气：维护关系——对方为战略合作伙伴。"]
- [如："管辖法律：须适用英国法，而非中国法。"]

## 关联事项

- [slug — 一行说明关联原因]

## 保密备注

[如为加强或清洁小组级别，说明原因。谁可以查看事项文件。即便全局开启跨事项上下文，本事项是否允许跨事项访问。]
```

## history.md 种子

```markdown
# 历史：[委托人] — [简短描述]

仅追加的事件日志。最新条目在顶部。

---

## [YYYY-MM-DD] — 事项开立

收案完成。简称：`[slug]`。状态：进行中。
[值得保留的初始上下文——如"响应[对方当事人]发来的主协议草稿而开立。"]
```

## 跨事项上下文

业务领域级 CLAUDE.md 有一个 `跨事项上下文:` 标记。当其为 `off`（默认）时，在事项A中工作的技能**绝不读取** `matters/B/` 中任何其他 `B` 的文件。这是该设置存在所提供的保密保证。

当其为 `on` 时，技能仅在用户明确要求时才跨事项读取文件（如"比较过去五份供应商事项中我方在责任上限的立场"）。即便为 `on`，默认仍仅加载当前事项，除非用户要求跨事项视图。

## 本技能不做的事

- **不运行利益冲突检查。** 利益冲突是执业者/律所的工作；收案只记录用户声明的内容。
- **不执行保留政策。** 关闭归档但不删除。保留政策不在范围内。
- **不自动路由输出。** 实质性技能决定写入什么；本技能告知哪个文件夹是当前的。
- **不决定跨事项是否合适。** 读取标记并遵从。
