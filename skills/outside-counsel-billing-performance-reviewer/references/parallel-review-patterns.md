# 并行审查模式

当发票数量足以支持子代理或并行审查时使用本参考。

## 良好的拆分模式
- 按律所
- 按事项
- 按发票批次
- 按季度或月份
- 按工作流，如合规、费率、人员配置和基准比较

## 对账规则
- 使用 [issue-taxonomy.md](issue-taxonomy.md) 保持单一主问题分类学
- 在所有子审查中使用相同的置信度标签
- 保留 `source_file`、发票 ID 和行 ID，避免重复发现
- 报告争议金额前先对重复问题对账

## 建议工作流
1. 一次性规范化源数据
2. 将规范化数据集拆分为不重叠的切片
3. 将每个切片分配给子审查员
4. 将输出合并为一份主问题日志
5. 进行最终检查，排查重复计算、比较基准不匹配和节省额虚增

## 何时不宜并行
- 发票数量很少
- 单一事项且所有结论均依赖同一预算或人员配置情境
- 环境无法安全协调子代理的审查
