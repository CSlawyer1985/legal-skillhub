# 文件导入规则

当用户上传混合文件类型或要求技能基于 CSV、Excel、LEDES、PDF、DOCX 或 JSON 工作时，使用本参考。

## 接受的输入
- `csv`、`tsv`
- `xlsx`
- `json`
- LEDES 式文本导出
- PDF 发票和 OCG（外部法律顾问指南）
- DOCX 或文本政策文件
- 如环境可解包，压缩的发票或导出包

## 来源优先级
1. 用户提供的 OCG、经批准的费率文件、预算、AFA（替代收费安排）和协商例外
2. 结构化账单导出，如 CSV、XLSX、JSON 或 LEDES
3. 发票 PDF 和仅叙述性材料
4. 仅经授权时的公开方向性材料

## 规范化规则
- 当两者都存在时，优先使用结构化导出而非从 PDF 手动提取。
- 分别规范化费用、支出、税费和贷项行。
- 尽可能保留源文件名、行号、发票 ID 和行 ID。
- 如果映射决定不确定，保留原始页眉。
- 如果多个源文件重叠，保留 `source_file` 或等效引用以进行对账。

## 规范数据预期
尝试规范化为 [PLAYBOOK-SCHEMA.md](../PLAYBOOK-SCHEMA.md) 中的账单事实字段。

## 实际使用
- 如果用户提供 CSV、TSV、XLSX、JSON 或 LEDES 式文本，优先使用 `scripts/normalize_billing_data.py`。
- 如果用户仅提供 PDF 或扫描件，说明提取质量可能实质性限制置信度。
- 如果工作簿包含多个工作表，除非明显，否则询问哪个工作表具有权威性。

## 注意事项
- 除非页眉和范围一致，否则不要假设工作簿选项卡可比较。
- 未经明确处理，不要合并不同货币。
- 不要用发票费率数据覆盖经批准的费率文件。
