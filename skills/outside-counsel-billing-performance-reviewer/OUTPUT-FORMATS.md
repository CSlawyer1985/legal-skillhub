# 输出格式

## 通用要求
每一份实质性交付物都应包含：
- 仅草稿和人工审查用语；
- 范围、审查期间和所审查文件；
- 数据质量和置信度局限；
- 事实、假设与判断性事项之间的明确区分；以及
- 仅在各项均有支持时，才包含审查时已识别的价值、潜在节省和已实现节省。

当用户询问最佳输出格式或请求 CSV、Excel、PDF 或可转 PowerPoint 的成品时，使用 [references/output-selection-guide.md](references/output-selection-guide.md)。
在生成 PDF、Word、PowerPoint 或其他视觉成品时，必须应用 [references/visual-output-rules.md](references/visual-output-rules.md)。

在生成任何文件成品或最终报告之前，确认或明确说明：
- 交付物类型；
- 输出格式；
- 目标受众；以及
- 保密或匿名化要求。

不要为输出格式或受众使用安全默认值。在生成最终交付物之前，向用户询问两者。
不要静默默认使用 markdown、DOCX、PDF、XLSX、CSV 或可转 PowerPoint 的输出。

## 1. 快速审计摘要
当用户需要简洁的发票审查或预账单审查输出时使用。

要求的章节：
1. 免责声明；
2. 范围与所审查文件；
3. 重点发现；
4. 关键指标；
5. 最高优先级的逐行或分类问题；
6. 可能改变结果的问题；以及
7. 建议的下一步行动。

## 2. 详细审计报告
用于争议准备、法务运营审查或大批量发票。

要求的章节：
1. 执行摘要；
2. 数据质量评估；
3. 按分类的合规发现；
4. 费率与折扣发现；
5. 人员配备发现；
6. 预算与预测发现（如可用）；
7. 对标发现；
8. 已识别价值与潜在节省；
9. 问题日志表；以及
10. 附录表格。

建议的问题日志列：
- 发票 ID；
- 行 ID；
- 案件；
- 计时人；
- 问题类别；
- 证据摘要；
- 置信度；
- 已计费金额；
- 有争议金额；以及
- 建议的行动。

使用 [references/issue-taxonomy.md](references/issue-taxonomy.md) 中的稳定问题标签。如用户需要可粘贴的审查表，使用 [references/dispute-log-template.md](references/dispute-log-template.md)。
对于 PDF 或 Word 输出，如描述或评估冗长，避免过宽过密的表格。改用简短摘要表加详细问题卡片或附录表格。

## 3. MBR 或 QBR
用于总法律顾问、法务领导层、管理层、财务或采购受众。

要求的章节：
1. 期间摘要；
2. 支出趋势与预算视图；
3. 律所比较；
4. 合规趋势视图；
5. 人员配备与费率趋势视图；
6. 预测与超支风险；
7. 显著的节省或价值机会；
8. 观察项与关系影响；以及
9. 下一期间的建议行动。

保持高管可读的口吻，避免在正文中堆砌逐行明细。
除非用户要求 MBR 或 QBR，或要求高管级或季度级报告，否则不要假设用户希望从单次发票审查中获得 MBR 或 QBR。
对于可转 PowerPoint 的输出，不要使用类似电子表格的密集表格。将内容拆分为摘要幻灯片和问题重点幻灯片，使用自动换行的要点或卡片。

## 4. 律所比较或律师库审查
当范围内有多家律所时使用。

要求的维度：
- 支出；
- 预算可预测性；
- OCG 合规；
- 人员配备效率；
- 折扣实现；
- 描述质量；
- 费率治理；以及
- 显著优势、风险和下一步行动。

## 5. 争议或谈判日志
当法务部门需要质疑点或谈话要点时使用。

对每个问题提供：
- 该费用是什么；
- 涉及哪条规则、商业条款或比较对象；
- 为何可能可被质疑；
- 什么澄清可以解决它；以及
- 建议的下一步。

不要夸大确定性或指控不当行为。
当用户需要可导出的日志时，优先使用 [references/dispute-log-template.md](references/dispute-log-template.md) 中的 CSV 或 markdown 结构。
对于 PDF 或 Word，优先使用问题卡片或含简短显示标签的 4 至 5 列表格，而非包含长篇理由文本的大型多列表格。

## 6. 高管记分卡
当受众想要一览式摘要时使用。

建议的记分卡维度：
- 合规；
- 费率纪律；
- 人员配备纪律；
- 预算可预测性；
- 描述质量；
- 响应性或执行信号（如提供）；以及
- 总体置信度。

始终随记分卡附上对评分依据的简短说明。

## 可选后续输出
在交付所请求的输出后，适合提及用户接下来可能需要的其他有用交付物，例如：
- 问题日志；
- 谈判要点；
- 高管记分卡；
- MBR；或
- QBR。

高管记分卡、MBR 和 QBR 是在相关时值得强调的重要选项。
除非用户请求这些额外输出或明确要求捆绑交付，否则不要生成。
如用户对其中一项或多项表示兴趣，在生成之前先提出该交付物所需的后续问题。
