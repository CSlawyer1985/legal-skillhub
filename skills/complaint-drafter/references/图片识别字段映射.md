# 起诉状图片识别与字段映射指南

本指南供专家在"用户上传起诉状图片"时，系统、完整地提取信息，并映射到要素式模板或一般起诉状结构。

## 一、识别前的准备（图片归一化）
若图片为手机照片、扫描件、尺寸过大或方向异常，先运行预处理脚本提升识别率：

```bash
python skills/complaint-drafter/scripts/preprocess_image.py <图片路径> --outdir <临时目录> --max-size 2200
```

脚本会按 EXIF 校正方向、缩放最长边至 2200px、另存为 PNG，并打印归一化后的路径列表。
随后用 **Read 工具**读取这些 PNG 图片（多页/多张图片逐张读取），进行视觉识别（OCR）。

> 若图片已经清晰、方向正确、尺寸适中，可跳过预处理，直接 Read 原图。

## 二、提取清单（逐项识别，缺失记"未识别"）
无论原图是"一般起诉状"还是"要素式起诉状"，都按以下清单提取：

### 1. 文书头
- [ ] 受诉法院（如"××××人民法院"）
- [ ] 文书标题（民事起诉状 / 行政起诉状 / 刑事自诉状 / 一般起诉状）
- [ ] 案由（若有）

### 2. 当事人信息
对每一位 原告 / 被告 / 第三人 / 委托诉讼代理人，提取：
- **自然人**：姓名、性别、出生日期、民族、公民身份号码、住所地/住址、联系电话、工作单位（如有）。
- **法人/非法人组织**：名称、住所地、法定代表人/主要负责人（姓名、职务）、统一社会信用代码（如有）、联系电话。

> 多原告/多被告：逐一编号（原告1、原告2…）。

### 3. 诉讼请求
- 逐条提取（"1. …；2. …"），保留原表述（金额、标的、履行方式）。

### 4. 事实与理由
- 提取关键事实脉络：法律关系的发生、履行/违约、争议焦点、损害结果、曾否协商等。
- 若为要素式模板图片，直接按模板字段（如"婚姻关系基本情况""借款金额""交付方式"）逐格提取。

### 5. 证据与证据来源、证人姓名和住址
- 逐条提取证据名称 + 证明目的。

### 6. 尾部
- 此致法院、具状人（签字/盖章）、日期。

## 三、案由推断
结合"诉讼请求 + 事实与理由 + 标题"推断案由，例如：
- 借贷/欠条/拒不还款 → 民间借贷纠纷
- 离婚/感情破裂/子女抚养/财产分割 → 离婚纠纷
- 交通事故/损害赔偿 → 机动车交通事故责任纠纷
- 买房/卖房违约 → 房屋买卖合同纠纷
- 拖欠工资/工伤/解除劳动关系 → 劳动争议纠纷
- 商标/专利/著作权侵权 → 对应知识产权案由
- 行政处罚不服 → 行政处罚（行政）

推断后回查 `references/67类要素式案由清单.md` 判定是否命中 67 类。

## 四、映射到生成数据
1. **命中 67 类（54 类起诉状模板）**：用 Read 读取 `references/templates/<对应文件>.txt`，将第二步提取的字段填入该模板的官方要素表，构造 `DATA`（见 SKILL.md 第六节 schema），运行 `generate_complaint_docx.py`。
2. **命中 damages/执行（13 类申请书）**：生成要素式申请书并说明文书性质。
3. **未命中**：按 `references/一般起诉状结构.md` 组织，构造 `DATA`（`include_notice=false`，`sections` 用 `free` 表达诉讼请求与事实理由，证据用 `rows`）。

## 五、识别质量与回退
- 若图片模糊、缺角、反光导致**关键信息无法识别**（如被告姓名、金额），不要臆造：
  - 在回复中列出"已识别"与"未能识别"的字段；
  - 请用户补充清晰图片或口述缺失项；
  - 可先生成带占位符的草稿，提示用户补全后我再定稿。
- 严禁将"未识别"字段填成编造内容，亦不得虚构事实（虚假诉讼须担责，见"说明"框）。
- 中文姓名/金额等易混淆处，若不确定请向用户确认，不要猜。
