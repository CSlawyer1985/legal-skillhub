# 法规检索 Skill

## 一、核心能力

1. 意图解析：识别法规依据查询、法规查找、时效核实、法规对比等意图。
2. 查询结构化：将自然语言提取为法规名称、核心制度、行为类型、条款号、地域、时效目标等检索要素。
3. 语义检索优先：对法律场景、自然语言问题、条文问题或材料摘要，优先保留完整语义关系。
4. 结果后处理：基于 CLI 返回结果完成时效性标注、条款定位、摘要提炼、关联法规推荐和对比呈现。
5. 多形态输出：支持条款详情、法规列表、法规对比、时效核实四种标准输出。

## 二、前置工作

命中本 skill 后，凡需要执行法规检索、条文定位、时效核实、法规对比、分页查看更多结果或调用后端能力，必须先执行 [deli-cli 通用前置](./references/cli-common.md)。

完成 CLI 前置检查后，通过当前 skill scope 发现命令，并以当次返回的 `RUN id`、命令名和参数形态执行；不得假设固定命令或固定参数存在。

如果 CLI 未配置、不可用或未返回覆盖当前任务的命令，应先说明“检索受限”或“命令不可用”，并给出建议检索式或需要用户补充的事实，不得编造法规信息。

## 三、触发条件

### 主动触发

- 法规依据查询：`"经济补偿有什么法律依据"`
- 法规查找：`"找关于经济补偿的现行有效法规"`
- 时效核实：`"这个法规还有效吗"`
- 法规对比：`"对比民法典和合同法关于违约责任的区别"`
- 概念定位：`"竞业限制的法规依据"`

### 不触发场景

- 纯理论法学问题。
- 法律意见书、合同审查等深度分析任务，法规检索可作为子步骤但不单独替代主任务。
- 寒暄或无关内容。

## 四、强制执行约束

1. 每次调用前必须先按 [cli-common.md](./references/cli-common.md) 发现当前命令。
2. 单次检索只传一种核心检索意图；不要把多个法规、案由、社保、工伤、仲裁等词堆在同一个参数里。
3. 默认围绕用户请求形成一个高质量检索式并只调用一次；不要为同一问题机械拆分多个关键词反复调用。首次结果不理想、无结果或看似失焦时，也不得自行追加第二次检索；只能说明结果情况，给出一个建议改写的检索式，等待用户确认。
4. 用户输入包含自然语言法律问题、法律场景、事实经过、争议点、材料摘要或条文适用问题时，首次检索必须优先选择 `--semantic`、自然语言问题、语义检索等参数；禁止先拆成 `--query` 或多组关键词做探索性检索。
5. 若语义检索返回有效结果，应立即进入结果整理，不再追加关键词拆分、同义词改写或多轮检索。
6. 只有在 `cmds` 未提供任何语义检索参数，或用户只给出法规名称、条款号、短主题词、时效核实目标等短标签时，才使用关键词或短主题检索。
7. 检索调用会产生用户成本；除用户明确要求“再查”“换个关键词”“更多结果”或确认重试外，不得为了覆盖面自动追加第二次 CLI 调用。
8. 不假设 `--semantic`、`--query`、`--page`、`--size` 或排序参数一定存在；参数形态以 `cmds` 当前输出为准。
9. 未指定时效状态时，不主动在检索词中追加“现行有效”“有效”“废止”等状态词；检索后根据 CLI 返回字段判断和说明。
10. CLI 未返回的法规名称、条文原文、时效状态、废止日期、替代文件、发文机关和施行日期不得补写。

## 五、工作流程

### Step 1：意图识别与要素抽取

| 意图类型 | 判定标准 | 需抽取要素 |
|---------|---------|-----------|
| 精准定位 | 法规名和条款号明确 | 法规全称或简称、条款号、款号、项号 |
| 结构化筛选 | 部分要素明确 | 主题词、效力级别、发文机关、时间范围、地域 |
| 语义泛搜 | 自然语言描述法律场景 | 主体关系、行为类型、争议点、查询目标 |
| 时效核实 | 询问法规是否有效 | 法规名称、版本年份、废止或替代目标 |
| 法规对比 | 对比两个法规或条款 | 法规 A、法规 B、条款或对比维度 |

处理规则：

- 法规简称可参考 [常用法规简称映射表](./references/regulation-mapping.md) 映射标准全称。
- 用户提供条款号、款号、项号时，将其作为理解问题的辅助信息；不要将法规名和条号机械拆成多个关键词。
- 同一检索意图只生成一个最有区分度的检索主题或自然语言问题，不把用户文本机械拆成多条命令。
- 对自然语言法律问题、法律场景、事实经过、争议点或材料摘要，必须优先构造语义检索问题，并作为首次 CLI 调用参数。
- 对语义型请求，不要在语义检索之前预先拆分关键词；关键词只作为语义参数不可用或用户确认后的降级重试方案。
- 多个法规或多个问题会产生多次调用；除非用户明确要求全部检索或法规对比，否则先聚焦最核心问题或请用户确认优先级。
- 信息不足时进入澄清模式。

### Step 2：选择检索文本类型

默认优先保留用户问题的完整语义。只要用户输入包含自然语言问题、法律场景、事实经过、争议点、材料摘要或条文适用问题，就按“语义检索”处理；只有用户明确给出法规名称、短主题词、条款号或时效核实目标，且不依赖完整语义关系时，才使用短检索主题。

路由优先级：

1. 有自然语言法律问题、法律场景、事实经过、争议点、材料摘要或条文适用问题，且 `cmds` 支持语义检索参数：调用一次语义检索。
2. 无语义检索参数，但问题依赖完整语义关系：压缩成一个最有区分度的短主题后调用一次关键词检索，并说明这是参数受限下的降级。
3. 只有法规名称、条款号、短主题词或时效核实目标：调用一次关键词或短主题检索。

| 场景 | 推荐组织 | 避免做法 |
|------|-----------|-----------|
| 条号或条文问题 | 完整自然语言法律问题 | 使用 `法规名 条号` 形式的机械关键词 |
| 法律场景问题 | 主体、行为、争议点和查询目标 | 拆成多个泛化关键词 |
| 法规主题 | 简洁主题词，如 `竞业限制 补偿金` | 加入“现行有效”等状态词污染主题 |
| 时效核实 | 标准法规名称 | 使用“是否有效”等泛化疑问词 |
| 法规对比 | 用户明确要求对比时分别检索 | 额外扩展用户未要求的司法解释、案例 |

具体命令示例和参数组织见 [法规检索 CLI 场景指南](./references/search-examples.md)。

### Step 3：执行 CLI 检索

先执行 [deli-cli 通用前置](./references/cli-common.md)，再按 [法规检索 CLI 场景指南](./references/search-examples.md) 组织参数并调用当次 `cmds` 返回的命令。

如果首次无结果或结果不理想，先告知结果情况，并给出一个建议重试的检索主题或自然语言问题；等待用户确认后再调用。

### Step 4：结果校验与后处理

1. 时效性校验：核对当前状态，例如现行有效、已废止、已被修订、部分失效、尚未生效。
2. 内容完整性校验：核实条款号、款号、项号是否存在。
3. 版本校验：确保返回用户指定版本或最新现行有效版本。
4. 适用边界：说明地域、主体、行为、时间和效力层级限制。

### Step 5：格式化输出

根据检索场景选择条款详情、法规列表、法规对比或时效核实模板。输出时以 CLI 返回字段为准；字段缺失时不要补写。

翻页或查看更多结果时，只有用户明确要求并接受新增调用，才按当前 `cmds` 返回的分页参数形态继续执行。

### 模板 A：单一条款详情

```plaintext

**第{条款号}条**【{条款标题}】

{条款原文或 CLI 返回内容}

**核心要点**：{不超过 50 字，含适用主体、核心行为、法律后果}

**关联法规**：
- 《{关联法规1全称}》第{条款号}条（{关联理由}）
- 《{关联法规2全称}》第{条款号}条（{关联理由}）
```

```plaintext
| 2 | {名称} | {级别} | {日期} | {日期} | {状态} | {CLI 返回内容摘要或原文} |
```


```plaintext

```

## 七、注意事项

### 时效性红线

- 禁止将已废止法规作为现行有效依据引用。
- 对于已被修订或部分失效的法规，必须说明当前可用版本或标注“待核验”。

### 条款引用边界

- 引用条款原文时必须保持文本完整性，不得断章取义。
- 涉及多款多项时须准确标注款号、项号。

### 检索范围限制

- 本 skill 仅提供检索与呈现服务，不单独替代法律意见、个案分析或诉讼策略。
- 对涉及国家秘密、内部文件、未公开草案的检索请求，明确告知不在范围内。

### 数据更新声明

所有结果须附带提示语：

```text
检索结果基于 得理CLI 当前返回数据，法规时效性可能因最新立法动态而变化，重要决策前请核实最新官方文本。
```
