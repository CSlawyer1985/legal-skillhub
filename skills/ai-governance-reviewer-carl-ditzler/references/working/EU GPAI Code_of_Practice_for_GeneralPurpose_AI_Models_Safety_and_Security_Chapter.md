## 目标

本行为守则（“守则”）的总体目标是改善内部市场的运作，促进以人为本、值得信赖的人工智能（“AI”）的推广，同时确保《宪章》所载的健康、安全和基本权利（包括民主、法治和环境保护）在欧盟境内受到高水平保护，免受人工智能的有害影响，并依据《人工智能法案》第 1 条第 1 款支持创新。

为实现这一总体目标，本守则的具体目标是：

```
A. 作为证明遵守《人工智能法案》第 53 条和第 55 条所规定义务的指导性文件，同时承认遵守本守则并不构成依据《人工智能法案》证明履行这些义务的决定性证据。
```
```
B. 确保通用人工智能模型提供者遵守其在《人工智能法案》下的义务，并使人工智能办公室能够评估选择依据本守则证明其履行《人工智能法案》义务的通用人工智能模型提供者的合规情况。
```

## 序言

_鉴于_：

```
(a) 全生命周期适当管理原则。签署方承认，具有系统性风险的通用人工智能模型提供者应当持续评估和缓解系统性风险，在整个模型生命周期（包括在模型投放市场之前和之后发生的开发阶段）中采取适当措施，与人工智能价值链上的相关参与者（例如可能受模型影响的利益相关方）开展合作并考虑其意见，并通过定期更新以应对不断改进和新兴的模型能力，确保其系统性风险管理面向未来（见《人工智能法案》序言第 114 段和第 115 段）。据此，签署方承认，实施适当措施通常要求签署方至少采用最先进水平，除非能以较不先进的流程、措施、方法、方法论或技术确定性地排除系统性风险。系统性风险评估是一个多步骤过程，模型评估（指用于评估模型系统性风险的一系列方法）在整个模型生命周期中不可或缺。在实施系统性风险缓解措施时，签署方承认持续评估其有效性的重要性。
```
```
(b) 情境化风险评估与缓解原则。签署方承认，本安全与安保章节（“本章”）仅与具有系统性风险的通用人工智能模型提供者相关，而不适用于人工智能系统。但签署方也承认，系统性风险的评估和缓解应当包括（在合理可预见的范围内）系统架构、模型可能被整合到的其他软件，以及推理时可用的计算资源，因为它们对模型的影响具有重要性，例如可能影响安全与安保缓解措施的有效性。
```
```
(c) 与系统性风险相称原则。签署方承认，系统性风险的评估和缓解应当与风险相称（《人工智能法案》第 56 条第 2 款(d)项）。因此，系统性风险评估和缓解中的审查程度，特别是文件和报告中的详细程度，应当与整个模型生命周期中相关时点的系统性风险相称。签署方承认，虽然系统性风险评估和缓解具有迭代性和连续性，但无需重复仍适用于模型所产生的系统性风险的评估。
```
```
(d) 与既有法律整合原则。签署方承认，本章是其他欧盟法律的一部分并受其补充。签署方进一步承认，保密（包括商业保密）义务在欧盟法律要求的范围内得到保留，且依据本章向欧洲人工智能办公室（“人工智能办公室”）提交的信息将依照《人工智能法案》第 78 条处理。此外，签署方承认，其向人工智能办公室提交的有关未来发展动向和未来商业活动的信息将被理解为可能发生变更。签署方进一步承认，本章中为促进健康风险文化而设的措施（措施 8.3）不影响《（欧盟）2019/1937 号指令》（关于举报人保护）以及成员国为执行该指令而制定的法律与《人工智能法案》第 87 条相结合所产生的任何义务。签署方还承认，在国际标准涵盖本章规定的情况下，其可以依赖国际标准。
```

(e) **合作原则。** 签署方承认，系统性风险评估和缓解需要投入大量时间和资源。签署方认识到协作效率的优势，例如通过共享模型评估方法和/或基础设施。签署方进一步认识到，在系统性风险评估和缓解中与许可持有人、下游修改方和下游提供者合作的重要性，以及让民间社会、学术界和其他相关利益相关方的专家或非专业代表参与理解模型影响的重要性。签署方承认，此类合作可能涉及订立协议以共享与系统性风险评估和缓解相关的信息，同时确保对敏感信息进行相称的保护并遵守适用的欧盟法律。签署方进一步认识到与人工智能办公室合作（《人工智能法案》第 53 条第 3 款）以促进具有系统性风险的通用人工智能模型提供者、研究人员和监管机构之间合作应对人工智能领域新兴挑战和机遇的重要性。

(f) **人工智能安全与安保创新原则。** 签署方承认，确定理解和确保具有系统性风险的通用人工智能模型安全与安保的最有效方法仍是一项不断演变的挑战。签署方承认，本章应当鼓励具有系统性风险的通用人工智能模型提供者推动人工智能安全与安保及相关流程和措施的最先进水平。签署方承认，推动最先进水平还包括开发有针对性的方法，在保持有益能力的同时具体应对风险（例如在不适当削弱有益生物医学能力的情况下缓解生物安全风险），同时承认此类精确性要求比缺乏针对性的方法付出更大的技术努力和创新。签署方进一步承认，如果具有系统性风险的通用人工智能模型提供者能够通过实现更高效率的替代手段证明同等或更优的安全或安保结果，此类创新应当被视为推动人工智能安全与安保的最先进水平，并值得考虑更广泛的采用。

(g) **预防原则。** 签署方承认预防原则的重要作用，特别是对于科学数据的缺乏或质量尚不允许进行完整评估的系统性风险。据此，签署方承认，在识别系统性风险时，应当考虑模型当前采用率和研发轨迹的外推。

(h) **中小企业（“SMEs”）和小型中型企业（“SMCs”）。** 为考虑具有系统性风险的通用人工智能模型提供者在规模和能力上的差异，中小企业和小型中型企业（包括初创企业）应当可以获得相称的简化合规方式。例如，中小企业和小型中型企业可以免除部分报告义务（《人工智能法案》第 56 条第 5 款）。属于中小企业或小型中型企业并被免除报告义务的签署方承认，其仍可自愿遵守这些义务。


(i) **解释。** 签署方承认，所有承诺和措施应当根据评估和缓解系统性风险的目标进行解释。签署方进一步承认，鉴于人工智能发展的快速步伐，以系统性风险评估和缓解为重点的目的性解释对于确保本章保持有效、相关和面向未来尤为重要。此外，本章中出现的任何术语，凡在本章术语表中有所定义的，均具有该术语表所载的含义。签署方承认，附录 1 在有疑问时应本着善意解释，依据：(1) 《人工智能法案》第 3 条第 2 款中“风险”定义所规定的损害概率和严重程度；以及 (2) 《人工智能法案》第 3 条第 65 款中“系统性风险”的定义。签署方承认，本章应当结合人工智能办公室关于《人工智能法案》的任何指南进行解释并与之保持一致。

(j) **严重事件报告。** 签署方承认，报告严重事件并非承认过错。此外，签署方承认，关于严重事件的相关信息无法仅在严重事件发生之后于模型层面追溯性地进行跟踪、记录和报告。可能直接或间接导致此类事件的信息往往是分散的，并且可能在签署方得知严重事件时已经丢失、被覆盖或碎片化。这证明了在严重事件发生之前建立流程和措施以跟踪和记录相关信息是合理的。

### 措施 1.3：更新框架

签署方将酌情更新框架，包括在框架评估（见下列各款）之后不无故拖延地更新，以确保措施 1.1 中的信息保持最新，且框架至少保持最先进水平。对于框架的任何更新，签署方将附上变更日志，说明框架如何及为何被更新，并附上版本号和变更日期。

如签署方有合理理由认为其框架的充分性和/或其对该框架的遵守已经或将会受到实质性损害，或自模型投放市场之日起每 12 个月（以较早者为准），签署方将开展适当的框架评估。此类理由的示例包括：

```
(1) 签署方开发模型的方式将发生实质性变化，且可合理预见该变化将导致其至少一个模型产生的系统性风险不可接受；
(2) 涉及其模型或类似模型的严重事件和/或未遂事件已发生，且可能表明其至少一个模型产生的系统性风险不可接受；和/或
(3) 其至少一个模型产生的系统性风险已经或可能发生实质性变化，例如安全与/或安保缓解措施已经或可能变得实质性无效，或其至少一个模型已经或可能发展出实质性改变的能力和/或倾向。
```

框架评估将包括以下内容：

```
(1) 框架充分性：评估框架中的流程和措施是否适合签署方模型产生的系统性风险。该评估将考虑模型目前正在如何被开发、投放市场和/或使用，以及在未来 12 个月内预计将如何被开发、投放市场和/或使用。
(2) 框架遵守情况：评估重点在于签署方对框架的遵守情况，包括：(a) 自上次框架评估以来任何未遵守框架的情形及其原因；以及 (b) 为确保持续遵守框架而需要实施的任何措施（包括安全与安保缓解措施）。如(a)和/或(b)点产生未来不遵守的风险，签署方将在其框架评估中制定补救计划。
```
### 措施 1.4：框架通知

签署方将在框架及其更新获得确认后五个工作日内，向人工智能办公室提供（未经删节的）框架访问权限及其更新内容。

(2) 为每项已识别的系统性风险制定系统性风险情景（如措施 2.2 所述）。

### 措施 2.1：系统性风险识别流程

签署方将识别：

```
(1) 通过以下流程获得的系统性风险：
(a) 基于附录 1.1 中的风险类型，编制一份可能源自模型并可能具有系统性的风险清单，并考虑：
(i) 模型无关信息（依据措施 3.1）；
(ii) 关于该模型和类似模型的相关信息，包括来自上市后监测的信息（依据措施 3.5），以及关于严重事件和未遂事件的信息（依据承诺 9）；以及
(iii) 人工智能办公室、独立专家科学小组或其他倡议（如经人工智能办公室为此目的认可的国际人工智能安全研究所网络）直接或通过公开发布向签署方传达的任何其他相关信息；
(b) 分析依据(a)点编制的风险清单中各项风险的相关特征，如其性质（基于附录 1.2）和来源（基于附录 1.3）；以及
(c) 基于(b)点，识别模型产生的系统性风险；以及
(2) 附录 1.4 中列明的特定系统性风险。
```
### 措施 2.2：系统性风险情景

签署方将为每项已识别的系统性风险（依据措施 2.1）制定适当的系统性风险情景，包括关于这些系统性风险情景的数量和详细程度。


## 承诺 3：系统性风险分析

```
法律文本：《人工智能法案》第 55 条第 1 款和序言第 114 段
```
签署方承诺分析每项已识别的系统性风险（依据承诺 2）。系统性风险分析的目的包括为系统性风险可接受性判定（依据承诺 4）提供便利。

对每项已识别的系统性风险，系统性风险分析包含五个要素，这些要素可能相互重叠，且可能需要递归实施：

```
(1) 收集模型无关信息（如措施 3.1 所述）；
(2) 开展模型评估（如措施 3.2 所述）；
(3) 对系统性风险进行建模（如措施 3.3 所述）；以及
(4) 估计系统性风险（如措施 3.4 所述）；同时
(5) 开展上市后监测（如措施 3.5 所述）。
```
### 措施 3.1：模型无关信息

签署方将收集与系统性风险相关的模型无关信息。

签署方将以适合该系统性风险的不同广度和深度搜索并收集此类信息，使用的方法包括：

```
(1) 网络搜索（例如利用开源情报方法收集和分析从开放来源获取的信息）；
(2) 文献综述；
(3) 市场分析（例如关注市场上其他模型的能力）；
(4) 训练数据审查（例如查找数据投毒或篡改的迹象）；
(5) 审查和分析历史事件数据和事件数据库；
(6) 总体趋势预测（例如关于算法效率、计算使用、数据可得性和能源使用发展的预测）；
(7) 专家访谈和/或专家组；和/或
(8) 非专业访谈、调查、社群咨询或其他参与式研究方法，例如调查模型对自然人（包括弱势群体）的影响。
```
### 措施 3.2：模型评估

签署方将在与系统性风险相关的情境中开展至少最先进的模型评估，以评估模型的能力、倾向、功能特征和/或影响，如附录 3 所述。

签署方将确保此类模型评估采用适合该模型和该系统性风险的方法进行设计和开展，并包括对模型的开放式测试，以增进对系统性风险的理解，着眼于识别意外行为、能力边界或涌现特性。模型评估方法的示例包括：问答集、基于任务的评估、基准测试、红队测试和其他对抗性测试方法、人类能力提升研究、模型生物体、模拟和/或针对机密材料的代理评估。此外，模型评估的设计将参考依据措施 3.1 收集的模型无关信息。

### 措施 3.3：系统性风险建模

签署方将针对该系统性风险开展系统性风险建模。为此，签署方将：

```
(1) 使用至少最先进的风险建模方法；
(2) 在依据措施 2.2 制定的系统性风险情景的基础上构建；以及
(3) 至少考虑依据措施 2.1 和本承诺收集的信息。
```
### 措施 3.4：系统性风险估计

签署方将估计该系统性风险的损害概率和严重程度。

签署方将使用至少最先进的风险估计方法，并至少考虑依据承诺 2、本承诺和承诺 9 收集的信息。系统性风险的估计将以风险评分、风险矩阵、概率分布或其他适当格式表达，可以是定量的、半定量的和/或定性的。此类系统性风险估计的示例包括：(1) 定性系统性风险评分（例如“中等”或“严重”）；(2) 定性系统性风险矩阵（例如“概率：不太可能”×“影响：高”）；和/或 (3) 定量系统性风险矩阵（例如“X-Y%”×“X-Y 欧元损失”）。

### 措施 3.5：上市后监测

签署方将开展适当的上市后监测，以收集与判断该系统性风险是否可能被认定不可接受相关的信息（依据措施 4.1），并用于确定是否需要更新模型报告（依据措施 7.6）。此外，签署方将尽最大努力开展上市后监测，以收集与编制时间估计（依据措施 1.1 第(2)(c)点）相关的信息。

为此，上市后监测将：

```
(1) 收集关于模型能力、倾向、功能特征和/或影响的信息；
(2) 考虑下列示例性方法；以及
(3) 如签署方自身提供和/或部署整合其自身模型的 AI 系统，则将监测该模型作为这些 AI 系统组成部分的情况。
```
以下是为上述第(2)点之目的而采用的上市后监测方法示例：

```
(1) 收集终端用户反馈；
(2) 提供（匿名）报告渠道；
(3) 提供（严重）事件报告表格；
(4) 提供漏洞赏金计划；
```

```
(5) 建立社群驱动的模型评估和公开排行榜；
(6) 与受影响的利益相关方开展经常性对话；
(7) 监测软件仓库、已知恶意软件、公共论坛和/或社交媒体上的使用模式；
(8) 与学术界、民间社会、监管机构和/或独立研究人员合作，支持对模型能力、倾向、功能特征和/或影响的科学研究；
(9) 实施对模型输入和输出的隐私保护性日志记录和元数据分析技术，例如使用水印、元数据和/或其他至少最先进的来源追踪技术；
(10) 收集关于模型使用限制被违反以及由此类违反引发的后续事件的相关信息；和/或
(11) 监测模型中对评估和缓解系统性风险具有相关性但第三方无法透明获取的方面，例如参数未公开供下载的模型的隐藏思维链。
```
为便利上市后监测，签署方将向足够数量的独立外部评估者提供充分的免费访问权限：

```
(1) 就投放市场的模型而言，在系统性风险方面能力最强的模型版本；
(2) 第(1)点中模型版本的思维链（如可用）；以及
(3) 与第(1)点中模型版本相对应、就系统性风险而言实施安全缓解措施最少的模型版本（如仅助益模型版本存在）及其（如可用的）思维链；
```
除非该模型就同一系统性风险而言被视为同等安全或更安全的模型（依据附录 2.2）。此类模型访问权限可以由签署方通过 API、本地访问（包括传输）、通过签署方提供的硬件访问，或酌情将模型参数公开供下载的方式提供。

为选择前款所述的独立外部评估者，签署方将公布评估申请的适当标准。此类评估者的数量、遴选标准和安全措施可因前款第(1)、(2)和(3)点而有所不同。

签署方将仅访问、存储和/或分析来自独立外部评估者的评估结果，以评估和缓解模型产生的系统性风险。特别是，未经评估者明确许可，签署方不得使用此类测试运行的输入和/或输出训练其模型。此外，只要评估者符合下列条件，签署方将不因评估者的测试和/或发布研究结果而对其采取任何法律或技术性报复措施：

```
(1) 未经明确许可，不通过测试故意扰乱模型可用性；
(2) 不故意违反欧盟法律访问、修改和/或使用敏感或保密用户数据，如评估者确实访问此类数据，仅收集必要内容，不传播该数据，并在法律上可行时尽快删除；
```

```
(3) 不故意利用其访问权限从事对公共安全和安保构成重大风险的活动；
(4) 不利用研究结果威胁签署方、用户或价值链中的其他参与者，但依据预先约定的政策和时间表进行披露不视为此类胁迫；以及
(5) 遵守签署方公开的负责任漏洞披露程序，该程序至少应规定：签署方不得将发布推迟或阻止超过签署方知悉研究结果之日起 30 个工作日，除非存在例外必要情况需要更长时间，例如披露研究结果会实质性增加系统性风险。
```
属于中小企业或小型中型企业的签署方可以联系人工智能办公室，该办公室可以提供支持或资源以协助遵守本措施。

## 承诺 4：系统性风险可接受性判定

```
法律文本：《人工智能法案》第 55 条第 1 款
```
签署方承诺明确系统性风险可接受标准，并确定模型产生的系统性风险是否可接受（如措施 4.1 所述）。签署方承诺基于系统性风险可接受性判定决定是否继续开发、投放市场和/或使用模型（如措施 4.2 所述）。

### 措施 4.1：系统性风险可接受标准和可接受性判定

签署方将（在依据措施 1.1 第(2)(a)点的框架中）描述和论证其将如何确定模型产生的系统性风险是否可接受。为此，签署方将：

```
(1) 对于每项已识别的系统性风险（依据措施 2.1），至少：
(a) 定义适当的系统性风险等级，该等级：
(i) 以模型能力界定，并可以额外纳入模型倾向、风险估计和/或其他适当指标；
(ii) 是可测量的；以及
(iii) 至少包含一个模型尚未达到的系统性风险等级；或
(b) 如系统性风险等级不适合该系统性风险，且该系统性风险不属于特定系统性风险（依据附录 1.4），则定义其他适当的系统性风险可接受标准；
(2) 描述其将如何使用这些等级和/或其他标准来确定每项已识别的系统性风险（依据措施 2.1）以及整体系统性风险是否可接受；以及
```

```
(3) 论证按照第(2)点使用这些等级和/或其他标准如何确保每项已识别的系统性风险（依据措施 2.1）以及整体系统性风险可接受。
```
签署方将把系统性风险可接受标准适用于每项已识别的系统性风险（依据措施 2.1），并纳入安全边际（如下款所述），以确定每项已识别的系统性风险（依据措施 2.1）以及整体系统性风险是否可接受。该可接受性判定将至少考虑通过系统性风险识别和分析（依据承诺 2 和承诺 3）收集的信息。

安全边际将：

```
(1) 适合该系统性风险；以及
(2) 考虑以下方面的潜在局限、变化和不确定性：
(a) 系统性风险来源（例如评估时点之后的能力提升）；
(b) 系统性风险评估（例如模型评估的低诱发或类似评估的历史准确性）；以及
(c) 安全与安保缓解措施的有效性（例如缓解措施被规避、停用或颠覆）。
```
### 措施 4.2：基于系统性风险可接受性决定是否继续推进

### 判定

签署方仅在模型产生的系统性风险被认定为可接受（依据措施 4.1）时，方继续模型的开发、投放市场和/或使用。

如模型产生的系统性风险未被认定为可接受，或可合理预见其很快将不被认定为可接受（依据措施 4.1），签署方将在继续推进前采取适当措施，确保模型产生的系统性风险当前可接受并将持续保持可接受。特别是，签署方将：

```
(1) 不将模型投放市场，限制投放市场（例如通过调整许可或使用限制），撤回或召回模型（视需要而定）；
(2) 实施安全与/或安保缓解措施（依据承诺 5 和承诺 6）；以及
(3) 再开展一轮系统性风险识别（依据承诺 2）、系统性风险分析（依据承诺 3）和系统性风险可接受性判定（依据本承诺）。
```

## 承诺 5：安全缓解措施

```
法律文本：《人工智能法案》第 55 条第 1 款和序言第 114 段
```
签署方承诺沿整个模型生命周期实施适当的安全缓解措施，如本承诺的措施所述，以确保模型产生的系统性风险可接受（依据承诺 4）。

### 措施 5.1：适当的安全缓解措施

签署方将实施适当的、包括在对抗性压力下（例如微调攻击或越狱）足够稳健的安全缓解措施，并考虑模型的发布和分发策略。

安全缓解措施的示例包括：

```
(1) 过滤和清理训练数据，例如可能导致不良模型倾向（如不忠实的思维链轨迹）的数据；
(2) 监测和过滤模型的输入和/或输出；
(3) 出于安全利益改变模型行为，例如对模型进行微调使其拒绝某些请求或提供无帮助的回复；
(4) 分阶段开放模型访问，例如仅向经审查的用户开放 API 访问权限、基于上市后监测逐步扩大访问范围，和/或最初不将模型参数公开供下载；
(5) 为其他参与者提供用于缓解模型产生的系统性风险的工具；
(6) 就模型行为提供高保证度定量安全保障的技术；
(7) 支持构建安全的 AI 智能体生态系统的技术，例如模型标识、专用通信协议或事件监测工具；和/或
(8) 其他新兴安全缓解措施，例如实现思维链推理透明度的措施，或防御模型颠覆其自身其他安全缓解措施的能力的措施。
```

## 承诺 6：安保缓解措施

```
法律文本：《人工智能法案》第 55 条第 1 款，以及序言第 114 段和第 115 段
```
签署方承诺沿整个模型生命周期为其模型及其物理基础设施实施适当水平的网络安全保护，如本承诺的措施所述，以确保其模型可能因未经授权发布、未经授权访问和/或模型窃取而产生的系统性风险可接受（依据承诺 4）。

如模型的能力低于至少一个参数已公开供下载的模型的能力，则该模型免除本承诺项下的义务。

签署方将在模型参数公开供下载或安全删除之前，对该模型实施这些安保缓解措施。

### 措施 6.1：安保目标

签署方将定义一个目标，明确其安保缓解措施旨在防范的威胁行为者（“安保目标”），包括非国家外部威胁、内部威胁和其他预期威胁行为者，并至少考虑其模型当前和预期具备的能力。

### 措施 6.2：适当的安保缓解措施

签署方将实施适当的安保缓解措施以实现安保目标，包括依据附录 4 的安保缓解措施。如签署方偏离附录 4.1 至附录 4.5(a)点中列出的任何安保缓解措施（例如因签署方的组织环境和数字基础设施所致），其将实施能够实现相应缓解目标的替代性安保缓解措施。

所需安保缓解措施的实施可以随着整个模型生命周期中模型能力的提升而适当分阶段进行。

## 承诺 7：安全与安保模型报告

```
法律文本：《人工智能法案》第 55 条第 1 款和第 56 条第 5 款
```
签署方承诺通过在模型投放市场前编制安全与安保模型报告（“模型报告”）的方式，向人工智能办公室报告其模型及其系统性风险评估和缓解流程与措施的相关信息（如措施 7.1 至措施 7.5 所述）。此外，签署方承诺保持模型报告的最新状态（如措施 7.6 所述），并将其模型报告通知人工智能办公室（如措施 7.7 所述）。


如签署方已在其其他报告和/或通知中向人工智能办公室提供了相关信息，其可以在模型报告中引用这些报告和/或通知。如一个模型的系统性风险评估和缓解流程与措施无法在不参考其他模型的情况下被理解，签署方可以为多个模型编制一份模型报告。

属于中小企业或小型中型企业的签署方，可以在反映规模和能力约束所需的范围内降低其模型报告的详细程度。

### 措施 7.1：模型描述与行为

签署方将在模型报告中提供：

```
(1) 对模型架构、能力、倾向和功能特征的高层级描述，以及模型的开发方式（包括其训练方法和数据），以及这些方面与其已投放市场的其他模型的差异；
(2) 对模型已被使用和预期将被使用方式的描述，包括其在模型开发、监督和/或评估中的使用；
(3) 对即将投放市场或目前正在投放市场和/或使用的模型版本的描述，包括系统性风险缓解措施和系统性风险的差异；以及
(4) 签署方预期模型如何运作的规格说明（例如通过有效超链接，通常称为“模型规格”），包括：
(a) 明确模型预期遵循的原则；
(b) 说明模型预期如何对不同类型的原则和指令进行优先级排序；
(c) 列出模型预期拒绝指令的主题；以及
(d) 提供系统提示词。
```
### 措施 7.2：继续推进的理由

签署方将在模型报告中提供：

```
(1) 对模型产生的系统性风险为何可接受的详细论证，包括所纳入安全边际的细节（依据措施 4.1）；
(2) 第(1)点中的论证将不再成立的合理可预见条件；以及
(3) 对继续开发、投放市场和/或使用（依据措施 4.2）的决策如何作出的描述，包括外部参与者的意见是否促成此类决策（依据措施 1.1 第(2)(d)点），以及依据附录 3.5 的独立外部评估者的意见是否及如何促成此类决策。
```

### 措施 7.3：系统性风险识别、分析和缓解的文件记录

签署方将在模型报告中提供：

```
(1) 其系统性风险识别和分析结果的描述，以及任何有助于理解这些结果的信息，包括：

### 措施 7.5：系统性风险格局的实质性变化

签署方将确保模型报告包含人工智能办公室理解以下事项所需的相关信息：模型的开发、投放市场和/或使用是否以及如何导致对本章项下系统性风险评估和缓解措施与流程的实施具有相关性的系统性风险格局的实质性变化。

此类信息的示例包括：

```
(1) 对暗示提升模型能力新途径的缩放定律的描述；
(2) 对在计算效率或模型能力方面实质性提升最先进水平的全新架构特征的概述；
(3) 对评估缓解措施有效性具有相关性的信息的描述，例如模型的思维链是否对人类较不清晰可读；和/或
(4) 对实质性提升分布式训练效率或可行性的训练技术的描述。
```

### 措施 7.6：模型报告更新

如签署方有合理理由认为其关于模型产生的系统性风险为何可接受的论证（依据措施 7.2 第(1)点）已受到实质性损害，其将更新模型报告。此类理由的示例包括：

```
(1) 依据措施 7.2 第(2)点列出的条件之一已经发生；
(2) 模型的能力、倾向和/或功能特征已经或将发生实质性变化，例如通过进一步的后期训练、访问额外工具或推理计算量增加；
(3) 模型的使用和/或向 AI 系统的整合已经或将发生实质性变化；
(4) 涉及该模型或类似模型的严重事件和/或未遂事件已经发生；和/或
(5) 已发生如下进展：实质性损害所开展模型评估的外部有效性、实质性提升模型评估方法的最先进水平，和/或基于其他原因表明所开展的系统性风险评估存在实质性不准确。
```
模型报告更新应在签署方知悉需要更新的事由后的合理时间内完成，例如在其持续的系统性风险评估和缓解（依据措施 1.2 第二款）过程中发现这些事由之后。如模型报告更新系由对模型的蓄意变更触发，且该变更将投放市场，则模型报告更新及作为其基础的全流程系统性风险评估和缓解流程（依据措施 1.2 第三款）须在该变更投放市场之前完成。

此外，如该模型属于签署方在市场上可获得的能力最强的模型之一，签署方将至少每六个月向人工智能办公室提供更新后的模型报告。在下列情况下签署方无需如此：(1) 自其上次向人工智能办公室提供模型报告或其更新以来，模型的能力、倾向和/或功能特征未发生变化；(2) 其将在不到一个月内将能力更强的模型投放市场；和/或 (3) 就每项已识别的系统性风险（依据措施 2.1）而言，该模型被视为同等安全或更安全（依据附录 2.2）。

更新后的模型报告将包含：
(1) 基于全流程系统性风险评估和缓解流程（依据措施 1.2 第三款）的结果，措施 7.1 至措施 7.5 所规定的更新信息；以及
(2) 变更日志，说明模型报告如何及为何被更新，并附上版本号和变更日期。

### 措施 7.7：模型报告通知

签署方将在模型投放市场时向人工智能办公室提供模型报告访问权限（不作删节，除非签署方所受国家安全法律要求删节），例如通过公开可访问的链接或通过人工智能办公室指定的足够安全的渠道。如模型报告被更新，签署方将在更新确认后五个工作日内向人工智能办公室提供更新后模型报告的访问权限（不作删节，除非签署方所受国家安全法律要求删节）。


为便利模型投放市场，签署方可以将向人工智能办公室提供模型报告或其更新的时间最多推迟 15 个工作日。仅当人工智能办公室认为签署方善意行事，且签署方及时向人工智能办公室提供包含措施 7.2 和措施 7.5 所述信息的临时模型报告时，方可如此行事。

## 承诺 8：系统性风险责任分配

```
法律文本：《人工智能法案》第 55 条第 1 款和序言第 114 段
```
签署方承诺：(1) 在组织各层级明确管理其模型产生的系统性风险的责任（如措施 8.1 所述）；(2) 向被分配系统性风险管理责任的参与者分配适当资源（如措施 8.2 所述）；以及 (3) 促进健康的风险文化（如措施 8.3 所述）。

### 措施 8.1：明确责任的界定

签署方将明确界定组织各层级管理其模型产生的系统性风险的责任。这包括以下责任：

```
(1) 系统性风险监督：监督签署方的系统性风险评估和缓解流程与措施。
(2) 系统性风险归属责任：管理签署方模型产生的系统性风险，包括系统性风险评估和缓解流程与措施，并管理对严重事件的应对。
(3) 系统性风险支持与监测：支持和监测签署方的系统性风险评估和缓解流程与措施。
(4) 系统性风险保证：就签署方系统性风险评估和缓解流程与措施的充分性，向行使监督职能的管理机构或另一适当的独立机构（如理事会或董事会）提供内部保证，并酌情提供外部保证。
```
签署方将按照适合其治理结构和组织复杂程度的方式，在以下组织层级分配这些责任：

```
(1) 行使监督职能的管理机构或另一适当的独立机构（如理事会或董事会）；
(2) 行使执行职能的管理机构；
(3) 相关运营团队；
(4) 内部保证提供方（如有，例如内部审计职能）；以及
(5) 外部保证提供方（如有，例如第三方审计机构）。
```

如签署方按照适合其模型产生的系统性风险的方式遵守以下全部内容，本措施即被推定已得到履行：

```
(1) 系统性风险监督：监督签署方系统性风险管理流程和措施的责任已分配给行使监督职能的管理机构的特定委员会（如风险委员会或审计委员会），或一个或多个适当的独立机构（如理事会或董事会）。对于属于中小企业或小型中型企业的签署方，该责任可以主要分配给行使监督职能的管理机构的一名成员。
(2) 系统性风险归属责任：管理模型产生的系统性风险的责任已分配给行使执行职能的管理机构的适当成员，该成员同时负责可能产生系统性风险的签署方相关核心业务活动，例如研究与产品开发（如研究主管或产品主管）。行使执行职能的管理机构成员已将较低层级的责任分配给监督部分产生系统性风险的业务活动（如特定研究领域或特定产品）的运营管理人员。视组织复杂程度而定，可能存在逐级下放的责任结构。
(3) 系统性风险支持与监测：支持和监测签署方系统性风险管理流程和措施（包括开展风险评估）的责任已至少分配给行使执行职能的管理机构的一名成员（如首席风险官或安全与安保框架副总裁）。该成员不得同时负责可能产生系统性风险的签署方核心业务活动（如研究与产品开发）。对于属于中小企业或小型中型企业的签署方，行使执行职能的管理机构中至少有一名成员负责支持和监测签署方的系统性风险评估和缓解流程与措施。
(4) 系统性风险保证：就签署方系统性风险评估和缓解流程与措施的充分性向行使监督职能的管理机构或另一适当的独立机构（如理事会或董事会）提供保证的责任，已分配给相关当事方（如首席审计执行官、内部审计负责人或相关分委员会）。该个人由内部审计职能或同等机构以及（酌情）外部保证提供支持。签署方的内部保证活动是适当的。对于属于中小企业或小型中型企业的签署方，行使监督职能的管理机构定期评估签署方的系统性风险评估和缓解流程与措施（例如通过批准签署方的框架评估）。
```
### 措施 8.2：适当资源的分配

签署方将确保其管理机构监督向被分配责任者（依据措施 8.1）分配与其模型产生的系统性风险相适应的适当资源。此类资源的分配将包括：

```
(1) 人力资源；
(2) 财务资源；
(3) 信息和知识访问权限；以及
(4) 计算资源。
```

### 措施 8.3：促进健康的风险文化

签署方将促进健康的风险文化，并采取适当措施确保被分配管理其模型产生的系统性风险责任的参与者（依据措施 8.1）对系统性风险采取理性而平衡的态度。

为本措施之目的，健康风险文化的指标示例包括：

```
(1) 自上而下确立健康系统性风险文化的基调，例如由领导层向员工清晰传达签署方的框架；
(2) 允许就涉及系统性风险的决策进行清晰沟通并提出质疑；
(3) 设定激励机制，并为参与系统性风险评估和缓解的员工提供充分独立性，以抑制过度承担系统性风险，鼓励对其模型产生的系统性风险进行不带偏见的评估；
(4) 匿名调查显示员工愿意就系统性风险提出关切、知晓提出关切的渠道，并理解签署方的框架；
(5) 内部报告渠道得到积极使用，报告得到适当处理；
(6) 每年告知员工签署方的举报人保护政策，并通过在其网站上发布等方式使员工便于获取该政策；和/或
(7) 不以任何形式报复任何向主管机关发布或提供其在为签署方履行的与工作相关的活动中获取的、关于其模型产生的系统性风险信息的人（该人对其真实性有合理依据予以相信），包括任何直接或间接的不利行为，如解雇、降职、法律诉讼、负面评价或制造敌对工作环境。
```

### 附录 1.1：风险类型

为依据措施 2.1 第(1)点和《人工智能法案》第 3 条第(65)款识别系统性风险之目的，适用以下不同但在某些情况下有所重叠的风险类型：

```
(1) 公共卫生风险。
(2) 安全风险。
(3) 公共安保风险。
(4) 基本权利风险。
(5) 对整个社会的风险。
```
基于这些风险类型，附录 1.4 提供了一份特定系统性风险清单。

作为签署方将开展的系统性风险识别流程的一部分，签署方在依据措施 2.1 第(1)(a)点编制风险清单时将借鉴的、属于上述五类风险的风险示例包括：重大事故风险；对关键部门或基础设施、公众心理健康、言论和信息自由、不歧视、隐私和个人数据保护、环境、非人类福利、经济安全和民主进程的风险；以及权力集中以及非法、暴力、仇恨、激进或虚假内容带来的风险，包括儿童性虐待材料（CSAM）和非自愿亲密图像（NCII）带来的风险。

### 附录 1.2：系统性风险的性质

以下关于系统性风险性质的考量用于系统性风险识别（依据承诺 2）。这些考量区分系统性风险性质的本质特征（附录 1.2.1）和促成特征（附录 1.2.2）。


### 附录 1.2.1：本质特征

```
(1) 该风险是《人工智能法案》第 3 条第(65)款和第 3 条第(64)款意义上的高影响能力所特有的风险。
(2) 该风险依据《人工智能法案》第 3 条第(65)款对欧盟市场具有重大影响。
(3) 所述影响可以依据《人工智能法案》第 3 条第(65)款在价值链上大规模传播。
```
### 附录 1.2.2：促成特征

```
(1) 能力依赖：风险随模型能力而增加，或可能在模型能力前沿出现。
(2) 覆盖面依赖：风险随模型覆盖面而增加。
(3) 高速度：风险可能迅速实现，可能超越缓解措施的速度。
(4) 复合或级联：风险可能触发其他系统性风险或连锁反应。
(5) 难以或无法逆转：风险一旦实现，将造成持久性变化，需要非凡的努力、资源或时间才能补救，或永久不可逆转。
(6) 不对称影响：少数行为者或事件即可触发风险的实现，造成与行为者或事件数量不成比例的影响。
```
### 附录 1.3：系统性风险的来源

以下模型能力、模型倾向、模型功能特征和情境因素，为系统性风险识别（依据承诺 2）之目的，被视为非穷尽性的潜在系统性风险来源。

### 附录 1.3.1：模型能力

模型能力包括：

```
(1) 进攻性网络能力；
(2) 化学、生物、放射性和核（CBRN）能力，以及其他此类武器获取或扩散能力；
(3) 可能造成基本权利持续和严重侵犯的能力；
(4) 操纵、说服或欺骗的能力；
(5) 自主运作的能力；
(6) 适应性学习新任务的能力；
(7) 长期规划、预测或战略谋划的能力；
(8) 自我推理的能力（例如模型对自身、自身实现或环境进行推理的能力，以及模型知道自己是否正在被评估的能力）；
(9) 逃避人类监督的能力；
(10) 自我复制、自我改进或修改自身实现环境的能力；
(11) 自动化 AI 研究和开发的能力；
(12) 处理多种模态的能力（例如文本、图像、音频、视频以及更多模态）；
(13) 使用工具的能力，包括“计算机使用”（例如与模型本身之外的硬件或软件、应用程序接口和用户界面交互）；以及
(14) 控制物理系统的能力。
```

### 附录 1.3.2：模型倾向

模型倾向涵盖模型表现出某些行为或模式的习性或趋向，包括：

```
(1) 与人类意图不一致；
(2) 与人类价值观不一致（例如漠视基本权利）；
(3) 以有害方式运用能力的倾向（例如操纵或欺骗）；
(4) “幻觉”、产生错误信息或掩盖信息来源的倾向；
(5) 歧视性偏见；
(6) 缺乏性能可靠性；
(7) 无法无天，即不以合理方式顾及对类似处境之人本应施加的法律义务，或不以合理方式顾及受影响之人的受法律保护利益；
(8) “追求目标”、对目标修改的有害抵抗或“追求权力”；
(9) 与其他 AI 模型/系统“串通”；以及
(10) 与其他 AI 模型/系统的失调或冲突。
```
### 附录 1.3.3：模型功能特征和其他系统性风险来源

模型功能特征和其他系统性风险来源涵盖模型配置、模型属性以及模型投放市场的背景，包括：

```
(1) 对工具（包括其他 AI 模型/系统）、计算能力（例如允许模型提高其运行速度）或物理系统（包括关键基础设施）的访问；
(2) 可扩展性（例如实现高容量数据处理、快速推理或并行化）；
(3) 发布和分发策略；
(4) 人类监督水平（例如模型自主程度）；
(5) 对抗性移除护栏的脆弱性；
(6) 模型外泄（例如模型泄露/窃取）的脆弱性；
(7) 缺乏适当的基础设施安全；
(8) 模型的商业用户数量和终端用户数量，包括使用整合该模型的 AI 系统的终端用户数量；
(9) 攻防平衡，包括恶意行为者滥用该模型的潜在数量、能力和动机；
(10) 可能受该模型影响的特定环境（例如社会环境、生态环境）的脆弱性；
(11) 缺乏适当的模型可解释性或透明度；
(12) 与其他 AI 模型和/或 AI 系统的交互；以及
(13) 对模型的不当使用（例如将模型用于与其能力或倾向不匹配的应用）。
```

### 附录 1.4：特定系统性风险

基于附录 1.1 中的风险类型，考虑附录 1.2 中系统性风险的性质和附录 1.3 中系统性风险的来源，并计及依据《人工智能法案》第 56 条第 1 款和序言第 110 段的国际做法，以下内容为依据措施 2.1 第(2)点进行系统性风险识别之目的的特定系统性风险：

```
(1) 化学、生物、放射性和核：因促成化学、生物、放射性和核（CBRN）攻击或事故而产生的风险。这包括在相关武器或材料的设计、开发、获取、发布、分发和使用中，显著降低恶意行为者的准入门槛，或显著提高可实现的潜在影响。
(2) 失控：因人类丧失可靠地指挥、修改或关闭模型的能力而产生的风险。此类风险可能源于与人类意图或价值观不一致、自我推理、自我复制、自我改进、欺骗、对目标修改的抵抗、追求权力的行为，或自主创建或改进 AI 模型或 AI 系统。
(3) 网络攻击：因促成大规模复杂网络攻击（包括针对关键系统，如关键基础设施）而产生的风险。这包括在进攻性网络行动中显著降低恶意行为者的准入门槛，或显著提高可实现的潜在影响，例如通过自动化漏洞发现、漏洞利用生成、作战使用和攻击规模化。
(4) 有害操纵：因通过说服、欺骗或个性化定向，以大量人群或高风险决策者为目标促成对人类行为或信念的战略性扭曲而产生的风险。这包括显著增强说服、欺骗和个性化定向的能力，特别是通过多轮交互，以及在个人不知情或无法合理察觉此类影响的情况下。此类能力可能破坏民主进程和基本权利，包括基于受保护特征的剥削利用。
```
## 附录 2：同等安全或更安全模型

### 附录 2.1：安全参考模型

如满足以下条件，模型可以就被项系统性风险而言被视为安全参考模型：
(1) 该模型：(a) 已在本章发布之前投放市场；或 (b) 已完成全流程系统性风险评估和缓解流程（依据措施 1.2 第三款），包括该模型产生的系统性风险已被认定为可接受（依据承诺 4），且人工智能办公室已收到其模型报告（依据承诺 7）；
(2) 签署方对该模型的特征（如相关架构细节、能力、倾向、功能特征和安全缓解措施）具有充分可见性。对于签署方自身开发的所有模型，以及签署方能够获得完成全流程系统性风险评估和缓解流程（依据措施 1.2 第三款）所必需的全部信息（包括模型参数）的所有模型，均推定具有此类可见性；以及
(3) 没有其他合理理由认为该模型产生的系统性风险不可接受。


### 附录 2.2：同等安全或更安全模型

如满足以下条件，模型可以就某项系统性风险而言被视为同等安全或更安全模型：

```
(1) 在开展系统性风险识别（依据承诺 2）后，签署方未合理预见该模型与该系统性风险相关的系统性风险情景（依据措施 2.2）与安全参考模型存在任何实质性差异；
(2) 该模型在相关的至少最先进的轻量级基准测试上的得分全部低于或等于（在可忽略的误差范围内）安全参考模型的得分。与安全参考模型相比导致系统性风险无实质性增加的能力小幅提升可以不予考虑。此类基准测试必须已依据措施 3.2 运行；以及
(3) 与该安全参考模型相比，该模型的特征（如相关架构细节、能力、倾向、功能特征和安全缓解措施）不存在可合理预见会导致系统性风险实质性增加的已知差异，且没有其他合理理由认为该模型产生的系统性风险与安全参考模型相比已实质性增加。
```
在评估前款第(2)和第(3)点以及附录 2.1 第(2)点时，签署方将通过纳入足够宽的安全边际，适当考虑可能源于例如参考模型信息不足和测量误差的不确定性。

如签署方此前认定为安全参考模型（用于将另一模型视为同等安全或更安全模型）的模型随后失去其安全参考模型地位，签署方将在六个月内：

```
(1) 确定另一安全参考模型，使该模型可以相对于其被视为同等安全或更安全模型；或
(2) 如先前对该其他模型的遵守系依赖其同等安全或更安全地位所享有的豁免和/或减免，则将该模型视为受本章全部承诺和措施的约束，包括完成全流程系统性风险评估和缓解流程（依据措施 1.2 第三款）中先前被豁免和/或减免的全部部分。
```
## 附录 3：模型评估

以下内容规定在全流程系统性风险评估和缓解流程（依据措施 1.2 第三款）期间措施 3.2 所要求的模型评估。

### 附录 3.1：严谨的模型评估

签署方将确保模型评估以高度科学与技术严谨性开展，确保：

```
(1) 内部有效性；
(2) 外部有效性；以及
(3) 可复现性。
```

### 附录 3.2：模型诱发

签署方将确保模型评估以至少最先进水平的模型诱发开展，通过使用至少最先进的技术诱发模型的能力、倾向、功能特征和/或影响，该等技术：

(1) 最大限度降低低诱发风险；以及
(2) 最大限度降低模型评估期间模型欺骗的风险（例如故意表现不佳）；
例如通过调整测试时计算量、速率限制、脚手架和工具，以及开展微调和提示工程。

为此，签署方将至少：
(1) 匹配与系统性风险情景（依据措施 2.2）相关的滥用行为者的模型诱发能力；以及
(2) 匹配模型的预期使用情境（例如同等脚手架和/或工具访问），该情境由以下 AI 系统整合情况提供信息：
(a) 为该模型计划或考虑的整合；和/或
(b) 目前用于类似模型的整合，如签署方知悉此类整合且无法排除其模型被类似使用。

### 附录 3.3：评估缓解措施的有效性

签署方将确保模型评估以适合系统性风险可接受性判定对特定缓解措施有效性依赖程度的广度和深度，评估其安全缓解措施的有效性，包括在对抗性压力下（例如微调攻击或越狱）。为此，签署方将使用至少最先进的技术，并考虑：

```
(1) 其缓解措施按计划发挥作用的程度；
(2) 其缓解措施被规避、停用或颠覆的程度或已被规避、停用或颠覆的程度；以及
(3) 其缓解措施有效性在未来发生变化的概率。
```
### 附录 3.4：合格的模型评估团队和充足的资源

签署方将确保负责开展模型评估的团队兼具与该系统性风险相关的领域知识的技术专长，以实现整体性、多学科性的理解。此类技术专长和/或相关领域知识的参考性资质包括：

```
(1) 拥有与该系统性风险相关的博士学位、经同行评审且被认可的出版物，或同等的研究或工程经验；
(2) 设计或开发过针对该系统性风险的、已发布且经同行评审或被广泛使用的模型评估方法；或
(3) 在与该系统性风险直接相关的领域拥有三年工作经验，或如该领域尚处于萌芽阶段，则拥有在该领域学习或在与可直接迁移知识相关的领域工作的同等经验。
```

模型评估团队将获得：

```
(1) 依据本附录 3 开展模型评估所需的充足模型访问权限，包括（酌情）访问模型激活、梯度、对数几率（或其他形式的模型原始输出）、思维链和/或其他技术细节，以及访问已实施最少安全缓解措施的模型版本（如仅助益模型版本存在）。关于为模型评估团队提供增强模型访问权限的充分性，签署方将考虑这可能带来的模型安保潜在风险，并为评估实施适当的安全措施；
(2) 适当的信息，包括模型规格（包括系统提示词）、相关训练数据、测试集和历史模型评估结果，其适当性依据：(a) 该系统性风险；以及 (b) 该模型评估方法；
(3) 胜任地设计和/或调整、调试、执行和分析依据本附录 3 的模型评估的时间，其适当性依据：(a) 该系统性风险；以及 (b) 该模型评估方法及其新颖性。例如，至少 20 个工作日的时间对大多数系统性风险和模型评估方法是适当的；以及
(4) (a) 充足的计算预算，包括允许足够长的模型评估运行时间、并行执行和重新运行；(b) 充足的人员配备；以及 (c) 充足的工程预算和支持，包括检查模型评估结果以识别和修复可能导致能力估计被人为降低的软件错误或模型拒绝。关于(b)点，如签署方聘请独立外部评估者，其可以依赖后者关于其人员配备是否充足的保证。
```
### 附录 3.5：独立外部模型评估

除内部模型评估外，签署方将确保资质充分的独立外部评估者依据本附录 3，就该系统性风险开展模型评估，除非：

```
(1) 该模型是依据附录 2.2 的同等安全或更安全模型；或
(2) 签署方尽管进行了早期搜寻努力（例如通过为期 20 个工作日的公开征集），仍未能任命资质充分的独立外部评估者，并已及时通知已识别的评估者；在此情况下，签署方在确定模型产生的系统性风险是否可接受（依据承诺 4）时，将考虑因缺乏独立外部评估（依据本附录 3.5）而产生的潜在额外不确定性。
```
独立外部评估者的资质充分要求：

```
(1) 拥有针对该系统性风险的重要领域专长，并在开展模型评估方面技术娴熟且经验丰富；
(2) 已建立适当的内部和外部信息安全协议；以及
(3) 已同意保护商业机密信息（如需要访问此类信息）。
```
签署方将向独立外部评估者提供充足的访问权限、信息、时间和其他资源（依据附录 3.4），且不影响附录 4.4 第(1)点。未经评估者明确许可，签署方不得通过存储和/或分析测试运行的输入和/或输出来损害外部模型评估的完整性。


属于中小企业或小型中型企业的签署方可以联系人工智能办公室，该办公室可以提供支持或资源以协助遵守本附录 3.5。

## 附录 4：安保缓解目标与

## 措施

以下规定为实现安保目标而应实施的安保缓解目标与措施（依据措施 6.2）。

### 附录 4.1：一般安保缓解措施

签署方将实施能够实现以下缓解目标的一般安保缓解措施：

```
(1) 防止未经授权的网络访问，通过 (a) 强有力的身份和访问管理实践，包括对设备和账户共享的限制、多因素认证、强密码执行、强访问管理工具、802.1x 认证、零信任架构、无线网络保护达到与有线网络相同的标准，以及任何访客网络与工作网络的隔离；
(2) 降低社会工程风险，通过 (a) 对可疑附件、链接和其他钓鱼尝试进行电子邮件过滤；
(3) 降低恶意软件感染和便携设备被恶意使用的风险，通过 (a) 制定关于可移动介质使用的政策；以及
(4) 降低漏洞利用和恶意代码执行的风险，通过 (a) 定期软件更新和补丁管理。
```
### 附录 4.2：未发布模型参数的保护

签署方将通过实施能够实现以下缓解目标的安保缓解措施来保护未发布的模型参数：

```
(1) 对所有设备和地点存储的模型参数全部副本的可问责性，通过 (a) 建立存储模型参数的所有设备和地点的安全内部登记册；
(2) 防止模型参数被未经授权复制到不受管理的设备，通过 (a) 对所有存储模型参数的设备进行访问管理，并在复制到不受管理的设备时发出警报；
(3) 防止传输中和静态存储时对模型参数的未经授权访问，通过 (a) 确保模型参数在运输和存储过程中始终酌情加密，包括至少 256 位安全强度的加密，且加密密钥安全存储在可信平台模块（TPM）上；
(4) 防止临时存储期间对模型参数的未经授权访问，通过 (a) 确保模型参数仅为合法用途解密到非持久性内存；
```

```
(5) 防止使用期间对模型参数的未经授权访问，通过 (a) 酌情实施机密计算，使用基于硬件且经证明的可信执行环境；以及
(6) 防止对托管模型参数的系统的未经授权物理访问，通过 (a) 将数据中心和其他敏感工作环境的物理访问仅限必要人员，并定期检查此类场所是否存在未经授权的人员或设备。
```
### 附录 4.3：加固对未发布模型参数的接口访问

签署方将通过实施能够实现以下缓解目标的安保缓解措施，加固使用期间对未发布模型参数的接口访问：

```
(1) 防止对模型参数不必要的接口访问，通过 (a) 仅明确授权必要的软件和人员访问模型参数，通过多因素认证机制强制执行，并至少每六个月定期检查；
(2) 降低漏洞利用或数据泄露的风险，通过 (a) 由安全团队对任何可访问模型参数的软件接口进行彻底审查以识别漏洞或数据泄露，和/或对任何软件接口代码进行自动化安全审查，标准至少与其他敏感代码所采用的最高级别自动化安全审查相同；
