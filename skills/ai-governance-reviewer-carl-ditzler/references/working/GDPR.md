(1) 自然人在个人数据处理方面的保护是一项基本权利。《欧盟基本权利宪章》（下称《宪章》）第8条第1款和《欧洲联盟运行条约》（TFEU）第16条第1款规定，人人有权获得与其有关的个人数据的保护。

```
(2) 无论国籍或居住地如何，关于自然人在其个人数据处理方面受到保护的原则和规则，均应尊重其基本权利和自由，特别是其个人数据受保护的权利。本条例旨在促进实现一个自由、安全和公正的区域以及经济联盟，促进经济和社会进步，加强内部市场内各经济体的实力并推动其趋同，并增进自然人的福祉。

(3) 欧洲议会和理事会第95/46/EC号指令（^4）旨在统一各成员国在处理活动方面对自然人基本权利和自由的保护，并确保个人数据在成员国之间的自由流动。

(4) 个人数据的处理应旨在为人类服务。个人数据受保护的权利不是一项绝对权利；必须结合其在社会中的功能来考量，并根据相称性原则与其他基本权利相平衡。本条例尊重《条约》所载《宪章》承认的所有基本权利和自由与原则，特别是尊重私人和家庭生活、住宅和通信，保护个人数据，思想、良心和宗教自由，言论和信息自由，经营自由，获得有效救济和公正审判的权利，以及文化、宗教和语言多样性。

```
(5) 内部市场运作所产生的经济和社会一体化，导致个人数据跨境流动大幅增加。整个联盟范围内，公共和私人主体（包括自然人、协会和企业）之间的个人数据交换有所增加。欧盟法律要求成员国的国家当局相互合作并交换个人数据，以便能够履行职责或代另一成员国的当局执行任务。
```
```
(6) 快速的技术发展和全球化给个人数据保护带来了新的挑战。个人数据的收集和共享规模显著增加。技术使私营公司和公共当局都能够在史无前例的规模上利用个人数据来开展其活动。自然人越来越多地在全球范围内公开提供个人信息。技术改变了经济和社会生活，并应进一步促进个人数据在联盟内的自由流动以及向第三国和国际组织的传输，同时确保对个人数据的高水平保护。
```
```
(7) 鉴于建立信任以允许数字经济在整个内部市场发展的重要性，这些发展要求联盟建立一个强大且更协调的数据保护框架，并以强有力的执法为后盾。自然人应当能够控制自己的个人数据。应当加强对自然人、经济经营者和公共当局的法律确定性和实践确定性。
```
```
(8) 凡本条例规定由成员国法律对其规则作出具体规定或限制的，成员国可以在此类规定为保持一致性以及使适用国家规定的相关主体能够理解所必需的范围内，将本条例的要素纳入其国内法。
```
```
(9) 第95/46/EC号指令的目标和原则仍然合理，但它未能防止联盟范围内数据保护实施的分裂、法律不确定性，以及公众普遍认为自然人的保护存在重大风险——特别是在线上活动方面。各成员国在个人数据处理方面对自然人权利和自由（特别是个人数据受保护的权利）保护水平的差异，可能阻碍个人数据在整个联盟内的自由流动。因此，这些差异可能构成在联盟层面开展经济活动的障碍，扭曲竞争，并妨碍当局履行其在欧盟法律下的职责。这种保护水平的差异源于第95/46/EC号指令在实施和适用上的差异。
```
```
(10) 为确保对自然人的保护水平一致且高，并消除联盟内个人数据流动的障碍，各成员国在对这类数据处理方面对自然人权利和自由的保护水平应当相同。应当确保整个联盟一致且统一地适用关于在处理个人数据方面保护自然人基本权利和自由的规则。对于为遵守法律义务、为执行公共利益任务或行使赋予控制者的官方权力而进行的个人数据处理，应当允许成员国保留或引入国内规定，以进一步具体化本条例规则的适用。结合实施第95/46/EC号指令的通用横向数据保护法律，成员国在需要更具体规定的领域制定了若干部门特定法律。本条例还为成员国具体化其规则提供了余地，包括对特殊类别个人数据（“敏感数据”）的处理。就此而言，本条例不排除规定特定处理情形（包括更精确地确定个人数据处理合法条件）的成员国法律。

```
```
（d）准确，并在必要时保持最新；必须采取一切合理步骤，确保考虑到其处理目的而不准确的个人数据得到及时删除或更正（‘准确性’）；

```

```

```

```

第33条
```
```
向监管机构通知个人数据泄露
```
1. 发生个人数据泄露时，控制者应当在没有不当延迟的情况下，并在可行的情况下不迟于知悉后72小时，向按照第55条有管辖权的监管机构通知该个人数据泄露，除非该个人数据泄露不太可能导致自然人权利和自由面临风险。如果在72小时内未向监管机构发出通知，应当附上延迟的原因。
2. 处理者在知悉个人数据泄露后，应当在没有不当延迟的情况下通知控制者。
3. 第1款所述通知至少应当：

```
（a）描述个人数据泄露的性质，包括在可能的情况下，相关数据主体的类别和大致数量，以及相关个人数据记录的类别和大致数量；
```
```
（b）传达数据保护官的姓名和联系方式或其他可以获得更多信息的联系点；
```
```
（c）描述个人数据泄露的可能后果；
```
```
（d）描述控制者为应对个人数据泄露而采取或拟采取的措施，包括在适当情况下减轻其可能不利影响的措施。
```
4. 当无法同时提供信息时，信息可以在没有进一步不当延迟的情况下分阶段提供。
5. 控制者应当记录任何个人数据泄露，包括与个人数据泄露有关的事实、其影响和采取的补救行动。该记录应当使监管机构能够核实对本条的遵守情况。

```

```
1. 当个人数据泄露可能导致自然人权利和自由面临高风险时，控制者应当在没有不当延迟的情况下向数据主体传达该个人数据泄露。

2. 本条第一款所述向数据主体的传达，应当以清晰明了的语言描述个人数据泄露的性质，并至少包含第33条第(3)款(b)、(c)和(d)项所述的信息和措施。
3. 在满足以下任一条件时，不要求进行第1款所述向数据主体的传达：

```
（a）控制者已实施适当的技术和组织保护措施，且这些措施已适用于受个人数据泄露影响的个人数据，特别是使个人数据对任何未经授权访问的人无法理解（如加密）；
```
```
（b）控制者已采取后续措施，确保第1款所述对数据主体权利和自由的高风险不再可能发生；
```
```
（c）这将需要不相称的努力。在此种情况下，应当改以公开传达或类似措施，以同样有效的方式告知数据主体。
```
4. 如果控制者尚未向数据主体传达个人数据泄露，监管机构在考虑该个人数据泄露导致高风险的可能性后，可以要求其进行传达，或者可以决定第3款所述的任何条件已得到满足。

第35条

```
数据保护影响评估
```
1. 当某类处理（特别是使用新技术的处理），考虑到处理的性质、范围、背景和目的，可能对自然人权利和自由造成高风险时，控制者应当在处理之前，对拟议处理操作对个人数据保护的影响进行评估。单一评估可以涵盖呈现类似高风险的一组类似处理操作。
2. 控制者在进行数据保护影响评估时，应当征求（如已指定）数据保护官的意见。
3. 在以下情况下，特别要求进行第1款所述的数据保护影响评估：

```
（a）对与自然人有关的个人方面进行系统性和广泛的评估，该评估基于自动化处理（包括画像），并以此为基础作出对自然人产生法律效力或类似地显著影响自然人的决定；
```
```
（b）大规模处理第9条第(1)款所述的特殊类别数据，或第10条所述与刑事定罪和违法行为有关的个人数据；或
```
```
（c）对大规模公开可进入区域进行系统性监测。
```
4. 监管机构应当建立并公布按照第1款须进行数据保护影响评估的处理操作类型的清单。监管机构应当将这些清单传达给第68条所指的数据保护委员会。
5. 监管机构还可以建立并公布不需要数据保护影响评估的处理操作类型的清单。监管机构应当将这些清单传达给数据保护委员会。

5. 数据保护官应当基于专业素质指定，特别是数据保护法律和实践方面的专业知识以及履行第39条所述任务的能力。
6. 数据保护官可以是控制者或处理者的工作人员，或基于服务合同履行任务。
7. 控制者或处理者应当公布数据保护官的联系方式，并将其传达给监管机构。

第52条
```
```
独立性
```
1. 每个监管机构在按照本条例履行其任务和行使其权力时，应当完全独立行事。
2. 每个监管机构的成员在按照本条例履行其任务和行使其权力时，应当不受任何直接或间接的外部影响，并且不应当寻求或接受任何人的指示。
3. 每个监管机构的成员应当避免任何与其职责不相容的行为，并且不应当在其任期内从事任何不相容的职业，无论是否有报酬。
4. 每个成员国都应当确保每个监管机构获得有效履行其任务和行使其权力所必需的人力、技术和财政资源、办公场所和基础设施，包括在互助、合作和参与数据保护委员会背景下进行的工作所需资源。
5. 每个成员国都应当确保每个监管机构选择并拥有自己的工作人员，这些工作人员应当仅受相关监管机构成员的专属指挥。
6. 每个成员国都应当确保每个监管机构受到不影响其独立性的财务控制，并拥有单独的、公开的年度预算，该预算可以是整个国家或国内预算的一部分。

第61条
```
```
互助
```
1. 监管机构应当以一致的方式相互提供相关信息和互助，以实施和适用本条例，并应当建立彼此有效合作的措施。互助应当特别涵盖信息请求和监督措施，例如进行事先授权和咨询、检查和调查的请求。

3. 援助请求应当包含所有必要信息，包括请求的目的和理由。交换的信息只能用于请求的目的。
4. 被请求的监管机构不得拒绝满足该请求，除非：

```
（a）其对请求的主题或被请求执行的措施没有权限；或
```
```
（b）满足该请求将违反本条例或收到请求的监管机构所遵守的欧盟或成员国法律。
```

6. 被请求的监管机构通常应当使用标准化格式，以电子方式提供其他监管机构请求的信息。
7. 被请求的监管机构不应当对它们按照互助请求采取的任何行动收费。监管机构可以商定规则，在特殊情况下就提供互助所产生的特定支出相互补偿。

第77条
```
```
向监管机构提出投诉的权利
```
1. 在不影响任何其他行政或司法救济的情况下，如果数据主体认为与其有关的个人数据的处理违反本条例，每个数据主体都有权向监管机构提出投诉，特别是向其经常居住地、工作地或涉嫌侵权发生地所在成员国的监管机构提出。

第78条
```
```
针对监管机构的有效司法救济权
```
1. 在不影响任何其他行政或非司法救济的情况下，每个自然人或法人都有权就监管机构作出的与其有关的具有法律约束力的决定获得有效的司法救济。
2. 在不影响任何其他行政或非司法救济的情况下，当按照第55条和第56条有管辖权的监管机构不处理投诉，或者在三个月内未告知数据主体按照第77条提出的投诉的进展或结果时，每个数据主体都有权获得有效的司法救济。
3. 针对监管机构的诉讼应当在监管机构设立所在成员国的法院提起。
4. 当诉讼是针对监管机构在一致性机制中先行获得数据保护委员会意见或决定后作出的决定而提起时，监管机构应当将该意见或决定转交给法院。

第79条
```
```
针对控制者或处理者的有效司法救济权
```
1. 在不影响任何可用的行政或非司法救济（包括按照第77条向监管机构提出投诉的权利）的情况下，当数据主体认为其在本条例下的权利因以不符合本条例的方式处理其个人数据而受到侵犯时，每个数据主体都有权获得有效的司法救济。
2. 针对控制者或处理者的诉讼应当在控制者或处理者设有机构的成员国法院提起。或者，此类诉讼可以在数据主体经常居住的成员国法院提起，除非控制者或处理者是行使其公共权力的成员国公共当局。

第81条

中止诉讼
```
1. 当成员国主管法院掌握关于同一控制者或处理者处理的同一事项的诉讼正在另一成员国法院待决的信息时，它应当联系该另一成员国的法院，以确认此类诉讼的存在。

第82条
```
```
获得赔偿的权利和责任
```
1. 任何人因违反本条例而遭受物质或非物质损害，都有权从控制者或处理者处获得对其所遭受损害的赔偿。
2. 参与处理的任何控制者都应当对违反本条例的处理造成的损害承担责任。处理者只有在未遵守本条例专门针对处理者的义务，或者超出或违反控制者合法指示行事时，才对处理造成的损害承担责任。
3. 控制者或处理者如果证明其对造成损害的事件没有任何责任，则应当按照第2款免除责任。
4. 当一个以上控制者或处理者，或控制者和处理者共同参与同一处理，且它们按照第2款和第3款对处理造成的任何损害负有责任时，为确保数据主体获得有效赔偿，每个控制者或处理者都应当对全部损害承担责任。
