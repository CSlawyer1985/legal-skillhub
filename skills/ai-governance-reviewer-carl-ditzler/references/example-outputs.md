# 示例输出

使用这些示例保持 skill 行为的一致性。

## 示例 1：仅接案回应

当用户要求审查但尚未提供足够事实或证据时，使用此模式。

```md
在起草审查意见之前，我需要一些事实和文件。

首先，我需要核心用例的详细信息：

- 该 AI 用例是什么，它要解决什么问题？
- 预期用户是谁？
- 贵组织在此的角色是什么：供应商的客户、部署者、集成商，还是其他？
- 涉及哪个模型或供应商（如已知）？

您分享这些之后，我会再问下一组简短问题。
```

不要将这些问题转换为 markdown 表格或填空表单。以用户可以用纯文本回答的直接问题形式提出，一次一个主题块。

## 示例 2：初步审查

仅在接案先行流程已经发生且用户不能或不愿提供更多信息后，使用此模式。

```md
# AI 治理审查草案

## 所请求 AI 用例摘要
- 用例：用于合同摘要的内部起草助手
- 场景：内部 AI 使用
- 组织角色：内部业务用户
- 预期用户：法律运营团队
- 模型／供应商：未知
- 涉及数据类型：合同文本；可能的机密信息
- 部署模型：未知
- 人类监督：使用前人工审查
- 测试与监测：未知
- 已审查文件／证据：仅用户描述

## 审查状态
初步审查

阻塞性未知项：
- 模型或供应商身份
- 部署模型
- 测试证据
- 监测计划
- 隐私与保留文件
```

只有在明确说明未知项和缺失证据会降低置信度之后，才继续评分卡。

## 示例 3：最终审查

仅在最低限度的事实和核心证据可用时，使用此模式。

```md
# AI 治理审查草案

## 所请求 AI 用例摘要
- 用例：面向客户的账单问题 AI 支持助手
- 场景：产品 AI 集成
- 组织角色：部署者和集成商
- 预期用户：现有客户
- 模型／供应商：供应商提供的 LLM 加内部检索层
- 涉及数据类型：账户数据和支持记录
- 部署模型：面向客户、供应商托管模型加内部控制
- 人类监督：升级至人工支持并手动覆盖
- 测试与监测：已完成功能、防滥用和分阶段发布测试；监测计划已记录
- 已审查文件／证据：架构概述、AI 影响评估、DPA、子处理者清单、测试摘要、披露文本、监测计划

## 审查状态
最终审查
```

继续评分卡、补救清单、置信度评估和后续步骤。
