# 《招投标合规风险尽调技能》完善建议 — 逐条评析与采纳结论

> 说明：以下对用户提供之「综合完善建议」逐条评析。判定分三类：**采纳 / 部分采纳 / 驳回**。
> 总方针：原稿业务逻辑（Domain Logic）优秀，问题集中在控制逻辑过载、示例矛盾、脱离真实网络环境。
> 修订方向遵循原建议八字——「修矛盾、做减法、补示例」，并叠加本专家对 LLM 推理能力的额外修正。

---

## 一、总体判断 —— 采纳
与原建议一致：底层业务逻辑（双轨验证、投诉/被投诉甄别、废标类型区分、时序加权）专家级；控制逻辑过载与矛盾；Few-Shot 最薄弱。方向「修矛盾、做减法、补示例」完全正确。

## 二、高优先级修订

### 2.1 修复示例定级逻辑矛盾 🔴 —— 采纳（方案 A）
- **问题真实**：原规则"虚假材料→红线→恒定高危"，但原 Few-Shot 将含"虚假材料行政处罚"的企业定为"中危"，直接冲突。
- **处理**：采用方案 A（改示例为高危），保持"红线恒定高危"核心原则自洽。同时在第7步合作建议中为高危保留"特殊情况严苛条件"的弹性路径，吸收方案 B"区分执行中/已了结"的合理关切，但不让定级算法复杂化。
- **已做一致性校验**：宪法级护栏第1条、第6步判定标准、示例1（高危）三者现已完全自洽。

### 2.2 修复 YAML 格式规范 🔴 —— 驳回（前提错误）+ 部分采纳（约束项）
- **关键发现**：原稿 YAML **本身合法**。`triggers:`、`parameters:`、`knowledge_bases:` 均带列表标记 `-`，且 `parameters` 用 `- name:` 正确缩进。原建议给出的"修正示例"反而**缺少 `-` 且 `name:` 缩进错误，是非法 YAML**，若照抄会破坏解析。
- **结论**：结构无需改。仅采纳其合理约束——为 `time_range` 增加 `max: 60` 上限，并将类型写为更规范的 `integer`/`boolean`。
- **风险提示**：该条是原建议中唯一存在事实误判的条目，已拦截，避免引入新 bug。

### 2.3 重构 KB 检索截断逻辑 🔴 —— 采纳（适配版）
- 原"机械读前2-3条"改为**相关性驱动选取**：优先读最相关 2-3 条，不相关则跳过/换词，单次 KB 调用硬上限 5 条。
- 不写死"relevance≥0.7"等数值（工具未必返回可依赖的分数字段），改为"与查询意图最相关"的语义判断，更稳健。

### 2.4 重构 URL 验证逻辑 🔴 —— 采纳（高价值）
- 新增 **A-级**：WebFetch 403/超时但搜索摘要同时含"政府域名+完整文号+处罚机构+日期"→ 视为有效，标注反爬限制、建议人工复核。
- 这是修复真实可靠性 bug 的关键改动：中国政府采购网/信用中国反爬常态，原"必须 200 才 A 级"会把大量真实处罚错误降级。

### 2.5 增加搜索总量熔断 🔴 —— 采纳（适配版）
- 设 WebSearch≤25、WebFetch≤8 的软上限；接近上限优先保留红线类与行政处罚维度，裁剪一般性废标/未中标；报告元数据如实标注裁剪。
- 避免 Agent 单次会话工具调用超限，提升稳定性。

### 2.6 增加企业状态前置检查 🔴 —— 采纳
- 第0步新增存续状态检查：注销/吊销/破产→转"历史合规回溯"；经营异常→纳入风险因子。低风险高价值。

## 三、中优先级修订

### 3.1 时序加权改定性规则 🟡 —— 采纳（强）
- LLM 无法可靠执行 ×1.5/×1.0/×0.7 浮点运算。改为定性升/降格：近6月升一级、12月前未复发降一级、红线恒定高危、禁入执行中按原级。显著降推理失败率。

### 3.2 输出格式拆互斥分支 🟡 —— 采纳
- quick 仅4模块且"严禁输出其余"；deep 全6模块，并约束【推演】≤200字、拓展分析仅≥2条同类型事件时生成。消除 quick 模式仍出推演的歧义。

### 3.3 法律标尺暂存区 🟡 —— 采纳（强）
- 第2.5步建立暂存区，后续引用必须从暂存区调用，防长上下文遗忘。属 scratchpad/working-memory 技术，显著提升法条引用准确性。

### 3.4 增加 region/industry 参数 🟡 —— 采纳
- 新增两可选参数，默认"全国/通用"，不增加默认路径负担，但支持属地化与行业化检索。

### 3.5 补充多场景 Few-Shot 🟡 —— 采纳（强）
- 原仅1个中危示例（且自相矛盾）。新增至5个：高危(deep)/中危(deep)/低危(时序降格)/无异常/quick。覆盖定级矩阵与模式分支，是稳定性提升最大单点。

### 3.6 优化科普过滤规则 🟡 —— 采纳（强）
- 原按 URL 含 law/falv 过滤会误杀 court.gov.cn 等有效证据。改为标题+摘要联合判断，保留"行政处罚决定书/投诉处理决定"等有效证据。修复误杀 bug。

### 3.7 安全边界与批量限制 🟡 —— 采纳
- 恶意意图词表（搞掉/整死/弄垮/找把柄打压）→ 拒绝；批量建议每次≤3家；免责声明嵌入执行摘要。原已有安全边界，此处强化。

## 五、架构级建议（Prompt 拆分）—— 部分采纳（落地为前置结构）

- 完整 Router+Analyst 双层拆分依赖框架多 Prompt 编排能力，当前单 SKILL.md 不支持。
- **已落地其兜底方案**：采用"宪法级护栏前置 + 详细规则后置"——把最不可违反的 6 条规则放在 instruction 最开头，利用 LLM 对首尾的高注意力。这在不改架构的前提下显著降低了"长指令末尾遗忘"风险。
- 若未来框架支持编排，可进一步拆为 Router（确定性逻辑：名称归一化、模式判定、计数、URL 状态码）与 Analyst（法律定性+模式分析+报告）。

## 六、专家额外诊断（原建议未覆盖）

1. **Few-Shot 占位符问题**：原示例用 "XX" 占位但分析逻辑空泛，模型学不到真实输出风格。新版示例给出具体文号、法条、定级链路。
2. **重复规则合并**：原稿证据分级与定级标准在"执行步骤"与"输出格式"两处重复出现，已合并至单一权威位置（做减法）。
3. **"第〇步"命名**：保留为"第0步"，避免非标准序号在部分解析器中的歧义。
4. **`instruction` 标量类型**：原稿用 `>`（折叠）会破坏多行表格；新版改用 `|`（字面量）确保 Markdown/表格完整保留。

## 七、一句话总结
业务逻辑满分答卷，修订核心是"修矛盾、做减法、补示例、适配 LLM 真实推理能力"。其中 2.2 的前提误判已被拦截（原 YAML 合法），2.4/3.6 修复了两个真实可靠性 bug（反爬降级、URL 误杀），3.1/3.3/3.5 是针对 LLM 推理的最关键稳定性提升。
