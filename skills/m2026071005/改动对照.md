# 改动前 / 改动后 对照表

> 版本：1.0.0（原稿 m2026071005）→ 2.0.0（bid-compliance-due-diligence-v2）

## 1. 结构重组

| 维度 | 改动前 | 改动后 | 理由 |
|---|---|---|---|
| 指令开头 | 直接进入角色定位 | **宪法级护栏 6 条置顶** | 利用 LLM 首尾高注意力，防长指令遗忘 |
| 指令标量 | `instruction: >`（折叠，破坏表格） | `instruction: \|`（字面量） | 保证 Markdown/表格完整 |
| 冗余 | 证据分级/定级在两处重复 | 合并至单一权威位置 | 做减法，降矛盾 |

## 2. 高优先级修复

| 条目 | 改动前（问题） | 改动后（修复） |
|---|---|---|
| 2.1 定级矛盾 | 规则"虚假材料=红线=恒定高危"，但示例定为中危 | 示例1 统一为**高危**；护栏第1条、判定标准、示例三方自洽 |
| 2.2 YAML | 建议称缺列表标记（误判） | **原 YAML 合法，未改结构**；仅加 `max:60`、类型 `integer` |
| 2.3 KB 截断 | "仅读前2-3条 highlight_content" 机械截断 | 相关性驱动选取，硬上限 5 条，不相关则换词 |
| 2.4 URL 验证 | 必须 WebFetch 200 才 A 级 | 新增 **A-级**（403/超时但摘要含政府域名+文号+机构+日期） |
| 2.5 搜索熔断 | 无上限，6轮×穿透≈30-40次搜索 | WebSearch≤25、WebFetch≤8；超阈优先保红线维度；元数据标注裁剪 |
| 2.6 状态检查 | 无 | 第0步新增注销/吊销/破产→历史回溯；经营异常→风险因子 |

## 3. 中优先级修复

| 条目 | 改动前 | 改动后 |
|---|---|---|
| 3.1 时序加权 | ×1.5/×1.0/×0.7 浮点（LLM 算不准） | 定性升/降格：近6月升一级、12月前降一级、红线恒定 |
| 3.2 输出分支 | 列6模块再文字说"quick省略" | quick/deep **互斥分支**；推演≤200字；拓展仅≥2条同类生成 |
| 3.3 法律标尺 | 步骤2检索法条隔6轮易遗忘 | 第2.5步**暂存区**，后续必须从暂存取用 |
| 3.4 参数 | 无地域/行业 | 新增 `region`/`industry`（默认全国/通用） |
| 3.5 Few-Shot | 1个中危示例（且矛盾） | **5个**：高危/中危/低危(降格)/无异常/quick |
| 3.6 科普过滤 | URL 含 law 即过滤（误杀 court.gov.cn） | 标题+摘要联合判断，保留"处罚决定/投诉决定"等 |
| 3.7 安全 | 拒恶意目的（弱） | 恶意意图词表+批量≤3家+执行摘要嵌免责 |

## 4. 低优先级采纳

- `version: 2.0.0` + `_meta.json` 版本
- 新增"适用边界"章节（境外/非招投标/个人/刑事不适用）
- 事件清单 9列→7列（信源/URL 转脚注）
- 报告元数据模块（生成时间/窗口/维度/KB版本/搜索次数）
