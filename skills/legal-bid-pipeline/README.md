# legal-bid-pipeline — 法务标书全链路生成

将投标文档制作从"人工逐章拼凑"升级为**多Agent协作自动化流水线**：可行性预评估 → 招标解析与模板识别 → 知识库优先并行写章 → 模板/自由双轨合稿 → 八道硬门槛质检 → 五维评审 → 评分项闭环补强 → 修改迭代 → PDF拼合交付 → 客户档案沉淀。覆盖政策合规、技术匹配、商务匹配、格式检查、模板对齐、废标风险六大管控维度。

---

## 快速开始

在 WorkBuddy 对话中直接说出意图即可，无需指定技能名称：

> 「帮我写XX项目的投标文件」「生成技术方案」「分析这份招标文件」「检查标书格式」「制作响应矩阵」「输出偏离表」

**你需要准备**：

| 类型 | 必需/推荐 | 说明 |
|------|:--------:|------|
| 招标文件（PDF/DOCX/MD/纯文本） | **必需** | 完整招标文件正文 |
| 律所简介、资质证书、案例库 | 推荐 | 阶段二编写时提取真实素材 |
| IMA知识库（`ima-mcp` 连接器） | 推荐 | 命中素材直接引用，减少AI幻觉 |

## 工作流概览

```
用户提供招标文件
   │
   v
阶段〇 投标可行性预评估 ────────── ← 确认点#0：继续投标 / 放弃
   │
   v
阶段一 总调度解析（要素提取+政策合规+风险库扫描+MECE拆解+模板识别）
   │                              ← 确认点#1：审核框架
   v
阶段二 IMA检索 → 知识库优先并行写章 → AI生成内容清单
   │                              ← 确认点#1.5：审核AI生成内容
   v
阶段三 模板/自由双轨合稿（模板=答题卡逐字填空，四步拷贝法保真）
   │
   v
阶段四 八道硬门槛质检（AND关系，一道不过即打回）
   │
   v
阶段五 五维并行评审（完整性20%+技术25%+商务15%+语言10%+评分博弈30%）
   │                              ← 确认点#2：交付 / 再改
   v
阶段五·B 评分项闭环补强（自动落稿）  ← 确认点#2.5：审核补强段落
   │
   v
阶段七 修改迭代（≤3轮）
   │
   v
阶段八 Word确认 → PDF拼合交付      ← 确认点#3：确认交付
   │
   v
阶段九 客户档案沉淀（private/clients/，下次投标复用）
```

> 全流程共 **6 个人工确认点**，其余阶段完全自动化。**Word-first 铁律**：先交付 docx 迭代，用户确认后才转 PDF。

### 核心设计原则

| 原则 | 含义 |
|------|------|
| **模板=答题卡** | 招标文件第五章给的格式逐字逐格填空，改一个字都有废标风险 |
| **四步拷贝法** | 模板进入标书唯一路径：段落deepcopy + numbering定义remap + 字体扁平化 + 失效样式清理 |
| **知识库优先** | 真实素材引用优先，AI生成段落强制标记溯源并集中人工确认 |
| **渲染验证** | XML对≠看着对，一切版面问题以转PDF逐页目检为最终裁决 |
| **三类材料三轨** | 招标模板→逐字填空 / 服务方案→按评分细则生成 / 业绩证件→图片内插 |
| **目录优先级链** | 招标规定组成顺序 > 评分标准结构（仅技术文件部分） > 招标目录线索 > 参考目录 |

### 八道硬门槛（AND关系）

字数 / 图表 / 表格 / 事实核查 / 格式 / 废标风险库复检 / 业务结构与团队边界 / 文档块唯一性与目录纯净度——任一不通过即打回。

│   └── review_checklist.md         #   评审标准与得分规则
│
├── scripts/                        # 辅助脚本
│   ├── setup_pagination.py         #   [v3.7.2] 页码与分节自动插入（合稿必调）

## 运行环境

- Python 3.9+（python-docx、PyMuPDF、Pillow）
- 阶段八 PDF 转换需本机安装 Microsoft Word（docx2pdf / AppleScript 调用，LibreOffice 不更新 TOC 域，禁用）
- 扫描件处理依赖 PyMuPDF + Pillow；OCR 字段抽取可选 PaddleOCR / Tesseract
- 无特定 IDE 或平台依赖
