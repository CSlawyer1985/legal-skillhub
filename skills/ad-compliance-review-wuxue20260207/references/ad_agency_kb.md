# 广告公司 AI 知识库（RAG）脚手架参考

本参考说明如何把"合规审查"从单文件词表匹配，升级为带语义检索的**多客户 RAG 知识库**，
并落实**权限隔离**。完整可运行脚手架见项目 `ad-agency-kb/`（由对话中落地）。

## 为什么升级到 RAG

- 词表匹配只能查"有没有这个词"，无法理解语义（如"见效最快"vs"见效快"）。
- RAG 让 AI 基于客户自己的资料（品牌调性、历史案例、合规口径）做**语义级审查与改写**，更准确。
- 多客户场景下，RAG + 权限隔离可同时服务 N 家广告客户，资料不串味、不泄密。

## 架构（三段式）

```
知识来源（多租户隔离）
  ├─ <client_A>/ brand.md, cases.md, banned_words.md ...
  └─ <client_B>/ ...
        │
        ▼
处理引擎
  ├─ 解析与切片（按段落 + 滑动重叠窗口）
  ├─ 向量化嵌入（本地哈希 / bge / API embedding）
  ├─ 标签与权限隔离（tenant = 客户）
  └─ 向量库检索（Chroma / Milvus / 本地 JSON）
        │
        ▼
应用场景
  ├─ 合规风险审查（本 skill 的 review.py 可作为其中一环）
  ├─ 智能文案生成
  ├─ 案例 / 素材检索
  └─ 新人培训 / 提案辅助
```

## 技术选型决策

| 维度 | MVP 推荐 | 生产升级 |
|------|----------|----------|
| 模型 | OpenAI 兼容接口（可切 DeepSeek / 通义 / GLM） | 私有化 / 开源模型（Qwen、ChatGLM） |
| 向量库 | 本地 JSON 存储（零安装） | Chroma / Milvus / pgvector |
| 嵌入 | 本地哈希（demo） | bge-small-zh / 通用 API embedding |
| 切片 | 段落打包 + 重叠窗口 | 同左，按文档类型调参 |
| 标签 | 文件名/关键词自动 + Markdown 前置 tags | 同左 + 人工校正 |
| 权限 | 目录即租户 + 检索 tenant 过滤 | JWT 租户 token + 行级过滤 |

## 权限隔离要点

- **隔离边界 = 租户（tenant = 客户）**：资料按 `data/<tenant>/` 组织，入库打 `tenant` 字段。
- **检索强制 tenant 过滤**：`query()` 只在指定租户资料内检索，默认禁止跨客户。
- **生产加固**：在 API 层用 JWT / 租户 token 校验调用方身份；存储层按租户分库或加 `tenant_id` 行级过滤。

## 与合规审查 skill 的关系

- `review.py` 是**轻量、零依赖**的合规闸，适合快速嵌入客户现有系统。
- RAG 知识库是**重装版**，适合做"客户专属 AI 知识助手"，把审查、生成、检索统一在一个带权限隔离的系统里。
- 两者共用同一套客户资料（brand.md / banned_words.md），可平滑升级。
