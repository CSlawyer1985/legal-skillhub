# GMP 合规知识库（references）

> 本文件是 gmp-compliance-check 的可按需加载知识库，供 AI 在解读报告、生成整改建议、做方案/打单/投标响应时引用。
> 脚本本身只做关键词/规则匹配；本知识库让"按字面命中 → 按法规/条款解读 → 落到信息化能力"形成闭环。

## 适用场景

- 解读 `review.py` / `generate_report.py` 输出的合规报告（覆盖/部分/缺失、风险等级）
- 把"缺失/部分覆盖"项转化为整改方案与优先级
- 把 GMP 合规点映射到信息化能力，用于方案编写、投标应答、打单话术
- 回答客户对某条 GMP 条款的具体疑问（条款编号、含义、对系统的要求）

## 2. 数据完整性 ALCOA+ 九项原则

| 原则 | 含义 | 信息化能力示例 |
|------|------|----------------|
| Attributable 可归因 | 谁、何时、何操作 | 用户登录、唯一账号、操作时间戳 |
| Legible 清晰 | 任何时候可读 | 长期可读格式、归档与查询 |
| Contemporaneous 同步 | 操作同时记录，不后补 | 实时记录、自动留痕 |
| Original 原始 | 第一手数据 | 不允许覆盖、保留原始痕迹 |
| Accurate 准确 | 与实际一致 | 输入校验、合理范围、双人复核 |
| Complete 完整 | 全部数据，无遗漏 | 必填校验、流程闭环 |
| Consistent 一致 | 跨系统/时序一致 | 主数据统一、唯一时间源 |
| Enduring 持久 | 留存期内可查 | 备份、归档、防丢失 |
| Available 可用 | 监管/质量可调取 | 高可用、检索能力 |

> 自检脚本的"数据完整性"域会扫描这 9 个原则的关键词；任意子项缺失即视为该域不合规。

## 3. CSV（计算机化系统验证）生命周期

```
URS（用户需求）→ FS（功能说明）→ DS（设计说明）
   → IQ（安装确认）→ OQ（运行确认）→ PQ（性能确认）
   → 验证报告与定期复核
```

关键交付物：
- 验证总计划（VMP）
- 风险评估与 GAMP 5 分类
- 供应商审计
- CSV 计划、验证矩阵
- 偏差/CAPA、变更控制
- 定期复核（periodic review）

## 4. 自检脚本输出解读

| 状态 | 含义 | 建议动作 |
|------|------|----------|
| ✔ 覆盖 | ≥50% 关键词命中 | 维持并定期复核 |
| ◐ 部分覆盖 | 有部分相关表述 | 补全规范/制度文档，明确流程 |
| ✘ 缺失 | 未覆盖任何关键词 | 高/中风险的需立即整改，落地制度+系统能力 |
| 整体风险=高 | 存在"高风险"项缺失 | 优先整改高风险项，再系统性补齐 |

> 关键词命中率是**初筛**：未命中 ≠ 一定不满足（可能用了同义词/换说法）；可启用 `--config` 接大模型做语义级确认。
> 反之，命中 ≠ 一定合规——必须配合文件制度+系统能力+定期复核。

## 5. 整改建议的常见最佳实践（不绑定具体厂商）

- **数据完整性**：建立数据治理组织与 SOP，关键数据启用审计追踪与防篡改
- **CSV**：建立 VMP，按 GAMP 5 风险分级实施验证；定期复核
- **审计追踪**：覆盖登录、创建、修改、删除、签发、审批等关键动作，不可关闭、定期审核
- **电子签名/权限**：唯一身份识别、密码策略（复杂度/有效期/锁定）、角色与权限矩阵
- **批次追溯**：批次主数据 + 批次谱系（正反向），物料平衡与放行流程
- **变更控制**：变更申请→评估→批准→实施→确认→关闭闭环
- **偏差/CAPA**：偏差识别、调查、根本原因（5Why/FTA/FMEA）、有效性确认
- **备份/容灾**：RTO/RPO 明确，定期演练
- **时间同步**：NTP、时区一致、关键记录时间不可篡改
- **培训/资质**：年度培训矩阵、上岗资格确认、复训机制

## 6. 合规→信息化能力的映射思路（方案/打单/投标响应）

把每条 GMP 合规诉求映射到信息化能力，回答两个问题：**"系统能否满足"** 和 **"如何证明满足"**：

| 合规诉求 | 能力维度 | 可提供的证据/演示 |
|----------|----------|---------------------|
| 审计追踪 | 系统能力 | 配置演示、日志样例、审计报告样例 |
| ALCOA+ | 数据治理 | 数据字典、元数据、保留期策略、归档与查询 |
| 电子签名 | 身份鉴别 | 签名流程、绑定关系、防篡改演示 |
| 批次追溯 | 业务能力 | 正反向追溯模拟、批次谱系图、物料平衡 |
| 变更控制 | 流程能力 | 变更流程配置、签审记录、关闭率 |
| 偏差/CAPA | 业务能力 | 偏差单、CAPA 跟踪、有效性复核记录 |
| 备份/容灾 | 运维能力 | 备份策略、RTO/RPO、演练报告 |
| CSV 验证 | 服务能力 | 方法论、文档模板、案例与客户认证 |
| 时间同步 | 基础设施 | NTP、统一时钟、可篡改防护 |
| 培训/资质 | 组织能力 | 培训矩阵、上岗资格、再认证 |

> 实际方案/投标时，按客户**品种**（化药/生物药/中药/原料药/制剂/包装）和**剂型**（口服/无菌/生物制品/细胞治疗等）进一步收敛重点条款——例如无菌制剂对环境监测和隔离器的要求、细胞治疗对患者/物料链追溯的要求。

## 7. 常见误区

- "上线" = "合规"：没有 URS/FS/IQ/OQ/PQ 与定期复核，仍属不合规
- 审计追踪默认关闭，或可由普通用户关闭：必须默认开启、不可关闭
- 共享账号/工号：违反 ALCOA 的 Attributable
- 截图/手填替代系统记录：违反 Original / Contemporaneous
- 修改无留痕（覆盖写、未留前后比对）
- 把"做过验证"等同"持续合规"：缺定期复核
- 仅做"功能满足"而不做"文件化证据"：监管看证据

## 8. 自检报告快速行动表

| 报告结果 | 优先级 | 行动 |
|----------|--------|------|
| 整体风险=高 且 高风险项缺失 | P0 | 立即启动整改；先补高风险项 |
| 整体风险=中 | P1 | 季度内整改，补齐中风险项 |
| 整体风险=低 | P2 | 维持 + 定期复核；持续优化 |
| 单一域缺失但其它域覆盖好 | P1 | 专项补齐该域；其它域可作为亮点话术 |
| 关键词命中但缺文件制度 | P1 | 词面合规 vs 实质合规：补制度+留存证据 |

## 9. 与打单/方案侧的衔接

把自检报告作为"客户教育"与"方案价值具象化"工具：
- 客户自检 → 看到高风险项 → 我们的方案对应"能力证据"（见第 6 节表）→ 形成对照
- 多个客户的报告聚类 → 形成"行业合规白皮书" → 获客内容
- 报告中的整改建议 → 直接转化为实施服务/产品配置清单
- 整体风险评分 → 纳入项目分级（高风险客户需更深咨询 + 更大服务范围）

> 上述话术不绑定具体厂商；映射到贵司产品/方案时替换"能力证据"列即可。
