# document-approval-tracker

**插件：** LPM 核心插件（14 个技能中的第 14 个）
**所属：** [LPM Skills for Claude](https://github.com/legalopsconsulting/lpm-skills)

---

## 本技能做什么

设计并跟踪多利益相关方的文件审批工作流——定义审查顺序、监控文件在级联中的位置、催促逾期的审查者、协调版本控制，并绘制跨法域的文件依赖关系。

文件审批是大多数法律案件上隐形的关键路径。合伙人和客户知道需要存在哪些文件；在截止日期出现之前，没有人跟踪它们在审查链中的位置。本技能旨在让级联在截止日期之前可见，而非之后。

---

## 模式

| 模式 | 何时使用 |
|---|---|
| **模式 1——级联设计** | 在案件设立时，定义谁审查文件以及按什么顺序 |
| **模式 2——位置跟踪** | 文件正在流转中——跟踪它在哪里以及已停留多久 |
| **模式 3——逾期催促** | 审查者逾期——在正确的升级阶段产出催促邮件 |
| **模式 4——版本控制** | 审查者手头是错误版本，或版本控制已崩溃 |

---

## 编码的关键设计原则

**在第一份草稿之前定义级联，而不是在它准备好时。** 审批顺序必须在案件设立时商定——而不是在文件流传时临时拼凑。

**客户侧的不透明是最难的问题。** 在首次流转前，询问客户的内部级联和具名的周转期限。"我们会审查并回复"不是承诺。

**电子邮件承担通知；案件站点承担文件。** 每一封电子邮件附件都会产生版本风险。SharePoint 是唯一事实来源；电子邮件仅用于通知。

**写明截止日期。不要软化它。** "当您有空时"教会审查者截止日期是灵活的。催促邮件写明日期、理由，然后停止。

**在 SLA 的 80% 处标记——而非到期时。** 一位文件在手 2.5 天、而 SLA 是 3 天的合伙人，现在就需要标记。

**在级联设计时绘制跨文件依赖。** 被德国税务意见阻塞的荷兰 SPA 是应在第一天就可见的依赖——而不是在第一份文件准备流转时才被发现。

## 输出

| 模式 | 主要输出 |
|---|---|
| 模式 1 | 审批级联文件——审查顺序、客户侧级联、依赖、缺口检查清单 |
| 模式 2 | 位置跟踪表——当前持有者、步骤停留天数、SLA 标记、下一步行动 |
| 模式 3 | 处于正确升级阶段的催促邮件（立即产出，无标识符关卡） |
| 模式 4 | 版本状态表 + 撤回邮件草稿 + 预防协议 |

## 使用说明（v1）

**模式 2/3——转发的邮件：** 粘贴描述逾期文件情况的转发"仅供参考"邮件时，在其前面加上 `[APPROVAL TRACKER]` 前缀。即使有该标记，此提示词模式也可能产生一般性建议输出，而非位置跟踪器和催促邮件。要可靠路由，请直接描述情况：*"NDA 在 [合伙人] 手中已 4 天，而 SLA 是 3 天。给我起草一封催促邮件。"*

**模式 1——级联设计：** 产出一份级联文件，而非关于审查顺序的建议性散文。如果出现的是散文，请重申：*"为 [案件] 上的 [文件名称] 产出审批级联文件。"*

- **文件的法律审查**——LPM 跟踪文件在级联中的位置；律师决定某个步骤是否完成
- **文件起草或修订**——本技能协调文件周围的工作流，而非文件本身
- **签署物流**——湿墨签名、公证、海牙认证（apostille）链——这些由 execution-and-signing-manager（LPM for M&A 插件，技能 19）处理

## 与本技能协作的技能

| 技能 | 关系 |
|---|---|
| matter-plan-builder | 文件产出任务 → 级联设计触发 |
| timeline-generator | 关键路径识别 → 对关键路径上文件的加速催促；审批延迟 → 时间线影响 |
| local-counsel-manager | 本地律师交付的文件在收到时进入级联 |
| stakeholder-comms-planner | 客户侧联系人和审批权限 → 客户级联输入 |
| status-report-drafter | 逾期文件和级联阻塞 → 风险与问题部分 |
| continuous-improvement-engine | 版本控制失败和级联缺口 → 经验捕获触发 |
