# 元典开放平台 - 根据企业 id / USCC 获取企业详情

> 接口文档来源：https://open.chineselaw.com/api-square/15
> 集成版本：v26.4.25.2006

---

## 1. 接口要点

| 项 | 值 |
|---|---|
| HTTP Method | `GET` |
| 正式 URL | `https://open.chineselaw.com/open/rh_company_detail` |
| 备用 URL（文档示例） | `/legal-insight/service/app/dify/company/companyDetail` |
| 鉴权 | Header `X-API-Key: <key>` |
| 入参 | `id`（企业 ID）或 `tyshxydm`（统一社会信用代码），二选一，互斥 |
| 优先级 | `id` 优先；两者皆空返回 `code=500, message="参数异常！"` |
| 计费 | **10 积分/次** |
| 单次返回 | size=1，永远只返一条最佳命中 |

> ⚠️ 文档 §2 与 §5 URL 不一致。客户端默认用 §2，若 404 再切 §5。

## 2. 客户端调用

```bash
export CHINESELAW_API_KEY=xxxxxxxx

# 按 USCC 查询，结果落盘到项目目录
python3 scripts/chineselaw_client.py company-detail \
    --uscc 91110108MA0074PN30 \
    --output <项目路径>/raw/chineselaw/

# 按企业 ID 查询，跳过扣费确认
python3 scripts/chineselaw_client.py company-detail \
    --id 078361f3-cee8-48c1-9af0-dcba3fa9a492 \
    --output <项目路径>/raw/chineselaw/ \
    --yes
```

## 3. 返回结构（全中文 key）

### 3.1 顶层

```json
{
  "status": "success" | "failed" | "notFound",
  "code": 200 | 201 | 404 | 500,
  "message": "...",
  "data": { ... } | null
}
```

判定成功：`status == "success"` 且 `code in (200, 201)`。

### 3.2 `data` 主要字段（可能存在的中文 key）

| 分组 | 字段 | 备注 |
|------|------|------|
| **基础标识** | `企业ID`、`企业名称` | 必有 |
| **工商登记** | `法定代表人`、`工商注册号`、`统一社会信用代码`、`组织机构代码`、`纳税人识别号`、`注册资本`、`企业类型`、`行业`、`成立日期`、`营业期限`、`核准日期`、`登记机关`、`注册地址`、`经营状态`、`经营范围` | 多数有 |
| **人员** | `董事`、`监事`、`经理`、`董事长`、`财务负责人`、`核心成员` | **逗号（中文「，」）分隔字符串**，非数组 |
| **股东** | `股东`（字符串）、`股东详情`（数组） | 出资额可能为空字符串 |
| **变更** | `变更`（数组） | 含 `变更项/变更前/变更后/变更时间` |
| **知识产权** | `商标`、`软件著作权`、`专利`、`知识产权`（聚合） | ⚠️ `知识产权` 是前三者的合并，**避免双计** |
| **涉诉** | `涉诉` | 仅在有数据时存在 |
| **风险** | `风险` | 仅在有数据时存在 |
| **分支机构、对外投资** | （文档列出但示例未现） | 仅在有数据时存在 |

### 3.3 已知数据质量问题

1. **字段动态存在**：必须用 `.get()` 容错，不能假设 key 一定有。已实测：无涉诉/风险/分支机构/对外投资的企业，对应字段**不会出现**（不是返回空数组）。
2. **列表条数封顶**：实测 `商标`/`软件著作权`/`专利` 各**最多返回 10 条**，`知识产权` 聚合**最多 15 条**。IP 较多的企业只能拿到部分清单，**不可视为完整**——应在底稿 §X.6 备忘中注明"清单不完整，需以企业自报或国知局检索为准"。
3. **日期格式混杂**：工商类 `2016年07月25日`，专利类 `2022-05-13` —— 写入底稿前应统一为 `YYYY-MM-DD`。
4. **数值带单位**：如 `注册资本: "6176.4706万人民币"` 是字符串，不能直接计算。
5. **空值表达不一**：`""` / `0` / `null` 都可能出现。
6. **重名歧义**：本接口不解决重名问题，**调用前应先用其他接口确认 USCC**。
7. **股东出资额常为空**：API 经常返回 `认缴出资额: ""`、`出资比例: 0`，**必须以章程/验资报告为准**。

## 4. 在 skill 各章节的使用规则

| 章节 | API 字段 → 底稿用法 | 注意 |
|------|----------|------|
| **第 1 章 主体资格** | `企业名称`/`统一社会信用代码`/`法定代表人`/`注册资本`/`成立日期`/`营业期限`/`登记机关`/`注册地址`/`经营状态`/`经营范围` → §1.4 调查发现 基础段落 | 必须与目标公司提供的营业执照核验，不一致时进 §1.5 风险 |
| **第 1 章** | `变更` 数组 → §1.4 历次变更段落 | 表格化呈现 |
| **第 2 章 股权结构** | `股东详情` → §2.4 股东列表初稿 | 出资额为空时**不得**填写"未出资"，应记"该接口未返回出资额，待章程/验资核实" |
| **第 3 章 公司治理** | `董事`/`监事`/`经理`/`董事长`/`财务负责人` → §3.4 董监高名单（split 中文「，」） | 任职文件仍需另行获取 |
| **第 4 章 核心资产** | `商标`/`软件著作权`/`专利` → §4.4 知识产权清单 | 用三个分项，不要再叠加 `知识产权` 聚合字段 |
| **第 9 章 诉讼** | `涉诉`（如有）→ §9.4 涉诉线索 | 仅作线索，需通过其他接口/裁判文书网获取详情 |
| **第 10 章 其他** | `分支机构`/`对外投资`（如有）→ §10.4 对外投资段落 | 仅作线索 |

## 5. 引用规范（写入底稿时）

固定模板（务必出现在 §X.4 调查发现 各段开头）：

> 经查阅元典开放平台「企业详情」接口（调用时间 `YYYY-MM-DD HH:MM`，原始数据见 `raw/chineselaw/company-detail-<key>-<ts>.json`），目标公司基本工商登记信息如下：……

如关键字段与目标公司提供材料**冲突**：

> 元典开放平台返回的[字段名]为「X」，与目标公司提供的[文件名]中记载的「Y」不一致。本所律师将进一步核实（见 §X.5 风险提示与 §X.6 律师备忘）。

## 6. 失败处理

| 场景 | 客户端表现 | 写入底稿 |
|------|-----------|---------|
| `code=500, "参数异常！"` | 退出码 0，已落盘 | §X.6 备忘记录 |
| `code=404, status=notFound` | 退出码 0，已落盘 | §X.6 记"该 USCC 在元典库中未命中"，并在 §X.5 标注 🟡 中风险（可能为新设企业或数据未收录） |
| 网络/超时 | 退出码 2 | §X.6 记调用失败时间与原因 |
| 凭证缺失 | 退出码 2 | 不进底稿（属环境配置问题） |
