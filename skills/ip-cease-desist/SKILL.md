# 知识产权侵权告知函

两种模式，选择其一：

- `--send` — 撰写一封与实施姿态匹配的侵权告知函。发送前通过交付前审查门。
- `--receive` — 对收到的侵权告知函进行分流分析，生成包含推荐的应对方案备忘录。

## 指引

1. **读取实务配置。** 加载法律实务配置文件（由运行时环境确定路径）。若配置文件包含 `[PLACEHOLDER]` 标记或不存在，停止并提示："本技能需要先完成初始配置才能产出有效结果。请先运行初始配置访谈——侵权告知函技能依赖你的实施姿态、审批矩阵和业务领域组合，这些均尚未配置。"

2. **检查事项工作区。** 依据配置中 `## 事项工作区` 的设定：若 `Enabled` 为 `✗`，跳过——技能使用实务层级上下文。若已启用但无活跃事项，询问："本次涉及哪个事项？请切换事项或说明使用实务层级。"

3. **根据参数分发：**
   - 若存在 `--send`：执行发送模式（见下文）。依次进行：确认权利、确认行为、确认关系、确认诉求、姿态校准、起草、交付前审查门。
   - 若存在 `--receive`：执行接收模式（见下文）。要求提供来函（路径或粘贴文本），然后评估、识别风险、呈现方案、撰写分流备忘录。
   - 若均未指定：询问一次——"我们是发出侵权告知函（主张权利）还是对收到的函件进行分流（防御应对）？"——然后分发。

4. **遵守审查门。** 发送模式下，交付前审查门在最终稿写入磁盘前运行。不得跳过。

5. **遵守审批矩阵。** 从 `## 实施姿态 → 审批矩阵` 中提取侵权告知函行的审批人。提取自动升级规则。在审查门中展示两者，不得掩盖。

6. **适时移交。** 接收模式下，若推荐方案为强硬回复，提议链接至 `--send` 模式并预填回复上下文。若推荐方案为提起确认不侵权之诉或提出无效宣告请求，升级至外部律师（依据实务配置的知识产权诉讼行）——不自行起草。

## 示例

```
--send
--receive ~/Downloads/incoming-cd-acme.pdf
（不带参数，由技能询问选择模式）
```

## 注意事项

- 对外发送的侵权告知函不包含律师工作成果标记。内部草稿、发送前简报和分流备忘录保留该标记。
- 商标权具有地域性；草稿默认使用实务配置中声明的注册辖区。若侵权行为或对方位于其他辖区，在起草前标出。
- 每一处 `[CITE:___]` 在经过法源核验前均为未核验状态。来源归属标签保留在草稿上。
- 非律师用户在审查门通过前获得一份供律师沟通的一页简报。

## 目的

侵权告知函主张一项法律权利，要求某人停止某项行为。这是知识产权实务发出或接收的最具影响力的函件之一。收到此类函件则启动了计时并迫使做出决定。本技能在双方场景下均设置了必要的保护机制。

两种模式：

- `--send` — 你在主张权利。撰写一封与实施姿态匹配的侵权告知函，交付前通过审查门。
- `--receive` — 你在防御应对。对来函进行分流分析，生成应对方案备忘录，必要时路由至事项创建。

若用户未传入模式参数，询问一次："我们是发出侵权告知函（主张权利）还是对收到的函件进行分流（防御应对）？"

> **对外交付物（发送模式）：** 起草的侵权告知函将发送给对方。对外发出的函件不得包含 `机密 — 律师工作成果` 标记。内部草稿、发送前简报和分流备忘录依据配置 `## 输出` 保留该标记。

## 管辖权假设

商标权具有地域性——中国注册商标不在其他国家自动生效。著作权虽依《伯尔尼公约》获得多边保护，但执法具有管辖权特定性，法定救济（包括中国《著作权法》第54条法定赔偿）取决于当地法律。本技能假设管辖权为事项或实务配置中声明的注册辖区。若侵权行为、对方或争议解决地在其他辖区，须标出——草稿可能不适用于该辖区。`[模型知识 — 需核验]`

## 加载上下文

- 实务配置文件（由运行时环境确定路径）→ `## 实施姿态`（姿态、侵权告知函触发条件、柔性函件标准、审批矩阵、自动升级），`## 知识产权实务配置`（业务领域组合、注册辖区、外部律师名册），`## 输出`（工作成果标记、角色），`## 使用者身份`（角色——律师 vs 非律师）
- 实务配置引用的任何侵权告知函模板或执法手册——读取并匹配结构
- **事项上下文。** 检查实务配置中 `## 事项工作区`。若 `Enabled` 为 `✗`（内部用户的默认值），跳过事项机制——技能使用实务层级上下文。若已启用但无活跃事项，询问："本次涉及哪个事项？请切换事项或说明使用实务层级。" 加载活跃事项的 `matter.md` 获取事项级别覆盖（如姿态覆盖、审批人覆盖）。将输出写入事项文件夹。不得读取其他事项的文件，除非 `跨事项上下文` 为 `on`。

## 发送模式 — 起草侵权告知函

### 步骤 1：确认权利

一次性询问：

> 我们主张哪项知识产权权利？
>
> - **商标权** — 是否已注册？注册机关（国家知识产权局）？注册号和类别？或仅享有未注册驰名商标/有一定影响的标识保护（驰名认定记录、使用范围）？
> - **著作权** — 是否已登记？作品名称、登记号、日期？或未登记（注：中国著作权自创作完成自动产生，登记非起诉要件，但在法定赔偿额度和证据效力上有实际意义）？
> - **两者兼具** — 分别确认。

记录每项权利。已注册权利按注册号引用。驰名商标/有一定影响的标识获取使用证据段落。未登记著作权标注提示："中国著作权自创作完成即产生，但未登记可能影响法定赔偿的主张——`[SME VERIFY]` 在函件威胁诉讼前确认。"

### 步骤 2：确认侵权行为

> 用具体事实而非形容词描述侵权行为：
>
> - **谁** 在实施——实体名称、个人、平台账号？
> - **什么** — 被控侵权的标识、被控侵权的作品、被控侵权的产品？附上或描述样本。
> - **哪里** — 网站URL、电商平台商品链接、实体零售、社交媒体？
> - **从何时起** — 首次发现日期、能证明的最早使用日期？
> - **证据** — 截图、购买凭证、监测服务报告、消费者混淆报告？

事实须具体。"你于[日期]在[URL]销售标有[标识]的产品X"优于"你一直在侵犯我们的权利"。证据薄弱时形容词反受其害。

### 步骤 3：确认关系

> 我方与收函方之间是什么关系？
>
> - **竞争对手**（直接或相关领域）——适用标准姿态
> - **经销商/渠道合作伙伴**——调整语气；考虑柔性函件路径
> - **前被许可人/前员工/前合作伙伴**——合同条款可能适用；引用相关条款
> - **陌生方/偶然侵权方**——标准姿态
> - **现有客户/合作伙伴**——依据实务配置自动升级；起草前标出

关系影响语气、审批人以及是否需要升级才能起草。

### 步骤 4：确认诉求

> 委托人实际想要什么？
>
> - **停止** — 停止侵权使用
> - **提供账目** — 报告销售、利润、数量（用于赔偿基数）
> - **销毁** — 销毁或召回侵权库存
> - **赔偿** — 金钱赔偿
> - **转移/转让** — 转让域名、移交账号、转让被控商标或著作权
> - **公开纠正** — 下架侵权内容、公开声明
> - **书面确认** — 在规定日期前提供合规承诺函

选择实际需要的救济方式。诉求须与损害相称——过度宽泛的诉求可能在后续诉讼中被认定为恶意主张。

**电商平台投诉并行路径（电商平台侵权）。** 若被控行为发生在电商平台（淘宝、天猫、京东、拼多多、1688、抖音电商、快手电商、小红书商城等），标出该平台的知识产权投诉路径作为更快、成本更低的并行途径，无需侵权告知函或诉讼：

- **阿里巴巴知识产权保护平台（IPP）** — 涵盖淘宝、天猫、1688、速卖通等阿里系平台（商标、著作权、专利投诉）
- **京东知识产权保护系统** — 商标/著作权/专利侵权投诉
- **拼多多知识产权保护平台** — 商标/著作权侵权投诉
- **抖音电商知识产权保护平台** — 商标/著作权/专利投诉
- **快手电商知识产权投诉** — 商标/著作权侵权投诉

电商平台投诉通常在数日内处理完毕；侵权告知函则给侵权方时间在谈判期间继续销售。两条路径并不互斥——当侵权行为发生在电商平台时，建议同时发起两条路径，侵权告知函覆盖平台投诉无法触及的站外行为（自营网站、批发渠道、社交媒体、实体零售）。在发送前简报中注明并行路径是否已提交、已排队或已放弃（及原因）。

**电商平台投诉的法律依据——《电子商务法》第42-45条：**
- **第42条（通知删除程序）：** 知识产权权利人认为其知识产权受到侵害的，有权通知电子商务平台经营者采取删除、屏蔽、断开链接、终止交易和服务等必要措施。通知应当包括构成侵权的初步证据。
- **第43条（反通知程序）：** 平台内经营者接到转送的通知后，可以向电子商务平台经营者提交不存在侵权行为的声明。声明应当包括不存在侵权行为的初步证据。电子商务平台经营者接到声明后，应当将该声明转送发出通知的知识产权权利人，并告知其可以向有关主管部门投诉或者向人民法院起诉。电子商务平台经营者在转送声明到达知识产权权利人后十五日内，未收到权利人已经投诉或者起诉通知的，应当及时终止所采取的措施。
- **第44条（平台信息披露义务）：** 电子商务平台经营者应当及时公示收到的知识产权侵权通知、平台内经营者的声明及处理结果。
- **第45条（平台连带责任——知道或应知侵权而未采取必要措施）：** 电子商务平台经营者知道或者应当知道平台内经营者侵犯知识产权的，应当采取删除、屏蔽、断开链接、终止交易和服务等必要措施；未及时采取必要措施的，对损害的扩大部分与平台内经营者承担连带责任。`[模型知识 — 需核验]`

### 步骤 5：姿态校准

读取 `## 实施姿态` → `默认姿态:` 并适用：

- **强硬** — 措辞坚定，短期限（通常7-14日），明示后果（诉讼、法定赔偿、惩罚性赔偿、禁令救济），不让步
- **适中** — 坚定但专业，标准期限（14-30日），后果表述不过度戏剧化，对方回复时开放讨论
- **保守** — 柔性函件框架，较长限期或无硬性限期，"我们希望商讨"的开场，后果表述弱化或省略

同时读取 `何时发送侵权告知函`、`何时先发柔性函`、`何时直接申请行政查处`。若事实表明依据实务配置应发柔性函或直接行政查处，在起草前标出："依据你的实施姿态，此模式匹配[柔性函/行政查处]。你仍然要发侵权告知函，还是选择[替代方案]？"

事项级别的覆盖（`matter.md` 中）优先于实务默认值。

### 步骤 5.5：对方尽调 — 必要前置条件

**在起草前，完成对方尽调并向用户展示结果。** 此步骤不以"对方看起来不大"为条件。每一封侵权告知函都带有确认不侵权之诉/反赔/恶意主张的风险，风险程度取决于收函方是谁。在用户确认尽调结果前，本技能不起草侵权告知函。

收集并一次性呈现以下内容，供用户确认：

- **法律主体** — 精确的企业名称、注册地、法定代表人、任何曾用名/别名。国家知识产权局商标注册人记录；国家企业信用信息公示系统查询；上市公司公告（如有）。来源未确认时标注 `[SME VERIFY]`。
- **规模与资源** — 大致员工数、已知营收区间、融资阶段（如为创业公司）、母公司（如为子公司）。公开来源（企查查/天眼查员工数据、新闻报道、上市公司年报）。无法确定时如实标注。
- **知识产权组合** — 对方是否持有相关类别的已注册商标、专利或著作权？拥有自身知识产权组合的对方更可能 (a) 理解你的姿态，(b) 反制主张，(c) 提起确认不侵权之诉。通过国家知识产权局商标查询系统、专利查询系统检索被控实体及关联方。`[模型知识 — 需核验]`
- **诉讼历史** — 通过中国裁判文书网、企查查/天眼查快速检索其作为原告或被告的知识产权诉讼记录。反复诉讼或倾向于提起确认不侵权之诉的对方改变决策考量。标出行业内已知的侵权告知函活动。`[模型知识 — 需核验]`
- **法律顾问** — 对方是否有已知的知识产权外部律师？律师事务所、可辨识的主办合伙人（来自先前案件代理记录）。"未查到法律顾问"本身也是一项信息。
- **确认不侵权之诉风险** — 综合规模、知识产权组合、诉讼历史、法律顾问和管辖法院：该对方是否可能将侵权告知函视为在其选择的法院提起确认不侵权之诉的契机？标出高/中/低并附一句话理由。`[模型知识 — 需核验]`
- **关系风险** — 我方是否为其客户、是否共享投资方、对方是否为潜在收购方或合作伙伴？从实务配置中确认"非其客户"信息；其余标出。

在起草前以内联备忘录形式呈现尽调结果：

```
## 对方尽调 — [实体名称]

- **主体：** [名称、注册地、母公司（如有）]
- **规模：** [员工区间、营收区间、融资阶段] — [来源，适用处标注 `[SME VERIFY]`]
- **知识产权组合：** [相关类别的已注册商标/专利/著作权 — 或"未查到"]
- **诉讼历史：** [作为原告或被告的知识产权案件 — 或"快速检索未查到"]
- **法律顾问：** [已知外部知识产权律师 — 或"未查到"]
- **确认不侵权之诉风险：** [高/中/低 — 理由]
- **关系风险：** [任何客户/投资方/合作伙伴/收购方关联 — 或"未查到"]

**本尽调触发的自动升级**（依据实务配置 `## 实施姿态` → 自动升级）：
- [列出每条被触发的升级规则]

**起草前确认：**
- 鉴于以上尽调，你是否仍要对该对方发出侵权告知函？
- 上述自动升级是否适用？如适用，配置中指定的审批人须在起草前签署，而非之后。
```

**用户未对尽调内容做出实质回应前，不得进入步骤6（起草）。** 一句空泛的"好的"比无确认更糟——追问："在我起草前——尽调中有没有什么改变你的判断？规模、先前诉讼、他们的律师、关系？"

若尽调发现了实务配置中自动升级列表里的任何事项（客户关系、更强势的对方、专利事项、可能引起媒体关注的等），路由至配置中指定的审批人——审批人签署前不得代替起草。

若关键尽调项目无法回答（如主体无法确认、规模未知且对方不在任何公开登记系统上），如实说明并标注："我无法从可用来源确认[主体/规模/法律顾问]。你有这些信息，还是我们应该暂停，等待律师或外部律师确认？"

### 步骤 6：起草

起草结构：

1. **发函方/信头及日期**
2. **收函方信息块**
3. **事由行** — 简明，不泄露保密策略。`事由：未经授权使用[商标]（中国注册号[•]）`
4. **开头** — 识别发函方、主张的权利、注册信息（如有）及本函性质
5. **权利依据** — 商标：注册号、类别、首次使用日期、注册状态；著作权：登记号、作品名称、年份、作品描述；有一定影响的标识：使用日期、使用范围、知名度证据
6. **侵权行为** — 具体描述：谁、什么、哪里、何时、证据
7. **法律依据** — `[CITE: 商标法第57条 / 反不正当竞争法第7条 / 著作权法第53条 / 反不正当竞争法第2条 / 合同第X条]` 视情况适用
8. **诉求** — 编号列出、具体、相称
9. **限期** — 具体日历日期、确认方式
10. **不履行的后果** — 与姿态匹配
11. **保全要求** — 与被控行为相关的文件、通讯、元数据
12. **权利保留** — "不放弃任何权利或救济，无论法律上还是衡平法上"
13. **签署块** — 依据实务配置的审批人

**起草规则：**

- **具体性优于形容词。** 日期、URL、注册号、样本。形容词是事实薄弱的信号。
- **不得过度宽泛主张。** 若商标在一个类别注册而被控使用在不同类别，如实说明——不要假装注册覆盖了两者。过度宽泛的侵权告知函是恶意的证据。
- **引证作为占位符，除非已核验。** `[CITE: 商标法第57条第1项]` 保持为占位符，除非用户提供或研究工具返回。为每个引证标注来源——`[法律数据库]`、`[用户提供]`、`[模型知识 — 需核验]`、`[网络检索 - verify]`。不得移除标签。
- **后果表述与姿态匹配。** 强硬 → 具体救济威胁（禁令、商标法第63条法定赔偿/惩罚性赔偿、著作权法第54条法定赔偿、律师费）。适中 → "我方保留一切权利。" 保守 → "我们希望在考虑进一步措施前先行商讨。"
- **管辖权特定要点** — 若为中国大陆：注意域名争议适用域名争议解决办法（CNDRP）或UDRP，有一定影响的未注册标识适用反不正当竞争法第7条，著作权法第54条法定赔偿无需登记前提。涉及港澳台或境外：标出管辖权，说明草稿可能需要当地律师审核。

## 接收模式 — 对来函进行分流

### 步骤 1：阅读来函

提取：

- **发函方** — 实体、签署人、外部律师（如有）
- **收函方** — 我方的哪个实体/人员
- **送达方式及日期**
- **主张的权利** — 商标（注册号？管辖权？）、著作权（已登记？作品名称？）、两者兼有、其他
- **被控行为** — 对方版本的我方行为
- **法律依据** — 引用的法律、合同条款、理论
- **诉求** — 对方想要什么；限期是否已陈述？
- **威胁** — 对方说会做什么
- **语气** — 强硬/柔性/极端施压；律师签名通常表示严肃性

### 步骤 2：评估主张

不是法律意见——是结构化阅读：

- **权利有效性。** 所主张的注册是否真实且有效？（查询国家知识产权局商标查询系统、著作权登记查询——标出任何看起来无效或未续展的。）对于有一定影响的标识主张，对方实际引用了什么证据？
- **混淆/相似性/侵权的可能性。** 就所述事实，这是否是一个有合理基础的主张还是过度延伸？对于商标：混淆可能性取决于多因素测试（参照《最高人民法院关于审理商标民事纠纷案件适用法律若干问题的解释（2020修正）》的混淆因素，包括商标近似程度、商品类似程度、知名度、主观意图等）——`[SME VERIFY]` 适用管辖法院的标准。对于著作权：接触 + 实质性相似。标出主张最薄弱之处。`[模型知识 — 需核验]`
- **过度宽泛。** 对方是否要求超出行为所保证的范围？（想要转让商标而注册最多只需覆盖重新贴标？想要全部销售额而仅一个渠道触及了该权利？）过度宽泛的诉求削弱对方谈判力，强化反不正当竞争法/恶意主张的抗辩。
- **时效。** 诉讼时效（《民法典》第188条三年）、登记时间（中国著作权法定赔偿无登记前提）——标出来函表面上可见的任何日期问题。`[模型知识 — 需核验]`
- **管辖法院。** 对方会在哪里起诉？管辖法院是否由合同约定（在知识产权纠纷中较少见）？我方是否有确认不侵权之诉的主动机会？

### 步骤 3：评估我方风险

- **我们是否确实构成侵权？** 诚实审视。记录显示什么？
- **能否低成本停止？** 合规成本 vs. 争议成本。
- **对方是投机投诉方还是真实权利人？** 反复原告？已知愿意诉讼者？近期对类似使用发出侵权告知函的记录？有时间可查阅公开案件记录。
- **此争议之外的利害关系？** 品牌价值、客户关系、对类似来函的先例效应。

### 步骤 4：应对方案

呈现4-5个方案及权衡：

**A — 快速合规**
- 适用：主张有合理基础，合规成本低，争议不值得
- 权衡：建立对方日后引用的让步；可能助长未来主张
- 下一步：书面确认合规（窄幅），不让步于更广泛的法律理论

**B — 谈判**
- 适用：存在中间地带的商业安排（许可、共存、品牌调整时间表）可解决争议
- 权衡：投入时间；需注意和解通讯的保密姿态（《最高人民法院关于民事诉讼证据的若干规定》关于调解/和解中让步的证据效力；保护取决于实质和情境，而非仅靠标签）`[模型知识 — 需核验]`
- 下一步：暂缓函 + 开启谈判通道

**C — 强硬回复（拒绝）**
- 适用：对方主张薄弱、过度宽泛或事实有误；我们希望不经诉讼终结此事
- 权衡：锁定立场；若主张实际有合理基础，我方回复将成为证据
- 下一步：起草回复函——考虑以回复语境运行 `--send` 模式

**D — 不予理会（但保全证据）**
- 适用：主张缺乏依据，对方明显无起诉能力，限期无法律约束力
- 权衡：沉默在某些语境下可被视为不否认；法律保全无论如何必须执行；存在后续起诉风险
- 下一步：通过事项级别流程发出法律保全通知；记录该主张；继续运营

**E — 主动提起确认不侵权之诉**
- 适用：我方面临真实的商业不确定性，对方主张薄弱，我方受益于选择管辖法院
- 权衡：我方转攻；需预算和领导层签署；此时正式进入诉讼
- 下一步：升级至外部律师（依据实务配置），不自行起草

**F — 申请宣告对方权利无效**
- 适用：对方权利本身存在瑕疵，我们希望从根本上消除该权利基础
- 权衡：周期长、成本高、公开进行；独立于争议本身
- 下一步：升级至外部律师

推荐一个方案并附两句话理由。具体说明推荐原因。

### 步骤 5：限期分流

- 对方声明的限期——记录，但不对我方产生法律约束力（除非特定法律或合同赋予其效力）。
- 我方内部决策限期——通常为对方声明限期减去足够起草、审核和批准回复的时间。在日历中标出。
- 法律限期——任何基础请求权的诉讼时效（《民法典》第188条）、合同补救期、程序性时限。

完全忽略对方声明限期是一种选择，而非默认。注意：诉讼通常跟随沉默发生，而非限期届满日。

### 步骤 6：撰写分流备忘录

输出：`<事项文件夹>/cease-desist/inbound/<slug>/triage.md`（或实务层级，若事项工作区未启用）。

**完整模板和保密继承规则见** [references/triage-memo-template.md](references/triage-memo-template.md)。读取该文件获取：分流备忘录的完整 Markdown 模板（含主张内容、权利有效性、法律依据、合理性评估、我方风险、应对方案A-F、限期、即时行动各节）以及按角色（律师/专利代理师/非律师）选择保密继承块的规则。

**保密继承关键要点：** 中国法下，律师依据《律师法》第38条享有保密义务；专利代理师仅受《专利代理条例》保密义务约束，不享有与律师同等的诉讼保密特权；非律师人员制作的文件不享有保密特权，须经执业律师审核后方可标注。

内联展示结束时逐字附上下列警示：

> 本文件为分流备忘录，非法律意见。上述强度评估仅基于来函的首次阅读——未考虑你尚未告知我的事实、我无法核实的注册、或管辖权问题。在你回复、决定不理会或选择某条路径之前，须由律师进行评估。

若用户为非律师，附上发送模式中的"寻找律师"指引段落。

### 步骤 7：移交

依据推荐方案和用户确认：

- 强硬回复 → 移交至 `--send` 模式，预填回复语境作为回复函（这将重新触发发送模式的审查门）。
- 谈判 → 在事项中启动暂缓函/谈判通道。
- 主动起诉或申请宣告无效 → 升级至外部律师（依据实务配置的知识产权诉讼行）；不自行起草。
- 事项创建 → 若无事项且事项重大，提议创建事项。
- 合规/不理会 → 在事项历史中记录决策；发出或确认法律保全通知；关闭分流记录。

## 决策姿态

依据实务配置中 `## 主观法律判断的决策姿态`：当不确定是否存在侵权、商标是否构成混淆性相似、作品是否构成实质性相似、主张是否有合理基础、或发送是否安全时——不得静默判定没有问题。标出待律师审核，呈现正反两方面的因素，注明不确定性。在假设基础上发送侵权告知函是一扇单向门；呈现疑虑是一扇双向门。

## 本技能不做的事

- **发送函件。** 仅起草。用户在审核后发送。
- **研究引证。** 占位符保持为占位符，除非用户提供权威来源或连接的研究工具返回结果。编造引证是执业责任风险。
- **绕过审查门。** 发送模式的审查门每次均运行。即使有 `--skip-gate` 标志（本技能不提供），技能也会在草稿文件中记录跳过。
- **在接收侧做出确定性的实质判断。** 评级是供路由的结构化阅读；正式的实质意见由律师出具。
- **验证对方引用的法律。** 为用户标出；不自主判定主张有效或无效。
- **做出事项创建决定。** 呈现推荐方案；用户决定。
