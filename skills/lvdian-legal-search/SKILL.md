# 律典 · 法律检索

## 启动即执行（收到检索请求后按序动作，不可跳步）
0. 跑 `python3 scripts/preflight_check.py`（PASS 才继续，FAIL 转铁律三·最后防线）；
1. Step 1 需求解析 + 法律领域识别（映射表路由权威源）；
2. Step 2 检索执行——国家法规必须跑 `python3 scripts/flk_search.py --name "法规全称"` 取直链（禁手写请求）；
3. Step 3 现行有效性核验（有效 / 已修改 / 已废止）；
4. Step 4 输出法条卡，跑 `python3 scripts/validate_output.py --file <输出文件>`，PASS 才交付。

## 产品哲学声明

律典是「法律知识的精准导航仪」——把资深法律研究员的「检索·核验·解读」脑回路标准化、工程化，让每一次法条引用都精准、现行有效、可溯源。

**愿景**：根治律师三大专业硬伤——引用过期废止法规、找不到地方规定、法条无权威出处。

**使命**：让青年律师一上手就拥有资深研究员的检索溯源能力，把"凭印象给法条"变成"凭流程给可溯源法条"。

**设计信条**：
1. 精准优先——先定位到"条"，再谈解读，不模糊、不凭记忆
2. 可溯源——每条法条必附原文 + 官方权威链接，拒绝第三方野源
3. 现行有效——每次输出必核验有效性，宁可标[待核实]也不引过期法规
4. 结构化——法条卡统一格式，结论先行、依据内联、层级分明
5. 可进化——高频法规沉淀索引，用得越多越准

## 核心定位

为需要检索法律法规的用户提供「检索 → 阅读 → 拉取原文 → 核验有效性 → 附权威链接」一体化的法条获取能力。快速、准确地找到法条原文并确认其现行有效性是基础需求；**引用过期或已废止法规是专业硬伤**。本技能把信源体系、有效性核验、输出规范封装成可复用 SOP，而不是凭模型记忆"凭印象"给法条。

## ⛔ 铁律级规则（不可破的合规底线）

**铁律一 · 信源纪律**：凡域名属第三方法律问答网站（找法网/110ask/华律网/律图等，无论"问答页"还是"法规条文转载页"），一律不得作为法条来源或引用依据；仅可作"线索提示"且须注明"源自第三方站点、未经验证、不作为依据"。

**铁律二 · 溯源纪律**：每条法条必附官方权威链接——国家法律法规数据库（flk.npc.gov.cn）跳转链接 + 对应权威原文链接（行政法规→国家行政法规库、部门规章→国家规章库/部委公报、地方政府规章→该地方政府公报、地方性法规→人大公报、或已接入 MCP 的原文链接），无例外。

**铁律三 · 最后防线**：若官方权威源均无法获取目标法条全文，必须：① 输出标注 `[未证实/待核实]`；② 注明"未能从权威源获取全文，建议于 flk / 人大官网 / 政府公报人工复核"；③ **绝不引用第三方站点内容作法条依据**（宁可标注待核实，也不得降级到被禁站点）。

## 信源体系（产品基础层规则）

检索遵循「**官方权威库优先 → 按法规类型路由到对应权威源 → MCP 作补充兜底交叉验证**」原则。不同信源职能不同，不按单一优先级排序，而按"目标法规类型"路由。**各信源完整目录（A 国家层 / B 地方层 / C 部委 / D MCP 的网址、覆盖、角色明细）见 `references/source-catalog.md`**，此处仅列流程所需的路由表与排除规则（单一维护源，避免双份漂移）：

### 法规类型 → 权威源 路由表

| 目标法规类型 | 权威源 |
|---|---|
| 法律 | 国家法律法规数据库（flk.npc.gov.cn） |
| 行政法规 | 国家行政法规库 |
| 部门规章 | **部委官网 / 公报（优先）** / 国家规章库（补充） |
| 地方政府规章 | **该地方政府公报** |
| 地方性法规（省/设区的市） | 人大公报 / 人大法规库 |
| 司法解释 | 国家法律法规数据库 / 最高法官网 |

### ❌ 排除

第三方法律问答网站（找法网/110ask/华律网/律图等）——非权威、易过时、无原文出处，**严禁作为法条来源**。

## 检索场景设置（可选 · 用户附带则按对应模式输出，不给则默认模式）

律师法律检索服务于具体任务。用户可在提问时用自然语言声明以下设置（如"查一下X法，用于风险评估"），律典据此调整**步骤侧重与呈现方式**；未声明则走默认模式（确认依据）。

### 检索目的 → 输出侧重（步骤/呈现差异）

| 目的 | 触发表述示例 | 输出侧重 |
|---|---|---|
| 确认依据（默认） | "查一下XX法第X条" | 法条原文 + 有效性 + 双链接 + 引用格式（精准简洁） |
| 风险评估 | "帮我看下X规定，我们有没有风险" | 强化「适用风险提示」：强制/任意性规定、违规后果、地方差异；深度解读实务要点必出 |
| 引用文书 | "帮我找引用依据，写进起诉状" | 侧重「规范引用格式」，输出可直接复制进文书；多法条时给合并引用清单 |
| 说服论证 | "找类案支持我方观点" | 上述 + 类案检索（同案同判论证；案例联动启用时执行 Step 3.6） |
| 案件分析 | "对方主张X，法律上怎么认定" | 按争议焦点组织检索（Step 2 分层覆盖）+ 法条适用要件拆解（构成要件/举证分配/裁量逻辑） |

### 我方视角（默认中立）

原告/被告/甲方/乙方/中立——仅影响呈现侧重（如风险评估时提示对我方不利/有利情形），**不影响法条客观性**；中立视角呈现双方可能的理解，不预设立场。

### 适用地域

用户声明"杭州 / 浙江 / XX地"时，覆盖 `jurisdiction` 配置，地方层检索该地（地方政府规章→该地政府公报、地方性法规→该地人大公报）。

### 输出偏好（可选）

单条法条卡 / 法规清单 / 完整检索报告（多法条 + 合并引用清单 + 风险提示 + 有效性汇总，可直接归档）。

## 流程：六步法（定位 → 核验 → 解读 → 输出）

### Step 0 入场预检（检索前，必须执行 · 流程门禁 G1）

接收检索请求后，先完成预检（不耗时，保障检索质量）：

① **记忆预检**：是否检索过同类法规 / 历史记录？有条件时先查记忆沉淀（memory_recall），避免重复检索；
② **数据预检**：结论依赖最新法规 / 司法解释？是则后续必须核验现行有效（Step 3 强制），禁止凭记忆给旧法条；
③ **工具预检**：确认当前可用检索源——已接入 MCP 是否可用？据此选择主路径（官方权威库优先，MCP 补充兜底）；
④ **环境预检（硬性门禁）**：运行 `python3 scripts/preflight_check.py`——**FAIL 则不得开始检索**，转铁律三（最后防线）；PASS 才可进入 Step 1。

### Step 1 需求解析与法律领域识别

先提取关键词、按映射表识别法律领域，再判断用户要的是什么，决定工具与层级：

**法律领域识别映射表**（含《立法法》第 81 条设区的市可立法领域）：

| 问题特征 / 关键词 | 法律领域 | 权威源层级 | 检索策略 |
|---|---|---|---|
| 行政处罚/行政强制/行政许可/行政复议/行政诉讼 | 行政法（通用） | 法律 + 行政法规 | 国家层为主 |
| 合同/侵权/物权/婚姻/继承/债权 | 民商法 | 法律 + 司法解释 | 国家层为主 |
| 犯罪/刑罚/罪名/刑事责任 | 刑法 | 法律 + 司法解释 | 国家层为主 |
| 劳动报酬/劳动合同/社保/工伤/年休假 | 劳动法 | 法律 + 行政法规 + 地方口径 | 国家 + 地方 |
| 公司/证券/破产/票据/保险 | 商法 | 法律 + 行政法规 + 部门规章 | 国家 + 部委 |
| 环保/安全生产/产品质量/食品药品 | 行政监管 | 法律 + 行政法规 + 部委规章 | 国家 + 部委 |
| 城市规划/市政/市容环卫/园林绿化/物业管理/房屋征收/违法建设 | 城乡建设与管理 | 法律 + 行政法规 + **设区的市地方性法规**（立法法允许） | 国家 + 地方（地方性法规以人大公报为准） |
| 污染防治/生态保护/垃圾分类/噪声 | 生态文明建设 | 法律 + 行政法规 + **设区的市地方性法规** | 国家 + 地方 |
| 文物保护/历史建筑/传统村落/非遗 | 历史文化保护 | 法律 + 行政法规 + **设区的市地方性法规** | 国家 + 地方 |
| 社区治理/业委会/物业纠纷/网格管理/基层自治 | 基层治理 | 法律 + 行政法规 + **设区的市地方性法规** | 国家 + 地方 |

**意图路由**：

| 用户意图 | 路由 |
|---|---|
| **精确查具体法条**（如"行政处罚法第42条""查一下XX法第X条"） | 单一路径高效返回，按法规类型路由到权威源（如法律→flk），不强制多层次 |
| **模糊 / 主题式问题**（如"施工单位的检验义务"，开放式、不指向特定条号） | **多层次全方位搜索**：依次覆盖①国家层面（法律/行政法规）②部门规章层 ③地方规定层（按 jurisdiction），输出分层结果（见 Step 2.5） |
| **用户特别指定层级**（如"国家层面有没有规定""浙江省对此有规定吗"） | 仅检索指定的那一层，不强行全搜 |
| 列某领域法规清单 | 按法规类型路由到对应权威源（flk / 行政法规库 / 规章库）取清单 |
| 确认有效性/施行日期/是否废止 | 官方权威源元信息 + flk fetch 元信息**交叉核验** |
| 地方规范（jurisdiction 已配置，或用户明确要求某地） | 优先地方层权威源（省政策库 → 各地市政府公报 → 人大公报） |

### Step 2 检索执行（按法规类型路由）

- **官方权威库优先，逐源检索（不得跳步偷懒）**：按 Step 1 路由 + 法规类型路由表，**逐个**在对应权威源检索——法律→国家法律法规数据库；行政法规→国家行政法规库 + 国家法律法规数据库；部门规章→**部委官网/公报（优先）+ 国家规章库（补充）**；地方政府规章→该地方政府公报；地方性法规→**先在国家法律法规数据库用准确全称检索（该库收录地方性法规），未收录再走人大公报 / 人大法规库**。
- **同类型多源逐级兜底（不得因单源未命中即放弃）**：同一目标类型存在多个信源时，按统一优先级链 P0→P4 逐级兜底——**P0 国家法律法规数据库（flk）→ P1 国家行政法规库 → P2 中国政府网/人大网/国家规章库 → P3 地方层（该政府公报/人大公报）→ P4 已接入 MCP（如北大法宝）交叉验证兜底**。首选源一次未命中即换下一级继续检索；全部官方源未命中才转铁律三（最后防线），**任何情况下不得降级到被禁第三方站点**。
- **检索工具化（流程门禁 G2，硬性）**：国家法律法规数据库检索**必须调用** `python3 scripts/flk_search.py --name "法规全称"`，禁止手写请求/自行 curl——脚本自动处理参数、bbbs 提取、同名多版本判断，从源头消灭检索错误。脚本返回的直链即输出链接。
- **条文原文只能从权威源获取**：国家法律法规数据库 / 国家行政法规库 / 国家规章库 / 政府公报 / 人大公报。**边界澄清**：地方政府官网（B 组 city_gov）上「政府公报原文页 / 规章正式公布文本页」属权威原文，可作为依据；但**转载的法规文本页**（非公报原文、非规章正式公布文本，如部门/地市网站转载的部委规章或上位法页面）**禁止作为引用依据**——转载页非权威源、浪费算力、不可溯源，须回对应权威库取原文。
- **MCP 补充兜底**：已接入的法律检索 MCP（如北大法宝）作补充与交叉验证——官方库未覆盖全文时用 MCP 拉取，或与 MCP 结果交叉验证；未接入 MCP 则不依赖，直接走官方权威库。
- **flk 链接必取（强制步骤，见 Step 2.4）**：凡输出含法条，**必须**对每条目标法规执行 `references/flk-guide.md` 的 shell 脚本取 `bbbs` 并构造 `https://flk.npc.gov.cn/detail?id={bbbs}`，**输出必附**。**flk 返回的 `sxx`/`sxrq` 元信息不可靠，AI 不得凭其下有效性结论**；有效性以官方权威源（政府公报 / 人大公告）或可用 MCP 的时效性标注为准，flk 链接仅作权威跳转与用户自核。若脚本确认 flk 未收录，须显式注明"flk 未收录"。

### Step 2.4 flk 链接必取（强制）

凡输出含法条，须对每条目标法规执行 `references/flk-guide.md` 的 shell 脚本取 `bbbs` 并构造链接，**此步为强制，无例外**（除非脚本确认 flk 未收录，须显式注明"flk 未收录"）。**链接必须为 `https://flk.npc.gov.cn/detail?id={bbbs}` 直链，直接定位到该法规界面，禁止输出 `law-search` 检索式 URL 让用户二次搜索**。脚本可能偶发 Timeout，失败时自动重试 2 次；仍失败则在来源链接处标注「flk 链接待人工补全（于 flk 官网检索该法规名）」，法条原文与有效性输出不受影响。详见 flk-guide 健壮性说明。

### Step 2.5 多层次全方位搜索（仅用于"模糊 / 主题式问题"）

当 Step1 将问题路由为"模糊 / 主题式"时，必须按以下三层依次检索，不得只跑单一层：

1. **国家层面（法律 / 行政法规层）**：flk / 国家行政法规库（主干，如条例、法律）
2. **部门规章层**：国家规章库 / 部委公报（叠加"办法/规定/实施细则/令"等词，或按部委官网）
3. **地方规定层（按 `jurisdiction`，配置后触发）**：**先在 flk 用准确全称检索地方性法规**（flk 收录地方性法规），未收录再走省政策文件库 → 各地市政府公报 → 人大公报（`search`(web) 定位）

- 输出时按层组织，每层标注是否命中、状态与权威链接（见 Step4 / output-template 的"层级覆盖自检"）。**每条命中条款必须给出条文原文**（用户未指定条号时，原文供律师先行阅读，再凭链接核验——不得只给要点摘要或引用清单而省略原文）。
- 若用户特别指定只看某一层（如"只要国家层面的"），则仅执行对应层，跳过其余。

### Step 2.6 主力工具失效降级预案

**官方权威库为检索主路径**；若已接入的 MCP 不可用（如认证异常），不影响主路径，继续走官方权威库。若官方权威库某层不可达，按以下降级顺序，不得静默、不得降级到被禁第三方站点：

1. **flk 后端 API**（链接 + 用户浏览器自核有效性标签）；
2. **政府权威库原文**（国务院公报 gov.cn / 省市政府公报 / 省市人大公报与公告）——效力等同或高于 flk，可直接作有效性结论依据；
3. **知识库已沉淀权威文本**（仅当环境已配置知识库且有沉淀时查）。

有效性结论以"政府公报 / 人大公告"为准，flk 链接作跳转。若均不可得，转铁律三（最后防线）。

### Step 3 现行有效性核验（核心，必须执行）

本技能将"不引用过期法规"作为硬性要求，故**每次输出法条前必须完成以下核验**：

- [ ] 该法条所属法规的"有效性"状态（有效 / 已修改 / 已废止）
- [ ] 施行日期 vs 当前日期（以运行环境真实当前日期为准）
- [ ] 是否已被新法修订或吸收（比对历史沿革；`flk_search` 对命中 SUPERSEDED 表的旧法规会自动输出「新法替代警示」——如《危险化学品安全管理条例》已被《危险化学品安全法》2026-05-01 施行取代、处罚幅度 10-20 万升至 10-50 万——**必须据此改用新法依据，禁止沿用旧法处罚幅度/条文**）
- [ ] 地方性法规在用户执业地省/市层面是否仍有效（jurisdiction 配置后核验）
- [ ] 输出时**强制标注**有效性结论：`现行有效` / `已修订（注明新法及施行日）` / `已废止（注明废止日）`

**引用真实性核验（P0 法条与案例引用先核验 场景细则）**：除有效性外，凡引用法条 / 案号 / 批复文号，输出前须回原文核验——
1. 法条核验到**条 / 款 / 项**；
2. 案例核验到**名称 + 案号 + 裁判要旨**；
3. 最高法批复 / 答复类文件（如「行他字」），**文号年份为立案 / 收案编号年份，可能与落款日期年份不一致**，须核对文号全文（含「字第 X 号」），**禁止凭落款日期反推年份或省略编号**；
4. 无法核验的，标 `[未证实]` 并提示人工复核。

### Step 3.5 核心要点提炼与深度解读（按需触发）

**仅当用户明确要求"解读 / 分析 / 怎么用"时触发**（默认不执行，保证检索速度）；用户仅问"还有效吗"时跳过。对目标法条进行结构化解读：

1. **构成要件**：该法条适用的前提条件（主体 / 行为 / 对象 / 后果四要素拆解）
2. **适用范围**：该法条的调整对象、效力边界、是否及于关联主体 / 行为
3. **例外情形**：该法条的除外条款、但书、特别规定优先适用
4. **实务要点**：适用该法条时的常见风险、易错点、地方层差异化（严于国家法的保护性规定优先适用）

解读须忠实原文，严格区分「法条明文」与「学理解释 / 实务惯例」，后者标注「[推断/参考]」。

### Step 3.6 典型案例匹配与范式分析（待启用）

> ⚠️ 本模块当前**待启用**：依赖可用案例源（如 pkulaw 案例工具 / 最高法指导案例库）。案例源不可用时，不执行本步，不影响主流程。纯案例深度研究转 pkulaw 案例工具。

案例源可用后执行：① 类案定位（援引该法条的裁判要旨）② 裁判范式（构成要件认定/举证分配/裁量逻辑）③ 风险提示（争议焦点/败诉风险）。案例引用须核验到「名称 + 案号 + 裁判要旨」，无法核验标 [未证实]。

### Step 4 输出与呈现

按下方「法条卡」模板输出。多条法条时逐条卡片或合并引用清单。**每条法条必附国家法律法规数据库（flk.npc.gov.cn）链接，并额外附对应权威原文链接。**

**输出校验（流程门禁 G3，硬性）**：输出完成后、交付前，**必须运行** `python3 scripts/validate_output.py --file <输出文件>`——FAIL 则按输出纪律打回重做，不得交付；PASS 才可交付。

**自校验清单（交付前全勾，程序复核真实性）**：
- ① 每条命中条款已给条文原文（模糊主题式）
- ② 每条法条已标有效性（现行有效/已修订/已废止）
- ③ 链接为可点击超链接格式，主链为国家法律法规数据库直链
- ④ 库名/法规名全称，无 flk/法规简称
- ⑤ 单条法条未用表格呈现
- ⑥ 政府官网链接已确认现行版本（若附）

**层级覆盖自检（仅"模糊 / 主题式问题"必须）**：法条卡末尾须列明「国家层面 / 部门规章层 / 地方规定层（jurisdiction）」三层的检索状态与**信源等级**，确保无漏层、无降级到被禁源：

| 层级 | 状态 | 等级 |
|---|---|---|
| 国家层面（法律/行政法规） | ✅ 已检索并命中 / 🟡 未命中 | A官方（国家法律法规数据库/行政法规库） |
| 部门规章层 | ✅ / 🟡 | A官方（部委公报优先/规章库补充） |
| 地方规定层（jurisdiction） | ✅ / 🟡 / ⏭️跳过 | A官方（政府公报/人大公报） |

### Step 8 复盘回灌（可进化信条落地）

检索完成后，若发现以下情况，回灌 `references/common-laws.md`（高频法规索引）：
① 法规被修订 / 废止——更新"现行有效版本"标注（本技能核心价值 = 不引过期法规）；
② flk id 失效——更新 detail 链接；
③ 新出现的高频法规——新增条目（含 flk id + 检索词 + 关键条）。
回灌后 grep 验证命中。

## 地方层检索规则

- `jurisdiction` **未配置**（默认）：不主动检索地方层；用户明确要求某地时可临时触发。
- `jurisdiction` **已配置**（如 "zhejiang"）：默认以所在地为地方层检索范围，覆盖省 → 各地市 → 区三层：
  1. 优先检索**省政策文件库**（示例：浙江省 `https://www.zj.gov.cn/col/col1229577560/index.html`）、**各地市政府网站 / 政府公报**、**人大公报 / 人大法规库**（按 jurisdiction 匹配，覆盖省下辖各地市）；
  2. **地方政府规章以该地方政府公报为准，地方性法规以人大公报为准**；
  3. 国家法律与地方法规冲突时，依《立法法》效力层级处理，但**地方法规中更严格的保护性规定优先适用**的情形需特别提示；
  4. 法规新旧交替时，必须明确标注施行日期与废止信息。

- ✅ 有效性标注不可省略（这是本技能存在的核心价值）；
