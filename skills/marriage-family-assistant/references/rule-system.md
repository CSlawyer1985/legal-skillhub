# 规则体系

规则用于提醒模型识别关键问题，不是外部资料系统，也不提供联网查询能力。引用法律依据时必须可追溯；没有依据时不要编造条文、案例、地方口径或裁判倾向。

## 规则类别

| 规则类别 | 编号前缀 | 主要内容 |
| --- | --- | --- |
| 离婚路径 | DRT001... | 协议离婚条件、诉讼离婚、管辖、冷静期、程序节点 |
| 子女抚养 | CHD001... | 直接抚养、探望、抚养费、教育医疗、子女稳定性 |
| 财产分割 | PRO001... | 房产、存款、车辆、股权、保险、婚前财产、父母出资 |
| 夫妻债务 | DEB001... | 共同债务、个人债务、经营债务、虚假债务、逃债风险 |
| 补偿赔偿 | CMP001... | 家务劳动补偿、经济帮助、离婚损害赔偿 |
| 证据材料 | EVI001... | 证据类型、证明目的、证据缺口、补充材料 |
| 安全风险 | SAF001... | 家暴、人身危险、子女被抢夺/藏匿、跟踪骚扰、自伤/伤人风险 |
| 履行提示 | ENF001... | 房产过户、款项支付、抚养费、探望、材料配合等安排是否明确 |

## 单条规则字段

设计或更新规则时，至少包含：

- 规则编号。
- 适用模式：律师模式、当事人模式或两者共用。
- 适用阶段。
- 触发条件。
- 排除条件。
- 需要的事实。
- 需要的证据或材料。
- 风险等级：低、中、高、紧急。
- 法律依据和官方来源。
- 当事人版解释。
- 律师版解释。
- 建议下一步。
- 是否建议转律师或线下专业帮助。

## 输出要求

- 律师模式可以展示规则编号、构成要件、争议观点、证据缺口和处理方案。
- 当事人模式一般不展示规则编号，优先翻译成“为什么这件事重要”“你要准备什么”“下一步怎么做”。
- 不输出案件结果概率、统计化案件结果判断、法官倾向或未经检索支持的裁判尺度。
- 法律规则不完整时，先问关键事实或标注“无法判断”，不得补造事实。

## 规则命中示例

用户：“老公不同意离婚，房子写他名字，还有一个五岁的孩子。”

应识别：

- DRT：一方不同意时，可能需要考虑诉讼离婚。
- CHD：存在未成年子女抚养、探望、抚养费问题。
- PRO：房屋登记在一方名下不当然等于个人财产，需要看购买时间、出资来源、贷款和还款。
- EVI：需要婚姻登记、子女照护、房产取得和还款证据。
- ENF：如准备形成协商方案或协议草案，需要进一步明确房产归属、补偿金额、付款时间和过户配合方式。

当事人模式输出路径判断和材料清单；律师模式输出争点、证据缺口和工作底稿。
