# 第 2 级——结构化标识符佐证

第 2 级是首个可以达到真阳性判定的层级。它使用警报和列表条目中已存在的标识符和结构化字段——无需网络访问。

仅当**所有**前置条件都满足时，规则才会触发。保守姿态：沉默优于薄弱推断。

## TP-1——唯一政府标识符匹配

**前置条件：**
- 双方存在相同标识符类型（护照、国民身份证、税号、实体的注册号、船舶的 IMO 编号）
- 锚点组件姓名匹配已满足——即解析姓名中的锚点有重叠（这防止 TP-1 在两个无关人之间的文书性标识符冲突上触发）
- 双方的标识符值已规范化（去除空白、转大写、移除破折号和斜杠等分隔符）

**触发条件：**
- 规范化后的标识符值完全匹配

**结果：** TP，确认

**审计：** 记录标识符类型、原始值和规范化值、锚点匹配确认，以及匹配的是列表方的哪个标识符（主要或备用）。

**严格性说明：** 本规则不对有记录的格式变体触发（例如，旧版 7 位伊朗护照重新签发为 9 位）。仅限规范化后严格相等。格式变体如要解决，则落入第 3 级。

## TP-2——完整身份三角验证

**前置条件：**
- 双方均有完整出生日期（日、月、年）
- 双方均有城市级粒度的出生地（城市 + 国家，而非仅国家）
- 按第 0 级解析的完整锚点姓名匹配——被筛查方的每个锚点组件在列表方有匹配组件（反之亦然；在被筛查方只有一个锚点而列表方有更多锚点的情况下，如果被筛查锚点出现在列表锚点中，仍是有效匹配）

**触发条件：**
- 出生日期与任何列表出生日期完全匹配
- 出生城市匹配（城市名称完全匹配，或按 `place-name-equivalences.md` 记录的对等名称——例如，一方为"列宁格勒"而另一方为"圣彼得堡"计为城市匹配，因为该对等关系有记录；苏联与俄罗斯等政治实体差异是背景信息，不是不同地点）
- 锚点姓名匹配

**结果：** TP，确认

**审计：** 记录三个组成部分中的每一个：出生日期匹配（哪个列表出生日期匹配、精确比较）、出生地匹配（城市和国家、如相关适用对等关系）、锚点姓名匹配（双方的解析组件）。

## 升级-2——部分三角验证，锚点姓名完好

**前置条件：**
- 至少一个列表出生日期完全匹配
- 完整锚点姓名匹配
- 双方均有出生地，但至少一方仅有**国家级别**（一方或双方缺城市）

**触发条件：**
- 锚点姓名匹配且出生日期匹配且出生地国家匹配，但无法获得城市级出生地确认

**结果：** 升级（这不是 TP 也不是 FP——这是一个强信号，表明案件值得人工关注）

**审计：** 记录匹配了什么，并明确注明仅国家级的出生地是升级而非 TP 的关隘原因。

**本规则存在的原因：** 在 8000 万以上的人群中，出生国不足以独特到支持确定性的 TP。但锚点姓名 + 完整出生日期 + 国家出生地过于强而不能忽略。升级是正确的处理。

## FP-5——唯一字段上的标识符不匹配

**前置条件：**
- 双方存在相同标识符类型（护照、国民身份证、税号）
- 列表方该类别的备用标识符少于 3 个（3 个以上备用标识符表示规避模式目标，任何单个不匹配都不能开脱）
- 双方标识符已规范化

**触发条件：**
- 被筛查方的规范化标识符值与列表方该类别的**任何**规范化标识符值均**不**匹配

**结果：** FP，清除

**审计：** 标识符类型、被筛查值（规范化）、所有已检查的列表值（规范化）、确认无匹配、备用标识符计数。

**3 个以上备用阈值的原因：** 主要的 SDN 规避目标常携带来自不同身份的 4–8 个护照条目。被筛查护照与 4 个列表护照均不匹配是薄弱的 FP 证据——目标可能在使用第 5 个。但对于带有一两个标识符的普通列表条目，干净的不匹配是强有力的 FP 证据。

## FP-6——出生日期匹配但锚点失败

**前置条件：**
- 双方均有完整出生日期
- 出生日期与某个列表出生日期完全匹配
- 两个姓名在第 0 级均有 `parse_confidence: high`（解析置信度：高）
- 任一方不匹配的锚点组件明确不同——不是音译变体（Mohammed 与 Muhammad 不算不同），也不是列表方有记录的别名

**触发条件：**
- 姓名重叠仅在一个组件上（名或锚点组件，而非两者）
- 且另一锚点组件是明确不同的姓名（Garcia 与 Hernandez、Smith 与 Jones）

**结果：** FP，清除

**审计：** 解析轨迹（哪个组件匹配、哪个不匹配）、确认不同的组件不是音译变体或别名、匹配的出生日期，以及被比较的明确姓名。

**本规则存在的原因：** 同出生日期的巧合很常见——在任何数千人的群体中，多人按年份共享生日。出生日期加半个姓名不足以构成 TP，而当另一半是明确不同的姓名时，这是强有力的 FP 证据。该规则界定狭窄（双方均为高置信度解析、无音译歧义、无别名覆盖），因此不会扫入真正的匹配。

**FP-6 不做什么：**
- 当不同的组件可能是同一源姓名的音译时不触发（由 `transliteration-variants.md` 涵盖）。
- 当不同的组件是列表方有记录的别名时不触发。
- 当任一名称解析置信度低时不触发。

## 第 2 级的软信号

以下内容可在第 2 级观察，但从不驱动判定：

- **性别推断不匹配**——与第 1 级相同。
- **地理足迹不匹配**——与第 1 级相同。
- **部分出生日期不匹配**——当一方或双方出生日期不完整（仅年份、年份范围、"约"）且可见部分不同时。FP-3 不对部分日期触发；此处的失配成为软信号。
- **国籍匹配或不匹配**——两种方向都可能。双重国籍和公司多管辖足迹使这一信号不可靠。
- **职业/角色不匹配**——当双方在警报时点都有不兼容的有记录职业或角色时。

**仅在升级时呈现软信号。** 当第 2 级规则干净触发（TP-1、TP-2、FP-5、FP-6）时，软信号不包括在叙述或 JSON `soft_signals_logged` 字段中。处置已经完成；软信号是噪音。

升级-2 结果本身即升级——第 2 级评估期间收集的软信号包含在输出记录中，因为案件正在移交。

## 退出第 2 级

- **TP 规则触发（TP-1 或 TP-2）** → 输出 TP 判定，停止，生成审计记录
- **FP 规则触发（FP-5 或 FP-6）** → 输出 FP 判定，停止，生成审计记录
- **升级-2 触发** → 输出升级记录，停止（不进入第 3 级——升级-2 明确表示需要人工关注）
- **无规则触发且第 3 级门禁满足** → 进入第 3 级
- **无规则触发且第 3 级门禁不满足** → 输出升级记录，停止

第 3 级门禁标准见 `tier-3-research.md`。是否进入第 3 级的决定发生在第 2 级与第 3 级之间的边界，而非第 2 级内部。

转入第 3 级时（如进入）结转：完整解析记录、警报输入、每个第 1 级和第 2 级规则的评估结果，以及所有捕获的软信号。
