# 劳动关系解除成本比较专项规则

本文件是本 Skill 的业务方法规则，不替代运行时法源核验。具体条文、司法解释、地方工资数据、地方程序口径和事实结论必须在项目内独立核验，并在内部底稿中保存来源标签、定位、日期和核验人。

## 一、先定性，再计算

在任何金额计算前，依次完成：

1. 确认劳动关系、用人单位、实际用工主体、劳动合同履行地和争议处理地；存在派遣、关联单位、承继用工或事实劳动关系线索时并行保留备选路径。
2. 区分解除与终止，识别提出方、解除理由、合同状态、拟解除日期和已发生的程序动作。
3. 将路径映射到请求与要件：协商一致、无过失解除、过失解除、经济性裁员、期满终止、违法解除或继续履行争议，不得因用户使用“裁员”“辞退”“离职”等俗称而直接套公式。
4. 检查保护性事实，包括医疗期、工伤停工留薪期、三期女职工、距退休年限、工会与集体裁员等；存在触发线索时，先停在条件化分析。
5. 只有在法律路径、工资基数、工龄、地方数据和程序证据达到核验门槛后，才输出确定性金额；否则输出公式、区间、缺口和补证路径。

## 二、方案分类与比较口径

下表是运行时的情景骨架，不是对任何个案的预先结论。每一行都要写明“适用前提、法源、已确认事实、待证事实、金额、现金时点、证据负担、主要风险和人工复核点”。

| 情景 | 计算骨架 | 必查事项 | 不能自动推出的结论 |
|---|---|---|---|
| 用人单位提出协商解除 | 协商金额；若以法定经济补偿为参照，单列 N | 提出方、协议自愿性、金额构成、支付日、结清范围、是否存在欺诈胁迫或显失公平 | 协议写成“协商”不等于当然有效，也不当然排除遗漏的法定项目 |
| 无过失解除且提前通知 | N | 解除理由、理由事实、培训/调岗或医疗期材料、提前 30 日书面通知、工会程序 | N 不是程序瑕疵或违法解除的免责 |
| 无过失解除并支付代通知金 | N + 上月工资口径的一个月金额 | 是否确属可适用的无过失解除路径、上月工资及通知事实 | “N+1”不是所有裁员或协商的法定标配；“+1”与 N 的工资口径可能不同，必须核验 |
| 经济性裁员 | N | 裁员人数比例、经营/生产依据、民主程序、向工会或职工说明、向主管部门报告、优先留用等 | 达到人数门槛不等于程序和实体条件全部满足 |
| 过失性解除 | 通常不以 N 作为法定补偿；另列已发生工资和附随项目 | 规章制度制定与公示、违纪事实、严重程度、同案一致性、解除通知和证据链 | “理论上 0”不等于“实际成本 0”；争议、补发工资和程序成本必须单列 |
| 违法解除或终止赔偿 | 以经核验的经济补偿基数和年限计算 2N；与继续履行方案分开 | 违法解除的要件、解除事实、理由和程序证据、是否选择继续履行、是否存在可继续履行期间工资 | 2N 不与 N 或 N+1 机械叠加；不能把违法认定当作算术变量直接由模型决定 |
| 继续履行 | 无固定赔偿金；按是否可继续履行、恢复期间工资和福利、执行条件单列 | 员工意愿、岗位与组织是否仍存在、恢复履行可行性、期间工资标准和裁判/仲裁状态 | 继续履行不等于一定恢复，也不与 2N 同时作为最终给付项目 |

## 三、核心变量和公式

### 1. 工龄折算

优先使用已核验的“在本单位工作年限”或连续工龄月数；如果只有起止日期，先由人工确认当地及案件口径，再把换算过程写入底稿。通用计算器可暂按下式生成待复核的 N 月数：

```text
完整年数 = 总月数 ÷ 12 的整数部分
余月 < 6 个月且余月 > 0 → N 月数加 0.5
余月 ≥ 6 个月 → N 月数加 1
余月 = 0 → 不加余数
```

日期换算、连续工龄、关联单位承继或跨主体用工存在争议时，计算器必须标记 `needs_human_review`，不得把自动换算当作法律认定。

### 2. 月工资基数

默认候选基数为解除或终止前十二个月的平均应得工资；工作不足十二个月时按实际工作月数处理。工资构成应逐项列明计时/计件工资、奖金、津贴、补贴及其他货币性收入，并把加班费、报销、福利、提成、年终奖等存在口径争议的项目列为“纳入/不纳入/待核”三栏，而不是静默排除。

若候选工资可能超过当地上年度职工月平均工资三倍，只有在以下事项均已核验时才应用封顶：工作地点、统计年度、官方公布数值、适用规范和案件事实的时间连接点。适用封顶后，再核验补偿年限最高十二年的规则。缺少任何一项时，同时展示未封顶与封顶情景，并暂停唯一总额。

### 3. N、N+1 与 2N

```text
N = 核验后的月工资基数 × 核验后的 N 月数
N+1 = N + 核验后的一个月代通知金额
2N = N × 2
```

“一个月代通知金额”不得默认等同于 N 的月工资基数；依适用规范、解除路径和事实核验其口径。2N 是违法解除或终止路径下的条件化赔偿情景，须与继续履行方案、期间工资和附随项目分开列示，避免重复计算。

### 4. 附随项目

按用户输入和独立依据逐项处理：解除前欠付工资、未休年休假工资、可证明的加班费、奖金/提成、社会保险或公积金补救、竞业限制补偿、工伤待遇、报销和其他经核验项目。每项应有：金额或区间、计算式、证据位置、法律依据、是否与 N/2N 叠加、支付时间和争议状态。

## 四、成本比较的双层结构

客户版至少给出以下表格，不以单一“最便宜”结论代替比较：

| 层级 | 必填内容 |
|---|---|
| 法律直接成本 | N、N+1、2N、继续履行期间工资、已确认附随项目，分别列式和汇总 |
| 商业/操作成本 | 通知等待、人员替代、招聘和交接、管理时间、谈判溢价、法律服务费用等；全部标为用户假设或商业估算 |
| 风险敞口 | 触发条件、对方最强论点、证据负担、程序缺口、最坏情景和可规避措施；不得使用无数据的精确概率 |
| 现金时点与可执行性 | 何时应付、是否可能分期、是否有协议或裁判依据、现实回收与执行限制 |
| 决策建议 | 主方案、替代方案、停止点、责任人、所需材料和复核期限；由人工决策人最终选择 |

## 五、强制停止条件

出现下列任一情形时，停止“可以解除”“最终应付金额”“一定节省”等确定性表述：

- 法域、劳动关系主体、解除日期、工作年限或工资基数未确认；
- 保护性事实、工伤、歧视、报复、集体裁员、派遣或关联用工可能改变路径但未核验；
- 核心法源、司法解释、地方口径或年度工资数据无法独立核验；
- PDF 转换失败、文件数不一致、哈希不一致或 evidence JSON 的质量状态为 `fail`；
- 工资、工龄、理由、通知、工会、制度公示或培训调岗的关键证据缺失；
- 用户要求把内部底稿、个人信息、来源台账、批注或修订放进客户版；
- Word 未通过 Office CLI 版本预检、OpenXML 验证、批注/修订/隐藏内容检查或视觉复核。

## 六、论证强度与标签

每个核心判断同时标注：

- 来源标签：`[法条原文]`、`[司法解释]`、`[官方说明]`、`[地方官方口径]`、`[本地知识库]`、`[用户提供]`、`[模型线索—需验证]`；
- 核验状态：已验证、部分验证、待验证、受阻；
- 论证强度：强、中、弱；弱或待验证必须紧跟补强方向；
- 数字状态：已确认、条件计算、用户假设、待核。

客户版显示足以理解结论的来源和边界；内部底稿保留完整来源台账和操作留痕。
