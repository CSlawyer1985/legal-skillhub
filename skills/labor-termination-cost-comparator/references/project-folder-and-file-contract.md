# 项目文件与三目录交付契约

## 1. 项目命名

项目根目录使用 `YYYYMMDD_关键词`，例如 `20260919_研发岗位解除测算`。关键词只表达事项，不放身份证号、完整姓名、手机号、邮箱、账号或凭证。创建前由用户指定根目录；Skill 先给计划，收到显式初始化授权后才创建目录。

## 2. 输入材料

`01_输入材料/` 保存用户提供的原件或授权只读副本。建立 `材料清单.json`，至少包含：材料编号、相对路径、文件名、格式、文件大小、SHA-256、来源说明、接收日期、是否原件、读取权限和备注。原始文件不在原处编辑；如果材料已在项目内，不重复复制。

PDF 使用法律文件规则的全量转换契约：

- 一份 PDF 对应一个转换包；保留同名 Markdown 和 evidence JSON；
- 正文读取 Markdown，证据形式和质量状态读取 evidence JSON；
- 文件数、页数、哈希、质量状态或关键坐标异常时回查 PDF并停在人工复核；
- 不把 OCR 结果、印章/签名检测或版面坐标直接当作真实性、原件性或证据效力结论。

## 3. 处理过程

`02_处理过程/` 最少保留：

- `01_材料清单与哈希/`：输入清单、哈希、复制记录和权限记录；
- `02_PDF转换包/`：PDF 对应的 Markdown 与 evidence JSON；
- `03_事实与证据/`：主体表、事件时间线、工资输入表、证据定位表、缺口和冲突表；
- `04_法律核验/`：检索表达、来源台账、法源快照/定位、核验日期、冲突和人工复核记录；
- `05_计算与方案/`：计算输入 JSON、计算输出 JSON、公式说明、方案表和情景敏感性；
- `06_Word生成与检查/`：客户版和底稿的生成记录、Office CLI 版本、OpenXML 校验、清洁检查、渲染路径和视觉复核；
- `07_人工复核/`：复核人、日期、事项、结论、未决问题和签发门禁。

## 4. 输出交付

客户版和底稿必须分别生成、分别检查、分别保存：

- `03_输出交付/01_客户版/`：`客户版_劳动解除成本方案比较_YYYYMMDD.docx`；只含对客结论、金额、方案、依据概要、边界、行动和“未经签发不得对外使用”提示；
- `03_输出交付/02_内部底稿/`：`内部底稿_事实与法源核验_YYYYMMDD.docx`；含材料定位、来源台账、计算输入输出、缺口、质量警告、人工复核和版本记录。

客户版不得含 `comments.xml`、批注范围、修订标记、隐藏文字、内部文件路径、生成提示词、API/账号信息、来源台账全文或作者品牌标识。底稿可以含来源和审计信息，但仍不得写入密钥。

## 5. 归档和回滚

每次重新生成创建新版本文件，不覆盖已交付文件。若需要修正输入，保留旧输入清单和哈希，建立新的处理过程版本；回滚通过删除或移出新生成的处理/输出版本完成，不删除原始材料。
