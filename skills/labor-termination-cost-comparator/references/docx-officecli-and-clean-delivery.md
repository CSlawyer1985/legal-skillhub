# Word 生成、清洁与视觉核验规则

## 1. 工具优先级

本机处理 DOCX 前先运行 `/opt/homebrew/bin/officecli --version` 并记录版本。Office CLI 可用时，优先使用它进行读取、结构修改、保存、OpenXML 验证和渲染/预览；不得因为 PATH 未命中 `officecli` 就判定不可用。只有稳定入口不存在、不可执行或实际调用失败时，才允许有限降级到 LibreOffice，并在处理记录中写明原始错误、兼容性原因和 LibreOffice 仅承担的工作。

Office CLI 的实际命令和文档结构以 `officecli --help`、`officecli help docx` 和当前版本能力为准；不要把创建者机器上的命令猜测写成运行时保证。

## 2. 两份 Word 的内容隔离

客户版与内部底稿必须从同一份事实/计算数据分别渲染，不通过复制底稿后删除内容来生成客户版。客户版保留结论、计算式、必要来源概要、条件、风险和行动；底稿保留全部来源、材料定位、检索失败、计算输入、程序状态、质量警告和人工复核。

客户版不写入作者、主页、Skill 名称、内部路径、提示词或审计字段；Skill 包的署名只留在 Skill 元数据和包内文档，不自动进入业务交付正文。

## 3. 生成和核验顺序

1. 读取并验证计算 JSON 和法源台账；未通过门禁不生成“最终”字样文件。
2. 用客户版模板和底稿模板分别填充，金额表同时显示输入、单位、公式、结果和状态。
3. 使用 Office CLI 保存并运行 OpenXML schema validation；有常驻进程时先 `save` 或 `close` 再让其他工具读取文件。
4. 运行包内 `scripts/verify_docx_clean.py --mode customer` 检查批注、修订、隐藏文字、敏感元数据和内部路径；底稿使用 `--mode workpaper`，允许来源审计但仍禁止密钥。
5. 通过 Office CLI 预览/渲染，人工检查封面、页眉页脚、表格分页、中文字体、数字对齐、脚注、页码、空白页、结论是否被截断和客户版/底稿是否错位。
6. 把 Office CLI 版本、命令、文件哈希、验证结果、视觉检查人和日期记录到 `02_处理过程/06_Word生成与检查/`。

## 4. 清洁门禁

客户版出现下列任一项即阻断交付：`word/comments.xml`、`w:commentRangeStart`、`w:commentRangeEnd`、`w:ins`、`w:del`、移动修订、`w:vanish`、内部绝对路径、源文件名中不应暴露的个人信息、密钥模式、批注作者或未清除的内部文档属性。清除操作必须在独立副本上完成并复核，不能覆盖底稿或输入原件。

“无批注/无修订”不等于“法律上已审查”。Word 清洁检查只证明文件边界，不证明金额、法源或法律结论正确。
