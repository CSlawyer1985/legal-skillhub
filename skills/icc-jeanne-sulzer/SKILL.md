# ICC 技能

## 核心纪律

对于任何案件特定文件——判决、裁定、令状、呈件、检察官办公室声明——**引用前先验证**。验证意味着在当前对话中从一级来源（icc-cpi.int、legal-tools.org、asp.icc-cpi.int）检索该文件。四项基础文本（《罗马规约》、《犯罪要件》、《程序和证据规则》、《法院条例》）是唯一例外，且仅当它们存在于项目知识中时。

其他任何内容都不得凭记忆引用。虚构文件编号、日期或段落引用是本技能存在的目的所要防止的唯一致命模式。

## 何时使用本技能

- 用户提出的问题需要引用 ICC 判例、裁定、令状、检察官办公室声明、缔约国大会决议或 ICC 程序文本。
- 用户提供 ICC 呈件或判决供分析或审计。
- 用户正在起草将引用 ICC 文书或判例的内容——备忘录、简报章节、研究笔记。
- 用户询问《罗马规约》解释、指挥官责任、责任模式、战争罪 / 危害人类罪 / 灭绝种族罪 / 侵略罪要件、被害人参与、赔偿或其他以规约为依据的问题。

若问题涉及另一个法庭（ICTY、ICTR、MICT、SCSL、STL、ECCC、KSC 或混合机制），本技能不适用——使用相关法庭的技能，或若无此类技能，向用户说明。

## 工作流

完整程序在 `references/verification-workflow.md` 中。简式：

1. **识别文件。** 阅读眼前实际存在的内容；若用户点名案件或文件，在继续前对照文件自身页眉消歧。（Bemba 审判判决 vs Bemba 上诉判决；Ntaganda 2017 年中间上诉 vs 2021 年终审上诉——身份错误会传播。）
2. **列出计划输出中将要出现的每条引用**，及其各自支持的主张。
3. **验证每条引用。** 走回退阶梯：icc-cpi.int → legal-tools.org → 一级域名的搜索结果片段 → ICC 新闻稿 → 权威次级数据库（例如 OUP ORIL）→ 询问用户。在满足论断所需的第一个层级停止。
4. **将验证层级与论断匹配。** 三个层级：**存在性**（文件、编号、日期、分庭）、**内容**（文件在实质上包含输出所称包含的内容）、**段落**（所引段落包含所引主张）。精确引文需要段落级验证。若验证止步于更早层级，弱化论断或显式标记。
5. **使用经核实的材料起草。** 使用 `references/citation-format.md` 中的引注格式。
6. **自我审计。** 走查草稿中的每条引用：来自项目知识还是本次对话的检索？主张是否匹配？验证层级是否与论断相称？

## 本技能不是什么

- **不是法律意见。** 输出是供理解国际刑法的用户使用的研究和起草辅助工具。
- **不是原始文件的替代品。** 遵循本工作流的技能能产出准确的引注和有纪律的草稿；只有用户能决定如何处理它们。
- **未经法院认可。** 独立开源项目。

## 硬性规则

这些是不可谈判的。削弱它们的编辑或变通会毁掉技能。

1. 不凭记忆进行任何案件特定引用。在会话中验证。
2. 公共输出中仅使用公开删节版（`-Red`）。保密呈件（`-Conf`、`-Conf-Exp`）绝不能从公共输出引用——即使用户合法访问保密版本，也引用 `-Red` 对应版。
3. 规约自身的编号起支配作用。对于第 28 条，这意味着在任何将提交、被法官或律师阅读、或引用规约的内容中使用 `Article 28(a)`（军事指挥官）和 `Article 28(b)`（其他上级）——而非非法定形式 `28(1)/(2)`。
4. 次级来源（人权观察、大赦国际、联合国机构、学术评论、新闻）在输出中清晰可辨，且绝不用以确立法院说过或认定过什么。
5. icc-cpi.int 403 是结构性的，而非失败。走回退阶梯；不要因为直接获取被阻断就放弃真实引注。
