## 一、连接律师已有的材料

**大部分律师已经有自己的管理方式。工作台要做的第一件事是"读它"，不是"替代它"。**

### 常见材料形态 → 怎么接

| 材料形态 | 怎么接 | 关键注意 |
|---|---|---|
| **Excel 月历日程表**（最常见） | 只读解析成"日期 + 事项" | 按「日期行识别」而不是固定列位 |
| **Excel 待办 / 备忘表** | 只读，当备忘录 | 通常无日期，用空行当分节符 |
| **系统日历**（macOS 日历 / Outlook） | 可读可写 | 权限跟着"谁启动进程"走 |
| **案件文件夹** | 扫目录元数据 | 只扫 mtime / size，不读内容，极快 |
| **别的管理软件** | 先问"能不能导出 Excel / CSV" | 别去逆向它的数据库 |
| **期限提醒工具** | 找它落盘的**副产品**（json / CSV） | **别改它**，只读它的产物 |
| **材料在微信 / 邮件里，导不出来** | **先解决导出** | 导不出来就做不了，早点说清 |
| **没有案件文件夹** | 退化为"只按归属分组的列表" | 案卷挂钩整块跳过，别硬做 |

### 探测优先，提问兜底

**不要让律师手打路径**——他多半不记得。先扫，扫到了给他确认：

```python
import os
from pathlib import Path

HOME = Path.home()
候选目录 = [HOME / "Desktop", HOME / "Documents", HOME / "Downloads"]
# 同步盘：按名字猜（问一下他有没有更快）
for d in HOME.iterdir():
    if d.is_dir() and any(k in d.name for k in ("同步", "云盘", "OneDrive", "Dropbox", "Nutstore")):
        候选目录.append(d)

for base in 候选目录:
    for p in base.glob("*.xlsx"):
        print("可能的日程表：", p)
    for p in base.glob("*"):
        if p.is_dir() and any(k in p.name for k in ("案件", "律师", "业务", "项目")):
            print("可能的案件夹：", p)
```

扫完**让律师确认哪些是对的**。（同名文件可能有多个版本，选不出来就问他。）

### Excel 月历栅格怎么解析

最常见的结构（**没有合并单元格**）：

```
第 3 行：B~H 七列 = 周一~周日（日期）
第 4 行：B~H 七列 = 那 7 天填的内容
第 5、6 行：下一周……
```

**正确做法：按"日期行"识别，不按固定行号** —— 判据是"一行里出现 >= 4 个日期值"，
它的下一行就是内容行。这样律师以后在表里插入 / 删除行，解析都不会错位。

⚠️ `openpyxl` 读日期单元格可能返回 `datetime` 也可能返回字符串，两种都要处理。
⚠️ 文件在同步盘里时可能正被占用 / 同步中，要捕获异常并给友好提示，不要崩。

### 其他常见结构（只改 `parse_calendar()` 一个函数）

| 你的表长这样 | 怎么解析 |
|---|---|
| **一行一条**：`日期 / 事项` 两列 | 直接遍历行取两列 |
| **带表头**：`序号 / 日期 / 内容 / 备注` | 跳过表头，**按列名定位**（别按列号，列可能被插入） |
| **按周分块**：每周一个标题行 | 遇到"第 N 周"就更新当前周，后面的行归它 |
| **一表一月**，表名如"9 月" | 正则匹配表名拿到月份，再在表内找日期 |
| **日期是文本**（`2026.9.14` / `9/14`） | 正则抽数字拼日期，注意补年份 |
| **材料是 PDF / 纸质** | 先 OCR 成文本再解析，或干脆让律师手工维护一份 CSV |

无论哪种，**目标都是把数据规整成同一个形状**，其余代码就不用动：

```python
[{"date": "2026-09-14", "text": "上午九点开庭", "sheet": "9 月"}, ...]
```

**改造顺序**：先让骨架用内置示例跑起来 → 再换成真实数据源 → 最后调页面文案。
不要一开始就接真实数据，那样两个变量同时动，出问题分不清是哪边。

### 系统日历怎么接

- macOS 上读写日历要 AppleScript / `osascript`，**都要权限**
- **权限跟着"谁启动这个进程"走**：终端启动的进程有权限，从别的宿主 App 启动的可能没有
- 交付时给一个**双击运行的 `.command`**，让权限挂在"终端"名下
- 脚本开头**先自检权限并打印结果**，让律师一眼看到通没通

## 二、脱敏的依据（律师会追问"谁定的"）

三层规范 + 一层法定义务，**都不是技术拦截**——平台只管存文件，没有内容扫描机制，
限制写在文档里、靠执行者遵守。答律师时要讲清"谁定的、什么性质"，不要笼统说"有规定不能"。

| 层 | 出处 |
|---|---|
| 平台规则 | 所用平台 / 服务的安全底线文档 |
| 角色规范 | 所用 skill / 专家角色的边界声明 |
| 律师自己的纪律 | 如"对外分发产物一律虚构" |
| **法定义务** | 《律师法》保密条款 |

⚠️ **引法条必须现查，绝不凭记忆。**
例：《律师法》保密条款在 **2026 修正版中是第四十一条**（2026-09-01 施行），旧版才是第三十八条——
**条号会随法律修订变化**。用法律检索工具核准确原文再引用。

**不触发脱敏的例外**（别把规则用成一刀切）：

- 全虚构的演示数据
- 客户已明确同意公开的信息
- 本身就是公开的信息（如已生效裁判文书里的案号）

## 三、选模块

律师版模块清单，按优先级：

| 优先级 | 模块 | 解决什么 |
|---|---|---|
| **P0** | **记一条**（写入层） | 所有动态的唯一出口。输入框 + 回车即存，**点文字能直接改** |
| **P0** | **今天要处理** | 逾期（红）+ 今天 + 3 天内 + 本周。昨天没做完的**自动顺延**而不是消失 |
| **P1** | **案件列表**（案件 / 项目分区 + 重要度排序） | 一眼看到全貌、哪个最急 |
| **P1** | **案卷挂钩**（一键开文件夹 + 最近变动） | 不用开访达翻目录 |
| **P2** | **诉讼期限** | 开庭 / 上诉期 / 缴费期不能漏 |
| **P2** | **备忘 / 沉淀** | Excel 里的备忘、定稿文档 |
| **P3** | 案卷台、日历同步 | 见 `architecture.md` |

### 案件与项目要分区、要配色区分

律师的列表里通常混着"真案件"和"非案件的事"（培训、出版、合作项目）。
两类**必须在视觉上分开**——分区标题 + 每条左侧色条，扫一眼就知道是哪类。

自动判定（强特征优先）：命中"讲座 / 培训 / 出版 / 公众号 / 课件 / 合作项目"等词 → 项目；
带案号或含"案 / 纠纷 / 执行 / 开庭 / 诉讼"等词 → **案件**；都不像 → 默认案件（贴合职业）。

**判错了要给一键纠正，并记住纠正结果**（存工作台自己的数据层，不动源文件）。

### 重要度排序的参考分值

```
期限逾期            6000 + 每项 100
期限 3 天内         5000
自己的提醒逾期       3000 + 每条 20
3 天内到期 / 有待办  2000 / 1000
备忘条数（体量）      最多 90
有案号              20
```

**紧迫度最低档（600）远高于体量最高档（90）** —— 这样没有急事的条目绝不可能盖过有急事的。

⚠️ 分数必须**可解释**：把理由显示在条目上（如"逾期1项 · 期限3天内1项"），律师才能判断对不对。

## 四、验证

### 1. 页面静态检查（不开浏览器）

```bash
python3 scripts/check_page.py index.html "动态生成的id,逗号分隔"
node --check /tmp/_page_check.js      # 脚本会导出提取好的 JS
```

六项：缺失 id / **隐式全局赋值** / **函数调用环（DFS）** / CSS 重复定义 / 关键类缺定义 / 外部依赖 + emoji。

### 2. 服务端断言

覆盖：数据解析计数、写入层 CRUD、办结计数变化、路径越界防护（403）、分区逻辑、排序断言。
**跑之前先备份数据目录，跑完恢复。**

⚠️ **不要在脏数据上连跑两遍** —— 第二遍的结果无效（被第一遍污染）。

### 3. 真实渲染确认

截图确认。并且**凡是要判断"内容有没有被裁掉、能不能滚"，截图无效，必须量 DOM 几何**
（headless 通常不渲染滚动条）：用 Chrome 调试端口读 `clientHeight` / `scrollHeight`。

### 4. 端到端走一遍律师的三个动作

1. 记一条 → 刷新 → 还在吗
2. 点一个案件 → 右栏是那个案的东西吗
3. 点日期 → 那天的事项对吗

## 五、交付与日常

### 交付清单

```
<工作台目录>/
├── 启动工作台.command     双击启动（后台运行，终端窗口可关）
├── 停止工作台.command
├── server.py             本地服务
├── index.html            工作台页面
├── README.md             写给律师看的说明
└── data/
    └── 动态.csv          唯一写入层（可双击用 Excel 打开改）
```

### README 必须写清三件事

1. **哪些是只读的**（"你的 Excel 一个字节都不会被改"）
2. **要改东西去哪改**（"有日期的继续在 Excel 改；没日期的在 `动态.csv` 改"）
3. **出问题怎么办**（服务没起来怎么重启、端口被占怎么看）

### 两个必须主动交代的坑

- **启动器不能"已在运行就直接退出"**。那样律师改了代码后，双击启动器看起来成功了、实际什么都没发生。
  必须比对代码时间戳，需要重启就**先停旧起新**，并在启动后**自检是否加载了新代码**。
- **进程与权限的绑定关系**：日历权限跟着"谁启动进程"走。报状态时要说清是哪个进程，否则会造成误判。

### 对律师的一句心态话

**律师不需要懂终端，只需要会双击。** 整个日常使用都在浏览器里，终端窗口只是一次性启动，
启动完就可以关掉。交付时把这句话讲明白，能省掉一半的"我不会用"。

## 六、与「工作台搭建师」专家的关系

小台（DeskCraft / 工作台搭建师）和本 skill 是**互补**的，但有一条**必须先说清的路线差异**。

### 小台值得借的地方

- 五类人群（学生 / 职场 / 自媒体 / 宝妈 / 生活）的需求理解与模块清单
- 十条通用铁律：全内联零外链、移动适配、"今天要处理"置顶、预置示例数据、
  需求过载控制、DAG 防循环、生成后冒烟自检
- 一键部署能力

本 skill 的九条铁律里，**有四条就是从它那套通用规范继承来的**。

### ⚠️ 但它的默认路线是「资料库全托管」——对律师场景必须改

小台的前置动作是：加载资料库 skill → **用云端数据表存储业务数据** → **部署成在线链接**。
默认假设是"数据上云、多设备同步"。**对案卷与当事人信息，这条路不能走。**

### 两种用法

| 情况 | 怎么做 |
|---|---|
| 律师只要"文件全在本地"（案卷场景） | **直接用本 skill**，不必选小台专家 |
| 律师想要小台的 UI / 交互 / 部署经验 | 可以选小台，但**第一句就必须明确**：<br>「数据必须全部留在本地，**不要用资料库存储与部署**」 |

⚠️ **选了小台却没说这句话，它会按默认流程把页面和数据往云端放。**

> 反向也成立：如果律师要的只是记账 / 习惯打卡这类**不含客户信息**的个人工作台，
> 小台那条路线反而更省事（手机直接打开、数据自动同步）—— **那就不必用本 skill**。
