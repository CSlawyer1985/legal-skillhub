# /customize

## 何时运行

用户键入 `commercial-customize`。他们想修改业务领域配置中的某项——风险姿态、上报联系人、审查指引立场、管辖、输出格式——而无需重新运行完整冷启动访谈，也无需手动编辑配置文件。

## 做什么

1. **读取配置。** 读取 `$LEGAL_AGENT_PROFILE_HOME/commercial-legal/profile.md`（以及上一层的 `$LEGAL_AGENT_PROFILE_HOME/company-profile.md`）。如果不存在或仍有占位符，说：

   > 你还没有运行设置。先运行 `commercial-cold-start-interview`——定制功能用于调整已有的配置。

2. **展示可定制项目清单。** 按组列出配置中的内容，附带当前值的一行摘要：

   - **公司/你是谁** — 名称、行业、法域范围、执业场景、销售方/采购方取向 *（与所有插件共享——变更通过 `company-profile.md` 传播至所有插件）*
   - **风险姿态** — 保守/中等/激进，各自对让步立场和上报触发的影响
   - **人员** — 上报链条、按金额阈值和条款类型设置的审批人
   - **审查指引立场** — 实质合同立场：责任上限、赔偿范围、知识产权归属、数据保护、期限和终止、自动续约、价格调整，及各自的让步方案
   - **保密协议分类偏好** — 绿色/黄色/红色对入站保密协议的含义
   - **审查偏好** — 修订风格、说明深度、是否默认生成利益方摘要
   - **行文风格** — 文档格式、续约提醒频道、偏离日志格式
   - **工作流** — 事项工作区路径、收案路径、续约监控节奏
   - **集成** — 电子签章（e签宝/法大大）/合同管理系统/飞书/文档存储状态及替代方案

3. **询问想修改什么。**

   > 你想调整什么？选一个部分，或用自己的话描述要做的变更。

4. **进行修改。** 展示当前值、询问新值、说明下游变更影响、确认、写入配置。

   示例：
   - *责任上限让步从12个月→6个月：* "`/review` 现在会将超过6个月的任何条款标注为偏离；现有的交易复盘条目保持原样记录。"
   - *新的上报审批人：* "超出你自身权限的任何修订，现在将默认路由至此审批人——`/escalation-flagger` 会自动将其纳入对应风险级别。"
   - *风险姿态从中等→激进：* "我将接受更多对供应商有利的立场而不标注为偏离，并相应提高 `/review` 的标注门槛。"

5. **共享配置变更**（公司名称、行业、法域范围、执业场景）：写入 `company-profile.md` 并注明：

   > 此变更影响所有插件——任何读取你法域范围的插件现在将看到[新值]。

6. **收尾。**

   > 完成。你的下一个输出将反映该变更。随时可运行 `commercial-customize` 进行调整。

## 防护措施

- **绝不删除任何配置部分。** 如果用户想"移除"某项，将其设为 `[未配置]` 并说明对插件行为的影响。
- **内部矛盾检测。** 如果变更会使配置不一致（如风险姿态激进 + "每项修订都需法务负责人批准"；或"销售方取向" + 采购方审查指引立场；或风险姿态设为"保守"同时某条款设为"可接受让步"），标注矛盾项并询问以哪个为准。
- **标注防护措施降级。** 如果用户要求关闭某项防护措施（取消 `[需审查]` 标注、跳过保密文件头、移除法规引用的 `[需核实]` 标签），说明该防护措施保护的内容并确认用户理解了权衡。
- **防护层级分类。** 明确区分"硬防护"（不可关闭）与"软防护"（可在确认权衡后调整）。**硬防护（拒绝关闭）**：法源引用 `[需核实]` / `[verify - 需对照原文]` 标注不可移除、不可商议 路由（escalation-flagger）不可跳过、保密文件头不可去除、来源归属标签不可移除（承重结构）。**软防护（可调）**：重要性阈值、提醒频率、模板措辞偏好等。
- **一次一项变更。** 不要重新问整个访谈。
