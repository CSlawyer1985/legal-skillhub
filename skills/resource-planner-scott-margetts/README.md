# resource-planner

**插件：** LPM Core  
**技能编号：** 19 个中的第 10 个  
**状态：** v1 已构建——第一阶段测试进行中

---

## 功能

设计事项团队结构、识别齿轮比问题、规划团队连续性，并跨事项建模资源冲突。以实际可用的内容工作——时间条目、声明的团队结构、已知缺勤、具体的具名冲突——并为合伙人产出分析和选项。

律所资源配置是流动的。合伙人基于非正式且滞后的可用性、关系和工作量信号配置人员。本技能不产出权威资源计划，也不解决冲突。它对情况建模、浮出财务和交付影响，并结构化为合伙人需要做的决策。

---

## 不做什么

- **做出人员配置决策**——合伙人将人员分配到事项。本技能建模并标记。
- **访问实时费率或 WIP 数据**——费率必须作为输入提供或从事项预算获取。实时系统数据需要实践管理 MCP 连接器（参见 SKILL.md 中的 M365 一节——未来能力）。
- **质疑人员配置理由**——技能浮出实际职级组合的成本和交付影响。不过问团队为何如此构成。
- **解决职业责任问题**——利益冲突筛查、监督义务和资格要求属于律师领域。

---

## 主要输入场景

1. **事项设置**——将范围转化为所需职级组合，与拟议团队比较，识别差距。

2. **事项中途齿轮比审查**——实际时间条目显示团队在错误的层级工作。建模成本影响并标记模式。

3. **团队成员不可用**——休假、离职、冲突、生病。评估对活跃工作流的影响、产出替补选项、识别所需决策。

4. **跨事项竞争需求**——某具体人员被过度分配。建模冲突、识别什么让位、为合伙人产出选项。

---

## 输入

- 事项范围描述或 matter-intake-scoping 输出
- 拟议团队（职级和已知的姓名）
- 按职级记录的时间（粘贴、上传 CSV 或描述）
- 事项预算和齿轮比假设（可用时来自 budget-and-fee-manager）
- 费率数据——来自事项预算、记录系统或用户陈述（指示性区间仅作回退）
- 具名缺勤、离职日期或竞争性事项需求
- 产能信号——“谁有产能？”邮件线程、日历描述、WIP 描述

---

## 输出

所有输出默认以 `.docx` 文件生成。

| 模式 | 主要输出 | 次要输出 |
|---|---|---|
| 模式 1——齿轮比模型 | 团队结构表，按阶段含职级/小时/成本 | CSV 导出 |
| 模式 2——齿轮比审查 | 实际 vs 预算齿轮比表 + 差异评论 | CSV 导出 |
| 模式 3——连续性规划 | 影响评估 + 替补选项 + 交接要求 | 合伙人决策清单 |
| 模式 4——竞争需求 | 冲突地图 + 带权衡的选项 | 合伙人决策清单 |

---

## 关于费率数据的说明

本技能无法从实践管理系统拉取计费费率。费率应从事项预算（budget-and-fee-manager 输出）提供或直接陈述。指示性市场区间仅作回退使用，且在任何面向客户的使用前必须与 Pricing 确认。未来的实践管理 MCP 连接器将启用实时费率和 WIP 数据——详见 SKILL.md。

## 设计说明

**资源配置现实被编码在技能中。** 技能明确承认律所产能数据是非正式、滞后且自报的。它按可靠性对输入信号排序（日历 > 时间条目 > 邮件回复 > WIP），并在每次产能分析中标记数据时效。这防止模型将陈旧图景呈现为定论。

**实践管理集成是被点名的未来路径。** 指向 SAP、Aderant、Elite 或等效系统的自定义 MCP 服务器将交付实时费率和 WIP 数据。技能方法论相同——数据质量提高。这在 M365 连接模式一节中被记录为 v2 集成路径。

**授权检验是核心分析动作。** 对每块工作：某人低一级是否也能达到足够质量完成？若能，那是带成本影响的授权机会。若团队中不存在该职级，那是资源配置差距。
