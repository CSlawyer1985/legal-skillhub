# matter-allocation-instruction

**OCM 技能插件**——8 个技能中的第 5 个
**状态：**已完成——阶段 1 和阶段 2 已测试

---

## 本技能的用途

执行事项分配和律所委托，从律所选聘一直到启动中的、已正确委托的事项。使用合理外包框架为新事项匹配合适的律所。生成完整的事项委托，可随时发送。生成关闭利益冲突清查、委托函、OCG 和电子计费门禁的入职检查清单。审计现有委托的缺口，并附可随时发送的补救说明。

这是已寻源事项的执行层。panel-design-selection（技能 2）定义哪些律所在律师库上。rfp-pitch-management（技能 3）通过竞争性流程选聘律所。本技能委托选定的律所并关闭入职门禁。

---

## 模式

| 模式 | 触发词 | 输出 |
|------|---------|--------|
| 1——事项分配 | "哪家律所应处理这个" / "分配这个事项" / "我们应该用谁" | 事项分配建议 + 总法律顾问/预算负责人说明 |
| 2——委托模板 | "委托律所" / "写委托" / "起草委托函" | 事项委托（可电邮）+ 内部分配记录 |
| 3——律所入职 | "让律所入职" / "设置事项" / "他们开始前我们需要什么" | 事项入职检查清单 + 律所入职确认请求 |
| 4——委托审计 | "我们的委托完整吗" / "审查委托" / "缺少什么" | 委托缺口评估 + 委托补救说明 |

---

## 关键设计决策

**利益冲突清查作为硬性门禁。**模式 3 阶段 1 的门禁按顺序设置以阻止工作启动。模式 2 将利益冲突清查作为独立条款包含。模式 4 将其缺失标记为关键。不是提醒——是结构性控制。

**委托时的电子计费设置。**作为带 2 个工作日截止日期和明确责任人的具名入职项目处理。发票以无 UTBMS 编码的 PDF 到达，因为没有人告知律所计费联系人格式要求——这种模式是委托环节的流程失败，而非发票审查环节的。

**模式 1 中的合理外包逻辑。**分配建议针对七个合理外包因素评分。默认的大型律所偏见——因为关系在那里就分配到 A 级——被点名为常见故障模式。检验标准：这个事项是否需要 B 级律所明确无法提供的技能或规模？

**可电邮的委托。**模式 2 输出结构化为可直接粘贴进发给主管合伙人的电子邮件。委托通过电子邮件发出。需要在使用前转换的技能输出会产生减少采用的摩擦。

**委托时的报告节奏。**模式 2 将报告节奏、格式和首份报告日期作为具名字段包含。这是客户拥有杠杆的时刻。

## 跨技能连接

| 技能 | 连接 |
|-------|-----------|
| panel-design-selection（技能 2） | 定义哪些律所在律师库上以及处于哪个层级。模式 1 在该结构内分配。 |
| rfp-pitch-management（技能 3） | 通过 RFP 任命的律所首次通过本技能委托。 |
| fee-arrangement-structuring（技能 4） | 商定的 AFA 在委托模板中被引用。 |
| engagement-terms-billing-guidelines（技能 1） | OCG 是在入职时确认的前提条件。模式 3 关闭确认门禁。 |
| invoice-review-compliance（技能 6） | 委托缺口（无 UTBMS 要求、无人员配置披露）是发票合规失败的上游原因。 |
| matter-intake-scoping（LPM 核心） | 事项委托是 LPM 接案在客户侧的对应物——相同信息、不同受众。 |
