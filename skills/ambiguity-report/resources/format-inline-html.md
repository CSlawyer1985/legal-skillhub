# 格式：单文件 HTML

一个自包含的 `.html` 文件，直接从规范编写。不运行脚本、不导入任何内容，结果可在任何机器上双击打开。

这是**通用后备方案**——唯一完全没有主机要求的格式——并且也是交付物需要经电子邮件发送、附入案件卷宗或由不愿解压文件夹的人打开时的正确首选。

## 何时使用

- 主机无法运行 Python 或写入目录树。这是唯一仍然可行的格式。
- 受众是一两个人需要阅读，而不是会回访的团队。
- 交付物必须以附件形式传输。
- 用户现在就要结果，而多页面网站对这项工作而言过于繁琐。

在可用且受众会回访的情况下，优先使用脚本生成的多页面网站——每个场景的 URL 值得拥有，而本格式没有。

## 构建

直接编写文件。不要调用 `scripts/generate_site.py`；不要尝试复现其输出结构。

**自包含正是全部意义所在。** 所有内容放在一个文件中：

- 所有 CSS 放在 head 中单个 `<style>` 块内。从 `assets/site-style.css` 取设计——阅读它并适配本版式所需的内容，而不是发明新的视觉语言，这样单文件输出与网站是明显同一产品。
- 任何 JavaScript 内联，并保持最小化。平滑滚动锚点和折叠开关值得拥有；其他都不需要。
- 无外部样式表、无外部脚本、无链接图片。
- **无网页字体。** 多页面网站从 Google Fonts 加载 Fraunces、Inter 和 Crimson Pro。本格式不得如此：打开时向外拨号的文件夹不符合电子邮件审查的要求，且在离线时渲染不佳。使用系统字体栈——正文用衬线栈，界面用无衬线栈——如果用户设置了 `design.primary_font`、`design.body_font` 和 `design.serif_font`，将其映射到该栈上。
- 遵循规范中的设计标记——`accent_color`、`accent_soft`、`dept_color`、`adv_color`、`background_color`、`family_palette`。将它们声明为样式块顶部的 CSS 自定义属性，这样后续调整就是一行编辑。

## 文档结构

镜像多页面网站的信息架构，扁平化为一个带顶部锚点索引的滚动页面。

1. **页眉**——标题、源文书、日期、品牌标识（如提供）。
2. **目录**——场景的链接列表，每个场景的缺陷类别显示为彩色标签。这是替代每场景 URL 的东西；做好它。
3. **执行摘要**——场景数量、涉及的类别，以及最重要的一个或两个接缝点。
4. **源文本**——文书或被审摘录，置于受限的滚动块中，条款 ID 作为锚点目标，使场景的锚点可以链接到其中。
5. **场景**——每个场景一个章节，按规范顺序，承载每个字段：标题、叙述、链接回源文本块的锚点、缺陷类别、弱点、可能结果以及改写文本或论证对。立场 A 和立场 B 采用两个侧面板颜色，与网站一致。
6. **改写文本附录**——每个拟议的治疗方案作为一个修改包集中收集，使起草人可以从单一列表出发工作。
7. **方法论**——分析是如何产生的、研究步骤使用了什么或无法核查什么，以及预测结果只是预测的免责声明。

## 规模

单文件 HTML 可以舒适地容纳常规审查。超过约四十个场景后，页面导航变得笨拙，目录列表不再能承载——如实说明，并在主机能生成时推荐多页面网站。

## 交付

一个文件 `report.html`。通过主机提供的任何机制交付，或陈述路径。它不需要压缩包、不需要文件夹、不需要静态托管：本地打开即是预期用途，上传到任何地方同样可行。
