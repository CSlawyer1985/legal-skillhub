# 专利无效宣告请求技能（patent-invalidation）

## ⏱ 快速开始（3 步上手）

### Step 1：装依赖

```bash
pip install requests python-docx PyMuPDF Pillow openpyxl
```

> `requests`——PatSeek 检索必备；`python-docx`——生成请求书；`PyMuPDF`——PDF 解析（解构目标专利）；`Pillow`——附图同色标注（G7）；`openpyxl`——Excel 证据清单生成。

### Step 2：配置 PatSeek API Key（三种方式，按需选）

⚠️ **本技能不内置任何 API Key**。每个用户须自行到 [https://patseek.cn](https://patseek.cn) 注册并创建 Key，**禁止把别人的 Key 写进代码/.env 提交到仓库**。

| 方式 | 适用 | 命令 |
|------|------|------|
| **A. 环境变量（推荐，临时）** | 单次会话 | `export PATSEEK_API_KEY=ps_你的Key`（Windows PowerShell: `$env:PATSEEK_API_KEY="ps_你的Key"`） |
| **B. .env 文件（推荐，持久）** | 跨会话使用 | 在 `scripts/.env`（或 skill 根目录 `.env`）写入一行：`PATSEEK_API_KEY=ps_你的Key` |
| **C. 命令行参数（一次性）** | 临时测试 | `python scripts/patseek_client.py --api-key ps_你的Key bool "..."` |

> 查找顺序（**不覆盖已有环境变量**）：`--api-key` > `$PATSEEK_API_KEY` > `scripts/.env` > skill 根 `.env` > 当前目录 `.env`。`.env` 示例见 `scripts/.env.example`（**该文件不含任何真实 Key**）。
>
> **没有 Key 也能用（v1.1.0 新增）**：检索主链路之外的解构、请求书生成、证据清单等全部脚本均不依赖 Key；检索环节可用 `python scripts/invalidation_search.py ... --offline` 生成**人工检索清单**（CNIPA 公布公告 / 专利检索及分析系统 / Espacenet / Google Patents 四条免费通道的逐步操作），详见 M3 模块说明。

### Step 3：跑通 hello-world

```bash
# 1. 看技能说明
python scripts/patseek_client.py --help

# 2. 检索验证（不需要目标专利号的轻量测试）
python scripts/patseek_client.py bool "IPC=(H01M) 电池" --page-size 5

# 3. 生成请求书模板（--out 为必填参数，指定输出路径）
python scripts/make_invalidation_doc.py --out output/无效宣告请求书_模板.docx
# → 输出到 output/无效宣告请求书_模板.docx（目录自动创建）

# 4. 目标专利解构
python scripts/analyze_target_patent.py --patent your_target.docx --out report.md

# 5. 无效检索计划（dry-run 不需 Key）
python scripts/invalidation_search.py \
    --target-patent CNxxxxxxxxA --priority-date 20150310 \
    --ipc G02B --features "特征1;特征2" --applicant "申请人"
```

### 常见错误

- ❌ 没装 `requests` → `pip install requests`
- ❌ 没配 Key → 401 MISSING_API_KEY，按 Step 2 选一种方式配置；**或改用 `invalidation_search.py --offline` 走人工检索清单**
- ❌ 检索式忘加 `PD<优先权日` → 命中混入申请日后文献，**全部不可用**
- ❌ IPC 写 6 位（如 `H01M10`）→ 漏匹配，统一**前 4 位**（如 `H01M`）
- ❌ 跑 `make_invalidation_doc.py` 不带 `--out` → 报 `the following arguments are required: --out`，输出路径是必填参数
- ❌ 跑 `make_invalidation_doc.py` 报 `FileNotFoundError` → 手动 `mkdir assets`（已在 v1.0.6 修复：自动建目录）
- ❌ 引用细则条款沿用旧号（65.2/66/67/69/20.1/20.2）→ 2024 版已重编号（69.2/70.2/71/73/22/23.2），对照表见 `references/无效宣告程序与证据规则.md` 文首

## 〇、定位与同族关系

本技能是"专利救济技能族"的第三条技能，与已有两项互补：

| 技能 | 方向 | 程序 | 主攻维度 |
|------|------|------|----------|
| `patent-oa-response` | 申请人**防守**（答复审查意见） | 实审 | 多为创造性 |
| `patent-reexamination` | 申请人**进攻自己**（驳回复审） | 复审 | 多为创造性 |
| **`patent-invalidation`（本技能）** | **第三人进攻他人**（无效宣告） | 无效宣告 | **多理由组合** |

**核心差异**：无效宣告是"以第三人之名，用公开证据击破已授权专利"，方向与他俩相反；其胜负不依赖"申请人改不改得动自己的专利"，而依赖"能否用证据链证明他人专利本不应授权"。因此本技能把**证据链、理由组合、程序博弈**提到第一位，创造性只是可选理由之一。

> 调用建议：收到"无效某专利"类任务时，本技能为第一入口；若任务实为"答复别人对我的专利提出的无效"（即专利权人应诉），请改用 `patent-oa-response` 的"无效宣告应诉"思路或另行说明。

## 一、适用场景

- 委托人拟对某项授权专利提出无效宣告请求（规避侵权、谈判筹码、清除市场壁垒、反击专利权人起诉）。
- 需对目标专利做**无效可行性分析 / 攻击点诊断 / 证据检索方向建议**。
- 需撰写**无效宣告请求书**核心内容（理由、证据、特征比对、论证）。
- 需设计**多理由组合策略**（主攻击破点 + 辅助佯攻）。
- 需评估"使用公开 / 域外证据 / 优先权文件 / 授权档案反悔"等特殊证据路径。

不适用：专利新申请撰写、实审答复、驳回复审（见同族另两项）；专利权人应诉（方向不同）；商标/著作权无效（非本技能范围）。

## 二、核心理念

1. **进攻性思维（方向反转）**：从"证明自己的方案可授权"转为"证明他人的授权本不该发生"。所有论证服务于"用证据链击穿授权根基"。
2. **证据链为王**：无效宣告的本质是**用现有技术/使用公开证据证明专利不符授权条件**。单一证据不够，必须形成时间、内容、形式上均无懈可击的**证据链**，达到"高度盖然性"证明标准（尤其使用公开类证据）。
3. **多维度精确打击**：相比复审通常单攻创造性，无效宣告应**组合多条法定理由**（新颖性/创造性/充分公开/清楚/支持/超范围/缺必特/客体/重复授权），形成"主攻+辅助"的立体攻击面。
4. **策略性佯攻**：善用辅助理由（如法33修改超范围、细则22（旧细则20.1）不清楚）作为**佯攻**，迫使专利权人在口头审理中亲口说出对主攻理由有利的事实（经典"两难陷阱"，见 references/无效宣告典型案例.md 的 W402284 案）。
5. **程序博弈意识**：利用**提出请求起1个月内可补充理由/证据**的窗口、口头审理的发问节奏、以及"行政+司法联动"（对无效决定不服可起诉北京知识产权法院）来安排整体节奏。
6. **商业目的导向**：无效是商业手段而非学术练习。理由与证据的选择应服务于委托人的真实目的（全无效 / 部分无效以缩小对方权利 / 拖延或谈判筹码），而非追求理由数量。

## 三、方法论

### 3.1 目标专利解构（所有攻击的前提）
- **权利要求树**：拆分独立权利要求的必要技术特征，理清从属权利要求的引用与限定关系，识别"从属权利要求是否作出实质性限定""独立权利要求是否缺少必要技术特征"。
- **说明书/附图印证**：权利要求与说明书是否一致？有无"权利要求超出说明书范围""说明书未支撑权利要求效果""自造词不清楚"等矛盾点。
- **授权档案反悔（file wrapper）**：调阅申请-审查-授权全过程档案，重点看：授权时补入的特征是否**原始公开过**（涉法33修改超范围）；审查中申请人对技术效果的**承诺/限制性陈述**（禁反言，可用于解释权利要求或证伪创造性）；审查员曾认可的现有技术（可用于创造性证据组合）。

### 3.2 无效理由体系（按法/细则条款）
| 类别 | 条款 | 攻击要点 | 典型证据 |
|------|------|----------|----------|
| 新颖性 | 法22.2 | 相同/实质相同技术方案在申请日前公开 | 单篇现有技术（文献或使用公开），公开日早于申请日 |
| 创造性 | 法22.3 | 三步法：最接近现有技术→区别特征→实际解决技术问题→显而易见 | 2+篇现有技术组合 + 公知常识证据 |
| 实用性 | 法22.4 | 不能制造/不能使用/无积极效果 | 原理性证据、技术常识 |
| 充分公开 | 法26.3 | 所属领域技术人员无法实现（缺必要实验数据/机理/参数） | 说明书本身 + 反证/专家意见 |
| 清楚性 | 法26.4 / 细则22（旧细则20.1） | 权利要求不清楚（自造词、含义模糊、引用错误） | 权利要求文本 + 说明书佐证 |
| 支持/依据 | 法26.4 | 权利要求概括过宽，得不到说明书支持 | 说明书公开范围对比 |
| 修改超范围 | 法33 | 授权文本相对原始申请文件新增内容 | 授权档案（原始申请 vs 授权文本） |
| 缺必要技术特征 | 细则23.2（旧细则20.2） | 独立权利要求缺解决技术问题必有的技术特征 | 说明书技术问题表述 |
| 重复授权 | 法9.1 | 同一发明两以上专利（含本人另一专利） | 两专利文本比对 |
| 客体 | 法5 / 法25 | 违法/公害、科学发现、智力规则、疾病诊疗方法等 | 权利要求内容分析 |
| 外观设计 | 法23.1/23.2 | 不相同/不近似、组合对比、惯常设计 | 现有设计文献/使用公开 |

> **条款编号说明（2024 施行版）**：本表"清楚性"所列"细则20.1"、"缺必要技术特征"所列"细则20.2"为 2010 版《专利法实施细则》编号；现行《专利法实施细则》自 2024-01-20 起施行，已重新编号——权利要求清楚简要 = **细则22**，缺少必要技术特征 = **细则23.2**；无效理由范围 = **细则69.2**（旧65.2）、1个月增加理由/补充证据 = **细则71**（旧67）、一事不再理 = **细则70.2**（旧66.2）、无效中修改不得扩大范围 = **细则73**（旧69）。完整新旧对照表见 `references/无效宣告程序与证据规则.md` 文首，引用时建议新旧对照，避免法律适用偏差。

### 3.3 证据体系与组合
- **时间节点硬约束**：所有证据公开日必须早于目标专利申请日（有优先权的，早于优先权日）。这是新颖性/创造性/使用公开的死线。
- **证据类型**：① 专利文献（最稳，公开日明确）；② 非专利文献（论文、手册、标准，注意发表日）；③ 使用公开（销售、展会、宣传册、产品，需发票/公证/高度盖然性证据链）；④ 优先权文件/原始申请档案（用于法33、优先权、支持问题）。
- **证据链组织**：单份证据薄弱时，用"产品+发票+宣传册+检测报告+展会记录"形成相互印证的链条，达到"高度盖然性"。
- **形式合法性**：域外证据需公证认证（2023-11-07 起公约成员国可以 **Apostille 海牙认证**替代领事认证）；外文需规范中文译文；使用公开需固定来源与时间；**图书类非专利文献须附版权页及原件**（仅提供复制页而无版权页/原件，合议组对公开日与真实性存疑时可能不予采信）。
- **公知常识证据**：技术词典、手册、教科书可在口头审理辩论终结前补充，用以证明区别特征属常规手段。
- **检索数据源（v1.0.4 修订 · G6）**：**PatSeek 为首选 / 主检索引擎**，现有技术 / 抵触申请 / 重复授权检索优先经 PatSeek 完成——国内文献走 `bool` 检索式，国外 / 全球文献走 `semantic` 语义检索（覆盖 JP/US/EP/KR 等）。**本技能不排斥其他检索途径**：当 PatSeek 无法获取某文献的全文、附图或图形，或无法检索 / 获取外国专利文献的全文与附图时，**应启用其他检索途径**（各国家/地区专利局官方公报、专利数据库门户、其他合规检索工具等）补全所需的专利文献、全文或附图。无论经何种途径获取，**应尽量取得对比文件的原始附图与说明书全文**，以保证特征比对（G7）与"证据具体出处"的准确性；PatSeek `patent` 详情接口目前仅稳定返回 CN，国外文献缺全文 / 附图时依本条款启用其他途径补全，并在证据清单中注明来源途径。涉案专利说明书中**自认引用**的国外文献（直接引用其公开号，内容以涉案专利背景技术的描述为准，具自认效力）可优先直接采用，无需另行检索。
- **无 PatSeek Key 时的降级工作流（v1.1.0 新增）**：未配置 Key 时检索能力不应归零——运行 `python scripts/invalidation_search.py ... --offline`，输出四条免费通道（CNIPA 公布公告系统 / CNIPA 专利检索及分析系统 / Espacenet / Google Patents）的**逐步人工检索清单**：含各通道入口、本技能检索式到各通道语法的转写、时间死线（公开日 < 申请日/优先权日）核对要点、结果固定与来源标注规范。人工检索结果回填证据清单后，M4–M11 全流程不受影响。
- **中国专利官方全文/附图获取通道（v1.0.5 新增 · G6 落地）**：PatSeek 的 `patent` 详情接口仅稳定返回 CN **文本**、**不含附图**。对于**中国专利**（目标专利或 CN 对比文件）需要权威全文 PDF 与原始附图时，应经 **国家知识产权局「中国专利公布公告系统」`epub.cnipa.gov.cn`** 获取——该系统为社会公众免注册入口，提供 1985 年至今的发明公布/授权、实用新型、外观设计的**专利单行本 PDF（含说明书全文 + 附图）**。获取方式：以公开号/申请号检索 → 结果页点『下载PDF』（含**图形验证码**，需人工或验证码服务辅助）；**附图亦可经在线图像浏览器直接查看，无需下载 PDF**。配套脚本 `scripts/cnipa_epub.py`（`url` 打印直达链接、`pdf` 尽力下载、`batch` 批量）已内置；详细流程、验证码说明与证据标注见 `references/CNIPA公布公告获取(CN全文与附图).md`。
- **国外专利附图/全文获取通道（v1.0.6 新增 · G6 落地 · 国外版）**：针对**国外专利**（US/EP/JP/KR/WO/DE/FR/GB/CA/AU 等）需附图或全文 PDF 时，应经 **Google Patents**（首选，无验证码、附图单独可下载）或 **Espacenet**（备选，完整 PDF 含说明书+附图）获取。配套脚本 `scripts/foreign_patent_fetch.py`（`info` 元数据 / `figures` 抓附图 / `pdf` 抓 PDF / `batch` 批量，公开号自动归一化）已内置。**附图下载后直接用 `scripts/figure_compare.py` 做 G7 同色标注比对**（子命令 `single` / `compare` / `from-json`）。详细流程、回退策略、证据标注规范见 `references/国外专利附图获取(Google_Patents_Espacenet).md`。

- **附图/全文获取失败的「可选应对」：用户上传 or SVG 重构降级（v1.1.1 新增交互分支）**：当经 PatSeek / CNIPA 公布公告系统 / Google Patents / Espacenet **任一途径仍无法取得**目标专利或某篇对比文件的**说明书全文或原始附图**时（典型情形：CNIPA 图形验证码阻断、PatSeek `identity_mismatch` 无 `enrichment`、国外文献无全文），**不要静默跳过，也不要不经询问就直接假定重构**——按下列可选分支处理：
  1. **询问用户是否手动上传（默认动作，须显式执行）**：向用户明确说明「未能自动获取 <专利号/名称> 的全文 / 附图，原因：<具体原因，如 CNIPA 验证码 / PatSeek 无 enrichment / 国外无全文>；若你能提供该专利的官方 PDF 或附图图片，我将以你提供的权威版本进行特征比对与附图比对」，并附上该专利的 CNIPA / Google Patents 直达链接方便用户下载。
  2. **若用户上传了正确的全文或附图 → 采用用户件（优先级最高）**：用 `scripts/ingest_upload.py` 规范落地——图片直接复制并重命名；PDF 用 PyMuPDF 提取指定绘图页（图像型 PDF 仍须用 contact sheet 核对绘图页，见 §3.5 避坑）为 PNG；生成 `source:"user_upload"` 的条目直接粘入 `report_data.json` 的 `figure_compare`；比对出处（图号/段落号）以用户件为准。
  3. **若用户选择不上传 → 自动执行「SVG 重构 + data-URI 内嵌」降级工艺**：从已取得的权威**说明书文字**（PatSeek `patent` 文本 / WebFetch Google Patents 全文 / 用户已提供文本）解析各部件与连接关系，用 SVG 框图**忠实重构**该专利的硬件结构 / 控制流程 / 装置框图（重构严禁臆造特征）；将 SVG（及后续取得的官方 PNG）以 **base64 data-URI** 内嵌进 `report_data.json`（可用 `scripts/embed_figures.py` 一键内联本地 `src`），`source` 标注为 `svg_reconstruction`，并在报告第六章与执行日志明确标注「此为基于说明书原文的 SVG 重构，非官方附图，正式提交前建议替换为官方附图」。
  4. **无论走哪条分支，报告必须诚实标注每张附图的来源**（`official` / `user_upload` / `svg_reconstruction`），`make_report_html.py` 已支持附图来源徽标（绿/蓝/橙）自动渲染（见 `references/无效检索分析报告_HTML生成规范.md` 第六章契约）——**这是证据诚实性的硬性要求，重构件绝不可冒充官方附图**。

### 3.4 理由组合策略（核心复杂度所在）
- **主攻 + 辅助佯攻**：选 1 条最有把握的主攻理由（通常新颖性或创造性，证据最硬），再配 1–2 条辅助理由牵制/引出有利事实。
- **避免逻辑冲突**：多项理由的论证前提不能互斥（如同时主张"权利要求不清楚"与"依某清楚含义不具备创造性"需处理好先后）。一次性堆砌证据不足的理由会削弱整体说服力。
- **至少一项成立原则**：组合目标是"确保至少一项理由能够成立"，而非理由越多越好。
- **两难陷阱（高阶）**：针对授权时补入的特征，同时主张"超范围（法33）"与"被对比文件公开（法22.2）"——专利权人承认其一即陷于另一不利（详见 references/无效宣告典型案例.md）。

### 3.5 论证逻辑
- **特征映射比对**：将权利要求逐特征与对比文件做"特征映射表"，逐项标注"公开/实质相同/上位概括/未公开"，**并务必在表中填列每项特征在对比文件中的具体出处（文献段落号/图号/权利要求号等）**——禁止"证据X的另一实施例"式模糊指向（否则合议组对该理由不予考虑，见第七节避坑指南）。
- **附图结合比对与同色标注（v1.0.3 新增 · G7）**：特征比对须**结合涉案专利与对比文件的相应附图**；对**相同的技术特征采用统一彩色标记**（色板见 `references/特征比对与附图标引.md`：散热器=红、压缩机=蓝、送风装置/叶轮=绿、旋转轴线=紫、分隔部/面板=橙、安装面/法线=灰、气流方向=青），在各自附图上以同色引线/色块标注同一特征，生成左右/上下并排的"特征对照图"，相同特征同色呼应，便于直观核查。比对表须增列"附图依据（涉案图号/对比文件图号）"列（与"证据具体出处"列互补）。**v1.0.6 G7 工具化**：附图取自 CNIPA / Google Patents（`scripts/foreign_patent_fetch.py`）后，可用 `scripts/figure_compare.py` 一键自动生成"特征对照图"（左右并排 + 同色叠加 + 色板图例），无需手工 Photoshop 贴色。
- **三步法（创造性）**：确定最接近现有技术→区别特征→实际解决的技术问题→现有技术是否给出结合启示（重点击破"技术启示"与"显而易见性"）。**三步法第③步须过 `references/无效理由体系与论证要点.md` §2.1「技术启示刚性三校验」（问题同源/结构兼容/公知常识证据化），缺一即不能认定显而易见；区别特征体现发明构思核心且无启示、无公知常识证据时，应认定具备创造性（后见之明反向护栏）**。论证链可复用同族 `patent-oa-response`（方向相反使用）。
- **充分公开论证**：从"技术领域、技术问题、技术方案、技术效果"四要素，论证所属领域技术人员依说明书无法实现。
- **支持/清楚论证**：对比权利要求概括与说明书实施例的落差。

### 3.6 程序利用
- **1个月补充窗口**：提出请求起 1 个月内可补充理由和证据；针对专利权人反证的补证、公知常识证据也可在此/口审前补充。
- **口头审理**：准备陈述、质证、技术比对、法律辩论预案；用辅助理由引导专利权人对主攻有利的陈述；**预演专利权人当庭口头提出删除式修改**（(2022)最高法知行终870号裁判要旨：删除式修改可当庭口头提出并被接受）后的文本变化与理由适配。
- **口审新增理由的严格限制（两例外）**：口头审理中拟增加新理由受到严格限制，**仅限两类例外**——① 针对专利权人以合并以外方式（含合并）修改的权利要求，在指定期限内针对修改内容增加理由；② 对明显与证据不对应的理由进行变更。超出 1 个月补充期且不属于上述例外的"当庭突袭"式新理由/新证据组合，合议组一律不予考虑（详见 references/无效宣告程序与证据规则.md 第三节）。
- **行政诉讼联动**：无效决定不利时，3 个月内向北京知识产权法院起诉，在诉讼中强化"技术启示/显而易见性"论证；**2026 指南修改后决定构成可简化，注意从简化说理中定位可诉争点**（见 references/无效宣告程序与证据规则.md 第五节）。

## 四、结构化工作流程（模块化 M0–M11）

> 各模块相对独立，可据任务类型裁剪。如仅做"无效可行性分析"，走 M0–M4 + M10；如要完整请求书，走 M0–M11。

- **M0 任务与目的确认**：明确目标专利号/文本、委托人身份（是否披露/可否第三方名义）、商业目的（全无效/部分无效/谈判）；**确认请求基于纠正不当授权的真实意思表示**（2026 指南 3.2 节：非真实意思表示的请求不予受理/驳回，见 4W120605 案）。
- **M1 目标专利解构**：先用内置 PatSeek 引擎 `patent <公开号>` 抓**目标专利画像**（权利要求全文、说明书、IPC 前4位、申请日、公开日、优先权日、申请人），作为解构与检索锚点；**若目标为 CN 专利且需原始附图/全文 PDF（用于 G7 同色标注与 G2 出处），再经 `scripts/cnipa_epub.py` 从 CNIPA 公布公告系统取官方专利单行本（见 G6 落地）；若仍无法取得（验证码 / PatSeek 无 enrichment），按 §3.3「附图/全文获取失败的『可选应对』」分支处理（优先询问用户上传，不上传则 SVG 重构降级），M11 报告须如实标注每张附图来源（official / user_upload / svg_reconstruction）**；再构建权利要求树，说明书/附图印证，授权档案反悔核查（原始申请 vs 授权文本、审查中承诺）；**为 M11 的 HTML 执行报告保留目标专利与对比文件的附图路径**（附图比对章节所需，详见 `references/无效检索分析报告_HTML生成规范.md`）；**若 ima 已连接，再用 `search_knowledge(knowledge_base_id="7373660469861345")` 在"专利无效决定"库检索同类/同领域专利的既往无效决定，预判本案可能的无效理由组合与证据路径**。
- **M2 法律状态与程序核查**：专利有效性/是否终止、有无在先无效决定（**以相同或者实质相同的理由和证据再次请求的不予受理**——细则70.2 + 指南 2.1/3.3 节，2026-01-01 起标准由"同样"扩为"相同或者实质相同"，检索在先决定时须比对理由与证据是否实质相同）、权属与共有人。
- **M3 证据检索与固定（PatSeek 为主 + 其他途径补全 + 无 Key 离线降级）**：以内置 PatSeek 引擎为外部文献**主引擎**（国内文献走 `bool` 检索式，国外/全球文献走 `semantic` 语义检索；**当 PatSeek 无法获取全文、附图/图形或外国专利文献时，依 G6 启用其他检索途径补全（若所有途径仍不可得，按 §3.3「附图/全文获取失败的『可选应对』」分支处理：用户上传 or SVG 重构降级）**，见 §3.3——**CN 文献优先经 `epub.cnipa.gov.cn`（中国专利公布公告系统）取官方 PDF/附图**，国外文献走 `semantic` 或其他官方途径），按 `references/无效检索策略(PatSeek).md` 执行五步——① `patent` 目标专利画像 → ② 现有技术 Bool 检索（强制 `PD<优先权日`、IPC 限领域、同义扩展，主攻新颖性/创造性）→ ③ 语义补盲（找 Bool 漏掉的隐蔽文献）→ ④ 抵触申请/重复授权同申请人拉网（`AP=(申请人)`）→ ⑤ 证据固定与公开日核验；**创造性检索须同步核查候选证据"实际解决的技术问题"与本案区别特征问题是否同源（校验 A 前置，见 `references/无效理由体系与论证要点.md` §2.1），避免仅因现象相似即拼凑对比文件**。**无 Key 时改用 `scripts/invalidation_search.py --offline` 生成人工检索清单**（CNIPA 公布公告 / 专利检索及分析 / Espacenet / Google Patents 四通道逐步操作，见 §3.3 降级工作流）。**同步在"专利无效决定"库（ID 7373660469861345）用 `search_knowledge` 检索相同/相近专利的无效在先案例，借鉴其证据组合与论证路径（仅可检索决定号/专利号，正文不可经 API 取得，见第八节）**。使用公开/域外证据不靠 PatSeek，仍按 `references/证据组合与证明标准.md` 走公证/固定流程。
- **M4 理由筛选与组合设计**：基于 M1/M3 匹配最适合的无效理由与证据组合，设计"主攻+辅助佯攻"布局，标注逻辑冲突风险；**优先权攻击点须落成"优先权不成立 → 窗口期证据 + 法22.2/22.3"的规范表述**（句式模板见 `references/理由组合策略.md` 三·甲节），不得将"优先权不成立"本身写作独立无效理由。
- **M5 特征映射比对（须结合附图、同色标注）**：逐权利要求 vs 对比文件做特征映射表，定位未公开/实质相同/上位概括特征；**按 G7 结合涉案专利与对比文件附图，对相同特征采用统一彩色标记并生成特征对照图**，比对表增列"附图依据（涉案图号/对比文件图号）"列（与"证据具体出处"列互补）；**附图来源（官方 / 用户上传 / SVG 重构）须与图号一并标注，确保诚实溯源**。
- **M6 各理由论证撰写**：分理由撰写论证（新颖性/创造性/充分公开/清楚/支持/超范围/缺必特/客体/重复授权/外观），每条均"具体说明并结合全部证据"。
- **M7 证据链组织与证明标准**：检查证据链完整性、高度盖然性、形式合法（公证/Apostille/译文）、公开日；撰写证据说明。
- **M8 请求书整合与格式**：按标准结构（请求事项、范围、理由、证据、对比文件对比）整合；附证据目录与特征比对表；**content.json 字段与章节对照见 `references/无效宣告请求书结构.md`**。
- **M9 程序策略建议**：补充期限利用、口头审理预案（含专利权人当庭删除式修改应对）、行政诉讼预案、商业节奏建议。
- **M10 质量自检**：对照第七节清单逐项核验。
- **M11 交付与决定后分析**：输出无效宣告请求书核心内容（.docx）+ 证据清单 + 理由组合建议书；**并强制产出《无效检索执行过程报告》（图文并茂 HTML，固定 7 章结构，由 `scripts/make_report_html.py` 依据 `report_data.json` 生成，见 `references/无效检索分析报告_HTML生成规范.md`）——该报告记录完整执行过程（检索 → 对比文件 → 特征比对 → 理由策略 → 附图比对），结构恒定、便于跨轮次/跨案例对照查看；**第六章附图比对中每张附图须如实标注来源徽标（官方 / 用户上传 / SVG 重构），经 SVG 重构的附图必须注明「非官方、建议替换为官方附图」**；归档。**收到审查决定后**：按"认定事实—证据—理由结论"对应关系核对决定说理（2026 指南修改后决定构成可简化，说理可能更概括——须从简化说理中定位可诉争点，明显缺乏事实认定基础的简化说理可作为行政诉讼攻击点），评估 3 个月起诉期内是否提起行政诉讼。

## 五、输入/输出规范

**输入**：
- 目标专利文本（授权公告文本 + 权利要求书 + 说明书 + 附图），最好含申请-授权档案。
- 委托人商业目的与身份约束（可选）。
- 已有证据线索或对比文件（可选）。
- 输出格式要求（默认 .docx 请求书 + 清单）。

**输出**：
- `无效宣告请求书_核心内容.docx`：标准章节（请求事项、无效范围、理由与证据、技术方案对比、各理由论证、结论）。
- `证据清单与特征比对表`（可并入请求书或单独）。
- `理由组合与策略建议书`：主攻/辅助布局、证据检索方向、程序节奏、风险提示。
- `无效检索执行过程报告.html`（**必产出**）：图文并茂、固定 7 章结构的执行过程报告，由 `scripts/make_report_html.py` 依据 `report_data.json` 生成，便于用户对照查看检索/分析/比对全过程（含目标专利附图与对比文件附图的并排比对）。

## 七、质量检查节点（M10 自检清单）

2. [ ] 每项无效理由均**具体说明**并结合提交的全部证据；每项理由指明所依据证据。

## 八、注意事项

- **方向勿混**：本技能是"第三人无效他人"。若用户实为"我的专利被提无效，要应诉"，应切换为专利权人防守视角（提复审/修改权利要求缩小范围、提交反证），不要用本技能的进攻逻辑直接套。
- **证据日死线**：公开日/使用日早于申请日是硬门槛，检索与固定证据时第一优先核查。
- **不超范围 vs 新颖性两难**：作为请求人可选择同时主张以制造专利权人两难，但需明确主攻方向，避免被牵制。
- **避免理由堆砌**：理由不在多而在精；证据不足的理由会稀释说服力。
- **尊重事实与法律**：所有论证须基于真实证据与法条，不得虚构证据或曲解。无效宣告是严肃的行政确权程序。
- **ima 知识库衔接（检索可用、取正文受限）**：用户 ima"订阅知识库"中确有"专利无效决定"库（库 ID `7373660469861345`，截至 2025-08 含约 20,139 件专利审查决定，含大量 `4W…` 无效宣告决定与 `5W…` 复审决定）。**经本机实测（2026-07-22）：该库全部文档 `can_fetch_content=False`，`fetch_media_content` 对任意决定均返回 220030「该文件获取失败，请至ima内查看处理」——库主「专利律师老徐」仅开放检索、关闭了内容导出。因此库内决定正文无法经 API 取得。** 正确用法：用 `search_knowledge(knowledge_base_id="7373660469861345", query=<理由/技术领域>)` 命中相关决定，取回**真实决定号 + 专利号**作为同源权威锚点（已用于 `references/无效宣告典型案例.md` 各节，第六节"修改超范围"专题即列表 100 件真实 4W 决定）；若确需某件正文，请在 ima 客户端内打开该文档，或依检索到的专利号做公开检索。本技能案例主体为 CNIPA 年度十大案件、最高法指导案例与公开典型案例（真实可溯源），库内决定号仅作锚点增强。
- **同族复用**：创造性论证可复用 `patent-oa-response` 的论证链（方向相反），证据规则与口审策略可参考 `patent-reexamination`。
- **内置 PatSeek 检索引擎（自包含）**：本技能已内嵌 `scripts/patseek_client.py`（bool / patent / semantic 三种模式）及配套参考文档，**无需另行安装 patseek-patent-search 技能即可独立检索**。使用需 PatSeek API Key（环境变量 `PATSEEK_API_KEY` 或 `--api-key`，于 https://patseek.cn 申请），且依赖 Python `requests` 库。**无 Key 时使用 `scripts/invalidation_search.py --offline` 走人工检索清单降级路径（v1.1.0 新增）**。检索式构造务必加 `PD<优先权日` 时间死线，否则结果不可用。检索流程设计见 `references/无效检索策略(PatSeek).md`。**PatSeek 为首选 / 主检索引擎**，国外/全球文献走 `semantic` 语义检索（覆盖 JP/US/EP/KR 等），国内走 `bool` 检索式（`patent` 详情接口目前仅稳定返回 CN）；**当 PatSeek 无法获取全文、附图/图形或外国专利文献时，依 G6 启用其他检索途径补全，本技能不排斥其他合规检索来源**。针对**中国专利**需官方附图/全文 PDF 时，优先经 `epub.cnipa.gov.cn`（中国专利公布公告系统）获取，详见新增 `references/CNIPA公布公告获取(CN全文与附图).md` 与 `scripts/cnipa_epub.py`。
