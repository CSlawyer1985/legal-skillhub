# 无效检索策略（基于内置 PatSeek 引擎）

## 〇、为什么无效检索是"专门的"检索

普通专利检索（查新 / 布局 / 避雷）目标是"找到相关专利即可"，对时间不太敏感。无效检索有本质不同：

1. **胜负取决于证据日**：找出的每篇对比文件，其公开日 / 申请日必须早于目标专利的**申请日（有优先权的，早于优先权日）**。超一天即不可用——这是新颖性 / 创造性 / 使用公开证据的死线。
2. **按理由定向**：不同无效理由需要的证据类型不同（现有技术文献 vs 同一申请人另一件专利 vs 原始申请档案），检索目的随之而变。
3. **证据链闭合**：单篇不够时要组合，且使用公开类证据须达到"高度盖然性"。

本技能已**内置 PatSeek 检索引擎**（`scripts/patseek_client.py`，自包含、随技能安装即可用），提供三种检索能力：

| 模式 | 命令 | 用途 |
|---|---|---|
| 画像 | `patent <公开号>` | 抓目标专利全文本（权要 / 说明书 / IPC / 申请日 / 公开日 / 申请人 / 被引次数）——**检索起点** |
| Bool | `bool "<检索式>"` | 带字段前缀的精确检索（`AP=`申请人 `IPC=`分类 `PID=`公开号 `AN=`申请号 `AD=`申请日 `PD=`公开日 `NOT=`排除）——**现有技术 / 抵触 / 重复主力** |
| 语义 | `semantic "<技术方案>"` | 异步语义检索，补盲"换种说法"的隐蔽文献——**查全补充** |

> 引擎语法细节见 `references/patseek_检索式语法.md`；API / 错误码见 `references/patseek_API参考.md`；同义词扩展对照表见 `references/patseek_关键词扩展.md`。
> 需 PatSeek API Key：`export PATSEEK_API_KEY=ps_你的Key` 或每次 `--api-key ps_你的Key`；无 Key 时的获取方式见引擎文档"无 API Key 时的提示"。
> 依赖 Python `requests` 库（如未安装：`python -m pip install requests`）。

> ⚠️ **检索数据源（v1.0.4 修订 · G6）**：**PatSeek 为首选 / 主检索引擎**，不排斥其他检索途径。国内文献用 `bool` 检索式；**国外 / 全球文献优先用 `semantic` 语义检索**（其索引覆盖 JP/US/EP/KR 等，可返回国外对比文件并给相似度）。注意 `patent` 详情接口目前仅稳定返回 CN——若某文献 `semantic` 命中但 `patent` 取不到全文 / 附图 / 图形，或 PatSeek 无法检索 / 获取某外国专利文献的全文与附图，**应启用其他检索途径**（各国家/地区专利局官方公报、专利数据库门户、其他合规检索工具等）补全；无论经何种途径获取，应尽量取得原始附图与说明书全文，供 G7 同色标注比对与"证据具体出处"使用。涉案专利自认引用的国外文献可直接采用（内容以涉案专利背景技术描述为准），无需另行检索。

## 一、无效检索目标体系（按理由分类 → 检索目的）

| 无效理由 | 检索目的 | 核心检索式要素 | 关键约束 |
|---|---|---|---|
| **法22.2 新颖性** | 找一篇在申请日前**单独公开相同方案**的文献（X 类） | 独立权要全部特征 + 同义扩展 | `PD < 优先权日` |
| **法22.3 创造性** | 找最接近现有技术（Y 类）+ 给出结合启示的文献（可多篇组合） | 区别特征 + 公知常识（教科书 / 标准） | 各篇均 `PD < 优先权日` |
| **法22.2 抵触申请** | 找"同一申请人 / 发明人在先申请、在后公开"的相同发明 | `AP=(申请人)` + 技术关键词 + `AD<目标申请日 PD>目标申请日` | 申请日早于目标、公开日晚于目标 |
| **法9.1 重复授权** | 找同一申请人就相同发明另申请的专利（含分案 / 不同国别 / 同日不同类型） | `AP=(申请人)` + 技术关键词 + 相近年份 | 申请日不同但发明相同 |
| **法26.3 / 26.4** | 通常不需外部检索；如需证"本领域无法实现"可检索通用教科书 / 标准 | 教科书 / 标准（PatSeek 偏专利，覆盖有限，需配合其他来源） | 公知常识证据 |
| **法33** | **不检索**，比对本专利原始申请 vs 授权文本 | — | — |
| **使用公开** | 找优先权日前已售 / 已展出的产品、已发布标准 | 产品名 / 标准号（PatSeek 主要覆盖专利，需配合其他来源） | 公开日 < 优先权日 |

> 关键点：法33 / 法26.3 / 26.4 / 缺必特 / 客体，多数靠"专利自身文本 + 公知常识"，**PatSeek 主要服务新颖性 / 创造性 / 抵触申请 / 重复授权这四条外部文献证据链**。

## 二、五步检索工作流（接入 M3）

### M3a 目标专利画像（必做第一步）
```bash
PATSEEK_API_KEY=ps_xxx python scripts/patseek_client.py patent <目标公开号>
```
产出：权利要求全文、IPC（用前 4 位）、申请日、公开日、优先权日、申请人、被引次数。
→ 把这些信息填入检索计划；**优先权日是所有后续检索的"时间死线"**。

### M3b 现有技术检索（新颖性 / 创造性主攻）
1. 从 M1 权利要求树提取独立权利要求的核心技术特征。
2. 对每个特征做**同义 / 近义 / 中英扩展**（见 `patseek_关键词扩展.md`），每组 `OR` 不超过 8 个。
3. 构造 Bool 式，**强制时间约束 `PD<[优先权日]`**，并用 `IPC=(前4位)` 限领域：
```bash
# 例：目标专利优先权日 2015-03-10，IPC G02B
python scripts/patseek_client.py bool "(光学 OR 光学的 OR optical) (减振 OR 防振 OR 隔振 OR vibration isolation) (测量 OR 检测 OR measurement) IPC=(G02B) PD<20150310" --page-size 30
```
- 命中 < 20 条：放宽（去 IPC 限定 / 扩同义组 / 加语义检索）。
- 命中 > 5000 条：加特征 / 加 IPC / 加 `NOT=` 排除。

### M3c 语义补盲
```bash
python scripts/patseek_client.py semantic "<独立权利要求文字或技术方案概述>" --timeout 180
```
语义检索不受术语限制，专门补 Bool 漏掉的"换种说法"的隐蔽文献；返回约 120 条带相似度，重点关注**高相似度且 `PD<优先权日`** 者。

### M3d 抵触申请 / 重复授权专项（同申请人拉网）
```bash
# 抵触申请：同一申请人、申请日早于目标、公开日晚于目标
python scripts/patseek_client.py bool "AP=(目标申请人) (技术关键词扩展) AD<[目标申请日] PD>[目标申请日]" --page-size 30

# 重复授权：同一申请人、相近年份的相同 / 相似发明
python scripts/patseek_client.py bool "AP=(目标申请人) (技术关键词扩展) AD=[目标年份±2年]" --page-size 30
```

### M3e 证据固定
- 对每条候选对比文件记录：公开号、名称、IPC、申请日、公开日（**必须 < 目标优先权日**）、摘要、权利要求相关段落。
- 截图 / 导出 PatSeek 结果页（含公开日），固定证据来源与时间。
- 形成《证据检索报告》：检索式 + 命中数 + 筛选后对比文件清单 + 公开日核验。

## 三、无效专用 Bool 检索式模板（直接套用）

替换 `<...>` 即可：

1. **现有技术（查准，找 X/Y 类单篇）**
   `(<特征1同义词组>) (<特征2同义词组>) IPC=(<前4位IPC>) PD<[优先权日]`

2. **现有技术（查全，多特征 OR 组合）**
   `(<特征1A OR 特征1B>) (<特征2A OR 特征2B>) PD<[优先权日]`

3. **最接近现有技术 + 区别特征分离检索**
   `(<区别特征同义词组>) IPC=(<IPC>) PD<[优先权日]`

4. **抵触申请**
   `AP=(<申请人>) (<技术关键词>) AD<[目标申请日] PD>[目标申请日]`

5. **重复授权**
   `AP=(<申请人>) (<技术关键词>) AD=[目标年份±2年]`

## 四、与 M1 / M3 的衔接

- **M1 目标专利解构前**，先用 `patent` 画像拿到权要与日期，比 ima 检索更直接；ima"专利无效决定"库仅作"同类案件决定号 / 专利号锚点"（正文不可经 API 取得，见第八节）。
- **M3 证据检索以 PatSeek 为外部文献主引擎**；使用公开 / 域外证据不靠 PatSeek，仍按 `references/证据组合与证明标准.md` 走公证 / 固定流程。
- 也可用脚本 `scripts/invalidation_search.py` 一键生成上述检索式（dry-run）或直接执行（需 API Key）。

## 五、常见错误（务必规避）

- ❌ 忘记加 `PD<[优先权日]` → 结果混入优先权日之后文献，全部不可用。
- ❌ IPC 写 6 位（如 `H01M10`）→ 漏匹配，统一**前 4 位**（`H01M`）。
- ❌ 同义词组 > 8 个 → 噪音大，收缩到语义距离 ≤ 2。
- ❌ 只做 Bool 不做语义 → 漏掉换说法的隐蔽文献。
- ❌ 未固定公开日 → 证据日后被质疑来源与时间。
- ❌ 把法33 / 法26.3 等"靠专利自身"的理由当成外部检索理由 → 浪费检索资源。
