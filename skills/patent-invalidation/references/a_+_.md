# 无效宣告请求书结构（标准章节骨架）

> 依据《专利法》《实施细则》《审查指南》对请求书的形式要求。请求书及其附件一式两份，须明确范围、具体说明理由并结合证据。

## 标准章节
1. **首部**
   - 标题：无效宣告请求书
   - 涉案专利信息：名称、专利号、专利权人、申请日/优先权日、授权公告日
   - 请求人信息：名称/姓名、地址、联系人；代理机构及代理人（附委托书）
2. **请求事项**
   - 明确宣告专利权**全部无效**或**部分无效**（具体到权利要求项）
3. **无效宣告范围**
   - 列明请求宣告无效的权利要求编号（全部/部分）
4. **无效理由与证据概述**
   - 逐条列出无效理由（对应法/条款）+ 所依据证据编号
   - 表明每项理由均具体说明并结合证据
5. **对比文件/证据说明**
   - 证据清单：编号、名称、来源、公开日、类型（文献/使用公开/档案）
   - 各证据与理由的对应关系
6. **技术方案对比（特征映射）**
   - 以表格呈现：涉案专利权利要求特征 ⇄ 对比文件对应特征 ⇄ **证据具体出处（文献段落号/图号/权利要求号）** ⇄ 是否公开/实质相同/上位/未公开 ⇄ 评述结论。
   - 任何"特征被证据公开"的主张，必须指明其在证据中的**具体出处**；禁止"证据X的另一实施例"式模糊指向（否则合议组对该理由不予考虑）。
7. **各无效理由的具体论证**（分节）
   - 7.1 新颖性（法22.2）：单篇实质相同论证 + 特征映射
   - 7.2 创造性（法22.3）：三步法 + 技术启示击破 + 公知常识证据
   - 7.3 充分公开（法26.3）：四要素缺失论证
   - 7.4 清楚性（法26.4/细则20.1，2024版：细则22）：含糊术语论证
   - 7.5 支持（法26.4）：概括与实施例落差
   - 7.6 修改超范围（法33）：原始申请 vs 授权文本比对
   - 7.7 缺必特（细则20.2，2024版：细则23.2）/ 重复授权（法9.1）/ 客体（法5/25）等按需
   - 每条结尾：结合证据小结 + 结论
8. **证据链与证明标准说明**
   - 使用公开类：证据链闭合性、高度盖然性、域外公证认证、译文
9. **结论**
   - 涉案专利不符合授权条件，请求宣告无效
10. **附件目录**
    - 证据复印件、译文、公证认证、特征比对表、委托书

## 撰写要点
- **具体说明**：每项理由须展开论证，不能仅列条款。
- **结合证据**：凡提交证据的，须结合全部证据说明；指明每项理由的证据。
- **特征映射清晰**：表格化比对最利于合议组理解。
- **逻辑分层**：多理由时分层表述，标注主攻/辅助，规避冲突。
- **范围明确**：无效范围与请求事项一致，指向具体权利要求。

## content.json 字段 ↔ 请求书章节对照（v1.1.0 新增 · 填实模式规范）

`scripts/make_invalidation_doc.py --content content.json` 填实模式的 JSON 字段与上述章节一一对应，撰写 JSON 时按下表组织，避免字段名错位：

| content.json 字段 | 对应章节 | 说明 |
|---|---|---|
| `target_patent.name / number / applicant / app_date / grant_date / ipc` | 1. 首部·涉案专利信息 | 专利号填完整 ZL 号 |
| `requester.name / address / agent` | 1. 首部·请求人信息 | 代理机构须与委托书一致 |
| `request_items` | 2. 请求事项 | 全无效/部分无效须与 scope 一致 |
| `request_scope` | 3. 无效宣告范围 | 具体到权利要求编号 |
| `reasons[].name` | 4. 理由概述 + 7.x 分节标题 | 建议格式"创造性(法22.3)"；条款编号按 2024 版细则 |
| `reasons[].main_argument` | 4. 理由概述 / 7.x 主攻论据 | 一句话核心主张 |
| `reasons[].evidence_refs` | 4. 理由-证据对应 / 7.x 依据证据 | 与 evidence_list 的 `no` 对应 |
| `reasons[].analysis` | 7.x 具体分析 | 详细论证（法条+事实+证据+结论） |
| `reasons[].conclusion` | 7.x 结论 | 本理由小结 |
| `evidence_list[].no/name/source/pubdate/type/reasons/form_legality/remark` | 5. 证据清单表 | 公开日须早于申请日/优先权日 |
| `feature_mapping[].claim_feature/compare_feature/type/evidence_ref/remark` | 6. 技术方案对比表 | `evidence_ref` 必须填具体出处（段落号/图号/权项号），禁止模糊指向 |
| `proof_standard` | 8. 证据链与证明标准说明 | 使用公开类写闭合性与高度盖然性 |
| `conclusion` | 9. 结论 | 与 request_items 呼应 |

> 模板模式（不带 `--content`）生成的空骨架中，各待填处以"【标签】+ 提示语"标出，标签名即上表章节要点；填实时标签处被 content.json 的值替换。
