# 案件归档助手 V3 — 安装与升级

## 从 V2 升级

1. 关闭 WorkBuddy。
2. 将原技能目录 `~/.workbuddy/skills/case-archiver/` 复制一份作为备份。
3. 用 V3 技能包替换该技能目录。
4. 不要删除 `~/.workbuddy/case-archiver/`；律所配置、模板路径和缓存都在这里，技能升级不会覆盖它。
5. 重启 WorkBuddy。

V2 的 `field_map.json` 可以继续运行。为避免表格错位，建议逐步把纯 `loc` 坐标迁移为 `marker`、`control_tag` 或 `cell_anchor`，并给暂时保留的坐标增加 `expected_text`。

## 依赖

```powershell
pip install python-docx PyMuPDF pypdf pywin32
```

OCR 按需安装。只有合并卷宗时的 Word→PDF 转换需要 Microsoft Word 和 `pywin32`。

## 第一次接入律所

在 WorkBuddy 中说“运行 case-archiver 接入向导”，或执行：

```powershell
python scripts/onboard.py
```

向导会生成 `~/.workbuddy/case-archiver/firm_config/<firm>/`。正式使用前必须审阅 `field_map.json` 中所有 `review_required=true` 字段。

## 检查 Word 模板

```powershell
python scripts/fill_docx.py "D:\模板\审批表.docx" --out "D:\模板\审批表-检查.json"
```

检查报告会列出真实表格网格、合并后单元格、标记符和内容控件标签。优先在模板中使用 `{{字段名}}`。

## 日常使用

| 你说的话 | 动作 |
|---|---|
| 归档张三诉李四案件 | 整理现有材料并填写表格 |
| 这个案件先归档现有材料 | 缺失项进入待补齐清单 |
| 完卷 / 补齐判决书 | 重新扫描并更新归档状态 |
| 合并卷宗 PDF | 确认后生成带页码和目录的合集 |

## V3 表格改进

- 合并单元格去重，不再把同一合并区识别成多个字段。
- 支持跨 run 的 `{{字段}}` 标记和 Word 内容控件 Tag。
- 支持按标签查找同格、右格或下格，减少坐标漂移。
- 支持选项框 `☒/☐`、多行文本、长度告警和可选自动缩小字体。
- 表格定位失败、标签歧义或写后校验失败时，不覆盖已有输出。
- 详细错误写入 `.归档状态.json` 的 `fill_report`。

## 安全试运行

升级后先用一份脱敏案卷测试：

1. 确认 `fill_report.errors` 为空；
2. 打开或渲染所有生成的 DOCX，检查合并单元格、选项框、长文本换行和字体；
3. 确认待补齐清单与实际材料一致；
4. 未经确认不要合并 PDF。
