# 法律意见书起草

对客户委托事项进行法律调研和分析论证，出具法条有据、结论清晰的法律意见书。**模板统一采用流式函件式**（首部表格+敬启者+两部分结构），不使用多节编号模板（11节式AI味重、不适于人阅读修改）。支持六种类型、四级结论、境内及跨境场景。

| 步骤 | 要点 |
|------|------|
| 1. 确认咨询事项 | 7 项必问（类型/成熟度/出具对象/用途/事实背景/法律问题/意见形式），支持上传文件 |
| 2. 事实梳理 | 区分已核实与假定事实，按时间线或主题组织 |
| 3. 法律调研 | **基座前置｜双源检索（强制，不可跳过）**：执行 `ndr-standards.md` §0（订阅检测）+ §1（双源检索：百宸库 + 互联网各 ≥2 组 + 深度fetch≥2-3件库+2件网）。 |
| 4. 分析论证 | 按「方案/主题」组织分析单元；每条：法条原文直引→事实适用→四级风险判断→结论；工作建议不写入正文 |
| 5. 出具意见书 | 流式函件式模板，调用 `scripts/generate_opinion.py` 生成 Word（含 post-check 一致性校验） |

轻量交付使用 `法律研究备忘录` 技能。

## Phase 1确认咨询事项

如不确定当前场景，参见 `ndr-standards.md` §10 分析类技能择技规则。

逐项确认（不可合并/跳过）

1. **意见书类型**六类（合规咨询/交易支持/争议解决可行性/监管回复/内部风控/专项）
2. **意见成熟度**初步意见（材料不完整）/ 最终意见（材料充分）——是否标注"初步"由律师自行判断，技能模板不预设
3. **出具对象**公司内部参考 / 外部合作方 / 备案呈报
4. **用途**决策参考 / 交易谈判 / 合规论证 / 诉讼仲裁准备
5. **事实背景**当事方、关键时间节点、目前状态、是否涉及境外因素
6. **法律问题**核心法律问题逐一列出；多方案对比时确认**方案命名**（默认"方案一/方案二"，可自定义甲乙/ABC）
7. **意见形式**流式函件式（默认唯一模板，见 Phase 5）；变体：补充法律意见书（第X次修订）、跨境意见书（限定中国法+境外另行委托）

确认后可上传文件或指定知识库。资料清单见 `references/document-checklist.md`。

## Phase 2事实梳理

- **已核实事实**基于文件或明确陈述，标注来源
- **假定事实**基于口述无文件支撑，标注"假定"并提醒核实

按主题聚类，跨境标注法域及关键事实。**敏感/内部细节**（关联方资金往来明细、内部审计发现、参保人数等）默认仅在正文作结论性提示，不展开细节（`ndr-standards.md` §2.7）。完成后请用户确认。

> **依据时效与程序前置（2026-08-31 补引）** 材料提取与依据时效遵循 `ndr-standards.md` §7.8：所涉法规、监管规则**必须**标注发布或最新修订日期与最后核验日；对拟议或历史行为**必须**说明适用行为时法还是评价时法；涉审批/备案/登记/前置许可/第三方同意/优先购买权/内部决议程序的，**必须**先行提示程序前置及未满足后果（未满足即交易不成立/不生效/存在瑕疵）；新旧或层级规则冲突**必须**明确取舍并说明理由，**禁止**并列罗列不作判断。⛔ **NDR 域不存在 §J 章节**（属法官文书公共标准）。

## Phase 4分析论证

**组织粒度**：按「方案/主题」组织分析单元（如"起诉回购分析""协商退出分析"），不以法律问题细分多节；每条分析独立评级（四级，详见 `references/opinion-levels.md`）。

**结论前置式标题**：分析单元标题采用结论式长句（"我们倾向于认为，……"或"提请贵司注意，……"），由结论字段自动生成，禁止问题式短标题。

**每条分析结构**：
1. **法律依据**：法条全称（下称"简称"）+第X条第X款+"条文原文直引"+适用说明（§2.1 条内分款）；案例引用标"入库案例编号XXXX-XX-2-XXX-XXX"+裁判要旨概述（§2.3.5）
2. **事实适用**：Phase 2 事实归入要件
3. **风险判断**：四级（无保留/保留/否定/无法表示），无法确定性判断的发表保留或无法表示意见并说明原因
4. **结论**：标注意见等级

**工作建议分离**：合规补强要点、待办事项等写入 sections 的 `working_notes` 字段，默认**不渲染进正文**；如需呈现，经用户同意并入"特别提示"或另附工作备忘录（`ndr-standards.md` §2.7）。

### 强制纪律（2026-08-31 B1 补强）

1. 引用法条**必须**按 §2.1.1 三态核验并落入「法条锚点」表；⚠️ 状态条文**不得**写入意见书正文；⛔ 状态条文**禁止**作为依据引用。
2. ⛔ **禁止**凭记忆编造条号；**禁止**引用未获官方原文印证的规范性文件；AI 生成条号一经发现**必须**删除并回退重检。
3. 四级结论（可行／附条件可行／存在障碍／不可行）**必须**逐项独立评定，⛔ **不得**相互牵连或整体打包；每项结论**必须**附对应依据。
4. 意见书出具前**必须**核对最新法规版本（含 2024-2025 修订），⛔ **不得**引用已废止条款；发现版本变化**必须**更新锚点表状态。

### 流式函件式模板（默认唯一）

| 模块 | 内容 |
|------|------|
| 标题 | 居中"法律意见书" |
| 保密标注 | 右对齐"保密文件"（可选） |
| 首部表格 | 日期/收件人/发件人/事由（四行两列，`ndr-standards.md` §2.7） |
| 称谓 | "敬启者：" |
| 引言（四段式） | ①感谢+委托背景（内联定义：贵司/我们/相对方/本案）②分析方法声明（"根据贵司提供的材料，我们依据现行有效的法律、法规和司法解释，结合法学理论研究成果、司法裁判案例及实践经验……供贵司参考"）③材料范围与责任边界直接陈述（"本意见基于贵司提供的材料出具，材料不完整可能导致意见调整"——禁用"需要说明的是"式引导语）④服务承诺（如有疑问随时联系） |
| 第一部分 本案主要事实 | 无编号时间线叙事（签约→交割→触发→催告/函件→现状）；敏感细节仅结论性提示 |
| 第二部分 法律分析意见 | 过渡段（客户关注问题：第一/第二/第三）→ 分析单元（结论式标题，每条：法条直引→事实适用→风险判断→结论）→ 多方案时附对比表格 |
| 结论 | "我们的判断是……"综合结论+推荐方案 |
| 声明 | 非决策声明（强制句）+ 出具日/材料日限定 + 用途限制 + "如贵司进一步补充材料，我们将出具补充法律意见书" |
| 附件（可选） | 材料清单、法规案例目录 |
| 落款 | 律所（盖章）/ 律师：XX / 中文大写日期 |

**方案命名**：默认"方案一/方案二"（中文数字），标题/正文/表格/结论全文统一（`ndr-standards.md` §2.6）。

执行 `ndr-standards.md` §3（含生成后一致性校验）。调用 `scripts/generate_opinion.py`。

**补充法律意见书**标题标注"补充法律意见书（第X次修订）"，引言引用原编号及日期。仅分析新增/变化部分，明确与原件不一致以本次为准。版本递增归档。

**跨境/多法域**涉及境外因素时，限定中国法范围、建议境外法域另行委托、引用境外法律意见副本注明来源及依赖限制。

## 写作规范

| # | 规范 | 要求 |
|---|------|------|
| 1 | 法条精确 | 执行 `ndr-standards.md` §2.1（含条内分款"第X款"） |
| 2 | 案例引用 | 人民法院案例库"入库案例编号XXXX-XX-2-XXX-XXX"+裁判要旨概述；裁判文书网完整案号（§2.3.5） |
| 3 | 结论前置 | 分析单元标题用结论式长句（"我们倾向于认为，……"），禁止问题式短标题 |
| 4 | 论证与建议分离 | 工作建议/合规补强要点不写入正文（`ndr-standards.md` §2.7），默认入 working_notes |
| 5 | 方案命名统一 | 默认"方案一/方案二"，全文（标题/正文/表格/结论）一致，禁止混用 |
| 6 | 事实-法律对应 | 每项结论须对应具体事实 |
| 7 | 禁止模糊措辞 | 执行 `ndr-standards.md` §2.2 |
| 8 | 风险表述客观 | 不用"肯定""一定""毫无疑问"，按四级标准表述 |
| 9 | 非决策声明（强制） | 声明**必须**载明"本意见书仅供贵司决策参考，不能代替贵司的决策意见"（浙江律协《律师出具法律意见书指引》第13条强制要求） |
| 10 | 首尾呼应 | 引言受托意识与感谢，结尾服务承诺；开篇和结尾**两处**均出现 |
| 11 | 格式规范 | 中文大写日期；缩略语首次内联定义；弯引号及嵌套单弯引号（`ndr-standards.md` §3） |

> 【2026-08-31 更正·地方性补注】浙江律协《律师出具法律意见书指引》系**地方律协指引（浙江省律师协会发布），非全国性规范，仅作参考；⛔ 不得作为法律依据**；非决策声明系行业惯例性强制要求，具体表述可结合委托场景调整。

> 论证深度分级：按 `ndr-standards.md` §2.6 繁简标准执行（⛔ 禁注水、篇幅与内容匹配）
