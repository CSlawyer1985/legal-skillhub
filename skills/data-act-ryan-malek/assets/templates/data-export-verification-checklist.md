> **起点提示。** 发布前须经合格律师进行实体审查。

## 1. 格式

- [ ] 数据为全面、结构化、常用且机器可读的格式。（示例：JSON、XML、CSV；不含许可限制格式。）
- [ ] 格式有成文说明（模式参考、列定义）。
- [ ] 格式与缔约前通知及任何 DPS 登记册（第26(b)条）中所述的格式一致。

## 2. 完整性

- [ ] 缔约前通知（第3(2)(a) / 3(3)(a)–(b)条）所述的所有产品数据类别均已存在。
- [ ] 解释数据所需的元数据已包含（第4(1)条）。
- [ ] 数量与缔约前通知中的数量估计一致。
- [ ] 相关服务数据在范围内时，相关服务数据类别均已存在。

## 3. 质量

- [ ] 数据看起来与数据持有人可获得时一样准确、完整、可靠、相关且最新。（序言第30段；FAQ Q22a。）
- [ ] 除数据持有人已识别的商业秘密保护类别外，无删减迹象。
- [ ] 排除衍生/推断数据时，该排除与 FAQ Q4 / Q5 一致。

## 4. 及时性

- [ ] 相对请求日期，响应无不当延迟。
- [ ] 如数据持有人主张延迟理由（安全/技术/法律），该理由相称。

## 5. 渠道

- [ ] 渠道安全（传输加密；端点经认证）。
- [ ] 对用户免费（第4(1)条）。

## 6. 商业秘密保护类别的识别

- [ ] 商业秘密保护数据已在元数据中识别（第4(6)条）。
- [ ] 如被扣留，数据持有人已依第4(7)或4(8)条提供书面理由。
- [ ] 如被扣留，已确认通知主管机关。

## 7. 个人数据

- [ ] 适用时包含用户的个人数据。
- [ ] 第三方个人数据（例如员工）的处理符合 GDPR——匿名化、删减，或在用户非数据主体时附带 GDPR 第6条的单独法律依据（序言第7段；FAQ Q25a）。

## 8. 第三方传输（如适用）

- [ ] 如导出是向第三方的第5条传输，第三方的收讫确认已存档。
- [ ] 第三方确认其非被指定的守门人（第5(3)条）。
- [ ] 与第三方之间的商业秘密保密措施已到位（第5(9)条）。

## 9. 使用限制（第4(10)条）

用户确认其不会：

- [ ] 使用数据开发与数据来源联网产品竞争的产品；
- [ ] 将该数据以该意图共享给第三方；或
- [ ] 洞察制造商或数据持有人的经济状况、资产或生产方法。
