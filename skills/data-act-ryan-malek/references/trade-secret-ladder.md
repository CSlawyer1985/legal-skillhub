# 商业秘密三级阶梯

用户请求适用第 4(6) → 4(7) → 4(8) 条；第三方请求适用 5(9) → 5(10) → 5(11) 条。序言 31 设定解释框架。

## 默认立场——采取保护措施披露

序言 31 明确该原则：

> “数据持有者原则上不能仅以某些数据被视为商业秘密为由拒绝本条例项下的数据访问请求，因为这将破坏本条例的预期效果。”

常规路径是采取保密措施披露，而非拒绝。

## 第 1 级——识别与保护（第 4(6)／5(9) 条）

### 操作性要求

- **在披露前识别**商业秘密数据，包括在相关元数据中识别。
- 与用户（或第三方）**约定相称的技术和组织措施**以维护保密性。条例中的示例：示范合同条款、保密协议、严格访问协议、技术标准、行为准则。
- **默认结果：** 在措施到位的情况下披露。

### 实务起草

保密措施协议应：
- 按名称／类别识别每个受商业秘密保护的数据要素。
- 定义允许的用途，包括对衍生品的任何禁止。
- 未经进一步约定，限制继续共享。
- 设定技术控制——加密、访问日志、角色限制。
- 设定组织控制——基于角色的访问、培训、定期审计。
- 指明违规通知和补救义务。

起点模板见 `assets/templates/trade-secret-confidentiality-agreement.md`。

## 第 2 级——扣留或中止（第 4(7)／5(10) 条）

### 触发事由（任一）

- 未就 4(6)／5(9) 条所述措施达成一致。
- 用户未实施约定措施。
- 用户损害商业秘密的保密性。

### 所需行动

- 决定必须**充分论证**并无不当迟延地**书面**提供给用户／第三方。
- **通知依据第 37 条指定的主管机关**，指明：
  - 哪些措施未获一致同意或未获实施；
  - 在相关时，哪些商业秘密的保密性受到了损害。

### 可逆性

第 2 级是可逆的。措施一经同意或实施，共享即恢复。

### 实务起草

“扣留／中止”函应：
- 引用未获同意或遭违反的具体措施。
- 按类别而非个别数据点识别被扣留的商业秘密。
- 说明扣留将持续至措施达成一致或补救完成。
- 包含主管机关通知文号。

模板：`assets/templates/trade-secret-withhold-suspend-letter.md`。

## 第 3 级——例外拒绝（第 4(8)／5(11) 条）

### 门槛

数据持有者必须**证明**：**尽管用户／第三方**依据 4(6)／5(9) 条**已采取技术和组织措施**，其**极有可能**因商业秘密披露而遭受**严重经济损失**。

序言 31 将“严重经济损失”定义为**“严重*且不可弥补*的经济损失。”**门槛很高。

### 论证要求

论证必须**基于客观要素充分说明**，尤其：

- **商业秘密保护在第三国的可执行性**——如拟向非欧盟法域继续披露，该地可执行性薄弱会强化论证。
- **所请求数据的性质与保密程度**——有多敏感、多不公开。
- **互联产品的独特性和新颖性**——越接近产品知识产权核心，权重越大。
- **网络安全影响**（序言 31）——可能削弱产品网络安全的披露可被考虑。

### 所需行动

- **逐案进行。** 绝不跨类别一揽子拒绝。
- **无不当迟延地书面通知用户／第三方。**
- **依据第 37 条通知主管机关。**

### 第 3 级的限制

- 拒绝不取代数据主体的 GDPR 权利（序言 31 末句）。
- 拒绝必须针对所涉特定数据，而非整个请求。
- 用户／第三方可以向主管机关投诉，由主管机关决定共享是否应开始或恢复以及以何种条件进行。

## 决策流程

```
收到请求
   │
   ▼
是否有任何数据要素属于商业秘密？
   │ 否 → 正常披露
   │ 是
   ▼
第 1 级——措施已达成一致并实施？
   │ 是 → 采取保护措施披露（默认结果）
   │ 否／遭违反／被损害
   ▼
第 2 级——书面扣留／中止＋通知主管机关
   │
   ▼
措施仍未达成一致 且 极可能发生严重＋不可弥补经济损失？
   │ 否 → 重新尝试第 1 级
   │ 是
   ▼
第 3 级——逐案书面例外拒绝＋通知主管机关
```

## 拒绝函中的常见缺陷

skill 在其产出的任何拒绝函草案中标记以下问题：

1. 跳过第 1 级——未先尝试约定措施即拒绝。
2. 跳过第 2 级——未先扣留／中止即直接拒绝。
3. 笼统引用“商业秘密”而不识别具体数据要素。
4. 未以客观要素论证“严重且不可弥补的经济损失”。
5. 将 FAQ 视为关于门槛的权威。
6. 未通知主管机关（第 37 条）。
7. 以商业秘密为由拒绝数据主体的 GDPR 访问权（依序言 31 不允许）。
8. 跨类别一揽子拒绝而非逐案进行。
