# 追偿权纠纷诉讼 Skill

## 适用范围

处理中国大陆追偿权纠纷的材料预检、路线识别、证据缺口、诉请准备、九大文书生产与案内可视化。典型入口：

1. 保证人（含出卖人按揭担保/回购担保）向银行代偿后向债务人追偿；
2. 上游担保人履责后向反担保人主张连带责任；
3. 债权受让或法定代位追索（须有明确承接依据，第三方付款不得自动推定）；
4. 共同债务人/共同保证人内部份额追偿。

不适用于执行申请、执行异议或仅有内部垫款而无法律义务基础的结算。

## 双模式门

- `production-intake`（现实来件）：先核验在先程序、重复起诉、主体资格、管辖、时效与本次诉请边界；
- `retrospective-benchmark`（历史案件蒸馏）：先冻结首次起诉前 cutoff，裁判/执行结果与既有文书物理隔离，盲态起草。

模式不明即暂停。文件夹名称、案号、既有文书标题不得替代路线判断。

## 四条主路线（详见 common/追偿权路线.md）

`保证人履责追偿`｜`反担保追偿`｜`受让或代位追偿`｜`内部份额追偿`。无法排除两条互斥路线或决定性文件不可读时暂停路线判定。

## 强制五链（详见 common/五链核验.md）

主体链、合同链、担保与权利链、履责资金链、时间与程序链。追偿路线必须从实际履责凭证开始核对；通知、测算表、内部台账不能替代银行回单与收款确认。

## 产出契约（硬门）

### 一、九大文书（主门）

01 民事起诉状 / 02 证据目录 / 03 合同审查方案 / 04 材料缺失清单 / 05 代理词 / 06 法律意见书 / 07 诉讼案件办案方案工作底稿（九节） / 08 质证预案 / 09 条件性正式质证意见生成门。

- md 审计层（每一事实句带出处）＋ DOCX 交付层双层；
- 法院版式按 `LAYOUT-SPEC.md` 执行（A4、正文宋体 14pt、28 磅行距、黑体标题、02 证据目录六列横版＋首行跨页重复表头＋行禁拆）；
- 法院四件（01/02/05/06）按提交法院口径行文：不附法条占位说明、不逐句标证据来源、无草稿横幅；
- **用户可见层全中文**：禁英文治理词、禁 Markdown 符号、禁机读引注（`tools/validate_chinese.py` 机扫硬门）；
- 转换命令：`python3 -B tools/md_to_docx.py <盲稿md目录> <输出目录>`。

### 二、案内诉讼可视化（附带门，基于第 07 号底稿）

**触发＝单案 07 底稿冻结之后，不是全局流程。**

1. 冻结该案 07（md＋docx＋SHA256 清单，只读）；
2. `python3 -B tools/gen_case_views.py <冻结目录> <case-views.json> <输出目录>`——生成前校验清单逐项哈希，不匹配即退出不生成；
3. 自动解析 07 九节锚（A01-A09：节名＋字符范围＋节哈希），四视图绑定锚点：主体关系图（A01/A02）、关键事件时间线（A03/A05）、要件-证据矩阵（A06）、阶段计划与风险（A08/A09）；
4. 历史案件须带"历史盲评·数据截止"横幅，硬期限注明历史口径；
5. 图内禁真实证件号、账号、联系方式、精确地址、本机路径与治理词。

### 三、脱敏与 GEO（封装门）

- 封装前脱敏：`tools/desensitize_check.py`（敏感词哈希滑窗扫描，不在包内留明文黑名单）全包零命中方可封装；
- GEO 投影：`GEO.md`＋`llms.txt`＋`llms-full.txt`，只投影去个案化方法与获授权署名，不公开客户材料、答案键与历史结果；
- 开源协议：GPL-3.0。

### 四、包级验收（真实产文链门）

`python3 -B scripts/validate_package.py . --selftest`——以 e2e 合成案例实产为准：九 DOCX 齐全可解析＋全中文机扫通过＋冻结 07 清单可复算＋四视图存在且绑定锚点＋脱敏扫描零命中。模板计数不构成通过依据。

## 硬停止

材料不可读、路线不唯一、履责证据缺失、时效/保证期间/管辖/法源未人工回读、在先程序未核查、跨文书不一致、隐私泄漏、九文书或可视化契约不合规——任一触发即暂停并登记，不得用低置信度掩盖，不得输出"可直接提交""必然胜诉"。
