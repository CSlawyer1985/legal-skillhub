# /comments

## 用途

征求意见稿有截止日。是否提交评议意见的决策是律师 / 法务的判断 —— 但 **截止日在没有登记决策的情况下消失**才是风险。本技能呈现开放的评议期并记录决策。

## 读取上下文

`$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/comment-tracker.yaml` → 全部已跟踪的征求意见稿及其状态。
`$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md` → 默认评议决策负责人。

## 默认视图 —— 开放评议期

```markdown
## 评议期台账 —— [日期]

### ⏰ 14 天内截止日

| ID | 监管 | 截止日 | 剩余天数 | 决策 | 负责人 |
|---|---|---|---|---|---|
| CMT-001 | [名] | [日期] | [N] | 未决 | [负责人] |

### 🟡 开放（>14 天）

[同表]

### 最近决定

| ID | 监管 | 决策 | 理由 |
|---|---|---|---|
| CMT-002 | [名] | 不提交 | [原因] |

---

**开放总数**：[N]  **<30 天截止日未决**：[N]
```

## 登记决策

```
regulatory-comments --decide CMT-001
决策：[filing / filing-via-association / not-filing / waived]
理由："[简要 —— 例如'规则不适用我们模式'或'就第 3 条提交评议'）"
```

更新台账。按决策类型走不同后续：

| 决策 | 后续行为 |
|---|---|
| `filing`（直接提交） | 提示评议起草内部截止日（评议截止日 - 5 个工作日内部复核）；触发 `escalation_path.重大业务影响决策` |
| `filing-via-association`（通过协会汇总提交）—— **中国本土化特色** | **必须**追问：(1) 通过哪个协会（如"中支付清算协会"、"中互金协"）；(2) 协会接口人姓名；(3) 协会内部汇总截止日（应早于监管截止日，通常早 7-10 天）；(4) 是否需要参加协会的行业意见汇总会议。填入 `comment-tracker.yaml` 的 `association` / `association_contact` / `association_deadline` / `association_meeting` 字段。然后触发 `escalation_path.重大业务影响决策` |
| `not-filing` | 触发 `escalation_path.首道审核`（理由复核） |
| `waived`（评议期错过） | 触发 `escalation_path.首道审核`（事后追责评估） |

### filing-via-association 详解（中国语境）

中国大公司提交评议意见，相当一部分**不是个体公司直接对监管提**，而是通过**行业协会汇总提交**：

- **中支付清算协会**（pcac.org.cn）：支付清算相关
- **中国互联网金融协会**（nifa.org.cn）：互金 / 消金
- **中国银行业协会**：银行业
- **中国保险行业协会**：保险业
- 其他：按业务领域选

协会汇总提交的好处：
- 立法档案上是"行业意见"而非"某公司意见"，减少直接对企立场曝光
- 协会有专门的法规研究团队，意见质量通常较高
- 多家会员单位联合，影响力更大

后续行为：技能不起草评议正文（律师 / 法务另段活），但**会准备一份"提交协会的内部建议"模板**，含公司就草案具体条款的立场要点。

**注**：本阶段（阶段 2）`filing-via-association` 已启用 ✓。

## 通知

征求意见稿首次检测时（由 `regulatory-reg-feed-watcher`（监管动态监测）登记）：如 DM 通道 MCP（飞书 / 钉钉 / 企业微信）已配置且 `负责人_DM` 已设，按 `regulatory-gap-surfacer`（内规差异呈现）的逐条预审规则发 DM 给评议决策负责人。

截止日 14 天前重发提醒（如决策仍"未决"）。
截止日 3 天前重发（如仍未决，紧急级）。

每次发送**逐条预审**给用户，等明确"发"才发。

## 重大动作确认环节（向监管提交评议 / 回应监管）

**把决策登记为"filing"之前 —— 且总是在产出提交版评议正文或回应监管草稿之前**：读 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md` 的 `## 谁在用这个插件`。

如果角色是**企业法务（无律师证）**或**业务部门人员**：

> 向监管提交评议意见或回应函有法律后果。这是公司立场的公开声明，进入立法档案 / 监管档案。在此处所持立场约束公司，且在后续程序中可能被援引追责。已经与律师 / 法务复核过吗？如果是，继续。如果否，这是带去复核的简报：
>
> - 立法 / 监管事项（监管机关、文号、截止日）
> - 拟评议 / 回应意见在哪些条文、说什么
> - 未决的开放问题
> - 可能出错的事（不利承认、与公司之前立场不一致、与行业协会汇总评议冲突）
> - 应当问律师 / 法务的（是否应提交、是否应通过行业协会联合提交、有哪些立场不应采取）
>
> 找律师 / 法务参见 `regulatory-cold-start-interview`（冷启动访谈）中的引荐资源。

**升级链 / 会签链触发逻辑（v2 字段化版）**：

读 `profile.md` 中 `## 内规差异响应流程 → escalation_path`，按评议决策类型路由：

| 决策类型 | 触发 `escalation_path` 字段 | 额外检查 |
|---|---|---|
| `filing`（直接向监管提交） | `重大业务影响决策` | "本动作进入立法档案。业务规范显示需要 [最终决策角色] 拍板。是否已上报？" |
| `filing-via-association`（通过协会汇总提交） | `重大业务影响决策` + 协会接口检查 | "本动作走协会汇总。业务规范显示需要 [最终决策角色] 拍板，**同时**确认 `comment-tracker.yaml` 中 `association` / `association_contact` / `association_deadline` 三字段是否填写。" |
| `not-filing` / `waived` | `首道审核` | "本动作有法律后果（默认不提交可能被援引追责）。业务规范显示由 [姓名 + 角色] 复核理由。是否已通过？" |

未明确"是"前**不要**登记 `filing` 或 `filing-via-association` 决策、**不要**产出提交版草稿。跟踪视图、截止日提醒**不**需要这个拦截。

**字段缺失时**：如 `escalation_path` 的某节点未配置，降级到通用提示"业务规范该节点未配置，请用 `regulatory-customize`（个性化调整）配置后再继续。"

## 本技能不做的事

- 起草评议信。那是另一段律师工作
- 做提交决策。它跟踪决策；律师 / 法务做决策
- 监控评议后活动。决策一经登记，本台账的工作完成 —— 通过 `regulatory-reg-feed-watcher`（监管动态监测）跟踪立法后续

> `comment-decision` 类型 `gap_type` 语义、逐条预审 DM 确认规则、`comment-tracker.yaml` 结构定义 —— 都在 **`regulatory-gap-surfacer`（内规差异呈现）** 参考技能中。做实质工作前先加载它。
