# stakeholder-comms-planner（利益相关方沟通规划器）

**插件：** LPM Core
**技能编号：** 19 个中的第 9 个
**状态：** v1 已构建——第一阶段测试进行中

---

## 功能

为法律事务设计并维护沟通架构，涵盖四种模式：利益相关方图谱、沟通计划设计、大型项目的汇报层级设计，以及利益相关方格局变化时的事务中期沟通更新。

核心问题：在复杂事务中，沟通结构往往是自然演化而非经过设计的。错误的人收到过多信息，正确的人收到过少信息，而没有人是有意为之。本技能在事务启动时即明确作出设计——利益相关方登记册、汇报流、节奏、层级——并在事务全生命周期内持续维护。

---

## 不做什么

- **状态汇报**——status-report-drafter（技能 1）负责产出报告。本技能设计谁接收报告、以何种频率、以何种格式。两个技能设计为配套使用：stakeholder-comms-planner 用于启动阶段，status-report-drafter 用于每个汇报周期。
- **资源规划**——团队结构和人员配置决策由 resource-planner（技能 10）处理。本技能将团队成员作为利益相关方记录其身份及其需要接收的内容；不设计团队本身。
- **当地法律顾问管理**——LC 沟通节奏和指示格式由 local-counsel-manager（技能 11）处理。本技能将 LC 负责人作为利益相关方纳入沟通计划。

---

## 主要输入场景

1. **新事务启动**——识别所有利益相关方，按影响力和利益分类，分配沟通角色，为内部流和客户面流程设计汇报节奏。

2. **跨法域项目**——构建三层汇报层级（法域 → 区域 → 项目 → 客户），定义升级阈值，并在总部与区域联系问题造成关系损害之前解决它。

3. **利益相关方格局变化**——关键联系人变更、客户重组或新增工作流。在不从头开始的情况下更新沟通计划。

4. **合伙人询问如何构建客户沟通**——设计一种满足客户信息需求、契合合伙人时间安排并减少客户临时沟通的汇报节奏。

---

## 输入

- 事务描述和已知当事方（客户联系人、内部团队、第三方）
- 客户组织结构（客户方谁向谁汇报）
- 汇报偏好与约束（合伙人时间安排、客户汇报窗口、董事会会议日程）
- 事务时间线与阶段结构（如 matter-plan-builder 提供）
- 利益相关方格局变化描述（用于模式 4）

---

## 输出

所有输出默认以 `.docx` 文件形式产出。利益相关方登记册和沟通计划是事务记录——应存放于事务文件夹中。

| 模式 | 主要输出 | 次要输出 |
|---|---|---|
| 模式 1——利益相关方图谱 | 利益相关方登记册 | 供 SharePoint 跟踪的 CSV 导出 |
| 模式 2——沟通计划 | 沟通日程表 + 流程设计 | CSV 导出 |
| 模式 3——汇报层级 | 层级图 + 层级说明 + 升级阈值 | — |
| 模式 4——事务中期更新 | 更新后的利益相关方登记册 + 修订后的沟通计划 | 变更摘要 |

**敏感性说明：** 利益相关方登记册的敏感性信息以及影响力/利益分类是内部分析工具。绝不得出现在面向客户的文件中。

## 设计说明

**权力/利益框架。** 利益相关方按其影响事务结果的能力和对事务进展的关注度分类——而非按资历。一位深度参与日常运营的初级内部联系人，可能比一位已完全授权委托的 C 级高管需要更密集的沟通管理。

**两条流程，分开设计。** 内部汇报（例外管理——哪些事项需要合伙人关注）和面向客户的汇报（受控信心——展示合格的项目进展管理）目的不同、标准不同。最常见的沟通失败是将两者当作同一条流程。

**总部与区域问题。** 在客户方有多个联系人的跨境事务中，冲突的沟通层级会导致不一致的信息到达客户组织的不同部分。本技能在启动时明确点出该问题并给出清晰解决方案：每条汇报流指定一名具名主要联系人，且在任何首份更新发出前与合伙人确认。

**节奏是设计决策。** 正确的汇报频率取决于事务阶段、风险水平、客户偏好和决策密度——而非上一个事务怎么做。本技能在启动时提出这些问题，而非默认套用标准模板。
