# 多端渠道 MVP 要求

产品包含多个端或渠道时使用。小程序只是其中一种渠道，不能替代 App、网站或 SaaS 的披露。

## 通用要求

每个端至少确认：

- 端或渠道名称；
- 该端的核心功能；
- 该端收集的个人信息；
- 第三方 SDK、插件或服务；
- 用户权利入口；
- 协议展示入口。

## 各端关注点

| 端或渠道 | MVP 关注点 |
| --- | --- |
| App | 首次隐私弹窗、系统权限、设备信息、推送、崩溃日志、SDK、注销入口 |
| 网站/H5 | Cookie、网页日志、表单、嵌入组件、统计分析、网页端权利入口 |
| 小程序 | 接口、组件、插件、平台授权路径、企业联系渠道 |
| SaaS | 企业租户、成员账号、协作数据、文件上传、角色权限 |
| 管理端 | 管理员账号、操作日志、客服查询、内容审核、后台访问 |
| 开放平台/SDK | 开发者账号、API key、接口字段、调用日志、宿主产品责任边界 |

## MVP 写法

不必为每个端写长篇专章，但收集清单、第三方清单和用户权利路径中应标明适用端。
