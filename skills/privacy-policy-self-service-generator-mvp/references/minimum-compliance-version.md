# MVP / 最小合规版本

最小合规版本用于产品上线前先形成一份可继续迭代的基础隐私协议。它不是低标准版本，而是用更短正文和必要表格覆盖核心要求。

## 适用场景

- 产品即将上线，需要先形成基础隐私协议。
- 团队已经确认主体、联系方式、产品范围、核心功能、个人信息类型、第三方状态和用户权利路径。
- 既有协议过长、混乱或不贴合产品事实，需要先整理成可审查结构。

## 不适用场景

缺少以下任一事实时，不直接生成：

- 个人信息处理者身份或联系方式；
- 产品范围和适用用户；
- 核心功能及收集的个人信息类型；
- 是否存在第三方 SDK、对外提供、跨境传输；
- 用户权利路径。

产品涉及敏感个人信息、未成年人、AI 训练、自动化决策或跨境传输但事实不清时，也应先列阻断问题。

## MVP 不可省略项

| 项目 | 要求 |
| --- | --- |
| 主体和范围 | 处理者、联系方式、产品范围、适用用户、生效/更新日期 |
| 摘要 | 核心收集、第三方、用户权利、AI/敏感事项 |
| 收集使用 | 功能、信息类型、必要性、目的、方式、保存期限、拒绝影响 |
| 第三方 | 是否存在；存在时列名称/类别、目的、信息类型和触发场景 |
| 安全 | 加密、访问控制、权限管理、日志审计、安全事件处理 |
| 权利 | 查询、复制、更正、删除、撤回、注销、投诉路径 |
| 存储跨境 | 存储地域、保存期限、是否跨境 |
| 更新展示 | 通知方式、长期入口、历史版本 |

## 输出物

- MVP 隐私协议正文；
- 个人信息收集简表；
- 第三方简表；
- 用户权利路径简表；
- 本版忽略或简化内容清单；
- 后续完善事项；
- 复查报告。

## 写作原则

- 只写已确认事实。
- 不留空白占位符。
- 不用“相关信息”等模糊分类。
- 尚未确认的非核心细节，写入后续完善事项。
- 声明“不涉及”时，应说明判断依据。
