# MVP 条款写作要求

用于把清单字段转化为可读的隐私协议正文。保持短、清楚、贴合产品事实。

## 总体规则

- 先写用户最关心的信息，再写细节。
- 能表格化的清单优先表格化。
- 不写产品没有的功能。
- 不用“可能”“相关信息”等泛化表达替代真实字段。
- 未确认事实不写成确定结论。

## 核心章节要求

| 章节 | 写作重点 |
| --- | --- |
| 摘要 | 用短句说明核心收集、第三方、AI/敏感事项、用户权利路径 |
| 收集使用 | 按功能列个人信息类型、目的、必要性、方式、保存期限、拒绝影响 |
| 第三方 | 按第三方单独列示，不把多个 SDK 合并成一句话 |
| 跨境 | 明确是否存在，存在时说明接收方、目的、信息类型、权利路径 |
| 用户权利 | 写清操作路径、响应时限、身份验证和投诉渠道 |
| 更新 | 写清通知方式、长期入口和历史版本入口 |

## 表达底线

- 不用空白横线、占位符或“待填写”。
- 不复制同领域样本原文。
- 不把免责声明混入正式发布正文，除非用户明确要求。
