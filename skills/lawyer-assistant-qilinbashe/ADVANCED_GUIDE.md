# 进阶教程手册（Advanced Guide）

> 面向已熟悉基础用法的用户。每篇教程统一格式：**目标 → 前置条件 → 分步操作 → 示例对话 → 验收标准 → 常见报错**。

---

## 第一篇：案件深度分析系统（要件九步法）

### 目标
基于邹碧华《要件审判九步法》，对接案评估→诉请构建→攻防推演→文书核验→庭审预演→策略复盘全流程进行系统分析。

### 前置条件
- 已有基本案情描述（当事人、时间、金额、核心争议）
- 建议先通过总控路由（31）初步匹配案由

### 分步操作

**第1步：触发深度分析**
```
直接说：「帮我深度分析一下我的案件」
或说：「用要件九步法分析一下这个案子」
```

**第2步：提供案情信息**
AI会引导你补充以下要素：
- 当事人信息（化名）
- 案件时间线
- 核心证据清单
- 争议焦点
- 已采取的维权措施

**第3步：九步法逐层推进**
AI按以下顺序自动分析：
1. 固定权利请求 → 2. 确定权利请求基础规范 → 3. 确定抗辩权基础规范 → 4. 基础规范构成要件分析 → 5. 诉讼主张的检索 → 6. 争点整理 → 7. 要件事实证明 → 8. 事实认定 → 9. 要件归入作出裁判

**第4步：获取交付物**
- 九步法分析报告（含攻防全景图）
- 有利因素与不利因素清单
- 诉讼策略建议
- 证据补强清单

### 示例对话
```
用户：帮我深度分析一下这个民间借贷的案子
  ↓
AI：好的，我用要件审判九步法帮您系统分析。请先说一下基本情况：
    1. 您和对方是什么关系？借款金额是多少？
    2. 有无借条？有无转账记录？
    3. 是否约定了还款日期和利息？
  ↓
用户：朋友借了15万，有借条写的2025年6月借的，约定年底还，到现在没还。有转账记录。
  ↓
AI：开始分析——
    【第一步】固定权利请求：请求返还借款本金15万元及逾期利息
    【第二步】请求权基础：《民法典》第667条（借款合同定义）、第675条（还款期限）
    【第三步】抗辩权预判：对方可能主张已部分还款、超过诉讼时效
    ...（逐层推进后输出完整报告）
```

### 验收标准
- [ ] 输出包含完整的9步分析
- [ ] 每步均有法律依据
- [ ] 包含攻防预判
- [ ] 含证据补强建议

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| AI直接给文书而非系统分析 | 未明确说「深度分析」或「九步法」 | 重新说「用要件九步法分析」 |
| 分析太笼统 | 案情描述不够详细 | 补充具体时间、金额、证据 |
| 跳过部分步骤 | 材料不足以支撑全部分析 | 先走87-案卷精读补充证据矩阵 |

## 第二篇：案卷精读防漏操作

### 目标
对上传的案件材料进行系统性精读，产出「证据清单 + 要件事实-证据矩阵 + 矛盾风险标记」三件套，防止漏读细节、误把单方主张当查明事实。

### 前置条件
- 已有案件材料文件（PDF证据册、庭审笔录、卷宗扫描件等）
- 材料中涉及自然人信息请先脱敏

### 分步操作

**第1步：上传材料并触发精读**
```
上传文件后说：「帮我精读这些案卷材料」
或说：「帮我做案卷防漏检查」
```

**第2步：AI产出三件套**
- **（甲）证据与庭审笔录清单**：编号、名称、来源、关键页、证明目的、三性意见
- **（乙）要件事实-证据矩阵**：纵轴为要件/待证事实，横轴为证据原文摘录、出处、主张方、认定状态
- **（丙）矛盾与风险标记**：双方陈述冲突、金额/时间前后不一等

**第3步：写作闸门**
所有后续文书写作必须以矩阵（乙）为唯一事实来源：
- 标「有争议」的事实，文书中不得写成确定事实
- 严禁把当事人主张直接当查明事实

**第4步：交付核对**
定稿前再跑一次  做二轮校验。

### 验收标准
- [ ] 三件套齐全：证据清单+要件矩阵+风险标记
- [ ] 矩阵中每个事实均有出处页码/行号
- [ ] 风险标记清楚区分「已查明/有争议/待核实」
- [ ] 后续文书与矩阵一致

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| AI未产出矩阵直接写文书 | 未明确说要「精读」 | 说「先做案卷精读三件套，再写文书」 |
| 矩阵中混入了AI推测的事实 | 信息来源标注不清 | 要求AI标注每个事实的出处 |
| 文件上传后AI说打不开 | 格式不支持 | 转成PDF或txt后重新上传 |

## 第三篇：模拟法庭对抗推演

### 目标
开庭前用AI同时模拟原告(代理)、被告(代理)、法官三方，按回合制做对抗推演，提前暴露薄弱争点、预演对方攻势。

### 前置条件
- 已完成案件深度分析（70）或至少已梳理案情确认书+证据矩阵
- 建议先走87-案卷精读建好证据矩阵
- MCP已配置（可选项，不配也有离线降级）

### 分步操作

**第1步：触发模拟法庭**
```
说：「帮我做个模拟法庭对抗推演」
或说：「模拟庭审，我要做三方PK」
```

**第2步：确认前置材料**
AI会检查是否已有6项固化材料：
①案情确认书 ②证据矩阵 ③争点清单 ④请求权基础 ⑤抗辩路径 ⑥裁判规则
缺哪项先补哪项。

**第3步：开始回合制对抗**
按以下顺序进行4回合：
1. **举证质证**：原告举证 → 被告质证 → 被告举证 → 原告质证
2. **法庭辩论**：原告代理意见 → 被告代理意见 → 互相反驳
3. **法官心证**：法官提问双方 → 总结争议焦点
4. **模拟裁判**：模拟判决书 + 裁判理由

**第4步：获取交付物**
- 三方对抗记录（完整对话）
- 攻防清单（我方强项/弱项）
- 证据运用表
- 模拟裁判文书
- 弱点扫描与改进建议

### 验收标准
- [ ] 完成4回合完整对抗
- [ ] 三方均基于材料发言，不空谈
- [ ] 含法条引用和证据锚点
- [ ] 输出弱点扫描报告

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| AI只做单方分析而非三方PK | 未明确说「模拟法庭/三方PK」 | 说「三方对抗，你同时扮演原告、被告、法官」 |
| 对抗不激烈，双方各说各的 | 前置材料不够详细 | 先走70-深度分析和87-精读补充材料 |
| 法条引用不具体 | MCP未配置或不可用 | 配置北大法宝/华宇元典MCP，或使用离线法规库 |

## 第四篇：导出国标Word文书

### 目标
将AI生成的法律文书自动排版为国标格式（A4、仿宋、页边距GB/T 9704-2012），含分节控制、页眉页脚、自动目录。

### 前置条件
- AI已生成文书初稿（起诉状、答辩状、代理词等）
- 内容已审核无误

### 分步操作

**第1步：触发导出**
```
文书生成后说：「导出Word文档」
或说：「帮我排版成正式Word」
```

**第2步：选择排版选项**
AI会询问是否需要：
- 自动目录（多级标题）
- 页眉页脚（案件信息/律所信息）
- 分节控制（起诉状分节、证据清单另起一页）
- 跨页表格修复（标题行重复）

**第3步：下载校验**
AI生成Word文档后，建议人工校验：
- 页边距是否为国标（上3.7/下3.5/左2.8/右2.6）
- 正文是否仿宋三号（16pt）
- 标题是否黑体二号（22pt）
- 行距是否为1.5倍

### 验收标准
- [ ] 文档为国标A4格式
- [ ] 含自动目录（3级以上）
- [ ] 页眉页脚正确
- [ ] 表格跨页重复标题行
- [ ] 字体字号符合国标规范

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| 导出后格式错乱 | 手动复制过内容，破坏了标记 | 从AI输出直接说「导出Word」，不要先复制粘贴 |
| 表格跨页不重复标题 | 未指定 | 说「表格跨页要重复标题行」 |
| 页眉内容不对 | 未指定页眉内容 | 说「页眉写XX律师事务所」 |

## 第五篇：案由竞合检测

### 目标
当用户描述涉及多个法律领域时，自动识别竞合案由并联动对应技能，处理刑民交叉、责任竞合、多领域并行等场景。

### 前置条件
- 用户描述中涉及两个以上法律领域
- 已通过总控路由初步匹配主案由

### 分步操作

**第1步：触发竞合检测**
```
说：「帮我检查一下我的案由对不对」
或说：「我这个案子好像涉及好几个方面」
或直接描述复杂案情（如「被辞退+工伤+公司还欠工资」）
```

**第2步：查看竞合分析**
AI输出：
- 主案由与次案由识别
- 各案由间的法律关系
- 联动建议（先处理哪个、哪个可以合并）
- 竞合风险提示（如刑民交叉可能中止民事审理）

**第3步：按建议推进**
根据竞合分析结果，选择：
- 先处理主案由（进入对应Agent）
- 同时处理多案由（多Agent联动）
- 纠正误匹配（如「不是借贷，是合伙纠纷」）

### 示例
```
用户：公司拖欠工资，我申请劳动仲裁，结果公司说我是合伙人不是员工
  ↓
AI：检测到案由竞合——
    主案由：劳动争议（拖欠工资）
    次案由：合伙协议纠纷（关系定性争议）
    建议：先解决「劳动关系认定」问题（15/17），再推进欠薪仲裁
```

### 验收标准
- [ ] 正确识别主案由和次案由
- [ ] 输出联动建议
- [ ] 含竞合风险提示

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| 只识别了一个案由 | 描述不够清晰 | 补充更多细节，明确涉及多个方面 |
| 案由识别错了 | 口语表达模糊 | 直接纠正「不是XX，是XX」 |
| 未触发竞合检测 | 复杂度不够 | 手动说「帮我做案由竞合检测」 |

## 第六篇：MCP连上后怎么用

### 目标
配置MCP（北大法宝+华宇元典）后，利用双源核验能力进行法条检索、案例查找、法律依据交叉验证。

### 前置条件
- 已完成MCP配置（见 ）
- 确保  和  连接器已连接

### 分步操作

**第1步：确认MCP可用**
```
说：「检查一下MCP连接状态」
AI应返回：北大法宝 ✅ / 华宇元典 ✅
```

**第2步：用法条检索**
```
说：「查一下《民法典》第585条关于违约金的最新规定」
或说：「帮我找一下最高法关于民间借贷利率的最新司法解释」
```

**第3步：做交叉核验**
AI会自动从北大法宝和华宇元典分别检索同一法条或同类案例，并做对比：
- 法条原文是否一致
- 是否有最新修订
- 两地司法实践是否有差异

**第4步：引用到文书**
AI在生成文书时，会自动从MCP获取法条原文，并在引用处标注：
- 「已实时核验 ✅ - pkulaw/yuandian双源一致」
- 「仅单源核验 ⚠️ - 请复核」
- 「离线待核 ❌ - 联网后请核实」

### 验收标准
- [ ] MCP连接状态正常
- [ ] 法条检索返回原文+出处链接
- [ ] 双源核验结果一致或有差异说明
- [ ] 文书中的法条引用标注核验状态

### 常见报错
| 问题 | 原因 | 解决 |
|------|------|------|
| MCP提示未连接 | 未配置或连接器未信任 | 按  配置或在WorkBuddy左侧连接器面板信任 |
| 检索返回空结果 | 关键词太模糊 | 用法条号+关键词精确检索 |
| 双源结果不一致 | 两库更新时点不同 | 以最新版本为准，并在引用中注明 |
| AI不自动调用MCP | 输出降级模式 | 明确说「用MCP核实一下XX法条」 |

## 第七篇：特殊格式文件上传与排障（v4.3.0）

### 目标
处理 Word/Excel/PPT/压缩包/视频/HEIC 等律师高频材料的上传解析，并在环境异常时自助排障。

### 前置条件
-  体检通过（或明确处于「降级」状态并知晓影响范围）
- 依赖按需安装：（Office/HTML/HEIC）；（图片OCR）； 并确保 ffmpeg 可用（音视频）

### 分步操作

**第1步：查看支持格式与缺依赖降级方式**
```bash
python scripts/multimodal_ingest.py --supported
```

**第2步：上传解析（单文件 / 目录 / 压缩包）**
```bash
python scripts/multimodal_ingest.py 材料.docx --out 材料.md
python scripts/multimodal_ingest.py 证据目录 --out 汇总.md
python scripts/multimodal_ingest.py 材料包.zip          # 自动安全解包递归解析
```
- 旧版 .doc / .ppt：先另存为 .docx / .pptx 再上传（脚本会明确提示）；
- 加密压缩包 / 损坏文件 / 超限文件（默认 100MB）：脚本返回结构化错误与替代路径；
- 未知格式：返回支持清单 + 三个可执行建议（转 PDF / 截图上传 / 粘贴文字）。

**第3步：解析结果进入证据链路**
解析出的 Markdown 直接交「87-案卷精读防漏技能」生成要件事实—证据矩阵，或交「39-案件承接与委托」生成《案情确认书》。

### 验收标准
- [ ]  输出 12 类格式矩阵
- [ ]  全绿（零依赖样例必过，依赖样例按环境）
- [ ] docx/xlsx/pptx 上传后能抽取文字与表格
- [ ] zip 解包不越权（zip-slip 防护），临时文件自动清理
- [ ] 缺依赖时提示明确，不假装成功

### 排障速查（doctor / present_panorama）

| 问题 | 原因 | 解决 |
|------|------|------|
| 全景图不显示 / 显示403 | 未发布到工作区，或发布件在隐藏目录 | （自动发布）； 自检自愈；仍失败自动输出纯文本节点树，**无需手动复制文件** |
| 首次使用不知道装什么依赖 | 未体检 |  查看就绪/降级/阻断状态，按需安装（退出码 0/2/1） |
| 上传 docx 提示打不开 | 缺 python-docx | ，或让用户另存为 txt 后上传 |
| 上传图片提示无法识别 | 缺 easyocr | ，或让用户直接粘贴文字 |
| 上传录音/视频提示失败 | 缺 whisper 或 ffmpeg |  + 安装 ffmpeg，或让用户先转文字稿 |
| 文件太大提示超限 | 超过 100MB | 压缩后上传，或  调整上限 |
