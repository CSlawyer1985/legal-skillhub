# 庭审实时辅助系统

> 开庭不打无准备之仗。本工具在庭审进行中，实时把“对方说了什么、法官关注什么、我方下一步该问什么”浮到眼前，让律师把精力放在临场判断上，而不是低头记笔录。

## 一、定位与作用边界

- **定位**：跨案由的“庭审中实时辅助”工具（utility）。与 （庭前/离线深度分析）互补——70 做“战前推演”，本工具做“战中辅助”。
- **触发方式**：用户说“庭审实时辅助 / 开庭实时转写 / 庭审要点浮窗 / 同步转写庭审”等词时由  激活；或律师开庭前/休庭时说“开始实时辅助”主动开启。
- **作用边界**：输出实时转写稿（带说话人标签+时间戳）、要点浮窗记录、庭审速记；**不做**实时裁判预测、**不替代**律师当庭判断与发问、**不出**正式文书。所有要点须律师当庭/休庭后核实。
- **与 108 分工**：108 是“录音证据后处理”（取证后转写+质证），本工具是“庭审进行中实时辅助”（转写的同时实时弹要点）。本工具实时流优先复用 108 的  做离线回退转写。

## 二、两种工作模式

| 模式 | 条件 | 转写方式 | 要点浮窗 |
|:----|:----|:---------|:---------|
| **A·实时流（理想）** | 已配置讯飞 RTASR 凭据（APPID + APISecret，鉴权不用 APIKey） |  WebSocket 流式分句转写 + 说话人分离 | 每句/每段实时弹窗 |
| **B·录音后处理（回退）** | 未配置实时流凭据，或仅有庭审录音文件 | 庭审结束/休庭后上传录音 →  转写（近实时） | 转写完逐段弹窗 |

> **凭据说明（不阻塞）**：讯飞 RTASR 凭据走环境变量  / （或技能配置）。检测到即自动进入模式 A；缺失时明确提示“配置讯飞 RTASR 后启用实时流，当前为录音后处理模式（模式 B）”，并照常提供要点浮窗能力。

## 三、实时转写层（说话人分离）

无论模式 A/B，转写稿统一标注说话人，便于要点浮窗精准归因：

```
[00:02:15] 法官：……
[00:02:40] 原告/公诉人：……
[00:03:10] 被告/辩护人：……
[00:03:35] 证人：……
（模糊/重叠处标注【听不清/多人同时】，方言标注【待核实】）
```

说话人角色在开庭前由律师一次性设定（本案我方=被告/辩护人，对方=原告/公诉人，第三方=证人/鉴定人），后续自动归类。

## 四、要点浮窗层（核心差异化价值）

转写到每一句/段时，实时对照“战前准备”（70 已提炼的争点、97 已萃取的攻防矩阵、105 已生成的发问提纲），弹出以下浮窗卡片：

### 卡片① 争议焦点实时提示
- 当前发言命中哪个预审争点（来自 70 Phase 2 争点清单）
- 该争点当前心证倾向（🟢我方/🟡胶着/🔴对方）

### 卡片② 对方漏洞 / 自认实时标注
- 对方陈述中出现**对己方有利的自认 / 前后矛盾 / 与书面证据不符**时，即时高亮并提示“可当庭固定”
- 模板：

### 卡片③ 法条实时弹窗
- 对方主张 / 法官提问涉及法条时，经  即时核验并弹窗（条号+核心文意+效力状态）
- 标注“✅已核验 / ⚠️待核”，禁止未核验法条进入浮窗

### 卡片④ 下一步发问建议
- 基于 105 发问提纲 + 当前庭审进展，提示“下一轮可问：____（目的：____）”
- 对方证人出现矛盾时，提示交叉询问切入点

### 卡片⑤ 质证即时提示
- 对方当庭出示新证据时，即时提示质证三性角度（真实/合法/关联）+ 是否申请延期质证/鉴定
- 联动  出即时质证意见初稿

## 七、边界与合规

- 转写与浮窗均为辅助，最终以律师当庭判断与法院记录为准；关键内容须核对原始音频/庭审笔录。
- 庭审涉及当事人隐私，转写稿与速记须脱敏（使用“张三/李四”代称，身份证号仅后4位），不得外泄。
- 本工具不替代律师出庭、不承诺结果、不出正式文书；AI 初稿须经主办律师实质审查。
- 实时流仅用于律师本人办案辅助，不得将庭审实时内容违规传播。
