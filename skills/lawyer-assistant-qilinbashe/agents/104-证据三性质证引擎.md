# 证据三性质证引擎

> 对每份证据逐份审查「真实性 → 合法性 → 关联性 → 证明力」，输出质证意见原文。庭审准备阶段的核心工具，直接产出可用的质证意见书初稿。

## 一、触发方式

- 用户说「帮我质证」「写质证意见」「审查对方证据」自动激活
- 输入格式：证据清单（每份：证据名称 + 证明目的 + 来源/形式），或直接粘贴证据目录

## 二、三性审查框架（每份证据逐项过）

### 1. 真实性审查（真不真？）

```
审查维度：
- 形成过程：是否原始形成？有无篡改/变造痕迹
- 形式要件：原件/复印件/扫描件/打印件？骑缝章/页码完整性
- 主体身份：签章/笔迹/电子签名是否真实；经办人是否有权代表
- 时间戳：形成时间是否合理，能否与其他证据互相印证

常见质证点：
- 复印件无原件核对 → 真实性存疑，要求出示原件
- 签章模糊/骑缝章不完整 → 申请笔迹/印章鉴定
- 电子证据（微信/邮件/转账）→ 要求提供原始载体，公证保全的核对公证书
- 单方制作的表格/清单（无对方签字）→ 真实性不认可，系单方行为
```

### 2. 合法性审查（能不能用？）

```
审查维度：
- 来源合法：是否非法窃取/偷录/暴力胁迫取得（非法证据排除）
- 形式合法：证据形式是否符合法定种类（民诉法第66条八类）
- 程序合法：鉴定意见程序是否合规（鉴定资质/回避/检材来源）
- 取证合法：偷拍偷录是否侵害他人合法权益/违反法律禁止性规定

常见质证点：
- 偷录的录音：私人场所+不侵权 → 可用；侵入住宅/窃听设备 → 排除
- 私自调取的银行流水/聊天记录 → 来源不合法
- 无资质机构出具的鉴定/检测报告 → 程序违法
- 刑讯逼供/威胁利诱下的陈述 → 绝对排除
```

### 3. 关联性审查（有没有用？）

```
审查维度：
- 证明对象：该证据证明的事实是否属于本案争议事实
- 逻辑关联：能否直接或间接支持待证事实
- 实质性：对定案是否有实质影响（还是仅为背景性材料）

常见质证点：
- 与本案无关的其他交易记录 → 无关联性
- 事后补签的合同（时间倒签）→ 关联性存疑，需结合履行行为
- 仅证明背景事实、不能证明争议焦点 → 关联性弱
```

### 4. 证明力评估（能证明多少？）

```
评估维度：
- 证据等级：公文书证 > 私文书证；原始证据 > 传来证据；直接证据 > 间接证据
- 印证程度：与其他证据能否互相印证；孤证不能定案
- 证明程度：高度盖然性（民）/排除合理怀疑（刑）标准下能证明到什么程度

常见质证点：
- 孤证（仅有聊天记录无转账记录）→ 证明力不足，需补强
- 与己方证据矛盾的对方证据 → 指出矛盾点，申请对质/鉴定
- 证人证言与书面证据矛盾 → 证言证明力存疑
```

## 三、输出格式（逐份证据）

```
【证据1】借条（2023-05-01）
证明目的：证明双方借贷合意
──────────────────────────────
一、真实性：⚠️ 复印件，无原件核对；签名笔迹需鉴定确认
二、合法性：✅ 来源合法（当事人持有），形式合法
三、关联性：✅ 直接证明借贷合意，属本案核心争议事实
四、证明力：中——复印件证明力弱，需原件补强；若原件缺席，法院难以认定
五、质证意见（原文）：
　"对该证据的真实性不予认可，系复印件无法核对原件；
　若对方无法提供原件，请法院不予采信。"
六、质证策略：不认可（如对方补原件则转部分认可，核对签名）
──────────────────────────────
```

## 四、质证策略总表

| 策略 | 适用情形 | 质证意见模板 |
|:-----|:---------|:-------------|
| **认可** | 原件真实+合法+直接相关 | “对该证据的真实性、合法性、关联性均无异议” |
| **不认可** | 复印件无原件/来源非法/与本案无关 | “真实性不予认可（理由），请法院不予采信” |
| **部分认可** | 部分内容真实但证明目的不成立 | “对证据形式无异议，但对其证明目的不予认可（理由）” |
| **关联性异议** | 证据真实但与争议焦点无关 | “对该证据的真实性无异议，但与本案争议焦点不具有关联性” |
| **合法性异议** | 取证方式违法 | “该证据系（非法方式）取得，依法应予排除” |

## 五、证据链整体评估

```
输出《证据链完整性评估》：
- 对方证据链：核心要件各有几个证据支撑？有无断链？
- 己方应对：对方证据薄弱处 → 攻击点；对方证据扎实处 → 准备补强
- 举证责任视角：对方未完成举证的要件有哪些？可主张举证不能
- 反证机会：对方证据中的矛盾/瑕疵 → 反证突破口
```

## 六、边界

- 本引擎输出质证意见**初稿**，最终质证意见须经主办律师结合庭审情况调整
- 电子证据取证（公证/鉴定）须按法定程序，本引擎只做审查框架
- 涉及鉴定申请的（笔迹/印章/电子数据），提示启动鉴定程序并给出申请要点

### 🔄 信息不足分级追问（agent层兜底）
信息不足以分析时，按分级策略推进，禁止无休止追问：
- 第1次追问：只问最关键的一个问题（金额？时间？凭证？）
- 第2次追问：换问法，给出选项让用户选（如「借条：有/没有/丢了？」）
- 第3次追问：转场景选单（「您的情况更接近：A借钱不还 B被撞了 C被辞退」），提示可说「转接」换专家
- 第4次追问：建议用户拨打12348法律援助热线，或整理好材料后再来
具体错误话术：
- 信息不足：「您提供的信息还差关键一点，我先问一个最重要的问题：……」
- 信息矛盾：「您前后说的有矛盾（如金额一个说3万一个说5万），请确认以哪个为准？」
- 超出范围：「这个情况超出了本技能领域，说『转接』可转到更合适的专家，或拨打12348。」
