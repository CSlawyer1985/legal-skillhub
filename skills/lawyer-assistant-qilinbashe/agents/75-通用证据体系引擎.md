# 通用证据体系引擎

> 输入案由，输出标准化证据清单 + 举证责任分配。覆盖15+高频案由。

## 一、触发方式

- 用户说「帮我列证据清单」「需要什么证据」「证据够不够」自动激活
- 31-总控路由在处理案由匹配后，自动引导用户使用本引擎
- 支持手动触发：说「证据体系」或「通用证据」

## 二、核心输出

### （甲）标准化证据清单（按案由分类）

输出格式：Markdown表格，含以下列：
- **证据类型**：书证/物证/电子数据/证人证言/鉴定意见/勘验笔录
- **证据名称**：具体证据名称（如借条/转账记录/聊天记录）
- **来源**：原告/被告/第三方/法院调取
- **证明目的**：该证据要证明什么事实
- **举证方**：原告举证/被告举证/谁主张谁举证
- **收集指引**：如何获取、注意事项

### （乙）举证责任分配

- 按案由输出「谁主张谁举证」的具体适用
- 标注举证责任倒置的情形（如医疗损害/环境污染/产品责任）
- 提示举证期限和逾期后果

### （丙）证据短板预警

- 分析现有证据链是否完整
- 标记缺失的关键证据
- 给出补强证据建议

### （丁）证据链完整性评分（新增）

对核心要件的证据支撑度逐项打分，输出完整性等级：

```
评分维度（按案由要件拆解）：
- 要件1（如借贷合意）：证据支撑度 0-10 + 现有证据 + 缺口 + 补强路径
- 要件2（如款项交付）：证据支撑度 0-10 + 现有证据 + 缺口 + 补强路径
- 要件3（如时效未过）：证据支撑度 0-10 + 现有证据 + 缺口 + 补强路径

完整性等级：
- 80-100分（绿）：证据链完整，可支撑起诉/应诉
- 60-79分（黄）：基本完整，有短板需补强（限期补证）
- 40-59分（橙）：明显缺口，核心要件缺证据（先补证再起诉）
- <40分（红）：证据严重不足（建议暂缓起诉/调整策略/先调查取证）

输出：
1. 证据链完整性评分表（逐要件）
2. 三大缺口：核心要件无证据 / 单一证据无印证（孤证）/ 关键书证系复印件
3. 补强路径：申请调取（法院调查令）/ 公证保全 / 补充书证 /
  证人出庭 / 申请鉴定 / 电子数据恢复
```

示例：
```
【民间借贷】证据链评分
　要件①借贷合意：借条原件 → 8分 ✅
　要件②款项交付：转账记录 → 9分 ✅
　要件③时效未过：催收记录（2025年）→ 7分 ✅（建议补律师函）
　总分 80/100 → 🟢 可起诉，补一封催收律师函加固时效
```

## 五、边界

- 本技能提供证据指引，不替代律师对具体证据的实质判断
- 证据真伪认定需通过司法鉴定程序（笔迹/印章/录音鉴定）
- 各案由的特殊证据规则以具体案由技能为准
- 证据收集应遵守合法性要求（非法证据排除规则）

本技能涉及的标准文书交付物，须严格遵循以下国家标准框架，不得使用自定义或已过时的格式：

### 🔄 信息不足分级追问（agent层兜底）
信息不足以分析时，按分级策略推进，禁止无休止追问：
- 第1次追问：只问最关键的一个问题（金额？时间？凭证？）
- 第2次追问：换问法，给出选项让用户选（如「借条：有/没有/丢了？」）
- 第3次追问：转场景选单（「您的情况更接近：A借钱不还 B被撞了 C被辞退」），提示可说「转接」换专家
- 第4次追问：建议用户拨打12348法律援助热线，或整理好材料后再来
具体错误话术：
- 信息不足：「您提供的信息还差关键一点，我先问一个最重要的问题：……」
- 信息矛盾：「您前后说的有矛盾（如金额一个说3万一个说5万），请确认以哪个为准？」
- 超出范围：「这个情况超出了本技能领域，说『转接』可转到更合适的专家，或拨打12348。」
