# 保密义务的标准例外（除外情形）

大多数可运作的 NDA 都包含清晰的例外。例外缺失或不可运作是常见的谈判驱动因素。

## 目录
- 五个标准除外情形
- 建议条款
- 举证责任
- 被迫披露除外情形
- 残余记忆（Residuals）不是例外
- 个人数据与监管披露

## 1) 五个标准除外情形

| 例外 | 含义 | 常见起草陷阱 |
|---|---|---|
| 公共领域 | 非因接收方过错而已公开 | “公开”定义过窄 |
| 先前知悉 | 接收方在披露前已知悉 | 要求不切实际的证明 |
| 第三方权利 | 接收方无限制地从第三方获得 | 假设第三方有权利 |
| 独立开发 | 接收方未使用披露方信息而开发 | 无证据标准 |
| 被迫披露 | 法律/监管机关/法院要求 | 通知期限过严 |

## 2) 建议条款（平衡式）

```
保密信息不包括接收方能够证明的以下信息：(a) 非因违反本协议而已公开或成为公开；(b) 在披露前已合法知悉；(c) 无违反任何保密义务而从第三方合法获得；或 (d) 由接收方在不使用或不参考保密信息的情况下独立开发。
```

## 3) 举证责任

### 应检查什么
- 谁必须“证明”一项例外？

### 平衡方式
- “接收方能够证明”是典型表述。
- 除非必要，避免“仅限同期书面记录”。

**接收方友好微调**
```
接收方可使用合理证据证明例外，该等证据可（在适当时）包括文档、系统记录或可信证言。
```

## 4) 被迫披露除外情形

**建议语言**
```
如接收方因法律、法规或法院命令须披露保密信息，接收方仅可披露法律要求的部分，并将在法律允许的范围内及时通知披露方，并合理配合寻求保护性处理。
```

## 5) 残余记忆（Residuals）不是“例外”

残余记忆条款通常通过允许使用保留的信息而起到类似例外的作用。将其视为独立条款（见 KEY_CLAUSES.md）。

## 6) 个人数据与监管披露

如涉及个人数据，当事人有时试图将隐私合规视为保密义务的“例外”。

### 实务指引
- 保密与隐私可以共存。
- 确保 NDA 不妨碍强制通知或合规。

> **雇佣/承包方变体：** 在雇佣情境中除外情形可能被收窄；确保实用性并遵守工作场所义务。
