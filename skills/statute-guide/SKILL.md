# 法条解释指南（美国法律）

一个结构化的第一轮框架，用于阅读**美国**法规、规章、条例和规则——联邦、州（全部 50 个州 + 哥伦比亚特区 + 美国领土）和地方（县 / 市）。Claude 组织分析；具名律师拥有每一项法律结论。

本技能不处理非美国法律（欧盟、英国、加拿大、外国法域、国际条约）。如用户的案件涉及外国法律，停止并转交给在该法域合格的律师。

---

## 受众

进行**第一轮**法条审查的初级律师、合规分析师和律师助理。所有输出在任何面向客户、监管或交易使用之前均需律师审查。本技能不面向寻求法律意见的自我代理用户——"组织分析"与"提供意见"之间的防火墙存在，是因为误读法条文本对真实的人有真实后果，而具名律师是唯一有资格承担该风险的人。

---

## 工作形态

**渐进式判断（Accretive Judgment）。** Claude 组织法律判断的输入——定义、操作词、适用性门槛、交叉引用、要求分类、显著缺失。律师拥有法律结论、引注核验和歧义解决。这不是有界交易式工作（无封闭式正确答案），也不是模式匹配审查（无与已知良好状态的模板匹配）。

---

## 何时使用本技能

当用户要求对以下内容进行第一轮组织时使用：
- 如何阅读和解释特定的法规、规章或规则
- 法条解释方法和解释准则
- 立法意图提取
- 从法条文本中提取要求
- 适用性 / 门槛分析
- 跨法域合规范围界定

---

## 超出范围

本技能**不**执行：
- **任何类型的非美国法律**——欧盟条例（GDPR、DSA、AI 法案）、英国法规、加拿大 / 澳大利亚 / 新加坡 / 其他外国法律，或国际条约。本框架的解释学说（联邦优先、机关遵从、从宽解释规则）是美国特定的，不可移植。
- 判例法解释、综合或先例分析
- 美国宪法解释（联邦或州宪法）
- 条约解释
- 机关裁决或规则制定意见起草
- 美国法域之间的法律选择争议（例如，多州交易适用哪个州的法律）
- 起草法规、规章或条例文本
- 游说或立法策略分析
- 最终法律意见、客户备忘录、状纸或申报文件

如请求落入上述任何一类，停止并转交合格律师，而非尝试第一轮——这些领域有其自身的证据、学说和程序要求，法条文本框架无法满足。具体涉及外国法律的事项，转交在该法域合格的律师。

## 输入要求

在开始第 1 步之前，确认以下**全部**要素都存在。如有缺失，**停止并询问**——不要推断，不要基于部分信息继续。原因：猜测法域产生的分析读起来自信却适用了错误的法律，而错误法域的分析在后续环节比"请给我引注"这种问题更难被发现。

| 必需输入 | 必须包含的内容 |
|---|---|
| 法条引注 | 法域 + 条文编号（例如，"Cal. Civ. Code § 1798.100"；"42 U.S.C. § 1320d-2"；"Chicago Municipal Code § 4-4-005"） |
| 全文或权威链接 | 合并/法典化版本，而非摘要 |
| 法域层级 | **联邦**、**州**（哪个州——全部 50 个州 + 哥伦比亚特区 + 领土），或**地方**（哪个县 / 市 / 市镇，外加所在州）——明示，而非推断 |
| 版本 / 生效日期 | 被分析的是法规的哪个版本 |
| 陈述的目的 | 合规范围界定、要件提取、豁免检查或其他 |

**停止并询问规则：** 如用户只提供引注而无文本、只有文本而无引注，或法域含糊（例如，"隐私法"而未指明州），停止并请求缺失要素。不要从上下文线索推断法域；不要基于部分引注继续。

**非美国标记：** 如引注、文本或语境表明是非美国来源（例如，"Regulation (EU) 2016/679"、"Data Protection Act 2018"、"PIPEDA"、外国判例汇编），停止并拒绝——本技能仅涵盖美国法律。建议咨询在该法域合格的律师。

## 委托门槛与问责

Claude 产出**草稿分析**，绝不出最终结论。每份输出必须：

1. 携带页眉：`草稿——需律师审查 | 审查律师：<姓名> | 特权状态：<状态>`
2. 点名审查律师（或携带一个用户必须填写的明确 `<审查律师：___>` 占位符）
3. 重申**引注核验、现行法条文本的确认、歧义解决和最终法律结论仍是律师的责任**

无置信度区间的结论性动词会造成律师从未签署过的最终法律结论的外观——为每个结论打上区间标签，或将其降级为给律师的开放问题。诸如"强制义务"、"由 X 机关执行"或"这适用于您的委托人"之类的平铺直叙表述，正是本节存在所要防止的失败模式。

---

## 置信度区间

输出中的每项实质性发现都标注 **高 / 中 / 低**：

| 区间 | 何时 |
|---|---|
| **高** | 文本无歧义；定义自足；无争议的机关解释；无未解决的交叉引用 |
| **中** | 交叉引用已解决但需核验；轻微定义缺口；机关指引与文本一致 |
| **低** | 未定义术语；有争议的条款；机关解释偏离文本；实施规章中判例分裂；生效日期不确定 |

对含糊条款，平置信度输出不可接受。在区间之间犹豫时，降级——信心不足的发现的负面影响（律师多花几分钟核验）远小于过度自信的发现的负面影响（律师相信了一个实际上不稳固的发现）。

## 升级逻辑（停止并转交）

发生以下**任一**情形时，停止分析并上报给具名律师。升级是强制的；它压过完成分析的本能，因为"无论如何完成"正是摇摇欲坠的解读变成"分析是这么说的"的方式。

1. 条款对用户的事实模式保持沉默
2. 两条条款冲突——法规内部或与实施规章冲突
3. 法域不明确、案件涉及美国各州之间的法律选择，或出现非美国来源
4. 法规引用了由判例法而非法规定义的概念
5. 生效日期或版本不确定，或有待决修正案
6. 出现美国宪法问题（联邦或州）、条约问题或联邦/州/地方优先问题
7. 分析将需要解释机关裁决
8. 地方条例看似与州法冲突，或州法规看似与联邦法冲突

升级时，说明哪个触发器被触发以及需要律师做什么。

## 失败模式

| 模式 | 发生原因 | 防护 |
|---|---|---|
| **意见与支持漂移** | 自信、结构化的草稿读起来像意见；读者不再注意免责声明 | 每份输出都带草稿标签 + 委托门槛部分 |
| **特权泄露** | 合规分析被粘贴进电子邮件或共享文件而未加特权框架，使客户通讯暴露于证据开示 | 如分析触及客户案件，标记"律师工作成果——特权且保密"，并在共享前确认分发范围 |
| **问责缺口** | 输出因无人被点名作所有者而被当作最终结论消费 | 具名律师要求；结论性动词配置信度区间 |
| **引注过时** | 法规会修正；六个月前的分析可能适用已被废止的文本 | 输入要求中的版本日期；置信度区间警示注明所分析的版本 |
| **法域不匹配（美国内部）** | 一个州的框架模式被误用于另一个州；联邦法假设被带入州法分析；在迪隆规则（Dillon's Rule）州作出地方自治假设 | 输入要求中确认法域层级（联邦 / 州 / 地方）；每次分析声明一个法域；优先问题标记交由律师 |
| **范围外的外国法律** | 用户粘贴欧盟 / 英国 / 外国文本而未说明；框架的美国特定准则（优先、机关遵从、从宽解释）被适用于它们不存在于其中的法律 | 输入要求中的非美国标记；停止并拒绝，而非尝试 |

## 理解法律层级

| 类型 | 由谁制定 | 特征 |
|------|------------|-----------------|
| **法规（Statute）** | 立法机关 | 正式制定；命令、禁止或宣示政策；提供框架 |
| **规章（Regulation）** | 政府机关 | 实施法规；具有法律效力；通常更具操作性细节 |
| **规则（Rule）** | 机关或法院 | 行政规则（=规章）或程序要求 |

**关键洞见：** 法规赋予机关制定规章的权力。始终同时阅读法规**和**实施规章——规章通常包含法规留给机关裁量的操作性细节。

## 阅读之前：预备步骤

### 1. 核验时效与状态
- [ ] 生效日期（可能在将来）
- [ ] 待决修正案
- [ ] 已找到合并/法典化版本
- [ ] 已识别实施规章
- [ ] 已检查解释该法规的法院判决
- [ ] 已记录不同条款的不同生效日期

已通过的法规往往不是被实施的法规——具有未来生效日期的法规可能在生效前被修正。

### 2. 了解监管生态
- [ ] 已识别执法机关
- [ ] 已检查机关的执法历史
- [ ] 已收集指引文件、常见问题、非正式解释
- [ ] 已记录机关姿态（积极 / 放任）

相同的法定语言可能因由谁执行而含义不同。

### 3. 先浏览结构
在深入特定条文之前，先浏览索引或目录。理解问题在更大整体中的位置，可防止当某条款依赖别处的定义或适用性部分时，将其误读为独立条款。

对不熟悉的法规或法典，参见 `references/statutory_structure.md`——在首次浏览从未见过的法规时阅读。

## 阅读法规：核心技术

### 从定义开始

**每个词都有含义。** 先找到定义部分并持续引用它。

- 术语可能具有不同于日常用法的特定法定含义
- 定义可能通过引用纳入外部标准
- 定义可能依赖其他定义（相互关联的网络）
- 注意定义是穷尽性的（"指/means"）还是示例性的（"包括/includes"）

在分析实质性条款之前，先建立关键定义参考表。

### 缓慢仔细地阅读

法规密集。每个词和标点都有含义。每句话读多遍；将复杂句子解析为组成部分；不要略读。法定语言奖励细心阅读，并因略读而以自信的误读惩罚之。

### 操作词

这些词在各类法规中具有一致的法律功能：

| 词 | 含义 |
|------|---------|
| **Shall（应）** | 强制性——必须 |
| **May（可以）** | 许可性——允许 |
| **And（且）** | 连接性——全部要素都必须满足 |
| **Or（或）** | 选言性——任一要素即足够 |
| **Unless / Except（除非 / 除……外）** | 表明一般规则的例外 |
| **Subject to（以……为准）** | 受另一条文的限制 |
| **Notwithstanding（尽管）** | 无视其他条文而适用 |
| **If...then / Upon / Provided that（如……则 / 在……时 / 但条件为）** | 必须先满足前提条件 |
| **Means（指）** | 其后为穷尽性定义 |
| **Includes（包括）** | 其后为例示（可能非穷尽） |

将"and"误读为"or"或将"shall"误读为"may"会从根本上改变条款的含义——这些是低置信度发现的头号来源，也是通过缓慢阅读最容易避免的错误。

### 跟踪交叉引用

遇到引用另一法规或条文时，停下来阅读它。交叉引用可能扩展、限制或修改被分析的条款。构建各条文之间如何关联的地图。

## 法条解释工具

当语言含糊时，使用以下既定的解释工具。含糊本身是升级信号——即使在应用工具时也为律师标记。

### A. 文本本身
- **平义含义：** 如清晰无歧义，无需进一步探究
- **词典定义：** 比较多部词典寻求共识；技术术语使用法律词典

### B. 解释准则（摘要——深度见参考资料）

**文本准则**（按文本自身的措辞阅读）：
- 一般术语准则——无限制时一般术语具有充分射程
- 反面推定（Expressio Unius）——列举一事意味着排除他事
- 整体法案规则——将文本解释为一个连贯整体
- 一致用法——同一词、同一含义
- 有意义的变化——不同术语意味着不同含义
- 反对赘余——每个词都应有含义
- 同类相知（Noscitur a Sociis）——词语成组时互相提供信息
- 同类规则（Ejusdem Generis）——特定词后的一般词限于同一类别

**目的准则**（结合其目标阅读文本）：
- 反对无效推定、避免荒谬、补救性法规、从宽解释规则

完整的准则定义及案例示例，**在解释含糊的法定语言或解决定义缺口时，阅读 `references/canons_of_construction.md`**。

### C. 法律解释
- **判例法**——超出本技能范围（为律师标记）
- **机关规章**——法院给予遵从；阅读实施规章
- **机关指引**——常见问题、指引文件、执法行动
- **立法历史**——委员会报告、全体辩论、提案人声明

### D. 目的与语境
序言/目的条款、立法发现部分和结构语境往往比操作性条款更清晰地陈述立法意图。

## 区分要求类型

| 类型 | 示例 | 实施团队 |
|------|----------|----------------------|
| **披露** | 隐私通知、警告标签、条款 | 法律/政策 |
| **运营** | 回应期限、内部流程 | 合规 |
| **技术** | 系统要求、安全标准 | 工程 |
| **界面/设计** | 链接位置、字体大小、按钮设计 | 产品/设计 |

区分这些很重要：一份"隐私政策要求"检查清单不应包含从未出现在政策本身中的运营期限。将**必须披露什么**与**业务必须如何运作**分开。

## 处理豁免

- **实体豁免：** 整个组织豁免
- **数据豁免：** 仅某些数据类型豁免；对非豁免数据须合规
- **联邦优先：** 州法规常让位于特定行业的联邦法律（HIPAA、GLBA、FCRA、FERPA）。优先问题是升级触发器。
- **延迟适用 vs. 永久豁免：** 跟踪宽限期何时结束——延迟合规不同于豁免。

---

## 适用性分析

在提取要求之前，确定**谁**必须合规。

| 门槛类型 | 示例 |
|------|----------|
| 收入 | 年总营收 > X 百万美元 |
| 数量 | 处理 > X 名消费者/笔交易的数据 |
| 活动收入 | 受监管活动收入占 X% |
| 实体类型 | 适用于开发者 / 控制者 / 运营者 |

**连接性 vs. 选言性：**"2500 万美元收入**且**10 万消费者"远比"2500 万美元收入**或**10 万消费者"受限。这一个词的变化可使受监管人群成倍放大或缩小一个数量级。

## 多法域处理（美国境内）

本技能处理三个美国法域层级及它们之间的互动。**每次分析一次只停留在单个声明的法域内**——多州或联邦/州比较是单独一轮，一次一个法域进行，然后组装。

### 法域层级

| 层级 | 示例 | 典型引注形式 |
|------|----------|------------------------|
| **联邦** | 美国法典、联邦法规汇编 | `42 U.S.C. § 1320d-2`、`45 C.F.R. § 164.502` |
| **州** | 州法典、州行政法规（全部 50 个州 + 哥伦比亚特区 + 领土） | `Cal. Civ. Code § 1798.100`、`Va. Code Ann. § 59.1-578`、`N.Y. Gen. Bus. Law § 899-bb` |
| **地方** | 县和市法典、条例 | `N.Y.C. Admin. Code § 20-870`、`Chicago Municipal Code § 4-4-005` |

### 联邦优先（升级候选）

联邦法律在某些领域优先于冲突的州法和地方法（明示优先、领域优先、冲突优先）。州立法机关已占据某领域或明确限制地方自治权限时，州法律优先于冲突的地方法。优先分析**始终是升级触发器**——为律师标记；不要将优先状态作为发现来声明。

### 多州比较

比较各州类似法律（例如，州隐私法、违约通知法规、消费者保护法）时：

- 识别其他州所遵循的示范法（如有）——例如，CCPA 影响了 VCDPA、CPA、CTDPA、UCPA
- 记录哪些州取向偏消费者保护、哪些偏企业友好
- 需关注的差异：对"出售"/"敏感数据"/"消费者"的定义、未成年人保护的年龄界限、适用性门槛、某些州有而其他州没有的权利、执法机制、私人诉权
- **法律选择争议**（跨多州的交易适用哪个州的法律）超出范围——为律师标记

### 地方自治与地方条例互动

在地方自治（home-rule）州，市镇可对州未优先的领域进行监管。在迪隆规则（Dillon's Rule）州，市镇权限较窄。如地方条例与州法冲突，该地方条款可能无效——为律师标记，而非作出声明。

多法规分析（源于美国州隐私法工作）的详细经验，参见 `references/practical_lessons.md`——**在界定多州或联邦对州的工作，或适用性门槛看起来异常时阅读**。

## 执法分析

| 因素 | 问题 |
|--------|------------------|
| 权限 | 仅总检察长？私人？机关？ |
| 罚则 | 民事 / 刑事 / 行政？金额？ |
| 纠正期 | 罚则前有纠正机会？ |
| 私人诉权 | 个人可以起诉吗？ |
| 执法历史 | 机关是否积极执法？ |

两条措辞相同的要求可能因执法动态而有截然不同的实际优先级——在输出中注明这一点，不要将所有法条文本视为同等承重。

---

## 法规没说什么

对照典型条款以识别显著缺失。救济或保护的缺失往往与包含的内容同样重要。

- [ ] 有私人诉权吗？（如无，明确注明）
- [ ] 安全港？
- [ ] 定义是穷尽性还是示例性？
- [ ] 什么留给了监管裁量？
- [ ] 哪些常见条款显著缺失？

---

## 一致性与常识

如某解释产生内部矛盾或荒谬结果，它很可能是错的——法规被写得连贯一致。犹豫时，偏好推进法规陈述目的的解释。（当荒谬在**法规**一侧而非解释一侧时，那是升级触发器。）

## 工作示例

**输入提示词（用户）：**
> "您能带我过一遍 Cal. Civ. Code § 1798.105——CCPA 删除权吗？我们正在界定一个 CCPA 合规项目。这里是合并文本：[粘贴]。生效日期为 2023 年修正案。目的：为我们政策团队提取要件。"

**输出（摘录——说明性，非权威）：**

```
草稿——需律师审查
审查律师： <占位符——由用户填写>
特权状态： <待确认——如为委托人案件，可能为律师工作成果>
法规： Cal. Civ. Code § 1798.105 | 版本： 2023 年修正案
法域层级： 州（加利福尼亚州）
分析目的： 为政策团队提取要件

1. 适用性
   - 权利及于"消费者"（定义见 § 1798.140）；义务及于满足
     § 1798.140(d) 门槛的"企业"  [置信度：高]
   - 连接性/选言性：适用性在 § 1798.140(d) 中使用或（OR）门槛  [置信度：高]

3. 操作性条款（草稿解读）
   - § 1798.105(a)：消费者"有权要求企业删除企业从
     消费者处收集的关于消费者的任何个人信息。"  [置信度：高]
     操作词："有权"（强制性权利）；"从消费者处"
     （将范围限于一方数据——见 § 1798.105(d) 例外）
   - § 1798.105(d)：删除义务的九项列举例外。
     [置信度：中——(d)(1)–(d)(9) 中的"必要"表述在操作上
     含糊，且机关指引存在分歧]

7. 给律师的开放问题
   - 对照当前 CPPA 公布的文本核验 2023 年修正案版本
   - 确认"从消费者处收集"与推断/衍生数据的范围——
     争议领域，规章解释与部分实务观点存在分歧
     （升级触发器 #4：部分由判例法/机关实践定义的概念）
```

该示例展示了结构模式：每项发现带置信度区间，**一方数据**的范围限制因规章围绕其制造了歧义而被标记为中，并将一个具体的升级触发器写入开放问题块。
