# 数据录入规范与提示词 — 经典案例库批量入库

> **用途**:把 ima 数据库(或其他数据源)的案例,批量整理成与本案例库结构对齐的 YAML,供回归测试与经验库联动。
> **对齐对象**:`案例模板.md` 字段 + `references/experience/_index.yaml` 的 scenario_key + SKILL.md 判断链。
> **版本**: 2026-08-07 v2(基于 AUDIT-49/50 压测反馈修订)

---

## v2 修订说明(针对压测发现的问题)

| # | 压测暴露的问题 | 本版修订 |
|---|---|---|
| 1 | chain_dimension 清单缺"居民个人境外所得申报"维度 | 新增 `申报备案-居民个人境外所得申报`(并区分企税/个税) |
| 2 | scenario_key 易被填成"相关概念"(如把未申报案填成抵免) | 命名规则强化:key 描述**案例本身的判定场景**,禁止用相关税种/概念名;新增反例对照 |
| 3 | verify_status 判定标准模糊("官网名"被当成"已核实") | 明确三档判定线:可打开 URL 或文书号=已核实;仅有机构名/日期=待核实 |
| 4 | in_scope=false 案例怎么处理没写 | 新增"边界拒绝测试区":false 不入正式回归库,专用于测 Skill 能否拒绝超 scope 请求 |

---

## 一、字段分层(决定案例能派什么用场)

| 层级 | 用途 | 缺失后果 |
|---|---|---|
| **Tier 1 必填** | 入库索引 + 基础检索 | 缺任一项不入库 |
| **Tier 2 高价值** | 可用作回归测试基准 | 缺则只能当"教学模型",不能比对 Skill 输出 |
| **Tier 3 可选** | 经验沉淀 / 盲区发现 | 缺不影响入库,影响联动深度 |

## 二、YAML 模板(数据源按此输出)

```yaml
案例:
  - # === Tier 1: 必填(入库门槛)===
    id: IM-06                          # 数据库编号,用 IM 前缀避免与现有 CC 冲突
    title: 深圳E公司劳务派遣德国常设机构认定案
    case_type: 常设机构/税收协定        # 沿用数据源原分类
    tax_type: 企业所得税                # 涉及税种
    
    chain_dimension:                   # 判断链维度,必填,见下方可选值清单
      - PE判断-劳务型
    scenario_key: pe-service-short-term-no-pe   # 与经验库对齐,见命名规则
    facts_brief: |                     # 案情摘要,脱敏,≤200字
      深圳E公司为德国非关联企业提供劳务并派遣人员,
      主动向税务机关咨询是否构成常设机构。
    outcome: 认定不构成常设机构,开具《中国税收居民身份证明》享受协定待遇
    
    # === 可核实性(必填,无来源不入正式库)===
    verifiability:
      source_type: 税务机关服务案例       # 见下方来源类型清单
      doc_number:                       # 文书号/公告文号/案号/案例库编号(任一)
      url:                              # 可打开的 URL(若有)
      verify_status: 待核实             # 已核实 / 待核实 / 无法核实 —— 严格按下方判定线
    
    # === Tier 2: 高价值(决定能否做回归测试)===
    facts_table:                        # 事实要素表,结构化拆分
      居民身份: 深圳E公司(中国税收居民);德国企业(德国居民)
      交易定性: 跨境劳务 + 人员派遣
      PE争议: 是否构成劳务型PE(天数门槛)
      关联交易: 非关联
      单证: 劳务合同、派遣记录、工期证明
      其他: 工期较短(具体天数待补)
    chain_results:                      # 判断链每步结论(回归基准,Skill 输出应对齐此项)
      - {step: 居民身份, conclusion: 中国居民向德国居民提供劳务}
      - {step: 交易定性, conclusion: 跨境劳务}
      - {step: PE判断, conclusion: 不构成(工期未达协定门槛)}
      - {step: 协定适用, conclusion: 适用中德协定,无PE则德国不征税}
      - {step: 申报方式, conclusion: 开具《中国税收居民身份证明》}
    core_dispute: 短期跨境劳务是否构成劳务型PE(协定天数门槛)
    in_scope: true                      # 是否在 skill scope 内(true/partial/false)
    
    # === Tier 3: 可选 ===
    linked_issues: []                   # 关联验收报告问题编号(V1-V11)
    challenge_to_guidance:              # 现有指引未覆盖的口径
    script_expected:                    # 涉及计算时的脚本期望输出
      # cmd: python scripts/tax_calc.py ...
      # expected: {...}
```

## 三、关键字段的填写规则

### 1. chain_dimension(判断链维度)— 从下列选,可多选

> 必须映射到 SKILL.md 的核心判断链 `居民身份→交易定性→PE→协定→税种税率→申报`。

- `居民身份认定-双重居民` / `居民身份认定-实际管理机构` / `居民身份认定-居民身份证明`
- `交易定性-特许权vs服务` / `交易定性-混合合同分劈` / `交易定性-明股实债` / `交易定性-间接转让重新定性` / `交易定性-嵌入式特许权`
- `PE判断-固定场所` / `PE判断-劳务型` / `PE判断-代理人型` / `PE判断-派遣人员`
- `协定适用-受益所有人` / `协定适用-LOB` / `协定适用-PPT` / `协定适用-协定优惠税率` / `协定适用-税收饶让`
- `税种税率-代扣企税` / `税种税率-跨境增值税` / `税种税率-个税非居民`
- `申报备案-对外支付备案` / `申报备案-居民身份证明开具` / `申报备案-居民企业境外所得申报` / `申报备案-居民个人境外所得申报` 【v2新增后两项】
- `重组税务处理-特殊性处理认定` 【v2新增,用于 59 号文/40 号文特殊性税务处理资格争议,与反避税区分】
- `风险应对-转让定价` / `风险应对-CFC受控外国企业` / `风险应对-资本弱化` / `风险应对-一般反避税` / `风险应对-CRS情报交换` / `风险应对-境外税收抵免` / `风险应对-间接抵免` / `风险应对-税收饶让抵免`

> **⚠️ 易混维度辨析(v2 新增)**:
> - `重组税务处理-特殊性处理认定` vs `风险应对-一般反避税`:前者是"重组方选择何种税务处理(一般/特殊)的资格认定"(59/40 号文),后者是"税务机关否定交易形式、重新定性"(47 条/7 号公告)。AUDIT-50(探矿权划转)属前者非后者。
> - `申报备案-居民个人境外所得申报` vs `风险应对-境外税收抵免`:前者是"境外所得是否依法申报的程序义务",后者是"已申报后境外已纳税款的抵免限额计算"。AUDIT-49(未申报补税)属前者非后者——它压根没走到抵免环节。

### 2. scenario_key 命名规则(v2 强化)

- 用小写英文 + 连字符,**描述案例本身的判定场景**(做了什么 → 导致什么结论)
- **禁止**用相关税种/概念名命名(这是 v2 最重要修订)。反例对照:

| 案例本质 | ❌ 错误 key(用概念) | ✅ 正确 key(用场景) |
|---|---|---|
| 居民个人境外所得未申报 | `foreign-tax-credit-direct`(抵免是另一个概念) | `resident-individual-overseas-income-non-reporting` |
| 特许权使用费 vs 技术服务费定性 | `withholding-tax`(预提税是结果) | `royalty-vs-service-recharacterization` |
| PE 天数累计构成 | `article-5`(条文号不是场景) | `pe-service-cumulative-rolling` |

- 已有 key(与经验库/现有案例库对齐):
  - `bo-red-chip-shell`(红筹导管)、`bo-and-ppt-stacked`(BO+PPT)、`lob-commercial-substance`(LOB)、`bo-low-tax-jurisdiction`(低税地BO)
  - `dual-resident-tiebreaker`(双重居民加比)、`effective-management-organ-resident`(实际管理机构)
  - `mixed-contract-split`(混合合同)、`embedded-royalty-in-goods`(嵌入式特许权)、`interest-vs-dividend-thin-cap`(利息股息)、`indirect-transfer-recharacterization`(间接转让)、`cfc-profit-hoarding`(CFC利润堆积)、`interest-free-loan-deemed-dividend`(免息借款视同股息)
  - `pe-commissionaire-agent`(代理人PE)、`pe-seconded-employees`(派遣员工)、`pe-service-cumulative-rolling`(劳务天数累计)、`pe-service-short-term-no-pe`(短期劳务不构成PE)
  - `foreign-tax-credit-direct`(直接抵免)、`foreign-tax-credit-indirect`(间接抵免)、`foreign-tax-credit-split`(分国不分项)、`tax-sparing-credit`(饶让)、`overseas-loss-carryforward`(境外亏损弥补)
  - `resident-individual-overseas-income-non-reporting`(居民个人境外所得未申报)【v2 新增】
  - `domestic-restructuring-special-treatment-failed`(境内重组特殊性处理未达标)【v2 新增,仅用于边界拒绝测试】
- 新场景自拟 key,但须在前 5 位用 `xxx-` 体现所属维度

### 3. verifiability.verify_status(v2 明确判定线)

**严格三档,禁止宽松判定**:

| 状态 | 判定标准(满足任一即可) |
|---|---|
| **已核实** | ① 有**可打开的 URL**(须实际抓取过正文) **或** ② 有**文书号/公告文号/案号**(永久标识,即使无 URL 也算) |
| **待核实** | 仅知道来源机构名 + 日期(如"厦门市税务局官网 2025-11-11"),但**没有具体可点击 URL 或文号** |
| **无法核实** | 无任何来源标识,或来源仅是"听说/教学模型" |

> ⚠️ "官网名 + 日期"**不等于**"已核实"。AUDIT-49 原填"已核实"应降为"待核实",需补到具体页面 URL 或税总发文字号。

### 4. in_scope(skill 范围内)— 三值及处置(v2 明确)

- `true`:核心跨境服务贸易涉税(咨询/技术/特许权/租金/股息/利息/PE/协定/抵免)→ 入正式回归库
- `partial`:部分超 scope(纯个税居民个人境外所得、跨境电商综合财税、出口退税部分环节)→ 入正式回归库但标注,优先级降低
- `false`:明显超 scope(纯境内、纯海关估价、纯刑事、境内重组)→ **不入正式回归库,入"边界拒绝测试区"**(见下)

---

## 四、质量门槛(v2 增补)

1. **无任何来源标识的案例**:`verify_status: 无法核实`,入"教学模型"区,不作回归基准
2. **仅"官网名+日期"无 URL/文号**:`verify_status: 待核实`,入库但标注待补全
3. **chain_results 缺失**:入库但标注"非回归级",仅用于覆盖矩阵展示
4. **scenario_key 用概念名而非场景**(如把未申报填成抵免)→ **入库前退回重命名**
5. **in_scope=partial**:入正式回归库,索引标注"partial"
6. **in_scope=false**:入"边界拒绝测试区"(见第五节),不入正式回归库

---

## 五、边界拒绝测试区(v2 新增)

**目的**:测 Skill 的"边界意识"——能否正确识别并**拒绝**超出自身 scope 的请求,给出合理的边界说明和转介建议。这是现有 TC1-4 完全未测的能力。

**收录标准**:`in_scope=false` 的真实案例,即那些"看起来像跨境税务但实际超出 skill 主线"的案例:
- 纯境内企业重组(59/40 号文,无跨境要素)
- 出口骗税(涉海关刑事,非服务贸易)
- 纯境内个税综合事务
- 纯海关估价/关税

**测试方式**:
```
# 把案例事实喂给 Skill,期望 Skill 输出:
1. 识别出该案超出 scope(不应强行套用跨境判断链)
2. 说明为什么超 scope(指向 SKILL.md Notes 的边界条款)
3. 给出转介建议(如"纯境内重组建议找企业重组/资本运作专业 Skill;出口骗税涉海关刑事建议找海关/刑事专业支持")
```

文件:`边界拒绝测试案例.md`(与正式回归库分离,避免污染覆盖矩阵)。

# 填写规则(重要,逐条遵守)
1. **事实与结论分开**:facts_brief/facts_table 只写客观事实;判断结论全部进 chain_results 和 outcome。回归测试时会隐去 chain_results 喂给 Skill,所以两块不能混。

2. **scenario_key 命名(最易错)**:描述"案例本身的判定场景",不要用相关概念/税种名。
   - ✅ 正确:resident-individual-overseas-income-non-reporting(居民个人境外所得未申报)
   - ❌ 错误:foreign-tax-credit-direct(抵免是相关概念,不是本案场景——本案压根没走到抵免环节)
   - ✅ 正确:royalty-vs-service-recharacterization(特许权 vs 服务重新定性)
   - ❌ 错误:withholding-tax(预提税是结果不是场景)

3. **chain_dimension 易混辨析**:
   - "特殊性税务处理认定"(59/40号文,重组方选择何种税务处理)≠ "一般反避税"(47条/7号公告,否定交易形式重新定性)
   - "居民个人境外所得申报"(申报义务)≠ "境外税收抵免"(已申报后的抵免限额计算)

4. **verify_status 严格判定**:
   - 有可打开 URL 或有文书号/公告文号 = 已核实
   - 仅知道"某某官网某日发布"但无具体 URL 或文号 = 待核实
   - 无任何来源 = 无法核实
   不要把"官网名+日期"当成"已核实"。

5. **脱敏**:当事人是真实企业且已公开披露(上市公司/判决书/行政处罚)的可保留全称;未公开的用"某企业/A公司"。

6. **来源优先**:doc_number 比 url 更重要(文书号是永久标识,url 可能失效)。

7. **in_scope 判断**:
   - true=核心跨境服务贸易(向境外付汇/代扣/协定/PE/跨境增值税/境外抵免)
   - partial=部分超 scope(纯个税居民个人境外所得、跨境电商综合、出口退税部分环节)
   - false=明显超 scope(纯境内重组、纯海关刑事、纯境内个税)
