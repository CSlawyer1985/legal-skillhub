# Cross-Border Service Trade Tax — 跨境服务贸易涉税业务指引

本 Skill 协助律师/税务师完成跨境服务贸易涉税业务的**尽职调查、税收协定待遇审查、代扣代缴税款计算与纳税申报/备案**,产出可直接用于办案的结构化分析报告。聚焦中国大陆跨境服务贸易(咨询/技术服务/特许权使用费/租金/股息/利息等),依据律协《律师办理跨境服务贸易涉税业务操作指引(2026)(试行)》。

> ⚠️ **定位**:律师办案的"首轮辅助筛查"。所有结论须律师结合本案交易实质复核;最终税务处理以主管税务机关认定为准。详见末尾 `## Notes`。

---

## 核心判断链(贯穿全流程,不跳步)

```
居民身份认定 → 交易定性 → PE判断 → 协定适用 → 税种/税率 → 申报或代扣方式
```

- **居民身份没定就先套协定税率 = 典型错误**。前环节不定,后环节无意义。
- **PE 是锚点**:非居民企业在境内**有 PE**(常设机构)→ 就 PE 归属利润按查账/核定征税(归并申报);**无 PE** → 就来源于境内所得**源泉扣缴(代扣代缴)**。两条路径的税种、税率、申报方式完全不同,必须先定 PE。
- 本 Skill 的 6 步工作流严格对应这条判断链。

## Workflow

### Step 1: 业务承接与利益冲突审查

**判断链位置**:前置环节(确定律师能否接案、接什么)

**目标**:明确委托事项范围,完成利益冲突审查,配置团队。

**(a) 确定业务类型**(决定后续工作深度,完整要点见 `references/业务承接与合同审查要点.md`):

| 业务类型 | 典型场景 | 工作侧重 |
|---|---|---|
| 常年代税顾问 | 跨境业务频繁的企业年度税务顾问 | 持续合规监控、定期自查 |
| 单项业务咨询 | 单笔跨境服务贸易涉税分析 | 一次性尽调+测算+报告 |
| 税务稽查应对 | 企业被税务机关立案检查 | 程序应对、证据梳理、陈述申辩 |
| 跨境重组涉税 | 跨境并购/重组的税务架构设计 | 架构设计、税务影响测算 |

**(b) 利益冲突审查**:确认委托方与交易对手方是否存在利益冲突;同一集团内多主体委托时审查冲突边界。

**(c) 团队配置**:跨境涉税业务通常需**律师+税务师**协同;涉及外文合同/协定的需外语能力;涉及转让定价的需经济学背景。

输出落盘:`委托范围确认书.md`(委托方/交易概况/委托事项/团队/收费)。

### Step 2: 尽职调查

**判断链位置**:居民身份认定 → 交易定性 → PE判断(**本步核心**)

**目标**:核查交易的全部涉税要素,为后续协定适用与税额计算提供事实基础。**这是全流程的事实基础,要素不全会导致后续判断偏差。**

**(0) 先查经验库(复用循环)** —— 深度分析前,先查本 Skill 沉淀的经验:

1. 读 `references/experience/_index.yaml`,看本案 `scenario_key`(如 `pe-service-6months`、`royalty-vs-service`、`foreign-tax-credit-indirect`、`bo-red-chip-shell`)是否有 `status=verified`(或 `provisional` 且 confidence 达 `_config.yaml` 的 `min_confidence_to_load` 门槛)的经验
2. 有匹配则深读对应 YAML,定位相近条目
3. **引用经验时必须带 sources**(法条/协定条文/公告文号);引用 `provisional` 经验**必须标注「[待验证经验]」**
4. 经验库中的 `search_queries` 是沉淀的有效检索式,**优先采用**
5. **【ref_count 计数,MANDATORY】**实际采用了某条经验的结论或检索式,须在报告中标注"本结论参考经验 [id]",并在 Step 6 经验固化时为该经验 `ref_count + 1`(用 `exp_upsert.py` 重新 upsert 同 id 草稿,带更新后的 ref_count)。**这是 provisional 升级门的触发器——不计数则永远无法触发复核**

**(a) 尽调要素抽取表**(完整要素清单见 `references/尽职调查要素清单.md`,**仅当案件涉及对应情形时才读对应小节**):

| 要素类别 | 必查内容 | 关键判断 |
|---|---|---|
| **居民身份** | 服务提供方/接受方注册地、实际管理机构所在地、税收居民身份 | 区分中国税收居民 / 非居民 / 双重居民(需协定 Tie-breaker) |
| **交易模式** | C2C / B2B / B2C;资金流、服务流、票据流方向 | 影响纳税义务人与扣缴义务人认定 |
| **交易实质** | 服务类型:咨询/技术/特许权使用费/租金/股息/利息 | **定性是核心**:"技术服务"vs"特许权使用费"税率可能不同 |
| **合同条款** | 付款条件、税费承担(net/gross)、知识产权归属、合同期限 | 税费转嫁条款影响实际税负 |
| **付款方式** | 支付币种、支付路径、是否经外汇登记 | 付汇合规、代扣时点 |
| **PE 判断** | 境外方在境内有无固定场所、工程/劳务持续时间、代理人 | **有 PE / 无 PE 决定整条征税路径**(见下) |
| **关联交易** | 交易双方是否关联企业、定价是否符合同期利润水平 | 触发转让定价审查(Step 5) |
| **单证完整性** | 合同、发票、付汇凭证、税收居民身份证明、备案回执 | 享受协定待遇与免税的前置要件 |

**(b) PE 判断(锚点)** —— 这是跨境服务贸易的核心分水岭。完整判断标准见 `references/尽职调查要素清单.md` 的 PE 章节:

| PE 类型 | 构成要件 | 跨境服务贸易常见情形 |
|---|---|---|
| **固定场所型 PE** | 在境内有固定营业场所,且非准备性/辅助性 | 境外公司在境内设办事处/项目部 |
| **工程/劳务型 PE** | 在境内提供劳务/工程,**任何12个月内累计≥183天**(一般协定) | 境外派人来华提供咨询/技术服务超6个月 |
| **代理人型 PE** | 非独立代理人经常为境外方签订合同/履行非独立活动 | 境内有代理签订合同的员工/中介 |

> ⚠️ **PE 判断的常见陷阱**:
> - 劳务型 PE 的天数计算:不同协定措辞不同(如"在任何12个月内"vs"财政年度内"),须查具体协定原文
> - "准备性/辅助性"豁免范围窄(如仅仓储、展示、信息收集),不可滥用
> - 独立代理人(按常规经纪、律师、会计师)一般不构成 PE,但**专为/几乎专为境外方活动**的除外

**(c) 交易实质审查(防滥用)** —— 区分真实交易性质,防止"名服务实特许权"等定性错误:
- 审查合同实际履行:是提供一次性劳务,还是授予持续使用权?
- 特许权使用费 vs 技术服务费:核心看是否**转让/授权使用**无形资产(专利、商标、专有技术、版权)
- 混合合同(如"设备+技术+服务"一揽子)需合理分劈

**抽取后向用户确认**:用表格列出已抽到的要素 + 缺失要素,请用户补充。**不要在要素不全时直接进入协定适用与税额计算。**

输出落盘:`尽职调查要素表.md`。

### Step 3: 税收协定待遇审查

**判断链位置**:协定适用(在 PE 已判断、居民身份已定之后)

**目标**:判断中国与对方国家/地区的税收协定是否适用、适用何优惠税率、有无 LOB/PPT 限制条款。

**(a) 协定适用前提**(完整指引见 `references/税收协定待遇审查指引.md`):

1. 对方国家/地区与中国**有生效的税收协定**(查 `references/法规与协定索引.md` 或在线核实)
2. 收益所有人(受益所有人)是**对方税收居民**(须取得对方税务机关开具的**税收居民身份证明**)
3. **受益所有人**认定:不能仅是导管公司/代理人(国家税务总局2018年第9号公告)

**(b) 按所得类型的协定待遇**(核心条款见 `references/税收协定待遇审查指引.md`,税率速查见 `references/税率速查表.md`):

| 所得类型 | 协定条款 | 协定通常处理 | 中国国内法 |
|---|---|---|---|
| **股息** | 协定第10条 | 通常5%/7%/10%(视持股比例与协定) | 法定10% |
| **利息** | 协定第11条 | 通常7%,部分免税(如政府/央行) | 法定10% |
| **特许权使用费** | 协定第12条 | 通常7%/10%,少数免税 | 法定10% |
| **技术服务费** | 协定第12条或13条 | 部分协定单列(如中印7.5%),部分并入特许权 | 法定10% |
| **营业利润** | 协定第7条 | **无 PE 不征税**;有 PE 就归属利润征税 | 查账/核定 |
| **财产收益** | 协定第13条 | 不动产/常设机构不动产/特定股权才征税 | 按国内法 |
| **独立个人劳务** | 协定第14条 | 通常固定基地或≥183天才征税 | 按个人所得税法 |
| **非歧视待遇** | 协定第24条 | 国民/常设机构无差别待遇 | — |

**(c) 反协定滥用条款**(Step 3 必查,决定协定优惠能否享受):

- **LOB(利益限制,Limitation on Benefits)**:部分协定(如中美、中韩)要求受益所有人满足"合格居民"测试(上市公司/政府/主动经营等)
- **PPT(主要目的测试,Principal Purpose Test)**:若获取协定优惠是交易的主要或主要目的之一,可拒绝优惠(普遍适用,多边公约 MLI 引入)
- **受益所有人**:实务中常被否定的情形——空壳公司、无实质经营、资金很快转出、税负极低

> ⚠️ 若触发 LOB/PPT 风险,**必须在报告中显著提示**,并建议补充实质经营证据。

输出落盘:在 `涉税业务分析报告.md` 中追加"协定待遇审查"章节(适用协定 → 条款 → 优惠税率 → LOB/PPT 分析 → 所需单证)。

### Step 4: 纳税申报与税收优惠备案

**判断链位置**:税种/税率 → 申报或代扣方式(**确定性计算必须用脚本**)

**目标**:确定具体税种、税率、应纳税额,给出申报/代扣方案与备案流程。

**(a) 税种判定**(完整指引见 `references/纳税申报与税收优惠备案.md`):

| 税种 | 征税对象 | 跨境服务贸易情形 |
|---|---|---|
| **企业所得税(源泉扣缴)** | 非居民企业来源于境内、境内未设机构场所的所得 | 境内向境外支付特许权/利息/股息/租金等,**付款方为扣缴义务人** |
| **企业所得税(归并申报)** | 非居民企业在境内设 PE,就 PE 归属利润 | 境外方在境内有常设机构 |
| **增值税** | 在境内销售服务/无形资产/不动产 | 跨境服务看**消费地**:境内消费→征税;境外消费→零税率/免税 |
| **个人所得税** | 非居民个人来源于境内所得 | 境外个人来华提供劳务 |

**(b) 增值税处理(消费地原则)**:

| 情形 | 处理 | 依据 |
|---|---|---|
| 境内单位/个人向境外**提供**完全在境外消费的服务 | **零税率**(部分)/ **免税**(多数) | 财税〔2016〕36号 |
| 境外单位/个人向境内**销售**服务(境内消费) | **由境内购买方代扣代缴**(一般计税6%) | 增值税法 |
| 工程、矿产资源在境外的工程勘察勘探服务 | **免税** | 财税〔2016〕36号 |

> 用 `scripts/tax_calc.py vat.classify` 快速归类(根据服务类型+消费地)。

**(c) 代扣代缴企业所得税计算(确定性,必须用脚本)**:

> ⚠️ 涉税金额计算涉及法定税率、协定优惠税率、税费转嫁(net/gross)等细节,**禁止口算**。一律调用脚本。

**脚本路径与调用约定(MANDATORY):** 先解析一次脚本目录的绝对路径,后续调用全部用绝对前缀。
```bash
CBT_SCRIPTS="<skill_directory>/scripts"
# Windows 上若 `python3` 指向 Microsoft Store stub(无输出/exit 49),改用 `python`
python "$CBT_SCRIPTS/tax_calc.py" wht.calc \
  --income 1000000 --legal-rate 0.10 --treaty-rate 0.07 --gross
```

子命令清单:
- `wht.calc` — 代扣代缴企业所得税:法定税率 vs 协定优惠税率对比,支持 gross/net(含税/不含税)转换,输出应纳税额与节税额
- `vat.classify` — 增值税归类:根据服务类型/消费地判定 零税率/免税/一般计税(零税率须精确匹配列举服务,关键词命中时降级为免税+人工确认提示)
- `vat.calc` — 增值税应纳税额(一般计税:销项-进项;简易计税)
- `treaty.lookup` — 协定税率查询:按国家+所得类型给出协定条文+优惠税率(内置常见协定,**非权威**,以协定原文为准);条件性税率(如股息持股门槛)会返回适用条件与 fallback 税率
- `treaty.check` — 协定税率表时效性检查:检测内置税率表是否超过12个月未核实(协定会修订/废止)
- `ftc.calc` — 境外税收抵免(outbound):直接抵免/间接抵免/分国vs综合/税收饶让/境外亏损弥补5种模式(对应居民企业境外所得,详见 `references/纳税申报与税收优惠备案.md` 第3章);**政策口径部分待人工核实**,脚本输出带 `verify_status` 提示

完整公式与算例见 `references/税率速查表.md`(**仅当涉及具体计算时才读**)。

脚本返回 JSON,将其中的金额、公式、法条依据回填到报告;**不要手工改写脚本输出的数字**。

**(d) 备案流程**(享受税收协定优惠的程序要求,2019年第35号公告核心):

1. **自行判断**是否符合协定优惠条件(改为"自行判断"而非审批)
2. **填报**《非居民纳税人享受协定待遇信息报告表》
3. **归集留存**相关资料备查(税收居民身份证明、合同、受益所有人证明等,**留存7年**)
4. 扣缴义务人享受协定优惠的,在**代扣代缴申报**时填报信息报告表

输出:在 `涉税业务分析报告.md` 中追加"税种税率判定 + 税额测算 + 申报/备案方案"。

### Step 5: 合规与风险应对

**判断链位置**:全链路风险复查(承接→尽调→申报→归档)

**目标**:识别薄弱环节,排查转让定价、情报交换、反避税风险,给出应对建议。

**(a) 薄弱环节自查清单**(完整要点见 `references/风险与合规要点.md`):

| 风险类别 | 自查要点 |
|---|---|
| **申报合规** | 是否按时申报/代扣、税率适用是否正确、备案资料是否齐全 |
| **转让定价** | 关联交易是否符合独立交易原则、有无同期资料、是否选择合理方法 |
| **情报交换(CRS)** | 金融账户信息是否会被自动交换、非居民账户尽调是否合规 |
| **一般反避税** | 交易有无合理商业目的、是否以减少税款为主要目的 |
| **特别纳税调整** | 受控外国企业、资本弱化、成本分摊等 |
| **受益所有人** | 协定待遇申请是否会被税务机关质疑受益所有人地位 |

**(b) 税务稽查应对**(若企业已立案):
- 程序合法性核查:检查通知、询问、调取账簿是否符合《税收征管法》
- 证据梳理:交易实质证据、同期资料、合理性说明
- 陈述申辩与听证权
- 税务行政复议(60日内)/行政诉讼(6个月内)的救济路径

输出落盘:在 `涉税业务分析报告.md` 中追加"合规风险清单 + 应对建议"。

### Step 6: 业务总结与归档(含经验固化)

**判断链位置**:收尾(归档 + 经验沉淀)

**目标**:完成工作底稿归档,把本次新发现沉淀入经验库供下次复用。

**(a) 归档**(第7章要求):
- 工作底稿:委托合同、尽调材料、分析报告、申报回执、往来函件,**留存10年**
- 保密:涉密信息加密存储,团队知悉范围最小化
- 成果总结:案件要点、疑难问题、处理结论

**(b) 经验固化(可选,默认自动触发)**:

**(b1) 判断是否触发** —— 读 `references/experience/_config.yaml`:
- 若 `auto_capture: true`(默认)→ 报告交付后**自动**执行下面的自检
- 若 `auto_capture: false` → 仅当用户明确说"记下这条经验"时才执行

**(b2) 自问:本次是否有可沉淀的新发现?** 检查这些信号:
- 🆕 发现了经验库未收录的新协定口径 / 新的 PE 判断场景
- 🔄 经验库现有经验被本案或本次检索到的案例**反驳**(可能是口径已变)
- 🔍 摸索出了比经验库更有效的检索式或定性方法
- 💰 税额计算中踩了坑或发现了边界情形(如混合合同分劈、税费转嫁)
- 👤 用户纠正了你的某个判断

**若没有任何新发现 → 跳过 Step 6 经验沉淀的新增,但仍须执行下面的(b2.5)ref_count 更新。**

**(b2.5) ref_count 更新(必做,即使无新发现)** —— 若本次在 Step 2(0)引用了经验库的某条经验(即报告里标注了"参考经验 [id]"),须:
1. 读该经验所在 YAML,把 `ref_count` 加 1
2. 重新 upsert 该 id(用更新后的 ref_count)
3. 若该经验 `status=provisional` 且更新后 `ref_count >= _config.yaml 的 provisional_review_threshold(默认3)`,**必须在报告中显著提示用户**:该经验已达复核门槛,建议专业人士复核后再升级;并可用 `assets/经典案例库/` 中覆盖相同 `scenario_key` 的案例做交叉验证(案例支持→可升级,反驳→加 `override_of` 重写)

**(b3) 生成草稿** —— 有新发现时,把经验写成单条 YAML,**status 只能填 `provisional` 或 `draft`**(模型不得自封 `verified`),保存到 `_incoming/<YYYY-MM-DD>-<slug>.yaml`。字段规范见 `references/experience/README.md`。**sources 不得为空**(引用必带法条/协定条文/公告文号)。

**(b4) 调用入库脚本**:
```bash
python "$CBT_SCRIPTS/exp_upsert.py" references/experience/_incoming/<你的草稿>.yaml
```
- 退出码 0 = 成功(自动校验、冲突检测、路由、重建索引)
- 退出码 3 = schema 错误 → 按报错修正后重试
- 退出码 4 = 冲突拒绝 → 若确为口径变更,加 `override_of: <旧经验id>` 后重试
- **非 0 退出时,不得谎称"已沉淀"**,须如实报告失败原因

**(b5) 用户反馈升级** —— 若用户说"这条经验对了/救了我",可建议把 `status` 改为 `verified`、`verified_by: tax_advisor`(须专业人士确认,模型不能自行升级)。

## Key Principles

1. **判断链不跳步** — 居民身份→交易定性→PE→协定→税种税率→申报,前环节不定后环节无意义
2. **税不重征** — 协定优惠税率≤法定税率,已缴境外税款可抵免(避免双重征税是协定核心目的)
3. **PE 是锚点** — 有 PE 归并申报查账/核定,无 PE 源泉扣缴;两条路径税种税率申报方式完全不同
4. **受益所有人要实** — 享受协定优惠须是真实受益所有人,导管/空壳会被否定(2018年第9号公告)
5. **确定性交脚本** — 凡涉税额计算一律用 `scripts/tax_calc.py`,不口算、不手工改写脚本输出
6. **法条/协定时效性** — 协定会修订、公告会废止,引用前核实现行有效;税收协定以国家税务总局公布原文为准
7. **留存备查** — 享受协定优惠改为"自行判断+留存备查",资料须留存7年,缺资料等于没享受
8. **经验必带溯源** — 写入经验库的条目 `sources` 不得为空;引用 `provisional` 经验须标注「[待验证经验]」;模型不得自封 `verified`;**provisional 累计被引用 ≥3 次须提示强制复核再升级,复核时用 `assets/经典案例库/` 中覆盖相同 `scenario_key` 的真实案例做交叉验证**(案例结论支持则可升级、反驳则加 `override_of` 重写)

## Notes — 免责声明与边界

1. **聚焦中国大陆跨境服务贸易涉税**(咨询/技术/特许权/租金/股息/利息等),不处理纯境内业务、关税与海关估价、纯个税居民个人综合事务
2. **定位为律师办案的首轮辅助筛查**:生成的协定分析、税额测算、风险清单仅供参考,不构成正式税务意见,**最终税务处理以主管税务机关认定为准**
3. **法条/协定时效性**:增值税法(2026年生效)、企业所得税法、各税收协定及国税公告会修订/废止,使用前请核实现行有效(参考 `references/法规与协定索引.md` 的更新日期)
4. **税收协定以原文为准**:本 Skill 内置的协定税率表为归纳参考,具体以国家税务总局公布的协定原文及议定书为准;**新签/修订协定可能未及时收录**
5. **税率地区差异**:部分优惠、免税政策有适用条件,实际以交易发生时的有效政策为准
6. **数据合规**:本 Skill 不内置企业隐私数据,在线检索仅指向公开法规;生成报告时对当事人信息脱敏
7. **保持专业中立**:呈现征税与不征税、优惠与限制两面,不做选择性呈现,不教唆避税
8. **经验库为归纳性参考,有固有局限**:
   - `verified_by: none` 或 `provisional` 的条目不代表权威结论
   - **lint 只校验格式,不校验内容真伪**——格式合规但税务内容错误的经验(如引用已废止公告)可能通过校验
   - 经验可能因协定修订、口径变化而过期,定期运行 `exp_lint.py` 复核(12个月未复核报 warning)
   - **错误放大风险**:provisional 经验若被反复引用,可能形成"错误归纳→误导分析→生成同向证据→升级"的正反馈污染。**累计被引用≥3次须提示强制复核再升级**
   - 强烈建议对 `references/experience/` 目录启用 `git`,每次入库前 commit
