# 公文格式 Word 文档

## 硬性规则（违反即视为任务失败）

1. **只能通过 `docfmt` MCP 的 `create_document` 工具生成文档。**
2. **禁止自行编写任何排版代码。** 不许用 python-docx、docx 库、pandoc、LibreOffice、
   shell 脚本或任何其他方式生成或修改 .docx。哪怕你觉得"自己写一段更快"——不行。
3. **禁止手工设置任何格式参数。** 字体、字号、行距、缩进、页边距全部由工具内部的
   规范表决定，工具也没有开放任何格式参数给你。你唯一能决定的是**写什么内容**。
4. 如果用户要求的格式与本规范冲突（比如"改成小四"），**不要自己想办法实现**，
   直接告诉用户：本工具锁定了所长办公室下发的统一格式，改格式需要联系工具维护者。

这三条不是风格建议。排版参数一旦交给模型现填，每次生成都会有细微漂移，
十份文件放在一起就能看出来不是一套。规范锁在程序里，才能保证第 100 份和第 1 份一模一样。

## 工作流

1. 需要确认规范细节时，调用 `get_spec`。
2. 组织内容，写成下面规定的受限 Markdown。
3. 调用 `create_document(markdown=..., output_path=..., title=...)`。
   - `output_path` 用**绝对路径**，放在用户的工作目录里。
   - 文件已存在时工具会报错，不要盲目加 `overwrite=true` 覆盖用户的文件，
     先问用户是覆盖还是换名字。
4. 工具会自动做格式自检。如果返回里出现"自检未通过"，那是工具本身的缺陷，
   照实告诉用户并把报告贴给他，不要试图自己动手修文件。
5. 用户拿到别人写的 .docx 想核对格式时，调用 `check_format(path)`。
   这个工具只报告问题、不改文件；改的话只能重新生成。

## 内容怎么写

`markdown` 参数只认四种结构，多一种都不认：

```
# 一、基本情况            ← 一级标题（黑体四号）
## （一）委托事项          ← 二级标题（楷体四号加黑）
### 1. 核查范围            ← 三级标题（仿宋四号加黑）
普通文字就是正文段落。      ← 正文（仿宋四号）
```

- **段落之间必须空一行。** 不空行的相邻两行会被拼成同一段。
- **标题序号自己写进标题文字里**，工具不做自动编号。推荐层级：
  `一、` → `（一）` → `1.`。序号连续性由你负责，写完自己核一遍。
- **题名**（报告全名）走 `title` 参数单独传，不要写成 `# 标题`。
  题名是二号黑体居中单独成行，一级标题是四号黑体缩进两字，两者不一样。
- **不要写**：列表（`- ` / `1. `）、表格（`|`）、代码块、分隔线、
  `**加粗**` 等行内标记。本规范里这些都没有对应格式，工具会降级处理并警告。
  并列内容请改写成"一是……二是……三是……"，或用（一）（二）（三）编号成段。
- 正文用书面语，不用口语和网络用语；引用法律法规写全称加书名号，
  首次出现后可用简称。

## 常见误区

- ❌ 「我先用 python-docx 生成，再用 check_format 校验」——第一步就违规了。
- ❌ 「用户要加个表格，我用 python-docx 补一下」——本规范不含表格格式，
  应告知用户当前工具不支持表格，问他是否接受改写成文字表述。
- ❌ 「把中文和数字拆成两段分别设字体」——工具在同一处声明了中西文两套字体，
  Word 会按字符自动分流，拆开反而出错。你根本碰不到这一层，也不需要碰。
