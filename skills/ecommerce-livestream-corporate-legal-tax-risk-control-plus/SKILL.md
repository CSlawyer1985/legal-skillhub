# 触发与识别

当用户提出以下任一类问题时，启用本技能：

- "我的电商/直播业务有没有法律风险"
- "直播带货模式合规吗""这个玩法会不会被处罚"

**业务模式识别**：启动后务必先确认用户业务的具体形态（以下一种或多种），以精准匹配法律规则：

# MCP 数据工具调用规范

本技能集成两个 MCP 数据源。**调用前必须先 ToolSearch 加载其 schema（首次使用各工具时需一次 ToolSearch，同工具后续调用可跳过）**，再通过 DeferExecuteTool 发起调用。

## 一、企查查 MCP（qcc-company）

**用途**：在分析的「民事角度」「行政角度」层，核查经营主体的工商登记、资质、行政处罚、诉讼与被执行记录，使风险判断建立在客观事实基础上，而非模型推断。

**前置准备**：若用户提供了企业名称或统一社会信用代码，在进入五层分析前，先并行发起以下核查（具体工具名以 ToolSearch 返回为准，须经 ToolSearch 加载 schema 后使用真实工具名，**严禁编造工具名**）：
- 企业基本工商信息（登记状态、经营范围、法定代表人）：企查查 MCP 的 `mcp__qcc-company__get_company_profile`、`mcp__qcc-company__get_company_registration_info`、`mcp__qcc-company__get_company_by_query`（先按名称检索定位主体）等真实工具；
- 行政处罚记录（市场监管、税务、广电、网信等）：**实际来自华宇元典 MCP** 的 `mcp__yuandian-mcp__yuandian_rh_enterprisePunishment`（按统一社会信用代码核验，已在下方工具清单列出），而非企查查工具；
- 诉讼记录与被列入经营异常/严重违法失信名单情况：华宇元典 MCP 的 `mcp__yuandian-mcp__yuandian_rh_enterpriseWritList`、`mcp__yuandian-mcp__yuandian_rh_enterpriseExecutions`、`mcp__yuandian-mcp__yuandian_rh_enterpriseAbnormalOperation`、`mcp__yuandian-mcp__yuandian_rh_enterpriseSeriousIllegal` 等真实工具。
- 资质许可（如《增值电信业务经营许可证》、食品经营许可、医疗器械经营许可、网络文化经营许可等是否与经营范围匹配）：企查查 MCP 的 `mcp__qcc-company__get_company_profile`（含经营范围、许可资质概览）等真实工具。

**使用规则**：

- 企查查数据用于印证「该主体是否已被处罚/是否具备资质/是否有涉诉」，属客观事实层。
- 凡在报告中引用企查查结果，须标注来源："据企查查MCP查询（查询时间：[日期]）"。
- 若用户未提供企业名称，本条可跳过，但须在报告中标注「未提供经营主体信息，主体资质风险未做数据核验，建议补充核查」。
- 企查查返回为空 ≠ 无风险，须明示"以公开信息为限，不排除未公示风险"。

## 二、华宇元典法律数据 MCP（yuandian-mcp）

**用途**：核验引用的法律法规有效性，并检索相关类案（建议优先关注近年尤其 2024 年 7 月 1 日《消费者权益保护法实施条例》施行以来的裁判案例，以反映新规适用态势），保证法条与案例引用不编造、不过时。

**工具清单**（以下为短名，实际通过 DeferExecuteTool 调用时须使用 ToolSearch 返回的全限定名，如 `mcp__yuandian-mcp__yuandian_law_vector_search`。调用前务必先 ToolSearch 加载 schema，严禁编造工具名）：

- `yuandian_law_vector_search`：法条有效性核验。将所有引用法条的编号与核心内容组织为单个自然语言 query（如"电子商务法第38条 平台连带责任 消费者权益保护法第44条"），调用本工具核验。
- `yuandian_case_vector_search`：类案检索。检索与用户业务模式相关的裁判案例（建议 `return_num` 设为 3-6），每个案例须含法院名称 + 案号 + 裁判日期 + 裁判要点。
- `yuandian_rh_enterprisePunishment`：行政处罚记录核验。按统一社会信用代码核验企业经营处罚记录，用于印证 `references/浙江电商直播行政处罚案例库.md` 中具名案例（序号1–13）及增量核验。凡在行政角度引用企查查/华宇元典处罚数据时，优先调用本工具做双源交叉验证。
- `yuandian_get_user_balance`：余额预检查。首次调用华宇元典 MCP 前先调用，检查剩余核验额度。

**余额预检查**：首次调用华宇元典 MCP 前，先调用 `yuandian_get_user_balance`（全名 `mcp__yuandian-mcp__yuandian_get_user_balance`）检查余额。若余额不足，跳过 MCP 检索，在报告中标注"因华宇元典MCP余额不足，本次法条与案例未做MCP核验，建议充值后补充检索"。

**使用规则**：

- 凡输出的具体法条，优先经 `yuandian_law_vector_search` 核验现行有效版本与条款序号，避免引用已废止或修改条文。
- 凡输出的案例，优先经 `yuandian_case_vector_search` 检索可核查案例，给出真实案号与裁判要点；不得编造案例名称或案号。
- 无法核验或检索无果的，必须明示"待人工通过北大法宝/裁判文书网等权威数据库复核"。

# 详略分明原则（核心机制·强制）

**本技能不追求四个分析层级平均用力，而是"按风险高低分配笔墨"：就用户提出的具体问题，判断民事、行政、税收、其他四个角度中哪一（或哪几）个部分风险最高，就重点、深入论述该部分；其余部分简要带过，突出重点、简化非重点。**

## 一、风险权重研判（分析前必做）

在进入逐层分析之前，先基于用户问题、业务形态、商品类目及 MCP/案例库核查结果，对民事、行政、税收、其他四个角度分别作**风险权重研判**，得出各层的相对风险高低。研判维度：

1. **用户问题指向**：用户问题本身聚焦或隐含哪个角度（如"私账收款要不要紧"直指税收；"这样宣传会不会被罚"直指行政；"消费者要求退一赔三"直指民事）。
2. **高风险事项密度**：哪个层级识别出的 🔴 高风险事项最多、后果最严重（处罚金额、赔偿、经营中断、行刑衔接）。
3. **实证执法态势**：案例库（浙江电商直播行政处罚案例库 / 浙江税收处罚典型案例库）中，与该业务同类型主体在哪个角度被实际处罚/查处最集中。

据此将四个角度划分为：

- **重点层（1–2 个）**：风险最高、用户最关切、后果最严重的层级 —— **详展开**。
- **次要层（其余 2–3 个）**：风险相对较低或与本业务关联弱的层级 —— **精简带过**。

## 二、重点层与次要层的论述标准

| 论述要素 | 重点层（高风险） | 次要层（低风险/弱关联） |
|----------|------------------|--------------------------|
| 风险识别清单表格 | 完整输出（风险事项/法律规范/风险等级/简要说明四列，逐项列全） | 仅列该层**最主要 1–3 项**，或用要点式一段话概括，可不制表 |
| 展开分析 | 逐项深入：法律关系、责任划分、推理过程、反向风险、行刑衔接均展开 | 只点明"存在何种风险、依据何法、建议关注"，一两句带过，不逐条论证 |
| MCP 核查与案例库引用 | 强制主动引用匹配案例、核验法条、双源交叉验证 | 视需要引用，无匹配案例可省略，法条给出名称即可 |
| 🔴 高风险事项提示小节 | 完整复述 | 若该层无 🔴 项，一句"本层未识别高风险事项"即可 |

## 三、执行要求

1. **不得省略任何层级**：四个角度仍须全部出现，但次要层允许高度精简（甚至一小段话），确保结构完整而重点突出。
2. **重点层必须显著详于次要层**：从篇幅、表格完整度、案例与法条密度上都应明显区分，让使用者一眼看出主风险所在。
3. **在报告中显式标注主风险层级**：风险概要的总体结论句须点明"最大风险集中于[层级]"，并在该重点层标题后以括号标注（本报告重点分析层），次要层标题后标注（简要）。
4. **研判结果须与风险等级一致**：被列为重点层的，通常应含 🔴 高风险项；若四层均无 🔴，则以 🟡 最集中者为重点层。
5. **多层并重的情形**：若确有两个层级风险相当（如既有税收偷税风险又有行政虚假宣传风险），可并列为重点层，其余精简。

# 五层分析框架（强制结构）

对用户业务的法律风险，**必须先在报告头部元信息之后输出强制前置的"风险概要"（见下方独立章节），将全部 🔴 高风险事项集中前置；随后严格按下述五个层级逐层分析**，各级标题使用"（一）""（二）"…顺序编号，不得增删层级或调换顺序。风险概要是前置提示环节，不计入五层层级编号。

> **详略要求（贯穿全框架）**：以下（一）民事、（二）行政、（三）税收、（四）其他四个分析层级，须按上文"详略分明原则"区分重点层与次要层——重点层详展开，次要层精简带过。第（五）合规意见和建议不分主次，须完整覆盖各层识别出的所有风险。各层描述的内容清单是"可选论述范围"而非"必答项"：重点层尽量覆盖相关项，次要层只取最相关的少数项即可。

> **刑事衔接处理**：本框架不单设"刑事角度"输出层级。凡业务风险可能升级为刑事责任的（如售假涉假冒注册商标罪、逃税涉逃税罪、非法采集用户数据涉侵犯公民个人信息罪、虚开发票涉虚开类犯罪），须在对应的（一）民事 / （二）行政 / （三）税收层内以"行刑衔接"方式提示，并在（五）合规意见中汇总刑事风险。涉刑罪名与司法解释见 `references/法规索引.md` 第四章节（标题为"四、刑事衔接（跨层专题，非独立输出层级）"）。

每一层内部，先给出「风险识别清单」（表格形式，列含：风险事项 / 对应法律规范 / 风险等级 / 简要说明），再视情况展开「分析」。

**风险等级三档**（全报告统一，必须可视化标注）：

- 🔴 **高风险**：极可能触发处罚、赔偿或重大经营中断，须优先处置
- 🟡 **中风险**：存在较高概率争议或被查处，应主动整改
- 🟢 **低风险**：偶发或争议空间大，建议纳入常规监测

> 🔴 红色圆点用于突出显示高风险事项。凡判定为 🔴 高风险的行，必须在风险等级列以 🔴 标记，且在每层末尾以"🔴 高风险事项提示"小节集中复述，便于用户一眼识别。

# 风险概要（强制前置）

**在五个层级逐层分析之前，必须先输出一段"风险概要"，将本次分析识别出的全部 🔴 高风险事项集中前置。** 其目的是让使用者在阅读详细逐层分析之前，一眼看到最大风险，优先作出处置判断。

**输出位置**：紧随报告头部"数据来源"元信息之后、第（一）民事角度之前（见下方输出模板）。

**内容规则**：

1. **只列 🔴 高风险**：风险概要仅汇总五层分析中判定为 🔴 高风险的项；🟡 中风险、🟢 低风险不进入概要，留待各层展开。
2. **结构化呈现**：以表格列出「序号 / 最高风险事项 / 所属层级 / 对应法律规范 / 一句话风险说明（含后果）」，列明该风险可能触发的最严重后果（如被处罚金额区间、民事赔偿、经营中断、刑事衔接等）。
3. **结论句收尾**：表格后以一段加粗文字给出总体结论，例如"本次分析共识别 N 项 🔴 高风险，最大风险集中于[层级/事项]，建议优先处置。"
4. **与五层保持一致**：概要所列高风险事项，必须与后续五层中 🔴 标记项完全一致，不得增减或改变定性；若五层分析过程中修正了风险等级，概要须同步修正。
5. **不替代逐层分析**：风险概要是前置提示，五个层级逐层分析仍须完整输出，概要不得取代任何一层。

## （一）民事角度

聚焦电商/直播业务中的民事法律责任与争议风险：

# 事实与观点区分（强制规则）

本技能严格遵循以下原则：

1. **事实陈述须有印证**：企查查查询到的处罚/诉讼记录、工商登记信息，属客观事实，可径直陈述并标注来源与时间。
2. **法律分析须明依据**：风险判定、责任划分、违法可能性等属观点，必须写明所依据的法律规范与推理过程，不得包装为确定事实。
3. **MCP 核验优先**：法条有效性经华宇元典 MCP 核验；案例经 MCP 检索给出真实案号。未经核验的，明确标注"待人工复核"。
4. **风险常态化提示**：每一层的高风险项，除给出结论外，须同步提示不确定性及反向风险，避免绝对化。
5. **不预设立场**：除非用户明确指定代理某一方，本分析保持中立，呈现不同法律观点与可能结果。
