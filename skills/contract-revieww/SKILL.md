# 合同审查全流程 Skill

## 概览

本 Skill 实现律师/法务合同审查的完整工作闭环，分为六大模块：

```
模块 A：预检与信息收集      ← 开始，必须首先执行
模块 B：合法性审查          ← 核心审查层 1
模块 C：风险扫描            ← 核心审查层 2
模块 D：形式审查            ← 核心审查层 3
模块 E：报告整合与交付      ← 输出交付
模块 F：经验沉淀与 Skill 更新 ← 闭环收尾
```

**参考资料体系（审查过程中随时调用）**：
- `references/legal-kb.md` — 法律法规知识库（强制性条款、效力性规范）
- `references/risk-rules.md` — 风险扫描规则库（高/中/低风险条款配置）
- `references/review-checklist.md` — 合同审查要点知识库
- `references/client-preferences.md` — 我方客户习惯偏好模板
- `references/lawyer-tips.md` — 律师个人审查经验与习惯

> 以上参考文件由用户自行编写维护，放入 references/ 目录后，审查各阶段自动读取调用。

**报告pdf生成脚本**
- `scripts/generate_legal_pdf.py` — 将 E2 结构化 JSON 转换为正式的 PDF 报告，包含格式设计和排版。

## 模块 A：预检与信息收集

### A1. 文件预检

收到文件后，**立即执行**以下检查，任何一项失败则停止并告知用户：

**格式检查**：
- [ ] 文件是否为可解析格式（PDF / Word / TXT）
- [ ] PDF 是否为文字版（非扫描图片版）
- [ ] 文件是否可正常打开，无密码保护
- [ ] 文件是否完整（无截断、无乱码）

**内容预判**：
- [ ] 文件是否确为合同文本（而非其他法律文书）
- [ ] 合同语言（中文/英文/双语）
- [ ] 合同页数与体量（预估审查工作量）
- [ ] 合同类型初判（见下方合同类型表）

**合同类型识别表**（初步判断，影响后续审查侧重点）：

| 类型 | 关键词 | 审查侧重 |
|------|--------|---------|
| 买卖合同 | 货物、交付、价款 | 质量条款、验收、违约金 |
| 服务合同 | 服务内容、报酬、期限 | 服务标准、知识产权归属 |
| 劳动合同 | 劳动者、工资、工时 | 强制性条款合规 |
| 租赁合同 | 出租、承租、租金 | 押金、维修责任、提前解约 |
| 借款合同 | 借款、利率、还款 | 利率合规、担保条款 |
| 合作协议 | 合作、共同、分成 | 权责边界、利益分配 |
| 保密协议 | 保密、NDA | 保密范围、期限、违约责任 |
| 其他 | — | 通用审查 |

**预检失败处理**：
```
❌ 文件无法解析 → 告知用户："文件似乎无法读取，可能原因：[具体原因]。请尝试：[具体建议，如转换格式/去除密码/重新导出]"
❌ 疑似非合同文件 → 告知用户："当前文件看起来是[判断结果]，而非合同文本。请确认是否上传了正确文件？"
❌ 扫描件无法识别文字 → 告知用户："当前 PDF 为扫描版图片，无法直接读取文字。建议使用 OCR 工具转换后重新上传。"
```

### A2. 信息收集（用户交互）

预检通过后，**主动向用户提问**收集以下信息。提问要精炼，一次性列出所有问题，避免多轮打扰。

**必问信息**：

```
感谢上传合同！在开始审查前，请帮我确认几个关键信息：

1. **审查立场**：您代表哪一方？
   □ 甲方（[从合同中识别甲方名称]）
   □ 乙方（[从合同中识别乙方名称]）
   □ 第三方中立审查

2. **审查目的**：本次审查的主要目的是？
   □ 签约前风险把控（保护己方利益）
   □ 合规合法性确认
   □ 对方草案审核，需出修改意见
   □ 诉讼/争议背景下的证据梳理
   □ 其他：___

3. **业务背景**（选填，有助于提升审查精准度）：
   - 交易金额/合同标的大概是？
   - 双方关系（首次合作/长期合作/有历史纠纷）？
   - 是否有任何特别关注的条款或已知争议点？

4. **交付要求**：
   □ 审查报告（Word/PDF）
   □ 逐条批注意见
   □ 修改建议版合同
   □ 以上均需要
```

**信息收集后确认**：
收到用户回复后，回显信息确认：
```
✅ 审查信息已确认：
- 审查立场：[X方]
- 审查目的：[目的]
- 合同类型：[类型]
- 将同时参考：[列出 references/ 中找到的参考文件名]
- 预计输出：[交付物]

开始审查...
```

## 模块 B：合法性审查

> 读取参考文件：`references/legal-kb.md`（法律法规知识库）、`references/review-checklist.md`

**核心逻辑**：对照法律法规判断合同能否成立，结论非黑即白。

### B1. 合同主体合法性

- [ ] 合同主体是否具有相应民事行为能力
- [ ] 法人/非法人组织是否依法登记
- [ ] 代理人是否有授权委托书，授权范围是否覆盖本合同
- [ ] 特殊行业主体是否持有相应资质证照（如建筑资质、金融牌照等）
- [ ] 外资主体是否符合外商投资准入规定

**输出格式**：
```
【主体合法性】✅ 合规 / ⚠️ 存疑 / ❌ 违规
问题描述：___
法律依据：___
处理建议：___
```

### B2. 合同内容合法性

逐一检查是否存在违反强制性规定情形：

- [ ] 是否违反法律、行政法规的**效力性强制规范**（导致合同无效）
- [ ] 是否违反法律、行政法规的**管理性强制规范**（不导致无效，但有行政责任）
- [ ] 合同目的是否合法（是否以合法形式掩盖非法目的）
- [ ] 是否损害国家利益、社会公共利益或第三人利益
- [ ] 利率约定是否在法定范围内（借款合同）
- [ ] 劳动合同是否包含法定必备条款（劳动合同）
- [ ] 是否存在无效免责条款（造成对方人身损害/故意或重大过失）

**效力判定等级**：
```
【效力判定】
■ 合同整体效力：有效 / 效力待定 / 可撤销 / 无效
■ 无效/可撤销条款：[条款编号列表]
■ 法律依据：[具体法律条文]
■ 处理意见：[删除/修改/补充]
```

### B3. 特殊监管合规

根据合同类型，检查行业特定合规要求：
- 金融类：是否涉及无牌经营、利率红线
- 房产类：是否符合当地限购/预售规定
- 劳动类：工时、工资、社保强制条款
- 数据类：个人信息保护、数据跨境

## 模块 C：风险扫描

> 读取参考文件：`references/risk-rules.md`（风险规则库）、`references/client-preferences.md`（客户习惯）、`references/lawyer-tips.md`（律师tips）

**核心逻辑**：在合法前提下，从**己方利益**视角识别不利条款，按红/黄/蓝三级标注。

### C1. 风险等级定义

| 级别 | 标志 | 含义 | 处理优先级 |
|------|------|------|-----------|
| 高风险 | 🔴 红色 | 重大利益损失、权利严重失衡、争议高发 | 必须处理 |
| 中风险 | 🟡 黄色 | 存在不利因素，但尚可接受或可谈判 | 建议处理 |
| 低风险 | 🔵 蓝色 | 措辞模糊或有优化空间，影响有限 | 可选处理 |

### C2. 核心风险条款扫描清单

**违约责任条款**：
- [ ] 🔴 违约金金额是否过低（无法覆盖实际损失）
- [ ] 🔴 违约金赔偿上限是否不合理（如"最高不超过合同金额5%"）
- [ ] 🟡 违约认定标准是否对己方过于严苛
- [ ] 🟡 不可抗力范围定义是否过宽（对方可轻易免责）
- [ ] 🔵 是否缺少违约通知程序约定

**争议解决条款**：
- [ ] 🔴 仲裁/诉讼地是否在对方所在地（对己方造成诉讼不便）
- [ ] 🔴 约定仲裁机构是否合法有效（约定不明可能导致仲裁条款无效）
- [ ] 🟡 是否遗漏争议解决方式约定（默认诉讼，影响效率）
- [ ] 🔵 适用法律是否明确（涉外合同）

**保密条款**：
- [ ] 🔴 保密信息范围是否过于宽泛（己方正常经营行为受限）
- [ ] 🟡 保密期限是否合理（过长或缺少终止条件）
- [ ] 🟡 保密义务是否对双方不对等
- [ ] 🔵 是否缺乏保密违约责任约定

**担保条款**：
- [ ] 🔴 担保方式与担保范围是否明确
- [ ] 🔴 抵押/质押物描述是否清晰，登记手续是否约定
- [ ] 🟡 保证人主体资格是否合适
- [ ] 🟡 担保期间是否明确

**付款条款**：
- [ ] 🔴 付款节点是否与己方义务完成节点挂钩
- [ ] 🔴 逾期付款利息约定是否缺失
- [ ] 🟡 发票条款是否完整（发票类型/开具时间）
- [ ] 🔵 付款方式是否明确（银行转账/现金）

**知识产权条款**（服务类/合作类）：
- [ ] 🔴 成果归属是否明确（委托开发成果默认归受托方？）
- [ ] 🟡 背景知识产权授权范围是否合理
- [ ] 🔵 是否约定了保留许可

**合同解除条款**：
- [ ] 🔴 单方解除权条件是否对己方过于不利
- [ ] 🟡 解除后结算方式是否公平
- [ ] 🔵 是否约定解除通知期限

### C3. 风险扫描结果格式

每个风险点输出：
```
[风险编号] 🔴/🟡/🔵 [风险等级] — [条款位置]
▸ 风险描述：___
▸ 原文摘录：___（引用相关条款原文）
▸ 风险后果：___
▸ 修改建议：___
```

## 模块 D：形式审查

> 读取参考文件：`references/review-checklist.md`

### D1. 文字审查
- [ ] 错别字、异体字
- [ ] 语病、歧义表达
- [ ] 数字格式不统一（大写/小写/阿拉伯数字混用）
- [ ] 日期格式不统一
- [ ] 当事人名称前后不一致

### D2. 结构完整性审查

**必备条款核查**（根据《民法典》第470条）：
- [ ] 当事人名称/姓名和住所
- [ ] 标的
- [ ] 数量
- [ ] 质量
- [ ] 价款或报酬
- [ ] 履行期限、地点和方式
- [ ] 违约责任
- [ ] 解决争议的方法

**格式规范核查**：
- [ ] 条款编号是否连续、无跳号
- [ ] 定义术语是否在首次使用时定义，后续使用是否一致
- [ ] 附件清单与正文引用是否一致
- [ ] 签章页是否完整（双方盖章/签字处、日期）
- [ ] 骑缝章/页码是否提及（纸质合同要求）

### D3. 内部一致性审查
- [ ] 同一概念是否有多种表述（如"乙方"/"需求方"混用）
- [ ] 前后条款是否存在矛盾
- [ ] 数字金额大小写是否一致

输出顺序必须严格如下：
1. 先输出完整的自然语言审查报告
2. 再输出 JSON 数据
3. JSON 必须放在单独代码块中，便于程序直接提取
4. JSON 中不得出现注释、解释性文字或多余说明
5. JSON 内容必须与前文自然语言报告保持一致，不得互相矛盾

### E4. 版本管理与归档信息

### F1. 法律服务机会洞见

审查完成后，必须生成深度且结构化的**新业务机会提醒**，发给律师参考，坚决避免简短的一句话概述：

## 注意事项

1. **立场优先**：整个审查过程中，所有风险评估均以用户确认的审查立场为准。同一条款，从甲方和乙方视角的风险等级可能完全不同。

2. **参考文件缺失处理**：如果 references/ 中某个文件不存在，审查仍正常进行，对应模块使用内置通用规则，并在输出中注明"本次未检测到自定义[文件名]，已使用通用规则"。

3. **合同语言**：如遇英文合同，全程使用英文审查，最终报告可根据用户需求输出中文或英文版。

4. **免责说明**：本 Skill 辅助专业律师进行合同审查，不替代律师的专业判断，最终审查意见需由执业律师审核确认。
