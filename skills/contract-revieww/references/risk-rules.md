## 1. 风险等级定义与阈值

```yaml
风险等级:
  RED:  # 🔴 高风险
    定义: 存在重大利益损失风险、权利严重失衡、历史高争议条款
    处理: 必须修改，否则建议不签
    典型特征:
      - 己方主要权利被排除或严重限制
      - 赔偿责任上限设置明显过低
      - 单方随意解除权
      - 争议解决地明显不利

  YELLOW:  # 🟡 中风险
    定义: 存在不利因素，但尚在可接受范围或可通过谈判改善
    处理: 建议修改，如对方坚持需评估接受必要性
    典型特征:
      - 条款模糊可能导致争议
      - 义务不对等但尚可接受
      - 缺少重要保障性约定

  BLUE:  # 🔵 低风险
    定义: 措辞可优化，影响有限
    处理: 可选择优化，对交易影响较小
    典型特征:
      - 表述不够精确但不影响核心权利
      - 惯例上律师会建议优化的标准措辞
```

## 2. 通用风险规则

### 规则 G-001：权利义务不对等
```yaml
规则ID: G-001
名称: 权利义务严重不对等
触发条件:
  - 一方享有的单方权利（如单方修改价格、单方延期）对等一方无相同权利
  - 一方义务明显多于另一方
风险等级: YELLOW（通常）/ RED（严重失衡时）
审查动作: 识别所有"甲方有权…/乙方必须…"结构，检查是否存在对等条款
输出格式: 列出不对等条款及其位置
```

### 规则 G-002：定义缺失
```yaml
规则ID: G-002
名称: 关键术语未定义
触发条件: 合同中多次使用某专业术语/关键概念，但全文无定义
风险等级: BLUE（一般术语）/ YELLOW（核心概念）
```

### 规则 G-003：时间节点模糊
```yaml
规则ID: G-003
名称: 重要时间节点约定不明
触发条件:
  - 使用"尽快"、"及时"、"合理期限"等模糊表述
  - 关键节点（交付/验收/付款）未给出具体时间或计算方法
风险等级: YELLOW
修改建议: 替换为具体天数或明确起算点
```

## 3. 违约责任条款规则

### 规则 V-001：违约金上限过低
```yaml
规则ID: V-001
名称: 违约金/赔偿上限设置不合理
触发条件:
  - 赔偿责任最高上限低于合同金额的 10%
  - 存在"赔偿上限为[X]元"且金额明显偏低
  - 使用"不超过合同金额的[N]%"，N < 10
风险等级: RED
修改建议: 删除赔偿上限，或提高至合同金额100%以上；至少应覆盖实际可能损失
```

### 规则 V-002：违约金标准缺失
```yaml
规则ID: V-002
名称: 缺少违约金约定
触发条件: 合同无违约金条款，也无损失赔偿计算方式
风险等级: YELLOW
修改建议: 补充违约金条款，建议按合同金额或日万分之五的逾期违约金
```

### 规则 V-003：不可抗力范围过宽
```yaml
规则ID: V-003
名称: 不可抗力定义过于宽泛
触发条件:
  - 不可抗力定义包含"政策变化"、"市场波动"、"疫情"等主观情形
  - 允许一方自行认定不可抗力
风险等级: YELLOW
修改建议: 不可抗力限于自然灾害、战争等客观不可预见情形，政策变化等应另行约定
```

### 规则 V-004：违约认定标准苛刻
```yaml
规则ID: V-004
名称: 对己方违约认定标准过于苛刻
触发条件:
  - 轻微违约即触发重大违约责任
  - 无宽限期/整改期约定
  - 对方享有不经通知直接解除并索赔的权利
风险等级: RED（无宽限期+直接解除）/ YELLOW（仅标准苛刻）
修改建议: 增加违约通知和合理整改期（通常5-30个工作日）
```

## 4. 争议解决条款规则

### 规则 D-001：管辖地明显不利
```yaml
规则ID: D-001
名称: 诉讼/仲裁地不利于己方
触发条件:
  - 约定在对方住所地/注册地法院诉讼
  - 约定在异地（己方所在地以外）仲裁
风险等级: RED
修改建议: 争取改为己方所在地法院，或约定原告就被告原则，或争取中立地点仲裁
```

### 规则 D-002：仲裁条款效力存疑
```yaml
规则ID: D-002
名称: 仲裁协议效力存疑
触发条件:
  - 仲裁机构约定不明确（如"由仲裁委员会仲裁"而未指定具体机构）
  - 既约定仲裁又约定诉讼（可能导致仲裁条款无效）
  - 仲裁地点与仲裁机构所在地不一致（可能引发争议）
风险等级: RED（可能导致争议解决机制失效）
修改建议: 选择具体仲裁机构并完整书写机构全称，不要同时约定仲裁和诉讼
```

### 规则 D-003：缺少争议解决条款
```yaml
规则ID: D-003
名称: 未约定争议解决方式
触发条件: 合同无任何争议解决条款
风险等级: YELLOW
修改建议: 建议补充，可选择：诉讼（指定管辖法院）或仲裁（指定机构+规则）
```

## 5. 保密条款规则

### 规则 C-001：保密范围过宽
```yaml
规则ID: C-001
名称: 保密信息范围定义过于宽泛
触发条件:
  - 保密信息包含"所有与合同相关的信息"
  - 已进入公众领域的信息仍被列为保密
  - 无"保密信息排除"条款（公开信息、已知信息、独立开发信息等）
风险等级: RED（对己方）
修改建议: 明确限定保密信息范围，增加合理例外情形（已公开/独立研发/法律要求披露）
```

### 规则 C-002：保密义务不对等
```yaml
规则ID: C-002
名称: 保密义务设置不对等
触发条件:
  - 仅一方负有保密义务
  - 保密期限双方不一致
风险等级: YELLOW
修改建议: 争取双方对等保密义务
```

### 规则 C-003：保密期限缺失或不当
```yaml
规则ID: C-003
名称: 保密期限未约定或设置不当
触发条件:
  - 无保密期限约定（永久保密负担过重）
  - 保密期限超过5年（通常合理范围）
风险等级: YELLOW
修改建议: 约定合理保密期限（通常2-3年），核心商业秘密可适当延长
```

## 6. 担保条款规则

### 规则 G-001：担保物描述不清
```yaml
规则ID: GU-001  
名称: 抵押/质押物描述不明确
触发条件:
  - 抵押物无详细描述（地址/面积/权证号等）
  - 质押物无具体清单
  - 未约定担保登记手续
风险等级: RED（担保可能无效）
修改建议: 详细描述担保物，明确办理登记的时间和责任方
```

### 规则 GU-002：担保范围不明
```yaml
规则ID: GU-002
名称: 担保范围约定不清
触发条件:
  - 未明确担保是否覆盖利息、违约金、实现担保权利费用
  - 最高额担保未明确最高限额
风险等级: YELLOW
```

## 7. 付款条款规则

### 规则 P-001：付款节点未与履行挂钩
```yaml
规则ID: P-001
名称: 付款节点设计对己方不利
触发条件（若己方为收款方）:
  - 付款条件为"对方单方确认"，无客观标准
  - 全部款项在服务开始前支付（资金风险）
  - 付款节点在交付验收后大幅延迟（资金占用）
风险等级: RED（付款条件完全依赖对方）/ YELLOW（其他情形）
修改建议: 建议付款与里程碑/验收直接挂钩，设置合理账期
```

### 规则 P-002：逾期付款责任缺失
```yaml
规则ID: P-002
名称: 缺少逾期付款违约金
触发条件: 合同无逾期付款利息/违约金约定
风险等级: YELLOW（己方为收款方时）
修改建议: 补充逾期利息条款，建议参考同期LPR计算
```

### 规则 P-003：发票条款缺失
```yaml
规则ID: P-003
名称: 发票开具条款缺失
触发条件: 涉及税务发票义务，但合同无发票类型/开具时间/不开具的后果约定
风险等级: YELLOW
修改建议: 明确发票类型（增值税专用/普通）、开具时间和税率
```

## 8. 知识产权条款规则

### 规则 IP-001：成果归属不明
```yaml
规则ID: IP-001
名称: 合同成果知识产权归属不明确
触发条件:
  - 涉及创作/开发/设计类服务，无知识产权归属约定
  - 仅约定"归属合同方"但未指明是哪方
风险等级: RED
修改建议: 明确约定合同成果（含中间成果）归属，或约定许可使用方式
```

### 规则 IP-002：背景知识产权未区分
```yaml
规则ID: IP-002
名称: 未区分背景知识产权与前景知识产权
触发条件: 合同未明确各方带入的既有知识产权范围及授权条件
风险等级: YELLOW（长期合作/高价值项目时为RED）
```

## 9. 合同解除条款规则

### 规则 T-001：单方随意解除权
```yaml
规则ID: T-001
名称: 对方享有宽泛的单方解除权
触发条件:
  - 对方可无需理由单方解除合同
  - 解除后赔偿责任极低（如仅退款）
  - 无合理预告期
风险等级: RED
修改建议: 限定单方解除条件，设置合理预告期（通常30-90天），约定合理补偿
```

### 规则 T-002：解除后结算不公平
```yaml
规则ID: T-002
名称: 解除后结算条款对己方不利
触发条件:
  - 解除后已完成工作/服务无对应报酬
  - 解除后损失计算方式不明确
风险等级: YELLOW
修改建议: 约定解除后按比例结算已完成部分
```

## 10. 外包/人力资源服务类合同专项规则

> 本节规则来源于管理咨询服务协议（含劳务外包、人力资源服务、驻场管理类合同）的实践审查积累。
> 此类合同核心法律风险在于：**混同雇主责任**、**收费计算透明度**、**甲方单方控制权过度**。

### 规则 HR-001：劳动关系性质认定风险
```yaml
规则ID: HR-001
名称: 合同实质可能构成劳务派遣或事实劳动关系
触发条件:
  - 乙方负责"人员招聘、面试、培训、日常技术指导、运营管理"
  - 人员在甲方现场工作，遵守甲方考勤、纪律、信息安全等制度
  - 甲方可直接对人员进行考核、处罚、要求整改
  - 人员工资由甲方核定清单后由乙方发放
  - 合同名称为"管理咨询"但实质为劳动力供给
风险等级: RED
风险说明: >
  若被认定为劳务派遣，须符合《劳动合同法》第57-67条规定：
  劳务派遣单位须持有《劳务派遣经营许可证》；
  派遣岗位须为"临时性、辅助性或替代性"岗位；
  比例不得超过用工单位总人数10%。
  若被认定为事实劳动关系，甲方将承担用人单位责任，
  包括但不限于经济补偿金、社保、劳动仲裁等。
审查动作:
  - 核查乙方是否持有《劳务派遣经营许可证》
  - 核查合同性质定性（咨询/外包/派遣）与实际安排是否一致
  - 关注甲方对"标的项目人员"的直接管控程度
修改建议: >
  若确为劳务外包：合同中应明确乙方对人员的独立管理权，
  甲方通过乙方管理人员而非直接管理；
  若为劳务派遣：须补充派遣许可证编号，确认岗位符合三性要求。
```

### 规则 HR-002：服务费计算公式风险
```yaml
规则ID: HR-002
名称: 服务费计算依赖甲方单方数据，乙方缺乏核查权
触发条件:
  - 服务费 = f(甲方收到的收入) - 人力成本，收入数据由甲方单方提供
  - 合同无乙方对收入数据的核查权或异议机制
  - "甲方收到款项后10个工作日内支付"但收款时间甲方单方掌握
  - 收费基数为"不含税收入×90%"，折扣原因未说明
风险等级: RED
风险说明: >
  服务费直接挂钩甲方自报收入数据，甲方有动机低报收入或延迟确认，
  乙方在收费核算上完全处于信息弱势地位。
  此外"×90%"条款未解释为何扣减10%，乙方实际利润空间极度压缩。
审查动作:
  - 检查合同是否有乙方查阅甲方对应账目的权利
  - 检查结算清单提供义务和时间节点是否明确
  - 计算在最坏情形（收入低/人力成本高）下服务费为负值的可能性
修改建议: >
  建议增加：①甲方须在每期结算时提供经审计或盖章确认的收入明细；
  ②乙方有权对收入数据提出异议并要求提供原始合同/发票；
  ③"×90%"折扣明确为覆盖甲方运营成本并书面约定计算方式。
```

### 规则 HR-003：服务费为负值时乙方补款义务
```yaml
规则ID: HR-003
名称: 服务费负值条款——乙方承担经营亏损风险
触发条件:
  - 存在"服务费为负值时乙方按通知补足"条款
  - 乙方收入直接与甲方上游收入绑定，但甲方市场拓展风险不受控
风险等级: RED
风险说明: >
  乙方不仅无法保证最低收益，在甲方收入下降时还须倒贴补款。
  实质上乙方承担了甲方的经营风险，而非提供独立管理咨询服务。
  此条款与咨询服务合同的有偿独立服务性质相悖。
修改建议: >
  建议删除负值补款义务；
  或约定：服务费最低不低于[X]元/月，确保乙方基本成本覆盖；
  至少增加：负值情形发生时双方有权协商调整合作方案，
  而非乙方单方承担无上限补款义务。
```

### 规则 HR-004：甲方解除权条件过宽
```yaml
规则ID: HR-004
名称: 甲方单方解除权条件数量多、标准主观
触发条件:
  - 甲方解除权触发条件包含"评估不合格"（甲方自评）
  - 解除权触发条件包含"乙方卷入诉讼"（不论诉讼与本合同是否相关）
  - 解除权触发条件包含主观性表述如"给甲方品牌形象造成严重损害"
  - 解除可"立即"生效，无预告期
风险等级: RED
修改建议: >
  建议将主观解除条件限定客观标准，如"连续[N]期考核低于[X]分"；
  "卷入诉讼"应限定为"与本合同直接相关的诉讼且已生效判决认定乙方违约"；
  增加解除前合理预告期（建议30个工作日）及整改机会；
  甲方行使解除权应向乙方支付合理补偿（已服务部分的未结算款项）。
```

### 规则 HR-005：标的项目员工争议全部由乙方承担
```yaml
规则ID: HR-005
名称: 员工劳动争议责任全部转移至乙方，包括甲方行为导致的争议
触发条件:
  - "标的项目员工与甲方产生的所有争议均由乙方承担"
  - 甲方向员工支付的绩效奖金、加班工资、年假、社保均由乙方埋单
  - 甲方可从应付服务费中直接扣除上述费用，无需经乙方确认
风险等级: RED
风险说明: >
  若员工争议由甲方行为直接引发（如甲方指令违规操作、甲方克扣奖金），
  让乙方承担全部责任显失公平，且可能导致乙方无上限的连带赔偿风险。
  直接从服务费扣款条款使甲方可单方核定损失金额，乙方无异议权。
修改建议: >
  建议区分责任归属：因乙方原因引发的争议由乙方承担；
  因甲方指令/管理行为引发的争议由甲方承担；
  扣款前须经双方书面确认损失金额，乙方有5-10个工作日异议期。
```

### 规则 HR-006：甲方对人员的直接管控条款
```yaml
规则ID: HR-006
名称: 甲方直接管控乙方人员，架空乙方管理权
触发条件:
  - 甲方可直接制定并修改适用于乙方人员的规章制度
  - 制度修改后"5个工作日后生效"，乙方无拒绝权
  - 甲方对人员考勤、纪律有直接管理权
  - 甲方可要求乙方对人员进行整改甚至驱离
风险等级: YELLOW
风险说明: >
  乙方作为独立服务方，其人员管理权被甲方实质架空；
  若甲方制度违法（如要求超时工作），乙方须执行但须承担违法后果。
修改建议: >
  建议约定：甲方制度若违反劳动法规，乙方有权拒绝执行并书面告知；
  乙方管理人员有权就甲方制度合法性提出异议；
  甲方不得直接对乙方人员发出具有法律约束力的指令，须通过乙方管理层传导。
```

### 规则 HR-007：竞业协议禁止条款的处理
```yaml
规则ID: HR-007
名称: 甲方不得以竞业协议限制乙方人员离职
触发条件:
  - 合同明确约定"甲方不得以竞业协议限制乙方人员离职"
风险等级: BLUE（对乙方有利，需确认）
审查动作: >
  此条款对乙方有利，应确保保留。
  同时核查：甲方现有竞业限制安排是否与此条款冲突；
  乙方人员入职甲方客户方时是否适用本条款。
```

### 规则 HR-008：人员平稳转移条款
```yaml
规则ID: HR-008
名称: 乙方成为客户方供应商后人员转移义务
触发条件:
  - 合同约定"乙方成为客户方合格供应商后，甲方须无条件配合人员转移"
  - 此条款对乙方有利，但表述是否具体可执行
风险等级: YELLOW（对乙方有利但执行风险存在）
审查动作: >
  核查"无条件配合"的具体操作程序是否约定：
  转移时间表、人员意愿处理、劳动关系衔接（工龄连续性）、
  甲方是否需支付配合转移期间的费用。
修改建议: >
  建议补充：转移启动条件（乙方取得供应商资格后[X]日内启动）；
  明确转移期间双方的费用承担；确认工龄延续性的具体安排。
```

### 规则 HR-009：服务费计算中增值税处理
```yaml
规则ID: HR-009
名称: 费用计算中含税/不含税口径混用
触发条件:
  - 服务费计算公式中基数为"不含税收入×90%"
  - 但减除的人力成本（工资/社保）为实发金额（通常不含税）
  - 最终服务费乘以"1.06"（6%增值税率）
  - 乙方须提供6%税率增值税专用发票
风险等级: YELLOW
风险说明: >
  税务处理口径需仔细核查：乙方提供的是管理咨询服务，
  一般纳税人适用6%增值税率；小规模纳税人适用3%（或征收率）。
  若乙方为小规模纳税人，合同约定的6%发票无法开具。
审查动作:
  - 核查乙方增值税纳税人身份（一般/小规模）
  - 确认能否开具6%税率的增值税专用发票
  - 核算含税/不含税口径的实际净利润
修改建议: >
  明确约定乙方的纳税人身份及可开具的发票类型；
  若乙方为小规模纳税人，调整计算公式及税率约定。
```

### 11.3 IT服务/人力外包行业——实战补充规则

> 来源：2026年4月《管理咨询服务协议》（甲：京北方信息技术股份有限公司 / 乙：北京小时领先科技有限公司）中立审查后总结。

```yaml
规则ID: IT-OPS-001
名称: "背靠背"付款无最长兜底期
触发条件:
  - 付款条件为"甲方收到客户款项后N个工作日内支付"
  - 无"无论客户是否付款，甲方最迟于X日支付"兜底条款
  - 乙方实际为用人单位，须每月垫付工资
风险等级: RED
风险说明: >
  外包/派遣性质合同中，乙方须按时发放人员工资（法定义务），
  而甲方收款时间由上游客户决定，可能无限期拖延。
  一旦上游客户拖付，乙方将面临无资金来源却须垫付工资的两难处境，
  极易引发群体性讨薪事件及劳动仲裁连锁风险。
修改建议: >
  无论甲方是否按时收到客户款项，
  甲方至迟不应晚于结算周期届满后的[20]个工作日向乙方支付完毕；
  超期不付的，乙方有权暂停提供服务并按日收取逾期利息。
```

```yaml
规则ID: IT-OPS-002
名称: 保密违约金与实际业务规模严重失衡
触发条件:
  - 固定违约金设定为100万元及以上
  - 合同性质为管理咨询/人力服务，非涉密技术项目
  - 违约金与合同实际标的（人力成本）不成比例
风险等级: RED
风险说明: >
  对于管理咨询/人力外包类合同，100万元保密违约金在司法实践中
  极易被法院认定为"约定违约金过高"并予以调低（《民法典》第585条）。
  设置虚高违约金实际无法执行，反而影响己方违约金约定的可执行性。
修改建议: >
  建议修改为"赔偿因保密违约实际造成的损失"；
  或设定合理的固定违约金（如人力成本的1-3个月），
  并明确可叠加主张实际超出损失的权利。
```

```yaml
规则ID: IT-OPS-003
名称: 解除后补偿公式约定不明确
触发条件:
  - 合同约定解除时乙方获赔"标的项目人员工资+奖金+五险一金×6"
  - 但未约定：触发时的人员规模如何确认、奖金如何计算基准
  - 未约定甲方正常经营情况下的最低赔付保障
风险等级: YELLOW
修改建议: >
  约定补偿计算基准期（如解除前3个月的平均月度人力成本）；
  明确"6"的含义（6个月补偿）；
  在合同附件中列明当前人员清单作为计算基准。
```
