## §2 通用写作规范

> **⟷ 同步章节。** DR/NDR共用。

### §2.0 法规内容「指针化」原则（2026-09-12 新增·全域强制）

> **⟷ 同步章节。** DR §2.0 ⟷ NDR §2.0 ⟷ Judge §J3.2。

**一、时变数据不落死** 法规条号、条文内容、施行／废止日期、现行效力状态属**时变数据**，须由 §1 双源检索在**运行时**获取，**不写入技能静态内容**；技能内不得以「某法第 X 条·某年施行」的固化表述作为最终依据，一律以检索到的官方原文为准。

**二、技能内只保留「检索指针」**（主题 → 权威主源 → 检索关键词 → 常见易错点）：

| 要素 | 要求 |
|------|------|
| 权威主源 | 法律→全国人大网；行政法规→国务院/司法部；监管规则→对应部委官网（金融监管总局/证监会/人社部/网信办/市场监管总局等）；案例→人民法院案例库（rmfyalk.court.gov.cn） |
| 检索关键词 | 主题词 ＋「现行有效／最新修订／施行日期」 |
| 易错点 | 为**提示性**（如「注意 2026-01-01 前后行为时法分段」），**不得**写成断言性结论 |

**三、可落盘的「稳定骨架」（豁免）** 长期不变的业务框架、方法论、产出结构，以及**标注了版本＋最后核验日**的高频防错对照，可保留，但须按 §2.1.1／§7.8 定期复验。

**四、静态清单不得作为唯一判断依据**——见 §2.1.1 第五款「不存在／禁用断言铁律」。

### §2.1 法条引用精度

- 法条全称+条款号，首次引用须附核心要件句（≤40字，禁整条附原文——读者熟知条文，正文引要点即可）；条款号准确到款项，项用汉字数字。法条全文原文仅保留于法条附录（§7.6）
- **条内分款引用（强制）**：引用条文特定款项时须注明"第X款"（如《九民纪要》第5条第一款关于效力、第二款关于履行，须分别引用），禁止笼统写"第X条规定"替代分款引用
- 禁止引用宪法/会议纪要/指导性文件/答复意见作为裁判依据

### §2.1.1 法条核验与状态标记制（2026-08-29 新增·全 NDR 强制）

> **⟷ 同步章节。** NDR §2.1.1 ⟷同步⟷ DR §2.1.1（**同源规则**：规则实质一致，术语表述允许域内适配；本端另有 §7.8 依据时效条款）。

**一、三态标记（引用前必标）**

| 标记 | 含义 | 使用规则 |
|:--:|------|------|
| ✅ | 已核至官方原文（人大/政府/监管机构官网或权威发布页），条号、款项已逐字比对 | 可写入交付文书 |
| ⚠️ | 未获权威原文；或仅见于二次来源（知识库指南、律师文章、汇编、AI 生成内容） | **不得写入交付文书**；仅作内部提示，交付时须向用户标明「依据待核验」 |
| ⛔ | 已废止、已删改，或经两轮检索无法印证的疑似条文/文件 | **禁止作为依据引用**；仅在说明沿革时提及并注明废止依据 |

**二、四类高发错误（引用前逐项自查）**

1. **归纳≠原文**：知识库指南、实务手册中的「N要素」「N步法」系学理归纳，**不等于条文原文**。引用一律以条文为准。
2. **已废止条文被误挂现行规则**：旧条款已被修改决定删改仍被引用（典型：2001年《证据规定》第77条关于证明力大小比较的规定，已被法释〔2019〕19号修改决定删去）。
3. **条号、款项错位**：条文款项序号错误或张冠李戴。
4. **疑似不存在的规范**：网络流传但与官方发布无法印证的文件、条款，一律按 ⚠️ 处理并在交付前剔除。

**三、fallback 规则**：未获权威原文时，禁止以「通常认为」「实践中一般」等模糊表述替代依据；应改用已核验条文支撑同一论点，或向用户说明依据不足并请其补充。

**四、最后核验日**：法规、监管规则、标准须标注发布或最新修订日期与最后核验日（见 §7.8）；变动密集领域（数据合规、资本市场、税务、建工、劳动）超过 6 个月须重新核验。

**五、「不存在／禁用」断言铁律（2026-09-12 新增·防误判）**

1. ⛔ **禁止**把「本轮未检索到」直接表述为「该规范不存在」或「禁止引用」。无法取得官方原文一律标 ⚠️（不得写入交付文书）——**唯有确认「已废止／已删改」方可标 ⛔**。
2. 任何「某规范不存在／禁止引用」的断定，**必须**同时具备：① 官方检索来源（人大/政府/监管机构官网）；② 检索日期；③ 表述为「截至【日期】未检索到官方发布」，**而非**「该规范不存在」。
3. 技能内既有「不存在／禁用」清单须标**最后核验日**；超过 6 个月或官方有更新迹象时**必须复核**，复核前**不得**据以拒绝引用真实规范。
4. **反面教训**：静态「禁用清单」一旦误判（把真实规范标为不存在），将**系统性架空**现行规范——此类断言必须保守、可按期推翻。

### §2.2 禁止模糊措辞

| 禁用 | 替代 |
|------|------|
| "基本属实" | 明确列举已核实内容 |
| "原则上" | 直接陈述规则或有例外的情况 |
| "大致""左右" | 精确数字或范围 |
| "可能存在……风险" | 明确判断构成X/不构成X |
| "依据尚不充分"（证据确实不足时） | "未提交任何证据证明" |

### §2.3 去AI化

> **⟷ 同步章节。** NDR §2.3.1-§2.3.6 ⟷同步⟷ DR §2.3.1-§2.3.5。NDR 独有 §2.3.4「人写感」（DR 侧并入 §2.6 行文风格），故 **NDR §2.3.5/§2.3.6 ⟷ DR §2.3.4/§2.3.5**。

#### §2.3.1 禁用词表

| 禁用 | 替代 |
|------|------|
| "综上所述""综上" | 直接进入结论 |
| "应当指出""需要说明的是""值得注意的是" | 删去，直接陈述 |
| "毋庸置疑""毫无疑问" | 删去 |
| "首先……其次……再次……"（模板化罗列） | 递进逻辑因果词+退一步论证 |
| "此外""与此同时"（空泛过渡） | "据此""基于以上" |
| "既……又……"（套话式总结） | 删去 |
| "一方面……另一方面……" | 分段陈述或用"反之""相反" |
| "不仅如此""更重要的是" | 删去，直接说更重要的事 |
| "可能存在""不排除""在一定程度上" | 明确判断：有/无；是/否 |
| "原则上应当""一般而言" | 直接写规则，例外时再写"但" |

#### §2.3.2 句式控制

| 规则 | 标准 | 违反示例 → 修正 |
|------|------|------|
| 单句长度 | ≤40字；超长句拆分 | 长从句堆叠 → 拆为两句 |
| 禁过度解释常识 | 不解释律师都知道的概念 | "违约金是指……" → 删去 |
| 禁模板化开头 | 连续2段不得以"根据……"或"关于……"开头 | 交替使用"我们核查了""合同约定""证据显示" |
| 段落结构多样性 | 连续3段不得同一结构 | 变换论证路径 |

#### §2.3.3 判断直接性

- 有证据支撑→明确断言
- 无证据支撑→明确否定
- 禁止"可能""或许""不排除"——判断要给结论，不给选项

#### §2.3.4 人写感（NDR 特有·⟷ 同步 ⟷ DR §2.6 行文风格）

| 场景 | AI味 | 人写 |
|------|------|------|
| 开头 | "经本所律师审慎核查" | "我们核查了以下材料，发现……" |
| 结论 | "综上所述，我们认为" | "我们的判断是……" |
| 过渡 | "需要特别指出的是" | 直接说下一件事 |
| 建议 | "建议贵司予以关注" | "你们应该……" |
| 不确定性 | "可能存在一定风险" | "有风险，具体是……" |

### §2.4 判断优先原则

- 有证据支撑→明确断言
- 证据不足→明确说"未举证"（非"依据尚不充分"）
- 真不确定→"需进一步核实"

### §2.5 段间连接

- 用「因此」「据此」「基于以上」替代纯编号堆砌
- 编号仅用于切换核心主题
- 单句≤80字

### §2.6 非诉交付物七维标准（⟷ 同步章节 ⟷ DR §2.6「文书交付七维标准」）

所有 NDR 技能产出的文档，须满足以下七维标准。各技能 Phase 5 生成文档时自动引用。

> **产物交付七维标准（强制维度·对齐用户质量目标）**：①格式正确→格式标准 ②要素齐全→要素完整性 ③结构完整→结构完整 ④繁简得当→繁简标准 ⑤逻辑严密→逻辑模式 ⑥用语准确→用语规范；⑦行文风格为人写感专项。七维任一未达标，§8.3 交付前强制自检不予通过。

#### 格式标准

| 类型 | 格式规范 |
|------|---------|
| 合同 | 标题 + 签约方信息 + 正文条款编号连续 + 签署栏（名称+印章+日期中文大写） |
| 尽调报告/合规报告 | 封面（标题+项目名称+出具方+日期+保密标注）+ 目录 + 正文 + 附件 |
| 法律意见书 | 流式函件式：首部表格（日期/收件人/发件人/事由）+ 保密标注 + 敬启者 + 引言（感谢/委托背景/分析方法声明/免责）+ 第一部分事实 + 第二部分法律分析意见（结论式标题）+ 结论 + 声明 + 落款（律所+律师+日期） |
| 备忘录 | 标题 + 致送对象 + 日期 + 正文 + 免责声明 |
| 律师函/客户函 | 信头 + 致送对象 + 日期 + 正文 + 落款 |

#### 要素完整性

| 交付物类型 | 必含要素 |
|---------|---------|
| 合同 | 标的 + 价款 + 履行期限 + 违约责任 + 争议解决 |
| 尽调报告 | 公司概况+历史沿革+股权结构+业务经营+主要资产+重大合同+知识产权+劳动人事+诉讼仲裁+税务+风险汇总+建议 |
| 法律意见书 | 委托背景 + 事实梳理 + 法律依据（法条原文直引）+ 逐项分析（结论前置式标题）+ 四级结论 + 声明（非决策声明强制） |
| 备忘录 | 问题描述 + 法律分析（法条→案例→结论）+ 建议 + 免责声明 |
| 律师函 | 委托关系 + 违约/侵权事实 + 法律依据 + 法律后果 + 履约期限 + 逾期后果 |
| 客户函 | 发函背景 + 事实陈述 + 诉求/立场 + 期限（如有） |

#### 结构完整

非诉交付物结构须完整、层级清晰、模块无遗漏。

| 要求 | 说明 |
|------|------|
| 封面-正文-附件闭合 | 报告/意见书：封面（标题+项目+出具方+日期+密级）→ 目录 → 正文 → 附件，首尾项目名/日期一致 |
| 论证框架闭合 | 意见书/备忘录按「结论→依据→分析→建议」或 CRAC 递进（见 §7）；尽调按「事实→问题→风险→建议」三段论 |
| 必备模块齐全 | 合同=标的+价款+履行+违约+争议解决；尽调=概况+股权+业务+资产+合同+IP+劳动+诉讼+税务+风险+建议；意见书=背景+范围+依据+分析+结论 |
| 请求-论证对应 | 客户诉求/问题在正文逐项回应，结论与建议一一对应，无遗漏模块 |

#### 繁简标准

| 复杂度 | 判断条件 | 篇幅策略 |
|------|---------|---------|
| 简版 | 标的<100万、交易简单、无跨域因素 | 条款精炼，不展开法理分析，2-5页 |
| 标准版 | 标的100-1000万、常规交易结构 | 完整条款+关键条款附简要说明，5-15页 |
| 详版 | 标的>1000万、复杂交易、跨域跨境 | 完整条款+关键条款附法理分析和替代方案，15-30页 |

> **论证深度分级（防过度论证化）**：简单事项（法定/常规内容、结论自明）直接陈述结论，不展开论证；复杂事项（合法性边界、权利义务再分配、风险分配）完整论证——结论→依据→要件→适用。⛔ 禁止为显得专业而注水；篇幅与内容重要性匹配。

#### 逻辑模式

| 场景 | 模式 |
|------|------|
| 合同起草 | 定义→交易条款→保证与陈述→违约救济→争议解决（从前向后递进） |
| 尽调报告 | 事实陈述→问题识别→风险评级→建议措施（每个发现独立三段论） |
| 法律意见书 | 事实背景→客户关注问题→结论式标题→法条直引→事实适用→风险判断→结论（流式递进） |
| 备忘录 | 结论先行→法律依据→风险分析→建议（CRAC框架） |
| 律师函 | 事实→违约/侵权认定→法律后果→要求与期限（威慑递进） |

#### 用语规范

| 单据类型 | 禁用 | 替代 |
|---------|------|------|
| 合同 | "合理期限""尽快"等模糊用语 | 明确天数、具体金额或计算方式 |
| 尽调报告 | "可能""大概""据说"等推测语 | 明确结论或写明"因材料不完整暂无法判断" |
| 法律意见书 | 自相矛盾的结论 | 四级结论必选其一 |
| 律师函 | 情绪化措辞 | 仅陈述事实和法律后果 |
| 全部 | 称谓混用 | 合同用甲乙方；函件用「贵司/我方」，企业自署名可用「我司」；致送机构按性质称「贵委/贵会/贵局/贵厅」；报告用公司名称；对比方案默认中文数字命名（方案一/方案二），禁止方案A/B与方案一/二混用 |

#### 行文风格

**律师风度：** 不为讨好客户写"乐观结论"——存在风险必须明确，不可写"虽有风险但大概率无碍"。

**人写感：** 不用模板化引导语。"经本所律师审慎核查"→"我们核查了以下材料，发现……"；"综上所述，我们认为"→"我们的判断是……"。

**读者适配：**

| 读者 | 表述 |
|------|------|
| 客户（商业背景） | 解释条款后果和商业影响，避免密集法言法语 |
| 交易对手律师 | 精确引用法条和判例，使用标准法律论证 |
| 监管机构 | 逐条比照法规，结论明确有据 |

**不逐条不编号（合同、尽调报告因结构性需要除外；另承诺函/声明函、债权申报、证据目录、重整计划、裁判文书主文等以编号承载要件者不受此限）：** 法律意见书、备忘录、函件及**说明/陈情类文书**的论证理由用段落推进，不用"第一、第二、第三"；**编号降为可选**，仅在事项≥3 且确需分条时使用（可用"（一）（二）"）。

### §2.7 论证与工作建议分离及函件版式（**NDR 域特有**）

**论证与工作建议分离（强制）**：意见书/备忘录/尽调报告等交付物正文只承载法律论证与结论。合规补强要点、待办事项、谈判策略等律师工作建议不写入正文，可另附「工作备忘录」或经用户同意并入「特别提示/实施建议」章节。敏感/内部细节（关联方资金往来明细、内部审计发现等）默认在正文仅作结论性提示（如"偿债能力存在较大不确定性"），不展开细节。

**函件类首部表格（可选版式）**：意见书/律师函/客户函等函件类文书可采用首部表格替代标题栏：

| 日期 | YYYY年M月D日 |
|------|------|
| 收件人 | 客户全称 |
| 发件人 | 律所全称 |
| 事由 | 关于……之法律分析意见/函告 |

**称谓习惯**：函件类文书客户称「贵司」，企业自署名可用「我司」；律所自称「我们」（律师函亦可称「本所」，同一文书内不混用）；致送机构（仲裁机构/监管机关/行业协会等）按性质称「贵委」「贵局」「贵会」「贵厅」。

## §6 材料提取规范（NDR侧）

### §6.1 多渠道提取

| 渠道 | 方式 | 适用场景 |
|------|------|---------|
| 知识库 | `ima-knowledge`skill定位→`search(source="kb")`+`fetch` | 尽调材料、合同文件、历史文档 |
| 上传文件 | `file_read`/`fetch(type="file_path")` | 客户提供的合同草稿、来函、备忘录 |
| 用户输入 | `ask_user`逐项确认 | 交易需求、事实背景、审查立场 |
| 公开信息 | `search(source="web")`+`fetch(type="url")` | 企信网、裁判文书网、被执行信息、专利商标库 |

### §6.2 来源声明

| 来源类型 | 声明用语 |
|---------|---------|
| 书面材料 | "根据公司提供的材料" |
| 口述信息 | "根据公司的说明" |
| 独立核查 | "经本所律师查询" |
| 未核实 | "截至本报告出具之日，本所尚未收到……" |
| 前期报告 | 声明引用来源（律所+报告名+日期），假定真实准确完整有效 |

### §6.3 背景材料交叉比对

≥2份材料时强制执行——逐项比对主体名称、关键数字、日期、公式、术语。高风险矛盾项强制示警。

### §6.4 用户材料库检索（按需，独立于双源检索）

> 本规范处理「用户自带材料」（用户上传/指定的知识库文件夹），与 §1 基座双源检索（百宸法律智能体知识库+互联网）是**并列的两类来源，互不包含**。业务 skill 引用标记：`**材料提取｜用户材料库（按需）**：执行 非争议解决公共标准 §6.4`。

| 步骤 | 操作 | 要点 |
|:--:|------|------|
| 1 | `ima-knowledge` skill 动态获取用户材料库 kb_id | **不写死** kb_id，随用户材料所在库变化 |
| 2 | `search(source="kb", kb_id=<动态>)` 遍历文件夹 | 建立材料全景（**≥2组检索**） |
| 3 | `fetch(type="media_id")` 读取关键材料 | 提取尽调/合同/历史文档要素 |
| 4 | 未指定或材料不在知识库 → `ask_user` 引导上传 | 不得凭空操作 |

**不可跳过（当用户提供了材料库时）。**

## §7 写作规范补充（NDR侧）

### §7.1 结论先行（CRAC框架）

| 环节 | 要求 |
|------|------|
| **C**onclusion（结论先行） | 开门见山给出结论，让读者先看到答案 |
| **R**ules（法律规则） | 法规全称+条款号+构成要件，逐字核对 |
| **A**nalysis（事实归入） | 将本案/项目事实对照法律要件逐一分析，标注事实来源（已核实/假定） |
| **C**onclusion（结论重申） | 重申结论，不确定时必须给出"最大可能性"，不能止于"it depends" |

### §7.2 一句一意

- 单句≤60字
- 一段只表达一个核心观点
- 编号分段，逻辑递进

### §7.3 读者分层

| 读者 | 策略 |
|------|------|
| **客户法务** | 省略基础法律概念，聚焦争议焦点和实务判断 |
| **客户业务团队** | 对基础概念做简要解释，用商业语言表述结论 |
| **内部使用** | 完整保留检索过程、方法和关键词 |

### §7.4 自指称规范

| 场景 | 规范 | 说明 |
|------|------|------|
| 声明/行动 | "本所" | 如"本所接受委托" |
| 理解/判断 | "我们" | 如"我们认为" |
| 同句不混用 | "本所"与"我们"不出现于同一句 | — |

### §7.5 建议引出语

统一加粗"**建议**"，不得用"本所律师建议""我们建议"。

### §7.6 风险标注

格式`（风险程度高/中/低）`。综合影响程度×发生概率×解决难度。

### §7.7 建设性建议

不仅指出问题，还给出可操作修改方案。告知改与不改的后果差异。区分理想版/底线版，提供折中建议。

### §7.8 依据时效与程序前置（NDR侧·2026-08-29 新增）

**一、依据时效标注**：合规、尽调、意见书、审查类交付物所引法规、监管规则、标准，须标注发布或最新修订日期与「最后核验日」；对拟议行为或历史行为，须说明适用行为时法还是评价时法，必要时双轨表述。

**二、程序前置**：非诉交付物中凡涉及审批、备案、登记、前置许可、第三方同意、优先购买权、内部决议程序的，单列「前置条件」章节置于实体分析之前，并标明「未满足即交易不成立/不生效/存在瑕疵」。

**三、规则冲突处理**：同一事项存在新旧规则或层级冲突时，须明确取舍并说明理由，禁止并列罗列不作判断。

## §8 质量自检通用项

### §8.1 交付前自检

| # | 检查项 | 标准 |
|:--:|------|------|
| 1 | 关键要素完整性 | 发函方/致送对象/核心事项/日期不缺失 |
| 2 | 金额一致性 | 大小写一致，关联金额自洽 |
| 3 | 交叉引用正确性 | 章节编号、条款编号、附件引用匹配 |
| 4 | 术语一致性 | 同一概念全文使用同一术语 |
| 5 | 法规有效性 | 引用法规未被废止或修订；如有修订以最新版为准 |
| 6 | 多源比对 | 关键法条和案例至少两个来源印证，不一致标注"来源存在差异" |
| 7 | 自动化一致性校验（强制） | 调用生成脚本内置 post-check（§3）：章节编号连续、方案/主体指代一致、全文日期一致；结果并入自检清单 |

### §8.2 格式校验

| # | 检查项 |
|:--:|------|
| 1 | 当事人信息完整性 |
| 2 | 签署页完整 |
| 3 | 条款/章节编号连续 |
| 4 | 金额大小写一致 |
| 5 | 日期一致性 |
| 6 | 附件引用匹配 |
| 7 | 涉外双语一致性（核心义务/金额/违约金/知识产权/争议解决/语言效力6项） |

### §8.3 交付前强制触发

各技能在 Phase 4 完成后、Phase 5 生成 Word 之前，**必须**执行以下自检流程

1. 调用本 §8.1 交付前自检表逐项检查
2. 调用本 §8.2 格式校验表逐项检查
3. 对照 §2.6 产物交付七维标准（格式正确/要素齐全/结构完整/繁简得当/逻辑严密/用语准确/行文规范）逐项核验
4. 检查结果输出为 checklist（通过/未通过/不适用）
5. 存在未通过项 → 回退 Phase 4 修改 → 重新自检 → 全部通过后方可进入 Phase 5

各技能 SKILL.md 的 Phase 5 开头增加一行`执行 ../baichen-ndr-standard/references/ndr-standards.md §8.3 交付前强制自检。通过后方可生成为 Word。`

## §9 风险评级统一标准

全部非诉业务技能统一使用以下三级风险评级

| 等级 | 含义 | 触发条件 |
|------|------|----------|
| 高风险 | 重大法律风险 | 可能影响交易可行性、导致重大损失、或违反强制性法律规定 |
| 中风险 | 中等风险 | 可通过交易条款设计或整改措施控制在可接受范围 |
| 低风险 | 低风险或无实质障碍 | 符合法律规定或仅有轻微瑕疵 |

各技能引用本定义，不得自行定义另一套评级标准。如需在特定技能中细化，必须以本定义为基础追加说明而非覆盖。

## §10 分析类技能择技规则（advisory / memo / opinion）

当客户提出法律问题，按以下流程选择技能

1. 客户是否需要书面交付物？
   - 否 → 使用 **客户法律咨询**
   - 是 → 进入 2
2. 律所是否署名并承担法律责任？
   - 是 → 使用 **法律意见书**
   - 否 → 使用 **法律研究备忘录**

三个技能各在 Phase 1 引用本规则。不确定时逐级上推口头答复无法满足→出 memo；客户要求律所担责→出 opinion。

## §11 横向/纵向技能边界表与上浮规则

### 架构说明

非诉业务技能采用两层架构横向基础技能（不限领域，提供统一方法论）和纵向深度技能（单一领域纵深，提供专有分析框架）。当横向技能处理的任务涉及领域专有分析时，自动上浮至对应纵向技能。

### 上浮规则

| 任务 | 横向 | 纵向 | 上浮条件 |
|------|:--:|:--:|------|
| 起草任何标准化日常合同 | 合同起草 | — | 不限领域，模板化 |
| 起草重大交易文件（SPA/SHA/JV/M&A） | — | 重大交易 | 涉及交割先决条件、对赌、多层次赔偿 |
| 起草治理文件（股东协议/激励方案/一致行动） | — | 公司治理 | 需治理结构设计、表决权安排、退出机制 |
| 起草竞业限制/裁员方案/解雇协议/员工手册 | — | 劳动人事 | 需劳动法专有分析框架 |
| 起草PIA/数据出境评估/分类分级方案 | — | 数据合规 | 需三法体系专有分析框架 |
| 商标检索/专利布局/商业秘密保护/IP资产管理 | — | 知识产权管理 | 需IP专有分析框架 |
| FDI/ODI合规路径/VIE结构分析/外资准入 | — | 跨境投资 | 需跨境投资专有分析框架 |
| 境内外上市/证券合规/披露文件审阅批注 | — | 资本市场与证券合规 | 需资本市场专有分析框架（M1-M6） |
| 起草遗嘱/离婚协议/夫妻财产协议/遗赠扶养/意定监护 | — | 婚姻家庭与继承 | 需婚姻家庭与继承专有分析框架（三维审查：合法性/公平性/执行可行性） |
| 审查任何合同草案 | 合同审查 | — | 独立横向能力 |
| 全面尽调（12章，含ESG） | 法律尽职调查 | — | 被动发现，12章全覆盖 |
| 任意领域合规审查 | 合规审查 | — | 不限领域，统一方法论 |
| 正式法律意见（署名担责） | 法律意见书 | — | 署名担责 |
| 书面法律研究（不署名担责） | 法律研究备忘录 | — | 统一 Word |
| 口头快速答复（无书面交付） | 客户法律咨询 | — | 无书面交付 |
| 客户名义发函 | 客户函告 | — | 不引法条 |
| 律所名义发函 | 律师函 | — | 引法条，有威慑力 |

### 分析类技能择技规则

参见 §10。总结无书面交付→客户法律咨询；有书面、署名担责→法律意见书；有书面、不署名担责→法律研究备忘录。

## §14 跨域桥接（NDR↔DR）

非诉业务产出可能触发争议解决流程。Phase 1 检测到以下场景时，自动建议触发对应 DR 技能

| NDR 场景 | 建议触发 DR 技能 | 理由 |
|---------|-----------------|------|
| 合同审查 发现严重违约 | 民事起诉状 | 合同纠纷已达到起诉门槛 |
| 律师函 律师函后无回应 | 民事起诉状 | 函告无效需进入诉讼 |
| 法律意见书 结论为不可行 | 民事起诉状 / 取保候审申请书 | 法律障碍需诉讼解决 |
| 劳动人事 裁员方案被拒 | 民事起诉状 | 劳动仲裁前置后诉讼 |
| 合规审查 高风险（风险涉及刑事） | 刑事控告 | 合规红线触发刑事控告 |
| 知识产权管理 发现严重侵权 | 民事起诉状 | IP侵权需诉讼维权 |
| 跨境投资 ODI被拒 | 行政复议申请书 | 行政决定需复议 |

反向DR 技能需要 NDR 能力支撑时，参见 dr-standards.md §11。

## §15 NDR交付物质量自检清单

所有 NDR 技能产出文档前，须逐项通过以下自检（对标 法官文书公共标准 §J5 自检体系）。

### §15.1 格式自检

| # | 检查项 | 标准 | 不通过处理 |
|:--:|--------|------|-----------|
| 1 | 文档结构完整 | 按 §2.6 格式标准，封面/目录/正文/附件齐全 | 补全 |
| 2 | 签署栏 | 名称+印章+日期中文大写 | 修正 |
| 3 | 法条引用格式 | 全称+条款号，首次附原文 | 修正 |
| 4 | 页码 | 正式报告须有页码 | 补全 |

### §15.2 内容自检

| # | 检查项 | 标准 | 不通过处理 |
|:--:|--------|------|-----------|
| 5 | 要素完整性 | 按 §2.6 要素表，交付物类型对应的必含要素无一遗漏 | 补全 |
| 6 | 风险评级明确 | 每个风险发现给出明确等级（高/中/低），不可用"可能存在" | 修正 |
| 7 | 法律依据完整 | 每个结论引用≥1条有效法条，不可引用AI编造法条（§2.3.6） | 补全或修正 |
| 8 | 禁止模糊措辞 | §2.2 禁止项无一使用 | 替换 |

### §15.3 去AI化自检

| # | 检查项 | 标准 | 不通过处理 |
|:--:|--------|------|-----------|
| 9 | 禁用词检查 | "综上所述""应当指出""毋庸置疑""首先其次再次"无一使用 | 替换 |
| 10 | 读者适配 | 按 §2.6 行文风格·读者适配表，用语匹配目标读者 | 润色 |
| 11 | 人写感检查 | 不用模板化引导语，有过渡无模板 | 润色 |

自检通过后方可进入 Phase 5（文档生成）。

### §15.4 法条状态与依据时效普检（全 NDR 交付物通用·2026-08-29 新增）

| # | 检查项 | 标准 | 不通过处理 |
|:--:|--------|------|-----------|
| 1 | 法条状态 | 全部引用规范已标状态；⚠️/⛔ 未出现在交付正文（见 §2.1.1） | 核验或剔除 |
| 2 | 时效标注 | 法规/监管规则已标发布日期与最后核验日 | 补标注 |
| 3 | 时法选择 | 已说明适用行为时法或评价时法 | 补说明 |
| 4 | 前置条件 | 涉审批/备案/登记/同意/决议者已设前置条件章节 | 补章节 |
| 5 | 冲突取舍 | 新旧或层级冲突已明确取舍并说明理由 | 补判断 |

## §16 NDR交付物多轮审核流程

NDR 交付物在交付客户前，须经过以下审核轮次。

| 轮次 | 审核重点 | 执行方式 |
|:--:|------|------|
| 第1轮 | AI自检 | 执行 §15 自检清单，逐项通过 |
| 第2轮 | 交叉审阅 | 由同家族另一技能（或人工）交叉审阅关键结论和风险评级 |
| 第3轮 | 客户适配 | 检查用语是否匹配目标读者（客户/交易对手/监管机构，见 §2.6 读者适配表） |
| 第4轮 | 终稿确认 | 确认所有改动已落实，版本号与日期更新 |

每轮审核须有记录：审核人/技能、审核时间、发现的问题、整改结果。
