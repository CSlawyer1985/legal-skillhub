# Changelog

本文件记录 `ai-legal-case-workflow` 的重要变更。

## [v2.5.1] - 2026-08-03

### 修改

- 适度增强 `SKILL.md` frontmatter 的 `description`，前置作者来源、目标用户、民事一审与二审双程序路径、核心任务和典型产出，使 WorkBuddy 首屏摘要更接近律师用户的业务理解方式。
- 保留卷宗读取、事实时间线、证据矩阵、诉讼时效、管辖、保全、上诉期限、起诉与应诉文书、质证和庭审等关键触发语义。
- 保留不适用场景、专门领域核验闸门和律师最终判断边界，摘要长度继续控制在平台允许范围内。

### 保持

- 不修改民事一审 1–7、民事二审 A0–A6、三类受控裁定上诉、输入输出契约、法律规则、模板、质量门、异常恢复或数据安全边界。
- 不修改许可条件，不处理 WorkBuddy 产品侧的 README 渲染或重复摘要展示问题。

## [v2.5.0] - 2026-08-03

### 新增

- 新增与一审七阶段并列的民事二审 A0–A6 专门路径：入口与期限、原审裁判拆解、上诉审计、证据增量与程序、二审材料包、庭审或询问、裁判交付。
- 新增 `appeal_track` 多方上诉轨道，对每份上诉分别管理请求、期限、费用和文书状态，并运行跨轨道一致性检查。
- 新增裁判错误审计链，将上诉请求连接到原审主文、事实认定、证据评价、法律适用、程序问题及结果影响。
- 新增 `references/appeal-workflow.md`、`appeal-templates.md`、`appeal-quality-checklist.md` 和 `appeal-case-examples.md`，覆盖二审工作流、固定模板、D0–D6 质量门及 T1–T8 虚构场景验收。
- 保留裁定上诉受控子路径，仅覆盖不予受理、管辖权异议和驳回起诉三类通常可上诉裁定。
- 在贡献规则中加入 SkillHub TRACE 评分优化规则：评分只作为质量信号，任何优化不得降低法律准确性、可追溯性、人工终审、安全边界和可维护性。

### 修改

- `SKILL.md` 从“一审专门流程”升级为一审与二审双程序入口。一审继续使用 `start_stage/end_stage`，二审使用 `start_phase/end_phase`，禁止混用。
- 更新 README、FAQ 和工具回退规则，增加二审触发方式、输入契约、外部等待、上诉期限证据闸门和版本说明。
- 将“没有裁判文书或可核验送达记录时不得认定确定上诉截止日”设为二审入口阻断规则。
- 将上诉费提交、通知、补交和缴费凭证纳入 A0；不再以“已经递交上诉状”替代上诉程序状态核验。
- 二审策略输出要求至少提供可比较选项，列明成立条件、作用、风险、证据缺口、程序动作和律师裁决点，不输出伪精确胜率。
- 根据独立复核补强三类受控裁定上诉的不开庭例外、普通不予受理裁定的当事人列明边界，以及二审建议输入参数的显式消费关系。
- 新增二审工具失败、降级和断点恢复的完整回执示例，并将 T1–T8 维护检查升级为按验收表列核验。
- 澄清裁定上诉审限延长应核验现行《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》第三百三十九条，不采纳“裁定上诉审限不能延长”的错误评审建议。

### 法律边界

- 以现行《民事诉讼法》及司法解释、民事证据规定和诉讼费用规则作为检索锚点，但真实案件运行时仍须从权威来源重新核验效力和原文。
- 二审以开庭为原则，但是否不开庭由法院依法判断；技能不得承诺审理方式。
- 再审、执行及其他裁定救济不纳入本版专门模块。涉外、港澳台、知识产权、海事海商和破产衍生诉讼继续只做识别、风险提示和专项核验闸门。
- 本版二审案例均为虚构结构示例。真实脱敏二审案例与基准继续作为非阻塞后续任务，不为补齐展示虚构外部事件。

### 保持

- 保留民事一审七阶段全部功能、运行状态、失败恢复、数据边界、法源核验和律师最终复核要求。
- 继续采用 CC BY-NC 4.0，商业使用仍需另行取得书面授权。
