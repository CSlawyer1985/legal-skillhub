# 完整输出样例：虚构买卖合同欠款纠纷

本文件展示一次从用户输入、运行状态到阶段产出的完整写法，用于帮助首次使用者理解“实际输出长什么样”。案例、主体、地址、编号和金额均为虚构演示值，不对应任何真实案件，不得直接作为法院提交件。

本样例只演示民事一审原告路径的阶段1和阶段3。阶段2需要实时企业查询，阶段4至阶段6依赖真实的应诉、排期和庭审材料，不使用虚构外部事件强行补齐。技能的“全流程”是按真实案件进度逐阶段推进，不是一次生成七阶段假想材料。民事二审示例与场景验收另见 `appeal-case-examples.md`。

## 一、示例输入

```yaml
case_type: 买卖合同纠纷
procedure: first_instance
role: plaintiff
materials_path: /示例案件/原始材料
start_stage: 1
end_stage: 3
output_formats: ["md"]
parallel_enabled: false
```

用户原话也可以是：

> 我代理原告，准备起诉追收货款。材料在“/示例案件/原始材料”，先完成案情分析，再准备起诉材料。先输出 Markdown，不要直接生成 Word 或 PDF。

## 三、阶段1完整输出样例

以下内容示范《案件概要报告》的完整最小结构。真实执行时必须替换为原始材料中的实际内容，并补充页码、段落或图片位置。

### 1. 首页状态

```yaml
run_status: completed
completed_scope:
  - stage_1
lawyer_review_status: pending
law_source_status: unverified
unreadable_or_unverified_items:
  - 合同管辖条款的效力及实际履行地尚待律师结合原件确认
  - 逾期付款损失的请求口径尚待实时法源核验
resume_from: stage_2
```

> 状态说明：`completed` 只表示阶段1预定步骤已执行，不表示律师已经确认事实、策略或法律结论。

| 日期 | 事件 | 证据锚点 | 来源层级 | 待核事项 |
|---|---|---|---|---|
| 2026-01-10 | 双方签订买卖合同，价款80万元 | M01第1至2页 | 原始材料 | 核对签章和合同原件 |
| 2026-01-20 | 原告交付合同设备，被告人员签收 | M02第1页签收栏 | 原始材料 | 核对签收人权限 |

### 4. 主张与证据矩阵

| 待证明事实 | 现有证据 | 支持程度 | 主要缺口 | 建议动作 |
|---|---|---|---|---|
| 买卖合同关系成立 | M01 | 较强 | 原件未核 | 核对原件及签章 |
| 原告已经交付 | M02、M03 | 较强 | 签收人权限待核 | 补充物流记录或人员身份材料 |
| 被告尚欠50万元 | M01、M04、M05 | 较强 | 原告内部账未提供 | 补充应收账款明细和完整银行流水 |
| 付款期限已经届满 | M01 | 较强 | 是否有延期协议待核 | 检索全部补充协议和聊天记录 |
| 逾期损失计算基础 | M01 | 待核 | 约定标准和法定标准均未核验 | 阶段3实时检索有效法源后确定请求口径 |

### 5. 初步争点

1. M02签收人是否有权代表被告签收。
2. M03验收是否覆盖合同约定的全部验收条件。
3. 被告是否提出过质量异议、抵销或延期付款抗辩。
4. 欠款本金是否已经扣除全部付款、折让和退货。
5. 逾期付款损失的起算点和计算标准如何确定。

### 6. 程序与风险预检

| 检查项 | 当前结论 | 状态 |
|---|---|---|
| 诉讼时效 | 从现有日期看未发现明显届满风险，但仍需核对全部付款、催收和确认债务材料 | 待律师确认 |
| 管辖 | 合同记载“原告所在地法院”，效力、原告住所地及与争议实际联系待核 | 待法源和原件核验 |
| 仲裁条款 | 现有合同片段未见仲裁约定 | 待核合同全文 |
| 财产保全 | 尚无被告资产和履行风险的可靠资料 | 阶段2核查后再判断 |
| 证据完整性 | 主要链条已形成，但签收人权限、内部账和完整银行流水需要补强 | 部分完成 |
| 诉讼费用 | 暂不写死金额，待诉讼请求确定后按现行规则计算 | 待核验 |

### 7. 策略候选与律师裁决点

| 方案 | 适用前提 | 优点 | 风险 |
|---|---|---|---|
| A. 补证后直接起诉 | 欠款及交付证据核对无误 | 尽快进入司法程序 | 对方可能提出质量或抵销抗辩 |
| B. 先发最后催告再起诉 | 对方仍有明确履行可能 | 可能降低诉讼成本 | 可能延误保全和起诉时点 |
| C. 先完成主体与财产核查 | 对方履行能力不明 | 便于决定是否保全 | 增加准备时间和查询成本 |

需要律师裁决：是否先完成阶段2主体核查；是否发出最后催告；是否申请财产保全；逾期损失采取何种请求口径。

### 8. 阶段1质量门

- 已逐份读取M01至M06，没有无法读取文件。
- 金额、日期和当事人名称已完成交叉核对，但仍需回原件确认。
- 事实、当事人陈述和分析推论已分层标注。
- 法源尚未实时核验，没有把法律候选写成确定结论。
- 阶段1完成，可在律师确认材料范围后进入阶段2。

## 四、阶段3文书样例

真实执行中，阶段2应先形成自己的状态块。本样例不虚构实时企业查询结果：如果阶段2因缺少查询能力而无法完成，应标记为 `partial` 或 `blocked`，列明未覆盖维度；只有用户确认继续且阶段3不依赖缺失结论时，才能以风险披露后的局部模式进入阶段3。以下阶段3内容用于展示文书结构，不表示本样例已经静默跳过阶段2。

下列文书只演示“事实如何回链、未核验事项如何显式保留”。由于法源和管辖尚未实时核验，运行状态为 `partial`，不得提交法院。

### 1. 首页状态

```yaml
run_status: partial
completed_scope:
  - 民事起诉状事实部分
  - 对外证据目录草稿
law_source_status: unverified
unreadable_or_unverified_items:
  - 管辖依据未完成实时核验
  - 逾期付款损失计算标准未完成实时核验
lawyer_review_status: pending
safe_to_retry: true
resume_from: stage_3_law_source_check
user_action_required:
  - 确认拟受理法院
  - 提供完整合同原件和原告银行流水
```

### 2. 民事起诉状草稿

```text
民事起诉状

原告：甲辰科技（示例）有限公司，住所地河南省郑州市示例区示例路1号。
法定代表人：张某，职务：执行董事。

被告：乙木贸易（示例）有限公司，住所地河南省郑州市示例区示例路2号。
法定代表人：李某，职务：经理。

诉讼请求：
1. 判令被告向原告支付货款500,000元；
2. 判令被告支付逾期付款损失，暂以500,000元为基数，自2026年2月21日起计算至实际清偿之日止，具体计算标准待实时法源核验和律师确认后补入；
3. 本案诉讼费用由被告承担。

事实与理由：
2026年1月10日，原、被告签订买卖合同，约定被告向原告购买设备，合同价款为800,000元，付款期限为2026年2月20日。该事实有《买卖合同》予以证明，见证据1。

2026年1月20日，原告按约向被告交付设备，被告工作人员在送货单上签收；2026年1月22日，被告签署验收确认。该事实有送货单、验收确认予以证明，见证据2、证据3。

2026年2月10日，被告支付货款300,000元，尚欠500,000元。付款期限届满后，原告于2026年3月5日催告付款，被告在完整微信对话中确认余款并表示延期支付，但此后未再付款。该事实有付款凭证、完整微信记录予以证明，见证据4、证据5。

原告认为，被告在收货并确认验收后未按约支付剩余价款，应承担相应责任。因管辖依据、法源效力和逾期付款损失计算标准尚待实时核验，本稿仅为律师工作底稿，完成核验与人工定稿前不得提交法院。

此致
[拟受理法院待确认]

具状人：甲辰科技（示例）有限公司
日期：2026年[ ]月[ ]日
```

### 4. 阶段3未完成事项

1. 回看合同原件，核实签章、争议解决条款和全部补充约定。
2. 通过当前可用的权威来源核实请求权基础、管辖和逾期付款损失规则。
3. 核对拟受理法院的现行立案要求、提交份数和电子文件规则。
4. 补充原告完整银行流水、内部应收账款明细和签收人身份材料。
5. 由律师确定最终诉讼请求、保全方案、文书措辞和提交版本。

## 五、失败回执样例

假设阶段3法源工具在3次调用（含首次）后仍失败，应返回以下信息，而不是继续写成“法源核验完成”：

```yaml
run_status: partial
failed_step: stage_3_law_source_check
attempts: 3
completed_outputs:
  - 案件概要报告
  - 民事起诉状事实部分草稿
  - 对外证据目录草稿
unreadable_or_unverified_items:
  - 请求权基础现行条文
  - 管辖依据
  - 逾期付款损失计算标准
fallback_taken: 保留事实分析，停止输出确定性法律结论
safe_to_retry: true
resume_from: stage_3_law_source_check
user_action_required:
  - 提供可用权威法源或授权稍后重试
```

## 六、如何使用本样例

- 第一次使用：先看“阶段1完整输出样例”，理解事实、证据和风险如何组织。
- 准备起诉：再看“阶段3文书样例”，理解工作底稿、对外件和内部分析的边界。
- 遇到失败：对照“失败回执样例”，确认已完成内容、未核事项和恢复位置是否清楚。
- 实际办案：只能复用结构，不能复用本样例的虚构事实、金额、日期或结论。
