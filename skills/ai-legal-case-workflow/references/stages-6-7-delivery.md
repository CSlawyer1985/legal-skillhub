## 阶段6：庭审阶段文书撰写

**目标**：覆盖庭前准备、庭审应对、庭后跟进三个时间段的全部文书工作。

**输入**：法院制作的庭审笔录（依《民事诉讼法》第一百五十条当庭宣读，或由法院告知当庭或五日内阅读；发现对本人陈述记载有遗漏或差错时申请补正，不予补正的要求将申请记录在案）+ 代理人依法所作的现场笔记 + 前序阶段全部材料。

当事人、律师和诉讼代理人可依规定查阅庭审录音录像，并复制录音或誊录内容；未经人民法院许可，不得自行对庭审活动录音录像，也不得拍录、复制、删除或迁移法院庭审录音录像（法释〔2017〕5号第十条、第十一条、第十五条）。

### 6A. 庭前准备文书（开庭前完成）

> **前序产出缺失时**：下表“来源”列中的 `trial-questioner`、`evidence-organizer`、`defense-drafter` 是阶段5的协作角色产出，定义见 `references/stages-3-5-litigation.md` 的阶段5章节。未执行阶段5时，先向用户说明缺口，再按相应职责就地补出争议焦点、证据三性和发问清单的最小版本，不得把空白提纲当作完成品交付。
>
> **材料读取**：庭审笔录、开庭传票等为 PDF 时，先尝试直接读取文本；返回为空或明显缺页时，使用当前平台已提供且已验证的 PDF 渲染或 OCR 能力，将相关页面按约 200dpi 转为图片后读取。平台不具备转换能力时，记录不可读文件并请用户提供图片版、OCR 版或文本版，不自动安装未授权工具，也不得声称已读取。

| 文书 | 内容 | 来源 |
|------|------|------|
| 庭审提纲 | 争议焦点梳理、举证顺序、质证要点、辩论框架 | 阶段5材料整合 |
| 发问提纲 | 向对方当事人/证人发问的问题清单（含预期答案和追问方向） | trial-questioner |
| 质证意见 | 对对方证据的三性分析（真实性/合法性/关联性） | evidence-organizer |
| 代理词（初稿） | 完整代理意见框架，留庭审调整空间 | defense-drafter |

### 6B. 庭审应对（开庭当天）

**庭审记录要点**（庭审后24小时内完成）：

1. **法庭归纳争议焦点**（与预判对比，标注偏差）
2. **法官询问方向**（识别法庭当前关注点，不等同于裁判倾向）
3. **双方举证质证情况**（已采信/有争议/未采信）
4. **对方自认/让步**（对我方有利的关键陈述）
5. **庭审新情况**（新证据、新论点、需要回应的事项）

### 6C. 庭后跟进文书（庭审后完成）

**操作步骤**：

1. 精读庭审记录，标注关键节点
2. 分析法庭归纳的争议焦点（与预判对比）
3. 评估双方证据采信情况与证明力对比
4. 根据法官询问识别需要庭后补强的事实或法律争点，并将判断标注为推测
5. 撰写庭审分析报告
6. 撰写庭后代理意见书（针对庭审新情况补充论证）
7. 准备最后陈述（如法院要求书面最后陈述）
8. 评估是否需要补充证据（庭后补证申请）
9. 更新调解方案（基于庭审新情况调整）

**输出模板**：详见 `references/templates.md` 中的"庭审文书模板"

**关键经验**：
- 法官反复追问的问题通常指向法庭当前关注的事实或法律争点，可作为庭后补强的优先方向；追问也可能用于排除某种可能、调解摸底或补充事实，不得等同于裁判结论
- 在法院安排的阅读时间内逐项核对法庭笔录；发现遗漏或差错时及时申请补正，不予补正的要求将申请记录在案，再按要求签名或盖章
- 庭审新情况必须在庭后意见中回应
- 调解方案要务实：基于双方实际强弱，最积极方案也要留余地
- 庭审记录24小时内完成，记忆最新鲜时最准确
- 庭后代理意见书不是重复庭审发言，而是补充庭审中未能充分展开的论证

## 阶段7：格式转换与交付

**目标**：按客户、法院和团队需求整理工作成果；当前平台具备且允许使用转换能力时生成并验证目标格式，否则保留可验证的 Markdown 或现有格式并完成归档。

**格式转换矩阵**：

| 源格式 | 目标格式 | 工具/方法 | 适用场景 |
|--------|----------|-----------|----------|
| MD | HTML | 当前平台可创建并用浏览器验证时生成；否则保留 MD | 案件报告展示 |
| MD | Word(.docx) | 当前平台已有文档工具；经用户授权后也可在 managed venv 中使用 python-docx | 正式法律文书（起诉状/答辩状/代理词） |
| MD | PDF | 当前平台已提供且已验证的 PDF 转换能力；不可用时保留 MD 或 DOCX 并说明限制 | 正式文件归档 |
| PDF | 图片 | 当前平台已提供且已验证的 PDF 渲染或 OCR 能力，约 200dpi；不可用时请求用户提供可读版本 | 扫描件 OCR 前处理 |
| PDF | MD | 当前平台已提供且已验证的文档提取能力；不可用时保留原件并记录未提取范围 | 文档内容提取 |

**交付物分级**：

| 交付对象 | 格式 | 内容 |
|----------|------|------|
| 法院 | DOCX / PDF / 扫描件 / 纸质件 | 按受理法院或网上立案系统要求准备起诉状、答辩状、代理词和证据目录；自然人按要求签名，企业或其他组织按要求盖章或完成系统规定的签署方式 |
| 客户（委托人） | 用户要求且已验证的格式；无转换能力时为 MD | 案件概要报告（简化版，突出策略建议、主要风险情景和不确定因素） |
| 团队内部 | MD | 全部分析报告（含完整分析过程和法源核实） |

**客户友好版摘要要求**：

- 去除法律术语，用委托人理解的语言
- 突出三个要点：案件现状、建议方案、主要风险情景与不确定因素。说明可能改变案件走向的变量、证据缺口和下一步依赖，不提供胜诉概率、结果区间或任何结果预测与承诺
- 附时间线和关键节点说明
- 标注需要客户配合的事项（补充证据、确认信息等）

**归档标准**：

```
[案件名称]/
├── 01_原始材料/          ← 客户提供的原始卷宗
├── 02_分析报告/          ← 阶段1-2产出
├── 03_起诉材料/          ← 阶段3产出（原告方）
├── 04_应诉材料/          ← 阶段4-5产出
├── 05_庭审文书/          ← 阶段6产出
├── 06_最终文书/          ← 律师定稿且已验证的文件；必要时保留 MD 降级件
├── 07_工作底稿/          ← 过程文件、草稿、参考材料
└── 08_归档清单.md        ← 全部文件索引
```

**关键约束**：
- 优先使用当前平台已有且可验证的文档工具，不预设特定工具一定可用
- 只有文件实际生成并完成打开、回读或渲染检查后，才能把相应格式标为完成；转换失败时标记 `run_status=partial`，列出失败步骤和恢复方式
- 确需安装 Python 包时先取得用户授权，并仅安装在 managed venv 中，禁止污染系统环境
- Word 文档格式：宋体正文/黑体标题、1.5倍行距、标准页边距
- 交付前执行文件命名检查（阶段_文书类型-版本号格式）
- 归档清单在案件结案时编制，包含全部文件索引和关键结论
