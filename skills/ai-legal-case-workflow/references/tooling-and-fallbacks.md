## 使用前准备（前置依赖）

### 快速判断：你能用这个技能吗？

在开始之前，用三个问题快速判断适用性：

1. **这是民事一审或二审案件吗？** → 是（合同/侵权/物权/婚姻家庭等）→ 继续，并先确认 `procedure`。刑事、行政、再审和执行不进入专门路由；二审使用 A0–A6，不得套用一审七阶段。
2. **你有案件材料吗？** → 是（合同/付款凭证/聊天记录/判决书等卷宗文件）→ 继续。否（纯咨询无材料）→ 可以直接提问，但不需要走本流程。
3. **你的程序和身份是？** → 一审按原告或被告选择七阶段路径；二审同时记录原审地位和本方为上诉人、被上诉人或双轨处理，再进入 A0–A6。

如果三个问题都是"继续"，往下看技术依赖。

### 技术依赖清单

缺项不会导致失败，但对应功能会降级（详见"异常处理与回退策略"）。

| 依赖项 | 用途 | 缺失影响 | 必需程度 |
|--------|------|----------|----------|
| **卷宗材料文件夹** | 阶段1的输入 | ❌ 无法启动，会要求提供路径 | **必需** |
| **程序与代理身份** | 决定一审七阶段或二审 A0–A6 及代理轨道 | ❌ 无法从材料确认时必须询问，不得默认程序或立场 | **必需** |
| 北大法宝 MCP (pkulaw) | 法条检索与效力验证、判例检索 | 法源核实改用其他权威来源；均缺失则标注 `【未经工具核实，仅供参考】` | 强烈建议 |
| 元典 MCP (yuandian-mcp) | 司法涉诉查询、企业信用、案例检索 | 主体核查仅用企查查，涉诉维度缺失 | 强烈建议 |
| 企查查 MCP (qcc-company) | 企业工商信息、股权结构、风险扫描 | 企业主体核查改用元典，工商维度缺失 | 企业被告时必需 |

> **数据安全提示**：本技能可能调用 AI 模型读取卷宗，材料是否离开本地取决于实际部署和工具链路。使用前按绿色、黄色、红色、红线四级边界审查任务必要性、授权范围、链路可信度和人工复核要求。红色数据并非当然禁用，但只能在任务必要、授权清楚、链路可信且有人工最终复核时处理；红线数据不得进入普通 AI 链路、外部代理或公开仓库。

## 工具使用指南

### MCP 工具

| 工具 | 用途 | 触发条件 |
|------|------|----------|
| 北大法宝(pkulaw) | 法条检索、判例检索、法条有效性验证 | 需要引用法律依据时（强制） |
| 元典(yuandian-mcp) | 司法涉诉查询、企业信用、案例检索 | 企业背景调查、类案检索 |
| 企查查(qcc-company) | 企业工商信息、股权结构、风险扫描 | 企业主体核查 |

**授权范围判定**：给出 `enable_mcp_tools` 时，仅可调用其中列出的工具；未列出的即使平台可用也视为未授权，并标注“该维度因未授权而未覆盖”。未给出该参数时，只可使用用户当前请求和既有数据边界内任务必要、只读、不会造成外部状态变化的能力，并在产出的工具使用说明中如实列出来源与调用时间。涉及外部写入、付费、敏感个人信息传输、跨平台或外部代理、扩大材料处理范围的，必须取得明确确认。平台可用不等于已经获得授权。

### 法源核查规则（强制执行）

引用任何法律、法规、司法解释、判例时：
1. 禁止凭记忆引用，必须通过当前可用的权威来源实时检索
2. 验证法条效力状态（现行有效/已废止/已修订）；已修正的法律和司法解释必须取现行文本
3. 判例需核实案号、裁判法院、裁判日期和裁判要旨
4. 核实通过时标注 `【已核实：<来源名称>，YYYY-MM-DD】`
5. 无法核实时标注 `【未经工具核实，仅供参考】` 并建议人工复核

### 子代理协作能力

不同平台的子代理接口并不统一。先确认当前平台实际支持以下能力，再映射到对应工具；不支持时由主代理串行完成。

| 能力 | 平台工具示例 | 用途 |
|------|--------------|------|
| 创建协作空间 | `TeamCreate` 或同类接口 | 建立阶段3或阶段5的协作上下文 |
| 启动子代理 | `Agent` 或同类接口 | 按明确任务说明启动角色代理 |
| 创建与更新任务 | `TaskCreate`、`TaskUpdate` 或同类接口 | 记录任务、负责人和状态 |
| 发送消息 | `SendMessage` 或同类接口 | 传递材料范围、审核意见和关闭请求 |
| 清理资源 | `TeamDelete` 或同类接口 | 在确认产出已保存后关闭协作空间 |

### PDF 处理

- 读取：先直接读取文本；返回为空或明显缺页时，使用当前平台已提供且已验证的 PDF 渲染或 OCR 能力，将相关页面按约 200dpi 转为图片后读取。平台不具备转换能力时，记录不可读文件并请用户提供图片版、OCR 版或文本版，不自动安装未授权工具，也不得声称已读取。
- 生成：优先使用当前平台已提供且已验证的 DOCX/PDF 转换能力；能力不存在时保留 Markdown 或 DOCX 交付并说明限制，不自动安装、不虚构转换成功。

### Word 文档生成

优先使用当前平台已有且可验证的文档工具。确需安装 `python-docx` 时，先取得用户授权，再安装到受管理的虚拟环境，不得修改系统 Python 环境。

```
# 获得用户授权后，在 managed venv 中安装
<managed-python-venv-pip> install python-docx
# 编写脚本生成 docx
<managed-python> generate_word_document.py
```

## 异常处理与回退策略

> **工具重试原则**：平台允许重复调用时，可在不扩大授权范围、不产生重复写入等副作用的前提下发起最多 3 次调用（含首次）。等待和超时能力取决于实际平台；本技能只规定处理顺序，不承诺系统级后台重试。

### 统一运行状态与失败回执

每次阶段回复和产出首页必须使用以下一种 `run_status`：

| 状态 | 含义 | 允许进入下一阶段 |
|---|---|---|
| `in_progress` | 当前阶段仍在执行，尚未形成阶段结论 | 否 |
| `completed` | 当前约定阶段的预定步骤已执行，阶段质量门已检查 | 是，但仍需遵守律师审核和外部等待条件 |
| `partial` | 已形成可保留产出，但仍有未完成或未核验事项 | 原则上否；律师明确接受风险且不依赖缺失项时除外 |
| `blocked` | 缺少必需输入、授权、工具或程序条件，当前无法安全继续 | 否 |
| `waiting_external` | 需要等待法院通知、对方材料、庭审或其他外部事件 | 否，待外部事件发生后恢复 |

`completed` 不等于律师已经确认，也不等于文件已经成功转换、发送或提交。律师审核状态、法源核验状态、格式验证状态和外部提交状态分别记录，不互相替代。

出现异常、降级或外部等待时，使用以下最小回执。字段没有事实依据时写 `unknown` 或空列表，不得自行补全：

```yaml
run_status: partial | blocked | waiting_external
failed_step: <阶段和步骤；外部等待时写 waiting_for>
attempts: <实际尝试次数；未调用工具时为 0>
completed_outputs:
  - <已经生成并完成最低检查的产出>
unreadable_or_unverified_items:
  - <无法读取、缺失或未经核验的事项>
fallback_taken: <已经执行的降级动作；没有则写 none>
safe_to_retry: true | false | unknown
resume_from: <可安全恢复的阶段和步骤>
user_action_required:
  - <需要用户补充、确认或授权的动作>
```

失败回执必须使用用户能理解的描述，同时保留必要的工具错误摘要。不要把原始堆栈、内部调试信息或可能含有敏感材料的完整错误正文直接交给用户。

### 恢复执行协议

1. 先读取最近一次阶段产出和失败回执，核对 `run_status`、`completed_outputs` 与 `resume_from`。
2. 回到原始材料确认材料范围和文件哈希或修改时间是否变化；发生变化时只把旧产出作为参考，不直接续跑。
3. 复用已经完成最低质量检查且与当前材料一致的产出，不重复读取无变化的大文件，不重复发起有费用、写入或外部状态变化的调用。
4. 对 `unreadable_or_unverified_items` 逐项判断是否已经补齐；未补齐且属于必需条件时继续保持 `partial` 或 `blocked`。
5. 从 `resume_from` 指定步骤恢复，记录本次新增内容和仍未完成事项。
6. 只有当前约定阶段的预定步骤和质量门均通过后，才把 `run_status` 更新为 `completed`。

完整状态块、阶段产出和失败回执示例见 `references/complete-output-example.md`。

### 输入异常

| 异常类型 | 检测方式 | 回退策略 |
|----------|----------|----------|
| `materials_path` 不存在 | 阶段1启动前检查 | 返回错误信息，提示用户提供有效路径 |
| 材料目录为空 | 阶段1步骤1 | 返回"指定目录中未发现卷宗材料"，终止当前阶段 |
| PDF 为扫描件 | 直接读取为空或明显缺页 | 使用当前平台已提供且已验证的 PDF 渲染或 OCR 能力，按约 200dpi 转图片后读取；无转换能力时记录文件并请用户提供图片、OCR 或文本版本 |
| 材料格式不支持 | Read 返回错误 | 记录到错误日志，跳过该文件并提示用户 |
| 被告信息缺失 | 阶段2启动前检查 | 从阶段1报告提取，提取失败则提示用户手动输入 |
| `plaintiff`/`defendant` 为空 | 阶段1步骤3 | 从材料中提取；提取失败则使用当前平台的用户询问能力确认，不猜测 |

### 工具异常

**重试规则（先于回退策略执行）**：MCP 工具调用失败时，先判断重复调用是否安全。安全且平台支持时再按下列顺序重试，不要直接假定工具永久不可用。

1. 第 1 次失败：等待 3 秒后原参数重试
2. 第 2 次失败：等待 5 秒后再试一次
3. 第 3 次失败：判定该工具不可用，执行下表回退策略
4. 超时（单次调用超过 60 秒无响应）视同失败，计入重试次数
5. 全部尝试失败后，向用户说明实际尝试次数、错误状态和降级方案；不得声称执行了平台并不支持的后台重试

| 异常类型 | 检测方式 | 回退策略 |
|----------|----------|----------|
| 北大法宝 MCP 不可用 | 安全重试后仍失败 | 切换其他已授权权威来源；均不可用则标注 `【未经工具核实，仅供参考】` 并建议人工复核 |
| 元典 MCP 不可用 | 安全重试后仍失败 | 仅使用企查查；提示数据覆盖可能不完整 |
| 企查查 MCP 不可用 | 安全重试后仍失败 | 使用元典企业查询；提示工商信息可能不完整 |
| 网络波动/超时 | 单次调用 60 秒无响应 | 按安全重试规则处理；重试期间仅继续无依赖、无冲突的其他步骤 |
| python-docx 未安装 | 阶段7 `import` 失败 | 优先使用平台已有文档工具；确需安装时先说明影响并取得用户确认 |
| MCP 返回数据为空 | 结果列表为空 | 不轻易判定"无记录"，标注"该来源未返回数据，建议结合线下材料补充" |

### 流程异常

| 异常类型 | 检测方式 | 回退策略 |
|----------|----------|----------|
| 子代理无响应 | 关闭请求超时 | 使用平台实际支持的停止能力；仍无法清理时报告真实状态，不假称已关闭 |
| 子代理产出质量不达标 | 主代理审核 | 发送具体修改意见要求子代理修改；仍不达标则由主代理修改并重新检查 |
| 阶段间发现前序错误 | 后续阶段分析不一致 | 回到前序阶段报告进行增量修正，标注修正记录 |
| 无反诉、有答辩 | 阶段4未收到反诉状 | 保留阶段4的答辩拆解、时效与管辖分析，仅跳过反诉专项分析；阶段5照常执行，证据目录不设反诉分部 |
| 对方完全未答辩 | 无答辩状且无反诉状 | 阶段4改为本诉自查，包括我方举证充分性、时效和管辖；阶段5产出对方可能到庭及缺席审理两套预案 |
| 已有开庭安排但尚未开庭 | 收到传票或排期通知 | 执行阶段6的6A庭前准备；6B、6C待开庭后再执行 |
| 尚未排期且诉讼继续 | 未收到传票或排期通知，案件未终结 | 阶段5后进入外部等待态；可形成明确标注的阶段性材料包，但不得标记全流程完成；收到排期通知后恢复6A |
| 调解、撤诉等无需开庭的终局结案 | 已有可核验的调解书、撤诉裁定或其他终局文件 | 记录依据后跳过阶段6，进入阶段7做最终归档和交付 |
| 被告方代理 | `role=defendant` | 跳过阶段3（起诉材料制作），从阶段4开始 |
| 存在有效仲裁协议 | 阶段1步骤7审查争议解决条款 | 停止法院起诉路径，改为仲裁准备。当事人对仲裁协议效力有异议的，应当在仲裁庭首次开庭前提出（《仲裁法》2025年修订第三十一条，自2026年3月1日起施行）；实际案件同时核验仲裁机构规则和协议效力 |
| 案件适用小额诉讼程序 | 核对程序告知、案件类型与标的额 | 识别一审终审及无上诉权后果，书面告知当事人并留存记录；如认为不应适用，按现行程序及时提出异议 |
| 案件多次开庭或设庭前会议 | 法院排期或程序通知 | 阶段6按每次开庭或会议循环执行，逐次形成提纲、笔录核对和庭后分析，保持证据编号与事实锚点一致 |
| 案件进入民事二审 | 收到一审裁判或上诉材料 | 停止一审七阶段，切换 `procedure=second_instance` 并读取 `appeal-workflow.md`；先执行 A0，不沿用一审期限、角色或模板 |
| 案件进入再审或执行 | 收到再审裁定、执行通知或相关申请 | 停止一审和二审专门路由；材料读取、时间线和一般争点分析仍可使用，并明确披露不属于相应程序的专门工作流 |
| 识别涉外、港澳台、知识产权、海事海商或破产衍生诉讼要素 | 阶段1案件性质与专门领域预检 | 标记 `specialist_review_required=true`，本版只输出要素清单、风险提示与专项核验问题；完成专门法源和专业人员复核前，不直接套用普通合同纠纷的程序结论 |
