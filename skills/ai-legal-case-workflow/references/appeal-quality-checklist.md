# 民事二审质量检查清单

执行二审任一阶段组后，先检查“通用门”，再检查对应 D0–D6。出现阻断项时，不得把当前阶段组标记为 `completed`。

## 通用门

### G1 范围与程序

- [ ] 已确认 `procedure=second_instance`，没有混用一审 `start_stage/end_stage`。
- [ ] 已确认属于民事二审，刑事、行政、再审和执行事项没有混入。
- [ ] 裁定上诉已限定为受控三类；其他裁定已进入专项核验。
- [ ] 涉外、港澳台、知识产权、海事海商或破产衍生诉讼已标记专项闸门。

### G2 材料与事实

- [ ] 已列出材料范围、不可读文件和版本或校验时间。
- [ ] 原审裁判、诉状、答辩、证据、庭审和程序材料的缺口已披露。
- [ ] 关键事实、金额、日期、身份、送达和证据编号均能回链到原始载体。
- [ ] 当事人主张、法院认定、模型推论和律师结论分开表述。

### G3 法源与期限

- [ ] 具体法律引用已从权威来源核验现行有效文本和日期。
- [ ] 未核实内容统一标记，未混用其他看似相同的标识。
- [ ] 每个期限均写明主体、文件类型、送达证据、起算依据、届满日、动作和复核状态。
- [ ] 无送达证据时没有输出确定截止日或“仍在期限内”。

### G4 输出与人工终审

- [ ] `run_status` 与实际完成范围一致。
- [ ] 已区分 AI 草稿、律师待复核和律师已定稿。
- [ ] 未承诺裁判结果、胜率或法院必然采取的审理方式。
- [ ] DOCX、PDF、发送、缴费和提交状态均以实际验证为准。
- [ ] 已列出需要律师和客户裁决的事项。

## D0 入口、可上诉性、期限与费用

- [ ] 裁判文书全部页面、审级、案号、文书类型和签章已核对。
- [ ] 已区分裁判日期、宣判日期和实际送达日期。
- [ ] 一审终审、小额诉讼或不可普通上诉的情形已经阻断。
- [ ] 判决十五日、裁定十日等只是经现行法核验后的规则锚点，没有脱离送达事实机械套用。
- [ ] 无中国境内住所当事人已进入三十日期间及送达专项核验。
- [ ] 每一当事人、每一上诉分别建立期限轨道。
- [ ] 上诉状书面提交、提交法院、接收或移送状态有材料依据。
- [ ] 上诉费计算基础、预交通知、七日补交风险和缴费凭证已核对。

**阻断项**：可上诉性不明；送达事实缺失却认定截止日；缴费未知却称上诉完成；多个期限轨道被合并。

## D1 原审卷宗与裁判拆解

- [ ] 原审请求、抗辩、反诉、主文逐项对应。
- [ ] 每项事实认定已连接采用证据和原审段落。
- [ ] 未采证据、反向证据和质证意见没有被遗漏。
- [ ] 请求权基础、构成要件、举证责任和原审法律适用已拆解。
- [ ] 原审程序事件已按时间线整理。
- [ ] 遗漏请求、超出请求或遗漏当事人只在有材料依据时标记。

**阻断项**：只摘要判决结论，没有请求、证据和理由的对应关系；把当事人主张写成法院认定。

## D2 上诉请求与裁判错误审计

- [ ] 每份上诉有独立 `appeal_track`。
- [ ] 每项请求连接具体原审主文，而非抽象要求“依法改判”。
- [ ] 每项错误主张连接原审段落、证据、法源和结果影响。
- [ ] 已区分事实、证据、法律、程序和计算错误。
- [ ] 已列出反向材料和对方可能回应。
- [ ] 至少形成两个可比较策略选项，说明条件、作用、风险、缺口和程序动作。
- [ ] 策略最终选择保留给律师，没有输出伪精确胜率。
- [ ] 多轨道主张已经交叉检查，不存在自相矛盾。

**阻断项**：只有结论，没有结果影响链；修改上诉请求但未核对授权；多方上诉被合并成一份理由。

## D3 证据增量、新请求与程序事项

- [ ] 新增证据记录来源、取得时间、原审未提交原因和证明目的。
- [ ] 真实性核验路径、逾期风险和对方质证预案已列明。
- [ ] 二审举证期限以法院通知和现行证据规则复核。
- [ ] 遗漏原审请求、新增独立请求、反诉和遗漏当事人分别处理。
- [ ] 严重程序违法连接具体笔录、通知、裁定或其他原始材料。
- [ ] 每个证据缺口有责任人、截止日和失败替代方案。

**阻断项**：把任何新取得材料自动称为二审新证据；把新请求直接写入上诉请求而未做程序核验。

## D4 二审文书材料包

- [ ] 上诉状或答辩状逐项对应当前上诉轨道。
- [ ] 原审裁判引文与页码已逐字复核。
- [ ] 请求明确、可执行，并在客户和律师授权范围内。
- [ ] 事实、金额、日期、证据编号在各文书间一致。
- [ ] 证据目录区分原审证据与二审新增证据，没有重排造成混淆。
- [ ] 法源报告含权威来源、效力、核验日期和适用边界。
- [ ] 对方上诉状尚未送达时，没有生成假想答辩结论。
- [ ] 裁定上诉模板只用于受控三类裁定。

**阻断项**：请求超授权；关键引文无法回链；未经核实法源被表述为确定依据；不同文书事实冲突。

## D5 庭审、询问、调解与庭后补强

- [ ] 没有提前承诺开庭或不开庭。
- [ ] 审理范围与法定例外分栏处理。
- [ ] 每个争点有事实、证据、法源、发问和底线回答。
- [ ] 新证据质证覆盖真实性、关联性、合法性、证明目的和逾期理由。
- [ ] 调解金额和条件明确标明是否已获客户授权。
- [ ] 庭审记录按庭次保存，法院要求和补充期限准确记录。
- [ ] 庭后新情况先回写共用底座，再更新文书。

**阻断项**：把 AI 建议当作调解授权；庭后意见引入未经审理且未经程序核验的新请求。

## D6 二审裁判、交付与归档

- [ ] 原审与二审主文、认定、理由和费用逐项对比。
- [ ] 已核对终审状态、送达、履行期限、保全和费用负担。
- [ ] 审限记录包含立案日和延长信息，没有承诺结案日期。
- [ ] 发回重审已建立新一审交接；再审和执行只作边界提示。
- [ ] 法院版、客户版和团队版的敏感信息与用途相匹配。
- [ ] 交付文件已实际打开、回读或渲染验证，未验证格式没有宣称完成。
- [ ] 归档包含上诉轨道、材料快照、法源报告、律师裁决和版本记录。

**阻断项**：误称二审后续专项工作已经完成；未验证文件却标记交付成功；客户报告遗漏立即履行或期限事项。

## 跨阶段一致性抽查

任选至少三项关键事实，从 A1 追踪到 A6：

| 检查对象 | A1 原审底座 | A2 错误矩阵 | A4 文书 | A5 提纲 | A6 报告 | 一致性结果 |
|---|---|---|---|---|---|---|

至少抽查：

- 一项决定请求范围的事实。
- 一项金额或期间计算。
- 一项核心证据及页码。
- 一条关键法律依据。
- 双轨案件中一组可能互相冲突的主张。

## 完成回执

```yaml
quality_gate: D0 | D1 | D2 | D3 | D4 | D5 | D6
gate_result: pass | conditional | fail
blocking_items: []
unverified_items: []
cross_document_conflicts: []
lawyer_decisions_pending: []
run_status: completed | partial | blocked | waiting_external
resume_from: <下一阶段组或待补步骤>
```

`conditional` 必须说明条件和负责解决的人。只要存在阻断项，`run_status` 不得为 `completed`。
