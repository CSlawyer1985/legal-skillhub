# 安全与案件数据边界

本仓库公开发布的是办案工作流、模板和质量检查规则，不应包含任何真实案件材料。

## 禁止公开提交的内容

请勿通过 Issue、Discussion、Pull Request、提交记录或示例文件上传：

- 未公开的合同、证据、庭审记录和诉讼策略。
- 可以识别自然人或企业案件关系的身份信息组合。
- 身份证号、联系方式、住址、银行账户和其他直接标识符。
- API Key、Token、Cookie、私钥、账号密码和内部访问地址。
- 涉密、合同明禁、监管明禁或其他刚性禁止处理的数据。

公开复现问题时，只使用虚构数据或不可逆脱敏的最小样本。

## 发现敏感信息怎么办

如果发现仓库中可能存在敏感信息：

1. 不要在公开 Issue 中复制或引用敏感内容。
2. 优先使用 GitHub 的私密安全报告功能联系仓库维护者。
3. 如私密安全报告不可用，请通过维护者 GitHub 主页提供的非公开联系方式报告。
4. 在维护者确认清理完成前，不要继续传播相关文件或链接。

## 使用真实案件材料

使用本技能处理真实案件时，应先完成数据分类和链路审查：

- 绿色数据可用于公开研究和普通测试。
- 黄色数据应限制范围，并使用可审计链路。
- 红色数据仅在任务必要、授权清楚、链路可信且有人工最终复核时处理。
- 红线数据不得进入普通 AI 链路、外部代理或公开仓库。

本技能不会因为部署在本地或使用官方 AI 服务而自动消除数据泄露、误外发和越权处理风险。

## 法律工作安全边界

- AI 输出是候选意见，不是最终法律结论。
- 引用法律、司法解释和案例前，应核实当前效力和原始来源。
- 关键事实、金额、日期、身份和证据引用应回到原始材料复核。
- 对外发送、提交法院或交付客户的文件必须经律师定稿。
