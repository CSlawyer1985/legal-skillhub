### CASE-001：辞退面谈 SOP

- **问题描述**：辞退员工时如何开展面谈，既合法合规又维护企业口碑，避免激化矛盾
- **涉及模块**：离职 / 员工关系
- **解决方案**：
  - **第一步（准备）**：分析被辞退者性格特点，收集过往业绩表现，梳理面谈流程，明确公司赔偿底线，预设对方可能问的问题
  - **第二步（谈判）**：共情优先，不盛气凌人，给对方台阶下；涉及赔偿原则时斩钉截铁，表明无商量空间
  - **第三步（利他）**：真诚提供职业发展建议，利用人脉提供招聘信息或推荐工作
- **关键依据**：心理学"利他行为"理论；劳动法相关赔偿规定
- **注意事项**：
  - 全程录音备份（提前告知对方）
  - 准备好 AB 两档赔偿方案
  - 避免单独在密闭空间长时间面谈
  - 准备好离职证明当场或约定时间交付
- **记录时间**：2026-04

### CASE-002：严重违纪证据采集与劳动关系处理

- **问题描述**：员工严重违纪（如旷工、违规操作）时，HR 如何合法有效地收集证据，为后续纪律处分或解除合同提供依据
- **涉及模块**：员工关系 / 劳动关系
- **解决方案**：
  - **第一优先**：让员工本人书写检讨书/情况说明（完整陈述时间/地点/原因/经过/后果），亲笔签名+日期
  - **第二优先**：违纪记录表，员工签字确认；对无法自写的，代填后诵读告知，员工按手印
  - **第三优先**：同事证言（需与其他证据形成证据链）
  - **物证**：损坏设备等拍照保存
  - **政府处理记录**：涉及违法（赌博/盗窃等）及时报警，获取处理结论
  - **视听资料**：监控/录音/微信记录，但需注意电子证据易被篡改
- **关键依据**：《劳动合同法》；最高法证据规则
- **注意事项**：
  - "大错不犯小错不断"：平时做好跟踪记录，积累日常违规证据
  - 证据链完整性比单一证据强度更重要
  - 任何证据上必须有员工签字确认，口头告知无效
- **记录时间**：2026-04

### CASE-005：公司搬迁的员工安置与风险控制

- **问题描述**：公司因经营需要搬迁办公地点，员工以通勤距离变远为由拒绝到岗，HR 如何处理？
- **涉及模块**：劳动合同 / 员工关系
- **解决方案**：
  - **第一步**：评估搬迁距离和通勤影响程度
  - **第二步**：制定配套措施（班车/弹性工时/交通补贴）降低影响
  - **第三步**：提前书面通知员工，说明搬迁安排及配套措施
  - **第四步**：员工仍无法到岗且措施到位的情况下，协商解除劳动合同
  - 协商不成：评估是否构成"客观情况重大变化"，依法支付补偿或走解除程序
- **关键依据**：《劳动合同法》第四十条第三项；最高法劳动争议司法解释
- **注意事项**：
  - 不可一刀切要求所有员工无条件到岗
  - 未提供任何配套措施直接要求员工到岗，员工拒绝后以旷工解除的，存在违法解除风险
  - 距离确实过远的，优先协商解除，给付经济补偿
- **记录时间**：2026-04

## 二、薪酬、社保与合规

---

### CASE-004：不胜任调岗后同步调薪的合规操作

- **问题描述**：员工不能胜任工作被调岗后，薪资是否必须同步调整？如何合法合规地操作？
- **涉及模块**：劳动合同 / 薪酬 / 异动
- **解决方案**：
  - **有制度规定或合同约定**：可直接按新岗位确定薪酬，无需二次协商
  - **无制度规定**：须与员工书面协商确认新岗位薪酬标准，不能单方决定
  - **操作步骤**：
    1. 确认不胜任事实（绩效记录/考核结果）
    2. 发布调岗通知（新岗位+新薪酬）
    3. 员工书面签收确认
  - 注意：调岗须有合理性（不胜任/客观情况/医疗期满等），不能借调岗之名变相降薪
- **关键依据**：《劳动合同法》第四十条；《工资支付暂行规定》
- **注意事项**：
  - 不能胜任调岗的，让渡的是完整岗位管理权（含薪酬权）
  - 无任何依据的单方调岗，员工拒不到岗不构成旷工
- **记录时间**：2026-04

### CASE-009：Yss 财务经理薪资争议

**副标题**：社保漏调 + 历史拆薪 + 加班费三合一

- **问题描述**：财务部广告线 BP 经理 Yss，提出三项历史薪资/社保争议：
  1. 2023年7月，公司未执行社保公积金基数年度调整，实际缴费基数偏低，要求补缴基数差额
  2. 2021年，公司将底薪拆分为两部分发放（8000元以内公司发，8000元以上由第三方公司代发，且社保公积金及个税统一按8000元为基数计算），要求补缴正确金额
  3. 2023年，员工存在 4 个工作日加班（共 8 小时）未支付 150% 加班工资

- **涉及模块**：社保公积金 / 薪酬 / 劳动合同 / 员工关系

- **风险评估**：

  **保留在职风险（不离职）**
  
  *内部风险*：
  - 团队氛围不稳定，影响工作环境
  - 单一员工补偿方案易引发团队不平衡，扩大化为更大规模员工关系风险
  
  *外部风险*：
  - 2023年7-9月社保公积金问题：若追溯补缴，可能全公司扩大化，还须支付滞纳金
  - 2021年历史拆薪：存在拆分收入偷逃个人所得税风险，可能引发税务稽查 + 罚款
  
  【依据】《中华人民共和国刑法》第 201 条（逃税罪）

- **解决方案**：
  - **推荐方案**：协商一致解除劳动合同，支付经济补偿金 N+1
  - 预计成本：N+1 + 额外费用（视具体 N 和额外谈判空间而定）
  
  【依据】《劳动合同法》第 36 条（协商一致解除）、第 46 条（经济补偿金支付情形）

- **关键依据**：
  - 《劳动合同法》第三十六条、第四十六条
  - 《中华人民共和国刑法》第二百零一条

- **注意事项**：
  - 历史拆薪问题是公司层面的合规风险，**不建议公开承认**，谈判时以"补偿离职"为口径，而非"承认违规补缴"
  - 此类案例具有高度传染性，务必保密处理，不进入仲裁或诉讼程序
  - 2021年拆薪问题若被员工向税务局举报，风险远超单个补偿，需快速通过协商出清风险

- **记录时间**：2026-05

### CASE-003：离职原因标准化分类与数据化分析

- **问题描述**：员工离职时 HR 如何准确记录离职原因，并建立可分析的数据体系以支持组织决策
- **涉及模块**：离职 / 数据分析
- **解决方案**：
  - 建立两级离职原因分类体系（一级：大类；二级：具体原因）
  - 主被动离职分别统计：主动离职反映组织管理问题，被动离职反映人才筛选问题
  - 定期分析：按部门/岗位/地区/在职时长多维度交叉分析
  - 关键指标：主动离职率、各离职原因占比、核心岗位离职率
  - 离职数据与组织事件（晋升/调薪/架构调整）关联分析
- **关键依据**：内部数据积累
- **注意事项**：
  - 离职面谈时由 HR 或 BP 记录，不依赖员工自填（自填往往过于简略）
  - 保护员工隐私，离职数据汇总分析用于管理改进，不针对个人
- **记录时间**：2026-04

### CASE-006：枫林项目——医疗期满员工离职处置

- **问题描述**：员工55岁+、司龄12年+，因病进入医疗期（12个月），医疗期满后无法继续工作，HR 如何依法处理离职及补偿？
- **涉及模块**：离职 / 医疗期 / 薪酬
- **解决方案**：
  - **医疗期**：本单位工龄15年以上 → 医疗期18个月，按18个月内累计病休计算
  - **离职补偿**：
    - 经济补偿金：N（按司龄12年 = 12个月工资）+ 1（代通知金）
    - 医疗补助费：不低于6个月工资（经劳动能力鉴定确认丧失/部分丧失劳动能力）
    - 重病/绝症：增加50%/100%
  - **补偿基数**：基本工资（含补贴/含奖金）逐级确认，取最高
  - **替代路径**：可申请非因工丧失劳动能力鉴定，若结果为完全丧失劳动能力满1年，可提前退休
- **关键依据**：《劳动合同法》第四十条；《江苏省劳动合同条例》第三十四条
- **注意事项**：
  - 社保缴纳合规性（基数/时间截点）影响离职成本测算
  - 商业保险（门诊1万/住院10万/重疾50万）在职期间仍可申请报销
  - 退休后医保待遇需等劳动能力鉴定审核完成后确定
- **记录时间**：2026-04

### CASE-007：北森系统上线——多角色协同切换

- **问题描述**：HRSSC 主导多系统同时上线（组织架构/考勤/工资单/招聘/数字人才），如何在短期内完成平稳切换并让员工快速上手？
- **涉及模块**：HRSSC运营 / HRIS
- **解决方案**：
  - **上线前（T-3天）**：线下运营预告（群/公告），提前告知员工切换安排
  - **上线前（T-2天）**：完成系统流程第三轮测试 + 工资条查看测试
  - **上线当天**：正式切换；确认OA配置完成；考勤假期数据导入
  - **上线后**：组织员工直播培训（PPT+演讲稿），同步发布操作手册（按角色×按客户端）
  - **持续运营**：云社区发布系列QA帖子，定期推广更新功能
- **关键依据**：北森系统上线运营实践总结
- **注意事项**：
  - 提前识别需要中间件的系统间数据打通问题
  - 关注唯一性字段（工号/花名/邮箱）在多系统间的一致性
  - 建立切换失败应急回退机制
- **记录时间**：2026-04

### CASE-008：HRSSC 突发事故——员工账号误删恢复

- **问题描述**：员工账号因系统或人为操作被误删（如从钉钉组织架构中被移除），HRSSC 如何快速响应并恢复？
- **涉及模块**：HRSSC运营 / 应急管理
- **解决方案**：
  - **即时（T+1小时）**：通过管理后台重新拉入组织（使用原userID），恢复组织角色权限和架构
  - **数据恢复申请**：联系平台CS团队，确认可恢复项（部门架构/群聊数据/审批流/考勤数据）及不可恢复项（日程/知识库文档）
  - **业务系统权限恢复**：组织绩效/财务系统（每刻报销/曹操专车/阿里商旅等）/ BI看板逐一检查并恢复
  - **内部信息同步**：钉钉群公告说明系统原因，直白告知无其他背后逻辑，消除员工疑虑
  - **后续预防**：依托系统传输数据，减少人工操作；建立数据恢复SOP和责任到人的checklist
- **关键依据**：突发事故应急处置实践
- **注意事项**：
  - 判断系统和人为原因比例，如实告知当事人
  - 需要子画（当事人）介入的操作，由相关方主动发起邀请
  - 未来通过北森系统打通内部用户中心，彻底排除人工误操作风险
- **记录时间**：2026-04
