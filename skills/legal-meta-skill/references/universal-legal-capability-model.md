# 通用法律能力模型

## 1. 目的与边界

本模型定义法律类 Skill 共同遵守的最低能力契约。共同底座不是对每项任务进行无边界的“万能分析”，而是对十二个模块**全部检查、条件展开**：每次运行都要逐一判断模块是否适用；适用时完成最低检查与最低输出，不适用时记录理由，受阻时记录缺口并执行降级或停止路径。

本模型只规定稳定的分析结构、输出字段和失败语义，不提供某一事项的现成法律结论。具体法条、司法解释、期限、案例、裁判规则和地方口径必须结合任务法域与法律时点在运行时独立核验。任何配置、模板或示例均不得以模型知识替代核验，也不得把联网服务、法律数据库、其他 Skill 或个人机器路径设为通用模型的运行依赖。

最低契约之上的标准化展开见第 6 节增强检查目录、[法律方法核心规则](legal-method-core.md) 与 [法律场景原型](legal-scenario-archetypes.md)；三者是增强层，不替代本模型的最低契约。

## 2. 基础链路

所有法律任务至少沿下列链路推进，并允许根据场景迭代回查：

`任务定义 → 主体角色 → 法域时间 → 法律关系 → 请求要件 → 事实证据 → 法源解释与涵摄 → 程序 → 救济执行 → 人工复核`

这条链路要求材料、事实、法律评价与程序状态分层记录。输出范围受任务目的约束；检查全部模块不等于扩张为全案、全合同或全法域审查。

## 3. 激活策略与状态码

`activation_policy` 固定为 `mandatory-review-conditional-expansion`，含义如下：

1. 十二个模块必须全部出现在配置中并逐一接受适用性检查。
2. `active`：模块适用，必须完成该模块的最低检查项并产生非空的最低输出；若场景需要，可在最低契约上继续展开。
3. `not_applicable`：模块已经检查但确实不适用。必须记录与本次任务事实和范围相联系的具体 `reason`，不得用“按需”“无”“略”等空泛表达，也不得借此跳过不利问题。
4. `blocked`：模块原则上适用，但因事实、材料、权威来源、权限、工具或人工判断缺口无法可靠完成。必须同时记录 `gap` 与 `fallback`；`fallback` 应说明可先行完成的范围、补充材料或核验动作，以及必要时停止哪一类结论或操作。

`blocked` 不是把缺口包装为结论的许可。凡缺口影响效力、金额、期限、责任、程序资格或其他核心判断，应停止输出确定性结论，并转入补充证据、独立检索或人工复核。

## 4. 通用字段约定

- `schema_version`：本模型版本，当前为 `universal-legal-core/v0.1`。
- `activation_policy`：固定为 `mandatory-review-conditional-expansion`。
- `modules`：以稳定模块 ID 为键的十二模块对象，不得新增近义 ID 或省略模块。
- `label_zh`：面向人的中文模块名。
- `status`：仅允许 `active`、`not_applicable`、`blocked`。
- `reason`：说明模块为何以当前状态处理；必须具体、非空。
- `required_outputs`：模块最低输出字段名列表；`active` 模块不得为空。
- `gap`：`blocked` 状态必填，列明无法完成的事实、证据、来源、权限或能力缺口。
- `fallback`：`blocked` 状态必填，列明降级、补充、人工复核或停止路径。

下列字段名是后续 Skill IR、校验器、模板与评测共享的稳定词典。字段值可按目标 Skill 的输出格式表达，但不得改变字段语义，也不得以一句空泛结论代替结构化最低输出。

## 5. 十二模块四段式契约

### 5.1 `task_context` — 任务目的与受众

**触发问题**

本次重复任务是什么，服务谁、影响谁的决策，由谁承担决策与复核责任，哪些事项明确不在范围内？

**最低检查项**

识别任务类型、决策目标、目标用户、实际受众、决策责任人、人工复核者、交付形态与排除项；检查用户请求是否授权扩展审查范围。

**最低输出**

`task_type`、`decision_goal`、`target_users`、`audience`、`decision_owner`、`reviewer`。

**停止或降级条件**

任务目标、受众或授权范围不明且会实质改变分析方向时，停止实质结论并请求澄清；仅能确定部分范围时，明确已处理与未处理部分后降级输出。

### 5.2 `jurisdiction` — 法域

**触发问题**

哪些国家、地区、监管体系、法院或仲裁地可能适用，准据法与争议解决地如何确定，是否存在冲突规范或强制性规则问题？

**最低检查项**

识别地域连接点、准据法依据、法院管辖或仲裁地、跨法域冲突、强制性规范与法域排除项；不得把港澳台或外国法默认为中国大陆法。

**最低输出**

`jurisdiction_scope`、`governing_law_basis`、`forum_or_seat`、`conflict_rules`。

**停止或降级条件**

关键连接点、选择法条款或管辖资料缺失时，不作确定的法域结论；列明待核事实并分别给出条件化分析，必要时转交相应法域专业人员复核。

### 5.3 `temporal` — 时间

**触发问题**

事实发生、权利义务形成、程序启动和法律适用分别处于什么时间，是否涉及新旧法衔接、期限、时效或持续性状态？

**最低检查项**

确定法律核验时点、关键事件时间线、规范版本、生效与失效状态，以及需要核验的诉讼时效、除斥期间、申报或程序期限；区分已确认日期与待核日期。

**最低输出**

`as_of_date`、`event_timeline`、`applicable_versions`、`limitation_and_deadline_checks`、`temporal_gaps`。

**停止或降级条件**

关键日期或规范版本无法确认时，不计算或承诺确定期限，不断言权利已消灭或仍可行使；输出条件区间、紧急保全动作和运行时核验要求。

### 5.4 `actors` — 主体角色

**触发问题**

有哪些自然人、法人、非法人组织、机关或代理参与，各自的法律地位、权限、利益与冲突是什么？

**最低检查项**

核对主体身份、法律地位、角色、权利义务、代理或授权、行为能力、签约或诉讼资格、控制与关联关系，以及潜在利益冲突。

**最低输出**

`actor_map`、`legal_status`、`roles_and_interests`、`authority_and_capacity`、`conflicts_of_interest`。

**停止或降级条件**

主体身份、授权链或资格材料缺失且影响效力或程序地位时，停止对应结论或操作；区分名义主体与实际参与者，列出核验材料和人工冲突检查。

### 5.5 `matter` — 法律事项

**触发问题**

任务涉及哪些法律关系、交易、行为、争议或监管事项，核心问题与边界是什么？

**最低检查项**

识别并区分法律关系、事项类型、关键行为与标的，形成问题树；记录已知重要事实、排除项及相邻但未获授权的问题，避免以文件标题代替关系定性。

**最低输出**

`issue_scope`、`legal_relationships`、`issue_tree`、`material_facts`、`exclusions`。

**停止或降级条件**

基础关系或事项类型存在多种合理定性且材料不足时，采用备选定性并行分析，不选定唯一结论；越出授权范围的相邻问题仅提示风险与所需授权。

### 5.6 `claims_and_elements` — 请求与要件

**触发问题**

各方可能提出什么请求、主张、抗辩或监管立场，每项成立需要哪些法律要件和事实支撑？

**最低检查项**

逐项拆解请求、抗辩、构成要件、例外、法律效果和反方最强论点；将每一要件映射到已知、待证、冲突或缺失事实，区分实体请求与程序申请。

**最低输出**

`claims_defenses`、`legal_elements`、`element_fact_mapping`、`remedies_requested`、`counterarguments`。

**停止或降级条件**

请求内容、法律关系或关键要件无法确定时，不给出胜负式结论；输出候选请求与要件缺口，限定可评估部分并要求补充事实或专业复核。

### 5.7 `authority_and_interpretation` — 法源与解释

**触发问题**

哪些法律来源支撑规则，效力层级、时点、地域、冲突和解释路径如何，规则如何涵摄本案事实？

**最低检查项**

分层列出法律、行政法规、司法解释、规范性文件、案例、地方口径及其他材料；核验名称、定位、效力和时点，说明文义、体系、目的等解释依据，并完成规则—事实涵摄与冲突处理。

**最低输出**

`authority_inventory`、`authority_hierarchy`、`verification_status`、`interpretation_method`、`application_analysis`、`conflicting_authorities`。

**停止或降级条件**

核心依据未找到、未核验、已失效或存在无法解决的冲突时，不用模型常识补足确定结论；保留检索记录，标注线索与核验状态，并转入补充检索或人工判断。

### 5.8 `proof` — 证明

**触发问题**

每项主张需要证明什么事实，现有证据位于何处，由谁承担举证责任，适用何种证明标准，缺口会造成什么后果？

**最低检查项**

逐项列出待证事实、证据名称及页码/段落/数据位置，分析真实性、合法性、关联性、证明力与相互印证；分配举证责任，识别证明标准、证据冲突、证据缺口及可能的不利后果。不得仅写“证据充分”或“证据不足”。

**最低输出**

`facts_to_prove`、`evidence_locator`、`burden_of_proof`、`standard_of_proof`、`evidence_gaps`、`adverse_consequences`。

**停止或降级条件**

关键材料不可读取、来源不明、完整性异常或待证事实无可靠证据时，不把材料内容直接认定为案件事实；输出缺口、保全或补强动作、可分析范围及需人工核验的证据问题。

### 5.9 `procedure` — 程序

**触发问题**

事项处于什么程序阶段，由何机构处理，需要满足哪些前置条件、资格、期限、送达、受理或证据规则？

**最低检查项**

识别法院、仲裁机构、行政机关或内部程序，核对程序地位、管辖、阶段、前置程序、申请或受理条件、送达、保全、举证、听证与需要运行时核验的期限。

**最低输出**

`forum_and_jurisdiction`、`procedural_posture`、`procedural_steps`、`deadlines_to_verify`、`admissibility_or_prerequisites`、`procedural_risks`。

**停止或降级条件**

程序状态、送达信息、资格或期限资料缺失时，不代替正式程序确认，不执行不可逆提交；先列紧急节点、补充材料和向受理机构或人工复核者确认的路径。

### 5.10 `outcomes_and_enforcement` — 结果与执行

**触发问题**

各类可能结果产生什么法律效果、责任与金额敞口，是否可执行、如何执行，现实回收或履行受哪些条件限制？

**最低检查项**

区分胜、负、和解、行政处理或交易调整等情景，分析法律效果、责任类型、金额口径、救济组合、可执行性、资产或履行条件、跨境或跨区域执行及回收约束。

**最低输出**

`outcome_scenarios`、`legal_effects`、`liability_and_exposure`、`enforceability`、`enforcement_path`、`recovery_constraints`。

**停止或降级条件**

金额基础、责任范围、资产状态或执行条件未经核验时，不给出确定回收额或执行承诺；以条件化情景和计算口径输出，并区分法律上成立与现实中可执行。

### 5.11 `strategy_and_uncertainty` — 策略与不确定性

**触发问题**

在法律、事实、证据、程序和商业约束下有哪些可选路径，关键假设和不确定性如何影响建议，何时应升级、停止或改道？

**最低检查项**

比较主要方案、成本、时效、风险、可逆性与商业影响；显式记录假设、未知项、反方动作和情景敏感性，提出责任人、时间点、材料与升级触发条件。

**最低输出**

`options`、`assumptions`、`uncertainties`、`scenario_analysis`、`recommended_actions`、`escalation_triggers`。

**停止或降级条件**

关键事实或法律依据不足以支持单一路径时，不将偏好包装为唯一答案；给出条件化选项、可逆的先行动作和需要决策者或专业人员选择的分歧点。

### 5.12 `governance` — 职业治理

**触发问题**

任务如何满足保密、数据边界、权限、来源留痕、利益冲突、专业责任、人工复核和定期更新要求？

**最低检查项**

检查客户与个人信息保护、原始材料只读、最小权限、外部传输授权、来源和操作审计、利益冲突、角色边界、人工复核责任及法律与模板的复核周期。

**最低输出**

`confidentiality_and_data_boundary`、`permissions`、`human_review`、`source_and_audit_trail`、`professional_responsibility_limits`、`review_cycle`。

**停止或降级条件**

存在未授权外传、密钥暴露、利益冲突、越权操作或缺少必要人工复核时，停止相关处理或正式交付；采用本地、脱敏、只读或人工接管路径，并记录未完成治理事项。

## 6. 模块增强检查目录（条件展开）

完成各模块最低契约后，按场景需要从下列增强检查中选用。增强检查是最低契约之上的标准化展开目录，不降低、不替代第 5 节的最低输出字段；各条方法纪律的完整表述见 [法律方法核心规则](legal-method-core.md)，场景化裁剪见 [法律场景原型](legal-scenario-archetypes.md)。

- `task_context`：商业目的转译（先明确委托人目的再倒推法律路径）；受众工程（按读者调整论证冗余度与结论前置程度）；多粒度表达（摘要/标准/完整三档）。
- `jurisdiction`：交叉程序的法域面（同一事实触发民行、刑民等交叉程序时的连接点识别）；强制性规范对法律选择的排除。
- `temporal`：时间效力三轨制（法律事实时点定位 → 新/旧/持续三分 → 法不溯及、有利溯及、空白溯及的类型判定）；政策敏感领域的监管政策时间轴。
- `actors`：名义主体与实际参与者区分；授权链逐环核验。
- `matter`：定性优先（按权利义务实质内容定性并写明特征依据）；多种合理定性并行展开；开放问题类型化（分类标准 + 逐类规则）。
- `claims_and_elements`：请求权基础映射链（请求 → 规范基础 → 要件 → 要件事实 → 证据）；请求权竞合与主位/备位请求结构；效力阶梯层级标注（成立/未生效/有效/无效/可撤销/效力待定/对抗力）。
- `authority_and_interpretation`：找法顺序纪律（具体规则穷尽 → 漏洞填补 → 基本原则）；规范性质辨识前置；准法源四档引用姿态（裁判依据/应当参照/仅能说理/须举证查明）；体系化找法（特别法不足时回填一般法）；类案一致性约束（三核验、可适用性论证、背离升级）。
- `proof`：证明责任双重结构（行为责任流动/结果责任分配）与两种失败语义（证据不足可补强/真伪不明担后果）；证明标准二维分层（程序阶段 × 事实类型）；推定二分法；证据链相互印证与心证公开。
- `procedure`：程序阶段—结论深度耦合（立案/实体/执行/再审各阶段只输出与之匹配的结论类型与确定性）；交叉程序路径选择。
- `outcomes_and_enforcement`：执行依据明确性审查（主体与给付内容明确）；执行程序不解决实体争议的边界。
- `strategy_and_uncertainty`：结论可接受性回检（逻辑与常识、实质公平一致）；利益衡量三步（指认冲突利益 → 对照评价序列 → 落地为解释技术）；风险四问（风险与成因/后果/概率敞口/缓释措施）与可容许性判断；主路径受阻时的 back-up plan。
- `governance`：检索质控留痕（法条识别、效力甄别四问、双源交叉验证、检索记录可复核）；执业免责操作（前提声明、适用范围限定、信息不全时的书面声明）。

## 7. 使用与复核

目标 Skill 应复制机器模板并按自身任务填充，不得删除模块。条件展开只增加场景所需字段与检查，不得降低本模型最低契约。评测至少应确认：十二模块均被检查，状态码使用正确，`active` 输出不为空，`not_applicable` 有具体理由，`blocked` 有缺口与降级/停止路径，且所有易变法律结论保留运行时核验和人工复核边界。
