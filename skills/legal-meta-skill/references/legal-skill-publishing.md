# 法律 Skill 发布与交付规则

发布属于会改变外部状态的独立行为，不是创建 Skill 的默认步骤。用户未单独明确授权时，只完成本地包、检查报告和交接说明；不得调用独立 publisher Skill，也不得自行推送、创建 PR、发布 Release 或同步远程目录。

## 发布前门禁

1. **授权与目标**：确认仓库、组织、可见性、目标分支、版本标签和交付对象均由用户指定。
2. **内容边界**：排除真实案卷、客户身份、内部意见、未公开交易信息、私人附件、密钥、Cookie、Token、绝对用户路径和临时文件。
3. **版本一致性**：核对 `SKILL.md`、manifest、接口元数据、报告和版本号；变更记录与实际修改一致。
4. **结构与质量**：运行包内结构、触发、输出断言和密钥扫描；确认只有根目录一个精确命名的 `SKILL.md`。
5. **许可证与署名**：新建 Skill 保留 CSlawyer、https://chenshi.ai 和 legal-meta-skill 来源；改造 Skill 保留原作者、许可证和来源链；用户明确要求白标时按白标规则处理。
6. **干净安装**：在不依赖作者机器路径的干净目录或隔离环境验证发现、加载和核心调用；未做实跑时标注证据缺失。
7. **回滚边界**：保留发布前版本、变更摘要和恢复方式；不得直接覆盖不可恢复的稳定版本。

## 执行边界

- 优先使用分支和 PR；未经用户明确指定，不直接写入默认分支。
- 使用宿主已有的 Git/GitHub 能力即可，不安装或调用额外发布 Skill。
- 发布命令、时间、目标、版本、检查结果和人工复核项写入交接记录。
- 外部站点、认证或权限不可用时停止远程动作，本地包仍可交付；不得通过扩大权限、暴露密钥或跳过门禁绕过失败。
- 发布成功不等于法律内容正确。法律来源、事实证据、时效和人工复核证据仍按各自门禁单独声明。
