# 法律核心规则

法律类 Skill 采用以下最低质量标准。合同、诉讼、尽调、咨询或合规场景可以增加更严格规则，但不得降低真实性、时效性、可追溯性、四层分离和人工复核边界。本规则与 [通用法律能力模型](universal-legal-capability-model.md)、[法律 Skill IR](legal-skill-ir.md) 共同构成下游 Skill 的稳定底座；它们规定检查与输出的最低结构，不把轻量任务变成全案、全合同或全法域的长报告。最低契约之上的方法纪律见 [法律方法核心规则](legal-method-core.md)，按任务类型的场景化裁剪见 [法律场景原型](legal-scenario-archetypes.md)。

## 全部检查、条件展开与完整推理链

下游 Skill 必须采用 `universal-legal-core/v0.1`，对通用模型的十二模块进行**强制检查、全部检查、条件展开**。机器字段必须使用稳定模块 ID，不得翻译、缩写或另造同义字段；中文名称用于界面和说明：

`task_context`、`jurisdiction`、`temporal`、`actors`、`matter`、`claims_and_elements`、`authority_and_interpretation`、`proof`、`procedure`、`outcomes_and_enforcement`、`strategy_and_uncertainty`、`governance`。

每一模块均须记录为：

- `active`：本任务适用，完成最低检查并输出相应的最低结论、事实、缺口或动作；
- `not_applicable`：已检查但确实不适用，记录与任务范围和事实相关的具体理由；
- `blocked`：原则上适用但因材料、权限、核验来源或人工判断缺口不能可靠完成，记录 `gap`、`fallback` 及必要的停止路径。

只有模块对该任务不适用时才能跳过实质展开，且必须记录理由；不得以“按需”“无”或“略”替代检查。全部检查不等于每个模块都写成长篇正文：轻量 Skill 可以用状态表、字段或短段落交付，但不得删除模块、掩盖缺口或将阻塞事项包装成结论。

适用模块按下列强制顺序推进；任务循环或事实变化时可以回查前项：

`任务与决定 → 主体与权限 → 法域与时间 → 法律关系定性 → 请求/抗辩/要件 → 待证事实/证据/证明责任 → 法源效力/解释/涵摄 → 程序与期限 → 法律效果/计算/执行 → 方案与不确定性 → 人工复核`

上述链路是工作顺序，不是把十二模块合并为十一个字段。每一步须回填对应模块状态和最低输出；其中“法域与时间”分别落入 `jurisdiction`、`temporal`，“方案与不确定性”与“人工复核”分别落入 `strategy_and_uncertainty`、`governance`。链路还应落实材料、事实、法律评价和程序状态的分层记录。任务目标、授权范围、法域或关键事实不明且会实质改变结论时，应先限定可处理范围或请求澄清，而非自行扩张审查范围。

## 法域、时间与来源

### 法域

- 法域不得只填国家或地区名称。应分别识别实体法、程序法、处理机构、地域连接点、法律选择或准据法依据，以及可能排除或优先适用的强制性规范。
- 默认法域仅在用户未指定且任务明显属于中国大陆法律时采用“中国大陆”；不得把港澳台或外国法默认为中国大陆法。
- 关键连接点、选择法条款、机构规则或管辖资料缺失时，不作确定法域结论；列明待核事实，采用条件化分析，并在必要时转交相应法域专业人员复核。

### 时间、时效与期限

- 时间不得只填检索截止日。应检查事实时间线、权利义务形成与程序启动时点、法律核验时点、规范生效/失效及新旧法衔接。
- 对诉讼时效、除斥期间、申报期限、送达、答辩、上诉、执行等特殊期间和程序期限，分别标明已确认日期、待核日期、计算依据与需要运行时复核的节点。
- 关键日期或规范版本不能确认时，不计算或承诺确定期限，不断言权利已消灭或仍可行使；改为输出条件区间、紧急保全动作和核验路径。

### 来源真实性与效力

- 具体法条、司法解释、诉讼时效、除斥期间、案例和地方口径必须独立检索或复核，不能仅凭模型知识形成核心结论。
- 权威性一般按：法律 → 行政法规 → 司法解释 → 规范性文件 → 指导性/参考性案例 → 地方口径 → 权威实务或学术资料 → 普通网络线索。
- 低层级材料不得对抗高层级规范；新旧法、特别法/一般法或地域口径冲突时，显式说明冲突、解释路径、涵摄理由和剩余不确定性。
- 引用至少包含文件全名、条文编号或案例定位，并标注来源类型与核验状态。核心依据未找到、未核验、已失效或存在未解决冲突时，停止相应确定性结论，保留检索记录并转入补充检索或人工判断。

建议使用以下来源标签或语义等价记录：

- `[法条原文]`
- `[裁判文书]`
- `[权威数据库检索]`
- `[本地知识库]`
- `[联网检索 — 需复核]`
- `[模型知识 — 需验证]`
- `[用户提供]`
- `[已验证 — YYYY-MM-DD]`

## 依据不足的三值处理

1. 有可靠依据：正常分析并给出定位、来源、核验状态和适用边界。
2. 信息可合理补充但尚未核验：仅作为线索，标注“需验证”，不得作为核心结论依据。
3. 关键依据缺失：停止给出确定性结论，列明缺失事实/法律来源、补充方式和可先行完成的工作。

效力、金额、期限、责任和程序资格等核心事项不得用未经验证的模型知识补足。不得用没有数据、方法和适用边界支持的精确胜诉率、败诉率或回收率，替代不确定性、证据缺口和条件化情景说明。

## 材料、事实、法律与程序四层分离

1. **材料层**：客观存在的文件、数据、物品和陈述；材料存在不等于内容真实。
2. **事实层**：经真实性、合法性、关联性、证明力和相互印证审查后形成的事实认知；区分已确认、待核实、冲突和缺口。
3. **法律评价层**：以事实为小前提，结合规范、构成要件、举证责任、证明标准和解释方法形成法律判断。
4. **程序层**：请求、主张、抗辩、申请、裁判或监管处理及其程序状态；分析者判断不得冒充裁判或监管认定。

核心结论应能够反向追溯：`程序动作或处理 ← 法律要件与评价 ← 待证/已证事实 ← 原始材料`。

## 法律关系、请求、证明与对抗

- 先识别法律关系、事项对象、专业领域和可选定性；基础关系存在多种合理定性而材料不足时，并行说明备选路径，不擅自选定唯一结论。
- 在争议、执法、合规处置或其他相关场景，保留“**法律关系—请求—要件—事实—证据—抗辩—程序—救济**”映射。每项请求或抗辩应对应构成要件、例外、法律效果，以及已知、待证、冲突或缺失的事实。
- 逐项检查待证事实、举证责任、证明标准、证据真实性/合法性/关联性、证明力、相互印证、保全需要和举证不能后果；不得仅写“有证据”“证据充分”或“证据不足”。
- 强制列出对方最强论点，以及裁判者、仲裁机构或监管者可能关注的程序、证据和实体问题；同时区分实体请求与程序申请。
- 关键主体身份、授权链、资格、待证事实或证据无法核验且影响效力、程序地位或责任时，停止对应结论或不可逆动作，列明补强、保全、人工复核和可分析范围。

## 程序、效果、风险与行动

- 识别处理机构、管辖、程序阶段、前置条件、受理/送达/举证/保全/鉴定/上诉/执行节点及其期限；程序状态或期限资料缺失时，不代替正式程序确认，也不执行不可逆提交。
- 区分胜、负、和解、行政处理或交易调整等可能结果，说明法律效果、责任类型、金额计算口径、救济组合、执行路径、资产或履行条件和回收限制。始终分开“法律上成立”与“现实可执行”。
- 重要风险至少说明风险类型及判断依据、触发条件和后果、损失敞口与发生概率、可规避性和证据/程序补强、商业权衡与紧迫性，以及具体行动、责任主体、所需材料和时间节点。
- 比较方案的成本、时效、风险、可逆性和商业影响，显式记录假设、未知项、反方动作、情景敏感性和升级触发条件；证据或法律依据不足以支持单一路径时，给出条件化选项，不把偏好包装成唯一答案。

不得把所有问题写成重大风险，也不得使用“必然”“百分之百”“毫无争议”等绝对化表达。

## 场景化最低契约与人工复核

场景化的完整定义见 [法律场景原型](legal-scenario-archetypes.md)：八类原型分别给出模块状态预设、专项检查清单、输出契约变体与评测重点；创建或改造 Skill 时先在 intake 中选定原型。以下四类最低契约仍然有效，是原型层的子集：

- **合同审查**：条款摘要、风险判断、触发条件、后果、具体修改和可谈判替代方案；检查主体、交易闭环、付款、交付验收、违约、解除、争议解决和条款一致性。
- **诉讼/仲裁**：争议焦点、事实状态、证据缺口、法律要件、举证责任、证明标准、程序节点、最强主张、对方最强论点和最稳妥路径；保留前述完整映射。
- **法律研究/咨询**：结论、依据、适用边界、行动路径；关键结论注明核验状态和论证强度，检索失败如实说明。
- **正式交付**：先结论后分析，正文形成完整论证闭环；结尾列出来源覆盖、未覆盖项、时效检查和待确认事项，或提供语义等价的审查备注。

保密、个人信息、原始材料只读、最小权限、外部传输授权、来源和操作留痕、利益冲突、职业责任边界、人工复核责任与更新周期均须检查。存在未授权外传、利益冲突、越权操作或缺少必要人工复核时，停止相关处理或正式交付，改用本地、脱敏、只读或人工接管路径。

下游 Skill 的输出契约必须能逐项追溯到十二模块。可以按业务习惯重命名章节或合并展示，但机器配置中的模块不得删除；合并展示时仍须分别保存状态、理由、最低输出和阻塞路径。
