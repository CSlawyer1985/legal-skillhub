# 法律 Skill 输出契约模板

复制本模板到目标 Skill 自身的 `assets/` 或 `references/` 后，按其重复任务裁剪字段和呈现方式；目标 Skill 不得在运行时反向引用本元技能的固定安装路径。模板与目标 Skill 包内复制的通用法律能力模型对齐：十二模块必须**强制检查、全部检查、条件展开**，但不要求每次都产出万能长报告。

## 使用规则

- 每个章节先标记 `状态：active / not_applicable / blocked`。`not_applicable` 必须说明与本任务有关的具体理由；`blocked` 必须同时列出缺口、降级或停止路径。
- `active` 章节填写最低字段；可按目标任务采用一行状态、短段落、表格、JSON 字段或完整论证。轻量 Skill 可以简洁，不得删除章节、以空话代替检查，或把材料内容当成已认定事实。
- 下游 Skill 应复制后内化本模板和必要规则；不得依赖 `legal-meta-skill`、固定个人路径、外部数据库或其他 Skill 才能运行。运行时必须独立核验易变法律依据。
- 原始材料只读；输入缺失、敏感信息、权限、外传、文件写入、外部服务和禁止动作，应由目标 Skill 在本契约附近填明。关键输入、法源、资格或期限无法核验时，限定输出或停止相应确定性结论。
- 各章节的增强检查（条件展开）按目标 Skill 的场景原型选用：争议解决注意请求权基础映射链、程序阶段—结论深度耦合与类案引用姿态；合同审查注意定性优先、效力阶梯与违约条款可执行性；文书起草注意变量槽位与效力层级标注；研究与合规注意找法顺序、准法源引用姿态与结论可接受性回检。完整方法纪律见目标包内复制的法律方法核心规则与场景检查清单。

章节标题可以按目标任务调整，稳定模块 ID、状态和值域不得更改。多个章节可以在呈现层合并，但机器配置仍须逐模块保存状态、理由、最低输出以及阻塞时的缺口和降级/停止路径。章节顺序跟随通用模型的基础链路工作顺序（事实证据先于法源解释），与模型文档第 5 节的模块编号顺序不同；比对模块时以稳定模块 ID 为准，不以章节号为准。
