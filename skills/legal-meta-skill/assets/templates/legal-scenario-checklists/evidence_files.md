# 证据与文件处理场景检查清单

适用于案卷整理、PDF 证据处理、证据清单与证据包构建、事实梳理工程。本清单叠加在十二模块最低契约与包内法律文件规则之上。

## 工作空间契约

- [ ] 原始材料置于 `input/` 且只读；中间产物在 `scratch/`；最终交付在 `output/`
- [ ] PDF 处理走项目规定的转换入口，保留 Markdown 与 evidence JSON 双文件包
- [ ] 质量警告全部进入人工复核台账，不静默吞掉
- [ ] 资源受控的串行处理，材料与中间产物可追溯

## 事实梳理

- [ ] 材料工程化：单文件化管理，命名含时间、主体、文件名，命名即排序
- [ ] 大事记/时间轴：关键事件按时间排列并标注来源位置
- [ ] 矛盾对照表：不同主体、不同程序中的叙述并列对照并标注出处
- [ ] 记录证据与当事人陈述的矛盾点，形成向委托人核实的清单

## 证据组织

- [ ] 按争议焦点/构成要件分组组织证据，不按材料来源堆砌
- [ ] 证明对象逐项拆解并做完整性校验，杜绝要件"裸奔"（无证据覆盖的证明对象显式列出）
- [ ] 每个事实主张锚定到证据编号、页码、段落
- [ ] 事实认定呈证据链相互印证结构，公开判断理由
- [ ] 材料内容不直接等同于已确认事实；区分已确认、待核实、冲突、缺口

## 四层分离

- [ ] 材料层、事实层、法律评价层、程序层分开记录
- [ ] 核心结论可反向追溯：程序动作 ← 法律要件与评价 ← 待证/已证事实 ← 原始材料
