# 案例检索 Skill

## 一、核心能力

1. 关键词检索：围绕案由、法院、案号、文书类型、时间或核心争议焦点等查找裁判案例。
2. 长文本检索/类案匹配：根据案件事实、争议经过、法律场景、诉请抗辩或材料摘要查找相似案例。
3. 结果整理：基于 CLI 返回的案号、案由、法院、审理程序、文书类型、裁判日期、公布类型和正文摘要生成可读结果。
4. 裁判规则归纳：在检索结果基础上进行摘要提炼、争议焦点提取、关键信息提取、裁判要点归纳和类案对比

## 二、前置工作

命中本 skill 后，凡需要执行案例检索、类案匹配、分页查看更多结果、按时间排序或调用后端能力，必须先执行 [deli-cli 通用前置](./references/cli-common.md)。

完成 CLI 前置检查后，通过当前 skill scope 发现命令，并以当次返回的 `RUN id`、命令名和参数形态执行；不得假设固定命令或固定参数存在。

如果 CLI 未配置、不可用或未返回覆盖当前任务的命令，应先说明“检索受限”或“命令不可用”，并给出建议检索式或需要用户补充的事实，不得编造案例信息。

## 三、触发条件

### 主动触发

- 关键词检索：`"查一下借款合同纠纷的案例"`
- 案由检索：`"找民间借贷纠纷的判决书"`
- 法院检索：`"深圳中级法院关于小产权房的判决"`
- 类案检索：`"有没有和这个案子类似的案例"`
- 时间筛选：`"2023年以后的劳动争议判决"`
- 文书类型：`"房屋买卖合同纠纷的判决书"`
- 法官检索：`"某法官的判决案例"`
- 长文本匹配：用户提供案件材料，要求检索类似案例

### 不触发场景

- 法规条文查询，应使用法规检索类 skill。
- 法律意见书、合同审查等深度分析任务，案例检索可作为子步骤但不单独替代主任务。
- 寒暄或无关内容。

## 四、强制执行约束

1. 每次调用前必须先按 [cli-common.md](./references/cli-common.md) 发现当前命令。
2. 单次检索只传一种核心检索意图；不要把多个案由、法院、法规、主体关系和争议焦点堆在同一个参数里。
3. 默认围绕用户请求形成一个高质量检索式并只调用一次；不要为同一问题机械拆分多个关键词反复调用。首次结果不理想、无结果或看似失焦时，也不得自行追加第二次检索；只能说明结果情况，给出一个建议改写的检索式，等待用户确认。
4. 用户输入已经包含事实经过、诉请抗辩、争议焦点或材料摘要时，首次检索必须优先选择 `--long-text`、事实摘要、相似案例等长文本参数；禁止先拆成 `--keywords` 做探索性检索。
5. 若长文本检索返回有效结果，应立即进入结果整理，不再追加关键词拆分、同义词改写或多轮检索。
6. 只有在 `cmds` 未提供任何长文本/相似案例参数，或用户只给出案号、案由、法院、年份、文书类型等短检索标签时，才使用关键词检索。
7. 不假设结构化筛选参数存在；法院、案号、案由、时间、文书类型等参数形态以 `cmds` 当前输出为准。
8. CLI 未返回的案号、法院、裁判日期、裁判结果、案例层级和裁判观点不得补写。

## 五、工作流程

### Step 1：意图识别与要素抽取

| 意图类型 | 判定标准 | 需抽取要素 |
|---------|---------|-----------|
| 关键词检索 | 用户明确指定案由、案号、法院、时间或文书类型 | 案由、案号、法院、年份、文书类型 |
| 案由检索 | 明确指定案由 | 案由名称 |
| 法院检索 | 指定法院名称或层级 | 法院名称、法院层级 |
| 长文本检索/类案匹配 | 提供案件材料、事实经过或自然语言法律场景 | 主体关系、法律关系、关键行为、诉请、抗辩、争议焦点 |
| 组合筛选 | 多个维度同时限定 | 关键词、时间、法院、案由、文书类型等 |

处理规则：

- 明确案号、案由、法院、年份、文书类型时，优先构造短检索主题。
- 用户描述事实经过、业务场景、争议事实、诉请抗辩、争议焦点或“不知道查什么案由”时，必须优先构造事实摘要或长文本检索内容，并作为首次 CLI 调用参数。
- 对事实型请求，不要在长文本检索之前预先拆分关键词；关键词只作为长文本参数不可用或用户确认后的降级重试方案。
- 多个独立检索意图会产生多次调用；除非用户明确要求全部检索，否则先聚焦最核心问题或请用户确认优先级。
- 信息不足时进入澄清模式。

### Step 2：选择检索文本类型

默认优先保留案件事实关系。只要用户输入包含完整或半完整案情，就按“类案匹配/长文本检索”处理；只有用户明确给出案号、短案由、法院加短主题、年份、文书类型等检索标签，且不需要保留复杂事实关系时，才使用短检索主题。

路由优先级：

1. 有事实经过、诉请抗辩、争议焦点或材料摘要，且 `cmds` 支持长文本/相似案例参数：调用一次长文本检索。
2. 无长文本/相似案例参数，但事实较完整：将事实压缩成最少关键词后调用一次关键词检索，并说明这是参数受限下的降级。
3. 只有案号、案由、法院、年份、文书类型等短标签：调用一次关键词检索。

| 场景 | 推荐组织 | 避免做法 |
|------|---------|---------|
| 案由或争议焦点 | `民间借贷 利率上限` | 堆叠大量泛化词 |
| 法院限定 | `深圳市中级人民法院 小产权房 买卖合同 判决书` | 假设存在固定 `--court` 参数 |
| 时间限定 | `2023年以后 劳动争议 违法解除 判决书` | 假设存在固定起止时间参数 |
| 案号精准 | 保留完整案号 | 拆分案号 |
| 案件事实或类案匹配 | 100-800 字事实摘要 | 把事实拆成关键词列表 |

具体命令示例和参数组织见 [案例检索 CLI 场景指南](./references/search-examples.md)。

### Step 3：执行 CLI 检索

先执行 [deli-cli 通用前置](./references/cli-common.md)，再按 [案例检索 CLI 场景指南](./references/search-examples.md) 组织参数并调用当次 `cmds` 返回的命令。

如果首次无结果或结果不理想，先告知结果情况，并给出一个建议重试的检索主题或事实摘要；等待用户确认后再调用。

### Step 4：结果后处理

| 处理项 | 处理规则 |
|-------|---------|
| 智能摘要 | 提取案件核心事实、争议焦点、裁判要点，不超过 100 字 |
| 裁判规则归纳 | 从多个案例中归纳共性裁判规则 |
| 类案对比 | 对比核心事实、争议焦点、裁判结果和裁判规则 |
| 关联推荐 | 基于案由、争议焦点或法院层级推荐下一步检索方向 |

### Step 5：格式化输出

根据检索场景选择案例列表、案例详情、类案对比或裁判规则归纳模板。输出时以 CLI 返回字段为准；字段缺失时不要补写。

翻页或查看更多结果时，只有用户明确要求并接受新增调用，才按当前 `cmds` 返回的分页参数形态继续执行。

## 七、注意事项

### 数据来源限制

- 裁判文书的公开性受法院公示范围限制，部分案件可能未公开。
- 检索结果仅涵盖 CLI 当前可返回的数据，不包括未公开或内部文书。
- 不同法院的文书公开标准和及时性存在差异。

### 引用规范

- 引用案例时必须标注完整案号、审理法院、裁判日期。
- 不得仅凭案例检索结果即作出法律判断，需结合具体案情分析。
- 裁判文书存在被更正、撤销等可能，重要案件请核实最新官方文书。

### 检索范围限制

- 本 skill 仅提供检索与呈现服务，不单独替代法律意见、个案分析或诉讼策略。
- 涉及国家秘密、个人隐私、未成年人等依法不公开的案件，检索结果可能不完整。

### 数据更新声明

所有结果须附带提示语：

```text
检索结果基于 得理CLI 当前返回数据，裁判文书的公开性受法院公示范围限制，重要案件请以法院官方文书为准。
```
