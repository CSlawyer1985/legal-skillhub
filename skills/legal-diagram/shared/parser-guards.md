# 解析器防护（共享）

在输出块之前为活动图表类型应用防护。生成之后（所有类型）：每个被引用的节点都已声明、无未闭合的括号或引号、每个含元字符的标签都加双引号、标签在预算内、每个块一张图。

## 节点和边缘标签（所有括号/形状类型）

默认规则：每当节点标签或边缘标签包含字母、数字、空格和简单连字符之外的任何内容时，都用双引号包裹。不确定时加引号。加引号绝不会改变渲染字形；它始终是安全的。

Mermaid 将标签内裸用的 `(` `)` `[` `]` `{` `}` `|` `#` `:` `;` `&` `<` `>` `"` `,` 读作语法。未加引号的法律引用会破坏解析。

- 正确：`N1["§ 237(a)(2)(A)(iii)"]` 和 `S1 -->|"per § 237(a)(2)(A)"| S2`
- 错误：`N1[§ 237(a)(2)(A)(iii)]`（第一个 `(` 开始一个形状标记，Syntax error）

已加引号标签内部的渲染层陷阱，解析干净但输出错误，已在固定的 Mermaid 11.x 上验证：

- 字面双引号：写作 `#quot;`（例如 `the #quot;Acquirer#quot;`）；裸 `"` 会提前闭合字符串。弯引号 `“ ”` 是安全的。
- 字面 `<`：静默截断标签（被读作标签开始）；写作 `&lt;`，或加空格包裹（`a < b`）。`>` 和 `&` 在引号内自动转义。
- 强调：普通 `**bold**` 按字面渲染。粗体/斜体仅在 Mermaid markdown-string 内渲染（反引号包裹的标签文本）。
- 换行：使用 `<br>`（在 `securityLevel:'strict'` 下有效；`\n` 也会转换为换行）。长多行标签优先拆分为更多节点。
- 边缘标签竖线：边缘标签文本中的裸 `|` 会闭合标签；保持标签加引号，并将字面竖线替换为 `/` 或 `&#124;`。

这些标签规则在两处是类型特定的：`mindmap` 和 `requirementDiagram` 不接受普通双引号转义（参见其各自行）。

|类型|防护|
|---|---|
|`requirementDiagram`|`id:` 值仅限字母数字（将连字符替换为 `_`，记录日志）。`{}` 内部零缩进。所有 `requirement` 块在 `element` 块之前。`text:` 值不能包含逗号、第二个冒号或分号（语法在该处结束值）；改写措辞（“pay then notify”“under s.7(2)”）或将逐字表述移至图形描述。加引号无法挽救 `text:`。|
|`gantt`|`dateFormat` 行在 `title` 之前且在任何 `section` 之前。日期格式一致；缺失时使用占位日期。里程碑：`:milestone, YYYY-MM-DD, 0d`。`dateFormat` 缺失或顺序错误会解析干净但渲染为空白，因此预览检查无法捕获；请通过目视检查确认该行存在且顺序正确。|
|`state diagram`|使用当前状态图语法，绝不使用旧简写。状态 + 转换非空；骨架化时发出警告。|
|`mindmap`|每层恰好 2 个空格，无循环父节点。纯文本叶节点用普通缩进。文本含 `( ) [ ]` 或其他形状定界符的叶节点必须使用显式 `id["Claim (a)(2)"]` 形式；含括号的裸叶节点或仅加双引号的叶节点会破坏解析。“无括号”指导仅适用于纯文本叶节点。|
|`sequenceDiagram`|消息 >5 条时使用 `autonumber`。在顶部声明 `participant` 别名。`:` 之后的消息文本可含冒号、逗号和括号，但不可含分号（它结束语句）；将 `;` 改写为逗号或拆分消息。参与者名称不得含 `;`。|
|`erDiagram`|规范化实体 ID（见下）：实体 ID 中的 SPACES（空格）破坏节点解析；连字符可解析，但为跨查看器安全规范化为 `_`。关系标签：仅当含标点或特殊字符时加引号；单个多词标签（`A \|\|--o{ B : places order`）不加引号也可解析。两端基数均必需。|
|`flowchart`|标签宽度上限约 40 字符（宽度限制，而非内容限制；必要时用省略号）：将长内容拆分为更多节点，绝不为了适配而丢弃或合并实体；长逐字文本也 → 图形描述。节点 ID 字母数字；规范化名称（见下），含保留字。`&` 是多节点运算符：当事方名称中的裸 `&` 会静默拆分节点，因此任何含 `&` 的标签都加引号。含特殊字符的子图标题使用 `id["Title (Phase 2)"]` 形式；含括号、冒号或逗号的裸未加引号标题会破坏解析。当 `grouping_suggested` 时：来自 `hierarchy` 的包含关系（深度 ≤ 2）或按 `grouping_axis` 键控的单层；子图 ID 字母数字且唯一；每层 `direction TB`；允许跨边界边，加标签，保持少量。|
|`timeline`|章节标题 = 裸日期或月份名称，不含冒号。事件文本中间的冒号没问题（它跟在日期分隔符之后，例如 `2020 : Filed: served on Acme`）。危险在于以冒号开头的活动文本：加前缀词语。不要笼统将冒号转义为 `&#58;`；那会破坏可读文本。|
|`quadrantChart`|x/y 分数为 `[0.0, 1.0]` 范围内的浮点数。轴标签（`x-axis`/`y-axis`）不得含冒号（那里的冒号会破坏解析）。点标签可含冒号；任何含 `( )`、`:` 或逗号的点标签都加双引号，例如 `"Claim (a)(2)": [0.3, 0.6]`。|

## 分组与可读性

当选择器设置 `grouping_suggested` 时适用（由密度信号或几何门控设置；参见 `workflows/generation.md` 第 3.4 步）。

- **深度上限 2。** 嵌套遵循 `extraction_result.hierarchy`；深度硬上限 2（三层）。更深层级折叠为摘要节点。每层设置 `direction`；子图 ID 跨所有层唯一。
- **按内容设定尺寸，绝不缩小。** “绝不缩小”约束的是字体、间距和画布，而非节点数。绝不压缩字体或间距来适配；HTML 查看器支持平移和缩放，因此大而清晰是正确的，拥挤是错误的。优先添加节点而非移除细节。
- **驱动挤压的是广度，而非数量。** 当某一层级（层）过宽时图表不可读，而非总节点数高时。深窄图没问题；浅宽图被挤压。几何门控在广度上标记 `band: split`（在适配框架视图中验证的交叉点约为每层 7-8 个节点）。
- **先拆分后折叠。** 兄弟节点过多的一组，或 `split` 几何判定，先按子轴（日期、当事方、类型）拆分；多图拆分参见 `workflows/generation.md` 第 3.4 步。仅作为最后手段将成员折叠为单个摘要节点（达到深度上限或确实不可读）；此时将每个被省略的实体逐字连同其来源引用倒入图形描述。绝不静默丢弃实体。
- **跨边界边。** 允许，但给每条穿墙边加标签；保持少量。Mermaid 在那里路由会退化。

## 实体名称规范化

`erDiagram`/`flowchart` 之前：节点 ID 拒绝空格；保留字和连字符也规范化。按顺序应用；向用户记录每次替换（“Entity name normalised: 'Operating Sub A' → 'OperatingSubA'”）：

1. 重音转写（NFD 分解，去除组合标记；仅节点 ID，标签保留重音逐字不变）：`Société Générale Ltée` → `Societe Generale Ltee`。
2. 去除空格：`Operating Sub A` → `OperatingSubA`。
3. 去除连字符：`Sub-A` → `SubA`（外观上的跨查看器安全；连字符可解析，但仍规范化）。
4. 前导数字 → 前缀 `E`：`1stFinance` → `E1stFinance`。
5. 冲突 → 数字后缀：两个 `OperatingSubA` → `OperatingSubA1`、`OperatingSubA2`。
6. 保留字 ID → 前缀 `N_`：`end`、`subgraph`、`class`、`click`、`style`、`graph`、`default`、`direction`、`state` → `N_end` 等。裸小写 `end` 作为 ID 会破坏流程图解析器。

在显示标签中保留原始名称：erDiagram 关系标签（含特殊字符时加双引号），或流程图节点文本 `Node["Operating Sub A"]`，ID 已规范化。含 `«»`、撇号、括号或 `,` 的标签采用双引号形式：`SGL["Société Générale Ltée (« l'Acheteuse »)"]`。

## 已确认缺陷（项目验证）

- 所有括号类型：节点或边缘标签内未加引号的 `(` `)` `{` `}` `"` 或 `|` 会被词法分析为形状/语法标记并抛出 Syntax error。任何含元字符的标签都加双引号；字面 `"` 使用 `#quot;`，`<` 使用 `&lt;`。
- `flowchart`：裸小写 `end` 作为节点 ID 破坏解析器；使用 `End` 或 `N_end`。标签中未加引号的 `&` 会静默将一个节点拆分为两个（多节点运算符）；加引号。
- `flowchart`/所有类型：语句后尾随 `%%` 破坏解析；注释仅在自己的行上有效。不要发出行内注释；将注释放入标签或图形描述。
- `flowchart`：子图到子图链接结合每个子图的 `direction` 语句在固定的 Mermaid 11.x 上有效并可渲染；它们在此前的 10.9.1 固定点上失败（“Syntax error”）。保持引擎固定在 11.x（`render_html.py` `MERMAID_VERSION`）。
- `requirementDiagram`：`id:` 值中的连字符抛出 `Expecting 'NEWLINE', got 'LINE'`（`-` 被词法分析为 `LINE` 标记）。使用 `PRIV001`，而非 `PRIV-001`。`text:` 值也会在逗号、第二个冒号或分号处破坏；加引号无济于事，因此改写措辞。
- `requirementDiagram`：`{}` 内的属性必须顶格；缩进会错误分词并失败。
- `gantt`：`dateFormat` 缺失，或 `dateFormat` 在 `title` 之后，会解析干净但静默渲染为空白；基于解析的预览不会捕获它，因此请通过目视检查确认 `dateFormat` 行。
- `timeline`：仅以冒号开头的活动文本，或章节标题中的冒号，会破坏解析器；事件文本中间的冒号没问题。不要笼统将冒号转义为 `&#58;`。
- `sequenceDiagram`：消息文本或参与者名称中的分号会结束语句并破坏解析；消息文本中的逗号、冒号和括号是安全的。
- `quadrantChart`：轴标签中的冒号破坏解析；点标签可容忍冒号，但任何含括号或逗号的都加引号。
- `mindmap`：不一致的缩进会破坏层级（全程每层 2 个空格）；含括号的叶节点需要 `id["..."]` 形式，因为普通双引号转义在此失败。
- `erDiagram`：实体 ID 中的 SPACES（空格）破坏节点解析；连字符可解析（仍规范化）。关系标签仅当含特殊字符时需要加引号。
- `stateDiagram`：使用当前状态图语法（旧简写会错误渲染）。已对照固定的 Mermaid 11.x 基线验证。
- 所有类型：标签上限仅是宽度限制。长标签溢出，因此截断标签并将内容拆分为更多节点；绝不为了适配而丢弃或合并实体。图形描述保存长逐字文本作为图表的补充，而非细节的唯一归宿。
