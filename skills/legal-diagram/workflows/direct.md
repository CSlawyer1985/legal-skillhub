# 直接工作流

高级用户前端。一次读取所有信号、解析输入、将丰富化提取交给共享生成核心。硬上限为一次中断。

## 第 0 步——读取其余信号

路由门控已解析输入源并运行第 1 遍（`manifest_cache`）。本通道在门控 A 之后进入。从用户消息中读取其余信息：(a) 图表类型（确切的 Mermaid 类型 / 法律类别 / “recommend”（推荐） / 无）；(b) 输出偏好（路径覆盖 / matter_type 覆盖）。HTML 报告是独立门控（门控 B），在图表绘制完成后决定。

## 第 1 步——携带路由清单进入第 2 遍

- **`manifest_cache` 存在**（文件或粘贴文本）→ 以 `skip_confirmation=true` 和 `manifest_cache` 进入 `workflows/extract.md`，使 extract.md 跳过第 1 遍并在第 2 遍继续。
- **无 `manifest_cache`**（仅事项描述）→ 从上下文窗口综合 `ExtractionResult`；人工构建覆盖范围映射。

**中断策略（硬上限 1）。** 置信度 ≥ 0.50 时继续。仅当提取完全为空（`is_empty()`）且无可用输入文本时停止。输入解析、文件缺失情形和无输入提示由路由门控在本通道加载前处理。

## 第 2 步——类型意图

- **点明图表类型**（“org chart”（组织结构图）或“timeline”（时间线）等通俗词语，或技术类型）→ 通过 `shared/diagram-type-map.md` 的“通俗名称”一节映射通俗词语，然后作为固定类型传递（核心在一次明确的不匹配后提出一次，然后尊重用户选择）。
- **给出法律类别** → 通过 `shared/diagram-type-map.md` 映射；歧义行交由选择器决定。
- **“推荐”或无** → 意图 = 事项类型 + 主导填充字段。

## 第 3 步——生成

以丰富化提取、意图（或固定类型）、`mode=direct` 和输出偏好加载 `workflows/generation.md`。执行选择、防护、生成、交付（理由 + 备选方案），并运行优化循环。
