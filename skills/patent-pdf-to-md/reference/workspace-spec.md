# 工作文件夹规范

> 本文件定义 patent-pdf-to-md skill 的标准化工作文件夹命名规范、文件组织架构。

---

## 路径变量

| 变量 | 说明 | 示例 |
|:---|:---|:---|
| `<skill_root>` | Skill 根目录 | `/path/to/.trae/skills/patent-pdf-to-md` |
| `<input_file>` | 输入文件绝对路径 | `/path/to/专利文件.pdf` |
| `<input_dir>` | 输入文件所在目录 | `/path/to` |
| `<input_stem>` | 输入文件名（不含扩展名） | `专利文件` |
| `<timestamp>` | 获取的真实时间戳 | `20260604_143025` |
| `<work_dir>` | 临时工作目录 | `<input_dir>/patent-pdf-to-md_<timestamp>` |
| `<base_name>` | 脚本输出的命名基础字符串 | `202210373749.5-CN114909579A-公开文本` |
| `<final_dir>` | 最终输出目录 | `<input_dir>/<base_name>` |

> 所有路径必须使用绝对路径，使用 `/` 作为路径分隔符以确保跨平台兼容性。

---

## 命名规范

### 专利公开/公告文件

**文件夹及文件命名格式**：`{申请号}-{公开号/公告号}-{文本类型}`

| 组成部分 | 说明 | 示例 |
|---------|------|------|
| 申请号 | 著录项目 (21) 申请号 | `202210373749.5` |
| 公开号/公告号 | 著录项目 (10) 申请公布号或授权公告号（去除空格） | `CN114909579A` |
| 文本类型 | 发明专利公开 → `公开文本`，发明/实用新型公告 → `公告文本` | `公开文本` |

**示例**：
- 发明专利公开：`202210373749.5-CN114909579A-公开文本`
- 发明专利公告：`202210373749.5-CN114909579B-公告文本`
- 实用新型公告：`201420522729.0-CN204119349U-公告文本`

### 审查文件

| 文档类型 | 命名格式 | 示例 |
|---------|---------|------|
| 审查意见通知书 | `{申请号}-{审查次数}{文档类型}-{发文序号}` | `202510345296.9-第二次审查意见通知书-2025042600034190` |
| 驳回决定 | `{申请号}-{文档类型}-{发文序号}` | `202510345296.9-驳回决定书-2025053000820090` |
| 复审决定书 | `{申请号}-{文档类型}-{发文序号}-{案件编号}` | `202510345296.9-复审决定书-2025071701747210-1F778674` |
| 无效宣告请求审查决定书 | `{申请号}-{文档类型}-{决定日}-{案件编号}` | `201420522729.0-无效宣告请求审查决定书-2016年08月31日-5W110364` |

### 命名规则

1. 各组成部分之间使用半角连字符 `-` 连接
2. 申请号、公开号/公告号、发文序号、案件编号等标识符需与原始文件信息完全一致
3. 文档类型名称需严格按照规范中的标准名称书写
4. 日期格式需保持统一（与原始文件中的格式一致）
5. 确保命名中不包含非法字符（`\/:*?"<>|`）

## 工作目录结构

### 专利公开/公告文件（PDF 输入）

```
{申请号}-{公开号/公告号}-{文本类型}/
├── {申请号}-{公开号/公告号}-{文本类型}.json    # 结构化 JSON
├── {申请号}-{公开号/公告号}-{文本类型}.md      # 结构化 Markdown（含图片引用）
├── {申请号}-{公开号/公告号}-{文本类型}.txt     # 原始提取文本（含页码分隔标记）
├── images/                                     # 说明书附图 PNG
│   ├── figPage1.png
│   ├── figPage2.png
│   └── ...
└── logs/                                       # 运行日志
    └── extract_<timestamp>.log
```

### 专利公开/公告文件（DOCX/DOC 输入）

```
{申请号}-{公开号/公告号}-{文本类型}/
├── {申请号}-{公开号/公告号}-{文本类型}.json    # 结构化 JSON
├── {申请号}-{公开号/公告号}-{文本类型}.md      # 结构化 Markdown
├── {申请号}-{公开号/公告号}-{文本类型}.txt     # 原始提取文本
└── logs/                                       # 运行日志
    └── extract_<timestamp>.log
```

> 注意：DOCX/DOC 格式不支持附图提取，无 `images/` 目录。

### 审查文件

```
{申请号}-{审查次数}{文档类型}-{发文序号}/       # 以审查意见通知书为例
├── {申请号}-{审查次数}{文档类型}-{发文序号}.json
├── {申请号}-{审查次数}{文档类型}-{发文序号}.md
├── {申请号}-{审查次数}{文档类型}-{发文序号}.txt
└── logs/
    └── extract_<timestamp>.log
```

> 注意：审查文件无附图提取步骤，不生成 `images/` 目录。

## 工作流程

1. Agent 创建临时工作目录：`<input_dir>/patent-pdf-to-md_<timestamp>`
2. 运行提取脚本，脚本自动解析文档并生成带规范命名的文件
3. 脚本通过标准输出 `BASE_NAME:<base_name>` 返回命名基础字符串
4. Agent 将临时工作目录重命名为最终输出目录：`mv "<work_dir>" "<input_dir>/<base_name>"`

---

## 多文件并行处理

当需要同时处理多个文件时，每个文件创建独立的工作目录：

```
patent-pdf-to-md_<timestamp>_file1/
├── {base_name_1}.json
├── {base_name_1}.md
├── {base_name_1}.txt
├── images/
└── logs/

patent-pdf-to-md_<timestamp>_file2/
├── {base_name_2}.json
├── {base_name_2}.md
├── {base_name_2}.txt
└── logs/
```

处理完成后，各临时目录分别重命名为对应的 `<base_name>`。

---

## 文件操作约束

- 所有中间产物必须保留在工作目录中（"用完即保留"而非"用完即清理"）
- 禁止在工作目录外创建中间文件
- 如果输出文件已存在，直接覆盖
- 禁止修改 `<skill_root>/scripts/` 目录下的任何脚本文件
