# 微调评估——AI 法案实质性修改分析

## 概述

微调是一系列技术的光谱，对第 25(1)(b) 条准提供者地位具有不同影响。本参考提供分级风险评估框架。

---

## 微调类别

### 第 1 级：参数高效微调（PEFT）——低风险

**技术：** LoRA、QLoRA、前缀微调、提示微调、适配器层

**技术描述：**
- 基础模型权重保持冻结
- 在冻结层旁添加小型可训练适配器模块
- 通常修改总参数的 <1%
- 移除适配器即可恢复原始模型

**风险评估因素：**

| 因素 | 评估 | 影响 |
|--------|-----------|--------|
| 基础模型完整性 | 保持——权重未改变 | 低 |
| 可逆性 | 高——适配器可移除 | 低 |
| 行为变化范围 | 有针对性——特定任务/领域适配 | 低 |
| 数据治理影响 | 有限——适配器训练数据范围狭窄 | 低 |
| 准确性/偏见影响 | 中等——适配器可引入领域特定偏见 | 中 |
| 提供者可预见性 | 通常可预见——许多提供者专为 PEFT 设计 | 低 |

**典型结论：** PEFT/LoRA 微调**不太可能**构成实质性修改，尤其是当：
- 提供者的文档预期基于适配器的定制
- 训练数据在系统预期领域内
- 适配器不从根本上改变输出类别或决策边界

**可能触发重新评估的情形：**
- 适配器在预期领域之外的数据上训练
- 适配器显著改变敏感类别的决策边界
- 适配器在引入受保护特征偏见的数据上训练

---

### 第 2 级：分层微调——中等风险

**技术：** 解冻并重新训练特定模型层（通常为顶层/最终层）、部分权重更新的迁移学习

**技术描述：**
- 选定层被解冻并用新数据重新训练
- 低层（特征提取）通常保持冻结
- 高层（任务特定）被修改
- 视所选层而定，修改总参数的 5-50%

**风险评估因素：**

| 因素 | 评估 | 影响 |
|--------|-----------|--------|
| 基础模型完整性 | 部分受损——重新训练的层发生偏离 | 中 |
| 可逆性 | 中等——需要原始权重备份 | 中 |
| 行为变化范围 | 显著——重新训练的层改变模型行为 | 中 |
| 数据治理影响 | 显著——需要新的训练数据治理 | 中 |
| 准确性/偏见影响 | 高——权重变化可改变准确性和偏见特征 | 高 |
| 提供者可预见性 | 除非明确记录，通常**不**可预见 | 中高 |

**典型结论：** 分层微调**可能**构成实质性修改，需要逐案分析：

**评估检查清单：**
1. 重新训练了多少层？（层数越多 = 风险越高）
2. 输出/决策层是否被修改？（是 = 风险更高）
3. 新训练数据是否来自不同领域？（是 = 风险更高）
4. 微调是否显著改变准确性指标？（是 = 风险更高）
5. 提供者是否明确允许该修改级别？（否 = 风险更高）
6. 第 9-15 条合规要求是否受到影响？（是 = 实质性修改）

---

### 第 3 级：全模型重新训练——高风险

**技术：** 完全权重初始化/重新训练、用新数据从头训练、主要架构修改与重新训练相结合

**技术描述：**
- 全部或实质上全部模型权重被重新训练
- 训练数据可能与原始数据完全不同
- 模型行为可能与原始模型显著偏离
- 实际上创建了一个新的模型变体

**风险评估因素：**

| 因素 | 评估 | 影响 |
|--------|-----------|--------|
| 基础模型完整性 | 丧失——全部新权重 | 高 |
| 可逆性 | 无——原始模型被替换 | 高 |
| 行为变化范围 | 全面——整个模型行为改变 | 高 |
| 数据治理影响 | 完全——需要全新数据治理 | 高 |
| 准确性/偏见影响 | 彻底——所有准确性/偏见特征均已改变 | 高 |
| 提供者可预见性 | 几乎从不被预见 | 高 |

**典型结论：** 全模型重新训练**极可能**构成触发第 25(1)(b) 条的实质性修改，除非原始提供者明确预期并将其纳入符合性评估。

## 元层面评估因素

除微调的技术层面外，评估以下总体因素：

### 因素 1：领域转移

| 问题 | 低风险 | 高风险 |
|----------|----------|-----------|
| 微调数据是否与原始训练同领域？ | 同领域 | 不同领域 |
| 微调是否改变应用语境？ | 同语境 | 不同语境 |
| 微调是否改变目标人群？ | 同人群 | 不同人群 |

### 因素 2：输出影响

| 问题 | 低风险 | 高风险 |
|----------|----------|-----------|
| 输出性质是否改变？ | 相同输出类型 | 不同输出类型 |
| 决策边界是否移动？ | 微小调整 | 显著移动 |
| 是否新增输出类别？ | 否 | 是 |
| 准确性指标是否显著改变？ | <5% 变化 | >5% 变化 |

### 因素 3：风险特征

| 问题 | 低风险 | 高风险 |
|----------|----------|-----------|
| 微调是否影响受保护特征？ | 否 | 是 |
| 微调是否改变偏见特征？ | 微小变化 | 显著变化 |
| 微调是否影响安全关键输出？ | 否 | 是 |
| 微调是否改变受影响人员范围？ | 否 | 是 |

### 因素 4：提供者文档

| 问题 | 低风险 | 高风险 |
|----------|----------|-----------|
| 提供者是否明确允许该微调？ | 是，已记录 | 未提及 |
| 微调是否在符合性评估覆盖范围内？ | 是 | 否 |
| 提供者是否提供微调指南？ | 是，附参数 | 无指南 |
| 提供者是否提供微调支持/验证？ | 是 | 否 |

## 实务指引

### 部署者在微调前应做什么：

1. **审查提供者文档**——检查微调许可和限制
2. **记录修改**——记录更改了什么、为什么及如何更改
3. **评估对第 9-15 条的影响**——评估对每项合规要求的影响
4. **评估数据治理**——确保微调数据满足第 10 条要求
5. **测试准确性和偏见**——比较微调前后的性能
6. **咨询原始提供者**——利用第 25(2) 条合作义务
7. **寻求法律评估**——对任何中或高风险微调

### 如触发准提供者地位：

1. **接受提供者义务**——第 16 条、第 8-15 条
2. **进行新的符合性评估**——除非第 25(4) 条已覆盖
3. **更新技术文档**——包括微调细节
4. **在欧盟数据库中登记**——作为新提供者
5. **与原始提供者接洽**——援引第 25(2) 条支持义务
