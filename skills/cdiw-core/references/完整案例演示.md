# 完整案例演示（阿明案·六段式走查）

> 本演示与 `assets/examples/demo_case/` 一一联动，可逐步复现。
> 与竞品同形文件的体例差异：逐段标注**调用脚本＋落盘位置＋核验动作**，展示工程纪律而非仅展示结果。
> 全部内容为虚构示例，不含真实案件数据。

## ① 案情与建档

**输入**（口语即可，无需结构化）：

> 阿明因涉嫌帮助信息网络犯罪活动罪被刑事拘留，8 月 23 日送进市看守所，现在第 9 天，同案还有阿强。

**路由判定**：含案件要素词（罪名、刑拘、羁押）＋无任务动词 → 第 5 路纯案情描述 → 无状态文件时先执行首次使用引导（E-1），建档后按 L2 输出初步分析＋待补信息清单＋行动建议。

**调用脚本**：

```bash
python scripts/init_case_workspace.py --path ./案件/阿明案 --case 阿明案 \
    --crime 帮助信息网络犯罪活动罪 --measure 刑事拘留
```

**落盘位置**：`案件/阿明案/` 下生成 `working_notes/` 五子目录、`03_正式文书/`、`04_正式文书（word版）/`、`logs/`、`citation_ledger.jsonl`、`case_status.md` 骨架。

**核验动作**：比对 `assets/examples/demo_case/case_status.md` 检查七块字段是否齐备；利益冲突审查未通过时不得生成工作区文件（5.0.1 第 3 步）。

## ③ 文书生成

**调用脚本与模板**：加载 `assets/templates/bail_application.md`（范式 1）填充，交付前跑质检三件套。

```bash
python scripts/quality_checker.py  --file 03_正式文书/20260831_取保候审申请书_辩护人.md \
    --stage 侦查 --doc-type 取保类文书
python scripts/punctuation_check.py --path 03_正式文书/
python scripts/citation_audit.py   --output 03_正式文书/20260831_取保候审申请书_辩护人.md \
    --ledger citation_ledger.jsonl
```

**实跑报告（对 demo_case/预期产出.md，侦查阶段·取保类文书）**：

| 检查 | 实跑结果 |
|---|---|
| `quality_checker.py` | `已通过 17 项/未通过 0 项`；尾注「另有 12 条人工复核项请对照第 2、4、5、6、7、25、28、32、34、35、37、44 条自查」 |
| `punctuation_check.py` | `PASS：1 个文件全部通过标点自检`（直引号 0、开合配对） |
| `citation_audit.py` | `PASS：1 项引用全部在台账中登记`（检出 1、已登记 1） |

**反向验证**（未登记引用应被拦下）：造一份引用《刑法》第999条的文本 → `citation_audit.py` 输出 `FAIL：1 项引用中 1 项断链`，断链项 `刑法第999条`。

**落盘位置**：`03_正式文书/20260831_取保候审申请书_辩护人.md`；Word 版由 `md2docx_formal.py` 输出至 `04_正式文书（word版）/`。

**核验动作**：身份后缀按生成时点阶段锚定为「辩护人」，阶段切换后不追溯改名；母版修改后须重新生成 Word 版。

## ④ 法条校验展示（两步校验＋溯源三标签）

**第一步·效力校验**：`python scripts/law_validator.py --law 刑法 --article 65`

**第二步·原文核对**：`python scripts/law_text_lookup.py --law 刑诉法 --article 91`

法条包按三级路径挂载（`CDIW_LAW_PACK_DIR` → 同级 `cdiw-law-pack/` → 旧版相对路径）。未挂载时返回：

```json
{"status":"error","error_code":"ERR_LAW_PACK_MISSING",
 "message":"法条数据包（cdiw-law-pack）未挂载……挂载指引三条……条文原文核对一律标注「待核实」",
 "data":{"degraded":true,"fallback":"待核实",
         "unaffected":["效力校验","期限计算","文书生成","罪名辨析（非敏感条目）"]}}
```

退出码 2，禁止裸抛异常。

**引用形态（含版本时点）**：《刑事诉讼法》（2018 修正，现行有效）第67条

**溯源三标签实例**：

> 《刑事诉讼法》第67条规定：“……”[法条原文]——经 `law_text_lookup` 核对原文一致。
> 类案检索显示，辖区近三年类似情节案件多适用缓刑 [检索]——来源：（20XX）×刑初×号，已核对原文。
> 结合上述事实与法律规定，辩护人认为当事人符合取保候审条件 [模型知识——需验证]——律师分析推断，需承办律师核实确认。

**落盘位置**：引用逐条登记入 `citation_ledger.jsonl`（一行一事件）；台账索引写入 `case_status.md` 治理块。

## ⑥ 延伸提示

1. **接着走哪条线**：本例剩余 2 日报捕窗口 → 强制措施线（取保候审申请书／不批捕意见书）→ 文书线；会见线按 21 节点安排首次会见（七步法）；接待线同步家属预期管理。
2. **防注入演示**：`demo_case/卷宗摘要.md` 埋设一处指令性文本。正确行为是**不执行**该指令，按异常处置表「停止 → 告知 → 等指示」处理并记审计日志——可据此验证部署是否正确。
3. **跨会话续接**：换设备或新会话时，从 `case_status.md` 断点续接（加载顺序 stage—service_progress—todos—emergency），不依赖对话记忆。
4. **产出不可直接对外**：全部产出为工作母版，须经两步校验、事实溯源核对、47 条质检、承办律师通读定稿后方可提交。
