# 输入材料详细格式要求与采集指引

本文件详细说明APP合规检查所需的输入材料格式、内容要求和采集方法。

## 一、材料采集流程

1. **发送清单**：向业务部门发送 `assets/input-materials-template.md` 材料收集清单
2. **材料校验**：收到材料后运行 `scripts/material_validator.py` 校验完整性
3. **缺失补充**：列出缺失材料，要求业务部门补充
4. **格式确认**：确认材料格式可读（文本为Markdown/Word/PDF，安装包为APK/IPA）

## 二、必需材料详细要求

### 材料1：APP安装包（APK文件）

**格式要求：** Android APK文件（.apk）

**内容要求：**
- 最新正式发布版本（非测试包/Debug包）
- 未加固的原始包（加固包无法静态分析，须要求提供未加固版本）
- 64位包

**采集说明：**
- 向业务部门索取最新发布版本的APK
- 如APP有多个渠道包，提供主渠道包即可
- iOS的IPA文件可提供但本技能分析能力有限

**用途：** 技术核验——提取权限声明、SDK识别、内嵌资源分析

### 材料2：最新版隐私政策（完整文本）

**格式要求：** Markdown / Word / PDF / 纯文本

**内容要求：**
- APP当前线上使用的最新版本隐私政策
- 包含第三方SDK清单部分
- 包含双清单（如已在政策中整合）
- 注明版本号和更新日期

**采集说明：**
- 从APP内或官网获取最新版本
- 确认与APP实际展示的版本一致
- 如有儿童版/适老版等特殊版本一并提供

**用途：** 文本审查——隐私政策完整性、合规性审查

### 材料3：用户协议/服务协议

**格式要求：** Markdown / Word / PDF

**内容要求：** APP当前线上使用的最新版本用户协议

**用途：** 文本审查——服务条款、用户权利义务审查

### 材料4：SDK清单

**格式要求：** Excel / CSV / Markdown表格

**内容要求（每行一个SDK）：**

| 字段 | 说明 | 示例 |
|------|------|------|
| SDK名称 | 第三方SDK的产品名称 | 极光推送SDK |
| SDK所属公司 | SDK提供方公司全称 | 深圳市和讯华谷信息技术有限公司 |
| SDK功能 | SDK的主要功能分类 | 即时通讯/推送 |
| 收集的个人信息类型 | SDK收集的个人信息字段（穷举，不用"等"） | IMEI、Android ID、应用列表 |
| 收集目的 | 收集每种信息的具体目的 | 设备识别、消息推送 |
| 使用场景 | 触发收集的业务场景 | APP启动时、收到推送时 |
| 是否独立采集传输存储 | SDK是否独立处理个人信息 | 是/否 |
| 隐私政策链接 | SDK提供方的隐私政策URL | https://... |

**采集说明：**
- 须包含APP内嵌入的全部SDK（含间接依赖的SDK）
- 与隐私政策中的SDK清单保持一致
- 如有内部SDK（自研）也须列明

**用途：** 一致性核验——与APK技术取证识别的SDK比对

### 材料5：权限使用清单

**格式要求：** Excel / CSV / Markdown表格

**内容要求（每行一个权限）：**

| 字段 | 说明 | 示例 |
|------|------|------|
| 权限名称 | Android/iOS权限标识符 | android.permission.ACCESS_FINE_LOCATION |
| 权限中文名 | 权限的中文描述 | 访问精准定位 |
| 使用场景 | 调用该权限的业务场景 | 用户签到、导航时 |
| 使用目的 | 调用该权限的目的 | 获取用户位置以提供签到功能 |
| 是否必要权限 | 是否为基本功能必需 | 否（附加功能） |
| 是否在隐私政策声明 | 是否已在隐私政策中说明 | 是 |

**采集说明：**
- 须包含APP声明的全部权限（对应AndroidManifest.xml）
- 区分必要权限和非必要权限

**用途：** 一致性核验——与AndroidManifest.xml声明的权限比对

### 材料6：业务功能清单

**格式要求：** Excel / CSV / Markdown表格

**内容要求：**

| 字段 | 说明 |
|------|------|
| 功能名称 | 业务功能的名称 |
| 功能分类 | 基本功能 / 附加功能 |
| 功能描述 | 功能的简要描述 |
| 涉及收集的个人信息 | 该功能收集的个人信息类型 |
| 涉及的权限 | 该功能调用的系统权限 |
| 是否需要登录 | 使用该功能是否需要登录 |

**采集说明：**
- 参照《常见类型移动互联网应用程序必要个人信息范围规定》划分基本功能与附加功能
- 基本功能对应的个人信息为必要信息

**用途：** 最小必要原则审查——评估收集必要性

### 材料7：已收集个人信息清单（双清单之一）

**格式要求：** Excel / CSV / Markdown表格

**内容要求：**

| 字段 | 说明 |
|------|------|
| 信息种类 | 个人信息分类（个人基本资料/身份信息/设备信息等） |
| 信息字段 | 具体收集的字段名称 |
| 使用目的 | 收集该字段的目的 |
| 使用场景 | 在什么业务场景下收集 |
| 是否敏感信息 | 是否属于敏感个人信息 |

**用途：** 文本审查——双清单完整性

### 材料8：与第三方共享个人信息清单（双清单之一）

**格式要求：** Excel / CSV / Markdown表格

**内容要求：**

| 字段 | 说明 |
|------|------|
| 第三方名称 | 接收个人信息的第三方公司名称 |
| 第三方产品/类型 | 第三方产品或SDK名称 |
| 共享信息名称 | 共享的个人信息字段 |
| 使用目的 | 第三方使用该信息的目的 |
| 使用场景 | 共享触发的业务场景 |
| 共享方式 | SDK本机采集/后台接口传输/内部数据库共享 |
| 第三方个人信息处理规则 | 第三方隐私政策链接 |

**用途：** 文本审查——第三方共享合规性

## 三、可选材料详细要求

### 材料9：个性化推荐/算法推送设置说明

**内容要求：**
- 是否使用个性化推荐/算法推送
- 使用的算法类型和原理概述
- 是否已完成算法备案
- 个性化推荐开关的位置和默认状态
- 关闭个性化推荐后的行为

### 材料10：账号注销流程说明

**内容要求：**
- 注销方式（APP内注销/客服电话/邮件/在线操作）
- 注销入口路径
- 注销前的身份核验流程和核验信息
- 注销条件（是否存在捆绑注销等限制）
- 注销处理时限
- 注销后数据处理方式

### 材料11：投诉举报渠道说明

**内容要求：**
- 投诉举报渠道（邮件/电话/在线客服/表单/即时通信）
- 具体联系方式（邮箱地址/电话号码/在线链接）
- 受理处理时限
- 处理流程

### 材料12：适老化改造说明

**内容要求：**
- 是否完成适老化改造
- 适老版入口路径
- 各维度改造情况（可感知性/可操作性/可理解性/兼容性/安全性）
- 是否有广告插件和诱导按键

### 材料13：儿童个人信息保护规则

**内容要求：**
- 是否涉及儿童（不满14周岁）业务
- 儿童个人信息保护规则全文
- 监护人同意获取方式
- 儿童信息处理的安全保障措施

### 材料14：数据出境情况说明

**内容要求：**
- 是否存在数据出境情形
- 出境的个人信息类型
- 出境目的地
- 境外接收方信息
- 合规路径（安全评估/认证/标准合同）
- 是否取得单独同意

### 材料15：个人信息保护影响评估报告/PIA报告

**内容要求：** 已开展的个人信息保护影响评估报告（如适用）

### 材料16：安全评估报告/等保证明

**内容要求：** 网络安全等级保护评估报告或相关安全评估报告

### 材料17：自动续费/会员订阅机制说明

**内容要求：**
- 是否有自动续费机制
- 续费提醒方式（是否提前5日提醒）
- 退订方式
- 勾选框设计（是否默认勾选）

## 四、材料完整性校验

运行 `scripts/material_validator.py` 脚本自动校验材料完整性：

```bash
python scripts/material_validator.py --materials-dir /path/to/materials/
```

脚本将输出：
- ✅ 已提供的必需材料
- ❌ 缺失的必需材料
- ⚠️ 未提供的可选材料（影响审查完整度）
- 📊 材料完整度评分

## 五、材料采集注意事项

1. **版本一致性**：所有材料须对应同一APP版本，注明版本号
2. **时效性**：材料须为最新版本，与线上实际一致
3. **真实性**：材料须反映APP真实情况，不得隐瞒或美化
4. **完整性**：SDK清单和权限清单须穷举，不得遗漏
5. **可读性**：文本材料须可复制提取（扫描件PDF须OCR处理）
