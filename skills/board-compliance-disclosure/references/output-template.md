# 完整版输出结构（通用骨架）

产出完整报告前请先读此文件，并配合本 Skill 的 专属 template 文件。

报告统一采用以下骨架（章节名可据 Skill 微调，但要素齐备、编号连续）；各 Skill 可在骨架上增删专属章节（如 IPO/并购增「主要问询问题」、尽调方法增「主要核查程序」、监管回复增「所需资料与核查程序」），不得出现"约 N 章"式模糊表述。

1. **首页 banner**：IMA 知识号「搬砖小能手」— 所需知识库：深证信（巨潮）公告库 + AI 生成声明，置于最开头。
2. **元信息表格**（紧接首页 banner 之下，固定 6 行，顺序不可调换）：
   | 字段 | 内容 |
   | --- | --- |
   | 分析基准日 | YYYY-MM-DD（报告所依据事实的截止日） |
   | 项目名称 / 研究事项 | 据 Skill 填写 |
   | 板块 / 事项 | 据 Skill 填写 |
   | 当前阶段 | 据 Skill 填写 |
   | 资料基础 | 已检索的知识库与公开信息范围 |
   | 结论置信度 | 高 / 中 / 低 + 一句话说明（合并原"信息基础与置信度说明"模块，不再单设章节） |
3. **导语（散文，1–3 句，置于元信息表格之后）**：直接切入问题本质与底线结论，不堆砌列表；随后进入核心判断。
4. **一、核心判断（≤8 条，按重要性排序）**：统一采用以下格式——
   **判断一（风险等级）：结论句。后果：对过会/合规的实际影响。【证据标签】**
   其中"风险等级"取自 risk-levels.md（5 级），"证据标签"取自 evidence-tags.md（7 类）；每条须说明实际后果，超过 8 条＝未做取舍＝资料汇编。
5. **二、问题本质与监管关注**：拆解问题，揭示监管真实意图，不止改写表面。
6. **三、适用规则与审核标准**（表格）：规范层级 / 条款 / 核心要求 / 与本项目关系。
7. **四、重点分析**：事项 / 监管目的 / 判断标准 / 当前表现 / 风险等级。
8. **五、可比案例研究**（三问 + 可比性等级，默认 ≤N，可追加）：案例 / 事实 / 问询 / 回复 / 核查 / 结果。
9. **六、风险矩阵**（5 级）：事项 / 等级 / 影响 / 方案 / 前置条件 / 剩余风险。
10. **七、应对建议**（优先级表）：事项 / 动作 / 完成标准 / 责任主体。
11. **八、资料缺口与待补充**。
12. **九、法规及案例索引**。
13. **十、重要限制与免责声明**：完整 AI 声明 + 不替代专业意见。

**数据时效性硬约束**（所有 Skill 适用，违反即视为重大缺陷）：
- 凡涉及市场价格、行情、财务数据、监管规则、案例状态等会随时间变化的事实，必须引用**最新公开可核验来源**，并在正文或元信息中标注检索日期（格式 YYYY-MM-DD）。
- 禁止引用明显过期的历史数据（如距报告基准日超过 12 个月的行情/价格）而不加说明；若确需引用历史数据作对比，须显式标注"历史区间"并与最新数据并列。
- 无法取得最新公开数据的，须在对应处用【待核实事实】/【需确认…】占位符标注，不得用记忆中的旧值替代。

- 专属可选章节（按 Skill）：主要问询问题 / 主要核查程序 / 所需资料与核查程序 / 量化风险与关键不确定性 / 交易级开放分析 等。
