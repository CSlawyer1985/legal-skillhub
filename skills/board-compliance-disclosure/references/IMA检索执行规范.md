# IMA 知识库检索执行规范（控制返回体量 · 防虚构）

本规范适用于本 Skill 所有调用 IMA 知识库（`mcp__ima-mcp__search_knowledge`）的场景。

**背景**：在 2026-07-29 的 11 个 skill 运行测试中实证发现，单次宽泛检索常返回 **12–13.5 万字符**，超出单次上下文读取上限，必须借助脚本落盘后分段解析才能利用；且未限定范围时命中偏宽、个别易变条款措辞易失真。本规范将核心规则中「知识库绑定 / 检索严格限定」操作化，固化以下强制约束。

> **复测结论（2026-07-29 晚，IPO审核关注要点小助手重跑）**：即便严格按本规范用「精确 query + folder_id 探查 + cursor 分页 + 落盘分段」，IMA 单次原始返回仍约 **12 万字符**，与修改前基本持平。根因是 **`search_knowledge` 对每条命中返回的是文档全文正文**，`folder_id` 只能缩小主题范围、无法减小单篇体积。因此：**`folder_id` 用于提升相关性；降体量的真正主手段是「精确 query 减少命中条数 + cursor 分页 + 超过 3 万字符即落盘分段解析」**，后者是可靠底线。

---

## 一、检索前：先缩小范围，别一上来就全库扫

1. **精确 query（首要手段）**
   在用户问题基础上，叠加 **板块 / 年份 / 条款名 / 公司类型 / 事项性质** 等限定词。
   - 与其搜「股份锁定」，不如搜「控股股东 科创板 股份锁定 36个月」；
   - 与其搜「关联交易」，不如搜「关联交易 创业板 IPO 审核关注 收入」；
   - query 越具体，返回越聚焦、体量越小、噪声越低。

2. **优先用 `folder_id` 限定（提升相关性，但非降体量主手段）**
   `search_knowledge` 支持 `folder_id`（文件夹 id）参数，可把检索锁定在知识库内某个主题文件夹，**提升命中相关性、减少无关主题噪声**。
   ⚠️ **实测提醒**：IMA 对每次命中返回的是**文档全文正文**，`folder_id` 只缩小主题范围、并不减小单篇体积；复测中即便探查并传入 folder_id，单次返回仍约 12 万字符。因此 **`folder_id` 用于聚焦主题，降体量的真正主手段是下面的「精确 query 减少命中条数 + cursor 分页 + 落盘分段」**。
   - 若你已知目标 folder 的 `folder_id`，直接传入；
   - 若未知 folder 结构，**先用 `mcp__ima-mcp__get_knowledge_base_list`（或询问用户）探查该知识库的 folder 体系**，取得相关 `folder_id` 后再检索；**不要跳过这步直接全库宽泛检索**。

3. **善用 `filters`**
   支持 `filters`（数组），可按 `media_type`（如只取 WORD / PDF / EXCEL）、`tags` 过滤，进一步收窄范围。

---

## 二、检索时：分页拉取，绝不一口吞下

1. **`cursor` 分页**
   `search_knowledge` **没有 `limit` / `top_k` 参数**，单次返回可能很大。务必用 `cursor` 参数分页：
   - 首页 `cursor: ""`；
   - 后续用上一次返回的游标继续翻页，逐步获取，而非一次性请求全量。

2. **先取「标题 + 摘要」层**
   拿到一页结果后，只提取各条目的 **标题 / 来源 / 摘要 / 时间** 做初步筛选，**不要把整段全文一次性塞入上下文**。

3. **按需二次精读**
   仅对筛选出的少数关键条目，再单独读取其全文内容展开论证；无关条目止步于摘要。

---

## 三、返回体量过大时的强制处理（关键）

若某次检索原始返回超过约 **3 万字符**（经验安全阈值，约为单次舒适读取量的 1/4），**严禁直接整段读入上下文**，必须按以下流程处理：

1. 用 Bash 将原始结果落盘：
   ```bash
   cat > ima_raw.json <<'EOF'
   <将 search_knowledge 的原始返回粘贴/写入此处>
   EOF
   ```
2. 用 `python` / `jq` 脚本解析，仅抽取 `title` + `summary` + `source` + `time` 字段，生成精简索引文件：
   ```bash
   python -c "import json,sys; d=json.load(open('ima_raw.json')); items=d.get('items',d.get('data',[])); print('\n'.join(f\"{i.get('title')} | {i.get('source')} | {i.get('time')}\n  {i.get('summary','')[:200]}\" for i in items))" > ima_index.txt
   ```
3. 阅读精简索引，定位需展开的条目，再二次检索或读取该条目全文。

> 目的：避免单次 12 万+ 字符阻塞上下文、拖慢产出。此流程已在测试中实证有效。

---

## 四、命中偏宽与易变条款的硬性核对

1. **命中偏宽时回到第一节**：加 query 限定词 + 用 `folder_id` 收窄，再展开，不要直接采信宽泛结果。
2. **易变条款以官方最新文本为准**：科创属性评价指标（如指标 3 措辞）、未盈利企业延长锁定期、各板块量化指标等，监管口径可能调整。IMA 检索结果仅作辅助参考，**不得作为唯一依据**；凡引用此类易变条款，须：
   - 用【待核实事实】标签标注；
   - 在报告中提示「请核对证监会 / 交易所官网最新规则原文」；
   - 不得给出确定性结论，除非已用官方文本交叉验证。

---

## 五、与其他护栏的关系

本规范是对核心规则「知识库绑定 / 检索严格限定」的操作化落地：
- **绑定**防跨库（只调本 Skill 所列知识库）；
- **本规范**防「跨库 + 全库宽泛 + 一次性吞下」导致的体量与准确性问题。

二者共同执行，缺一不可。


---

## 六、KB 不可用时的降级处理

1. **预检**：加载 Skill 后，先发起一次轻量 `search_knowledge`（简单 query + `cursor=""` 最小页，只取首页判断是否返回有效结果）。**不要跳过**
2. **判断**：若返回 0 条 / 权限错误 / 超时 / 返回中无有效 hit → KB 不可用。


> **⚠️ 连接器清单陷阱（强制）**：严禁仅凭连接器列表中没有名为“巨潮 / 深证信 / IPO案例”的独立连接项，就判定 KB 不可用并降级。** 本 Skill 的全部知识库均为 IMA 知识库，统一走 `ima-mcp` 通道；唯一有效的“KB 不可用”信号，是本步骤预检 `search_knowledge` 实际返回 0 条 / 权限错误 / 超时。

3. **提示用户**：在输出报告开头显式声明：
   > ⚠️ 检测到 IMA 知识库不可用（可能未关注知识号「搬砖小能手」）。请先在 IMA 中订阅以下知识库：深证信（巨潮）公告库。本报告将降级使用公开网络检索（WebSearch），可靠性显著降低，建议订阅后重新生成。
4. **降级到 WebSearch 模式**：
   - 仍然遵守方法论（拆解→本质分析→案例三问→结论→建议）；
   - 所有案例/规则引用标注为【公开网络检索】，不再标【公告案例】/【现行规则】；
   - 每条结论附"KB 缺失导致的不确定性"说明；
   - 无法从公开网络验证的内容不写确定性结论。
5. **结尾强化**：免责声明中补充说明"本报告因 IMA 知识库不可用，所有信息源自公开网络检索，未经知识库交叉验证，可靠性显著降低。"
