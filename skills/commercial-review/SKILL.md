# /review

根据审查指引审查接收方协议。从标题识别协议结构，选择合适的技能，如 `confirm_routing` 启用则在继续前与用户确认。

## 指令

1. **加载审查指引。** 读取 `$LEGAL_AGENT_PROFILE_HOME/commercial-legal/profile.md`。如果存在占位符，停止并提示："请先运行 `commercial-cold-start-interview`——我需要了解你的审查指引后才能对照审查。"

   同时读取 `## 审查偏好` → `confirm_routing`。如果字段缺失，视为 `true`。

2. **获取协议：** 从文件路径、云文档链接、合同管理系统ID或粘贴文本获取。如未提供，询问。

3. **读取文件结构——先看标题。**

   在阅读正文前，提取：
   - 主协议标题（如"主服务协议""保密协议"）
   - 所有展示件、附件、附录和附表标题（如"展示件A——数据处理补充协议""附件一——订阅订单表""附录B——服务水平协议"）

   这是路由信号。不要仅依赖正文关键词——一份通篇含"保密"字样的40页主协议不是保密协议。

4. **根据文件结构选择技能。**

   将识别到的每份文件或章节映射至相应技能：

   | 文件/条款标题包含 | 技能 |
   |---|---|
   | 保密协议、NDA、保密协议书（作为*主*协议） | **保密协议审查** |
   | 主服务协议、专业服务、工作说明书、咨询服务协议 | **供应商协议审查** |
   | 订阅、SaaS、云服务、带自动续约的订单、带周期性费用的软件许可 | **SaaS审查**（叠加于供应商协议审查之上） |
   | 数据处理协议、DPA（作为展示件或独立文件） | 注记供**供应商协议审查**→数据保护部分 |
   | 服务水平协议、SLA（作为展示件） | 注记供**SaaS审查**→SLA部分 |

   多个技能可适用。常见组合：
   - 主协议 + 数据处理协议展示件 → 供应商协议审查，附DPA注记
   - SaaS订阅 + 订单表 + SLA展示件 → SaaS审查（覆盖全部三份）
   - 主协议 + 带自动续约的订单 → 供应商协议审查 + SaaS审查叠加层

   当阅读标题后结构仍真的存在歧义（如文件标题为"协议"且无附件列表），阅读正文前两页加以判断——然后停止并路由。

5. **如果启用，确认路由。**

   如果 `confirm_routing` 为 `true`（或字段缺失）：

   ```
   我将按以下方式审查：[协议类型]。

   已识别文件：
   - [主协议标题] → [技能]
   - [展示件A标题] → [如何处理]
   - [展示件B标题] → [如何处理]

   是否正确？（是/否——或告诉我哪里不对）
   ```

   等待确认后再继续。如果用户更正了路由，按其指示执行并继续。

   如果 `confirm_routing` 为 `false`：无声继续。在审查备忘录顶部记录路由决定，让用户能看到适用了哪个技能。

6. **运行技能。** 完全执行每个技能的工作流。如多个技能适用，依次运行并将输出整合为单一备忘录——不要生成多份独立备忘录。

7. **检查上报：** 如果任何问题超出审查者权限（对照审查指引中的审批矩阵），调用**上报标注器**路由并起草上报说明。

8. **提供后续操作：**
   - 给业务负责人的利益方摘要
   - 带修订痕迹的.docx
   - 合同管理系统记录创建（如已连接）
   - 加入续约登记册（如发现自动续约条款）

## 配置 confirm_routing

在 `$LEGAL_AGENT_PROFILE_HOME/commercial-legal/profile.md` → `## 审查偏好` 中添加：

```markdown
## 审查偏好

confirm_routing: true   # 设为 false 则跳过路由确认，自动继续
```

冷启动访谈应询问此偏好。默认为 `true`——确认开启。随着信任积累，用户可设为 `false`。

## 示例

```
commercial-review vendor-msa.pdf

```

## 输出

按技能格式的完整审查备忘录。路由决定记录在顶部。逐条偏离、具体修订语言、具名审批人。按 `## 行文风格` 中的配置保存至指定位置。
