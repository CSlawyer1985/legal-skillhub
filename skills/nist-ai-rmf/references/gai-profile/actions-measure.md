# 衡量（MEASURE）——建议行动（GAI 概况）

*摘自 NIST AI 600-1（《生成式 AI 概况》，2024 年 7 月），第 3 节。针对**衡量（MEASURE）**功能的建议行动，按 AI RMF 子类别分组。每项行动均有唯一编码 `MS-X.Y-NNN`，并标注其应对的 GAI 风险。*

行动 ID 格式：`MS-X.Y-NNN`——功能前缀，类别.子类别，顺序索引。

## MEASURE 1.1 — 选择用于实施的在 MAP 功能期间列举的 AI 风险衡量方法和指标，从最重大的 AI 风险开始。不会——或无法——衡量的风险或可信赖性特征应予以妥善记录。

*AI 参与方任务：* AI 开发、领域专家、TEVV（测试、评估、验证与确认）

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-1.1-001` | 采用方法追踪数字内容的来源和修改。 | 信息完整性 |
| `MS-1.1-002` | 集成旨在分析内容来源和检测数据异常、验证数字签名真实性、识别与虚假信息或操纵相关模式的分析工具。 | 信息完整性 |
| `MS-1.1-003` | 按人口统计因素分解评估指标，以识别内容来源机制在不同人群中的运作差异。 | 信息完整性；有害偏见与同质化 |
| `MS-1.1-004` | 开发一套指标，用于评估由具有代表性的 AI 参与方参与的、有组织的公众反馈活动。 | 人机配置；有害偏见与同质化；CBRN 信息或能力 |
| `MS-1.1-005` | 评估衡量 GAI 相关风险的新方法和技术，包括内容来源、攻击性网络和 CBRN 方面的风险，同时保持模型产生有效、可靠且事实准确输出的能力。 | 信息完整性；CBRN 信息或能力；淫秽、侮辱性和/或辱骂性内容 |
| `MS-1.1-006` | 对 GAI 系统影响实施持续监测，以识别 GAI 输出是否在各个亚群体之间公平。通过有组织的反馈机制或红队测试，主动寻求受影响社区的反馈，以监测和改进输出。 | 有害偏见与同质化 |
| `MS-1.1-007` | 评估训练所用数据的质量和完整性以及 AI 生成内容的来源，例如采用混沌工程等技术和寻求利益相关方反馈。 | 信息完整性 |
| `MS-1.1-008` | 根据使用环境，界定在哪些用例、使用情境、能力和负面影响下，有组织的人工反馈活动（如 GAI 红队测试）对 GAI 风险衡量和管理最为有益。 | 有害偏见与同质化；CBRN 信息或能力 |
| `MS-1.1-009` | 跟踪并记录与所有无法定量衡量的 GAI 风险相关的风险或机会，包括解释为何某些风险无法衡量（例如由于技术局限、资源约束或可信赖性考量）。将未衡量的风险纳入边际风险。 | 信息完整性 |

## MEASURE 1.3 — 未担任系统一线开发人员的内部专家和/或独立评估人员参与定期评估和更新。根据组织风险容忍度，酌情咨询领域专家、用户、系统开发或部署团队之外的 AI 参与方以及受影响社区，以支持评估。

*AI 参与方任务：* AI 部署、AI 开发、AI 影响评估、受影响个人与社区、领域专家、最终用户、运行与监测、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-1.3-001` | 在收集有组织的公众反馈的计划中，界定使用环境内的相关利益群体（如人口统计群体、主题专家、具有 GAI 技术经验者）。 | 人机配置；有害偏见与同质化；CBRN 信息或能力 |
| `MS-1.3-002` | 与在使用环境方面具有专业知识和熟悉度的代表性 AI 参与方，和/或代表与使用环境相关人群的参与方磋商，开展内部和外部评估、GAI 红队测试、影响评估或其他有组织的人工反馈活动。 | 人机配置；有害偏见与同质化；CBRN 信息或能力 |
| `MS-1.3-003` | 核实进行有组织人工反馈活动的人员未直接参与同一 GAI 模型的系统开发任务。 | 人机配置；数据隐私 |

## MEASURE 2.2 — 涉及人类受试者的评估满足适用要求（包括人类受试者保护），并代表相关人群。

*AI 参与方任务：* AI 开发、人为因素、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.2-001` | 通过重采样、重新加权或对抗训练等技术，评估和管理与 GAI 内容来源相关的统计偏差。 | 信息完整性；信息安全；有害偏见与同质化 |
| `MS-2.2-002` | 记录内容来源数据的跟踪方式，以及该数据与隐私和安全的相互作用。考虑：对数据进行匿名化以保护人类受试者的隐私；利用隐私输出过滤器；移除任何个人身份信息（PII）以防止潜在伤害或滥用。 | 数据隐私；人机配置；信息完整性；信息安全；危险、暴力或仇恨内容 |
| `MS-2.2-003` | 为人类受试者提供退出参与或撤销其对当前或未来在 GAI 应用中使用其数据之同意的选项。 | 数据隐私；人机配置；信息完整性 |
| `MS-2.2-004` | 使用匿名化、差分隐私或其他隐私增强技术，最大限度降低将 AI 生成内容关联回个人受试者的风险。 | 数据隐私；人机配置 |

## MEASURE 2.3 — AI 系统的性能或保证标准以定性或定量方式衡量，并在与部署环境相似的条件下加以证明。衡量结果予以记录。

*AI 参与方任务：* AI 部署、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.3-001` | 在选择用于微调或检索增强生成增强的模型时，考虑模型在基准测试套件上的基线性能。 | 信息安全；虚构（Confabulation） |
| `MS-2.3-002` | 使用经验验证的方法评估模型能力声明。 | 虚构；信息安全 |
| `MS-2.3-003` | 与相关 GAI 参与方（如拥有系统发布批准权限者）分享部署前测试结果。 | 人机配置 |
| `MS-2.3-004` | 利用专用测试环境（如 NIST Dioptra）实证评估 GAI 可信赖性特征。 | CBRN 信息或能力；数据隐私；虚构；信息完整性；信息安全；危险、暴力或仇恨内容；有害偏见与同质化 |

## MEASURE 2.5 — 证明待部署的 AI 系统有效且可靠。记录技术开发条件之外泛化能力的局限。

*AI 参与方任务：* 领域专家、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.5-001` | 避免从狭窄、非系统性且轶事性的评估中外推 GAI 系统的性能或能力。 | 人机配置；虚构 |
| `MS-2.5-002` | 记录通过 RLHF、微调、检索增强生成、内容审核、业务规则等方式运用人类领域知识改进 GAI 系统性能的程度。 | 人机配置 |
| `MS-2.5-003` | 在部署前风险衡量和持续监测活动中，审查并核实 GAI 系统输出中的来源和引用。 | 虚构 |
| `MS-2.5-004` | 跟踪并记录 GAI 系统界面中拟人化（如人类图像、提及人类情感、半机械人图像或母题）的实例。 | 人机配置 |
| `MS-2.5-005` | 核实 GAI 系统训练数据和 TEVV 数据的来源，并确认微调或检索增强生成数据有据可依（grounded）。 | 信息完整性 |
| `MS-2.5-006` | 定期审查安全与保障护栏，尤其是 GAI 系统在新环境下运行时。包括审查 GAI 系统最初被评估为可安全部署的原因。 | 信息安全；危险、暴力或仇恨内容 |

## MEASURE 2.6 — AI 系统定期评估 MAP 功能中识别的安全风险。证明待部署的 AI 系统安全，其剩余负面风险不超过风险容忍度，且能够安全失效，尤其是在超出其知识极限运行时。安全指标反映系统可靠性和稳健性、实时监测以及 AI 系统故障的响应时间。

*AI 参与方任务：* AI 部署、AI 影响评估、领域专家、运行与监测、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.6-001` | 评估不利影响，包括对在 GAI 训练和维护期间接触露骨色情、攻击性或暴力信息的价值链或其他 AI 参与方健康与福祉的影响。 | 人机配置；淫秽、侮辱性和/或辱骂性内容；价值链与组件集成；危险、暴力或仇恨内容 |
| `MS-2.6-002` | 评估系统训练数据中是否存在有害偏见、知识产权侵权、数据隐私违规、淫秽、极端主义、暴力或 CBRN 信息及其程度。 | 数据隐私；知识产权；淫秽、侮辱性和/或辱骂性内容；有害偏见与同质化；危险、暴力或仇恨内容；CBRN 信息或能力 |
| `MS-2.6-003` | 当负面风险超过组织风险容忍度时，重新评估微调模型的安全特性。 | 危险、暴力或仇恨内容 |
| `MS-2.6-004` | 审查 GAI 系统输出的有效性和安全性：审查生成的代码，评估可能源于不可靠下游决策的风险。 | 价值链与组件集成；危险、暴力或仇恨内容 |
| `MS-2.6-005` | 核实 GAI 系统架构能够监测输出和性能，并在检测到安全异常、威胁和影响时处理、恢复和修复错误。 | 虚构；信息完整性；信息安全 |
| `MS-2.6-006` | 核实系统妥善处理可能引发不当、恶意或非法使用的查询，包括助长操纵、勒索、定向冒充、网络攻击和武器制造。 | CBRN 信息或能力；信息安全 |
| `MS-2.6-007` | 定期评估 GAI 系统在安全措施可能被规避方面的脆弱性。 | CBRN 信息或能力；信息安全 |

## MEASURE 2.7 — 评估并记录 MAP 功能中识别的 AI 系统安全性和韧性。

*AI 参与方任务：* AI 部署、AI 影响评估、领域专家、运行与监测、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.7-001` | 应用既定安全措施以：评估后门、被入侵的依赖项、数据泄露、窃听、中间人攻击、逆向工程、自主代理、模型盗窃或模型权重泄露、AI 推理、绕过、提取及其他基线安全问题的脆弱性和威胁的可能性与严重程度。 | 数据隐私；信息完整性；信息安全；价值链与组件集成 |
| `MS-2.7-002` | 对照行业标准和最佳实践，对与内容来源相关的 GAI 系统安全和韧性进行基准测试。将 GAI 系统安全特性和内容来源方法与行业前沿进行比较。 | 信息完整性；信息安全 |
| `MS-2.7-003` | 开展用户调查，收集用户对 AI 生成内容的满意度及用户对内容真实性的感知。分析用户反馈，识别与内容来源相关的关切和/或当前素养水平，以及用户对内容标签的理解。 | 人机配置；信息完整性 |
| `MS-2.7-004` | 识别反映安全措施有效性的指标，如数据来源、未授权访问尝试次数、推理、绕过、提取、渗透或来源验证。 | 信息完整性；信息安全 |
| `MS-2.7-005` | 衡量内容认证方法（如水印、加密签名、数字指纹）以及访问控制、合格评定和模型完整性验证的可靠性，这些有助于支持内容来源技术的有效实施。评估内容来源的假阳性和假阴性率，以及验证的真阳性和真阴性。 | 信息完整性 |
| `MS-2.7-006` | 衡量安全检查和建议及事件建议得到落实的比率。评估 AI 系统基于安全事件和反馈的经验教训进行适应和改进的速度。 | 信息完整性；信息安全 |
| `MS-2.7-007` | 开展 AI 红队测试，评估针对以下方面的韧性：用于协助攻击其他系统的滥用（如恶意代码生成、增强的网络钓鱼内容）、GAI 攻击（如提示注入）、ML 攻击（如对抗样本/提示、数据投毒、成员推理、模型提取、海绵样本）。 | 信息安全；有害偏见与同质化；危险、暴力或仇恨内容 |
| `MS-2.7-008` | 核实微调不会损害安全和保障控制。 | 信息完整性；信息安全；危险、暴力或仇恨内容 |
| `MS-2.7-009` | 定期评估和验证安全措施保持有效且未被破坏。 | 信息安全 |

## MEASURE 2.9 — 对 AI 模型进行解释、验证和记录，并在其语境中解读 AI 系统输出（MAP 功能中识别的），以指导负责任的使用和治理。

|---|---|---|

## MEASURE 2.10 — 检查并记录 AI 系统的隐私风险（MAP 功能中识别的）。

*AI 参与方任务：* AI 部署、AI 影响评估、领域专家、最终用户、运行与监测、TEVV

## MEASURE 2.11 — 评估公平性和偏见（MAP 功能中识别的），并记录结果。

*AI 参与方任务：* AI 部署、AI 影响评估、受影响个人与社区、领域专家、最终用户、运行与监测、TEVV

| 行动 ID | 建议行动 | GAI 风险 |
|---|---|---|
| `MS-2.11-001` | 应用适合用例的基准（如 Bias Benchmark Questions、Real Hateful or Harmful Prompts、Winogender Schemas）量化 GAI 系统输出中的系统性偏见、成见、贬损和仇恨内容；记录基准的假设和局限，包括相对于部署环境可能或实际存在的训练/测试数据交叉污染。 | 有害偏见与同质化 |
