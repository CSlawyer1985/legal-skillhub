# WeChat Publisher — Digest 摘要撰写规则

> 按需加载：仅在「自定义 HTML 发布（mp-draft-push）」路径需要 AI 手写摘要时阅读。`publish.js` 自动发布路径由脚本取正文前 35 字，无需读本文件。

## 两条路径

| 路径 | 触发条件 | 摘要来源 |
|------|---------|---------|
| `publish.js` 自动发布 | 跑 `node publish.js` 时 | 脚本自动取正文前 35 字 |
| 自定义 HTML 发布 | 手写 HTML 走 mp-draft-push 时 | **AI 必须主动撰写摘要**，不得留空或机械截取 |

## AI 撰写摘要的规则（自定义 HTML 路径必遵守）

摘要显示在分享卡片上，是读者除了标题之外看到的唯一文字。写得好能显著提高打开率。

**核心原则**：摘要不是文章第一句话的拷贝，而是一个简短的"预告片"——告诉读者为什么值得点进来。

**写法要点**：

1. **呼应标题，但不重复标题**——标题已经说了核心观点，摘要要补充一个具体的钩子
2. **用一句话制造好奇心缺口**——让读者觉得"我得点进去看看"
3. **可以提问、可以下结论、可以用金句**
4. **不超过 60 字**（微信摘要显示约 2-3 行）
5. **口语化、有活人感**，避免说明书式平铺

**好摘要 vs 坏摘要**：

```
❌ 坏：本文介绍了法律人使用AI的三大心法，包括数据质量、溯源验证和任务布置。（机械复述标题，无钩子）
❌ 坏：很多律师对AI感到失望，不是因为它能力不行，而是因为你饲喂的"原材（硬截断）
✅ 好：很多律师第一次深度用AI就失望了。不是AI不行，是你还没学会"带"它。三条实操心法，让你的AI真正好用起来。
✅ 好：AI查法条不准、写文书不对味？问题不在AI，在你不会"带"它。我用三年踩坑总结的三条心法，今天一次讲透。
```

**生成方法**：

1. 通读全文，找出最有冲击力的一句话或一个观点
2. 用这个观点做开头，一两句收束到"这篇文章能帮你解决什么"
3. 读一遍，确认独立于标题之外也有吸引力

**示例**：

```
标题：像带实习生一样带AI：律师的三大核心心法
摘要：很多律师第一次深度用AI就失望了。不是AI不行，是你还没学会"带"它。三条实操心法，让你的AI真正好用起来。
```

> ⚠️ 用 mp-draft-push 发布时，`digest` 参数**必须手动填入 AI 撰写的摘要**，不能用空字符串或机械截取的第一句话。
