# 质证意见写作

## 执行目标

根据对方提交的证据、案件材料及要件分析，起草一份以我方当事人名义提交的书面质证意见。

## 输入要求

- 案件文件夹路径
- 我方代理角色
- 对方证据清单及内容（可从 `办案记录.md` 或工作底稿中提取）

## 强制约束

1. **正文格式**：质证意见正文为纯段落文字，不使用表格（质证意见汇总表除外）和项目符号列表（`-`、`*`、`1.` 等）。分点论证用“其一、……其二、……”嵌入段落中。
2. **标题层级**：严格遵循 `一、` → `（一）` → `1.` → `（1）`，不使用 `#` 号标题。
3. **脱敏要求**：所有示例必须脱敏，不出现真实案件当事人信息、案号、具体金额、地点等。
4. **提问机制**：关键事实缺失时主动向用户提问，每次 1-3 个问题，不自行脑补案件事实。
5. **结论明确**：对每份证据的三性（真实性、合法性、关联性）和证明目的，给出“认可”“不认可”或“无法确认”的明确结论。
6. **语言风格**：简洁专业，使用陈述句；不使用反问句、套话导语、文学化修辞、评价对方举证行为。

## 执行前检查

按 `references/执行前强制检查清单.md` 完成基础检查，并补充：

**通用行为原则读取（强制）**：
- 读取 `references/通用行为原则.md`，全程遵守事实与观点区分、法律分析不预设立场、观点保持一致性、法条与案例引用先核验、事实一致性优先、风险提示常态化、输出结构化可复核等原则。

- 读取 `./办案记录.md`，确认格式偏好（如是否写“致法院”、是否需要综合质证意见等）。
- 回查已有同类定稿质证意见，保持首部格式与排版风格一致。
- 通读案件工作底稿中的答辩状/答辩提纲、案情分析报告、法律分析报告，确保质证意见与在先文书在日期、金额、时间线、核心论点、证据描述立场等方面一致。
- 确认当前程序阶段（一审/二审/再审）和对方当事人名称。
- 当前会话中若已读取过 `案件卷宗/` 或 `工作底稿/` 下静态文件，可直接复用；但每次启动新任务前必须重新读取 `办案记录.md` 和 `OCR状态.json`，确认版本和状态未更新。

**前置模块依赖检查（强制）**：
- 按 `references/执行前强制检查清单.md` 第 6 节，检查 01 立项建档和 02 案情梳理是否已完成。
- 01 或 02 未完成时，**默认阻断当前任务**，提示用户先执行前置模块。仅当用户明确确认跳过时方可继续，且必须在 `办案记录.md` 中记录"用户选择跳过 01/02，直接执行本模块"。

**前期工作成果检查（团队协作）**：
- 读取 `办案记录.md` 中的「前期工作成果索引」，检查 02 模块是否已完成。
- 若 02 已完成：直接读取索引中列出的成果文件（案情分析报告、要件映射表、关键事实基准表），不重复执行案情梳理。
- 若 02 未完成：按前置模块依赖检查处理。

## 执行步骤

### Step 1：收集案件背景信息与对方证据

#### 1.1 案件背景

从 `./办案记录.md` 提取：案由、案件全称、案号、我方代理角色、当前程序阶段、核心争议焦点、**最新版本索引**、**文件重要性索引**。

#### 1.2 文件读取范围

按 L1-L4 读取等级执行：

| 读取等级 | 文件位置 | 读取内容 | 说明 |
|:---|:---|:---|:---|
| **L1 必读** | `案件卷宗/03_对方文件/` 下的证据目录及全部证据材料 | 对方证据清单、证明目的 | 必须逐份读取 |
| **L1 必读** | `案件卷宗/03_对方文件/` 下的对方起诉状/答辩状/代理词 | 对方主张和论证 | 若存在则读取 |
| **L2 按需** | `案件卷宗/02_己方文件/` 下的己方证据目录 | 用于比对和矛盾识别 | 若存在则读取 |
| **L2 按需** | `工作底稿/` 下的案情分析报告、要件映射表 | 将要件框架映射到证据 | 若存在则必读 |
| **L3 触发** | `资料收集/一审材料/` | 对方历史审级证据 | 当前为二审/再审且涉及相同证据时读取 |
| **L4 兜底扫描** | `资料收集/` | 全部文件名 + 01 生成的一句话摘要 | 不读全文，用于判断是否存在明显遗漏 |

#### 1.3 对方证据清单

整理对方提交的全部证据，每份证据确认：证据编号、名称、类型、内容摘要、对方主张的证明目的。

#### 1.3 要件基础继承

优先读取 `工作底稿/` 下最新的案情分析报告，获取「要件映射表」。将对方每份证据的证明目的映射到对应构成要件，以要件框架判断证据与待证事实的关联性、证明力。若映射表不存在，按 `references/请求权基础检索总表.md` → `references/案件类型要件库_{{类型}}.md` 自行加载；若 10 个要件库均未覆盖，读取 `references/案由请求权基础检视总览.md`。

### Step 2：逐份质证分析（双层次框架）

对每一份/每一组证据，按以下框架完成分析：

#### 第一层次：三性审查（形式门槛）

| 审查维度 | 核心问题 | 结论要求 |
|:---|:---|:---|
| 真实性 | 该证据本身是否真实？有无伪造、变造、篡改？如为复印件，是否有原件核对？ | “认可”“不认可”或“无法确认” + 理由 |
| 合法性 | 证据的来源、形式、收集手段是否符合法律规定？ | “认可”或“不认可” + 理由 |
| 关联性 | 该证据与待证事实之间是否存在逻辑上的关联？ | “认可”或“不认可” + 理由 |

#### 第二层次：证明力阻击（实质攻防）

1. 逻辑切断：即使证据三性无异议，能否必然推导出对方主张的待证事实？
2. 矛盾发现：该证据是否与我方证据、对方其他证据、或对方陈述存在矛盾？
3. 孤证不立：该证据是否为证明某一要件事实的唯一证据？
4. 证明力强弱：属于直接证据还是间接证据？间接证据是否形成完整证据链？

#### 特殊证据专项审查

当证据类型为电子证据、证人证言、鉴定意见，或当前程序为二审/再审时，读取 `references/特殊证据质证要点.md`，在相应证据的质证中引入专项审查要点。

#### 交互规范

- 用户对某份证据判断不清晰时，主动提供法律分析辅助，最终判断由用户做出。
- 认可的部分简洁处理，不认可的部分详尽论证。
- 每份证据分析完毕后可请用户确认，随时回退修改。

### Step 3：法条与案例检索

按 `references/引用核验规范.md` 执行检索与核验：

- 证据规则适用存疑时，检索 `laws` 和 `books`。
- 需类案支撑质证时，检索 `cases`（按案由打 `--tag` 过滤）。
- 凡引用具体法条、案例，均须先经外部检索核验，方可写入文书。
- 检索无结果或结果冲突时，标注“【待核实】”并向用户报告。

### Step 4：生成质证意见

#### 4.1 正文结构

```
[标题页] → [引导语] → [逐份证据质证] → [综合质证意见（可选）] → [落款]
```

#### 4.2 各部分规范

**标题页**：

```
质证意见

案件：[案件全称]
案号：[案号]

质证人：[我方当事人姓名]
```

> 质证意见属当事人名义提交的文件，不做“致：XX法院”的致送格式，不列对方当事人。

**引导语**（标题页与正文之间以 `---` 分隔线分隔）：

> [质证人]就[对方当事人]在[案件全称]（案号：[案号]）中提交的证据，发表如下质证意见：

**逐份证据质证**——标题必须用完整句子归纳核心质证观点：

```markdown
一、对证据N“[证据名称]”的质证意见：[一句完整论点句归纳核心质证结论]

（一）真实性：[认可/不认可/无法确认]。[理由]
（二）合法性：[认可/不认可]。[理由]
（三）关联性：[认可/不认可]。[理由]
（四）证明目的：[直接陈述意见]
```

**综合质证意见**（可选，由用户决定是否需要）：

> 从总体维度归纳对方证据体系的根本缺陷，不重复逐项分析已展开的具体内容。篇幅控制在 4-5 个自然段以内，每个段落一个宏观论点。如用户不需要，直接省略。

**落款**：

```
质证人：[我方当事人姓名]

委托代理人：[律师姓名]（可选，根据实际需要）

[日期]
```

> 质证意见不写“此致 XX法院”。

#### 4.3 写作规范

- 纯段落文字：全文不使用表格（汇总表除外）和项目符号列表。
- 标题归纳：每份证据的一级标题（`一、`）必须是完整句子，读到标题即可把握质证结论。
- 详略得当：认可部分简洁，不认可部分详尽论证，不对认可事项长篇大论。
- 证明目的直接陈述：使用“（四）证明目的：”后接意见，不使用“对证明目的的辩驳”等标题。
- 引法精准：涉及法律依据时，注明具体法条，不使用“根据相关法律规定”等笼统表述。
- 语言精炼：每一句话都有信息量，不使用反问句、套话导语、文学化修辞、评价对方举证行为。

## 引用核验与外部检测

- 输出前按 `references/引用核验规范.md` 执行引用核验（含引用继承、增量核验、来源标注）。
- 输出前必须通过 `mcp__yuandian-mcp__yuandian_hall_detect` 进行外部独立检测。结果“不一致”时按元典权威原文修正后重新检测；“未命中”时标注“【元典未命中，待人工核实】”并向用户报告。

- [ ] 综合质证意见（如有）不重复逐项分析内容，仅做宏观归纳
