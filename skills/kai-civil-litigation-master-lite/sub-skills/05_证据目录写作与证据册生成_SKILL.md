# 证据目录写作与证据册生成

## 强制约束

1. 证据分组按请求权/抗辩权基础的构成要件划分，不按时间顺序或证据类型（书证/物证/证人证言）分组。
2. 证明结合诉讼请求的构成要件：说明该证据对应哪一项诉请，以及证明该项诉请的成立或满足。证明目的不写"证明合同成立"这类笼统表述。
3. 证据名称整行加粗：`**证据 1. 证据全称**`（"证据"、数字、"."、空格及证据全称均需加粗）。
4. 格式使用文本式，不使用表格。证据目录按分组陈述，先列举证据，再陈述证据说明和证明。
5. 证据目录仅收录案件事实发生过程中形成的原始材料，不纳入以下材料：
   - 律师在案件处理过程中形成的分析、计算、策略、报告等内部工作文件；
   - 对方提交的起诉状、证据目录、答辩状等诉讼材料；
   - 程序性申请文件（如鉴定申请、调查取证申请），该类文件以单独申请书形式提交，不列入证据目录。

## 执行步骤

### Step 1：读取 `./办案记录.md`
读取案件基本信息、代理方身份、八模块分析结论（特别是模块五"事实及证据分析"）、诉讼方案。

### Step 2：确认代理方身份
- 明确代理原告还是被告。
- 原告侧：确保每个攻击要件都有对应证据。
- 被告侧：确保每个抗辩点都有对应证据。

#### 多方被告/被申请人的证据目录拆分
若案件存在多个被告/被申请人，且各方需独立提交证据目录，遵循以下原则：
- **不共同提交**：各方分别编制独立的证据目录，各自编号从1开始。
- **不重复提交**：同一证据不在多方目录中重复出现。
- **归属规则**：两方都要用的证据，按与哪一方的关联性更强，归属该方提交。关联性强弱判断标准：（1）该证据直接支撑哪一方的抗辩点；（2）该证据的形成主体或接收主体是哪一方；（3）哪一方更依赖该证据证明其主张。
- **分组独立**：每方的证据分组按其自身的抗辩权基础构成要件设计，不求各方分组一致。

### Step 3：读取前期已完成的工作底稿（新增强制步骤）

**目的**：避免重复纳入前期已排除的证据，确保证据筛选结论与前期文书一致。

**必须查阅**：
- `./工作底稿/` 目录下前期已完成的工作底稿，包括但不限于：
  - 答辩提纲/答辩状中的"拟提交证据清单"
  - 案情分析报告中的"证据排除结论"
  - 材料审阅报告中的证据评价
- **提取要点**：记录前期已确定的"拟提交证据"和"已排除证据"及其排除理由。
- **同步记录**：将排除理由同步记入Step 6的筛选确认清单。

**严格禁止行为**：不忽略前期工作底稿，擅自重新筛选证据。

---

### Step 4：按需读取知识库
- **必须读取**：`references/请求权基础检索总表.md`，用于确定本案核心的请求权/抗辩权基础及其构成要件框架。
- **要件基础继承（强制）**：优先读取 `工作底稿/` 下最新的案情分析报告，获取其中的「要件映射表」（02 Step 7.A 输出）。以映射表的构成要件作为证据分组的直接依据——每个构成要件对应一组证据，证明目的直接锚定该要件。若映射表不存在（02 未输出），按以下步骤自行加载：读取 `references/请求权基础检索总表.md` → 读取对应的 `references/案件类型要件库_{{类型}}.md` → 逐要件对照本案事实输出要件映射。若 10 个要件库均未覆盖，自动加载 `案由请求权基础检视总览.md`。
- **严格禁止行为**：不照搬知识库原文，只提取"构成要件清单"用于证据分组和证明目的设计。

### Step 5：法条与案例检索（强制触发）
若出现以下情形，执行外部检索辅助证据分组与证明目的设计：
- **请求权/抗辩权构成要件不明确**：通过北大法宝 MCP / 元典 MCP / 国家法律法规数据库 / Web 检索，明确本案法律关系的具体构成要件，据此确定证据分组。
- **需类案验证证明力**：对某组证据是否足以证明待证事实存疑时，检索人民法院案例库、北大法宝案例库、元典案例库（按案由过滤），查看最高人民法院类似案件中法院对同类证据的采信标准。
- **新型/复杂案由**：同时检索法律法规、案例、司法解释、权威学理解释。
- **引用纪律**：仅引用 top 3 最相关结果，将检索到的"构成要件"和"证明标准"转化为证据分组标题和证明目的，严格禁止编造。
- **法条引用强制核验**：凡引用具体法条，必须先通过北大法宝 MCP / 人民法院案例库 / 国家法律法规数据库 / Web 检索核验条文原文，方可写入文书。
- **案例引用强制核验**：凡引用具体案例，必须先检索人民法院案例库或北大法宝案例库，确认案号真实存在，方可写入文书。
- **不确定性标注**：检索无结果或结果冲突时，不自行取舍；必须标注"【待核实】"并向用户报告。

### Step 6：筛选待提交证据
基于请求权基础或抗辩权基础的构成要件，筛选关键证据：
- **必要性**：只选与构成要件直接相关的证据。
- **充分性**：每个要件事实尽量有完整证据链。
- **经济性**：同类证据只选证明力最强的，避免重复。
- **合法性**：排除形式不合法或可能被排除的证据。
- **排除法定权利**：若某项诉请属于法定权利（如知情权中的委托中介机构），无需提供证据支撑。

**新增筛选检查项（排除规则）**：
- 该证据是否属于案件事实发生过程中形成的原始材料？如系律师在案件处理过程中形成的分析、计算、策略、报告等内部工作文件，不作为证据提交。
- 该证据是否由对方提交？如系对方起诉状、证据目录、答辩状等诉讼材料，不作为我方证据，优先在质证意见中引用或反驳。
- 该证据是否系程序性申请文件？如鉴定申请、调查取证申请等，应以单独申请书形式提交，不列入证据目录。
- 该证据是否已由对方提交？如是，优先在质证意见中引用，不重复提交。
- 该证据本身是否系本案审查对象（如调解书、裁定书等）？如是，原则上不纳入本方证据目录。
- 该证据是否在前期工作底稿中已被排除？如是，保持排除结论，不重新纳入。

输出《待提交证据筛选确认清单》（文本式），**本清单为内部工作底稿，不混入正式证据目录**：

**证据 1.**《借款合同》
- 对应要件：合同成立
- 证明力：★★★★★（关键直接证据）
- 是否入选：✓
- 排除理由：（如被排除，写明原因）

**证据 2.** 银行转账凭证
- 对应要件：款项交付
- 证明力：★★★★☆
- 是否入选：✓
- 排除理由：（如被排除，写明原因）

> **⚠️ 关键边界**：Step 6 的筛选清单是供律师团队内部审核使用的**过程性文件**，Step 9 的证据目录是向法院提交的**正式诉讼文书**。二者必须分离开，严格将筛选清单直接粘贴进证据目录正文。

### Step 7：用户确认（新增步骤）

在正式撰写证据目录前，先向用户汇报筛选确认清单的核心内容，征求确认：

**汇报内容**：
1. 入选证据清单（按分组列出证据名称和编号）
2. 排除证据清单及排除理由
3. 证明策略概述（每组证据要证明什么）

**待确认事项**：
- 入选/排除的证据是否合理
- 分组逻辑是否符合抗辩/攻击要点
- 是否有遗漏或需要调整的证据

**用户确认后，方可进入Step 8正式撰写。** 如用户提出调整意见，返回Step 6重新筛选并更新筛选确认清单。

### Step 8：要件化分组
按请求权基础（或抗辩权基础）的构成要件分组。常见分组示例：

- **合同纠纷**：合同成立 → 合同生效 → 原告履行义务 → 被告违约 → 损失及因果关系
- **侵权纠纷**：侵权行为 → 损害后果 → 因果关系 → 过错/违法性
- **被告抗辩**：主体不适格 → 管辖异议 → 权利障碍 → 权利消灭 → 责任减轻

### Step 9：撰写证据说明和证明

**统一格式（两项，标签强制加粗）**：
- **证据说明：** 介绍证据内容、与本案的关联、来源背景（客观陈述，不写主观评价和内部信息）。（标签写作 `**证据说明：**`）
- **证明：** ……（直接说明该证据用来证明什么，合并原证明对象和证明目的）。（标签写作 `**证明：**`）

**信息边界规则**：
- 证据说明中不出现内部交流内容（律师与当事人的会谈记录、内部评价等）。
- 不出现主观评价性语言（"账做得太清爽""非常明显"等）。
- 只陈述证据本身载明的客观内容和来源背景。

**细节适度规则**：
- 聚焦"证据内容与本案的关联"，不写无关细节。
- 不写证件编号、保管人、设备型号等无关信息。
- 背景信息点到为止（时间、主体、核心内容即可）。

**原件/复印件标注规则**：
- 证据名称一律不标注"原件""复印件""扫描件"等字样。
- 该信息仅在内部筛选清单中记录，供律师自己掌握。

**示例**：

```markdown
**证据说明**：2002年4月，杭州市重特钢铁材料有限公司与蔡正华签订承包经营合同，约定蔡正华承包经营重特钢铁门市部。该合同系原审诉讼中按法院要求提供并提交给法院。

**证明**：蔡正华与金禾公司之间存在真实的承包经营关系，涉案债权源于真实资金往来。
```

### Step 10：生成证据目录

#### 8.1 头部格式

```markdown
# 证据目录

**案件：**

**提交人：** [提交人全称]

**提交日期：** [日期]

---
```

**头部说明**：
- **案件**：自动从 `./办案记录.md` 中读取"案件名称"填入，不留空。格式为"[提交人全称]与[对方当事人全称][案由]案"，如"上海瑞道设备租赁有限公司与河北津西钢铁集团股份有限公司合同纠纷案"。仲裁案件同样适用此格式。
- **提交人**：填写提交证据目录的当事人全称（如"上海瑞道设备租赁有限公司"）。
- **提交日期**：填写实际提交日期，未确定时可留空（"2026年  月  日"）。
- **不写代理身份**：证据目录头部不写"代理身份""被申请人/原告"等诉讼地位信息，这些内容由委托书/授权手续另行证明。

#### 8.2 正文格式（两种模式择一适用）

**模式A：一组统一陈述**（适用于一组内多个证据共同证明同一要件事实）

```markdown
## 一、证明[诉请对应要件1]的证据

### **证据 1.** 《借款合同》（第1-3页）
### **证据 2.** 银行转账凭证（第4页）

**证据说明**：原告于某年某月某日与被告签订《借款合同》，约定借款金额100万元，借款期限6个月；原告于某年某月某日通过银行转账向被告交付借款100万元。上述合同及转账凭证系双方真实签署和履行。

**证明**：原告与被告之间存在借贷合意，原告已履行款项交付义务，符合借款合同成立的构成要件。
```

**模式B：每个证据单独陈述**（适用于每个证据证明独立的要件事实，或需要详细展开证据说明和证明）

```markdown
## 第一组  [分组标题]

**证据 1. [证据全称]**
页码：第  页至第  页

**证据说明：** [介绍证据内容、与本案的关联、来源背景，客观陈述]

**证明：** [该证据用来证明什么]

---

**证据 2. [证据全称]**
页码：第  页至第  页

**证据说明：** ……

**证明：** ……
```

**模式选择规则**：
- 若一组内有多个证据共同指向同一要件事实，用模式A（统一陈述）。
- 若每个证据证明独立的要件事实，或证据说明/证明需要详细展开，用模式B（单独陈述）。
- 被告/被申请人侧的证据目录通常采用模式B，因为抗辩点分散、每个证据证明独立抗辩事实。

#### 8.3 格式要求
- 一级标题 `#`：证据目录
- 二级标题 `##`：要件分组标题（对应诉请/抗辩的构成要件），首行缩进两格
- 头部"提交日期"后必须添加 `---` 分割线，然后再接分组标题
- 证据名称整行加粗：`**证据 1. 证据全称**`（"证据"、数字、"."及证据全称均需加粗）
- 证据名称：一律不标注"原件""复印件""扫描件"等字样
- 页码：可先留空（"第  页至第  页"），待证据册装订后补充
- 标签强制加粗：`**证据说明：**` 和 `**证明：**`（标签文字及冒号均需加粗，标签后正文不加粗）
- 采用"证据说明+证明"两项格式，证据说明客观陈述事实，证明直接说明法律意义
- 文本段落式，不使用表格
- 各证据条目之间使用 `---` 分割线分隔

#### 8.4 尾部与补充说明（对外版本不包含）

- 证据目录是向法院/仲裁庭提交的正式文件，**仅包含已确定的证据**。
- 不出现"待补充证据"、"内部备注"、**Step 6 的筛选确认清单**等面向内部的表述。
- 不出现内部交流内容、主观评价性语言、证件编号、保管人、设备型号等无关信息。
- 不纳入律师在案件处理过程中形成的分析、计算、策略文件，以及对方提交的诉讼材料。
- **证据目录正文末尾不附加"说明""备注""附注"等段落，用以解释排除理由、内部工作安排或损失计算口径**。上述内容仅可写入内部筛选确认清单或律师工作备忘录，不混入对外提交的证据目录。
- 证据目录正文必须从"# 证据目录"标题开始，直接从第一组证据分组进入，在开头附加任何内部审核材料。
- 证据目录 Markdown 初稿、定稿均存放于工作底稿。

### Step 10.5：案件关键事实基准表一致性核对（新增）

> 本步骤为强制执行步骤。在输出最终证据目录前，必须核对证据说明和证明内容中的关键事实与 `工作底稿/YYYYMMDD_案件关键事实基准表.md` 是否一致。

**执行流程**：

1. 提取证据目录中的关键事实：日期、金额、主体名称、案号、合同/协议名称、法院名称、关键事件描述；
2. 与案件关键事实基准表进行逐项比对；
3. 不一致的：
   - 若基准表正确：修正证据目录中的证据说明或证明；
   - 若基准表遗漏或错误：更新基准表（追加变更记录），并同步修正证据目录；
4. 在 `办案记录.md` 中记录本次核对结果。

**强制纪律**：
- 基准表存在时，任何不一致必须修正或标注“待核实”并向用户报告；
- 证据目录中不出现与基准表矛盾的事实表述。

### Step 11：多方主体拆分（条件触发）
若案件存在多个被告/被申请人，且Step 2已确认需独立提交证据目录，执行拆分：
- 按Step 2的归属规则，将证据分配至各方。
- 各方证据重新独立编号（从证据1开始）。
- 各方证据分组按其自身的抗辩权基础重新设计，不求与原始整理版一致。
- 输出多份独立证据目录Markdown文件，文件名区分提交方：
  - `YYYYMMDD_证据目录_案件简称_提交方1.md`
  - `YYYYMMDD_证据目录_案件简称_提交方2.md`

### Step 12：输出Word文档（手动触发，不自动执行）
> **本步骤不自动执行**。证据目录Markdown定稿完成后，由用户手动调用 `markdown-to-word` skill 转为Word文档。
>
> **调用方式**：`@skill:markdown-to-word` 或手动运行转换脚本。建议使用 `--doc-type evidence` 参数调用，以应用证据目录专用排版。
>
> **关键提示**：
> - 证据目录属于当事人名义提交的文件，不使用律师模板（不加 `-d` 参数）。
> - 排版规范：A4纸张（210mm×297mm），上/下边距25.4mm，左/右边距28mm；标题黑体三号（16pt）居中；正文宋体四号（14pt）首行缩进两格（28pt），1.5倍行距；分组标题加粗首行缩进两格；证据名称整行加粗首行缩进两格；"证据说明：""证明："标签加粗、值不加粗。
> - Word文件与Markdown文件同路径存放，扩展名改为 `.docx`。

### Step 13：整理证据材料及实体文件

**13.1 生成证据册PDF**
- 将证据按目录顺序排列。
- **生成证据册PDF**（不含证据目录正文）：`YYYYMMDD证据册（提交方-当事人）.pdf`
- 该文件直接存放于 `案件卷宗/` 根目录。
- 若存在重复证据材料，移入 `资料收集/00_已清理/`。

**13.2 同步整理拟提交证据实体文件（新增）**
- 根据证据目录，从 `资料收集/` 及各子文件夹中复制对应文件到指定文件夹。
- 文件夹路径：默认存放于 `工作底稿/拟提交证据_YYYYMMDD/`
- 文件名统一格式：`证据编号_证据名称.扩展名`
- 如用户要求存放至其他位置，按用户指令执行。
