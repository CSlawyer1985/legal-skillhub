# 民事答辩状写作

## 执行目标

根据原告起诉状、案件材料及要件分析，起草一份以被告/被上诉人/被申请人名义提交的民事答辩状。

## 输入要求

- 案件文件夹路径
- 我方代理角色（必须是被告方）
- 原告起诉状（或相关诉请内容）

## 强制约束

1. **首部结构**：首部仅列答辩人信息，不列原告及其他被告。
2. **称谓规范**：全篇使用当事人全称或简称，不使用“原告”“被告”“被答辩人”“上诉人”“被上诉人”等诉讼地位代称。公司类当事人简称以“公司”结尾，首次出现时以括号注明“（以下简称‘某某公司’）”。
3. **内容结构**：答辩状包含首部、引导句、抗辩理由、落款。不包含“答辩请求”段落、证据清单说明、副本说明、过渡性摘要。
4. **标题格式**：抗辩点使用 `## 一、……` 二级标题，格式为段落式长句，标题下方不空行，正文紧随标题。
5. **多被告处理**：多被告案件时，仅就答辩人自身的事实和责任发表意见，不为其他被告免责或分析连带责任。
6. **事实依据**：答辩状中的事实表述以客观证据内容为准，关键日期、金额、身份关系等细节回查原始证据文件。

## 执行前检查

按 `references/执行前强制检查清单.md` 完成基础检查，并补充：

**通用行为原则读取（强制）**：
- 读取 `references/通用行为原则.md`，全程遵守事实与观点区分、法律分析不预设立场、观点保持一致性、法条与案例引用先核验、事实一致性优先、风险提示常态化、输出结构化可复核等原则。

- 回查已有同类定稿答辩状（如一审答辩状），保持首部格式与排版风格一致。
- 若存在 `工作底稿/YYYYMMDD_案件关键事实基准表.md`，必须读取并作为事实表述基准。
- 确认答辩状中引用的事实以证据内容为准，区分客户会谈记录与证据事实。
- 当前会话中若已读取过 `案件卷宗/` 或 `工作底稿/` 下静态文件，可直接复用；但每次启动新任务前必须重新读取 `办案记录.md` 和 `OCR状态.json`，确认版本和状态未更新。

**前置模块依赖检查（强制）**：
- 按 `references/执行前强制检查清单.md` 第 6 节，检查 01 立项建档和 02 案情梳理是否已完成。
- 01 或 02 未完成时，**默认阻断当前任务**，提示用户先执行前置模块。仅当用户明确确认跳过时方可继续，且必须在 `办案记录.md` 中记录"用户选择跳过 01/02，直接执行本模块"。

**前期工作成果检查（团队协作）**：
- 读取 `办案记录.md` 中的「前期工作成果索引」，检查 02 模块是否已完成。
- 若 02 已完成：直接读取索引中列出的成果文件（案情分析报告、要件映射表、关键事实基准表），不重复执行案情梳理。
- 若 02 未完成：按前置模块依赖检查处理。

## 执行步骤

### Step 1：读取 `./办案记录.md`

读取案件基本信息、代理方身份、诉讼方案、已整理文件清单、**最新版本索引**、**文件重要性索引**。

### Step 1.5：确定文件读取范围

按 L1-L4 读取等级执行：

| 读取等级 | 文件位置 | 读取内容 | 说明 |
|:---|:---|:---|:---|
| **L1 必读** | `案件卷宗/03_对方文件/` 下的最新起诉状/上诉状 | 原告诉讼请求、事实理由、证据 | 必须读取；多版本时按最新版索引选取 |
| **L1 必读** | `案件卷宗/04_法院文书/` 下的判决书/裁定书（二审/再审场景） | 法院认定、程序状态 | 若不存在，跳过 |
| **L2 按需** | `案件卷宗/02_己方文件/` 下的己方证据目录 | 了解己方证据体系 | 若存在则读取 |
| **L2 按需** | `工作底稿/` 下的案情分析报告、要件映射表、关键事实基准表 | 若存在则必读 |
| **L3 触发** | `资料收集/一审材料/`（二审/再审时） | 一审/原审起诉状、答辩状、证据 | 当前为二审/再审时必读 |
| **L3 触发** | `资料收集/关联案件/` | 仅当 `办案记录.md` 标记为涉及核心事实时 |
| **L4 兜底扫描** | `资料收集/` | 全部文件名 + 01 生成的一句话摘要 | 不读全文，用于判断是否存在明显遗漏 |

### Step 2：确认代理方身份

- 必须是被告/被上诉人/被申请人一方。
- 若不是，立即告知用户本模块仅适用于被告方，停止执行。

### Step 3：审查原告起诉状（六来源）

1. 主体来源：原告资格？被告适格？
2. 管辖来源：法院是否有管辖权？
3. 权利来源：请求权基础是否存在？
4. 救济来源：诉请是否超出法定/约定范围？
5. 成就来源：权利行使条件是否成就？
6. 内容来源：原告事实理由是否自相矛盾？证据是否支撑？

### Step 4：按需读取知识库

- 读取 `references/请求权基础检索总表.md`，分析原告请求权基础的漏洞及最优抗辩方向。
- 优先读取 `工作底稿/` 下最新的案情分析报告，获取「要件映射表」。以映射表为抗辩框架，逐一审查原告对每个构成要件的满足状态，寻找要件缺失或证明不足的突破口。
- 若映射表不存在，按 `references/请求权基础检索总表.md` → `references/案件类型要件库_{{类型}}.md` 自行加载；若 10 个要件库均未覆盖，读取 `references/案由请求权基础检视总览.md`。
- 只提取与本案抗辩直接相关的“要件缺失/证明不足”要点，不照搬知识库原文。

### Step 5：法条与案例检索

按 `references/引用核验规范.md` 执行检索与核验：

- 抗辩权基础存疑时，检索 `laws` 和 `books`。
- 需类案支撑抗辩时，检索 `cases`（按案由打 `--tag` 过滤）。
- 新型/复杂案由同时检索 `laws`、`cases`、`books`。
- 凡引用具体法条、案例，均须先经外部检索核验，方可写入文书。
- 检索无结果或结果冲突时，标注“【待核实】”并向用户报告。

### Step 6：构建三级防御体系

1. 积极否认：直接否认原告主张的积极要件（举证责任不转移）。
2. 狭义抗辩：
   - 权利障碍（请求权自始未发生）
   - 权利消灭（请求权曾成立但已消灭）
   - 权利阻止（有权拒绝履行）
3. 备位防御（按需设置）：“退一步讲，即便原告主张成立，……”

### Step 7（可选）：先列答辩提纲

如用户要求“先列提纲”或“先梳理抗辩点”，以结构化形式列出：对方主张点 → 我方抗辩点 → 拟提交证据。存于 `工作底稿/YYYYMMDD_民事答辩提纲_案件简称_工作底稿.md`，经用户确认后再起草正文。

### Step 8：撰写首部

**格式要求**：
- 首部使用段落式排版，不使用 `## 答辩人信息` 标题或 markdown 列表罗列信息。
- 若已有同类定稿答辩状，必须与其保持完全一致的首部排版。
- `# 民事答辩状` 标题居中。
- “答辩人：”“法定代表人：”首行缩进两个中文字符；标签加粗，内容不加粗。
- 委托诉讼代理人默认不写入首部；用户明确要求时添加，格式为“**委托诉讼代理人**：姓名，律所，律师。”否则整行删除，不留空白标题行。
- 引导句不加粗、首行缩进两个中文字符，使用当事人全称并在首次出现时注明简称。
- 引导句与第一个抗辩标题之间空一行。
- 当事人信息各行之间空一行。

**审级区分**：
- 一审：答辩人就[原告全称]诉[被告全称]（以下简称“[简称]”）……一案，答辩如下：
- 二审：答辩人就[原告全称]诉[被告全称]……一案，不服[法院名称]（[案号]）民事判决，提起上诉，答辩如下：
- 再审（调解书）：答辩人就[申请人全称]因与[被申请人全称]、原审[原审当事人地位及名称]……一案，不服[法院名称]（[案号]）民事调解书，向贵院申请再审一案，答辩如下：
- 再审（判决/裁定）：答辩人就[申请人全称]因与[被申请人全称]……一案，不服[法院名称]（[案号]）民事判决/裁定，向贵院申请再审一案，答辩如下：

```markdown
# 民事答辩状

**答辩人**：姓名/名称，住所地，统一社会信用代码。

**法定代表人**：姓名，职务。（如答辩人为法人）

答辩人就[原告姓名/名称]诉[被告名称]（以下简称“[简称]”）……一案，答辩如下：
```

### Step 9：撰写抗辩理由

每个抗辩点格式：

```markdown
## 一、……（段落式长句标题）
[自然段落，简要陈述事实与法律依据。Markdown源文件不缩进、不手动加粗，由markdown-to-word自动处理首行缩进两个中文字符及加粗。标题与正文之间不空行。]

## 二、……
[自然段落]
```

**排版细则**：
- 抗辩点标题使用 `##` 二级标题，格式为 `## 一、……`，不手动加粗、不手动添加全角空格。
- 标题下方不空行，正文段落紧随标题之后。
- 不同抗辩点之间是否空行由律师根据繁简需要决定，但标题与其所属正文之间必须紧贴。
- 正文中不使用“原告”“被告”等诉讼地位指称，使用当事人全称或已规定的简称。

**结构建议**：
- 简：具体证据编号、账目核对细节、差异数字等留给证据目录和质证意见。
- 繁：法律适用错误的核心论证、期限起算的逻辑层次、债权/事实形成的时间线脉络。
- 避免在答辩状中做证据层面的具体反驳，留给质证意见。

**写作要求**：
- 标题必须是段落式长句，反映核心观点。
- 法条引用点到为止：“根据《XX法》第X条的规定”，至多附加1-2句核心内容；不连续引用超过3项完整条款。
- 反自认审查：逐字核对，删除不利事实表述。
- 事实表述以证据内容为准：日期、金额、比例、身份信息等关键事实必须回查原始证据文件。
- 删除空泛评价（如“该论证存在根本性的逻辑跳跃”）、关联度弱的外部事实、反向推论式论证、当事人单方陈述直接作为事实依据。

### Step 10：设置备位防御（按需）

根据案件需要决定是否设置。若前面论证已充分，可省略。

```markdown
> **退一步讲**，即便[对方当事人全称/简称]主张成立，……
```

### Step 11：撰写落款

```markdown
综上所述，……

此致

**××××人民法院**

答辩人：（签名/盖章）

法定代表人：（签字）

日期：××××年××月××日
```

- “综上所述，……”首行缩进两个中文字符，不加粗。
- “此致”首行缩进两个中文字符，不加粗；与受诉法院名称之间空一行。
- “××××人民法院”顶格、加粗。
- “答辩人：（签名/盖章）”“法定代表人：（签字）”“日期：××××年××月××日”右对齐，不加粗；“日期：”前空一行。

### Step 12：替换诉讼地位指称及不适宜简称

执行全文检索：
1. 将“被答辩人”“原告”“被告”“上诉人”“被上诉人”等替换为对应当事人全称或已规定的简称；
2. 检查并修正公司类当事人简称，确保以“公司”结尾；
3. 确保法条原文中的“原告”“被告”等词汇未被误替换。

- [ ] 标题或正文段落前未手动添加全角空格
- [ ] “此致”与“××××人民法院”之间已空一行
- [ ] 正文中已无“原告”“被告”“被答辩人”等诉讼地位指称
- [ ] 公司类当事人简称以“公司”结尾，并在首次出现时以括号注明
- [ ] 首部默认未列“委托诉讼代理人”（除非用户明确要求）
- [ ] 抗辩点标题使用 `## 一、……` 格式且下方正文紧跟不空行

### Step 14：文件存放与更新

- 命名格式：`YYYYMMDD_内容简述_身份后缀.扩展名`。
- 初稿：`工作底稿/YYYYMMDD_民事答辩状_案件简称_初稿.md`
- 修改版：`工作底稿/YYYYMMDD_民事答辩状_案件简称_修改版.md`

- 定稿：`工作底稿/YYYYMMDD_民事答辩状_案件简称.md`

**Word 转换指引**：
- 使用 `markdown-to-word` Skill 转换，命令示例：
  ```bash
  /usr/bin/python3 ~/.workbuddy/skills/markdown-to-word/md2word_converter.py \
    <输入.md> -o <输出.docx> --no-reference-doc --doc-type defense
  ```
- `--doc-type defense` 自动处理首部缩进、引导句缩进、抗辩标题加粗与缩进、落款右对齐、日期前空行等。

## 案件关键事实基准表一致性核对

输出最终答辩状前，核对答辩状中的关键事实（日期、金额、主体名称、案号、合同/协议名称、法院名称、关键事件描述）与 `工作底稿/YYYYMMDD_案件关键事实基准表.md` 是否一致：
- 基准表正确：修正答辩状表述；
- 基准表遗漏或错误：更新基准表并同步修正答辩状；
- 在 `办案记录.md` 中记录核对结果。
- 基准表不存在时，提醒用户“尚未建立跨Skill事实基准表，事实一致性由人工复核”。
