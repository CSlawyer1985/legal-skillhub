# 引用核验规范

> 适用范围：所有涉及法条引用、案例引用、裁判规则阐述的任务。

## 一、引用真实性四级校验

| 级别 | 校验内容 | 通过标准 |
|:---:|:---|:---|
| L1 存在性校验 | 引用的法条/案例是否真实存在 | 有外部数据库检索结果支撑，或标注“【待核实】” |
| L2 准确性校验 | 条文序号、内容、生效状态是否准确 | 与检索结果逐字核对，条文序号、款、项无误 |
| L3 完整性校验 | 是否引用条文全文/裁判要旨完整内容 | 不得仅标注“依据《XX法》相关规定” |
| L4 来源标注校验 | 是否标注了检索来源 | 必须标注“北大法宝”“人民法院案例库”等来源 |

## 二、检索来源优先级

1. 北大法宝 MCP（pkulaw）
2. 元典 MCP（yuandian-mcp）：`law_vector_search`、`qwal_search`、`case_vector_search`、`hall_detect`
3. 人民法院案例库（rmfyalk.court.gov.cn）
4. 国家法律法规数据库（flk.npc.gov.cn）
5. Web 检索补充

## 三、幻觉预警触发条件

| 预警级别 | 触发条件 | 处理方式 |
|:---:|:---|:---|
| 阻断级 | 引用了一条本次任务未执行检索且用户未提供的法条 | 暂停输出，调用北大法宝/元典/Web 核验，确认真实存在后方可继续 |
| 阻断级 | 引用了一个具体案号，但该案号未在本次检索结果中出现 | 暂停输出，重新检索该案号，确认真实存在后方可继续 |
| 阻断级 | 法条内容与检索结果不一致 | 暂停输出，以检索结果为准修正，无结果则删除或标注“【待核实】” |
| 阻断级 | 元典 `hall_detect` 返回“不一致”判定 | 暂停输出，以元典权威原文修正，重新检测通过后方可继续 |
| 警告级 | 案例裁判要旨表述过于“完美契合”，存在 AI 改写风险 | 重新检索该案号原文，核对裁判要旨是否被改写，被改写则恢复原文或删除 |
| 警告级 | 同一法条在不同任务中引用内容不一致 | 核对法律修订历史，确认适用版本，统一引用文本 |
| 警告级 | 元典 `hall_detect` 返回“未命中”判定 | 法条：删除引用或标注“【元典未命中，待人工核实】”；案例：核实案号，不实则删除，真实则标注“【元典未收录】” |
| 注意级 | 引用内容仅来自 AI 训练记忆，无任何检索来源 | 标注“【记忆引用，待核实】”，向用户报告，由用户决定是否保留 |

## 四、输出前强制核验步骤

1. 列出引用清单：逐一列出正文中所有法条引用（法律名称+条号）和案例引用（案号）。
2. 溯源核对：确认每条引用是否来自本次任务的外部检索结果。仅来自记忆的标注“【记忆引用，待核实】”。
3. 冲突处理：检索结果与记忆不一致时，以检索结果为准；检索无结果时，删除或标注“【待核实】”。
4. 引用继承与增量核验：优先读取 02 模块输出的「已验证引用清单」。已在清单中的引用直接通过；新增引用经 MCP 检索验证后追加到清单。
5. 元典外部独立检测：通过 `mcp__yuandian-mcp__yuandian_hall_detect` 传入文书全文，进行外部独立检测。
6. 外部通用 AI 返回内容回验：外部 AI 生成的法条、案例必须经权威数据库回验后方可写入正式文书。
7. 向用户报告：将“【待核实】”清单及元典检测报告向用户展示，由用户决定保留、删除或补充检索。

## 五、引用规范示例

**正确示例**：
> 依据《中华人民共和国民法典》第五百七十七条（来源：北大法宝），“当事人一方不履行合同义务或者履行合同义务不符合约定的，应当承担继续履行、采取补救措施或者赔偿损失等违约责任。”

**错误示例**：
> 依据《民法典》第577条，被告应承担违约责任。（缺少条文全文和来源标注）

## 六、外部 AI 生成材料使用规范

1. 外部通用 AI 生成的法律研究思路、攻防角度、风险点可作为内部参考。
2. 拟写入正式文书的法条、案例、司法解释、裁判要旨，必须通过权威渠道逐项核验。
3. 外部 AI 返回的案例、法条不得直接录入「已验证引用清单」，必须回验后方可录入。
4. 外部 AI 生成的报告归入 `工作底稿/`，命名后缀标注来源（如 `_DeepSeek`、`_Kimi`），并在办案记录中注明“外部AI生成，引用需核验”。
