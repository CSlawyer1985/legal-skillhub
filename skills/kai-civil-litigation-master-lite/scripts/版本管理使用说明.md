# 版本管理使用说明

## 概述

为确保每次技能文档修改后，界面显示的技能名称版本号同步更新，本技能包提供自动化版本管理脚本 `version_manager.py`。

## 快速开始

### 1. 查看当前版本
```bash
cd ~/.workbuddy/skills/KAI·民商事诉讼律师助手
python3 scripts/version_manager.py --current
```

### 2. 递增版本号（以 minor 为例）
```bash
python3 scripts/version_manager.py --bump minor --desc "新增文档管理三场景集成"
```

### 3. 手动完善变更日志
脚本会在 `CHANGELOG.md` 开头添加新版本条目框架，请编辑该文件：
- 填写具体的**核心更新**内容
- 描述**影响范围**
- 确保格式与现有条目一致

## 版本递增规则

| 递增类型 | 使用场景 | 示例 |
|----------|----------|------|
| **major** | 重大架构变更，向后不兼容 | 1.0.0 → 2.0.0 |
| **minor** | 新增功能，向后兼容 | 2.0.0 → 2.1.0 |
| **patch** | bug修复、小优化 | 2.1.0 → 2.1.1 |

**本次更新（文档管理三场景集成）属于 minor 更新。**

## 自动化工作流

### AI 操作规范（强制）
每次修改技能文件后，必须按顺序执行：
1. **确定修改类型** → 选择版本递增类型
2. **运行版本管理脚本** → 自动更新版本号
3. **编辑变更日志** → 完善具体更新内容
4. **重新打包** → 如需分发（可选）

### 用户自动化选项

#### 方案A：手动运行（推荐）
```bash
# 添加到 ~/.zshrc 或 ~/.bashrc 的别名
alias bump-skill='cd ~/.workbuddy/skills/KAI·民商事诉讼律师助手 && python3 scripts/version_manager.py'

# 使用示例
bump-skill --bump minor --desc "更新描述"
```

#### 方案B：Git 预提交钩子（如使用 git）
在 `.git/hooks/pre-commit` 中添加：
```bash
#!/bin/bash
# 检测技能文件变化，自动更新版本号
# （需自定义实现）
```

#### 方案C：文件监控（高级）
使用 `watchdog` 或 `fswatch` 监控技能文件变化，自动触发版本更新。

## 脚本工作原理

1. **读取当前版本**：从 `SKILL.md` 的 `version:` 字段提取
2. **递增版本号**：根据参数计算新版本号
3. **更新文件**：
   - `SKILL.md`：version 字段、name/name_zh 字段、主标题
   - `README.md`：标题版本号
   - `CHANGELOG.md`：添加新条目框架
4. **输出提示**：告知用户需要手动完善的步骤

## 文件结构影响

```
技能包目录/
├── SKILL.md                    # 版本号：2.1.0 → 2.1.1
├── README.md                   # 标题：v2.1.0 → v2.1.1
├── CHANGELOG.md                # 新增版本条目
└── scripts/
    ├── version_manager.py      # 版本管理脚本
    └── 版本管理使用说明.md     # 本文档
```

## 故障排除

### 常见问题

1. **"未找到 version 字段"**
   - 检查 `SKILL.md` 格式，确保有 `version: X.X.X` 行

2. **版本号未更新**
   - 确认文件路径正确
   - 检查文件读写权限

3. **变更日志格式错乱**
   - 手动编辑 `CHANGELOG.md` 恢复格式
   - 确保条目以 `## vX.X.X（YYYY-MM-DD）` 开头

### 手动恢复
如脚本出错，可手动修改以下文件：
1. `SKILL.md`：第7行 `version:` 字段
2. `SKILL.md`：第2-3行 `name:` 和 `name_zh:` 字段
3. `SKILL.md`：第10行主标题
4. `README.md`：第1行标题
5. `CHANGELOG.md`：在开头添加新版本条目
