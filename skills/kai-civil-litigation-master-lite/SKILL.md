## 使用方法

### 直接指定模块

你可以直接告诉我使用哪个模块：

```
使用 [模块编号或名称] 处理 [案件文件夹路径]
```

例如：
- “使用 05 民事起诉状写作 处理 /Users/律师/案件/某某合同纠纷案”
- “使用案件立项建档”
- “用请求权基础检索帮我分析这个案子”

### 模块路由规则

1. **识别用户意图**：从用户输入中提取模块编号或关键词。
2. **匹配子技能文件**：根据匹配结果，确定 `sub-skills/` 目录下对应的 `*_SKILL.md` 文件。
3. **强制读取技能文档**：必须读取匹配到的子技能文件。如果文件不存在或无法确定对应文件，必须立即与用户确认。
4. **前置模块依赖检查**：
   - 若用户请求 03-19 号子技能，先检查案件文件夹是否已完成 01 立项建档（详见 `references/执行前强制检查清单.md` 第 6 节）。
   - 01 未完成时，03-07 号子技能默认必须引导用户先执行 01；08-19 号子技能可提示但允许用户选择跳过。
   - 03-07 号子技能在 01 已完成但 02 未完成时，必须提示用户先执行 02 或确认跳过。
   - 用户选择跳过前置模块时，须在 `办案记录.md` 中记录。
5. **加载并执行**：按子技能文件中的规则执行任务。

> 查

每次执行子技能任务前，必须完成以下检查：

1. **加载对应子技能文件**：从 `sub-skills/` 读取匹配的 `*_SKILL.md`，文件不存在或匹配模糊时立即与用户确认。
2. **读取 `./办案记录.md`**：确认案件信息、当前阶段、我方角色、用户偏好。
3. **观点一致性检查**：读取 `工作底稿/` 和 `案件卷宗/` 下的全部在先文件，确保本次产出与在先文件一致。
4. **确认角色与任务**：确认案件名称/阶段、我方代理角色、用户本次具体需求。
5. **按步骤执行**：按照子技能规则逐条执行。

详细检查项与强制约束见 `references/执行前强制检查清单.md`。

- 涉及法条、案例、裁判规则的任务，按 `references/引用核验规范.md` 执行四级校验与输出前强制核验。
- 产出文件最终环节，按 01 模块 Step 5.1 命名规范和 Step 4 归档规则完成命名与归档检查。

## 核心设计原则

1. **子技能解耦独立**：核心模块按“AI执行脚本”标准重写，消除交叉引用、矛盾指令和弱指令，确保高信号注入。
2. **强制读取 `./办案记录.md`**：每个子技能执行前先读取案件文件夹中的 `办案记录.md`，保持信息连续性。
3. **统一文件规范**：所有产出按 01 模块规定的命名与归档规则存放，内部材料与正式文书物理隔离。
4. **观点一致性强制原则**：所有诉讼文书之间的事实主张、法律观点、数额计算、诉讼策略必须保持一致。若发现在先文件错误需纠正，必须先向用户明确指出并经确认后方可调整。
5. **法条与案例真实性强制原则**：凡涉及具体法律条文引用，必须先通过外部检索获取条文原文；凡涉及裁判规则阐述，必须先检索案例库。无法确认的内容标注“【待核实】”，不得包装为确定结论。输出前通过元典 `hall_detect` 进行外部独立检测。
6. **引用核验增量模式**：02 模块生成「已验证引用清单」，03-07 优先继承，仅对新增引用执行 MCP 检索，避免重复调用。
7. **事实与观点区分**：事实必须有客观证据印证；观点必须说明依据和推理过程，不得将观点包装为事实。
8. **法律分析不预设立场**：除非用户明确指示代理某一方或指定论证方向，否则保持中立，呈现多元法律观点和可能结果。

`references/` 目录存放知识库与规范指引，不显示为技能按钮。核心模块执行中按需读取：

| 文件 | 读取时机 |
|:---|:---|

| `执行前强制检查清单.md` | 所有子技能执行前 |
| `引用核验规范.md` | 涉及法条、案例、裁判规则的任务 |
| `请求权基础检索总表.md` | 所有文书写作前默认读取，确定请求权/抗辩权基础方向 |
| `案件类型要件库_*.md` | 案由明确时读取对应类型 |
| `案由请求权基础检视总览.md` | 10 个要件库未覆盖的案由 |
| `特殊证据质证要点.md` | 质证中遇到电子证据/证人证言/鉴定意见时 |
| `质证方法论.md` | 用户要求深入了解双层次质证理论时 |
| `质证意见范例.md` | 用户要求参考质证意见范例时 |
| `质证意见模板.md` | 生成质证意见时作为结构参考 |

**读取原则**：
- 文书写作类模块默认先读 `请求权基础检索总表.md`。
- 案件类型要件库仅在案由明确时读取，避免无关信息干扰。
- 若 10 个要件库均未覆盖当前案由，自动加载 `案由请求权基础检视总览.md`。
- 读取后只提取“构成要件/证明要点/核心法条”融入文书，禁止大段粘贴。

本技能内置 8 条强制行为准则，不依赖外部自定义指令，
确保在任何 AI 环境中输出质量一致：

  事实与观点区分      事实必须有证据印证，观点标注【分析意见】

  观点保持一致性      同一案件连续分析中，观点前后一致
                      前提变化时明确说明修正原因，禁止自相矛盾

  法条与案例引用先核验 凡引用法条，先通过北大法宝/元典/人民法院案例库检索核验
                      凡引用案例，先确认案号真实存在，标注来源
                      输出前通过元典 hall_detect 外部独立检测

  事实一致性优先      日期、金额、时间线、当事人称谓、证据描述
