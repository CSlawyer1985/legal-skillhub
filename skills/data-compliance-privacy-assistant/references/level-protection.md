# 网络安全等级保护（等保2.0）定级备案与测评指南

> 标准依据：《中华人民共和国网络安全法》第21条、GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》、GB/T 22240-2020《信息安全技术 网络安全等级保护定级指南》、GB/T 28448-2019《信息安全技术 网络安全等级保护测评要求》、《信息安全等级保护管理办法》（公通字〔2007〕43号）。
>
> ⚠️ 免责声明：本指南仅供参考，具体定级备案与测评要求以国家标准最新版本及公安部发布的最新规定为准。

本文档是 Phase 3「数据分类分级与等级保护」的核心依据，系统阐述等保2.0的定级方法、备案流程、各等级技术与管理要求及测评实务。

---

## 一、法律依据与制度概述

### 1.1 法律依据
- **《网络安全法》第21条**：国家实行网络安全等级保护制度。网络运营者应当按照网络安全等级保护制度的要求，履行下列安全保护义务，保障网络免受干扰、破坏或者未经授权的访问，防止网络数据泄露或者被窃取、篡改：
  - 制定内部安全管理制度和操作规程，确定网络安全负责人，落实网络安全保护责任；
  - 采取防范计算机病毒和网络攻击、网络侵入等危害网络安全行为的技术措施；
  - 采取监测、记录网络运行状态、网络安全事件的技术措施，并按照规定留存相关的网络日志不少于六个月；
  - 采取数据分类、重要数据备份和加密等措施；
  - 法律、行政法规规定的其他义务。

### 1.2 等保2.0核心标准族

## 二、等级划分与定级方法

### 2.1 五个安全保护等级（GB/T 22240-2020）

| 等级 | 保护等级名称 | 受到破坏后侵害的客体 | 侵害程度 | 典型系统 |
|------|------------|-------------------|---------|---------|
| 第一级 | 自主保护级 | 公民、法人合法权益 | 损害 | 一般小型网站、非核心业务系统 |
| 第二级 | 指导保护级 | 公民、法人合法权益；社会秩序、公共利益 | 严重损害 | 一般企业业务系统、行业信息平台 |
| 第三级 | 监督保护级 | 社会秩序、公共利益；国家安全 | 特别严重损害（社会秩序/公共利益）或损害（国家安全） | 关键业务系统、大型平台、政府核心系统 |
| 第四级 | 强制保护级 | 国家安全 | 特别严重损害 | 国家重要领域核心系统 |
| 第五级 | 专控保护级 | 国家安全 | 严重损害 | 极特殊国家关键系统 |

### 2.2 定级方法

定级采用"**客体侵害 + 侵害程度**"二维矩阵法：

**侵害客体：**
- 公民、法人或其他组织的合法权益（最低）
- 社会秩序、公共利益（中等）
- 国家安全（最高）

**侵害程度：**
- 损害（一般）
- 严重损害
- 特别严重损害

**定级原则：**
1. 确定定级对象（信息系统、通信网络、数据资源等）；
2. 分析受破坏后侵害的客体；
3. 分析侵害程度；
4. 查表确定安全保护等级。

### 2.3 定级实务要点
- 一般企业的**核心业务系统**多定为**第二级或第三级**；
- 处理大量个人信息或重要数据的系统通常不低于**第三级**；
- 关键信息基础设施（CIIO）的核心系统通常不低于**第三级**；
- 一个单位可能有多个不同等级的系统，应分别定级。

## 三、备案流程

### 3.1 备案要求
- **第二级及以上**信息系统须向公安机关备案（《信息安全等级保护管理办法》）；
- 备案时限：确定安全保护等级后**30日内**向所在地设区的市级及以上公安机关网安部门备案。

### 3.2 备案材料清单
1. 《信息系统安全等级保护备案表》（一式两份）；
2. 信息系统安全等级保护定级报告（参照GB/T 22240）；
3. 信息系统拓扑图及说明；
4. 信息系统安全管理制度（初步）；
5. 信息系统安全保护设施规划实施方案；
6. 专家评审意见（第三级及以上）；
7. 其他公安机关要求的材料。

### 3.3 备案审核
- 公安机关受理后，对材料齐全、符合要求的，在规定期限内颁发《信息系统安全等级保护备案证明》；
- 第三级及以上系统由设区的市级公安机关审核后报省级公安机关复核。

## 四、等级测评

### 4.1 测评要求

| 等级 | 测评频次 | 测评机构要求 |
|------|---------|------------|
| 第二级 | 建议定期（通常每两年至少1次） | 公安部推荐测评机构 |
| 第三级 | **每年至少1次** | 公安部第三级以上测评机构 |
| 第四级 | **每半年至少1次** | 公安部第四级以上测评机构 |
| 第五级 | 依照特殊规定 | 特定机构 |

### 4.2 测评结论判定（GB/T 28448-2019）

测评结果分为四类：
- **优**：不存在高/中风险问题，测评项符合率高；
- **良**：不存在高风险问题，部分中风险问题；
- **中**：存在高风险问题，但影响可控；
- **差**：存在严重高风险问题，系统存在重大安全隐患。

> 等保测评报告中"不符合"项较多时需整改后复测，高风险问题必须整改关闭。

### 4.3 测评机构选择
- 应选择**经公安部认证**的等级保护测评机构；
- 查询渠道：国家网络安全等级保护工作协调平台、各省级公安网安部门公示；
- 注意区分测评机构可开展的等级范围。

## 五、安全技术要求（"一个中心，三重防护"）

GB/T 22239-2019 采用"**一个中心，三重防护**"的纵深防御架构：

```
                    ┌──────────────────┐
                    │   安全管理中心     │
                    │ （系统管理+安全管理）│
                    │  +集中管控+安全审计 │
                    └────────┬─────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
┌───────────────┐  ┌───────────────┐  ┌───────────────┐
│ 安全通信网络   │  │ 安全区域边界   │  │ 安全计算环境   │
│（网络架构/通信 │  │（边界防护/访问│  │（身份鉴别/访问│
│  传输/可信接入）│  │  控制/入侵防范）│  │  控制/数据安全）│
└───────────────┘  └───────────────┘  └───────────────┘
```

### 5.1 安全通信网络

| 控制项 | 核心要求（第三级） |
|--------|------------------|
| 网络架构 | 合理划分网络区域，关键网络设备冗余设计 |
| 通信传输 | 采用校验技术或密码技术保证通信过程中数据完整性和保密性 |
| 可信接入 | 可基于可信根验证通信设备可信性 |

### 5.2 安全区域边界

| 控制项 | 核心要求（第三级） |
|--------|------------------|
| 边界防护 | 跨边界访问和数据流通过安全设备控制 |
| 访问控制 | 基于五元组（源/目的地址、端口、协议）的访问控制 |
| 入侵防范 | 部署入侵检测/防御系统，监测网络攻击行为 |
| 恶意代码防范 | 部署防恶意代码产品 |
| 安全审计 | 对边界访问行为进行审计，日志留存≥6个月 |

### 5.3 安全计算环境

| 控制项 | 核心要求（第三级） |
|--------|------------------|
| 身份鉴别 | 对登录用户进行身份标识和鉴别，口令复杂度要求 |
| 访问控制 | 基于角色/主体的访问控制，最小权限原则 |
| 安全审计 | 对用户行为、安全事件进行审计记录 |
| 入侵防范 | 检测对主机/应用的入侵行为 |
| 恶意代码防范 | 安装防恶意代码软件 |
| 数据完整性 | 保证重要数据传输/存储过程中的完整性 |
| 数据保密性 | 对敏感数据采用加密等保密措施 |
| 数据备份恢复 | 提供本地/异地数据备份与恢复功能 |
| 剩余信息保护 | 鉴别信息/敏感数据存放空间释放或分配前清除 |
| 个人信息保护 | 仅采集和保存业务必需的个人信息 |

### 5.4 安全管理中心

- **系统管理**：对系统资源、运行状况、配置进行统一管理；
- **安全管理**：对安全策略、安全机制、安全审计进行集中管理；
- **集中管控**：划分特定管理区域，对分布在网络中的安全设备/安全措施进行集中管控；
- **安全管理中心**：对网络中发生的各类安全事件进行识别、报警和分析。

## 六、安全管理要求

GB/T 22239-2019 管理要求分为五大类：

| 管理类别 | 核心要求（第三级） |
|---------|------------------|
| 安全管理机构 | 成立指导和管理网络安全工作的委员会或领导小组，设立网络安全管理部门 |
| 安全管理人员 | 配备专业安全管理人员，关键岗位人员签署保密协议，定期安全教育与考核 |
| 安全建设管理 | 系统建设需经过定级备案、方案设计评审、产品采购、软件开发、工程实施、测试验收等环节 |
| 安全运维管理 | 环境管理、资产管理、介质管理、设备维护管理、漏洞和风险管理、网络与系统安全管理、恶意代码防范管理、密码管理、变更管理、备份与恢复管理、安全事件处置、应急预案管理 |
| 安全管理制度 | 制定总体安全策略、安全管理制度、操作规程，定期修订 |

## 七、扩展要求（等保2.0新增）

等保2.0针对新技术新应用场景增加了扩展要求，企业涉及以下场景须额外满足：

### 7.1 云计算扩展要求
- 明确云服务商与云租户的安全责任边界；
- 虚拟化安全（虚拟机隔离、镜像安全）；
- 云平台多租户数据隔离；
- 云服务商选择与评估。

### 7.2 移动互联扩展要求
- 移动应用安全（App代码安全、通信安全）；
- 移动终端管理（设备管控、数据加密）；
- 移动应用商店上架安全检测。

### 7.3 物联网扩展要求
- 感知层设备安全（身份认证、固件安全）；
- 数据传输安全（加密传输）；
- 感知节点物理防护。

### 7.4 工业控制系统扩展要求
- 控制设备安全（PLC/SCADA安全）；
- 工控网络与办公网络隔离；
- 工控系统漏洞管理（注意补丁兼容性）。

## 八、关键信息基础设施（CII）保护

### 8.1 等保与CII的关系
- **等保是基础**：CII安全保护在等保基础上实行重点保护（《关键信息基础设施安全保护条例》第8条）；
- CII运营者须履行等保义务 + 附加义务（供应链安全审查、数据本地化存储等）。

### 8.2 CII认定标准
重要行业和领域（公共通信和信息服务、能源、交通、水利、金融、公共服务、电子政务、国防科技工业等）的核心设施、信息系统，一旦遭到破坏可能严重危害国家安全、国计民生、公共利益的，认定为CII。

## 九、常见问题

| 问题 | 解答 |
|------|------|
| 等保是强制的吗？ | 网络安全法第21条规定等保是法定义务，第二级以上须备案 |
| 小型网站需要做等保吗？ | 视系统重要程度和受破坏危害程度定级，即使第一级也需履行基本安全保护义务 |
| 等保测评多久做一次？ | 第三级每年至少1次，第四级每半年至少1次 |
| 等保测评没通过怎么办？ | 整改后申请复测，高风险项须整改关闭 |
| 云上系统谁负责等保？ | 云服务商负责云平台本身，云租户负责其上的应用系统，双方共同承担（责任共担模型） |
| 等保和密评（密码应用安全评估）有什么关系？ | 等保侧重整体安全，密评侧重密码技术应用合规，第三级以上系统建议同步开展密评 |

## 十、等保建设实施路线图

```markdown
# 🛡️ 网络安全等级保护建设路线图

## 阶段一：定级与备案（T-0 ~ T+1月）
- [ ] 确定定级对象
- [ ] 编制定级报告（参照GB/T 22240-2020）
- [ ] 第三级及以上组织专家评审
- [ ] 向公安机关备案（定级后30日内）

## 阶段二：安全建设与整改（T+1 ~ T+4月）
- [ ] 差距分析（对照GB/T 22239-2019差距评估）
- [ ] 安全方案设计与评审
- [ ] 技术措施建设（部署安全设备/系统加固）
- [ ] 管理制度建设（五大类管理制度）
- [ ] 安全产品采购（选择经认证的产品）

## 阶段三：等级测评（T+4 ~ T+6月）
- [ ] 选择具有相应资质的测评机构
- [ ] 配合开展现场测评
- [ ] 测评报告整改（关闭高风险项）
- [ ] 获取测评报告

## 阶段四：持续运维（T+6月起）
- [ ] 建立安全运维机制
- [ ] 按频次开展定期测评（第三级每年/第四级每半年）
- [ ] 持续安全监测与应急响应
- [ ] 系统重大变更后重新定级备案（如适用）
```
