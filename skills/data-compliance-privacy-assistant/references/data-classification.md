# 数据分类分级实操指南

> 标准依据：《中华人民共和国数据安全法》第21条、GB/T 43697-2024《数据安全技术 数据分类分级规则》、GB/T 35273-2020《信息安全技术 个人信息安全规范》、GB/T 38667-2020《信息安全技术 数据分类分级规则》（已被GB/T 43697-2024替代整合）。
>
> ⚠️ 免责声明：本指南仅供参考，具体分类分级标准以国家标准最新版本及各行业主管部门发布的重要数据目录为准。

本文档是 Phase 1「数据合规现状评估」与 Phase 3「数据分类分级与等级保护」的核心依据，系统阐述数据分类分级的原则、标准、方法与落地管控要求。

---

## 一、法律依据与基本概念

### 1.1 法律依据

- **《数据安全法》第21条**：国家建立数据分类分级保护制度，根据数据在经济社会发展中的重要程度，以及一旦遭到篡改、破坏、泄露或者非法获取、非法利用，对国家安全、公共利益或者个人、组织合法权益造成的危害程度，对数据实行分类分级保护。国家数据安全工作协调机制统筹协调有关部门制定重要数据目录。
- **《网络安全法》第21条**：网络运营者应当按照网络安全等级保护制度的要求，采取数据分类、重要数据备份和加密等措施。
- **《个人信息保护法》第51条**：个人信息处理者应当根据个人信息的处理目的、处理方式、个人信息的种类以及对个人权益的影响、可能存在的安全风险等，采取相应的加密、去标识化等安全技术措施。

### 1.2 核心概念

| 概念 | 定义 |
|------|------|
| 数据分类 | 根据数据的属性或特征，将其按一定原则和方法进行区分和归类，形成具有一定从属关系的数据集合 |
| 数据分级 | 根据数据安全保护需要，按照一定规则对数据进行级别划分 |
| 核心数据 | 对领域、群体中具有最高安全保护价值的数据，关系国家安全、国民经济命脉、重要民生、重大公共利益 |
| 重要数据 | 特定领域、特定群体、特定区域或达到一定精度和规模的数据，一旦遭到泄露可能直接危害国家安全、经济运行、社会稳定、公共健康和安全 |
| 一般数据 | 不被纳入核心数据、重要数据范畴的其他数据 |

## 二、数据分级标准

### 2.1 三个基本层级（数安法第21条确立的框架）

| 级别 | 名称 | 定义与特征 | 典型示例 |
|------|------|----------|---------|
| 第一级 | 核心数据 | 关系国家安全、国民经济命脉、重要民生和重大公共利益等的数据 | 国家政务基础数据、国防军工数据、关系国计民生的大型基础设施数据 |
| 第二级 | 重要数据 | 一旦遭到篡改、破坏、泄露或非法获取、非法利用，可能危害国家安全、公共利益的数据 | 人口健康大数据、自然资源数据、大规模经济运行数据、重要行业关键数据 |
| 第三级 | 一般数据 | 核心数据、重要数据之外的其他数据 | 企业一般运营数据、非敏感的用户偏好数据 |

### 2.2 一般数据的进一步分级（GB/T 43697-2024）

一般数据可根据安全保护需要进一步分级（通常划分为4级），主要依据**影响对象**与**影响程度**：

#### 影响对象维度

| 影响对象 | 说明 |
|---------|------|
| 国家安全 | 危害国家政权、主权、统一和领土完整等 |
| 公共利益 | 危害社会秩序、公共安全、生态环境等 |
| 个人合法权益 | 危害公民人身权、财产权、人格权等 |
| 组织合法权益 | 危害法人或其他组织的合法权益 |

#### 影响程度维度

| 影响程度 | 表现 |
|---------|------|
| 特别严重 | 造成大规模、系统性、长期性损害 |
| 严重 | 造成较大规模、较严重的损害 |
| 一般 | 造成有限范围内的损害 |
| 轻微 | 造成轻微、可迅速恢复的损害 |

> **分级原则**：影响国家安全的数据→核心数据；影响国家安全/公共利益的数据→重要数据；仅影响个人/组织合法权益的→一般数据（并按影响程度进一步分级）。

### 2.3 个人信息分级（敏感程度判定）

个人信息按敏感程度分为两类，保护要求差异显著：

| 类别 | 定义（个保法第28条） | 保护要求增量 |
|------|-------------------|------------|
| 敏感个人信息 | 一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息 | 单独同意 + 告知必要性 + PIA + 加密/脱敏 |
| 一般个人信息 | 不属于敏感个人信息的其他个人信息 | 一般告知同意 + 基本安全措施 |

**敏感个人信息具体范围（个保法第28条）：**
- 生物识别：人脸、指纹、虹膜、掌纹、声纹、基因等；
- 宗教信仰；
- 特定身份；
- 医疗健康：病历、健康检查、诊疗记录、基因检测等；
- 金融账户：银行账户、支付账户、证券/保险账户等；
- 行踪轨迹：位置信息、出行轨迹；
- 不满14周岁未成年人的个人信息（一律按敏感处理）；
- 其他一旦泄露或非法使用可能危害个人权益的个人信息。

## 三、数据分级方法（GB/T 43697-2024 四步法）

### 步骤一：数据资产识别

- 梳理企业全部数据资产，编制数据资产目录；
- 明确每个数据项的来源、用途、存储位置、流转路径；
- 识别数据资产的责任主体（业务部门/数据owner）。

### 步骤二：影响对象分析

- 分析每个数据集安全属性（保密性、完整性、可用性）遭到破坏时，影响哪些客体；
- 客体层级从高到低：国家安全 > 公共利益 > 个人/组织合法权益。

### 步骤三：影响程度评估

- 结合数据规模、精度、场景，评估一旦泄露/篡改/丢失/损毁的潜在危害程度；
- 评估方法可参照定性与定量相结合的方式。

### 步骤四：级别确定

- 综合影响对象与影响程度，查表确定数据级别（核心/重要/一般，一般可进一步细分）；
- 对个人信息叠加敏感程度判定（敏感/一般）；
- 形成数据分级目录。

## 四、分级差异化管控要求

不同级别数据应采取差异化安全管控措施，保护强度应与数据级别相匹配：

| 管控维度 | 核心数据 | 重要数据 | 一般数据（较高） | 一般数据（较低） |
|---------|---------|---------|---------------|---------------|
| 访问控制 | 最高权限+审批+双人复核 | 强制访问控制+审批 | 角色权限控制 | 基础权限控制 |
| 加密存储 | 强制高强度加密 | 加密存储 | 建议加密 | 按需加密 |
| 传输安全 | 专用加密通道 | 加密传输 | 加密传输 | 按需加密 |
| 数据脱敏 | 严格禁止明文使用 | 高强度脱敏 | 按需脱敏 | 可不脱敏 |
| 日志审计 | 全量审计+实时告警 | 全量审计 | 定期审计 | 基础日志 |
| 备份恢复 | 异地多副本+定期演练 | 定期备份+演练 | 定期备份 | 按需备份 |
| 共享出境 | 极严格限制/禁止 | 安全评估审批 | 合规审批 | 一般审批 |
| 销毁 | 不可恢复+全程记录 | 不可恢复+记录 | 标准销毁 | 标准销毁 |

## 五、重要数据识别要点

### 5.1 识别方法
- 参照**各行业、各领域**制定的重要数据具体目录；
- 由国家数据安全工作协调机制统筹，各行业主管部门负责制定本行业重要数据目录；
- 企业应持续关注主管部门发布的目录更新。

### 5.2 常见重要数据特征（参考）
- 大规模个人敏感信息汇集数据；
- 关系国民经济运行的重要行业（能源、交通、水利、金融、公共服务等）的运行数据；
- 关系自然资源与环境的重要数据；
- 关系关键技术、大型工程的重要数据；
- 达到一定精度/规模的经济、人口、地理测绘数据。

> ⚠️ 重要数据的认定具有动态性，同一数据在不同行业、不同规模下可能认定不同，须结合行业目录判定。

## 七、分类分级工作落地建议

### 7.1 工作步骤建议
1. 成立分类分级工作组（数据安全负责人牵头，业务+IT+合规参与）；
2. 开展数据资产盘点（可借助自动化工具扫描发现数据资产）；
3. 编制数据资产目录（含元数据信息）；
4. 按四步法进行分级判定；
5. 编制《数据分类分级目录》，经审批后发布；
6. 建立分级目录动态维护机制（数据新增/变更时及时更新）；
7. 将分级结果嵌入业务系统（按级别自动施加管控策略）。

### 7.2 常见问题与误区

| 问题 | 正确做法 |
|------|---------|
| 误将业务数据全部定为一般数据 | 应评估大规模聚合后可能提升级别（如大量用户数据汇集可能构成重要数据） |
| 忽视个人信息敏感程度 | 应区分敏感/一般个人信息，分别施策 |
| 分级后未落地管控 | 分级是手段，差异化管控才是目的，须嵌入业务流程 |
| 一次性定级不再更新 | 数据资产动态变化，分级目录应定期复审更新 |

### 7.3 分类分级与等级保护的关系

| 维度 | 数据分类分级 | 网络安全等级保护 |
|------|------------|----------------|
| 管理对象 | 数据本身 | 信息系统/网络 |
| 核心标准 | GB/T 43697-2024 | GB/T 22239-2019 |
| 法律依据 | 数据安全法第21条 | 网络安全法第21条 |
| 关联 | 重要数据所在系统通常不低于等保第三级 | 承载高级别数据的系统定级应更高 |

> 💡 **实务提示**：数据分类分级与等级保护应协同推进。数据级别是系统定级的重要参考——承载核心数据、重要数据的系统，其等保级别通常不低于第三级。
