# 数据安全事件应急预案和报告模板

> 法律依据：《中华人民共和国数据安全法》第29-30条、《中华人民共和国个人信息保护法》第57条、《中华人民共和国网络安全法》第25条、第51条、《国家网络安全事件应急预案》。
>
> ⚠️ 免责声明：本模板仅供参考，企业应根据自身业务特点和监管要求制定具体预案，具体报告义务以法律法规最新版本为准。

本文档是 Phase 6「数据安全事件应急响应」的核心依据，提供数据安全事件分级标准、应急响应流程、法定报告义务及预案与报告模板。

---

## 一、法律依据

### 1.1 数据安全法相关义务

**第29条（事件处置与报告义务）**：
开展数据处理活动应当加强风险监测，发现数据安全缺陷、漏洞等风险时，应当**立即采取补救措施**；发生数据安全事件时，应当**立即采取处置措施**，按照规定及时**告知用户**并向有关主管部门**报告**。

**第30条**：
重要数据的处理者应当按照规定**定期开展风险评估**，并向有关主管部门报送风险评估报告。

### 1.2 个人信息保护法相关义务

**第57条（个人信息泄露处置义务）**：
发生或者可能发生个人信息泄露、篡改、丢失的，个人信息处理者应当**立即采取补救措施**，并**通知履行个人信息保护职责的部门和个人**。

> **例外情形**：采取措施能够有效避免信息泄露、篡改、丢失造成危害的，个人信息处理者可以**不通知个人**；履行个人信息保护职责的部门认为可能造成危害的，有权**要求其通知**。

**通知应包括以下内容：**
1. 发生或者可能发生个人信息泄露、篡改、丢失的**信息种类、原因和可能造成的危害**；
2. 个人信息处理者采取的**补救措施**和个人可以采取的**减轻危害的措施**；
3. 个人信息处理者的**联系方式**。

### 1.3 网络安全法相关义务

- **第25条**：网络运营者应当制定网络安全事件应急预案，及时处置系统漏洞、计算机病毒、网络攻击、网络侵入等安全风险。
- **第51条**：关键信息基础设施的运营者应当制定网络安全事件应急预案，并定期进行演练。

## 二、数据安全事件分级

参照《国家网络安全事件应急预案》，数据安全事件分为四个等级：

| 等级 | 名称 | 分级标准（参考） |
|------|------|----------------|
| 一级 | 特别重大 | 国家重要数据/核心数据大规模泄露，或造成特别严重的社会影响/国家安全危害 |
| 二级 | 重大 | 大规模敏感个人信息泄露（涉及人数多），或重要数据泄露，造成严重社会影响 |
| 三级 | 较大 | 一定规模个人信息泄露/篡改/丢失，造成较大影响 |
| 四级 | 一般 | 少量个人信息或一般数据受影响，危害较轻 |

### 分级考量因素

| 因素 | 说明 |
|------|------|
| 数据类型与级别 | 核心数据 > 重要数据 > 一般数据；敏感个人信息 > 一般个人信息 |
| 受影响规模 | 涉及的数据量、个人数量 |
| 危害程度 | 对国家安全/公共利益/个人权益/组织利益的影响程度 |
| 影响范围 | 影响的地域、行业、人群范围 |
| 持续时间 | 事件持续的时间长短 |

## 三、应急响应流程（五阶段）

```
┌──────────────────────────────────────────────────────────────┐
│                     应急响应五阶段                              │
│                                                              │
│  阶段一          阶段二          阶段三          阶段四/五        │
│  事件发现        事件遏制        调查评估        恢复改进        │
│  与报告          与根除          与定级                          │
│                                                              │
│   │              │              │              │              │
│   ▼              ▼              ▼              ▼              │
│ 监测发现       隔离受影响      查明原因       系统恢复         │
│ 立即报告       系统/阻断       评估影响       安全加固         │
│ 启动预案       泄露渠道        判定等级       总结经验         │
│ 通知部门       保全证据        记录处置       完善预案         │
│ 和个人                         过程           和制度           │
└──────────────────────────────────────────────────────────────┘
```

### 阶段一：事件发现与报告

- **发现渠道**：安全监测告警、用户投诉举报、第三方通报、员工发现等；
- **立即响应**：发现事件后**立即启动应急预案**，组建应急响应团队；
- **报告义务**：按事件等级向相应主管部门报告；
- **通知个人**：如涉及个人信息泄露，依法通知受影响个人（个保法第57条）。

### 阶段二：事件遏制与根除

- **隔离**：隔离受影响的系统、网络、设备，阻断数据泄露渠道；
- **取证**：保全日志、系统镜像等证据（用于调查和合规举证）；
- **根除**：清除恶意程序、修复漏洞、关闭风险入口。

### 阶段三：调查与影响评估

- **查明原因**：技术原因（漏洞/攻击）或管理原因（内部人员/操作失误）；
- **评估影响**：受影响数据范围、个人数量、潜在危害；
- **事件定级**：依据分级标准确定事件等级。

### 阶段四：恢复与改进

- **系统恢复**：在确保安全的前提下恢复服务；
- **加固改进**：修复缺陷、加强防护、完善制度；
- **总结复盘**：编写事件总结报告，更新应急预案。

### 阶段五：持续改进

- 将事件经验纳入安全管理制度；
- 定期开展应急演练；
- 完善监测预警能力。

## 四、法定报告义务履行要点

### 4.1 向主管部门报告

| 事件类型 | 报告对象 | 法规依据 | 时限 |
|---------|---------|---------|------|
| 网络安全事件 | 公安机关（网安部门）/行业主管部门 | 网安法第25条 | 立即 |
| 数据安全事件 | 有关主管部门 | 数安法第29条 | 立即/按规定 |
| 个人信息泄露 | 履行个人信息保护职责的部门（网信办等） | 个保法第57条 | 立即 |
| CIIO网络安全事件 | 保护工作部门/公安机关 | 关键信息基础设施保护条例 | 立即 |

### 4.2 向用户/个人通知

个人信息泄露/篡改/丢失时，须向受影响个人通知，内容包括（个保法第57条）：
1. **信息种类、原因和可能造成的危害**；
2. **补救措施**和个人可以采取的**减轻危害的措施**；
3. **联系方式**。

> 通知方式：可通过站内信、短信、邮件、公告等有效方式通知；无法逐一通知的，可采取公告方式。

### 4.3 报告与时限
- 法律法规多用"**立即**"表述，实务中应在合理最短时间内（通常事件确认后数小时内）报告；
- 后续按要求提交书面事件报告。

## 四、应急响应流程

### 4.1 事件发现与报告（0-1小时）
1. 发现事件后立即报告应急总指挥；
2. 应急总指挥根据初步信息判定事件等级；
3. 法务合规组启动报告程序（向主管部门）；
4. 技术处置组启动初步遏制。

### 4.2 事件遏制与根除（1-24小时）
1. 隔离受影响系统，阻断泄露渠道；
2. 保全现场证据（日志/镜像/内存）；
3. 清除威胁源，修复漏洞。

### 4.3 调查与评估（24-72小时）
1. 查明事件原因与技术细节；
2. 评估受影响数据范围与个人数量；
3. 确认事件等级（必要时调整）；
4. 对外沟通组启动用户通知。

### 4.4 恢复与改进（72小时后）
1. 安全恢复系统服务；
2. 编写事件总结报告；
3. 落实改进措施；
4. 更新应急预案。

## 八、应急响应常见问题

| 问题 | 正确做法 |
|------|---------|
| 事件未及时报告 | 法律要求"立即"报告，拖延将加重责任 |
| 仅技术处置未履行通知义务 | 须同时履行向主管部门报告+向用户通知 |
| 未保全证据导致无法溯源 | 第一时间保全日志/镜像/内存等证据 |
| 预案停留在纸面无演练 | 关键信息基础设施运营者须定期演练（网安法第51条） |
| 事后未总结改进 | 每次事件都应复盘总结，完善预案和制度 |

## 九、违规后果

| 违规情形 | 法律后果 | 依据 |
|---------|---------|------|
| 未立即采取处置/补救措施 | 责令改正、警告、罚款 | 数安法第45条 |
| 未按规定告知用户/报告主管部门 | 责令改正、警告、罚款，情节严重可责令停业 | 数安法第45条 |
| 未制定应急预案 | 责令限期改正、警告 | 网安法第59条 |
| 个人信息泄露未通知 | 责令改正、警告、罚款 | 个保法第66条 |
| CIIO未定期演练 | 责令改正、警告、罚款 | 网安法第59条 |
