# 知识产权官文自动归档系统 — 用户参考文档

## 项目背景

在企业知识产权管理中，专利、商标、软件著作权等各类官文 PDF 文件数量庞大、格式各异，人工分类归档耗时费力且容易出错。本系统旨在实现知识产权官文 PDF 的自动化归档处理，通过智能识别文件类型、提取关键字段、规范化命名、组织化存储，大幅提升知识产权文件管理的效率和准确性。

## 系统功能

### 核心功能

1. **智能 PDF 解析**：自动识别专利、商标、软著三大类共八种文件子类型，从 PDF 首页文本中提取申请号、通知书名称、权利人等关键字段
2. **规范化文件命名**：根据文件类型和提取字段，按统一命名规则自动重命名，便于检索和管理
3. **组织化目录存储**：按知识产权类型、权利人、法律状态等维度自动建立多级目录结构
4. **法律状态自动判定**：根据同一知识产权的多份官文，综合判定当前法律状态、状态变更历史、当前权利人
5. **汇总报表生成**：自动生成专利、商标、软著三类汇总报表，每个知识产权仅保留一条最新状态记录
6. **幂等性保证**：重复运行不会产生重复记录，已处理的文件自动跳过

### 支持的文件类型

| 主类型 | 子类型 | 说明 |
|--------|--------|------|
| 专利文件 | 专利通知书 | 各类审查通知书、决定书等（20+种） |
| 专利文件 | 专利证书 | 发明/实用新型/外观设计专利证书 |
| 专利文件 | 专利登记簿副本 | 专利登记簿摘录文件 |
| 商标文件 | 商标通知书 | 各类商标审查通知书（13种） |
| 商标文件 | 商标注册证 | 商标注册证书 |
| 商标文件 | 商标注册申请书 | 商标注册申请文件 |
| 软著文件 | 软著受理通知书 | 计算机软件著作权受理通知书 |
| 软著文件 | 软著证书 | 计算机软件著作权登记证书 |

## 使用方法

### 环境要求

- **Python**：3.10 或更高版本
- **PDF 解析库**（至少安装一个）：
  - `pdfplumber`（推荐，对中文 PDF 文本提取效果最佳）
  - `PyMuPDF`（即 `fitz`，备选引擎）
  - `PyPDF2`（备选引擎）

安装依赖：

```bash
pip install pdfplumber pymupdf PyPDF2
```

### 运行方式

#### 方式一：命令行运行（推荐）

```bash
python -m scripts.run_archive --input <PDF文件目录> [--output <输出目录>]
```

**参数说明：**

| 参数 | 必选 | 说明 |
|------|------|------|
| `--input` | 是 | 待处理的 PDF 文件所在目录，脚本会递归扫描该目录下所有 `.pdf` 文件 |
| `--output` | 否 | 输出根目录。若不指定，自动在输入目录的父目录下创建 `ip_archives` 文件夹 |

**示例：**

```bash
# 处理 D:\patents 目录下的所有 PDF，输出到默认位置
python -m scripts.run_archive --input D:\patents

# 指定输出目录
python -m scripts.run_archive --input D:\patents --output D:\archived
```

#### 方式二：作为模块运行

```bash
python -m scripts
```

此方式使用默认配置（当前工作目录作为根路径，`temp-in` 子目录作为输入目录）。

### 运行流程

系统按顺序执行三个核心脚本：

1. **脚本1（扫描处理）**：扫描输入目录中的所有 PDF 文件，逐文件执行解析→幂等性检查→复制归档→写入 CSV→记录日志
2. **脚本2（路径同步）**：根据标识号、法律状态、当前权利人等信息，将归档文件重新组织到更清晰的目录结构中
3. **脚本3（报表生成）**：基于归档 CSV 数据生成汇总报表

任一脚本异常将中断后续脚本执行。

## 输出目录结构

```
<输出目录的父目录>/
├── <输入文件夹>/          ← 原始输入目录（处理完成后 PDF 文件被移走）
├── <输出目录>/            ← 默认 ip_archives
│   ├── archives/          # 归档的 PDF 文件
│   │   ├── 专利/          # 专利类文件
│   │   │   └── <权利人>/  # 第一级：按当前权利人分组
│   │   │       └── <法律状态>/  # 第二级：按法律状态分组
│   │   │           └── <专利号>-<专利类型>-<法律状态>-<当前权利人>/  # 第三级
│   │   ├── 商标/          # 商标类文件
│   │   │   └── <标识号>-<商标类别>-<法律状态>-<当前权利人>/
│   │   └── 软著/          # 软著类文件
│   │       └── <权利人>/  # 第一级：按当前权利人分组
│   │           └── <标识号>-<法律状态>-<当前权利人>/  # 第二级
│   ├── csv/               # CSV 数据文件
│   │   ├── patent_files_archive.csv      # 专利归档明细（每份官文一条记录）
│   │   ├── patent_report.csv             # 专利汇总报表（每个专利一条记录）
│   │   ├── trademark_files_archive.csv   # 商标归档明细
│   │   ├── trademark_report.csv          # 商标汇总报表
│   │   ├── software_files_archive.csv    # 软著归档明细
│   │   └── software_report.csv           # 软著汇总报表
│   └── logs/              # 日志文件
│       ├── <timestamp>system.log  # 系统运行日志（DEBUG 级别）
│       └── <timestamp>.json       # 每次处理的 JSON 详细日志
└── failed/                # 处理失败的 PDF 文件
```

## PDF 文件重命名规范

系统在归档时会自动根据 PDF 内容识别文件类型，并按照标准命名规则对文件进行重命名。各组成部分之间以下划线 `_` 连接，多个权利人之间以 `&` 连接。

### 一、专利类文件

#### 1. 专利通知书

**命名格式：** `{专利号}_{发文日期缩写}_{专利通知书名称}_{专利权人}.pdf`

**命名示例：** `CN202010123456.1_20231215_授予发明专利权通知书_华为技术有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 专利号 | 专利申请号，统一添加 CN 前缀，格式为 CN+12位数字+点+校验位 | 从 PDF 中提取 ZL/CN/纯数字格式的专利号，统一加 CN 前缀 |
| 发文日期缩写 | 发文序号前8位对应的日期，紧凑格式（如 20231215） | 从16位发文序号前8位解析 |
| 专利通知书名称 | 通知书的具体名称 | 从 PDF 中匹配到的通知书名称，若匹配到多个则以 `&` 连接 |
| 专利权人 | 专利权人名称 | 从"专利权人："字段提取；若为受理通知书则从"申请人："字段提取 |

**可识别的专利通知书名称及对应法律状态：**

| 通知书名称 | 对应法律状态 |
|------------|-------------|
| 专利申请受理通知书 | 受理 |
| 发明专利申请公布通知书 | 受理 |
| 发明专利申请初步审查合格通知书 | 受理 |
| 收费减缴审批通知书 | （不改变状态） |
| 发明专利申请进入实质审查阶段通知书 | 实审 |
| 第N次审查意见通知书 | 实审 |
| 补正通知书 | 实审 |
| 驳回决定 | 驳回 |
| 复审决定书 | 复审 |
| 复审通知书 | 复审 |
| 复审请求受理通知书 | 复审 |
| 授予实用新型专利权通知书 | 办登 |
| 授予发明专利权通知书 | 办登 |
| 授予外观设计专利权通知书 | 办登 |
| 办理登记手续通知书 | 办登 |
| 手续合格通知书 | （不改变状态） |
| 恢复权利请求审批通知书 | （不改变状态） |
| 专利权终止通知书 | 失效 |
| 视为撤回通知书 | 撤回 |
| 视为放弃取得专利权通知书 | 撤回 |
| 撤回专利申请手续合格通知书 | 撤回 |

#### 2. 专利证书

**命名格式：** `{专利号}_{授权公告日缩写}_{专利证书名称}_{授权公告号}_{专利权人}.pdf`

**命名示例：** `CN202010123456.1_20231215_发明专利证书_CN109876543A_华为技术有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 专利号 | 专利申请号，含 CN 前缀 | 同专利通知书 |
| 授权公告日缩写 | 授权公告日期的紧凑格式 | 从"授权公告日："字段提取后压缩，如"2023年12月15日"→"20231215" |
| 专利证书名称 | 证书的具体名称 | 匹配"发明专利证书"/"实用新型专利证书"/"外观设计专利证书" |
| 授权公告号 | 授权公告号，含 CN 前缀 | 从"授权公告号："字段提取，自动补 CN 前缀 |
| 专利权人 | 专利权人名称 | 从"专利权人："到"地址："之间的文本提取 |

#### 3. 专利登记簿副本

**命名格式：** `{专利号}_{发文日期缩写}_登记簿副本_{专利权人}.pdf`

**命名示例：** `CN202010123456.1_20240115_登记簿副本_华为技术有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 专利号 | 专利申请号，含 CN 前缀 | 同专利通知书 |
| 发文日期缩写 | 国家知识产权局发文日期的紧凑格式 | 从"国家知识产权局：YYYY年MM月DD日"提取后压缩 |
| 登记簿副本 | 固定字面值 | 固定为"登记簿副本"，不从 PDF 提取 |
| 专利权人 | 专利权人名称 | 从"专利权人："到"专利权人地址："之间的文本提取 |

### 二、商标类文件

#### 1. 商标通知书

**命名格式：** `{商标申请号}_{商标通知书名称}_{商标申请人}.pdf`

**命名示例：** `75012345_商标注册申请受理通知书_腾讯科技（深圳）有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 商标申请号 | 商标申请号，7-8位纯数字 | 从"申请号："字段提取；若无法提取则从"商标："+数字或纯数字匹配 |
| 商标通知书名称 | 通知书的具体名称 | 从 PDF 中匹配到的商标通知书类型名称 |
| 商标申请人 | 申请人名称 | 从"申请人："字段提取，过滤长度≤2的短文本避免误匹配 |

**各商标通知书类型提取的字段及法律状态：**

| 通知书名称 | 提取字段 | 对应法律状态 |
|------------|---------|-------------|
| 商标注册申请受理通知书 | 商标申请号、商标通知书名称、商标申请人、商标申请日期、商标申请类别、发文编号 | 受理 |
| 商标驳回复审决定书 | 商标申请号、商标通知书名称、商标申请人、商标复审委托代理人 | 复审决定 |
| 商标注册申请缴费通知书 | 商标申请号、商标通知书名称、商标申请人、发文编号 | 受理 |
| 商标驳回通知书 | 商标申请号、商标通知书名称、商标申请人、发文编号 | 驳回 |
| 商标部分驳回通知书 | 商标申请号、商标通知书名称、商标申请人、发文编号 | 部分驳回 |
| 商标注册申请初步审定公告通知书 | 商标申请号、商标通知书名称、商标申请人、发文编号 | 初审公告 |
| 商标评审申请受理通知书 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 商标评审案件补正通知书 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 商标续展注册申请受理通知书 | 商标申请号、商标通知书名称、商标申请人 | 续展 |
| 注册商标续展申请受理通知书 | 商标申请号、商标通知书名称、商标申请人 | 续展 |
| 商标使用许可合同备案通知书 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 提供注册商标使用证据通知书 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 商标续展注册证明 | 商标申请号、商标通知书名称、商标申请人 | 续展 |
| 商标变更核准证明 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 商标转让核准证明 | 商标申请号、商标通知书名称、商标申请人 | （不改变状态） |
| 商标变更申请补正通知书 | 商标申请号、商标通知书名称、商标申请人、发文编号、变更申请号、变更事项 | （不改变状态） |

**发文编号提取与验证规则：**

| 通知书名称 | 发文编号格式 | 示例 |
|------------|-------------|------|
| 商标注册申请受理通知书 | TMZC+商标申请号+ZCSL+流水号 | TMZC73055497ZCSL01 |
| 商标注册申请缴费通知书 | TMZC+商标申请号+JFTZ+流水号 | TMZC73055497JFTZ01 |
| 商标部分驳回通知书 | TMZC+商标申请号+BFBH+流水号 | TMZC73055497BFBH01 |
| 商标注册申请初步审定公告通知书 | TMZC+商标申请号+CSGG | TMZC73055497CSGG |
| 商标注册申请初步审定公告通知书（驳回后复审成功） | BHFS+复审流水号+CSGG+公告流水号 | BHFS20240000151499CSGG01 |
| 商标驳回通知书 | TMZC+商标申请号+BHTZ+流水号 | TMZC73051073BHTZ01 |
| 商标变更申请补正通知书 | TMBG+变更申请号+BGBZ+补正流水号 | TMBG20240001568099BGBZ01 |

系统会对提取的发文编号进行格式验证，确保符合各通知书类型的特定规则。验证失败时会在日志中记录警告信息，但不影响归档处理。

**BHFS格式说明：** 对于驳回后复审成功的商标，其《商标注册申请初步审定公告通知书》的发文编号采用"BHFS+复审流水号+CSGG+公告流水号"格式，与常规的TMZC格式不同。系统优先匹配TMZC格式，未匹配到时再尝试BHFS格式。

#### 2. 商标注册证

**命名格式：** `{注册号}_商标注册证_{注册类别}_{注册日期}_{注册人}.pdf`

**命名示例：** `55012345_商标注册证_第6类_2023年06月15日_腾讯科技（深圳）有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 注册号 | 商标注册号，7-8位纯数字 | 从"第 X 号"格式提取；若失败则匹配7-8位纯数字 |
| 商标注册证 | 固定字面值 | 固定为"商标注册证"，不从 PDF 提取 |
| 注册类别 | 商标注册类别 | 从"国际分类：X"格式提取并格式化为"第X类" |
| 注册日期 | 商标注册日期 | 从"注册日期："到"有效期"之间的文本提取 |
| 注册人 | 注册人名称 | 从"注册人："到"注册人地址："之间的文本提取 |

#### 3. 商标注册申请书

**命名格式：** `{代理文号}_商标注册申请书_{申请人}.pdf`

**命名示例：** `TMZC202301012345_商标注册申请书_阿里巴巴集团控股有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 代理文号 | 代理机构文号 | 从"代理文号："字段提取 |
| 商标注册申请书 | 固定字面值 | 固定为"商标注册申请书"，不从 PDF 提取 |
| 申请人 | 申请人名称（中文） | 从"申请人名称（中文）："字段提取 |

### 三、软著类文件

#### 1. 软著受理通知书

**命名格式：** `{软件名称}_软著受理通知书_{受理日期}_{申请人}.pdf`

**命名示例：** `智能数据分析平台V2.0_软著受理通知书_2024年01月24日_北京科技有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 软件名称 | 软件的全称 | 从"软件名称："到"登记类型："之间的文本提取 |
| 软著受理通知书 | 固定字面值 | 固定为"软著受理通知书"，不从 PDF 提取 |
| 受理日期 | 受理通知书的发文日期 | 从 PDF 文本中提取最后一个日期，格式统一为"YYYY年MM月DD日" |
| 申请人 | 申请人名称 | 从"申请人："到"代理人："之间的文本提取 |

**额外提取字段：**

| 字段 | 提取规则 | 示例 |
|------|---------|------|
| 受理号 | 匹配"YYYYR11SXXXXXXX"格式 | "2023R11S1234567" |
| 软著代理 | 从"代理人："后提取代理机构名称 | "代理人：江苏中正知识产权有限公司" → "江苏中正知识产权有限公司" |

#### 2. 软著证书

**命名格式：** `{软件名称}_软著证书_{证书日期}_{著作权人}.pdf`

**命名示例：** `智能数据分析平台V2.0_软著证书_2025年11月04日_北京科技有限公司.pdf`

| 组成部分 | 含义 | 来源 |
|----------|------|------|
| 软件名称 | 软件的全称 | 从"软件名称："到"著作权人"或"权利取得方式"之间的文本提取 |
| 软著证书 | 固定字面值 | 固定为"软著证书"，不从 PDF 提取 |
| 证书日期 | 证书的发文日期 | 从 PDF 文本中提取最后一个日期，格式统一为"YYYY年MM月DD日" |
| 著作权人 | 著作权人名称 | 从"著作权人："到"权利取得方式"或"权利范围"或"登记号"之间的文本提取 |

**额外提取字段：**

| 字段 | 提取规则 | 示例 |
|------|---------|------|
| 证书号 | 匹配"软著登字第XXXXXXX号"格式 | "软著登字第1234567号" |
| 登记号 | 匹配"YYYYYSRXXXXXXX"格式 | "2023SR1234567" |
| 权利取得方式 | 从"权利取得方式："后提取 | "权利取得方式：原始取得" → "原始取得" |

### 四、命名规范注意事项

1. **字段缺失处理**：若某个字段在 PDF 中无法提取到（返回空字符串），该字段将不会出现在文件名中，其余字段仍按顺序以下划线连接。若所有字段值均为空，则无法生成文件名，该文件会被移至 `failed/` 目录。

2. **多权利人连接**：当存在多个权利人/申请人时，以 `&` 符号连接，如 `公司A&公司B`。

3. **非法字符替换**：文件名中的非法字符（`< > : " / \ | ? *`）会被自动替换为下划线 `_`，换行符和制表符会被移除，连续空格会合并为单个空格。

4. **文件名冲突处理**：若目标路径已存在同名文件，系统会自动在文件名后追加 `_1`、`_2` 等序号后缀，避免覆盖已有文件。

5. **日期紧凑格式**：命名中使用的日期为紧凑数字格式（去除"年月日"文字），如"2023年12月15日"→"20231215"，仅用于专利通知书的发文日期、专利证书的授权公告日和专利登记簿副本的发文日期。

6. **固定字面值**：部分命名组成部分为固定字面值（如专利登记簿副本中的"登记簿副本"、商标注册申请书中的"商标注册申请书"），这些值不从 PDF 内容中提取，而是由系统根据文件类型自动填充。

7. **仅支持文本型 PDF**：系统依赖从 PDF 中提取文本进行类型识别和字段解析，扫描件/图像型 PDF（无可提取文本）无法处理，会被移至 `failed/` 目录。

8. **专利号格式统一**：无论 PDF 中出现的专利号格式是 `ZL202010123456.1`、`202010123456.1` 还是 `CN202010123456.1`，重命名时统一使用 `CN` 前缀格式。

## 法律状态判定规则

### 专利法律状态判定

专利法律状态采用四级优先级判定策略：

1. **第一优先级 — 专利证书**：若存在专利证书，则根据是否同时存在终止通知书判定为"授权"或"失效"
2. **第二优先级 — 通知书映射**：按优先级从高到低遍历所有通知书，取优先级最高的法律状态
3. **第三优先级 — 登记簿副本**：从专利登记簿副本中读取法律状态（"专利权有效"→"授权"，"专利权终止"→"失效"）
4. **第四优先级 — 手续合格通知书**：若仅有手续合格通知书，则判定为"受理"

**专利法律状态优先级排序：**

受理(1) → 实审(2) → 驳回(3) → 复审(4) → 办登(5) → 授权(6) → 失效(7) → 撤回(8)

**专利权人变更记录计算：**
- 从"手续合格通知书"中提取专利权人变更信息
- 仅授权公告日之后的变更才更新当前权利人
- 变更记录以"→"连接，如"公司A→公司B→公司C"

### 商标法律状态判定

商标法律状态采用三级优先级判定策略：

1. **第一优先级 — 注册证**：若存在商标注册证，则判定为"已注册"
2. **第二优先级 — 初审公告**：若存在初步审定公告通知书，则判定为"初审公告"
3. **第三优先级 — 最新有效映射**：按处理时间降序遍历，取第一条有效通知书的状态映射值

### 软著法律状态判定

软著法律状态采用两级优先级判定策略：

1. **第一优先级 — 证书**：若存在软著证书，则判定为"登记下证"
2. **第二优先级 — 最新有效映射**：按处理时间降序遍历，取第一条有效通知书的状态映射值

### 状态变更历史

系统自动计算每个知识产权的状态变更历史，以"→"连接，连续相同状态会自动去重。例如：`受理→实审→授权`

## 标识号计算规则

标识号用于将同一知识产权的多份官文关联在一起，不同类型的计算规则如下：

| 知识产权类型 | 标识号计算规则 | 说明 |
|-------------|---------------|------|
| 专利 | 申请号 | 如 CN202010123456.1 |
| 商标 | 申请号 或 注册号 | 优先使用申请号，若为空则使用注册号 |
| 软著（受理通知书） | 受理号 | 如 2023R11S1234567 |
| 软著（证书） | 登记号 | 如 2023SR1234567；系统会尝试通过"软件名称"在全部记录中查找对应的受理号，以确保证书与受理通知书使用相同的标识号 |

## 幂等性判断规则

系统在处理 PDF 文件时会进行幂等性检查，避免重复归档。不同文件类型的去重键如下：

| 文件类型 | 去重键 |
|---------|--------|
| 专利通知书 | 申请号 + 通知书名称 + 发文序号 |
| 专利证书 | 申请号 + 子类型 |
| 专利登记簿副本 | 申请号 + 子类型 + 发文日期 |
| 商标通知书 | 申请号 + 通知书名称 + 发文编号 |
| 商标注册证 | 注册号 + 子类型 |
| 商标注册申请书 | 代理文号 + 子类型 |
| 软著受理通知书 | 受理号 + 子类型 |
| 软著证书 | 登记号 + 子类型 |

**重复文件处理逻辑：**
- 若归档文件仍存在于目标路径：删除重复的源文件，跳过处理
- 若归档文件已缺失：重新复制源文件到归档目录，更新 CSV 中的路径记录

## 注意事项

### PDF 文件要求

1. **仅支持文本型 PDF**：系统通过提取 PDF 文本进行类型识别和字段解析，扫描件/图像型 PDF（无可提取文本）无法处理，会被移至 `failed/` 目录
2. **PDF 格式需符合官文标准格式**：正则匹配依赖官文的标准排版格式，非标准格式的 PDF 可能导致字段提取失败
3. **首页需包含关键信息**：系统仅读取 PDF 首页文本，关键信息需在首页中呈现

### 运行注意

1. **三个脚本按顺序执行**：任一脚本异常将中断后续脚本执行
2. **单文件异常不影响整体**：脚本1中单个文件处理失败不会中断其他文件的处理
3. **处理完成后源文件会被删除**：成功归档的 PDF 文件会从输入目录中删除，失败的文件移至 `failed/` 目录
4. **CSV 编码为 UTF-8-BOM**：所有 CSV 文件使用 UTF-8-BOM 编码，确保 Excel 打开时中文不乱码
5. **日志保留**：每次运行都会生成系统日志和 JSON 处理日志，不会自动清理历史日志

### 数据安全

1. **幂等性保证**：重复运行不会产生重复记录
2. **文件名冲突保护**：目标路径已存在同名文件时自动追加序号，不会覆盖
3. **CSV 列头校验**：若 CSV 文件的列头与预期不符，会自动备份并修复
4. **只读文件处理**：Windows 系统上只读属性的文件也能正常处理（自动移除只读属性）

### 性能说明

1. **全量覆写策略**：CSV 写操作采用全量覆写（读取→修改→写入），适用于中小规模数据（数千条以内）
2. **法律状态批量更新**：所有文件处理完成后统一执行法律状态更新，减少 CSV 读写次数
3. **PDF 引擎降级**：按 pdfplumber → PyMuPDF → PyPDF2 顺序尝试，优先使用效果最佳的引擎
