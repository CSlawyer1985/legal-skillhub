# 金标准库（references/golden/）

> 本目录是「模式三 · 知识回流」沉淀下来的**信任主源**。
> - 联盟条目 `⏳ 待人工核对`：候选，引用时须标注「待核对」，**不算金标准**。
> - 晋升条目 `✅ 金标准`：**人工确认**后的条款，可零摩擦直接引用（agent 优先 `lookup` 调用，不重新抓取、不弹 ⚠️）。
>
> **金标准 ≠ 永久正确**：须由 `scripts/refresh_golden.py` 定时核验官网是否更新/废止（见「模式五」）。

## 写入规则
- 由 `scripts/golden.py` 写入，agent 不直接手改。
- 去重键：`(规范编号, 条款号, 版本)`。同键已存在则跳过，不重复。
- 来源域须为白名单（gov.cn / openstd / mohurd / mem 等），否则拒绝写入。
- 每条记录格式：
```
### <规范编号> 第 <条款号> 条
- 原文：（逐字，待人工核对）
- 来源：<权威页 URL>
- 抓取日期：<YYYY-MM-DD>
- 版本：<如 2023-06-01 施行>
- 核对状态：⏳ 待人工核对
```
- 绝不覆盖已存在的 ✅ 条目；新抓只作为候选追加。

## 自动 / 手动开关
- 默认 `manual`：agent 先把发现呈现用户，征得确认后再写。
- 切 `auto`：自动写回为待核对，并显式告知用户「已缓存 X 条款新版，待你核对」。
- 开关在调用 `golden.py` 时以 `--auto` 体现，或由 SKILL.md 的配置决定。

## 晋升为金标准（人工确认）
- 用户核对某 ⏳ 条目无误后，调 `python scripts/golden.py confirm --std <规范> --clause <条款>`。
- 该条 `⏳ 待人工核对` 变为 `✅ 金标准（YYYY-MM-DD 人工核对）`，此后作为本地基准。
- **机器永不自动把 ⏳ 标成 ✅**——最终裁定权永远在人手里（法律条文错一字含义全变）。

## 直接调用（lookup）
- 用户再问同一 (规范, 条款) 时，agent **先**调 `python scripts/golden.py lookup --std <规范> --clause <条款>`。
- 命中 ✅ → 直接输出原文 + 出处小字，**不重新抓取、不弹 ⚠️**，保证绝对准确。
- 未命中 / 非 ✅ → 回退「模式一 / 模式二」，新条款首次照常标 ⚠️（仅首次有摩擦）。

## 文件组织
- 每个规范一个文件：`<规范编号>.md`（空格转义为下划线，如 `GB_55037-2022.md`）。
- 已晋升 `✅` 的条目作为本地基准，输出优先级高于在线 ⏳ 候选。
- **`seed_hf_sft.md`（社区校验问答参考）**：由 `scripts/import_hf_sft.py` 从 HuggingFace 数据集 `sdzjoy/fire-safety-sft-dataset`（Apache-2.0）抽取，含 Q&A 对 + 元数据索引，每条 `⏳ 待官方核对`。它**不是**本信任主源的一部分、不计入 ✅ 金标准；其块标记 `### [HF-SFT]` 与条款键 `### <规范> 第 <条款> 条` 不冲突，故 `refresh_golden.py` 不会误将其当权威条款刷新。仅用于 reconcile 交叉核对 / 启发式参考，引用前须经官方源核实。
- **`penalty_cases.md`（罚则 + 典型案例参考索引）**：人工基于公开《消防法》及主要部门规章 + 公开报道案例整理，全部 `⏳ 待核对`，**非 ✅ 金标准**、不计入信任主源；其块标记 `### 一/二/三` 与条款键不冲突，`refresh_golden.py` 不刷新。用于「罚多少 / 有什么后果 / 有无先例」类查询，引用前经模式一复核，案例以官方处罚决定书/裁判文书为准。
- **`feedback.log`（用户纠错/评分回流 · 运行数据）**：由 `scripts/feedback.py` 写入的 JSONL（模式七），是**运行时生成的产物**，**不随 skill 仓库分发**（本地 git 场景下应加入 .gitignore 忽略；上传 SkillHub 时本文件尚未生成，无需处理），经复核队列反哺 golden。

## 废止清理
当联网检索 / 定时刷新发现某条款被官方标注「废止」时，`golden.py abolish` 会把该条从本目录**移入** `../archive/`（格式见 archive/README.md），不再作为有效依据输出。
