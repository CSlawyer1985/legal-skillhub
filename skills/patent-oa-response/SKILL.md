# 专利审查意见答复技能

## 一、概述

本技能将"答复专利审查意见通知书"的方法论沉淀为结构化、可复用的标准流程，使智能体能够针对审查员指出的各类缺陷（新颖性、创造性、清楚性、权利要求独立性、单一性、修改超范围等），产出逻辑严密、针对性强、说理充分、策略灵活的意见陈述书或权利要求修改方案。

核心理念：以《专利审查指南》为尺、以事实（说明书与对比文件原文）为据、以论证链为骨、以附图为证、以整体性原则为纲，逐条回应用户关切，杜绝泛泛而谈与自相矛盾。

## 二、适用场景

- 收到**第一次审查意见通知书**或**第N次审查意见通知书**，需要整体答复。
- 审查员引用一篇或多篇对比文件，认定权利要求**不具备新颖性**或**不具备创造性**（"三步法"评述）。
- 审查员指出权利要求**不清楚**、**得不到说明书支持**、**缺少必要技术特征**、**多项引多项**、**不具有单一性**、**修改超范围**、**公开不充分**等形式/实质缺陷。
- 需要撰写**意见陈述书**，或在答复同时**修改权利要求书/说明书**。
- 需要检索、学习在先**无效决定、复审决定**等先例以支撑论证。

不适用（另有专门技能）：专利新申请撰写、PCT 国际阶段答复。**针对驳回决定请求复审（复审请求书撰写、复审阶段权利要求修改）请调用 `patent-reexamination` 技能**——其复用本技能的创造性论证方法论（论证链模板、审查指南条款速查），并叠加复审程序、前置审查策略、细则第66条修改纪律与复审请求书结构。**以第三人身份无效他人已授权专利（方向相反、多理由组合、证据链策略）请调用 `patent-invalidation` 技能**。

## 三、核心理念

1. **逻辑严密**：每一个反驳观点都须形成完整论证链（前提→事实→法条→结论），环环相扣，不可跳跃、不可自相矛盾。
2. **针对性强**：逐条回应审查意见，不回避、不转移、不泛泛而谈；审查员说哪一条，就答哪一条，做到"件件有回音"。
3. **说理充分**：每个主张都要有证据支撑——说明书具体段落、对比文件原文与标号、审查指南具体条款（含条款号）。"我认为"不够，"审查指南第X条规定……且本案事实是……故……"才合格。
4. **策略灵活**：区分"必须争辩"与"可让步修改"。能修改权利要求克服缺陷时，优先修改（成本更低、授权更快）；修改不能克服或会严重限缩保护范围时，才正面争辩。避免全盘否认导致程序空转。
5. **整体性原则**：创造性评述须从发明整体出发，考察特征之间的协同关系与整体技术效果；坚决反对割裂技术特征、孤立评价、事后诸葛亮（从结果反推发明过程）。
6. **程序合规意识**：审查员的认定同样须受《专利审查指南》约束。凡审查员偏离指南（如选错最接近现有技术、作用不同却认定有启示、随意认定"常规技术手段"），均须明确指出并引用指南条款驳斥。

## 四、关键方法论

### 4.1 逐条拆解审查意见（结构化清单）
将审查意见通知书拆解为结构化清单，每条记录：①涉及的权利要求号；②驳回理由（新颖性/创造性/清楚性/……）；③引用的证据（对比文件编号+具体段落/标号）；④审查员的认定逻辑与关键表述（原文摘录）。此清单是后续所有工作的索引。

### 4.2 区分"形式问题"与"实质问题"
- **形式问题**（如标号不一致、引用基础错误、文字笔误）：修正成本低，通常配合修改直接解决。
- **实质问题**（如创造性、新颖性、不支持）：需正面说理或实质性修改。先识别类型，再决定走"修改路线"还是"争辩路线"。

### 4.3 合理引用《专利审查指南》
建立审查指南条款速查表（见 `references/审查指南条款速查.md`），高频引用包括：
- 最接近现有技术的选择标准（技术领域、所要解决技术问题、技术效果、公开特征最多且最接近）；
- 区别特征与"三步法"的适用；
- 技术启示的判断（对比文件须"公开且作用相同"才能给出启示）；
- 公知常识/常规技术手段的认定与举证责任（审查员主张公知常识应举证或说明理由）；
- 创造性评述须从整体考量、禁止事后诸葛亮；
- 权利要求清楚性、支持、必要技术特征、单一性的判断标准。

### 4.4 构建反驳论证链
对每条实质缺陷，按固定句式组织：
> **前提**：审查指南规定……（条款号）
> **事实**：本案中，本申请……（说明书段落/标号）；对比文件……（原文/标号）
> **推理**：对比文件未公开/作用不同/属于整体协同特征，故审查员认定不成立
> **结论**：权利要求N具备创造性/应撤销该认定

### 4.5 附图印证（提升直观性）
提取申请文件与对比文件的附图，在论证处**左右并列**放置，并辅以"图示对比小结"。附图比文字更具确定性，尤其对结构/拓扑差异（如"冷头穿越波纹管"vs"框架悬挂"）。提取时注意按文档真实嵌入顺序核对图号（见 `scripts/extract_figs.py`）。

### 4.6 知识库与先例学习
答复前检索用户知识库中的"专利无效决定""复审决定"等先例，提炼关于最接近现有技术选择、区别特征认定、常规技术手段、整体性原则、事后诸葛亮的认定规则与典型判例，作为论证的权威支撑。

### 4.7 策略性修改权利要求
若修改能克服缺陷且不过度限缩，优先修改并说明修改不超范围（依据原权利要求/说明书）；修改后重新评估其余权利要求的依存关系。

## 五、标准工作流程（模块化、可扩展）

> 流程按"模块"组织。创造性类答复执行模块 M1–M9；新颖性/清楚性等其他类型选择性执行相应模块（见 §六 类型路由）。每个模块独立、可单独调用。

**M0 接收与通读**
- 读取：审查意见通知书（PDF/Word）、申请文件全文（含权利要求、说明书、附图）、全部对比文件。
- 用 `scripts/extract_figs.py` 或等价方式提取各文件附图备用。
- 建立全案理解：本申请解决的技术问题、核心技术手段、技术效果；各对比文件的技术方案与定位。

**M1 结构化拆解审查意见**
- 输出结构化清单（见 §4.1），作为后续索引。

**M2 选定主攻方向与策略定调**
- 多理由并存时，通常以**创造性**（或新颖性）为主攻；形式问题配合修改。
- 定调：整体争辩 / 修改+争辩 / 仅修改。

**M3 审查意见合规性审查（找审查员偏差/违规）**
- 核查审查员是否违反审查指南：选错最接近现有技术、割裂特征、作用不同却认定有启示、随意认定常规技术手段、事后诸葛亮。逐条列出可能的违规点，作为答复的"破题"抓手。

**M4 构建区别特征对比表（本申请 vs 最接近现有技术）**
- 制作详细技术特征对比表（逐特征：本申请特征→对比文件对应特征→差异→作用）。
- 论证该对比文件不适合作为最接近现有技术（技术领域/问题/效果/公开特征最多且最接近；若无改进基础，则"起点"错误）。

**M5 核查区别特征准确性（防止割裂与忽略协同）**
- 核实审查员归纳的区别特征是否准确；重点回击"将本应协同的多个特征割裂评价""忽略特征间相互作用与整体效果"。

**M6 核查其余对比文件技术特征的实质与作用**
- 对审查员引用的每篇其他对比文件，核实其是否**真实公开**相应特征，且**实际所起作用相同**。作用不同则依法不能给出技术启示——这是最有力的反驳点之一。

**M7 驳斥"常规技术手段"等笼统认定**
- 凡审查员以"常规技术手段/惯用手段/常规设置"否定创造性，须质疑其认定随意、概念不清；论证该特征属于对现有技术做出贡献的特征，并引用审查指南关于公知常识举证/说理的要求。

**M8 整体性原则与事后诸葛亮分析**
- 指出审查员割裂技术特征、忽略协同关系，违反整体判断原则；梳理"事后诸葛亮"情形，提醒从还原发明角度正向理解创造过程，而非从结果反推。
- 重申创造性审查原则，并可视情况强调技术（如关键设备国产化）价值作为辅助论点（注意：产业价值非创造性法定要件，仅作辅助）。

**M9 撰写意见陈述书（模块化、附图印证）**
- 按 `assets/意见陈述书_模板.docx` 的章节骨架组织正文；在 M4/M6/M8 对应论证处嵌入并列附图对比表与"图示对比小结"。
- 论证链须可直接映射到 M1 清单的每一条。

**M10 质量自检（见 §七）**
- 逐条核对自检清单，修正后再交付。

**M11 交付与归档**
- 输出意见陈述书（docx）、修改后权利要求（如适用）、附图比对材料。
- 写入项目工作日志，记录策略与关键论点，供后续轮次累积。

## 六、审查意见类型路由（模块化覆盖）

| 类型 | 启用模块 | 主攻论证 |
|------|----------|----------|
| 创造性 | M1–M10 | 区别特征+技术启示+常规技术手段+整体性（§四、参考 `references/论证链模板.md`） |
| 新颖性 | M1–M3, M9–M10 | 单独对比原则：一篇对比文件单独、完整地公开全部技术特征（含作用/效果），并引用"新颖性单独对比"规则 |
| 清楚性/不支持 | M1–M3, M9–M10 | 结合说明书语境解释术语含义、上下文自洽性；区分"本领域技术人员能理解"与"必须字面展开" |
| 缺少必要技术特征 | M1–M3, M9–M10 | 论证被认定"必要"的特征实为可选/可由其他特征实现，或已隐含于其他特征 |
| 多项引多项 | M1–M3, M9–M10 | 指出引用关系错误，配合修改权利要求引用基础 |
| 单一性 | M1–M3, M9–M10 | 论证存在相同/相应的特定技术特征，或基于检索报告核实 |
| 修改超范围 | M1–M3, M9–M10 | 论证修改依据原权利要求/说明书明确记载或可直接/毫无疑义确定 |

## 七、输入输出规范

**输入**
- 审查意见通知书（PDF/Word，必需）
- 申请文件（权利要求书、说明书、附图，必需）
- 对比文件（专利/文献，必需；引用几篇提供几篇）
- 可选：用户知识库（无效决定/复审决定）、行业教科书/标准（用于支撑公知常识反驳）

**输出**
- `意见陈述书_答复第N次审查意见.docx`（主交付物，含并列附图对比）
- `权利要求书_修改后.docx`（如采用修改路线）
- `附图比对材料/`（提取的对比图，供核验）
- 项目工作日志（策略与关键论点，累积用）

## 八、质量检查节点（答复质量自检）

完成 M9 草稿后，逐条核对（任一不满足须返回修正）：

- [ ] **全覆盖**：M1 清单中每一条审查意见都有针对性回应，无遗漏。
- [ ] **可映射**：每个反驳观点都能在论证链中找到"前提（指南条款）→事实（原文/标号）→推理→结论"。
- [ ] **引用准**：审查指南条款号、对比文件段落与标号、本申请说明书段落均准确无误，可复核。
- [ ] **不矛盾**：修改方案与争辩理由不自相矛盾；修改未超出原申请记载范围。
- [ ] **附图对**：嵌入的附图图号正确（已按文档真实顺序核对），左右对照与文字描述一致。
- [ ] **整体观**：创造性论证未割裂特征、未忽略协同、未事后诸葛亮；已重申整体性原则。
- [ ] **合规性质疑有据**：对审查员的每条偏差/违规指控都附有指南条款与事实依据。
- [ ] **策略自洽**：争辩与修改的组合符合 M2 定调，无过度限缩也无无谓对抗。

## 九、注意事项

1. **不要全盘否认**：策略性让步（修改）往往优于硬争，避免程序空转与授权延迟。
2. **区分"指南规定"与"审查员个人理解"**：审查员偏离指南之处，正是答复的突破口，须点名并引条款。
3. **附图提取须核对图号顺序**：docx 媒体文件名（image1/2/3）不等于图1/2/3，须按 document.xml 真实嵌入顺序定位（见 `scripts/extract_figs.py`）。
4. **作用不同则无启示**：这是创造性反驳的硬核，对比文件须"公开且作用相同"才构成启示，二者缺一不可。
5. **产业价值是辅助而非要件**：国产化/产业价值可增强说服力，但创造性法定判断仍基于技术方案本身，勿本末倒置。
6. **保护修改痕迹**：修改权利要求时保留原文本对照，证明不超范围。
7. **尊重用户把关**：结构/拓扑类结论（尤其附图）建议请用户目检关键标记；存在不确定时主动说明，不臆断。
