# scope-change-controller

法律事项整个生命周期中的范围管理 — 从事项设置时的基线捕获，到进行中的变更控制、范围外（OOS）识别与文档化，以及结案时的回顾。

## 本技能的功能

范围是其他一切引用的基线。状态是对照范围的进展。风险是对范围交付的威胁。预算是范围的价格。当范围未被管理时，每一项其他 LPM 纪律都在对照一个不可靠的目标工作，客户会被意外。

技能按事项复杂度缩放在两个层级运行：

**轻量模式：** 一份范围摘要、一份简单变更日志，以及一项在范围外信号出现时予以标记的常设指令。适用于完整变更控制将不成比例的直截了当事项。

**完整变更控制：** 正式范围登记册、结构化 OOS 评估工作流、带财务和时间线影响的变更通知、用于核销或追加费用对话的 OOS 报告，以及结案时的范围回顾。

**核心设计原则：** 不要要求 LPM 创建记录 — 创建记录并要求 LPM 确认它。在手动模式下，这意味着技能根据提供的输入产出 OOS 条目草稿、客户沟通草稿和范围登记册更新草稿。在 M365 连接模式下，它在往来函件中检测范围信号、带来源证据起草条目，并将其浮现供确认。"记录这个"（15 分钟，不会发生）与"我发现这个了 — 确认还是驳回？"（30 秒，会发生）之间的区别。

## 与 matter-intake-scoping 的关系

这两个技能设计为按顺序工作。matter-intake-scoping 模式 2（快速接案）产出结构化范围摘要 — 纳入项、排除项、假设、约束、里程碑、费用基础 — 这就是 scope-change-controller 在事项存续期间管理的基线。

如果您在没有 matter-intake-scoping 的情况下安装 scope-change-controller，技能会提示您在变更控制开始前建立范围基线。您可以手动提供。

## 输入

- 来自 matter-intake-scoping 的范围摘要（或手动定义的范围基线）
- 包含范围信号的电子邮件、通话记录、往来函件
- 可能构成额外工作的客户请求或指示
- 暗示超出原始参数工作的 WIP 或计费数据

## 产出

- OOS 识别通知（内部）
- 范围变更通知（面向客户）
- 范围登记册（商定范围和变更的实时记录）
- OOS 日志（所有已识别、评估和解决的 OOS 项目记录）
- OOS 报告（供核销理由或追加费用对话的摘要）
- 范围电话议程（用于与客户就范围变更进行结构化对话）
- 范围回顾（事项结案时 — 范围了什么、什么变了、为什么）

## 跨技能交接

- **来自 matter-intake-scoping：** 范围摘要是本技能管理的基线
- **来自 risk-and-issues-manager：** 从决定提取中得到的范围信号；假设被违反
- **来自 status-report-drafter：** 暗示范围问题的预算偏差
- **至 budget-and-fee-manager：** 范围变更已评估 — 需要财务影响分析
- **至 timeline-generator：** 范围变更影响项目时间线
- **至 risk-and-issues-manager：** 新的范围界定假设作为 RAID 日志中的 A 条目记录
- **至 continuous-improvement-engine：** 回顾发现为未来的范围界定校准提供输入
