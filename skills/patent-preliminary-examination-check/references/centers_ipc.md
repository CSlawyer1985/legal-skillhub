## 精确匹配校验逻辑

**算法**：
1. 提取权利要求 1（或每项权利要求）的 IPC 主分类小类（申请人/代理通常已知；若未知，由 LLM 根据技术方案推断候选小类）。
2. 在目标中心的白名单集合中查找该小类：
   - 命中 → 通过「技术领域匹配」。
   - 未命中 → 标记「严重-必改（受理前提）：不在目标保护中心产业领域/IPC 白名单」，附中心名称与白名单来源。
3. 目标中心无内置白名单时，退回到 `centers_rules.md` 的「产业领域」做粗匹配，并提示用户确认。

**校验示例**（假设权利要求主分类小类如下）：

| 候选 IPC | 技术含义 | 北京 | 深圳 | 江苏 | 浙江 | 广东 |
|----------|----------|------|------|------|------|------|
| G06F | AI 数据处理方法 | ✓ 新一代信息技术 | ✓ 互联网 | ✗ | ✓ 新一代信息技术 | ✓ 新一代信息技术 |
| H01M | 动力电池 | ✓ 高端装备制造 | ✓ 新能源 | ✓ 高端装备 | 查绿色低碳清单 | ✗ |
| A61B | 诊断设备 | ✗ | ✓（含于列表） | ✗ | ✓ 生物 | ✓ 生物 |
| C12N | 基因工程菌 | ✗ | ✗ | ✗ | ✓ 生物 | ✓ 生物 |

**结论演示**：
- 若目标中心 = 江苏，权利要求主分类为 G06F → 命中"不在领域"一票否决，应在步骤 2 终止并提示。
- 若目标中心 = 广东，H01M（电池） → 不在新一代信息技术/生物 → 一票否决；但同题若改为 C12N（生物）则通过。
- 上述示例验证：精确匹配可有效区分"同是发明"却分属不同中心受理范围的情形，避免误提交。
