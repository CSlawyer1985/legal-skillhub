# 专利预审自检 Skill

## 概述
本 Skill 面向专利代理师、企业知识产权人员，在向地方知识产权保护中心提交预审申请前，对专利申请文件做自动化合规检查。覆盖准入资格、形式规范、明显实质性缺陷、非正常申请风险四大类问题，定位预审高频驳回点并给出可落地修改建议，辅助提升预审一次性通过率。

**V1.0 范围：发明专利、实用新型专利。外观设计专利预审不在本版范围**，各中心外观预审规则后续单独扩展（知识库中注明各中心是否支持外观设计）。

## 适用场景与触发
- 专利申请文件定稿后、提交预审前的正式质检。
- 代理机构内部案前质量管控，批量排查低级错误。
- 企业申请人自行提交预审前的自助合规检查。
- 预审补正阶段的针对性复核。

触发关键词：专利预审 / 快速预审 / 预审自检 / 预审合规 / 保护中心提交前检查 / 预审不受理排查。

## 前置输入要求
执行前确认以下信息，缺失时主动询问补充：
- **必填**：申请类型（发明 / 实用新型）；目标保护中心（精确到城市/区域）；申请文件全文（权利要求书、说明书含摘要、附图、请求书核心字段）。
- **选填**：申请人备案状态（已备案 / 未备案）；费用减缴备案状态；优先权 / 分案等特殊说明。

## 标准执行工作流
严格按 6 步顺序执行。**步骤 2 命中任一受理前提类（一票否决）问题时，直接高亮并终止深度检查**，仅输出受理前提问题清单与官方规则依据。

### 步骤 1 输入解析与参数初始化
解析申请文件，提取结构化信息：权利要求项数、说明书章节、附图数量、请求书关键字段（发明名称、申请人、发明人、勾选项）。加载目标保护中心规则：从 `references/centers_rules.md` 取产业领域与特殊要求；IPC 精确匹配调用 `scripts/ipc_match.py`（数据见 `references/ipc_whitelist.json`，覆盖全国 80 家中心，含完整/部分清单与置信度）。确认申请类型对应的检查标准，初始化检查清单。

### 步骤 2 准入资格前置校验（受理前提 / 一票否决）
排查直接导致预审不予受理的核心门槛，命中任一项标记为「严重-必改（受理前提）」：
- 技术领域与目标保护中心产业领域 / IPC 白名单匹配性（调用 `scripts/ipc_match.py --center <中心> --ipc <主分类小类>` 精确匹配；返回 `exact_full` / `exact_partial` / `unknown` 三档，`exact_partial` 或 `unknown` 时提示核对官方清单或做产业领域粗匹配）。
- 申请类型排除：PCT 申请、进入中国国家阶段的 PCT、同日双申（专利法第 9 条第 1 款）、分案申请、需保密审查申请（**细则第 8 条**）。
- 申请人备案资格：未备案属于**受理前提**（非文件缺陷），提示先备案；已备案主体与未备案主体共同申请须第一申请人已备案并提交共同研发证明。
- 基础客体排除：明显属于专利法第 5 条、第 25 条的情形。

> 注：备案问题按"受理前提"分级，与"文件类缺陷"区分；未备案不计入可修改缺陷计数。

### 步骤 3 全维度形式合规检查
对请求书、权利要求书、说明书、附图执行全覆盖形式校验：
- 先调用 `scripts/mechanical_checks.py` 完成确定性机械检查（编号连续性、每项权利要求句号数、摘要≤300 字、附图标记双向一致性、发明名称≤25 字、项数比对、勾选项存在性）。
- 再由 LLM 补充语义形式校验：请求书字段一致性、预审专项勾选（发明：请求早日公布 + 请求实质审查 + **放弃主动修改的权利（细则第 57 条）**；实用：放弃主动修改权利）、费用减缴与备案一致性、文件清单匹配、承诺书（申请人 + 代理机构）签署、XML 格式要求。
- 对齐各中心已发布的官方"预审文件自检表"作为检查项来源（如安徽、新乡、厦门），优先采用官方勾选项。

### 步骤 4 明显实质性缺陷初筛
仅排查「明显可判定」的实质缺陷，不做全面新颖性/创造性判断：
- 权利要求清楚性、单一性、必要技术特征初判。
- 说明书公开充分性初步评估（核心方案是否达到本领域技术人员可实现）。
- 授权客体符合性（是否构成技术方案，排除纯商业方法、智力活动规则；专利法第 2 条）。
- **明显创造性可初筛**（部分中心预审审查含明显创造性，如湖北）；全面创造性仍不做。

### 步骤 5 非正常申请风险排查
依据**局令 77 号《规范申请专利行为的规定》第三条 8 类情形**，识别高风险特征，输出预警等级：
- 文本编造/伪造/拼凑痕迹、技术方案合理性。
- 低质量改写、模板化套作（句式模板化、技术细节缺失、AI 生成高风险特征）。
- 技术效果夸大、无数据支撑。
- 技术方案与申请人研发能力 / 主营业务明显不符（局令 77 号第（五）项）。
- 多项申请分散提交规避监管、倒买倒卖 / 虚假变更发明人。

### 步骤 6 生成结构化自检报告
按"输出规范"整合结果，按风险等级排序，附法条依据与修改建议，交付《专利预审自检报告》。

## 核心检查模块明细
（完整规则见 `references/law_rules.md` 与 `references/centers_rules.md`）
- **模块 1 准入资格校验（受理前提）**：技术领域匹配、申请类型排除、主体备案、基础客体排除。
- **模块 2 请求书形式合规**：基础信息一致性、预审专项勾选、文件清单匹配、承诺书 / XML 格式。
- **模块 3 权利要求书规范**：编号连续性、引用关系（禁多引多 / 非择一 / 无引用基础）、不确定用语、主题一致性、必要技术特征、单一性、保护范围清楚性、客体（细则第 2/22-25 条）。
- **模块 4 说明书及附图**：五部分完整性（细则第 20 条）、附图标记双向一致性（细则第 21 条）、附图规范、摘要规范（≤300 字，细则第 26 条）。
- **模块 5 明显实质性缺陷**：客体、公开充分性、新颖性初步、单一性（明显创造性可初筛）。
- **模块 6 非正常申请预警**：局令 77 号 8 类。

## 机械检查脚本
`scripts/mechanical_checks.py` 对申请文本做确定性检查，输出 JSON。用法：
```
python mechanical_checks.py --claim <权利要求文本> --spec <说明书文本> --abstract <摘要文本> --title <发明名称> --type invention
python mechanical_checks.py --file <申请文件.txt 或 .docx> --type invention   # 支持 .docx：内置 zipfile+xml 解析，无需第三方库；自动还原 Word 自动编号(numbering.xml)的序号、兼容无"权利要求书/说明书"标题词的真实代理所排版、权利要求号按行首+层级(ilvl)识别以避开化学式 C66./小数 1.0 等行内数字干扰
```
检查项：权利要求编号连续性、每项权利要求句号数（须恰为 1）、摘要字数（≤300，含标点）、附图标记在说明书文本与附图说明间双向一致（兼容全角/半角括号，细则第 21 条）、发明名称≤25 字、发明勾选项存在性（早日公布 / 实质审查 / 放弃主动修改）。脚本结果作为步骤 3 的输入。

## IPC 精确匹配脚本
`scripts/ipc_match.py` 对任一保护中心做候选 IPC 主分类小类的精确匹配（数据见 `references/ipc_whitelist.json`，覆盖全国 80 家中心）。用法：
```
python ipc_match.py --center 北京 --ipc H01M
python ipc_match.py --center 73 --ipc G06F --verbose
python ipc_match.py --center 深圳 --info        # 查看该中心白名单信息
```
匹配档位：`exact_full`（完整清单命中，高置信通过）/ `exact_partial`（部分清单命中，可能因清单不全漏判，建议核对官方）/ `exact_partial_miss`（部分清单不命中，结论不确定）/ `unknown`（无官方数据，退回产业领域粗匹配 + 用户确认）。步骤 2 命中 `exact_full_miss` 或确认不属领域时，一票否决终止深度检查。

## 知识库引用
- `references/law_rules.md`：现行法条依据（2024 版实施细则、局令 77 号、国知办发办字〔2023〕25 号、国知发保字〔2025〕39 号）。
- `references/centers_rules.md`：全国 77 家保护中心名单、产业领域、官网及 13 家特殊规则。
- `references/centers_ipc.md`：全国 80 家中心 IPC 白名单索引（5 家标杆内置完整清单 §1–§5，其余 75 家附官方来源 URL + 置信度）与精确匹配校验逻辑。
- `references/ipc_whitelist.json`：80 家中心 IPC 白名单结构化数据（逐条小类 + 置信度 + partial 标记 + 来源 URL），供 `scripts/ipc_match.py` 精确匹配；11 家为完整清单、其余为部分清单或派生。
- 规则检索基准日：2026-07-22；法规/中心规则变动后须刷新并标注版本。

## 输出规范（报告结构）
1. **检查概览**：申请基本信息、总体评估（问题计数 + 三级分级：严重/中等/优化 + 通过率分级描述；V1.0 不输出伪百分制评分）、问题统计。
2. **受理前提清单**（一票否决，红色高亮，附官方规则依据）。
3. **分级问题明细**：严重问题 / 中等问题 / 优化建议，每项含定位、判定依据、风险说明、修改建议。
4. **属地保护中心专项提示**：目标中心特殊要求、提交材料清单、注意事项。
5. **提交前核对清单**：可勾选项（含承诺书勾选、XML 格式、预审合格后 1 个工作日内提交并缴费、文本一致性、时限）。

## 限制与免责
- 本工具为预审辅助自检，不替代官方审查，最终以保护中心审查结论为准。
- 仅排查明显形式缺陷与常见明显实质缺陷，不进行全面新颖性/创造性/实用性审查。
- 不对预审通过率、授权结果作承诺，修改建议仅供参考。
- 涉密或涉及国家秘密的技术方案勿使用本工具。
- 标杆中心 IPC 白名单为种子数据，须以各中心官方公告为准定期刷新。
