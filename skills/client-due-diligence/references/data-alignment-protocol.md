# 数据对齐基准表规范（Data Alignment Protocol）

> 目的：收敛多源数据口径冲突，输出一份**权威基准值**，供报告引用、洽谈时背书、后续追踪。

---

## 为什么必须做数据对齐

律所谈客户时，若在统一社会信用代码、实控人持股、净资产等关键字段上口径打架，会瞬间暴露功课不扎实，损害专业形象。典型案例（仕净科技）：
- 统一社会信用代码：多源出现过 `91320500773222051M`（正确）与 `91320500566893154L`（编造值）
- 实控人持股：`朱叶 15.64%` 与 `合计 14.96%（质押违约转让后）` 两个口径并存
- 净资产：`-4.67 亿`（2025 末，另一口径）与 `-4.44 亿（年报口径）/ -11.59 亿（2026 中报归母）`

## 对齐流程

对每个关键字段：
1. **列来源**：记录所有来源的值 + 来源机构 + 时点
2. **判定状态**：`一致` / `口径差异` / `实质冲突`
3. **定基准值**：按下方优先级取权威基准值
4. **记冲突**：`实质冲突` 字段进入"待核实事项"清单

## 权威优先级（从高到低）

| 优先级 | 来源 | 适用字段 |
|---|---|---|
| 1 | 政府登记机关（国家企业信用信息公示系统） | 统一信用代码、法人、注册资本、成立日期 |
| 2 | 交易所/证监会官方 | 纪律处分、立案、退市风险警示 |
| 3 | 公司一手公告/定期报告 | 财务数据、股东、质押冻结、预重整进展 |
| 4 | 法院决定书/裁判文书 | 预重整、涉诉、执行 |
| 5 | 中央级权威媒体 | 舆情、事件背景 |
| 6 | 商业数据库（企查查/天眼查/启信） | 辅助核验，不作为基准 |

## 关键字段基准来源（速查）

| 字段 | 基准来源 | 备注 |
|---|---|---|
| 统一社会信用代码 | gsxt.gov.cn | 18 位，禁止编造 |
| 法定代表人 | gsxt.gov.cn | 记录变更时间线 |
| 成立日期 | gsxt.gov.cn | |
| 实控人/持股 | 上市公司定期报告 | 注意"质押违约后"等变动 |
| 净资产/资产负债率 | 定期报告"主要会计数据" | 年报与中报口径不同 |
| 财务数据 | 定期报告 | 年报若存在两套营收口径，以"主要会计数据"章节为准 |

## 输出格式（数据对齐基准表）

字段 | 权威基准值 | 来源 | 时点 | 冲突说明
---|---|---|---|---
（每字段一行）

## 冲突处理原则

- **口径差异**（如年报 vs 中报的净资产）：同时列出，标注"年报口径 / 中报口径"，不判定对错
- **实质冲突**（如统一信用代码不一致）：以最高优先级源为准，其余标"待核实"
- **单源无印证**：标"待印证"，进入待核实清单
- **完全无源**：不写入报告，或仅作"未检索到"陈述
