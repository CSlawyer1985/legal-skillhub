# 报告结构规范

本规范对齐最高人民法院《关于统一法律适用加强类案检索的指导意见（试行）》（法〔2020〕35 号）对类案检索报告的栏目要求，并结合律师实务研究报告的通行做法制定。报告正文按以下部分组织：摘要 + 正文六部分 + 附录，不得缺省摘要与第 1–5 部分。

## 〇、摘要：先看结论（固定栏目）

报告首页、正文之前必须有 300–600 字摘要，让读者 30 秒抓住核心判断：

1. **核心判断一句话**：果断给出总判断（如"本命题不能用一条规则回答，决定责任结构的第一变量是……"）；
2. **变量框架**（如适用）：把命题解构为 2–4 个决定结论走向的关键变量（时间效力、行为状态、责任主体、程序路径等），说明哪个变量先查、哪个后查；
3. **编号结论 3–6 条**：每条一句话，对应正文展开的主要结论，编号与正文呼应。

摘要只写结论不写论证；拿不准的地方如实写"尚待统一"并指明依据层级（如"仅有征求意见稿"）。

## 一、问题的界定与检索路径

1. **问题界定**：将命题拆解为 3–5 个子问题（论证节点），说明需要辨析的核心概念（如"未届期股权"与"瑕疵股权"的区分）。
2. **检索路径**：说明使用的数据库/平台、检索维度（三源：法规/案例/实务）、核验方式。
3. **检索过程记录表**（指导意见明确要求"检索主体、时间、平台、方法、结果"）：

| 检索要素 | 内容 |
|----------|------|
| 检索人 | （AI 辅助 + 人工复核，注明使用者） |
| 检索日期 | YYYY-MM-DD |
| 检索平台 | （如法智法律数据库 / 国家法律法规数据库 / 人民法院案例库 / 通用搜索引擎） |
| 检索关键词 | （列举核心检索语句，3–6 条） |
| 检索结果 | 法条 N 项、案例 N 个（其中入库参考案例 N 个）、实务文章 N 篇 |
| 核验方式 | （逐条核验效力状态 / 交叉印证 / 未能核实项的处理） |

## 二、法律依据

以**条文核验表**呈现，逐条注明效力状态：

| 规范 | 条文 | 规则要点 | 效力状态 |
|------|------|----------|----------|
| （法规全称） | 第 N 条 | （要件 + 法律后果） | 现行有效 |

- 必须使用法规全称；核心条文在表后可附 3–5 条"规范要点说明"（制度源流、适用边界、条款间关系）；
- 已被修改/失效的规范不得作为现行依据；但经时间效力分析仍适用于历史法律事实的旧规范（如新规施行前发生的交易），应列为该情形的适用依据并说明理由；仅在历史沿革语境引用时须明确标注。

## 三、类案检索与裁判规则

1. **类案一览表**（置于本节开头，总览全部引用案例，按裁判日期降序排列，便于看出规则迁移轨迹）：

| 案号 | 审理法院 | 裁判日期 | 立场 | 裁判要点 | 效力层级 | 是否受新规影响 |
|------|----------|----------|------|----------|----------|----------------|
| （完整案号） | （法院全称） | YYYY-MM-DD | 支持担责/免责/边界 | （30 字以内） | 入库参考案例/普通裁判文书 | 不受影响/判理已被排除/以关键时点为准 |

2. **分述**：按"支持方 / 反对方 / 适用边界"分组展开，每个案例说明案情要点、法院观点与裁判结果；入库参考案例、指导性案例、最高法裁判优先并注明。命题涉及近期新规时，应增设"最新裁判动向"分组（按债权人/当事人实现路径细分），呈现新规落地后的裁判走向。
3. **被新规改变判理的样本**（按需）：所引案例的法律适用路径已被后续规范排除的，专设本小节列表对照（原判理 → 新规后的评价），保留以观察规则变迁；该类案例不作为可援引的裁判规则。
4. **裁判规则提炼**：归纳为 3–5 条可操作的规则（如时间线分水岭、构成要件清单、责任形态、实现路径、多手转让顺位等）。鼓励进一步提炼为**可操作模型**（如"恶意认定的因素叠加模型：不能清偿状态 × 知情程度 × 交易异常度 × 受让人资力 × 后续强化事实"），但**必须声明模型是经验归纳而非机械要件**——因素叠加越多越可能被认定，不等于任一因素单独成立即担责。

## 四、实务分歧观点及主流倾向

以**分歧对照表**呈现：

| 分歧点 | 观点一 | 观点二 | 主流倾向 |
|--------|--------|--------|----------|
| （争议焦点） | （支持方观点 + 理据） | （反对方观点 + 理据） | （通行做法/最新权威意见） |

分歧包括：规范解释分歧、司法裁判分歧、学术争议、新旧法衔接（溯及力）问题。每个分歧必须双方案例或来源支撑。**"主流倾向"一栏允许填写"样本不足，无法判断主流"——禁止为填满栏目而把少量样本包装成趋势**；个案只能表述为"本次检索样本中存在此种处理路径"，除非样本量与检索方法足以支撑趋势判断。

## 五、研究结论与风险提示

1. **研究结论**：逐条回应对问题界定的各子问题，果断明确；取决于事实差异时分情形讨论；信息不足时指出缺失及其影响。**涉及多变量分流的命题，研究结论首选以"决策树/决策步骤表"呈现**（步骤 → 要查明的事实/问题 → 法律分流 → 直接结论），例如第一步锁定行为时点、第二步锁定行为状态、第三步检查加速/加重事由、第四步确定请求主体与程序——让读者可以照表操作，而不是在段落文字里找结论。
2. **风险提示**：按主体（如转让方/受让方/债权人/企业/个人）分别给出 3–5 条可操作建议。**诉讼类命题应增设"诉讼证据清单"表**（证据模块 / 重点材料 / 证明目的），把建议落到可执行的取证动作上。
3. **一句话结论**（按需）：报告用于路演、汇报、客户沟通的，结尾附一段 100–200 字"一句话结论"，可脱离上下文直接引用。
4. 不得作绝对化承诺（保证胜诉、保证无责任等）。

## 六、未采信事项说明（固定栏目）

检索过程中遇到但决定不予采信或仅作有限使用的素材，集中说明，体现核验纪律：

1. **未能核实裁判文书/官方文本的传闻**：说明传闻内容、出处、未能核实的检索范围，不予引用；
2. **判理已被规则变迁取代的老案例**：说明未采用的原因（判理已被新规/批复框架取代），仅作历史对照；已收入一览表但判理失效的案例，在此重申其不可援引；
3. **实务文章与新闻类来源的处理原则**：仅用于把握学术争议与实务动态，不作为论证依据。

## 七、附：数据库定位信息一览表与说明

1. **数据库定位信息一览表**：分三组汇总全部引用来源的链接（格式见 `citation-rules.md`）。表首须加说明：法智、元典、北大法宝等为商业数据库，**全文阅览需相应数据库账号**，链接作为精确的数据库定位信息使用——不得宣称"点开即看全文"。
   - 法条类（法规全称+条号 → 详情页链接；关键批复/司法解释给双库链接）
   - 案例类（案号+审理法院+**效力层级**（入库参考案例/普通裁判文书）→ 详情页链接）
   - 实务文章与新闻类（标题+来源平台 → 原始 URL）
2. **信息来源与核验说明**：声明检索渠道限于公开渠道、检索与核验时间、AI 工具辅助情况、未核实项的标注与处理。

## 交付前自检清单

- [ ] 摘要"先看结论"已成文（核心判断 + 变量框架 + 编号结论），无摘要不得交付
- [ ] 五要素结构完整，含检索过程记录表与类案一览表
- [ ] 全部法条注明效力状态，无失效规范误用；关键批复/司法解释已双库逐字核验并照引原文
- [ ] 全部案号真实（来自检索结果），无编造拼接
- [ ] 正反方案例均不少于 2 个
- [ ] 关键结论均有两个以上独立来源；孤证已标注
- [ ] 互联网引用已回库核实，未核实项已注明
- [ ] 规则时效性审查已完成：所引案例的法律适用路径均仍然有效，失效者已标注"判理已被排除"并单列对照
- [ ] 多变量分流命题的研究结论已决策树化；诉讼类命题已附证据清单
- [ ] 规则提炼为模型/公式的，已声明"经验归纳而非机械要件"
- [ ] 全部引用附数据库定位信息（正文内嵌 + 文末总表）；商业库账号要求已如实说明
- [ ] 未采信事项说明已成独立小节（传闻/老案例/实务文章三类）
- [ ] 无绝对化承诺，无把个案当通则的表述
