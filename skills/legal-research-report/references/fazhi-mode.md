# 模式 A：法智数据库三源检索流程

适用前提：当前会话存在法智（或等价法律数据库）MCP 工具。以下以法智六工具为例；使用其他法律数据库 MCP（北大法宝、元典、威科等）时按等价工具替换，流程不变。

## 工具清单

| 来源 | 检索工具 | 读取/核验工具 |
|------|----------|----------------|
| 法规规范 | `legal_article_search` | `law_content_visit` |
| 司法案例 | `case_search` | `case_browser` |
| 互联网实务 | `webpage_search` | `webpage_visit` |

## 检索流程（通常 2–3 轮）

### 第 1 轮：三源并行（一次发出全部检索）

- `legal_article_search`（1–2 条）：用自然语言法律问题 + 同义术语穷举（如"认缴出资期限未届满 转让股权 出资义务 受让人 转让人 补充责任 公司债权人"），`status="现行有效"` 优先；已明确法规名+条号时用 `law_name` + `item` 精确检索。
- `case_search`（2–3 条，`size` 建议 10–15）：每条 10–30 字完整句，≥2 个维度（事实+争议焦点 / 法条+时间）；必须包含一条"反方"检索（如"……法院驳回/不承担责任"）；可加 `time`/`area` 过滤。
- `webpage_search`（1–2 条）：实务分析 + 权威解读（如"XX 理解与适用""XX 观点分歧"），优先公众号实务文章。

### Read 阶段：按需读取

- 核心法条内容不全时 → `law_content_visit`（传 `law_id` + `goal`）；
- 关键案例需核验裁判理由 → `case_browser`（传案号）；
- 重要官方/权威网页 → `webpage_visit`（传 url + goal）。
- **强制记录**：每篇文章/文书引用的法条编号与案号，供回库核实。

### Reflect 阶段（每轮后内部回答）

1. 正反方是否均覆盖（各 ≥2 个独立来源）？
2. 互联网引用的法条/案例是否已回库核实？
3. 三源是否冲突？法条效力状态是否全部确认？
4. 是否涉及近 1–2 年新规？如是，必须专项核查时间效力/溯及力（司法解释、批复、备案审查动态）。

不足则进入下一轮：每工具补 1–2 条**改变表述**的新检索语句；同一目标失败最多重试一次。

## 结果处理规则

- 法条：`lawStatus=现行有效` 方可作现行依据；`已被修改/失效` 仅历史语境引用并标注。
- 案例：不得编造拼接案号；入库参考案例（`caseSource`/`refer` 标注）优先引用；存在裁判分歧时说明主流倾向，不得将个案上升为普遍规则。
- 链接：按 `citation-rules.md` 模式 A 规则，用返回的 `lawId`/`lawsuitId` 拼 fazhi.law 深链。
- 案例检索结果较大时，按"与命题的争议焦点相似度"筛选，优先：入库案例 > 最高法 > 近年 > 正反观点代表性。
