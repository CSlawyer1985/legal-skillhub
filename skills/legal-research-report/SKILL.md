# legal-research-report — 公司股权类法律检索研究报告生成器

把一个公司股权法律研究命题，变成一份**结构规范、来源可溯、结论经得起追问**的法律检索研究报告。

## 设计理念

AI 法律研究的最大风险是"看似专业的幻觉"——编造法条、拼接案号、把个案当通则。本 Skill 的全部设计围绕一个原则：**可核验性**。每一条法条注明效力状态，每一个案例标注真实案号与详情页链接，每一个未能核实的信息如实标注，让读者（律师、法官、客户、评委）可以一键溯源、逐条复核。

## 领域聚焦：公司股权

本 Skill 以**公司股权类争议**为深耕方向：出资责任、股权转让、股权代持、对赌回购、法人人格否认、董监高责任、公司决议效力、股东权利救济等命题属于主场；其他法律领域命题可复用同一流程，但领域知识（核心规范清单、命题类型地图、特有风险点）以公司股权为中心维护。

开始检索前，先读 `references/equity-domain.md`：它给出公司股权领域的**核心规范清单**（新公司法重点条文、公司法解释三、九民纪要、变更追加规定等）、**命题类型地图**（命题 → 拆解维度 → 必查规范），以及**股权类研究特有风险点**（新规密集、溯及力高发、程序与实体分离、主体边界复杂）。命中有图的命题按图拆解，不在图上的按通用五阶段流程处理。

## 启动：先检测环境，选定运行模式

加载本 Skill 后，第一步必须判断当前环境可用的检索能力，并据此选择模式（也可运行 `scripts/detect_tools.sh` 辅助判断）：

1. **检查是否存在法律数据库 MCP 工具**：当前会话工具列表中是否存在 `mcp__fazhi-law__legal_article_search`、`mcp__fazhi-law__case_search`、`mcp__fazhi-law__webpage_search`（或其他等价的法律数据库 MCP，如北大法宝、元典、威科等提供的检索类工具）。
2. **模式 A（数据库模式）**：存在上述工具 → 按 `references/fazhi-mode.md` 执行三源权威检索（法条/案例/实务三源并行、互相印证）。
3. **模式 B（通用降级模式）**：不存在任何法律数据库工具，但宿主产品具备网页搜索能力 → 按 `references/fallback-mode.md` 执行：通用搜索 + 公开权威源清单检索 + 人工核验纪律。
4. **两者皆无**（无任何检索能力）→ 明确告知用户"当前环境无检索能力，只能基于训练知识撰写框架，所有法条与案例必须人工复核后方可使用"，并在报告附录显著标注。

**禁止事项**：无数据库工具时，不得假装完成了"权威数据库核验"；检索不到的内容必须写"未检索到"，不得编造法条、案号、链接。

## 主流程（五阶段）

### 阶段 1：命题拆解（内部）

将用户的命题拆解为 3–5 个论证节点（子问题），确定研究维度：基础法条（必选）、司法解释/配套规范、类案支持方、类案反对方（必选）、实务分歧与动态（必选）、地域/审级/时效差异（按需）。公司股权类命题先对照 `references/equity-domain.md` 的命题类型地图确定拆解维度与必查规范。

### 阶段 2：三源检索

按所选模式执行检索。无论模式 A 还是模式 B，都必须遵守：

- **三源并行**：法规规范、司法案例、互联网实务三类来源并行检索，互相印证；
- **正反方必查**：类案必须同时检索支持与不支持两种裁判结果，不得只呈现一面；
- **孤证不立**：关键结论至少两个独立来源支撑，单一来源必须标注"单一来源，仅供参考"；
- **效力核验**：逐条确认法条效力状态（现行有效/已被修改/失效），失效规范不得作为现行依据引用。

各模式的检索语句构造、工具调用顺序、读取与核验步骤，见对应 `references/fazhi-mode.md` 或 `references/fallback-mode.md`。

### 阶段 3：交叉验证与扫漏

- 互联网文章引用的法条/案例，必须回到法规、案例来源中核实；未核实到的标注"互联网来源引用，检索未核实到对应文件"；
- 三源结论冲突时，同时呈现分歧并说明主流倾向；
- 新法（近 1–2 年生效）必须专项核查其时间效力（溯及力）问题。
- **规则时效性审查**（v1.1 新增）：命题涉及近 1–2 年新规、司法解释或批复时，除核验规范本身的效力状态外，还必须核验**所引案例的法律适用路径是否仍然有效**——即案例裁判所依据的条款是否已被后续规范（新司法解释、批复、修订）排除或改变。已被排除的：在该案例说明处加醒目标注"判理已被排除，其法律适用路径现已不能援引"，并在类案部分专设"被新规改变判理的样本"小节保留对照，观察规则变迁。切勿只写"新规则已成定局"而不点破自己正文引用案例的失效判理——这是答辩/质询中最容易被攻击的漏洞。

### 阶段 4：报告撰写

严格按 `references/report-structure.md` 的结构撰写（对齐最高人民法院《关于统一法律适用加强类案检索的指导意见（试行）》的栏目要求）：

0. 摘要：先看结论（固定栏目：核心判断 + 变量框架 + 编号结论 3–6 条）
1. 问题的界定与检索路径（含**检索过程记录表**）
2. 法律依据（条文核验表：规范/条文/规则要点/效力状态；关键司法解释、批复须**双库逐字核验后照引原文**）
3. 类案检索与裁判规则（**类案一览表**——含效力层级、是否受新规影响两列，按裁判日期降序 + 正反方分述 + 规则提炼，鼓励提炼为可操作模型但须声明"经验归纳而非机械要件"）
4. 实务分歧观点及主流倾向（分歧对照表）
5. 研究结论与风险提示（多变量分流命题首选**决策树表**呈现结论；诉讼类命题附**诉讼证据清单**；分主体给出建议；路演场景附**一句话结论**）
6. 未采信事项说明（固定栏目：未能核实的传闻/判理已被规则变迁取代的老案例/实务文章处理原则）
7. 附：数据库定位信息一览表 + 信息来源与核验说明

引用与链接格式必须遵守 `references/citation-rules.md`：正文内嵌超链接 + 文末来源一览表双轨呈现。撰写骨架可直接复用 `assets/report-template.md`。

### 阶段 5：交付与自检

输出前逐项自检（checklist 见 `references/report-structure.md` 末节）：引用是否全部来自真实检索结果、链接是否可打开、正反方是否覆盖、孤证是否标注、是否把个案当通则、失效法规是否误用。如宿主产品具备文档生成能力（如 docx 流水线），可进一步产出排版规范的 Word 文档。

### 阶段 6（可选）：测试与评分

当用户要求验证本 Skill 的输出质量（或在交付前做质量背书）时，进入测试环节：

1. **机械校验**：运行 `scripts/check_report.py <报告文件>`，自动检查结构完整性（七部分栏目、四类必备表格）、红线违规（绝对化用语、把个案当通则的表述）、案号与链接格式、计数一致性，输出 PASS/FAIL 清单；
2. **命题测试**：`tests/test-cases.md` 内置 3 个公司股权标准测试命题（含预期命中点与埋设陷阱），可用于回归验证——用测试命题跑一遍完整流程，核对输出是否命中全部预期要点、是否踩中陷阱；
3. **人工评分**：按 `tests/scoring-rubric.md` 的百分制评分表打分（结构 20 分 / 法条核验 25 分 / 案例真实性 25 分 / 分析深度 15 分 / 红线纪律 15 分），80 分为合格线。

详见 `tests/README.md`。

## 输出纪律（红线）

1. 不编造任何法条、案号、链接、网页内容；
2. 不把单个案例上升为普遍规则；样本不足时明确写"样本有限，尚不足以认定主流趋势"，禁止为填满"主流倾向"栏目而制造趋势；
3. **程序建议须区分实体责任与程序路径**：认定实体责任成立，不等于可以直接适用执行追加等程序便利（追加须符合严格法定条件，如最高法法答网答疑所强调）；不得从实体责任直接推导出程序选择建议；
4. 不作绝对化承诺（不保证胜诉、不保证无责任）；
5. 不输出违法、规避监管、隐匿财产等操作方案；
6. 检索过程与内部推理不写入报告正文，报告只呈现结论与可核验来源。
