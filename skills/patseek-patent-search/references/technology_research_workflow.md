## 1. 任务边界与决策问题

技术调研回答“技术如何演进、谁在做、方案如何分化、哪里值得继续研究”，不是查新、FTO、无效或市场规模测算。先记录用户要据此做的决定：

| 决策类型 | 典型问题 | 主要输出 |
|---|---|---|
| 研发立项 | 哪些路线成熟、哪些问题未解决 | 技术树、问题-方案-效果矩阵、研发机会 |
| 竞品/对标 | 主要主体布局什么、近年如何变化 | 申请人归一化、技术组合、代表专利 |
| 技术路线选择 | 路线优缺点、替代方案和迁移方向 | 路线比较、证据、成熟度代理指标 |
| 专利布局 | 哪些主题拥挤、哪些表达或组合较少 | 密度与空白假设、代表文献、验证建议 |
| 合作/引进 | 哪些主体和发明团队值得进一步核查 | 主体/发明人线索、技术互补性、证据限制 |
| 持续监测 | 新进入者、新路线和新申请如何变化 | 基线检索式、增量规则、复核清单 |

用户实际要判断新颖性或侵权时，切换本 Skill 对应工作流；需要无效证据或专利权稳定性分析时，本 Skill 不再承接，应改用相应的专业流程。不能把技术调研结论代替法律分析。

## 2. 企业与发明人输入

### 企业输入

至少确认：业务决策、产品/产业链位置、目标市场、时间范围、关注主体、技术边界、交付深度和可接受的外部数据范围。无法确认时说明假设后继续首轮，不把未知项伪装成事实。

### 发明人输入

至少记录：拟解决问题、现有方案痛点、已知技术路线、关键约束、希望了解的替代方案、允许公开的技术细节。未申请方案先提示发送到PatSeek的保密风险并做去标识化。

### 需求路由

| 用户 | 必答问题 |
|---|---|
| 企业管理/战略 | 结论如何影响立项、竞品、合作或布局决定 |
| 企业研发/IP | 技术簇、代表文献、主体组合、数据质量和后续检索入口 |
| 发明人 | 现有解决路径、仍存问题、可替代机制、可验证研究方向 |

## 3. 数据范围与分析单位

执行前建立范围表：

| 项目 | 必须记录 |
|---|---|
| 数据库 | PatSeek CN/world及外部来源 |
| 国家/语言 | 已覆盖和未覆盖的市场、语言 |
| 时间 | 起止年份、检索日期、是否含未完整年度 |
| 文献 | 专利申请/授权、论文、标准、产品资料等 |
| 分析单位 | 同族、申请、公开文本或文献；默认优先同族 |
| 日期口径 | 趋势优先最早优先权年，其次申请年；不得混用公开年 |
| 主体口径 | 集团/母子公司/历史名称/联合申请规则 |

PatSeek无法取得完整同族成员时，不得宣称完成同族去重。可以输出“公开文本口径”或“可识别同族口径”，并说明可能重复计数。

专利数量不是市场规模、收入、研发投入或技术价值。引用量受年龄、法域和数据完整性影响，只能作为辅助信号。

## 4. 技术分类树与检索矩阵

先建立二至三级技术分类树，再执行规模统计。分类树至少包含：

1. 应用对象/产业链环节；
2. 核心问题或目标；
3. 解决机制/技术路线；
4. 关键结构、材料、步骤或控制逻辑；
5. 性能/效果和约束条件。

每个节点记录定义、纳入标准、排除标准、关键词、IPC、相邻节点和示例文献。节点应尽量互斥；不能互斥时明确允许多标签，统计时不得把多标签简单相加成总量。

为每个主题设计以下检索块：

| 检索块 | 用途 |
|---|---|
| 核心块 | 主题对象 × 核心机制，建立基线候选池 |
| 路线块 | 各技术路线、材料、结构或算法分支 |
| 问题/效果块 | 从待解决问题和技术效果发现不同表述 |
| 上下游块 | 上游部件/材料和下游系统/应用 |
| 相邻领域块 | 识别跨领域迁移路线，不并入核心统计前先复核 |
| 主体块 | 重点企业、研究机构、历史名称和子公司 |
| 分类块 | 单独验证下位IPC，再用上位IPC补召回 |
| 国际块 | world、英文/当地语言、国家代码和分类号 |
| 语义块 | 发现术语和不同表达，结果回到Bool核验 |

宏观统计可保留宽检索，但显示10,000上限时不能直接做份额或趋势分析。应按时间、分类、主体或路线拆分，确保每个统计分区未被截断且抽样相关性合格。

分区后必须同时验收“未截断”和“技术相关性”。若各分区简单相加，应先处理重叠文献和多标签；仅通过日期切片把10,000拆小，不代表检索边界已经准确。

## 5. 试检索与迭代

先用少量试检索校准边界，不直接批量统计：

1. 每个一级技术簇执行一条核心式和一条路线/分类式；
2. 抽样前10及跨页结果，标记R（相关）、A（相邻）、N（噪声）、D（重复/日期异常）；
3. 记录主要噪声类型、遗漏术语、新IPC、主体和上下游关系；
4. 修订分类定义和查询矩阵；
5. 边界稳定后再执行分年、分主体、分国家统计。

每轮增加条件后，逐项记录该条件在前10原文或结构化字段中的可观察率。新增条件低于50%或H/H+M率未改善时，视为无效收窄并更换分类、字段、语言或技术切角；不能仅因总量下降就继续统计。

world复合式为0时先做`对象 + CC`、机制/关系 + `CC`、IPC子类 + `CC`、准确IPC主组紧凑/空格两种写法 + `CC`四层预检。任一层为0表示该字段、语言或表达式尚未验证，不能把更长组合式的0条用于路线排除、密度或国际布局判断。

国际多语言路径独立验收：每条路径记录语言、原文术语、回译、国家前缀核验率、样本精确率和关键特征可观察率。英文、日文、韩文等路径的原始命中数不得相加或互相替代；仅把达到相同技术边界和质量门的路径合并为“多语言已覆盖”。当地语路径关键特征低于50%时只可取词或修订翻译，不得以英文路径结果替它背书。

新增术语须来自至少两篇相关文献、分类定义、标准、用户确认或其他权威来源。连续两轮只增加同类噪声时切换分类、语言、引证或语义渠道，不继续堆叠低置信词。

## 6. 数据质量与抽样

### 相关性抽样

候选池少于30篇时检查全部；不少于30篇时至少抽样30篇，并覆盖主要年份、技术簇、申请人和结果页，不能只检查相关度前排。报告：抽样方法、相关篇数/样本数、样本精确率和主要误差类型。

样本精确率只衡量已抽样结果，不代表召回率。发现任一主要技术簇样本精确率明显低于总体时，单独修订该簇检索式。

### 归一化检查

| 对象 | 检查 |
|---|---|
| 同族 | 最早优先权、重复公开、目标法域成员；不可得时报告限制 |
| 申请人 | 全称、简称、英文名、子公司、并购前后名称、联合申请 |
| 年份 | 最早优先权年/申请年、未完整年度、异常日期 |
| 分类 | 同一文献多标签规则、分类版本和过宽上位组 |
| 国家 | 公开国不等于销售市场或有效权利地区 |
| 引用 | 年龄和法域偏差、字段缺失、是否已核对来源 |

所有图表必须保留分母、分析单位、时间口径、数据截止日和截断说明。

主体/竞品分析对每个`AP=`结果抽样反查`applicant`字段，并另行评价技术相关性。只有字段命中和技术相关性均通过，才能计入该主体的布局数量；字段命中但技术不相关、技术相关但主体未命中均应排除。名称归一化规则和未识别别名必须随报告交付。

同一主体的简称、法定全称、英文名、历史名称和子公司必须分别试检索，再将命中按PID/可识别同族合并去重；不得选择命中最多的单一名称代表全部布局，也不得比较不同名称检索式的原始总量。默认只有跨年份/页面抽样不少于30篇且“申请人字段+技术相关性”联合精确率达到70%，才进入定量主体图表；未达门槛时继续校准，或只交付定性代表文献并披露误差。

不得把“高校、大学、研究院、公司、集团”等组织类型普通关键词当作申请人过滤条件；它们出现在说明书、背景或合作描述中，不证明申请人属于该类型。合作对象发现先用技术式取得代表文献，从`applicant`和详情发明人字段提取具体名称，再对每个确认名称使用`AP=`分别检索和归一化。

关键词块连续失效时，改用“名称变体 × 已单独验证IPC × 时间分区”取得主体候选池，再在本地按关键技术特征和关系筛选。候选池不超过100篇时检查全部，不只看前10；超过100篇时跨页/年份分层抽样。若完整小池仍无技术命中，报告“当前PatSeek范围内未形成该主体的可核对技术样本”，不得用AP原始命中数代替。

## 7. 分析模块

按决策问题选择模块，不为凑报告全部执行。

### 技术演进

按最早优先权年或申请年展示技术簇变化；标记未完整年度。用代表文献解释路线变化，不把年度数量波动直接解释为市场增长。

### 技术路线与成熟度

为各路线记录：问题、机制、关键部件/步骤、效果、主要约束、代表主体、代表文献和证据年份。成熟度只能使用“申请持续性、主体多样性、实施例/产品证据、标准化线索”等代理指标，并列明缺失数据。

路线比较必须逐路线建立独立检索块并分别验收，不能选出“最佳检索块”后只抽样该路线。每条决策关键路线分别报告：检索边界、总量是否截断、跨页/年份样本、样本精确率、特征可观察率、代表文献和缺失证据。候选池不少于30篇时每路线至少抽样30篇；少于30篇时检查全部。只有口径和精确率可比时才比较数量；否则输出定性路线卡片，不生成路线份额或成熟度排名。

### 主体与竞品

在归一化后比较主体的技术簇覆盖、近年活动、代表文献和合作关系。不得仅按专利件数排序后宣称技术领先；申请质量、法律状态和商业化需另行核验。

### 地域布局

比较公开来源和可识别同族分布，说明公开国、优先权国、申请市场和有效权利地域不是同一概念。

### 关键文献

关键文献优先依据技术代表性、多路命中、特征/机制证据、时间位置和引用线索选择。调用详情记录权利要求、说明书位置和日期；高引用不能单独决定关键性。

### 技术空白与机会

只输出“当前数据范围内的低密度组合/未充分解决问题假设”。每个机会同时列出：支持证据、可能原因、相邻文献、商业/工程约束和下一步验证。低专利量可能源于检索遗漏、保密、不可专利、技术不可行或市场不足，不等于可专利、可实施或有商业价值。

低密度机会使用三级状态：

| 状态 | 通过条件 | 允许表述 |
|---|---|---|
| 未验证 | 任一主要检索块截断、样本精确率不足、仅检查前排或未覆盖关键同义/分类/语义/国际渠道 | “当前证据不足以判断密度” |
| 低密度假设 | 各独立渠道未截断；每个不少于30篇的池跨页抽样至少30篇、较小池检查全部；技术边界稳定且未见直接反例 | “在所列范围内形成低密度假设，需继续验证” |
| 已有反例 | 任一适格文献在权利要求或可复核详情中公开目标组合 | 不得称空白；缩窄组合或改为相邻路线分析 |

语义返回量大、Bool总量小或完整率低都不能单独证明低密度。市场团队是否开展客户访谈还需客户痛点、成本、供应链、法规和替代方案证据；专利数据只能提供访谈假设，不能替代市场判断。

### 合作对象与高校团队

把输出分为“技术线索”“主体线索”和“合作适格性”三层：

1. 技术线索要求代表文献同篇覆盖目标机制和关键用途；
2. 主体线索要求详情中的申请人/共同申请人和发明人字段可复核，并完成名称归一化；
3. 合作适格性还需核验团队持续研究、当前任职/联系方式、权属处分权限、现有许可、研发成熟度和合作意愿。

只有一件相关专利时可列“待联系线索”，不得做团队排名。若要比较团队，默认每个团队至少核对两件可识别独立同族的技术相关文献；不足时明确样本不足。详情增强字段为空只表示数据缺失，不表示没有发明人、同族或法律状态。

## 8. 企业工作流

1. 把业务问题转换为3-5个可回答的分析问题；
2. 与企业确认技术分类树、重点竞品和统计口径；
3. 用试检索和分层抽样校准边界；
4. 执行技术演进、主体、地域、路线或机会模块；
5. 为每个关键判断提供文献证据、数据口径和反例/不确定性；
6. 输出“发现 → 对企业的含义 → 可选行动 → 风险/验证”的决策表；
7. 将FTO、法律状态、市场规模和商业尽调需求转交专项流程。

企业版报告至少包含一页管理摘要，不以专利列表代替结论。

## 9. 发明人工作流

1. 以“问题—已有机制—局限—替代机制”组织文献，不以申请人排名为主；
2. 对最相关路线提取关键结构/步骤、参数、效果和实施约束；
3. 标记已见、待证和未充分覆盖的技术组合；
4. 提出可验证研究假设、替代实施方式和需要补充的实验/参数信息；
5. 区分研发启发、查新候选和撰写素材，禁止复制他人权利要求或保证可专利性；
6. 把需要正式新颖性/创造性判断的方案转入查新工作流。

发明人版输出优先技术地图、问题-方案矩阵、代表文献卡片和待确认问题，不堆砌宏观图表。

## 10. 中止与验收

固定Top N不能证明技术调研完成。至少满足：

- 每个一级技术簇有定义、检索式和相关文献样本；
- 主要年份、主体、国家和结果页均进入分层抽样；
- 连续两轮不再出现新的一级技术路线、关键主体或高价值术语；
- 统计分区未受10,000上限截断，或已明确无法消除的限制；
- 同族、申请人、年份和多标签口径已记录；
- 关键结论能追溯到数据表或文献证据；
- 企业/发明人需要的决策问题逐项得到回答或标记无法回答。

## 11. 输出结构

### 企业版

1. 管理摘要与建议动作
2. 决策问题、范围和数据质量
3. 技术分类树与路线演进
4. 主体/竞品和地域分析
5. 关键文献与证据
6. 低密度机会假设及反证
7. 风险、未覆盖项和下一步

### 发明人版

1. 研发问题与边界
2. 现有技术路线图
3. 问题-机制-效果-限制矩阵
4. 代表文献卡片
5. 替代路线和研究假设
6. 待补技术信息及查新入口
7. 数据限制和保密提醒

## 12. 结论纪律

禁止使用：

- “专利最多，所以技术最好/市场最大”；
- “没有检索到，所以没有人做”；
- “这是专利空白，因此可以自由实施或一定能授权”；
- “公开国就是企业销售市场”；
- “高引用必然代表高价值”。

推荐口径：

> 截至[日期]，在[数据库、国家、语言、时间和检索式]范围内，识别出[技术路线/主体/变化]。该发现基于[分析单位和抽样口径]，受[同族、字段、截断、非专利来源等]限制，主要用于[研发/战略决策]的第一轮证据支持，不替代FTO、可专利性、市场或商业尽调。
