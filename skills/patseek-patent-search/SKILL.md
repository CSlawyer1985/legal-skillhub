# PatSeek 专利检索

## 核心原则

1. 先确定任务类型，再选择流程；不得用可专利性查新替代 FTO。
2. 把 PatSeek 作为专利文献召回工具，不把相似度、命中数或模型结论直接当作法律结论。
3. 报告所有数据库、市场、检索式、日期、限制和未覆盖来源，保证可复核。
4. 对未公开技术先提示保密：完整方案会发送到 PatSeek；使用 `--no-call-log` 可禁用本地调用统计，缓存仍可能保存 API 响应。
5. 费用以 API 返回的 `credits_charged` 为准，不用文档估算替代实际返回。

## 任务路由

| 用户目的 | 路由 | 必读参考 |
|---|---|---|
| 查新、能否申请、新颖性、创造性 | 可专利性检索 | `references/novelty_search_workflow.md` |
| FTO、侵权风险、上市避雷、能否实施 | FTO 检索 | `references/fto_workflow.md` |
| 行业、竞品、技术路线、技术趋势、研发机会 | 技术调研 | `references/technology_research_workflow.md` |
| 已知公开号/申请号、简单关键词 | 直接检索 | 本文件“命令”章节 |

若任务信息不足，先做不收费的方案拆解并展示检索范围；只在即将调用 API、扩大法域或增加付费/耗时操作时请求确认。

本 Skill 不提供无效证据检索或专利权稳定性分析；收到此类请求时应明确说明任务边界，并改用相应的专业流程。

## 运行与保密

使用当前 Skill 目录中的脚本：

```bash
python3 <skill-dir>/scripts/patseek_client.py --help
```

通过环境变量传 Key，避免把 Key 写进命令历史：

```bash
export PATSEEK_API_KEY=ps_你的Key
```

保密选项：

```bash
# 不写本地调用统计日志；公共参数可写在子命令之前或之后
python3 <skill-dir>/scripts/patseek_client.py bool "检索式" --no-call-log

# 完全禁用调用统计
export PATSEEK_DISABLE_CALL_LOG=1
```

脚本的调用日志只保存 Key 指纹、技术词摘要、页码和积分，不保存查询原文。结果缓存默认位于 `~/.cache/patseek/`；高度敏感任务结束后提醒用户自行清理缓存。不要在报告、终端输出或日志中回显 API Key。

## 执行前检查

| 检查项 | 必须确认的内容 |
|---|---|
| 任务 | 可专利性、FTO、调研或直接检索 |
| 使用者与决策 | 企业管理/市场/IP/研发、发明人、技术经理或高校团队；报告要支持什么决定 |
| 对象 | 产品/方法、必要技术特征、部件关系、参数和效果 |
| 日期 | 可专利性：目标申请日及最早优先权日；FTO：计划实施时间；技术调研：分析时间范围与数据截止日 |
| 地域 | CN 或 world；FTO 必须列明具体实施国家，`WO/EP` 不能直接代表可执行国家权利 |
| 文献 | 专利文献是否足够；是否需要论文、标准、手册、网页或官方登记簿 |
| 保密 | 是否包含未申请的关键参数、配方、源代码或商业秘密 |

制药/化学/生物、通信标准或高校成果转化任务还必须读取`references/special_domain_gates.md`，执行结构/序列、参数、标准必要性和商业化边界检查。

## 关键词与分类构造

读取 `references/keyword_expansion.md`。对每个概念标注术语关系，禁止把相关概念伪装成同义词：

| 关系 | 用法 |
|---|---|
| 严格同义、缩写、拼写/旧称 | 可放入同一 OR 组 |
| 上位/下位概念 | 分别组成宽检索和窄检索，不默认混入同一组 |
| 功能、结构、应用、效果相关 | 作为独立 AND 块或补充检索切角 |
| 多语言术语 | 按目标库生成并回译核对；分类号作为跨语言补充 |

不要使用固定“最多8词”或未定义的“语义距离”。扩展多少由概念边界、结果抽样和验证集表现决定。记录每个扩展词的关系与来源。

IPC 不一律截断到4位：先用准确下位组查准，再用上位组补召回。CN实测格式为子类与主组之间保留空格，如 `H01M 10/0525`；客户端会自动修复常见紧凑写法。复合检索前先单独预检IPC；若为0条，先修复格式或回退上位组，不得把错误分类与关键词叠加后的0条解释为无现有技术。不同市场需分别验证。完整语法见 `references/query_syntax.md`。

## Bool 检索式质量闸门

除专利号精确查询、单一申请人盘点或用户明确要求的宏观态势统计外，**不得只用技术对象+宽泛功能词执行 Bool 检索**。技术检索式通常必须包含三个相互独立的 AND 块：

1. **技术对象**：产品、部件、材料或方法场景；
2. **核心机制/技术问题**：方案如何工作或具体解决什么问题；
3. **关键区别特征**：结构关系、步骤关系、控制逻辑、特定部件、参数范围或特殊技术效果中的至少一项。

信息不足以构造三个块时，使用两个高置信概念块并增加已验证的准确 IPC 或关系词组，不要用“系统、装置、方法、设备、处理、控制”等通用词凑数。CN普通关键词不保证短语匹配，中文可能按单字分析；引号不能替代结果抽样和详情核对。优先加入能排除同领域噪声的特征，顺序通常为：**关键关系/机制 > 特定结构或步骤 > 参数 > 特殊效果 > 通用场景词**。

执行前用下表自检：

| 项目 | 通过标准 |
|---|---|
| 独立概念块 | 通常≥3；每块表达不同技术维度 |
| 关键特征 | 至少1个，不得全部是上位或通用词 |
| OR扩展 | 只扩展块内同一概念，不把不同特征用OR混成一个块 |
| 精确限定 | 至少考虑一个关系短语、下位IPC、参数、日期或申请人条件 |
| 可解释性 | 能说明新增特征将排除哪类噪声 |

命中后执行强制收窄规则：

| 命中数 | 动作 |
|---:|---|
| 0-20 | 检查是否过窄；保留用于高精度块，并用其他块补召回 |
| 21-500 | 适合逐篇或分批核对 |
| 501-4,999 | 抽样5-10篇；噪声较多时增加一个关键区别特征后重检 |
| ≥5,000 | 判定为过宽，不得直接进入候选池；必须增加关键特征、已验证IPC或日期后重检 |
| 10,000或显示上限 | 视为截断结果，当前命中数不可用于统计或法律分析；必须收窄 |

收窄时先查看前5-10篇的噪声类型，一次性选择最有区分力的新增条件；不要机械堆叠多个低置信词。CN关键词块连续两轮仍显示上限或对象块未在前排原文出现时，不再追加中文词，改用已单独验证的IPC、关键日前公开日期、world/英文或语义召回。除宏观态势任务外，高精度块以可核对规模和前排质量为目标；显示10,000可能是计数上限，不能仅凭总量判断策略成败。

### 条件可观察性闸门

Bool请求成功或命中量下降，不证明新增AND块真正生效。每轮抽样前10篇，为每个对象、机制、区别特征及字段限定建立“条件—原文/字段证据”矩阵：

1. 只把题名、摘要、权利要求、说明书或对应结构化字段中可定位的原词、确认同义词或等价技术表达记为“可观察”；单字散落、模型联想和仅同领域不算命中该条件。
2. 任一必需条件在某篇中不可观察，该篇不得标为QX的H或FTO高覆盖候选；多篇结果不能拼成单篇覆盖。
3. 新增条件在前10中可观察率低于50%，或命中量下降但H率/H+M率未提高，判定该条件“检索约束无效”；不要继续沿同式加词，改用已验证IPC、字段过滤、英文/world、语义或另一特征组合。
4. `AP=`、`CC=`、日期和IPC等字段条件必须用返回的申请人、公开号、日期和分类字段逐篇反查。申请人统计同时要求“申请人命中”和“技术相关”两道门，不能因申请人正确就把无关专利计入竞品布局。
5. 高精度块即使命中少于5,000条，若前排必需条件可观察率或H率不合格，仍不得进入候选池或统计。反之，宏观调研的宽池必须拆成未截断分区并跨页分层抽样，不能只凭前10质量宣称可统计。

## 命令

### Bool 检索

```bash
# 中国库
python3 <skill-dir>/scripts/patseek_client.py bool '(固态电池 OR 全固态电池) (热管理 OR 温度控制) (相变材料 OR 冷却流道 OR 热失控预警)' --page-size 20

# 国际库与公开机构代码；CC 只过滤公开号前缀，不代表 FTO 法域有效性
python3 <skill-dir>/scripts/patseek_client.py bool '(solid-state battery) (thermal management) (phase-change material OR cooling channel) CC=(US OR EP)' --market world --page-size 20

# 正常翻页，不触发近似检索拦截
python3 <skill-dir>/scripts/patseek_client.py bool '(solid-state battery) (thermal management)' --market world --page 2
```

字段：`AP` 申请人、`IPC` 分类、`PID` 公开号、`AN` 申请号、`AD` 申请日、`PD` 公开日、`NOT` 排除、`CC` world 公开号前缀。`AN` 在 world 库可能无数据。

### 专利详情

```bash
python3 <skill-dir>/scripts/patseek_client.py patent CN118658342A
python3 <skill-dir>/scripts/patseek_client.py patent US10234567B2 --market world
```

详情缓存12小时。增强字段可能缺失或来自聚合源；法律状态用于筛查，不代替目标法域官方登记簿复核。

### 语义检索

```bash
python3 <skill-dir>/scripts/patseek_client.py semantic '完整且去标识化的技术描述' --timeout 180 --no-call-log
```

语义检索仅支持中国库。只把它用于召回不同术语的候选，不把相似度当作新颖性、创造性或侵权判断。失败、取消或超时必须报告为失败，不能解释为0条结果。

语义任务不限总次数，但默认串行提交，相邻两次提交至少间隔60秒；不要并发批量提交。每次使用不同的技术角度，并记录新增术语、分类和高覆盖候选；连续两轮无新增时停止该角度。

批量语义检索逐任务流式保存结果，不要等整批结束后一次性写出。单个任务失败或服务端超时时，记录任务ID、失败状态和已接收数量，保留此前已完成结果并继续后续独立角度；失败任务不能当作0条，也不能让整批证据丢失。需要重试时使用更窄或不同机制的描述，并继续遵守60秒提交间隔。

两个以上语义角度优先使用断点脚本。任务文件为JSON数组或JSONL，每项包含`id`和`query`；检查点不保存查询原文和Key，完整结果逐任务原子写入输出目录：

```bash
python3 <skill-dir>/scripts/semantic_batch.py semantic_tasks.json \
  --checkpoint semantic_checkpoint.jsonl --output-dir semantic_results
```

重跑相同命令会跳过已成功保存的任务；失败项会再次执行。不要把检查点或结果目录放入公开仓库，高度敏感方案仍先去标识化。

### 缓存与重复调用

- 相同查询优先命中缓存：Bool 15分钟、详情12小时、语义60分钟。
- `--no-cache` 表示明确要求最新数据，并跳过近似拦截；它仍会更新缓存。
- `--force` 只跳过近似拦截；不要用于翻页。
- 公共参数可以放在子命令前或后。

## 候选池与证据核对

查新时先读取 `references/adaptive_xy_search.md`，再读取 `references/evaluation_and_reporting.md`。执行以下硬约束：

1. 语义分只决定是否进入候选池；最终相关度以特征覆盖、关系、日期、证据位置和任务适格性为准。
2. 优先按同族聚合；若 API 只有同族数量而无成员清单，标注“无法完成同族去重”，不得假装已经完成。
3. 不固定只看 Top 20-30。至少覆盖各检索块结果并以“连续两轮/两页不再出现新关键分类、申请人、特征或引证线索”作为可解释的初步中止条件。
4. 每个要素记录：文献原文位置、权项/段落/附图、明确或隐含披露、日期角色、可信度。
5. 对新颖性，披露在权利要求、实施例或附图中并不形成机械强弱等级；判断是否由同一适格文献公开全部必要特征。
6. 对创造性，评价权利要求整体：最接近现有技术→区别特征及技术效果→实际技术问题→是否存在技术启示；禁止只给孤立特征评级。
7. 分别执行 QX、QY-Base 和按需执行 QY-Comp；不能用一条越来越窄的检索链同时替代 X 与 Y 文献检索。
8. 每轮抽样前10篇并记录 H/M/N/D、H率、H+M率、X/Y新增情况；下一式必须针对已观察到的噪声或缺失特征。

路线比较、低密度机会、申请前查新、FTO预筛或合作对象筛选形成结构化证据后，使用`scripts/decision_gates.py evidence.json`执行结论闸门。world证据还必须输入逐件`CC`前缀核验率与IPC/语言预检状态。脚本只判断证据是否足以支持相应标签，不替代专利代理人、市场或合作尽调判断。

交付Markdown报告前，用`scripts/report_guard.py evidence.json --output report.md`检查范围、检索式、样本、闸门和限制是否齐全。缺少字段、未解释的0条结果、FTO非候选筛查闸门或保证性结论会拒绝渲染；详情没有权项/段落位置时自动标为文本或字段代理，不得伪装为权项映射。

## 外部核验与限制

PatSeek 不能覆盖全部非专利公开、同族成员、审查档案和各国官方法律状态。任务需要时：

- 用可用浏览/检索工具查询官方专利登记簿、WIPO、CNIPA、EPO、USPTO 等；
- 按领域补论文、标准、产品手册、会议资料、网页和序列/化学数据库；
- 在报告中逐项列明“已检索/未检索/无法访问”，并提供来源链接和检索日期。

没有外部工具或权限时继续完成 PatSeek 范围内工作，但必须显著保留：“未检索非专利文献/未核验官方法律状态/未完成同族成员分析”。

## 结论纪律

禁止输出“已经具备新颖性”“不存在侵权风险”“全球无人申请”等保证性结论。使用：

> 截至[日期]，在[数据库、国家、语言和文献类型]及所列检索式范围内，未发现一篇在关键日期前公开并披露全部必要技术特征的文献。本结果不排除未公开申请、数据库缺口、非专利公开或术语差异造成的漏检。

FTO 还必须补充：

> 本次结果仅为候选权利筛查。是否影响实施须结合目标国家、计划时间、有效授权权利要求、官方法律状态及具体实施方案作专项法律分析。
