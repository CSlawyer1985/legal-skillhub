# Skill——上市公司治理（`gouvernance-emetteurs-cotes`）

面向科学目的的文献分析工具，主题为**法国上市公司的治理**。该 skill 以**带来源的分析索引**形式，汇集一组有年代的监管和学说语料（AMF 和 HCGE 2020-2025 年年度报告、AMF 学说、HCGE 2024-2025 年适用指南、AFEP-MEDEF 2022 年准则、ESMA 2025 年优先事项、Paris Europlace 2024 年指南、2025 年参议院报告、法律和欧洲文本——详见下文“已索引语料”），并能够对其进行还原、随时间分析并应用于具体发行人。

## 该 skill 的功能

三种用途，由共同的 **13 板块（A-M）** 分析网格支持：

1. **带来源的还原**——查找某项立场、统计或精确引文及其来源和页码。
2. **纵向分析**——比较某项立场或统计在时间上以及机构之间（AMF / HCGE / ESMA）的演变。
3. **发行人审计**——将 A-M 网格应用于某家公司，以其通用注册文件（DEU）为基础，并以已索引语料和互联网检索（学说、新闻、官方来源）补充。

## 示例（快速入门）

**用途 1——带来源的还原。**
*问题*：“据 AMF，2022 年有多少比例的公司对其董事会进行了评估？”
*典型回答*：据 AMF 2023 年报告（第 28 页），2022 年“样本中 92% 的公司”和“样本中 CAC 40 的 100%”进行了董事会评估（2022 会计年度；范围：AMF 样本，勿与 SBF 120 混淆）。如有后续发展，必要时以网页检索补充。

**用途 2——纵向分析**（时间轴摘录，主题“董事会评估”）：
- HCGE 2022 年报告，第 36 页：“所有公司均设立了董事会评估。”
- AMF 2024 年报告，第 36 页：向 21 家公司（其中 5 家 CAC 40）发出建议；18 家整改合规。

有日期的序列并置呈现，从不作定性评价。时间轴追溯至语料之前的起源，并通过网页检索纳入后续发展。

**用途 3——发行人审计**（示例性摘录；完整资料卡涵盖 13 个 A-M 板块，以发行人 DEU + 语料 + 网页为基础）：
- *B 板块——构成与独立性*：独立董事比例、资格理由、超过十二年的情形——每项认定均注明来源（报告 + 页码）并与 DEU 对照。
- *E 板块——薪酬 / 薪酬表决*：薪酬结构、企业社会责任标准、公平比率（第 L. 22-10-9 条）——数字在 DEU 和薪酬报告中核实。

每个板块均指向已索引语料（准确页码）和发行人的一手来源（链接）。

## 指导原则

- **客观聚合者姿态**：有来源的事实和趋势，无观点、无评价性形容词。
- **严格分类**：AMF（监管机构，公开点名）、ESMA 和 ANC（监管机构）、HCGE 和 AFEP-MEDEF（软法，原则上匿名化）绝不混淆。
- **文本还原**：逐字引用并注明准确页码；仅使用字面数字；每项点名提及均说明理由。
- **版权**：对受保护文件（HCGE、AFEP-MEDEF 准则）引用有限并注明来源；仅直接还原不受保护的客观事实。
- **J 板块（CSRD/ESRS 可持续性）**：风险较高的领域，受方法声明约束（适用批次、DPEF/CSRD 制度）。

已索引文件的准确清单（获取链接见 `references/sources.md`）：

## 分析网格（13 个板块 A-M）

A. 治理模式 · B. 董事会的组成与运作 · C. 继任与任命 · D. 各委员会（含风险监督）· E. 薪酬（含公平比率）· F. 股东大会与股东权利 · G. 财务补充 · H. 遵守或解释 · I. 股权结构与控制 · J. 可持续性（CSRD/ESRS）· K. 财务和非财务信息 · L. 投票顾问机构（proxy advisors）· M. ESG 评级与数据。

横向子板块“男女混合与多样性”；“新兴主题”栏目（网络安全、治理中的人工智能、专题研究）。

## 产出

该 skill 生成**发行人资料卡**和**主题资料卡**（Word），每张均注明来源，区分记录层级（已索引语料 / 一手网页来源 / 二手来源），附二手来源链接，并采用适合移动阅读的呈现。每份产出页脚载明：*“本资料卡使用 gouvernance-emetteurs-cotes skill 编制——© Gillan Saleh”。*

## 工具——核查或充实语料

该 skill 包含索引完整性和一致性检测器 `scripts/check_completeness.py`。它不修正也不评判任何内容：它**提示**需要对照源 PDF 核实的区域。在添加或编辑任何索引后，从 skill 目录运行：

```
python3 scripts/check_completeness.py .
```

五个检测器：
- **D1**——不完整的行内系列（同系列相邻项有引文而某一子项无引文）。
- **D2 / D2b**——骨架式子章节或单薄统计（仅设标题而无内容）。
- **D3**——「」引号不平衡（引文被截断或未正确闭合）。
- **D4**——替代性参见（“见图第 X 页”、“可索取”）[提示性]。
- **D5**——系列差异（年份异常单薄或密集）[提示性]。

提示不一定是自动错误：它是需要在来源处核实的点。**充实语料的方法**：在本地对 PDF 进行索引（切勿再分发——见 `NOTICES.md`），在 `references/sources.md` 中添加其官方链接，然后运行检测器。

## 由第二实例核验——验证代理

该 skill 内置生产者自检（`SKILL.md` 第 8 节清单）。但自我复核存在原则性弱点：是**同一个**代理在复核自己，而代理可能说服自己已核验其并未重新打开的内容。因此，保真保证不来自向生产者添加的指令——它来自一个**中立、全新的第二实例**，它不知道生产者相信自己核验了什么。

由此形成一个简单协议，由使用者自己以**两次连续请求**编排：

1. **生产者**——第一实例使用该 skill 制作资料卡。
2. **验证者**——在**全新对话**中，第二实例收到资料卡和来源，只有一项任务：逐项认定地审计保真度。它不重写、不补充、不改进——它核验并制作一份**证明表**。

独立性不是宣告出来的：它在于验证者是独立实例这一事实。skill 本身无法援引真正独立的验证者；是用户通过发起第二次请求来创造这种分离。验证标准只有一句话：**“把那一页给我看。”**

### 保真审计协议（粘贴到新对话中）

```
你是验证代理，独立于制作下述文件的代理。你唯一任务是审计其相对于来源的保真度。你不重写、不补充、不改进：你核验。

待审计文件：[粘贴资料卡]
参考来源：[可访问的 skill / 索引 / PDF]

方法，无例外：
1. 提取每一条事实性认定：每个数字、每段引号内引文、每个所引页码、每个公司或人名、每个日期、每个法律条款、每个章节编号。
2. 对每一条，重新打开来源（索引或 PDF）并找到准确段落。不依赖被审计文件，也不依赖记忆。
3. 为每项认定提供一行证明：认定原文 | 来源（报告 + 页码）| 源文本原文 | 状态。
4. 状态：CONFORME（源文本逐字/逐数确认）；ÉCART（任何差异，即使微小：引号内改写、页码不同、数字近似、添加或删去修饰语、章节编号未确认）；INTROUVABLE（认定在来源中不存在）。
5. 对于来自网页的事实：核实链接来自真实来源，数字得到第二独立来源或一手来源的印证，且会计年度和范围正确。

阻断规则：任何差异都是违规。仅一条 ÉCART 或 INTROUVABLE 状态的认定即足以拒绝文件。只要有一行不属 CONFORME，不得得出“符合”结论。如某项认定不在来源中，明确说明——不为其辩护，不加以修补。

交付物：完整的证明表，然后一行结论——VALIDÉ（全部行符合）或 À CORRIGER（差异或无法找到的认定清单）。
```

### 证明表格式

| 认定（原文） | 来源（报告 + 页码） | 源文本原文 | 状态 |
|---|---|---|---|
| “2021 年 CAC 40 中有 13 项决议被否决” | AMF 2021，第 26 页 | “2021 年有 13 项决议被否决（2020 年为 4 项）” | CONFORME |
| “终止了这一咨询性呈现” | AMF 2023，第 56 页 | “该公司终止了其职务合一做法” | ÉCART |

`check_completeness.py` 检测器（见上文）与验证代理互补：前者**机械地提示**需要对照 PDF 核实的区域；后者**审计**成品相对于来源的保真度，逐项认定，从独立实例进行。
