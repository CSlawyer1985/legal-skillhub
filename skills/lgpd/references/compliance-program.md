## 2. 处理活动记录（RoPA）模板

*依 LGPD 第 37 条和 ANPD 第 2/2022 号决议*

| 字段 | 描述 |
|-------|-------------|
| 处理活动名称 | 例如“客户账户管理” |
| 控制者 | 法定名称、CNPJ |
| DPO 联系方式 | 姓名、电子邮件、电话 |
| 处理者 | 如适用——名称、CNPJ、角色 |
| 目的 | 特定、合法的目的 |
| 法律依据 | 第 7 条或第 11 条依据；如为合法利益，附权衡测试引用 |
| 数据类别 | 例如身份、财务、健康、生物识别 |
| 敏感数据？ | 是/否；如为是，第 11 条下的依据 |
| 儿童数据？ | 是/否；同意机制 |
| 数据主体 | 类别：客户、员工、供应商等 |
| 接收方/共享 | 内部部门；外部第三方 |
| 国际转移 | 国家；转移机制 |
| 保留期限 | 期限；保留或删除的依据 |
| 安全措施 | 技术和行政措施摘要 |
| RIPD 引用 | 如已进行 DPIA/RIPD——引用编号 |
| 最后更新 | 日期 |

## 3. 数据主体请求（DSR）程序

### 第 1 步——接收
- 提供可访问的请求渠道（网络表单、电子邮件、当面）
- 记录每项请求：日期、请求人身份、请求类型
- 在 1 个工作日内发送确认

### 第 2 步——核验身份
- 要求最低限度的必要身份证明（姓名 + CPF + 账户引用）
- 不要要求过多文件——与风险相称
- 代表他人提出的请求：要求有效授权委托书

### 第 3 步——对请求分类
| 请求类型 | LGPD 条文 | 典型回应 |
|-------------|-------------|-----------------|
| 处理确认 | 第 18 条第 I 项 | 立即（简化） |
| 数据访问 | 第 18 条第 II 项 | 15 天（完整报告） |
| 更正 | 第 18 条第 III 项 | 不无故迟延 |
| 匿名化/封存/删除 | 第 18 条第 IV 项 | 不无故迟延 |
| 可携性 | 第 18 条第 V 项 | ANPD 格式（待定） |
| 删除基于同意的数据 | 第 18 条第 VI 项 | 不无故迟延 |
| 关于共享的信息 | 第 18 条第 VII 项 | 不无故迟延 |
| 拒绝同意的后果 | 第 18 条第 VIII 项 | 不无故迟延 |
| 同意撤销 | 第 18 条第 IX 项 | 不无故迟延 |
| 自动化决定审查 | 第 20 条 | 经请求 |

### 第 4 步——评估豁免
控制者可在以下情形拒绝（第 18 条第 3 款）：
- 数据主体或第三方将受到损害
- 国家安全
- 金融情报或财政活动
- 刑事/民事调查
- 公共实体的经济或财务保护
必须告知数据主体所适用的豁免及向 ANPD 投诉的权利。

### 第 5 步——回应
- 免费
- 清晰、可访问的语言
- 简化回应立即作出；完整访问报告 15 天内作出
- 记录回应并保留记录

## 4. 数据保护影响评估（RIPD）模板

*Relatório de Impacto à Proteção de Dados Pessoais——LGPD 第 38 条*

### 第 1 节——处理描述
- 处理活动的名称和目的
- 法律依据（第 7 条或第 11 条）
- 个人数据类别和数据主体
- 处理的量和频率
- 所用系统和科技
- 涉及的第三方（处理者、次处理者）
- 国际转移

### 第 2 节——必要性和比例性评估
- 处理对所述目的是否必要？
- 是否可以用更少的数据实现目的（必要性原则）？
- 保留期限是否相称？
- 匿名化或假名化能否降低风险？

### 第 3 节——风险识别
| 风险 | 可能性 | 影响 | 风险等级 |
|------|-----------|--------|-----------|
| 未经授权访问 | 高/中/低 | 高/中/低 | 高/中/低 |
| 数据丢失或删除 | ... | ... | ... |
| 非法披露 | ... | ... | ... |
| 歧视性使用 | ... | ... | ... |
| 数据不准确 | ... | ... | ... |

### 第 4 节——缓解措施
针对每项已识别风险：
- 拟实施的技术措施
- 行政/流程措施
- 缓解后的残余风险
- 责任方和实施日期

### 第 5 节——DPO 意见
- DPO 姓名和审查日期
- DPO 建议：进行 / 附条件进行 / 不进行
- 条件/建议（如适用）

### 第 6 节——管理层批准
- 控制者代表签名和日期
- 决定：进行 / 修改 / 取消处理

## 5. 泄露通知模板

### 初步 ANPD 通知（3 个工作日内）
*ANPD 第 15/2024 号决议*

**门户：** https://www.gov.br/anpd/pt-br/assuntos/incidentes-de-seguranca

所需字段：
- 控制者识别（名称、CNPJ、DPO 联系方式）
- 事件发现日期；通知提交日期
- 事件描述（发生了什么）
- 受影响数据的近似类别
- 受影响数据主体的近似数量
- 已采取的即时遏制措施
- 初步风险评估

### 完整 ANPD 报告（20 个工作日内）
附加字段：
- 根本原因分析
- 受影响数据的完整范围（类别、数量）
- 受影响系统/地区的完整清单
- 已实施的所有纠正和预防措施
- 向数据主体的沟通（如要求）
- 更新后的风险评估

### 数据主体通知（如要求）
在以下情形通知：可能对数据主体造成重大损害时（第 48 条第 1 款）

内容：
- 事件的性质
- 哪些数据受到影响
- 对数据主体的风险
- 控制者已采取的措施
- 咨询联系人（DPO）
- 如何行使权利

## 6. DPO（Encarregado）职位描述

### 法定职能（第 41 条第 2 款）
1. 接受数据主体的投诉和沟通
2. 接收 ANPD 的沟通并采取必要行动
3. 指导员工和承包商遵守 LGPD 义务
4. 履行控制者或 ANPD 定义的其他职责

### 建议的附加职能
- 维护和更新 RoPA
- 协调 DPIA（RIPD）
- 监测 ANPD 监管更新
- 开展或监督 LGPD 培训
- 审查新产品/服务的隐私合规性
- 管理数据主体权利请求
- 协调泄露响应
- 就 LGPD 事务与法律顾问联络
- 为管理层编制年度 DPO 报告

### DPO 公布要求（第 41 条第 1 款）
控制者必须公布 DPO 的身份和联系方式——通常在：
- 公司网站（隐私政策页面）
- 隐私通知/ cookie 通知
- 任何收集个人数据的表格

### DPO 豁免（ANPD 第 2/2022 号决议）
处理活动风险较低的微型和小型企业（ME/EPP）可豁免强制任命 DPO，但仍必须为数据主体指定联系人。
