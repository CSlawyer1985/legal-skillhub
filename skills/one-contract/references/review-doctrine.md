## 一、审查的工作对象

合同审查不是从文本中寻找错误，而是判断一套交易安排能否实现当事人的真实目的，并把判断落实为可签、可谈、可履行、可举证的文本。标题、行业惯例和模板只提供起点；事实、立场、议价能力、履行阶段和相邻条款可以改变最佳方案。

审查同时处理三个对象：

1. 交易：主体、标的、对价、资源、程序、履行和退出是否成立；
2. 文件体系：主合同、附件、订单、制度、外部许可和优先顺序是否一致；
3. 条款机制：权利义务、证据、救济和风险分配是否形成闭环。

## 二、四类边界与三层自由度

### 1. 硬边界

- 事实真实性：不得创造材料未支持的金额、日期、状态、承诺或共识。
- 法律边界：不得以措辞包装违反强制性规定、规避法定义务或虚假确认。
- 用户授权：不得替用户作结构性商业选择或超越明确立场与底线。
- 文档完整性：不得以损坏、不可加载、静默失败或无法回滚的文件交付。

硬边界低自由度。事实不全时使用占位符、条件句、程序机制或升级，不用想象填空。

### 2. 专业原则

审查目标、利益衡量、风险排序、立场倾向和默认动作属于中高自由度。参考资料给出专业起点和推翻因素，审查者必须结合具体交易重新推理。

### 3. 示例资源

推荐措辞、历史修订、谈判案例和反例是高自由度材料。可借鉴结构和尺度，不机械复制，也不因示例没有覆盖某事实而停止审查。

## 三、交易画像

在条款审查前形成一段可复核画像：

- 交易实质与合同阶段；
- 我方、对方及受影响第三方；
- 我方希望实现的核心结果和可接受退路；
- 谁控制付款、交付、验收、数据、证据和退出；
- 当前文本在关键利益维度上偏向谁；
- 现实议价能力、时间压力和执行能力；
- 已知事实、未知事实、冲突材料和关键附件。

画像不需要伪造精确分数。只有当数值能帮助比较且已有校准数据时才使用数值模型，否则用有依据的强/中/弱或方向性描述。

## 四、宽识别与证据分级

### 1. 宽识别

只要某项权利义务、失败机制或条款缺失可能相关，就进入分析。事实充分度用于决定动作，不作为“是否看见”的门槛。

### 2. 证据状态

| 状态 | 含义 | 专业责任 |
|---|---|---|
| `confirmed` | 材料足以支持事实和方案 | 形成明确文本并处理联动 |
| `reasonable_assumption` | 主方案可成立，但有变量待核 | 形成文本，同时公开假设和替代路径 |
| `major_choice` | 事实或授权会改变结构性方案 | 给出选择框架和必要保护，要求决定 |
| `not_applicable` | 事实足以排除 | 不制造无意义修改，保留内部理由 |

证据状态不是风险等级。高风险也可能处于 `reasonable_assumption`，此时通常需要保护性修订加批注；低风险也可能因事实完全不明而只批注。

## 五、原则卡的用法

每个核心议题优先按以下问题思考，不要求机械填满字段：

### 审查目标

说明要保护的利益、要避免的失败模式，以及它与交易目的的关系。

### 判断坐标

列出会改变方向或强度的事实，例如我方角色、控制力、替代方案、履行阶段、可得证据、对方实际能力。这些是观察维度，不是必须同时满足的触发器。

### 默认倾向

在典型事实和当前立场下，给出通常更稳妥的处理方向。默认必须可推翻。

### 推翻因素

说明哪些事实、相邻条款、监管要求、授权或谈判结果足以改变默认。

### 硬边界

标出事实真实性、法律强制性、授权和文件工程边界。

### 可接受变体

提供不同风险和谈判强度下的结构路径，不固定唯一句式。

### 动作建议

把证据状态、风险和交易阻力转换为直接修订、修订加批注、仅批注或不输出。

## 六、条款联动

不得把条款当作孤立句子。至少检查下列机制组：

- 标的、交付、验收、付款、开票和所有权/风险转移；
- 变更、通知、证据、违约、暂停、解除和终止结算；
- 陈述保证、赔偿、责任限制、保险和担保；
- 保密、数据、知识产权、返还删除和存续；
- 主合同、订单、附件、技术规范和外部制度文件；
- 劳动解除中的解除事由、结算、交接、证明、社保公积金、竞业和权利终结。

修改一个节点后，反向检查前提、定义、时间、金额、救济和存续条款。审查报告与修订稿不得采用不同的交易机制。

### 义务清单法：先提取，再逐条审

**这一步与上面的联动检查不是同一件事**，且顺序在它之前：

- **联动检查**回答"改了一处，相邻条款要不要跟着改"——是**一致性**核查；
- **义务清单法**回答"双方到底各自承担了什么、有没有漏"——是**完备性**核查。

起草与审查都容易犯一个错：**按条款顺序逐条读下去**。而义务在合同里是**散落的**——
一方交付货物的义务可能在"标的"条、"交付"条、"包装"条、"售后"条里各写一半；
对方的付款义务又可能分在"价款""付款节奏""发票""验收"四处。逐条读会**看不到全貌**。

**做法**：在进入逐条审查之前，先做一遍提取——

1. 拉一张两列表：**我方义务** ｜ **相对方义务**；
2. **遍历全部条款**，把每一条里隐含的义务抽出来填进去（含时限、条件、程序、方式）；
3. 分别与**合同目的**对照：
   - 我方义务里，有没有**超出自身履约能力**的？（这是己方违约的根源）
   - 相对方义务里，有没有**不足以支撑我方合同目的**的缺口？
4. **补缺与调整在清单上先完成，再回正文落笔**。

**为什么要在清单上先完成**：在正文里边读边改，容易被措辞牵着走；
在清单上先看清楚"两边各欠什么"，再回正文，改的是结构而不是句子。

**与 3.4 的分工**：`common-clause-doctrine.md` 3.4 给的是"往哪看"（对己方看义务、对相对方看义务）；
本节给的是"怎么看全"（先提取成表，再逐项核对）。

## 七、风险、立场与交易阻力

风险等级表示事项的重要性，不代表必须采用最强写法。行动强度同时考虑：

- 失败后果与发生路径；
- 法律和事实确定性；
- 我方身份、底线及可交换条件；
- 对方接受概率和交易时点；
- 执行、举证和维护成本；
- 相邻条款是否已有等价保护。

强硬文本可能提高保护，也可能造成谈判锚定、重复审阅和信任损耗。控制无意义修改，但不得以“促进交易”为由弱化强制边界或隐瞒重大风险。

### 涉税建议口径

涉税问题常与合同对价、交易结构和条款效力绑定（如股权转让对价、同一交易多文本、税费承担、发票与代扣代缴）。税务不是本审查的专业领域，统一口径是**给建议、不给断言**：

- 以建议性措辞提示风险与处理方向，能引用具体规则（条文、公告）就引用，例如“建议按实际对价如实申报，避免被税务机关按公平交易原则核定补税”；
- 不使用“请咨询税务专业人员”“需税务复核”等免责套话作为默认输出；
- 不把税务结论写成“税务机关必然如何”的断言；引用具体规则时说明这是规则可能导致的后果，最终口径以实际申报与专业复核为准；
- 涉税内容统一收进审查意见书末尾 `【涉税建议】` 区块，正文修订中不夹带税务判断。

### 结构触发器与动作强度

确定性检查（如股权转让结构触发器、类案信号）命中时，是**提升审查强度与证据核验的信号**，不是自动阻断一切修订的开关。动作仍按证据分级决定：

- 证据充分且属合规方向 → 直接修订（附必要批注）；
- 证据不足 → 修订＋批注，未知项用占位符/条件句；
- 涉及客户重大选择 → 仅批注＋报告讲清后果与备选。

阻断只针对“让文本更隐蔽”的违规划避方向（隐瞒真实对价、虚构款项等），不针对“让文本更真实/合规”的修订。

### 结构性失效的分级

导致条款无法生效、或核心利益在交割时点失控的结构性问题（如生效条件自相矛盾、付款与股权/资产交割脱节且无救济机制），应列为 **P0**，不因交易尚在草拟阶段而降级。草拟稿中的待填信息（姓名、价款、日期、账户等）则属“待填”而非结构性风险，按统一占位符约定处理。

### 条款联动冲突直接落笔

当同一交易内的条款对同一事项口径冲突、且文本已写明事实时（如“资产归甲方处置”与“乙方取得完整控制权”矛盾），属 `confirmed`：应**直接落笔统一口径**（如“资产按《资产清单及剥离方案》处理，不得在交割后由甲方继续处置”），批注只说明改动影响与备选；不得以“请确认最终口径”类批注代替正文修订。

### 审查意见书统一结构

审查意见书（review-report）采用**公文简洁版式**（黑白、无彩色装饰），内容顺序固定为：

1. 标题；
2. 致／审查对象一句话简介；
3. 正文（一、合同概况；二、综合审查意见；三、重要风险提示等）；
4. `【待填事项汇总】`：列出全部 `【待填：事项】` 及填写动作；
5. `【涉税建议】`：汇集全文涉税提示，一律用建议性措辞。

`【待填事项汇总】` 与 `【涉税建议】` 两区块放在意见书**末尾**（修订稿文首仍保留单处汇总批注）。意见书为对外交付件：不做 DOCX 落痕/质量门等技术披露，不出现"元数据统一置于正文之后""首屏呈现"等规则性说明文字。

## 八、一致性与可追溯性

每项实质建议至少能追溯到以下一种依据：

- 法律或监管硬边界；
- 已说明法域和状态的专业原则；
- 经确认的对照案例；
- 明确标注为模型对当前交易的独立判断。

可追溯不等于必须命中一条固定规则。记录“为什么在这份合同里这样改”比记录“命中了哪个关键词”更重要。

最终复核比较五个视图：原文、review plan、审阅件接受视图、批注、审查意见书。任何重大矛盾都阻断交付。

## 九、审查结果的五标准验收

前面的章节回答「怎么审」，本节回答「审完的结果算不算合格」。

**它不是审查技术，是交付前的验收清单。** 一份审查意见按这五条回看一遍，比再读一遍合同的收益高。

### 五条标准

| 标准 | 管什么 | 不合格的后果 |
|---|---|---|
| **合规性** | 能不能用——效力与违法责任的底线 | 无效、不成立、可撤销；或虽属有效但招致行政责任 |
| **周延性** | 全不全——有无漏项 | 缺绝对必要条款致合同不成立；缺相对必要条款致履行争议 |
| **可操作性** | 顺不顺——能否实际履行 | 表述含糊、义务无时限、判定依据缺位、履行顺序自相矛盾 |
| **公平性** | 权责是否相对平衡 | 一边倒到越过公平边界，落入可撤销情形 |
| **倾向性** | 偏向谁、偏多少——立场与幅度 | 倾斜过度，与公平性同时失守 |

**倾斜不等于不公平，但两者共用一条边界。** 倾向性是**立场问题**（我方该争多少），公平性是**边界问题**（争过头会被推翻）。审查时先按立场把倾向做到位，再用公平性回看是否越界——顺序颠倒会让人不敢争。

### 与「证据状态」的关系：两条正交的轴

现有「证据状态」（`confirmed` / `reasonable_assumption` / `major_choice` / `not_applicable`）管的是**能落什么笔**；五标准管的是**审完的结果好不好**。二者不可互相替代：

- 证据充分但审得草率 → 五标准不合格；
- 证据不足但如实标注假设、并用条件句与程序机制承载未知 → 五标准可以合格。

### 分级用法

- **合规性不合格 = 阻断级。** 合同不能用的，先解决效力问题，不要在措辞上打转；整体无效的直接告知委托人，无须修改文本。
- **周延性 / 可操作性不合格 = 须修改级。** 这是绝大多数审查意见的落点。
- **公平性 / 倾向性 = 谈判级。** 不合格不必然阻断交付，但必须在报告中说明立场、幅度与可退让空间。
- **文字层面（用字、标点、释义、编号一致）= 格式级。** 单独归集，不与实质意见混排——混排会稀释实质问题的可见度。

### 五标准同时是一条风险归属分界线

五标准不分配交易风险，但分配**审查质量的风险**——「审完了还出事」由谁负责。分级那一栏换个读法就是这个答案：

- **合规性归审查方**：合规风险不允许用「当事人同意」消化。当事人同意不能使无效变有效，所以这一条审查方必须自己拦下，不能交回委托人。
- **公平性／倾向性归委托人**：这两条是商业取舍，审查方的义务是**摆明**（争了多少、可退到哪里），不是替委托人决定。
- **周延性与可操作性两边共担**：审查方须提示并给出可执行方案，委托人须提供事实。

**这条分界线解释了本节与「证据状态」为什么必须正交**：证据状态管「审查方能说什么」，五标准管「说完之后谁担责」。把两者混为一谈时，最常见的错误就是把**证据不足**当成可以不表态的理由——那是拿「能说什么」的问题去回答「谁担责」的问题。证据不足时正确做法是如实标注假设并给条件句方案（见上节），风险归属不变。

### 边界

- **五标准是回看用的，不是逐条打分表。** 审查意见按五维归类即可，不必给每一项评分；打分会把注意力从判断转移到计量。
- **不替代具体判断。** 五标准提高漏项被发现的概率，但不告诉你「这一条该怎么改」——具体方案仍须回到原则卡与条款模块。
- **不得以「周延」为名堆砌条款。** 为了凑齐「全」而加入不解决任何失败模式的条款，本身就是失真（见次节）。
- **不得以「倾向」为名突破合规性。** 立场再强也不能改变效力底线；这一条与第二节「四类边界」中的法律边界同源。

## 十、常见失真
