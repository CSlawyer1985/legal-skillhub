## 已实现的运行机制

1. 分类画像增加 `primary_domain_code` 和 `secondary_domain_codes`。
2. 资产选择结果分层返回 `global_rules_applied`、`domain_principle`、`type_principles`、`modules`、`coverage_level`、`coverage_notice` 和 `shadow_domain_metadata`。
3. 只有主类型、主大类和角色达到执行门槛时，才允许加载 active 大类卡；中低置信、角色未知或主大类未确认时只返回候选元数据并请求确认。
4. 混合合同只执行已确认的主大类，辅大类只提示人工确认，不加载其规则或模块。
5. 全局事实真实性、强制性法律、用户授权和文档完整性边界不可被下层覆盖。具体类型规则仅在明确适用范围内优先于大类默认；类型规则与大类硬边界实质冲突时输出 `rule_conflict` 并转人工。
6. 大类卡的 `module_index` 只帮助发现议题，不复制条款正文，也不改变被引用模块的批准或激活状态。
7. P0 继续采用定向阻断；材料缺失或待填事项本身不自动升级为 P0。股权转让保持正式 active，商品房预售许可保持“先核验事实、再限定阻断范围”的三层门。
8. `【待填事项汇总】` 与 `【涉税建议】` 继续统一放在审查意见书末尾。

## 法律筛查状态

EC-01 至 EC-09 已于 2026-09-13 通过项目侧元典检索完成最低限度现行法方向筛查，共九次检索。该筛查不包含 API、密钥或调用配置，也不随 Skill 打包原始检索归档。

最低限度筛查不等于律师批准或激活前的最终法律核验，因此九张候选卡的 `legal_checked_at` 仍为空。其中：

- EC-07 本轮结果不足以完整覆盖现行担保制度，激活前须围绕《民法典》担保制度及现行担保司法解释重新作精确条文核验；
- EC-09 的广告真实性方向已有现行法支持，但转售价格限制未被本轮结果充分命中，激活前须以《反垄断法》及纵向垄断协议规则精确复核；
- EC-10 没有实质候选规则，不以全局通用规则换名填充，也不进行虚假的领域法律核验。

## 验证状态与剩余工作

第二层结构、目录、路由、选择器和候选隔离已经通过自动化回归。建设时共通过 42 项 Skill 内测试和 93 项项目测试；该结果证明当时的实现基线通过，不代替每张卡的独立内容审查和合同样本回归。

建议依次审核：

1. EC-02、EC-04：先确认抽象尺度和运行接口；
2. EC-01、EC-05、EC-06、EC-07、EC-08：处理监管和强制性边界较多的领域；
3. EC-03、EC-09：重点确认有限覆盖和禁止外推范围；
4. EC-10：只确认知识缺口及后续研究簇。

每张实质卡必须独立完成：

`candidate → lawyer_approved → regression_passed → active`

进入 `lawyer_approved` 前，应逐条确认审查目标、判断坐标、默认倾向、适用条件、推翻因素、领域硬边界、证据要求、模块索引和禁止外推事项。进入 `active` 前，还须填写审核人、审核日期和最终法律核验日期，并至少完成一个已有 active 类型样本、一个无 active 类型样本、一个低置信或混合交易样本的影子对照。EC-10 在形成独立来源和实质规则前不得激活。
