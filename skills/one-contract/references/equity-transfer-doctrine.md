# 股权转让专项审查原则

## 当前用途与资产状态

本文件是 `EC-01-001 / type-equity-transfer` 的正式专项原则。该类型及其经批准资产为 `active`，可由 `select_active_assets.py` 在角色、场景和依赖条件满足时加载。股权转让已完成去试点化，不再使用“候选试点”作为运行时定位。

正式资产包包括：原则卡、8个条款模块、3个联动组、4个结构性异常触发器、6张脱敏经验卡、23项来源记录和1份实质交易协议 DOCX 基础骨架。

## 先过结构触发门

股权转让审查先建立交易事实表，至少核对：

- 全部主协议、补充协议、确认函和相关付款安排；
- 每份文本的标的、总对价、用途、签署时间及取代关系；
- 实际资金流、申报价、估值和会计处理；
- 标的股权的认缴、实缴、期限和瑕疵；
- 对外转让通知、同等条件、章程限制和收悉/放弃证据。

可用 `scripts/knowledge/detect_equity_transfer_triggers.py --facts <事实JSON>` 对结构化事实运行确定性检查。脚本不根据关键词推定违法；材料缺失时返回人工确认但不单独定为 P0；P0 命中时返回 `directed_block_required`，仅阻断触发器列明的规避性输出，不阻断“让文本更真实/合规”或不依赖缺失事实的修订方向。

## 多文本和价格不一致

多文本对价不一致（如实际对价与备案/申报文本不一致、低价申报）是**风险提示点，不是自动改文阻断点**。审查不代替业务执行者判断“应否如实申报、应否接受低价申报”，而是：

- **列明当前可能风险清单**：两套文本对价差异及勾稽关系；低价申报可能被税务机关按公平交易原则核定转让收入并补税的风险；虚假申报的责任后果；备案文本“仅作过户使用”不能消除申报与披露风险的边界；备选处理方向（如实反映真实对价 / 接受低价申报但留存正当理由并安排兜底 / 其他）。
- **不阻断自动改文**：正文修订仍按证据状态正常落笔，不因命中多文本不一致而拒绝改文；是否接受、如何选择，由业务执行者基于风险清单**自行决断**。
- 涉税内容用建议性措辞、收进意见书 `【涉税建议】` 区块。

### 动作政策：触发器命中只提高强度，不自动阻断

按四态证据分级决定动作，触发器命中是强度信号而非阻断信号：

| 证据状态 | 触发器命中时的动作 |
|---|---|
| `confirmed`（文本已写明两套文本关系） | 正常修订＋批注/风险清单 |
| `reasonable_assumption`（申报口径等仍未知） | 修订＋批注，未知项用 `【待填：…】`/条件句 |
| `major_choice`（客户选择申报口径等） | 批注＋风险清单，由业务执行者决断 |
| `not_applicable`（证据足以排除风险） | 不输出 |

**条款联动冲突直接落笔**：同一交易内条款对同一事项口径冲突且文本已写明事实时（如“资产归甲方处置”与“乙方取得完整控制权”矛盾），属 `confirmed`，直接落笔统一口径，批注只说明影响与备选。

### 立场相关判断（尽调确认与权属保证）

尽调确认能否替代权属/出资/未披露负债保证，**取决于我方身份**：

- **受让方立场**：尽调确认**不**替代转让方的权属、出资、未披露负债保证——保留完整保证更有利；
- **出让方立场**：尽调确认**可以替代或减轻**权属保证，以减轻自身义务——对出让方有利。

审查按我方身份选择相应默认倾向，并在批注/意见书中说明立场依据。

登记或备案表单是实施文件，不是第二套独立交易模板。即使实质协议约定其优先，也只能解决当事人内部的文件解释，不能自动消除真实价款申报、付款证据或对外披露风险。系统不得从登记备案表单提取母版，只能把它与实质协议逐字段核对。

## 专项审查顺序

1. 标的股权与出资状态；
2. 全部真实对价与付款；
3. 多文本、资金、估值、申报与会计一致性；
4. 优先购买权、章程和公司程序；
5. 先决条件、付款、股东名册和登记交割；
6. 陈述保证、披露、一般赔偿与专项赔偿；
7. 治理和控制移交。

不得孤立使用某一条款模块。具体依赖和冲突以 `module_group_catalog.json`、`module_catalog.json` 为准。

## 来源边界

`source_catalog.json` 保存公开来源元数据和内部脱敏汇总登记，不保存公众号、律所文章或客户模板全文。`wechat_practice_article_local_fulltext` 只用于审查维度、谈判经验和案例线索，法律边界仍由官方法源控制；`wechat_practice_article_discovery` 仅为后续取得正文的发现记录，不得用于法律结论。运行时只使用目录中状态为 `active` 的来源与提炼结论；其余状态仍受知识资产治理门约束。
