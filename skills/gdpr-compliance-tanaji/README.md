# GDPR 合规

一个充当专家级 GDPR 合规助手的 Claude skill——将深入的监管知识与实用的技术理解相结合，帮助团队构建、记录和审计隐私合规系统。

---

## 该 Skill 做什么？

本 skill 赋予 Claude 四项独特能力，每当出现 GDPR 或数据隐私话题时自动激活：

**1. 代码与系统审计**——审查代码、数据库架构、API 设计和架构描述是否存在 GDPR 违规。产出一份结构化审计报告，发现按严重程度分级（🔴 高 / 🟡 中 / 🟢 低），每项映射到被违反或存在风险的具体 GDPR 条款。

**2. 文档起草**——从内置模板生成可直接定制的 GDPR 合规文件，包括隐私通知、数据处理协议（DPA）、Cookie/同意横幅、数据保护影响评估（DPIA）、数据留存政策和数据主体权利程序。

**3. 合规问答**——使用结构化格式回答 GDPR 问题并附权威条款引用：先直接回答，然后是管辖条款、任何例外和实际影响。

**4. 数据流与 PII 审查**——从六个维度（什么、为何、何处、谁、保存多久、如何保护）分析数据流和 PII 处理实践，核验与处理活动记录（RoPA）要求的一致性，并产出一份 PII 处理检查清单。

所有回答都引用相关 GDPR 条款——例如："同意必须自由给予、具体、知情且明确（第 7 条；序言 32）。"

## 目标受众

本 skill 为经常需要就 GDPR 合规协作的两类主要受众设计：

**开发人员与工程师**

- 处理个人数据的后端和全栈工程师
- 管理存储 PII 的基础设施的 DevOps / 平台工程师
- 评估技术控制措施的安全工程师
- 设计跨系统或跨境数据流的架构师

**法律、合规与隐私专业人士**

- 数据保护官（DPO）
- 公司法务和隐私律师
- 进行审计的合规经理
- 推行 GDPR 框架的隐私项目负责人

该 skill 自动调整语气——对开发人员侧重技术和代码，对合规和法律专业人士则法律上精准。

## 如何使用该 Skill

### 安装

1. 下载 `gdpr-compliance.skill`
2. 在 Claude 中，前往**设置 → 技能**
3. 点击**上传技能**并选择该文件
4. 该技能现在在您的 Claude 会话中处于激活状态

### 触发该 Skill

当您提及 GDPR 相关话题时，该技能自动激活。您无需任何特殊命令。可触发它的示例提示：

- _"Is this code GDPR compliant?"_（这段代码符合 GDPR 吗？）
- _"Draft me a privacy policy for [my app]"_（为[我的应用]起草一份隐私政策）
- _"What lawful basis should I use for analytics?"_（我应该为分析使用什么合法依据？）
- _"Review our data flow diagram for GDPR gaps"_（审查我们的数据流图是否存在 GDPR 缺口）
- _"What does a DPA need to include under Art. 28?"_（根据第 28 条，DPA 需要包含什么？）

### 获得最佳结果的提示

**代码审计**——直接粘贴相关代码、架构或架构描述。您提供的上下文越多（技术栈、数据主体、处理目的），审计就越精确。

**文档起草**——准备好提供：您组织的名称和角色（控制者/处理者）、涉及的个人数据类型、处理目的、任何第三方或次级处理方，以及数据转移的目标国家。

**问答**——直接提问。该技能将先以管辖条款回答，然后解释例外和实际步骤。

**数据流审查**——描述或图示您的数据管道：什么数据进入、流向何处、谁可以访问、保存多久。

### 范围与限制

- 涵盖**欧盟 GDPR**和**英国 GDPR**——已针对**《2025 年数据（使用与访问）法》**（DUAA）更新，该法引入了公认合法利益、不同的国际转移测试和高级负责个人（SRI）角色；英国充分性认定于 2025 年 12 月续期至 2031 年 12 月
- **不**涵盖 ePrivacy 条例、CCPA 或其他非欧盟隐私法律（但可能注明相似之处）
- 回答是**信息性指引**，而非法律意见——高风险决策应始终由合格的 DPO 或数据保护律师审查
- 该技能会在事项需要专家法律顾问时予以标记

## Skill 实现细节

### 架构

```
gdpr-compliance/
├── SKILL.md                    # 核心技能——四项工作流定义 + 触发规则
└── references/
    ├── documents.md            # 六个文档模板（隐私通知、DPA、同意
    │                           #   横幅、DPIA、留存政策、DSR 程序）
    ├── privacy-notice.md       # 独立的第 13/14 条隐私通知参考
    ├── dpa-template.md         # 独立的第 28 条 DPA 参考，含当前转移
    │                           #   机制（EU-US DPF、2021 SCC、英国充分性）
    └── updates-2025.md         # 2024-2026 年实质性监管更新：DPF + 欧盟法院
                                #   上诉、英国 DUAA 2025、EDPB 关于 AI 的
                                #   第 28/2024 号意见、欧盟法院 SRB 假名化裁决、
                                #   Russmedia 平台控制者裁决、EDPB 关于合法
                                #   利益的 1/2024 指南、CEF 2025 删除执法、
                                #   ePrivacy 撤回
```

该技能使用**渐进式披露**——`SKILL.md` 始终在上下文中，而参考文件仅在触发文档起草时按需加载，保持上下文窗口高效。

### 构建方式

**用于构建本 skill 的输入：**

| 输入 | 值 |
| -------------------- | -------------------------------------------------------------------------- |
| 主要能力 | 代码审计、文档起草、合规问答、数据流审查 |
| 目标受众 | 技术人员（开发人员）和法律/合规专业人士 |
| 引用风格 | 在所有回答中引用具体 GDPR 条款 |
| 监管范围 | 欧盟 GDPR（主要）+ 英国 GDPR 说明 |
| 文档模板 | 隐私通知、DPA、同意横幅、DPIA、留存政策、DSR 程序 |

**关键设计决策：**

- **双语气适应性**——该技能检测上下文（代码 vs 文档 vs 问题）并相应调整语言语域，无需用户指明其角色。
- **条款优先引用**——每项合规主张都锚定到具体的 GDPR 条款，使回答可审计、可辩护，而非咨询性意见。
- **审计中的严重程度分级**——发现按高 / 中 / 低分类并附清晰定义，使开发人员和法律团队可以确定整改工作的优先级。
- **升级护栏**——内置免责声明在高风险场景（特殊类别数据、国际转移、儿童数据、执法风险）中自动触发，防止该技能替代专家法律顾问。
- **模板模块化**——每个文档模板使用 `[PLACEHOLDER]` 标记组织特定细节，使输出立即可用作工作草稿，而非通用示例。

### GDPR 覆盖范围

该技能涵盖整个条例的以下关键领域：

| 主题领域 | 涵盖的条款 |
| -------------------------------- | ------------------ |
| 数据主体权利 | 第 15-22 条 |
| 合法依据与同意 | 第 6-8 条 |
| 控制者/处理者义务 | 第 24-28、30-31 条 |
| 特殊类别数据 | 第 9-10 条 |
| 透明度与通知 | 第 12-14 条 |
| 安全与泄露应对 | 第 32-34 条 |
| DPIA 与事先咨询 | 第 35-36 条 |
| 国际转移 | 第 44-49 条 |
| 处罚与执法 | 第 77-84 条 |
