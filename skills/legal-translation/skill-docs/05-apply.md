### 步骤 5：将翻译直接应用到原始文件

*[内部合规检查——不要向用户复述或转述。在执行前重新阅读本步骤中的每一条规则。不要偏离技能的任何一行。不要捆绑工作、跳过检查或"为效率而解释"——每一次此前的偏离都产生了低于技能设计应交付质量水平的输出。无论如何，技能的硬性门禁都会阻止偏离；提前合规总比撞上门禁并重写 paragraphs.json 更快。]*

**区分技能门禁与脚本错误。**如果 `apply_translations_textmatch.py` 以退出码 2 退出、抛出提到 `BLOCK` 的 `RuntimeError`，或打印 `SKILL GATE FIRED — INTENTIONAL BLOCK, NOT A SCRIPT ERROR`（技能门禁触发——有意阻止，非脚本错误）横幅，那是门禁有意触发。脚本没有崩溃、没有截断、也没有缺陷。阅读退出/抛出之前立即打印的 BLOCK 消息——它会确切告诉你哪个门禁触发了（定义部分缺少 en_runs、超出逐批上限、validate_apply 标记不匹配、剥离后漂移等）以及如何修复 `paragraphs.json`。**不要通过从绕过自动调用验证器的包装器调用 `textmatch_apply()`、抑制 `--strict` 标志或修补脚本使其返回成功来绕过门禁。**门禁存在是因为操作者每一次绕过它们都交付了低于技能设计应交付质量水平的输出。修复根本问题并重新运行应用；这总是比变通方案更快。

```bash
python <skill-path>/scripts/apply_translations_textmatch.py \
  <original_source_language>.docx \
  <workdir>/paragraphs.json \
  <workdir>/final/word/document.xml
```

这是唯一最重要的步骤。它一次性完成所有工作：

1. 直接从源 .docx ZIP 读取原始 document.xml
2. 对于 paragraphs.json 中的每个翻译条目，**匹配源语言文本**以找到正确的原始段落（自动处理任何索引偏移）
3. 仅将 w:r（文本运行）元素替换为新的英文运行
4. 保留所有段落属性（样式、编号、缩进、间距）
5. 恢复原始命名空间声明（防止 Word 中出现"内容不可读"错误）
6. **验证命名空间完整性**——扫描文档正文中任何已使用但未在根元素中声明的命名空间前缀，并注入缺失的声明。这捕获原始 .docx（尤其是 .doc→.docx 转换）在嵌入元素上使用 `a:` 或 `pic:` 等命名空间而未在根中声明的情况。没有这一步，Word 会以 422/内容不可读错误拒绝打开文件。
7. **剥离语言标签**（`w:lang` 元素），从运行级和段落级属性均剥离。源文档在每个运行上携带 `w:lang val="it-IT"`（或类似）；如果这些存活到英文输出，Word 会在每个段落上显示"已改为英语（英国）"的修订追踪。移除 `w:lang` 让 Word 自动检测语言。
8. **剥离修订追踪属性**（`w:rsidR`、`w:rsidRDefault`、`w:rsidRPr`、`w:rsidP` 等）从所有元素。这些会导致 Word 在输出中将格式变更显示为修订追踪。
9. **扫描源语言残留**——应用所有替换后，扫描整个输出 XML 中常见的源语言词汇，并报告找到的任何残留及其周围上下文。这捕获段落级替换遗漏的拆分运行段落、结构化文档标签或嵌套元素中的文本。

脚本打印摘要，显示精确匹配与偏移匹配以及任何未匹配条目。目标：零样式/编号不匹配。

**辅助 XML 文件（编号、页眉/页脚、批注、脚注、尾注）在步骤 8 中单独翻译——见下文步骤 8。** 步骤 5 只修改 `document.xml`。步骤 6 对 `document.xml` 进行后处理。步骤 7 重排 `document.xml` 中的定义。所有其他 XML 部件等待步骤 8。
