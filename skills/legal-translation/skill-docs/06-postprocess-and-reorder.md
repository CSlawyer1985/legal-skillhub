### 步骤 6：后处理

*[内部合规检查——不要向用户复述或转述。在执行前重新阅读本步骤中的每一条规则。不要偏离技能的任何一行。不要捆绑工作、跳过检查或"为效率而解释"——每一次此前的偏离都产生了低于技能设计应交付质量水平的输出。无论如何，技能的硬性门禁都会阻止偏离；提前合规总比撞上门禁并重写 paragraphs.json 更快。]*

```bash
python <skill-path>/scripts/post_process.py <workdir>/final/word/document.xml --fix --variant uk
```

**变体标志——输入前重新验证。** `--variant uk` 是硬编码默认值，除非用户的原始提示中明确包含美式英语指示，否则应使用它。在传递 `--variant us` 之前，回去重新阅读用户的*原始*请求。仅当提示中包含 "US English"、"American English"、"American spelling" 等明确内容时才使用 `us`。如有任何疑问，传递 `--variant uk`。（约 98% 的翻译使用英式英语——英式是真正的默认值，而非礼貌性建议。）

这将应用自动化质量修复：
- 元素之间缺失的空格
- 定义边界间距（"Xmeans" → "X means"）
- 双标点（::、..、,,,、;;）
- 术语标准化（Facility Agreement、Secured Assets 等）
- 按活动变体的拼写修复（默认：英式——authorise、judgement、favour、centre、organisation 等）
- Annex → Schedule
- 内部交叉引用 Article → Clause
- 重复词移除
- 定义词的引号配平
- 定义换行移除
- 伪斜体移除
- Schedule 分页插入（每个 Schedule 从新页开始）

**修订追踪运行格式按作者原样保留。**`w:ins` / `w:del` 包装器内的运行级属性（`w:sz`、`w:szCs`、`w:rFonts`、`w:color`）从源文件逐字节保留。不要将其规范化，即使源作者对删除内容使用了较小字号或不同颜色、结果在交付的英文文档中看起来视觉上不一致。对源作者格式选择的忠实胜过外观和谐化——翻译不得静默修改原始文件的样式方式。（匹配的评分规则见 grading-skill methodology.md 标准 13。）

**TC 文档上的无操作修订追踪自动剥离。**当文档包含 `<w:ins>` / `<w:del>` / `<w:delText>` 时，`post_process.py` 在末尾自动调用 `strip_noop_tracked_changes.py`——在同一 `post_process.py --fix` 调用中运行，无需单独的操作者命令。剥离过程：

* 查找规范化文本内容相同的相邻 `<w:del>` + `<w:ins>` 对（任一顺序，容忍它们之间的 `commentRangeStart`/`commentRangeEnd`/`bookmarkStart`/`bookmarkEnd`/`proofErr`）；移除 `<w:del>` 并解包 `<w:ins>`。这将仅正字法的源编辑——荷兰语 `mn` ↔ `m.n.`、德语 `daß` ↔ `dass` 等两侧翻译为相同英文的情形——折叠为一段普通英文文本，而非无操作红线。
* 移除规范化后内容为空、纯空白或纯标点的 `<w:del>` / `<w:ins>` 包装器。
* **保留**任何英文内容相差哪怕一个字母或数字的对。日期数字变更（`2` → `6`）、附件字母变更（`Schedule X` → `Schedule G`）、定义词替换以及任何其他真实内容编辑都以修订追踪形式保留在输出中。
* **括号感知**：纯括号的 ins/del 包装器（`[`、`]`、`(`、`)`）在与 8 个兄弟元素内的内容性 ins/del 相邻时**保留**——保持占位日期修订追踪的连贯性。

**配套翻译规则**：为 TC 段落起草 `en_segments` 时，当源编辑仅涉及正字法时，给 `del` 和 `ins` 片段**相同的英文文本**（见步骤 4 中"折叠仅正字法的 TC 编辑——强制性"）。自动剥离依赖这一点。如果你在源编辑仅涉及正字法的情况下将 del 和 ins 翻译为不同的英文，自动剥离将无法检测到无操作，标记将保持可见。

幂等。运行 `post_process.py --fix` 两次在第二次运行时无效果。

### 步骤 7：按字母顺序重排定义——强制性

*[内部合规检查——不要向用户复述或转述。在执行前重新阅读本步骤中的每一条规则。不要偏离技能的任何一行。不要捆绑工作、跳过检查或"为效率而解释"——每一次此前的偏离都产生了低于技能设计应交付质量水平的输出。无论如何，技能的硬性门禁都会阻止偏离；提前合规总比撞上门禁并重写 paragraphs.json 更快。]*

**先运行干跑**，以便在脚本触碰文档之前看到它将做什么。这是一个 30 秒的预检，可捕获此前每次出现约耗费 8 分钟的缺陷类别：

```bash
# 1. 带预期数量的干跑
python <skill-path>/scripts/reorder_definitions.py \
    --doc <workdir>/final/word/document.xml \
    --dry-run --expected-defs <N>

# 2. 如果数量和提取的术语看起来正确，正式运行
python <skill-path>/scripts/reorder_definitions.py \
    --doc <workdir>/final/word/document.xml
```

`<N>` 是你在源文档中实际数出的定义词数量。每次运行都传递它——如果脚本提取的数量多于或少于 `<N>`，它会大声中止，而非重排错误的内容。如果文档没有定义部分，省略 `--expected-defs`（脚本将以"未找到定义部分"干净退出）。

在应用翻译之后运行，因为我们按英文定义词排序。

**不要跳过此步骤。**源语言的字母顺序几乎从不等同于英文的字母顺序——例如，匈牙利语定义 "Elidegenítési tilalom" 位于 "E" 之下，但其英文翻译 "Prohibition on transfer" 位于 "P" 之下。让该部分保持源语言顺序，会为英文读者留下突兀的、非字母顺序的定义列表——这是一个高严重性缺陷。

脚本**结构性**地检测定义块：定义部分是紧密窗口内匹配"粗体词后加冒号"形状（或引号包裹词后加冒号形状）的 ≥2 个段落的簇。无需语言特定短语匹配——适用于所有受支持的源语言，无需硬编码任何关键词。如果不存在这样的簇，脚本干净退出且不修改任何内容。

**Rev11 保障（缺陷类别捕获器）。**任何写回前运行三项独立检查：

1. **术语健全性（A2）**——检查每个提取的"定义词"。如果任何术语包含引号、子串 "means" / "indica" / "shall mean" 或以冒号结尾，脚本以可疑术语列表中止。这捕获了此前静默破坏重排的 LibreOffice `<w:b w:val="0"/>` 误读。
2. **预期数量交叉检查（A6）**——如果设置了 `--expected-defs N` 且数量不匹配，中止。
3. **窗口外不变式（A3）**——`[def_start, def_end)` 之外的每个段落索引在重排后必须与重排前具有相同文本。如果定义块之外的任何内容发生了移动，中止。

这些中止中的任何一个都意味着磁盘上的文档**未改变**——无损坏。

**Rev45 检测器加固（账户质押 / 配额质押事后复盘）。**
三项额外保护叠加在 rev11 保障之上，使脚本在文档包含结构性呈定义形状但并非真实定义词的段落——信函主题行、序言开头（`WHEREAS:` / `PREMESSO:`）、通知栏标签（`Address:`、`Attention:`）和收件人行（`If to the Borrower:`）——时不会误检测（或检测失败）定义部分。

1. **修复 A——`get_bold_term` 处的停止列表。**一份精选的粗体后加冒号前缀列表（`subject`、`re`、`whereas`、`now therefore`、`attention`、`address`、`attn`、`fax`、`tel`、`email`、`e-mail`、`pec`，外加十一种词典语言中的源语言对应词，以及短语起始模式 `if to ` / `with copy to `）在提取时被拒绝。匹配器通过取第一个冒号前的子串进行规范化，因此完全粗体的信函行如 `Subject: Account Pledge Agreement - Acceptance` 会比较为 `subject` 并被拒绝。真实定义词绝不在停止列表上（如 `Subject Matter of the Pledge` 被保留——第一个冒号前的词首是 `subject matter of the pledge`，不在列表中）。

2. **修复 B——簇失败回落到标题回退。**如果主检测器返回 ≥2 个候选但 K=20 / K*3=60 簇守卫拒绝它们（因为虚假候选将前三个分散在超过 60 个段落中），脚本现在运行标题锚定回退（`Definitions` 标题 + 接下来 8 个内 ≥3 个谓词形状段落），而非返回 `(None, None)`。此前回退仅在主检测器找到 <2 个候选时运行，这使脚本在有许多虚假粗体冒号命中的文档上保持沉默。

3. **修复 C——修剪前导孤立误报。**在簇守卫之前，如果 `def_starts_idx[0]` 与 `def_starts_idx[1]` 相距超过 K=20 个段落**且**尾部形成紧密簇，则丢弃头部并在修剪后的列表上重新检查簇守卫。以 `max_trims=5` 为界以避免病态输入。这是配额质押案例的恢复路径，其中 `WHEREAS:` 位于 P[28]，在真实定义簇 P[62..92] 之前 34 个段落。

三项修复均保持 rev11 保障（A2/A3/A6）完整。当标题锚定路径是定位该部分的路径时，仍会打印回退警告——但警告文本现在列出*两个*常见原因（定义段落缺少 `en_runs` 或停止列表未命中），而不仅仅是第一个。

**如果重排拒绝（健全性检查触发）。**最可能的原因是 LibreOffice 在将 `.odt` → `.docx` 转换时发出的 `<w:b w:val="0"/>`。粗体检测辅助函数现在按 ECMA-376 ST_OnOff 识别 `0` 和 `off`（不区分大小写），但如果文档遇到其他变体，最安全的变通方案是：

- 使用 `--dry-run` 重新运行以检查提取的术语。
- 如果数量错误，接受文档按源顺序交付。定义保持未字母排序；quality_check 会发出 `definition_order` 警告作为已知误报。在交付说明中记录这一点。

如果文档明显有定义部分但脚本打印 `"no definitions section found"`（未找到定义部分），原因几乎总是 rev45 停止列表未捕获的结构性定义形状段落（不支持的语种中的 Subject 行、不寻常的通知栏标签、异国情调的序言开头）。使用 `--dry-run` 检查簇候选：在干跑输出中搜索任何明显不是定义词的提取"术语"，并扩展 `reorder_definitions.py` 中的 `_NON_DEFINITION_BOLD_PREFIXES_EXACT` 或 `_NON_DEFINITION_BOLD_PREFIX_STARTS`。如果该部分仍通过标题+谓词回退被检测到，该路径可以交付——只需审查干跑输出以确认被排序的是真实定义。
