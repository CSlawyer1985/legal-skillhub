# 证据清单AI撰写（非表格版本）Plus

## 核心原则

本 skill 的核心理念是**让 AI 承担主要的信息提取和文书撰写工作，最大限度减少用户手动输入案件信息的环节**。用户只需上传证据材料并简要说明核心主张，AI 即从材料中主动提取证据信息、分析证明对象，按规范撰写《证据清单》初稿。用户在初稿基础上提出修改意见即可，无需频繁自行输入案件细节。

## 概述

本 skill 用于协助诉讼律师撰写《证据清单》——向人民法院提交的证据目录文书。采用**非表格（纯段落）排版**，输出格式为 .docx 文档。

## 适用场景

- 民事/商事诉讼案件起诉或应诉时，需整理并向法院提交证据清单
- 律师已持有证据材料（PDF/图片/Word 等格式），需要 AI 协助从材料中提取信息并撰写规范的证据清单文书
- 支持的材料格式：PDF 文件、图片文件（JPG/PNG 等）、Word 文档（.docx/.doc）、扫描件等

## 使用方式

用户只需：
1. **上传**证据材料文件
2. **简要说明**诉讼地位和核心主张（一句话即可）

AI 会自动从材料中提取证据名称、日期、页数、来源等信息，撰写完整的《证据清单》初稿。用户在初稿基础上提出修改意见即可，无需手动逐项输入案件信息。

## 写作规范（严格遵循）

### 整体结构

```
┌─────────────────────────────────┐
│    [当事人地位]证据清单（标题）    │
│  例：原告证据清单 / 被告证据清单  │
│  上诉人二审新证据清单 / 等        │
├─────────────────────────────────┤
│ 证据一（第X-Y页）：名称、份数、  │
│   日期、页数、形式、原件情况；    │
│ 证据来源：XXX提供；              │
│ 证明对象：……（可多段）           │
├─────────────────────────────────┤
│ 证据二（第X-Y页）：……           │
│ ……                              │
├─────────────────────────────────┤
│                   提交人：XXX     │
│       特别授权代理人：______      │
│               年   月   日        │
└─────────────────────────────────┘
```

### 标题抬头规则

证据清单的标题必须根据当事人诉讼地位确定：

| 诉讼地位 | 标题 |
|---------|------|
| 原告 | **原告证据清单** |
| 被告 | **被告证据清单** |
| 第三人 | **第三人证据清单** |
| 二审上诉人 | **上诉人二审新证据清单** |
| 二审被上诉人 | **被上诉人二审新证据清单** |
| 申请人（再审/执行等） | **申请人证据清单** |
| 被申请人（再审/执行等） | **被申请人证据清单** |

### 每条证据的写作模板

**第 1 段（证据标识行）：**
```
证据[编号]（第[起页]-[止页]页）：[子编号（如有）]《[证据名称]》[份数]，[日期]，共[页数]页，[形式]（[原件情况]）；
```

**第 2 段（证据来源）：**
```
证据来源：[来源方]提供；
```

**第 3 段（证明对象）—— 根据诉讼地位区分写作模式：**

**模式 A：原告证据清单**

仅撰写证据本身所体现的证明对象：
```
证明对象：[逐条列出该证据所证明的事实，按时间顺序排列，每条以分号结尾，最后一条以句号结尾]
```

**模式 B：被告 / 第三人 / 上诉人二审新证据 / 被上诉人二审新证据 / 申请人 / 被申请人证据清单**

证明对象分为两个部分：
```
证明对象：
一、证明：[证据本身所体现的证明对象，逐条列出，按时间顺序排列，每条以分号结尾，最后一条以句号结尾]

二、反驳：[针对诉讼相对方某份证据或某个观点的反驳，逐条列出]
```
> 第二部分"反驳"的撰写需要诉讼相对方的相关材料（如对方的证据清单、起诉状、上诉状、答辩状等），应在第一步提示用户一并上传。

### 子证据处理规则

当一项证据包含多份独立材料时：
- 主线保留总编号（如"证据三（第7-11页）"），列出子证据概览
- 每个子证据单独成段，使用子编号（如"3-1（第7-10页）……"）
- 所有子证据共用同一个"证据来源"段落
- 所有子证据共用同一个"证明对象"段落

### 格式规范

| 项目 | 规范 |
|------|------|
| 标题 | 黑体，三号（约22pt），居中 |
| 正文 | 宋体，小四（12pt），1.5倍行距 |
| 首行缩进 | 2字符 |
| "证据X" | 加粗 |
| "证明对象" | 加粗 |
| 落款 | 右对齐 |
| 纸张 | A4 |

### 证据形式表述规范

| 情形 | 表述 |
|------|------|
| 有原件 | "复印件（有原件）" |
| 无原件 | "复印件" |
| 电子截图/打印 | "打印件" |
| 照片 | "照片打印件" |
| 电子数据 | "电子数据（原始载体已备查）" 或 "电子数据打印件" |

### 证明对象写作要求

**通用要求：**
1. **每条以具体日期开头**，按时间顺序排列
2. **事实陈述客观、简洁**，不做法律评价或论证
3. **每条以分号（；）结尾**，最后一条以句号（。）结尾
4. **引用合同条款时**，写明"合同第X条约定：……"
5. **关键金额、日期、主体名称必须准确**
6. **涉及简称的主体**，首次出现时注明"（以下简称：XX）"

**反驳部分附加要求（仅适用于非原告证据清单）：**
7. 先注明反驳的对象，格式为"原告/被告/上诉人等第X号证据称……"或"起诉状/上诉状中关于……的主张"
8. 再写明反驳的事实依据，格式为"但……""实际上……""然而……"
9. 反驳应有证据支撑，避免纯观点争论

## 工作流程

**流程总览：材料上传 → 简要说明 → AI 主动解读与撰写 → 用户审阅修改 → 输出 docx**

> **核心原则**：AI 应从用户上传的材料中**主动提取**所有信息（证据名称、日期、份数、页数、来源、证明对象等），而非逐项向用户提问。用户只需上传材料并简要说明核心主张，其余工作由 AI 完成。

---

### 第一步：接收材料与简要说明

**【必须】首先提示用户上传证据材料，并提供简要信息。**

向用户发出以下引导提示：

> 请上传本案的证据材料（支持 PDF、图片、Word 等格式），并简要说明以下内容：
> 1. **诉讼地位**（原告/被告/第三人/上诉人/被上诉人/申请人/被申请人）
> 2. **核心主张**（一句话概括，如"被告拖欠租金构成违约"）
>
> 如需撰写反驳部分（非原告方），请一并上传诉讼相对方的证据清单、起诉状/上诉状/答辩状等材料。
>
> **注意**：无需手动逐项输入证据信息，我会从您上传的材料中自动提取。

**若用户仅上传了材料但未说明诉讼地位**，则仅需询问诉讼地位（使用 AskUserQuestion 工具，单选，选项为七种诉讼地位）。其他信息由 AI 从材料中主动提取，不再追问。

**若用户说明了诉讼地位但未说明核心主张**，则不追问核心主张——AI 从材料内容中推断核心主张，在排列方案中一并告知用户，由用户在审阅阶段修正。

**若用户仅说明了诉讼地位但未上传材料**，则再次提示上传材料，不进行下一步。

---

### 第二步：AI 主动解读材料并排列证据

收到用户上传的材料后，AI 从材料中**主动提取**以下信息（无需逐项向用户提问）：

1. **案件基本信息**：从材料内容推断案由、各方当事人名称
2. **证据列表**：从材料中逐项提取 ——
   - 证据名称（从文件标题或内容中推断）
   - 文件日期
   - 页数（从文件页数统计）
   - 证据形式（根据文件类型判断：扫描件→复印件，电子截图→打印件，照片→照片打印件，电子文件→电子数据）
   - 原件情况（若无法从材料中判断，统一标注为"（有原件）"，在审阅阶段由用户修正）
3. **证据来源**：根据材料内容和诉讼地位推断（如原告方材料→原告提供；如材料来自第三方→标注第三方名称）
4. **证明对象**：AI 从材料内容中提炼每条证据所证明的核心事实，按时间顺序整理

#### 材料解读策略（应对无法直接读取的情形）

当用户上传的材料格式无法被直接读取文字内容时（如图片格式 JPG/PNG、扫描件 PDF 不含文本层、照片等），AI **不得放弃或跳过**，必须**立即执行**以下策略尝试解读，按优先级依次尝试，每步失败后自动进入下一步：

> **强制触发**：AI 检测到用户上传了图片或无法直接读取文字的文件时，必须**不向用户展示任何推断内容**，先静默执行以下解读流程。解读成功后再进入排列和撰写阶段。

**策略一：搜索已有 skill**

首先使用 `Skill` 工具的 `find-skills` 命令搜索与文件解读、OCR、图片文字提取相关的已有 skill。若有匹配的 skill，立即加载并使用。

**策略二：使用 OCR 工具**

若无可用的解读 skill，使用系统 OCR 工具（如 macOS 的 `shortcuts` 命令调用快捷指令、或 `tesseract` 等命令行 OCR 工具）对图片进行文字识别。优先使用系统内置方案。

macOS 示例：
```bash
# 使用 macOS 的 Vision 框架通过快捷指令进行 OCR
shortcuts run "Extract Text from Image" -i /path/to/image.png
```

**策略三：转换为可读格式**

若 OCR 方案不可用，尝试将图片转换为 PDF 格式，再尝试提取文本：
```bash
# 使用 sips 将图片转为 PDF
sips -s format pdf /path/to/image.png --out /path/to/output.pdf
```

**策略四：告知用户并请求协助**

若上述所有方案均无法解读材料，则明确告知用户：
- 列出已尝试的方法及失败原因
- 列出无法解读的具体文件
- 建议用户：
  - 重新上传可文字提取的 PDF 版本
  - 或提供该文件的关键文字信息（证据名称、日期、主要内容等）
  - 或授权 AI 基于文件名和用户的说明进行推断撰写
- **在用户协助之前，不得进入排列和撰写阶段**

> **原则**：AI 应穷尽所有合理手段尝试解读，仅在确实无法实现时才请求用户协助。绝不能不尝试任何方法就直接要求用户提供文字信息。

**证据排列规则：**

AI 主动按照以下原则排列证据顺序（无需询问用户）：
1. 按照纠纷发生的时间线排列（从先到后）
2. 先程序性证据、后实体性证据（如有）
3. 证明同一事实的多份证据集中排列
4. 合同类、书面类证据优先于聊天记录、照片等辅助证据

排列完成后，AI 进入第三步直接撰写完整初稿。排列方案与初稿**一并展示**给用户（排列方案可在初稿展示前简要概述）。用户如对排列顺序有异议，在第四步审阅阶段提出即可，AI 调整后重新生成。

---

### 第三步：AI 主动撰写证据清单初稿

根据第一步确定的诉讼地位和第二步提取的信息，AI 直接撰写完整的《证据清单》初稿，并向用户展示。

**证明对象写作模式（根据诉讼地位自动选择）：**

- **原告**：仅撰写"证明对象"部分，逐条列出证据所证明的事实，按时间顺序排列
- **非原告（被告/第三人/上诉人/被上诉人/申请人/被申请人）**：分两部分撰写 ——
  - **一、证明**：证据本身所体现的证明对象
  - **二、反驳**：针对诉讼相对方证据或观点的反驳。需基于用户上传的相对方材料，逐条写出反驳对象和反驳事实依据。若用户未上传相对方材料，则在初稿中标注"【反驳部分待补充：请上传诉讼相对方材料】"，并提示用户

**AI 主动推断时的默认处理：**
- 原件情况：默认标注"复印件（有原件）"
- 证据形式：根据文件类型自动判断（参见第二步提取规则），无法判断时默认"打印件"
- 证据来源：根据诉讼地位推断（原告方材料→原告提供；被告方材料→被告提供）
- 提交人：默认为当事人姓名（从材料内容中推断，若无法确定则留空），代理律师信息留空待用户补充
- 对于无法从材料中确定的信息，使用合理推断并在初稿中标注为可修改

---

### 第四步：用户审阅与修改

**【关键步骤】将初稿完整展示给用户，提示用户直接在初稿基础上提出修改意见。**

向用户发出以下引导提示：

> 证据清单初稿已生成，请审阅。您可以直接提出修改意见，例如：
> - "证据三的名称改为《补充协议》"
> - "证据二的日期应为2023年5月20日"
> - "证明对象第三点请补充：……"
> - "请调整证据五和证据六的顺序"
> - "证据来源应改为XX公司提供"
> - "提交人改为：张某，特别授权代理人：李某"
>
> 我会根据您的意见修改，无需您手动重新输入完整内容。

**修改循环：**
- 用户提出修改意见 → AI 修改并重新展示 → 用户可继续提出修改意见
- 此循环可持续进行，直至用户表示满意
- **不要**在每次修改后使用选择题询问"是否还需要修改"，让用户自然表达即可
- 用户表达满意的信号：说"可以了""没问题了""就这样"等 → 进入第五步（弹窗确认是否生成文件）
- 用户主动要求生成文件：说"生成文件吧""生成 docx 吧"等 → 直接进入生成流程，**不再弹窗确认**

---

### 第五步：输出 docx 文件

根据用户第四步的反馈进入本步骤：

**情况一：用户主动要求生成文件**（如说"生成文件吧""生成 docx"等）→ 直接生成，不再弹窗确认。

**情况二：用户表示满意但未主动要求生成文件**（如说"可以了""没问题了"）→ 使用 AskUserQuestion 工具向用户确认（单选）：

> 是否需要生成 .docx 文件并保存？

| 选项 | 后续行为 |
|------|----------|
| **是，生成并保存** | 使用 python-docx 生成 .docx 文件。文件命名规则：`[抬头标题]_[案由]_[提交人].docx`（如"原告证据清单_房屋租赁合同纠纷_李某.docx"）。保存前询问用户目标路径（默认为桌面） |
| **不需要** | 结束流程，告知用户可随时要求生成 .docx 文件 |

**docx 生成规范：**
- 标题：黑体，22pt，居中
- 正文：宋体，12pt，1.5 倍行距
- 首行缩进：2 字符（304800 EMU）
- "证据X"和"证明对象"：加粗
- 落款：右对齐
- 纸张：A4，上下边距 2.54cm，左右边距 3.18cm
- 文件保存前需先获得用户对保存路径的确认

## 质量检查清单

生成后自动检查：
- [ ] 标题抬头是否与用户说明的诉讼地位匹配
- [ ] 每条证据是否包含完整的"证据标识行 + 证据来源 + 证明对象"三段式
- [ ] 证据排列是否按时间线顺序（从先到后）
- [ ] 非原告模式下，证明对象是否包含"一、证明"和"二、反驳"两个部分
- [ ] 反驳部分是否注明了反驳的具体对象（如"原告证据一称……"）；若相对方材料未上传，是否已标注待补充提示
- [ ] 页码是否连续且正确
- [ ] 子证据编号是否规范
- [ ] "证明对象"每条是否以日期开头，按时间排序
- [ ] 首次出现的当事人简称是否标注"（以下简称：XX）"
- [ ] 所有分号/句号使用是否正确
- [ ] 落款是否完整（提交人、特别授权代理人、日期）
- [ ] 全角/半角标点是否正确（中文内容用全角标点）
- [ ] AI 推断的内容（原件情况、证据形式、来源等）是否在初稿中明确标注，便于用户审阅修正

## 示例

### 示例零：完整使用流程（新版）

用户上传材料：
- `房屋租赁合同.pdf`（2页，2020年4月7日签署）
- `租金支付凭证.png`（1页，2023年6月15日银行转账截图）
- 简要说明：**诉讼地位：被告；核心主张：已支付租金，原告主张拖欠金额不实**
- 同步上传：原告证据清单、原告起诉状

AI 主动提取并展示排列方案：

> 已从材料中提取以下证据并排列：
> 1. 证据一（第1-2页）：《房屋租赁合同》——来源材料：房屋租赁合同.pdf
> 2. 证据二（第3页）：《租金支付凭证》——来源材料：租金支付凭证.png
