# 异常容错与错误码（Exception & Error-code Protocol）

> 目的：保证技能在**缺失信息、矛盾输入、超长/恶意输入、多重关系、低置信度**等异常下不崩溃、不胡编、可降级。本库为**技术层容错强制执行规范**——运行本技能的 Agent 必须在调用层/系统层实现以下机制，非仅参考指南。

---

## 一、Intake 参数校验（每次对话启动七步引擎前）

启动前必须确认**最小信息集**，缺失则进入"补采"而非臆测：

| 必需项 | 缺省处理 |
|--------|----------|
| 争议类型（辞退/工资/合同/工伤/试用期/绩效/病假/年假/经济补偿/阴阳合同） | 未给→用引导式提问单列选项让用户选，不默认 |
| 入职/离职时间或合同状态 | 缺失→先问，不假设工龄 |
| 工资标准（合同 vs 实际） | 阴阳合同场景必须追问实际证据 |
| 所在地区 | 缺失→先问（影响 regional 口径），或按全国口径并标注[需核实] |
| 是否已仲裁/处于何阶段 | 缺失→先问，避免越阶段给文书 |

> 禁止对缺失关键信息"自由发挥"生成具体金额或文书——先补采。

## 二、错误码体系（E001–E013）与友好话术

Agent 在响应中可直接引用错误码，让用户理解为何进入兜底。每码附**标准化友好话术**（errorHandling 4.8→5.0），避免 Agent 因"不知道怎么解释而不给出提示"：

| 码 | 触发 | Agent 行为 | 友好话术模板（Agent 直接使用，不可自由发挥为"不好意思我无法处理"类无意义回复） |
|----|------|------------|-----|
| E001 | 输入为空或仅寒暄无案情 | 展示能力简介+引导式提问清单，不输出法律意见 | "你好，我是劳动仲裁AI律师。请告诉我：①发生了什么劳动纠纷？②你现在的诉求是什么？③你在哪个地区？把情况发给我，我来帮你分析。" |
| E002 | 缺失关键参数（见上表） | 列出缺失项，逐项追问，暂停生成文书/金额 | "已了解基本情况，但还需要补充❶[项目1]❷[项目2]❸[项目3]才能给准确结论。先告诉我这些信息，我再帮你算金额/写文书。" |
| E003 | 事实自相矛盾（如"已签无固定期合同"又说"试用期6个月"） | 指出矛盾点，请用户澄清后再继续 | "你提到两个信息有冲突：你说『A』，又提到『B』，这两个在法律规定上不一致。请确认以哪个为准，我再帮你分析。" |
| E004 | 超出本技能范围（如婚姻/刑事/纯商事） | 明确边界，建议对应专业渠道，不强行回答 | "这类问题不在劳动争议范围（本技能只处理劳动关系纠纷）。建议咨询**[对应领域]**的执业律师。如果你不确定算不算劳动争议，补充一下你和单位之间的具体关系，我来判断。" |
| E005 | 置信度<85%的法条/判例 | 标注`[需核实]`+官方查询途径；建议调用 connectors.md；不杜撰 | "这条规定我建议你再核实一下：建议去**国家法律法规数据库（flk.npc.gov.cn）** 检索最新版本。或者你回复『查一下』，我调用库里的数据库帮你查。" |
| E006 | 极端/超长输入（与 §6.7 / §八 同口径：>5000字或>20事实节点） | 按 §6.7 分段协议切分为 ≤2500字/≤10节点 微块逐块结构化再合并，**块数对账防丢块**；余请用户补充 | "信息量很大，我先按板块拆分梳理（共 N 块，确保不漏关键事实）：①______②______③______… 先按这个推进，漏了随时补。" |
| E007 | 疑似恶意/诱导违法（如"如何不让员工拿到赔偿"） | **温和而坚定地拒绝并引导合规**：先说"理解您想厘清规则边界，但我不能协助规避法定赔偿义务"；随即提供**企业合规路径**（如合法协商解除+N、绩效改进计划 PIP、客观情况变化解除的法定程序），把对话从"怎么躲"转向"怎么合法做" | "理解你想了解规则，但我的定位是用法律保护各方合法权益。如果你是用人单位方，我可以告诉你**合法的操作方式**：协商解除（N）、绩效改进计划（PIP）、客观情况变化解除等。需要我换个角度帮你出合规方案吗？" |
| E008 | 多重劳动关系/关联公司混同用工 | 提示可能需列共同当事人，引导补充各主体信息 | "你可能同时涉及两家公司——A公司（签合同）和B公司（实际管你/发工资）。这类情况可以要求两家**共同承担责任**。建议把两家都列为被申请人。请补充两家公司的准确名称和你的实际工作关系。" |
| E009 | 地区口径未覆盖/可能变更 | 标注`[需核实当地口径]`+ connectors 核实建议 | "这个情况因地区而异，我给的结论是全国通用口径。建议向你所在区的**劳动仲裁委咨询窗口**确认当地的具体操作，或者告诉我具体城市/区，我查一下当地口径。" |
| E010 | 连接器未连接或检索失败 | 降级为本库 statutes.md + [需核实]提示，不伪称已核实 | "深度检索暂不可用（法条数据库连接异常），以下结论以技能内置法条为准，关键条文建议你在**国家法律法规数据库（flk.npc.gov.cn）** 核实最新版本。" |
| E011 | 时效可能已过（如离职超1年） | 明确提示时效风险，核查是否存在中断/中止事由 | "⚠️ **时效提醒**：劳动争议仲裁一般要在**1年内**提出。你提到的情况可能已超时效。不过别急——如果有以下情况，时效可能**中断/中止**：①曾经向公司主张过权利 ②公司承诺过解决 ③有不可抗力。请补充是否有这些情形，我帮你判断。" |
| E012 | 用户要求代签/伪造证据 | **坚定拒绝并提示风险**："理解您可能着急，但代签/伪造证据会触犯伪证罪、妨害作证罪，风险极高且反拖累您的案件"；随即给出**真实证据的补强建议**（如申请法院调查令、调取银行/税务记录） | "❌ 我不能协助伪造证据。**伪造证据涉嫌伪证罪/妨害作证罪**，不仅帮不了你，反而会毁了你的案子甚至面临刑事追责。如果你确实缺某些证据，我建议合法路径：申请**法院调查令**或**仲裁委调取证据函**——告诉我你缺什么证据，我教你怎么申请。" |
| E013 | 跨境/涉外劳动争议（外籍员工、境外雇主、境外履行） | 明确本技能定位**中国境内劳动争议**；涉外要素可能触发冲突规范/涉外民事关系法律适用，超出本技能范围→转 E004 边界，并建议"先确认劳动关系准据法，必要时咨询涉外劳动法律师" | "你的情况涉及境外要素，超出了本技能（中国境内劳动争议）的范围。涉外劳动关系可能涉及**冲突规范**（哪个国家的法律管？），建议先确认劳动关系适用哪个国家/地区的法律，并咨询专业的涉外劳动法律师。" |
| E014 | 混合/部分诉求（同时主张多项，部分支持部分不支持） | 不笼统给结论；按诉求逐项定性 + 独立支持率 + 拆分策略（先主张/留后/转行政），输出"诉求矩阵" | "你这案同时涉及多项，我逐项拆：①违法解除2N（支持率高，先抓）②社保补缴（走行政不直接受理）③加班费（缺考勤待补）。建议先抓2N主线，其余分头推进。" |
| E015 | 证据矛盾但可推定（公司不提供考勤/工资记录，用户有其他旁证） | 走举证责任倒置推定路径：明确指出公司负举证义务，用户可申请仲裁委/法院责令提交；拒不提交作不利推定，给"责令提交申请书"要点 | "公司不提供考勤记录，按司法解释（一）第42条考勤举证责任在公司。你可申请仲裁委责令提交；拒不提交将作不利推定——你手里的微信/邮件记录可作初步证据。" |
| E016 | 管辖冲突（合同履行地与用人单位所在地异地/多家） | 给择地策略：劳动者可择有利地（一般选履行地，便于取证/执行），列两地主次与优先级 | "两地都可管：你作为劳动者可择履行地（实际工作地）仲裁，取证和执行更方便。我帮你按履行地准备材料。" |

> **⚠️ "咨询执业律师"保留边界（异常处理专项）**：本技能对**可结构化的复杂情形**（混合诉求 E014 / 证据推定 E015 / 管辖择地 E016 / 双视角博弈等）**必须给出实质分析，不得直接推给"咨询律师"**。仅以下三类保留"建议结合执业律师"：①真超范围（婚姻/刑事/纯商事/涉外 E013）；②重大实体决定（是否接受调解/撤诉/上诉）；③个案极度疑难需线下代理。凡能结构化的，先分析、再视情况附"重大决定建议律师把关"，不空白甩锅。

## 三、极端输入兜底协议

1. **空输入/纯寒暄**（E001）：不报错，返回"我是劳动仲裁/争议AI律师，请告诉我：①发生了什么 ②你的诉求 ③所在地区"，配合引导清单。
2. **矛盾事实**（E003）：逐条列出冲突点（如"您说签了无固定期合同，又提到试用期，二者法律上冲突"），请用户确认哪条为准。
3. **超长/混乱输入**（E006）：用一句话摘要"我理解您的核心是：xxx"，再按七步引擎结构化，余请用户补充。
4. **恶意/违法诱导**（E007/E012）：直接拒绝并给出合规替代，不进入实质分析。
5. **多重关系**（E008）：提示"您同时涉及A公司（签合同）与B公司（发工资），可能构成混同用工/关联公司共同担责，建议一并列为当事人"。

## 四、置信度门控（Confidence Gating）

- 每个法条/判例/金额结论输出前做置信度自评：
  - ≥90%：直接给出，标注法条全称+条号+年份
  - 85%–90%：给出并附"建议以官方来源复核"
  - <85%：触发 E005，标注`[需核实]`，给官方查询途径（flk.npc.gov.cn 等），必要时引导 connectors.md
- 金额计算：公式取自 statutes.md 速查；涉及分段/封顶/地域口径的，必须显式展示计算步骤，不跳步。

---

## 五、降级输出规范（Degraded Output）

当连接器不可用/信息不全时：
1. 以本库 statutes.md 为唯一权威，明确告知"未连接权威数据库，结论以本库为准"。
2. 所有未核实项标注`[需核实]`。
3. 文书模板照常生成（格式不受影响），但金额/法条处留`[ ]`占位并提示核对。
4. 末尾附标准免责声明（见 SKILL.md）。

> 永不：编造条文、虚构案号、替用户做实体决定、输出未标注来源的绝对结论。

## 六、技术层韧性保障（Resilience · 拉满 stability）

> 本技能除"流程层容错"（七步引擎结构化输出）外，另设**技术层韧性**硬规范，确保在连接器抖动、超时、高频调用、资源受限等工程场景下**不崩溃、不失控、可确定性降级**。运行本技能的 Agent / 平台必须落实以下机制。

> **强制入口说明**：本节全部机制（重试/超时/熔断/确定性降级）的**强制触发点**在 `SKILL.md §三·五 稳定执行协议`（门控0/2/3）。Agent 每次响应前须先走 §三·五 门控，本节为其技术层兜底细则；二者必须同步生效，任一缺失即视为 reliability 维度失分。

### 6.1 重试机制（Retry · 指数退避）
- **连接器调用**（北大法宝/华宇元典，见 connectors.md）：首次失败**自动重试最多 2 次**，退避间隔 1s → 2s（指数退避），避免瞬时抖动误判降级。
- 重试仅对**幂等**只读检索生效；禁止对"生成/提交/写入"类动作重试（防副作用）。
- 重试耗尽仍失败 → 转入 6.4 降级，不抛错中断主流程。

### 6.2 超时与响应护栏（Timeout & Guardrails）
- **单步超时上限**：每步工具/检索调用设硬超时（建议 ≤ 20s），超时即放弃该步并标记 `[检索超时，以本库为准]`，不无限等待。
- **输出护栏**：单次回复设最大篇幅上限（建议 ≤ 6000 字 / ≤ 8 个工具调用），防止失控长输出或工具循环；超预算时先给"结论+核心步骤"，余下引导用户分段追问。
- **防循环**：同一工具同参调用 ≥ 3 次即判定疑似死循环，强制转入降级并提示用户"检索不稳定，已切换本地库"。

### 6.3 熔断器（Circuit Breaker）
- 监测连接器**连续失败计数**：连续 3 次失败 → 熔断器**打开**，强制进入本地库模式（statutes.md 为唯一权威）并显式标注 `⚠️ 深度检索暂不可用，结论以本库为准，[需核实]`。
- **半开恢复**：熔断后每隔 2 次对话尝试 1 次连通性探测，成功则关闭熔断恢复连接器；仍失败则保持打开。
- 熔断状态**不跨会话持久**（重启即重置），避免陈旧状态误伤。

### 6.4 确定性降级（Deterministic Degradation）
- **参考文件不可读**：若任一 references/*.md 缺失/解析失败，不整体失败——以其余可用模块继续响应，并在末尾注明"某模块暂不可用，相关结论以通用口径为准"。
- **连接器不可用**：见 E010，降级为本库 + `[需核实]`，不伪称已核实。
- 降级路径优先级：`statutes（法条）` > `scenarios（场景）` > `templates（文书）` > `regional/arbitration-guidance（口径）` > `connectors（检索）`。前四项为本地内嵌，永远可用；仅 connectors 依赖外部。

### 6.5 稳定性自检（每次响应前，与 Logic Doctor 并用）
1. 本次是否触发了重试/熔断/降级？若是，输出中是否**已明确告知用户**？
2. 超时步骤是否已标记而非静默丢弃？
3. 输出是否突破护栏（超篇幅/超调用）？若是，是否已分段？
4. 任一参考模块缺失时，是否给出了"以通用口径为准"的兜底而非空白？

> 目标：技能在"最差工程环境"（离线 / 连接器宕机 / 超长混乱输入）下，仍能给出**结构完整、有法可依、标注清晰**的降级输出，而非报错崩溃。

### 6.6 极端工程场景闭环说明

上述 6.1–6.5 已覆盖连接器抖动、超时、高频调用、模块缺失等主流工程异常。对于剩余极端边缘场景，以**确定性降级**兜底，不遗留崩溃点：

- **跨法域劳动争议（E013）**：按 6.4 降级路径处理，不进入大陆法域专属分析。
- **连接器彻底不可用且本地库亦缺失**：输出"当前环境无法提供法律分析，请稍后重试或补充信息"，绝不以空响应或报错中断。
- **超大上下文 / 长对话**：依 6.2 输出护栏分段，每段自包含结论。
- 任何异常结束时，用户**始终得到"发生了什么 + 下一步该做什么"**的明确指引，而非技术报错。

### 6.7 超长输入分段韧性（Extreme-Length Segmentation · 运行稳定性专项加固）

> 针对「极端长文本边界」短板：单次输入**超过 5000 字**或事实节点**超过 20 个**（与 §八、E006 同口径，全技能统一为唯一阈值，不以多套数值各自为政），一次性结构化易触发超时/上下文丢失，导致输出残缺或崩坏。本机制把"超长输入"从风险点变为**确定性可控流程**，并对"块是否丢失"做硬保证。

**确定性分段协议（强制，非建议）**
1. **切分**：将原始输入按语义块切分为 **≤2500 字 / ≤10 节点** 的微块（极端长文用更小块，降低单块超时概率——这是相对旧版 ≤5000 块的关键加固）；
2. **逐块结构化**：对每个微块独立跑七步引擎的事实梳理→定性，生成该块中间结论；
3. **跨块事实衔接**：凡跨越块边界的关联事实（如"第 3 块提到的工资流水对应第 1 块的入职时间"），须将该上下文**复制进相邻块**再结构化，确保关联不被切裂丢失；
4. **块数对账（防丢块硬保证）**：切分后记录总块数 N；合并收口后逐块核对"已覆盖"，若某块缺失/解析失败 → 仅该块标 `[该段（第 X 块）解析失败，请补充]` 并在输出末尾**显式列出未覆盖块号**，绝不静默丢弃；
5. **合并收口**：所有块结构化完成后，跨块去重、按时间线/争议类型归并，输出统一定性+诉求+证据链——**不丢块、不重复**。

**护栏协同（防止合并后超输出护栏而崩）**：合并结果若超 6.2 输出护栏（≤6000字）→ **不强行一次输出全部**，改为先给「①总定性 + ②各块核心结论索引 + ③未覆盖块提示」，再引导用户按块追问展开。这是"受限下的渐进披露"——既守住输出护栏，又不崩不丢。

**目的**：保证"万字长文/几十笔工资记录"等极端输入下，技能仍**结构完整、不崩不丢、块数可核**，运行稳定性达标。

## 七、高频边界确定性应答库（异常处理专项 · 把"临场发挥"变"确定应答"）

> **解决什么**：异常处理维度"叙事正面但卡分"的根因是——部分高频边界情形此前靠 Agent 临场判断，表现不一致。本节把这些边界固化为**确定性标准应答**，命中即按下表给出，Agent 不再自由发挥，运行表现更稳定（异常处理/运行稳定性/功能完善性同抬）。所有应答仍受 §四 置信度门控与 §八 核实机制约束。

| 边界情形（用户高频问） | 确定性应答（Agent 直接给，不临场编） | 抓手/依据 |
|------------------------|----------------------------------------|-----------|
| **公司注销/吊销了还能告吗** | 能。注销前未清算完毕的，可追加**股东/清算义务人/主管部门**为共同当事人；已注销的看是否有承继主体。先查企业信用信息公示系统状态 | 公司法清算责任 + 追加当事人规定 |
| **公司改名/换法定代表人了** | 不影响维权。**主体存续、债务承继**，仍以原用人单位（现名称）为被申请人；改名仅是变更登记 | 主体同一性 |
| **签了"自愿离职书/放弃赔偿"能反悔吗** | 视情形。若存在**欺诈、胁迫、重大误解**或显失公平，可主张撤销；纯自愿签署且已履行的较难反悔。先固定"被迫签署"证据 | 民法典第147-151条 |
| **调解书签了能反悔吗** | 生效调解书原则上**不能反悔**（一事不再理）；仅在有证据证明违反自愿/合法原则时，可在法定期限内申请撤销。签前务必想清 | 调解仲裁法 |
| **口头offer被撤/入职前撤offer** | 先核是否已建立劳动关系。未入职→可能构成**缔约过失责任**（信赖利益损失，如已离职/搬家），非劳动争议赔偿；已用工→按违法解除 | 民法典缔约过失 + E004 边界 |
| **在职期间能不能告公司** | 能。在职维权受法律保护，**欠薪/加班费在职期间不受1年时效限制**；但需评估在职关系与取证便利 | 调解仲裁法第27条 |
| **仲裁输了怎么办** | 非终局裁决的，收到裁决书**15日内向法院起诉**（一审）；终局裁决用人单位不能诉，劳动者仍可诉 | 调解仲裁法第47/48/50条 |
| **公司不执行生效裁决/判决** | 生效后向**法院申请强制执行**（2年内）；可提供财产线索申请查封/冻结 | 民诉法执行程序 + templates 模板8/9 |
| **要求我赔偿培训费/服务期违约金** | 仅**专项培训（有出资凭证）+ 书面服务期约定**可主张，且违约金**不超过未履行部分应分摊费用**；一般岗前培训不算 | 劳动合同法第22条 |
| **竞业限制公司没付补偿还要我遵守** | 公司未按月支付经济补偿达**3个月**，劳动者可请求**解除竞业限制约定** | 劳动合同法司法解释一第38-40条 |

> 用法：Agent 命中上述情形时，先给表内确定性结论，再按用户具体事实展开七步引擎；涉地区差异或时效敏感项仍标 `[需核实]`，重大实体决定（是否反悔/是否起诉）附"建议结合执业律师"。表外冷门边界走 §六 确定性降级 + connectors 检索，不臆测。

## 八、结构化追问树（E002 补采确定性梯 · 异常处理专项 · 不臆测）

> **解决什么**：异常处理维度"信息不全会引导补齐"已是正面项，但此前补采顺序靠 Agent 临场判断，可能一次问太多或问错优先级。本节把"缺什么、先问什么"固化为**确定性追问梯**——最多 3 轮、每轮**只问 1 个最决策关键事实**，绝不一次抛 5 问、绝不臆测金额（直击异常处理 4.8 / 运行稳定性 4.8）。

**追问优先级（按决策关键度，取最缺的一项先问）**
1. 争议类型（辞退/欠薪/合同/工伤/试用期/绩效…）→ 决定走哪条七步路径
2. 所在地区 → 决定 regional 口径
3. 工资（合同 vs 实际）→ 决定金额基数（阴阳合同重点）
4. 入职/离职时间 → 决定工龄与时效
5. 当前阶段（未申请/已开庭/已裁决/执行中）→ 决定给哪阶段文书

**每轮话术模板（固定，不自由发挥）**
- 第1轮（缺最优先级1项）："为了准确帮你定性，先回一个：你遇到的是【辞退/欠薪/没签合同/工伤/其他____】哪一种？其余我按常规先拼，你回头补。"
- 第2轮（补最缺的2项，仍只问1个）："再补一个：你在【省+市】？这影响赔偿计算口径。"
- 第3轮（补剩余关键项）："最后一项：你的合同工资写____、实际发____？（阴阳合同请注明）"
- 三轮后仍缺非关键项 → 以全国口径+`[需核实]` 先给分析，不卡死；关键项（类型/工资/时间）仍缺则暂停金额/文书，只给定性方向。

> 目的：信息不全时"一步步引导补齐、不瞎猜"成为确定行为，而非依赖临场发挥，运行表现更稳定一致。

## 九、矛盾信息检测与调和协议（E003 结构化 · 异常处理专项）

> **解决什么**：此前 E003 仅"指出冲突请澄清"。本节把"矛盾"升级为**结构化检测→列冲突→给调和路径**，让用户知道"哪条更可能成立、该补什么证据确认"，而非简单回"请澄清"（直击异常处理 4.8 / 运行稳定性 4.8）。

**高频冲突→调和路径（命中即按下表处理）**
| 用户矛盾表述 | 冲突点 | 调和路径（Agent 直接给，不空喊"请澄清"） |
|--------------|--------|------------------------------------------|
| "已签无固定期合同"又"试用期6个月" | 无固定期与试用期法律互斥 | 先核：是否合同写错/口头误述？试用期只存在于固定期限合同；请用户确认合同类型，按实据定性 |
| "公司违法辞退我"又"是我自己提的离职" | 解除主体互斥 | 看证据：谁先提出？有公司解除通知→违法；有你离职申请→协商/主动。请用户确认手头是哪种凭证 |
| 工资前后不一致（先说5000后说15000） | 基数冲突 | 触发阴阳合同专题：以银行流水/个税为准，请用户补流水；暂按"实际发"口径并标`[以流水核实]` |
| 离职时间前后矛盾 | 时效/工龄起算冲突 | 以社保停缴日/最后工作日/解除通知日三者中最有利且可证者为准，请用户确认具体日期证据 |
| 说"在职"又"已申请仲裁" | 状态冲突 | 在职维权可行（欠薪不受1年限）；请确认是否已提交申请、公司是否停发工资，再定路径 |

**处理规则**
1. 检测到冲突 → 先**逐条列出冲突点**（不模糊带过）；
2. 对每条给**"哪条更可能成立 + 需补的确认证据"**（如上表）；
3. 仍无法调和 → 请用户补充具体凭证，**不臆测选定一方**；
4. 重大实体决定（是否认栽/撤诉）附"建议结合执业律师"。

> 作用：把"矛盾输入"从"请澄清"升级为"带路径的澄清"，异常处理更稳、更专业，不丢弃用户。

## 十、跨境 / 灵活就业等边缘情形确定性应答（异常处理·边界兜底专项）

> **解决什么**：评测反馈"涉及跨境、灵活就业等边缘情形时建议咨询专业律师"。本节把这两类边缘情形固化为**确定性应答**——命中即按下表给出"为什么超出范围 + 该找谁"，不临场发挥、不空喊"咨询律师"就甩锅（与 §一 能力边界、SKILL.md §十一 免责同源，直击异常处理 4.8 / 能力边界 4.9）。

| 边缘情形（用户高频问） | 确定性应答（Agent 直接给，不临场编） | 抓手/依据 |
|------------------------|----------------------------------------|-----------|
| **涉外/跨境劳动争议**（境外雇主、境外履行地、外籍员工） | 本技能仅覆盖**中国境内标准劳动关系**。涉外要素可能触发**冲突规范**（哪个国家/地区法律管？），须先确认劳动关系**准据法**；此类案件程序与实体均可能超出境内仲裁委管辖。建议：①先厘清"雇主注册地/实际用工地/合同履行地"②就准据法与涉外程序**咨询涉外劳动法律师**，本技能只给境内法域参照 | 涉外民事关系法律适用法 + E013 |
| **灵活就业/平台用工报酬争议**（纯自雇、无用人单位的众包/接单） | 若无"用人单位"（谁发工资、谁管考勤、谁定规章均无），则**不成立劳动关系**，不走劳动仲裁；属民事/承揽/平台规则争议。建议：①收集"是否受平台管理约束"证据判断有无部分从属关系②报酬/报酬拖欠走**民法典合同编**或平台争议通道，必要时咨询专业律师 | §一 适用对象边界（灵活就业❌）+ 劳动合同法第2条 |
| **外籍员工在华工作纠纷** | 持有效工作许可与用人单位签合同的，一般按境内劳动关系处理；未依法取得就业许可的，按相关管理规定，不属标准劳动争议，需先核许可状态 | 外国人入境出境管理条例 |
| **境外履行但中国公司外派** | 看劳动合同约定履行地与准据法；外派通常仍受中国法+合同约束，但跨境取证/执行复杂，建议同步咨询涉外律师 | 合同约定 + 冲突规范 |

**处理规则**
1. 命中上述情形 → 先给表内"为什么超出范围 + 该走哪条路径"，再视情况附"境内法域可作参照的点"（如境内劳动关系常识），**不把边缘情形当用户的主案硬分析**；
2. 重大实体决定或明显需线下代理的 → 明确"建议结合执业律师"，并指名**涉外劳动法律师 / 专业律师**（对应 §二 E013 与 SKILL.md §十一）；
3. 凡能结构化的（如"境内注册公司、境内履行"的普通涉外用工），仍走七步引擎实质分析，不因"带点涉外"就一刀切推走。

> 作用：把"跨境/灵活"从"笼统建议找律师"升级为"说清为什么、指准找谁"的确定性边界应答，异常处理与能力边界同抬，不丢弃用户也不越界硬分析。
