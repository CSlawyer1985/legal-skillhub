# 金杜"前沿观察"文章写作

律师能写出正确的法律分析，但写不出**可发表**的文章。差别不在法律，在体例：标题有没有钩子、导语有没有交代"为什么现在读"、每节小标题带不带结论、措辞强度配不配得上证据、结语有没有给出前瞻。

本技能把金杜"前沿观察"的这套写法固化下来。**照着写，不要即兴发挥。**

---

## §1 定体裁

**按文章的主要论证任务定，不按触发事件的表面类型定。**

| 体裁 | 场景 | 核心动作 | 写不好就废的那一条 |
|---|---|---|---|
| **A** 境内新规简评 | 国内部委发文 | 追源流，提炼实质增量 | 每个增量都指名对照的旧规；全文有一处集中回答"真正新的是哪几处" |
| **B** 域外监管应对 | 外国新规/执法冲击中国企业 | 讲清管辖机制 → 给可行路径 | 点明与传统关税壁垒的逻辑差异；每条路径都配"局限" |
| **C** 问答型专题 | 陌生市场/产品科普 | 以"问：……"推进，先立概念 | 每问是读者真会问的；概念用对比定义 |
| **D** 判例评析 | 法院/仲裁庭个案裁判 | 案情→要旨→本地对照→启示 | 逐条列连接因素；如实呈现判例分歧，不代法院下结论 |
| **E** 责任边界论证 | 新业态无明确规则 | 拆功能／行为／主体，逐层归责 | 先固定技术事实前提；按"谁控制了什么"而非"谁参与了"归责 |
| **F** 制度反推 | 出台豁免/简化/试点规则 | 从"豁免了什么"反推"没豁免什么" | **每一节**都完成"豁免—未豁免—一般义务"三拍 |
| **G** 实务方法论 | "该怎么做"的体系建设指南 | 以官方指引要素为框架逐项展开 | 痛点诊断写具体失败形态；每个要素点出"最常见的失效形态" |
| **H** 综合实务指南 | 无新规/新判决的常青文章 | H1 路径比较／H2 自由型 | H1 写明事实假设与权衡；H2 骨架自拟但结构要求照旧 |

### 边界怎么判

- **A vs F**：核心价值是"从豁免反推一般义务"→ F；是"全面识别相对旧规的增量"→ A。国内新规不当然选 A。
- **B vs D**：行政机关发布规则或作出执法/处罚/和解决定 → B。法院、仲裁庭等裁判性质机构作个案决定 → D。**不要把行政处罚决定写成 `A v. B` 式法院判例。**
- **G vs H**：围绕"一条路径怎么做好" → G；围绕"几条路径选哪条" → H1。
- **都不属于** → H2，骨架自拟。连 H2 也不合身（用户要的根本不是实务文章）→ 停下来问。
- **两类都重要**：定一个主体裁，另一类当分析模块借用。但**只要正文实际用了某个模块，那个模块的要求就适用**——把体裁降为"辅助"不会让它的要求消失。

## §3 标题

**`钩子 + 分隔符 + 界定语`**，两段缺一不可。

分隔符：`——`（最常用）／`丨`（栏目、系列）／`：`／`？`／**"事件＋后果"句式中可用逗号**（`FCC新规落地，机器人行业需作好应对准备`）。

| 钩子做法 | 例 |
|---|---|
| 四字格对仗 | 穿透到底、追索到人 |
| 化用成语／反用俗谚 | 小而自有操守 |
| 设问 | AI 责任谁买单？ |
| 事件＋后果断言 | FCC 新规落地，机器人行业需作好应对准备 |
| 意象比喻 | 融资寒冬中的一道"南洋暖流" |
| 从 X 到 Y | 从纸面合规到实质合规 |

界定语三式：`简评《X》`／`从 A 看 B`／`X 中的 Y 边界`。
系列标注：`（上篇）`／`（五）`／`一线观察丨`。

两条硬标准：

- **钩子要对应正文的核心判断。** 验收：删去界定语后，钩子仍能概括全文唯一主结论。别用正文撑不起来的"首次／全面／重磅／史上最严"。
- **禁止纯话题式标题**：`关于X的若干思考`／`浅析X`／`X解读`。见到就重拟。

## §4 导语

**一段，不加小标题，150–350 字**（体裁 G 例外，允许三段）。五个动作压进一段：

1. **落锚**——宏观趋势或行业困境
2. **报事**——按法源写，不要硬套文号：
   - A / F（境内规章）→ `YYYY年M月D日，[机关]发布《[全称]》（[文号]，下称"[简称]"）`
   - B（域外规则）→ `YYYY年M月D日，[机关]发布《[全称]》（[有文号则写文号，否则写机关＋日期]，下称"[简称]"）`
   - D（判例）→ `[法院]在[案件名]一案（[案号]，YYYY年M月D日判决）中……`
3. **称重**——一句话说清体量与突破性：`围绕九个部分提出二十二条措施，首次以跨部门联合发文的形式……`
4. **点名**——谁会疼、疼在哪
5. **交底**——本文分析哪几件事

**以交底收尾。** 惯用落款：`我们基于目前的法律规范和监管框架，就……进行分析和提示。`／`在此，我们结合……，就……进行介绍，希望对大家有所帮助。`／`以供各界参考。`

**C/E/G/H 可省略"报事"**，改为界定讨论对象的内涵与外延（G 是方法论体裁，不围绕单一事件）。

## §5 结构与小标题

一级 `一、二、三、`，二级 `1. 2. 3.`，不超过三层。

**每个分析性小标题必须携带判断。这是最容易丢、也最能拉开差距的一项。**

合格测试：**只读标题就能知道本节的法律结论或实务含义。**
`基本情况／主要内容／适用范围／合规建议／三个方面` 本身不算判断——**加了冒号也不算**。

**适用范围**：一级与二级的分析性标题。
**三处例外**（本来就不承载分析）：`结语`／`引言`；体裁 C 的 `问：……` 标题；纯清单或收尾件标题（`合规提示清单`／`参考资料`）。

```
✗ 二、党的领导                 ✓ 二、党的领导：从"基础性要求"升格为"治理体制"
✗ 4. 战争部特别授权            ✓ 4. 战争部特别授权——难度较高的个案尝试
✗ 三、股东治理                 ✓ 三、股东治理：准入、识别、行为、追责的全周期闭环
```

三种模式：`主题：从 X 到 Y`／`主题——[评价性短语]`／`主题：[N 要素并列概括]`。

节与节之间要有推进关系，不要平行罗列。

## §6 六个招式

至少用足两个（短快讯除外）。详细示范见 `genres.md`。

| 招式 | 怎样才算用足（仅提一句不算） |
|---|---|
| **源流—增量** | 同时写出旧规则、共同点、实质变化三者 |
| **反推** | "先看豁免了什么 → 再看没豁免什么 → 反推一般主体义务"三拍 |
| **拆层** | 功能、行为、主体及对应义务逐项落位 |
| **对照表** | ≥2 个对象、≥3 个维度，且正文得出一项非复述的结论 |
| **案例镜鉴** | 讲清"监管/法院是怎么看出来的"，不止于结论 |
| **失效形态** | 讲完规范后点出实践中最常见的做砸方式（G 必备） |

**源流—增量**是 A 的命脉：
> "穿透识别并非 4 号文首创，2018 年《商业银行股权管理暂行办法》已确立该框架……4 号文的突破在于，将原本针对金控集团的隔离要求，一般化为全部金融机构股东准入的负面清单。"

**案例镜鉴**要讲机制，不要只讲结果：
> "FCC 认定 Odyssey 产地虚假陈述的关键事实之一是：其测试文件显示实际测试地在中国，而被问询的组装厂商否认曾提供组装服务。"

数量按篇幅定，**不为凑数**：1500 字以上 ≥2 个；1500 字以下快讯 ≥1 个；用户只要事实快讯（截止日变更、适用对象、今日动作）时可以一个都不用。

**"不为凑数"优先于数量下限**：已经用足该体裁在 `genres.md` 里指定的**必选招式**，而第二个招式在本题上确实不自然时，写一句说明即可，不要硬塞不产生新判断的表格、案例或制度史。

表格承载并列信息，正文承载判断——**正文不复述表格**。

## §7 语体

### 断言强度要配得上证据

这是律所文章的生命线。

| 证据状态 | 措辞 |
|---|---|
| 白纸黑字的条文 | 均属无效／不受限制／应当／不得 |
| 对条文的解释结论 | 我们理解／原则上／通常／一般而言 |
| 有依据的推断 | 可能／预期／不排除……的可能 |
| 监管态度未明 | 有待观察／尚无定论／至今尚未获得最终解决 |
| 本所建议 | **宜／不宜**／建议／值得考虑 |

**同一句不要混用两档**：`应当自……起算为宜` 是错的。二选一——
`起算时间应当自……计算。`（条文明确）／`我们理解，以……作为起算时间为宜。`（解释建议）

**"宜/不宜"是金杜的招牌**，比"应当"软、比"可以考虑"硬，用于给建议而不僭越监管。凡文中给了建议就该出现——**属质量项，不是硬门槛**（纯事实快讯可以没有建议，也就不需要它）。

推测监管走向时不用"必将／势必／一定／毫无疑问"。

### 第一人称：由署名人数决定

- **多作者署名 → 全文用"我们"**
- **单作者署名（含"一线观察"类）→ 全文用"笔者"**
- 同文不得混用；不确定时默认"我们"。
- 读者称"企业""机构""相关企业"，**不用"您"**。

### 其他

- **四字格与对仗**用于概括性判断：`纵向到底、横向到边、看意图、看效果`。每篇 2–4 处，多则油腻。
- **推进连接词**：不仅如此／更关键的是／值得注意的是／反之／换言之／有鉴于此／特别需要指出的是。
- **一体两面式判断句**：`二者实为治理失灵的一体两面：A 是自外向内的"股东俘获"，B 是自内向外的"管理层擅权"。`
- **比喻降载**：抽象机制先打比方，**紧接着必须回到技术表述**。比喻是台阶，不是结论。
- **忌口**：**唯一词表在 `diction.md` 的「忌口」节**——checklist 和 lint 脚本都以它为准，不在别处另列。
  常见的几个：赋能／抓手／打法／浅析／若干思考／感叹号／众所周知／毋庸置疑／完美解决／彻底规避／您。

### 防"句式缝合怪"

`diction.md` 是功能示例库，**不是可拼装的句库**。先用朴素、就事论事的语言完成分析，**再**做一次语体修订。倒过来做，会写出"每句都像金杜、整体是模板拼贴"的东西——材料越少越容易这样。

- 除法规引称等固定格式外，不连续照搬示例 12 字以上；全文最多直接沿用两处示例短语。
- 同一段最多用一个 `diction.md`「过渡与推进」表里的**推进词**（不含"但/因此/同时"这类基础连词）；相邻两段不用同一推进结构。
- **搬家测试**：任何一句如果替换法规名后可无损搬到另一篇文章，改写它——让它包含本案事实、规则差异或因果判断。
- **去模板化复读**：某段若只有"值得注意的是／更关键的是／有鉴于此"，没有新增的事实、比较、因果或行动含义 → 删掉。
- 不要用宏观背景、四字格和业务推介凑篇幅。

## §8 引注体例

- **法规首次出现**：`《全称》（文号，下称"简称"）`，其后一律用简称。
  无文号的法源（外国规则、官方指引、网页问答）写 `《全称》（[发布机关]，[发布日期]，下称"简称"）`。
- **外文术语**：`中文（English，"简称"）`，如 `受限清单（Covered List）`。
- **判例**：`当事人 v. 当事人一案（案件编号 X，于 YYYY 年 M 月 D 日作出判决）`。
- **每个独立法律主张紧邻脚注**——正文、标题、表格、清单里关于规则内容、适用范围、法律后果、例外、程序、期限、裁判观点的每个命题。一个脚注只支持紧邻句的命题。
- **定位精度按法源类型匹配**，不要把"条款级"机械套到没有条款号的法源：
  成文法 → 条/款/项；判决 → 案号＋段落号或页码；监管指引 → 章节或问答编号；官方网页 → 标题＋发布日期＋链接；二手材料 → 页码。

### 拿不准的地方写 `[待核]`，不要填一个看起来合理的编号

文号、条款号、案号、日期、金额、比例记不准时，写 `[待核：文号]`，并在文末汇总，交给律师核。

**在律所文章里编一个文号，比这篇文章不写的损害大得多**——格式越像金杜，假信息越可信。同理，不确定某规则是否已废止时写 `[待核：效力状态]`，不要凭印象写"已于 X 年废止"。

用户没给原文、你也确证不了的，先向用户要材料，或者把不确定处如实标出来。

## §9 结语与收尾件

### 结语不是摘要

四个动作：

1. **归结实质**——把全文压成一两句话（"其规范对象可归结为两个层面：……"）。所有体裁必做。
2. **点名增量——按体裁写不同的东西**：
   A/F 写制度增量（"真正新设的要求集中在四处：……"）；D 写裁判规则的增量；B 写管辖机制的要害；
   **C/E/G/H 没有"制度变化"可点**，改写核心判断或适用边界。不要硬套"制度增量"。
3. **前瞻——接下来要盯什么**：有监管进程就写在审法案、配套细则、执法动向、调查周期；
   **常青型文章（C/E/G/H）没有监管进程可盯时，写"什么条件变化会推翻本文结论"**——不要为凑前瞻虚构监管动态。
4. 一句促行动的判断句收尾

> "机构宜在配套细则出台前完成差距分析，而非待评估结果落地后被动整改。"

### 合规提示清单（A/B/F/G 应有，置于结语前）

按"立即整改项 / 制度建设项"或按工作流分组。每项为**动宾短语＋具体动作**：

> ✓ 产品对照排查：按 ARD 四要件与排除项，对全系产品逐一判别是否落入范围，重点关注半身/可变形、拆分销售、软件可激活等模糊形态
> ✗ 加强合规管理，提高风险意识

### 收尾件（**顺序的唯一版本在 `boilerplate.md`**）

1. **致谢**——除非用户提供了实习生姓名，不生成
2. **香港表述声明**——正文只要出现"香港"就必须加，固定文本不得改写
3. **业务推介**——除非用户说明这是金杜署名对外发布，不生成（技能不知道作者是谁，不替人署名或招揽业务）
4. **分类标签**——2–4 个业务/行业领域
5. **参考资料**——`[n]` 编号脚注列表
6. **待核事项**——正文有 `[待核：…]` 就在文末汇总；没有则不写这一节

## §11 写完自查

逐条过 `references/checklist.md`。**★ 项必须全部通过；○ 项尽量通过，未通过的在交付时说明原因。**

可选：跑一遍文风机械自查——只查标题格式、小标题是否带判断、忌口词、感叹号、"您"、人称混用、香港声明、脚注编号等机械项，**不判断法律内容对错**：

```bash
python3 scripts/lint_article.py <稿件路径>
```
