# 专利申请文件撰写规范详解

> 本文件详细说明说明书、权利要求书、摘要等申请文件的撰写要求，供撰写和审核时对照使用。

---

## 一、说明书（Description）撰写规范

### 1.1 基本框架

```
┌─────────────────────────────────────────────┐
│ 发明/实用新型名称                            │ ← 居中，与请求书一致
├─────────────────────────────────────────────┤
│ 技术领域                                    │ ← 具体技术领域
│ 背景技术                                    │ ← 引证最接近现有技术
│ 发明/实用新型内容                            │ ├── 要解决的技术问题
│                                             │ ├── 技术方案
│                                             │ └── 有益效果
│ 附图说明                                    │ ← 各幅附图简略说明
│ 具体实施方式                                │ ← 详细描述优选方式
│ [序列表]                                    │ ← 核苷酸/氨基酸序列时需包含
└─────────────────────────────────────────────┘
```

### 1.2 名称（Title）

| 要求项 | 规范 | 不规范示例 |
|--------|------|-----------|
| 字数 | 一般≤25字，必要时≤60字 | 超过60字 |
| 内容 | 简短准确表明主题和类型 | 仅用"方法""装置"等笼统词 |
| 用词 | 使用技术术语 | 含人名、商标、代号、型号 |
| 一致性 | 与请求书名称一致 | 不一致 |
| 宣传 | 不得使用商业性宣传用语 | "世界首创""国内领先" |

**正确示例**：
- "一种燃煤锅炉节能装置及其制造方法"
- "用于钢水浇铸的模具"
- "拉链及其制造方法"

**错误示例**：
- "一种新式装置"（未给出任何发明信息）
- "张三发明的机器"（含人名）
- "XX牌智能控制器"（含商标）
- "一种方法及其他类似物"（含糊词语）

### 1.3 技术领域（Technical Field）

**要求**：写明要求保护的技术方案所属或直接应用的具体技术领域。

**判断标准**：
- ✅ 正确："本发明涉及一种挖掘机，特别是涉及一种挖掘机悬臂"
- ❌ 错误上位："本发明涉及一种建筑机械"（太宽泛）
- ❌ 错误具体："本发明涉及挖掘机悬臂的椭圆形截面"（就是发明本身）

**技巧**：通常与国际专利分类表中的最低位置相关。

### 1.4 背景技术（Background Art）

**必须包含的内容**：
1. 对理解、检索、审查有用的背景技术描述
2. 引证反映背景技术的文件（专利/非专利均可）
3. 客观指出存在的问题和缺点（仅限于发明要解决的）

**引证文件要求**：
- 必须是公开出版物（包括电子出版物）
- 非专利文件公开日应在本申请申请日之前
- 专利文件公开日不晚于本申请公开日
- 外国文献应使用原文出处并给出中文译文

**格式示例**：
> "目前，挖掘机的悬臂普遍采用长方形截面结构。例如，中国专利CNXXXXXX公开了一种挖掘机悬臂，其悬臂主体采用长方形空心钢管制成。然而，这种结构在重载作业时容易产生应力集中，导致疲劳裂纹的产生，影响设备的使用寿命和安全性能。"

### 1.5 发明/实用新型内容（Summary of Invention）

#### （1）要解决的技术问题

**要求**：
- 针对现有技术的缺陷或不足
- 使用正面、简洁、客观的语言
- 不得采用广告式宣传用语
- 可列出一个或多个技术问题（但都应与总发明构思相关）

**示例**：
> "本发明要解决的技术问题是提供一种椭圆形截面的挖掘机悬臂，以减小重载作业时的应力集中，提高悬臂的抗疲劳性能和使用寿命。"

#### （2）技术方案

**核心要求**：至少反映包含全部必要技术特征的独立权利要求的技术方案。

**撰写要点**：
- 首先写明独立权利要求的技术方案（用语与权利要求相应或相同）
- 以必要技术特征总和的形式阐明实质
- 可进一步描述从属权利要求的附加技术特征改进

**示例**：
> "为解决上述技术问题，本发明提供一种挖掘机悬臂，其特征在于：所述悬臂主体的横截面为椭圆形，椭圆的长轴方向与悬臂受力方向一致。"

#### （3）有益效果

**定义**：由构成发明的技术特征直接带来的，或者由所述技术特征必然产生的技术效果。

**表达方式**：
- 结构分析 + 理论说明（机械、电气领域常用）
- **实验数据**（化学领域必需）
- 统计结果（感官判断类如味道、气味）

**注意事项**：
- 不得只断言具有有益效果而不作分析
- 应与现有技术进行比较
- 列出实验数据时应给出必要的实验条件和方法

**示例**：
> "与现有长方形截面悬臂相比，本发明的椭圆形截面悬臂具有以下有益效果：（1）应力集中系数降低约30%，显著提高了抗疲劳性能；（2）在同等材料用量下，承载能力提升约15%；（3）通过有限元仿真验证，疲劳寿命延长约2倍。"

### 1.6 附图说明（Brief Description of Drawings）

**要求**：
- 对所有附图作出图面说明
- 零部件较多时可列表说明
- 图名+简要内容说明

**示例**：
> "图1是本发明挖掘机悬臂的主视图；
> 图2是图1所示悬臂的A-A剖视图；
> 图3是图2中椭圆形截面的局部放大图；
> 图4是本发明与现有技术的应力分布对比图。"

### 1.7 具体实施方式（Detailed Description）

**这是说明书最重要的部分！**

**基本要求**：
- 详细描述申请人认为实现发明的优选的具体实施方式
- 适当情况下举例说明
- 有附图的应当对照附图进行说明
- 使所属领域技术人员能够实现该发明

**实施例数量指导**：

| 情况 | 推荐实施例数量 |
|------|---------------|
| 权利要求范围窄，一个实施例足以支持 | ≥1个 |
| 权利要求范围宽，概括需要支持 | ≥2个不同实施例 |
| 涉及数值范围 | 两端值附近各一个 + 中间值至少一个 |

**产品发明实施方式应描述**：
- 机械构成 / 电路构成 / 化学成分
- 各部分之间的相互关系
- 可动作产品还需说明动作过程/操作步骤

**方法发明实施方式应描述**：
- 方法步骤
- 工艺条件（可用参数或参数范围表示）

**附图标记使用规范**：
- ✅ "电阻3通过三极管4的集电极与电容5相连接"
- ❌ "3通过4与5连接"（不加括号，不用纯数字）
- 附图标记应与附图所示一致
- 放在相应技术名称后面

## 二、权利要求书（Claims）撰写规范

### 2.1 基本结构

```
权利要求书
├── 1. 独立权利要求1（第一独立权利要求，保护范围最宽）
├── 2. 从属权利要求1（引用权1，附加特征A）
├── 3. 从属权利要求2（引用权1，附加特征B）
├── 4. 独立权利要求2（并列独立权利要求）
├── 5. 从属权利要求3（引用权4，附加特征C）
└── ...
```

### 2.2 独立权利要求（Independent Claim）

**定义**：从整体上反映发明/实用新型的技术方案，记载解决技术问题的必要技术特征。

**必要技术特征的判断**：
- 从所要解决的技术问题出发
- 考虑说明书描述的整体内容
- **不应简单将实施例中的全部特征认定为必要技术特征**

**典型格式**：

**产品权利要求**：
> "1. 一种[产品名称]，其特征在于，包括：[必要技术特征A]；[必要技术特征B]；以及[必要技术特征C]。"

**方法权利要求**：
> "1. 一种[方法名称]，其特征在于，包括以下步骤：[步骤A]；[步骤B]；以及[步骤C]。"

### 2.3 从属权利要求（Dependent Claim）

**定义**：包含了另一项同类型权利要求的所有技术特征，且用附加技术特征作进一步限定。

**格式**：
> "2. 根据权利要求1所述的[产品/方法]，其特征在于，[附加技术特征]。"

**注意**：
- 保护范围落在所引用权利要求的保护范围之内
- 可以引用独立权利要求或其他从属权利要求
- 多项从属权利要求只能作为择一引用的基础

### 2.4 特殊类型权利要求撰写

#### 用途权利要求（Purpose-Limited Product Claim）

**格式**：
> "一种用于[用途]的[化合物/组合物/产品]X"

**用途限定的作用**：
- 对产品本身有实际影响 → 限定保护范围
- 仅描述用途/使用方式 → 新颖性/创造性判断时不考虑

**物质的医药用途**（瑞士型权利要求）：
> "化合物X在制备治疗Y疾病的药物中的应用"

#### 功能性限定（Functional Limitation）

**适用条件**（须同时满足）：
1. 某技术特征无法用结构特征限定
2. 或用结构特征限定不如功能/效果特征恰当
3. 该功能/效果能通过规定实验/操作/惯用手段直接肯定地验证

**风险提示**：
- 功能性限定覆盖所有能实现该功能的实施方式
- 如果说明书中只有特定实现方式 → 可能得不到支持
- 纯功能性权利要求不允许

#### 马库什权利要求（Markush Claim）

**定义**：用可选择要素（马库什要素）的并列选择方式撰写的权利要求。

**示例**：
> "一种组合物，包含选自下组的组分A：甲、乙、丙..."

**单一性判断**：
- 所有可选择要素具有共同的性质/作用
- 能够预见任一选择均能解决同样的技术问题

### 2.5 权利要求常见缺陷

| 缺陷类型 | 表现形式 | 后果 |
|---------|---------|------|
| 缺少必要技术特征 | 未记载解决技术问题不可缺少的特征 | 保护范围不清楚 |
| 非必要技术特征写入独立权利要求 | 将非必要特征写入独立权利要求 | 保护范围不当缩小 |
| 上位概括无支持 | 概括超出说明书公开范围 | 得不到说明书支持 |
| 功能性限定过宽 | 无法验证功能能否以所有方式实现 | 可能被驳回 |
| 引用关系混乱 | 多项从属权利要求作为基础再引用 | 形式缺陷 |
| 主题名称不一致 | 权利要求主题与限定内容矛盾 | 保护范围不清 |

## 三、摘要（Abstract）撰写规范

### 3.1 文字部分要求

| 项目 | 要求 |
|------|------|
| 内容 | 名称+技术领域+技术问题+技术方案要点+主要用途 |
| 字数 | **≤300字**（含标点符号） |
| 标题 | 不得使用标题 |
| 宣传语 | 不得使用商业性宣传用语 |
| 引用 | 不得引用附图标记（如需标注应加括号） |
| 重点 | 以技术方案为主 |

### 3.2 摘要附图

| 项目 | 要求 |
|------|------|
| 选择 | 由申请人指定最能说明技术方案主要技术特征的一幅附图 |
| 大小 | 缩小到4cm×6cm时仍能分辨细节 |
| 替代 | 可包含最能说明发明的化学式（视为摘要附图） |
| 无合适附图 | 可不要求指定 |

### 3.3 摘要与说明书的区别

| 特征 | 摘要 | 说明书 |
|------|------|--------|
| 法律效力 | 无法律效力 | 有法律效力 |
| 修改依据 | 不能作为修改依据 | 可作为修改依据 |
| 解释范围 | 不能解释保护范围 | 可用于解释权利要求 |
| 性质 | 技术信息载体 | 公开/确定保护范围的文件 |

## 四、外观设计申请文件特殊要求

### 4.1 图片或照片

| 要求项 | 规范 |
|--------|------|
| 视图名称 | 主视图、后视图、左视图、右视图、俯视图、仰视图、立体图等 |
| 图片绘制 | 清晰、线条均匀、不得涂改、不得使用工程蓝图 |
| 照片拍摄 | 清楚反映外观设计、避免反光/阴影、背景单色 |
| 比例 | 同一附图相同比例，局部可另加放大图 |
| 标注 | 中文必要时括号注明原文 |

### 4.2 简要说明

**必须包含的内容**：
- 外观设计产品的名称
- 外观设计产品的用途
- 设计要点（可省略时说明省略）
- 指定一幅最能表明设计要点的图片/照片

**可选内容**：
- 请求保护色彩
- 省略视图的情况
- 平面产品的单元图案排列方式的说明
- 细长物品省略长度的情况

### 4.3 图形用户界面（GUI）特殊要求

**提交方式**：
1. 产品整体外观设计方式提交
2. 局部外观设计方式提交

**动态GUI**：
- 提交能够确定动态变化状态的图片/视频
- 说明动态变化过程

## 五、申请文件审核检查清单

### 5.1 说明书检查清单

- [ ] 名称是否与请求书一致？字数是否符合要求？
- [ ] 是否按顺序包含五大部分？（技术领域→背景技术→发明内容→附图说明→具体实施方式）
- [ ] 技术领域是否为具体技术领域而非上位或发明本身？
- [ ] 背景技术是否引证了最接近的现有技术？
- [ ] 是否清楚说明了要解决的技术问题？
- [ ] 技术方案是否反映了独立权利要求的全部必要技术特征？
- [ ] 有益效果是否有理有据？（化学领域是否有实验数据？）
- [ ] 具体实施方式是否足够详细使技术人员能够实现？
- [ ] 实施例数量是否足以支持权利要求的保护范围？
- [ ] 附图标记使用是否规范？
- [ ] 是否使用了禁止性用语？（如"如权利要求…所述"）
- [ ] 是否含有商业性宣传用语？
- [ ] 计量单位是否为国家法定计量单位？

### 5.2 权利要求书检查清单

- [ ] 是否至少有一项独立权利要求？
- [ ] 编号是否正确？（阿拉伯数字顺序编号，前不加"权利要求"）
- [ ] 独立权利要求是否记载了全部必要技术特征？
- [ ] 从属权利要求的引用关系是否正确？
- [ ] 权利要求类型是否清楚？（产品/方法）
- [ ] 是否以说明书为依据？（概括是否得到支持？）
- [ ] 是否清楚、简要？
- [ ] 是否含有插图？（权利要求中不得有插图）
- [ ] 特殊类型权利要求是否符合相关规定？

### 5.3 摘要检查清单

- [ ] 字数是否≤300字？
- [ ] 是否包含名称、技术领域、技术问题、技术方案要点、主要用途？
- [ ] 是否使用了商业性宣传用语？
- [ ] 是否指定了摘要附图（如有附图）？

### 5.4 申请文件一致性检查

- [ ] 请求书发明名称 = 说明书发明名称？
- [ ] 说明书附图标记 = 附图中标记？
- [ ] 说明书技术方案 = 权利要求技术方案？
- [ ] 摘要附图 = 说明书附图之一？
- [ ] 各文件中的申请人/发明人信息一致？
