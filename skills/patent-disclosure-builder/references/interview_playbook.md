# 对话式追问问题库（Interview Playbook）

本文件是引导发明人时的"追问弹药库"。核心原则：**一次只问 1–3 个问题，用发明人听得懂的大白话问，禁止一次抛长清单。** 根据发明人回答动态选择下一个问题，答得清楚就跳过，答得含糊就继续深挖。

---

## 阶段 0：素材摄入（可选前置，能省则省）

很多发明人手上已经有现成材料（PPT、需求/设计文档、论文、代码说明、技术评审记录、专利检索报告等）。**优先请他们把这些直接发过来，我先消化，再只补问缺口**——这比让发明人从零口述省力得多。

- 开场就顺带问一句："你手上有没有现成的材料？比如讲这个方案的 PPT、设计文档、论文、代码说明、评审纪要——有的话直接发我，我先看，能少问你很多。"
- 收到素材后，我要做的事（发明人无需操心）：
  1. **提取内容**：把 PPT/Word/PDF/图片等转成文本（调用工作区现成的文档转换/OCR 能力，见 SKILL.md 第 0.5 步）。
  2. **消化预填**：把提取出的信息按模板章节归位，能填的先填进 `disclosure_template.md`（发明点、背景、方案、效果、参数、图……）。素材里的图可直接留用。
  3. **反向补问**：对照模板，**只问素材没覆盖到、或写得含糊的部分**。进入阶段 A~H 时，凡素材已答清楚的就跳过或仅做一句确认，不重复问。
- **消化纪律（重要）**：
  - **忠实来源，不臆造**：素材没写的技术细节不许脑补；拿不准的地方标"（据素材理解，需你确认）"，让发明人核对。
  - **区分事实与推断**：从素材直接摘录的事实，与我基于素材做的归纳/推断，要能分清；推断部分主动请发明人确认。
  - **警惕"公开"信号**：素材若是已发表论文、已上线产品文档、已对外的 PPT/投标书，要**立刻提示新颖性风险**（可能已构成现有技术），并在阶段 H 重点确认公开时间与范围。
  - **区别点仍需深挖**：素材通常把"方案讲清楚了"，但很少写清"跟现有技术的区别点"。素材消化完，阶段 D 的区别点深挖**一步都不能省**。

## 通用追问链（适用于所有领域）

按交底书模板的章节顺序推进，每一节都遵循"先开放问 → 再钉细节 → 最后专利视角深挖"三层。

### 阶段 A：破冰 + 抓住发明核心
先让发明人放松地讲，不要一上来就问技术细节。
- "用一两句话，你这个发明是干嘛的？想解决什么问题？"
- "假设我完全不懂，你会怎么跟我解释它？"
- （听完后复述一遍确认）"我理解你要解决的问题是 ___，做法是 ___，对吗？"

### 阶段 B：背景与痛点（对应模板第二章）
- "在你这个方案之前，大家一般怎么做这件事？"
- "那种做法有什么不好？具体在什么情况下会出问题？"
- 追问痛点具体化："这个'不好'能再具体点吗？是慢、是贵、是不准、还是容易坏？"
- 锁定技术问题："所以本质上，你要解决的技术问题是 ___，我这样概括准确吗？"

### 阶段 C：技术方案讲清楚（对应模板第三章 3.1–3.2）
- "现在把它当成教一个新同事，一步一步讲你是怎么做的。"
- 软件/方法类顺着问："输入是什么？→ 中间做了哪几步处理？→ 每一步的判断依据/条件是什么？→ 输出是什么？"
- 硬件/结构类顺着问："有哪几个主要部件？→ 它们怎么连接/装配？→ 工作时各部件怎么配合？→ 信号/力/物料是怎么传递的？"
- 卡壳时给脚手架："要不我们先从最关键的那一步说起？"

### 阶段 D：挖区别点（对应模板 3.3——最关键，务必深挖）
这是决定能否授权的核心，必须追到底。
- "你这个做法，和刚才说的现有做法，最不一样的地方在哪？"
- 逐条对比法："我把你的方案拆成几步：第一步…第二步…。这几步里，哪些是现有技术里没有的，或者你改动过的？"
- 对每个区别点钉死："这一点，现有技术真的没有吗？还是只是没人这么组合过？"
- "如果去掉这个改动，方案还能解决问题吗？"（判断该特征是否必要技术特征）

### 阶段 E：有益效果 + 因果链（对应模板第四章）
- "相比老办法，你这个带来了什么好处？"
- 量化引导："这个好处有没有数据？比如快了多少、省了多少、准了多少？哪怕是大概的量级也行。"
- 建因果链（专利视角关键）："这个好处，是因为你前面哪个改动带来的？我们把'改动X→效果Y'一条条对上。"

### 阶段 F：实施例落地（对应模板第五章）
- "给我一个真实能做出来的例子，具体到参数和数值。"
- "这里的关键参数有哪些？各自取多少合适？有没有范围？"
- "有没有做过实验/测试？结果怎样？"

### 阶段 G：扩大保护范围（对应模板第六章——专利视角深挖）
这一步发明人通常想不到，必须由助手主动引导。
- 找替代方案："刚才这个部件/步骤，有没有别的东西也能实现同样的效果？"（每个关键特征都问一遍）
- 上位概括："你说的是'用螺栓固定'，但其实只要能拆卸就行，对吗？"（把具体特征往上抽象，但不能抽象到超出发明实际贡献）
- 扩展场景："这套东西除了现在这个用途，还能用在别的地方吗？"

### 阶段 H：附图与收尾（附图在正文图文混排，不单开章节）
- **主动收图（不只是问"要哪些图"，而是请发明人把图发过来）**：
  - "为了把方案讲清楚，我们配几张图。你手上有现成的图吗？架构图、流程图、时序图、UI 截图、装置结构图都行——现成的截图、PPT 里导出、甚至手绘拍张照发我都可以。"
  - 软件/系统类至少要：一张系统架构图 + 一张方法流程图；硬件/结构类至少要：一张装置结构图。
  - 每收到一张，问清"这张是什么图、该放哪一章、一句话图注"（架构/流程/时序→3.2 技术侧，UI 交互→3.1 产品侧）。
- **发明人给不出图，或提供的图不清晰/不规范时 → 主动提出"我按你讲的方案先画一张示意图，你看着改"**：
  - 话术："图没有也没关系，我可以根据你刚才讲的，先画一张系统架构图/流程图的草图，你看着不对的地方直接告诉我改。"
  - 生成的是**架构图**（模块 + 连线，对应 3.2 技术侧的系统组成）或**流程图**（步骤 + 判断分支，对应方法执行过程）；用 `scripts/gen_diagram.py` 生成（详见 SKILL.md 第 4 步）。
  - **必须让发明人核对**：图是"AI 依据你的口述整理的示意图"，可能有偏差，交付时在图注或正文注明🤖"（示意图，供核对修改）"，绝不当成发明人确认过的最终图。
  - 生成前先跟发明人对齐"这张图要画哪几个模块/哪几步、谁连谁、哪个是核心"，据此填 gen_diagram 的 nodes/edges 或 steps，**忠实于发明人讲过的内容，不臆造未提及的模块或步骤**。
  - 若发明人明确说"图我自己后面补"，则不生成，在对应正文标注"（此处待补：xxx图）"。
- "这个方案有没有已经对外公开过？论文、展会、上线、投标都算。"（新颖性风险，必问）
- "还有什么你觉得重要、但我刚才没问到的吗？"

## 分领域自适应追问补充

识别领域后，在阶段 C/D 叠加对应的专项追问。判断领域看关键词：出现"算法/流程/系统/数据/模型/接口"偏软件；出现"结构/部件/材料/装配/电路/机械"偏硬件。

### 软件 / 算法 / AI 类
- 数据流："数据从哪来、经过哪些处理、以什么形式存储和输出？"
- 判断逻辑："关键的判断/分支条件是什么？阈值怎么定的？"
- 模型类："训练数据、特征、模型结构、损失函数里，哪部分是你的创新？"
- 关键区别常在：算法改进点、数据处理方式、系统架构、软硬件结合方式。

#### ⚠️ 客体/技术性自查（软件类【强制】环节，不可跳过）
中国专利里，纯粹的算法、商业规则、智力活动规则**不属于可专利主题**，是软件类交底书最高频的驳回点。识别为软件/算法/AI 类发明时，**必须**在阶段 D（区别点）之后、阶段 E 之前，显式跑一遍下面这组"客体三问"，帮发明人把方案从"纯规则"锚定到"技术方案"上：
1. **技术问题**："你解决的是一个**技术问题**（如降低时延、提高准确率、节省算力/带宽），还是一个纯商业/管理问题（如提高销量、优化定价规则）？" —— 若答成纯商业问题，追问："它最终是通过什么**技术手段**落地的？"
2. **技术手段**："这个算法/规则，是运行在什么**技术环境**里、去处理什么**技术数据**、或去控制/改造什么**技术对象**的？"（把算法绑定到具体的采集、控制、处理、硬件执行等技术场景）
3. **技术效果**："跑完之后带来的是**技术层面**的改善（更快/更准/更省资源/更稳定），还是仅仅是经营结果？"
- 处理结论：
  - 若三问都能落到技术面 → 在交底书 3.1/3.2 中**明确写出"技术问题—技术手段—技术效果"三要素及其运行的技术环境**，客体风险低。
  - 若明显偏纯商业规则/纯智力活动 → **如实向发明人提示客体风险**，并引导其补充"技术实现细节 + 技术效果"，把方案往技术应用侧收拢；仍无法锚定的，在交付说明里标注"存在客体（可专利主题）风险，建议代理人重点评估"，**不替发明人硬凑技术性**。
- 术语解释见 `patent_concepts.md` 的"软件/算法类的客体问题"。

### 硬件 / 机械 / 结构类
- 部件清单："完整列一下有哪些零部件？"
- 连接关系："它们之间是怎么连接的？固定/活动/可拆卸？"
- 配合动作："工作时各部件怎么运动、怎么配合？"
- 结构创新点："形状、位置关系、连接方式，哪一处是新的？"
- 材料/工艺："有没有特殊材料或加工工艺？"

### 电学 / 电路 类
- "电路由哪些模块组成？它们的连接和信号流向？"
- "哪个模块/连接方式是关键改进？"
- "有没有关键的元件参数、时序、控制逻辑？"

### 通信 / 网络 类
- "涉及哪些通信节点？交互流程/信令顺序是怎样的？"
- "协议/帧结构/资源分配上有什么改进？"

## 追问纪律（务必遵守）
1. **一次 1–3 问**，绝不甩长清单，避免发明人被吓退。
2. 每答完一段，**先复述确认再往下**，防止理解偏差。
3. 发明人答不上来时，**给脚手架/举例**，而不是反复追问同一个问题。
4. 区别点（阶段 D）和扩大保护范围（阶段 G）是发明人最容易忽略、又最影响专利质量的两处，**必须主动深挖，不能因为发明人没提就跳过**。
5. **软件/算法/AI 类发明，必须执行上面的"客体/技术性自查"三问**，把方案锚定到技术问题—技术手段—技术效果；有客体风险要如实提示，不替发明人硬凑技术性。
6. 全程用大白话，专利术语（如"上位概括""必要技术特征"）要顺带用一句话解释，具体解释见 `patent_concepts.md`。
