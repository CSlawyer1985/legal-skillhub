## 1、\*发明点概述

弹幕已成为视频用户观剧过程中互动的重要场景，为用户提供发表感想、解答疑惑、抒发感情的主要渠道。海量弹幕数据中蕴含着丰富的用户观剧信息，可作为平台挖掘用户诉求及痛点、提升体验、促进活跃的重要数据来源。当前弹幕的产品形态主要有两类：一是**普通用户弹幕**（用户直接发送或通过弹幕评论形成用户之间的互动）；二是**平台运营弹幕**（平台人工编辑，用于 IP 宣发、氛围营造等）。现有形态下，用户在观剧过程中产生的疑问（如对剧情、角色、演员）与情绪，不能得到及时有效的反馈解决，播中互动需求未被很好满足。

基于此，我们发明了一种**基于 LLM 实时分析用户弹幕数据、挖掘播中互动诉求、通过智能 Agent 实现播中智能互动的系统和方法**。核心思路：先用弹幕过滤模型从海量弹幕中过滤出「用户问题」类弹幕；再送入聚类模型进行智能聚类，将多个相近问题聚合成一个搜索 Query，并结合剧情生成合适的投放时间点；在用户观剧过程中，Query 以特殊运营弹幕的形态在投放时间点呈现，引导用户交互；用户触发交互后，Query 被送到基于媒资、剧情等私域信息训练的智能 Agent 解答，第一时间响应用户问题，从而大幅提升播中互动体验。

## 2、\*【背景技术】与本方案最相近的现有技术

### 2.1 现有技术的技术方案

目前视频平台提供的播中互动方式常见两种：
1. **弹幕**：用户在观看过程中发表弹幕，并可通过点赞、回复、评论他人弹幕的方式进行互动。*（图1. 弹幕互动形式）*
2. **AI 语音助手**：在 OTT、车载等大屏业务中，用户可在播放过程中通过语音与智能助手交互，进行设备操控、信息查询。*（图2. AI 语音助手交互形式）*

### 2.2 现有技术的缺点及本技术方案会解决的问题

- **弹幕**：更多是用户情绪出口（赞叹、感动、吐槽、疑惑），互动发生在用户之间，无法承担用户与平台的沟通渠道，不能满足观剧过程中对剧情解读、角色介绍等内容本身相关信息的搜索及拓展需求。
- **AI 语音助手**：一方面功能依赖硬件设备支持语音交互，独立 APP 使用语音需获得硬件厂商语音权限，渗透率低；另一方面交互质量受限于用户语音输入的问题质量。

本发明通过智能分析弹幕数据，提取用户观剧过程中共同产生的问题，形成互动主题并交由智能 Agent 解答，答案经运营人工审核后以运营弹幕形式在观剧过程中投放，用户点击即可获取官方互动信息。由此**以运营弹幕方式搭建官方与用户的互动渠道**，通过「Agent 生成 + 人工审核」保证内容准确性，且**不依赖语音功能**，以极低的交互成本实现用户与智能 Agent 的交互。

## 3、\*【发明内容】本技术方案的详细阐述

### 3.1 产品侧

本发明应用于在线视频 APP 观剧过程中的互动场景。观剧时，后台以运营弹幕形式向用户投放互动主题，运营弹幕在样式上区别于普通用户弹幕。*（图3. 以运营弹幕方式投放的互动主题）*

用户看到运营弹幕后，可通过点击（移动端 / PC / Pad）或遥控器操作（TV 端）触发交互，调起智能 Agent 交互面板；面板以半屏浮层的方式针对互动主题反馈相关结果，满足观剧过程中对剧情解读、角色介绍等信息的搜索及拓展需求；查阅完毕后可关闭面板。*（图4. 智能 Agent 交互面板实时呈现互动结果）*

### 3.2 技术侧

**（一）系统架构**　*（图5. 系统架构图）* 系统各模块说明如下：

- **视频终端设备**：安装在线视频 APP 的终端（手机、Pad、TV 等），提供找片、看片、弹幕发表与运营弹幕投放展示等功能。
- **弹幕发表接口**：接收用户弹幕交互信息（发表、点赞），请求持久化存储，并向弹幕变更通知队列写入变更消息。
- **运营弹幕投放接口**：向终端返回运营弹幕数据（含运营弹幕内容与投放时间点）；终端起播前调用它拉取需投放的运营弹幕。
- **运营系统**：运营人员操作平台，从互动数据存储拉取已生成的互动主题，以其为 Query 查询智能 Agent 获取答案，并可对主题与答案人工审核、修改，将通过的结果回写互动数据存储。
- **弹幕变更通知队列**：消息中间件，接收弹幕变更消息。
- **弹幕数据接入服务**：订阅变更消息或从存储拉取待处理弹幕，做预处理（区分优先级、过滤有效弹幕），写入弹幕数据缓存队列。
- **弹幕数据缓存队列**：消息中间件，缓存待处理弹幕；区分增量队列（增量变更弹幕）与存量队列（从存储拉取的存量弹幕）。
- **互动主题生成服务**：轮询消费弹幕数据，调用弹幕过滤模型做 LLM 语义过滤，调用主题聚合模型做聚类，生成新的互动主题，并将主题与聚类弹幕信息存入互动数据存储、处理流水写入流水存储。
- **弹幕过滤模型**：文生文大模型（如 hunyuan-turbos），输入弹幕内容，过滤出与影视作品相关的问题。
- **主题聚合模型**：文生文大模型（如 DeepSeek-V3），对一组按时间排序的弹幕聚类成簇，据每簇内容生成一条风格一致的新互动主题。
- **智能 Agent**：基于视频平台建设的影视模型，提供找片、操控、闲聊等能力，用于解答互动主题。
- **弹幕数据存储 / 互动主题生成流水存储 / 互动数据存储**：分别持久化弹幕原始数据、生成过程流水日志、以及最终互动数据（互动主题 ID、内容、答案、审核结果、投放时间、原始聚簇弹幕 ID、投放状态等）。

**（二）方法流程**　本方法分为四个阶段，原文分别配有时序图：

1. **弹幕接入及预处理**　*（图6. 弹幕数据接入及预处理时序图）*
   接入服务从变更通知队列取新弹幕消息（含弹幕 ID、类型、内容、归属视频 ID）→ 按类型过滤，仅保留新增弹幕 → 按归属视频 ID 请求媒资信息服务，仅保留特定媒资品类正片的弹幕 → 写入增量队列。变更队列为空时进入存量处理：按待处理视频 ID 从弹幕数据存储拉取弹幕列表写入存量队列。全程将预处理流水（流水 ID、视频 ID、操作类型、弹幕 ID 列表、起止时间、结果、错误信息等）写入流水存储。

2. **语义过滤及聚类任务创建**　*（图7. 语义过滤及聚类任务创建时序图）*
   从缓存队列消费弹幕（优先增量、其次存量，无数据则短暂休眠后重试）→ 调用弹幕过滤模型（输入弹幕内容 + Prompt），标注是否为影视问答类 → 符合条件的弹幕存入过滤结果表并写过滤流水 → 每次过滤后检查该视频已过滤弹幕数是否达到聚类阈值（保证聚类效果）→ 达标则打包成聚类任务加入聚类任务列表并写流水。

3. **互动主题生成**　*（图8. 互动主题生成时序图）*
   从聚类任务列表取出任务 → 解析聚类弹幕，调用主题聚合模型（输入弹幕内容 + 视频打点时间）生成新互动主题及对应投放时间点参考 → 将互动主题信息（主题 ID、内容、打点时间、原始弹幕 ID 列表、所属视频 ID 等）存入互动数据存储并写流水。

4. **人工审核及线上投放**　*（图9. 审核及投放流程时序图；图10~12. 审核列表 / 主题列表 / 审核页面）*
   运营系统拉取互动主题列表 → 运营人员选择视频与主题打开审核页 → 系统将视频 ID、主题输入智能 Agent，Agent 结合剧情库、媒资库解答并返回答案 → 运营人员对主题、投放时间点、答案人工审核修改后提交 → 结果（审核状态、投放状态、投放时间点、内容、答案）回写互动数据存储。投放阶段：终端起播前调用运营弹幕投放接口拉取可投放主题；终端解析后按播放进度到达投放时间点时展示互动主题，用户进一步交互则拉起面板展示答案。

## 4、技术方案所产生的有益效果

本发明借助大模型对海量弹幕实时分析与聚合，以运营弹幕方式在观剧过程中搭建官方与用户的互动渠道，丰富观剧交互体验；通过「Agent 生成 + 人工审核」保证互动内容准确性；且不依赖语音功能，以极低的交互成本实现用户与智能 Agent 的交互。

## 5、发散思维：针对第 3 节技术方案，是否还有其他替代方案

1. **过滤 / 聚合模型可替换**：弹幕过滤模型与主题聚合模型不限于 hunyuan-turbos / DeepSeek-V3，可替换为任意具备语义理解能力的大语言模型，或「轻量分类模型 + 聚类算法」的组合（如 BERT 类语义分类 + K-means/DBSCAN 聚类）。权利要求中相应特征应作上位概括，避免限定于特定模型。
2. **投放时机的替代确定方式**：投放时间点除按「弹幕对应的视频打点时间」确定外，可替换或结合剧情标签 / 剧情节点、章节或分集边界、广告位空档、剧情高能时刻标记、用户交互空闲期等信号确定。
3. **交互触发形态的替代**：调起交互面板的触发方式，除点击运营弹幕（移动端）、遥控器操作（TV 端）外，可替换为语音唤醒、手势操作、摇一摇、扫码跳转等。
4. **审核环节的替代**：运营人工审核可替换为「模型自动审核 + 置信度阈值放行、低置信度转人工复核」的半自动方案，覆盖全人工、半自动、全自动三档实施方式。
5. **Agent 知识来源的替代**：智能 Agent 的知识来源除媒资库、剧情私域库外，可叠加实时检索增强生成（RAG）、第三方百科 / 知识库等，以提升答案的时效性与覆盖面。
