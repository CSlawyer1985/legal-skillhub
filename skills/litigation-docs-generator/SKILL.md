# 诉状文本生成

## 概述

本技能一次性生成民商事诉讼立案所需的全部配套文书，共 10 份（含委托代理合同、所函、要素式起诉状）。所有文书中的人名/名称、案号、金额等关键信息保持严格一致。被告为自然人且用户选择调取人口信息时，另生成 **2 份无锡公安制式表**（附件1 案件当事人授权委托书、附件2 查询人口信息业务申请表）。

能力沿革（v2 → v2.7）见文末「版本沿革」；完整执行路径见「生成工作流程」。

## 适用场景

- 用户说「帮我写起诉状」「准备立案材料」「生成诉讼文书」
- 案件类型：**仅限民商事案件**（合同纠纷、侵权、债务、公司纠纷、劳动争议等）
- 不适用：刑事案件、行政案件

## 前置检查（必须执行）

### 1. 法律数据库连接器检查

本技能支持通过以下专业法律数据库进行法规和类案检索：

| 连接器 | 数据库 | 功能 |
|--------|--------|------|
| `yuandian-mcp` | 华宇元典 | 法规检索、类案检索、企业信用信息 |
| `pkulaw` | 北大法宝 | 法律法规、司法案例、法学期刊 |

每次生成文书前，按以下逻辑检查：

**情况 A：至少一个数据库连接器已连接**
→ 使用已连接的数据库进行法律检索。如同时连接多个，优先使用元典。

**情况 B：所有数据库连接器均未连接**
→ 不阻止生成，按降级模式运行：

- 跳过数据库法律检索步骤（第二步）
- 法条引用基于模型知识生成
- 在所有文书末尾追加醒目标注：

> ⚠️ 本文书未连接专业法律数据库，法条引用基于 AI 模型知识生成，请在使用前由执业律师逐条核实。

降级模式下先向用户确认：

> 当前未连接任何专业法律数据库（华宇元典 / 北大法宝等）。
>
> 我可以降级运行——引用法条基于模型知识生成，但存在法律幻觉风险。
>
> 是否继续降级生成？或者先去连接数据库？

### 2. 模型推荐

推荐使用 **DeepSeek V4 PRO** 或其他最新 DeepSeek 模型运行此技能，以获得最佳的法律推理和文书撰写效果。如当前未使用 DeepSeek 模型，建议在对话开始前切换。

### 3. 无锡律师识别与前置互动提示（v2.7 新增，必须执行）

**识别标准**（满足任一即认定为无锡律师）：

| 判据 | 说明 |
|------|------|
| 律所全称含「无锡」 | 如「北京德恒（无锡）律师事务所」 |
| 律所地址在无锡 | 用户提供的律所地址位于无锡市辖区 |
| 用户明确告知 | 用户自称在无锡执业，或直接要求生成无锡制式表 |

**认定后，在第一步信息收集开始之前，必须先作一次前置互动提示**（不可跳过，也不可后置到交付阶段）：

> 📋 **无锡律师提示**：无锡地区律师因**申请立案**需要查询**对方当事人**户籍登记信息的，应向公安机关提交四份材料：
>
> ① 律师执业证书　② **案件当事人授权委托书（附件1）**　③ 律师事务所介绍信或法律援助公函　④ **律师、基层法律服务工作者因代理诉讼、仲裁查询人口信息业务申请表（附件2）**
>
> 其中 ②④ 两份表由我为您生成填好的版本——附件1 归入文件清单 **05-4**（**需委托人签字捺印或盖章**）；附件2 由您填写、**律所盖章**，不进当事人清单。
>
> 依据：无锡市人民政府《律师如何申请办理人口信息查询?》（2026-09-08，https://www.wuxi.gov.cn/doc/2026/09/08/4828126.shtml ）；《江苏省常住户口登记管理规定》第 172 条。可向本市任一公安户籍派出所或市、区（县）政务服务中心公安户政窗口申请，也可通过「太湖e警」公安政务服务平台在线申请。

**非无锡律师**：不生成上述两份表格，仅按同一话术提示「凭律师执业证书 + 律师事务所介绍信/公函 + 委托人授权委托书，向被查询人户口所在地公安派出所或户政窗口申请查询」。如用户主动要求按无锡制式表生成，可以生成，但须提示「无锡制式表，跨地区使用前请先向当地公安机关确认表格格式与材料要求」。

**查询范围提示**（须告知用户）：查询内容限于被查询人**姓名、性别、民族、出生日期、公民身份号码、常住户口所在地住址**；需查询其他信息的，应持**法院调查令**申请（附件2「□其他信息」栏据此填写）。

### 4. 二进制模板还原（仅从 SkillHub 安装时需要）

**前提知识**：SkillHub 服务端**不接受 .docx 等二进制 Office 模板**（上传报 `400 不允许的文件类型`；商店上已有的同类 skill 其安装包内也不含 .docx）。因此本 skill 的 5 份 .docx 模板以 **base64 文本载体** `references/templates-b64.json` 随包分发，安装后需还原一次。

**检查与还原**（幂等，已还原过则是空操作）：

```bash
python3 scripts/restore_templates.py check     # 检查：列出缺失/不一致的模板
python3 scripts/restore_templates.py unpack    # 还原：逐文件写回并校验 md5，已存在则跳过
```

`unpack` 的安全边界：文件已存在且 md5 不一致时**中止并提示**，不覆盖你的本地模板；确要覆盖加 `--force`。

> ⚠️ 本机开发副本（含 .docx 原件的目录）**无需执行**此步——`check` 会显示 5/5 就位。

> ⚠️ **二进制模板必须放顶层 `assets/`（2026-09-12 实测）**：Skill 包只允许「根目录 / 二级目录 / 文件」两级结构，`references/assets/xxx.docx` 会被平台判为「**目录层级超限**」，桌面 zip 或网页上传都会解析失败（`skillhub` CLI 发布同样受此限）。故 5 份 .docx 统一置于 `assets/`，Markdown 模板留在 `references/`，全包最大层级 = 2。

## 模板系统（v2 架构）

### 模板结构

每个 `references/*.md` 模板由两部分组成：

1. **YAML frontmatter**（`---` 之间的部分）— 定义所有格式规则
2. **Markdown 正文**（`---` 之后的部分）— 定义内容结构和变量占位符

### 格式约定（YAML 头中的 style 标签）

| 标签 | 说明 | 典型用途 |
|------|------|---------|
| `#` | 文书标题 | 18pt 宋体 bold 居中 |
| `##` | 段落标题 | 16pt 宋体 bold，无缩进，前间距 8pt。用于：原告、被告、诉讼请求、事实与理由、申请人、被申请人、请求事项、事实及理由、委托人、受托人 |
| `body` | 正文 | 14pt 仿宋，首行缩进 28pt（空两格），1.5 倍行距 |
| `cizhi` | "此致"行 | 继承 body 格式，额外 `gap_before: 6pt` |
| `court` | 法院名称 | 14pt 仿宋，**不缩进（顶格）** |
| `sign` | 签名/盖章行 | 14pt 仿宋，右对齐 |
| `date` | 日期行 | 14pt 仿宋，右对齐，模板 `{year}年  月  日` |
| `note` | AI 声明 | 14pt 仿宋，首行缩进 |

### 缩进约定

| 值 | 含义 |
|----|------|
| `indent: false` | 顶格（不缩进），用于：`##` 标题、法院名称 |
| `indent: true` | 使用默认缩进 28pt（空两格），用于：body、cizhi |
| `indent: 28pt` | 显式指定缩进量 |

### 内联标签

Markdown 正文中可用以下标签覆盖默认样式：

| 标签 | 功能 |
|------|------|
| `[sign]文字` | 右对齐签名 |
| `[date]` | 日期（取 `{year}` 变量） |
| `[court]法院名` | 顶格法院行 |
| `[note]文字` | AI 声明注释 |
| `[meta]文字` | 无缩进元数据行（笔录头部） |
| `[qa_gap]` | Q&A 段落间小间隔 |

### 变量替换

模板中所有 `[变量名]` 会被替换为实际值。变量名在 `[` `]` 之间**不包含标签文本**。

- ✅ 正确：`文书送达地址：[原告文书送达地址]`，变量名 = `原告文书送达地址`
- ❌ 错误：`[文书送达地址：送达地址]`，变量名 = `文书送达地址：送达地址`（包含了标签）

**案由变量**：模板中写 `[案由]一案`，变量值应为 `民间借贷纠纷`（不含"纠纷"后缀），避免出现 `民间借贷纠纷纠纷一案`。

### 段落标题统一性

起诉状中 `## 原告：`、`## 被告：`、`## 诉讼请求：`、`## 事实与理由：` 属于同一级别，全部使用 16pt 宋体 bold。保全申请书中 `## 申请人：`、`## 被申请人：`、`## 请求事项：`、`## 事实及理由：` 同理。

当事人的详细信息（如法定代表人、地址等）应放在 `##` 标题行**之后**的 body 行中，而非嵌入标题行内。

示例：
```markdown
## 原告：[原告姓名/名称]，[原告基础信息]
法定代表人：[原告法定代表人]
文书送达地址：[原告文书送达地址]
```

## 生成工作流程（v2）

### 第一步：收集案件信息

#### 1.0 委托合同上传（推荐）

在逐项收集信息之前，**主动提醒用户上传《委托代理合同》**（即律师与当事人签订的委托协议）。

> 💡 提示：如果您有已签署的《委托代理合同》（.docx / .pdf / 图片均可），上传后我将自动提取以下信息，省去手动填写：
>
> - 代理律师姓名、执业机构（律师事务所全称）
> - 律师联系电话、律所地址
> - 委托事项和代理权限范围（用于授权委托书）
> - 委托人（原告）信息（可用于交叉核验）
>
> 如果您暂时没有合同或不想上传，也可以手动提供代理信息。
>
> **📋 提示**：如果您有自己的委托合同模板（贵所/团队的常用版本），也可以一并上传。我会将其作为定制模板，后续生成委托代理合同时将直接套用您的模板格式和条款，而非使用系统默认模板。这样生成的合同更贴合您的实际业务需求。

**委托合同处理流程**：

1. 用户上传合同文件后，读取并提取关键信息
2. 将提取的信息填入后续各文书变量中：
   - `律师姓名` → 授权委托书、接待笔录
   - `律师事务所全称` → 授权委托书、接待笔录
   - `律师电话` → 授权委托书
   - `律所地址` → 授权委托书
   - 委托权限内容 → 与现有模板权限列表交叉比对，差异部分提示用户确认
3. 提取结果展示给用户确认，确认后继续收集其余信息

**注意**：如用户选择不上传合同，按原有流程逐项收集代理信息即可，不影响文书生成。

#### 1.1 案件信息收集

#### 1.3 人口信息调取询问与信息收集（v2.7 新增，必须执行）

**触发条件：被告中有自然人（个人）→ 一律先询问一次**，不预先按有无身份证号自行过滤。

时机：被告信息收集完毕后、进入第二步法律检索之前。话术必须包含「有无身份证号」的判断说明：

> 📋 **是否调取被告人口信息？**
>
> 本案被告 [被告姓名/名单] 为自然人。如果**已有其公民身份号码**，起诉状可直接写明被告身份信息，一般**无需**另行调取；如果**没有公民身份号码**，或需要户籍登记住址等信息用于立案，则建议向公安机关调取。
>
> 是否需要我生成人口信息调取材料？

- **用户选择「需要」** → 收集下列信息，进入阶段 E 生成：
  1. **被查询人清单**：姓名 / 性别 / 出生日期 / 已有公民身份号码，逐人向用户确认。⚠️ 以用户提供为准，**不得猜测、不得用同名他人信息补全、不得据模型记忆填身份证号**。
  2. **介绍信（公函）编号**：与所函/律所介绍信文号一致（如「德恒（无锡）民（2026）字第12号」）；尚未出具介绍信时可留空手写。
  3. **查询人（承办律师）信息**：默认复用已收集的律师姓名、执业证号、联系电话；另需律师本人公民身份号码（授权委托书与附件2「查询人」栏，通常未在其他文书中收集，须单独询问）。
- **用户选择「不需要」** → 跳过阶段 E，在交付回复中一句话说明即可，**不得反复追问**。

**须同步告知的两点风险**：

1. **同名风险**：被查询人姓名、出生日期须与身份证完全一致，否则可能查到同名的他人；公安机关只负责查询、不负责为律师核对案件关联性，**律所应对被查询人信息审核确认**（附件2 表末注记亦如此要求）。
2. **查询范围有限**：户籍查询限于姓名、性别、民族、出生日期、公民身份号码、常住户口所在地住址；需银行、不动产等其他信息的，须另持**法院调查令**。

### 第四步：生成全部文书

**两阶段生成：**

**阶段 A：利息计算表**
```bash
python3 scripts/generate_interest_calc.py <output.xlsx> \
  --principal <金额> --start <起始日> --end <截止日> \
  --lpr-term 1Y --submitter "<提交人>"
```

- 无约定利率时自动使用 LPR 数据库，按利率变化节点分段
- 利息 = 本金 × 天数 × 利率 ÷ 360
- 相邻同利率段自动合并
- 所有计算列为 Excel 公式（可点击核验）
- 输出含「利息计算表」+「利率数据库」两个 sheet，利息计算表在前

**阶段 B：docx 文书**（逐份调用 `render_docx.py`）
```bash
python3 scripts/render_docx.py <模板.md> <输出.docx> --vars '<JSON>'
```

## 核心规则（严格遵守）

### 人名一致性

起诉状和诉讼保全申请书中的原告/被告姓名/法定代表人必须完全一致。

### 当事人视角

- 担保书：申请人是原告
- 授权委托书：委托人是原告，受托人是代理律师。**生成两份**：
  - 05-1 承办律师版：`受托人全称`=律师姓名+律所名，`律师姓名`=承办律师名
  - 05-2 律所备用版：`受托人全称`=律所名（不写律师姓名），`律师姓名`=全角空格占位留白
- 法定代表人身份证明：仅当原告为企业时生成

### 人口信息调取材料（v2.7）

- **触发**：被告中有自然人 → 一律先询问一次（不预先按有无身份证号过滤）；「用户选择调取」+「无锡律师」两个条件同时成立才生成
- **两份表同源同用**：附件1（案件当事人授权委托书，**委托人**签字捺印或盖章）是公安受理查询的前提；附件2（查询人口信息业务申请表，**申请律师**签字 + **律所盖章**）载明查询人、被查询人与反馈项目，二者缺一不可
- **原件为准**：两份表均以陆律师提供的无锡公安制式表为模板，脚本只填空、不改版式与文字；`assets/` 下的原文件**不得就地修改**（脚本读原件、写新文件）
- **不许猜**：被查询人姓名/性别/出生日期以用户提供为准，身份证号未知就**留空**——这正是需要调取的原因；严禁据模型记忆补身份证号或用同名他人信息填空
- **查询人身份**：附件2「查询人」栏默认沿用模板中陆凌燕律师的姓名/证号/电话；**换律师承办必须显式传参**，否则会出现"名义查询人不是承办律师"

### 利息计算规则

- 利息 = 本金 × 天数 × 利率 ÷ **360**（360 天/年）
- 无约定利率时自动使用 LPR 数据库，按利率变化节点分段
- 利率档位：6M / 1Y / 1-3Y / 3-5Y / 5Y，默认 1Y
- Excel 中**所有计算列必须为公式**（`=B11-A11+1`、`=本金*D*C/360`、`=SUM(...)`），禁止写入死数字
- Excel 必须设置 `calcMode="auto"` 确保打开即算

### 变量命名注意事项

- 模板中 `[案由]一案` → 变量值应为 `民间借贷纠纷`（不含"纠纷"后缀）
- 避免在变量名中嵌入标签文本（如 `[文书送达地址：送达地址]`）
- 变量 JSON 中的 key 必须与模板 `[key]` 精确匹配

### 法定代表人字段映射

三个变量表示同一人物的不同粒度：

| 模板 | 变量 | 示例值 |
|------|------|--------|
| complaint | `原告法定代表人` | `张三，执行董事` （姓名+职务合写） |
| legal_rep_certificate | `法定代表人姓名` | `张三` （纯姓名） |
| legal_rep_certificate | `法定代表人职务` | `执行董事` （纯职务） |

填充时：已知 `原告法定代表人` 的合写值后，从中拆分出姓名和职务分别填入身份证明的两个变量。反之，如果先收集到姓名和职务，则合并填入 `原告法定代表人`。

### 管辖条款引用（协议管辖，v2.6.3 新增；v2.6.4 修订）

**原则：一般案件（原告就被告）无需写任何管辖依据；有特殊约定或特殊条款时，把该条款原文写进诉状即可——只引用条款，不附加管辖权法律依据论述（不写「依据《民事诉讼法》第×条贵院享有管辖权」之类的话）。**

案件涉及合同管辖约定的（合同中有协议管辖条款，如「因本合同发生的争议，由××人民法院管辖」），**必须在起诉状「事实与理由」部分原文引用该管辖条款**，写明合同名称、条款序号及约定原文。

示例：「原、被告签订的《××合同》第×条约定：『因本合同发生的争议，由××市××区人民法院管辖。』」

⚠️ 只引用条款即可，**不要**再追加「依据该约定及《民事诉讼法》第三十五条之规定，贵院对本案依法享有管辖权」等管辖权论述——条款原文本身就是依据，画蛇添足反而显得刻意。否则法官立案审查时看不到管辖约定，会按「原告就被告」的一般地域管辖规则确定管辖，可能导致约定管辖落空、起诉被移送或不予受理。

对应地，在第一步 1.1 收集案件信息时，凡案由属合同类纠纷，应主动询问用户：**合同中是否有管辖（争议解决）条款？如有，请提供合同名称、条款序号及原文。**（若约定为仲裁而非法院管辖，应提示用户本案应申请仲裁而非起诉，并中止诉讼文书生成流程。）

## 修改模板指南

如需调整格式或内容，**只改 `references/*.md` 文件**，Python 代码不需改动：

- **改格式**：编辑 YAML frontmatter（字号、缩进、对齐等）
- **改内容结构**：编辑 Markdown 正文（增加/删除段落、调整变量位置）
- **改样式级别**：改 `##` 标签的使用位置

修改后直接重新运行渲染即可生效。

### 私有配置（发布物零个人信息，2026-09-12 确立）

**原则：skill 里可以出现「律所公开信息」（律所名/地址/总机/费率），但不得出现任何个人或第三人信息**——包括律师本人身份证号、手机号、执业证号，以及客户名称、客户地址、客户联系人、案号、客户身份证号。

- **真实值存放**：`private/lawyer-profile.json`（本机私有目录）
- **`.gitignore` 已排除 `private/`**：`skillhub-publisher` 的 `create_clean_publish_copy.py` 会读 `.gitignore`，因此发布副本与桌面打包**自动不含该目录**
- **模板与脚本里只有 `〔…〕` 占位符**，由脚本按下列优先级回填：`--vars` > `private/lawyer-profile.json` > 保留占位符（并打印 ⚠️ 提示）
- **换律所/换律师使用**：填 `private/lawyer-profile.json` 即可；如需整体换合同模板，直接替换 `assets/` 下的 docx
- **自检兜底**：`fill_wuxi_population_form.py` 与 `fill_retainer_deheng.py` 均会在输出中检查 `〔` 残留，有残留即报错或在生成时告警

> ⚠️ **发布前必查**：`private/` 目录不得随发布物或桌面 zip 出现；`assets/*.docx` 全文不得含真实姓名/身份证号/手机号/客户名。

  - `fill_wuxi_poa.py`：按「自然人 / 法人 / 受托人 / 本人同意授权由受托人代理」等关键词定位段落，靠**文字**锚定，改版后如提示「未找到××段落」需更新 `_find` 关键词

- 两份脚本均内置 `self_check()`，**不通过不落盘**；如出现「旧案残留」报错，检查模板是否被换成了别的案件的已填版本

## 注意事项

- **不编造事实**：所有事实基于用户提供的信息
- **法条时效性**：引用前确认法规为"现行有效"
- **文书一致性**：生成后交叉核对所有文书中的关键信息
- **原告联系方式**：默认不写原告电话号码
- **证据清单**：起诉状中不生成证据清单章节
- **财产线索**：保全申请书中不以手机号笼统作为财产线索
- **利率风险**：如约定利率超过 LPR 四倍，在起诉状和接待笔录中标注风险提示
- **LPR 数据源**：`scripts/generate_interest_calc.py` 顶部 `RATE_DATABASE` 内置完整数据库（2006-01 至 2026-06，含央行基准利率与 LPR 全时段），**无联网自动更新**；新一期 LPR 公布后需在该列表末尾按 `RateRecord(date(y, m, d), 6M, 6M-1Y, 1-3Y, 3-5Y, 5Y+)` 补录，补完重跑脚本即可生效
- **人口信息调取**：被告为自然人时必问一次，问话必须说明「已有公民身份号码的可不调取，缺号的才需要」；被查询人身份证号未知就留空，**不得猜测或补全**（详见「核心规则 · 人口信息调取材料」）
