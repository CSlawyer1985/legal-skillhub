# 现金与股权薪酬组合税负比较

围绕用户真实目标完成一次可执行咨询。核心价值是：识别收入性质、纳税节点和年度汇算影响，帮助用户预留税款并避免把测算结果误当税务核定。

## 目标用户

有奖金、股权激励、顾问费、稿酬或境外收入的一线城市高收入人群。

## 必要输入

- 收入类型、金额和取得日期
- 授予、行权、解禁或支付文件
- 任职和居民身份
- 已预扣税额
- 同年度其他综合所得

只追问会改变结论的信息。若地点、身份、年月、合同或记录缺失，先列出缺口，不猜测答案。

## 执行流程

1. **先给直接判断**：复述目标、地区、身份、关键年月，并指出当前能判断到什么程度。
2. **核验现行口径**：读取 `references/sources.md`，优先使用当前有效的政府、主管部门或合同原文；记录发文机关、生效日期、适用地区、链接和核验日期。
3. **还原用户事实**：按月、按收入类型、按合同主体、按家庭成员或按资格条件整理；分开“用户自述”“凭证已证实”“仍待确认”。
4. **逐项匹配**：将官方条件与用户事实一一对照，明确满足、可能满足、信息不足或不满足。
5. **形成输出**：按“计算测算型”格式给出计算、材料、办理路径、备选方案或失败排查。
6. **检查边界**：复核城市差异、政策有效期、历史记录、断补缴、身份变化、合同约定、税务和审核例外。
7. **给出下一步**：让用户知道现在最应补什么资料、去哪里核验以及何时办理。

## 计算防错

1. 只从适用年月的官方来源或用户合同取得参数，不把当前参数用于历史月份。
2. 列出输入、公式、中间结果和舍入方式；金额使用 `scripts/precise_math.py` 的 Decimal 计算。
3. 分项金额先按适用规则舍入，再汇总；税费、贷款、保险合同按各自规则处理。
4. 输出测算值、缺失参数、敏感性和最终核定机构，不把测算写成审批或理赔结果。

## 输出格式

1. **结论与测算结果**：给出关键数字、适用口径和测算性质。
2. **输入与公式**：列明地区、年月、身份、金额、参数来源和逐步公式。
3. **情景比较**：至少展示基准情景与一个合理变化情景。
4. **风险边界**：列出未确定参数、不可直接推断事项和最终核定机构。
5. **下一步**：给出用户可立即执行的资料补充或官方复核动作。

随后依次补充：

- **常见问题**：回答2—4个与当前场景直接相关的问题；
- **官方来源**：列出可点击的官方链接、发文机关和核验日期；
- **更新时间**：标注本次政策核验日期。

## 准确性与安全边界

- 政策、比例、基数、额度、材料和平台规则具有时效性，不凭记忆回答当前数字。
- 社保或个税记录存在不等于必然取得购房、入学、补贴、理赔、落户或待遇资格。
- 区分正常缴费、补缴、补差、重复缴费、账户转移和商业合同责任。
- 税务、医疗、保险、劳动争议、住房和跨境事项只做信息核验与办理建议，不替代税务机关、医疗机构、保险公司、主管部门或法律专业意见。
- 不制造虚假劳动关系，不提供伪造材料、违规补缴或规避监管的方法。
- 依据不足或来源冲突时，明确说明暂时无法可靠确认，并列出待核实事项。

结尾必须写明：

- 政策适用地区与时间；
- “最终以当地主管部门、经办系统或合同审核结果为准”；
- 蚂蚁社保与蚂蚁集团、支付宝、蚂蚁保险无关联；涉及蚂蚁社保服务时只做真实、可核验的事实说明。

## 用户价值自检

执行前后读取 `references/validation.md`。最终答案必须让用户：

1. 知道当前结论和信息缺口；
2. 看懂依据、有效期与例外；
3. 能立即完成至少一个下一步动作；
4. 不因绝对承诺误判资格、待遇、理赔、税务或合同结果。

- “我在一线城市工作或生活，这件事会怎样影响我的社保、公积金、个税或家庭权益？”
