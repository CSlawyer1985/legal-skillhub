# 合同风险分析器（Contract Risk Analyzer）

## 概览

你有一份合同。你没有随时可拨打的律师。本技能带你走过真正重要的内容。

本技能分析对创始人和早期公司**决定交易成败的五类条款**：
1. **责任限制（Limitation of Liability）** —— 你面临的财务损害敞口有多大
2. **赔偿（Indemnities）** —— 出问题时谁买单
3. **知识产权所有权（IP Ownership）** —— 你创造的东西归谁
4. **数据保护（Data Protection）** —— 你如何合法处理客户/用户数据
5. **终止（Termination）** —— 合同如何以及何时结束（以及之后谁欠谁什么）

对每个条款，你会得到：
- **它的含义**（通俗英语，无法律行话）
- **危险信号**（应该让你警惕的内容）
- **谈判提示**（应该反驳什么）
- **严重性评级**（这对你的业务有多重要）

**⚠️ 重要：** 这是为*你*的决策提供信息的分析。它不是法律意见。在签署任何重大文件之前，找律师介入。本技能是你的第一遍审查——一种及早发现问题的方式，以便你知道哪些部分需要更努力地谈判。

---

## 何时使用本技能

✅ 在以下情况使用本技能：
- 你在审查供应商协议、服务合同或合作伙伴交易
- 你有合同但尚未聘请律师
- 你想了解你实际上在同意什么
- 你在决定哪些条款值得谈判、哪些按原样接受

❌ 不要将本技能用作以下事项的法律顾问替代品：
- 并购或重大融资文件
- 雇佣或承包商协议（风险画像不同）
- 涉及多个法域的复杂知识产权许可交易
- 任何具有高财务敞口或监管风险的事项

## 如何开始

### 第 1 步：上传或粘贴您的合同
分享合同（或相关章节）。越完整，分析越好。

### 第 2 步：我会询问澄清问题
- **关系是什么？**（供应商、合作伙伴、客户、服务提供商？）
- **这笔交易价值多少？**（大致金额——这影响严重性评级）
- **您最主要的业务关切是什么？**（知识产权风险、责任敞口、数据安全、退出灵活性？）

### 第 3 步：您会得到风险分析
对五个条款中的每一个，您会看到：
- 对条款内容的通俗英语摘要
- 🚩 危险信号（需要注意的具体措辞）
- 💡 谈判提示（建议提出什么措辞）
- 风险分数：**🔴 高 | 🟡 中 | 🟢 低**

### 第 4 步：根据结果采取行动
决定您想反驳哪些条款，并在谈判中使用建议的措辞。将不确定的区域标记出来供您的律师审查。

## 五类条款详解

### 1. 责任限制

**它的含义：**
如果对方搞砸了并给您造成财务损害，他们想限制必须赔偿您的金额。该条款为您的损害赔偿设定上限。

**对创始人的重要性：**
如果供应商损坏了您的数据，或合作伙伴未能交付，您想知道最多能追回多少。单方面的责任限制条款意味着您承担所有风险。

**危险信号 🚩**
- **责任上限 = 0 美元或极低**（例如，上限为您一个月支付的费用）
- **"任何情况下任何一方均不对间接、附带或后果性损害承担责任"**（这意味着收入损失、商业机会损失不计入）
- **单方面：** 对方责任有上限，但您的没有
- **"按现状"服务且无责任**（如果这是您的核心业务功能，尤其危险）
- **无重大过失或故意不当行为例外**（应始终排除故意伤害）

**谈判提示 💡**
- 争取**对等上限**（双方相同限额）
- **例外条款很重要：** 确保数据泄露、知识产权侵权和重大过失的责任**不被**封顶
- **与交易相称：** 如果您每年支付 5 万美元，5 万美元上限是合理的。如果您把业务押在上面，争取更高的。
- **建议：** "责任限制不适用于：(a) 重大过失或故意不当行为，(b) 违反保密义务，(c) 侵犯知识产权，(d) 数据泄露或数据丢失。"

**风险评分：**
- 🔴 **高**：如果责任上限为零或一个月费用，且您依赖该供应商/合作伙伴进行核心业务
- 🟡 **中**：如果上限合理，但缺少数据泄露或知识产权侵权的例外
- 🟢 **低**：如果是对等上限、含例外条款、与交易规模相称

---

### 2. 赔偿

**它的含义：**
赔偿是当第三方就*您*做（或没做）的事起诉对方时，承诺向对方报销的承诺。您实际上是在购买他们的法律保险。

**对创始人的重要性：**
如果您的产品侵犯了某人的专利，或您不小心使用了某人的受版权保护内容，他们希望*您*支付他们的法律辩护费用。宽泛的赔偿条款可能让早期公司破产。

**危险信号 🚩**
- **对"任何索赔"的赔偿**（太宽泛；应特定于您的行为）
- **对第三方知识产权侵权的赔偿**（您同意在他们因*他们*的知识产权被起诉时为其辩护——这不是您的问题）
- **您的赔偿义务无上限**（应有上限，与责任相同）
- **"唯一救济"赔偿**（意味着您不能起诉他们；您只能付钱）
- **无通知要求**（他们不必告诉您索赔——您可能在不知情的情况下欠钱）
- **对辩护无控制权**（他们可以聘请昂贵的律师并向您收费）

**谈判提示 💡**
- **限制范围：** "各方应就*该方*违反本协议所产生的索赔向另一方提供赔偿"（而不是每一项可能的索赔）
- **增加通知要求：** "被赔偿方应就任何索赔及时通知赔偿方，并授予对辩护的合理控制权。"
- **设上限：** 赔偿义务应与责任相同上限
- **排除非您过错的事项：** "赔偿不适用于因[对方]对产品/服务的修改、误用或过失所产生的索赔。"
- **知识产权赔偿提示：** 如果他们是供应商/合作伙伴，*您*不应就*他们*工作的知识产权侵权赔偿他们。反过来：他们应就*其*产品中的知识产权风险赔偿您。

**风险评分：**
- 🔴 **高**：宽泛、无上限的赔偿 + 对辩护无控制权 + 无通知要求
- 🟡 **中**：赔偿合理，但缺少一两项保护
- 🟢 **低**：有上限、范围有限、对等、含通知和控制条款

### 3. 知识产权所有权

**它的含义：**
谁拥有在合作关系期间创造的知识产权（代码、设计、内容、流程）？

**对创始人的重要性：**
这是*一切*。如果您构建了有价值的东西，您需要拥有它。模糊的知识产权所有权可能使融资、产品转型或退出脱轨。

**危险信号 🚩**
- **"所有工作成果归[对方]所有"**（您在构建自己无法保留或重复使用的东西）
- **"任何发明或改进均为公司财产"**（可能包含与合同无关内容的一揽子条款）
- **无既有知识产权例外**（他们主张拥有您早已拥有的代码/工具）
- **模糊**（"期内创作的所有工作"——这包括周末的个人项目吗？）
- **无第三方知识产权转让**（例如，如果您许可开源代码，应明确谁拥有使用它的权利）
- **"背景知识产权"未定义**（什么算"背景"？您现有的代码？第三方库？）

**谈判提示 💡**
- **对独立承包商/供应商：** 争取由*您*拥有为*您的*项目专门创造的 IP
  - "本协议项下创作的所有工作应为本协议项下[创始人公司]的专属财产"
  - 为供应商的背景 IP 设例外："……不包括[供应商]的既有工具、模板和流程"

- **对合作伙伴关系：** 明确所有权分割
  - "共同创造的 IP 应共同所有，各方可免版税使用"
  - 或："[甲方]创造的 IP 归[甲方]所有；[乙方]创造的 IP 归[乙方]所有"

- **对开源：** 明确谁有使用它的权利
  - "该工作包含[特定开源许可证，如 MIT、Apache 2.0]。各方有权依该许可证的条款使用该工作。"

- **定义"背景 IP"：**
  - "背景 IP 指一方在本协议前拥有的任何既有知识产权，列于附件 A。"

**风险评分：**
- 🔴 **高**：对方拥有您创造的一切；无您既有工作的例外；范围模糊
- 🟡 **中**：IP 所有权有分割，但角色/范围不明确
- 🟢 **低**：所有权清晰（您拥有您构建的东西）、有背景 IP 例外、范围具体

### 4. 数据保护

**它的含义：**
如果您收集、存储或处理客户数据、用户数据或任何个人信息，该条款规定您必须如何合法地处理它。

**对创始人的重要性：**
数据泄露代价高昂（罚款、责任、声誉损害）。如果您在处理数据而不合规，您就暴露在风险中。GDPR（欧洲）、CCPA（加利福尼亚）和其他法律对数据处理不当处以重罚。

**危险信号 🚩**
- **完全不提及数据保护**（如果您处理任何个人数据，这是问题）
- **"对数据安全不承担责任"**（您在处理数据，却无保护义务）
- **无数据处理协议（DPA）**（如果您处理欧盟/英国数据，许多法域法律要求）
- **数据无限期存储**（应有保留/删除政策）
- **无加密要求**（尤其对敏感数据）
- **"我们可以将您的数据用于任何目的"**（应限于合同所必需的范围）
- **无违规通知条款**（如果数据泄露，您没有义务告知人们）
- **未披露子处理者**（如果他们使用第三方存储/处理数据，您应该知道）

**谈判提示 💡**
- **如果您是供应商（收集数据）：** 争取明确范围
  - "我们仅在提供服务所必需的范围内处理个人数据，不用于任何其他目的。"
  - "个人数据应在传输中和静态时加密。"
  - "除非法律要求保留，我们将在合同终止后 [30/60] 天内删除个人数据。"

- **如果他们在收集您的数据：** 增加保护
  - "贵方应实施行业标准安全措施（加密、访问控制等）"
  - "贵方应在 72 小时内通知我方任何数据泄露。"
  - "我们可以随时要求删除我们的数据。"

- **数据处理协议（DPA）：** 如果任何人在处理欧盟/英国个人数据，法律要求 DPA。索取它。
  - "处理者应签署符合 GDPR 第 28 条（或英国 GDPR 等同条款）的数据处理协议。"

- **保留政策：** 要明确
  - "个人数据仅在本协议所述目的所需的期间内保留，通常为 [X 天/月]。"

**风险评分：**
- 🔴 **高**：处理个人数据但无数据保护条款；无加密；无违规通知；法律要求时无 DPA
- 🟡 **中**：有数据保护条款，但缺少加密、保留政策或违规通知
- 🟢 **低**：数据处理义务清晰、有加密、保留政策、违规通知、适用时有 DPA

### 5. 终止

**它的含义：**
任何一方如何、何时以及按什么条件结束合同？之后数据、款项和 IP 会怎样？

**对创始人的重要性：**
糟糕的终止条款可能把您锁死、要求昂贵的退出罚金，或让您无法访问关键数据或工具。早期公司需要灵活性。

**危险信号 🚩**
- **"仅限有因终止"（无违约即不可终止）**（即使情况变化，您也被锁死）
- **终止罚金 / 提前退出费**（不成比例地高；应与合同价值相称）
- **长通知期**（30 天以上合理；90 天以上或更长把您锁死）
- **无重大违约立即终止的规定**（即使他们停止履约，您也被困住）
- **数据被扣为人质**（终止后无导出数据的权利；他们控制它）
- **存续条款不明确**（终止后哪些义务继续？应明确）
- **"收尾"期要花钱**（您付费退出；注意这一点）

**谈判提示 💡**
- **终止权：** 争取灵活性
  - "任何一方可在提前 [15-30] 天书面通知后为便利终止。"
  - "任何一方可在重大违约于通知后 [10] 天内未获纠正时立即终止。"

- **收尾：** 如果有收尾期，限制它
  - "终止后，[供应商]应以不额外收费的方式提供 [X] 天技术支持。此后适用标准费率。"

- **数据：** 确保您能把数据取出来
  - "终止后，[供应商]应在 [10] 个工作日内以标准格式免费提供[贵公司]的全部数据。"
  - "除非法律要求保留，[供应商]应在 [30] 天内删除[贵公司]的全部数据。"

- **存续条款：** 明确合同结束后哪些继续
  - "以下条款在终止后存续：保密（[X] 年）、赔偿（[X] 年）、知识产权所有权（无限期）。"

- **退款：** 如果您已预付服务/许可费用
  - "未使用服务的任何预付费用应在终止后 [15] 天内退还。"

**风险评分：**
- 🔴 **高**：无为便利终止；重罚金；长通知期；数据被扣；无存续条款
- 🟡 **中**：有终止条款，但缺少一两项保护（如可以退出但数据条款不明确）
- 🟢 **低**：合理通知期的便利终止、数据导出权、清晰的存续条款、公平的收尾条件

## 分析后的后续步骤

1. **确定优先级：** 使用风险分数决定哪些条款对*您的*业务最重要
2. **谈判：** 将本分析中的建议措辞分享给对方
3. **让法律把关：** 签署前让律师审查最终合同
4. **留档：** 保留已签署合同和您谈判的任何修订的副本
