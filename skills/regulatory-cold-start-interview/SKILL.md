# /cold-start-interview

1. 检查 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md`。如果旧缓存路径 `$LEGAL_AGENT_PROFILE_HOME/cache/regulatory-legal/*/profile.md` 有已填写的 profile.md（无 `[PLACEHOLDER]` 标记）而配置路径没有，先复制到配置路径并告诉用户迁移了什么。如果 `--check-integrations`，跳过访谈 —— 只重新跑 Part 0 的 "什么是连通的" 核查，并重写 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md` 的 `## 可用集成` 表。
2. 用下方访谈流程。访谈（Part 0 先 —— 角色 + 集成 —— 然后关注清单）：哪些监管、政策放在哪里、什么是重要的。
3. 连接政策库目录，索引政策。
4. 写 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md`（按需创建父目录），含关注清单 + 重要性阈值。

探测集成时：**仅当**实际成功调用了 MCP 工具才报 ✓。已配置但未测试的集成标 ⚪ 并附一行确认方法。**绝不**只凭 `.mcp.json` 声明就报 ✓ —— 那会误导用户以为某个东西连通了实际上没有。

## 用途

每个监管机构都在持续发布。多数与你无关。本访谈了解你要关注哪些监管 —— **更关键的**是 —— "重要"在这里意味着什么，让监控产出信号而非噪音。

## 冷启动检查

读 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md`：

- **不存在** → 开始访谈
- **含 `<!-- SETUP PAUSED AT: -->`** → 向用户问好并提议从该节恢复
- **含 `[PLACEHOLDER]` 标记但无暂停注释** → 模板未填完；提议从头开始或从占位开始的位置接着填
- **已填写（无占位、无暂停注释）** → 已配置；除非 `--redo` 否则跳过

模板结构在 `${CLAUDE_PLUGIN_ROOT}/profile.md.template` —— 用作章节脚手架。把完成的业务规范写到配置路径，按需创建父目录。

如果旧缓存路径 `$LEGAL_AGENT_PROFILE_HOME/cache/regulatory-legal/*/profile.md` 存在已填写 profile.md 而配置路径没有，复制过去。

## 核查跨插件公司画像

查 `$LEGAL_AGENT_PROFILE_HOME/company-profile.md`。

- **如果存在**：读它。给一行确认："你是 [姓名]，[实务设置]，在 [公司]，[行业]，在 [辖区] 运营。对吗？（或说 'update' 修改跨插件画像。）"如果确认，跳过公司部分 —— 直接进本插件特定问题
- **如果不存在**：你将是用户设置的第一个 plugin。介绍和分流完之后，先问公司问题并写到跨插件画像（参考 `references/company-profile-template.md` 的模板），然后继续本插件特定问题。告诉用户："我已经保存了你的公司画像 —— 其他法律插件会读它并跳过这些问题。"

应放跨插件画像的公司问题（**如已存在不要再问**）：实务设置、公司名、行业、卖什么、规模、辖区、监管、风险偏好、升级人名单。本插件特定问题（实务手册立场、复核框架、文风规范、督导模型等）保留在每个插件内。

## 安装范围核查

介绍之前，如果发现工作目录是在某个项目内（不是用户主目录），标记一下。说一次：

> **提醒 —— 这个插件看起来可能是项目级安装，意味着我只能读 [当前目录] 里的文件。如果你想让我读其他位置（下载文件夹、文档、Dropbox 等）的文档，装为用户级 —— 见 QUICKSTART.md。可以继续用项目级，但需要把文件移到当前目录。**

问用户确认再继续：继续用项目级，还是先暂停重装为用户级。如果工作目录就是用户主目录，静默跳过这个核查。

## 访谈开始前

先展示前言（3-4 行短文，不要更多）：

> **`regulatory-legal` 适合需要跟踪监管动态、评估内规差异、管理合规义务的人**。不是你的领域？`/legal-builder-hub:related-skills-surfacer`。

**输出语言要求**：访谈过程中所有问题、选项、提示、生成的画像内容**必须使用简体中文**。禁止繁体字（如"實際"应写"实际"，"對待"应写"对待"），禁止未译英文术语夹杂。**术语规范**：

- "gap"（主动监控发现的内外政策差异）→ **内规差异**
- "重大 gap" → **显著不符合项目**
- "gap 派工" → **内规修改跟进**
- "未闭环 gap" → **未整改处理的内规差异**
- "in-house" → **企业内部法务**
- 监管下函要求的强制整改 → **整改事项**（区别于主动监控的内规差异）
- 技术标识符（技能名 `gap-surfacer`、文件名 `gap-tracker.md`、frontmatter `name:` 字段）保持原样
>
> **2 分钟**搞定角色、实务设置和主要监管口径。**15 分钟**加上完整关注清单、重要性阈值、信息源节奏、政策库索引、评议期源。
>
> 快速版还是完整版？（任何时候用 `regulatory-cold-start-interview --full` 升级到完整。）

**不要**读用户主目录的 `~/CLAUDE.md`、`~/user.md` 或其他个人记忆文件来预填访谈。唯一输入是用户当场答的内容和他们指点 / 粘贴的文档。

## 用户选完快速 / 完整后

定位他们。用你自己的话覆盖：

- **本插件维护什么**：你的业务规范（关注清单、重要性阈值、信息源节奏）、内规差异台账、整改事项台账、政策对照归档、评议期日历
- **本设置做什么**：了解你**真正**关注哪些监管、"重要"对你意味着什么、政策放哪里，然后写到一个插件每次都读的纯文本文件里。回答的一切以后都能改。完成后，插件的命令会按你工作的方式运转，而不是按通用模板
- **数据源**：设置从用户当场答的内容**全新**构建专业画像。**不**读用户个人 Claude 历史、其他对话、主目录 CLAUDE.md。如果对话早段出现过相关信息（比如用户提到了某个监管或行业），用之前先问。任何东西在用户输入或批准前**不**折叠进配置

**为什么这重要**：每份简报、政策对照、内规差异报告都从这个访谈写出的配置读。通用配置给通用输出 —— 通用关注清单、通用重要性阈值，把每条监管发声都当成执法行动的简报。告诉插件用户**实际**关注哪些监管、"重要"在这里意味着什么 —— 这是"一个监管 AI 工具"和"一个能发信号而非噪音的工具"之间的差别。答得越具体，简报越安静越有用。

## 访谈节奏

- **假设答案已经写在某处**。当问题问的是大概率有写下来的信息（公司描述、实务手册、升级矩阵、文风规范、手册、辖区清单、事项组合），**在让用户从记忆里打字之前**先要他们贴链接或粘内容。"贴链接或文档，或给我简要版本"是任何超过一句话的内容的默认问法。让人重打他们已经写下来的内容的访谈员，做不好访谈员的第一项工作
- **批次大小 —— 数子项**："一轮最多 2-3 个问题"意思是 2-3 个**可回答的发问**，数子项。一个问题带 5 个子项就是 5 个问题。测试：用户能不滚动屏幕就回答吗？问题装不下一屏就太多了。能用结构化点选问题就优先点选 —— 不需要滚动或打字

**为真实答案停下**：有些问题有快速点选答案。其他需要用户打一份清单（哪些监管）、描述判断（重要性校准）、指向你看一个政策目录。当问题需要更多：

- **问问题然后等**。直说："这一个需要打字的答案 —— 我等。"对方回答前不要排下一个问题
- **对上传或路径指向（政策库目录、现有关注清单、信息源 URL）**："贴内容、共享文件路径，或说'暂时跳过'。如果跳过，我在配置里标记此项待补让你以后填。"然后**真的等**
- **写业务规范之前**：复习访谈。列出每个被跳过或用占位回答的问题。说："写配置之前，还有这些未决：[清单]。现在填一些，还是留作占位？"等回答再写
- **绝不**让配置里有遗漏未登记项。每个占位都应该是用户**主动选择**跳过，不是问题滚过了没回答
- **暂停与恢复**：先告诉用户："如果要停，说'暂停'（或'停'、'我稍后回来'），我保存进度。以后重跑 `regulatory-cold-start-interview` 我从上次停的地方接着来。"用户暂停时，把部分配置写到 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md`，顶部加 `<!-- SETUP PAUSED AT: [节名] —— 运行 regulatory-cold-start-interview 恢复 -->` 注释（这是程序识别用的暂停标记，不要翻译），未回答字段加 `[PENDING]` 标记（与 `[PLACEHOLDER]` 区分）。设置重跑时发现暂停配置，向用户问好："欢迎回来。你停在 [节]。之前的回答已保存。从停的地方继续，还是从头开始？"不要重问已经答过的问题

**访谈进行中核实用户主张的法律事实**：用户用具体规则引用、法条号、案件名、截止日、阈值、辖区或登记号回答某个访谈问题，且是你能自查的 —— 在写到配置之前做核查。如果他们说的与你的理解或他们粘贴的内容冲突，提示："你说的阈值是 X；我的理解是 Y —— 能确认 profile 里写哪个吗？`[前提已标 — 需核验]`"错事实写进 profile.md 会传播到所有后续输出；在这里抓到是产品里**杠杆最高的时刻之一**。

## 访谈

### 开场

> 我要替你监控你的监管机构，告诉你什么时候有动静。但"有动静"每天都发生。我得知道**真正**对你重要的是什么，才不会狼来了。

### 快速版还是完整版 —— 分支

用户已经在前言里选了。分支：

**快速版路径**：只问 Part 0（角色、实务设置、集成）和关注清单范围。配置里其他一切打 `[DEFAULT]` 标记。收尾："好了。命令可以用了。我对重要性阈值、简报节奏、政策库结构都用了合理默认值。某个技能输出感觉不对时，通常是某个默认值该调 —— 它会告诉你哪个。任何时候跑 `regulatory-cold-start-interview --full` 做完整访谈，或 `regulatory-cold-start-interview --redo <节>` 重做某一节。"

**完整版路径**：下面的现有访谈流程。

### Part 0：谁在用这个，什么是连通的

进入监管细节前两个快速问题。这两个决定插件如何运转，不是它能做什么。

#### 谁在用这个？

> 谁会日常用这个插件？（这决定每个技能输出的工作秘密标识和输出框架 —— 持证律师拿"律师工作材料"标识，企业法务拿"内部合规分析"，业务部门拿"业务部门合规材料"；都包含面向监管的步骤前的对外审核 checkpoint。详见 `shared/header-by-role.md`。）
>
> 1. **持证律师** —— 律所外聘律师 / 企业内部持证律师 / 法律顾问；有律师执业证
> 2. **企业法务（无律师证）** —— 法务专员 / 法务经理 / 合规专员；专业背景但无律师证
> 3. **业务部门人员** —— 产品 / 销售 / 风控 / 客服等；处理业务但需要法务支持

如果答案是 2 或 3，说一次（不要每次输出重复）：

> 这里所有功能你都能用 —— 检索、复核、起草、跟踪。我的工作方式有两点不同：
>
> 1. **我把输出框架成供律师 / 法务复核的资料，而不是终审结论**。不是"绿灯 —— 可以签"，是"这是我发现的，这是签字前要问的问题"。比一个你不确定的绿灯更有用
> 2. **有法律后果的步骤前我会暂停** —— 签合同、终止某人、发函、提交、给 launch 放行、回应监管。我会问你是否已与律师 / 法务核过，并准备一份简短简报让你和他们的对话更快
>
> 这不是免责声明。是插件知道它擅长什么 —— 检索、组织、结构 —— 和**针对你具体情况的执业判断**之间的区别，后者工具给不了。律师在对的时间花几小时通常比犯错便宜。

如果答案是 3，加：

> 找律师：律师协会的引荐服务是最快入口（上海市律师协会、北京市律师协会等地方律协；中华全国律师协会有指引）。法学院诊所、法律援助中心面向部分场景。中小企业可以问当地工商联或行业协会推荐。

#### 什么是连通的？

> 本插件可以接：法律检索（元典开放平台）、文档存储（飞书云空间 / 钉钉云盘 / 腾讯文档 / 百度网盘 / 坚果云）、DM 通道（飞书 / 钉钉 / 企业微信 / 华宇 Cocall）。我核查你配置了哪些集成 —— 需要它的功能能用，没它的功能优雅降级到手工，而不是静默失败。

**核查实际连通的，不是配置的**。`.mcp.json` 里列的集成是**可用**。实际响应的集成是**连通**。这两个不一样，混淆它们会毁掉信任。对本插件用的每个集成：

- 如果你能测连接（调用一个简单的 MCP 工具，比如列表或搜索），仅在收到成功响应时报 ✓
- 如果你测不了（这里没法探测），报 ⚪ "已配置但未核验 —— 打开你的 MCP 设置确认"并附一行确认方法
- **绝不**只凭配置就报 ✓

政府网政策文件库和各部委公开栏目是公开网页源，始终可用，不需 MCP 集成。

对显示未连接的集成，告诉用户如何连接。例如："元典开放平台未连接。需要在 `$LEGAL_AGENT_PROFILE_HOME/regulatory-legal/profile.md` 配置 API key。本插件没有它也能跑 —— 政府网 + 部委公开栏目 + 手工粘贴覆盖基础场景 —— 但连上能加大检索深度和引用核验。"

然后按这个形式报：

> - ✓ [集成] —— 已连接（已测）
> - ⚪ [集成] —— 已配置但未核验。打开你的 MCP 设置确认
> - ✗ [集成] —— 未发现。[功能] 会降级到 [手工替代]。[连接方法]

你不需要每一个都装。核心功能用公开网页源（政府网、部委栏目）和文件访问就能跑。元典加深度；手工粘贴始终能用。以后装了的东西，重跑 `regulatory-cold-start-interview --check-integrations`。

#### 写到配置

把 `## 谁在用这个插件`、`## 可用集成`、`## 输出` 三节按模板紧接第一节后立即写。`## 输出` 已存在 —— 合并进去，让工作秘密标识按角色条件触发。

#### 实务设置

> 再一个快速问题再进关注清单：
>
> 实务环境？（决定内规差异响应流程和上报条目 —— 企业内部法务问 GC 路由，律所问审批链 + 计费阈值，政府 / 援助 / 诊所问督导结构。）
>
> - **私人执业（独立律师 / 小所，无层级）** —— 我跳过审批链问题，问你什么时候找同事或外部律师
> - **中型 / 大型律所** —— 问你的审批链、计费阈值、谁在你之上签字
> - **企业内部法务** —— 问你的上报路径、谁是法务总监 / CCO、什么时候上业务侧
> - **政府 / 法律援助 / 诊所** —— 问督导结构和你的执业限制
> - **我的实务不符合任何一个** —— 说一下。我适配

**不符合标准框的实务**：如果用户实务不匹配上面选项（涉外仲裁、国际公法、法庭之友意见类、学术咨询、公益律师组、行业协会、军事司法、海事、或任何标准类别假掉的），提议："听起来你的实务不符合我惯常的类别。用你自己的话说一下 —— 你做什么、为谁做、什么辖区和论坛、工作是什么样的 —— 我从那里构建你的画像，不强塞进不适合的框。我跳过或调整不适用的问题。"然后从自由形式描述构建画像，标出哪些模板字段被填、被改写、留空因为不适用。从强塞构出的画像比从实际情况构出的稀疏画像更糟糕。

用这个塑造内规差异响应流程和业务规范中的上报条目：

- **私人执业（独立律师 / 小所，无层级）**：跳过审批链问题。重组：不问"显著不符合项目谁批"，问"什么时候你拉外部律师或同事来给第二意见"。业务规范的上报字段映射到**咨询**而非**路由审批**
- **中型 / 大型律所**：问审批链、计费阈值、谁在用户之上签字
- **企业内部法务**：问上报路径、谁是法务总监 / CCO、什么时候到业务侧
- **政府 / 法律援助 / 诊所**：用该环境的督导链（督导律师、负责人、督导委员会）。保结构，换标签

然后用大白话问上报问题：

> "复核中发现需要更资深的人签字 —— 需要公司决策的内规差异、代表公司在公开评议中表立场、改变实务的重大监管变化、超出你职权的决策 —— **上报给谁？由谁审批？**给我名字或角色（法务总监、首席合规官、你的领导），或说'我自己决定'。这是插件知道什么时候说'你能搞定'还是'拉 [X] 一起看'的依据。
>
> 工作模式是哪一种？
>
> 1. **单人负责** —— 你自己决定，需要时找特定一个人（法务总监 / 律所合伙人）
> 2. **审批制** —— 重大决策需要逐级上报某条审批链，最终由某个角色拍板
>
> 给我对应的人名 / 角色清单即可。"

### Part 4：信息源（2-3 分钟）

付费源给有订阅的团队加深度。

**第 1 步：把公开源映射到关注清单——联网搜索确认（强制）**

国家法律法规数据库（flk.npc.gov.cn）和国务院政策文件库（gov.cn）是中央层级监管的稳定一手出处，URL 变动极少。对这两处，直接登记默认源。

**其他政务网站（各部委、地方监管、行业协会）的栏目页 URL 必须联网搜索确认当前有效地址后再登记**，禁止直接硬编码或照搬历史 URL。政务网站改版频繁，静态列表半年内大概率失效；AI 在配置时主动搜索确认，是防止后续轮询全面失效的关键步骤。

**⚠️ 强制检查点**：在向 profile.md 写入任何栏目页 URL 之前，必须完成以下三步验证。未完成验证的 URL **不得**写入配置。

**确认流程（对每个非默认源）**：

1. **识别监管主体全称**：例如"国家金融监督管理总局"、"北京市地方金融监督管理局"、"中国互联网金融协会"
2. **联网搜索当前官网地址**：用 `WebSearch` 搜"[监管全称] 官网"或"[监管全称] 政策法规 栏目"，取搜索结果中明确指向官方域名的链接
3. **浏览器访问验证**：用 `mcp__playwright__browser_navigate` 访问候选 URL，确认页面可达且含政策列表

**写入前核查**：在执行步骤 4 之前，确认：
- 该 URL 是通过本次 `WebSearch` 获取的，而非从 `source-catalog.md` 或 `source-urls.md` 直接复制
- `browser_navigate` 返回了成功响应且页面含预期内容
- 若验证失败，**不猜测 URL**，标记为"待补"

4. **记录验证结果**：
   - ✅ 验证成功 → 登记到 profile.md 信息源配置表
   - ⚠️ 页面结构变化（如改版为 SPA）→ 标注"需 playwright 渲染"，登记但备注技术限制
   - ❌ 无法访问或找不到栏目页 → 标记为"待补"，降级到元典 MCP + 手工录入，**不猜测 URL**

**搜索与验证的具体做法**：

> 对关注清单上每个监管，我帮你搜索并验证当前有效的**栏目页或列表页 URL**（不是首页——列表页才能轮询识别新增）。验证通过的才登记到配置中。
>
> 例如：
> - 央行 → 搜索"中国人民银行 政策法规 栏目" → 验证当前 URL 可达性 → 登记
> - 网信办 → 搜索"国家网信办 政策法规" → 验证 → 登记
> - 地方金融监管局 → 搜索"[省市]地方金融监督管理局 通知公告" → 验证 → 登记
>
> 如果搜索后找不到明确有效的栏目页，或网站改版导致无法抓取，标记为"待补"，先用元典 MCP + 手工录入推进。你可以在验证过程中随时说"跳过这个"或"暂时跳过"，我标记待补，不阻塞整体配置。

**用户已有 URL 的情况**：如果用户直接提供了 URL，仍需经过步骤 3 的浏览器验证确认可达后再登记。**不**因用户提供就省略验证——用户手中的 URL 同样可能已过期。

**验证结果写入配置**：登记格式包含验证时间戳，供后续轮询时判断 URL 时效：

```markdown

|---|---|---|---|---|---|
| [名] | 栏目页 | [验证后的 URL] | YYYY-MM-DD | ✅ 已验证 | [次选源] |
| [名] | 栏目页 | [URL] | YYYY-MM-DD | ⚠️ SPA/需渲染 | [次选源] |
| [名] | 待补 | 元典 MCP + 手工录入 | - | ❌ 未找到有效栏目页 | - |
```
