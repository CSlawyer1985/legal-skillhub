> **定位：搜索验证的起点，不是可直接登记的清单。**

> 本清单记录历史上曾测试可达的栏目页入口，供 cold-start 的**联网搜索**步骤作为起点关键词使用。

> ⚠️ **严禁行为**：禁止直接从本清单复制任何 URL 到 profile.md。必须先执行联网搜索 + 浏览器验证流程。

## 信息源类型说明

**栏目页（静态）**：HTML 直出列表，`WebFetch` 可直接抓标题 + 链接。轮询时记录指纹（已见 URL 集合），对比识别新增。

**栏目页（SPA / 动态）**：列表通过 JavaScript 加载，`WebFetch` 拿到的只是页面壳。需 **playwright MCP** 渲染后抓，或调用站点内部 API（如有公开）。

**元典开放平台 MCP**：通过 `mcp__yuandian-law__*` 工具结构化查询。覆盖中央层级法律 / 行政法规 / 部门规章 / 司法解释 / 指导性案例 / 行政处罚。**最稳定的源，优先用**。

**官方 RSS**：中央监管基本无；少数行业自律协会或地方部门可能有。遇到时填 XML URL 由 `WebFetch` 拉。

## 维护备注

发现某个栏目页 URL 失效时：
1. **不要硬改成猜的新 URL** —— 会误导后续验证流程
2. 在状态列改为 ⚠️ 并附"YYYY-MM-DD 失效，待搜索重新验证"
3. cold-start 流程遇到标记为 ⚠️ 的源时，自动执行联网搜索重新验证；**不**因清单中有旧 URL 就跳过搜索步骤

不要凭空增加未测试的 URL。本文件的可信度依赖"清单里的都曾经实测过"这一前提，但不保证当前仍有效。

## 与 cold-start 验证流程的配合

`regulatory-cold-start-interview` 配置信息源时：

1. 先用本清单了解某监管的历史栏目页结构（如央行有"政策法规"和"行政处罚公示"两个常见入口）
2. 用 `WebSearch` 搜"[监管名] [栏目类型] site:[官方域名]"或"[监管名] 政策法规 当前网址"获取候选 URL
3. 用 `mcp__playwright__browser_navigate` + `browser_snapshot` 验证候选 URL 可达且含政策列表
4. 验证成功后写入 profile.md，记录验证时间戳
5. 验证失败（404/改版/无列表）时标记"待补"，不阻塞整体配置

**禁止行为**：不经验证直接从本清单复制 URL 到 profile.md；不搜索验证就直接使用用户提供的历史 URL。
