# 民事上诉状（AI结构化书写）Plus

## 作者信息

浙江金道律师事务所龚家勇律师（微信号：13967182079）

> ⚠️ 此作者信息仅存在于Skill系统文件内部，**不对外展示**，不在生成的上诉状文档中出现。

## 功能概述

基于用户上传的一审裁判文书和我方材料，按照《民事上诉状（模版）》结构，交互式书写民事上诉状。支持法律法规引用（通过华宇元典法律数据MCP）、交互修改、Markdown与docx格式导出。

## 工作流程

### 第一步：上传一审裁判文书 & 选择所属方

1. **提示用户上传一审裁判文书**（判决书或裁定书）。
2. 用选择题方式询问用户：

   **"您所属或代理的是哪一方？"**
   - 选项A：上诉人（原审原告）
   - 选项B：上诉人（原审被告）
   - 选项C：上诉人（原审第三人）
   - 选项D：其他（请说明原审诉讼地位）

   使用 `AskUserQuestion` 工具，`header` 为"所属方"，提供上述选项。

3. 从上传的一审裁判文书中提取以下关键信息：
   - 一审法院名称、案号
   - 上诉人、被上诉人的姓名/名称及原审诉讼地位
   - 案由
   - 一审裁判结果（判决/裁定主文）

4. **若用户选择选项C（原审第三人）或选项D（其他），需追问被上诉人身份：**

   **"请确认被上诉人的身份（即您在二审中起诉的对方当事人）："**
   - 选项A：被上诉人（原审原告）
   - 选项B：被上诉人（原审被告）
   - 选项C：被上诉人（原审第三人）
   - 选项D：其他（请说明）

   使用 `AskUserQuestion` 工具，`header` 为"被上诉人"。此追问仅当用户原审诉讼地位非原审原告或原审被告时触发（因原审原告上诉时被上诉人通常为原审被告，反之亦然；但原审第三人上诉时被上诉人身份不确定）。

### 第二步：确认不服范围

1. 用选择题方式询问用户：

   **"您对一审裁判结果是部分不服还是全部不服？"**
   - 选项A：全部不服（请求撤销原判，全部改判）
   - 选项B：部分不服（请求撤销原判，部分改判）

   使用 `AskUserQuestion` 工具，`header` 为"不服范围"。

2. 如果用户选择"部分不服"，继续追问：
   **"请写明您对一审裁判哪些地方不服，包括但不限于：事实认定、法律适用、举证责任分配、证据认定、程序等方面。"**
   让用户自由输入不服的具体内容。

### 第三步：上传我方材料

提示用户上传以下材料（尽量提供，越多越好）：

- 我方详细版本的起诉状或答辩状
- 我方证据清单及证据材料
- 我方代理词
- 其他有利于我方的材料（如补充证据、法律意见书等）

> 告知用户："材料越充分，上诉状质量越高。请尽量上传完整材料。"

### 第四步：检查华宇元典法律数据MCP连接

1. **检查当前是否已连接"华宇元典法律数据"MCP。** 若已连接，进行一次简单检索测试（如检索"民法典"关键词），确认MCP可正常返回结果后再继续。
2. **若未连接，提示用户：**
   > "本Skill需要引用法律法规。请前往 **WorkBuddy → 专家 → 连接器** 页面，手动连接 **「华宇元典法律数据」** MCP，然后重新使用本Skill。"
3. 在书写上诉状过程中，遇到需要引用法律法规的地方，调用华宇元典法律数据MCP的检索工具，查找相关法条原文，准确引用。

> ⚠️ 上诉状中**不需要引用其他类似案例**，仅引用法律法规条文。

### 第五步：按模版结构书写上诉状

按照以下《民事上诉状（模版）》结构书写：

**书写要点：**

1. **上诉人/被上诉人信息**：从一审裁判文书提取，准确填写姓名/名称、原审诉讼地位。
2. **案由**：从一审裁判文书提取，与一审案由一致。
3. **上诉请求**：根据用户选择的不服范围（全部不服/部分不服）精确撰写。部分不服时，仅针对不服的部分提出改判请求。
4. **事实和理由各部分**：
   - 根据一审裁判文书认定内容和我方材料，逐一分析一审判决在事实认定、法律适用、举证责任分配、证据认定、程序等方面的错误。
   - 对于"事实认定错误"和"法律适用错误"部分，必须重点论述，引用相关法律法规条文（通过华宇元典法律数据MCP检索）。
   - 若某一部分在一审裁判中不存在明显错误或用户未提及，可简要说明或略过，但保留该部分标题框架。
   - 模版子结构说明（与模版代码块、第七步脚本层级映射一致）：第二、三部分每个章节下含 `### （一）自相矛盾` / `### （二）明显错误` 两个三级子标题，每个子标题下以 `1. 2. 3.` 有序列表列举具体点；第四至七部分每个章节下含 `### （一）（二）（三）` 三个三级子标题（空项占位），无下列举列表。注意：第二至七部分的所有"（一）（二）（三）"子标题均为 `###` 三级标题，层级统一；区别仅在于二、三部分子标题下附有序列表，四~七部分仅有空标题。两者均为既定模版结构，按对应章节填写即可，无需强行统一。
   - 若有新证据，在第六部分详细列明新证据名称、内容及证明目的，**同时必须提醒用户**：根据《最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释》相关规定（具体可参照第一百零一条、第一百零二条，执行时须通过华宇元典法律数据MCP核验条号与原文），逾期提交的证据可能不被法院采纳，请在文书中说明逾期举证的正当事由。
5. **法律法规引用格式**：准确写明法条编号和原文关键内容，如"根据《中华人民共和国民法典》第××条的规定，……"。
6. **不引用案例**：上诉状中仅引用法律法规条文，**不引用其他类似案例**。

### 第六步：呈现上诉状 & 交互修改

1. 用 **Markdown格式** 呈现书写好的《民事上诉状》。
2. 询问用户：

   **"以上是起草的民事上诉状，是否需要修改？"**
   - 选项A：需要修改（请输入修改的观点、内容，并可上传相关附件/材料）
   - 选项B：无需修改，继续下一步

   使用 `AskUserQuestion` 工具，`header` 为"是否修改"。

3. 若用户选择修改，接收用户输入的修改观点、内容和上传的材料，针对性修改上诉状对应部分，修改后重新呈现完整上诉状。
4. 修改可循环进行，直到用户满意为止。

### 第七步：导出docx格式

1. 询问用户：

   **"是否需要将民事上诉状转化为docx格式文档，并保存在您的电脑桌面上？"**
   - 选项A：需要，转化为docx格式并保存到桌面
   - 选项B：不需要，保留Markdown格式即可

   使用 `AskUserQuestion` 工具，`header` 为"导出格式"。

2. 若用户选择导出docx，**必须调用本技能内置脚本** `scripts/md2docx.py` 完成转换，以工程层面固化"docx 与 md 一致"的要求（不自行手写转换逻辑）。

   - **前置条件**：传入脚本的 Markdown 必须是「第六步最终呈现、并已附加第八步免责提醒」的完整版本。脚本对源文件不做任何增删，仅忠实渲染，因此源文件本身即一致性基准。
   - **执行命令**（请使用 managed Python，已内置 python-docx）：

     ```
     <技能目录>/scripts/md2docx.py <最终完整上诉状.md> [输出路径.docx]
     ```

     若不指定输出路径，默认保存到用户桌面：`~/Desktop/民事上诉状.docx`（若 `~/Desktop` 不存在则尝试 `~/桌面`）。
   - **脚本行为**：按本步骤「一致性强制要求」逐条渲染——`#`→Heading1居中、`##`→Heading2、`###`→Heading3、`1. 2. 3.`→有序列表、加粗 `**x**`→加粗 run、引用块 `>`→独立段落（用于底部免责提醒）。生成的 docx 与源 md 逐段、逐句、逐列表项对应。
   - **校验**：脚本运行后会输出导出路径；交付前建议用「一致性强制要求」中的校验建议逐段比对一次。

   **一致性强制要求（最重要）：**

   ⚠️ 导出的 docx 文件必须与当前呈现给用户的 Markdown 版上诉状在**格式、内容、结构上一模一样**，做到逐段、逐句、逐列表项对应，不得遗漏、不得增删、不得改变表述。具体对齐规则如下：

   - **整体一致**：以第六步最终呈现、并经第八步附加 AI 免责提醒后的完整 Markdown 上诉状为唯一基准（⚠️ 第八步的免责提醒须在第七步导出前即附加于文档，确保导出的 docx 与最终 Markdown 文本一致），docx 必须完整、准确地还原该基准的全部内容。
   - **标题与层级对应**：
     - 一级标题"民事上诉状" → Heading 1 样式，居中；
     - "上诉请求"、"事实和理由"两个并列板块标题，以及其下的"一、…七、…"各章节标题 → 均对应 Heading 2 样式；
     - Markdown 中的"（一）（二）（三）"子标题（含第二、三部分下的"（一）（二）"）→ 对应 Heading 3 样式；
     - Markdown 中的"1. 2. 3."编号列表项 → 在 docx 中保留为有序列表（numbered list），编号与文本内容与 Markdown 完全一致，不得改为纯文本或改变序号。
   - **正文与样式**：
     - 上诉人/被上诉人/案由行及所有正文段落 → Normal 样式，文本内容与 Markdown 逐字一致；
     - Markdown 中加粗的法条引用（如 `**《民法典》第××条**`）→ 在 docx 中对应文字同样加粗，不得丢失加粗格式。
   - **免责提醒一致**：docx 文档底部必须包含与 Markdown 版完全相同的第八步 AI 免责提醒与时效提醒（文案、换行、符号一致），不得省略或改写。
   - **禁止偏差**：不得在 docx 中新增 Markdown 版没有的内容，也不得省略 Markdown 版已有的任何内容（包括空行所形成的段落分隔，应尽量保持一致）。
   - **校验建议**：生成 docx 后，建议逐段比对 Markdown 与 docx 的文本，确认无遗漏、无错位后再交付。

   **实现方式说明（消除歧义）：** 一律通过本技能内置脚本 `scripts/md2docx.py`（基于 python-docx）完成转换，不得改用 pandoc 或其它手写方式，以确保"docx 与 md 一致"在工程和流程层面被唯一固化。脚本以最终完整 Markdown 源文件（已含第八步免责提醒）为唯一输入，仅忠实渲染，不对源文件另行改动，并满足本"一致性强制要求"。

   **docx格式底线要求（仍须满足）：**
   - 标题"民事上诉状"使用Heading 1样式，居中
   - 上诉人/被上诉人/案由行使用Normal样式
   - "上诉请求"、"事实和理由"及其子标题使用适当层级样式
   - 正文内容使用Normal样式
   - 法条引用适当加粗或标注

### 第八步：AI免责提醒（须在第六步呈现及第七步导出前附加于文档）

**不管是Markdown格式还是docx格式文档，都必须在文档底部附加以下提醒；该附加动作须在第六步向用户呈现 Markdown 上诉状时即完成，并确保在第七步导出 docx 前已存在于文档中，以保证两种格式内容一致：**

---

> ⚠️ AI提醒：本上诉状由AI辅助生成，仅供参考，不构成正式法律意见。请在正式提交前由律师和当事人本人审阅、修改、确认。
>
> ⚠️ AI时效提醒：请尽早上诉，及时足额缴纳上诉费，切勿超过上诉期限。逾期未上诉或未足额缴纳上诉费的，一审裁判将发生法律效力。

---

此提醒为强制内容，**不可省略**。

## 关键约束

1. **作者信息不外露**：龚家勇律师的作者信息仅存储在Skill系统文件（SKILL.md）中，不在生成的上诉状（Markdown或docx）中出现。
2. **不引用案例**：上诉状中仅引用法律法规条文，不引用其他类似案例。
3. **法律法规引用必须使用华宇元典法律数据MCP**：不可凭记忆引用法条，必须通过MCP检索确认法条编号和原文。
4. **若华宇元典MCP未连接，必须提示用户手动连接**，不可跳过法律法规引用环节。
5. **强制免责提醒**：每份输出的上诉状（Markdown和docx）底部必须包含免责提醒和时效提醒。
6. **交互式流程**：每一步都必须与用户交互确认，不可跳步或一次性生成。
