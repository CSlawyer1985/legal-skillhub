# 模板：第 4(7) 条暂不提供或暂停通知（第二阶段）

产出数据持有者在满足第 4(7) 条三项触发事由之一时，对认定为商业秘密的数据作出暂不提供或暂停共享的、理由充分的第二阶段书面决定，并附并行向主管机关作出的通知。

形式：双输出。(i) 致用户的通知，以及 (ii) 主管机关通知。两者均为必需。默认为 Markdown。

仅在依据第 4(6) 条的第一阶段协商已经发生、且满足第 4(7) 条三项触发事由之一后使用本模板：
- 尽管善意协商，仍未就必要措施达成一致；
- 用户已同意措施但未能实施；或
- 用户已损害商业秘密的机密性。

不要将本模板用作第一阶段的替代。如第一阶段协商尚未尝试，转至 `art4-6-trade-secret-safeguards-agreement.md`。不要将其用于对第 4(1) 条请求的直接拒绝；那属于 `art4-8-refusal-letter.md` 下的第三阶段。

## 第一部分：致用户的暂不提供/暂停通知

```
[数据持有者信头占位符]

致：[用户，完整法定实体名称 / 自然人姓名及地址]

日期：[日期]

编号：[内部编号；援引基础第 4(1) 条请求及任何第 4(6) 条保障措施
       协议]

主题：依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(7) 条
      [暂不提供 / 暂停] 共享受商业秘密保护数据的决定

1. 背景

   用户于 [日期] 依据《数据法案》第 4(1) 条提交了数据访问请求。
   数据持有者认定请求范围内的某些数据属于《数据法案》第 2(19)
   条及《指令 (EU) 2016/943》（《商业秘密指令》）第 2(1) 条含义
   内受商业秘密保护的数据。双方 [于 [日期] 就保障措施达成一致 /
   自 [日期] 起依据第 4(6) 条进行了第一阶段协商]。

2. 本通知的触发事由

   [识别三项第 4(7) 条触发事由中哪一项被触发。仅使用事实支持的
   触发事由；除非多项触发事由真实地独立成立，否则不得合并。]

   [触发事由一：未就必要措施达成一致]

   双方自 [日期] 起依据第 4(6) 条进行了善意协商。协商未就
   必要的技术与组织措施达成一致，原因如下：

   [协商的事实陈述。识别数据持有者提议的措施、用户接受的措施
   以及未能达成一致的措施。识别用户不同意数据持有者提议措施的
   理由，以及数据持有者认为用户反对提议不充分的原因。]

   数据持有者已善意寻求适当措施。就 [具体措施] 持续缺乏一致，
   使数据持有者无法在按必要程度保持机密性的前提下披露受商业
   秘密保护的数据。

   [触发事由二：未能实施已同意的措施]

   双方通过日期为 [日期] 的协议依据第 4(6) 条同意了保障措施。
   用户未能实施以下已同意的措施：

   [具体识别用户未实施的已同意措施。实施失败的事实陈述：用户
   应做什么、用户做了什么、数据持有者何时发现该失败，以及数据
   持有者此前给予用户的任何通知。]

   数据持有者已 [于 [日期] 识别该失败 / 于 [日期] 通知用户纠正
   该失败，但未在 [期限] 内得到纠正]。

   [触发事由三：损害商业秘密的机密性]

   用户按以下方式损害了商业秘密的机密性：

   [损害的具体事实陈述：用户采取了什么行动、何时采取、对商业
   秘密机密性的影响，以及对数据持有者的任何后果。损害必须得到
   证明；仅有怀疑不充分。]

3. 受影响商业秘密的识别

   本通知 [暂不提供 / 暂停] 共享的商业秘密数据为：

   [按类别或按字段识别。如任何商业秘密在触发事由三下机密性已
   受损，识别具体哪些。]

4. 决定

   基于第 2 节和第 3 节所列依据，数据持有者依据《数据法案》
   第 4(7) 条 [暂不提供 / 暂停] 第 3 节识别的受商业秘密保护数据
   的共享。

   [暂不提供（数据尚未共享）时：“数据持有者在 [能够使共享继续
   进行的具体补救，例如用户同意必要措施、实施此前已同意的措施
   或纠正损害] 之前，不会共享受影响的
   数据。”]

   [暂停（数据已部分共享）时：“数据持有者暂停受影响类别中任何
   进一步数据的共享。已共享的数据继续受既有保障措施及用户在第
   4(10) 条、第 4(11) 条和《商业秘密指令》下义务的约束。”]

5. 主管机关通知

   数据持有者已在本通知发出之同时，依据第 37 条将本决定、未
   达成一致或未实施的措施，以及如相关机密性已受损的商业秘密，
   通知 [设立地成员国] 指定的主管机关。通知副本随附。

6. 用户的救济选项

   用户在不影响在任何阶段于成员国法院或裁判机构寻求救济的权利
   的前提下，保留：
   (a) 依据第 37(5)(b) 条向依据第 37 条指定的主管机关提出投诉
       的权利。主管机关应无不当延误地决定数据共享是否以及在
       何种条件下开始或恢复；以及
   (b) 与数据持有者约定，按照第 10(1) 条将争议提交争议解决
       机构的权利。

7. 补救路径（如适当）

   [触发事由一下暂不提供时：“数据持有者仍愿就适当措施继续
   协商。如用户希望提出调整建议，数据持有者将善意参与。”]

   [触发事由二下暂不提供时：“用户在实施已同意的措施并确认实施
   情况（附 [用户须提供的证据] 支持）后，数据持有者将恢复
   共享。”]

   [触发事由三下暂停时：“数据持有者仅在 [具体补救：例如恢复
   受损害的某项技术措施、从未经授权的接收者处移除数据、附加
   经证明能有效防止进一步损害的保障措施] 之后恢复共享。”]

[签署栏占位符]

附件：
- 日期为 [日期] 的主管机关通知副本
- 如适用：第 4(6) 条保障措施协议；协商函件；未能实施或损害
  机密性的证据。
```

## 第二部分：主管机关通知

```
[数据持有者信头占位符]

致：[ [设立地] 成员国中依据《数据法案》第 37 条指定的主管机关]

日期：[日期]

编号：[内部编号]

主题：依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(7) 条
      暂不提供或暂停数据共享的通知

1. 通知实体

   [数据持有者，完整法定实体名称、注册地址，如有依据第 37 条
   设立的联系点。]

2. 主题事项

   数据持有者已通过日期为 [日期] 的致用户通知，决定 [暂不提供 /
   暂停] 共享用户日期为 [日期] 的第 4(1) 条请求范围内识别的受
   商业秘密保护数据。致用户通知副本随附。

3. 第 4(7) 条触发事由与识别

   依据第 4(7) 条第三句，数据持有者通知主管机关：

   (a) 哪些措施未达成一致或未实施：[具体识别]；
   (b) 如相关，哪些商业秘密的机密性已受损：[具体识别]。

4. 用户信息

   [暂不提供 / 暂停] 对其生效的用户为 [姓名，如适当可含联系
   方式]。用户已获告知其依据第 4(9) 条和第 37(5)(b) 条的救济
   选项。

5. 第一阶段记录（支持性文件）

   数据持有者为支持本通知随附：
   - 第 4(6) 条保障措施协议 [触发事由二或三时]；
   - 协商函件 [触发事由一时]；
   - 未能实施或损害机密性的证据 [触发事由二或三时]。

[签署栏占位符]
```
