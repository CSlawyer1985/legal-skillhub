# 模板：数据持有者对第 4(1) 条用户请求的回应

产出数据持有者依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(1) 条对用户请求产品及相关服务数据作出的实质性书面回应。

形式：正式信函。默认为 Markdown。视所请求数据的范围及任何保障措施或限制，通常为一至两页。

本模板涵盖四种典型回应姿态：(i) 完全合规；(ii) 附带第 4(6) 条商业秘密保障措施的合规；(iii) 附带格式或范围澄清的合规；(iv) 部分合规，并告知在进一步发布数据前须先进行商业秘密第一阶段协商。对于第 4(8) 条下的直接拒绝，使用 `art4-8-refusal-letter.md`。对于第 4(2) 条下的安全或安保限制，使用 `art4-2-safety-handbrake-notice.md`。

---

```
[数据持有者信头占位符]

致：[请求用户，完整法定实体名称 / 自然人姓名及地址]

日期：[回应日期]

编号：[内部编号；援引用户请求的日期及用户使用的任何编号]

主题：关于依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(1) 条
      请求访问产品数据及相关服务数据的回应

1. 确认收到请求

   [数据持有者] 已收到用户日期为 [日期] 的请求，用户在其中请求
   访问 [按数据持有者理解简要复述请求范围]。数据持有者已识别
   用户为 [以下物联网产品的使用者：[标识符] / 以下相关服务的
   订户：[标识符]]，并基于 [随附的用户身份证据 / 数据持有者
   记录] 核验了用户身份。

   [用户请求依据第 4(1) 条第二句指定代理方时：“数据持有者已审查
   请求所附的授权委托书，并已确认 [代理方] 代表用户行事的
   权限。”]

2. 数据持有者将提供的数据范围

   数据持有者将提供以下数据，并附解释和使用该数据所必需的
   相关元数据：

   [逐类列举数据并作简要描述。注明数据系一次性导出、持续推送
   或通过 API 访问交付。注明格式（通常为 [JSON / CSV / Parquet /
   指定的行业标准]）。]

   [数据持有者识别出用户请求中属于第 4(1) 条范围之外的数据时，
   予以识别并说明理由：“用户请求的以下项目不属于第 2(17) 条
   含义内的即可获得数据，因此不在第 4(1) 条范围内：[项目，逐项
   说明理由：例如按序言第 15 段属于派生数据；非在使用物联网
   产品或相关服务过程中生成的数据；所请求的信息系数据持有者
   的内部业务数据]。”如请求的实质部分超出范围，在发送前通过
   `references/scenarios/ch2-data-holder-response.md` 处理该事项；
   本模板假设请求实质在范围内。]

3. 商业秘密识别（如适用）

   [数据持有者识别出任何数据受商业秘密保护时，具体予以识别：]

   数据持有者已认定以下数据属于《数据法案》第 2(19) 条及
   《指令 (EU) 2016/943》（《商业秘密指令》）第 2(1) 条含义内
   受商业秘密保护的数据：

   [按类别或按字段识别；数据以机器可读形式提供时，在元数据中
   加注商业秘密标记。]

   依据第 4(6) 条，数据持有者提议采取以下技术与组织措施以保持
   受商业秘密保护数据的机密性：

   [具体拟议措施。示例（按比例原则校准；实际措施因场景而异）：

   - 用户基于 [示范合同条款 / 随本回应附上的定制保密协议]
     作出保密承诺。
   - 访问控制：数据交付给经认证为用户授权代表的指定联系点；
     用户组织内的内部共享限于具名人员。
   - 技术保障：传输中和静态时加密；对商业秘密记录加水印和
     指纹标记；用户方审计日志，数据持有者在合理通知后享有
     审计权。
   - 事件响应：针对疑似保密泄露的既定通知程序。]

   数据持有者准备与用户协商对该等措施的适当调整。用户确认约定
   措施到位后，数据持有者将及时提供受商业秘密保护的数据。

4. 交付安排

   数据持有者将按以下方式交付数据：

   [交付细节：端点、格式、时间表、如适用的实时推送、检索窗口。]

   依据第 4(1) 条，数据以与数据持有者自身可获得的质量相同的
   质量提供，采用全面、结构化、常用且机器可读的格式。
   [持续实时交付可行时：“持续实时交付在技术上可行，数据持有者
   将自 [日期] 起提供该等交付。”不可行时：“持续实时交付目前
   在技术上不可行，原因如下：[原因]。数据持有者将提供
   [替代节奏] 交付。”]

5. 个人数据条件的遵守（如适用）

   [涉及个人数据且用户为数据主体时：“数据包含作为数据主体的
   用户的个人数据。用户依据《欧盟法规 (EU) 2016/679》（GDPR）
   享有的权利，包括第 15 条下的权利，不受本回应影响。”]

   [涉及个人数据且用户非数据主体时：“数据包含用户以外的自然人
   的个人数据。数据持有者基于以下基础向用户提供该数据：用户
   已表示其依据 GDPR 第 6(1) 条具备有效的处理法律依据，且如
   适用，GDPR 第 9 条和《指令 2002/58/EC》第 5(3) 条的条件已
   满足，符合《数据法案》第 4(12) 条。数据持有者依赖该表示。”]

6. 使用限制告知（信息性）

   数据持有者提请用户注意第 4(10) 条的使用限制（不得使用数据
   开发与数据来源物联网产品相竞争的产品；不得出于该意图与
   第三方共享；不得用于获取关于数据持有者或制造商经济状况、
   资产或生产方法的洞见）以及第 4(11) 条的限制（不得使用胁迫
   手段或滥用数据持有者技术基础设施的漏洞获取进一步数据）。

7. 联系点

   就本回应的问题，包括与数据交付相关的运营事项，用户可联系
   [具名联系人或依据第 3(2)(g) 条设立的一般《数据法案》联系点]。
   就第 3 节商业秘密保障措施相关事项，用户可联系 [具名联系人，
   通常为法务或合规一方]。

8. 救济告知

   用户在任何阶段均保留向 [数据持有者设立地] 成员国中依据
   《数据法案》第 37 条指定的主管机关提出投诉的权利，以及在
   成员国法院或裁判机构寻求救济的权利。

[签署栏占位符]

附件（如适用）：
- 保密协议 / 示范合同条款
- 拟议交付安排的技术规范（API 文档、模式、安全态势）
- 带商业秘密标记的元数据字段清单
```
