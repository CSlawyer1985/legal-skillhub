# 模板：用户的第 4(1) 条数据访问请求

产出用户依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(1) 条向数据持有者提出的、请求物联网产品及相关服务数据的书面请求。

形式：简短正式信函。默认为 Markdown。通常为一页。

---

```
[用户信头占位符]

致：[数据持有者，完整法定实体名称及注册地址]
    [可选：具名收件人或部门，例如依据第 3(2) 条公布时的
    “《数据法案》联系点”]

日期：[请求日期]

主题：依据《欧盟法规 (EU) 2023/2854》（《数据法案》）第 4(1) 条
      请求访问产品数据及相关服务数据

1. 请求用户的身份

   请求方为 [完整法定实体名称 / 自然人姓名]，[注册办公地址 /
   用户为自然人时的居住地址]。[如用户依据第 4(1) 条第二句通过
   代表其行事的当事方提出请求：“[代理方] 依据日期为 [日期] 的
   授权委托书，代表 [用户] 提交本请求。授权委托书副本随附。”]

   用户为 [使用者 / 承租人 / 所有人] 的[物联网产品标识符：
   型号、序列号、VIN、资产编号或其他唯一标识符]
   [如适用：并是以下相关服务的订户：[服务名称]]。

2. 请求的数据

   [所请求数据的具体描述。按类别识别，已知时按数据字段识别，
   并按时间窗口识别。请求范围包括数据以及解释和使用该数据
   所必需的相关元数据。]

   所请求的数据属于《数据法案》第 2(15) 条和第 2(16) 条含义内的
   “产品数据”和“相关服务数据”范围。用户理解，本请求涵盖第
   2(17) 条定义的即可获得数据，不延伸至数据持有者通过超出
   物联网产品或相关服务日常运营范围的大量投资而已经获得或
   将不得不获得的数据。

3. 法律依据

   本请求依据《数据法案》第 4(1) 条提出。凡用户无法直接从
   物联网产品或相关服务访问数据，数据持有者应无不当延误地使
   即可获得数据以及解释和使用该数据所必需的相关元数据对用户
   可访问，且质量与数据持有者自身可获得的质量相同，易于访问、
   安全、免费，采用全面、结构化、常用且机器可读的格式，并在
   相关且技术上可行时，持续实时提供。

4. 格式与交付

   用户请求通过 [安全文件传输至 [端点] / 在 [端点] 通过 API 访问
   / 以物理介质寄送至上述地址 / 通过数据持有者公布的 [URL]
   《数据法案》门户] 交付。[如持续或实时交付在技术上可行：
   “用户进一步请求依据第 4(1) 条，自 [日期] 起持续实时提供
   数据。”]

   用户接受机器可读格式，包括 [JSON / CSV / Parquet / Avro /
   指定的行业标准]。如数据持有者拟采用替代格式，用户请求事先
   通知以确认兼容性。

5. 目的陈述（可选，仅在有用时包含）

   [如用户选择披露，简要描述预期用途。披露目的并非使第 4(1) 条
   请求成立所必需。如予以披露，用户表明其知悉第 4(10) 条关于
   不得利用数据开发与数据来源物联网产品相竞争的产品的限制。]

6. 商业秘密预先接触

   用户确认，所请求数据中的某些部分可能被数据持有者认定为受
   商业秘密保护。用户准备依据第 4(6) 条参与关于为保持任何此类
   数据机密性所必需的适当技术与组织措施的第一阶段协商。用户
   请求数据持有者在收到本请求后 [数字] 个工作日内，识别其主张
   受商业秘密保护的具体数据类别，并提出初步保障措施。

7. 个人数据

   [选项 A，用户为数据主体时：“用户是本请求范围内任何个人数据
   的数据主体。用户依据《欧盟法规 (EU) 2016/679》（GDPR）享有
   的数据主体权利，包括第 15 条下的权利，均予以保留，不受本
   《数据法案》请求影响。”]

   [选项 B，用户非数据主体且为企业时：“用户对本请求范围内的
   个人数据，依《欧盟法规 (EU) 2016/679》（GDPR）含义，与《数据
   法案》序言第 34 段一致，作为控制者行事。用户依据 GDPR 第
   6(1) 条处理的法律依据为 [法律依据及简要论证]。用户已按照
   GDPR 第 13 条和第 14 条告知受影响的数据主体相关处理。”]

8. 时间与回应

   用户请求在 [数字] 个工作日内确认收到，并在无不当延误的情况下
   作出实质性回应。如数据持有者预计需要援引第 4(6) 条（商业秘密
   保障措施）、第 4(2) 条（安保限制）或对请求的任何其他限制，
   用户请求在同一期限内收到通知，以便及时协商任何保障措施或
   限制。

9. 救济权利保留

   本请求的提出不影响用户向依据《数据法案》第 37 条指定的主管
   机关提出投诉的权利，以及用户在成员国法院或裁判机构寻求
   救济的权利。

[签署栏占位符]

附件（如适用）：
- [用户] 向 [代理方] 出具的日期为 [日期] 的授权委托书
- 用户身份证明（购买凭证、租赁协议、订阅确认），如数据持有者
  档案中可能没有该等文件
```
