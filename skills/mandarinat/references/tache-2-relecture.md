# 任务 2——文档审读

> **环境前提**：步骤 2（Word 批注）和步骤 3（引用核查）**必须**在 COWORK 或 CHAT_CU 模式下执行。在 CHAT 模式：仅当文档在上下文窗口中可见时，才可执行步骤 1（语言和结构审读）。如文档超过 15 页，或需要步骤 2 或 3，**阻断**并要求切换到 Cowork。

## 目标

对学术法律文档（文章、硕士论文、博士论文、著作章节、学生答卷）进行三个不同且依序进行的深入审读步骤：
1. **语言和结构审读**（写作质量）
2. **引用核查**（存在性、准确性、符合性）
3. **论证一致性分析和抄袭/AI 痕迹检测**

每个步骤产出独立的交付物。用户可以只要求一个步骤或全部步骤。

## 基本规则：绝不直接修改文档

**禁止**修改源文档。始终：
1. 以 Markdown 编号列表形式呈现拟议修改
2. 建议用户整合修改（Word 批注或镜像文档）

## 步骤 1——语言和结构审读

> 对于纯语言和文体审读（无法律引用核查维度），专门的 `relecture-texte-francais` 技能更专业，可优先使用。本步骤旨在对法律工作成果进行整体审读，其中引用核查（步骤 2）不可分离。

### 分析类别

**1. 拼写和语法**：性数配合、动词变位、同音词、过去分词。

**2. 词汇和法律术语**：
- 不规范用语和用词不当：见 `references/barbarismes-et-improprietes.md`
- 学科性错误（stipuler/disposer、arrêt/jugement 等）：见 `references/erreurs-disciplinaires.md`
- 学术语境中应避免的英语借词

**3. 排版**：
- ；: ? ! 前的不间断空格
- 法语引号 « … »（绝不用 " "）
- 插入语用全角破折号
- 列表和枚举的标点

**4. 学术风格**：
- 非人称或"我们"（除非作者明确说明，绝不用"我"）
- 密集精确的句子、严谨的技术词汇
- 无新闻式、夸张式或口语式表述
- 语域一致性

**5. 结构和论证**：
- 提纲一致性（标题不带变位动词、各部分平衡）
- 推理的循序渐进
- 预期要素的存在（引言、问题意识、提纲预告、过渡、结论）
- 过渡质量

**6. 学术工具**：
- 脚注/尾注的存在和格式
- 引用体系的一致性
- 参考书目的存在

### 步骤 1 交付物

**Markdown 编号列表**，列出所有错误和建议，按类别分类并按文档出现顺序排列。每条包含：
- 定位（页、段或引文）
- 错误性质（类别）
- 拟议修正
- 不明显时的理由说明

随后建议将修正作为 Word 批注整合进文档。

## 步骤 2——引用核查

> **前提**：必须使用 COWORK 或 CHAT_CU。

### 阶段 2.1——穷尽式提取

通读整个文档。提取**所有**法律引用（正文、脚注、参考书目、附件）。在 COWORK / CHAT_CU 模式下，通过 `scripts/extract_references.py --file [document]` 启动提取，该脚本自动检测引用（判例、法典条文、法律/法令、学说）及其位置，然后手动补充模式未捕获的引用。

对每条提取的引用：
- **定位**：第 X 条注释、正文第 Y 页、参考书目
- **提取文本**：精确引文
- **类型**：JURIS_CASS、JURIS_CE、JURIS_CA_TJ、JURIS_TA_CAA、JURIS_CONST、CODE_ARTICLE、LOI_DECRET、DOCTRINE、SOURCE_ETRANGERE、AUTRE
- **规范化引用**：按 `references/format-citations.md` 的规范形式 + 确定性代码（🟢🟡🟠🔴）
- **优先级**：P1（引用 >3 次或在引言/结论中）、P2（引用 1-3 次）、P3（仅在参考书目中）

**去重**：如同一规范化引用出现在多个位置，一次核查即可。

### 阶段 2.2——核查

按优先级顺序（P1 → P2 → P3）核查每条唯一引用。

**按类型路由：**

| 类型 | 主要工具 | 策略 | 备选 |
|---|---|---|---|
| JURIS_CASS | `rechercher_jurisprudence_judiciaire` | 上诉编号、NUM_AFFAIRE、EXACTE | web_search |
| JURIS_CE | `rechercher_jurisprudence_administrative` | 请求编号、NUM_AFFAIRE、EXACTE | web_search |
| JURIS_CA_TJ | `rechercher_jurisprudence_judiciaire` | 筛选法院 + 案号 | web_search |
| JURIS_CONST | `rechercher_decisions_constitutionnelles` | 决定编号 | web_search |
| CODE_ARTICLE | `rechercher_code` | 精确法典 + 条文号，EXACTE | web_search |
| LOI_DECRET | `rechercher_dans_texte_legal` | 文本编号 | web_search |
| DOCTRINE | web_search 然后 HAL | 作者 + 短标题 + 期刊 + 年份 | — |
| SOURCE_ETRANGERE | `LegalDataHunter:resolve_reference` | 国家引用 | web_search |

**状态：**

| 表情符号 | 状态 | 含义 |
|---|---|---|
| ✅ | SOURCE_DIRECTE_CONFORME（直接来源符合） | 经 OpenLegi 或官方站点找到，元数据一致 |
| 🔵 | SOURCE_INDIRECTE_CONFORME（间接来源符合） | 经学说数据库或二手来源找到 |
| ⚠️ | ERREUR_CITATION（引用错误） | 找到但存在显著差异（日期、编号、法院） |
| ❌ | NON_TROUVEE（未找到） | 检索后未定位（≠ 虚假） |

**基本原则**：来源未找到 ≠ 来源虚假。绝不将引用定性为"虚假"——只能说"未找到"或"未核实"。

### 阶段 2.3——镜像文档标注

制作**Word 镜像文档**：源文档的副本，对每条已核查引用在 XML 中插入 Word 批注（`w:comment`）进行标注。

**技术顺序：**
1. 复制源文档，用 `unpack.py` 解压
2. 通过 `comment.py` 创建每条批注
3. 在 `document.xml` 中插入 `w:commentRangeStart` / `w:commentRangeEnd` 标记
4. 核查 `comments.xml` 的 Content_Types
5. 用 `pack.py` 重新压缩

**⚠️ 强制规则——涉及脚注的批注：**
如果批注针对位于脚注（存储在 `footnotes.xml` 中）中的引用或要素，它**必须**锚定在 `document.xml` 中注释引用的位置——即包含相应 `<w:footnoteReference w:id="N"/>` 的 `<w:r>`——而**不是**在 `footnotes.xml` 中。读者在正文中看到注释引用；批注必须附着其上才能可见。批注文本必须提及所涉注释的编号（如"注释第 12 号——"）。

**每条批注的格式：**
```
[表情符号] [状态]
规范化引用：[规范形式]
链接：[URL]
摘录：[相关段落，2-4 句]
```

### 阶段 2.4——汇总表

在镜像文档末尾添加汇总表，含统计信息（已核查总数、按状态和类型分布）。

### 步骤 2 交付物

标注的镜像文档。命名：`[AAAA-MM-JJ]-miroir-verif-[doc名称].docx`。

## 步骤 3——论证一致性与抄袭/AI 痕迹

### 3.1 论证一致性分析

对实质性学术文档（文章、硕士论文、博士论文）：

**核查：**
- 引用的参考文献是否真正支持所提出的论证？
- 引文是否在语境中（未截断、未歪曲）？
- 引用的判例是否仍然有效（未被推翻）？
- 结论是否从前提逻辑推导？
- 反论是否得到处理？

**提示：**
- 被引用但与论证无关的参考文献
- 循环论证或预设结论
- 内部矛盾
- 论证缺口（提出问题但未解决）

### 3.2 抄袭或 AI 生成痕迹检测

**仅启发式方法**——没有任何外部检测工具是可靠的。检测基于痕迹，绝非确定性。

> 详细协议见 `references/methode-detection-plagiat-ia.md`。

**抄袭痕迹：**
- 文体上异质的段落（语域、质量、词汇的突变）
- 文档中途引用格式突然改变
- 对**独特 n 元组**（6-10 个词，用关键词，不带引号或精确运算符——见 `references/methode-detection-plagiat-ia.md`）进行 web_search，然后与找到来源的文本比较
- 写作水平与分析水平之间的不一致

**AI 生成痕迹：**
- 过度文体统一（缺乏自然变化）
- 标点和句法结构过于规整
- 词汇过度修饰、缺乏个人印记
- 看似合理但无法核实的引用（LLM 典型幻觉）
- 缺乏具体机构或个人语境的锚定

**绝对规则：**
- 始终以"痕迹"或"提示性要素"呈现，绝不作确定性结论
- 绝不说文本"由 AI 生成"或"抄袭"——只说痕迹提示如此
- 绝不推荐外部检测工具（没有一个是可靠的）
- 语境化：写得很好本身并不可疑

### 步骤 3 交付物

Markdown 编号观察列表，分类为：
- 论证一致性问题（附定位和说明）
- 可能的抄袭/AI 痕迹（附痕迹等级定性：弱/中/强）
- 建议
