# 参考 —— 边缘情形、失败模式、护栏与自检清单

> 安全层。该 skill 在将输出呈现为“可交付”之前，会先对自己的输出运行 QA 检查清单（§3），并呈现 §4 中的免责声明/律师提示标记。首要指令贯穿一切：**只陈述用户确认的内容；绝不默认加入讨好性或增加风险的条款。**

---

## 1. 边缘情形与正确处理

1. **“我们不收集个人数据”的网站——仍需政策。** 被动型网站仍会记录 IP（依 GDPR 属个人数据）并运行分析，且 Google Analytics 的条款*要求*提供政策。→ 生成一份简短但真实、描述被动收集（服务器日志、分析、必要 Cookie）的政策；只要存在任何分析/托管，就绝不输出“我们不收集任何数据”。
2. **独立创始人 / 发布前 MVP / 未注册公司。** 该个人即为控制者。→ 写明个人姓名 + 联系方式；不暗示公司存在；提示日后注册公司将需要更新控制者条款。
3. **多实体 / 控股公司。** → 询问哪个实体决定目的/手段；将**该**实体列明为控制者；仅在实际有数据流向关联公司时才将其列为接收方（不要松散地扩展“公司家族”——那是 OkCupid 的陷阱）。
4. **B2B 与 B2C。** B2B 仍处理个人数据（客户公司的联系人）。→ 不要跳过政策；范围限定于商务联系人数据；B2C 增加消费者权利重点和更多州法覆盖。
5. **国际销售 / 用户位置未知。** → 适用**最严格共同标准**（GDPR + CCPA + COPPA）；呈现所有主要法域板块。
6. **儿童与混合年龄。** 13 岁以下 → 完整 COPPA + 硬性律师提示标记；青少年/混合 → 年龄声明 + 未成年人保护 + 年龄门槛；非面向儿童 → 标准的否定式“我们不知情地不向 13 岁以下者收集”。
7. **健康 / 生物识别 / 金融 / 精确地理位置。** → 敏感数据条款；GDPR 第 9 条明示同意；CPRA“限制使用敏感个人信息”链接；HIPAA → 单独的通知（NPP）；BIPA 州 → 生物识别同意；始终附硬性律师提示标记；不要引用法定损害赔偿金额。
8. **员工 / HR / 应聘者数据。** → 单独的通知；将其排除在消费者政策之外，并建议单独的员工通知。
9. **用户生成内容与公开资料页。** → 披露 UGC/公开字段对他人可见且可能被索引；用户控制其发布的内容；说明已共享内容的删除限制。
10. **数据经纪商 / 出售 / 广告科技。** → 出售/共享条款 + “不要出售或共享”链接 + 12 个月追溯；经纪商 → 登记标记 + 硬性律师提示标记。提示 Meta/Google 像素通常算作“共享”。
11. **使用用户数据训练 AI。** → 明确的 AI 训练条款 + 目的 + 退出方式；默认不训练，除非经确认；如为是，附硬性律师提示标记（OkCupid/Clarifai 先例；允许训练的政策可摧毁任何保密预期）。
12. **收购 / 业务转移。** → 纳入标准的“如我们合并/被收购，数据可能作为业务资产转移；我们将通知 / 政策继续适用”条款（近乎普遍、低风险）。
13. **第三方链接与嵌入内容。** → “对第三方隐私实践概不负责”条款；注明嵌入内容（YouTube、地图、社交）可能设置自己的 Cookie。
14. **Do Not Track / GPC 信号。** → 披露 DNT 响应（CalOPPA 要求披露，即使“我们不响应”）；说明 GPC 处理——但仅在技术上属实的情况下才声称“我们尊重 GPC”（在加州/科罗拉多/康涅狄格/新泽西具有约束力；虚假断言 = 欺骗）。
15. **免费与付费 / 忠诚度计划。** → 以数据换取折扣的忠诚度计划触发 CCPA 财务激励披露。
16. **非英语 / 阿拉伯语 / 多语言。** → 翻译版本；面向阿拉伯语的 RTL 感知；控制语言条款；提示机器翻译的法律文本需要人工审查（见 `structure-clauses-and-craft.md` §7）。

## 2. 失败模式与 skill 必须执行的护栏

| # | 失败模式 | 护栏 |
|---|--------------|-------|
| F1 | **政策与实际做法不符**（第一大法律风险——FTC §5 欺骗；OkCupid/Match 2026；政策是可执行的承诺）。 | 只陈述用户明确确认的内容。无有利默认。跳过或不确定处 → 可见的 `[GAP — 发布前请确认]` 标记，而非猜测。输出**已确认实践与已生成条款的对账**。 |
| F2 | **过度承诺安全**（陈述被解读为保证）。 | 默认为“合理……措施”+“没有系统是 100% 安全的”；仅在经确认时点名具体控制措施；禁止“军用级/银行级/100% 安全/保证”。 |
| F3 | **错误的样板文本**（引用错误法律/主体/实践的通用模板）。 | 法域优先生成：仅呈现 intake 第 2 组所选法律对应的条款；绝不保留没有确认答案支撑的条款。 |
| F4 | **缺失强制性的法域特定链接。** | 条件检查清单：出售/共享 → “不要出售或共享”链接；敏感个人信息 → “限制使用敏感个人信息”链接；欧盟 → 监管机构引用；营销 → 退订。触发链接缺失则 QA 失败。 |
| F5 | **给人提供法律意见的印象。** | 强制“信息性/模板，非法律意见，不构成律师-客户关系”免责声明。 |
| F6 | **幻觉式法条引用**（零幻觉的关键）。 | 不得编造法律/条文编号、罚款金额或生效日期。允许：以平实语言提及法律名称（“加州 CCPA/CPRA”“欧盟 GDPR”）并从功能上描述权利。精确引用仅在可追溯至参考包或实时 `legal-data-hunter` 查询时才可出现。任何不确定的具体内容 → 省略或标记 UNVERIFIED。优先功能性描述而非引用法条。 |

## 3. 自检清单（在将生成的草稿呈现为可交付之前运行）
1. **完整性** —— 每个触发的条款均存在；无未解决的 `[GAP]` 标记（如有剩余须呈现，不得静默交付）。
2. **内部一致性** —— 数据收集表、目的、接收方、保留、权利不得相互矛盾（如顶部“我们不出售”+ 下方“不要出售”板块 = 失败）。
3. **强制链接存在** —— 不要出售或共享（如出售/共享）、限制使用敏感个人信息（如含敏感个人信息）、监管机构引用（如适用 GDPR）、退订（如营销）。
4. **与陈述的实践相符** —— 每个条款都追溯到一个确认的答案；无无支撑答案的条款；输出对账。
5. **法域覆盖** —— 恰好涵盖第 2 组所选法律；无缺失、无多余。
6. **控制者/联系方式已识别** —— 具名实体/个人 + 有效的联系方式。
7. **可读性** —— 达到平实语言门槛（约八年级水平，除非要求专家/正式）；无未定义术语。
8. **版本/日期存在** —— 生效/最后更新日期 + “本政策变更”条款（不能仅有“定期检查”）。
9. **无被禁的模糊限定词 / 过度承诺** —— 扫描并拒绝“军用级 / 100% 安全 / 完全合规 / 保证”以及含糊限定词（may/might/such as/from time to time——当其掩盖事实时）。
10. **无法条引用来源** —— 扫描法条编号、罚款金额、生效日期；每个都必须可追溯至参考包/实时查询，否则删除或泛化。**零编造引用。**（如可用，`cite-guard` 在此运行。）
11. **免责声明存在** —— “非法律意见”+ 律师审查横幅（强度匹配）。
12. **敏感触发审计** —— 如选择了任何硬性标记类别（儿童/健康/生物识别/AI 训练/数据经纪商/金融科技），则“坚持咨询律师”横幅存在。

## 4. 免责声明与何时**坚持**咨询律师
- **始终在输出中包含**：“这是信息性模板，非法律意见；使用它不构成律师-客户关系；发布前请由合格律师审查。”
- **在 skill 的对话中**（不仅在文档中）：预先说明输出是起始草稿。
- 当**任何一项**为真时，**坚持咨询律师**（硬性横幅，建议在发布前停止）：
  - 13 岁以下儿童（COPPA）/ 面向未成年人的服务。
  - 健康/受保护健康信息（HIPAA）、生物识别（BIPA 州）、基因数据。
  - 金融服务 / 金融科技 / 超出标准处理商的支付。
  - 出售数据 / 数据经纪商 / 广告科技转售。
  - 使用用户/客户数据训练 AI。
  - 大规模处理或系统性监控（GDPR DPO/DPIA 领域）。
  - 大规模精确地理位置。
  - 同时涉及欧盟/英国 + 美国 + 其他地区的多法域。
- **校准免责声明强度**，以 intake 中风险最高的答案为准（第 0.3 组 + 硬性标记）。

## 5. 输出包（交付多于一段文字）
输出：政策（以所请求的语言，阿拉伯语需 RTL 感知）· 带日期的版本页眉 + 变更条款 · 条件链接检查清单状态 · **实践与条款对账**（最有价值的反欺骗产物）· `[GAP]` 清单 · 风险层级/律师横幅。对于非英语输出，建议人工翻译审查。
