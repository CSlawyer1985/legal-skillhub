# NZISM 分类框架与控制适用性

本参考文件详述新西兰政府信息分类系统（ISCS）以及分类等级如何决定适用哪些 NZISM 控制。在为给定系统提供分类决策、控制范围界定或处理要求咨询时使用。

---

## 新西兰政府信息分类系统（ISCS）

ISCS 提供基于未授权披露可能造成的潜在危害对政府信息进行分类的标准化方式。

### 分类等级

| 等级 | 标记 | 描述 | 未授权披露的潜在危害 |
|-------|--------|-------------|---------------------------------------------|
| **非密（Unclassified）** | U | 非敏感政府信息；适合公开 | 无或可忽略 |
| **内部机密（In-Confidence）** | IC | 业务敏感；限于有知悉需要者 | 可能使机构或个人难堪；违反信任 |
| **敏感（Sensitive）** | SEN | 需要谨慎处理的敏感事项 | 披露可能使新西兰利益难堪或受损 |
| **受限（Restricted）** | R | 正式保密；仅限新西兰政府有限访问 | 可能损害新西兰政府利益或运营 |
| **机密（Confidential）** | C | 显著敏感；严格控制 | 对新西兰国家利益造成重大损害 |
| **秘密（Secret）** | S | 高度敏感；极严格控制 | 对新西兰国家利益或国际关系造成严重损害 |
| **绝密（Top Secret）** | TS | 最敏感分类 | 对新西兰国家利益造成极其严重的损害 |

> **注：**"敏感"有时被用作处理警示语而非仅作分类等级。机构应参考现行 GCSB/NCSC NZ 指南以了解各标记的精确现行用法。

---

## 按分类的控制适用性

NZISM 中的控制带有标记，指明其适用于哪些分类等级。较高分类等级的系统继承所有较低等级的控制。

### 基线控制（非密 / 内部机密）

这些控制适用于**所有**新西兰政府系统，无论分类如何：

| 领域 | 关键控制 |
|--------|-------------|
| 治理 | 信息安全政策；CISO 任命；风险管理流程 |
| 物理 | 楼宇门禁控制；访客管理；清桌 |
| 人员 | 背景调查；安全意识培训；可接受使用政策（AUP） |
| 信息 | 基本分类标注；安全电子邮件实践 |
| 基础设施 | 资产清单；补丁管理（严重漏洞 30 天窗口）；加固配置 |
| 网络 | 防火墙；DNS 过滤；电子邮件安全（SPF/DKIM/DMARC） |
| 访问控制 | 唯一账户；最小权限；密码政策 |
| 认证 | 复杂密码；账户锁定 |
| 审计与日志 | 系统和应用日志；90 天保留 |
| 备份 | 定期备份；测试可恢复性 |
| 事件管理 | 事件响应计划；报告程序 |

---

### 受限控制（在基线之上附加）

处理**受限**信息的系统还必须实施：

| 领域 | 附加控制 |
|--------|-------------------|
| 物理 | 服务器设备的专用安全区域；访问日志 |
| 密码学 | 受限数据的静态加密；所有传输中数据使用 TLS 1.2+ |
| 访问控制 | 所有远程访问使用 MFA；特权账户分离 |
| 审计与日志 | 特权操作增强日志；12 个月日志保留 |
| 第三方供应商 | 与 NZISM 相当的合同控制；供应商安全评估 |
| 认证 | 系统上线前要求正式认证与认可（C&A） |
| 云 | 要求云风险评估；数据驻留评估 |
| 移动性 | 强制 MDM 注册；远程擦除能力 |
| 备份 | 带适当分类控制的异地备份 |

**C&A 要求：** 所有处理受限信息的系统必须在上线前由认可机构正式认证和认可。

---

### 机密控制（在受限之上附加）

处理**机密**信息的系统还必须实施：

| 领域 | 附加控制 |
|--------|-------------------|
| 物理 | 带经批准门禁的安保房间；闭路电视；适当时配备保安 |
| 密码学 | 强制静态 AES-256 加密；仅使用 NCSC NZ 批准的密码套件；密钥存储优选 HSM |
| 网络 | 专用网络分段；无经批准网关不得存在面向互联网的系统 |
| 访问控制 | 所有管理员需要背景审查；生物识别或硬件令牌认证 |
| 审计与日志 | 实时安全监控；SIEM；防篡改日志存储 |
| 第三方供应商 | 未经认可机构批准禁止离岸处理 |
| 事件管理 | 任何涉及机密数据的事件立即通知 NCSC NZ |

---

### 秘密和绝密控制

处理**秘密**或**绝密**信息的系统受最严格的控制约束，并要求与 GCSB/NCSC NZ 直接接触以获得认可：

| 领域 | 附加控制 |
|--------|-------------------|
| 物理 | 专门建造的安全设施；需要 TEMPEST 评估和缓解 |
| 密码学 | GCSB 批准的密码设备和密钥管理 |
| 网络 | 气隙或专用加密网络；不得连接至较低分类网络 |
| 人员 | 所有用户和管理员进行秘密或绝密级的全面安全审查 |
| 认可 | GCSB 直接参与认可流程 |
| 供应链 | 系统组件仅使用 GCSB 批准的供应商 |

> 计划建设秘密或绝密系统的机构必须在设计过程早期与 NCSC NZ / GCSB 接触。

## 分类决策指南

在帮助机构确定适当分类时使用本指南：

**提出以下问题：**
1. 系统存储、处理或传输什么信息？
2. 谁需要访问该信息？
3. 未授权披露的潜在危害是什么？
4. 适用哪些法律或监管义务（《2020 年隐私法》、《1982 年官方信息法》）？
5. 系统是否连接或集成到较高分类的系统？

**关键原则：**
- **按系统所持任何信息的最高等级分类**
- **聚合风险**——合并多个非密数据集可能产生受限级信息
- **系统分类**由系统曾经处理的最高敏感数据决定——即使大多数数据等级较低
- **降密**需要正式批准，并证明较高分类数据已被移除

## 按分类的处理要求

### 标注
- 所有文件、电子邮件和文件必须带有分类标记（如 RESTRICTED、IN-CONFIDENCE）
- 电子邮件主题行和页脚必须包含分类
- 为一致性优先采用自动标注工具

### 传输
| 分类 | 可接受的传输方式 |
|---------------|-------------------------------|
| 非密 / IC | 标准电子邮件、公共云存储 |
| 敏感 / 受限 | 加密电子邮件（TLS）；加密文件传输；系统对系统使用 VPN |
| 机密 | NCSC NZ 批准的加密渠道；不使用标准电子邮件 |
| 秘密 / 绝密 | 仅使用 GCSB 批准的密码设备 |

### 存储
| 分类 | 存储要求 |
|---------------|---------------------|
| 非密 / IC | 带访问控制的标准机构系统 |
| 受限 | 静态加密；保密存储区域 |
| 机密 | 静态加密（AES-256）；物理安保的服务器机房 |
| 秘密 / 绝密 | GCSB 认可的存储介质和设施 |

### 处置
| 分类 | 处置方式 |
|---------------|----------------|
| 非密 / IC | 标准电子删除；纸质文件横切碎纸 |
| 受限 | 认证电子数据擦除（NIST 800-88 或同等标准）；横切碎纸 |
| 机密及以上 | 消磁 + 介质物理销毁；需要销毁证书 |
| 秘密 / 绝密 | 依 GCSB 批准的程序销毁；见证并认证 |

## 认证与认可时间表

| 阶段 | 活动 | 典型时长 |
|-------|---------|-----------------|
| 1. 准备 | 制定 SSP、风险登记簿、安全控制文件 | 4–8 周 |
| 2. 认证 | 对照 NZISM 控制的独立安全评估 | 2–4 周 |
| 3. 补救 | 处理调查结果；更新 POA&M | 2–6 周 |
| 4. 认可 | 认可机构审查并签署 ATO | 1–2 周 |
| 5. 监控 | 持续监控；定期重新认证 | 持续进行 |

**重新认证触发因素：**
- 重大系统变更（新集成、托管迁移、重大架构变化）
- 重大安全事件
- 分类等级变更
- 定期重新认证（视风险通常每 1–3 年）
