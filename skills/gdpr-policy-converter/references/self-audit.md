# 第五阶段自检清单（核验后门禁）

产出独立《合规缺口报告》附在成品旁，逐项过以下清单。任何一项不通过，回到对应阶段修正或加蓝字批注。

## 一、完整性（对标 Art. 13/14 + ICO 式必备披露清单）

- [ ] 控制者全称+注册地址；DPO 联系方式（如适用）；无欧盟实体时 Art. 27 欧盟代表信息
- [ ] 每个处理目的 ↔ 数据类别 ↔ 法律依据 ↔ 存储期限 一一对应绑定（WhatsApp 案：笼统表述被处罚）
- [ ] 合法利益目的均附平衡理由（对用户/我方/公众的益处）
- [ ] 接收方类别或实名；集团内共享单列；共同控制者提示（如社媒插件）
- [ ] 间接收集场景：数据类别+来源（是否公开来源）+告知时限；Art. 14.5 免除情形有评估记录提示
- [ ] 跨境章节具体到机制（SCCs 模块/BCR/充分性认定），非笼统"符合欧盟法律"；含收件方/国家表
- [ ] 权利章节全套（访问/更正/删除/限制/可携带/反对/撤回同意）+1 个月时限（复杂情形+2 个月）+监管机构投诉权（写明当地 DPA 名称）
- [ ] 自动化决策/画像：无则明确声明，有则单独成段（存在、逻辑、后果、人工干预渠道）
- [ ] 儿童条款：写明年龄门槛（默认 16，注明以所在国规定为准）
- [ ] 特殊类别数据：仅在真实涉及时启用 Art. 9 条款
- [ ] Cookie 章节四分类+设置面板+与 banner 描述一致（拒绝与同意同等显眼）
- [ ] 泄露通知：72 小时监管通报+高风险时通知数据主体
- [ ] 安全措施的实质性描述（非"我们非常重视您的隐私"空话）

## 二、准确性

- [ ] 与问卷事实一致：无凭空目的、无漏写实际用途、无虚构实体/代表/认证
- [ ] 二手资料中的事实性主张已联网核验（如标杆企业的欧盟代表现状）
- [ ] 所引指南/决定标注版本与日期；动态文件（充分性清单、DPF 名单）运行时核查过

## 三、可理解性（对标 EDPB 透明度指南 + CEF 执法维度）

- [ ] 简洁、平实语言；无法律术语堆砌；关键信息前置（分层摘要 at-a-glance）
- [ ] 逐段英文接中文，术语一致；无 PIPL 残留术语（false-friends.md 逐项过）
- [ ] 面向儿童的信息特别易懂（如涉及）

## 四、可及性

- [ ] 政策在收集点可见（注册/首次使用）、永久可获取、变更时通知
- [ ] 权利行使渠道具体（邮箱+账户内路径）；无障碍获取

## 五、国别兜底条款核查

- [ ] "适用范围"章含中英双语兜底条款：如成员国另有强制性或更严格落地规定，以该国规定为准，并请用户参阅所在国具体规则
- [ ] 存在成员国差异点（Cookie 规则、年龄门槛、行业规则）处已加蓝字批注提示律师核实，未展开国别内容

## 六、行业专项

- [ ] 快消电商：按 retail-template.md 第四节问卷逐项核对场景模块取舍与事实一致
- [ ] AI 平台：按 ai-platform-module.md 第五节 Garante 四焦点逐项核对（欧盟代表、存储流转披露、训练数据合法性、透明度）；训练条款含 opt-out 与来源披露；不以"去标识化"作豁免

## 七、文书形式

- [ ] 蓝字批注仅用于重大风险/需进一步工作（DPIA、TIA、SCCs 签署状态等），以【提示】开头置于对应条款下
- [ ] 文档结尾免责声明："本文档由合规起草辅助工具生成，需律师最终审核后方可对外发布。"
- [ ] 日期戳+版本号；与境内版不构成"同一政策两个版本"的混同表述

## 输出

自检结果生成《合规缺口报告》：每项标注 通过/需修正/需客户补充/需律师判断（附依据引用：条文号+指南名+版本日期）。

**报告范围限定（用户硬性要求）**：报告只体现两类内容——①隐私政策文本本身的合规问题；②由隐私政策延伸、与数据合规直接相关的法律问题分析。与法律观点无关的内容（文书形式核查、问卷核对过程记录、行业报告式描述、排版与呈现说明）不写入报告，仅在对话中按需口头说明。结构建议：一、隐私政策文本本身的合规缺口（Art. 13/14 逐项）；二、延伸数据合规法律问题分析（跨境、DPO、法律依据、营销、儿童、Cookie、自动化决策等）；三、发布前法律待办（P0/P1/P2）。
