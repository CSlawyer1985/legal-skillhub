# 中欧"假朋友"术语对照表（直译陷阱清单）

机械直译会把中国法概念原样搬进英文政策文本，造成法律含义错位或自证违规。起草欧盟版时逐项校验以下清单。

| 中国式写法 | 直译的风险 | 改写方向 |
|---|---|---|
| "个人信息处理者" → "personal information processor" | 与 GDPR "processor"（受托方）混淆；中国法下"处理者"是控制者角色 | 按实际角色译为 controller / processor；多数出海企业对自己的产品用户是 controller |
| "个人信息保护负责人" → "personal information protection officer" | 与 GDPR DPO（Art. 37-39，法定职责与独立性）混淆 | 若未正式任命 DPO，写 privacy contact；若任命 DPO，须满足 GDPR 条件并披露联系方式 |
| "去标识化/脱敏" → "anonymised" | 假名化数据仍是个人数据（EDPB Opinion 28/2024、指南 01/2025、CJEU C-413/23 P）；宣称 anonymised 会被认定虚假告知 | 用 pseudonymised；只有满足匿名化三测试（不可 singled out / 不可关联 / 不可推断）才可用 anonymised |
| "敏感个人信息加粗+单独同意"承诺 | GDPR 特殊类别（Art. 9）体系不同；零售场景常处理出生日期、尺码等非特殊类别数据 | 仅在真实涉及 Art. 9 类别时启用特殊类别条款；普通数据去掉"加粗+单独同意"承诺 |
| "境内存储+出境三条路径" | 方向相反：欧盟视角是数据出境 EEA；CAC 安全评估路径对欧盟用户无意义 | 改写为 SCC+补充措施+收件国表（见 crossborder.md） |
| "撤回同意后我们可能无法响应/无法提供服务" | 捆绑同意，违反自由给出要件（同意指南 05/2020） | 删除；改为撤回不影响撤回前处理的合法性，基础功能与营销分开 |
| "15 个工作日内回复" | 时限口径与 GDPR 不符（Art. 12(3)：1 个月，复杂情形可延长 2 个月并告知） | 1 个月内响应，复杂请求可再延长 2 个月并告知 |
| "请求解释权" | PIPL 特有概念，直译造成困惑 | 删除；并入访问权附简单说明义务 |
| "基础功能/增值功能"二分 | GDPR 无此分类 | 改为逐目的合法性基础标注 |
| SDK 实名清单+设备权限表直译 | 自证一批未经评估的第三方传输与超量收集 | 类别化+点名关键伙伴；权限逻辑改写为逐目的最小化说明 |
| "六类重大变更+PIA 高风险触发" | 中国监管逻辑 | 简化为重大变更通知承诺 |
| "超合理限度请求可收费/拒绝" | 与 GDPR 收费例外范围不符 | 仅在明显无据或过度（重复性）时收费，先告知 |
| "应用安装列表/进程信息用于安全" | 欧盟下默认认为不必要 | 删除；反欺诈改用交易与行为数据的合法利益 |
| "网络实名制依据收集手机号"（AI 平台场景） | 欧盟无此义务，不能作为收集依据 | 手机号改以合同/安全目的论证必要性，或提供邮箱注册替代 |
| "未成年人 14 周岁以下" | GDPR Art. 8 默认 16 岁（成员国可降至 13） | 写明目标市场年龄门槛（默认 16，注明以所在国规定为准） |
