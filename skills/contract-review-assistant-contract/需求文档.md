# 合同检查智能小助手 — 需求文档（Requirements）

> 版本：1.0.1  ｜  适用平台：WorkBuddy / QClaw / ima  ｜  语言：中文合同
> 本文档定义技能的功能范围、验收标准与发布要求，是开发与上架的依据。

## 1. 背景与目标

用户常在签署/谈判前需要快速判断一份合同「有没有坑、能不能签」，但缺乏法律专业背景，逐条审阅成本高。本技能以中国法（《民法典》合同编）为基准，对各类中文合同执行**结构化、可复用的风险审查**，自动输出一份带风险评分与修订建议的 Markdown 报告，作为人工决策辅助。

**目标**：输入一份合同文本（可选签名图片），输出可交付的风险审查报告；不替代律师，只做自动化初筛。

## 2. 适用范围与边界

| 项目 | 说明 |
|---|---|
| 适用合同类型 | 买卖 / 服务 / 合作 / 租赁 / 保密(NDA) / 劳动 / 借款 / 技术IP / 其他 |
| 适用语言 | 中文合同；外文合同需先翻译 |
| 触发意图 | 审查 / 检查 / 合同体检 / 风险报告 / 对比签名笔迹 |
| 不触发 | 纯合同起草（无审查意图）、非合同的一般法律咨询 |

**能力边界**（须在报告中声明）：
- 脚本仅做确定性/结构性检查；法律判断由人工审查层完成。
- 签名笔迹比对为基础筛查，**非司法鉴定**。
- 合规红线以《民法典》等通用规则为参考；金融、医疗、数据等专项监管以最新法规为准。
- 不构成法律意见，重大交易/争议须咨询执业律师。

## 3. 功能需求

### FR-1 完整性检查
- 对照「通用必备要素」（8 项：当事人信息、标的、数量与质量、价款/报酬、履行、违约责任、争议解决/管辖、生效与终止）逐项标注缺失（✅/❌）。
- 检查常见但易忽略条款（保密、知识产权、不可抗力）是否缺失。
- 数据来源：`references/contract-basics.md` 第二节；脚本 `missing_core_sections` / `missing_common_sections`。

### FR-2 风险条款识别
- 逐条比对 14 类高风险条款目录（`references/risk-catalog.md`），命中记录：位置、风险类型、等级（高/中/低）、问题描述、修改建议。
- 重点：单方加重责任、完全免责、管辖不明、任意解除、权属不清、自动续约、签字盖章主体不一致等。

### FR-3 合法合规性审查
- 核查效力红线：格式条款提示义务与无效情形（第496–497条）、违约金 30% 酌减参考线、定金 ≤20%、租赁 ≤20 年、试用期法定上限、无效/可撤销情形。
- 命中红线在报告中单列，等级至少「高」。

### FR-4 歧义与笔误检测
- 脚本自动输出：未填占位符（`XXX`/`____`/`【】`/待填/TBD 等）、条款编号断点、抽取的金额与日期。
- **金额前后矛盾自动比对**：仅当某金额上下文出现总额关键词（总费用/总额/总价/总价款/合同金额/合同总价/本合同总/总报酬/总承包）时视为「合同总额」，抽取中文大写（兼容简体+财务大写壹贰叁）与阿拉伯两种写法并数值比对，不一致直接标记。

### FR-5 签名核对
- 用户提供签名图片（签署件 vs 样本）时，调用多模态能力做笔迹初步筛查，输出相似度（高/中/低）+ 置信度，并声明非司法鉴定。
- 仅文本合同时，提示核验签字盖章主体与授权书一致性。

### FR-6 结构化风险评分报告
- 加载 `assets/report_template.md` 骨架，按 `references/report-format.md` 填充。
- 综合风险评分（高25/中10/低3，完整性缺失每项5，合规红线每项+15，封顶100），映射等级：低0–24 / 中25–49 / 高50–74 / 极高75–100。
- 风险清单按等级降序；给出 P0–P2 修订清单与「是否建议签署」结论。

## 4. 输入输出

**输入**
- 合同文本：`.txt`/`.md` 直接读；`.docx`/`.pdf` 先提取纯文本。
- 可选签名图片（签署件 + 样本）。
- 可选审查立场（甲方/乙方/中立）。

**输出**
- 结构化 Markdown 风险审查报告（评分+等级、降序风险清单、P0–P2 修订、签署结论）。
- 脚本基线事实：缺失条款、占位符、编号断点、金额矛盾、签名行。

## 5. 非功能性需求

- **依赖**：Python 3.8+，仅标准库（`re`/`json`/`sys`/`argparse`），无需 pip 安装。
- **确定性**：`scripts/contract_check.py` 对同一文本输出可复现，作为报告事实基线。
- **可维护性**：法律规则集中在 `references/`，脚本只做事实抽取，二者解耦。
- **本地化**：面向中文合同；金额同时支持中文大写与阿拉伯写法。

## 6. 验收标准（Acceptance Criteria）

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-1 | 运行 `contract_check.py <合同>.txt --json` | 输出合法 JSON，含全部 9 个字段 |
| AC-2 | 合同缺失「争议解决」条款 | `missing_core_sections` 含「争议解决/管辖」 |
| AC-3 | 含「【】」「待填」占位符 | `placeholders` 列出对应行与片段 |
| AC-4 | 条款编号第3条后直接第5条 | `clause_numbering.missing` 含 4 |
| AC-5 | 同文出现「本合同总价款壹拾万整（¥100,000）」与「本合同总价款贰拾万整（¥200,000）」 | `amount_inconsistencies` 检出 1 对矛盾 |
| AC-6 | 含「签字/盖章」字样 | `signature_line_present` = true |
| AC-7 | 通过 `package_skill.py` 校验 | 校验通过并生成 zip |

> 以上用例见仓库 `sample_contract.txt`（含全部 planted 问题，已用 AC-2~AC-6 验证通过）。

## 7. 发布要求（SkillHub）

- 必须文件：`SKILL.md`、`README.md`、`_skillhub_meta.json`、`LICENSE`、`CHANGELOG.md`、图标（`assets/icon.png` 256×256）、预览图（`assets/screenshot-1.png` / `screenshot-2.png`）。
- `_skillhub_meta.json` 字段需完整：id/name/version/description/summary/category/platforms/tags/author/license/homepage/repository/icon/screenshots/triggerKeywords/capabilities。`author`/`homepage`/`repository` 为提交前须由作者替换的占位符。
- 命名：`name` 必须为小写连字符（hyphen-case），本技能 `contract-review-assistant`。
- 提交方式：导入 `contract-review-assistant.zip` 或提交至 SkillHub。

## 8. 已知限制

- 脚本基于关键词与正则，对句式高度改写、表格化、图片内嵌文字的合同检出率下降；此类情形需人工读取或先 OCR/提取文本。
- 多份合同交叉引用、主从合同联动不在自动检查范围。
- 金额总额比对仅针对带总额关键词的金额，分期/单价款项不做矛盾判定。
