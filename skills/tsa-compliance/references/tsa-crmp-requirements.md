# TSA CRMP——详细要求与实施指南

来源：基于公开可得的 TSA 安全指令摘要、联邦公报通知以及 DHS/CISA 出版物。

---

## CRMP 组成部分 1：网络安全实施计划（CIP）/ COIP

### 目的
CIP（在 NPRM 下为 COIP）是证明被覆盖实体如何实施和维持所有必要网络安全措施的总合规文件。必须提交 TSA 审查和批准。

### 必需部分

**第 1 部分：领导与问责**
- 责任主管（Accountable Executive）身份（指定的、对网络安全决策和资源拥有权限的 C 级高管）
- 网络安全协调员（主要）和备用指定人的身份
- 两者的联系信息（包括 24/7 电话号码）
- 协调员与责任主管之间的汇报结构

**第 2 部分：关键网络系统（CCS）清单**
- 被指定为关键网络系统的系统完整清单
- 每个 CCS：系统名称、类型（IT/OT/ICS）、功能、所有者、物理位置、网络分区
- CCS 判定使用的方法
- 架构变更时更新清单的流程

**第 3 部分：网络架构概述**
- 当前网络拓扑图（IT 和 OT——必须准确且最新）
- IT/OT 边界机制描述（防火墙、DMZ、数据二极管）
- 进入 OT 环境的远程访问架构
- 第三方和供应商与 CCS 的连接
- 识别任何分段能力受限的遗留系统

**第 4 部分：网络安全措施（四个技术领域）**

*领域 1——网络分段：*
- 分段政策及其实施方式
- 实施 IT/OT 边界的技术控制描述
- 无法完全分段的系统的补偿控制
- 例外授权的流程

*领域 2——访问控制：*
- CCS 访问的认证要求（远程和特权访问的 MFA）
- 账户生命周期管理（开通、审查、注销）
- 特权访问管理方法
- 第三方/供应商访问控制

*领域 3——持续监控：*
- 监控工具和覆盖范围（IT 和 OT）
- 日志收集和保留政策
- 告警阈值和升级程序
- 与 SOC 或监控团队的集成

*领域 4——补丁管理：*
- 基于风险的补丁优先级排序方法
- 按严重程度的补丁时间表（严重、高、中、低）
- OT 特定补丁流程（供应商批准、测试、维护窗口）
- 未打补丁的遗留 OT 系统的补偿控制

**第 5 部分：事件检测与响应**
- 事件检测方式的高层描述（监控、告警、用户报告）
- 从检测到网络安全协调员的升级路径
- 引用网络安全事件响应计划（独立文件）
- CISA 24 小时报告程序

**第 6 部分：年度审查流程**
- 审查和更新 CIP 的频率和流程
- 周期外审查的触发因素（重大架构变更、重大事件、新威胁情报）
- CIP 更新的批准流程
- 重大变更的 TSA 提交流程

### CIP 批准流程
1. 被覆盖实体通过指定安全渠道向 TSA 提交 CIP
2. TSA 审查完整性和与指令要求的一致性
3. TSA 可批准、要求修改或拒绝
4. 实体实施 CIP；在获得批准前不得声称拥有 TSA 批准的 CIP
5. CIP 的重大变更需要重新提交

## CRMP 组成部分 2：事件响应计划（IRP / CIRP）

### 必需的 IRP 要素

**1. 范围与目标**
- 涵盖哪些系统（所有 CCS）
- IRP 目标：遏制、根除、恢复、报告

**2. 角色与职责**
- 事件指挥官（通常为网络安全协调员）
- IT 响应团队
- OT/ICS 响应团队（可能包括 OT 供应商支持）
- 法律和传播（用于监管报告）
- 高管升级路径

**3. 事件分类**
定义严重程度层级：
| 层级 | 定义 | 响应时间 |
|------|-----------|--------------|
| 严重 | 对 CCS 运营/安全的积极威胁 | 立即——全员 |
| 高 | 确认对 CCS 的未授权访问 | 1 小时内 |
| 中 | 疑似入侵；调查进行中 | 4 小时内 |
| 低 | 入侵指标；无确认访问 | 24 小时内 |

**4. 检测与初步分析**
- 异常如何识别（监控告警、用户报告、第三方通知）
- 初步分流流程：确认 vs 误报
- 从最初时刻起保存证据

**5. 遏制程序**
- IT 遏制：将受影响系统与网络隔离
- OT 遏制：将 OT 与 IT 隔离的程序（事件条件下的 IT/OT 隔离）
- 手动操作回退：如果控制系统被隔离，如何操作 OT 资产
- 在遏制网络威胁的同时保持运营能力

**6. 根除与恢复**
- 威胁清除程序
- 备份恢复：恢复前的完整性验证
- 重连前的系统重建和加固
- 分阶段恢复运营

**7. CISA 和 TSA 通知**
- 24 小时 CISA 报告触发（见 `tsa-incident-reporting.md`）
- TSA 通知程序
- 向责任主管的内部升级
- 监管通知日志（所有已发出通知的记录）

**8. 事件后审查**
- 事件关闭后 30 天内进行事后审查
- 根本原因分析
- 记录经验教训
- 根据调查结果更新 CIP/IRP
- 考虑与 CISA/ISAC 共享

### 年度 IRP 测试

被覆盖实体必须**每年至少测试两项 IRP 目标**。测试可通过以下方式进行：
- **桌面演练**：基于讨论的场景走查（最低可行性测试）
- **功能演练**：与实际系统交互的部分 IRP 激活
- **全面演练**：由 IT/OT 团队完成的完整 IRP 激活

**为 TSA 合规推荐的测试场景**：
1. **IT/OT 隔离演练**：模拟 IT 入侵；测试隔离 OT 并继续手动运营的能力
2. **勒索软件响应演练**：在 IT 上检测到恶意软件；测试遏制、备份完整性检查、恢复程序
3. **对 OT 的未授权访问**：模拟导致 OT 访问的凭据泄露；测试检测和响应
4. **供应商访问滥用**：模拟第三方远程访问滥用；测试检测和撤销

**需要的测试文件**：
- 演练日期和类型
- 场景描述
- 参与者
- 测试的目标
- 每项目标的通过/未通过
- 调查结果和纠正措施
- 纠正措施关闭跟踪

## CRMP 组成部分 3：架构设计审查（ADR）

### ADR 目标
1. 确认网络图是最新、准确且完整的
2. 评估 IT/OT 分段的有效性
3. 识别对 CCS 的未记录或未授权连接
4. 评估远程访问安全性
5. 评估供应商/第三方连接风险
6. 产出调查结果和补救计划

### ADR 流程

**步骤 1：清单和文件审查**
- 收集当前网络拓扑图（IT 和 OT）
- 审查 CCS 清单的完整性
- 将图纸与实际架构比较（被动发现或授权扫描）
- 记录任何差异

**步骤 2：分段评估**
对每个 IT/OT 边界连接：
- 该连接是否已记录并授权？
- 什么安全控制强制边界（防火墙、DMZ、数据二极管）？
- 防火墙规则是否审查并最小化？
- OT 侧是否有默认拒绝规则？
- 是否存在从互联网到 OT 环境的直接连接？

**步骤 3：远程访问审查**
- 清点进入 OT 的所有远程访问路径（VPN、RDP、供应商跳板服务器）
- 确认所有远程 OT 访问均强制 MFA
- 确认所有远程访问均记录和监控
- 确认供应商访问有时限且需要明确批准

**步骤 4：第三方连接**
- 映射所有与 CCS 的第三方连接（供应商远程支持、SCADA 托管、基于云的 OT 监控）
- 评估第三方的合同网络安全义务
- 确认未经实体批准和监控，第三方无法访问 OT

**步骤 5：漏洞与风险识别**
- 识别高风险架构模式：
  - IT 和 OT 共享同一子网的扁平网络
  - 具有直接互联网连接的 OT 设备
  - 无补偿控制的过时 OT 系统
  - IT 和 OT 之间共享的账户
  - OT 网络上的未加密协议（对 HMI 的 Telnet、FTP、HTTP）

**步骤 6：调查结果与补救计划**
对每项调查结果：
| 调查结果 ID | 描述 | 风险等级 | 建议 | 负责人 | 目标日期 |
|-----------|-------------|-----------|----------------|-------|-------------|
| ADR-001 | PLC 子网未与公司局域网分段 | 严重 | 部署防火墙；实施 DMZ | OT 经理 | 第二季度 |

### ADR 输出
- 更新并验证的网络拓扑图
- 调查结果报告（调查结果、风险评级、建议）
- 带负责人和目标日期的补救行动计划
- 责任主管签署

## CRMP 组成部分 4：网络安全评估计划（CAP）

### 目的
CAP 记录实体每年将如何评估其 CRMP 的有效性。它本身不是评估——而是开展评估的计划。结果每年向 TSA 报告。

### 必需的 CAP 要素

**1. 评估范围**
- 每个评估周期内哪些 CCS 和 CRMP 组成部分在范围内
- 任何被排除在范围之外的 CCS 的理由（附补偿覆盖说明）

**2. 评估方法**
定义要执行的评估类型：
| 评估类型 | 描述 | 适用对象 |
|----------------|-------------|---------------|
| 漏洞扫描 | 对 IT/OT 资产进行已知 CVE 的自动化扫描 | IT；有限的 OT（优选被动） |
| 渗透测试 | 测试防御的授权模拟攻击 | IT；安全且经同意的 OT |
| 配置审查 | 将系统配置与加固标准比较 | IT 服务器；网络设备；可能时 OT |
| 流程审查 | 基于访谈的政策和程序审查 | 所有 CRMP 组成部分 |
| 红队演练 | 针对 CCS 的对手模拟 | 大型/复杂环境 |

**OT 评估注意事项**：
- 主动扫描 OT 网络可能干扰工业通信——使用被动监控工具
- OT 中的渗透测试需要供应商协调和运营批准
- 对 OT，优先配置审查和架构审查，而非侵入性测试

**3. 评估时间表**
提供 12 个月的时间表：
| 季度 | 评估活动 | 范围内 CCS |
|---------|-------------------|-------------|
| Q1 | 漏洞扫描（IT）；IRP 桌面演练 | 所有 IT CCS；IRP |
| Q2 | 配置审查（OT）；ADR | OT CCS；架构 |
| Q3 | 渗透测试（IT 外部 + 内部） | IT CCS |
| Q4 | 流程审查（所有 CRMP 组成部分）；CAP 结果汇编 | 所有 |

**4. 责任方**
- 内部评估团队或第三方评估机构
- OT 评估需要具备 OT 资质的人员（GICSP、GCIA 或同等资质）
- 独立性要求：评估者不应评估自己的实施

**5. 向 TSA 的年度报告**
- 汇编评估调查结果和补救状态
- 每年通过指定安全渠道向 TSA 提交结果
- 包括：调查结果摘要、风险评级、补救计划、未决事项、纠正措施进展

## 四个技术领域——详细实施指南

### 领域 1：网络分段——实施细节

**最低可接受架构：**
```
[互联网] → [边缘防火墙] → [公司 IT 网络]
                                      ↓
                              [IT/OT 防火墙 / DMZ]
                                      ↓
                              [OT 网络 / ICS 网络]
                                      ↓
                              [现场设备：PLC、RTU、HMI]
```

**每个边界的安全控制：**
- **边缘到 IT**：状态防火墙；面向互联网服务的 DMZ；IDS/IPS
- **IT 到 OT**：专用防火墙或数据二极管；默认拒绝；仅白名单所需协议/端口；无直接路由
- **OT 到现场**：为不同工艺区域分段 VLAN；限制 VLAN 间流量

**数据二极管/单向网关**：最高安全 OT 环境的首选。数据单向流动（OT → IT 用于监控/历史记录）——不可能有返回路径。供应商：Waterfall Security、Owl Cyber Defense、Bayshore Networks。

**扁平网络的补偿控制**（完整分段无法立即实现时）：
- 所有 IT 系统上的主机防火墙，阻止 OT 流量
- 在扁平网络层面增强监控和告警
- 带补救时间表的书面例外
- 在 OT 设备层面的增强访问控制

### 领域 2：访问控制——OT 特定指南

**OT 账户管理挑战**：
- 许多 OT 系统的账户管理能力有限（单一共享管理员账户）
- 遗留 HMI 可能不原生支持 MFA
- 供应商账户通常为维护所需，但可能常开

**OT 访问控制局限的解决方案**：
| 挑战 | 解决方案 |
|-----------|---------|
| 遗留 HMI，无 MFA | 在 HMI 前部署带 MFA 的跳板服务器/堡垒主机；仅通过跳板服务器访问 HMI |
| 共享 OT 管理员账户 | 通过 PAM 工具记录所有访问；共享账户使用需经批准的借出 |
| 供应商远程访问 | 使用带 MFA 的供应商专用 VPN；限时会话；所有会话记录；任务结束后撤销 |
| OT 不支持 LDAP/AD | 在 OT 设备上维护强密码的本地账户；每季度轮换 |

**OT 的特权访问管理（PAM）**：
- 特权 OT 凭据的借出工作流
- 所有特权 OT 访问的会话录制
- 供应商会话自动过期
- 非工作时间特权访问告警

### 领域 3：持续监控——OT 特定工具

**推荐的 OT 监控方法：**
| 方法 | 工具 | 备注 |
|---------|-------|-------|
| 被动网络监控 | Claroty、Dragos Platform、Nozomi Networks Guardian、Armis | 无流量注入；监听学习 |
| 资产发现 | 通过监控工具被动发现 | 自动构建 CCS 清单 |
| 异常检测 | Dragos、Claroty、Nozomi | 对偏离 OT 通信基线的告警 |
| 日志收集 | 支持 OT 的设备的 Syslog；带 OT 解析器的 SIEM | 并非所有 PLC 都支持 syslog |
| 威胁情报 | Dragos WorldView、Claroty Team82、CISA ICS-CERT 公告 | OT 特定威胁情报 |

**OT 环境中应监控的内容：**
- OT 网络上出现的新设备（未授权资产）
- 新的通信路径（协议、端点对）
- 维护窗口之外工程工作站与 PLC 的连接
- 对 OT 的远程访问会话
- 命令注入尝试（Modbus、DNP3、EtherNet/IP 异常命令）
- OT 设备上的认证失败

### 领域 4：补丁管理——OT 特定指南

**OT 补丁生命周期：**
1. **供应商通知**：接收 OT 供应商的补丁/公告
2. **风险评估**：评估 CVE 严重性与打补丁的运营影响
3. **供应商确认**：确认补丁受您的固件版本支持
4. **测试环境**：在生产前于实验室/测试环境测试补丁
5. **变更批准**：变更管理工单；停机窗口的运营批准
6. **部署**：在计划维护窗口内应用
7. **验证**：打补丁后确认系统运行
8. **文件**：记录应用的补丁、日期、版本

**未打补丁的遗留 OT 系统（补偿控制）**：
| 补偿控制 | 描述 |
|--------------------|-------------|
| 网络隔离 | 将遗留系统进一步隔离到自己的 VLAN；限制为最低必要通信 |
| 增强监控 | 提高对遗留系统的监控灵敏度 |
| 应用程序白名单 | 如操作系统支持，仅白名单授权可执行文件 |
| 移出互联网路径 | 确保到遗留设备无互联网连接路径 |
| 文件 | 在 CIP 中记录遗留系统、其风险和补偿控制 |

**补丁优先级排序（基于风险）：**
| CVSS 评分 | 严重程度 | 目标补丁时间表 |
|-----------|---------|----------------------|
| 9.0–10.0 | 严重 | 30 天（或在 7 天内采取补偿控制） |
| 7.0–8.9 | 高 | 60 天 |
| 4.0–6.9 | 中 | 90 天 |
| 0.1–3.9 | 低 | 180 天或下次计划维护 |
