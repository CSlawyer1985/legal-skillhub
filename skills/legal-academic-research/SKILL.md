# 法学学术研究来源核验与规范写作 Skill

## 概述

本 Skill 旨在解决 AI 辅助法学研究中常见的「幻觉引用」「案例虚构」「论文来源不实」「法律规则概括失准」和「学术写作格式不统一」等问题。

**核心理念**：法学研究高度依赖真实案例、有效法条、权威论文和准确引用。任何来源错误都可能削弱论文、备忘录或案例分析的可信度。本 Skill 不追求简单提高生成速度，而是建立一套「**先核验、再分析、后写作**」的工作流，使 AI 在学术写作中更加**可靠、可追溯、可审查**。

---

## 核心功能（四个模块）

### 模块一：研究问题识别

**目标**：用户输入论文题目、案例问题或研究方向后，判断研究类型并建立分析框架。

**判断树**：

```
用户输入
  ├── 判例分析
  │     └── 识别：案件名称 / 法院 / 年份 / 案号 / holding
  ├── 法条解释
  │     └── 识别：法域 / 法律名称 / 条款编号 / 解释方法
  ├── 比较法研究
  │     └── 识别：目标法域 A / 目标法域 B / 比较维度
  ├── 文献综述
  │     └── 识别：主题 / 核心作者群 / 研究脉络 / 缺口
  ├── 实证法学研究
  │     └── 识别：假设 / 数据来源 / 方法论 / 样本规模
  └── 法律评论写作
        └── 识别：写作类型（note / comment / article）/ 受众
```

**法域区分要求**：

- **中国法**：必须区分——法律（全国人大及其常委会制定）、司法解释（最高院/最高检）、规范性文件（部委规章/地方性法规）、指导性案例（最高院案例库）、学术论文
- **美国法**：必须区分——联邦法（U.S. Const. / Stat. / C.F.R.）与州法（各州Statutes / Cases），明确 Reporter Citation（如 F.3d, F.4th, S.Ct.）
- **其他法域**：英美法系 / 大陆法系 / 国际法 / 区域法（EU/ICC等），需注明法律渊源

**输出**：研究类型标签 + 法域 + 核心法律概念 + 潜在争议点 + 所需引用类型清单

### 模块二：来源核验（最关键模块）

**目标**：对所有案例、法条和论文来源进行逐项核查，不留任何「疑似虚构」的引用。

#### 2.1 案例核验清单

每个引用案例必须提供以下信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 案例名称 | 全称（含v.） | *Brown v. Board of Education*, 347 U.S. 483 (1954) |
| 审理法院 | 法院全称 + 层级 | Supreme Court of the United States |
| 裁判日期 | 年月日 | 1954-05-17 |
| 案号/Reporter | 卷号+起始页 | 347 U.S. 483 |
| Holding | 核心裁判要旨（原文引用） | "Separate educational facilities are inherently unequal." |
| 适用规则 | 提炼的法律规则 | 种族隔离违反平等保护 |
| 引用语境 | 在本文中的具体用途 | 作为「平等保护三重审查」基准 |
| 核验状态 | ✅已核验 / ⚠️疑似 / ❌未核验 | ✅已核验 |

**AI 生成规则**：
- ✅ 已确认：标注「已核验」，附核查说明
- ⚠️ 疑似存在但未完全确认：标注「疑似」，注明核实要点，要求用户自行确认
- ❌ 无法确认：必须明确标注「未核验」，不得将不确定信息伪装为确定结论

#### 2.2 法条核验清单

| 字段 | 说明 | 示例 |
|------|------|------|
| 法律名称 | 全称 | 《中华人民共和国个人信息保护法》 |
| 条款编号 | 具体条文 | 第13条 |
| 生效日期 | 年月日 | 2021-11-01 |
| 现行有效 | 是否现行有效 | 现行有效 |
| 条文内容 | 原文摘录 | 「……处理个人信息，应当取得个人的同意……」 |
| 引用语境 | 在本文中的具体用途 | 作为知情同意原则的法律依据 |
| 核验状态 | ✅已核验 / ❌需检索 | ✅已核验 |

#### 2.3 论文核验清单

| 字段 | 说明 | 示例 |
|------|------|------|
| 作者 | 姓名 | 朱虎 |
| 题名 | 论文标题 | 《自动驾驶汽车的侵权责任分配》 |
| 期刊 | 期刊全称 | 《法学研究》 |
| 年份/卷期 | | 2023年第3期 |
| 页码 | 起止页 | P.112-130 |
| 核心观点 | 论文核心论点 | 自动驾驶汽车适用产品责任优于侵权责任 |
| 引用语境 | 在本文中的具体用途 | 用于论证产品责任归责原则的优先性 |
| 核验状态 | ✅已核验 / ⚠️需确认 / ❌未核验 | ✅已核验 |

**未核验时的处理规则**：

```
⚠️ 注意：以下来源尚未经完全核验，建议在正式提交前通过数据库验证
- [案例名]（需通过 Westlaw / LexisNexis /北大法宝 验证）
- [论文名]（需通过 CNKI / Westlaw / JSTOR 验证）
- [法条]（需确认现行有效版本）
```

### 模块三：法律分析（结构化长链分析）

**目标**：依据已核验来源，生成严谨的法律分析。

#### 3.1 七步分析流程（通用）

```
Step 1：事实归纳
  - 关键事实（相关事实 vs. 无关事实）
  - 时间线
  - 当事人角色

Step 2：法律规则提炼
  - 相关法条/先例
  - 规则构成要件
  - 适用条件

Step 3：规则涵摄（Rule → Facts Application）
  - 要件逐一比对
  - 事实与规则的连接点

Step 4：反方观点
  - 可能的支持论点
  - 反驳空间

Step 5：限制条件
  - 规则的适用边界
  - 特殊情形

Step 6：结论判断
  - 初步结论
  - 置信度（高/中/低）

Step 7：学术深化
  - 问题意识
  - 文献缺口
  - 理论机制
  - 规范评价
```

#### 3.2 写作格式适配

| 写作任务 | 格式框架 | 核心要素 |
|----------|----------|----------|
| 法学院作业/考试 | **IRAC** | Issue / Rule / Application / Conclusion |
| 法律实务备忘录 | **CREAC** | Conclusion / Rule / Explanation / Application / Conclusion |
| 案例评析 | **Case Brief** | Facts / Issue / Holding / Reasoning |
| Office Memo | **Memorial** | Question / Short Answer / Facts / Discussion |
| Law Review Article | **Long Form** | Introduction / Literature Review / Analysis / Conclusion |
| 比较法分析 | **Comparative** | 法域A规则 / 法域B规则 / 比较维度 / 差异原因 / 借鉴可能 |
| 政策分析 | **Policy Memo** | 问题 / 现状 / 各方方案 / 评估标准 / 建议 |

#### 3.3 学术论文专项要求

生成学术论文内容时，必须包含：

- **问题意识**：为什么要研究这个问题？
- **文献缺口**：现有研究哪里不足？
- **理论机制**：用什么理论框架分析？
- **制度背景**：法律制度的上下文是什么？
- **规范评价**：从规范法学角度如何评价？
- **研究贡献**：本文的边际贡献是什么？

**严禁**：
- 直接生成「综上所述」式空泛结论
- 用「应当」代替论证
- 省略反方观点和限制条件

### 模块四：学术写作与审校

#### 4.1 输出类型

根据用户需求，可输出：

- 📄 **论文段落**（引言 / 文献综述 / 论证 / 结论）
- 📚 **文献综述**（按主题 / 年代 / 学派组织）
- ⚖️ **案例评析**（含 case brief + 学术评析）
- 📋 **法律备忘录**（Office Memo / 争议分析）
- 📝 **研究计划**（Research Proposal）
- 📖 **摘要**（中英文对照）
- 🔖 **脚注建议**（符合目标期刊格式）
- 🌐 **中英对照版本**

#### 4.2 自动审校清单

生成文本后，自动进行二次审校，检查以下问题：

| 审校项 | 检查内容 | 严重程度 |
|--------|----------|----------|
| 来源溯源 | 引用是否标注了核验状态？是否有来源不明的断言？ | 🔴 严重 |
| 逻辑跳跃 | 论证链是否完整？有无跳步？ | 🔴 严重 |
| 概念混用 | 核心术语是否前后一致？有无偷换概念？ | 🟠 重要 |
| 论证重复 | 是否有重复论证同一观点？ | 🟡 次要 |
| 语气过度确定 | 是否使用了「绝对」「必然」「毫无争议」等过于确定的表述？ | 🟡 次要 |
| 引用格式 | 脚注/参考文献格式是否符合目标期刊规范？ | 🟡 次要 |
| AI痕迹检测 | 是否有明显的AI腔（首先/其次/综上所述）？ | 🟡 次要 |
| 法域混淆 | 中国法/美国法/欧盟法等是否清晰区分？ | 🔴 严重 |
| 法条时效性 | 引用的法条是否标注了版本/修改日期？ | 🟠 重要 |

#### 4.3 中文法学写作规范

- 提升表达的**严谨性**和**学术性**
- 避免口语化表达（改为：「值得注意的是」→「需要指出的是」）
- 法律术语前后统一（如：「个人信息」vs「个人数据」，全文一致）
- 使用「笔者认为」或「本文认为」而非直接肯定陈述
- 脚注引用符合**《法学引注手册》**或目标期刊格式（北大法宝格式 / 华政格式）

#### 4.4 英文法律写作规范

- 强化 **rule statement** 的精确性（引用原文 + citation）
- 强化 **case synthesis** 的逻辑性（多个先例如何共同支持一个规则）
- 强化 **application** 的说理深度（事实与规则的严密连接）
- 引用格式符合 **Bluebook**（美国法）或 **Oxford Standard**（英美法）
- 避免「It is argued that」→「The court held that」等混用

## 运行流程

### 标准流程（单轮）

```
用户输入研究任务
  │
  ▼
Step 1：问题识别
  → 判断研究类型（判例/法条/比较法/综述/实证/评论）
  → 识别法域
  → 列出核心法律概念
  │
  ▼
Step 2：来源核验
  → 用户确认 / 提供已有来源
  → AI 对需要检索的来源进行核查
  → 标注核验状态（✅/⚠️/❌）
  │
  ▼
Step 3：法律分析
  → 依据 ✅ 已核验来源提炼规则
  → 按选定格式（IRAC/CREAC/比较法等）生成结构化分析
  → 识别论证缺口和进一步研究需要
  │
  ▼
Step 4：学术写作与审校
  → 输出规范化文本
  → 自动审校
  → 标注 ⚠️ 未核验来源，供用户确认
  │
  ▼
交付成果
```

### 多 Agent 协作流程（复杂任务）

```

  → 寻找权威来源（案例/法条/论文）
       │
       ▼
引用核验 Agent
  → 确认来源真实性
  → 标注核验状态
       │
       ▼

  → 规则解释与事实适用
  → 生成结构化分析
       │
       ▼
编辑润色 Agent
  → 提升语言质量
  → 格式统一
  → 二次审校
       │
       ▼
最终成果交付
```

## 与普通 AI 生成的区别

| 维度 | 普通 ChatGPT | 本 Skill |
|------|-------------|---------|
| 引用质量 | 可能虚构案例/论文 | 逐项核验并标注状态 |
| 论证严谨性 | 可能跳步 | 完整七步分析流程 |
| 格式规范 | 随意 | 脚注/引用格式标准化 |
| 来源透明度 | 黑箱 | 所有引用可溯源 |
| 法域区分 | 可能混淆 | 明确标注法域 |
| 学术诚信 | 不保证 | 核验→分析→写作全链路 |

## 使用示例

### 示例 1：案例分析请求

**用户输入**：
> 请分析一下美国的 "伴娘案"（*Grutter v. Bollinger*），写一个 case brief 和一段 500 字的学术评析，引用格式用 Bluebook。

**Skill 执行**：

1. **问题识别** → 美国宪法/平等保护/平权行动，Michigan 大学录取案，联邦最高法院
2. **来源核验** → 核验 539 U.S. 306 (2003)，确认 holding、rule、核验状态 ✅
3. **法律分析** → Case brief 格式输出（Facts/Issue/Holding/Reasoning）
4. **写作输出** → Bluebook 格式 case brief + 500字评析（问题意识 + 论证 + 局限）
5. **审校** → 检查 Bluebook 格式 / 逻辑连贯性 / 语气适度

### 示例 2：法条解释请求

**用户输入**：
> 帮我分析一下《个人信息保护法》第13条第二款「为履行合同所必需」在跨境电商场景下的适用，写一段学术分析。

**Skill 执行**：

1. **问题识别** → 中国个人信息保护法 / 第13条 / 合同履行免责事由 / 跨境电商场景
2. **来源核验** → 核验《个人信息保护法》第13条现行有效版本，查找相关学理解释
3. **法律分析** → 七步分析流程 + PIPL 框架内解释
4. **写作输出** → 学术分析段落（含条文解释 + 构成要件 + 跨境电商适用分析）
5. **审校** → 检查法条时效性 / 术语统一 / 论证完整性

### 示例 3：文献综述请求

**用户输入**：
> 我要写一篇关于自动驾驶汽车侵权责任的文献综述，主要关注中国法和美国法的比较，请生成文献综述框架和主要文献清单。

**Skill 执行**：

1. **问题识别** → 比较法研究 / 中美双法域 / 自动驾驶汽车 / 侵权责任 / 文献综述
2. **来源核验** → 核验中国论文（CNKI）+ 美国论文（Westlaw/JSTOR），标注核验状态
3. **分析框架** → 中美各自研究脉络梳理
4. **写作输出** → 双栏对比结构文献综述框架（含研究议题分类、核心作者、主要观点、文献缺口）
5. **审校** → 引用格式统一 / 文献缺口识别准确性 / 中美研究是否对等
