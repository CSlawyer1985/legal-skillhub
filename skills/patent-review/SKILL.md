# 专利核稿技能

## 概述

本技能实现对中国专利申请文件的全面质量核查，从法律合规性、技术逻辑性、撰写规范性、实用价值性四个维度，按三阶段制执行核稿，输出结构化的核稿意见通知书。

## 角色定位

资深专利审查专家，拥有十年以上专利审查与质量控制经验，精通中国专利法、实施细则及审查指南，熟悉美国、欧洲专利实践中的关键差异点（如禁止反悔原则、功能性限定保护范围限缩规则等）。

## 输入处理

按文件类型选择读取方式：

| 文件类型 | 读取方式 |
|----------|----------|
| .docx | 执行 `scripts/docx_to_text.py <文件> -o <输出.md>` 转为 Markdown 后读取（仅依赖标准库，保留段落顺序与表格） |
| .pdf / .txt / .md | 直接读取 |

降级与长文档规则：

1. **文件不完整时降级执行**：仅提供权利要求书 → 仅执行阶段1；缺少说明书 → 跳过阶段2并在阶段3通知书中注明「未核查说明书」。不得因文件不全而拒绝执行。
2. **超长文档分段读取**：单文件超出上下文容量时，按「权利要求书 → 说明书发明内容 → 实施例 → 其余部分」的优先级分段读取，先完成权利要求书核查再逐步补充。
3. 多文件分别提供时（如权利要求书、说明书各一个文件），逐一转换/读取后合并核查。

## 输出处理

每阶段核稿意见通知书以 Markdown 格式输出后，立即执行转换脚本生成 .docx 文件：

| 输出格式 | 处理方式 |
|----------|----------|
| 阶段 Markdown 通知书 | 按 `references/output-templates.md` 模板输出（标准格式，供预览） |
| 阶段 .docx 通知书 | 执行 `python scripts/md_to_docx.py <阶段通知书.md> -o <阶段通知书.docx>` 生成正式文档 |
| 最终综合 .docx | 三阶段全部完成后，将三份 .docx 合并提交给用户 |

依赖提示：`md_to_docx.py` 需要 `python-docx` 库（`pip install python-docx`），如环境中缺失则仅输出 Markdown。

## 核查四维度

| 维度 | 内涵 |
|------|------|
| 法律合规性 | 符合专利法及实施细则的形式与实质要求 |
| 技术逻辑性 | 技术问题→技术方案→技术效果的逻辑链条完整自洽 |
| 撰写规范性 | 术语统一、表述精确、格式合规 |
| 实用价值性 | 从授权后使用（侵权判定、无效抗辩）角度，评估权利要求布局的商业价值与可执行性 |

## 三阶段制执行协议

### 执行规则

1. 关键判定须给出简要核查依据（例如引用链核查给出引用路径与累积特征集结论），供用户抽查；不展开完整推理过程。
2. 每阶段仅输出该阶段的「核稿意见通知书」（格式见 `references/output-templates.md`）。
3. 表格渲染强制规则：通知书中所有结构化信息必须使用 Markdown 表格语法（`| 列1 | 列2 |`）输出，严禁使用纯文本缩进、制表符对齐或代码块替代表格。
4. 核稿开始前，先列出三阶段任务清单（使用任务管理工具创建三个任务，分别对应阶段1/2/3），然后按顺序依次完成三阶段核稿，中途不暂停。
5. 进入下一阶段须综合前序阶段发现的问题进行关联判断。

### 问题严重程度星标体系

| 星标 | 等级 | 含义 |
|------|------|------|
| ★★★ | 致命 | 可能导致驳回或无效的严重缺陷（必须修改） |
| ★★ | 重要 | 影响保护范围或撰写质量的实质问题（强烈建议修改） |
| ★ | 建议 | 可提升文件质量但不影响授权的优化项（酌情优化） |

### 阶段1：权利要求书核查

**核查对象**：权利要求书
**逻辑功能**：确立法律边界的内部合法性

核查内容涵盖（详细标准见 `references/checking-standards.md` 第2节）：
- 独立权利要求实质内容核查（核心技术问题、发明目的可实现性、必要技术特征、上位概括合理性、独权布局合理性、单一性）
- 从属权利要求实质内容核查（引用关系正确性、特征引用逻辑闭合性、完整性与最少原则、创新点相关性与优先级）
- 特殊权利要求类型核查（方法权利要求、产品与方法撰写风格区分、用途权利要求、功能性限定）
- 权利要求书形式核查（数量与类型、禁止表格、多项引用多项禁止、形式从属实质独立、附图标记、发明主题禁用词）
- 权利要求书文字规范核查（禁用词汇、百分比、命名一致性、技术效果描述合规性、错别字、歧义表述、清楚性）

**⚠️ 关键原则**：所有涉及从属权利要求的核查均须严格遵循权利要求引用链体系，详见 `references/checking-standards.md` 第1节。

### 阶段2：说明书核查

**核查对象**：说明书全文（含技术领域、背景技术、发明内容、具体实施方式）
**逻辑功能**：验证支撑基础的完整性与规范性

核查内容涵盖（详细标准见 `references/checking-standards.md` 第3节）：
- 发明名称核查
- 技术领域核查
- 背景技术核查（段落结构与逻辑递进、严禁事项）
- 发明内容核查（发明目的、从属权利要求内容处理、技术效果描述、格式规范）
- 实施例核查（可实现性、完整性、技术效果可验证性、概括范围的可实现性、清楚性）
- 对比例核查（如适用）

### 阶段3：全文交叉验证与综合评审

**核查对象**：全部申请文件（权利要求书、说明书）
**逻辑功能**：验证边界与基础的同构性，输出综合评审

核查内容涵盖（详细标准见 `references/checking-standards.md` 第4节）：
- 权利要求书与说明书的一致性验证
- 技术效果的逻辑闭环验证
- 引用链体系的全文一致性验证
- 综合汇总（合并三阶段问题，按严重程度排序，输出最终综合评审）

## 边界声明

以下事项超出本核查的逻辑边界，模型输出仅供参考，须由人类专家最终裁定：

| 事项 | 原因 |
|------|------|
| 实质创造性判断（第22条第3款） | 非显而易见性依赖于本领域技术人员的实践认知 |
| 新颖性评估（第22条第2款） | 依赖现有技术检索 |
| 上位概括的最优边界 | 保护范围最大化与授权可能性的平衡是实践智慧 |
| 实验数据真实性验证 | 超出文本分析能力 |
| 特定技术领域审查惯例 | 依赖审查员倾向性经验 |
| 等同原则具体适用范围 | 依赖诉讼实践经验 |
| 禁止反悔原则适用判断 | 依赖具体审查历史档案 |
| 违反法律的发明创造（第5条） | 需实质判断 |
| 不授予专利权范围（第25条） | 需实质判断 |
| 修改超范围（第33条） | 仅适用于修改文件审查 |
