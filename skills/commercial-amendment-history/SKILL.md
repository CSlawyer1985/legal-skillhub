# /amendment-history

加载基础协议及所有修订，然后总结历次变更内容或追踪特定条款的当前有效语言。

## 指令

1. **获取文件：** 从文件上传、合同管理系统ID（即将上线）或存储库链接（即将上线）获取。接受一次调用中的多个文件。如未提供，询问。

2. **检测模式：** 通过解析请求判断运行模式。明确指出条款名称→模式2。未提及条款→模式1。仅在真的存在歧义时才询问。

3. **运行以下工作流。** 完全执行。

4. **输出后提供后续操作：**
   - "是否需要追踪其他条款？"
   - "是否需要对修正后的现行协议进行完整审查指引审查？（路由至供应商协议审查）"
   - "是否需要关键变更的利益方摘要？（路由至利益方摘要）"

## 示例

```
commercial-amendment-history acme-msa.pdf amendment-1.pdf amendment-2.pdf
```

```
commercial-amendment-history --provision 赔偿
```

```
commercial-amendment-history
[粘贴协议和修订文本]
```

## 目的

合同不断积累修订。到第三份修订时，没有人记得原版写了什么或哪个条款版本现行有效。本技能按时间顺序阅读基础协议及所有修订，总结整个合同的变更或追踪特定条款的当前有效语言。

## 模式检测

解析用户请求以确定运行哪种模式。除非请求真的存在歧义，否则不要询问模式。

**模式1 — 摘要**（未提及具体条款）
触发语："改了什么""修订历史""显示历次变更""摘要修订内容""合同现在是什么样子"

**模式2 — 条款追踪**（指明具体条款或主题）
触发语："[条款]在哪里""最新的[条款]""[条款]如何变化的""找一下赔偿条款""[主题]现在说什么"

常见条款映射：
- "赔偿""赔偿责任" → 赔偿章节
- "责任""责任上限" → 责任限制
- "终止""解除" → 期限和终止
- "数据""隐私""数据处理协议" → 数据保护条款
- "知识产权""IP" → 知识产权所有权和许可
- "价格""费用""支付" → 支付条款
- "自动续约""续约" → 续约机制

如果条款名称模糊且对应多个条款，列出候选项并询问：
> "我发现[N]个与[条款]相关的条款——[列表]。您要追踪哪个？"

如果整体请求在两种模式之间存在歧义，问一个问题：
> "是对整份合同所有变更的摘要，还是追踪特定条款——例如赔偿、责任或终止？"

## 步骤1：加载并排列文件

从以下来源接受文件：

**合同管理系统集成（即将上线）：** 按对方当事人名称或协议标题搜索。获取基础协议及所有修订。记录元数据通常包含执行日期——用于建立时间顺序。

**文档存储库集成（即将上线）：** 按对方当事人名称或文件名搜索。查找匹配"修订""补充协议""第X号修订协议"或编号后缀的文件。拉取所有匹配项并按文件日期或文件名编号排序。

**直接上传：** 用户直接提供文件。多数情况下文件标题自解释（如"补充协议一""第二份修订协议"）——无需询问直接继续。

仅在以下情况要求用户确认顺序：
- 文件名无顺序指示（例如"协议-终版.pdf""协议-v2.pdf""协议-标注版.pdf"）
- 文件名和文件头均无日期
- 两份文件似为同一修订版本

如顺序系推断而非确认，仅在不确定之处在输出顶部标注：
> "顺序根据文件标题推断——有一项我不太确定：[具体文件]。如影响审查请确认。"

**排列规则：** 始终在阅读内容前建立时间顺序。优先使用元数据中的执行日期；如无，查看文件头或前言（"本修订协议，日期……"）。修订通常引用所修改协议（"本主服务协议修订协议，基础协议日期为[X]"）——用这些引用确认链条。

## 保密特权继承

本技能读取基础协议及修订——这些文件本身通常具有保密性，且通常用于特权分析。输出继承来源文件的保密地位。在每项输出前加上工作成果文件头（参见 CLAUDE.md `## 输出规范`），仅在保密特权圈内分发，并存于保密材料存放位置。对外交付前移除文件头。

## 步骤2：阅读并索引

按时间顺序阅读每个文件。提取：
- 文件类型（基础协议、第N号修订协议、补充协议等）
- 执行日期
- 当事人（确认各文件间一致——如新增当事人或名称变更须标注）
- 明确修改、新增或删除的条款清单

在产出输出前构建内部工作索引。用于内部驱动输出——不向用户显示。

## 模式1：所有变更摘要

### 条款引用规范

每项发现必须内联条款引用，让读者无需搜索即可对照来源文件核实：

  "任意解除权（§12.3）：新增。客户可在初始期限结束后提前90天书面通知终止，无需支付费用。"

如果条款跨越多个章节或章节编号在修订间发生变化，引用所有引用：
  "赔偿（§9.1基础协议；§9.1在修订五中重述）"

### 输出格式

```markdown
# 修订历史：[对方当事人] — [协议类型]

**基础协议：** [日期]
**修订：** [N]份（[首份日期] → [末份日期]）
**最后修订：** [日期]

---

## 变更内容——按时间顺序

### 修订一 — [日期]
**目的：** [一句话——此修订存在的原因，来自前言或明显可见。如不清楚，省略而非猜测。]

**实质变更：**
- [条款]（§[X.X]）：[变更前 → 变更后，普通话表达]
- [新增条款]（§[X.X]）：[其作用]
- [删除条款]（§[X.X]）：[删除内容及重要性]

### 修订二 — [日期]
[同上结构]

[每份修订重复]

---

## 现行有效状态

| 条款 | 当前立场 | §引用 | 最后变更 |
|---|---|---|---|
| [条款] | [简明描述] | §[X.X] | 修订N, [日期] |
| [条款] | [与基础协议一致] | §[X.X] | 基础协议 |

---

## 观察事项
[标注不一致之处——如修订修改了已删除的条款、修订间矛盾语言、当事人名称变更但无正式权利转让、条款编号在各文件间变动。每项标注附带条款引用。]
```

## 模式2：条款追踪

### 输出格式

仅显示有变更的内容。对该条款未作任何修改的修订——完全省略，不要列出。

```markdown
# 条款追踪：[条款名称]
## [对方当事人] — [协议类型]

---

### 原版 — [基础协议日期], §[X.X]
> "[精确引用原文]"

*说明：* [一句话]

---

### 修订[N] — [日期], §[X.X]

**曾为：**
> "[先前的精确引用]"

**现为：**
> "[替代语言的精确引用]"

*变更内容：* [一句话——对当事人的实际影响]

---

[仅包含触及该条款的后续修订。其他全部省略。]

---

## 现行有效语言

**§[X.X] — [来源文件, 日期]**
> "[精确引用原文]"

*说明：* [一句话]

---

## 观察事项
[标注、不一致、待解决问题——附带条款引用。常见检查项：该条款是否受责任上限约束或被排除在外；条款编号是否在修订间变动；修订语言是否与其他条款冲突。]
```

如条款从未修订：
> "本条款未被任何修订修改。原版语言现行有效。§[X.X]，基础协议，[日期]。"

## 以下一步行动决策树收尾

以 CLAUDE.md `## 输出规范` 中的下一步行动决策树收尾。根据本技能刚完成的工作定制选项——五个默认分支（起草X、上报、补充事实、监控等待、其他）是起点，而非锁定。决策树是输出；律师选择。

## 本技能不做的事

- 不判断基础协议与修订冲突时哪份文件有效——这是法律解释问题。标注冲突并路由至法务。
- 不起草新修订。
- 不对照审查指引比较——那是供应商协议审查技能的工作。本技能纯属历史追踪。
- 不推断修订含义——如语言存在歧义，精确引用并标注歧义供法务判断。
