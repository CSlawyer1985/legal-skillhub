# 优先级矩阵

在接案之后、条款审查之前使用本矩阵。目标是决定对**这位特定用户**而言什么最重要，而不是对一个抽象律师而言什么最重要。

## 优先级模型

基于以下因素为每个条款族分配工作优先级：

1. 合同类型
2. 用户代表哪一方
3. 用户角色或职能
4. 交易背景
5. 跨职能影响

使用以下工作级别：

- `Critical（关键）`：可能是障碍，强制红线或批准
- `High（高）`：应带着意识进行谈判或批准
- `Medium（中）`：杠杆允许时予以改进
- `Low（低）`：修饰性或低杠杆事项

## 全局常审条款

以下条款除非明显无关，否则始终至少为 `High`：

- 当事方与合同结构
- 范围与交付物
- 费用与付款机制
- 期限与终止
- 保密与允许用途
- 数据与安全义务
- 知识产权所有权与许可范围
- 保证、免责声明与服务级别
- 赔偿
- 责任限制
- 适用法律与争议
- 转让与控制权变更
- 附件与并入文件

## NDA 矩阵

### 用户代表披露方

| 条款族 | 优先级 | 备注 |
|---|---|---|
| 保密信息的定义 | Critical | 避免使保护失效的狭窄定义和排除。 |
| 允许用途 | Critical | 将用途限于所述目的。 |
| 残留信息 | Critical | 通常应抵制残留信息条款，除非获批准。 |
| 披露接收方 | High | 限于知悉必要者并使接收方受约束。 |
| 安全标准 | High | 共享敏感数据时要求合理保障措施。 |
| 返还或销毁 | High | 信息生命周期重要时需要。 |
| 被迫披露 | High | 在法律允许处要求通知和配合。 |
| 保密期限 | Critical | 商业秘密和高敏感信息可能需要更长的存续期。 |
| 宣传／姓名使用 | Medium | 存在品牌风险时重要。 |
| 禁令救济 | Medium | 有帮助，但不总是决定性的。 |

### 用户代表接收方

| 条款族 | 优先级 | 备注 |
|---|---|---|
| 保密信息的定义 | Critical | 防止覆盖琐碎或已知信息的过度宽泛。 |
| 残留信息 | High | 对产品和工程团队重要。 |
| 允许用途 | High | 确保内部评估或服务交付用途可行。 |
| 返还或销毁 | High | 保留法定留存、备份和合规需求。 |
| 保密期限 | Critical | 除商业秘密外，避免不切实际的永久义务。 |
| 非招揽／竞业 | Critical | 通常超出 NDA 范围。 |
| 数据或 AI 使用限制 | High | 确认是否涉及模型训练、遥测或分析。 |

## SaaS MSA 矩阵

### 用户代表 SaaS 提供者审查客户文件

| 条款族 | 优先级 | 备注 |
|---|---|---|
| 范围／优先顺序 | Critical | 防止通过附件或政策隐藏义务。 |
| 费用／付款／抵销 | Critical | 保护开票时间、不付款救济和不得宽泛抵销。 |
| 服务级别／积分 | High | 除非另有批准，积分应为唯一救济。 |
| 安全承诺 | Critical | 将详细控制转交安全部门。 |
| DPA／隐私／数据传输 | Critical | 涉及个人数据时转交隐私部门。 |
| AI／模型训练／使用限制 | High | 产品使用 AI 功能或遥测时关键。 |
| 知识产权所有权／反馈 | Critical | 保留提供者对平台和衍生作品的所有权。 |
| 保证 | High | 抵制无限制的性能承诺或路线图承诺。 |
| 赔偿 | Critical | 收窄提供者赔偿；注意客户滥用除外条款。 |
| 责任上限／除外 | Critical | 保护基于费用的上限并收窄除外。 |
| 审计权 | High | 避免无限制审计、技术渗透权或成本转嫁。 |
| 保险 | Medium | 保险级别超出保单现实时升级。 |
| 终止／过渡协助 | High | 避免永久性的终止后义务。 |
| 基准测试／最惠国待遇／价格冻结 | Critical | 需要业务和财务部门批准。 |

### 用户代表按供应商文件采购的客户

| 条款族 | 优先级 | 备注 |
|---|---|---|
| 范围／订单准确性 | Critical | 确认产品、服务和实施承诺。 |
| 安全承诺 | Critical | 通常需要安全审查。 |
| DPA／隐私／数据使用 | Critical | 通常需要隐私审查。 |
| 可用性／SLA／支持 | Critical | 将义务与业务需求挂钩。 |
| 终止权／退款 | High | 对长期违约和破产包含退出权。 |
| 数据返还／删除／可携带性 | Critical | 常被遗漏且极具实质性。 |
| 知识产权／许可范围 | High | 确保内部关联公司和承包商可以使用。 |
| 赔偿 | High | 适当时要求供应商的知识产权和隐私或安全赔偿。 |
| 责任上限 | Critical | 避免相对于风险和支出的过低上限。 |
| 审计／合规权利 | High | 在受监管环境中重要。 |
| 子处理者／分包商 | High | 按需转交隐私和安全部门。 |

| 条款族 | 优先级 | 备注 |

| 验收 | Critical | 包含客观的验收机制。 |
| 变更单 | High | 防止范围蔓延和未经批准的支出。 |
| 费用／支出 | High | 控制开票和费用报销。 |
| 知识产权所有权／工作成果 | Critical | 所有权和回授许可必须明确。 |
| 人员／分包 | High | 服务质量重要时限制委托。 |
| 保密／数据安全 | High | 安全和隐私可能都需要审查。 |
| 保证／返工 | Critical | 使救济具有实际意义。 |

| 条款族 | 优先级 | 备注 |

| 变更单 | Critical | 无签署的变更单不做额外工作。 |

| 责任上限 | Critical | 避免商业服务的无上限风险敞口。 |

| 人员承诺 | Medium | 除非必要，抵制指名人员不可更换。 |

## DPA／隐私叠加

涉及个人数据、跨境传输、受监管数据、定向广告、模型训练或客户数据分析时，升至 `Critical`：

- 目的限制和处理指示
- 控制者或处理者角色分配
- 子处理者权利和通知
- 国际传输
- 安全措施
- 事件通知时限
- 保留与删除
- 审计和认证权利
- 将数据用于模型训练、服务改进或去标识化

## 地区与行业叠加

满足以下条件时升至 `Critical` 并要求显式的附属文件核查：

- 客户是美国医疗保健提供者或医疗保健服务组织，且涉及 PHI 的传输、处理或存储
- 交易与欧盟或欧洲经济区有关联，且可能向金融行业或保险实体提供 ICT 或云服务
- 客户在 EMEA，客户从事保险或金融服务，营业地为欧洲，且提供的是云服务

第一项条件为真时：

- 将 BAA、HIPAA 隐私与安全、分包商控制、事件通知和数据使用限制至少升至 `Critical`

第二项条件为真时：

- 运行 DORA 适用性筛查，如触发，将 DORA 相关的运营韧性、审计、分包、退出和事件支持条款至少升至 `Critical`

第三项条件为真时：

- 将审计权、安全控制、分包商监督、数据位置、韧性、退出协助、过渡和业务连续性条款至少升至 `Critical`

## 角色调整叠加

选择合同类型矩阵后，适用以下基于角色的调整：

- `商业法务／律师`：在所有核心条款上维持基础优先级。
- `采购`：提升费用、基准测试、期限灵活性、供应商承诺和审计成本条款。
- `销售／收入负责人`：提升成交速度事项、使用权、实施时点和续约障碍；未经明确指出不得降低核心风险条款。
- `隐私法务`：将所有数据条款至少升至 `Critical`。
- `安全`：将安全附表、事件通知、审计权、加密和分包商控制至少升至 `Critical`。
- `财务`：提升费用、税费、积分、与费用挂钩的上限、付款条款、收入确认问题和退款机制。
- `产品／工程`：提升范围、集成、路线图承诺、验收、变更控制、AI 功能限制和支持义务。

## 审批路由矩阵

出现以下触发事由时，将条款路由给相应人员审查或批准：

| 触发事由 | 审查人 |
|---|---|
| 个人数据、DPA、数据传输、保留、模型训练 | 隐私 |
| 安全附件、审计、渗透测试、事件时限、BCP 或灾难恢复 | 安全 |
| 定价承诺、积分、付款时点、税费、宽泛抵销、最惠国待遇 | 财务 |
| 范围、集成、定制工作、路线图、验收标准 | 产品或工程 |
| 保险限额、异常赔偿、无上限风险 | 保险或风险 |
| 受监管义务、公共部门、制裁、无障碍、反贿赂 | 合规 |
| 独家性、战略限制、异常商业让步 | 高管或业务负责人 |
| 美国医疗保健客户且涉及 PHI | 隐私、安全、合规 |
| 欧盟或欧洲经济区关联且可能涉及 DORA | 安全、合规、法务、相关业务负责人 |
| EMEA 使用云服务的金融或保险客户 | 安全、合规、法务、相关业务负责人 |

## 最终优先级输出

在条款审查之前，产出一份简短的工作摘要：

- 审查模式
- 本次交易的 5 个关键条款族
- 所需内部审查人
- 有意降级的任何条款族及原因
