# 失败模式

在审查草稿完成后、最终答复发出前运行本检查清单。

## 接入失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 缺少当事人身份 | 建议未反映用户代表哪一方。 | 重新核查接入并修订优先事项。 |
| 缺少角色语境 | 建议忽略用户是法律、采购、销售、隐私还是安全角色。 | 以角色叠加重新运行优先级加权。 |
| 缺少主导文件 | 分析引用错误版本或忽略红线稿。 | 识别主导版本并重述假设。 |

## 阅读失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 附件盲区 | 审查了主协议但忽略附表或政策。 | 构建文件地图并审查附件。 |
| 定义术语漂移 | 红线或批注中术语使用不一致。 | 重新核查定义和依赖条款。 |
| 交叉引用遗漏 | 修改条款而未核查关联章节。 | 核实每个受影响的交叉引用。 |
| 缺失纳入文件 | 忽略 URL、政策、订单表格或 DPA。 | 标记缺失文件并评估该缺口的风险。 |

## 分析失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 泛泛识别问题 | 输出在未阅读本合同的情况下也能写出。 | 将每个问题与条款引用和合同事实挂钩。 |
| 松散的 playbook 比较 | 凭直觉而非规范化立场判断合同。 | 按 playbook 模式重建条款比较。 |
| 未评分的退回批注 | 描述对方变更但无偏差评分或影响标签。 | 对照 playbook 重新评分退回草稿。 |
| 语境稀释 | 一次加载过多合同和 playbook 文本，遗漏文档中间的问题。 | 以结构化部分加载和条款网络检索重新运行。 |
| 缺失辅助文件触发 | 未检查是否需要 SLA、安全附表、AI 条款、BAA、DORA 或金融云附表。 | 从接入和文件地图重新运行辅助文件检查。 |
| 静态优先级 | 所有问题同等对待，无论角色或纸张方。 | 重新应用优先级矩阵。 |
| 幻觉的市场标准 | 输出声称某条款非常规而无依据。 | 改为基于 playbook 或基于用户的推理。 |
| 缺失遗漏分析 | 未识别缺失条款。 | 为相关合同类型增加缺失条款分析。 |

## 红线失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 过度编辑 | 低风险条款被大幅重写而无益。 | 将编辑收窄至真实风险。 |
| 起草破坏 | 红线破坏语法、定义术语或结构。 | 为法律和语言连贯性重新起草。 |
| 无退路 | 输出建议拒绝但无备份路径。 | 增加可接受的退路立场。 |
| 编辑不一致 | 修订后多个条款相互冲突。 | 跨协议统一红线。 |

## 谈判失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 无让步阶梯 | 一切都标为关键。 | 区分必须赢、可交易和低杠杆点。 |
| 无商业理由 | 用户无法向对手方解释请求。 | 为每个重大问题添加一行谈判理由。 |
| 缺少杠杆分析 | 策略忽略紧迫性、文件所有者或交易价值。 | 用杠杆因素更新谈判计划。 |

## 审批失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 遗漏安全审查 | 安全附表仅作为纯法律语言审查。 | 路由至安全部门。 |
| 遗漏隐私审查 | DPA 或 AI 使用条款缺少隐私上报。 | 路由至隐私部门。 |
| 遗漏财务审查 | 定价机制或责任经济缺少财务审批。 | 路由至财务部门。 |
| 遗漏产品审查 | 范围或路线图承诺缺少产品审查。 | 路由至产品或工程部门。 |

## 输出失败

| 失败 | 表现 | 强制修正 |
|---|---|---|
| 无缺失文件清单 | 用户无法判断什么会提高置信度。 | 增加缺失文件和未决问题。 |
| 无不确定性声明 | 尽管缺少语境，答案听起来确定。 | 增加置信度说明和假设。 |
| 无 QA 追溯 | 最终答复未显示质量门禁已运行。 | 增加 QA 和基准摘要。 |
| 无严重性信号 | 用户无法判断退回的变更哪些严重、哪些轻微。 | 增加偏差分数、影响区间、颜色标签和置信度。 |
| 无地区或行业触发摘要 | 用户无法判断是否运行了 BAA、DORA、SLA、安全附表、AI 条款或金融云附表检查。 | 增加辅助文件和监管触发摘要。 |

## 停止条件

如以下类别中仍有任何障碍，不要定稿审查：

- 错误的当事人或角色假设
- 未审查的附件或纳入文件
- 关键条款分析缺失
- 红线破损或冲突
- 缺少必需的跨职能审批
