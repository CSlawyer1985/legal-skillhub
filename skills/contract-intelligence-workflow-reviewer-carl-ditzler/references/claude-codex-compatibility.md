# Claude 与 Codex 兼容性

使用本文件保持技能在 Claude 和 Codex 之间的可移植性。

## 核心规则

只要可能，工作流应在各工具间保持一致。工具差异应改变执行机制，而非法律标准。

## 共享事实来源

- `.contract-review/` 是主要的跨平台工作区状态。
- `CLAUDE.md` 是持久设置面向 Claude 友好的镜像。
- `SKILL.md` 和附带的参考文件为两个系统定义工作流。

## 兼容性规则

- 在两个工具中都先读取 `.contract-review/`。
- 如果 `CLAUDE.md` 存在，保持其与 `.contract-review/` 对齐。
- 保存的工件使用纯 Markdown、YAML、JSON 和 CSV。
- 不要依赖产品特定的隐藏记忆作为唯一存储配置。
- 在两个工具中使用相同的最小权限连接器默认值、保留默认值和安全通知。

## 优雅降级

如果某项能力不可用，按以下方式继续：

- 无 MCP 或连接器：请求文件上传或粘贴文本。
- 无文件系统写入权限：保持相同工作流，但内联呈现工件并告知用户持久化不可用。
- 无子代理：在单个代理中顺序执行各阶段。
- 无直接文件转换工具：请求更清晰的剧本来源，或从可用文本手动规范化并降低置信度。

## 输出可移植性

- 保持输出为普通 Markdown 以供人类阅读。
- 保持结构化工件为 YAML、JSON 或 CSV。
- 使用文本颜色标签，如 `Green`（绿）、`Yellow`（黄）、`Orange`（橙）和 `Red`（红），而非 UI 特定的格式假设。

## 面向用户的披露

如果当前环境缺少影响工作流的能力，简要说明：

- 哪些能力不可用
- 使用了什么回退路径
- 置信度或自动化范围是否降低

如果环境支持连接器或远程 MCP，还披露提供者保障措施会降低但不会消除敏感数据暴露、提示注入或意外工具行为的风险。
