# 安全与隐私

本文件规范合同上传、云源连接和 MCP 支撑工作流的默认安全姿态。

## 核心规则

这些控制措施降低风险。它们不消除风险。

OpenAI 警告称，连接器和远程 MCP 服务器可能向模型暴露敏感数据、允许对敏感系统的读取访问、能够在外部服务中执行操作，并产生提示注入风险。Anthropic 同样警告称，自定义连接器可以访问外部系统并在其中操作、可能在无警告情况下改变行为，且并非完全免疫恶意行为。将这些控制措施视为保障，而非保证。

## 必需的用户告知

在首次使用连接器、首次使用远程 MCP 或在新工作区首次上传合同之前，提供简明告知，说明：

- 已连接来源可能向模型或提供方暴露敏感合同数据
- 远程 MCP 服务器和连接器可能在外部系统中读取或采取行动
- 提示注入和意外工具行为仍然可能发生
- 批准、狭窄范围和可信连接器可降低风险，但并非万无一失
- 除非用户另行选择，本技能将默认使用狭窄的文件或文件夹范围、不保留本地合同副本、保守保留，以及外向连接器操作仅"建议"（`suggest-only`）

## 默认安全设置

除非用户明确另行选择，否则使用以下默认设置：

- 仅批准合同工作流所需的最小特定文件或文件夹
- 在可能采用更窄范围时，不要批准整个驱动器、站点、工作区或仓库
- 保持 `write_local_contract_copies`（写入本地合同副本）关闭
- 在用户明确批准更强的自动化之前，将外向连接器操作和通知保持为仅"建议"（`suggest-only`）
- 除非用户确认自定义或远程 MCP 服务器可信且经过审查，否则将其视为不允许
- 保持合同保留保守，并在合同工作流结束时审查已保存的产物
- 在可用时，优先使用企业或管理员管理的连接器策略

## 连接器范围规则

- 对控制剧本（playbooks）和活动合同，优先采用文件级批准。
- 如果文件级批准不实际，优先批准一个文件夹，而非整个驱动器或整个站点。
- 将批准的准确范围记录在 `.contract-review/connectors.yaml` 中。
- 如果用户要求广泛访问，警告更宽范围会增加意外披露和提示注入风险。

## 外向操作规则

- 起草和函件准备可在本地进行。
- 通过连接器的发送、发布、创建工单或改变状态的操作应默认为仅"建议"（`suggest-only`）或"需批准"（`approval-required`）。
- 仅在用户明确批准连接器、目的地和操作模式后，才将可写连接器操作提升到仅"建议"（`suggest-only`）以上。

## 保留与清理规则

- 默认不持久化完整合同文本。
- 将保存的产物限制在运营所必需的范围内。
- 当合同完成时，提醒用户审查本地产物、缓存衍生物和连接器授权应保留还是移除。
- 如果用户要求保守处理，建议在工作流关闭后删除合同特定产物。

## 跨平台规则

这些设置对 Codex 和 Claude 均受支持，因为它们通过技能工作流、已保存配置和人工批准门槛执行，而非隐藏的产品特定记忆。
