# 设置与持久化

本文件管理合同审查的首次运行设置、持久记忆和可复用工作区配置。

## 目的

目标是避免每次都询问相同的组织性问题，同时默认将机密交易内容排除在长期记忆之外。

使用双层模型：

- `CLAUDE.md` 是面向 Claude 的持久指令和偏好摘要。
- `.contract-review/` 是 Claude 和 Codex 共用的跨平台事实源。

如两者同时存在且冲突，以 `.contract-review/` 为准。更新 `CLAUDE.md` 以保持一致。

## 首次运行检测

满足以下任一条件时进入设置模式：

- `.contract-review/config.yaml` 不存在
- `.contract-review/connectors.yaml` 不存在
- `.contract-review/approvals.yaml` 不存在
- `CLAUDE.md` 不存在且用户需要 Claude 兼容性
- 用户表示设置已变更

## 应向用户询问的内容

分批简短询问设置信息。除非用户要求完整表单，否则不要一次性倾倒全部问卷。

### 第 1 批：组织默认项

- 组织或业务单元名称
- 默认代理方
- 通常审查的合同类型
- 默认用户角色或团队
- 默认风险立场
- 团队通常审查本方文件还是对方文件

### 第 2 批：手册与来源位置

- 标准模板存放位置
- 手册、条款库、备用措辞和既往交易存放位置
- 首选比较来源顺序
- 既往协议是否可用作备用先例
- 手册是直接上传、从批准的云来源获取，还是两者皆可
- 原始手册文件是否可复制到本地
- 首选衍生手册格式顺序：源 Markdown、规范化 YAML，或两者

### 第 3 批：审批路由

- 法律审批人姓名和联系方式
- 财务审批人姓名和联系方式
- 安全审批人姓名和联系方式
- 隐私审批人姓名和联系方式
- 采购审批人姓名和联系方式
- 产品或工程审批人姓名和联系方式
- 合规审批人姓名和联系方式
- 保险或风险审批人姓名和联系方式
- 高管审批人姓名和联系方式
- 哪些审批是阻断性的而非咨询性的
- 每位审批人首选的通知路径：Slack、电子邮件、工单或人工
- 批准 Slack 通知时的 Slack 用户 ID、Slack 用户名或频道
- 升级联系人或备用审批人
- 合同特定审批人是否应覆盖已保存的默认值

### 第 4 批：文件系统与输出偏好

- 合同文件夹的工作区路径
- 是否自动保存合同工件
- 首选文件格式
- 合同文件夹命名约定
- 是否保存谈判草稿和审批包

### 第 5 批：MCP 连接器

- 批准使用哪些连接器
- 每个连接器或来源的别名
- 批准哪些具体文件或文件夹
- 是否确有必要访问更广泛的驱动器、站点或集合
- 上传或获取的文件是否可写入本地
- 连接器数据是否可用作手册或先例输入
- 是否有企业或管理员管理的连接器控制可用并应主导审批

### 第 5B 批：工作流工具与操作

- 批准哪些工作流工具用于路由任务或更改状态
- 哪些目的地可接收摘要、审批包或红线指示
- 哪些操作属于 `allowed`（允许）、`approval-required`（需审批）或 `suggest-only`（仅建议）
- 系统是否可自动更新合同状态
- 系统是否可起草但不发送外部通信
- 是否可使用 Slack、电子邮件、工单或其他消息工具进行内部通知
- 工具是否可从连接器目录解析用户，而非手动输入
- 工具是否可自动发送私信、发布频道帖子或创建工单
- 出站写操作是否应默认保持 `suggest-only`

### 第 6 批：记忆、保密性与子代理

- 哪些内容可持久存储
- 哪些内容绝不可存储
- 合同保留偏好
- 是否可保留对方记忆
- 是否可使用子代理
- 并行子代理的最大数量
- 哪些任务可委派

### 第 7 批：研究与起草偏好

- 批准的研究来源
- 引用要求级别
- 摘要应面向业务、面向法律，还是两者
- 红线、备忘录、电子邮件和问题摘要的首选起草风格
- 首选机器可读负载格式

## 保存目标

将答案保存到以下文件：

- `.contract-review/config.yaml`
- `.contract-review/connectors.yaml`
- `.contract-review/workflow-tools.yaml`
- `.contract-review/approvals.yaml`
- `.contract-review/memory-policy.yaml`
- `CLAUDE.md`

对于进行中的工作，在 `.contract-review/contracts/<contract-slug>/` 下创建合同特定文件。对于可复用手册，在 `.contract-review/playbooks/<playbook-slug>/` 下创建手册特定文件。

## 必需文件语义

### `.contract-review/config.yaml`

以下内容的全局默认值：

- 组织画像
- 合同审查默认值
- 文件系统偏好
- 子代理偏好
- 输出偏好
- 手册摄取偏好

### `.contract-review/connectors.yaml`

已批准的连接器清单、别名、批准来源位置和允许的用例。

该文件还应记录哪些连接器可提供主导性手册文件。记录尽可能狭窄的批准范围，以及是否禁止广泛的驱动器或站点访问。

### `.contract-review/workflow-tools.yaml`

已批准的操作工具、路由目的地、目录来源、消息权限和允许的自动化操作。

除非用户明确另作选择，出站连接器操作应默认设为 `suggest-only`。

### `.contract-review/approvals.yaml`

审批人身份、职能、升级触发条件、阻断状态和首选通知目标。

设置中的审批人映射仅为默认基线；合同特定的审批人和路由仍须在收件和审查期间确认。

### `.contract-review/memory-policy.yaml`

可持久化什么、绝不可持久化什么、保留规则，以及是否允许对方记忆。

该文件还应反映合同关闭时是否应审查合同特定工件以决定删除或保留。

### `CLAUDE.md`

面向 Claude 的简明操作摘要，镜像以下内容：

- 组织默认项
- 审批人映射
- 存储位置
- 连接器别名
- 记忆限制
- 子代理规则
- 工作流操作限制
- 研究与起草偏好
- 手册摄取偏好

不要在 `CLAUDE.md` 中放置大型表格、原始合同或合同特定的机密事实。

## 更新规则

- 如用户可能在意差异，绝不静默覆盖现有设置。
- 将新答案合并到现有文件中。
- 保留未变更的值。
- 将未知值记录为 `unknown`，而非捏造猜测。
- 如用户给出合同特定覆盖，保存在合同文件夹中，而非全局配置。
- 将保存的审批人映射仅视为默认基线。在收件期间，当合同要求时确认合同特定审批人和覆盖项。

## 默认不持久化的内容

除非用户明确授权，否则不保存以下内容：

- 完整合同文本
- 个人数据
- 与特定合同相关的特权法律意见
- 在办合同中的对方律师策略
- 标记为一次性使用机密的定价或交易条款

## 必需的安全披露

在工作区中首次上传、首次使用连接器或首次远程使用 MCP 之前，按 [security-and-privacy.md](security-and-privacy.md) 所述发出通知。

## Claude 与 Codex 兼容性规则

Claude 和 Codex 都应先读取 `.contract-review/`。Claude 可以额外读取 `CLAUDE.md`。更新持久记忆时，在适用时同时更新两者，以便任一工具随后都能恢复工作流。
