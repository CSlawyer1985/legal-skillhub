## 二、六类核心违规行为（认定标准）

依据《App违法违规收集使用个人信息行为认定方法》：

1. **未公开收集使用规则** —— 无隐私政策或隐私政策不可见
2. **未明示目的、方式、范围** —— 收集行为与声明不符
3. **未经用户同意** —— 缺乏有效告知同意机制（强制同意、默认勾选等无效）
4. **违反必要原则** —— 超范围收集个人信息（必要信息清单外的收集）
5. **未经同意向第三方提供** —— SDK、合作方共享未告知
6. **未提供删除/更正机制** —— 缺乏用户权利行使渠道

## 三、权限分类与合规要求

### 高敏权限（需单独告知+逐项同意）
- 精确位置（GPS）
- 通讯录
- 麦克风
- 摄像头
- 生物特征（指纹/面部）
- 短信/通话记录

### 中敏权限（需在隐私政策中明确说明）
- 粗略位置（网络/基站）
- 存储（读写）
- 设备标识符（IMEI/OAID/AndroidID）
- 剪切板
- 已安装应用列表

### 权限使用原则
- **最小化原则**：仅申请业务功能所必需的权限
- **知情同意原则**：申请前须用弹窗/说明告知用途
- **撤回权**：用户可随时在系统设置中撤回权限，App不得因此降级服务（核心功能除外）
- **禁止后台滥用**：后台收集须有合理说明，禁止静默收集

## 四、SDK 合规要求

### 常见高风险 SDK 类型
- 广告 SDK（穿山甲/优量汇/广点通等）
- 数据分析 SDK（友盟/CNZZ/神策等）
- 推送 SDK（极光/个推等）
- 第三方登录（微信/QQ/微博）
- 支付 SDK（微信支付/支付宝）
- 地图 SDK（高德/百度）

### SDK 合规义务
1. 在隐私政策中列明所有第三方 SDK 及其收集数据清单
2. 与 SDK 服务商签署数据处理协议（DPA）
3. 确保 SDK 版本经过官方隐私合规认证
4. 定期审查 SDK 更新，避免因 SDK 升级引入新违规行为

## 五、不同主体的合规重点

### 企业法务
- 合规体系建设（制度文件）
- 违规风险法律后果（行政罚款、下架、刑事责任）
- 与监管部门沟通口径
- 用户投诉/举报处理合规

### 技术人员
- 权限申请代码规范
- SDK 集成合规
- 数据最小化技术实现
- 加密传输/存储技术要求
- 隐私合规 SDK（合规检测 API）

### 外部律师
- 隐私政策文本法律审查
- 违规整改法律意见书
- 监管应对策略
- 跨境数据合规（数据出境评估/SCCs）
