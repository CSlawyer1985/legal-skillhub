# 专利点资产清单、轻量查新、评分与取舍确认（Step 3–4）

## 执行门禁

扫描项目材料后，默认 **不得直接进入交底书生成**。必须先输出一份含 **轻量相似专利初筛** 的“专利点资产清单”，让用户决定：

- 哪些点写成专利
- 哪些点暂不写
- 哪些点建议作为商业秘密保护
- 哪些点材料不足，需要补充后再判断

只有用户明确确认拟申请的专利点后，才进入深度查新与交底书生成。用户明确说“跳过清单、直接生成”时，可以跳过，但须在对话中说明“已按用户要求跳过专利点清单与轻量初筛”。

## Step 3：候选专利点盘点

从材料中尽量完整挖掘候选专利点，通常列出 **5–12 个**；材料较少时可少于 5 个，但须说明原因。不要只列最强的一个。

每个候选点至少包含：

- **候选名称**：一句话标题，避免泛泛的“系统优化”。
- **证据来源**：对应材料、代码模块、设计文档或用户描述；可用脱敏路径/模块名。
- **技术问题**：该点解决什么具体技术问题。
- **核心方案**：关键步骤、模块、数据结构、规则、算法或链路。
- **技术效果**：准确率、稳定性、效率、可维护性、安全性、可追踪性等。
- **可实施性**：现有材料是否足以让本领域技术人员实施。
- **公开风险**：公开后是否容易被竞争对手复制或规避。
- **相似公开技术**：轻量检索中找到的最相近专利/文献；若未检索到，写“未发现高相似结果”或“检索受限”。

## 轻量相似专利初筛

资产清单阶段须先做 **轻量初筛**，用于影响评分和取舍；它不同于 Step 5 深度查新。轻量初筛目标是快速识别“是否已有高度相似公开技术”，避免在明显撞车的点上直接成文。

### 检索渠道

- **优先**：Google Patents（`https://patents.google.com/`），用候选点的中英文关键词、方法名、核心模块组合检索。
- **补充**：WebSearch、Google Scholar、CNIPA 公布公告或其它公开专利页。
- 每个“建议申请”或“可合并”的候选点，至少构造 **1–3 组关键词**；每组尽量包含技术对象 + 核心手段，例如“natural language SQL field whitelist data source context”、“语义索引 训练版本 标签 召回”等。
- 每个候选点最多记录 **0–3 条最相近公开结果**，不要堆无关结果。
- 若网络、权限或站点限制导致无法完成，必须在清单中显式写明：**“轻量检索未完成，本清单不构成最终可申请结论”**。

### 相似度等级

| 等级 | 判定 | 对结论的影响 |
|------|------|--------------|
| 高度相似 | 公开文献已覆盖同一技术问题、核心步骤和主要效果，仅剩实现细节不同 | 通常不建议按原范围申请；可改写为改进点、缩窄保护点，或放弃/商业秘密 |
| 部分相似 | 公开文献覆盖背景或部分步骤，但缺少本案关键约束、闭环、参数关系或组合效果 | 可以继续，但须在推荐结论中写明差异化方向 |
| 背景相似 | 属于同一技术领域，但技术问题或核心手段不同 | 可以继续，后续 Step 5 深度查新再精化区别 |
| 未发现高相似 | 轻量检索未发现明显接近结果 | 可以进入候选，但仍须 Step 5 深度查新 |

### 相似不等于不能写

检索到相似公开技术时，不得简单写“不能申请”。须给出以下判断之一：

- **放弃原点**：核心方案已被完整公开，无法形成有意义区别。
- **缩窄申请**：保留差异步骤、特定约束、特定组合关系或技术效果，放弃过宽表述。
- **改成改进专利**：围绕现有技术未解决的缺点写改进方案。
- **合并从属**：单独创新弱，但可作为主案从属特征。
- **商业秘密保护**：差异主要来自参数、规则、样本、提示词或客户口径，公开代价高且侵权难检测。

## 评分维度

对每个候选点按 1–5 分评分，并给出一句理由：

| 维度 | 说明 |
|------|------|
| 技术性 | 是否是技术方案，而非业务规则、管理制度或展示文案 |
| 新颖性潜力 | 相对常规方案是否有可识别差异 |
| 创造性潜力 | 差异是否产生技术效果，是否不是简单拼装 |
| 可实施性 | 材料是否足以支撑实施例、流程、模块与参数 |
| 可检测性 | 侵权时是否能从产品行为、接口、日志、文档或结果中看出 |
| 保护价值 | 是否覆盖核心产品能力、商业价值或竞品绕不开的环节 |
| 公开代价 | 公开后对商业秘密、模型策略、规则库或数据资产的泄露风险；分数越高表示越适合公开申请 |
| 相似风险 | 轻量检索发现的相似公开技术风险；分数越高表示越不容易被公开技术覆盖 |

可给出总分，但总分不得替代判断。若某点“公开代价”低分但其它分高，通常建议商业秘密保护或拆分公开。

## 分类要求

必须把候选点分入以下四类之一：

1. **建议申请专利**：技术方案完整、差异明确、公开代价可接受，轻量初筛未发现覆盖核心方案的高度相似公开技术。
2. **可合并进其它专利**：单独成案偏窄或创造性不足，但可作为主专利从属点、实施例或效果增强点。
3. **暂不建议申请**：不够技术化、材料不足、容易被现有技术覆盖、难以检测侵权或保护价值较低。
4. **建议商业秘密保护**：公开后容易泄露核心规则、参数、训练数据、模型选择、提示词策略、客户业务口径、运营经验等，且外部较难反向观察。

## “不能形成专利”的常见原因

当判断为“暂不建议申请”时，必须写明原因，常见包括：

- 只是业务流程、界面交互或配置项，没有技术问题和技术效果。
- 只是调用通用大模型、向量库、数据库或开源框架，缺少自己的技术约束或处理机制。
- 只是常规 CRUD、常规缓存、普通日志记录或普通接口封装。
- 方案过于抽象，缺少数据流、控制流、参数、规则或实施例。
- 技术效果不可验证，无法说明相对现有技术的改进。
- 侵权不可检测，即使他人使用也难以从外部或证据保全中证明。
- 公开后价值小，反而暴露关键 know-how。

## 商业秘密保护判断

当判断为“建议商业秘密保护”时，须说明：

- 建议保密的具体对象：规则库、参数阈值、提示词模板、训练样本、标签体系、数据清洗映射、客户口径、模型路由策略等。
- 为什么不适合公开写专利：公开后易复制、难检测侵权、生命周期短、依赖内部数据或业务 know-how。
- 是否可拆分：把外围流程或系统结构申请专利，把关键参数、样本、规则内容、提示词细节留作商业秘密。
- 最小披露建议：若仍要写专利，哪些细节只写成“预设规则/预设模型/预设阈值”，不披露具体值或完整规则表。

## Step 4：融合、拆分与推荐组合

在清单后给出组合建议：

- **主专利候选**：1–3 个最适合成案的独立专利标题。
- **从属/实施例候选**：适合并入主专利的点。
- **拆分建议**：哪些点不宜塞进同一件专利，避免主题不单一或保护范围混乱。
- **秘密保护建议**：哪些点不写进专利，或只抽象写外围机制。

先输出简短总览，再输出表格。建议结构如下：

### 决策表

## 禁止事项

- 禁止只输出一个“最有价值专利点”后直接生成交底书。
- 禁止在未说明轻量检索结果或检索受限原因的情况下，把候选点标为“建议申请专利”。
- 禁止看到相似专利就机械判定“不能写”；必须分析覆盖范围和可区分点。
- 禁止把商业秘密点的具体参数、完整规则表、客户口径、训练数据样例、提示词全文写入交底书。
- 禁止为了凑专利点，把普通工程实现包装成“创新算法”。
- 禁止仅用总分排序而不解释不能申请或不宜公开的原因。
