# 版本化产出目录规范

## 目标

专利交底书会反复生成、补充技术细节、重新导出 Word / PDF。所有用户可见产物必须按版本目录保存，避免在同一层目录堆放大量带时间戳的文件。

## 目录结构

用户给出产出目录时，将其视为**专利组根目录**或**案件根目录**。根目录只保留版本索引、修订日志和版本文件夹：

```text
{专利组或案件根目录}/
├── 版本索引.md
├── 交底书修订对话记录.md
├── v1-初版-YYYYMMDDHHMMSS/
│   ├── {案件名}_{YYYYMMDDHHMMSS}.md
│   ├── {案件名}_{YYYYMMDDHHMMSS}.docx
│   ├── {案件名}_{YYYYMMDDHHMMSS}.pdf
│   ├── {项目名}_专利簇通俗说明清单_{YYYYMMDDHHMMSS}.md
│   ├── mermaid_figures/
│   └── math_figures/
└── v2-技术细节增强-YYYYMMDDHHMMSS/
    └── ...
```

若用户指定的是单件专利目录，也使用同样结构；若一次交付多件专利，所有同批次文件放入同一个版本目录。

## 版本目录命名

版本目录格式：

`vN-简短说明-YYYYMMDDHHMMSS`

规则：

1. `N` 为当前根目录下已有 `v数字-` 目录的最大编号加 1；没有旧版本时从 `v1` 开始。
2. 简短说明用 4-12 个中文字符或短词，例如 `初版`、`导出PDF`、`技术细节增强`、`补充实施例`、`纠错修订`。
3. 时间戳使用本次交付时间，与主文件名时间戳保持一致。
4. 不覆盖旧版本目录；用户明确要求覆盖时，也应先提醒覆盖会破坏版本追溯。

## 文件放置规则

- `.md`、`.docx`、`.pdf`、专利簇通俗说明清单、生图提示词、自动生图 PNG、mermaid / math 资源目录，均放在**当前版本目录**。
- 当前版本 Markdown 内的相对图片路径必须指向同版本目录内的资源目录，例如 `mermaid_figures/fig_001.png`。
- 根目录不得新增定稿文件；根目录只更新 `版本索引.md` 和 `交底书修订对话记录.md`。
- 若发现历史产物已经平铺在根目录，后续交付前应整理到 `v1/v2/...` 或至少从新版本开始遵守本规则。

## 版本索引

每次交付或迭代后，必须创建或更新根目录 `版本索引.md`，至少包含：

1. 当前推荐阅读版本。
2. 版本清单表：版本目录、生成时间、内容、阅读建议。
3. 当前版本包含的专利文件、专利簇说明清单、Word / PDF 情况。
4. 后续版本规则：新一轮修改创建下一个 `vN-说明-时间戳/`，不覆盖旧版本。

`版本索引.md` 面向用户阅读，语言要直白，让用户一眼知道应该看哪个版本。

## 迭代时的处理

补材料、纠错、强化权利要求偏向点时：

1. 读取用户指定或 `版本索引.md` 标记的当前推荐版本作为基准。
2. 新建下一个版本目录，例如 `v4-补充实施例-YYYYMMDDHHMMSS/`。
3. 把本轮生成的所有交付文件写入该版本目录。
4. 更新根目录 `版本索引.md`，将当前推荐版本指向新版本。
5. 在根目录 `交底书修订对话记录.md` 追加本轮记录；必要时可在版本目录内同步一份 `本版本说明.md`。

## 回复用户时

交付回复中应给出：

- 根目录 `版本索引.md` 路径。
- 当前推荐版本目录。
- 主要 Word / PDF / Markdown 文件路径。

不要只给出一串平铺文件名。
