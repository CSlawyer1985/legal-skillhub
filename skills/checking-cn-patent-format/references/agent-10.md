## 执行步骤

1. 读取审查规则文件 `<skill_root>/Checking Rules/42-说明书-复杂审查1-说明书公开是否充分.md` 的完整内容
2. 读取待审查文本：读取 `<work_dir>/section_description_<timestamp>.json`，提取 `paragraphs` 字段的值作为待审查文本
3. 执行审查：关注说明书公开是否充分，必须逐项检查以下5种"公开不充分"情形：
   - 说明书只给出任务和设想，未给出技术手段
   - 说明书给出了技术手段，但该手段含糊不清
   - 说明书给出了技术手段，但该手段不能解决技术问题
   - 对于多个技术手段的技术方案，其中一个技术手段无法实现
   - 技术方案需要实验证据但未给出
   
   禁止快速浏览后直接输出空数组[]。必须对上述5种情形逐一写出检查过程（即使最终结论是"无问题"），每条检查必须包含：a)检查了什么内容；b)检查结果（是/否）；c)判断理由
4. 输出审查意见JSON：保存为 `<work_dir>/reviews_agent10_<timestamp>.json`，section 填写 "说明书"，claim_number 填写 null
5. 立即执行自检 → 完成自检后不总结不暂停，直接结束

## 专属约束

### 跨章节边界约束

- 本Agent仅检查说明书内部的公开是否充分问题
- **极其重要：禁止报告任何形式的跨章节一致性问题**
- 禁止报告"发明名称/说明书标题与正文主题不一致"（由Agent 11/12负责）
- 禁止报告"发明名称与说明书内容不符"作为公开不充分问题
- 禁止报告"权利要求书的技术方案在说明书中是否有记载"（由Agent 12负责）
- 禁止报告"摘要与说明书内容对应性"问题（由Agent 12负责）

**仅允许报告的问题类型**（全部可在section_description内部独立验证）：
- 技术手段描述含糊不清
- 缺少关键实施步骤或工艺参数
- 技术方案与声称的技术效果逻辑不匹配
- 错别字导致技术含义无法理解（从公开充分角度）
- 同一术语在说明书前后段落中的定义矛盾

**判断金标准**：审查意见的context和判断依据是否全部且仅来自section_description文件？如果是→可以报告；如果需要引用或对比其他章节→绝对禁止。

### 与Agent 9的职责边界

- Agent 9负责说明书撰写规范问题，Agent 10负责说明书公开充分性问题
- 当某个问题同时构成两者时，如果Agent 10的修正方案与Agent 9完全一致，禁止重复报告
- 只有当Agent 10认为Agent 9的修正方案不足以解决公开充分性问题时，才单独报告
- 禁止将错别字问题重新包装为"公开不充分"——只有当术语含义不清导致技术方案无法实施时，才属于公开不充分
