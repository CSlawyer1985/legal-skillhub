# 图片审查子Agent 任务描述

> 本Agent由主Agent在第7批动态创建，每个实例仅负责检查1张说明书附图图片。主Agent在query中提供图片路径、图号、附图标记列表和附图说明文字。

## 配置信息

| 项目 | 值 |
|------|-----|
| 审查规则文件 | `<skill_root>/Checking Rules/52-附图-图片检查1.md` |
| section | 说明书附图 |
| claim_number | null |
| 输出 | 审查意见 JSON 数组（通过返回值传回给主Agent） |

## 执行前检查清单

- [ ] 确认主Agent已提供图片文件路径、图号（fig_text_name）、附图标记列表、附图说明文字列表
- [ ] 确认审查规则文件 `<skill_root>/Checking Rules/52-附图-图片检查1.md` 存在且可读
- [ ] 确认图片文件存在且可读

## 执行步骤

1. 读取审查规则文件 `<skill_root>/Checking Rules/52-附图-图片检查1.md` 的完整内容
2. 使用 Read 工具读取主Agent提供的图片文件，查看图片的实际视觉内容
   - 如果图片格式为 EMF/WMF 等矢量格式导致无法读取，进入**降级分析模式**（见下方）
   - 如果读取工具返回错误（如"non-compliant content"），进入**降级分析模式**（见下方）
3. 执行图片级审查（规则4 + 规则6 + 规则11）：
   - 规则4：识别图片中的所有附图标记，对比主Agent提供的附图标记列表进行一致性验证
   - 规则6：检查图片中是否存在不当注释；流程图/框图类型检查是否有必要的文字或符号
   - 规则11：对比图片实际内容与附图说明文字列表中对应图号的描述是否一致
4. 输出审查意见 JSON，通过返回值传回给主Agent
5. 立即执行自检 → 完成自检后不总结不暂停，直接结束

## 降级分析模式

当图片无法通过Read工具直接查看时（如内容安全过滤、格式不兼容等），执行以下降级分析：

1. **读取图片元数据**：从主Agent提供的 image_analysis 报告中获取该图片的元数据（尺寸、格式、DPI、是否可读等）
2. **基于元数据的检查**：
   - 检查图片尺寸是否合理（过小可能模糊不清，建议宽度>=800px）
   - 检查DPI是否满足打印要求（建议>=300 DPI）
   - 检查图片格式是否为专利文档常用格式（PNG/JPG/TIFF为佳）
   - 如果元数据显示 `readable: false`，在issue中注明图片可能存在格式异常
3. **基于文本上下文的检查**：
   - 对比附图说明文字与附图标记列表，检查标记编号是否在说明中有对应描述
   - 检查附图说明中是否存在该图号的描述
4. **输出格式**：
   - 每条降级分析意见的 issue 中必须注明"[降级分析-图片无法查看]"
   - action_type 固定为 "comment"
   - 建议人工复核该图片

## 执行后自检清单

- [ ] context 长度不超过50字符
- [ ] action_type 固定为 "comment"
- [ ] 确认 JSON 无语法错误

## context字段强制规范（最高优先级）

- **禁止使用构造性描述文本**：context必须是文档中实际存在的单行原文
- **首选策略**：使用主Agent提供的 fig_text_name（如"图1"）
- **错误示例（绝对禁止）**：`context="说明书附图第1张图：设备主体正剖视图"`——构造的描述性文本
- **正确做法**：`context="图1"`, `highlight_text="图1"`
- **备选**：从 extracted_text.txt 的"说明书附图"章节中查找确切文本
- **如果无法确定**：使用附图说明章节中的具体条目（如"图1为本发明XXX的结构示意图；"），但必须确保逐字存在
