# 执行文书生成

## 概述

本技能覆盖执行立案阶段的**全链路**：从生效法律文书的信息提取，到三道合法性关口（时效、管辖、金额）的校验，再到全套文书的批量生成。

**格式保障**：文书生成使用 `fill_template.py`（与 `docx-template-filler` 技能共用），基于用户原始 .docx 模板替换 `[变量]` 占位符，**字体、字号、加粗、对齐、缩进全部保持原样**。模板使用与用户原始文件完全一致的宋体 12pt/14pt 格式。

> 💡 **推荐使用 DeepSeek V4 PRO 大模型运行本技能**，以获得最佳的法律推理和文书撰写效果。如当前未使用 DeepSeek 模型，建议在对话开始前切换。

## 适用场景

- 用户说「帮我准备执行立案材料」「生成执行文书」「申请强制执行」
- 前置条件：用户提供生效法律文书（判决书/裁定书/调解书等，.pdf/.docx/图片均可）

**第一问（委托材料）：是否一并生成委托合同等委托材料？**
> 💡 您是否需要生成**委托代理合同等委托全套材料**？
> - **如否**：跳过，直接生成上述执行文书（风险告知书、委托反馈表仍按固定模板自动渲染，列入文件清单第三部分自留，防遗漏）。
> - **如是**：请用户提供/上传委托所需信息：
>   1. 委托代理合同（模板或既往合同参考，否则按标准模板生成）；
>   2. **风险告知书**（固定模板自动渲染生成，无需用户提供，委托人签署后自留）；

> - 如涉公司：生成文书前**调用华宇元典（yuandian-mcp）**——通过案例检索（`yuandian_case_vector_search`）核查该公司的涉诉、被执行、失信情况；必要时配合法律检索（`yuandian_law_vector_search`）核对相关法条。核查结果并入案件事实与执行风险提示（如该公司已被列为被执行人/失信名单，可补充财产线索与执行策略建议）。
> - 如均为自然人：跳过核查，直接进入生成流程。

> ⚠️ 前置条件：调用元典需当前会话已连接 yuandian-mcp；未连接时向用户说明并询问是否需要连接，或按用户指定改用其他企业信息工具（如企查查/天眼查）。

用户确认后继续执行以下流程。

## 生成工作流程

### 第零步：上传判决文书，提取关键信息

从生效法律文书中自动提取：

| 提取项 | 用于 |
|--------|------|
| 文书类型、案号、作出机构 | 强制执行申请书 |
| 生效日期、履行期限 | 时效计算 |
| 申请执行人/被执行人姓名、身份信息 | 全部文书 |
| 案由 | 强制执行申请书 |
| 本金、利息条款（利率、起算日） | 利息计算 |
| 诉讼费用承担 | 执行金额汇总 |

---

### 第零步附带：生效时间确认（必须在时效计算前执行）

从判决书提取信息后，**立即向用户确认文书生效时间**。按以下三级规则确定（优先级递减）：

| 优先级 | 来源 | 规则 |
|--------|------|------|
| 1 | 律师提供 | 用户直接告知生效时间 → 以此为唯一依据，不再参考其他来源 |
| 2 | 邮件信息 | 用户未提供生效时间，但法院送达邮件（如诉讼信息中枢 `litigation-hub` 收录的法院通知邮件）中包含生效日期信息 → 以邮件信息为准 |
| 3 | 判决书计算 | 以上两项均无 → 按判决书上的日期依法推算 |

**向用户提问（必须执行）**：

> ⚠️ 请确认本案法律文书的**生效时间**：
>
> 从判决书中提取的信息如下：
> - 判决日期：XXXX年XX月XX日
> - 履行期限：XX日
>
> 请问文书的**生效时间**是？
> - 如您已知生效时间，请直接告知（如「2025年6月15日」）
> - 如不确定，是否有法院送达邮件可参考？
> - 如以上均无，我将按判决书依法推算

根据用户回答确定生效时间后，记录来源（律师提供 / 邮件信息 / 判决书推算），再进入下一步时效计算。

---

### 第一步：时效计算

根据《民诉法》第250条，三条规则（优先级递减）：
1. 文书规定履行期间的 → 自期间最后一日起算
2. 分期履行的 → 自最后一期届满日起算
3. 未规定履行期间的 → 自文书生效日起算

输出：起算点、届满日、当前状态（未超期/临界/已超期）。

如已超期或临界，检查中断事由（申请执行、和解、催告、同意履行）。

---

### 第二步：管辖校验

法院判决 → 一审法院，或同级被执行财产所在地法院。

输出：有管辖权法院列表 + 推荐排序。

---

### 第三步：金额计算

四段拆分：
1. 本金（判决书确定）
2. 一般债务利息（本金×天数×年利率÷360，截止履行期间届满日）
3. 加倍部分利息（本金×天数×0.000175，履行期间届满次日起算）
4. 诉讼费用

#### 利率处理：三种模式

根据判词写法自动选择，**无论判词多简单都能正确生成**：

| 判词示例 | 模式 | 处理方式 |
|---------|------|---------|
| 「按年利率 24% 计算」 | `fixed` | 固定利率，不分段 |
| 「按 LPR 计算」 | `LPR` | 按 LPR 变化节点自动分段，内置月度数据 |
| 「按同期银行贷款利率计算」 | `benchmark` | 2019.8 前按央行基准利率分段，2019.8 起按 LPR 分段 |

利率数据库覆盖 2006 年至今全时段，含 5 个期限档位（6M / 1Y / 1-3Y / 3-5Y / 5Y+），算法自动匹配。

> **LPR 数据更新（联网校验）**：内置利率库为静态维护（当前内置至 2026-06）。每月 20 日央行公布新一期 LPR 后，**无需改代码**，二选一即可同步，之后自动合并进计算：
> - `--sync-lpr`：联网尽力同步最新一期（官方页面多为 JS 动态渲染，可能失败，失败会提示改用手动方式）
> - `--set-lpr YYYY-MM-DD 1Y 5Y`：手动填入（离线可靠，**推荐**）。例：`--set-lpr 2026-07-20 3.00 3.50`
>
> 每次生成时脚本自动做**离线过期校验**：利率库末条距今天超过一个公布周期即提示同步。同步数据存于脚本同目录 `lpr_data.json`。

**固定利率**：
```bash
python3 scripts/generate_execution_interest.py <输出.xlsx> \
  --principal <金额> \
  --general-start <起始日> --general-end <截止日> \
  --general-rate <年利率> \
  --doubled-start <起始日> --doubled-end <截止日> \
  --submitter "<提交人>" --case-info "<案号>"
```

**LPR 自动分段**（判决书只写了「按 LPR」）：
```bash
python3 scripts/generate_execution_interest.py <输出.xlsx> \
  --principal <金额> \
  --general-start <起始日> --general-end <截止日> \
  --general-rate-type LPR \
  --doubled-start <起始日> --doubled-end <截止日> \
  --submitter "<提交人>"
```

**同期银行贷款利率**（判决书只写了「按同期银行贷款利率」）：
```bash
python3 scripts/generate_execution_interest.py <输出.xlsx> \
  --principal <金额> \
  --general-start <起始日> --general-end <截止日> \
  --general-rate-type benchmark \
  --doubled-start <起始日> --doubled-end <截止日> \
  --submitter "<提交人>"
```

> `--rate-term` 可指定利率档位（如 `--rate-term 1Y`），未指定时自动按期间长度选择。

输出为双 sheet Excel：「执行标的计算表」+「利率数据库」，所有计算列均为公式（可点击核验），利息 = 本金 × 天数 × 年利率 ÷ 360。

### 第四步：文书生成

#### 4.0 从已有文书创建模板（如用户上传的是成品而非模板）

如果用户上传了一份填好的 .docx 文件（如之前做过的强制执行申请书），而非带 `[变量]` 的模板，skill 会自动完成以下转换：

1. 将判决书已提取的信息与上传文件中的文字做匹配，生成候选替换映射：

```
张三            → [申请人姓名]
320123198001011234 → [申请人身份证号]
李四            → [被申请人姓名]
100,000           → [本金金额]
...
```

2. 展示映射表让用户确认（可增删改）
3. 调用 `create_template.py` 执行反向替换，生成模板 .docx
4. 模板存入当前会话，供本次和后续生成使用

命令：
```bash
python3 scripts/create_template.py 上传的文件.docx 模板.docx \
  --map '{"张三":"[申请人姓名]","李四":"[被申请人姓名]",...}'
```

#### 4.1 模板选择（用户自定义优先）

如果用户在第四步之前上传了自用的 .docx 模板，**直接使用用户上传的模板**。用户可上传全部 4 份模板，也可只上传其中某几份——未上传的文书使用技能内置默认模板。

替换逻辑：
- 用户上传 `强制执行申请书.docx` → 替代内置的 `强制执行申请书_模板.docx`
- 用户上传 `授权委托书.docx` → 替代内置的 `授权委托书_模板.docx`
- 未上传的文书 → 使用内置默认模板

生成时统一调用 `fill_template.py`：

```bash
python3 scripts/fill_template.py <模板.docx> <输出.docx> --vars '<JSON>'
```

#### 4.2 默认模板（首次运行时自动生成）

技能内置模板生成脚本，首次使用时自动在输出目录创建 .docx 模板文件：

```bash
python3 scripts/create_enforcement_template.py <输出目录>/强制执行申请书_模板.docx
python3 scripts/create_other_templates.py <输出目录>/
```

生成后模板文件：
- `强制执行申请书_模板.docx`
- `失信被执行人名单申请书_模板.docx`
- `限制消费申请书_模板.docx`
- `授权委托书_模板.docx` |

**授权委托书执行**：同一模板生成两份——
1. `06-1 授权委托书（承办律师版）.docx`：`律师姓名` 填承办律师姓名
2. `06-2 授权委托书（律所备用版）.docx`：`律师姓名` 传全角空格占位（如 `　　　　`），其余变量相同
生成命令两次调用 `fill_template.py`，输出文件名与文件清单 06-1/06-2 完全一致。

#### 4.3 传统格式排版规范（严格参照用户提供的模板）

用户提供了传统格式强制执行申请书模板（`references/docx-templates/强制执行申请书_用户模板.docx`）。**生成传统格式文书时，排版与字段顺序必须严格对齐该模板，不得自行发挥。**

**字段顺序（申请人/被申请人一致）**：
`姓名，性别，民族，出生（X年X月X日出生），居民身份证号码：XXXXXXXX，户籍所在地：XXXX`

**多被申请人排版铁律**：
- ❌ 禁止把多名被申请人姓名并排写在一行（如「被申请人：张三、李四、王五」）。
- ✅ 每名被申请人**独立成行**，每行以「被申请人：」开头，完整列出姓名、性别、民族、出生、身份证号、户籍所在地。
- 示例（5 人，示例数据均为虚构占位）：
  ```
  被申请人：耿某，男，汉族，1975年5月出生，居民身份证号码：320421197505XXXXXX，户籍所在地：××省××市××区××路××号；
  被申请人：朱某，女，汉族，1948年9月出生，居民身份证号码：320219194809XXXXXX，户籍所在地：××省××市××镇××村××号；
  ……
  ```
- 联系方式字段：仅当判决书/用户提供时填写，无数据则不写（不要留空占位）。

> 多被申请人排版落地方式：`fill_template.py` 替换前，先对模板做段落扩展——将「被申请人：[被申请人姓名]，[被申请人身份信息]」段替换为每人独立段落（复制原段格式，每行以「被申请人：」开头），再执行变量替换（`[被申请人姓名]` 保留为名单用于正文叙述）。

**强制执行申请书变量**：

| 变量 | 说明 |
|------|------|
| `申请人姓名`、`申请人身份信息` | 含性别、民族、出生日期、身份证号、户籍所在地（见 4.3 格式） |
| `被申请人姓名`、`被申请人身份信息` | 含性别、民族、出生、居民身份证号码、户籍所在地（按 4.3 字段顺序，分人列出） |
| `本金金额`、`利息起算日`、`年利率`、`利息暂算日`、`利息暂算金额` | 利息相关 |
| `加倍利息起算日`、`加倍利息暂算日`、`加倍利息暂算金额` | 加倍利息相关 |
| `合计金额` | 本金+一般利息+加倍利息（不含诉讼费） |
| `案由`、`作出机构`、`案号`、`文书类型` | 案件信息 |
| `履行期限`、`诉讼费金额` | 判决确定 |
| `管辖法院全称`、`year` | 管辖+签署年 |

**失信/限消申请书变量**：

| 变量 | 说明 |
|------|------|
| `申请人姓名`、`申请人身份信息` | 同强制执行申请书 |
| `被申请人姓名`、`被申请人身份信息` | 同强制执行申请书 |
| `管辖法院全称`、`year` | 管辖+签署年 |

**授权委托书变量**（同一模板生成两份：06-1 承办律师版 / 06-2 律所备用版）：

## 核心规则

- 当事人称谓：执行阶段用「申请人」/「被申请人」
- 时效：2 年，起算规则三条
- 利息：一般债务利息（本金×天数×年利率÷360）+ 加倍部分（本金×天数×0.000175）
- 利率模式：`fixed`（判词写固定利率）/ `LPR`（判词写 LPR，自动分段）/ `benchmark`（判词写同期银行贷款利率，跨 LPR 制度自动切换）
- 利率数据库：内置 2006 至今完整数据（含央行基准利率 + LPR，5 个期限档位），并可经 `--set-lpr` / `--sync-lpr` 合并外置 `lpr_data.json` 自动更新；按利率变化节点自动拆分期间，相邻同利率段合并；每次生成自动做离线过期校验
- 文书一致性：所有文书中人名/案号/金额严格一致

## 排版与字体铁律（2026-08-22 沉淀）

1. **字体统一（三通道 + docDefaults 兜底）**：
   - 所有 run 显式设置宋体三通道：`w:ascii` / `w:hAnsi` / `w:eastAsia` 均为「宋体」。**新建/改写的段落**（多被申请人行、请求事项改写段、事实理由段、授权委托书联系方式）创建 run 时必须立即锁宋体，禁止留空继承——否则回退系统默认字体，与宋体正文混排成"字体不对"。
   - **docDefaults 锁宋体（一劳永逸）**：生成完成后统一修改 styles.xml 的 docDefaults → rPrDefault → rFonts，显式设 ascii/hAnsi/eastAsia=宋体，并**清除主题字体引用**（`asciiTheme`/`hAnsiTheme`/`eastAsiaTheme`/`cstheme`）。否则编辑器（editor_sdk 等）后续插入的新文本会回退主题默认字体（典型现象：插入的电话/备注不是宋体）。
   - Mac 兼容：本机无 Windows「宋体(SimSun)」，docx 中「宋体」打开时自动回退「宋体-简」（Songti.ttc，/System/Library/Fonts/Supplemental/），字形一致，**不影响打印与提交**；如需与 Windows 完全一致须另装 SimSun。
2. **「被申请人」加粗规则**：仅当事人信息行（段落以「被申请人：」开头）中的「被申请人」4 字加粗；正文（请求事项、事实与理由、失信/限消正文叙述）中的「被申请人」**一律不加粗**。
3. **授权委托书联系方式**：`律师联系方式行` 变量填 `，联系方式：<电话>`（前导逗号+空格），无电话则留空，模板已处理。

## 多笔本金计算表（2026-08-22 沉淀）

`generate_execution_interest.py` CLI **仅支持单本金、单段一般利息**（`--principal` 单值 + 单 `--general-start/end`）。判决书含多笔本金（多张借条、各自起算日、同利率）时：

- ❌ 禁止把多笔本金合并成一个 `--principal` 估算
- ✅ 自定义多本金版：`import generate_execution_interest as gei` 复用其样式常量（`TITLE_FONT`/`SECTION_FONT`/`HEADER_FILL`/`_set_cell`/`_build_rate_db_sheet` 等），自行构造 workbook：
  - 一般债务利息明细：**每笔本金一行**（本金 / 起算日 / 截止日 / 年利率 / 利息公式 `=B{r}*(D{r}-C{r}+1)*E{r}/360`），小计 `=SUM(...)`
  - 加倍部分基数 = 本金合计（判决确定的金钱债务总额，不含利息/诉讼费）
  - 合计 = 本金汇总 + 一般利息小计 + 加倍利息小计
- **利息被驳回案件**（判词"利息部分不予支持"）：一般债务利息整段置 0（`general_periods=[]`，rate_type 传 `fixed`）；强制执行申请书请求事项**删除利息项**，事实理由注明"一审判决已驳回利息主张"；要素式申请执行事项填「一般债务利息：0 元」并注明驳回原因。

## 生效时间推算与利息起算（2026-08-22 补充）

- 一审判决无送达信息时：**推算生效日 = 判决作出日 + 15 日上诉期届满次日**；文书中生效日期须标注"（推算）"，并提示用户以送达回证/生效证明为准（实际送达晚于推算日时，履行期与加倍利息起算日相应顺延）。
- 履行期"生效之日起十日"：生效日当日不计入（期间起算日不计算），自次日起算 10 日；**加倍部分利息自履行期届满之次日起算**。
- 申请执行时履行期尚未届满：加倍利息暂算金额为 0（计算表注明起算日与届满日），文书中如实体现，并提示用户届满后再行提交。
- 暂算日 = 申请执行之日；计算表所有计算列为 Excel 公式（可点选改日期自动更新金额）。

## editor_sdk 协作经验（2026-08-22 沉淀）

文书生成后如需在预览面板实时编辑（`tencent-local-office-edit` skill）：

- `open_file` 返回的 `file_id` 即**文件路径**（非 UUID）；已用 `present_files` 打开的文档用 `get_pool_status` 按路径匹配拿 `file_id`，不要重复 open。
- ⚠️ 批量 open 多个文件后逐个编辑并 `save_file`，**偶发"返回 ok 但未落盘"**（坐标基于旧实例/实例冲突，典型症状：验证时改动不存在）。**每次 save 后必须重新读文件验证**；不通过则改用 python-docx 直接写入该文件。
- 编辑后坐标漂移：连续操作前重新 `doc_find`，坐标来自查询结果，禁止手算。
- `doc_insert_text` 插入的新 run 无显式字体 → 靠 docDefaults 锁宋体兜底（见字体铁律），或 `doc_update_text_property` 设 `font_family=宋体`。
- 操作工具前必须 `edsdk.py schema <工具名>` 查必填项，禁止凭子文档一句话摘要拼参数。
