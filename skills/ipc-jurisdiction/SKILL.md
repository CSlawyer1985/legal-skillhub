# 信息网络传播权纠纷 · 一审管辖判定

## 核心纪律：管辖不靠推理，靠查表

**绝对禁止凭记忆或推理直接回答管辖问题。** 级别管辖门槛逐省不同、法院辖区划分是纯事实数据、管辖规则近年频繁调整——模型对这三类信息的记忆都不可靠，一旦答错，代价是立案被退或案件被移送，损失几个月。

所有结论必须由 `scripts/jurisdiction.py` 查表算出。本 skill 中模型的职责是三件事，不含第四件：

1. 从案件材料里**抽取**连接点参数
2. **运行**引擎
3. **解读**输出、起草文书

不包括「自己算一遍管辖」。

## 时效分水岭：2025-11-01

自 2025-11-01 起，**涉网络著作权纠纷不再由互联网法院管辖**，回归普通基层法院按知识产权案件集中管辖分工审理。

依据是《最高人民法院关于互联网法院案件管辖的规定》（法释〔2025〕14号）：第一条列举的九类案件中已不含著作权、邻接权；第四条规定「本规定施行前已经受理的案件由原受理人民法院继续审理」「此前发布的司法解释与本规定不一致的，以本规定为准」。

- 该日之后受理的信网权案件：不要再考虑北京/广州/杭州互联网法院
- 该日之前已受理的：由原受理法院继续审理，不受影响
- 判断标准是**案件受理时间**，不是侵权行为发生时间

引擎已按新规则实现，不会输出互联网法院。若用户手上有该日之前的旧案或旧文书，据此解释差异。

## 适用范围

**适用**：影视、音乐、图文、短视频等作品的信息网络传播权侵权一审民事案件。

**不适用，需另行判断**：计算机软件著作权案件（属技术类，归知产法院/中院）、专利商标不正当竞争案件、不涉网络传播的著作权权属纠纷、二审再审执行管辖。

## 工作流

### 1 抽取连接点

从被告工商信息、侵权页面公证书、起诉状草稿等材料中提取：

| 参数 | 来源 | 缺失时 |
|---|---|---|
| 被告住所地（省/市/区县） | 工商登记地址、ICP 备案主体地址 | **必需**，缺失则中止并向用户索取 |
| 诉讼请求标的额（元） | 起诉状诉请金额合计 | 必需，决定级别管辖 |
| 服务器/设备所在地 | 备案信息、IP 归属、公证书记载 | 跳过该通道 |
| 原告住所地/发现地 | 委托人信息、取证地 | 跳过兜底通道 |
| 被告是否在境外/无法确定 | 域名 whois 隐私保护、境外主体 | 默认否 |
| 是否涉外或涉港澳台 | 当事人身份 | 默认否 |

地址只到「市」也能跑，但可能落在多个分片法院之间而无法锁定。**能拿到区/县就一定要拿**。

### 2 运行引擎

```bash
python scripts/jurisdiction.py --def-prov 浙江省 --def-city 杭州市 --def-district 西湖区 --amount 800000 --text
```

可选参数：`--server-prov/--server-city/--server-district`（服务器所在地）、`--pl-prov/--pl-city/--pl-district`（原告发现地）、`--def-abroad`（被告或侵权行为地在境外/无法确定）、`--foreign`（涉外或涉港澳台）。

默认输出 JSON 便于程序处理，`--text` 输出人类可读格式。改动脚本或数据后运行 `--selftest` 验证（含 19 条回归用例）。

### 3 解读输出

引擎给每个方案标 `confidence`，**必须原样转达，不得省略**：

- **medium** — 数据有明确出处，可作为立案依据；仍建议立案前拨 12368 确认当期口径
- **low** — 数据为推定值或未能锁定法院，只能作方向性参考，必须明确告知用户

`precise: false` 表示未锁定到唯一法院，绝不能在文书里写死法院名。`warnings` 数组每一条都要转达。

结论中出现「知识产权案件实行集中管辖，某某市无独立知产管辖法院」时，要向用户解释：这不是数据缺失，而是制度设计——并非每个基层法院都有知产管辖权，一个地级市通常只有一到两家集中管辖。

### 4 产出

按用户需要选择：

- **管辖方案对比**：列出全部可选通道，标注各自的异议风险，给出推荐并说明理由
- **起诉状管辖依据段落**：见 `references/templates.md`
- **立案预案**：法院可能提出的质疑及应对
- **管辖权异议申请书**：见下

## 数据来源与已知风险

**辖区名单**：《最高人民法院关于印发基层人民法院管辖第一审知识产权民事、行政案件有关事项的通知》（法〔2025〕167号，2025-09-23 发布，**2025-10-01 施行**）附件，31 省 570 家**有知识产权管辖权的**基层法院。注意收录口径是知产集中管辖法院，不是全部基层法院。

**标的额标准**：同一份附件，表列「民事案件诉讼标的额（**不含本数**）」。京沪不受标的额限制；苏浙豫鄂津琼渝 500 万；广东两档（广深佛莞中珠惠肇江 9 市 1000 万、其他区域 500 万）；其余多为 100 万。

「不含本数」意味着标的额正好等于门槛时归中级法院，引擎按严格小于判断。

**法〔2022〕109号已被法〔2025〕167号废止**，不得再援引；但 167 号规定「本通知施行前已经受理的案件，仍按照原标准执行」，处理跨期旧案时需注意。

**行政区划归位**：内置 27 省 2962 个县级→地级市映射（源：modood/Administrative-divisions-of-China）。用于把「开原市」这类县级市归位到「铁岭市」再定位集中管辖法院。

**已知风险，必须向用户披露**：

1. **数据系附件表格图片识别所得**（附件无文字层），存在识别错误可能。关键案件建议抽查核对原附件。
2. 各省高院可能另发细化文件，本表未必覆盖。

元数据见 `data/provinces.json` 的 `cap_status` 与 `cap_source`。31 个省级行政区的标的额门槛均已核对附件原文，`cap_status` 全部为 `sourced`，无推定值。

## 反向用法：被告方管辖异议

同一套规则反过来用，审查原告选的法院站不站得住：

1. **级别管辖**：标的额是否达到该省中院门槛？原告是否为拉低级别而故意少报诉请？
2. **互联网法院**：2025-11-01 后原告仍告到互联网法院的，可主张该院已无管辖权
3. **知产法院**：原告把信网权案件告到知识产权法院的，可主张该院无管辖权（软件案件除外）
4. **集中管辖**：原告告到无知产管辖权的基层法院的，可主张应移送集中管辖法院
5. **侵权行为地**：原告主张服务器在本地的，要求其举证；举证不能则该连接点不成立
6. **原告发现地**：这是兜底条款，只在被告住所地和侵权行为地**均**无法确定时才能用。原告已知被告住所地却主张发现地的，异议成立率高

异议须在**提交答辩状期间内**（收到起诉状副本之日起十五日内，涉外三十日）提出，逾期视为接受管辖。该期限为不变期间，提示用户立即入日程。

## 法条纪律

写进法院提交文本的法条，必须核验原文后再引用，不得凭记忆写条号。可用的核验渠道：国家法律法规数据库（flk.npc.gov.cn）、中国裁判文书网、所在单位订阅的法律数据库，或所内已接入的法规检索工具。

本 skill 内置的法条引用均已核验原文，条文见 `data/special_courts.json` 的 `key_text` 与 `references/legal-basis.md`。

两点易错处：其一，知产法院管辖规定的现行版本是 2020 年修正版，**旧文号法释〔2014〕12号已被修改，不得再引用**；其二，「法释〔2020〕19号」是 2020-12-29 一个修正决定的文号，同时对应多部被修正的司法解释，写入文书时应写全规定名称，仅附文号易生歧义。
