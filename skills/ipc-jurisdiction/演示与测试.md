## 演示一 · 常规案件

**场景**：被告公司住所地在杭州市西湖区，诉请赔偿 80 万元。

```bash
python scripts/jurisdiction.py --def-prov 浙江省 --def-city 杭州市 --def-district 西湖区 --amount 800000 --text
```

```
信息网络传播权纠纷 · 一审管辖分析
整体置信度：中

方案 1 · 被告住所地
  法院：杭州市西湖区人民法院（基层人民法院）
  依据：被告住所地人民法院管辖（《最高人民法院关于审理侵害信息网络传播权民事
        纠纷案件适用法律若干问题的规定》（法释〔2020〕19号）第15条）。
        标的额 80万元 ＜ 本地基层受理上限 500万元，由基层法院管辖
  定位：已按“西湖区”定位（该院辖区含：西湖区）
  策略：最稳妥通道，管辖异议风险最低。
  置信度：中

本结论由查表计算得出。标的额门槛与辖区名单均据法〔2025〕167号附件（2025-09-23
发布，2025-10-01 施行；同时废止法〔2022〕109号）。各省数据的出处见
data/provinces.json。立案前应复核标的法院当期立案口径。
```

**说明**：结论同时给出了法院、级别管辖的算式（80 万 < 500 万）、法条依据和辖区匹配过程。律师可以逐项复核，而不是只看到一个法院名。

## 演示二 · 县级市被告，知产集中管辖归位

**场景**：被告住所地在辽宁省开原市（县级市），诉请 50 万元。

```bash
python scripts/jurisdiction.py --def-prov 辽宁省 --def-city 开原市 --amount 500000 --text
```

```
方案 1 · 被告住所地
  法院：铁岭市银州区人民法院（基层人民法院）
  依据：被告住所地人民法院管辖（法释〔2020〕19号第15条）。
        标的额 50万元 ＜ 本地基层受理上限 100万元，由基层法院管辖
  定位：“开原市”属铁岭市，已按“铁岭市”定位（该院辖区含：铁岭市）。知识产权
        案件实行集中管辖，“开原市”无独立知产管辖法院，由所属铁岭市的集中管辖
        法院受理
  策略：最稳妥通道，管辖异议风险最低。
  置信度：中
```

**说明**：这是最容易出错的一类情形。开原市有自己的人民法院，但**没有知识产权案件管辖权**——知产案件实行集中管辖，一个地级市通常只指定一到两家基层法院。程序内置 2962 个县级单位的归属映射，自动完成"开原市→铁岭市→集中管辖法院"的两级推导，并在输出中说明推导过程，避免使用者误以为定位失败。

## 演示三 · 标的额升至中院，排除知产法院

**场景**：被告在苏州市虎丘区，诉请 800 万元。

```bash
python scripts/jurisdiction.py --def-prov 江苏省 --def-city 苏州市 --def-district 虎丘区 --amount 8000000 --text
```

```
方案 1 · 被告住所地
  法院：苏州市中级人民法院（中级人民法院）
  依据：被告住所地人民法院管辖（法释〔2020〕19号第15条）。
        标的额 800万元 ≥ 本地基层受理上限 500万元，由中级法院管辖
  定位：中院为 苏州市中级人民法院
  策略：最稳妥通道，管辖异议风险最低。
  置信度：中（未锁定到唯一法院）

!! 风险提示
  · 信息网络传播权侵权民事案件不属知识产权法院管辖范围，达到中院级别标准的
    应向普通中级人民法院起诉（计算机软件著作权案件除外）
```

**说明**：两个细节值得注意。

其一，程序主动提示"不属知识产权法院管辖范围"。实务中容易想当然地认为知识产权案件升到中院就该去知识产权法院，但知产法院管辖的是技术类案件与相关行政案件，著作权侵权民事案件（软件除外）不在其列，误诉会被裁定不予受理或移送。

其二，中院名称是由地级市名推导而非查表得出，因此标注"未锁定到唯一法院"。程序对"推导所得"与"查表所得"作了区分，不把推导结果伪装成确定结论。

## 演示四 · 境外被告，多通道对比

**场景**：盗版站被告主体在境外、服务器所在地不明，域名注册信息处于隐私保护状态。原告在杭州市上城区取证。被告国内关联主体住所地在温州市瓯海区，诉请 30 万元。

```bash
python scripts/jurisdiction.py --def-prov 浙江省 --def-city 温州市 --def-district 瓯海区 \
  --amount 300000 --def-abroad --pl-prov 浙江省 --pl-city 杭州市 --pl-district 上城区 --text
```

```
方案 1 · 被告住所地
  法院：温州市瓯海区人民法院（基层人民法院）
  策略：最稳妥通道，管辖异议风险最低。
  置信度：中

方案 2 · 原告发现地（兜底）
  法院：杭州铁路运输法院（基层人民法院）
  依据：被告住所地与侵权行为地均难以确定或在境外的，原告发现侵权内容的计算机
        终端等设备所在地可以视为侵权行为地（法释〔2020〕19号第15条后段）。
        标的额 30万元 ＜ 本地基层受理上限 500万元，由基层法院管辖
  定位：已按“上城区”定位（该院辖区含：上城区）
  策略：适用前提严格：须确实无法确定被告住所地和侵权行为地，否则极易被裁定移送。
  置信度：中
```

**说明**：程序列出全部可用通道供律师选择，同时对兜底通道标注严格的适用前提。原告发现地是有条件的兜底条款，只在被告住所地与侵权行为地**均**无法确定时才能适用；已知被告住所地却主张发现地的，被裁定移送的风险很高。程序不替律师作策略选择，但把每条通道的风险讲清楚。

## 演示五 · 关键参数缺失时主动降级

**场景**：律师只提供了被告地址，忘了填诉讼请求标的额。

```bash
python scripts/jurisdiction.py --def-prov 浙江省 --def-city 杭州市 --def-district 西湖区 --text
```

```
信息网络传播权纠纷 · 一审管辖分析
整体置信度：低

方案 1 · 被告住所地
  法院：杭州市西湖区人民法院（基层人民法院）
  依据：被告住所地人民法院管辖（法释〔2020〕19号第15条）。未提供有效的诉讼
        请求标的额，级别管辖无法判定
  定位：已按“西湖区”定位（该院辖区含：西湖区）
  策略：最稳妥通道，管辖异议风险最低。
  置信度：低

!! 风险提示
  · 未提供标的额（或填了非正数），无法判断本案应由基层还是中级人民法院管辖。
    下方法院仅为地域管辖的结果，补充标的额后必须重新判定。
```

**说明**：标的额是级别管辖的唯一决定因素。早期版本在标的额缺失时会静默按 0 计算，输出一个看似正常的「基层人民法院」结论——**本该由中院管辖的案件会被悄悄判成基层**，而使用者无从察觉。

现在的处理是：地域管辖的结果照常给出（这部分不依赖标的额），但级别管辖明确标注「无法判定」，整体置信度降为「低」，并要求补充后重新判定。

**宁可说"这里我不确定"，也不给一个错误的精确答案**——这是本作品在可靠性上的基本立场，也是与"让 AI 直接回答管辖问题"最本质的区别。

判定逻辑由脚本承担，与调用它的模型无关，因此结论在各平台完全一致。**本作品可完整运行于国产智能体与国产大模型之上。**

每条用例都对应一个曾经出错或容易出错的实际情形。例如关于法院名称的两条：中国有大量以"州"字结尾的普通地级市（苏州、温州、常州、湖州、台州、郑州、福州等），其中院名称应为"××市中级人民法院"；而自治州、盟、地区的中院名称不含"市"（如延边朝鲜族自治州中级人民法院）。早期版本按单字"州"判断，会把"苏州市中级人民法院"错写成"苏州中级人民法院"。这类错误在文书中足以引起退案，但肉眼极易忽略——固化为回归用例后，任何后续修改都不会再让它复现。

修改数据或代码后应重新运行本测试。
