## 一、这个 Skill 解决什么问题

信息网络传播权（下称"信网权"）案件的一审管辖，需要同时判断三件事：

1. **地域管辖**——被告住所地、侵权行为地、原告发现地，三个连接点各有适用条件
2. **级别管辖**——标的额是否超过本省基层法院受理知产案件的上限，各省标准不同
3. **集中管辖**——并非每个基层法院都有知识产权管辖权，一个地级市通常只有一到两家

判断错了的代价是实打实的：立案被退回、案件被裁定移送，一个批量维权项目可能因此拖延数月。而这三件事依赖的都是**事实性数据**——各省标的额门槛、570 家法院的辖区名单、2962 个县级行政区的归属关系——恰恰是人脑和大语言模型都记不准的东西。

本 Skill 把这部分工作交给确定性程序，让 AI 只做它擅长的事。

## 二、核心设计：AI 不算管辖，只抽参数和解读

这是本作品最重要的设计决策，也是它区别于"让 AI 直接回答管辖问题"的根本所在。

```
案件材料（工商信息/公证书/起诉状草稿）
        ↓  AI 负责：抽取连接点参数
   省 / 市 / 区县 / 标的额 / 是否涉外
        ↓  程序负责：确定性查表计算  ← 不经过模型
   管辖方案 + 法律依据 + 置信度 + 风险提示
        ↓  AI 负责：解读输出、起草文书
   方案对比 / 起诉状管辖段落 / 管辖权异议申请书
```

**为什么这样设计**：大语言模型对"辽宁省基层法院受理知产案件的标的额上限是多少"这类问题会给出流畅但不可靠的答案，且错误无法从输出中察觉。把判定环节固化为查表程序后，同样的输入永远得到同样的、可追溯到具体文件的结论；模型即使理解偏差，也只影响参数抽取，而参数是可以让律师肉眼复核的。

SKILL.md 中将此写为第一条纪律：**绝对禁止凭记忆或推理直接回答管辖问题**。

## 三、怎么用

### 导入

把整个目录放入所用智能体的 `skills/` 目录即可，无需其他配置。

### 对话中使用

直接用自然语言提问：

- "被告在温州瓯海，诉请 30 万，这个案子告到哪个法院？"
- "对方把我们告到 XX 法院，管辖有没有问题？要不要提管辖异议？"
- "标的额多少要上中院？"

也可以直接把被告工商信息、侵权公证书发给 AI，由它抽取参数后调用引擎。

引擎也可脱离 AI 单独运行：

```bash
python scripts/jurisdiction.py --def-prov 浙江省 --def-city 杭州市 --def-district 西湖区 --amount 800000 --text
```

验证安装是否正常：`python scripts/jurisdiction.py --selftest`（19 条回归用例）。

### 已实测的智能体平台

本作品采用 `SKILL.md` + 脚本 + 数据的结构。该结构已是国产 CLI 智能体的通行格式——例如字节 Trae 的内置技能即为 `SKILL.md` 加 YAML frontmatter 的同一形态。

将本目录放入下列任一智能体的 `skills/` 目录后，均实测可正常加载并运行（各平台 19 条回归用例全部通过）：

| 智能体 | 归属 | 实测结果 |
|---|---|---|
| 通义千问 Code | 阿里巴巴 | 19/19 通过 |
| 心流 iFlow | 心流 | 19/19 通过 |
| Trae | 字节跳动 | 19/19 通过 |
| CodeBuddy | 腾讯 | 19/19 通过 |
| Codex | OpenAI | 19/19 通过 |
| Claude Code | Anthropic | 19/19 通过 |

其中**前四者为国产智能体**，可搭配国产大模型使用。

**这意味着本作品可完全运行在国产智能体与国产大模型之上**，判定过程与数据均不出本地，不依赖境外服务。

多个智能体共用同一份技能时，可将技能目录集中存放（如 `~/.agents/skills/`），再从各智能体的 `skills/` 目录建立链接，一处更新、多端生效。

### 运行环境说明

| 项目 | 说明 |
|---|---|
| 依赖 | Python 3.6+，仅用标准库，**无需 pip 安装任何包** |
| macOS / Linux | 系统自带 Python 3，命令用 `python3` |
| Windows | 系统不自带 Python，需从 python.org 安装；安装后命令用 `python`（Windows 上没有 `python3` 命令） |
| 终端中文显示 | 已适配：终端场景按终端编码输出，管道场景强制 UTF-8，Windows 默认 GBK 代码页下不会乱码 |
| 网络 | 全程离线运行 |

### 关于纯云端智能体平台

扣子、文心智能体等云端平台通常只提供系统提示词、知识库检索与预置插件，不能执行本地脚本。本作品的确定性引擎在这类平台上无法原样运行，两种折中各有代价：把引擎部署为在线接口会使案件参数离开本地，牺牲数据安全；改由模型读知识库自行查表则牺牲确定性，而确定性正是本作品要解决的问题。

因此本作品定位于可执行本地脚本的智能体。如赛事技术文档对云端平台有明确要求，可在保留现有版本的前提下另行适配。

完整演示见 `演示与测试.md`。

## 五、数据来源与已知局限

**数据来源全部为公开司法文件**：

- 法院辖区名单：《最高人民法院关于印发基层人民法院管辖第一审知识产权民事、行政案件有关事项的通知》（法〔2025〕167 号，2025-09-23）附件
- 标的额标准：同上附件，表列「民事案件诉讼标的额（不含本数）」（授权依据：法发〔2010〕5 号第三条）
- 地域管辖规则：法释〔2020〕19 号第 15 条
- 互联网法院排除：《最高人民法院关于互联网法院案件管辖的规定》（法释〔2025〕14 号）第一条、第四条
- 知产法院排除：《关于北京、上海、广州知识产权法院案件管辖的规定（2020修正）》第一条；法释〔2022〕13 号第一条
- 行政区划：开源数据集 modood/Administrative-divisions-of-China

**已知局限，使用者必须知悉**：

1. **辖区数据系 PDF 视觉识别所得**。法〔2025〕167 号附件为网页打印版，表格无文字层，数据通过逐页渲染识别获得，存在识别误差可能。关键案件建议抽查核对原附件。
2. **法〔2022〕109 号已废止**，不得再作为标的额依据援引。法〔2025〕167 号自 2025-10-01 施行时将其废止，并规定「本通知施行前已经受理的案件，仍按照原标准执行」——处理跨期旧案时需注意区分。
3. **各省高院可能另发细化文件**，本表未必覆盖。

程序对上述不确定性的处理方式是**主动降级并告警**，而非给出看似确定的答案。数据为推定值或未能锁定唯一法院时，输出 `confidence: low` 和 `precise: false`，SKILL.md 要求 AI 必须原样转达、不得省略。

**宁可说"这里我不确定"，也不给一个错误的精确答案**——这是本作品在可靠性上的基本立场。

## 六、合规与数据安全

| 项目 | 说明 |
|---|---|
| 数据外传 | 无。判定全部为本地计算，不调用任何外部接口 |
| 案件信息留存 | 无。程序不写入任何日志或缓存文件 |
| 内置数据 | 仅公开司法文件与开源行政区划数据，不含任何案件信息、当事人信息或办案经验参数 |
| 第三方依赖 | 无。仅使用 Python 标准库 |
| 网络访问 | 无 |

传入程序的仅为"省/市/区县/金额"等地理与数额参数，不涉及当事人姓名、案情或证据内容。使用者向 AI 提交案件材料时的数据边界，仍应遵守所在单位的 AI 使用规范与律师保密义务。

## 七、可推广性

**同类场景直接复用**：本 Skill 的架构不限于信网权。凡"结论依赖分散的事实性数据、算错有实质代价"的法律场景，都可以套用同一套做法——把判定固化为查表程序，AI 只做参数抽取与结果解读。例如：

- 诉讼时效与各类不变期间的计算
- 各地劳动争议仲裁时效与前置程序判断
- 各省法定赔偿裁量区间的检索

替换 `data/` 下的数据文件与 `scripts/` 中的判定规则即可，SKILL.md 的纪律部分与置信度机制可直接沿用。

**本 Skill 自身的迁移**：其他类型的知识产权案件（商标、专利、不正当竞争）管辖判断，与本作品共用同一套法院辖区与级别管辖数据，只需替换地域管辖规则即可扩展。

**平台兼容性**：判定逻辑完全由 Python 脚本承担，不依赖特定模型的能力或特定平台的专有接口——模型换成任何一家的都不影响结论。已实测可在通义千问 Code、心流 iFlow、字节 Trae、腾讯 CodeBuddy、Codex、Claude Code 六个智能体中加载运行，其中四者为国产（详见第三节）；脱离 AI 环境后，判定引擎也可作为独立命令行工具直接使用。
