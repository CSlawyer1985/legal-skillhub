# PCI DSS v4.0.1——全部 12 项要求

来源：PCI DSS v4.0.1（PCI 安全标准委员会，2024 年 6 月）
https://www.pcisecuritystandards.org/document_library/

## 目标 1：构建并维护安全的网络和系统

### 要求 1——安装并维护网络安全控制

网络安全控制（NSC）——防火墙、路由器、云安全组——防止对持卡人数据环境（CDE）及来自 CDE 的未经授权网络访问。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 1.1 | 定义、实施并维护 NSC 政策和程序 | 政策文件、网络拓扑图、变更记录 |
| 1.2 | NSC 配置将流量限制在必要范围内 | 防火墙/路由器规则集审查、默认全部拒绝 |
| 1.2.1 | 定义 NSC 配置标准 | 记录在案的基线标准 |
| 1.2.2 | NSC 配置变更通过变更控制管理 | 变更工单、审批记录 |
| 1.2.3 | 网络拓扑图是最新且准确的 | 注明日期的、显示 CDE 边界的网络拓扑图 |
| 1.2.4 | 所有账户数据流的数据流图是最新的 | 数据流图（DFD） |
| 1.2.5 | 所有允许的服务/端口均有记录并附业务理由 | 防火墙规则文档 |
| 1.2.6 | 每项服务的安全功能均有记录并已实施 | 每项服务的配置基线 |
| 1.2.7 | NSC 配置至少每 6 个月审查一次 | 含日期和审批人的审查记录 |
| 1.3 | 入站和出站网络流量限制在必要范围内 | 出站过滤、其余一律拒绝规则 |
| 1.3.1 | 进入 CDE 的入站流量限制在经授权的来源和服务 | 已审查的防火墙规则 |
| 1.3.2 | 来自 CDE 的出站流量限制在经授权的目的地 | 记录在案的出站规则 |
| 1.3.3 | 在无线网络和 CDE 之间安装 NSC | 无线到 CDE 的防火墙规则 |
| 1.4 | 受信任与不受信任网络之间的连接受控 | DMZ 架构、流量检查 |
| 1.4.1 | 受信任/不受信任网络之间的 NSC 检查并过滤流量 | 状态检测、IDS/IPS |
| 1.4.2 | 来自不受信任网络的入站流量：不得直接路由到 CDE | 无直接路由；必须经代理/DMZ |
| 1.4.3 | 反欺骗措施以检测并阻止伪造的源 IP 地址 | 反欺骗 ACL、RFC 3704 过滤 |
| 1.4.4 | 未经授权的流量（持卡人数据）被阻止进入不受信任网络 | DLP 规则或网络控制 |
| 1.4.5 | 内部 IP 地址不向未经授权方披露 | NAT、私有 RFC 1918 地址空间 |
| 1.5 | 设备连接不受信任网络的风险得到管理 | 端点安全控制 |
| 1.5.1 | 同时连接不受信任和受信任网络的设备的安全控制 | MDM/端点策略、拆分隧道控制 |

**常见缺口**：过期的防火墙规则从未审查；无出站过滤；扁平网络（无 CDE 隔离）；无线网络未与 CDE 分离。

### 要求 2——对所有系统组件应用安全配置

部署前必须消除默认凭据和不必要的服务。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 2.1 | 管理供应商默认值和其他安全参数的流程 | 加固策略、配置标准 |
| 2.2 | 制定并实施系统配置标准 | CIS 基准或等效标准；各平台标准 |
| 2.2.1 | 系统配置标准解决所有已知安全漏洞 | 与标准对应的漏洞扫描结果 |
| 2.2.2 | 在部署系统前管理供应商默认账户 | 禁用/重命名默认凭据；删除证据 |
| 2.2.3 | 需要不同安全级别的主要功能位于独立组件上 | 服务器隔离、角色分离 |
| 2.2.4 | 仅启用必要的功能、端口、协议和服务 | 端口扫描结果；服务审计 |
| 2.2.5 | 如使用不安全协议，记录业务理由和附加控制 | 协议例外日志 |
| 2.2.6 | 系统安全参数配置为防止滥用 | 配置加固证据 |
| 2.2.7 | 所有非控制台管理访问均加密 | 所有管理访问使用 SSH、HTTPS、TLS |
| 2.3 | 无线环境安全配置和管理 | Wi-Fi 配置审查、WPA3 或 WPA2-Enterprise |
| 2.3.1 | 安装时更改默认无线供应商默认值 | AP 配置记录 |
| 2.3.2 | 当知晓密钥的人员离职时更换无线加密密钥 | 密钥轮换程序和证据 |

**常见缺口**：供应商默认密码未更改；不必要服务（Telnet、FTP）仍启用；无记录在案的加固标准。

## 目标 2：保护账户数据

### 要求 3——保护存储的账户数据

尽量减少账户数据的存储；授权后绝不存储 SAD；在一切存储位置保护 PAN。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 3.1 | 定义并实施保护存储账户数据的流程 | 数据留存政策 |
| 3.2 | 账户数据存储最小化 | 数据留存计划；删除程序 |
| 3.2.1 | 授权后不保留 SAD | 证明存储中无 SAD 的扫描结果；代码审查 |
| 3.3 | 授权后不保留 SAD | 通过系统扫描和应用审查确认 |
| 3.3.1 | 不存储 SAD（完整磁条、CAV2/CVV2/CVC2/CID、PIN/PIN 块） | 应用代码审查；数据库扫描 |
| 3.3.2 | 授权前存储的 SAD 已加密 | 授权前数据的加密证据 |
| 3.3.3 | 授权前 SAD 的加密密钥安全管理 | 密钥管理文档 |
| 3.4 | PAN 在一切存储位置受保护 | 加密、掩码或标记化证据 |
| 3.4.1 | PAN 在任何存储位置均不可读 | AES-256 加密；标记化证明；掩码 |
| 3.4.2 | PAN 副本仅存于经授权的可移动介质 | 介质清单和控制 |
| 3.5 | PAN 使用强加密保护 | 加密算法和密钥管理审查 |
| 3.5.1 | 主账号使用强加密保护 | AES-256 或等效；无 DES/RC4 |
| 3.5.2 | 用于 PAN 加密的加密密钥受保护 | 密钥管理政策和程序 |
| 3.6 | 实施加密密钥的密钥管理程序和流程 | 密钥保管人指派；知识拆分 |
| 3.6.1 | 密钥管理政策和程序 | 密钥轮换、密钥加密密钥、密钥退役 |
| 3.7 | 密钥管理程序覆盖完整的密钥生命周期 | 生成、分发、存储、退役 |
| 3.7.1 | 密钥存储安全 | HSM、加密密钥库 |
| 3.7.2 | 密钥访问限制在最少必要的保管人 | 双重控制；知识拆分 |
| 3.7.3 | 密钥退役/更换政策已记录并执行 | 轮换记录 |
| 3.7.4 | 密钥泄露按记录在案的程序管理 | 密钥泄露的应急响应 |
| 3.7.5 | 手动密钥使用知识拆分和双重控制 | 两人密钥操作证据 |
| 3.7.6 | 防止非正式密钥替换 | 仅允许正式密钥管理 |
| 3.7.7 | 密钥保管人确认其责任 | 签署的保管人协议 |
| 3.7.8 | 使用密钥管理服务时，其须满足要求 3.6–3.7 | CSP KMS 合规证据 |

**常见缺口**：数据库中存储 CVV；日志文件中的 PAN；无密钥轮换；使用弱算法加密（完整性方面用 MD5、SHA-1）；密钥与加密数据一同存储。

### 要求 4——在传输过程中使用强加密保护持卡人数据

通过开放、公共网络传输的 PAN 必须使用强加密。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 4.1 | 定义并实施传输中 PAN 保护流程 | 加密政策 |
| 4.2 | 在开放、公共网络上传输期间保护 PAN | TLS 1.2+ 配置；证书审查 |
| 4.2.1 | 使用强加密保护传输中的 PAN | TLS 1.2 或 1.3；无 SSL、TLS 1.0、1.1 |
| 4.2.1.1 | 维护证书清单 | 证书管理工具或清单 |
| 4.2.1.2 | 传输 PAN 的无线网络使用强加密 | Wi-Fi 加密：WPA2-Enterprise 或 WPA3 |
| 4.2.2 | PAN 不通过未受保护的最终用户消息传递（电子邮件、聊天）发送 | DLP 政策；电子邮件加密控制 |

**常见缺口**：仍启用旧版 TLS 1.0/1.1；过期的 SSL 证书；通过明文电子邮件发送 PAN；无证书清单。

## 目标 3：维护漏洞管理计划

### 要求 5——保护所有系统和网络免受恶意软件侵害

反恶意软件控制防范病毒、勒索软件、间谍软件和其他威胁。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 5.1 | 定义恶意软件防护流程 | 反恶意软件政策 |
| 5.2 | 在所有适用组件上部署反恶意软件解决方案 | 防病毒部署清单；管理控制台 |
| 5.2.1 | 在所有可能受恶意软件影响的组件上部署反恶意软件解决方案 | 覆盖报告；记录例外 |
| 5.2.2 | 反恶意软件解决方案检测所有已知类型的恶意软件 | 供应商能力矩阵 |
| 5.2.3 | 不常受恶意软件影响的系统定期评估 | 定期风险分析；记录例外 |
| 5.3 | 维护并监控反恶意软件解决方案 | 定义更新日志；扫描结果 |
| 5.3.1 | 反恶意软件解决方案保持最新 | 自动更新策略；最新定义证明 |
| 5.3.2 | 反恶意软件执行定期扫描和主动/实时扫描 | 扫描计划；启用实时防护 |
| 5.3.3 | 可移动介质的反恶意软件解决方案 | USB 扫描策略；端点配置 |
| 5.3.4 | 维护并监控反恶意软件日志 | 日志留存；SIEM 集成 |
| 5.3.5 | 用户无法禁用反恶意软件机制 | 仅管理员可卸载；启用防篡改 |
| 5.4 | 反钓鱼机制保护用户（**v4.0 新增**） | 反钓鱼过滤器；电子邮件网关配置 |
| 5.4.1 | 自动化技术解决方案检测并防范钓鱼 | 电子邮件安全网关；URL 过滤；DMARC/DKIM/SPF |

**常见缺口**：防病毒未覆盖 Linux/Unix 系统；定义未自动更新；用户可以禁用防病毒；无钓鱼防护（v4.0 新要求）。

| 6.3.2 | 维护定制和自研软件清单 | 软件清单/SBOM |

## 目标 4：实施强访问控制措施

### 要求 7——按业务需要知悉限制对系统组件和持卡人数据的访问

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 7.1 | 定义访问控制流程和程序 | 访问控制政策 |
| 7.2 | 限制对系统组件和持卡人数据的访问 | 基于角色的访问矩阵；IAM 配置 |
| 7.2.1 | 所有用户基于最小权限和需要知悉原则获得访问 | 访问审查结果 |
| 7.2.2 | 根据工作分类和职能分配访问 | 角色定义；访问请求记录 |
| 7.2.3 | 特权访问经授权人员批准 | 审批工作流记录 |
| 7.2.4 | 用户账户和访问权限至少每 6 个月审查一次 | 含日期的访问审查日志 |
| 7.2.5 | 应用/系统账户按政策管理 | 服务账户清单；访问控制 |
| 7.2.6 | 对持卡人数据存储库的查询访问限于定义的应用 | 数据库访问控制；应用级认证 |
| 7.3 | 管理系统组件和数据的访问 | IAM 系统；访问控制执行 |
| 7.3.1 | 实施访问控制系统以限制对 CDE 的访问 | IAM/PAM 工具部署证据 |
| 7.3.2 | 访问控制系统配置为强制执行最小权限 | ACL 审查；默认拒绝配置 |
| 7.3.3 | 访问控制系统保持最新 | 审查和更新周期证据 |

**常见缺口**：共享账户；无访问再认证；服务账户权限过高；数据库访问未执行需要知悉原则。

### 要求 8——识别用户并验证对系统组件的访问

每个用户必须有唯一 ID；CDE 访问需要强认证。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
| 8.1 | 定义用户识别和认证流程 | 认证政策 |
| 8.2 | 管理用户 ID 和认证凭据 | IAM 系统；唯一账户验证 |
| 8.2.1 | 所有用户有唯一 ID | 账户审计；无共享账户 |
| 8.2.2 | 仅在例外情况下管理组、共享或通用账户 | 记录理由的例外 |
| 8.2.3 | 第三方/供应商使用的账户需要额外认证 | 供应商访问的 MFA |
| 8.2.4 | 仅通过正式流程添加/修改/删除用户账户 | 身份生命周期管理记录 |
| 8.2.5 | 终止用户的访问立即撤销 | 离场检查清单；IAM 取消供应证据 |
| 8.2.6 | 不活跃账户在 90 天内禁用 | 账户审查；自动禁用策略 |
| 8.2.7 | 用于系统/应用功能的账户得到适当管理 | 服务账户政策合规 |
| 8.2.8 | 超过 15 分钟不活跃的会话需要重新认证 | 会话超时配置 |
| 8.3 | 建立并管理强认证 | MFA 配置证据 |
| 8.3.1 | 所有用户对 CDE 的访问均使用 MFA（**v4.0 中扩展**） | 所有 CDE 访问的 MFA 部署证明 |
| 8.3.2 | 从外部对 CDE 的所有访问均使用 MFA | 远程访问 MFA（VPN、RDP 等） |
| 8.3.4 | 无效认证尝试受限 | 账户锁定策略（最多 10 次尝试） |
| 8.3.5 | 密码/口令满足最低要求 | 密码策略配置：最少 12 个字符、复杂度 |
| 8.3.6 | 密码每 90 天更改（或采用补偿控制/风险分析） | 密码策略；过期设置 |
| 8.3.7 | 个人不得提交与最近 4 个密码中任何一个相同的密码 | 密码历史设置 |
| 8.3.8 | 认证政策传达给用户 | 培训记录；政策确认 |
| 8.3.9 | 不使用 MFA 的用户的密码至少每 90 天更改 | 密码过期配置 |
| 8.3.10 | 按规定间隔向用户提供更改密码的指导 | 沟通记录 |
| 8.4 | 对 CDE 的所有访问实施 MFA | 所有特权用户和普通用户访问的 MFA |
| 8.4.1 | 对 CDE 的所有非控制台管理访问使用 MFA | 管理 MFA 配置 |
| 8.4.2 | 对 CDE 的所有访问均使用 MFA（**v4.0 关键新变更**） | 所有访问 CDE 的人员均需 MFA |
| 8.5 | MFA 系统配置为防止滥用 | 反 MFA 绕过控制 |
| 8.6 | 管理应用/系统账户的使用 | 自动化或手动交互式使用控制 |

**常见缺口**：共享管理员账户；弱密码（少于 12 个字符）；并非所有 CDE 访问均使用 MFA（v4.0 关键缺口）；账户未在不活跃 90 天内禁用；无会话超时。

### 要求 9——限制对持卡人数据的物理访问

物理控制防止对 CDE 中的系统、介质和设施的未经授权访问。

| 子要求 | 说明 | 供 QSA 审核的证据 |
|---------|-------------|-----------------|
