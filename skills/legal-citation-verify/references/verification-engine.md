# 六组验证引擎详解

## 验证流程总览

每条 Citation 经过以下验证流程：

```
Citation + LawRecord(缓存)
  ↓
底线层（默认）
  G1 来源溯源 (3项)
  G2 元数据核验 (3项)
  G3 效力与版本 (3项)
  ↓ 全部通过？
  ├─ 是 → 标记"基本可信"
  │   └─ 深度层启用？→ 是 → 继续 G4-G6
  │                  → 否 → 完成
  └─ 否 → 自动触发深度层
      G4 法理一致性 (3项)
      G5 适用条件 (3项)
      G6 引用质量 (4项)
  ↓
验证结果汇总
```

---

## G1 来源溯源组

**目标**：确认法规原文来自制定机关官方渠道，非民间转载或AI编造。

### G1-1 官方渠道验证

**检查逻辑**：

**通用验证流程**：
1. 从 LawRecord.`issuing_authority` 字段获取制定机关信息（该字段在 Pass 1 阶段已通过 pkulaw `get_law_list` 获取并缓存，无需等待 G2-3 的机关权责匹配结果，G1 与 G2 之间不存在循环依赖）
2. 根据制定机关选择对应官方渠道进行验证（如全国人大 → npc.gov.cn / flk.npc.gov.cn，国务院 → gov.cn，最高人民法院 → court.gov.cn）
3. 检查 LawRecord 中的 `official_source_url` 是否来自官方渠道（见 official-sources.md 白名单）
4. 如果 pkulaw/yuandian 有收录，标记来源为"权威数据库"
5. 如果仅有 WebSearch 结果，检查网页域名是否为政府官网（.gov.cn）

**政策文件专用验证流程**（当 Citation.doc_type = "政策文件" 时触发）：

政策文件的特殊性决定了其验证逻辑与法律法规不同——数据库覆盖率低、原文分散在各级政府门户、内容可能被非官方渠道截取或改写。因此政策文件必须执行独立于通用流程的专用验证：

1. **强制官方门户检索**：从 LawRecord.`issuing_authority` 获取制定机关，定位对应官方域名：
   - 国务院 → gov.cn（中央人民政府门户）
   - 海南省人民政府 → hainan.gov.cn
   - 海南自贸港相关 → wjk.hnftp.gov.cn（自贸港法规政策库，最高优先级）
   - 其他省级政府 → 对应 .gov.cn 域名
   - 市级/区级政府 → 对应 .gov.cn 域名
   - 各部委 → 对应部委官网 .gov.cn

2. **WebSearch 检索官方门户**：使用 `"{文件标题}" "{发文字号}" site:{域名}` 精确检索（检索模板见 official-sources.md）

3. **原文获取与比对**：WebFetch 打开官方页面，提取文件原文，比对标题、文号、发文机关、核心内容

4. **来源类型标注**：
   - 官方门户获取成功 → LawRecord.`source_type = "official_portal"`，`source_confidence = "high"`
   - 官方门户未找到 → 启用降级验证，LawRecord.`source_type = "database"` 或 `"web_multi_source"`，`source_confidence` 对应降级

**通用判定规则**：
- 来源为 gov.cn 域名或 pkulaw/yuandian → 通过
- 来源为非 gov.cn 但为权威法律网站 → 存疑
- 来源为微信公众号/百度百科/民间网站 → 存疑，需交叉验证
- 完全找不到来源 → 错误

**政策文件专项判定规则**（与通用规则互补）：
- 来源为官方门户（source_type = "official_portal"）→ 通过（标注"官方门户验证通过"）
- 来源为数据库但官方门户未找到（source_type = "database"）→ 存疑（标注"官方门户未找到原文，以数据库为准。建议通过政务公开渠道确认"）
- 来源为多源互联网交叉验证（source_type = "web_multi_source"）→ 存疑（标注"官方门户和数据库均未找到，以下验证基于互联网多源交叉比对"）
- 来源为非 gov.cn 域名 → 错误（政策文件必须来自官方门户，民间转载不可接受）

**工具调用**：
- pkulaw `get_law_list`：返回结果中通常包含来源信息
- WebSearch：`"法规全称" site:gov.cn` 检索官方发布页面

### G1-2 非官方来源过滤

**检查逻辑**：
1. 如果用户提供的引用附带了来源URL，检查该URL是否在非官方来源黑名单中
2. 非官方来源包括：微信公众号（mp.weixin.qq.com）、百度百科（baike.baidu.com）、民间法律咨询网站、AI生成内容
3. 如果来源为非官方，标记"来源需交叉验证"

**判定规则**：
- 来源为官方渠道 → 通过
- 来源为非官方但内容与官方原文一致 → 通过（标注"已交叉验证"）
- 来源为非官方且无法与官方原文比对 → 存疑
- 来源为非官方且内容与官方原文不一致 → 错误

### G1-3 原文比对

**检查逻辑**：
1. 将 Citation 中的 `article_text`（AI概述的条款内容）与 LawRecord 中的 `articles[条款号]`（官方原文）进行比对
2. 使用 yuandian `hall_detect` 工具检测内容幻觉
3. 比对维度：关键信息是否一致、是否有遗漏前置条件、是否有歪曲

**判定规则**：
- AI概述与原文语义一致 → 通过
- AI概述与原文有小幅差异（如措辞不同但含义相同）→ 存疑
- AI概述遗漏关键前置条件（如"但书"条款）→ 存疑
- AI概述与原文含义相反或严重偏离 → 错误

**工具调用**：
- yuandian `mcp__yuandian-mcp__yuandian_hall_detect`：传入AI概述文本和官方原文，检测幻觉
- **政策文件**：原文优先从官方门户获取（LawRecord.source_type = "official_portal"），hall_detect 输入为"AI概述 + 官方门户原文"。如果官方门户未找到（source_type ≠ "official_portal"），G1-3 标注"原文来源非官方门户，内容比对可信度降低"

**`article_text` 为空时的隐式概述提取**（三级降级策略）：

当引用仅包含条款号而无内容概述时（即 `article_text` 为空，这是最常见的引用格式如"《XX法》第39条"），按以下策略处理：

1. **第一级——上下文隐式概述提取**：
   - 从 Citation.`context`（引用所在上下文段落）中，提取引用前后 2-3 句话作为"隐式概述"
   - 将隐式概述写入 Citation.`implicit_summary` 字段
   - 使用 `implicit_summary` 替代 `article_text` 与官方原文进行语义比对
   - 如果上下文中有实质性内容描述（如"根据第39条，用人单位在劳动者...的情况下可以解除劳动合同"）→ 执行 hall_detect 比对

2. **第二级——条款号存在性检查**：
   - 如果上下文中也无实质性内容描述（纯条款号引用，如"详见《XX法》第39条"）→ 跳过 hall_detect
   - 降级为仅执行 G2-1（条款号存在性检查），确认该条款号在当前版本法规中确实存在
   - 在报告中标注"⚠️ 条款内容未验证（引用未包含内容概述，且上下文无可提取的隐式概述）"

3. **第三级——原文摘要回填**：
   - 对第二级降级的引用，从 LawRecord.`articles[条款号]` 中提取官方原文的前 100 字作为摘要
   - 将摘要写入报告的"条款原文参考"栏，供用户人工核对
   - 这样即使无法自动验证内容准确性，用户也能在报告中看到官方原文摘要

**准确率预估**：
- 有 `article_text` 或可提取隐式概述时：85-90%
- 仅条款号引用（第二级降级）：条款号存在性检查 90%+，但内容准确性未验证

## G2 元数据核验组

**目标**：验证文号、标题、发文机关三项齐全且逻辑自洽。

> **政策文件条款结构规则**：当引用类型为"政策文件"但引用文本中包含"第X条"等条款编号时，G2 条款精确性检查（G2-1 条款号存在性 + 原文比对）自动启用。此时验证管道从"仅 G1-G3 + G5"升级为"G1-G3 + G5 + G2 条款精确性"。详见 classification-rules.md 中的"后置规则——条款结构检测"。

### G2-1 文号格式与存在性

**检查逻辑**：
1. 从 Citation 原始文本中提取文号（如"国务院令第743号""主席令第X号"）
2. 验证文号格式是否符合该类型法规的规范：
   - 法律：主席令第X号
   - 行政法规：国务院令第X号
   - 部门规章：XX部令第X号 / XX局令第X号
   - 司法解释：法释〔XXXX〕X号 / 高检发释字〔XXXX〕X号
   - 政策文件：X发〔XXXX〕X号 / X函〔XXXX〕X号
3. 在 LawRecord 中验证该文号是否与法规匹配

**判定规则**：
- 文号格式正确且与法规匹配 → 通过
- 文号格式正确但与法规不匹配 → 错误
- 文号格式不规范 → 存疑
- 无文号（政策文件常见）→ 跳过（不视为错误）

**工具调用**：
- pkulaw `get_law_list`：返回结果中包含文号信息

### G2-2 标题-文号一致性

**检查逻辑**：
1. 验证引用中的法规标题与文号是否对应
2. 例如：引用"《关键信息基础设施安全保护条例》国务院令第743号"
   - 查询 pkulaw 确认"国务院令第743号"对应的标题是否为"关键信息基础设施安全保护条例"
3. 检查标题中的机关名称与发文机关是否一致

**判定规则**：
- 标题与文号完全对应 → 通过
- 标题与文号不对应 → 错误
- 标题有细微差异（如多/少"中华人民共和国"前缀）→ 存疑

### G2-3 发文机关权责匹配

**检查逻辑**：
1. 验证发文机关是否具备制定该层级法规的权限
2. 权限矩阵：
   - 全国人大及常委会 → 可制定法律
   - 国务院 → 可制定行政法规
   - 国务院各部委 → 可制定部门规章
   - 省/市级人大 → 可制定地方性法规
   - 最高人民法院/最高人民检察院 → 可制定司法解释
   - 各级政府/部门 → 可制定规范性文件
3. 如果发文机关与法规层级不匹配（如县级政府发布"行政法规"），标记错误

**判定规则**：
- 发文机关权限与法规层级匹配 → 通过
- 不匹配 → 错误
- 无法确定发文机关 → 存疑

**准确率预估**：90-95%

## G3 效力与版本组

**目标**：确认法规现行有效，使用的是最新版本。

### G3-1 效力状态读取

**检查逻辑**：
1. 从 LawRecord 的 `validity_status` 字段读取效力状态
2. 状态分类：现行有效 / 已废止 / 已被修订 / 尚未生效 / 部分失效
3. 对于政策文件，执行额外的有效期检查（见 classification-rules.md 中的有效期判断规则）。**政策文件有效期核查须优先从官方门户检索**废止/替代声明，不依赖数据库的时效性标注。

**判定规则**：
- 现行有效 → 通过
- 已废止 → 失效（报告中提供替代指引）
- 已被修订 → 存疑（报告中提示"已有修订版，请确认引用版本"）
- 尚未生效 → 存疑（报告中提示"该法规尚未施行"）
- 部分失效 → 存疑（报告中标注哪些条款已失效）

**工具调用**：
- pkulaw `get_law_list`：返回结果中的时效性字段
- WebSearch：`"法规全称" 废止 OR 失效` 检索最新废止公告

### G3-2 修订历史链追溯

**检查逻辑**：
1. 从 LawRecord 的 `revision_history` 获取完整修订记录
2. 列出该法规的所有版本（初次发布 + 每次修正/修订）
3. 确认当前引用的版本是否为最新版本
4. 如果引用了旧版本，检查文章时间语境是否支持使用旧版本

**判定规则**：
- 引用最新版本 → 通过
- 引用旧版本但时间语境匹配 → 通过（标注"历史版本引用"）
- 引用旧版本且时间语境不匹配 → 存疑
- 无法确定版本 → 存疑

### G3-3 最新版本确认

**检查逻辑**：
1. 检查是否有比当前引用版本更新的修订版
2. 检查是否有替代性新法（如《民法典》替代《合同法》《民法通则》等）
3. 如果有替代关系，在报告中提供替代指引

**判定规则**：
- 无更新版本，无替代法 → 通过
- 有更新版本但旧版仍有效 → 存疑（提示更新）
- 有替代法且旧版已废止 → 失效（提供替代指引）
- 有替代法但旧版仍有效 → 存疑（提示注意适用优先级）

**替代指引输出格式**：
```
原引用：《中华人民共和国合同法》第X条
状态：已废止（2021年1月1日《民法典》施行后废止）
替代引用：《中华人民共和国民法典》第三编（合同编）第X条
```

**准确率预估**：85-92%

## G4 法理一致性组（深度层）

**目标**：检查引用条款与上位法是否冲突，与同位法是否协调，内部逻辑是否自洽。

**验证模式**：
- 保守模式（默认）：仅做结构化检查（条款号存在、关键词重叠），不做深度语义推理。输出"建议人工复核"而非确定性结论。
- 激进模式（用户开启）：使用 LLM 做深度语义分析，输出置信度 + 风险提示。

> **保守模式"通过"的含义**：保守模式下判定"通过"仅表示**未发现表面结构矛盾**（条款号存在、关键词无直接冲突），**不代表无法理冲突**。保守模式的假阴性率较高——两部法规可能关键词高度重叠但含义完全不同，结构化检查无法发现。报告中保守模式通过项标注为"通过（基础结构检查）"，激进模式通过项标注为"通过（深度法理分析）"，用户可据此区分验证深度。

### G4-1 上位法一致性

**检查逻辑（保守模式）**：
1. 识别引用法规的上位法（如部门规章的上位法是对应的行政法规和法律）
2. 提取引用条款的关键词
3. 在上位法中检索相同主题的条款
4. 检查是否存在明显的关键词矛盾

**检查逻辑（激进模式）**：
1. 同上步骤1-3
2. 使用 LLM 比对两条款的语义是否一致
3. 输出冲突风险等级：无冲突 / 轻微差异 / 潜在冲突 / 明显抵触

**判定规则**：
- 未发现冲突 → 通过
- 轻微差异（措辞不同但含义一致）→ 存疑（保守模式：建议人工复核）
- 潜在冲突 → 存疑
- 明显抵触 → 错误

**工具调用**：
- yuandian `mcp__yuandian-mcp__yuandian_rh_fg_search`：检索上位法条款
- yuandian `mcp__yuandian-mcp__yuandian_law_vector_search`：语义检索相关条款

### G4-2 同位法协调性

**检查逻辑**：
1. 识别同一领域内与引用法规同位阶的其他法规
2. 检查对同一事项的规定是否一致
3. 如果存在不一致，标注"同位法冲突风险"

**判定规则**：
- 无同位法或规定一致 → 通过
- 存在不一致但属于细化差异 → 存疑
- 存在直接矛盾 → 错误

### G4-3 内部逻辑自洽

**检查逻辑**：
1. 提取同一部法规内引用条款的前后条款
2. 检查是否存在循环引用或自相矛盾
3. 检查引用条款是否与该法的总则部分原则一致

**判定规则**：
- 未发现矛盾 → 通过
- 存在表述模糊但不矛盾 → 存疑
- 存在自相矛盾 → 错误

**准确率预估**：保守模式 70-80%，激进模式 50-65%

## G5 适用条件核验组（深度层）

**目标**：确认法规适用于文章讨论的地区、对象和时间。

### G5-1 适用地区核查

**检查逻辑**：
1. 从 LawRecord 或法规标题中提取适用地区信息
2. 从文章上下文中提取讨论的地区
3. 比对两者是否匹配

**判定规则**：
- 全国性法规 + 文章讨论全国性问题 → 通过
- 全国性法规 + 文章讨论地方问题 → 通过（全国性法规在全国适用）
- 地方性法规 + 文章讨论该地区问题 → 通过
- 地方性法规 + 文章讨论其他地区问题 → 错误（标注"地域不匹配"）

**示例**：
- 引用《海南省自由贸易港条例》但讨论的是全国性税收政策 → 错误
- 引用《北京市控制吸烟条例》但讨论的是上海的情况 → 错误

### G5-2 适用对象核查

**检查逻辑**：
1. 从法规内容中提取适用对象（如"适用于上市公司""适用于外商投资企业"）
2. 从文章上下文中提取讨论的对象
3. 比对两者是否匹配

**判定规则**：
- 法规适用对象与文章讨论对象匹配 → 通过
- 法规适用对象包含文章讨论对象 → 通过
- 法规适用对象与文章讨论对象不匹配 → 错误

**示例**：
- 引用《上市公司信息披露管理办法》但讨论的是非上市民营企业 → 错误
- 引用《外商投资法》但讨论的是内资企业 → 存疑

### G5-3 有效期限核查

**检查逻辑**：
1. 对于有时效限制的政策文件（阶段性政策），检查是否仍在有效期内
2. 对于司法解释，检查母法是否仍有效（与司法解释特殊路径步骤2联动）
3. 对于"暂行/试行"类文件，检查是否已超过合理试行期限

**判定规则**：
- 在有效期内 → 通过
- 已过有效期 → 失效
- 有效期不明确但无废止声明 → 存疑
- 暂行/试行文件发布超过5年且无续期 → 存疑

**准确率预估**：80-88%

## G6 引用质量组（深度层）

**目标**：检查引用行为本身的质量，包括引用是否支撑论点、是否使用兜底条款、地方性法规的特殊性。

**验证模式**：
- 保守模式（默认）：仅做结构化检查
- 激进模式（用户开启）：使用 LLM 做深度语义分析

> **保守模式"通过"的含义**：与 G4 同理，保守模式下 G6 判定"通过"仅表示结构化检查未发现异常（如非兜底条款、引用格式规范），**不代表引用意图与条款内容实质匹配**。报告中标注为"通过（基础结构检查）"。

### G6-1 引用意图-条款匹配

**检查逻辑（激进模式）**：
1. 提取文章中引用该条款的上下文段落
2. 提取该条款的官方原文
3. 使用 LLM 判断：条款内容是否真正支撑文章的论点
4. 输出匹配度评分：高/中/低

**判定规则**：
- 条款内容直接支撑论点 → 通过
- 条款内容间接支撑论点 → 存疑
- 条款内容与论点无关或矛盾 → 错误

**示例**：
- 文章说"企业可以单方面解除所有合同"，引用《民法典》第563条
- 第563条规定的是法定解除权的几种具体情形，不能推导出"所有合同都可单方解除"
- 判定：错误（引用不支撑论点）

### G6-2 废止替代关系指引

**检查逻辑**：
1. 当 G3 判定法规已废止时，自动检索替代性法规
2. 常见替代关系映射：
   - 《合同法》→ 《民法典》合同编
   - 《民法通则》→ 《民法典》总则编 + 人格权编 + 侵权责任编
   - 《民法总则》→ 《民法典》总则编
   - 《物权法》→ 《民法典》物权编
   - 《侵权责任法》→ 《民法典》侵权责任编
3. 在报告中提供具体替代条款指引

**输出格式**：
```
原引用：《中华人民共和国合同法》第94条
状态：已废止
替代引用：《中华人民共和国民法典》第五百六十三条
注意：条款内容基本一致，但条款号已变更
```

### G6-3 兜底条款风险标记

**检查逻辑**：
1. 检查引用条款是否为兜底条款
2. 兜底条款识别模式：
   - "法律、行政法规规定的其他情形"
   - "国务院另有规定的除外"
   - "等"（作为条款最后一句的结尾词）
   - "其他严重情节"
3. 如果文章将兜底条款作为核心论证依据引用，标记风险

**判定规则**：
- 非兜底条款 → 通过
- 兜底条款但作为辅助引用 → 通过
- 兜底条款作为核心论证依据 → 存疑（标注"兜底条款不宜作为核心依据"）

### G6-4 地方性法规特有风险

**检查逻辑**：
1. 当引用类型为"地方性法规"时执行
2. 检查文章是否同时引用了全国性法律和地方性法规
3. 如果两者存在潜在冲突，提示适用优先级问题
4. 检查地方性法规是否有"特别规定"属性（在本地域内优先适用）

**判定规则**：
- 仅引用地方性法规，无冲突 → 通过
- 同时引用全国性法律和地方性法规，无冲突 → 通过
- 同时引用且存在潜在冲突 → 存疑（标注"需结合具体地域和事项判断适用优先级"）

**准确率预估**：保守模式 75-85%，激进模式 60-75%
