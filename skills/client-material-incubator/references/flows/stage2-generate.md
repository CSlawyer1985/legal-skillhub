# 阶段2 · 日常生成（成果复用，详细流程）

> 本文件由 SKILL.md 按需加载。适用：律所模板库已建成，日常接案产材料。

## 通道输入归一化（任选其一或组合）

| 通道 | 输入 | 处理 |
|------|------|------|
| 笔录通道 | 风险告知笔录（docx/pdf/图片） | 解析 → 提取事实 |
| **起诉状通道** | 民事起诉状 / 仲裁申请书（docx/pdf） | **推荐**：起诉状本身即含完整的委托人/对方当事人/案由/金额/法院等信息，无需重复询问。AI 从起诉状正文提取全部变量后直接生成确认表 |
| 录音通道 | 客户录音（mp3/m4a/wav 等） | **本地离线 ASR**（`scripts/transcribe_audio.py`，faster-whisper + OpenAI Whisper small/medium，100% 本地推理、数据不出律所电脑）→ 带时间轴+三档置信度 JSON（≥0.5 直接采信 / 0.3-0.5 建议核对 / <0.3 必须人工复核）→ 事实提取 |
| 对话通道 | 直接描述案件情况 | 引导式问答（最小提问原则） |

> 💡 **精准说法**：对话通道口述时按「当事人 → 案由 → 金额 → 法院」顺序一次说清（如"张伟诉李强民间借贷，标的 8 万，永康法院"）；起诉状 / 笔录 / 录音通道直接说明文件用途即可。详见 `references/prompt-skills.md`。

## 流程（五步）

四通道 → ① 归一化为「案例事实提取表」→ ② 变量核对 → ③ 产物存放位置确认 → ④ 按材料包批量生成 → ⑤ 交付

**① 归一化**：无论哪条通道，先把输入归一化为统一的「案例事实提取表」（委托人/对方当事人/案由/金额/法院/承办律师/日期等字段）。

**② 变量核对（一次确认）**：只问缺失+红色置信度（<0.3）必填项，录音模糊处标 ⚠️，黄色区间（0.3-0.5）采信但附原始文本供核对，非必填缺失留 `____` 占位。

**②-1 跨文件变量一致性校验**（确认表生成后、批量生成前）：
1. **同名变量一致**：跨文件共享变量（`{{委托人姓名}}`、`{{案由}}` 等）的值必须一致，不一致标注并提示确认；
2. **语义重叠变量校验**：识别不同名但语义重叠的变量——如授权委托书的电话 vs 送达确认书的电话（律所办公电话 vs 当事人手机）、委托合同的地址 vs 送达确认书的送达地址——用户填其中一个时，主动提示"该值是否也用于 XXX？"，避免填错文件；
3. **用户输入覆盖提示**：用户提供的联系方式等可能影响多份文件时，主动列出影响范围（"您提供的 13800000000 将同时用于 X 的律所电话和 Y 的当事人电话，是否确认？"）；
4. **通过标准**：共享变量值一致、语义重叠变量已明确区分或确认、用户输入已正确分配到对应变量。

**③ 产物存放位置确认（主动询问，不等待用户指定）**：
> 「成套委托材料生成后，建议存放在哪个位置？
> - **推荐**：在**您投喂材料所在文件夹内**新建一个子文件夹，命名 `委托材料（{案件名}）`，全部材料统一放入，便于归档查找；
> - 或您可自定义命名格式，如 `{案号}-委托材料`、`{委托人姓名}委托材料`，我将按该格式命名并沿用。」

将最终确定的存放路径与命名格式记录于进度登记，后续同所生成沿用同一格式（除非客户再次调整）。

**④ 按材料包批量生成**：见下方「批量生成」。

**⑤ 交付**：按模式输出文档链接列表或本地文件路径，附材料包交付清单（含「⚠️ 交付备注块」）。

**交付后收尾（下一步选项，不直接收工）**：

> 下一步？
> 1. **登记进度** —— 自动更新进度登记与验证日志；
> 2. **补做母版** —— 进入阶段1 为新材料包建库；
> 3. **导出/打印** —— 需要 Word 或打印版，我帮您导出；
> 4. **其他** —— 告诉我您的打算。

## 批量生成（按阶段1 选定的制作模式）

> 🔒 **强制约束（不可违反，违反视为系统缺陷）**：生成文书**必须从母版克隆后仅做 `{{变量}}` 文本替换**，禁止新建空白文档再填充。线上模式从在线母版复制（腾讯文档 `manage.copy_file` / 金山文档 `copy_file`）；线下模式必须调用 `scripts/build_master.py`（XML 级替换）——**不得使用 python-docx 等库从头创建文档**（新建文档会丢失母版全部格式，格式零改动铁律的必然要求）。

- **线上模式 A1（腾讯文档三步法）**：
  1. `manage.copy_file`（在线母版 → 新文档，含 title）
  2. `manage.set_privilege` policy=3（任何人可编辑）
  3. `doc.find_and_replace`（doc-mcp endpoint）批量替换 `{{变量}}`（同名变量一次替换，跨材料一致；**变量按名称长度降序替换**，避免 `{{勾选_一审}}` 与 `{{勾选_行政一审}}` 等前缀冲突）
  - 交付：**在线文档链接列表**（带 `_fid`）+ 材料包交付清单；所内同事可在线查看、协作编辑
- **线上模式 A2（金山文档三步法）**：
  1. `copy_file`（在线母版 → 新文档，复制到产物目录）
  2. `share_file` / `set_share_permission`（开启分享，所内同事可查看）
  3. `wps.core_execute` → `replaceContent`（`findText="{{变量}}"`, `replaceText="真实值"`, `isAll=true`）逐变量全文替换（**变量按名称长度降序替换**，避免前缀冲突）
  - 交付：**在线文档分享链接列表** + 材料包交付清单；导出 DOCX 用 `wps.export`（format=docx）
- **线下模式**：调用 `scripts/build_master.py` 基于本地母版执行 XML 级变量替换，产出本地 DOCX，统一放入第③步确认的存放位置；交付本地文件路径清单。

## 生成后自检（每次生成必做，通过后才交付）

> 自检发现问题时，先对照 `references/troubleshooting.md` 的「症状 → 怎么说」给出对应解决指令，而不是直接改——多数问题用一句精准指令就能让 AI 定位修复。

1. **残留变量扫描**：检查生成文件是否仍含 `{{变量}}` 占位符——有则标红警告并修正；**线上模式（金山文档）注意**：`search_replace` 替换后编辑器层与存储层存在短暂同步延迟，立即 `read_file` 可能读到旧值误判"替换失败"——改用 `search` 动作逐变量确认 `found:false`，或延时重读 1-2 次再判；
2. **格式零改动比对**：剥除 `<w:t>` 文本节点后与母版 XML 逐字节比对，确认格式层无变动（`build_master.py --verify` 已内置，线上模式用 `get_content` 抽查关键段落格式）；
3. **必填变量完整性**：核对所有必填变量已赋值（非空），生成缺失清单；
4. **run 绑定校验**：逐 run 比对下划线归属与母版一致（`build_master.py --verify` 第 4 项，补 T9 盲区——T9 剥文本比对查不出下划线归属错位）；
5. **页数核对**（分页契约，T9 覆盖不到的盲区）：用 `scripts/check_pages.py --check <母版.docx> <映射.json>` 检测分页标记 + 分析"替换后变长"的变量；若成品页数超过母版基准页数（manifest 的 `page_count`），**告警**并提示"内容因变量变长被撑到下一页，建议微调行距/页边距"——分页是"软分页"，由内容长度决定，最终以 Word 打开为准；
   - **线上/线下页数规则差异（重要）**：`check_pages.py` 检测的是 DOCX 的 XML，**仅适用于线下模式**。线上模式（腾讯文档）的成品是在线文档，其排版引擎 ≠ Word——**在线显示的分页与导出 Word 后打开的分页可能不一致（分页漂移）**。线上模式须：① 导出 DOCX 后用 check_pages.py 检测，或 ② 明确提示客户"在线预览页数以导出 Word 后的实际页数为准"；建议线上母版排版时**不要排到刚好满一页**，预留余量吸收分页漂移；
6. **合规提示**（生成成品时主动给出，不改写内容）：
   - **法条引用校验**：提取成品中的法条引用，对照 `references/compliance/citation-check.md` 现行条文号；不一致 → 提示"建议核实，现行为第 X 条"，附来源，交律师确认；
   - **收费合规提示**：识别案件类型与收费方式，对照 `references/compliance/risk-agency-checklist.md`——属禁止风险代理的 8 类案件 → 提示"依法不得实行风险代理"；可风险代理 → 按标的额套五档阶梯，提示"约定比例合计不得超过 X% / X 元"；
   - **边界（重要）**：以上均为**提示建议，不强制拦截**——律师执意按自己的方式收费，是其自主执业选择，AI 只提示、不替律师做决定、不拒绝生成。
7. **正文残留检查（告知笔录专项）**：告知笔录成品若正文「答：」后仍有非空内容（当事人姓名/金额/案情陈述未清空），说明「问留答空」未执行——标红提示"正文答句未清空，可能残留真实案情"，须清空后重出。

## ⚠️ 交付备注块（每次生成必出，随成套材料一起交付）

> 位置：生成后自检全部通过后，输出成套材料**之前**，先输出下面这个块。它汇总律师交付前需要知道的全部信息，不散落在正文各处。

```
⚠️ 交付备注（随成套材料交付，供承办律师核对）

- 来源核对：法条引用已对照 citation-check.md —— [已核对 YYYY-MM-DD] X 处 / [需核实] X 处
- 必填完整性：N 个必填变量已赋值，缺失 M 个（见下）
- 需人工复核：录音通道低置信度片段 X 处（时间段「内容」，置信度 X，需回听）
- 格式保证：已通过 XML 逐字节比对（格式零改动）+ 页数核对（未超基准）
- 交付前需做：① 核对上述 [需核实] 项；② 确认下划线区域是否需手调
```

**折叠规则（防止过度标记）**：全部为绿色时（无 [需核实]、无缺失、无低置信度、格式页数均通过），折叠为一句话：

> ⚠️ 交付备注：法条已核对 · 必填齐全 · 无低置信度片段 · 格式已比对 · 可放心交付

**缺省值**：缺失变量清单、低置信度片段列表照实列出，不为凑篇幅显示"无问题"条目。与「一次确认表」分工明确——**一次确认表管"生成前核对变量"，交付备注块管"交付时汇总检查"**，两者不重复。

## 格式提示（生成后自动提醒）

- **页面控制**：分页是"软分页"（由内容长度决定），一页的母版生成后可能因变量变长被撑到两页——此风险已由「生成后自检第 5 项页数核对」检测。若确认超页，给出格式微调建议（行距可缩至 22pt 或微调页边距），由律师确认后执行。**不完全自动化——格式调整保留客户决策权**。
- **落款署名处理**：署名区（甲方/乙方/日期）若被挤到单独一页，**微调格式让署名上移**与正文同页（行距/页边距/段落间距），**不得截断正文末段、不得加分页符强制换页让署名单独成页**——截断或单独成页都是错误做法。
- **下划线区域**：变量替换后，原模板下划线区域可能因字符数变化而缩放。此为 DOCX 底层机制限制，非系统缺陷。生成后提示"变量填完后请确认下划线区域是否需要手调"。

## 技术实现

事实核对用 `scripts/extract_case.py`——加载 manifest 变量字典（自动展开 `{{勾选_*}}` 占位族、扫描母版实际变量兜底）、合并 AI 抽取结果、按置信度三档分层输出「一次确认表」Markdown（✅已识别 / ⚠待复核 / ❓待补充）。语义抽取本身由 AI 在对话中完成，脚本只做机械化归并与格式化。
