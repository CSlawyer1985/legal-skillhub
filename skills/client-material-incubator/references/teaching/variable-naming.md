# 变量命名规范（阶段1 教学用）

供律所在验收母版时参照，用于确认 AI 提出的变量命名是否符合统一标准。

---

## 规则一览

| 规则 | 正确示例 | 错误示例 |
|------|----------|----------|
| 使用全角花括号 | `{{委托人姓名}}` | `{委托人姓名}` |
| 中文表意名 | `{{债务人全称}}` | `{{debtor_full_name}}` |
| 名称简洁，不加序号或版本后缀 | `{{案由}}` | `{{变量1}}`、`{{案由(第二次出现)}}` |
| 同一含义全库统一命名 | `{{委托人姓名}}` 全库一致 | 一份写 `{{甲方姓名}}`，另一份写 `{{委托人}}` |
| 金额等数字独立为变量 | `{{标的额}}` | 直接在正文保留具体数字 |

## 横线（填空线）处理规范

**模板中的横线 = 变量位置的指示符**，必须纳入变量化处理，不能跳过：

| 横线形态 | 识别 | 变量化处理 | 生成效果 |
|----------|------|-----------|----------|
| 空白横线（`＿＿＿＿＿＿`） | 分析时识别为「填空横线」候选 | old=横线串 → new=`{{变量}}`（横线被删除） | 填入数据 |
| 带字横线（`＿＿民间借贷纠纷＿＿`） | 分析时识别为「填空横线」候选 | old=横线+示例字 → new=`{{案由}}`（示例字是变量值样例，横线删除） | 填入数据 |
| 格式型下划线（Word 下划线格式的 run，内容可能为空或带字） | 分析时识别为「下划线填空」候选 | old=run 内文本 → new=`{{变量}}`；**下划线格式由 XML 替换天然保留** | 填入数据时**自动带横线**（下划线格式随 run 保留） |
| 无横线的普通字段（`联系电话：`后无横线） | 若上下文可推断是变量位，AI 主动补 `{{变量}}` | old=空 → 提示补充变量 | — |

**铁律**：
1. **横线不得原样保留在母版中**——空白横线被 `{{变量}}` 替代后即消失，母版不应残留无意义横线；
2. **格式型下划线不要手动删除**——它是"生成时数据带横线"的关键：Word 中带下划线格式的空白 run，替换为 `{{变量}}` 后下划线属性自动保留，生成时填入的数据自带横线，符合司法文书的填空式排版；
3. **带字横线示例字是变量值样例**，不是固定文本——替换为变量，不保留示例字；
4. 生成完成后若发现某处数据需要横线但母版无下划线格式，在 Word 中手动为该值设置下划线即可（少量场景）。

**验收清单增加**：
- [ ] 模板中所有横线位置是否都已识别为变量？（无遗漏的空白横线残留）
- [ ] 需要"生成时带横线"的字段，其母版变量是否带下划线格式？

## 命名依据

1. **全角花括号**：与云文档（腾讯文档/金山文档）的查找替换功能兼容，便于系统自动识别和批量处理。
2. **中文表意名**：变量名应直观反映内容含义，无需对照外部字典即可理解其用途。英文名或编号名在维护阶段可读性不足。
3. **全局统一**：同一套材料包内的变量名需保持一致。例如，合同中的"甲方"与授权书中的"委托人"如对应同一实体的同一属性，应使用同一变量名，确保一次填充、全包生效。

## 特殊情况的处理（验收时参照）

| 情况 | 处理方式 |
|------|----------|
| 同一变量出现多次 | 仅映射一次，全文替换自动覆盖所有出现位置 |
| 抬头案号与正文案号相同 | 视为同一变量 |
| 日期被 Word 拆分为多个节点（如 `【2026】年【5】月`） | 使用精确区间替换（v5），映射时以完整字符串为准 |
| 全角括号与半角括号 | 以模板中的实际字符为准，映射需精确匹配 |
| 数字金额含小数点或逗号 | `500` 与 `500.00` 视为不同值，按模板原文映射 |
| 勾选框（☑/□ 选项） | 使用 `{{勾选_选项名}}` 变量，生成时替换为 ☑ 或 □（详见下节） |
| .doc 旧格式文件 | 先在 Word/WPS 中另存为 .docx 后投喂，系统无法读取二进制 .doc 格式 |
| 送达地址确认书 | 需单独变量：`{{致送法院}}`（函件抬头法院）、`{{开户行}}`（执行款收款账户开户行）、`{{银行账号}}`（执行款收款账号）。管辖法院与致送法院**不同变量**——管辖法院是合同中约定的，致送法院是具体函件抬头的法院，随案不同 |

## 案件类型特定文本检查清单（建库时逐项过）

**问题背景**：模板可能是某案件类型（如买卖合同纠纷）的专用模板，变量化时若只处理人名/金额等字段，会遗漏**案件类型预设的叙述段落**——这些硬编码文本在用于其他案件类型时不会替换，导致文书内容与事实不符。

**逐项检查（验收必做）**：

| 检查项 | 处理方式 |
|--------|----------|
| 法院名（如"××市人民法院"）是否在**所有出现位置**变量化？ | 管辖法院与致送法院分别变量化，全域替换 |
| 案由是否全部变量化？ | 标题、正文、授权书等多处出现时逐处确认 |
| 交易/纠纷类型描述（如"××买卖关系"）？ | 属于案件类型预设，**不适合做成每案变量**——建议将整段「事实与理由」标注为**人工撰稿区**：母版中该段保留空白或加括号提示「（本段叙述框架适用于××案件类型，其他类型请律师按案情重写）」 |
| 是否有其他案件类型专属条款（如特定管辖约定）？ | 涉及类型差异的条款建议建多套母版（按案件类型分组），而非塞进一套母版硬编码 |

## 勾选框变量处理

委托材料中常见的勾选区示例：

```
代理权限：☑ 一般代理  □ 特别授权
```

处理方式：每个选项独立为一个状态变量，不对整行进行变量化。

```
代理权限：{{勾选_一般代理}} 一般代理  {{勾选_特别授权}} 特别授权
```

生成时，系统根据案情将 `{{勾选_一般代理}}` 替换为 `☑`、`{{勾选_特别授权}}` 替换为 `□`（或相反）。勾选框的字号、间距、位置均原样保留。

**验收要点**：勾选变量统一使用 `勾选_` 前缀，便于系统识别其为二态开关而非填字占位。

## 验收自检项

1. 变量名是否直观可读，无需对照字典即可理解？
2. 材料包内同一含义的变量名是否统一？
3. 是否存在应标记但未标记的变量（如律所联系电话、地址等）？
