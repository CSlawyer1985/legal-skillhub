# 置信度分级标准

**用于「委托材料孵化器」全链路质量控制**

---

## 概览：两层置信度

本 Skill 的事实提取与确认流程涉及**两套独立但协同的置信度机制**。它们作用于不同环节、使用不同阈值，但共享相同的分档逻辑（绿/黄/红）。

```
录音(mp3) → [ASR 置信度] → 转写文本 → [抽取置信度] → 一次确认表
             Layer 1                         Layer 2
```

| 层级 | 作用环节 | 输入 | 阈值 | 表示含义 |
|------|----------|------|------|----------|
| Layer 1 | 语音转文字 | Whisper avg_logprob | ≥0.5 / 0.3-0.5 / <0.3 | 这段话转录得准不准 |
| Layer 2 | 从文字中抽取事实 | AI 语义置信度 | ≥0.9 / 0.6-0.9 / <0.6 | 这段文字里抽出来的信息对不对 |

两套阈值差异的原因：ASR 面对的是声学歧义（同音字/噪音），置信度天然偏低；事实抽取面对的是语义歧义（同名/多义），AI 的判断更可靠，阈值可以更严。

---

## Layer 1：ASR 转写置信度

### 原始值

faster-whisper 为每个转写片段输出 `avg_logprob`（平均对数概率），取值范围约 -2.0（完全不可靠）到 0（接近完美）。对于中文法律电话录音，正常质量区间约为 -0.5 ~ -0.1。

### 映射公式

```python
confidence = clamp((avg_logprob + 0.50) / 0.55, 0, 1)
```

**设计理由**：此公式将中文法律电话录音的"正常质量区间"（avg_logprob ≈ -0.2 ~ -0.3）映射到中间值（0.55~0.36），避免对电话录音的天然质量劣势做过度惩罚。

### 三档阈值

| 置信度 | 颜色 | 含义 | 处理方式 |
|--------|------|------|----------|
| **≥ 0.5** | 🟢 绿色 | 转录可信 | 文本直接进入事实抽取 |
| **0.3 ~ 0.5** | 🟡 黄色 | 基本可用 | 采信但附原始文本供律师比对 |
| **< 0.3** | 🔴 红色 | 可能错误 | 列入 `low_confidence_ranges`，附时间戳，提示回听 |

### 输出格式

```json
{
  "segments": [
    {
      "start": "00:00:08.4",
      "end": "00:00:14.9",
      "text": "我们打算给张伟做特别授权代理",
      "confidence": 0.56
    }
  ],
  "low_confidence_ranges": [
    {
      "start": "00:00:04.4",
      "end": "00:00:08.4",
      "text": "对方当事人是李强",
      "confidence": 0.27,
      "raw_logprob": -0.35
    }
  ]
}
```

### 实测数据（small 模型，中文法律对话 TTS）

| avg_logprob | 映射置信度 | 颜色 |
|-------------|-----------|------|
| -0.15 | 0.64 | 🟢 |
| -0.20 | 0.55 | 🟢 |
| -0.30 | 0.36 | 🟡 |
| -0.35 | 0.27 | 🔴 |
| -0.40 | 0.18 | 🔴 |

## Layer 2：事实抽取置信度

### 来源

AI 从对话/笔录/转写文本中抽取案件事实时，为每条抽取结果附加的置信度标注。

### 三档阈值

| 置信度 | 颜色 | 含义 | 一次确认表中的处理 |
|--------|------|------|--------------------|
| **≥ 0.9** | 🟢 直接采信 | 明确提及 | 进入「✅ 已识别信息」栏 |
| **0.6 ~ 0.9** | 🟡 低置信 | 推断/模糊匹配 | 进入「✅ 已识别信息」栏，标注 ⚠️ |
| **< 0.6** | 🔴 不采信 | 猜测/低质 | 进入「🔍 需人工复核」栏 |

### 置信度判断依据

| 置信度 | 典型场景 |
|--------|----------|
| 0.95 | 对话中明确说出"委托人叫张伟" |
| 0.90 | 从"我是原告"推断诉讼地位=原告 |
| 0.85 | "收费捌仟"——金额明确但单位未说明 |
| 0.80 | "民间借贷纠纷"→推断为民事诉讼一审 |
| 0.55 | 录音模糊段"听起来像李强"——需回听确认 |
| 0.40 | 转写质量差，AI 仅能猜测部分字段 |

### 输出格式（一次确认表）

```markdown
## ✅ 已识别信息（请核对）

| 项目 | 值 | 来源 |
|------|-----|------|
| 委托人姓名 | 张伟 | 对话 |
| 律师费金额 | 捌仟 ⚠️低置信 | 对话 |

## 🔍 需人工复核（置信度低，未采信）

- **对方当事人**：识别为「李强」（置信度 0.55）——确认或更正
```

## 两层的协同：录音通道的置信度叠加

录音通道涉及两层置信度的串联——这是本 Skill 特有的复杂度：

```
录音 → ASR 置信度(0~1) → 转写文本 → AI 抽取 → 抽取置信度(0~1) → 确认表
```

**叠加规则**：

- ASR 红色（<0.3）的片段不进抽取，直接进入确认表 `low_confidence_ranges`
- ASR 黄色（0.3-0.5）的片段进入抽取，但抽取置信度**整体降一档**处理（例如原本 0.85 的抽取按 0.75 的规则处理）
- ASR 绿色（≥0.5）的片段正常抽取，抽取置信度不变

**律师端的体验**：

```
[对话通道] "张伟 民间借贷 李强" → 6条事实，全部绿 ✓
[录音通道] 同一段内容录成 mp3 → small 模型转写 →
           5条事实绿 ✓ + 1条黄 ⚠️（"按计件"转成了"案继件"，置信度下降）
```

录音通道比对话通道多一层不确定性，但通过置信度标注，律师清楚地知道哪些该核对、哪些可以直接信。

## 设计决策记录

### 为什么两套阈值

- ASR 面对的是物理信号降级（噪音/口音/同音字），属于**不可修复的误差**
- 事实抽取面对的是语义推理，AI 的判断能力远超 ASR
- 因此 ASR 阈值需要更宽松（接受 0.36 的"基本可用"文本），抽取阈值可以更严格（0.6 以下不采信）

### 为什么不用旧公式

旧公式 `(raw + 1.5) / 2.0` 将中文电话录音的 -0.3 avg_logprob 映射为 0.60，表面看起来"绿色"，但实际上对电话背景噪音完全不敏感，把大量值得复核的片段掩盖了。

新公式 `(raw + 0.50) / 0.55` 将 -0.3 映射为 0.36（黄色），提示律师该段转录可能不完美，但又不至于像原始 logprob 那样让律师完全不知道 -0.3 到底意味着什么。
