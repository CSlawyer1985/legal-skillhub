# 母版中枢 · 委托材料孵化器

> 「母版中枢」系列 · 委托材料这一站：**先从委托材料开始，把手中的模板变成可复用的 AI 母版库，让每一单成套高效产出。这里孵化的不是文书，是您驾驭 AI 的那份从容。** 同一套「模板变量化」方法论，把散落的模板沉淀成所里可传承的资产，后续外溢到起诉状、法律顾问合同等更多场景。

---

## 一、为什么从委托材料开始

AI 能帮律师做文书，早已不是新鲜事——但对大多数律师来说，AI 仍然停在"听说过、不敢用"的阶段。不是不信任技术，而是**不知道从哪里迈出第一步**。

我们的观察是：**委托材料是律师接待客户之后，遇到的第一份模板化法律文书。**

- 它**高频**——每接一单必办，没有例外
- 它**简单**——结构固定、变量清晰，天然适合模板化
- 它**安全**——内容格式来自律所自己的成熟模板，AI 只负责填空，不出终稿

正因为简单，它成了学习"模板化文书 AI 化"的最佳入口：律师在委托材料上学会"把模板挖成变量、建成母版库"这套方法之后，自然能把它迁移到法律顾问合同、起诉状、执行申请等更复杂的文书场景。

**万事开头难。本 Skill 的意义不在于替代律师写委托材料——手工替换确实也不慢——而在于帮不懂 AI 的律师，用最简单、最安全的第一课，跨进这扇门。**

## 二、这个 Skill 解决什么问题

律师接一单委托，要出一整套材料：委托代理合同、风险告知书、授权委托书、律所函……每份都要改人名、案号、金额、日期，一个材料包改几十处。

现状的三道坎：

| 痛点 | 具体表现 |
|------|----------|
| **低效易错** | 每单手工复制旧文档逐个改，漏改一处就是执业风险 |
| **资产沉淀不下来** | 模板散在律师个人电脑里，换电脑就丢，所内无法复用 |
| **想用 AI 不敢用** | 怕 AI 改写格式、怕客户信息上传云端泄露 |

**本 Skill 的思路**：不替律所做模板，而是**教律所把自己的模板变量化**——把每次会变的人名/案号/金额挖成 `{{变量}}`，建成**律所自己的母版库**；之后上传起诉状、笔录、客户录音、或直接口述案件，AI 一次核对后成套产出材料，**格式与律所原模板一字不动**。

**回应「手动替换和 AI 替换速度差不多」这个疑问**：

> 就一份文书而言，两者的速度难分高下。但时间的价值，从来不在"这一次"快不快，而在这一次的投入能否成为下一次的起点——手动替换，快在当下、散在事毕；母版库，慢在开端、快在此后每一单。放到更长的时间尺度看：

| 维度 | 手动替换 | 母版库 |
|------|---------|--------|
| 一年 20 单 | 每单重来一遍 | 建库后每单约 1 分钟 |
| 换电脑 / 换所 / 带新人 | 模板散失，重头再来 | 母版库随所传承，不随个人电脑丢失 |
| 文书场景扩展 | 每类文书都要手工改 | 一套方法外溢到起诉状、顾问合同、执行 |

**本质区别**：手动替换，做完就散了；母版库，让每一次委托都沉淀下来，成为所里可传承的资产。这个 Skill 交付的不是「替你写这一份文书」，而是「把散落在个人电脑里的模板，沉淀成所里代代相传的底气」。

## 三、五大设计理念

| 设计理念 | 具体做法 |
|----------|----------|
| **教方法，不替做** | 内置 15 分钟概念教学（变量/母版/材料包），引导律所从零建库；律师学会后可脱离 Skill 独立维护，方法可迁移到任何文书场景 |
| **资产归所** | 模板、变量字典、材料包清单全部存于律所自己的空间；Skill 不持有、不上传任何律所资产；内置示范包全脱敏（张三/××公司占位） |
| **线上母版·所内复用** | 支持线上模式：母版上传云文档模板库（腾讯文档或金山文档），**所内同事在线直接复用**，模板成为律所共享数字资产；生成走云文档三步法，交付在线链接、可协作编辑 |
| **格式零改动** | 生成时只做 `{{变量}}` 文本替换，字体/字号/行距/表格边框一律不动；用"剥除文本后 XML 逐字节比对"做回归验证 |
| **开箱即用** | 内置脱敏示范包，先看效果再动手；四通道输入任选；最小提问、一次确认 |

## 四、四阶段使用流程

```
阶段0 上手引导 ──→ 阶段1 模板制作 ──→ 阶段2 日常生成 ──→ 阶段3 持续运营
（教概念）        （教+做 建母版库）   （四通道成套产出）   （增量补模板）
   15分钟            每份模板约10分钟       每单约1分钟           随业务成长
```

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| **0 · 上手引导** | 概念教学 + 内置示范包演示 + 准备清单核对 | 律师理解方法，备好自家 DOCX 模板 |
| **1 · 模板制作** | 先选制作模式（线上云文档：腾讯文档/金山文档 / 线下本地）→ 六步流水线：投喂（可批量）→ 脱敏审核 → 分析 → 变量化 → 验收 → 入库 | 母版库 + 变量字典 + 材料包清单（manifest） |
| **2 · 日常生成** | 四通道输入 → 事实提取 → 一次确认 → 批量生成 | 成套委托材料（线上模式交付腾讯文档/金山文档链接，可直接打印盖章） |
| **3 · 持续运营** | 新文书类型补做母版；模板改版重新变量化 | 模板库随业务持续生长 |

## 五、四通道输入：从"零门槛"到"合规增强"

接案信息怎么进来？四条通道任选，事实提取与确认流程完全一致：

| 通道 | 输入方式 | 适用场景 | 门槛 |
|------|----------|----------|------|
| **起诉状通道**（推荐） | 上传民事起诉状/仲裁申请书（docx/pdf） | 已草拟起诉状的案件——起诉状本身含完整当事人/案由/金额/法院信息，无需重复询问 | **零门槛** |
| **对话通道** | 直接向 AI 口述案件情况 | 任何场景，即开即用 | **零门槛，无需任何安装** |
| **笔录通道** | 上传风险告知笔录（docx/pdf/图片） | 接案时已做书面笔录的律所 | 零门槛 |
| **录音通道**（可选增强） | 上传客户谈话录音（mp3/m4a/wav） | 电话谈案、谈话录音留痕的律所 | 需一次性安装本地 ASR（约 10 分钟） |

### 录音通道：为什么坚持"本地离线"

客户谈话录音包含大量个人隐私与案件秘密。《律师法》第 38 条规定律师的保密义务——**把客户录音传给任何云端语音识别服务，都存在合规瑕疵**。

本 Skill 的录音通道采用 **faster-whisper（OpenAI Whisper 模型的本地实现，MIT 开源协议）**：转写全程在律所自己的电脑上完成，不发起任何网络请求，录音数据**从未离开律所电脑**。普通办公笔记本（8GB 内存、无需显卡）即可运行，10 分钟录音约 30-60 秒转完。

> 模型简介、硬件门槛、国内镜像稳定下载方案、常见问题排查，均已整理成文档供参考：`references/whisper-intro.md`

## 六、实测效果（可现场复现）

以下数据均来自真实开发测试，非演示摆拍：

| 测试项 | 结果 |
|--------|------|
| **示范母版变量化** | 委托代理合同母版 **34 个变量**、授权委托书+律所函母版 **20 个变量**，勾选框（☑/□）亦建模为变量 |
| **格式零改动验证** | 剥除 `<w:t>` 文本后，母版与原模板 XML **逐字节一致**——字体、字号、行距、表格边框分毫不动 |
| **对话通道端到端** | 口述"张伟委托我们打民间借贷，被告李强，收费捌仟按计件"一句话 → 自动抽取 11 项事实 → 一次确认 → 产出成套材料，**全程约 1 分钟** |
| **录音通道实测** | TTS 合成中文法律对话录音 → small 模型转写，关键词命中 5/6，置信度分层准确标出唯一瑕疵段 |

### 双层置信度：让律师知道"哪里该核对"

AI 不能替律师拍板，但必须告诉律师**哪里可能错**。本 Skill 设计了覆盖全链路的双层置信度标准（详见 `references/confidence-tiers.md`）：

```
录音 ──Layer1: ASR 转写置信度──→ 文本 ──Layer2: 事实抽取置信度──→ 一次确认表
       ≥0.5 🟢 直接采信                 ≥0.9 🟢 已识别
       0.3~0.5 🟡 附原文核对            0.6~0.9 🟡 标注⚠️
       <0.3 🔴 必须回听                 <0.6 🔴 需人工复核
```

律师看到的确认表按"✅已识别 / 🔍待复核 / ❓待补充"三栏分层——**只看该看的，一次确认完毕**。

## 七、合规与安全设计

1. **数据不出所**：录音转写 100% 本地离线；对话/笔录内容仅在当次会话使用，不写入任何长期存储
2. **资产不共享**：每家律所的母版库存于各自空间，Skill 本身不持有任何一家律所的模板
3. **示范全脱敏**：内置示范包使用"张三/××公司"占位，随 Skill 公开分发零泄露风险
4. **脱敏清单审核**：客户交付原始模板即可，无需手动脱敏——系统自动识别敏感信息（姓名/手机号/身份证号/地址/公司名/银行账号等）生成**脱敏清单**，经客户逐项审核确认后执行脱敏，生成副本供变量化使用；原件保留在律所本地，审核前模板内容不进入任何变量化或共享环节
5. **人审环节强制**：任何通道产出的材料，必须经律师一次确认后才批量生成；AI 不直接产出终稿

## 八、技术架构（复用成熟工具链，不重复造轮子）

| 能力 | 实现 | 说明 |
|------|------|------|
| 母版化引擎 | `scripts/build_master.py` | v5 精确区间替换：单节点替换 → 长词优先防污染 → 按映射区间精确替换（解决 Word 把日期拆进多个 XML 节点的经典坑，且不丢下划线、不拆行）；内置映射冲突检测、原子写入、T9+run 绑定双校验 |
| 模板分析 | `scripts/analyze_templates.py` | 段落+表格+页眉页脚全量提取；15 类疑似变量正则候选；脱敏告警；多套文书检测、布局画像、别名归一提示 |
| 事实核对 | `scripts/extract_case.py` | 变量字典归并 + 勾选框占位族展开 + 三栏分层确认表生成 |
| 页数核对 | `scripts/check_pages.py` | 检测分页标记估算页数 + 分析"替换后变长"变量，提示分页风险（T9 覆盖不到的盲区） |
| 录音转写 | `scripts/transcribe_audio.py` | faster-whisper 封装；置信度校准公式针对中文法律电话录音调优 |
| 分页符插入 | `scripts/insert_page_break.py` | 两套文书之间安全插入分页符，单次字符串替换 + 段落数/XML/分页数三重自检（杜绝逐段偏移替换截断段落） |
| 批量生成 | 云文档三步法（腾讯文档 / 金山文档） | 腾讯文档：copy_file → set_privilege → find_and_replace；金山文档：copy_file → share_file → replaceContent；同名变量跨材料一次替换、处处一致 |

全部脚本（含回归测试）合计约 2100 行 Python，依赖均为成熟开源库（python-docx 生态 / faster-whisper），无境外服务依赖。

## 十、从第一课到整个课堂

委托材料只是起点。我们设想的路径是：

- **律所内**：一个律师学会 → 带全所建库 → 模板库成为律所数字资产
- **律所间**：Skill 包（含教学方法与工具链）可直接分发；各家建各家的库，互不涉密
- **方法外溢**：变量化方法论同样适用于法律顾问合同、起诉状、执行申请等任何高频文书场景——本 Skill 教的是"渔"，不是"鱼"

律师行业的 AI 普及，不缺高大上的系统，缺的是一位普通律师敢用、会用、用得放心的**第一课**。我们希望委托材料孵化器就是这第一课。
