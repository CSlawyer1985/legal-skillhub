# 标签体系质量审查详细规则

## 三项逻辑准则

### 准则 A｜逻辑自洽

同一维度内的标签必须属于同一逻辑层面。

**违反示例**：
创新点维度中同时出现：
- "结构创新"（抽象层）
- "螺栓连接方式改进"（具体层）

后者应为前者的下位概念，不应并列出现于同一层级。

**修改建议**：将具体层标签归入上位标签之下，或删除具体层标签。

### 准则 B｜层次分明

若标签体系含上下位关系，上位标签与下位标签不得出现在同一维度的同一层级中。

**违反示例**：
功能维度中同时出现：
- "数据传输"（上位）
- "蓝牙数据传输"（下位）

标引时无法判断应归入上位还是下位。

**修改建议**：将上下位标签拆分为不同层级，或统一为同一层级（如全部用下位标签）。

### 准则 C｜边界清晰

同一维度内任意两个标签的外延不得显著重叠。

**违反示例**：
效果维度中同时出现：
- "提升效率"
- "提高生产速度"

二者在多数技术语境下语义高度重叠。

**修改建议**：合并为一个标签，或重新定义以消除语义重叠。

## 审查报告格式

```
⚠ 标签体系审查报告

维度：[维度名称]
问题标签：[标签A] 与 [标签B]
违反准则：[A/B/C]
问题说明：[简要描述重叠/层级混淆/逻辑不自洽的具体表现]
修改建议：[合并 / 删除其一 / 拆分 / 调整层级]

（如有多组问题，逐条列出）
```

## 审查执行流程

1. 对用户提供的每一个维度，逐一检查标签是否违反上述三项准则
2. 发现违反 → 输出审查报告，等待用户修改
3. 用户修改后重新提交 → 重新审查
4. 用户明确表示"维持原标签体系" → 在后续标引中标注"用户已知悉标签 [A] 与 [B] 存在重叠，维持使用"，继续流程
5. 全部维度均通过 → 静默进入下一步骤
