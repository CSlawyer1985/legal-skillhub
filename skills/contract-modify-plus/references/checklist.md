# checklist.md — 合同修改审查清单（三方法论融合版）

> 与 SKILL.md 配套，作为 **Step 3「三观逐层两比一找」** 的分层核查工具。
> 本清单融合三部方法论：
> 1. **《合同起草审查指南：三观四步法（第五版）》**——提供"宏观/中观/微观"三观视角与"沟通/规划/审查修改/复核"四步流程（本清单的**视角顺序与流程骨架**）。
> 2. **《完美的合同：合同的基本原理及审查与修改（第四版）》**（吴江水，北京大学出版社 2024.4）——提供"三重质量标准（内在/外在/版式）+ 五大基本模块（质量/价格/期限/对象/违约）+ 两比一找"（本清单的**审查标尺与交易主线**）。
> 3. **《合同审查与修改实务》**（杨司和，2022）——提供"增删改调"技术动作与"表述/体例技术规范"（本清单的**动作落点与文字要求**）。
>
> 民法典规范体系贯穿全程，华宇元典 MCP 为法条校验防线。

## 〇、四步流程映射（对应《三观四步法》）

| 四步 | 本清单对应阶段 | 关键动作 |
|---|---|---|
| 沟通 | 接收合同、明确交易目的与授权边界 | 搞清"改什么、为谁改、能改到哪" |
| 规划 | 加载 PLAYBOOK、确定三观审视路径 | 定锚立场与审查顺序 |
| 审查修改 | 第一~三部分（宏观→中观→微观）逐层两比一找 | 核心产出，落 `modify-plan.json` |
| 复核 | 第四部分（复核收口） | 三观回溯 + 两比一找闭环 + 事实一致性 |

## 一、动作决策矩阵（最小必要修改 + 杨司和"增删改调"）

| 情形 | 动作(action) | 修订痕迹 | 三观视角 | 质量维度/模块 |
|---|---|---|---|---|
| 主体名称错、金额/日期前后不一致、编号错、术语不统一 | `replace`/`delete` | 是 | 微观/宏观 | inner/outer；object |
| 明显违法、明显失衡、不可执行表述 | `replace` | 是 | 微观 | inner；各模块 |
| 缺关键条款（违约/解除/争议解决/保密） | `insert` | 是 | 中观/微观 | inner；liability |
| 合同定性错误（名实不符，如"合作"实为"借款"） | `comment`/`replace` | 视情况 | **宏观** | inner/outer；object |
| 主体不适格、授权缺失 | `replace`/`comment` | 是/批注 | **宏观** | inner；object |
| 应报批/登记/备案/内部程序缺失 | `comment`/`insert` | 视情况 | **宏观** | inner；object |
| 交易模式违法（违反效力性强制规定） | `comment` | 否（提示） | **宏观** | inner；object |
| 格式条款未公平拟写（民法典第 496–498 条） | `replace`/`comment` | 是/批注 | 微观 | inner；price/liability |
| 免责/限制责任条款违法（民法典第 506 条） | `replace`/`comment` | 是/批注 | 微观 | inner；liability |
| 意向书/预约/阴阳合同/空白合同风险 | `comment` | 否（提示） | **中观** | outer |
| 体例缺失、章节/编号/交叉引用错乱 | `replace`/`insert` | 是 | **中观** | outer |
| 定义表/签署栏/附件清单不齐 | `insert`/`replace` | 是 | **中观** | outer |
| 权利义务群（义务清单）遗漏、失衡 | `insert`/`replace` | 是 | 中观/微观 | inner；各模块 |
| 价格、比例、期限、范围等商务取舍 | `comment` | 否（批注） | 微观 | 微观商务；price/term |
| 名称/金额/日期/附件等留空信息 | `comment` | 否（提示补录） | 微观 | layout |
| 词句歧义、句式异常、重点词语误用 | `replace` | 是 | 微观 | outer；语言 |
| 引用不规范（"相关规定"、缺条号） | `replace` | 是 | 微观 | outer；语言 |
| 纯优化、说明型问题 | `comment`/仅入说明 | 否 | 微观 | outer/layout |

> 杨司和"增删改调"：增=`insert`，删=`delete`，改=`replace`，调=`comment`（不直接改文，留批注待客户决断）。

## 二、三观分层检查项（审查修改阶段主体）

### 【宏观 Macro】交易结构·先决层（对应对象模块 + 内在质量"与法律比"）
- [ ] **交易定性**：合同名实相符？"合作/租赁/服务"是否实为"借款/买卖/劳动"？定性错误优先 `comment`/`replace` 并提示。
- [ ] **主体适格**：各方全称、统一社会信用代码、法定代表人准确（可用企查查 MCP / 华宇元典核验）。
- [ ] **主体授权**：签字/盖章权限完整，无越权代理风险。
- [ ] **交易模式合法**：不违反效力性强制规定（民法典第 153 条）。
- [ ] **合同程序**：需批准/登记/备案/内部决策的是否齐备（第 502 条等）。
- [ ] **担保/增信**：抵押/质押/保证是否齐备、可执行。

### 【中观 Meso】合同形式·体例·交易条件层（对应外在质量 + 五大模块权利义务主线）
- [ ] **合同形式**：与交易阶段匹配（意向书/预约/本约，民法典第 495 条）；无阴阳合同、空白合同。
- [ ] **体例结构**：首部/正文/签署/附件齐全；章节编号连续、交叉引用无误。
- [ ] **定义与签署**：定义表与正文用词统一；签署栏要素（名称/授权/日期/盖章）齐备。
- [ ] **交易条件闭环（义务群）**：五大模块逐项比对 Playbook 立场：
  - [ ] Quality 质量模块：标的、规格、标准、验收节点、质保期明确。
  - [ ] Price 价格模块：价款/报酬、支付节奏、发票、调价机制清晰。
  - [ ] Term 期限模块：履行期限、生效、解除/终止、续展齐备。
  - [ ] Object 对象模块（中观侧）：交易条件中的相对方义务与增信落实。
  - [ ] Liability 违约模块：违约责任、赔偿范围、管辖/送达、保密/IP 无缺口。
- [ ] **权利义务对称**：甲方义务对应乙方权利，无单向义务群遗漏。

### 【微观 Micro】条款·文字层（对应内在/外在质量"语言" + 两比一找 + 杨司和表述技术）
**与法律比（合法性·逐条）：**
- [ ] 格式条款公平拟写（民法典第 496–498 条）。
- [ ] 免责/限制责任条款不落入无效情形（民法典第 506 条）。
- [ ] 具体条款效力（违约金过高可调整、质保法定下限等）。

**与利益比（利己性/利益平衡·逐条）：**
- [ ] 五大模块逐条比对 Playbook 标准立场；失衡/不可执行 → `replace`/`comment`。

**找缺陷（逐条）：**
- [ ] 效力瑕疵、歧义、重点词误用（应当/可以/有权/视为）。
- [ ] 句式异常、引用不规范（须写全称+条号）、金额/日期/比例前后不一致。
- [ ] 杨司和表述技术落地：模糊词（"等/相关/适当"）清理、列举项规范、否定范围明确、长句嵌套≤两层。

### 【版式 Layout】呈现规范层（交付前由 Step 5 统一处理，此处仅核查提示）
- [ ] 签署栏、落款完整。
- [ ] 附件清单、编号体系一致。
- [ ] 留白字段已 `comment` 提示补录。
- [ ] 页码（Step 5 统一插入）。

## 二-补、实战审查要点（九维·龚家勇律师实务提炼）

> 本段将「从律师视角修改合同的要点」（龚家勇律师实务提炼，2026-07-31）映射至三观视角与五大模块，作为 Step 3「两比一找」的**实战维度补充清单**。其与上文三观分层检查项同源互补：上文偏"结构—质量"视角，本段偏"交易实务"视角，二者交叉核对、不得相互替代。
>
> 九大维度 → 三观视角 / 五大模块 映射：
>
> | 维度 | 三观视角 | 五大模块 | 核心关切 |
> |---|---|---|---|
> | ① 主体资格审查 | 宏观 | Object | 适格性、履约能力、代理权限 |
> | ② 合同标的与标的条款 | 宏观/中观 | Quality | 具体可识别、权属与瑕疵担保 |
> | ③ 价款与支付条款 | 中观/微观 | Price | 金额明确、节点挂钩、账户锁定 |
> | ④ 履行期限、地点与方式 | 中观/微观 | Term | 可操作、管辖与风险转移连接点 |
> | ⑤ 违约责任 | 微观 | Liability | 枚举化、可计算、救济并列 |
> | ⑥ 保密、知识产权与不可抗力 | 微观 | Liability（附随） | 期限、归属、定义与后果 |
> | ⑦ 争议解决与管辖 | 微观 | Liability | 仲裁/诉讼择一、管辖有效 |
> | ⑧ 合同效力与形式要件 | 宏观/中观 | Object/Layout | 生效条件、签署规范 |
> | ⑨ 律师修改通用方法论 | 贯穿 | 全模块 | 风险分级、事实一致性、观点区分 |

### ① 主体资格审查（前置校验·宏观/Object）
- [ ] **签约主体适格**：自然人核身份证与行为能力；法人核营业执照、统一社会信用代码、法定代表人身份，必要时调工商登记档案（企查查/天眼查 MCP）。
- [ ] **履约能力与资信**：是否存在经营异常、行政处罚、大额未决诉讼、失信被执行记录（可用 qcc/tyc MCP 核验）。
- [ ] **代理权限**：签约人是否持合法有效授权委托书，授权范围覆盖本次合同事项；越权代理风险 → `replace`/`comment`。
- [ ] **风险标注**：主体不适格/资信瑕疵 → 高/中风险 `comment` 提示，不替客户决断交易与否。

### ② 合同标的与标的条款（宏观/中观·Quality）
- [ ] **标的描述具体可识别**：名称、规格、型号、数量、质量标准唯一确定，清理"优质""合格"等模糊表述 → `replace`。
- [ ] **权属与瑕疵担保**：标的是否存在抵押/质押/查封；卖方应承诺无权利瑕疵 → `insert`/`replace`。

### ③ 价款与支付条款（中观/微观·Price）
- [ ] **金额与币种明确**：大小写一致；含税与否、税率、发票类型（增值税专用/普通）写明。
- [ ] **支付节点与条件挂钩**：采用"里程碑+验收"付款，而非单纯时间节点；预留质保金（通常 5%–10%）→ `insert`/`replace`。
- [ ] **收款账户锁定**：指定唯一收款账户，约定账户变更须书面确认，防范冒领 → `insert`。

### ④ 履行期限、地点与方式（中观/微观·Term）
- [ ] **时间可操作**：清理"尽快""适时"等不确定词；明确起算点与宽限期 → `replace`。
- [ ] **履行地点关联管辖与风险转移**：交货地/服务地直接影响诉讼管辖与标的物毁损风险承担，须明确 → `replace`/`insert`。

### ⑤ 违约责任（微观·Liability）
- [ ] **违约情形枚举化**：迟延付款/迟延交付/质量不符/根本违约分别设定责任 → `insert`/`replace`。
- [ ] **违约金可计算且不过高**：以实际损失为基准，避免被依《民法典》第 585 条酌减；可约定"每日万分之五"等明确比例 → `replace`。
- [ ] **救济手段并列**：继续履行、解除合同、赔偿损失、违约金请求权可并存，不宜相互排斥 → `replace`/`comment`。

### ⑥ 保密、知识产权与不可抗力（微观·Liability 附随）
- [ ] **保密义务**：期限覆盖合同终止后（常设 2–5 年），明确保密信息范围与例外 → `insert`/`replace`。
- [ ] **知识产权归属**：委托创作、合作开发成果归谁，使用许可范围清晰 → `insert`/`replace`。
- [ ] **不可抗力定义**：列举具体情形，约定通知义务与后果（延期或解除）→ `insert`/`replace`。

### ⑦ 争议解决与管辖（微观·Liability）
- [ ] **仲裁/诉讼择一**：二者不得同时约定；仲裁一裁终局、保密性强，诉讼可上诉 → `replace`。
- [ ] **管辖法院明确**：约定与合同有实际连接点的法院（履行地/被告住所地等），避免"由原告所在地法院管辖"被认定无效的风险 → `replace`。

### ⑧ 合同效力与形式要件（宏观/中观·Object/Layout）
- [ ] **生效条件**：签字盖章、预付款到账、审批通过等生效要件写明 → `insert`/`replace`。
- [ ] **签署规范**：核对签章与备案印鉴一致；多页合同加盖骑缝章；附件须双方确认 → `comment`/`insert`。

### ⑨ 律师修改通用方法论（贯穿·全模块）
- [ ] **逐条标注风险等级**（高/中/低），区分"必须改/建议改/可谈判"。
- [ ] **保持事实一致性**：不擅自改动当事人名称、金额、日期等关键信息；发现矛盾主动提示委托人核对。
- [ ] **区分事实与观点**：修改建议附依据（法条/案例/交易惯例），不将策略判断包装为必然结论。
- [ ] **提示反向风险**：任何从严条款都可能对委托人谈判地位产生反作用，须同步说明。

## 三、复核收口（对应《三观四步法》第四步）

- [ ] **三观回溯**：宏观→中观→微观修改无遗漏、无错位；宏观硬伤已优先处理。
- [ ] **两比一找闭环**：合法性、利己性、缺陷三项均已覆盖，无遗漏 finding。
- [ ] **事实一致性**：未改变原合同日期、金额、当事人称谓等关键信息（笔误修正已在说明标注）。
- [ ] **法条核验**：所有 `legal_basis` 经华宇元典核验，`unverified` 项已汇总提示人工复核。
- [ ] **理念约束**：修改契合"交易目的导向、利益平衡与可交易性、歧义控制"，无过度修改阻碍交易。

## 四、禁止项

- 不得擅自改变原合同日期、金额、当事人称谓等关键信息（笔误修正须在说明中标注）。
- 不得代客户决断事实（如"实际交货日应为 X"）。
- 不得将未核验法条写入修订。
- **宏观/中观缺陷不得被微观优化掩盖**：发现定性错误、主体不适格、效力瑕疵，应优先提示，不先纠结措辞。
- 修改须受三大理念约束：不因过度严苛或冗余条款阻碍合法交易达成，不因文字优化制造新的歧义。
- 杨司和"增删改调"纪律：确定性错误用增/删/改落修订痕迹；商务取舍与事实缺口用"调"（批注），不越权代决。
