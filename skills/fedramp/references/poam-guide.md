# POA&M 指南

行动计划与里程碑（POA&M）是 SSP 的附录 O。它记录所有已知安全弱点以及云服务提供商（CSP）的补救计划。POA&M 是活文档——在持续监控期间每月更新。

> 始终使用官方 FedRAMP POA&M 模板。

---

## POA&M 行字段（必需）

| 字段 | 描述 |
|---|---|
| POA&M 项目 ID | 唯一标识符（如 V-001、F-001） |
| 控制项 | 受影响的 NIST 800-53 Rev 5 控制项 ID |
| 弱点名称 | 调查结果的简要名称 |
| 弱点描述 | 差距或漏洞的详细描述 |
| 联系人 | 负责补救的人员/团队 |
| 所需资源 | 所需工具、预算、人员 |
| 总体补救计划 | 如何修复弱点 |
| 原始检测日期 | 首次识别于何时？ |
| 计划完成日期 | 目标补救日期（必须满足 SLA） |
| 里程碑变更 | 跟踪日期/描述变更 |
| 状态 | 未解决 / 已解决 / 风险调整 / 供应商依赖 |
| 备注 | 额外背景 |
| 自动批准 | 由 3PAO 自动关闭的标记 |
| 偏差请求已批准 | 是/否——针对经 AO 批准的 DR |
| 风险评级（原始） | 严重 / 高 / 中 / 低 |
| 风险调整 | 如已调整风险，新的风险等级和理由 |
| 误报 | 是/否 |
| 运营需求 | 是/否（如偏差系运营必要性） |

---

## FedRAMP 补救 SLA

| 风险评级 | 补救期限（自识别起） |
|---|---|
| 严重（在与高区分时） | ≤ 30 个日历日——立即优先处理 |
| 高 | 30 个日历日 |
| 中 | 90 个日历日 |
| 低 | 180 个日历日 |

来源：FedRAMP 持续监控绩效管理指南。错过 SLA 是最常见的持续监控调查结果之一。仔细跟踪。

---

## POA&M 项目类型

### 标准调查结果（F-）
- 由 3PAO 在评估或年度评估期间识别
- 必须在 SLA 内补救

### 供应商依赖（VD-）
- 补救依赖第三方（操作系统供应商、SaaS 工具、IaaS 提供者）
- 必须记录：供应商名称、跟踪 ID（CVE 或供应商工单）、预期修复日期
- 3PAO 在年度评估中验证 VD
- AO 必须同意接受 VD；CSP 必须有补偿控制

### 偏差请求（DR-）
三种子类型：
1. **误报（FP）**：调查结果实际上不是漏洞——提供证据
2. **风险调整（RA）**：漏洞存在，但因缓解因素风险较低——必须量化
3. **运营需求（OR）**：漏洞无法在不破坏功能的情况下修复——必须记录商业理由和补偿控制

所有 DR 在 POA&M 中标记前均需机构 AO 批准。

---

## POA&M 撰写技巧

1. **一项调查结果一行**——不要将多个漏洞捆绑到单个 POA&M 项目中
2. **CVE 要具体**——对漏洞扫描调查结果，始终包含 CVE ID
3. **里程碑日期必须现实**——过度承诺和错过里程碑本身即是调查结果
4. **已关闭项目需要证据**——关闭项目时，记录补救证据（扫描结果、配置截图、日期）
5. **清单表是必需的**——POA&M 模板包含清单标签页；保持其最新
6. **与 SAR 调查结果对应**——SAR 中的每项调查结果必须出现在 POA&M 中；审查者会交叉引用

## 初始授权期间与持续监控期间的 POA&M

**初始授权：**
- POA&M 记录 3PAO 评估的剩余风险（ATO 前未补救的 SAR 调查结果）
- 机构 AO 审查并在授予 ATO 时接受剩余风险
- 中/高风险项目如未补救或未获偏差批准，可能阻碍 ATO

**持续监控：**
- POA&M 每月更新
- 每月提交机构 AO
- 未解决项目必须显示积极进展（里程碑更新）
- 过期的 POA&M 项目（无更新、错过里程碑）可能触发 ATO 暂停
