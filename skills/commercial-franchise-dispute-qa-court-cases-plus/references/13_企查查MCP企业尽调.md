# 企查查 MCP 企业尽调通道（特许人主体核查）

> 本文件定义在「商业特许经营纠纷问答+法院案例Plus」技能中，如何用**企查查 MCP** 对加盟公司（特许人）做主体资格与合规尽调。加盟公司名称由技能启动第0步「维度三」经 `AskUserQuestion` 主动向用户收集。

## 一、通道定位与连接状态

- **连接名**：`qcc-company`（企查查）
- **定位**：特许人主体尽调的**优先通道**——工商登记、股东结构、对外投资、涉诉信息、行政处罚、经营异常、知识产权（商标/专利）等一站式查询。
- **✅ 当前连接状态：connected（已连接，工具已注册可用）**
  - 已于 2026-07-11 实测验证：`get_company_by_query`（搜"蜜雪冰城股份有限公司"）精准锁定唯一主体，返回统一社会信用代码。
  - 工具名已确定（见下方标准流程），**无需每次再 ToolSearch 确认**；若后续工具清单有变，可用 `ToolSearch`（关键词 `qcc`/`企查查`）核验。
  - 企查查不可用时，转用下文"备选通道·华宇元典 MCP"。

## 二、尽调核查项（特许经营纠纷针对性）

| 核查项 | 意义 | 与本库规则的衔接 |
|---|---|---|
| **主体性质**（是否企业法人） | 特许人须为企业；自然人/个体户签特许经营合同→合同**无效** | 最高法〔2010〕民三他字第19号复函（见 `04`） |
| 成立日期、注册资本、经营状态 | 存续/注销/吊销；成立时间关系"两店一年" | 《条例》第7条（见 `01`） |
| 是否具备"两店一年"、是否**备案** | 欠缺为管理性瑕疵，不影响效力但为欺诈佐证 | 18号复函（见 `04`）、备案办法（见 `02`） |
| **涉诉分布**（作为被告的特许经营合同纠纷数量、批量退费诉讼） | 大量同类退费诉讼是**"套路加盟"**重要信号 | `07`/`10` 套路加盟刑民界分 |
| **行政处罚**（虚假宣传、无证经营等） | 佐证信息披露欺诈、经营合规瑕疵 | 《条例》第23-29条（见 `01`）、信息披露办法（见 `03`） |
| **破产/清算/执行/失信**（经营恶化信号） | 特许人偿付能力存疑，影响返还可执行性 | 民法典清偿（见 `11`） |
| **投诉**（黑猫/12315 等消费者集中投诉） | 大量同类"加盟不退费"投诉=套路加盟信号 | `07`/`10` 套路加盟刑民界分 |
| 股东/实控人/关联企业 | 识别"金蝉脱壳"、关联转移经营资源 | 民法典撤销权（见 `11`） |

## 二·附 企查查标准工具链（已验证可用）

**步骤 0 · 锁定主体**：`get_company_by_query`（传 `searchKey` = 公司名称/简称/品牌名）
- 返回"唯一精确匹配"→ 取**统一社会信用代码**，`searchKey` 改传该代码，直调下游；
- 返回"多候选"（≤5）→ **完整列出候选交用户选定**，禁止自挑排名第一（防错主体）；
- 未匹配 → 提示核对关键词重试。

**步骤 1 · 工商登记（主体资格核心）**：`get_company_registration_info`（传 `searchKey` = 名称或信用代码）
- 取：法定代表人、注册资本、成立日期、登记状态（存续/注销/吊销）、注册地址 → 直接对应本库 `04` 的 19 号复函（是否企业法人）、`01` 的"两店一年"。

**步骤 2 · 企业画像**：`get_company_profile`（传 `searchKey`）→ 业务模式/产品，辅助判断是否真实特许经营业态。

**步骤 3 · 股权穿透**：`get_shareholder_info`（一层股东）/ `get_actual_controller`（实控人）/ `get_beneficial_owners`（UBO，AML 口径）/ `get_branches`（分支机构）。

**步骤 4 · 经营异常/变更**：`get_change_records`（变更聚合）/ `get_annual_reports`（年报）。

**步骤 5 · 财务（可选）**：`get_financial_data`。

**数据纪律（企查查工具自带约束，必须遵从）**：
- 股权/财务比例（总持股、表决权、净利率等）为服务端**已聚合的终值**，AI 须**逐字引用**，禁止自乘重构或"四舍五入"圆场；
- 禁止臆测中间层主体（如"通过 X 间接持股"）——工具不返回逐路径中间层；
- 聚合值与任何自算分项不一致时，以工具返回值为准。

> 企查查当前**暂无直接"涉诉/行政处罚"专属工具**（其强项为工商/股权/财务）。涉诉分布、行政处罚仍以**华宇元典 MCP**（`rh_enterpriseWritAgg`/`rh_enterpriseWritList`/`rh_enterprisePunishment`）为主；企查查侧重主体资格与股权结构核查。

## 三、备选通道 · 华宇元典 MCP（已连接，企查查不可用时回退）

连接名 `yuandian-mcp`（connected）。企业尽调相关接口（以 MCP 实际注册为准，可用 `list_apis`/`get_api_doc` 核验）：

| 接口 | 用途 |
|---|---|
| `rh_company_info` / `rh_company_detail` | 工商基本信息、主体资格 |
| `rh_enterpriseAggregationSummary` | 企业多模块统计总览（各类信息聚合 + Top20 摘要） |
| `rh_enterpriseWritAgg` | 涉诉信息**分布统计**（案件类别、案由、文书种类、审判程序、法院层级、结案方式、结案年份、地域、诉讼身份、对手当事人身份） |
| `rh_enterpriseWritList` | 涉诉**明细**列表 |
| `rh_enterprisePunishment` | 行政处罚 |
| `rh_enterpriseAnnualReport` | 企业年报（基本信息、股东出资、资产、对外投资/担保等；须传年份 `year`） |

> 入参一般支持企业 `id` 或统一社会信用代码 `tyshxydm`；仅有公司名称时，先经企业检索接口取得 id/信用代码，再查明细。

## 四、调用与输出规范

1. **触发**：仅当技能启动第0步「维度三」用户**填写了加盟公司名称**时执行；留空则跳过，并在输出**第六段"需要注意的其他问题"**注明"用户未提供特许人名称，未做主体尽调，建议补充后核查"。
2. **通道选择**：企查查（`qcc-company`，**已连接**） → 优先用企查查（工商/股权/财务/经营异常强项，更快更全）；仅当企查查偶发不可用时，回退华宇元典企业接口——不得因单一通道失败而中断尽调。
3. **⚠️ 并行化（强制）**：企查查侧 `get_company_by_query` 与 `get_company_registration_info` 一并并行；华宇元典侧 `rh_enterpriseBaseInfo`/`rh_enterpriseAggregationSummary`/`rh_enterpriseWritAgg`/`rh_enterpriseWritList`/`rh_enterprisePunishment`/`rh_enterpriseSeriousIllegal`/`rh_enterpriseAnnualReport` 等**互不依赖、一次并行发出**（均仅以统一社会信用代码/企业ID为入参）。详见 SKILL.md「三·五、并行化执行规范」第2条。任何尽职接口不得为提速而串行等待或省去。
3. **核查项（三通道合查）**：
   - **企查查 MCP**（`qcc-company`）：主体性质（是否企业法人）、登记状态、经营范围/业态、股东/实控人/UBO、变更、年报、财务。
   - **华宇元典 MCP**（`yuandian-mcp`）：涉诉分布（`rh_enterpriseWritAgg`/`rh_enterpriseWritList`）、行政处罚（`rh_enterprisePunishment`）、破产/执行/失信等（见 `rh_enterpriseExecutions`/`rh_enterpriseExecutedPerson` 等）。
   - **公开网站核查**：国家企业信用信息公示系统（登记/处罚/经营异常/严重违法）、中国裁判文书网（诉讼）、信用中国（失信/破产程序）、黑猫投诉/全国12315平台（消费者投诉）。**注：公开网站的实时抓取受环境限制，能访问时以之佐证，无法访问时以 MCP 返回为准并注明"公开网站未能实时核验"**。
4. **⚠️ 不良信息导向输出（强制，对接 SKILL 第六段）**：
   - **无不良信息**：经三通道核查，被查公司**无**处罚、诉讼、破产、投诉等任何不良信息 → **第六段"特许人主体尽调结论"整体不体现**（不写"经核查无不良"等中性冗余结论，直接省略该小节）。
   - **有不良信息**：被查公司存在任一不良（处罚/诉讼/破产/投诉等）→ **在本段展示具体不良信息**：列明类型、来源（企查查/华宇元典/公开网站）、查询日期、关键内容（诉讼须注案由/批量同类退费=套路加盟信号；处罚须注违规事由；投诉须注主题/平台；破产须注程序阶段）。
5. **结果回填**：尽调结论（仅当有不良信息时）写入输出**第六段**，覆盖上述具体不良项；主体资格异常（如非企业法人）本身即属不良信号，须展示。
6. **溯源标注**：企查查结果标注"企查查 MCP（YYYY-MM-DD）"；华宇元典结果标注"华宇元典法律数据 MCP（YYYY-MM-DD）"；公开网站标注站点名与访问日期。
7. **禁止编造**：MCP / 公开网站未返回的工商/涉诉/处罚/投诉信息不得凭记忆生成；查无结果如实标注"未查询到/接口无返回"。
8. **重要结论**（如"主体为个体户→合同可能无效""业态与奶茶加盟严重不符"）须提示用户以**国家企业信用信息公示系统/裁判文书网/信用中国**等官方渠道最终核验。
