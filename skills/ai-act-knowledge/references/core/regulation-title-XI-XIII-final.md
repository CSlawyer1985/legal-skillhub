## 附件三——第 6 条第 2 款所指的高风险人工智能系统

根据第 6 条第 2 款，高风险人工智能系统为以下任一领域所列的人工智能系统：

| 1. | 生物识别，只要其使用在相关欧盟或国家法律下被允许：

(a) 远程生物识别系统。<br>这不包括拟用于生物识别验证、且唯一目的是确认某一特定自然人确为其所声称之人的人工智能系统；

(b) 拟用于根据敏感或受保护属性或特征进行推断，进而进行生物识别分类的人工智能系统；

(c) 拟用于情绪识别的人工智能系统。 |

| 2. | 关键基础设施：拟作为安全部件用于关键数字基础设施、道路交通的管理和运行，或用于水、燃气、供暖或电力供应的 AI 系统。 |

| 3. | 教育和职业培训：

(a) 拟用于确定接受教育或录取资格，或将自然人分配到各级教育和职业培训机构的人工智能系统；

(b) 拟用于评估学习成果的人工智能系统，包括当这些成果被用于引导各级教育和职业培训机构中自然人的学习过程时；

(c) 拟用于评估个人在各级教育和职业培训机构中将要获得或能够获得的适当教育水平的人工智能系统；

(d) 拟用于在各级教育和职业培训机构的考试中监测和检测学生违规行为的人工智能系统。 |

| 4. | 就业、劳动者管理及自主就业准入：

(a) 拟用于招聘或选拔自然人的人工智能系统，尤其是用于投放定向招聘广告、分析和筛选求职申请以及评估候选人；

(b) 拟用于作出影响工作关系条款、晋升或终止劳动关系合同关系的决定，根据个人行为或个人特质或特征分配任务，或监测和评估此类关系中人员的表现和行为的 AI 系统。 |

| 5. | 获取和享受基本私人服务以及基本公共服务和福利：

(a) 拟由公共当局或代表公共当局使用，用于评估自然人获得基本公共援助福利和服务（包括医疗服务）的资格，以及用于授予、减少、撤销或收回此类福利和服务的人工智能系统；

(b) 拟用于评估自然人信用worthiness或确定其信用评分的 AI 系统，但用于检测金融欺诈的 AI 系统除外；

(c) 拟用于人寿保险和健康保险情形中对自然人进行风险评估和定价的 AI 系统；

(d) 拟用于评估和分类自然人紧急呼叫，或用于调度紧急第一响应服务（包括警察、消防和医疗救助）或确定其调度优先级，以及用于紧急医疗患者分诊系统的 AI 系统。 |

| 6. | 执法，只要其使用在相关欧盟或国家法律下被允许：

(a) 拟由执法机关或代表执法机关使用，或由欧盟机构、团体、办公室或机构为支持执法机关或代表执法机关使用，以评估自然人成为刑事犯罪受害者风险的人工智能系统；

(b) 拟由执法机关或代表执法机关使用，或由欧盟机构、团体、办公室或机构为支持执法机关使用，作为测谎仪或类似工具的人工智能系统；

(c) 拟由执法机关或代表执法机关使用，或由欧盟机构、团体、办公室或机构为支持执法机关使用，以在刑事犯罪的调查或起诉过程中评估证据可靠性的人工智能系统；

(d) 拟由执法机关或代表执法机关使用，或由欧盟机构、团体、办公室或机构为支持执法机关使用，以评估自然人犯罪或再犯罪风险的人工智能系统，且该评估并非仅基于指令 (EU) 2016/680 第 3 条第 4 款所指的自然人画像，或用于评估自然人群体的人格特质和特征或过往犯罪行为；

(e) 拟由执法机关或代表执法机关使用，或由欧盟机构、团体、办公室或机构为支持执法机关使用，以在刑事犯罪的侦查、调查或起诉过程中对指令 (EU) 2016/680 第 3 条第 4 款所指的自然人进行画像的人工智能系统。 |

| 7. | 移民、庇护和边境管理，只要其使用在相关欧盟或国家法律下被允许：

(a) 拟由主管公共当局或代表主管公共当局使用，或由欧盟机构、团体、办公室或机构作为测谎仪或类似工具使用的人工智能系统；

(b) 拟由主管公共当局或代表主管公共当局使用，或由欧盟机构、团体、办公室或机构使用，以评估拟进入或已进入成员国领土的自然人所带来的风险（包括安全风险、非正常移民风险或健康风险）的人工智能系统；

(c) 拟由主管公共当局或代表主管公共当局使用，或由欧盟机构、团体、办公室或机构使用，以协助主管公共当局审查庇护、签证或居留许可申请及相关申诉，涉及申请某种身份的自然人是否符合资格，包括对证据可靠性的相关评估的人工智能系统；

(d) 拟由主管公共当局或代表主管公共当局使用，或由欧盟机构、团体、办公室或机构在移民、庇护或边境管理背景下使用，以检测、识别或确认自然人身份的人工智能系统，但旅行证件查验除外。 |

| 8. | 司法行政和民主进程：

(a) 拟由司法机关或代表司法机关使用，以协助司法机关研究和解释事实和法律并将法律适用于具体事实，或以类似方式用于替代性争议解决的人工智能系统；

(b) 拟用于影响选举或公投结果或影响自然人在选举或公投中行使投票时的投票行为的 AI 系统。这不包括自然人未直接接触其输出的 AI 系统，例如从行政或后勤角度用于组织、优化或构建政治竞选活动的工具。 |

## 附件四——第 11 条第 1 款所指的技术文档

第 11 条第 1 款所指的技术文档应至少包含以下适用于相关 AI 系统的信息：

| 1. | AI 系统的一般描述，包括：

(a) 其预期目的、提供者名称及体现其与先前版本关系的系统版本；

(b) AI 系统如何与不属于 AI 系统本身的硬件或软件（包括其他 AI 系统）交互，或可如何用于与之交互（如适用）；

(c) 相关软件或固件的版本，以及与版本更新有关的任何要求；

(d) AI 系统投放市场或投入使用的所有形式的描述，例如嵌入硬件的软件包、下载或 API；

(e) AI 系统拟在其上运行的硬件描述；

(f) 当 AI 系统是产品的组成部分时，显示外部特征、标记和内部布局的产品照片或插图；

(g) 向部署者提供的基本用户界面描述；

(h) 供部署者使用的使用说明，以及向部署者提供的基本用户界面描述（如适用）； |

| 2. | 对 AI 系统要素及其开发过程的详细描述，包括：

(a) 为开发 AI 系统而执行的方法和步骤，包括（如相关）诉诸第三方提供的预训练系统或工具，以及提供者如何使用、集成或修改这些系统或工具；

(b) 系统的设计规范，即 AI 系统和算法的一般逻辑；关键设计选择，包括所作出选择的理由和假设，包括关于拟使用该系统的人或人群的假设；主要分类选择；系统设计为优化什么，以及不同参数的相关性；系统预期输出和输出质量的描述；为遵守第三章第二节规定的要求而采用的技术解决方案方面所作的任何权衡的决定；

(c) 系统架构的描述，解释软件组件如何相互构建或衔接并整合到整体处理中；用于开发、训练、测试和验证 AI 系统的计算资源；

(d) 如相关，数据要求，以数据表形式描述所采用的训练方法和技巧及所用训练数据集，包括这些数据集的一般描述、其来源、范围及主要特征的信息；数据是如何获得和选择的；标注程序（例如用于监督学习）；数据清理方法（例如异常值检测）；

(e) 根据第 14 条所需的人工监督措施评估，包括根据第 13 条第 3 款第 (d) 项评估为便利部署者解读 AI 系统输出所需的技术措施；

(f) 如适用，对 AI 系统及其性能的预定变更的详细描述，以及为确保 AI 系统持续符合第三章第二节规定的相关要求而采用的技术解决方案的所有相关信息；

(g) 所用的验证和测试程序，包括所用验证和测试数据及其主要特征的信息；用于衡量准确性、稳健性以及是否符合第三章第二节规定的其他相关要求以及潜在的歧视性影响的指标；测试日志以及由负责人员签署日期和签名的所有测试报告，包括涉及 (f) 项所述预定变更的测试报告；

(h) 已落实的网络安全措施； |

| 3. | 关于 AI 系统监测、运行和控制的详细信息，特别是关于：其性能能力和局限，包括系统拟用于的特定人或人群的准确度以及与其预期目的相关的总体预期准确水平；考虑到 AI 系统的预期目的，可预见的意外结果以及健康和安全、基本权利和歧视方面的风险来源；根据第 14 条所需的人工监督措施，包括为便利部署者解读 AI 系统输出而采取的技术措施；适当的输入数据规格； |

| 4. | 对特定 AI 系统性能指标适当性的描述； |

| 5. | 根据第 9 条对风险管理体系的详细描述； |

| 6. | 提供者在系统整个生命周期内对系统所作相关变更的描述； |

| 7. | 全部或部分适用且其参考文献已公布在《欧盟官方公报》上的统一标准清单；如未适用此类统一标准，则需详细描述为满足第三章第二节规定的要求而采用的解决方案，包括所适用的其他相关标准和技术规范清单； |

| 8. | 第 47 条所指欧盟符合性声明副本； |

| 9. | 根据第 72 条在售后阶段评估 AI 系统性能的现行体系的详细描述，包括第 72 条第 3 款所指的售后监测计划。 |

| 5. | 当 AI 系统涉及个人数据处理时，一份说明该 AI 系统符合条例 (EU) 2016/679 和 (EU) 2018/1725 及指令 (EU) 2016/680 的声明； |

## 附件七——基于质量管理体系评估和技术文档评估的符合性

1.   引言

基于质量管理体系评估和技术文档评估的符合性是指基于第 2 至 5 点的符合性评估程序。

2.   概述

根据第 17 条，经批准用于 AI 系统设计、开发和测试的质量管理体系应按照第 3 点进行审查，并应接受第 5 点规定的监督。AI 系统的技术文档应按照第 4 点进行审查。

3.   质量管理体系

|     |     |     |
|  | 3.1. | 提供者的申请应包括：

(a) 提供者的名称和地址，如申请由授权代表提出，则还包括授权代表的名称和地址；

(b) 同一质量管理体系涵盖的 AI 系统清单；

(c) 同一质量管理体系涵盖的每个 AI 系统的技术文档；

(d) 关于质量管理体系的文档，该文档应涵盖第 17 条所列的所有方面；

(e) 为确保质量管理体系保持充分和有效而建立的程序的描述；

(f) 一份书面声明，说明同一申请未向任何其他公告机构提出。 |

|     |     |     |
|  | 3.2. | 质量管理体系应由公告机构评估，公告机构应确定其是否满足第 17 条所述的要求。<br>决定应通知提供者或其授权代表。<br>通知应包含质量管理体系评估的结论和附理由的评估决定。 |

|     |     |     |
|  | 3.3. | 经批准的质量管理体系应由提供者继续实施和维护，以保持其充分和有效。 |

|     |     |     |
|  | 3.4. | 对经批准的质量管理体系或其涵盖的 AI 系统清单的任何拟议变更，应由提供者提请公告机构注意。<br>拟议变更应由公告机构审查，公告机构应决定修改后的质量管理体系是否继续满足第 3.2 点所述的要求，或者是否需要进行重新评估。<br>公告机构应将其决定通知提供者。通知应包含变更审查的结论和附理由的评估决定。 |

4.   技术文档的控制。

|     |     |     |
|  | 4.1. | 除第 3 点所述申请外，提供者还应根据其选择向公告机构提出申请，以评估提供者拟投放市场或投入使用、且属于第 3 点所述质量管理体系涵盖范围的 AI 系统的技术文档。 |

|     |     |     |
|  | 4.2. | 申请应包括：

(a) 提供者的名称和地址；

(b) 一份书面声明，说明同一申请未向任何其他公告机构提出；

(c) 附件四所指的技术文档。 |

|     |     |     |
|  | 4.3. | 技术文档应由公告机构审查。如相关，且以完成任务所需为限，公告机构应获准完全访问所用的训练、验证和测试数据集，包括（在适当且遵守安全保护措施的前提下）通过 API 或其他相关技术手段和工具进行远程访问。 |

|     |     |     |
|  | 4.4. | 在审查技术文档时，公告机构可要求提供者提供进一步证据或进行进一步测试，以便对 AI 系统是否符合第三章第二节规定的要求进行适当评估。当公告机构对提供者进行的测试不满意时，公告机构应视情况自行直接进行适当测试。 |

|     |     |     |
|  | 4.5. | 为评估高风险 AI 系统是否符合第三章第二节规定的要求所必需，且在所有其他核实符合性的合理手段均已用尽且被证明不足之后，经附理由的请求，公告机构还应获准访问 AI 系统的训练模型和已训练模型，包括其相关参数。此种访问应遵守关于保护知识产权和商业秘密的现行欧盟法律。 |

|     |     |     |
|  | 4.6. | 公告机构的决定应通知提供者或其授权代表。通知应包含技术文档评估的结论和附理由的评估决定。<br>当 AI 系统符合第三章第二节规定的要求时，公告机构应签发欧盟技术文档评估证书。证书应载明提供者的名称和地址、审查结论、其有效性的条件（如有）以及识别 AI 系统所需的数据。<br>证书及其附件应包含所有相关信息，以便评估 AI 系统的符合性，并在适用的情况下，对使用中的 AI 系统进行控制。<br>当 AI 系统不符合第三章第二节规定的要求时，公告机构应拒绝签发欧盟技术文档评估证书，并应相应通知申请人，详细说明拒绝理由。<br>当 AI 系统不符合与其训练所用数据有关的要求时，需要在申请新的符合性评估之前对 AI 系统进行重新训练。在此情况下，公告机构拒绝签发欧盟技术文档评估证书的附理由评估决定应包含对用于训练 AI 系统的数据质量的特别考量，特别是关于不合规原因。 |

|     |     |     |
|  | 4.7. | 对 AI 系统可能影响其符合要求或其预期目的的任何变更，应由签发欧盟技术文档评估证书的公告机构进行评估。提供者应将其拟引入任何上述变更的意图告知该公告机构，或者在其以其他方式知悉此类变更发生时告知。拟议变更应由公告机构评估，公告机构应决定这些变更是否需要根据第 43 条第 4 款进行新的符合性评估，或者是否可通过补充欧盟技术文档评估证书的方式解决。在后一种情况下，公告机构应评估变更、将其决定通知提供者，并在变更获得批准时向提供者签发欧盟技术文档评估证书补充件。 |

5.   经批准的质量管理体系的监督。

|     |     |     |
|  | 5.1. | 第 3 点所述由公告机构实施的监督，其目的是确保提供者适当遵守经批准的质量管理体系的条款和条件。 |

|     |     |     |
|  | 5.2. | 为评估目的，提供者应允许公告机构进入进行 AI 系统设计、开发、测试的场所。提供者还应向公告机构提供所有必要信息。 |

|     |     |     |
|  | 5.3. | 公告机构应进行定期审计，以确保提供者维护并实施质量管理体系，并应向提供者提供审计报告。在此类审计的背景下，公告机构可对已签发欧盟技术文档评估证书的 AI 系统进行额外测试。 |

## 附件十一——第 53 条第 1 款第 (a) 项所指的技术文档——通用人工智能模型提供者的技术文档

第 1 节

所有通用人工智能模型提供者应提供的信息

第 53 条第 1 款第 (a) 项所指的技术文档应至少包含以下根据模型规模和风险状况适用的信息：

| 1. | 通用人工智能模型的一般描述，包括：

(a) 模型拟执行的任务以及可集成该模型的 AI 系统的类型和性质；

(b) 适用的可接受使用政策；

(c) 发布日期和分发方式；

(d) 架构和参数数量；

(e) 输入和输出的模态（如文本、图像）和格式；

(f) 许可证。 |

| 2. | 对第 1 点所述模型要素的详细描述，以及开发过程的相关信息，包括以下要素：

(a) 通用人工智能模型集成到 AI 系统所需的技术手段（如使用说明、基础设施、工具）；

(b) 模型和训练过程的设计规范，包括训练方法和技巧、关键设计选择及其理由和假设；模型设计为优化什么以及不同参数的相关性（如适用）；

(c) 如适用，用于训练、测试和验证的数据信息，包括数据的类型和来源以及整理方法（如清理、筛选等）、数据点数量、其范围和主要特征；数据是如何获得和选择的，以及用于检测数据来源不适宜性的所有其他措施和用于检测可识别偏见的方法（如适用）；

(d) 用于训练模型的计算资源（如浮点运算次数）、训练时间，以及与训练有关的其他相关细节；

(e) 模型已知或估计的能耗。

关于第 (e) 点，当模型的能耗未知时，能耗可根据所用计算资源的信息进行估算。 |

第 2 节

具有系统性风险的通用人工智能模型提供者应提供的额外信息

|     |     |     |
1. 对评估策略的详细描述，包括基于现有公开评估协议和工具或其他评估方法得出的评估结果。评估策略应包括评估标准、指标以及识别局限性的方法。

|     |     |     |
2. 如适用，为进行内部和/或外部对抗性测试（如红队测试）、模型调整（包括对齐和微调）而采取的措施的详细描述。

|     |     |     |
3. 如适用，解释软件组件如何相互构建或衔接并整合到整体处理中的系统架构的详细描述。

## 附件十三——第 51 条所指的认定具有系统性风险的通用人工智能模型的标准

为确定通用人工智能模型具有与第 51 条第 1 款第 (a) 项所列相同的能力或影响，委员会应考虑以下标准：

(a) 模型的参数数量；

(b) 数据集的规模或其质量，例如通过 token 衡量；

(c) 用于训练模型的计算量，以浮点运算次数衡量，或通过其他变量的组合予以表示，如训练的估计成本、训练所需的估计时间或训练的估计能耗；

(d) 模型的输入和输出模态，如文本到文本（大语言模型）、文本到图像、多模态，以及为每种模态确定高影响能力的现行最优阈值，以及输入和输出的具体类型（如生物序列）；

(e) 模型能力的基准和评估，包括考虑无需额外训练即可完成的任务数量、学习新的不同任务的能力、其自主性和可扩展性水平、其可访问的工具；

(f) 模型是否因其覆盖面而对内部市场产生高影响，当该模型已提供给欧盟境内至少 10 000 家注册商业用户使用时，应推定存在高影响；

(g) 注册终端用户的数量。
