## 决策树 A：这是人工智能系统吗？（第 3 条第 1 款）

> **解释性说明：** 委员会关于 AI 系统定义的指南（2025 年 2 月）是不具约束力的软法。下述边界情形反映委员会当前的解释，而非既定法律。凡标注“边界性”或“很可能”之处，应由法律顾问作出最终认定。

```
开始：该系统是否满足以下全部标准？
│
├─ 1. 基于机器系统？
│     （软件、硬件或嵌入式——排除纯人工流程）
│     └─ 否 → 不是 AI 系统。停止。
│
├─ 2. 设计为以不同程度的自主性运行？
│     （一定程度的独立运行——即使由人发起）
│     └─ 否 → 不是 AI 系统。可能是传统软件。
│
├─ 3. 部署后可能表现出适应性？
│     （“可能”——能力而非要求；包括静态模型）
│     └─ 注：不具适应性的静态模型，如满足其他标准仍符合条件。
│
├─ 4. 接收输入并推断如何生成输出？
│     （推断 = 超越简单的预定义规则或固定逻辑）
│     ├─ 简单 if/then 规则 → 不是 AI 系统
│     ├─ 统计模型、机器学习、神经网络 → 是
│     └─ 带推理引擎的专家系统 → 很可能是
│
├─ 5. 生成输出（预测、内容、推荐、决定）？
│     └─ 否 → 不是 AI 系统。停止。
│
└─ 6. 能够影响物理或虚拟环境？
      （直接或通过向人类决策者提供信息）
      └─ 否 → 不是 AI 系统。停止。

全部为是 → 依第 3 条第 1 款，这是 AI 系统。
```

**边界情形**（均为解释性——法律上未定）：

| 技术 | 可能的分类 | 理由 | 确定性 |
|------------|----------------------|-----------|-----------|
| 传统软件（无机器学习的 ITSM、ERP） | 不是 AI | 无超越预定义规则的推断 | 高 |
| 无机器学习的 RPA | 不是 AI | 执行脚本化步骤，无推断 | 高 |
| 带统计公式的电子表格 | 不是 AI | 无推断，确定性计算 | 高 |
| 无机器学习的基于规则聊天机器人 | **边界性** | 可能缺乏推断标准——取决于复杂度 | 低 |
| 带排序算法的搜索引擎 | **很可能是 AI** | 推断相关性，生成排序输出 | 中 |
| 推荐系统（协同过滤） | **很可能是 AI** | 推断偏好，生成推荐 | 中-高 |

**引用：** AI 法案第 3 条第 1 款；欧盟委员会关于 AI 系统定义的指南（2025 年 2 月）
**文件：** `guidelines/ai-system-definition.md`、`core/regulation-title-I-general.md`

## 决策树 B：风险分类

> **解释性说明：** 第 6 条第 3 款例外和附件三领域边界涉及重大法律判断。委员会关于高风险分类的实务指南仍在制定中（预计 2026 年）。在其发布之前，下述评估遵循条例文本和现有委员会指引。

```
开始：已确认符合第 3 条第 1 款的 AI 系统
│
├─ 第 1 步：范围检查（第 2 条）
│  该系统是否完全被排除在 AI 法案之外？
│  • 军事/国防用途（第 2 条第 3 款）
│  • 投放市场前的研究与开发（第 2 条第 6 款）
│  • 个人/家庭使用（第 2 条第 10 款）
│  • 无禁止或高风险用途的开源（第 2 条第 12 款）
│  • 输出不影响欧盟的第三国使用（第 2 条第 1 款）
│  └─ 任一为是 → 不在范围内。停止。
│
├─ 第 2 步：禁止做法筛查（第 5 条）
│  该系统是否落入以下 8 项禁止之一？
│  (a) 潜意识操纵
│  (b) 利用脆弱性
│  (c) 公共机关的社交评分
│  (d) 个人犯罪风险评估（仅基于画像）
│  (e) 无目标的人脸图像抓取
│  (f) 工作场所/教育中的情绪识别
│  (g) 生物特征分类（种族、政治、工会、宗教、性取向）
│  (h) 公共场合的实时远程生物识别（执法——狭窄例外）
│  └─ 是 → 被禁止（第 5 条）。最高处罚：3500 万欧元或 7% 营业额。
│
├─ 第 3 步：高风险评估（第 6 条 + 附件一与三）
│  ├─ 路径 A：附件一产品立法（第 6 条第 1 款）
│  │  该 AI 系统是否为附件一所列欧盟协调立法涵盖产品的安全组件
│  │  或本身即是此类产品？
│  │  （医疗器械、机械、玩具、车辆、航空等）
│  │  且需要第三方合格评定？
│  │  └─ 是 → 高风险
│  │
│  ├─ 路径 B：附件三领域（第 6 条第 2 款）
│  │  该系统是否落入 8 个高风险领域之一？
│  │  1. 生物识别（超出第 5 条禁止）
│  │  2. 关键基础设施管理
│  │  3. 教育与职业培训
│  │  4. 就业、员工管理、自主就业准入
│  │  5. 基本服务获取（信用、保险、公共福利）
│  │  6. 执法
│  │  7. 移民、庇护、边境管制
│  │  8. 司法和民主进程的管理
│  │  └─ 是 → 检查下述第 6 条第 3 款例外
│  │
│  └─ 第 6 条第 3 款例外：满足全部条件时不属于高风险：
│     (a) 执行狭窄的程序性任务，且
│     (b) 改进先前已完成的人类活动的结果，且
│     (c) 不替代人类评估（无实质性推翻风险），且
│     (d) 不对自然人进行画像
│     另外：如 AI 系统执行画像，该例外绝对不适用（第 6 条第 3 款最后一句）
│     └─ 全部条件满足 → 尽管列入附件三，仍不属于高风险
│
├─ 第 4 步：GPAI 检查（第 51-56 条）
│  这是通用人工智能模型吗？
│  （使用大量数据经大规模自监督训练，
│   能够胜任广泛任务）
│  ├─ 否 → 继续第 5 步
│  ├─ 是，累计 FLOP ≤ 10^25 → GPAI 标准义务（第 53 条）
│  └─ 是，累计 FLOP > 10^25 → 具系统性风险的 GPAI（第 51 条第 2 款、第 55 条）
│     （或经委员会基于其他标准指定）
│
└─ 第 5 步：透明度触发情形（第 50 条）
   该系统是否：
   (a) 直接与自然人交互？→ 披露 AI 性质
   (b) 生成合成音频/图像/视频/文本？→ 标记为 AI 生成
   (c) 执行情绪识别？→ 告知主体
   (d) 生成深度伪造？→ 标注为人工生成
   └─ 任一为是 → 有限风险（透明度义务适用）
   └─ 全部为否 → 最低风险（无特定义务，仅自愿守则）

最终分类：
┌─────────────────────┬──────────────────────────────────────┐
│ 风险等级             │ 关键义务                               │
├─────────────────────┼──────────────────────────────────────┤
│ 禁止                │ 不得投放欧盟市场                         │
│ 高风险              │ 完整的第三章要求（第 8-49 条）           │
│ GPAI——系统性风险    │ 第 53 条 + 第 55 条（行为守则）          │
│ GPAI——标准          │ 仅第 53 条                              │
│ 有限风险            │ 第 50 条透明度                           │
│ 最低风险            │ 无强制义务                               │
└─────────────────────┴──────────────────────────────────────┘
```

## 决策树 C：提供方还是部署方？

> **解释性说明：** “实质性修改”（第 3 条第 23 款）与常规配置之间的区分尚未在有约束力的指引中明确界定。委员会关于实质性修改的指南正在制定中（预计 2026 年）。下述门槛遵循条例文本和可用的 MDCG/合规指引。

```
开始：你与 AI 系统是什么关系？
│
├─ 你是否开发或委托开发了该 AI 系统？
│  └─ 是 → 提供方（第 3 条第 3 款）
│     义务：第 16-25 条（全部提供方要求）
│
├─ 你是否将你的名称/商标置于其上？
│  └─ 是 → 提供方（第 3 条第 3 款）——即使你未开发它
│
├─ 你是否在市场投放后对其进行了实质性修改？
│  └─ 是 → 新提供方（第 25 条）——触发全部提供方义务
│     见：compliance-guides/modifying-ai-classification.md
│
├─ 你是否在你的权限下使用它（非个人使用）？
│  └─ 是 → 部署方（第 3 条第 4 款）
│     义务：第 26 条（部署方要求）
│
├─ 你是否将其进口到欧盟？
│  └─ 是 → 进口商（第 3 条第 6 款）
│     义务：第 23 条
│
├─ 你是否在欧盟分销它（未进口）？
│  └─ 是 → 分销商（第 3 条第 7 款）
│     义务：第 24 条
│
└─ 你是否改变了高风险系统的预期用途？
   └─ 是 → 准提供方 → 成为新提供方（第 25 条第 1 款(c)项）

⚠ 多重角色：一个实体可以同时持有多个角色。
  示例：开发并部署自身 AI 系统的公司既是提供方（第 16-25 条）
  又是部署方（第 26 条）。
```

**引用：** AI 法案第 3 条第 3–7 款、第 25 条、第 28 条
**文件：** `core/regulation-title-I-general.md`、`core/regulation-title-III-high-risk.md`、`compliance-guides/modifying-ai-classification.md`
