# 法律研究备忘录

对客户委托事项进行法律检索和分析论证，输出法律研究备忘录。定位介于 客户法律咨询（客户即时答复）与 法律意见书（正式法律意见书）之间。

## Phase 0上下文检测

执行 `ndr-standards.md` §4。搜索 outputs/*_case_profile.json → 按 type="NDR" 过滤 → ask_user 确认继承 → 未找到则创建新 Profile。继承确认后跳过已完成采集步骤。

***

## 工作流

```
Step 1 · 明确研究问题 + 确认输出格式 + 术语定义
    ↓
Step 2 · 法律检索（双源并行）→ 校验
    ↓
Step 3 · 叙事化分析论证（CRAC内化为思维工具，不对客户暴露标签）
    ↓
Step 4 · 输出交付
```

## Step 1明确研究问题

### 1.1 问题提取

从客户输入中提取核心法律争议点，分解为可逐一研究的子问题。涉及主体、金额/利益、时效性、是否跨境。信息不足时提示律师补充。

以律所名义出具但不承担法律意见书责任，统一输出 Word 格式。如客户要求律所署名并承担法律责任，应转由 法律意见书 处理。

如不确定当前场景，参见 `ndr-standards.md` §10 分析类技能择技规则。

> **依据时效与程序前置（2026-08-31 补引）** 材料提取与依据时效遵循 `ndr-standards.md` §7.8：所涉法规、监管规则**必须**标注发布或最新修订日期与最后核验日；对拟议或历史行为**必须**说明适用行为时法还是评价时法；涉审批/备案/登记/前置许可/第三方同意/优先购买权/内部决议程序的，**必须**先行提示程序前置及未满足后果（未满足即交易不成立/不生效/存在瑕疵）；新旧或层级规则冲突**必须**明确取舍并说明理由，**禁止**并列罗列不作判断。⛔ **NDR 域不存在 §J 章节**（属法官文书公共标准）。

### 1.2 术语定义（强制）

首次提及以下主体时，须以"（下称'XX'）"定义简称：
- 客户（如"苏州境成高锦股权投资企业（有限合伙）（下称'境成'或'贵司'）"）
- 交易对方/被调查方
- 标的公司
- 其他反复出现的主体

在 JSON meta.definitions 中列出所有定义对。律所自身也须定义（如"北京市百宸律师事务所（下称'我们'）"）。

### 1.3 备忘录结构规范

备忘录按以下固定结构组织（16 区块：保密文件 → 抬头表格 → 敬启者 → 术语定义 → 引言 → 保留声明 → 联系方式 → 第一部分事实 → 第二部分分析 → 序言/简短回答 → 子问题分析 → 结论 → 结尾声明 → 落款），不可省略任何部分。**完整结构与各区块要求**详见 `references/memo-template.md` 的「1.3 备忘录结构规范」表。

## Step 2法律检索

**基座前置｜双源检索（强制，不可跳过）**：执行 `ndr-standards.md` §0（订阅检测）+ §1（双源检索：百宸库 + 互联网各 ≥2 组 + 深度fetch≥2-3件库+2件网）。业务附加：§2.3.5（AI 虚假案例防范）；聚焦直接依据，不可跳过。

> **法条核验**：引用前按 §2.1.1 标 ✅/⚠️/⛔，⚠️/⛔ 不入文书；规则全文在公共标准不重复。⛔ NDR 域不存在 §J，法条核验对位设施即 §2.1.1＋§7.8＋§15.4。

### 检索校验

| 校验项 | 标准 |
|--------|------|
| 法规有效性 | 确认未被废止或修订；以最新版为准 |
| 案例效力 | 优先指导性案例、人民法院案例库案例、最高院裁判；确认未被推翻 |
| 多源比对 | 关键法条和案例至少两个来源互相印证，不一致时标注"来源存在差异" |

## Step 3分析论证

### 3.1 核心原则：CRAC是思维工具，不是输出格式

CRAC 须内化为思维框架，在单一叙事段落中自然呈现，不对客户暴露"法律依据/事实适用/风险判断/结论"标签。**完整内化方式对比表与新旧版示例**详见 `references/research-framework.md` 的「3.1 CRAC 内化」。

### 3.2 叙事规范

叙事化输出的子标题、递进、风险提示、段末/全文收束、简短回答、语气、段落等规范，**完整规范表**详见 `references/research-framework.md` 的「3.2 叙事规范」。

### 3.3 读者分层

| 读者 | 策略 |
|------|------|
| **客户法务** | 省略基础法律概念，聚焦争议焦点和实务判断 |
| **客户业务团队** | 对基础法律概念做简要解释，用商业语言表述结论 |
| **内部使用** | 完整保留检索过程、方法和关键词 |

### 3.4 分析论证强制纪律（2026-08-31 补引）

1. **必须**将 CRAC 内化为思维工具，在单一叙事段落中自然呈现，⛔ **禁止**对客户暴露「法律依据/事实适用/风险判断/结论」标签。
2. **必须**遵循叙事规范：子标题用中文序号「一、二、三」；风险提示用「在此需提醒贵司注意」引出；段末收束用「据此，」或直接陈述结论，⛔ **禁止**使用「综上/综上所述」式引导语。
3. **必须**执行 `ndr-standards.md` §2.2 禁止模糊措辞、§2.3 去AI化（§2.3.1 禁用词表／§2.3.2 句式控制／§2.3.3 判断直接性／§2.3.4 人写感）：⛔ **禁止**模板化「首先……其次……再次……」堆砌（自然递进逻辑除外）；⛔ **禁止**「可能」「或许」「不排除」式判断——判断要给结论，不给选项。
4. **必须**执行 `ndr-standards.md` §2.3.5（AI生成虚假案例防范）：引用案例**必须**标注「入库案例编号XXXX-XX-2-XXX-XXX」＋裁判要旨概述，或裁判文书网完整案号，⛔ **禁止**无编号、无案号的笼统引用。
5. **必须**按 `ndr-standards.md` §2.1.1 三态标记法条：✅ 方可写入正文；⚠️ **不得**写入；⛔ **禁止**作为依据引用；未获权威原文时⛔ **不得**以「通常认为」「实践中一般」等模糊表述替代依据。
6. **必须**执行 `ndr-standards.md` §7.4 自指称规范；首次提及主体**必须**以「（下称'XX'）」定义简称并落入 JSON meta.definitions。
7. **必须**按读者分层调整用语：客户法务省略基础概念；客户业务团队用商业语言；内部使用完整保留检索过程；⛔ **禁止**混合读者层级的术语口径。
8. **必须**落实论证深度分级：简单事项（法定/常规内容、结论自明）直接陈述结论，不展开论证；复杂事项（合法性边界、权利义务再分配、风险分配）完整论证——结论→依据→要件→适用；⛔ **禁止**为显得专业而注水，篇幅与内容重要性**必须**匹配。

## Step 4输出交付

执行 `ndr-standards.md` §8.3 交付前强制自检。通过后方可生成为 Word。

> **法条状态与依据时效普检（2026-08-31 补引）** 交付前**必须**执行 `ndr-standards.md` §15.4 五项普检（法条状态／时效标注／时法选择／前置条件／冲突取舍）：法条锚点表中 ⚠️/⛔ 项**不得**出现在交付正文，⛔ 状态条文**禁止**作为依据引用；未获权威原文时按 §2.1.1 fallback 处理。

调用 scripts/generate_memo.py 生成 Word。脚本接收的 JSON 输入结构（meta / part_one / part_two / closing_summary 完整字段说明）详见 `references/memo-template.md` 的「Step 4 JSON 输入结构」。

底部自动生成律所落款和中文大写日期。

## 写作规范

1. **面向客户**：用"贵司""我们"；不写"法律依据""事实适用"等标签
2. **实用性第一**：回应客户关切、给出方案建议。不确定时须给出"最大可能性判断"，不限于"it depends"
3. **法条精确**：执行 `ndr-standards.md` §2.1。首次引用附原文；条款号准确到款项
4. **事实-法律对应**：每项结论须对应具体事实，标注事实来源（"根据贵司提供的材料""经本所律师查询"）
5. **禁止模糊措辞**：执行 `ndr-standards.md` §2.2
6. **去AI化**：执行 `ndr-standards.md` §2.3。特别禁止：模板化"首先……其次……再次……"在没有实质递进关系时堆砌；但自然递进逻辑中的"首先/其次"是允许的
7. **过渡语**：风险提示用"在此需提醒贵司注意"；段末收束用"据此，"或直接陈述结论（禁用"综上/综上所述"式引导语）
8. **自指称规范**：执行 `ndr-standards.md` §7.4

> 论证深度分级：按 `ndr-standards.md` §2.6 繁简标准执行（⛔ 禁注水、篇幅与内容匹配）
