# 法律研究备忘录 — 结构模板与 JSON 输入结构

> 本文件由 SKILL.md 抽取而来，含 Step 1.3 备忘录结构规范（16 区块固定结构）与 Step 4 generate_memo.py 的 JSON 输入结构。起草备忘录 / 组装 JSON 时读取。

## 1.3 备忘录结构规范

备忘录按以下固定结构组织，不可省略任何部分：

| 序号 | 区块 | 要求 |
|:--:|------|------|
| 1 | 保密文件 | 居中黑体加粗（"保密文件"或"保密"） |
| 2 | 抬头表格 | 日期 / 收件人 / 发件人 / 事由，四行两列，去除边框 |
| 3 | 敬启者 + 感谢段 | "敬启者："单独一行；感谢段表达感谢+委托背景 |
| 4 | 术语定义段 | "下称"格式，分号分隔，句号收尾 |
| 5 | 引言段 | "根据贵司……出具本法律备忘录" |
| 6 | 保留声明段 | 自然段落，说明意见的局限性和可调整性 |
| 7 | 联系方式行 | "如有任何疑问，请随时与我们联系……" |
| 8 | 第一部分标题 | "第一部分  本案主要事实"（黑体二级标题） |
| 9 | 事实叙述 | "鉴于"体，客观陈述已核实的事实 |
| 10 | 第二部分标题 | "第二部分  关于……的法律风险分析"（黑体二级标题） |
| 11 | 序言段 | "我们建议贵司在现阶段主要关注以下问题：一、……二、……" |
| 12 | 简短回答 | "我们的初步判断是："起头，3-5句概括性结论，直接回应客户核心关切 |
| 13 | 子问题分析 | 中文序号标题（一、二、三……）+ 叙事化段落块 |
| 14 | 综上所述 | "综上所述，"起头，全文总结性判断 |
| 15 | 结尾保留声明 | "以上系我们根据目前材料……" |
| 16 | 落款 | 律所全称（右对齐黑体）+ 中文大写日期（右对齐仿宋） |

## Step 4 JSON 输入结构

调用 `scripts/generate_memo.py` 生成 Word，脚本接收以下结构：

```json
{
  "meta": {
    "date": "2026年06月09日",
    "recipient": "收件人全称",
    "recipient_short": "简称",
    "law_firm": "律所全称",
    "law_firm_short": "我们",
    "matter": "关于……之法律备忘录",
    "definitions": [{"full": "全称", "short": "简称"}],
    "thanks_text": "感谢段",
    "opening_text": "引言段",
    "caveat_text": "保留声明段",
    "contact_line": "联系方式行",
    "confidentiality": "保密文件"
  },
  "part_one": {
    "title": "第一部分  本案主要事实",
    "body": "事实叙述（鉴于体）"
  },
  "part_two": {
    "title": "第二部分  关于……的法律风险分析",
    "intro": "序言段（我们建议贵司关注以下问题：一、……二、……）",
    "brief_answer": "我们的初步判断是：……（3-5句，直接回应核心关切，CRAC的C前置）",
    "sections": [
      {"heading": "一、子问题标题", "body": "完整叙事段落（可用\\n\\n分隔多个自然段）"}
    ]
  },
  "closing_summary": {
    "summary_text": "综上所述，……",
    "closing_caveat": "结尾保留声明",
    "closing_remark": "结尾敬语（如有）"
  }
}
```

底部自动生成律所落款和中文大写日期。
