# 原告证据清单+起诉状AI撰写Plus

## 概述

本 skill **仅适用于原告**。核心逻辑是**材料驱动、AI 主动撰写、用户审阅修改**：

- **用户上传材料**（PDF、图片、Word 等格式均可），简要说明核心主张；
- **AI 主动解读材料**，从中提取证据信息和案件事实，自动撰写《原告证据清单》和《民事起诉状》草稿；
- **用户审阅 AI 草稿**，提出修改意见，AI 据此调整；
- 通过华宇元典法律数据 MCP 核验起诉状规范性，检索相同管辖法院的最新相似裁判文书供用户人工核对；
- 最终生成 .docx 文件。

> **适用限制**：本 skill 专为原告设计，不适用于被告、第三人、上诉人、被上诉人、申请人、被申请人等其他诉讼地位。若需要撰写其他诉讼地位的证据清单或其他文书（如答辩状、上诉状等），请单独提出。

## 适用场景

- 民事/商事诉讼案件中，原告方律师已准备好证据材料（合同、协议、借条、聊天记录等），需要快速整理为规范的原告证据清单并撰写起诉状
- 需要借助华宇元典法律数据，对起诉状的事实理由、诉讼请求进行规范化核验

## 核心理念

**尽可能减少用户手动输入案件信息的环节。** 用户只需做三件事：
1. 上传证据材料文件
2. 简要说明核心主张（一句话即可）
3. 审阅 AI 草稿，提出修改意见

AI 主动完成：解读材料 → 提取事实 → 编排证据 → 撰写草稿 → 核验 → 生成文件。

## 启动阶段：材料上传与解读

### 第一步：确认诉讼地位 + 引导用户上传材料

#### 1.1 确认诉讼地位

**【必须】首先使用 AskUserQuestion 工具确认用户为原告方：**

> 本技能仅适用于原告。请问您的当事人在本案中的诉讼地位是？

| 选项 | 后续行为 |
|------|----------|
| **原告** | 继续下一步 |
| **非原告（被告/第三人/其他）** | 告知本 skill 仅适用于原告，建议其单独提出需求 |

> 若用户选择非原告，结束本技能流程。

#### 1.2 引导用户上传材料并简要说明核心主张

用户选择"原告"后，**【必须】引导用户一次性上传所有材料**，只需简要说明核心主张即可。不要逐项追问信息，不要列出冗长的信息清单。提示语：

> 请上传本案的证据材料（PDF、图片、Word 等格式均可），并简要说明您的核心主张（如：被告欠款未还、对方违约、侵权赔偿等）。我会主动解读材料，为您撰写《原告证据清单》和《民事起诉状》草稿。

**如果用户在第一步已随材料附带了核心主张（如"被告欠原告民间借贷款项未付"），则直接进入第二步，不再重复询问。**

#### 1.3 信息补充策略

在用户上传材料后，AI 应尽可能从材料中提取信息。**仅在以下情形才向用户补充询问**：

| 情形 | 处理方式 |
|------|----------|
| 材料中完全无法识别原告、被告姓名/名称 | 一次性询问，不要逐项追问 |
| 材料中完全无法确定管辖法院 | 一次性询问 |
| 材料明显缺页或关键内容缺失 | 提醒用户补充材料 |
| 当事人详细信息（身份证号、住址等）缺失 | 在草稿中留空 `[ ]`，由用户事后自行填写，不追问 |

**禁止的行为：**
- ❌ 逐项询问证据的日期、份数、页数、原件情况（AI 应从材料中自行判断）
- ❌ 逐项询问证明对象（AI 应从材料中自行提炼）
- ❌ 要求用户手动列出证据清单
- ❌ 要求用户手动撰写事实陈述

### 第二步：AI 解读材料，主动提取信息

**【必须】在收到用户上传的材料后，AI 逐份阅读并解读每份证据材料。**

#### 2.1 材料解读策略

**正常情况**：直接使用 Read 工具读取材料文件（PDF、图片、Word 等），从内容中提取以下信息：

1. **当事人身份**：从材料中识别原告、被告的姓名/名称，如有其他当事人一并识别
2. **证据基本信息**：每份证据的名称、日期、份数、页数（从材料中判断）
3. **证据形式**：从材料判断是原件还是复印件（无法判断时默认为"复印件"）
4. **证据来源**：从材料内容推断来源方（如协议双方中原告方提供）
5. **核心事实**：从材料中提取时间线、金额、权利义务关系、违约事实等
6. **案由推断**：基于材料内容推断案由（如民间借贷纠纷、买卖合同纠纷等）
7. **管辖法院推断**：从材料中的管辖条款推断（如有），否则后续一次性询问

**无法直接解读时（如图片格式在当前模型下不可读）**：**【必须】主动尝试以下变通方式，按优先级依次尝试，不要直接放弃或要求用户手动输入：**

| 优先级 | 方式 | 操作 |
|--------|------|------|
| 1 | **查找 OCR/图片读取相关 Skill** | 调用 `Skill` 工具（使用 `command: "find-skills"`）搜索是否有可用的 OCR 或图片处理 skill，加载后尝试读取 |
| 2 | **基于用户核心主张 + 文件名推断** | 结合用户的核心主张（如"被告欠款未还"）和文件名（如"代为还款协议"），主动推断证据内容和案件事实，形成初步解读，直接向用户展示解读结果请用户确认 |
| 3 | **调用历史对话记忆** | 若同一材料在历史对话中曾被成功解读过，从历史记录中调取解读结果直接复用 |
| 4 | **请求用户提供文字版关键信息** | 仅在前 3 种方式均无法获取足够信息时，才一次性请求用户提供材料中的关键文字信息（不要逐项追问，一次性列明所需的关键字段） |

> **重要**：无论如何不要直接说"无法读取图片"就停下来。穷尽以上方式后仍无法获取关键信息时，再向用户说明已尝试的方式，并一次性请求必要的关键信息。

> **特别提示**：优先级 2（基于用户核心主张 + 文件名推断）是最常用的变通方式。例如用户上传了一张名为"截屏2024-04-20 11.18.36.png"的图片并说明"被告欠款未还"，AI 应结合历史对话中用户曾提及的文件信息（如"代为还款协议""张三""李四"等），主动推断材料内容并向用户展示解读结果。不要等到所有方式都试完才用此方式——它通常应作为第二优先级使用。

#### 2.2 展示解读结果

解读完成后，**【必须】向用户展示解读结果**，并使用 AskUserQuestion 工具让用户确认基本信息是否正确：

> 我已解读您上传的材料，初步整理如下：
> - 原告：[姓名/名称]
> - 被告：[姓名/名称]
> - 案由：[推断案由]
> - 证据数量：[N]份
> - 核心事实：[简要概括]

| 选项 | 后续行为 |
|------|----------|
| **准确，继续撰写** | AI 据此进入第三步，撰写证据清单草稿 |
| **有误，需要修正** | 请用户指出错误之处，AI 修正后重新确认 |

> **修改循环**：如果用户选择"有误"，修正后再次展示修正结果并重新询问，直至用户选择"准确，继续撰写"。

# 第一阶段：原告证据清单撰写

## 写作规范（严格遵循）

### 整体结构

```
┌─────────────────────────────────┐
│         原告证据清单（标题）       │
├─────────────────────────────────┤
│ 证据一（第X-Y页）：名称、份数、  │
│   日期、页数、形式、原件情况；    │
│ 证据来源：XXX提供；              │
│ 证明对象：……（可多段）           │
├─────────────────────────────────┤
│ 证据二（第X-Y页）：……           │
│ ……                              │
├─────────────────────────────────┤
│                   提交人：XXX     │
│       特别授权代理人：______      │
│               年   月   日        │
└─────────────────────────────────┘
```

### 每条证据的写作模板

**第 1 段（证据标识行）：**
```
证据[编号]（第[起页]-[止页]页）：[子编号（如有）]《[证据名称]》[份数]，[日期]，共[页数]页，[形式]（[原件情况]）；
```

**第 2 段（证据来源）：**
```
证据来源：[来源方]提供；
```

**第 3 段（证明对象）：**
```
证明对象：[逐条列出该证据所证明的事实，按时间顺序排列，每条以分号结尾，最后一条以句号结尾]
```

### 子证据处理规则

当一项证据包含多份独立材料时：
- 主线保留总编号（如"证据三（第7-11页）"），列出子证据概览
- 每个子证据单独成段，使用子编号（如"3-1（第7-10页）……"）
- 所有子证据共用同一个"证据来源"段落
- 所有子证据共用同一个"证明对象"段落

### 格式规范

| 项目 | 规范 |
|------|------|
| 标题 | 黑体，二号（22pt），居中 |
| 正文 | 宋体，小四（12pt），1.5倍行距 |
| 首行缩进 | 2字符 |
| "证据X" | 加粗 |
| "证明对象" | 加粗 |
| 落款 | 右对齐 |
| 纸张 | A4 |

### 证据形式表述规范

| 情形 | 表述 |
|------|------|
| 有原件 | "复印件（有原件）" |
| 无原件/无法判断 | "复印件" |
| 电子截图/打印 | "打印件" |
| 照片 | "照片打印件" |
| 电子数据 | "电子数据（原始载体已备查）" 或 "电子数据打印件" |

### 证明对象写作要求

1. **每条以具体日期开头**，按时间顺序排列
2. **事实陈述客观、简洁**，不做法律评价或论证
3. **每条以分号（；）结尾**，最后一条以句号（。）结尾
4. **引用合同条款时**，写明"合同第X条约定：……"
5. **关键金额、日期、主体名称必须准确**
6. **涉及简称的主体**，首次出现时注明"（以下简称：XX）"

## 证据清单工作流程

### 第三步：AI 主动撰写证据清单草稿

第二步解读结果经用户确认后，**【必须】由 AI 主动撰写《原告证据清单》草稿**，无需用户提供额外信息。

#### 证据编排原则

AI 按以下原则自动编排证据：
1. 按照纠纷发生的时间线排列（从先到后）
2. 先程序性证据、后实体性证据（如有）
3. 证明同一事实的多份证据集中排列
4. 合同类、书面类证据优先于聊天记录、照片等辅助证据

#### 页码编排

AI 按编排后的证据顺序，从第1页开始连续编排页码。若用户上传材料已自带页码，优先使用原页码。

#### 提交人

默认为原告姓名/名称。特别授权代理人留空。

#### 信息缺失处理

若当事人详细信息（身份证号、住址、联系电话等）在材料中缺失：
- 在证据清单中留空 `[ ]` 占位
- 在生成 .docx 时保留占位符
- **不追问用户**，在最终交付时提醒用户自行补充

### 第四步：用户审阅修改，直至定稿

生成证据清单草稿后，请用户逐项核对，使用 AskUserQuestion 工具询问：

> 原告证据清单草稿已生成，请核对以下内容：
> 1. 证据名称、日期、页数是否准确
> 2. 证明对象的事实陈述是否完整、准确
> 3. 页码编排是否正确
>
> 是否需要修改？

| 选项 | 后续行为 |
|------|----------|
| **需要修改** | 请用户提出具体修改意见，AI 修改后重新展示并再次询问 |
| **不需要修改** | 证据清单定稿，进入第二阶段撰写起诉状 |

> **修改循环**：修改完成后再次展示修改后的内容，并重新询问，直至用户选择"不需要修改"。

## 质量检查清单（证据清单）

生成后自动检查：
- [ ] 标题是否为"原告证据清单"
- [ ] 每条证据是否包含完整的"证据标识行 + 证据来源 + 证明对象"三段式
- [ ] 页码是否连续且正确
- [ ] 子证据编号是否规范
- [ ] "证明对象"每条是否以日期开头，按时间排序
- [ ] 首次出现的当事人简称是否标注"（以下简称：XX）"
- [ ] 所有分号/句号使用是否正确
- [ ] 落款是否完整（提交人、特别授权代理人、日期）
- [ ] 全角/半角标点是否正确（中文内容用全角标点）

# 第二阶段：起诉状撰写

> **进入条件**：原告证据清单已定稿（用户选择"不需要修改"）。

## 第五步：AI 主动撰写起诉状草稿

证据清单定稿后，**【必须】由 AI 基于证据清单的内容，主动撰写《民事起诉状》草稿**。

### 5.1 补充必要信息

在撰写前，**仅当以下信息在材料中无法确定时才向用户一次性询问**（不要逐项问）：

- **管辖法院**：从证据材料中的管辖条款推断；无法推断时一次性询问
- **当事人详细信息**：姓名/名称已在第二步确认；身份证号、住址、联系电话等在材料中缺失的，在起诉状中留空 `[ ]` 占位，不追问用户

### 5.2 诉讼请求——AI 主动草拟

**【必须】由 AI 基于证据清单中的证明对象内容，主动草拟诉讼请求**。草拟原则：
- 从证据材料中提取金额、期限、违约责任等要素
- 参考常见案由的诉讼请求表述惯例
- 诉讼请求应具体、明确、可执行
- 最后一项固定为"本案诉讼费用由被告承担"
- 草拟后向用户展示，请用户确认或修改

### 5.3 事实和理由——AI 主动撰写

基于证据清单的证明对象内容，按时间顺序撰写事实叙述，并标注对应证据编号。在法律分析部分，AI 应主动检索并引用相关法律条文。

### 起诉状模板

参考中国大陆人民法院立案通用模板格式：

```
                    民事起诉状

原告：[原告全称/姓名]，[性别]，[出生日期]，[民族]，
      住址：[详细地址]，身份证号：[号码]，联系电话：[号码]。
      （如为法人：住所地：[地址]，统一社会信用代码：[代码]。
       法定代表人：[姓名]，[职务]，联系电话：[号码]。）
```

### 起诉状写作要求

1. **诉讼请求**：应具体、明确、可执行，逐条列出；涉及金额的应写明具体数额
2. **事实和理由**：
   - 以时间线为主线，按纠纷发生经过叙述事实
   - 每项关键事实应注明对应的证据编号（如"（证据一）"）
   - 内容应与证据清单中的证明对象保持一致，不得出现证据清单中未体现的事实
   - 事实叙述应客观、完整，避免主观评价
   - 法律分析部分应主动引用具体法律条文

## 第六步：华宇元典 MCP 核验起诉状规范性

起诉状草稿生成后（经 5.4 用户确认"不需要修改"），**【必须】使用华宇元典法律数据 MCP（yuandian-mcp）进行规范性核验。**

### 核验流程

1. **调用华宇元典 MCP 的案例检索功能**，检索相同管辖法院的最新相似裁判文书（检索3份即可，按裁判日期降序排列，优先选取最近裁判的案例，与第七步共享结果）
2. **将 AI 撰写的起诉状与相似裁判文书中原告的诉讼请求、事实和理由进行比对**，重点核验：
   - 诉讼请求的表述是否符合该管辖法院的裁判习惯
   - 诉讼请求的项目是否完整（是否有遗漏的常见请求项）
   - 事实和理由的叙述方式是否符合该法院的文书规范
   - 法律条文的引用是否准确、完整
   - 金额计算方式是否符合司法实践

3. **核验后输出一份简短的核验报告**，内容包括：
   - 比对参考的裁判文书案号
   - 发现的不规范之处（如有）
   - 建议修改的内容

4. **若发现不规范之处，AI 自动进行一轮修改**，修改后重新展示起诉状，向用户说明修改了哪些内容，并**请用户确认修改是否接受**。若用户不接受某项修改，则恢复该项原文；若用户接受，则进入第七步。
5. **保留本轮检索到的裁判文书**，供第七步直接展示给用户，避免重复检索。

### 核验报告格式示例

```
【起诉状规范性核验报告】

参考裁判文书：
- （20XX）XX民初XX号
- （20XX）XX民初XX号

核验意见：
1. 诉讼请求第X项表述建议调整为：……
2. 事实和理由部分建议补充：……
3. 法律依据引用建议：……

修改情况：
已根据上述意见完成修改。
```

> **注意**：如果华宇元典 MCP 不可用或检索不到相似裁判文书，应向用户说明情况，跳过核验步骤，直接进入下一步。
