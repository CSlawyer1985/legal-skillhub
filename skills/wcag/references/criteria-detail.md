## 1.1 文本替代

### SC 1.1.1 非文本内容（A 级）

**要求：** 所有非文本内容都有能提供等效用途的文本替代。

**充分技术：**
- `G94`：为非文本内容提供具有相同用途的简短文本替代
- `H37`：在 `<img>` 元素上使用 `alt` 属性
- `H36`：在用作提交按钮的图像上使用 `alt` 属性
- `ARIA6`：使用 `aria-label` 为对象提供标签
- `H67`：对辅助技术（AT）应忽略的图像，在 img 上使用空 alt 文本且不带 title 属性

**常见失败：**
- F3：使用 CSS 背景图像传达信息而无文本等效
- F20：非文本内容改变时未更新文本替代
- F30：使用的文本替代并非真正的替代（与文件名、占位文本等相同）
- F38：未对装饰性图像进行标记以便 AT 忽略
- F65：在 img 元素、area 元素或 type 为 "image" 的 input 元素上省略 alt 属性或文本替代

**范围：**
- 信息性图像 → 有意义的 alt 文本
- 装饰性图像 → `alt=""` 且不带 title
- 功能性图像（按钮、链接）→ alt 描述功能而非外观
- 复杂图像（图表、示意图）→ 简短 alt + 通过 `aria-describedby`、`longdesc` 或相邻文本提供的详细描述
- 验证码 → 提供音频验证码或说明验证码用途的文本替代
- 纯装饰性文本或标志的一部分文本 → 可按装饰性处理

## 1.2 基于时间的媒体

### SC 1.2.1 纯音频和纯视频——预先录制（A 级）
为预先录制的纯音频提供文本转录。为预先录制的纯视频提供文本替代或音轨。

### SC 1.2.2 字幕——预先录制（A 级）
同步媒体中所有预先录制的音频内容都有字幕。仅自动生成的字幕不满足此要求，除非经过准确校对。

**字幕的关键要求：**
- 与音频同步
- 逐字对应（经编辑的字幕可为近似等效）
- 标明说话人
- 在传达含义时包含相关音效 [鼓掌]、[笑声]

### SC 1.2.3 音频描述或媒体替代——预先录制（A 级）
为同步媒体中预先录制的视频内容提供基于时间的媒体替代或音频描述，除非媒体本身是文本的媒体替代且已明确标注为如此。

### SC 1.2.4 字幕——实时（AA 级）
同步媒体中所有实时音频内容都有字幕。实时字幕可由 CART（通信无障碍实时翻译）服务提供。

### SC 1.2.5 音频描述——预先录制（AA 级）
为同步媒体中所有预先录制的视频内容提供音频描述。描述音轨中未传达的视觉信息：动作、场景变化、屏幕文字。

## 1.3 可适配

### SC 1.3.1 信息和关系（A 级）

**要求：** 通过呈现方式传达的信息、结构和关系可以编程方式确定或可以文本形式获得。

**关键模式：**
- 标题使用 `<h1>`–`<h6>`——不使用经过样式处理的 `<div>` 或 `<p>` 元素
- 数据表使用带 `<th scope="col|row">` 的 `<table>`；表标题使用 `<caption>`
- 使用 `<label for="id">` 关联表单标签，或使用 `aria-labelledby`/`aria-label`
- 相关输入组（单选按钮、复选框）使用 `<fieldset>` 和 `<legend>`
- 列表使用 `<ul>`、`<ol>`、`<dl>`；不要用连字符和换行伪造列表
- 必填字段：以 `aria-required="true"` 或 `required` 标记；不要仅依赖颜色

**常见失败：**
- F2：使用文本呈现方式的变化传达信息而未使用适当的标记
- F17：依赖 CSS 视觉位置将标签与表单控件关联
- F33：在纯文本中使用空白字符创建多列
- F34：在纯文本中使用空白字符格式化表格
- F42：使用脚本事件模拟链接而无适当语义标记
- F43：以不能表示内容中关系的方式使用结构标记
- F46：在布局表上使用 `summary` 属性（使其被误认为数据表）
- F48：使用 `pre` 元素标记表格信息
- F68：标签与控件之间的关联不能以编程方式确定
- F87：在用于布局的表格中插入无 alt 文本的分隔图像
- F91：未正确标记表头

### SC 1.3.2 有意义的顺序（A 级）
当呈现顺序影响含义时，阅读顺序可以编程方式确定。DOM 顺序应与视觉阅读顺序一致；CSS 定位不得重排有意义的内容。

### SC 1.3.3 感官特征（A 级）
指示不只依赖形状、颜色、大小、视觉位置、方向或声音等感官特征。失败示例："点击圆形按钮"或"查看右侧栏中的表单"。

### SC 1.3.4 方向（AA 级——WCAG 2.1）
内容不将其视图和操作限制为单一显示方向，除非确有必要。除非方向至关重要（如钢琴应用），移动网站应同时支持竖屏和横屏。

### SC 1.3.5 识别输入目的（AA 级——WCAG 2.1）
每个收集用户信息的输入字段的目的都可以使用带有定义令牌值的 HTML `autocomplete` 属性以编程方式确定。

**关键 autocomplete 令牌：**
- `name`、`given-name`、`family-name`
- `email`、`tel`
- `street-address`、`address-line1`、`address-line2`、`postal-code`、`country`
- `bday`、`sex`
- `current-password`、`new-password`
- `cc-name`、`cc-number`、`cc-exp`

## 1.4 可区分

### SC 1.4.1 颜色的使用（A 级）
颜色不作为传达信息、指示动作、提示响应或区分视觉元素的唯一视觉手段。

**修复：** 在颜色之外添加文本标签、图标、图案或其他非颜色区分手段。

### SC 1.4.2 音频控制（A 级）
自动播放超过 3 秒的音频可以由用户暂停或停止，或音量可以独立于系统音量调整。

### SC 1.4.3 对比度——最低（AA 级）
- 正常文本（低于 18pt 或 14pt 粗体）：最低对比度 **4.5:1**
- 大文本（18pt/24px+ 常规 或 14pt/18.67px+ 粗体）：最低 **3:1**
- 标志、非活动 UI 组件、装饰性文本：豁免

**公式：** 对比度 = (L1 + 0.05) / (L2 + 0.05)，其中 L1 为较亮的亮度，L2 为较暗的相对亮度。相对亮度使用 sRGB 色彩模型。

**工具：** WebAIM 对比度检查器、Colour Contrast Analyser（桌面应用）、浏览器 DevTools > Accessibility > Contrast。

**边缘情形：**
- 输入框中的占位文本：经常失败——若它是唯一可见内容，必须达到 4.5:1
- 图像中的文本：必须满足对比度要求
- 渐变/图像背景上的文本：在最差的重叠区域检查

### SC 1.4.4 调整文本大小（AA 级）
在不使用辅助技术的情况下，文本可以放大至 200% 而不损失内容或功能。字体大小和容器高度使用相对单位（`rem`、`em`、`%`）而非 `px`。在 200% 浏览器缩放下单列内容不应出现水平滚动条。

### SC 1.4.5 文本图像（AA 级）
使用文本而非文本图像传达信息，除非是标志，或文本图像对所传达的信息是必要的。

### SC 1.4.10 回流（AA 级——WCAG 2.1）
内容可以在不损失信息或功能、且无需二维滚动的情况下呈现，适用情形：
- 垂直滚动内容，宽度相当于 320 CSS 像素
- 水平滚动内容，高度相当于 256 CSS 像素

**例外：** 其使用或含义需要二维布局的内容（数据表、地图、示意图、视频、游戏）。

**测试方法：** 将浏览器视口设置为 320px 宽（或在 1280px 显示器上缩放至 400%），验证不出现水平滚动条。

### SC 1.4.11 非文本对比度（AA 级——WCAG 2.1）
UI 组件（表单字段、按钮、焦点指示）和信息性图形与相邻颜色之间的对比度至少为 **3:1**。

**范围：**
- 输入框边框与背景
- 复选框/单选按钮轮廓
- 焦点指示（自定义）
- 图表线条、图形条、数据点
- 传达含义的图标（非装饰性）

**豁免：** 不活动/禁用组件；标志；纯装饰性图形。

### SC 1.4.12 文本间距（AA 级——WCAG 2.1）
当以下所有文本间距属性同时被覆盖时，不损失内容或功能：
- 行高 ≥ 字体大小的 1.5 倍
- 字距 ≥ 字体大小的 0.12 倍
- 词距 ≥ 字体大小的 0.16 倍
- 段后间距 ≥ 字体大小的 2 倍

**测试：** 使用 Text Spacing 书签工具一次性应用全部四项属性，检查文本是否被裁剪/重叠。

### SC 1.4.13 悬停或聚焦时的内容（AA 级——WCAG 2.1）
在悬停或键盘聚焦时出现的附加内容必须：
1. **可解除**——用户无需移动指针或焦点即可解除（通常通过 Escape 键）
2. **可悬停**——如果触发方式是悬停，指针可以移动到附加内容上而不消失
3. **持久**——内容保持可见，直到用户解除、移开焦点/指针，或信息不再有效

**常见失败：** 指针移向其时消失的提示框；无法解除的提示框。

## 2.1 键盘可访问

### SC 2.1.1 键盘（A 级）
所有功能均可通过键盘操作，且不要求特定按键节奏。

**所需键盘模式（ARIA 创作实践指南）：**
- 下拉菜单：方向键导航，Enter/Space 激活，Escape 关闭
- 对话框/模态框：Tab 在模态框内移动，Escape 关闭，关闭时焦点回到触发器
- 标签页：方向键在标签页之间移动，Tab 进入标签面板内容
- 滑块：方向键改变值，Home/End 到最小/最大
- 日期选择器：方向键按日导航，Page Up/Down 按月份/年份
- 树视图：方向键，Enter 激活
- 自动完成：方向键，Enter 选择，Escape 关闭

**常见失败：** 仅在不可聚焦元素上使用鼠标 `onclick`、`onmouseover` 处理程序；无键盘替代的拖放；无法访问的自定义小部件。

### SC 2.1.2 无键盘陷阱（A 级）
键盘焦点可以使用标准键（Tab、Shift+Tab、方向键）从任何组件移出。如果需要非标准键，须告知用户。

**模态对话框：** 焦点可以有意图地限制在模态框内，但必须有关闭并让焦点回到触发器的方式。

### SC 2.1.4 字符键快捷键（A 级——WCAG 2.1）
如果实现了单字符键快捷键，至少满足以下之一：快捷键可以关闭、重新映射，或仅在聚焦时生效。

## 2.2 充足时间

### SC 2.2.1 可调整时间（A 级）
对于内容设定的时间限制：用户可以关闭、调整或延长该限制。例外：实时事件（拍卖）、必要的时间限制、超过 20 小时。

**最佳实践：** 在会话超时前 20 秒警告用户，并提供延长时间选项。

### SC 2.2.2 暂停、停止、隐藏（A 级）
对于自动开始且持续超过 5 秒的移动、闪烁、滚动或自动更新信息：提供暂停、停止或隐藏的控件。例外：必要的移动。

---

## 2.3 癫痫发作和身体反应

### SC 2.3.1 三次闪烁或低于阈值（A 级）
内容每秒闪烁不超过三次，或闪烁低于一般闪烁和红色闪烁阈值。适用于视频、动画、GIF 和脚本效果。

## 2.4 可导航

### SC 2.4.1 绕过块（A 级）
提供跳过在多个页面上重复的内容块的机制。通常实现为跳转链接（"跳到主要内容"）或通过 ARIA 地标区域（`main`、`nav`、`header`、`footer`、`aside`）。

**最佳实践：** 同时提供可见的跳转链接和适当的地标结构。跳转链接应是第一个可聚焦元素，并应在聚焦时可见。

### SC 2.4.2 页面标题（A 级）
网页标题描述主题或用途。标题在站点范围内应唯一，并遵循"页面特定标题——站点名称"的模式。

### SC 2.4.3 焦点顺序（A 级）
可聚焦组件以保持含义和可操作性的顺序接收焦点。DOM 顺序应与视觉阅读顺序一致；避免使用大于 0 的 `tabindex` 值，它会破坏自然 Tab 顺序。

### SC 2.4.4 链接目的——在上下文中（A 级）
每个链接的目的可以从链接文本本身或链接文本加上其编程上下文（所在句子、列表项、表格单元格或关联表头）确定。

**失败：** "点击此处"、"阅读更多"、"了解更多"且无可访问上下文。

**修复：** 使用描述性链接文本（"阅读我们的 WCAG 2.2 指南"）或辅以 `aria-label` 或 `aria-describedby`。

### SC 2.4.5 多种方式（AA 级）
在一组页面中定位页面有不止一种方式。至少满足以下两种：站点导航、站点搜索、站点地图、目录、相关页面列表。例外：作为流程结果的页面（结账确认）。

### SC 2.4.6 标题和标签（AA 级）
标题和标签描述其适用内容的主题或用途。标题必须有意义——不能是"第1节"或"内容"。

### SC 2.4.7 焦点可见（AA 级）
任何可通过键盘操作的界面都有键盘焦点指示器可见的操作模式。不要在无替代焦点样式的情况下使用 `outline: none`。

**最佳实践：** 使用 `focus-visible` CSS 伪类，仅向键盘用户（而非鼠标点击）显示焦点。

### SC 2.4.11 焦点不被遮挡——最低（AA 级——WCAG 2.2）
当 UI 组件接收键盘焦点时，不会被作者创建的内容（粘性页头、横幅、Cookie 通知、聊天气泡）完全隐藏。组件可以部分被遮挡；只是不能完全隐藏。

**修复：** 确保 `scroll-margin-top` 或等效方式补偿粘性页头高度；或使用具有足够顶部偏移的 `position: sticky`。

### SC 2.4.12 焦点不被遮挡——增强（AAA 级——WCAG 2.2）
聚焦的组件不被任何作者创建的内容隐藏。聚焦时整个组件完全可见。

### SC 2.4.13 焦点外观（AAA 级——WCAG 2.2）
焦点指示区域：(a) 包围 UI 组件或其文本；(b) 聚焦与非聚焦状态之间的对比度至少为 3:1；(c) 与相邻颜色的对比度至少为 3:1；(d) 不完全被遮挡。

## 2.5 输入方式

### SC 2.5.1 指针手势（A 级——WCAG 2.1）
使用多点（捏合/缩放）或基于路径的手势（滑动）的所有功能都有不要求特定路径的单指针替代方式。

### SC 2.5.2 指针取消（A 级——WCAG 2.1）
对于用单指针激活的功能：至少满足以下之一：不在按下事件时激活；松开事件可以中止/撤销；松开事件逆转按下事件；按下事件是必要的。

**失败：** 点击操作在 `mousedown` 而非 `mouseup` 时触发，使用户无法通过移开指针取消。

### SC 2.5.3 名称中的标签（A 级——WCAG 2.1）
对于有可见文本标签的 UI 组件，可访问名称（由 `aria-label`、`aria-labelledby` 或原生标签计算出的名称）包含可见标签文本。

**失败：** 按钮视觉标签为"提交表单"，但 `aria-label="发送"`——使用语音控制说"点击提交表单"的用户无法激活它。

### SC 2.5.4 运动驱动（A 级——WCAG 2.1）
由设备运动（摇晃、倾斜）触发的功能也可以通过 UI 组件操作，并且运动响应可以被禁用（除非运动是必要的）。

### SC 2.5.7 拖拽移动（AA 级——WCAG 2.2）
所有使用拖拽移动进行操作的功能都可以用单指针实现，无需拖拽。

**示例：** 带拖拽手柄的可排序列表——必须有上/下按钮；带拖拽的范围滑块——必须有文本输入或增减按钮；看板卡片拖放——必须有键盘可访问的替代方式。

### SC 2.5.8 目标大小——最低（AA 级——WCAG 2.2）
指针输入目标的大小至少为 24×24 CSS 像素，但以下情形除外：
- **间距：** 尺寸不足的目标在其他方向上与其他目标至少偏移 24px
- **等效：** 该功能可以通过满足标准要求的等效控件实现
- **行内：** 目标在句子中，或其大小受非目标文本行高限制
- **用户代理：** 目标大小由用户代理决定且作者未修改
- **必要：** 特定呈现对所传达的信息是必要的

**建议：** 所有触摸目标力求至少 44×44 CSS 像素（iOS/Android HIG 建议）。

## 3.1 可读性

### SC 3.1.1 页面语言（A 级）
每个网页的默认人类语言可以编程方式确定。在 `<html>` 元素上设置 `lang` 属性（如 `<html lang="en">`）。使用有效的 BCP 47 语言标签。

### SC 3.1.2 部分语言（AA 级）
内容中每个段落或短语的人类语言都可以编程方式确定，但专有名词、技术术语、无法确定的语言以及已成为日常用语一部分的词语除外。

**修复：** 行内外语内容使用 `<span lang="fr">Bonjour</span>`。

## 3.2 可预测

### SC 3.2.1 聚焦时（A 级）
当 UI 组件接收焦点时，不会引发上下文变化（新窗口、表单提交、重大页面变化）。

### SC 3.2.2 输入时（A 级）
更改 UI 组件的设置不会自动引起上下文变化，除非用户在使用该组件前已被告知。

**失败：** 选择单选按钮或 select 元素中的选项立即导航到新页面，而无提交按钮。

### SC 3.2.3 一致的导航（AA 级）
在多个页面上重复的导航机制每次重复时以相同的相对顺序出现，除非变化由用户发起。

### SC 3.2.4 一致的标识（AA 级）
在一组网页中具有相同功能的组件被一致地标识。

**失败：** 搜索功能在大多数页面上标为"搜索"，但在其他页面上标为"查找"；或同一表单操作使用"前往"而非"提交"。

### SC 3.2.6 一致的帮助（A 级——WCAG 2.2）
如果网页提供帮助机制（联系方式、人工联系、自助选项、自动联系机制），这些机制在一组网页中相对于其他页面内容出现在相同位置，除非变化由用户发起。

## 3.3 输入辅助

### SC 3.3.1 错误识别（A 级）
如果自动检测到输入错误，应识别出错的条目并以文本形式向用户描述错误。

**要求：**
- 错误消息必须以文本形式（不能仅用颜色或图标）
- 必须识别哪个字段出错
- 必须描述错误
- 必须与字段以编程方式关联（`aria-describedby` 或相邻文本）

### SC 3.3.2 标签或说明（A 级）
当内容需要用户输入时，提供标签或说明。格式提示（如"MM/DD/YYYY"）必须在表单字段之前或之内提供。

### SC 3.3.3 错误建议（AA 级）
如果自动检测到输入错误且知道更正建议，则向用户提供该建议。

**不充分：** "无效输入"——错误必须说明问题所在。

**充分：** "请输入 MM/DD/YYYY 格式的日期"或"密码必须至少 8 个字符且包含数字"。

### SC 3.3.4 错误预防——法律、财务、数据（AA 级）
对于引起法律承诺、财务交易、修改/删除用户控制数据或提交测试答案的页面，至少满足以下之一：
1. **可逆**——提交是可逆的
2. **已检查**——输入的数据经过错误检查，用户有机会更正
3. **已确认**——提供在最终确定前审查、确认和更正信息的机制

### SC 3.3.7 冗余输入（A 级——WCAG 2.2）
在同一流程中再次要求提供用户先前已输入或提供给用户的信息时，该信息自动填充或可供用户选择。

**例外：** 出于安全原因必须重新输入的信息（如密码确认），或先前输入的信息已不再有效时。

### SC 3.3.8 无障碍认证——最低（AA 级——WCAG 2.2）
认证过程的任何步骤都不要求认知功能测试（记住密码、解谜、识别物体），除非该步骤提供了不依赖认知功能测试的替代方式、帮助用户完成认知功能测试的机制，或该认知功能测试是识别物体。

**常见失败：** 无无障碍替代方式的验证码（无音频验证码、支持联系选项或一次性登录链接）。

**通过：** 电子邮件魔术链接（无认知测试）；通行密钥/生物特征认证；带音频替代和支持选项的验证码。

## 4.1 兼容

### SC 4.1.1 解析（A 级——在 WCAG 2.2 中已移除）
在 WCAG 2.0 和 2.1 中，要求有效的标记（无重复 ID、完整的开始/结束标签、正确的嵌套）。在 WCAG 2.2 中已移除，因为现代浏览器能优雅地处理解析错误。对 WCAG 2.0/2.1 符合性声明和第508条合规仍具有相关性。

**仍然存在的关切：** 重复 ID 仍会导致 `aria-labelledby` 和 `aria-describedby` 关联失败。

### SC 4.1.2 名称、角色、值（A 级）
对于所有 UI 组件，名称和角色可以编程方式确定；用户可设置的状态、属性和值可以编程方式确定；这些项的变更通知可供用户代理（包括辅助技术）使用。

**关键 ARIA 模式：**

| 小部件 | 所需 ARIA |
|--------|--------------|
| 手风琴 | `role="button"`、`aria-expanded`、`aria-controls` |
| 警报 | `role="alert"` 或 `aria-live="assertive"` |
| 自动完成 | `role="combobox"`、`aria-expanded`、`aria-autocomplete`、`aria-activedescendant` |
| 按钮（切换） | `role="button"`、`aria-pressed` |
| 复选框（自定义） | `role="checkbox"`、`aria-checked` |
| 对话框 | `role="dialog"`、`aria-modal`、`aria-labelledby` |
| 菜单 | `role="menu"`、`role="menuitem"`、`aria-haspopup`、`aria-expanded` |
| 进度条 | `role="progressbar"`、`aria-valuenow`、`aria-valuemin`、`aria-valuemax` |
| 单选按钮（自定义） | `role="radio"`、`aria-checked`，位于 `role="radiogroup"` 内 |
| 滑块 | `role="slider"`、`aria-valuenow`、`aria-valuemin`、`aria-valuemax` |
| 标签页/标签面板 | `role="tablist"`、`role="tab"`、`role="tabpanel"`、`aria-selected`、`aria-controls` |
| 提示框 | `role="tooltip"`，由 `aria-describedby` 触发 |

### SC 4.1.3 状态消息（AA 级——WCAG 2.1）
状态消息可以通过角色或属性以编程方式确定，以便辅助技术无需接收焦点即可呈现。

**ARIA 实时区域模式：**
- `aria-live="polite"`：非紧急状态消息（表单已保存、商品已加入购物车）
- `aria-live="assertive"`：紧急消息（错误、会话即将过期）——慎用
- `role="status"`：礼貌实时区域（等同于 `aria-live="polite"`）
- `role="alert"`：断言式实时区域（等同于 `aria-live="assertive"`）
- `role="log"`：聊天、活动日志——项目按顺序添加
- `aria-atomic="true"`：任何变化发生时播报整个区域内容

**常见失败：**
- 成功横幅注入 DOM 但无实时区域角色——屏幕阅读器不播报
- 错误摘要附加到表单，但无焦点管理或实时区域
- 加载完成时"加载中…"旋转指示器没有可访问的实时区域更新

自动化工具组合通常能发现所有 WCAG 失败的 30–40%。手动测试必不可少。

### 手动测试检查清单

1. **键盘导航**——用 Tab 遍历整个页面；验证所有交互元素可到达；验证焦点顺序符合逻辑；验证无陷阱
2. **屏幕阅读器**——NVDA+Chrome、JAWS+Chrome、VoiceOver+Safari（macOS）、VoiceOver+Safari（iOS）、TalkBack+Chrome（Android）
3. **颜色对比度**——对所有文本、UI 组件、信息性图形使用 Colour Contrast Analyser
4. **缩放/回流**——浏览器缩放到 200%（SC 1.4.4）；视口设置为 320px（SC 1.4.10）
5. **文本间距**——应用文本间距书签工具（SC 1.4.12）
6. **表单**——验证所有输入都有标签；验证错误消息已关联；验证 autocomplete 属性
7. **动态内容**——验证实时区域播报更新；验证模态框焦点管理
8. **图像**——检查 alt 文本质量；验证装饰性图像对 AT 隐藏
9. **视频**——验证字幕；验证音频描述
10. **触摸/指针**——验证触摸目标大小；验证无仅拖拽交互
