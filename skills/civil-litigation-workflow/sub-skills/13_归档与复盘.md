# 13 案件归档与复盘

## Step 0 强制检查

加载本文件 → 读办案记录.md → 确认案件已终结。终结只认四种形态：

1. **判决生效**（一审判决过上诉期未上诉 / 二审判决送达 / 再审裁判送达）；
2. **调解结案**（调解书送达生效，或庭外和解已履行完毕并撤诉）；
3. **撤诉**（裁定准许撤诉，且和解/放弃安排已落实）；
4. **执行完毕或终本**（模块 12 出口——到位的以履行凭证为准，终本的确认无恢复线索已登记）。

未达任一形态的，退回对应模块（11/12），不得提前归档。四种形态即本模块唯一入口。

## 任务目标

案件终结后回答三件事：**卷齐了吗？预测准了吗？经验留下了吗？**——归档核对、结果偏差归因、方法论回写，结案尾巴事务逐项销号，台账闭卷并交付客户结案简报。

## 复用路由（编排不复制）

- **结案简报格式、_log.yaml 台账格式** → `capabilities/案件登记与简报.md` 技能（客户版按其简报模板、closed 条目按其字段规范）；
- **六目录结构与内外隔离规范** → 本 skill SKILL.md 第六节；
- 本模块只新增：归档/结果核对、复盘五段、知识回写路由、结案事务清单。

## 操作步骤

### 1. 归档检查：六目录映射核对法

- **新案**（全程按工作流办理）：按六目录逐项核对完整性，确认正式对外文书（03/04）与内部底稿（01/02/05/06）物理隔离未破坏；
- **历史办结案件不重组原始卷宗**（案例D实证）：用「标准六目录 × 原始卷宗目录」映射表核对——左列标准目录、中列原始路径、右列状态（齐/缺/待补），缺项单列补正计划，禁止为重排目录搬动原始卷；
- 工作流盲测产物（如有）单独成区、与原始卷宗物理隔离；纸质卷宗装订按当事人要求另行安排。

### 2. 结果核对：预测 vs 实际

对照办案记录「判决预期值台账」逐项核对，偏差必须归因到具体要件/争点，禁止只写「基本符合预期」：

- **请求兑现率**（案例D口径）：实际获支持额 ÷ 诉请/上诉请求额（请求改判 563,805.76 vs 实际 579,625.22 = 91.2%）；差额逐笔归因（哪项被驳、哪项法院路径更优）；
- **防线核对**：未涉金额的定性点、利息/违约金防线单独核对（案例D：利息防线维持驳回 = 零偏差）；
- **费用核对**：受理费等逐笔与判决分担、履行回执、退费申请吻合，差额即线索；
- **净效果核算**：一审/预判敞口 vs 终审实付，给出减损/增益金额结论。

### 3. 复盘报告：五段写法

落盘 `06-案件简报/YYYYMMDD_结案复盘报告.md`，五段缺一不可：
1. **策略回顾**：当初《诉讼方案》的请求权基础/抗辩体系选择对不对？主线逐条给「选对/选错+依据」；
2. **亮点**：哪些操作被判决采纳、被对方针对性攻击（被针对 = 打中要害的印证）；
3. **不足**：证据缺口没补上的、争点判断失误的、概率评高/评低的——每条注明是否已回写及去向；
4. **经验沉淀**：可复用方法论，逐条标注回写去向（见第 4 步路由表）；
5. **后续事项**：表格列「事项/截止节点/状态」，逐项留销号位（执行跟踪/退费到账/再审期/系列案/回访）。

### 4. 知识回写路由表

| 经验类别 | 回写去向 |
|---------|---------|
| 案由方法论（请求权/抗辩/裁判规则） | `references/claim-basis/` 对应案由文件增补 |
| 程序经验（保全/执行/管辖等） | `references/procedure/` 对应指引增补 |
| 技能缺陷/流程改进 | 本 skill 版本维护记录 |
| 无沉淀 | 复盘报告显式标注「本次无沉淀」，禁止留白 |

### 5. 结案事务清单（案例D真实归档实证增补，2026-08-07）

结案不是拿到生效判决就结束，以下事务逐项销号后方可归档：

1. **主动履行**：败诉方（含部分败诉）应在判决指定履行期内主动付款——杜绝迟延履行利息（日万分之一点七五）、执行费、失信/限高风险；付款回单**附言注明案号**，凭证扫描归档；
2. **诉讼费结算**：对照判决受理费分担逐项核对——①我方预交多于负担的，向**作出该费用认定的法院**申请退费（附缴费凭证+判决书，退费申请书模板见案例D `退费/`）；②我方应负担对方预交部分的，主动支付并取回执；
3. **再审/上诉期核对**：我方胜诉的，评估对方申请再审风险并预置应对口径；我方败诉的，再审期限（六个月）倒计时登记；
4. **系列案联动**：本案有利/不利认定对关联案件的辐射（可作参照弹药或需提前防反用的口径），写入复盘报告后续事项；
5. **退费到账跟踪**：退费申请后登记台账，到账销号（周期通常 1–2 个月，以法院办理为准）。

> 实证来源：案例D（2025-1-8 生效 → 1-14 履行 → 1-17 退费申请，三日链式办结）。

### 6. 台账与状态头闭卷

- 更新台账 `_log.yaml`（格式路由 `capabilities/案件登记与简报.md`）：`status: closed`，补 `closed_date`、`result`（含兑现率）、`performance`、`archive_path`；`next_deadline` 置 null，未销号事项写入 `next_action`（参照样本：案例D `_log.yaml`）；
- 办案记录.md 状态头改为「已结案」：当前阶段=结案、模块打满、下一步=后续事项跟踪（或「无」）。

### 7. 客户回访与结案简报

- 产出**客户版结案简报**（格式路由 `capabilities/案件登记与简报.md`，按客户受众调整：通俗语言、结果导向、费用结算与后续事项明确），与内部复盘报告**双产出**——复盘对内留底稿，简报对外交付；
- 送达时一并完成当事人回访（满意度、尾款结算、后续合作意向），回访留痕归档。

## 办结案的二次利用：盲测验证载体

办结案事实与结果均已确定，是**工作流各模块的免费验证场**——归档时评估本案材料可否支撑模块 02/07/09/11 等盲测，够的登记为盲测候选案源——今日归档的卷，就是明天盲测的题。

防后见之明协议（已在案例A/B/C/D 四案验证）：

1. **密封**：隐去判决结果，只提供办理节点当时可得材料；
2. **先产出**：盲测者按对应模块产出方案/争点/预期值，落盘密封稿；
3. **对照**：启封真实判决与当时实际策略逐项比对；
4. **归因回写**：偏差归因（方法论缺陷 or 个案特异），回写对应模块或 references，记入版本维护记录。
