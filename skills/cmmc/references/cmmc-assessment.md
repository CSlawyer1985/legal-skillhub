# CMMC 2.0——评估指南：SPRS 评分、C3PAO 流程与 POA&M 规则

## SPRS 评分计算

### 评分方法
SPRS 分数按国防部针对 NIST SP 800-171 的评估方法论计算：
- **起始分数**：110 分
- **每项未满足（NOT MET）的实践**：扣除分配的分值
- **部分实施**：全额扣分（不给部分分）
- **分数范围**：＋110（全部实践满足）至 −203（全部未满足）
- **提交**：所有第 2 级合同均须提交；在 sprs.csd.disa.mil 提交

### 按领域的分值
分值根据实践的安全影响分配：

| 领域 | 实践数 | 风险总分 |
|--------|-----------|---------------------|
| AC（访问控制） | 22 | ~50 |
| AU（审计与问责） | 9 | ~17 |
| CM（配置管理） | 9 | ~19 |
| IA（识别与认证） | 11 | ~22 |
| IR（事件响应） | 3 | ~5 |
| MA（维护） | 6 | ~11 |
| MP（介质保护） | 9 | ~8 |
| PE（物理保护） | 6 | ~11 |
| PS（人员安全） | 2 | ~4 |
| RA（风险评估） | 3 | ~9 |
| CA（安全评估） | 4 | ~9 |
| SC（系统与通信） | 16 | ~39 |
| SI（系统与信息完整性） | 7 | ~14 |

*每项实践的确切分值发布在《DoD 评估方法论》文件（v2.2，2020 年 11 月）中。*

### 影响最大的实践（扣分最多）
补救时优先处理这些——它们权重最高：
1. **AC.L2-3.1.3**——CUI 流量控制（5 分）
2. **SC.L2-3.13.8**——传输中加密／FIPS 验证（5 分）
3. **SC.L2-3.13.11**——FIPS 验证密码学（5 分）
4. **IA.L2-3.5.3**——多因素认证（5 分）
5. **SI.L2-3.14.6**——攻击监测（5 分）
6. **AC.L2-3.1.5**——最小权限（3 分）
7. **AU.L2-3.3.1**——审计日志（3 分）
8. **CM.L2-3.4.1**——基线配置（3 分）

## C3PAO 评估流程

### 预评估（承包商责任）
在聘请 C3PAO 之前，确保：
- [ ] 系统安全计划（SSP）完整并覆盖全部 110 项实践
- [ ] 系统边界已定义并附网络图
- [ ] CUI 数据流已记录
- [ ] POA&M 列出所有尚未满足的实践
- [ ] SPRS 分数已自行计算
- [ ] 每项实践的负责人员已确定

### 评估阶段

**阶段 1——文件审查（远程）**
- C3PAO 审查 SSP、网络图、政策和 POA&M
- 索取工件清单：日志、截图、配置导出、培训记录
- 时长：2-4 周

**阶段 2——评估活动（现场或远程）**
- 与系统管理员、安全人员和执行层访谈
- 技术测试：漏洞扫描、配置审查、访问控制验证
- 流程观察（事件响应桌面推演、维护程序）
- 时长：视范围 1-3 周

**阶段 3——发现与报告**
- C3PAO 出具《发现报告》：每项实践为 MET（满足）、NOT MET（未满足）或 NOT APPLICABLE（不适用）
- 承包商可为有争议的发现补充证据（限时窗口）
- 最终报告提交 CMMC-AB

**阶段 4——认证决定**
- **全部 110 项实践 MET**：签发完全认证；有效 3 年
- **少量未满足实践（非关键）**：附 POA&M 的有条件认证；须在 180 天内补救
- **关键实践未满足**：不予认证；补救后重新安排

### 关键实践（认证时不得有 POA&M）
以下实践必须完全 MET 才能签发任何认证：
- AC.L2-3.1.3（CUI 流量控制）
- IA.L2-3.5.3（多因素认证）
- SC.L2-3.13.8（传输中加密）
- SC.L2-3.13.11（FIPS 验证密码学）
- SI.L2-3.14.6（攻击监测）
- AU.L2-3.3.1（审计日志）
- IR.L2-3.6.1（事件响应能力）

## POA&M 规则与管理

### 认证时 POA&M 可包含的内容
- 第 2 级：认证时最多可有少量非关键实践保留在 POA&M 中
- POA&M 补救期限：自认证之日起 **180 天**
- 未能补救＝撤销认证
- 第 3 级：认证时不得有 POA&M——所有实践必须 MET

### POA&M 条目格式

| 字段 | 说明 |
|-------|-------------|
| 实践 ID | CMMC 实践标识符（例如 CM.L2-3.4.2） |
| 弱点说明 | 未实施什么以及为何 |
| 补救步骤 | 实现合规的具体行动 |
| 里程碑 1-N | 带日期的中间检查点 |
| 计划完成 | 全面实施的目标日期 |
| 所需资源 | 人员、工具、预算 |
| 状态 | 开放 / 进行中 / 已完成 |
| 关闭证据 | 哪些工件将证明完成 |

### POA&M 最佳实践
- 寻求认证时，绝不在 POA&M 中列入关键实践
- 每月更新；过时的 POA&M 会引起审计员关注
- 将每个 POA&M 条目链接到相关 SSP 章节
- 记录根本原因，而不仅仅是症状

## 按实践类型的证据要求

### 文件证据（政策、程序、计划）
- 可接受格式：PDF、Word、带元数据的截图
- 必须显示：作者、日期、版本、批准签名
- 示例：SSP、访问控制政策、事件响应计划、培训记录

### 技术证据（系统配置、日志）
- 来自防火墙、Active Directory、SIEM 的配置导出
- 漏洞扫描报告（优先经过认证的扫描）
- 显示所有特权用户注册的 MFA 注册报告
- 显示补救时间线的补丁管理报告

### 访谈证据
- 评估员将访谈：ISSO／ISSM、系统管理员、最终用户、执行层
- 准备人员描述其安全职责
- 不能用文件替代访谈——两者都必需

## DIBNET 事件报告（DFARS 7012）

DFARS 252.204-7012 强制网络安全事件报告，无论 CMMC 级别：
- **报告至**：DIBNET 门户（dibnet.dod.mil）
- **期限**：发现事件后 **72 小时**内
- **报告内容**：受影响的系统、涉及的 CUI 类别、攻击向量、取证指标
- **保全证据**：保留磁盘镜像和取证证据 90 天；国防部可索取副本
- **通知总包**：如你是分包商，通知总包，由其通知国防部

### 什么构成可报告事件
- 未经授权访问包含 CUI 的系统
- CUI 外泄（实际或疑似）
- 在处理 CUI 的系统上检测到恶意软件
- 可能导致 CUI 访问的凭据失窃

## 常见评估发现

| 实践 | 常见发现 | 典型补救 |
|----------|---------------|---------------------|
| IA.L2-3.5.3 | 未为所有特权账户或远程访问启用 MFA | 部署 MFA 解决方案（Azure MFA、Duo、Okta）；通过条件访问强制执行 |
| SC.L2-3.13.11 | 仍启用 TLS 1.0／1.1；使用非 FIPS 算法 | 禁用 TLS 1.0／1.1；仅启用 FIPS 验证密码套件 |
| AU.L2-3.3.1 | 日志未按政策保留；并非所有设备都向 SIEM 记录 | 部署／配置 SIEM；设置 3 年保留期；覆盖所有触及 CUI 的系统 |
| CM.L2-3.4.1 | 无正式基线配置文件 | 按操作系统／应用创建基线配置文档；存入变更管理 |
| AC.L2-3.1.5 | 管理员权限过多；共享管理员账户 | 实施 PAM 解决方案；每季度审计／移除多余权限 |
| RA.L2-3.11.2 | 漏洞扫描未认证；未覆盖所有资产 | 配置凭据扫描；每月扫描所有范围内资产 |
| CA.L2-3.12.4 | SSP 过时或不完整 | 更新 SSP；每年或重大变更后审查并重新批准 |
| AC.L2-3.1.3 | CUI 可被无知悉必要者访问 | 实施数据分类标签；在文件／文件夹层面强制执行访问控制 |
