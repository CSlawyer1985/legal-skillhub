# NIST CSF 2.0——功能、类别与子类别

来源：NIST 网络安全框架 2.0（2024 年 2 月）
https://doi.org/10.6028/NIST.CSWP.29

---

## 治理（GOVERN，GV）

组织层面的网络安全风险管理战略、期望和政策得以建立、传达和监测。

### GV.OC——组织背景
组织网络安全风险管理决策所处的环境得以理解。

| ID | 子类别 |
|----|-------------|
| GV.OC-01 | 组织使命得以理解，并为网络安全风险管理提供信息 |
| GV.OC-02 | 内部和外部利益相关方得以理解，其关于网络安全风险管理的需求和期望得以理解和考虑 |
| GV.OC-03 | 关于网络安全的法律、监管和合同要求——包括隐私和公民自由义务——得以理解和处理 |
| GV.OC-04 | 利益相关方依赖或期望组织提供的关键目标、能力和服务得以理解和传达 |
| GV.OC-05 | 组织所依赖的成果、能力和服务得以理解和传达 |

### GV.RM——风险管理战略
组织的优先事项、约束条件、风险偏好和风险容忍度声明及假设得以建立、传达，并用于支持运营风险决策。

| ID | 子类别 |
|----|-------------|
| GV.RM-01 | 风险管理目标得以建立并获组织利益相关方同意 |
| GV.RM-02 | 风险偏好和风险容忍度声明得以建立、传达和维护 |
| GV.RM-03 | 网络安全风险管理活动和成果纳入企业风险管理流程 |
| GV.RM-04 | 描述适当风险应对选项的战略方向得以建立和传达 |
| GV.RM-05 | 就网络安全风险（包括来自供应商和其他第三方的风险）建立跨组织的沟通渠道 |
| GV.RM-06 | 计算、记录、分类和排序网络安全风险的标准化方法得以建立和传达 |
| GV.RM-07 | 战略机遇（即正向风险）得以描述并纳入组织网络安全风险讨论 |

### GV.RR——角色、职责与权限
促进问责、绩效评估和持续改进的网络安全角色、职责和权限得以建立和传达。

| ID | 子类别 |
|----|-------------|
| GV.RR-01 | 组织领导层对网络安全风险负责并承担责任，培育具有风险意识、合乎道德且持续改进的文化 |
| GV.RR-02 | 与网络安全风险管理相关的角色、职责和权限得以建立、传达、理解和执行 |
| GV.RR-03 | 与网络安全风险战略、角色、职责和政策相称的充足资源得以分配 |
| GV.RR-04 | 网络安全纳入人力资源实践 |

### GV.PO——政策
组织网络安全政策得以建立、传达和执行。

| ID | 子类别 |
|----|-------------|
| GV.PO-01 | 基于组织背景、网络安全战略和优先事项的网络安全风险管理政策得以建立、传达和执行 |
| GV.PO-02 | 管理网络安全风险的政策得以审查、更新、传达和执行，以反映要求、威胁、技术和组织使命的变化 |

### GV.OV——监督
组织范围内的网络安全风险管理活动和绩效结果用于为风险管理战略提供信息、改进和调整。

| ID | 子类别 |
|----|-------------|
| GV.OV-01 | 审查网络安全风险管理战略成果，为战略和方向提供信息并作出调整 |
| GV.OV-02 | 审查并调整网络安全风险管理战略，确保其覆盖组织要求和风险 |
| GV.OV-03 | 评估和审查组织网络安全风险管理绩效，确定所需调整 |

### GV.SC——网络安全供应链风险管理
网络供应链风险管理流程由组织利益相关方识别、建立、管理、监测和改进。

| ID | 子类别 |
|----|-------------|
| GV.SC-01 | 网络安全供应链风险管理计划、战略、目标、政策和流程得以建立并获组织利益相关方同意 |
| GV.SC-02 | 供应商、客户和合作伙伴的网络安全角色与职责得以建立、传达，并在内部和外部协调 |
| GV.SC-03 | 网络安全供应链风险管理纳入网络安全和企业风险管理、风险评估及改进流程 |
| GV.SC-04 | 供应商得以识别并按关键性排序 |
| GV.SC-05 | 应对供应链网络安全风险的要求得以建立、排序，并纳入与供应商及其他相关第三方的合同和其他类型协议 |
| GV.SC-06 | 在进入正式的供应商或其他第三方关系之前，开展规划和尽职调查以降低风险 |
| GV.SC-07 | 供应商及其产品和服务以及其他第三方构成的风险在关系存续期间得以理解、记录、排序、评估、应对和监测 |
| GV.SC-08 | 相关供应商和其他第三方纳入事件规划、响应和恢复活动 |
| GV.SC-09 | 供应链安全实践纳入网络安全和企业风险管理计划，并在技术产品和服务生命周期内监测其绩效 |
| GV.SC-10 | 网络安全供应链风险管理计划包含针对合作伙伴关系或供应链关系结束后所发生活动的规定 |

## 识别（IDENTIFY，ID）

组织当前的网络安全风险得以理解。

### ID.AM——资产管理
使组织能够实现业务目的的资产（数据、硬件、软件、系统、设施、服务、人员）得以识别和管理，并与其对组织目标和组织风险战略的相对重要性保持一致。

| ID | 子类别 |
|----|-------------|
| ID.AM-01 | 维护组织管理的硬件清单 |
| ID.AM-02 | 维护组织管理的软件、服务和系统清单 |
| ID.AM-03 | 维护组织授权网络通信及内部和外部网络数据流的表示 |
| ID.AM-04 | 维护供应商提供服务的清单 |
| ID.AM-05 | 基于分类、关键性、资源和对使命的影响对资产进行排序 |
| ID.AM-07 | 维护指定数据类型的数据及相应元数据清单 |
| ID.AM-08 | 在系统、硬件、软件、服务和数据的整个生命周期内对其进行管理 |

### ID.RA——风险评估
组织对组织、资产和个人所面临的网络安全风险有所理解。

| ID | 子类别 |
|----|-------------|
| ID.RA-01 | 识别、验证和记录资产中的漏洞 |
| ID.RA-02 | 从信息共享论坛和来源接收网络威胁情报 |
| ID.RA-03 | 识别并记录组织面临的内部和外部威胁 |
| ID.RA-04 | 识别并记录威胁利用漏洞的潜在影响和可能性 |
| ID.RA-05 | 利用威胁、漏洞、可能性和影响理解固有风险，并为风险应对优先事项提供信息 |
| ID.RA-06 | 选择、排序、规划、跟踪和传达风险应对措施 |
| ID.RA-07 | 管理和评估变更与例外情况的风险影响，并予以记录和跟踪 |
| ID.RA-08 | 建立接收、分析和响应漏洞披露的流程 |
| ID.RA-09 | 在获取和使用硬件和软件之前评估其真实性和完整性 |
| ID.RA-10 | 在获取关键供应商之前对其进行评估 |

### ID.IM——改进
在所有 CSF 功能中识别组织网络安全风险管理流程、程序和活动方面的改进。

| ID | 子类别 |
|----|-------------|
| ID.IM-01 | 从评估中识别改进 |
| ID.IM-02 | 从安全测试和演练（包括与供应商及相关第三方协调开展的测试和演练）中识别改进 |
| ID.IM-03 | 从运营流程、程序和活动的执行中识别改进 |
| ID.IM-04 | 将事件、漏洞和其他发现传达给指定的内部和外部利益相关方 |

## 保护（PROTECT，PR）

用于管理组织网络安全风险的保障措施得以使用。

### PR.AA——身份管理、认证与访问控制
对物理和逻辑资产的访问限于授权用户、服务和硬件，并与所评估的未经授权访问风险相称地管理。

| ID | 子类别 |
|----|-------------|
| PR.AA-01 | 组织管理授权用户、服务和硬件的身份与凭据 |
| PR.AA-02 | 基于交互背景核验身份并将其绑定到凭据 |
| PR.AA-03 | 对用户、服务和硬件进行认证 |
| PR.AA-04 | 身份断言得以保护、传递和验证 |
| PR.AA-05 | 访问权限、权利和授权在政策中定义，并予以管理、执行和审查，且纳入最小权限和职责分离原则 |
| PR.AA-06 | 对资产的物理访问得以与风险相称地管理、监测和执行 |

### PR.AT——意识与培训
组织人员获得网络安全意识和培训，使其能够执行与网络安全相关的任务。

| ID | 子类别 |
|----|-------------|
| PR.AT-01 | 人员获得意识和培训，使其具备在考虑网络安全风险的情况下执行一般任务的知识和技能 |
| PR.AT-02 | 担任专门角色的人员获得意识和培训，使其具备在考虑网络安全风险的情况下执行相关任务的知识和技能 |

### PR.DS——数据安全
数据的管理与组织的风险战略保持一致，以保护信息的机密性、完整性和可用性。

| ID | 子类别 |
|----|-------------|
| PR.DS-01 | 静态数据的机密性、完整性和可用性得到保护 |
| PR.DS-02 | 传输中数据的机密性、完整性和可用性得到保护 |
| PR.DS-10 | 使用中数据的机密性、完整性和可用性得到保护 |
| PR.DS-11 | 创建、保护、维护和测试数据备份 |

### PR.PS——平台安全
物理和虚拟平台的硬件、软件（包括固件和代码）和服务的管理与组织的风险战略保持一致，以保护其机密性、完整性和可用性。

| ID | 子类别 |
|----|-------------|
| PR.PS-01 | 建立并应用配置管理实践 |
| PR.PS-02 | 软件与风险相称地维护、更换和移除 |
| PR.PS-03 | 硬件与风险相称地维护、更换和移除 |
| PR.PS-04 | 生成日志记录并使其可用于持续监测 |
| PR.PS-05 | 防止未经授权软件的安装和执行 |
| PR.PS-06 | 整合安全软件开发实践，并评估其安全性 |

### PR.IR——技术基础设施韧性
安全架构的管理与组织的风险战略保持一致，以保护资产和技术基础设施，并实施适当的冗余。

| ID | 子类别 |
|----|-------------|
| PR.IR-01 | 保护网络和环境免受未经授权的逻辑访问和使用 |
| PR.IR-02 | 保护组织的技术资产免受环境威胁 |
| PR.IR-03 | 实施机制以在正常和不利情况下实现韧性要求 |
| PR.IR-04 | 保持充足的资源容量以确保可用性 |

## 检测（DETECT，DE）

可能的网络安全攻击和入侵得以发现和分析。

### DE.CM——持续监测
监测资产以发现异常、入侵指标和其他潜在不利事件。

| ID | 子类别 |
|----|-------------|
| DE.CM-01 | 监测网络和网络服务以发现潜在不利事件 |
| DE.CM-02 | 监测物理环境以发现潜在不利事件 |
| DE.CM-03 | 监测人员活动和技术使用以发现潜在不利事件 |
| DE.CM-06 | 监测外部服务提供商的活动和服务以发现潜在不利事件 |
| DE.CM-09 | 监测计算硬件和软件、运行时环境及其数据以发现潜在不利事件 |

### DE.AE——不利事件分析
分析异常、入侵指标和其他潜在不利事件，以描述事件特征并检测网络安全事件。

| ID | 子类别 |
|----|-------------|
| DE.AE-02 | 分析潜在不利事件以更好地理解相关活动 |
| DE.AE-03 | 关联来自多个来源的信息 |
| DE.AE-04 | 理解不利事件的估计影响和范围 |
| DE.AE-06 | 向授权人员和工具提供不利事件信息 |
| DE.AE-07 | 将网络威胁情报和其他背景信息纳入分析 |
| DE.AE-08 | 当不利事件符合既定的事件标准时宣布为事件 |

## 响应（RESPOND，RS）

针对已检测到的网络安全事件采取措施。

### RS.MA——事件管理
对已检测到的网络安全事件的响应得以管理。

| ID | 子类别 |
|----|-------------|
| RS.MA-01 | 事件宣布后，与相关第三方协调执行事件响应计划 |
| RS.MA-02 | 对事件报告进行分类和验证 |
| RS.MA-03 | 对事件进行分类和排序 |
| RS.MA-04 | 视需要升级或提升事件处理级别 |
| RS.MA-05 | 适用启动事件恢复的标准 |

### RS.AN——事件分析
开展调查以确保有效响应，并支持取证和恢复活动。

| ID | 子类别 |
|----|-------------|
| RS.AN-03 | 开展分析以确定事件期间发生了什么以及事件的根本原因 |
| RS.AN-06 | 记录调查期间采取的行动，并保存记录的完整性和出处 |
| RS.AN-07 | 收集事件数据和元数据，并保持其完整性 |
| RS.AN-08 | 估计并验证事件的规模 |

### RS.CO——事件响应报告与沟通
响应活动按法律、法规或政策的要求与内部和外部利益相关方协调。

| ID | 子类别 |
|----|-------------|
| RS.CO-02 | 将事件通知内部和外部利益相关方 |
| RS.CO-03 | 与指定的内部和外部利益相关方共享信息 |

### RS.MI——事件缓解
开展活动以防止事件扩大并减轻其影响。

| ID | 子类别 |
|----|-------------|
| RS.MI-01 | 事件得到遏制 |
| RS.MI-02 | 事件得到根除 |

## 恢复（RECOVER，RC）

受网络安全事件影响的资产和运营得以恢复。

### RC.RP——事件恢复计划执行
开展恢复活动，以确保受网络安全事件影响的系统和服务的运营可用性。

| ID | 子类别 |
|----|-------------|
| RC.RP-01 | 自 RS.MA 子类别启动后，执行事件响应计划中的恢复部分 |
| RC.RP-02 | 选择、界定范围、排序并实施恢复行动 |
| RC.RP-03 | 在将备份和其他恢复资产用于恢复之前，验证其完整性 |
| RC.RP-04 | 考虑关键使命功能和网络安全风险管理，以确立事件后运营规范 |
| RC.RP-05 | 验证已恢复资产的完整性，恢复系统和服务，并确认恢复正常运营状态 |
| RC.RP-06 | 依据标准宣布事件恢复结束，并完成事件相关文件 |

### RC.CO——事件恢复沟通
恢复活动与内部和外部各方协调。

| ID | 子类别 |
|----|-------------|
| RC.CO-03 | 将恢复活动及恢复运营能力的进展传达给指定的内部和外部利益相关方 |
| RC.CO-04 | 使用经批准的方法和消息发布事件恢复的公开更新 |
