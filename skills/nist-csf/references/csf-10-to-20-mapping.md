# NIST CSF 1.1 → CSF 2.0 迁移指南

来源：NIST CSF 2.0（2024 年 2 月）和 CSF 1.1（2018 年 4 月）

---

## 变更摘要

| 方面 | CSF 1.1 | CSF 2.0 |
|--------|---------|---------|
| 功能 | 5 个（ID、PR、DE、RS、RC） | 6 个（+ **GV：治理 Govern**） |
| 子类别总数 | 108 | 106 |
| 治理功能 | 嵌入 ID/PR 中 | 独立——6 个类别，23 个子类别 |
| 供应链风险 | ID.SC（5 个子类别） | GV.SC（10 个子类别）——显著扩展 |
| 概要（Profiles） | 基本概念 | 强化——组织概要模板、社区概要 |
| 层级（Tiers） | 4 个层级 | 4 个层级——描述精炼 |
| 参考性引用（Informative References） | 内嵌 | 移至在线 NIST 参考工具（可检索） |
| 受众 | 关键基础设施为主 | 明确面向所有行业、所有规模 |
| 快速入门指南 | 无 | 新增：面向中小企业、企业风险管理者、政府 |

## 迁移检查清单：CSF 1.1 → CSF 2.0

在迁移现有 CSF 1.1 实施时使用此检查清单：

**治理（新的 GV 功能）**
- [ ] 正式记录网络安全战略和风险容忍度（GV.RM-01、GV.RM-02）
- [ ] 明确分配网络安全角色并对领导层问责（GV.RR-01、GV.RR-02）
- [ ] 建立网络安全政策和审查周期（GV.PO-01、GV.PO-02）
- [ ] 创建监督机制以审查风险战略结果（GV.OV-01 至 03）
- [ ] 将供应链风险管理扩展至覆盖 GV.SC-01 至 GV.SC-10
- [ ] 记录组织情境和利益相关方依赖关系（GV.OC-01 至 05）

**识别更新**
- [ ] 添加数据和元数据清单（ID.AM-07）
- [ ] 实施资产生命周期管理（ID.AM-08）
- [ ] 建立漏洞披露流程（ID.RA-08）
- [ ] 在收购前评估硬件/软件真实性（ID.RA-09）
- [ ] 创建改进跟踪流程（ID.IM-01 至 04）

**保护更新**
- [ ] 添加使用中数据保护控制（PR.DS-10）
- [ ] 整合安全软件开发实践（PR.PS-06）

**检测更新**
- [ ] 将威胁情报整合到事件分析中（DE.AE-07）
- [ ] 定义并记录事件声明标准（DE.AE-08）

**响应更新**
- [ ] 正式化事件分诊、分类和升级（RS.MA-02 至 04）
- [ ] 改进事件数据收集和完整性（RS.AN-07）

**恢复更新**
- [ ] 添加事件后运营规范评估（RC.RP-04）
- [ ] 定义事件恢复结束标准（RC.RP-06）
- [ ] 建立事件恢复的公开更新流程（RC.CO-04）

## CSF 版本共存

拥有 CSF 1.1 实施的组织无需立即迁移——CSF 2.0 在意图上向后兼容。关键的实际变化是：

1. **治理不是可选项**：如贵组织已将治理实践嵌入 ID 或 PR，请明确映射到新的 GV 功能
2. **供应链是一等关注事项**：ID.SC（5 个子类别）必须扩展为 GV.SC（10 个子类别）
3. **改进现在结构化**：新的 ID.IM 类别将此前临时的做法正式化
4. **参考性引用移至在线**：使用 NIST CSF 2.0 参考工具 https://csrc.nist.gov/Projects/cybersecurity-framework/Filters#/csf/filters 查找每个子类别的当前参考性引用
