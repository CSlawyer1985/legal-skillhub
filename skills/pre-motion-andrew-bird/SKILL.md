# Pre-Motion——英国诉讼的对抗式事前验尸

您认为您已构建了案件的最强版本。Pre-Motion 通过结构化的对抗式管线运行它，以找出它实际会在哪里输——对方律师会首先拉扯的程序、实体、证据和策略失败模式。按设计，这是确认偏误的对立面。

适用于：提起诉讼前进行压力测试的事务律师、签署前的内部法律顾问、评估和解价值的调解人、为案件定价的诉讼资助方，以及任何决定是否承接案件的人。

## 它如何运行

对案件进行四次遍历。如您的环境支持，在第 3 阶段以并行子代理运行四次对抗式遍历；否则顺序运行——方法和输出无论哪种方式都相同。

1. **乐观基线。** 构建证据支持的最强案件版本。这是之后一切的对照面。
2. **证据检查。** 三项检查：文件审查（缺口、薄弱文件）、交叉引用（一份文件与另一份矛盾）、时间顺序（时间线缺口、不吻合的日期）。产出带各自严重程度的证据标记。
3. **事前验尸对手。** 四次对抗式遍历，每个下方失败类别一次。给每次同样的框架：*"现在是 [审判日期 + 1 年]。本案已经败诉。回溯——您所在类别中的什么导致了败诉？"* 按类别产出排序的失败场景。
4. **综合。** 将乐观基线与对抗式发现进行比对。产出简报。

`--depth=fast` 运行单次合并的对抗式遍历以快速阅读；`--depth=thorough` 完整运行全部四次遍历。

## 输入

- 案件事实：当事人、简要时间顺序、索赔项、法域、审理地。
- 证据引用：文件、证人陈述、专家报告——指向案件内容的指针，而非重新上传。
- 用户所看到的最强案件版本（乐观基线）。
- 可选：相对方已陈述或预期的抗辩。
- 可选：`--depth=fast|thorough`。

## 第 1 步——允许使用检查（CPR 31.22 + 特权）

在阅读案件文件之前：

- 宿主工作区强制执行硬性关卡（案件标识与程序引用匹配、特权姿态）。如果本技能正在运行，该关卡已经通过——本步骤不替代它。
- 仍须向用户确认：是否有任何文件取自*其他*程序中的证据开示？如有，在获得许可、当事人同意或公开法庭引用确立之前停止（CPR 31.22 默示承诺）。
- 如案件的特权姿态混杂，在输出中添加 `[PRIVILEGE FLAGGED]` 横幅，并建议在任何对外分发前由律师审查。

## 失败模式类别

第 3 阶段的四次遍历专门针对英国民事案件失败的四种方式。

### 程序

- 时效已过或有争议（《1980 年时效法》第 5 / 11 / 14A 条）。
- 诉前协议不合规（诉前行为实务指引、行业协议）。
- 被驳回或即决判决的脆弱性（CPR 3.4、CPR 24）。
- 费用制裁风险（CPR 44.2）。
- 拒绝替代性争议解决（ADR）的敞口（Halsey 案；Churchill v Merthyr Tydfil [2023]）。
- 送达 / 管辖缺陷（CPR 6）。
- 证据开示制度的失误（CPR 31 对 PD 57AD）。

### 实体

- 诉因要件未证明。
- 因果关系缺口，事实或法律层面（Wagon Mound、Fairchild、SAAMCO）。
- 减损义务的失败（British Westinghouse）。
- 肯定性抗辩（禁反言、放弃、免除、共同过失、ex turpi causa）。
- 法定障碍（《消费者权利法》、UCTA、法定时效）。

### 证据

- 特权敞口（Unilever 例外、共同抗辩破裂、Rush & Tompkins 边界）。
- 证据开示失败和不利推断风险（CPR 31、PD 57AD）。
- 证人可信度、可用性、不一致。
- 传闻弱点（《1995 年民事证据法》第 2-4 条通知失败）。
- 专家报告缺陷（CPR 35；联合指令失败；Toth v Jarman）。
- 文件真实性和保管链。

### 策略

- 和解杠杆误判（与对方的 BATNA 差距）。
- 成本/收益比与客户目标错位。
- 提起诉讼或庭审带来的声誉或监管敞口。
- 信息不对称对客户不利。
- 相对方的 BATNA 强于乐观基线所假设的。

每次遍历都应为其类别引用相关权威依据，并将其无法钉到条文或引注的任何规则或判例标记为 `[CITE NEEDED]`，而非将其陈述为定论。

## 输出

按以下章节产出简报。将其呈现为成品简报——不要将此清单作为模板回显，也不要编造事实来填满章节；如某章节无内容，如实说明。

- 一行审查者说明：*工作成果，为诉讼而准备，受诉讼特权约束。*
- 页眉：案件名称、生成日期、深度、特权姿态和结论（Steelman / Borderline / Strawman）。
- **那句不留情面的话**——"如果我们输掉此案，原因将是：[一句话]。"
- **乐观基线**——基线遍历所构建的最强案件版本。
- **排序的失败场景**——按程序 / 实体 / 证据 / 策略分组。每个场景为一段，附严重程度（高/中/低）、可能性（高/中/低）和缓解措施。
- **证据不一致**——第 2 阶段的标记。
- **盲点**——基线假设已解决而对手发现的开放问题。
- **缓解措施**——在适用时为每个场景提出一项具体行动：强化证据、修改诉状、和解、撤诉、以不同方式向律师布置任务。
- **和解姿态影响**——仅定性。将失败画像转化为姿态，例如"多项程序失败模式被评为高——比基线所建议的更积极和解；考虑在起诉前提出 Calderbank 要约。"不产出数字；完整的 BATNA / ZOPA 分析属于 v0.2 的 `settlement-helper` 技能。

随时内联标记不确定性：

- `[SME VERIFY — failure mode]`——边界性的对手输出；由律师决定。
- `[CITE NEEDED — authority]`——引用了无条文或判例的规则或学说；在依赖前核验。
- `[EVIDENCE FLAG — severity]`——由第 2 阶段提出；对照源文件检查。

## 本技能不做什么

- 预测结果。它呈现失败模式；结果取决于裁判庭、法官、证人和那一天。
- 替您决定是否承接案件。结论（steelman / strawman）是模型对简报的解读，而非建议。
- 替代律师的策略决定。和解、撤诉、强化——都是律师的决定。
- 涵盖非英国程序（美国联邦、苏格兰、北爱尔兰）。
- 在庭审期间运行。这是诉前、和解前或资助前使用。
- 替代正式的律师意见。御用大律师（KC）对案件强弱的看法比此输出更重要。Pre-Motion 是该对话的结构化提示词，而非其替代品。
