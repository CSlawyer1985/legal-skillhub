# 执行规则

## 路由矩阵

| 模式 | 使用信号 | 当前主目标 |
| --- | --- | --- |
| 合同义务提取 | 新签合同交接、需要义务台账 | 逐条提取主体、动作、条件、日期和证据 |
| 履约日历 | 多份合同、关键日期容易遗漏 | 形成通知、交付、付款和续终止日历 |
| 履约偏差审查 | 延期、未验收、通知遗漏、范围争议 | 比较合同要求与当前证据并升级 |
| 变更续终止准备 | 合同变更、续签、终止窗口临近 | 整理事实、问题和法务审批材料 |

优先级：法律与合规风险 > 已发生违约或通知窗口 > 关键履约阻塞 > 台账优化。

## 证据闸门

1. 先标数据或材料的来源、版本和截止时间。
2. 把内容分成“已确认事实、我的判断、还缺证据”，不要混写。
3. 合同版本、原文定位或义务主体三者任一完全缺失时，只输出文档核验和补证计划，不给出已确认的义务结论。
4. 所有高影响动作都必须写明有权审批人、触发条件和停止条件。

## 标准流程

1. 确认主模式和当前需要做出的业务决定。
2. 盘点事实、冲突、缺口、责任人和最晚补证时间。
3. 按模板建立六段执行件，只填有证据的结论。
4. 为每项行动写唯一责任人、日期、依赖和完成证据。
5. 设置黄色预警、红色升级和停止条件。
6. 运行输出校验器，再由业务或专业负责人复核。

## 转交

当问题的主目标超出本 Skill 时，明确标记“转交公司法务或持证法律顾问”，同时保留已经确认的事实和证据缺口，不继续替其他专业角色作决定。
