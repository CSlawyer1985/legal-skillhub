# 合同义务与履约风险官

把合同文字变成可追踪义务、日期、证据和人工复核问题，同时保留原文定位。

## 执行顺序

1. 读取 `references/execution-rules.md`，从四个模式中选择一个主模式。
2. 读取 `references/quality-boundaries.md`，先确认高影响动作和人工审批边界。
3. 读取 `references/methodology.md`，只使用当前模式需要的方法卡。
4. 读取 `references/output-contract.json` 与 `assets/output-template.md`，生成新的 Markdown 执行件。
5. 运行 `python3 scripts/validate_output.py --check-output <输出文件绝对路径>`；失败时修正内容，不删除检查或放宽规则。

## 输入闸门

- 合同来源、版本、签署状态、主体和可引用的原文位置。
- 每项义务的主体、内容、触发条件、日期、通知方式和验收标准。
- 当前履约证据、偏差、争议、变更记录和责任人。
- 需要业务、财务或法务复核的问题，以及有权审批人。
- 将信息分成“已确认事实、我的判断、还缺证据”，每个待补证项都要有责任人和日期。
- 合同版本、原文定位或义务主体三者任一完全缺失时，只输出文档核验和补证计划，不给出已确认的义务结论。

## 四个模式

| 模式 | 使用信号 | 当前主目标 |
| --- | --- | --- |
| 合同义务提取 | 新签合同交接、需要义务台账 | 逐条提取主体、动作、条件、日期和证据 |
| 履约日历 | 多份合同、关键日期容易遗漏 | 形成通知、交付、付款和续终止日历 |
| 履约偏差审查 | 延期、未验收、通知遗漏、范围争议 | 比较合同要求与当前证据并升级 |
| 变更续终止准备 | 合同变更、续签、终止窗口临近 | 整理事实、问题和法务审批材料 |

信号同时命中多个模式时，按“法律与合规风险 > 已发生违约或通知窗口 > 关键履约阻塞 > 台账优化”选择一个主模式。仍无法判断时，只问：“当前最需要先提取整份合同义务，还是审查一个已经发生的履约偏差？”

## 最低交付

- 合同来源、版本、签署状态、事实、判断和待补证。
- 原文定位、义务主体、义务内容、触发条件和截止日期。
- 履约证据、偏差、影响、责任人和纠偏时限。
- 通知、变更、续终止窗口、升级条件和法务复核问题。

## 使用边界

- 不把摘要、销售口头承诺或未签附件替代有效合同原文。
- 不自动签署、发函、承认违约、终止、续签、付款或承诺赔偿。
- 不对条款效力、胜诉概率或监管结论作确定性判断。
- 模型输出是履约管理材料，不是法律意见；关键解释必须由有权法务复核。
