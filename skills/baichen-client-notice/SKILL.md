# 客户函告起草

以客户自身名义起草各类正式函告文书，发函主体为客户本人/本公司（非律师/律所），覆盖催告、回复、说明、通知、声明、汇报、承诺、举报八大场景。

## 质量准则

| 准则 | 要求 |
|------|------|
| **格式统一+要素齐全** | 同类函告结构一致，标题/称谓行/落款标准化；各项逐项齐备 |
| **繁简得当+逻辑严密** | 事实抓关键节点，法律分析点到即止；正文~1200-2000字，复杂可至3000-4000字 |
| **用语准确** | 金额/日期/条款编号与原始材料一致，事实限定语恰当 |

## Phase 0上下文检测

执行 `ndr-standards.md` §4。搜索 outputs/*_case_profile.json → 按 type="NDR" 过滤 → ask_user 确认继承 → 未找到则创建新 Profile。

如不确定当前场景应使用本技能还是 律师函，参见 `ndr-standards.md` §11。

## 整体流程

```
步骤 0跨函件规划（选做）
    ↓
步骤 1信息采集（含意图识别+特殊场景检测）
    ↓
步骤 2强制法律检索
    ↓
步骤 3事实梳理
    ↓
步骤 4函告类型确认、策略定级与模板匹配
    ↓
步骤 5起草函件 → 质量自检
    ↓
步骤 6用户审校
```

***

## 步骤 0跨函件规划（选做）

同一事件需多份关联函告时先规划函数序列（类型/顺序/目的）、引用关系+事实分工（前函详述，后函引编号+结论）、语气差异化。单份函告直接跳过。

## 步骤 1信息采集

### 1.1 信息渠道

| 渠道 | 方式 |
|------|------|
| 知识库 | `ima-knowledge` skill 定位 → search(source="kb") + fetch |
| 上传文件 | file_read 读取 |
| 用户输入 | 直接接收案情陈述 |

### 1.2 引导式信息采集

用自然对话逐个问，用户答一个补一个，缺失槽位逐个提示。

#### 通用槽位（八类均须采集）

| 槽位 | 提问方式 | 默认值 |
|------|---------|--------|
| 发函方身份 | "请确认发函方全称、地址、联系人、电话" | — |
| 信息块模式 | "落款模式还是置顶模式？" | 落款模式 |
| 致送对象 | "致送对象全称是什么？" | — |

#### 类型专属槽位

| 函告类型 | 引导话术示例 |
|---------|------------|
| 催告函 | "请提供合同签订日期、付款/履约期限条款、违约金条款——不需要整份合同。对方欠了多少、逾期多久了？" |
| 回复函 | "请把对方来函发给我。你认为对方的核心主张是什么？" |
| 说明函 | "你想说明哪几件事？是对方要求还是你主动？" |
| 通知函 | "你要通知什么？依据合同哪一条？" |
| 声明函 | "你要声明什么？是澄清误解还是驳斥不实信息？" |
| 汇报函 | "为什么汇报——定期的还是应要求？有什么需要对方决策的问题吗？" |
| 承诺函 | "为什么要出具这份承诺？有没有相关的协议/风险披露文件？" |
| 举报函 | "你是个人还是公司举报？被举报人是个人还是公司？举报到哪个部门？" |

#### 采集规则

逐个提问（一次1-2个槽位）；自动跳过已提供信息；允许延迟（标记缺失，步骤4再提示）；能推断的直接进入专属槽位提问。

### 1.3 函告意图识别

| 用户表述关键词 | 初步判定类型 |
|---------------|:----------:|
| "催""催款""限期""尽快履行""再不付" | 催告函 |
| "回复""答复""就来函""对方来函说" | 回复函 |
| "说明一下""解释""澄清""情况是" | 说明函 |
| "通知""告知""解除""终止""变更" | 通知函 |
| "声明""表态""公开""澄清立场" | 声明函 |
| "汇报""进展""报告""情况汇报" | 汇报函 |
| "承诺""保证书""担保函""维好协议""一致行动""不竞争""竞业""保密承诺""权属承诺""合规承诺""还款承诺"等 | 承诺函 |
| "举报""揭发""反映""查处""实名" | 举报函 |

初步判定结果在步骤4与用户确认。

#### 承诺函场景域识别（细分十大域）

| 场景域 | 信号词 | 开篇鉴于段重点 |
|--------|-------|--------------|
| 私募/投资 | LP出资、基金分配、回购承诺、对赌、缴款 | 风险披露→知情确认→责任承担 |
| 并购交易 | 反垄断配合、过渡期约束、陈述保证、交割条件 | 交易背景→义务范围→违约后果 |
| 公司治理 | 一致行动、关联交易、同业竞争避免、不竞争、董事承诺 | 主体关系→约束范围→期限 |
| 合规/监管 | 反腐败、数据安全、环保合规、安全生产、反洗钱 | 法规依据→合规现状→持续义务 |
| 融资/担保 | 流动性支持、维好协议、还款承诺、连带责任 | 主债务→增信措施→追偿路径 |
| 知识产权 | 权属承诺、不侵权保证、技术来源合法性 | 权利状况→无争议声明→赔偿 |
| 劳动/人事 | 竞业限制、保密、离职交接、培训服务期 | 雇佣关系→约定义务→违约后果 |
| 房地产/工程 | 质量承诺、按期交付、农民工工资、安全施工 | 项目信息→承诺事项→监管后果 |
| 政府/行政 | 项目申报真实性、补贴合规、招投标诚信 | 申报项目→真实性声明→行政责任 |
| 诉讼/争议 | 和解承诺、执行担保、财产处置、调解履行 | 争议背景→承诺内容→违约后果 |

### 1.4 特殊场景检测

读取 `references/special-scenarios.md`，检测是否匹配破产/清算、国资/政府、群体性纠纷。如匹配，步骤4提示，步骤5起草时叠加适用。

## 步骤 3事实梳理

按五要素梳理时间线**签约 → 付款 → 履约期满 → 违约/争议事实 → 沟通记录 → 现状**。

| 要素 | 内容 |
|------|------|

## 步骤 4函告类型确认、策略定级与模板匹配

### 4.1 类型确认

向用户呈现步骤1初步判定结果，询问确认、切换类型、或自定义标题。

#### 回复函 vs 说明函辨析

| 场景信号 | → 推荐类型 |
|----------|:--------:|
| 对方来函逐条列出质疑、需正面回应反驳 | 回复函 |
| 对方来函要求"说明情况"/"汇报整改"，重在陈述事实 | **说明函** |
| 希望保持建设性合作姿态、避免对抗色彩 | 说明函 |
| 需引述对方原文并逐条回击 | 回复函 |

### 4.2 发函主体确认

**公司**→印章模式（公章+法定代表人/授权代表）；**个人**→签名模式。

### 4.3 模板匹配

读取 `references/letter-type-templates.md` 获取结构模板。

### 4.4 策略定级

读取 `references/strategy-levels.md`，根据三要素（双方关系/事项严重程度/用户意图）自动判定策略等级（L1/L2/L3），向用户呈现建议等级+语气特征摘要，询问确认或调整。**默认 L2**（中性标准姿态）。

### 5.1 通用结构要素

```
标题 → 称谓行 → [发函方信息块（置顶模式）] → 正文段落 → [后续动作|举报请求|法律适用与争议解决（承诺函）] → 结尾敬语 → 落款 → [附联系方式]
```

### 5.2 论据策略

`file_read ../baichen-ndr-standard/references/knowledge-letter.md` 获取收件人画像与写作模式。

`file_read references/writing-patterns.md` 获取可复用用语库（风险披露/后果清单/合同对照/举报函用语等八类语料）。

| 策略 | 做法 | 适用性 |
|------|------|:--:|
| **引用链** | 后函引用前函编号+结论，避免重复 | 通过 |
| **第三方背书** | 精确引用报告全称+机构+编号+日期+结论 | 通过 |
| **条款要件拆解** | 仅拆解合同条款逐条匹配事实，不拆解法条 |  |
| **深度论证** | 仅限事实层面逐层回应，禁引判例、禁下法律定性 |  |
| **后果清单** | 商业后果+法律后果逐条列明 | 通过 |

### 引用对方书面承诺增强催告效力

函告正文引述对方在先函件/邮件/对账单/结算单中的书面确认（如"贵方2025年X月X日来函确认……""贵方在对账单中盖章确认欠付……"），作为催告依据。注：更正说明（原文引"《最高人民法院关于民事诉讼证据的若干规定》第三条·另一方当事人无需举证证明"为错误引用，现更正）：此类诉前往来材料属**诉讼外承认**，仅可作为证明该事实的**书证**，不产生《最高人民法院关于民事诉讼证据的若干规定》（法释〔2019〕19号，2020-05-01施行）**第3条第2款**（该款仅规范诉讼中的自认）的免证效力，故**不得**表述为"另一方当事人无需举证证明"；其价值在于构成认定事实的重要证据材料，可显著降低我方举证难度。若确需援引自认规则，须限定于**已进入诉讼程序后**对方在证据交换、询问、调查过程中，或在起诉状、答辩状、代理词等书面材料中的承认，并引第3条第2款。格式：`贵方[日期]在[文书名称]中确认[内容]，请贵方按此履行。`

### 5.3 警示语匹配（催告函专用）

催告函后续动作须 `file_read ../baichen-ndr-standard/references/knowledge-letter.md`，根据致送对象身份类型匹配定制化警示语。身份无法确定时默认"普通企业"。

`file_read references/recipient-profiles.md` 获取客户自署函称谓适配与嵌入方式（共享警示语正文见 ../baichen-ndr-standard/references/knowledge-warning-phrases.md §二）。

### 5.4 文风与格式硬规

**格式硬规**法条引用具体到条款项；正文仿宋12号1.5倍行距；称谓公司→"贵司"、个人→"贵方"、己方→"我方"/"本公司"/"我司"/"本人"、对公机构（仲裁委/监管机关/协会等）→"贵委"/"贵会"/"贵局"/"贵厅"；单句≤80字；金额大小写兼顾；严禁侮辱、诽谤、恐吓、夸大。

**通用铁律（全程强制遵守）**

| 铁律 | 要求 |
|------|------|
| ③ **事实直接陈述** | 不加暗示性修辞，让事实自己说话 |
| ⑤ **以客观态势替代主观立场** | 用"条件不具备""存在不确定性""依据尚不充分"等客观判断代替主观表态 |
| ⑥ **法律施压靠合同+事实+后果清单** | 不引法律条文（客户不是律师），不下法律定性结论。威慑力来源合同约定→事实差距→商业+法律后果清单。**举报函豁免**允许正文引法条作为举报依据，允许适度评价。**承诺函例外**：承诺函的「法律适用与争议解决」条款须引法条（约定管辖法院/适用法律） |

**场景铁律（按需适用）**

| 铁律 | 要求 | 适用指引 |
|------|------|---------|
| ① **以逻辑代编号** | 段间过渡用因果/递进连接。**例外**承诺函、声明函以编号条款推进 | 所有类型 |
| ② **法条→判例→判断** |  客户自书函**禁止**引判例、**禁止**下法律定性，仅限后台检索辅助 | — |

> **【2026-08-31 更正·适用边界注记】** 铁律②「客户自书函**禁止**引判例、**禁止**下法律定性」适用于**对外发送函告**（收件人为对方当事人/第三人）；**内部汇报函**（客户向上级/出资人/监管报送的法律风险分析）适用 `references/quality-checklist.md` 第 21 项与 `references/strategy-levels.md`「汇报函策略分级」的「法条→判例→判断」**强制**递进要求——两者适用对象不同（对外函 vs 内部汇报函），不构成冲突，⛔ 两条规则均保留、**均不得**删除。
| ④ **共情仅限一句** | 开篇最多一句，正文不重复 | 回复/声明函重点 |

**八类函告语气梯度**

| 类型 | 语气定位 | 关键特征 |
|------|---------|---------|
| 催告函 | 礼貌而坚定 | "请贵方…"代替"要求贵方…" |
| 回复函 | 理性克制 | 以事实和合同回应，不逐条激辩 |
| 说明函 | 客观坦诚 | 不回避不利面，措辞得体 |
| 通知函 | 明确而克制 | 通知事项不容含糊 |
| 声明函 | 严肃而有分寸 | 逐条列明，措辞克制 |
| 汇报函 | 平实理性 | 如实汇报，不以"表功/诉苦"笔调 |
| 承诺函 | 郑重而审慎 | "经审慎考虑""郑重承诺"，条款式推进 |
| 举报函 | 正式克制 | 协助性开篇，允许适度评价 |

> 论证深度分级：按 `ndr-standards.md` §2.6 繁简标准执行（⛔ 禁注水、篇幅与内容匹配）

### 5.5 交付前质量自检（强制）

起草完成后读取 `references/quality-checklist.md`，逐项自检全部检查项（62项）。任一项不通过→立即修正→复查关联项。全部通过后向用户呈现确认项。

### 5.6 风险红线自动检测（强制）

起草完成后逐条扫描以下五项风险红线。任一条触发→**立即暂停交付，向用户提示风险+建议修改方案**，用户确认后方可进入步骤6

| # | 风险红线 | 检测方式 |
|---|---------|---------|
| 1 | **内容失实风险** | 是否存在未经材料支撑的断言性事实陈述 |
| 2 | **胁迫风险** | 是否存在超越民事函告范畴的威胁性表述（**举报函豁免**） |
| 3 | **商业秘密泄露风险** | 是否披露了合同价款以外的对方非公开商业信息 |
| 4 | **时机风险提示** | 诉讼时效临近届满或除斥期间即将经过 |
