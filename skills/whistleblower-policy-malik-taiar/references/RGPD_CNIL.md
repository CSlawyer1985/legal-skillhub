# RGPD 合规——CNIL 专业举报参考框架

> **参考**：CNIL 2023年7月6日关于用于实施举报机制的个人数据处理参考框架

---

## 1. 参考框架的适用范围

### 1.1 相关机构

参考框架面向：
- **私营或公共机构**，有义务或决定实施 DAP（专业举报机制）者，无论其规模大小
- **第三方实体**，提供与举报的接收、处理和保存相关服务者

### 1.2 涵盖的处理活动

参考框架适用于能够实现以下目的的自动化处理：
- 接收、处理和保存任何**善意**作出的举报
- 举报或报告违反法律（法国、欧洲、国际、外国）或道德规则的行为

**涵盖的机制类型**：
- 依《Sapin 2 法》第17条第II.2°条设立的 DAP（行为守则/反腐败）
- 依修订后《Sapin 2 法》第6条及后续条款设立的 DAP（一般举报）
- 尽调义务 DAP（《商法典》第 L. 225-102-4 条）
- 自愿设立的 DAP（道德守则）
- 涵盖多项目的的单一 DAP

> **重要提示**：本参考框架不具约束力。机构可以偏离之，但必须证明并记录保证 RGPD 合规的替代措施。

## 2. 授权目的（参考框架第3节）

### 2.1 处理目标

内部举报数据的处理可用于：

| 目的 | 说明 |
|----------|-------------|
| **收集举报** | 接收和处理旨在报告违反特定规则行为的举报 |
| **核实与调查** | 开展必要的核实、调查和分析 |
| **确定后续处理** | 确定对举报的处理结果 |
| **保护人员** | 确保相关人员的保护 |
| **权利抗辩** | 在司法程序中行使或抗辩权利 |

### 2.2 数据使用规则

```
禁止事项：
[ ] 将数据用于与上述目的不相容的重新使用
[ ] 进行目的之外的其他关联

相容使用（示例）：
[ ] 在与举报相关的诉讼中为机构权利抗辩
```

## 3. 处理的法律依据（参考框架第4节）

### 3.1 两种可能的法律依据

| 法律依据 | 条件 | 示例 |
|-------------|------------|----------|
| **法定义务**（RGPD 第6.1.c条） | 实施 DAP 的义务源于法国法、国际承诺或欧盟法律，且该机构确实受其约束 | 《Sapin 2 法》第8条和第17条、尽调义务 |
| **合法利益**（RGPD 第6.1.f条） | DAP 的设立不源于法定义务，但不得侵害相关人员的权利和自由 | 自愿 DAP、内部道德守则 |

### 3.2 多重目的的 DAP

当 DAP 服务于**多重目的**（法定义务 + 自愿承诺）时，处理负责人必须：
- 区分各目的本身
- 区分支撑各目的的法律依据

## 4. 涉及的个人数据（参考框架第5节）

### 4.1 分阶段的最小化原则

#### 第一阶段：举报的收集
> 涵盖举报接收和回执发送的期间

```
收集阶段的要件：
[ ] 仅收集实现目的所必需的数据
[ ] 提醒举报人，信息应当：
    - 保持事实性
    - 与举报事项有直接关联
    - 不涉及受保护的秘密（国防、医疗、
      司法评议、侦查/预审、律师）
```

#### 第二阶段：举报的调查处理
> 从收到举报到对处理结果作出决定并通知举报人的期间

**通常相关的数据类别**：

| 类别 | 数据 |
|-----------|---------|
| **举报** | 被举报的事实 |
| **身份、职务、联系方式** | 举报人 |
| | 被举报人 |
| | 参与、被咨询或被听取的人员 |
| | 协助者及与举报人相关的人员 |
| **调查要素** | 核实过程中收集的要素 |
| **文档** | 核实工作的记录 |
| **处理结果** | 对举报作出的处理 |

**附加义务**：在整个处理过程中确保数据质量（准确且最新）。

#### 第三阶段：对处理结果作出决定之后
> 仅可保存实现以下目的所必需的数据：

```
决定后保存的目的：
[ ] 保护利益相关方免遭报复
    （举报人、协助者、被举报人）
[ ] 在司法程序中确认、行使和抗辩权利
[ ] 对合规流程进行内部或外部审计
```

### 4.2 敏感数据的处理（RGPD 第9条）

**需要强化警惕的数据**：
- 民族或种族出身
- 政治观点
- 宗教或哲学信仰
- 工会会籍
- 基因数据
- 生物识别数据
- 健康数据
- 性生活或性取向

**处理的具体法律依据**：
- RGPD 第9.2.g)条：重大公共利益
- RGPD 第9.2.f)条：在司法程序中确认、行使或抗辩权利

### 4.3 违法数据（违规、定罪）的处理（RGPD 第10条 / LIL 第46条）

与违规、定罪和保安处分相关的数据可以收集：
- 依据国内法的具体规定（《Sapin 2 法》第8条、第17条，《商法典》第 L. 225-102-4 条）
- 为使处理负责人能够“准备并在必要时行使和跟进法律诉讼”（LIL 第46-3°条）

### 4.4 举报人身份的处理

#### 4.4.1 匿名举报

**定义**：举报人选择不透露其身份（姓名、职务、标识符、实名电子邮箱地址等）的举报，即使日后有可能识别其身份。

```
匿名举报的要求：
[ ] DAP 应允许举报人发出匿名举报
[ ] 允许在保持匿名的情况下继续交流
    （例如：不具识别性的电子邮箱地址、邮政信箱）
[ ] 不得进行任何重新识别的尝试
    （除非相反的法定义务或同意）
[ ] 不得使用重新识别的技术手段：
    - Cookie 和跟踪器
    - 收集 IP 地址
    - 终端配置参数
    - 信息交叉比对
[ ] 在程序中载明“对匿名举报的处理结果”
    （对依《Sapin 2 法》第6条及后续条款的举报为强制性要求）
```

#### 4.4.2 具名举报

如举报人选择表明身份，其身份由负责举报管理的人员**保密**处理。

## 5. 访问者与接收者（参考框架第6节）

### 5.1 一般原则

- 数据必须**仅限依据其职责被授权的人员**访问
- 访问授权必须**记录在案**
- 访问必须采取**可追溯性**措施

### 5.2 举报处理的外包

#### 实体的可能定性

| 定性 | 后果 |
|---------------|-------------|
| **处理负责人** | 决定处理的目的和手段 |
| **处理者** | 代表处理负责人处理 |
| **联合负责人** | 共同决定目的和手段 |

**要求**：必须订立界定处理特征和各方义务的合同（见 RGPD 第四章）。

#### 依《Sapin 2 法》第6条及后续条款设立的 DAP 的外包规则

| 操作 | 可否外包 |
|-----------|-------------------------------|
| **举报的接收** | 可以——广泛开放（律师事务所、专业平台、邮件服务提供商） |
| **可委托的职能** | 接收、音视频记录、转写、笔录记录、受理性分析、发出回执 |
| **资源共享** | 仅限少于250人的机构（集团成员与否均可） |
| **全面委托** | 法规未规定 |

> **例外**：市镇和公共机构可委托地方公务员管理中心承担举报收集和处理双重职能，无论人员数量多少（《Sapin 2 法》第8条第I.B.4°条）。

### 5.3 访问数据的人员

```
被授权人员（示例）：
[ ] 专门负责举报管理的人员
[ ] 指定的负责人或服务提供者（附合同承诺）
[ ] 协助机构的律师/顾问
[ ] 同一集团的其他实体（严格条件）

负责人/服务提供者的承诺：
[ ] 不得将数据用于举报管理以外的目的
[ ] 确保保密性
[ ] 遵守有限的保存期限
[ ] 服务结束后销毁/归还载体
```

### 5.4 数据披露规则

```
严格的披露规则：

举报人身份：
[ ] 仅可经其同意披露
[ ] 唯一例外：依法有告发义务时向司法机关通报
    （《Sapin 2 法》第9条第I款第2段）

被举报人身份：
[ ] 仅在举报的实性成立后披露
[ ] 例外：向司法机关通报

集团内部举报的移交：
[ ] 机构不得移交举报
[ ] 仅可建议举报人自行直接移交
```

### 5.5 向欧盟境外传输

任何向欧盟境外的传输均须受（RGPD 第44条及后续条款）约束：
- 充分性决定，或
- BCR（公司内部规则），或
- 标准数据保护条款，或
- 经 CNIL 批准的行为守则/认证机制，或
- 经 CNIL 授权的特订合同条款，或
- RGPD 第49条例外

## 6. 保存期限（参考框架第7节）

### 6.1 一般原则

数据仅在实现目的**严格必要**的期间内以可识别形式保存（RGPD 第5-1-e条）。

保存期限的信息必须**告知相关人员**。

### 6.2 分阶段期限

| 阶段 | 保存期限 | 说明 |
|-------|----------------------|--------------|
| **活动数据库** | 直至对处理结果作出**最终决定** | 自收到之日起的合理期间 |
| **中间档案** | 与处理及利益相关方保护**严格相称**的时间 | 考虑可能补充调查的期限（《Sapin 2 法》第9条第III款） |
| **纪律/诉讼程序** | 直至**程序终结**或**救济时效届满** | 适用于已对被举报人或滥用举报人启动程序的情形 |
| **长期存档** | 依法律义务或证据需要 | 会计、社保、税务义务；诉讼；质量审计 |

### 6.3 匿名化数据的保存

```
匿名化规则：

[ ] 匿名化后的数据不再受 RGPD 约束
    （第29工作组关于匿名化技术的第 05/2014 号意见）

[ ] 《Sapin 2 法》第9条第III款：“举报相关数据可以
    保存超过[...]，条件是相关自然人既未被识别
    也不可识别”

[ ] 如数据经充分匿名化，可无限期保存
[ ] 机构必须保证匿名状态的持久性

注意：“匿名举报”（《Sapin 2 法》）≠“匿名化数据”（RGPD）
《Sapin 2 法》意义上的匿名举报可能包含 RGPD 意义上的
个人数据
```

## 7. 信息告知（参考框架第8节）

### 7.1 相关人员的识别

#### “可能相关人员”
所有可能发出举报或被举报的人：
- 本机构人员（员工、公职人员、临时工、实习生、借调人员、志愿者等）
- 外部合作者、客户、供应商（自然人）
- 有合同关系的法人的工作人员

#### “相关人员”
所有数据被**实际处理**的自然人：
- 举报人
- 被举报人
- 协助者（自然人）
- 可能提供信息的人员
- 间接受保护人员（《Sapin 2 法》第6-1条第2°和3°条）

### 7.2 告知内容（RGPD 第12、13、14条）

```
强制告知事项：
[ ] 处理的存在
[ ] 特征：
    - 追求的目的
    - 可能包含的数据类型
    - 可能发出举报或被举报的人员类型
    - 程序的主要步骤
    - 保存期限
[ ] 访问、更正和删除权
[ ] 向欧盟境外传输的适用规则
[ ] 向 CNIL 提出投诉的权利

建议告知事项：
[ ] 滥用 DAP 将面临制裁/追诉
[ ] 善意使用不会受到任何纪律制裁
[ ] DAP 仅是多种举报方式之一
[ ] 不使用 DAP 不会招致任何制裁
```

### 7.3 告知方式

#### 7.3.1 设立前的磋商
- 告知和/或咨询主管机构
- 建议：定期向职工代表机构报告 DAP 的使用情况

#### 7.3.2 部署时的一般告知
- 在 DAP 引入**之前**告知所有可能相关人员
- 如存在实际困难：使信息易于获取（网站）
- 优先采用个别告知（电子邮件、纸质文件）

#### 7.3.3 对举报人的专项告知

| 时机 | 方式 |
|--------|----------|
| **在线举报** | 在填写前显示页面/文本块 |
| **其他举报方式** | 最迟在**回执**时 |

**回执**：
- 无论适用何种制度均为强制性
- 必须带有时间戳
- 概括信息和附件
- 如举报人希望匿名，**不得**以提供识别信息为前提

**反馈**（2022-1284 号法令第4条第III款）：
- 书面告知拟采取/已采取的措施
- 这些措施的理由
- 不得以识别举报人为前提

#### 7.3.4 对被举报人的专项告知

```
告知期限：
[ ] 合理期限，自举报发出之日起不得超过一个月
    （有充分理由的例外除外）

可以推迟（RGPD 第14-5-b条）：
[ ] 如告知“可能严重损害处理目标的实现”
[ ] 示例：证据灭失风险
[ ] 风险消除后应立即告知

告知内容：
[ ] 确保正确送达的方式
[ ] 不包含举报人身份的信息
[ ] 不包含第三方身份的信息
```

## 8. 个人权利（参考框架第9节）

### 8.1 权利概览

| 权利 | RGPD 依据 | DAP 特殊性 |
|-------|-----------|-------------------|
| **反对** | 第21条 | 依法律依据有限行使 |
| **访问** | 第15条 | 不得损害他人权利 |
| **更正** | 第16条 | 仅限事实性数据，不清除历史记录 |
| **删除** | 第17条 | 严格条件 |
| **限制** | 第18条 | 例如：核实准确性期间临时冻结 |

### 8.2 访问权（RGPD 第15条）

**受益人**：任何数据正在或曾经被处理的人（举报人、推定受害人、被举报人、证人、被听取的人、协助者、间接受保护人员）。

**限制**：
- 不得损害他人的权利和自由
- 包括商业秘密、知识产权
- 但不得剥夺对第15.1条全部信息的访问（EDPB 第 01/2022 号指南）

### 8.3 反对权（RGPD 第21条）

```
反对权不适用：
[ ] 基于法定义务的处理
    → 依《Sapin 2 法》第8条B款和/或第17条的 DAP
    → 尽调义务 DAP（《商法典》第 L. 225-102-4 条）

反对权适用但可被拒绝：
[ ] 自愿设立的 DAP
[ ] 举报中提及或在调查处理期间出现的人员

拒绝理由：
[ ] 优先于个人利益的合法且重大的理由
[ ] 为确认、行使或抗辩司法权利所必需的处理
```

### 8.4 更正权和删除权

**更正（RGPD 第16条）**：
- 仅用于更正**事实性数据**
- 处理负责人必须能够核实材料的准确性
- **不删除也不替换**最初收集的数据
- 不得妨碍修改时间线的重建

**删除（RGPD 第17条）**：
- 按 RGPD 规定的条件行使
- 须结合证据需要和保护需要评估

## 9. 安全（参考框架第10节）

### 9.1 一般原则

机构必须根据处理所呈现的风险采取**一切有用的预防措施**，以：
- 保护数据安全
- 防止数据被歪曲、损坏
- 防止未经授权的第三方访问

### 9.2 详细安全措施（17类）

| 类别 | 措施 |
|-----------|---------|
| **提高用户意识** | 告知和宣传数据处理人员 |
| | 制定有约束力的计算机使用章程 |
| **用户身份认证** | 每个用户唯一标识（登录名） |
| | 符合 CNIL 建议的密码政策 |
| | 强制更换自动分配的密码 |
| | 限制访问尝试次数 |
| **权限管理** | 定义权限配置 |
| | 删除过时的访问权限 |
| | 年度权限审查 |
| **访问记录与事件管理** | 日志记录系统 |
| | 告知用户日志记录 |
| | 保护日志设备和信息 |
| | 事件管理程序（包括违规通知） |
| **工作站安全** | 会话自动锁定 |
| | 定期更新的杀毒软件 |
| | 软件防火墙 |
| **移动设备安全** | 移动设备加密 |
| | 定期备份/同步 |
| | 智能手机解锁保密 |
| **内部网络保护** | 将网络流量限制在严格必要范围 |
| | 远程访问使用 VPN |
| | Wi-Fi 安全（WPA3 协议） |
| **服务器安全** | 限制管理工具访问 |
| | 及时安装关键更新 |
| | 确保数据可用性 |
| **网站安全** | TLS 协议 |
| | URL 中不含密码/个人数据 |
| | 用户输入控制 |
| | 非必要 Cookie 的同意横幅 |
| **备份与连续性规划** | 定期备份 |
| | 载体存放于安全场所 |
| | 运输途中保护备份 |
| | 定期业务连续性测试 |
| **安全归档** | 档案的特定访问方式 |
| | 过时档案的安全销毁 |
| **软件开发管理** | 设计阶段的数据保护 |
| | 默认隐私友好参数 |
| | 严格管理评论区域 |
| | 开发测试使用虚构/匿名数据 |
| **维护与报废管理** | 干预登记簿 |
| | 第三方干预管理 |
| | 报废前数据擦除 |
| **处理者管理** | 合同中的特定条款 |
| | 数据返还和销毁条件 |
| | 安全审计、走访 |
| **与其他机构交流安全** | 发送前数据加密 |
| | 核实正确的接收者 |
| | 通过不同渠道传递秘密 |
| **场所保护** | 门禁上锁 |
| | 定期检查的防入侵报警 |
| **加密、哈希或签名** | 使用公认且安全的算法、软件和库 |
| | 秘密和加密密钥的安全保存 |

## 10. AIPD——数据保护影响评估

### 10.1 建议性质

CNIL 参考框架构成**实施 AIPD 的辅助工具**。

专业举报处理可能对相关人员的权利和自由产生高风险，原因尤其包括：
- 处理数据的性质（可能敏感或涉及违规）
- 对被举报人的潜在后果
- 监督和调查的特殊背景

### 10.2 方法

```
建议步骤：
[ ] 使用 CNIL 的方法工具（网站）
[ ] 确定确保必要性和相称性的措施
[ ] 保障个人权利
[ ] 控制风险
[ ] 如已指定 DPO 则咨询 DPO
[ ] 依托 CNIL 关于 AIPD 的指南
```

## 11. 完整的 RGPD 合规检查清单

### 11.1 关键控制点

```
法律依据与目的：
[ ] 已识别法律依据（法定义务或合法利益）
[ ] 如多重目的：为每项目的区分法律依据
[ ] 目的明确、具体且合法
[ ] 无不兼容的数据重新使用

数据最小化：
[ ] 收集的数据严格必要（收集阶段）
[ ] 保存的数据严格必要（调查处理阶段）
[ ] 决定后数据限于保护/司法/审计目的
[ ] 提醒举报人信息的事实性和相关性

敏感数据与违规数据：
[ ] 已识别具体法律依据（RGPD 第9.2.g或9.2.f条）
[ ] 违规数据符合 RGPD 第10条 / LIL 第46条条件

匿名举报：
[ ] 提供匿名举报可能
[ ] 可在保持匿名的情况下交流
[ ] 无重新识别尝试
[ ] 无技术追踪手段（Cookie、IP 等）

访问者与接收者：
[ ] 被授权人员记录在案
[ ] 权限限于职责范围
[ ] 访问可追溯
[ ] 如外包：合同符合 RGPD
[ ] 如为处理者：已核实充分保障
[ ] 举报人身份披露规则已遵守
[ ] 被举报人身份披露规则已遵守
[ ] 如向欧盟境外传输：符合 RGPD 第44条及后续条款

保存期限：
[ ] 分阶段确定期限（活动、档案、诉讼）
[ ] 期限已告知相关人员
[ ] 延长保存时有匿名化程序
[ ] 保证匿名状态的持久性

信息告知：
[ ] 部署前的一般告知
[ ] 信息持续可获取
[ ] 对举报人的专项告知（最迟于回执时）
[ ] 带时间戳且完整的回执
[ ] 一个月内告知被举报人（有充分理由的例外除外）
[ ] 内容符合 RGPD 第13/14条

个人权利：
[ ] 访问权得到保障（附合法限制）
[ ] 依法律依据处理反对权
[ ] 更正权限于事实性数据且不清除历史记录
[ ] 限制权适用
[ ] 已定义请求处理程序

安全：
[ ] 技术和组织措施记录在案
[ ] 静态和传输中数据加密
[ ] 强身份认证
[ ] 访问日志记录
[ ] 识别数据隔离
[ ] 安全备份
[ ] 事件管理程序
[ ] 违规通知程序

文档：
[ ] 登记于处理登记册（RGPD 第30条）
[ ] 已完成 AIPD（建议）
[ ] 已咨询 DPO（如已指定）
[ ] 记录与参考框架的任何偏离
```
