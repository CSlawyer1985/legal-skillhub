01 / PURPOSE

它不是回答一个法律问题，
而是制造一套能重复工作的法律能力。

当一个法律任务反复出现、需要稳定的输入输出契约，并且对法域、时点、证据和人工复核有要求时，legal-meta-skill 负责把它治理成一个可复用的 Agent Skill 包。

适合

重复法律工作流、既有 SOP、成熟提示词、代表性输入与优秀输出、现有 Skill 的改造与审计。

不适合

一次性法律咨询、单份文书起草、普通翻译或总结，以及替代律师作出最终法律决定。

02 / MECHANISM

六阶段工作流：先建模，再交付。

每一步都对应一类文件、一个判断门槛和一组可核验成果。流程允许判断，但不允许跳过边界、法源和证据。

01

意图 / Intent

收敛任务目的、受众、法域、时点、主体、事项和排除范围，确认是否值得做成可复用 Skill。

→ task scope / decision goal
02

研究 / Research

只读研究相关法源、权威性、既有方案与许可证，记录保留、改造、拒绝或重新设计的理由。

→ source map / prior art
03

建模 / Model

把下游法律工作流映射到十二模块法律能力模型，先写 Skill IR，再决定缺口与门禁。

→ legal Skill IR
04

封装 / Package

保持 SKILL.md 作为最小入口，把方法、模板、案例和检查器放入自包含目录，支持渐进式披露。

→ self-contained package
05

评测 / Evaluate

分别评测“应该触发 / 不应触发 / 近邻场景”和输出契约、法律来源、证据分层与治理边界。

→ trigger + output eval
06

审查 / Review

把静态检查、模型运行、人工复核和真实项目证据分开，按成熟度决定发布、交接或停止。

→ audit / handoff
03 / CONTRACT

输入端要求与输出端成果

它把模糊的“帮我做一个法律 Skill”，转换为可填写、可检查、可追溯的输入与交付契约。

INPUT / 需要带进来
  • 重复出现的中国大陆法律工作流
  • SOP、既有提示词或现有 Skill
  • 代表性输入与优秀输出样例
  • 法律来源、项目约束与权限边界
  • 触发案例、反例与输出评测样例
→
OUTPUT / 最终留下
  • 自包含法律 Skill 包
  • 法律能力配置与输入/输出契约
  • references、templates、evals 与 scripts
  • 触发评测、输出断言与审计报告
  • 证据边界、成熟度判断与创建交接报告
DEFAULT 本地优先，数据默认留在本机；外部研究、发布、发送与远程同步必须单独授权。

06 / GUARDRAILS

静态通过，不等于已经证明能在真实项目中工作。

legal-meta-skill 会把“已检查”和“仍缺证据”分开。它的价值不在于承诺自动正确，而在于让缺口被看见、被记录、被复核。

PRESENT

包内确定性检查

结构、配置、触发案例、输出断言、生成器和成熟度门禁都有可重复运行的脚本与测试。

MISSING EVIDENCE

不能伪装成已验证

模型提供商运行、独立人工盲审、真实客户遥测和公开安装回归，必须另行取得证据。

HUMAN REVIEW

最后责任仍在人

正式法律结论、发布、外传和不可逆外部动作，不由元 Skill 自动替用户决定。
