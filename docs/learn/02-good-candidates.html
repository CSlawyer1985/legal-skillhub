02 · 什么适合做 Skill

不是所有工作都值得封装。判断标准就三条：反复做、有判断框架、有质量标准。三条缺一条，先别写 Skill。

一、适合封装的五类法律工作

工作类型为什么适合站内实例（可点击查看）
合同审查高频重复、审查标准明确、立场稳定（买方/卖方/风控）construction-contract-review
案件时间线整理材料格式各异但整理方法恒定chronology-builder
证据目录制作格式法定、证明目的写法有章法evidence-list-ai-writing
法律检索检索路径、来源优先级、验证方法可固化prc-legal-research
风险报告风险分级口径、报告结构可复用company-credit-rating
客户访谈提纲同类型案件的必问清单高度稳定家事尽调 fazhixing

二、不适合封装的三种事

  1. 一次性任务。只为一个案件、一个客户服务的内容，写在对话里就好，封装是浪费。
  2. 纯创意工作。"帮我想一个谈判策略的出奇招"——这类工作的价值恰恰在于不设框架。
  3. 没有稳定判断标准的事。如果你自己也说不清"什么叫做得好"，AI 只会把你的含糊放大。先沉淀标准，再谈封装。
一个简单的自测：想象你要把这项工作交给一个聪明但完全不懂你们业务的新人，你能不能在一张纸写清楚"怎么算做完、怎么算做好"？能，就值得封装。

三、七步蒸馏法：从工作经验到 Skill 骨架

选定一项工作后，按七个步骤把经验"蒸馏"出来。以"审查一份买卖合同（乙方立场）"为例：

  1. 任务边界：做什么、不做什么。——"审查买卖合同的商务与法律风险，不出具正式法律意见，不替代最终决策。"
  2. 输入条件：需要什么才能开始。——"合同文本（Word/PDF/粘贴文本）；若缺关键信息（如双方主体），先索取再审查。"
  3. 判断节点：哪些地方必须做判断、依据什么。——"付款与交付是否匹配？验收标准是否可操作？违约责任是否对等？所有权与风险何时转移？"
  4. 操作步骤：先后顺序本身就是专业。——"先主体资格 → 再效力性条款 → 再价格与支付 → 再交付验收 → 再违约救济 → 最后争议解决。"
  5. 质量标准：怎么算做好。——"每个风险点必须定位到具体条款、说明为什么是风险、给出修改建议；不能只罗列'存在风险'。"
  6. 异常处理：遇到意外怎么办。——"合同为英文→先说明以中文输出审查意见；关键页缺失→明确标注'待补充'，不猜测内容。"
  7. 输出格式：交付物长什么样。——"风险清单（高/中/低三级）+ 修改建议表 + 一页结论摘要。"

这七步填完，你的 Skill 骨架就有了——剩下的是把它写成 SKILL.md 的格式（下一讲的内容）。

四、从"我的工作"到"团队的工作"

写 Skill 时建议多想一步：这个 Skill 是给"我"用，还是给"一类人"用？给自己的可以写满个人口径（"我们团队的标准是……"）；给团队或公众的，要把口径显式化、参数化（"违约金超过 LPR X 倍视为过高，X 默认 4，可调整"）。本站 2049 个 Skill 里，凡是好用的，都是把判断标准写"显"了，而不是藏在形容词里。

你可以先在技能库里搜一搜自己常做的工作，看看别人封装到什么程度——也许你要的已经存在，也许你能看出"我可以写得比他好"。
