案例解剖：中国法律研究助手

来自prc-legal-research——中文法律检索类 Skill 的工程化标杆。

一、背景与触发

面向中国境内法律研究的 Agent Skill：用户提出法律问题，Skill 系统性检索和分析法律资料，最终输出一份客观的法律研究备忘录。它的 description 明确定位："你的工作是根据用户的问题，系统性检索和分析法律资料，最终输出一份客观的法律研究备忘录"——研究框架参考英美法 IRAC/CREAC 与德国法 Gutachtenstil 推理模式。

二、模式归类：流程 SOP 型 + 工具调用型（L3）

  • 八阶段工作流：信息完整性检查 → 研究问题提出与确认 → 二手文献检索 → 二手文献分析 → 一手权威资料检索与验证 → 分析与推理 → 验证和风险识别 → 生成法律研究备忘录
  • 双检索架构：一手权威资料走元典 API（法条/法规/权威案例/普通案例四类检索），二手文献走 Tavily 网络检索
  • 首次使用检查：运行前先验证两个 API Key 是否配置，未配置则引导用户注册获取并写入 config.py——而不是默默报错

三、结构解剖

部件实现可借鉴点
Intake第一阶段"信息完整性检查"：先确认问题所需信息是否齐备分析前的完整性检查，避免基于残缺信息的错误分析
双源检索一手（元典）+ 二手（Tavily）分层检索一手权威资料与二手文献分离，来源层级清晰
验证闭环第七阶段"验证和风险识别"：输出前复核检索结果验证是流程的正式阶段，不是可选项
输出契约法律研究备忘录的固定结构交付物结构化，可直接进文档
脚本封装scripts/ 封装元典与 Tavily 的调用函数API 调用抽象为函数，模型只需传参

四、亮点摘录

  • 框架的诚实：明确声明研究框架参考 IRAC/CREAC（英美法）与 Gutachtenstil（德国法）——方法论有出处，不装原创；
  • 引导式配置："请前往元典 API 平台注册获取密钥，然后把密钥告诉我，我来帮你写入配置文件"——把运维工作做成对话，律师零门槛；
  • 来源可追溯：每条法条带时效性字段（现行有效/失效/已被修改/部分失效/尚未生效），案例带案号。

五、可复用方法论

  1. 检索类 Skill 先解决"数据从哪来"：一手+二手双层来源设计，比让模型自由发挥可靠得多；
  2. 首次使用检查是标配：任何依赖 API key/外部服务的 Skill，都应该先自检依赖再开工；
  3. 八阶段里的"验证"要独立成段：验证不是最后随手做，而是流程中的正式阶段；
  4. 脚本传参而非让模型写代码：把 API 调用封装成函数，模型只负责组织参数——大幅降低出错率。

六、法域适配讨论

本 Skill 完全绑定中国大陆法域（元典 API + 中文法规库）。移植到其他法域的启示：把"数据源"和"方法论"解耦——同样的八阶段流程，换成美国法可以用 Westlaw/Lexis 检索，换成欧盟法可以用 EUR-Lex——流程骨架可复用，数据源替换即可。

注意：本 Skill 需要元典 API key（免费额度 1000 积分/首月）与 Tavily API key（免费 10000 次/月）。安装后需先配置密钥才能使用，详情见其详情页的"依赖与配套条件"。
