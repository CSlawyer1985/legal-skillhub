04 · 工作环境与配套条件

一个 Skill 下载下来跑不动，十有八九不是 Skill 的问题，而是配套条件没就位。这一讲讲清：Skill 在哪里运行、各类 Skill 分别需要什么配套、怎么快速判断一个 Skill 的依赖。

一、Skill 在哪里运行

Skill 是"宿主 Agent + 约定目录"的机制。以 Claude Code 为例：

~/.claude/skills/            ← 个人级：对你所有项目生效
└── contract-review/
    └── SKILL.md
<项目目录>/.claude/skills/   ← 项目级：只对此项目生效
└── case-analysis/
    └── SKILL.md

安装一个 Skill，本质上就是把这个文件夹按原结构复制到上述目录。本站每个详情页都提供三种安装方式（curl 逐文件 / git sparse-checkout / 让 AI 助手代装），效果相同。安装后不需要重启——下一次对话中，当任务与 Skill 的 description 匹配时，宿主会自动调用。

验证安装是否成功：直接向 AI 描述一个该 Skill 覆盖的任务（比如装了合同审查 Skill，就丢一份合同过去），观察它是否明确说出"我将使用 xxx skill"。

二、四类配套条件，逐类对照

1. 纯 Markdown Skill（约 65%）

只有 SKILL.md（±LICENSE）。零依赖，复制即用。本站多数 Skill 属于此类。

2. 带脚本（scripts/）的 Skill（约 20%）

脚本意味着运行时依赖。最常见的三类：

脚本特征配套条件检查方法
.py 文件Python 3 运行时；import 了第三方库（如 python-docx、requests）还要先 pip install看 scripts/ 里的 import 语句
调用外部 API（搜代码里的 api_key/requests）需要对应平台的 API key，且通常要联网看 README 或 SKILL.md 的"首次使用检查"段
读写本地文件/调用 pandoc、ffmpeg 等需要安装对应命令行工具看脚本中的 subprocess/os.system 调用

典型实例：prc-legal-research——它内置的"首次使用检查"是教科书级做法：运行前先检查两个 API key 是否配置，没配置就引导用户完成，而不是直接报错。

3. 处理文档的 Skill

生成 Word 报告、读取 docx 批注、处理 PDF——这类 Skill 的能力上限取决于宿主的文档工具链：

  • 生成 docx：需要宿主环境能操作 OOXML（有 docx 处理能力或相应脚本库）；
  • 读取批注/修订：普通文本提取会丢掉批注层，需要能解析 OOXML 批注结构的工具；
  • 扫描件 PDF：需要 OCR 能力。

写这类 Skill 时，正确做法是把工具要求显式写进 SKILL.md（"本 Skill 需要 docx 处理能力；若当前环境不具备，应改为输出结构化 Markdown 供后续转换"）——给模型留降级路径，而不是让它撞墙。

4. 需要外部数据/系统的 Skill

  • 联网检索：需要宿主有搜索工具；
  • MCP 数据库（法规库、企业信息库）：需要预先配置对应 MCP server 和账号；
  • 本地知识库：需要用户自备知识库文件（SKILL.md 里应说明目录约定）。

三、三秒钟看懂一个 Skill 的依赖

在本站详情页，依赖判断已经替你做好了——每个 Skill 的"安装与部署"区块都有依赖与配套条件一栏（由全量内容分析得出）：

  1. 看文件树：有没有 scripts/？→ 有就有运行时依赖；
  2. 看依赖栏：写了 "python3 运行时" / "需要 API key（元典）" / "需要联网检索" 中的哪些；
  3. 拿不准就点开 scripts/ 里的文件直接读代码——本站文件浏览器就是为这个设计的。

四、不触发、误触发的排查

症状常见原因处理
Skill 从不被调用description 太抽象，AI 匹配不到；或安装目录错了检查目录结构；把触发词说得更直白（"用 xx skill 处理"）验证
不该调用时乱调用description 太宽泛，没写"不触发场景"在 description 里补"不适用于……"；对话中明确"这次不用 skill"
调用了但输出不对配套条件缺失（如没联网、没 API key）按第二节对照检查；让 AI 先自述"我检查了哪些条件"
脚本报错Python 库缺失、路径假设不符（如假设了 ~/.claude/skills 之外的目录）按报错装库；检查脚本里的路径变量
给自己 Skill 的良心建议：在 SKILL.md 开头加一个"首次使用检查"段——让 Skill 自己验证依赖是否就位，缺什么就引导用户补什么，而不是默默给出残缺输出。
